# 进入游戏恢复战斗退出链(enter-game-battle-pause-exit)迭代设计(总纲)

## 0. 元信息

- 迭代目标:用户裁定——`EnterGame.check_screen` 增加暂停面板、确认弹窗识别分支(插入位置:未知兜底前),使客户端重启恢复到战斗退出链画面族时主动退出战斗收敛,消灭死循环超时(用户对话裁定,2026-11-16;探索走查记录 `.debug/temp/operation-explore/2026-11-16-enter-game-battle-pause/`)。
- 状态:定稿(用户 2026-11-16 裁定:第三分支结算页确认、跳过对抗审直接实施)
- 文档清单:(无详设——本文即完整设计)

## 1. 问题与动机

### 1.1 现状症状

- 2026-11-16 实损:客户端重启后恢复上次中断的战斗(虚构叙事暂停面板态),`EnterGame.check_screen` 全不命中落入未知画面兜底;兜底点「菜单-右上角返回」(1867,52)(`src/sr_od/operations/enter_game/enter_game.py` L105-107,坐标源 `phone_menu.yml` 右上角返回)与暂停面板右上关闭X(1866,63)重叠 → 陷入「点X关面板→回战斗→再点→再弹面板」循环,retry 60 轮 382s 失败(`.log/mcp_server.log` 10:56 段)。
- 副本类型多(花萼/隧洞/历战/饰品/忘却之庭/模拟宇宙/逐光捡金系列等),哪些副本中断后重登会恢复在战斗画面**族谱未知**——恢复链画面(暂停面板/确认弹窗)没有正面识别分支,任何一种恢复态都会落兜底。

### 1.2 根因归层

**约定层**:未知画面兜底把「战斗中点右上角」当成「关弹窗」语义(它对新版本宣传页成立),而恢复链必经画面族(暂停面板/确认弹窗/结算页)无识别约定。不是流程层(兜底三道闸机制本身健康——战斗过程态下点右上角恰好是打开暂停面板的正确动作)也不是语义层。

### 1.3 解决到哪;明确不解决

- 解决:`check_screen` 增加三个正面识别分支(确认弹窗/暂停面板/战斗结算页),插入位置在未知兜底之前;配套建档确认弹窗屏。修复后恢复态收敛链:暂停面板 → 点退出位 → 确认弹窗 → 点确认 → 结算页 → 点退出 → 玩法选关屏(右上关闭X 与兜底点击位重合自动关闭)→ 大世界 → 既有收敛链。
- 明确不解决:
  - **货币战争形态**:暂停面板确认弹窗按钮文案「放弃并结算」非「确认」,且 CW app 起跑有自己的恢复链(`CurrencyWarApp._recover_if_paused` → `CwEntryExit`)。本期 EnterGame 遇 CW 形态点撤退后弹窗无人接 → 有界失败(retry 耗尽),**不劣于现状**;CW 恢复仍由 CW app 自检负责。
  - **忘却之庭/模拟宇宙等其他战斗的暂停面板形态实测**(设计按位置锚定不依赖按钮文案,同族形态自动覆盖;异形态遇上有界失败,届时补档)。
  - **识别顺序不改既有分支**:登录相关/交互/大世界判断保持原位原序(用户裁定「之前的分支都是比较明确的」)。

## 2. 方案(单文档完整设计)

### 2.2 恢复态收敛链(实测依据)

全链 2026-11-16 实机走查(screen-flow.md):暂停面板点「结束战斗并结算」(1237,984) → 确认弹窗「是否结束本场战斗?」点确认(1177,672) → 结算页「挑战结束/积分0」点「退出」(630,950) → 末日幻影选关屏(is_precise)。虚构叙事形态退出位按钮「返回虚构叙事」(1218,984)同位置(凌晨残留局实证);货币战争形态「撤退」(1222,981)同位置(CW doc)。

恢复态入口分支(族谱未知也不阻塞):
- 恢复到**暂停面板** → 分支A 接住(本迭代);
- 恢复到**战斗过程态**(无面板) → 画面无建档落未知兜底 → 点右上角(1867,52) = 战斗中暂停钮 → 弹暂停面板 → 下轮分支A 接住——既有兜底在此场景是正确动作,补分支后链路即活。

### 2.3 check_screen 三分支(核心设计)

插入位置:`in_game_result`(大世界角色图标)判断之后、`self._unknown_rounds += 1` 之前(`enter_game.py` L87-100)。分支内顺序:确认弹窗 → 暂停面板 → 结算页(弹窗是模态且弹出时暂停面板左上标题仍可见,弹窗必须先于面板判定,否则死循环点退出位——2026-11-16 对话裁定)。

**分支B 确认弹窗**(新建档「战斗-退出确认弹窗」):
- 识别:`round_by_find_area(screen, '战斗-退出确认弹窗', '标识-提示')` 命中 **且** `round_by_find_area(screen, '战斗-退出确认弹窗', '按钮-确认')` 命中(双锚同时才算——「提示」单词区分度差,全屏「提示」文字场景多)。
- 动作:取「按钮-确认」area 中心,`controller.click(center, pc_alt=True)` 显式点击(恢复态光标可能锁定,Alt+点击自由光标下无害——先例 `back_to_normal_world_plus.py` CW 大厅分支 L219-221)。
- 出口:`round_retry('战斗退出确认弹窗', wait=2)`(点掉后下一轮重识别;点击可能不落地,round_retry 逐帧重识别,拒 WAIT 永动——同 CW 大厅分支先例)。
- 与既有「确认」词分支的关系:既有 `check_screen_to_interact` 全屏 OCR「确认」词在新分支**之前**跑,正常情况弹窗已被它点掉;分支B 只在 OCR 未命中但弹窗存在时兜住(正面识别,可控)。两者并存不冲突。

**分支A 暂停面板**(档已建「战斗-暂停面板」):
- 识别:`round_by_find_area(screen, '战斗-暂停面板', '标识-战斗暂停')` 命中(双 id_mark 已随建档生效,精准档)。
- 动作:取「按钮-结束战斗并结算」area 中心(1140-1350, 950-1015 的中心),`pc_alt=True` 点击——**按位置不按文案**:AS「结束战斗并结算」/PF「返回虚构叙事」/CW「撤退」三形态同位异文案(screen-flow.md 实测),位置锚定对族谱未知防御。
- 出口:`round_retry('战斗暂停面板', wait=2)`。

**分支C 战斗结算页**(退出链必经中间站,AS 实测:确认后必落「挑战结束」页,右上角无按钮,不处理则兜底点击无效重试循环):
- 识别:全屏 OCR 匹配「挑战结束」(判定词独有性:胜利结算页标题是「挑战成功」、战败页「战斗失败」,无撞车;battle.md)。
- 动作:同帧 OCR 匹配「退出」词,命中其文字中心 `pc_alt=True` 点击(点 OCR 命中文字本身免建 area——先例 `check_screen_to_interact` 确认词点击);「退出」词未命中(形态差异)则不动作,落后续兜底(有界失败,挂未知项)。
- 出口:`round_retry('战斗退出结算页', wait=3)`(结算过渡较长)。

**模块级常量**:`BATTLE_SETTLE_PAGE_WORD: str = '挑战结束'`(分支C 判定词,同 `LOGIN_PAGE_MARK_WORD` 风格)。

**红线**:放弃战斗不可逆但有界——TL 系列免费挑战零消耗(挑战不耗开拓力);本链只在登录恢复语境触发,不存在「正在跑的有效战斗」被误杀;对已通关节点放弃亦无损失。

### 2.4 测试计划

1. **mock 流程快测**(核心):测试仓假控制器 harness 按剧本演——fixture 帧序列(暂停面板→确认弹窗→结算页→选关屏)喂假截图,断言:各帧命中对应分支、点击坐标落在对应 area(退出位/确认/退出文字)、round 结果按设计推进、正常登录画面(大世界帧)不受新分支影响(不误触发)。fixture 素材 = 探索存证截图。
2. **离线识别回验**:建档后 `analyze_screen(screenshot=fixture)` 三帧(暂停面板/确认弹窗/结算页)各自精准命中、互不误配(暂停面板帧已验;弹窗/结算页帧建档阶段验)。
3. **实机回归**:正常路径跑 EnterGame(游戏在大世界/选关态)不误触发新分支、登录成功不回归;真实恢复场景(杀进程)不在实机验证范围(mock+离线帧已覆盖),挂未知项备查。

## 3. 关键取舍

- **三分支 vs 用户拍板的「两个分支」**:探索实测 AS 退出链确认后必经「挑战结束」结算页,右上角无按钮、无「确认」词,不处理则兜底点击无效循环——结算页是链路必经站,非可选。作为第三分支写入设计,向用户显式说明此超出原拍板范围的新事实,待确认。
- **确认弹窗独立建档 vs 复用既有「确认」词分支**:全屏 OCR 词匹配不可控(任意画面出现「确认」二字即误触发),且弹窗态下暂停面板标题仍可见——若无正面分支,暂停面板分支会重复点退出位死循环。正面双锚建档(提示+确认)可控。既有「确认」词分支保留(先跑,正常路径它点掉;新分支兜 OCR 失误)。
- **按位置点退出位 vs 按按钮文案**:三玩法实测同位异文案,族谱未知副本的形态差异在「文案」维度概率高、「位置」维度概率低(同族 UI 家族布局一致)——位置锚定是族谱未知的防御。
- **CW 形态不覆盖**:CW 弹窗按钮文案「放弃并结算」需独立分支+档,且 CW app 已有恢复链——重复建设,收益低;EnterGame 遇 CW 形态有界失败不劣于现状。挂未知项,后续按需立项。

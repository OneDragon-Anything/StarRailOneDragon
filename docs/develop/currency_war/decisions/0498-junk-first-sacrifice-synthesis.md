# ADR-0498: 变宝为废·牺牲合成先行(装备合成排序器)

## 1. 背景与问题

投资环境词缀「变宝为废」效果(游戏内词缀原文实采,机制真值单一源 =
`data/affix_effects_data.AFFIX_EFFECTS['变宝为废']`):「每个位面开始时,
首次合成的进阶装备会有 50% 的概率变成垃圾袋」——粒度 = **每位面各一次**
(P1/P2/P3 的首次进阶合成各自承担 50% 垃圾化风险),产物 = 垃圾袋。

bot 侧现状:装备分配器(`cw_comps.equip_allocation`,M7 角色级分配)
的拖拽序决定合成事件序,但分配序对「哪次合成先发生」不敏感。变宝为废
环境下,若位面首次进阶合成落在高价值配对(例外①)上,垃圾化可能落在
最不该落的产物上。

> 勘误(2026-09-11,用户纠正):本 ADR 初版按「用户口述机制」建模
> (粒度=每局一次、概率未知挂账);机制实为游戏内写明效果、数据已在
> `affix_effects_data` 注册表——本版已按真值改写(每位面一次/50%/垃圾袋),
> 「缺数据挂账」框架作废。策略结构(排序器/牺牲对判据/推迟预算)不变,
> 推迟预算语义由「整局一次」改为「每位面一次」。

## 2. 决策

在装备合成决策排序层(非执行层)引入「牺牲合成先行」后处理:

1. **环境判据**:`state.enemy_affixes` 名单 contains「变宝为废」
   (`cw_junk_first.junk_first_env_active`)。读取链 = 简报词缀 ∪ 位面详情
   横条随采 → `session.briefing_affixes` → `state.enemy_affixes`;
   **读不到 = 无该环境,安全默认不启用**。
2. **牺牲排序(sacrifice_first)**:分配序列中存在牺牲对(非 core 角色的
   回收合格基础件配方对,P14 定理 3 判据——两件都不是任何目标进阶的
   组件,产物必然 ∉ key_equips,不碰主线凑件;一件可已穿于前帧)→
   该对的分配条目移到队首:拖拽序 = 合成事件序,牺牲合成先消耗**该位面**
   的垃圾化判定。
3. **推迟一帧(deferred)**:存在高价值合成计划(例外①完成点)但无牺牲对
   → 移除高价值合成的完成件(件留 owned,等死库存对到场),**每位面**
   推迟预算 1 帧(`JUNK_FIRST_DEFER_BUDGET`,依据:50% × 进阶件损失 ≫
   一帧推迟成本;预算只防死库存永不到场时无限推迟);预算耗尽后原样
   放行。位面消耗记账 = `session.junk_first_done_plane`(发射牺牲合成或
   发生推迟后记当前 `state.plane`;位面读不到 → 整局一次哨兵降级)。
4. **开关生命周期第 1 态**:`junk_first_sacrifice_enabled` 默认关(零漂移
   锚:关 = `equip_allocation` 基分配原样)。**开臂判据(挂账,本批拍定)**:
   ① 环境读取通道稳定——实机 ≥2 局含该词缀的局 `enemy_affixes` 均读到
   (零漏采);② 牺牲对识别可靠——实机 ≥2 次决策日志动作与画面合成事件
   对得上、误判 0。两钥匙齐 → A/B 后翻默认值。机制数据(每位面/50%/
   垃圾袋)已在注册表,不构成开臂阻塞。

## 3. 落点

- 新模块 `kernel/cw_junk_first.py`(纯函数排序器 + 包装入口
  `junk_first_allocation`:读 registry 开关 → 环境判据 → 后处理 →
  位面记账写 `session.junk_first_done_plane`,同位面推迟预算
  1 帧/位面;整局推迟计数字段已随粒度真值修正废止);
- 消费点 `operations/prep/equip_all.py` 决策调用行换包装函数(输入输出
  形态不变;W849 拖拽/验穿执行链零改动);
- sim 侧 `engine_p1` 继续直调 `equip_allocation`(基分配语义不变);
  变宝为废环境在 sim 尚未建模(出现率低,专用批待环境种子,挂账)。

## 4. Considered Options

- **A. 执行层拦截(equip_all 内判断先拖牺牲件)**:决策散落执行层,
  与 W849 治理后的执行链纠缠,不可单测——否决。
- **B. 分配器内改 equip_allocation 本体**:基分配语义被环境分支污染,
  sim 消费点连带受辖、哈希锁面扩大——否决(纯后处理隔离)。
- **C. 纯后处理排序器(采纳)**:决策排序单点、纯函数可锁、默认关
  零漂移;代价 = 排序只能重排/摘除分配条目,不能改变分配器容量决策
  (显式边界,非缺陷——「不碰主线凑件」判据本就要求不动主线分配)。

## 5. 挂账与边界

- **验证挂账(2026-09-11 用户指令暂停 pytest/cw_quick)**:真值修正后的
  锁组(test_cw_w861_junk_first 位面粒度版)、adr0293 普查、受影响装备
  测试、cw_quick 均待恢复后运行;初版(整局粒度)曾全绿,修正只动
  位面记账语义。恢复后验证清单见 REPORT。
- **残余边界**:排序器视野外的合成事件(如 C6 转移拖拽凑齐配方)会
  提前消耗位面判定而未被记账——代价仅为多保守一帧,不产生错误合成。
- **sim A/B**:变宝为废环境 sim 未建模(出现率低),专用批待环境种子;
  真值修正后 A/B 判据可引用 50% 概率直接算期望差,不需新假设。

## 1. 写入 AGENTS.local 的自主推进纪律(登记镜像)

> 自主推进节由通用模板生成(围栏固定文本+CW 纪律条);固定文本之外,CW 增补写入 AGENTS.local 的纪律行=下方代码块全文(整块照抄进指令文件的自主推进节)——**新增须用户逐条批准**;镜像与实际写入保持一致(改任何一侧时同步另一侧):

```markdown
- **实机判读与早停**:局终了 = 实机监控角色按「单局复盘协议」派复盘子 agent(协议=`sr-od-currency-war-dev` skill references/match-review.md;数据=对局档案 `--match <game_id>` 直读,产出落 `.debug/currency_war/deep_review/<game_id>.md`,候选修复项由编排者裁决立项进账本)——编排者只裁决与记档,不自己做复盘。**重大修复 commit 后=无条件早停在跑旧代码局重开**(素材价值趋零);通关门等早停条件=sentinel 脚本组事件触发;连续 3 局不同根因=停下做架构层反思,禁止逐局打补丁
- **改货币战争策略**(细则单一源=`sr-od-currency-war-dev` skill 的 references/strategy-work.md):
  - 修改任何策略前,一定先读玩法文档(玩法研究/证明集/设计文档;清单入口=strategy-work「改策略前」;策略命题权威=math_proofs 证明与 sim/实机实证,未证口述按待证假设对待)——没读就改=凭猜
  - 动手前必须明确本次修改是治本而非打补丁,说不清就是补丁,停下按根源两问走
  - 策略修复方案能用数学证明的尽量用数学证明——能算能证的一律优于拍死值(细则=strategy-work.md「决策规则数学先行」硬门)
  - 引入策略开关先过「策略开关的生命周期」门——唯一合法理由=行为输入未就绪+开臂判据挂账,禁悬置默认关(细则=strategy-work.md「策略开关的生命周期」节)
  - 旧测试锁拦路时先判锁再判改——**锁红≠改动错**,可能是锁钉着已被新设计取代的旧语义:先对照设计出处重推锁语义是否仍是当前意图,禁为保绿机械跟绿或回退好改动(判据与手法=strategy-work「锁的存在性纪律」)
- **模拟常开**:始终保持有子 agent 在跑模拟测试,找出货币战争策略的问题与优化方向(先阅读 sr-od-currency-war-dev skill 的 references/sim-testing.md「找问题」三步主线;一批交付即补派下一批)——不必等漫长的实机验证
- **实机运行时先武装哨兵**:起实机对局前,先把哨兵脚本三件跑起来(脚本=`sr-od-currency-war-dev` skill 的 scripts/ 目录;武装命令口径与重武三步入口=`sr-od-currency-war-dev` skill 的 references/runtime-ops.md「哨兵脚本组」节;报警怎么消费=`sr-od-currency-war-dev` skill 的 references/autonomous-loop.md §3)——不武装=对局卡死/断流没人报,烧几十分钟才发现
- **实机卡住=现场修复,禁手动续跑**:实机运行卡在游戏流程上(哨兵报卡死/节点重试不前进/画面死等)时,必须保住现场——**派一个专属子 agent 独占负责处置**(以卡住画面+日志+对局数据为证据定位根因、修复代码、重跑验证,全链一个子 agent 干完;排查走 od-dev-debug-automation;卡在陌生/未建档画面=先 od-dev-screen-onboarding 建档再改,别猜),编排者只控制互斥(同一实机现场同时至多一个处置子 agent);**处置子 agent 同样禁止手动操作游戏让流程继续**(代点卡点画面/代打/手动切到下一画面再交还 bot 接着跑)——手动绕过=把 bug 藏进「看起来跑通」,同一卡点必复发,该局验证价值也作废
- **不干等实机**:实机运行期间禁止干等,实机在跑 ≠ 无事可做——判读上一局、跑 sim 批、改下一版策略这些离线可做的事照常推进,按派发兜底提醒或账本 ready 派子 agent 并行工作
```

写入准则:动作判断本身完整写进指令文件,指针只作细则入口——不是拿一句「见某 skill」代替内容。

## 2. 定时任务增补角色:实机监控 + 模拟找问题

以通用角色集(构成与间隔见 od-dev-agent-autonomous-mode references/reminder-net.md「角色集」,单一源在那边)为基线建网,形态 A 提示词模板整块照抄同文件;CW 增补角色:

| 角色 | 间隔 | 类型 | 盯什么 |
|---|---|---|---|
| 实机监控 | ~20min,与通用角色错峰 | 两形态 | 只管实机:哨兵脚本存活、对局/空窗、局中卡死巡检、**局终提醒编排者派复盘**(单局复盘协议)、等待期不空转(见下两模板) |
| 模拟找问题 | ~50min,登记时刻与其它角色错开(防齐发) | 派 agent(两形态) | 模拟常开纪律的周期兜底:没有在飞 sim 批就派一个跑「找问题」三步主线(见下模板) |

### 触发形态选择(CW 叠加)

选择规则单一源=通用仓 od-dev-agent-autonomous-mode references/reminder-net.md「触发形态与选择规则」(按环境能力选形态,不在此复制)。CW 角色归属:

- **实机监控=两形态**:形态 A=编排者自执行巡检、局终派复盘子 agent;形态 B=到点直启子 agent 自己巡检,看到局终**只提醒编排者派复盘**(复盘派单权在编排者,符合发起权铁律)。哨兵与对局状态走命令与文件,两形态都可判;编排者的子 agent 状态清单只有形态 A 能看(在飞批活性归通用值守兜底,不受影响)。只启用其一;
- **派发兜底=两形态齐备,CW 零叠加**:形态 A 用通用「派发兜底」提醒模板、形态 B 用通用「派发兜底(直启)」任务书,均逐字照抄,不写 CW 领域版(「禁止以等实机为由不找活」封条的承载面=AGENTS.local「不干等实机」纪律行);
- **模拟找问题=两形态齐备**(模板见下):形态 A 的派单决策(额度/在飞判断)留编排者;形态 B 到点直启的就是 sim 找问题子 agent 本身(任务书自包含,判据单一源=sim-testing)。

### 实机监控

- **实机监控**(间隔 20min;逐字复制下方整块照抄):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【实机监控】当前任务:请按下述步骤严格执行。

1. 哨兵脚本还活着吗?——机械命令:`uv run python tools/cw/rewatch.py --verify N`(项目根执行,N=应岗件数,缺省两件传 2、三件传 3;**非零退出=有哨兵不在岗=报警**,立即按 runtime-ops「哨兵重武三步」补位,补位完成前声明接受降级监控),不凭印象答,以命令输出为证据
2. 在打局还是空窗?
3. 打局中,逐项巡检:
   - **画面巡检**:截图当前游戏画面并亲自看图——现在在哪个画面/节点、与日志及对局档案说的进度一致吗、有没有弹窗或异常界面挡着 bot 的路;陌生画面先把截图存档留证,按 od-dev-screen-onboarding 建档,别猜
   - **节点时长巡检**:本局对局档案最新一条记录距现在多久——超过 ~5 分钟没有新记录 = 当前位面节点可能异常(正常节点分钟级内该有新记录),结合画面判断是慢还是卡
   - **循环卡死巡检**:最近 ~10 分钟日志找循环特征——同一句警告反复刷、同一决策/动作反复出现、轮号/节点号不前进,任一命中 = 循环卡住,停局处理(停局=保现场,按「实机卡住=现场修复」纪律走)
4. 局终了 → **派一个子 agent 按「单局复盘协议」复盘本局**(后台异步,不占本监控回合;不自己 inline 做,不用旧的四问)。子 agent 开工令必含:
   - 执行协议 = sr-od-currency-war-dev skill references/match-review.md 全文(阶段 1 阅读理解 → 阶段 2 逐节点四步**每节点出结论** → 阶段 3 位面三问);
   - 数据入口:本局的对局档案(主 agent 已按局拆分;字段面见协议阶段 2);判读工具 = telemetry-reading「查询工具」节;
   - 产出 = 逐节点结论清单 + 位面三问总答 + 候选修复项,每条带轮号证据,异常条目带来源定位;**报告落盘** `.debug/currency_war/deep_review/<game_id>.md`(深评固定落点;子 agent 直接写文件;候选修复项由编排者裁决立项进账本)。

   结论回来由编排者(本监控)裁决与记档,裁决先**分诊**:**感知/运行时 bug**(识别误判/gate 误杀/死数据)→ 防线=fixture 帧锁+回放对拍+哨兵,别为此扩 sim;**策略行为病** → 治本修复,且修代码之外必须固化成 sim 检查项(先验形态在 sim 内可达,不可达走构造账本锁)或单帧锁——只修不复盘=再交学费;新检查须过守卫移除验证(临时去掉被检守卫重跑小批,违规必须涌现;全量基线 100% 命中=伪检查)。有异常 → 先确定异常来源,再找出治本的修复方案,然后将方案的实施状态记录到进度账本中合适的位置;同一个问题出现两次 → 必须走到治本方案这步,不许再当单局异常放下;单局结论不留。

每步结论必须带本轮工具输出的证据(哨兵存活=rewatch --verify 的输出行原文,画面=截图文件+所见一句话,节点时长=档案最新记录时间戳与差值,日志判读=引到的那几行,局终=结算数据摘录),拿不出当轮输出=没查过,不算数。汇报局中进展时,必须说这局的达成进度:打到第几轮、进的哪个阶段、阵容凑齐了多少、金的进出正不正常——不许拿血量充当进展(血量高低不等于打得好坏),血量只在跌破报警线以下才值得提一句。实机对局由 server 自动跑,不占用你的时间和子 agent 额度;且在跑的局用的代码在开局时已定型,等待期间做任何事(sim 批/下一版策略/文档)都不影响它在跑的结果。**「等实机跑完再说」永远是错的**:改下一版策略、跑 sim、审上局判读,都是现在就能做且该做的事。一切正常时一行结论,不写别的。(细则源=sr-od-currency-war-dev skill references/runtime-ops.md「哨兵脚本组」节)
```

### 实机监控·形态 B(定时直启子 agent;间隔 20min,与通用/模拟找问题错峰;任务标签示例「自主推进·实机监控(自动子agent)」)

任务书(建形态 B 任务时整块照抄;「你」=被直启的监控子 agent,编排者以第三人称出现):

```markdown
你是货币战争自主推进的「实机监控」子 agent。本任务书是你的完整指令;最终输出直接送达编排者,严格按【产出格式】写,不写寒暄。

【职责边界】你只管实机侧:哨兵存活核对、打局/空窗判定、局中巡检、局终提醒。你不复盘(复盘由编排者派子 agent 按 match-review.md 协议做)、不派活、不修复、不停局——发现卡死/异常只报告(现场处置由编排者另派专属子 agent,按「实机卡住=现场修复」纪律)。

【执行】
1. 哨兵存活:项目根执行 `uv run python tools/cw/rewatch.py --verify N`(N=应岗件数,缺省两件传 2、三件传 3)——非零退出=有哨兵不在岗,报告缺岗数
2. 打局还是空窗:以对局档案最新记录与日志判定
3. 打局中逐项巡检:①画面——截图当前游戏画面存档留证+一句话所见(陌生画面按 od-dev-screen-onboarding 建档,别猜);②节点时长——对局档案最新记录距现在超 ~5 分钟 = 节点异常嫌疑;③循环卡死——最近 ~10 分钟日志同一警告反复刷/同一决策反复出现/轮号节点号不前进,任一命中 = 卡死嫌疑

5. 循环卡死/哨兵缺岗/异常 → 只报告:证据(截图文件/日志行/档案时间戳/rewatch 输出行)+现状一句话;停局与现场修复由编排者另派专属处置子 agent

【产出格式】第一行固定为「【实机监控】打局中(第 X 轮/阶段 Y)」或「【实机监控】空窗」或「【实机监控】局终 <game_id>,请派复盘」或「【实机监控】异常:<一句话>」。局终时附结算数据摘录,供复盘子 agent 与编排者判读。汇报局中进展说达成进度(第几轮/阶段/阵容/金进出),不许拿血量充当进展。

【结论合格线】每步结论带当轮工具输出证据(rewatch 输出行/截图文件/档案时间戳/日志行),拿不出=没查过。一切正常时一行结论,不写别的。(判据与协议口径=sr-od-currency-war-dev skill references/runtime-ops.md、match-review.md、telemetry-reading.md)
```

形态 B 任务书(建形态 B 任务时整块照抄;间隔 50min,登记时刻与其它角色错开防齐发;任务标签示例「自主推进·模拟找问题(自动子agent)」,过用户可读自检):

### sim 批组织细则(承接 sim-testing 的批怎么组织;判据与做法=sim-testing「找问题」主线)

- **交付完整性 = 指纹 + 可运行的检查项**:问题较大的要留下回归——sim 批自己把检查项写进检查网(检查网可改,策略/sim 语义仓不可改);同类问题出现 ≥3 次 = 上升架构审查立案,不再点修。

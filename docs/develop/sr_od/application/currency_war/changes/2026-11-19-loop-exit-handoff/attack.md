# 设计对抗报告（第 1 轮 · 三核）

- 审对象：本目录 design.md + landing.md 草案（对抗审启动时版本）
- 核一（无前提攻击）/ 核二（规范遵循）/ 核三（治本核验）三路独立攻击，本报告汇总裁定
- 三核共同结论：§1 归层结论成立（三症状代码实证全对），架构方向（编排层交接、异常出口 success 化、route⑤ 原语化）经攻击后仍立，无结构性返工；但存在落地即破坏既有契约的阻断项与一批未申报后果面，修订后再进第 2 轮

术语约定（本批文档统一）：**交接** = loop 结束时把「该退出但还没退」的状态移交给 exit op 处置——loop 返回带标记的结束文本，app 编排层读取后调用 `CwEntryExit` 完成退局。

## 2. 阻断处置

### 2.1 A1：出口语义与检测载体分离（核三 A1 = 核一 A-1，同点交叉印证）

**发现**：loop 内一条把多个画面操作串成链的分支（投资环境链）靠「返回结果 = FAIL」判断节点失败计数已耗尽、提前结束不跑链尾。耗尽出口改成 success 后该判定恒不命中——链尾照常派发，早退语义静默失效；且既有测试锁着「FAIL + 链尾不空跑」，按字面同步测试会把「链尾空跑」这个回归锁进测试。

**修法（四件套，T-2 范围扩**）：
1. 耗尽点出口按模式分流（见 2.2）：app 主路径 `round_success(f'{交接前缀}{键}')`；
2. 链形分支早退判定改读交接前缀常量（`STATUS_HANDOFF_PREFIX = '异常退出交接:'`，cw_loop 模块级常量，与 app 判定共用单一源）——「链尾不空跑」语义保留；
3. 包装 docstring 的 FAIL 出口契约段、链首调用点注释同步重写；耗尽点 ERROR 日志行文案同步（核三 N6）；
4. 既有测试改断言：FAIL → success 且文本带前缀；「链尾不空跑」断言保留不删。

### 2.2 A2：委托清理模式参数（核一 A-2）

**发现**：route⑤ 委托 `CwLoop(stop_at_prep=True)` 构造的是新实例，节点失败计数从零重算；对 loop 分发表覆盖不了的吸附浮层，委托重放耗尽后同样返回交接成功文本，exit 误判「已清理完成」，残局遗留且 app 账面成功——静默失败，与 §2.3 申报矛盾。

**修法**：`CwLoop` 加构造参数 `cleanup_delegate: bool = False`（默认 False = app 主路径新语义；route⑤ 构造点显式传 True）。True 时耗尽点维持 `round_fail`（现状语义）——exit 节点重试承接，重试预算耗尽 exit fail → app fail，残局可见。

**残局面申报（写进 §2.4）**：委托清理覆盖 loop 分发表已知分支；分发表外画面（未建档浮层）委托耗尽 → exit fail → app fail，残局由下次启动预检兜底——显式接受，非静默。

**连带**：exit 侧「零改动」申报修正为「唯一改动 = route⑤ 构造点补一参」。

## 3. 修订采纳明细

### 3.1 交接节点两段式 + 三形态表修正（N2 + N5 + 载体点名）

- 交接节点改两段：**弹窗守卫段**（复用进局链守卫注册表 ENTRY_POPUP_GUARDS，覆盖局末自动弹的积分奖励/星琼详情/星徽详情等大厅态白名单弹窗）→ **exit 调用段**。
- 三形态表第 3 行「其余」改两形态并列：max_rounds 停备战（留局采样）、开局失败-中断（假局守卫，已在大厅且对局状态已清，无需退出动作）。
- 形态判定载体点名 = `self._previous_round_result.status`（框架每轮写入，operation.py:505）；节点间边匹配是文本全等、带动态后缀的文本不能走边，故 app 侧读上一轮结果对象。

### 3.2 sim 面申报全改（N1）

exit 识别链三处（进对局画面名识别等）均裸图像识别、无 sim 应答口改道；sim 现役直驱 loop 不经 app 编排链，交接节点在 sim 下不执行，断裂不发生——三行全改「不可达」申报，删「通」的错误结论。「sim 走 app 全链需先补 exit 识别 sim 改道口（后端答口已存在未接线）」立挂账待办。

### 3.3 幻影 run 申报 + 挂账（N4）

委托清理 loop 的运行记录重铸（幻影 run）与对局状态重建又拆除，本批申报为已知噪音；「委托清理 loop 不参与运行记录生命周期（构造开关跳过运行记录启动门控）」立挂账待办——涉及运行门控深水面（跳过后日志归属行为未实证），不并本批。假局守卫警告「开局阶段即回大厅」在委托态的误导性写入 loop 正本交接申报段。

### 3.4 未知画面兜底维持 fail（B1）

连续多轮画面全盲 → fail 维持现状。理由：exit 同为识别驱动，画面全盲时交接无从处置；残局走下次启动预检。§2.3 触发面收窄申报补此句——异常交接出口仅辖「节点失败计数耗尽且画面态可识别」面。

### 3.5 敌人信息浮层改口（M1）

「内联特判保留」改「保留至浮层画面 op 落地，清偿义务仍在挂账板 §二.9，非终态申报」；T-4 正本更新 entry-exit.md 时同句改写并留 §二.9 指针。

### 3.6 cw_match 清理口径统一（M2）

统一申报：**分层清理、app 兜底**。loop 正常收尾分支既有清理不动；假局守卫既有置 None 不动；app 交接节点在两交接形态 exit 返回后置 None（兜底清理点，幂等无害）。原稿「无需重复」与「防御性清」两说删，同此一句。

### 3.7 消费面补录（M3）

exit 现役生产消费点 = 三处：app 启动预检恢复链、回大世界链（back_to_normal_world_plus.py 第二处现役）、本批新增 app 交接节点。回大世界链本批不动，正本消费面清单如实补录。

### 3.8 结构修正（M4）

正本更新清单迁 landing.md（design 留一行指针）；阶段重排：T-1 app 交接节点 → T-2 loop 出口语义 → T-3 收尾核签 → T-4 正本更新+挂账板（正本更新末位）；landing.md 补章节序号。

### 3.9 挂账 ④ 销账拆两半（D6）

- 「局终收尾归属」半：收尾簿记是对局流程的终点账，归 loop 本职（用户模型推演）；
- 「分发回调簿记」（统一置战斗窗回调）半：是 loop 运行期管理的组成部分（所有战斗窗交回路径统一设置），同归 loop 本职。
- 销账时两半各自一句理由，不捆绑。

### 3.10 其余采纳项

- 出口文本常量面补第二常量 `STATUS_LOBBY_DONE = '对局结束,回大厅'`；max_rounds 不设常量（三形态判定是互补结构，前两形态不中即落「其余」，行为安全）——正本留一句「可升级为结构化 data 载体」备忘（核三提示 6）；
- T-2 补耗尽点 ERROR 日志行文案同步（核三 N6）；T-4 对 guards.md 该网出口语义段从「核对」升格为「重写」（语义从「停机显式化」变「停机转交接」）；
- §2.8 备选否决补全：loop 转退出模式自清理被「绝不点放弃并结算」红线结构性禁止（cw_entry_exit.py 退局范式节点守则），补进否决理由（核三提示 1）；
- route⑤ 正本补句「清理 = 处理到可交还态，期间按正常流程推进（含战斗），非瞬时放弃」（核三 Q2）；
- app 测试打桩先例点名 test_nameless_honor_app.py（核一 C-2）；loop 出口测试镜像位置 = test_cw_loop.py（核二 D5，不用 prep_special_flow 目录）；
- 黑话替换：新稿文本不用「接线/收口」等未定义词；代码位置引用用「文件 + 符号名」不用裸行号（行号随代码漂移）；
- §2.9「exit 侧零改动」改「唯一改动 = route⑤ 构造点一参」（A2 连带）。

## 5. 分歧与驳回记录

- **cw_match 口径（M2）**：核二建议统一为「不清」；本稿采「分层清理、app 兜底」。分歧理由：弃局后残留的对局状态只有内存与遥测归属污染两害（核三 N4 同证污染面），一行代码成本买干净收尾；「不清」省的复杂度有限。第 2 轮复核此点。
- **弹窗守卫位置（N2）**：核三给出守卫前置（①）/exit 补去向（②）/接受 app fail（③）三选；本稿采①——归层与 §2.2 一致（交接前置状态归 app 编排层），②违反 exit 侧最小改动，③把高频窗口留成已知坑。

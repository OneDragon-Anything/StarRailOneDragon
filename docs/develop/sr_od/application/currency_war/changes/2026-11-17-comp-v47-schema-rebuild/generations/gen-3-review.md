### 1.2 逐项证据与理由

#### 增量 1：计数口径四分派 —— 采纳（附一条出处精度修正）

**核实结果：属实，且比 gen-3 表述的更值得采纳。**

- 注册表 `cw_traits_data.py` 条目 `101102` 少女乐队 simple_desc 原文：「【少女乐队】进行独奏或全员大合奏：**仅在上场恰好1/4名【少女乐队】角色时激活羁绊**」。layers 只有 1（独奏）与 4（全员大合奏）两档——档位是恰好值不是下限，2/3 人无效、超员同样熄灭。这是 [图鉴] 级官方原文。
- v2 的三分派（TOTAL / STAR3 / 双龙吟尾注特例）确实漏了它：少女乐队 `count_mode='TOTAL'`，v2 按 count_mode 分派会把它当普通人数羁绊处理。
- 真实消费案例核实：G 篇 §5 希露瓦线（15 帖）原文——「4 少女乐队（知更鸟 r2/火花 r1/乱破 r3/希露瓦 r4）+5~7 持续伤害并存」「火花/乱破要**先捏在手上**（=买下备着不上场），希露瓦来之前只上知更鸟独奏，凑齐 4 人一起上」「乐队与 DOT 档位解耦，4 乐队不占 DOT 人数」。v2 口径下凑件表会推荐第 5 人上场直接熄灭羁绊——不是理论风险，是普通玩家真实路线上的必然错。
- 三处连带后果全部成立：V4 可行性改「点名人数**恰等**档位，多了少了都报错」（该羁绊无星徽可补——装备注册表 21 件星徽覆盖其余 10 阵营 + 11 流派，G 篇与注册表双向核实独缺云上五骁/少女乐队）；V10 凑件表禁含 EXACT 羁绊键；Q2 凑档推荐跳过。
- **出处精度修正**（并入融合案）：EXACT 不是从 `count_mode` 枚举派生的——注册表枚举注释只定义了 TOTAL/STAR3 两种，少女乐队的 count_mode 值仍为 'TOTAL'，EXACT 是对 simple_desc 文本的判读；文件尾注明说「召唤型激活特例……与 count_mode 接线同批归策略批，板面计数接线批须按羁绊特例处理」。因此四分派在库层的载体是一张**口径特例表**（TOTAL/STAR3 走枚举，EXACT/召唤复合走特例名单 + 出处指针），版本重跑时 diff 该表是前置检查；长期改进 = 注册表生成器批把 EXACT（及召唤复合）落进 count_mode 枚举，消掉判读层（记开放问题 N5）。

**裁决：改采。** 带子的三格方向正确、五个案例相容，比 v2 的「双强/悬殊」无数字状态（开放问题 N4）是实质进展；但它有一个未覆盖格（占比 <1/3 且帖量 ≥5），而 gen-3 自引的 E、B2 恰好都落在这个格子里——现行处置其实都出自结构判据与既有归并裁定（E 姬子/帕姆王立条靠 R11 结构裁定：姬子=同 build 变体走阶段合并、帕姆王「运营目标与瓦/姬线不连续，硬截止独立成段」；B2 的 9/7 帖峰沿用「只登主流峰」），带的数字没管住它们。修补后采纳（修补内容见 §3 修订 R2）：补第四格「占比 <1/3 且帖量 ≥5 → 默认挂起，有结构硬证据者列显式裁决点」；明确带只作用于「结构判为重构后是否立数据条目」，结构判型本身仍由 V8 判据先裁；占比 分母统一为类签名簇总帖量，逐裁决记录。

#### 增量 3：H1 黄泉双峰明确拆两条 —— 采纳

**核实结果：帖量与结构差异均属实。** H1 篇 §6：峰 A 永动锁轴流「约 20 篇：全 1 星、9-10 级高人口、装备极简（启动链+黄泉三件套）、单梦境转驱动」；峰 B 高练度输出流「约 15 篇：黄泉 3 星、6-7 件满配（杀红眼出现地）、速 8 D 牌；4梦4群/5梦4群 标准面」；分岔变量成文（奇缘持有度/梦境转有无/群攻档位）。两条的 need_star（{} vs 黄泉:3）与 equip_assign（极简三件 vs 6-7 件满配）差异是字段级的——塞一条目会让 need_star 语义含混，gen-3 的理由成立。双强过修补后的带（45%/34%）。裁决：**采纳为库预置结论**（峰 A「黄泉·永动锁轴」/峰 B「黄泉·高练度输出」，命名归落库批终审）。

#### 增量 4：Gate 评估时机修正 —— 改采（二分法采纳，「账号级」平断否决）

**核实结果：证据面冲突，gen-3 的平断过度主张。**

- A3 篇 §4（gen-3 引的是 §7 邻近内容）：「奇缘星魂：景元的**账号级**强化星魂（游戏内配置，plaza 数据源无注册表）」「账号有景元奇缘星魂（峰 A 前置）」——支持账号级。
- H1 篇 §7：「奇缘星魂=**局内道具**，使用效果不在任何官方数据源（T-6 道具盲区），待实机」——支持局内获得。B3 篇与 README 的「道具类盲区」清单（虚照/防火墙/优盘/金色复制器/奇缘星魂）同判。H4 篇措辞「**开局有**奇缘星魂→按 ★1 成型线走」只支持开局时点评估，不区分来源。
- 三篇判读两派对立，且全部挂着 [社区]/待实机标签——**机制本身未证实，谁也不能引为定论**。gen-3 只引 A3 一侧下「修正为账号级」的平断，不成立。

**裁决：改采。** 采纳 gen-3 的改进本体——Gate 语义按评估时机二分（账号级：每账号评估一次可缓存；局级：每局开局评估），这比 v2 把三类门槛时机混写清楚；但奇缘星魂的归类改为**保守归局级**，依据是安全超集论证：若实为账号级持有，局级评估照样在开局看到（不漏判）；若实为局内道具而按账号级缓存「无」，会把局内能拿到道具的账号永久错杀出局（误杀）。账号级归档 + 缓存优化等实机证实后再移。取证清单（开放问题 4）显式增补「奇缘星魂获取途径裁断（A3 账号级判读 vs H1 局内道具判读）」。

#### 增量 5：校验 V11 —— 采纳

**核实结果：可机器化、零误报。** v2 把「主 C 让位序全名单最小」写成了字段 5 的落库纪律文字，校验清单 V1-V10 无对应防线；gen-3 的 V11（逐阶段 min(core) ≤ min(support)）与该纪律等价（主 C 在 core 且取全名单最小 ⟺ core 最小值不超过 support 最小值），import 期可查。对五个示意草稿验算：A1（1≤1）、B4（1≤1）、D1（1≤2）、F（1≤1）、E（1≤1）全部通过，无误报。双 C 制豁免方式（core 内并列最小合法、core 首键=终盘主 C 需落库注明）一并成文。裁决：**采纳**。

## 3. 融合方案（v3 = v2 + 修订清单）

骨架不变：**17 字段（条目 3 + 阶段 8 + 过渡 2 + 库级 4）+ 3 构件（Cond/Gate/EquipPool）+ 两库分立 + 消费八问 + 三层归宿**，全部沿用 v2（current.md）的字段清单与语义，本节不重复罗列；以下修订项直接改写到 v2 对应位置。

### 修订清单（7 项）

**R1（改 v2 设计原则 4 + 校验 V4/V10 + 消费 Q2）——计数口径四分派。**
口径表：TOTAL=人数∪佩徽者（默认，27 条）/ STAR3=三星数∪佩徽三星者（唯千星商会，佩徽计数 [社区 待实机]）/ **EXACT=恰好值（唯少女乐队：恰好 1 或 4 人在场才激活，2/3 人无效、超员熄灭；出处 = simple_desc 原文「仅在上场恰好1/4名……激活羁绊」，非 count_mode 枚举值）**/ 召唤复合=双龙吟尾注特例（成员+后台召唤物，饮月 1 人即 2 档）。EXACT 连带三处：V4 该羁绊点名人数**恰等**档位（多 少都报错，无星徽可补）；V10 `FILLER_PRIORITY` 键禁含 EXACT 羁绊；Q2 凑档推荐跳过。真实案例 = G 希露瓦线（4 乐队 + 5-7 持续伤害，「火花/乱破先捏在手上凑齐 4 人一起上」）。实现载体 = 库模块口径特例表（TOTAL/STAR3 走 count_mode 枚举，EXACT/召唤复合走特例名单 + simple_desc/尾注出处指针）。

**R2（改 v2 设计原则 3 拆分判据段）——帖量带成文（修补版）。**
结构判据（V8）先行不变；帖量带只管「结构判为重构/独立形态后是否立数据条目」：

1. 双方簇内占比均 ≥ 1/3 → 都立条目（C 20/18、H1 20/15、A3 10/14）；
2. 一方占比 < 1/3 且帖量 < 5 → 主形态立条，其余 final_comps 篇内挂「待帖量增长立条」（D1 六壳、B2 列车 1/生存 3）；
3. 帖量 < 5 且占比 ≥ 1/3 → 显式裁决点，不静默挂起（B4 5:4）；
4. **【本轮补格】占比 < 1/3 且帖量 ≥ 5 → 默认挂起；有结构硬证据（档位目标不连续 / 名单实质减换且帖间一致）者列显式裁决点**（B2 幻月 9/千星 7 → 挂起；E 姬子 21（31%）/帕姆王 5（7%）→ 结构硬证据 + R11 既有裁定立条——既有归并裁定优先于带的默认值）。

占比分母统一 = 类签名簇总帖量，落库批逐裁决记录分母与判读理由；带是默认值，人判可偏离但须记录。

**R3（落库批预置结论）——H1 拆两条目。**
「黄泉·永动锁轴」（峰 A，20 帖：need_star={}、装备=启动链+黄泉三件套极简、单梦境转驱动）与「黄泉·高练度输出」（峰 B，15 帖：need_star={黄泉:3}、6-7 件满配、速 8 D 牌）各自立条；命名归落库批终审。

**R4（改 v2 构件 Gate 语义行）——评估时机二分 + 奇缘星魂保守归局级。**
Gate 语义补时机分类：账号级（`('命座',...)`：每账号评估一次，可缓存）/ 局级（`('菜单含',...)`、`('奇缘星魂',...)`：每局开局评估）。奇缘星魂归类依据 = 安全超集（账号级事实蕴含开局可见，反之不然；误归账号级缓存会错杀局内可得道具的局），证据冲突期（A3 判账号级 vs H1/B3 判局内道具，均待实机）保守取局级；实机证实账号级后移档并开缓存。

**R5（校验清单 V1-V10 → V1-V11）——新增 V11 让位序纪律。**
逐阶段 min(core 让位序) ≤ min(support 让位序)（主 C 全名单最小的机器化）；双 C 制 core 内并列最小合法，core 首键 = 终盘主 C 需落库注明（巡海任命派生取首键的约定）。

**R6（库级成文规则增补一条）——版本纪律。**
库数据随 final_comps 重建批次联动重跑（frontmatter `rebuilt` 对齐）；重跑前置检查 = 口径特例表 diff（EXACT/召唤复合/STAR3 名单与 simple_desc/尾注比对），防注册表文本变更引入新计数特例而字段值不报错（流程性防线，机器无防线）。

**R7（小项归并）——注记级。**
唯一装备派生集 = 8 件（4 普通 + 4 特权，注册表 effect「（唯一装备）」grep 派生）；星徽→羁绊映射不建表（装备注册表 effect 原文派生）写入派生优先清单；Gate 案例集补 A3 赌狗峰。

## 6. 六维度对比裁决

| 维度 | 裁决 | 依据 |
|---|---|---|
| 表达力 | **gen-3 胜（窄）** | EXACT 派生让 G 希露瓦线可被正确建模（v2 口径下该线凑件推荐必然出错）；H1 双峰落定为两条独立可执行条目 |
| 简洁性 | 平 | 同为 17 字段 + 3 构件；gen-3 多一条帖量带与 V11，但换掉的是 v2 更含混的「双强/悬殊」文字——净复杂度持平 |
| 普通玩家覆盖度 | **gen-3 胜** | 希露瓦线（15 帖）与 H1 峰 A（20 帖，全 1 星试用友好）都是「照攻略能抄」的普通玩家路线，v2 口径下前者建模即错、后者语义含混 |
| 机制一致性 | **互有胜负** | gen-3 对 EXACT 与注册表一致（[图鉴] 原文）、对奇缘星魂时机与证据面不一致（平断）；v2 漏 EXACT（与 simple_desc 不一致）、时机表述保守不错 |
| 可校验性 | **gen-3 胜** | V11 + V4 EXACT 恰等 + V10 禁键，三处新增全部机器可判 |
| 分层正确性 | 平 | 三层归宿（数据/策略运行时/文档层）两案同构；gen-3 术语表对分层边界的显式化略优，属表述层 |

**综合：gen-3 是严格改进案**——五项增量四项成立（三项采纳、两项修细节后改采），无一增量为倒退；v2 无 gen-3 未覆盖的独有优点（防漏过账 §2 全部落 v2 已有或等价）。

## 7. 收敛判断

**变化量：小。** 相对 v2：0 字段增删、0 类型变更；校验 +1（V11）、成文规则 +1（帖量带）+1（版本纪律）、口径表扩一格（EXACT）及三处连带、库预置拆条结论 1 项（H1）、Gate 时机语义补注。对比 v1→v2 轮（1 合并 + 1 换型 + 1 新常量 + 校验体系扩容），本轮分歧面进一步收窄，且全部落定为有事实源的可判定项。

**演化循环判断：已收敛，建议停轮。** 依据：①17 字段骨架经第三次独立生成（v2 融合 + gen-3 独立推导）逐字复现，独立变异的实质空间已耗尽——本轮五项增量全是判据细化与防线补强，无一是结构替代；②剩余开放问题（2/3/4/6/7/8/N1-N3/N5）全部是「实机取证后裁 / 策略层成稿后裁 / 落库批人判 / 注册表批次」门槛型，schema 结构层面无待决变量；③继续生成第四轮独立稿的期望增益低于成本。建议以本案（v3 = v2 + R1-R7）为终稿候选转正设计正文，进入落库批（写 COMP_LIBRARY/TRANSITION_LIBRARY 实数据 + V1-V11 校验落地）；后续结构变更由实跑问题驱动、走增量修订。

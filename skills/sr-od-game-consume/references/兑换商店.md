# 兑换商店(常驻商店·光锥呈现)——ExchangeShopBuyGoods

流光余晖兑换 4 星常驻光锥的操作路由。op 机制/入参/失败语义用 MCP
`describe_operation(op_id='ExchangeShopBuyGoods')` 查;本档只写路由与实机坑位,
不复制 op 内部机制。

## 1. 调用路由

| 步骤 | 用什么 |
|---|---|
| 导航 | MCP `goto_screen(target_screen_name='商店')`(大世界右上商店袋图标亦可;商店页不锁光标) |
| 切 tab | 通常不用——op 自带 tab 切换(内部走 ShopSwitchTabOp,until 选中态模板锚) |
| 购买 | MCP `run_operation(op_id='sr_od.application.cultivation.account.operations.shop_buy_goods.ExchangeShopBuyGoods', args={goods, count})` |
| 读结果 | run data:goods/tab/bought(实际购买数量)/unit_price/balance_left/monthly_left |

## 2. 光锥呈现 tab(light_cone_manifest)

- 4 星常驻光锥,**200 流光余晖/把,单次兑换上限 5 张**(弹窗横条「单次兑换上限
  5 张」)。流光余晖即俗称「余光」(忘却之庭/虚构叙事/末日幻影/历战余响产出)。
- 已注册商品:菇菇嘎嘎历险记(`goods='mushyshroomysadventures'`)。未注册商品 op 会
  拒绝——如实告知用户,勿尝试硬调。
- 典型请求口径:「给 X 角色补一把/叠一把某光锥」= 按 gap 换算 count(叠影需求
  张数),先报预计消耗(count × 200 流光余晖)并获用户同意后执行。

## 3. 实机坑位(2026-11-13 首跑实测,op 内已兜底)

- **弹窗中部布局随描述行数浮动**:光锥型(描述多命途限定+叠影说明两行)的滑条
  /价格行比月限型(余烬材料,左下月限胶囊)靠上 35px;两变体相对「兑换数量」
  标签的偏移一致(滑条 +24px/价格 +55px)——op 已按标签锚运行时推导控件位,
  **勿再为中部控件按固定矩形补建档**。
- **数量数字 OCR 噪声**:单个小数字全图 OCR 可读成 'a'/'O' 且 3x 裁剪兜底仍
  可能空;op 用价格整除反推数量与「+一击测单价」自举兜底,兜不住时诚实报
  「兑换数量读取失败」。
- **4★ 锥确认后先播全屏展示动画**:静止等待输入(不自动连播),右上角 ▶| 跳过;
  跳过后出获得物品弹窗(多件并列,「点击空白处关闭」)。op 后购收尾节点统一
  点右上角 (1875,68) 收敛,预算烧尽会带「购买可能已完成」+尽力余额显式失败
  ——此时先对账(读背包/叠影页确认到货)再决定是否重跑,勿盲目重复购买。

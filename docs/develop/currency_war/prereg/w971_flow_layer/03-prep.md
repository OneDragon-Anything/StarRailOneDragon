## 1. 稳定门退役


## 1.1 画面 op 生命周期五段(2026-09-02 用户定稿,全 op 同构)

**外循环是唯一循环**;备战决策环(内环)整体拆除——bail/同因计数/ping-pong 停机随内环消失(2026-09-02 实机事故定谳:遭遇 overlay 在内环 bail ping-pong 停机,单层循环下该机制整体不需要)。每个画面 op(备战/商店/overlay 全体)按同构五段运行:

```
① 数据观察 → 写 session
② 对账:本轮观察 vs session 历史/上轮期望(异常当场留证)
③ 决策:输出**一系列原子 op**(批)
④ 计算期望态:批内每个原子 op 执行后,画面应该变成什么样
⑤ 按序执行原子 op 批(各原子 op 自带结束判定):
     · 等待秒数(DD-011 形态①)
     · 等待特殊标记(期望态达成验证,DD-011 形态②)
  批执行完 → 交回外循环(重新识别画面:可能还是本画面=下一轮,可能流转)
```

- 备战决策环(prep_director 内环)拆除:其单轮逻辑(观察→decide_prep_screen→执行)提取为**备战单轮 op**,由外循环每轮调用。
- stall 防线平移外循环:连续 N 轮备战画面 session 字段无变化且决策空 → 留证(规格最小集见 §3 附注)。
- 概念归位:②对账 = 现役拖动对账网语义推广;④期望态 = W530/W209g 期望态机制推广;⑤两形态 = DD-011 amended。
PREP_SETTLE_S 3.0s 备战稳定门去除——**识别到什么画面,就进入对应的 op**。半开帧/延迟 overlay 的防护替身 = ①逐动作回流程层确认画面(W970 §4.3.1:overlay 弹出当步即见,转入 overlay op)②触发计算式追加等待(见 §3 原子 op 表 DeployMove 行)。比固定盲等更精确(门是按最长动画盲等;逐动作确认是每步实测)。

## 2. 干净备战 op

1-1 起每轮迭代的第一个 op:观察段 = 干净备战全量识别(20 项,见下清单)→ **逐项写 session**(黑板模式);决策段 = 调 `decide_prep_screen(session, config)` → 动作序列;执行段 = 逐动作派原子 op,逐动作回流程层确认画面。

| 区域 | 项(现役读法) |

| 备战席 | ⑬备战席身份 ⑭席满标志 |

## 3. 原子 op 清单 × 结束等待(DD-011 两形态 + 验证式)

| 原子 op | 动作 | 结束等待 | 依据 |
|---|---|---|---|
| DeployMove | 拖备战角色上阵/换位 | 固定 2.0s(羁绊徽章 #10)+ **触发计算式追加等待**:部署使触发型羁绊的**阶段变化**(计数跨激活档,档位表 = 注册表羁绊建模)→ 追加等待(overlay 弹出窗 #24,~2.5s 待校准);换位不触发;**触发清单(已确认):盛会之星、列车同行**(选人 overlay);其他待定。不做 overlay 识别,交回外层循环分发 | #10/#24 |
| SellDeployed / SellBench(备战侧腾席) | 拖到出售区 | 固定 1.0s(金币动画 #21) | #21 |

- **执行段语义**(对抗轮 1 P2 择一):决策输出**动作序列**,执行器按序执行;每动作后轻量锚快查(干扰检测,#24 族),命中 = **中止序列交回循环**(执行器只检测不处理,判定权在流程层)——「干净备战 op」= 观察+决策+序列执行的组合单元,序列执行完才交回。
- **流程层 stall 规格最小集**(对抗轮 1 P2 补,接替 defer_count 门与 PREP_SETTLE_S):对账字段族 = 球数/金/轮次/deployed 占用(session 可读);无变化判定窗 = 连续 N 轮(初值 3,校准)字段无变化且决策空序列 → 升级动作(round_wait 留证 → 超限停机);腾席链 d 留置臂(strategy.py:972 DeferSpheres)改空序列表达列入批 B 决策适配项。

- **点击消耗品(武装箱型)**:即 OpenBox 同族(点备战栏箱/消耗品 → 弹对应 overlay 交 handler)。
- **流程信号意图退役**(用户质疑成立):`DeferSpheres`/`BailToOuter` 不进词表——①`BailToOuter` 存在前提是旧「决策长环」;新架构流程层每步重识别分发,op 做完即交回,**交回是默认行为不是信号**;②`DeferSpheres` 的「故意不点球」= 序列不含点球动作即可,空序列合法;stall 判定归流程层基于 session 状态变化对账。两者随实现批删除。

三种等待复用全覆盖:固定时长(有口述值)/画面身份确认轮询(时长未知有独有锚)/验证式(结果可测)。RunDeploy/RunEquip 内部逐拖拽等待随其原子化批次整理。

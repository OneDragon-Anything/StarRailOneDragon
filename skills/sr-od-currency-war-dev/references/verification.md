# 验证工作台细则(sim / telemetry / 单帧锁 / 实机判读)

> SKILL.md §验证工作台 的展开。读者 = 智能体;本文全是操作判据,不是说明文档。

## sim 批量对照(反馈梯度第 2 层)

- 入口:`src/sr_od/application/currency_war/cw_sim.py`(`simulate_p1_batch(n, pool=...)` 或 CLI `uv run python -m sr_od.application.currency_war.cw_sim batch --n N --pool snapshot`);跑法 `PYTHONPATH=src` 下 uv 调用(项目 Python 一律 `uv run python`,不用裸 python)。
- **A/B 纪律**:改前跑基线 → 改后同参数再跑 → 对照分布再上实机。**基线与对照都显式 `pool='snapshot'`**(主仓提交快照:裸默认 `auto` 在无 replay 数据的环境直接 raise、在开发机随实机追加漂移——跨日对照必核两次运行的 `pool_fingerprint` 一致,不一致=不可比)。指标看:验收线达标占比 / `battle_losses_le_2`(战斗节点败场≤2 占比,胜利是策略质量真指标)/ 末态均值 / 方向建立率(r1-r4 建立方向的局占比)/ 刷新次数——最后一个常暴露「买了件就不刷」类金闲置回归。
- **差异必须解释**:改后指标变差不是「sim 不准」的免死金牌——要么定位机制(如围栏把刷新门挡了),要么声明该维度 sim 不可信的已知边界并给实机判读锚点补偿;两者都做不到 = 别上实机。
- **代理语义自检**:任何 sim 结论上实机前,核对该结论依赖的代理量与实机语义一致(曾因代理量与实机语义错位得出增益伪影——bench 计数不等于上阵人数)。新增 sim 观测口径时同步查遥测视图是否同构。

### sim 的诚实性分层(架构;深度挖掘的立足点)

- **真代码层**(与生产同源,结论可信):策略决策(`update_target`+`decide_prep` 直接跑)、发牌概率(`REFRESH_PROB` 实机 OCR 表)、有限牌池(27/27/9/9/9,买走减/卖回池)、角色注册表、XP 升级表、**板深条件化实机 Δ 池**({节点:深度桶:Δ} 经验分布重放;三态 `resolve_pool('auto|snapshot|fallback')`——进程内缓存,改快照文件后 `reset_resolved_cache()`)。
- **校准模拟层**(参数可注入覆盖,改进方向):开局 bench 构成/收入模型/战斗结算(方向二元模型 + Δ 池回退)/节点序列(25 帧众数表 + 变异位采样)。
- **代理近似(部分建模,消费前核语义)**:deploy 上阵语义——sim 维护 `st.deployed` 代理名单(bench 引擎件+阵营 count≥2,r361b/r375 对齐产线口径),非完整上阵模拟;板深=`_deployable_depth` 可部署口径(≠已部署事实,视图带 `*` 标)。
- **未建模(已知缺口)**:装备效果、星级、词条/boss 克制、P2/P3。

### 深度挖掘方向(当前只用了一小部分;按杠杆排序)

1. **遥测回放对拍**(sim↔实机互相校准;**正式工具已有**:`uv run python -m sr_od.application.currency_war.cw_replay [--run ID] [--diff] [--strategy line|default]`,ADR-0231):用真实局的关键帧 state 喂当前策略,对拍实机 actions——发现「同局面不同决策」的回归/漂移。**边界自持**:分歧≠好坏只=行为漂移;首发分歧 vs 级联分歧看首发点;低置信轮打 ⚠。改动后必跑一轮 diff(秒级)看影响面,比实机验证便宜三个数量级。反向用实机 Δ 分布持续喂校准层(池已在做,扩维度:节点类型×深度×**方向态**)。
2. **压力/边界态批量**:稀有态系统扫描(金 0-100×等级 3-9×板面形态网格)——单帧测试想不到的输入空间;连刷语义/金尽未升级/席满链等边界的行为锁。扫描脚本模板在 `cw_dev/rare_state_scan.py`(本地工具,gitignored——不存在则照本判据重建);**扫描发现的候选须回放对拍定性**(合成态死区可能在实机不触发——判读两步走:扫描找候选,对拍验真实)。
3. **经济对账**(⑤,r360 实战定型):sim 收入模型在真实局逐轮重放算账 vs 遥测 gold 差分——模型外收入/支出的指纹仪。**判读三律**:①残差归因前先推符号方向(漏收入→正/漏支出→负),符号不符的假设直接出局;②零花子集隔离法(spend=0+连胜0 的最净子集先钉死收入侧常数,再放开变量);③结论**先过对抗审查再信**(子代理攻击假说,一轮审查杀一个方向错的归因比多轮实验便宜)。已知修正:息基数=结算时点金(花后非备战帧);plan≠执行的 spend 偏差是噪声主体(根治=执行层 spend_ledger 记账,待实现)。工具链 `cw_dev/econ_reconcile_v0~v6.py`(本地工具,gitignored,缺则照三律重建)。
3. **策略 A/B 之外的第 3 用途——**参数敏感度**:同一策略扫参数(阈值/预算分配),看指标对参数的弹性——弹性大 = 该参数值得实机精调;弹性平坦 = 别花实机局数调它。
4. **校准层升级路径**(每一步都换真机制,Δ 池模式可复制):星级→Δ(遥测 star 字段已采)/装备分配质量→Δ(equips 已采)/词条→Δ 修正。升级一维 = 跑一次 sim vs 实机残差对比验证增益。
5. **种子化复现**:同 seed 同池指纹同局——正式入口 `uv run python -m sr_od.application.currency_war.cw_sim replay --seed N --pool snapshot [--expect-fingerprint FP]`(不符即拒);checks 报的 games 索引 + seed_base = 重放 seed。bug 报告带 seed+指纹,任何人可重放逐步看决策(配合单帧锁固化)。
- 判据:sim 能模拟到的维度**别拿实机试错**;sim 不能模拟的维度(散面 vs 集中方向相反的已知边界)以实机判读为准并记录偏差。

## 实机暴露问题的分诊与回灌(防「实机才发现」;sim↔实机闭环)

「很多问题实机才发现」时,先分诊再决定走哪条反馈线——两类问题的防线完全不同:

- **A 类 感知/运行时 bug**(识别误判、gate 误杀、import/作用域雷、生产链死数据):sim 不执行观测层与 op 框架,**永远测不出**;防线 = fixture 帧锁 + 回放对拍 + 哨兵。别为这类问题扩 sim。
- **B 类 策略行为病**(过程行为不合理:无方向清金、金滞留、破息窗买不满、伪档硬抗):sim **本可提前发现**——没发现的根源只有三种,排查时逐一对照:
  1. **过程不可观测**:sim 只评终态分布(末 HP/方向轮/刷新数),过程行为病在 sim 里天天发生,但没有判读视图可查——「找不合理指纹」只能查遥测、不能查 sim 局;
  2. **指纹未回灌**:实机病修完即止,指纹没固化成 sim 检查项 → 同类病重交学费;
  3. **校准层缺维度**:病的本质维度(如阵容质量:羁绊档位够但核心角色不在场)在 Δ 池没有键——按「遥测已采字段」优先补键(方向态/星级/装备)。

判据与纪律:

- **判读同构原则**:sim 局产出与遥测 jsonl 同构的三流账本(decisions/outcomes/shop_snapshots;ADR-0242),判读 CLI 直接查 sim 批次——`cw_telemetry query --sim-batch <名|latest> --view rounds|economy|supply|...`,实机判读的全部「找不合理」手法秒级扫几百局 sim。配套:Δ 池三态(`pool='auto|snapshot|fallback'`,缺源 raise 不静默;跨日基线对照须核 `pool_fingerprint` 一致)、单局重放 `cw_sim replay --seed N --pool snapshot`(bug 报告带 seed+指纹)。
- **回灌纪律(学费变现)**:每个实机定位的 B 类病,修代码**之外必须**固化:① sim 异常断言或判读视图检查项(分布级预警;进 `cw_sim_checks` 的 `_BATCH_CHECKS`,batch 默认内嵌——**先验证形态在 sim 内可达**,不可达的形态才走构造账本锁,别盲目内嵌空转);② 可单帧化的形态固化成单帧锁(回归级)。只修不复盘 = 下次同类病仍靠实机暴露(数十分钟/局)。
- **检查的非空转验证(变异探针)**:新检查报 0 违规 ≠ 检查有效——可能是被检守卫在 sim 内根本没触发(空转)。验证法:**临时去掉被检守卫(变异)重跑小批次,违规必须涌现**;违规词表与该守卫放行路径一致才算验证过(实战:冷启动检查基线 0 违规,去门后 44 笔 pair 涌现;但原始病形态 reason='off' 曾漏报——变异要覆盖「历史上真实发生过的失效形态」,不只当前代码路径)。
- **自检问句**:修完实机病后问「sim 要有什么检查项,才能在实机之前发现它」——答不上来 = 同构/回灌仍有缺口,把缺口本身记待办。
- **校准数据可复现性**:sim 结论依赖任何 gitignored 运行时数据(Δ 池/回放 jsonl)时,该数据必须**快照化 + 内容指纹随结果记录 + 缺源大声报错**——禁止 `except: pass` 静默回退空池(实测同 seed 有池/无池可让达标判定翻转:校准层静默缺失 = 固定 seed 与 CI 锁全是假信心)。裸 seed 不构成可重放承诺,重放 = seed + 池指纹。
- **sim↔生产遥测写入隔离**:sim 批量运行**绝不写生产 replay 目录**——校准池的数据源若混入 sim 产出,就形成「sim 校准 sim」的自中毒回路,池随每次跑批漂移。防线落在真风险点:**池快照生成器加源目录断言(≠ sim 目录)**,其次才是 sim 走独立落盘目录/不复用生产 recorder——禁令写在生成器上,不靠调用方自觉。

## telemetry 判读(反馈梯度第 3 层)

- 查询即判读,入口见 SKILL.md §判读;`--view hp` 看逐轮掉血×板深,`--view economy` 看金轨迹滞留轮,`--view supply` 对账「牌面 vs 买了什么」。
- **跨局对照表**是判读主力:把近 N 局的同维数据并列(逐轮 HP 轨迹/购买明细/板面构成),找共线与反例——单局归因是判读大忌(单局相关≠因果的教训在 design/ ADR 存档)。
- 判读锚点(实机第 5 层的前置):改动上线前写下「预测 X 会变」;局后核对。锚点没中 = 改动没生效或假设错,两者都要查。

## 单帧锁测试(反馈梯度第 4 层)

- 位置:`sr-od-test/test/sr_od/app/currency_war/test_cw_<主题>.py`;模式 = 构造 `GameState`(plane/round/gold/level/board/bench/shop/xp_progress)+ `StrategySession` → 调被测方法 → 断言动作序列。
- 模拟器批量跑出的异常情况(稀有态/边界态)**固化成单帧锁**才算回归资产——模拟是发现工具,不是回归工具。
- 断言写**语义**不写巧合:「配方 gap 时围栏内只买配方件」而非「买了卡 X」(换发牌就碎)。
- 依赖路径:测试仓 gitignored 独立维护,提交在测试仓;锁旧行为副作用的断言要随语义演进而改,改时在 docstring 记一句为什么旧语义过期。

## 实机验证(反馈梯度第 5 层)

- 验收以当期目标为准(进度树/goal 里有),不是固定数值;险胜不算过——贴线通过是策略缺陷症状,与明显失败同权重分析。
- 局中巡检看**轨迹**不只看卡死:中期掉血轨迹已注定不达验收线即早停(SKILL.md §实机运维),别陪跑到局终。
- 每局跑完的局后判读是**必做项**不是可选:异常条目当场定位;定位不了不准进下一局。

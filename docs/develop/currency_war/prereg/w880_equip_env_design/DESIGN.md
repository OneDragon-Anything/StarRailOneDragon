## 1. 族内效果机制精读(有文本依据)

「装备穿满族」= 效果落在**装备穿戴完备度**上的敌词缀。按 affix_effects_data 逐字,族内共 2 条未处理 + 2 条已处理的同域效果:

### 1.1 软弱无力(未处理)

> 真值:「没有穿戴3件装备的角色及其忆灵,造成的伤害为原伤害的80%.」

机制语义拆解:
- **判据是角色级穿满数(3 件)**,不是队伍持有量。后果:同样 6 件装备,「3+3 给两人」全员合规,「2+2+2 给三人」**三人全部吃 80% 罚**——分配的**集中度**本身成为决策变量,这是当前 `equip_allocation` 分配语义里不存在的轴(现有排序只回答「件给谁」,不回答「每人穿几件」);
- 「及其忆灵」:判据覆盖召唤物伤害路径,量级上对召唤流 comp 罚得更实,但这属 comp 评分面(见 §4.3),不改变穿戴侧语义;
- 对穿戴策略的**时序影响**:过渡期(r70 语义「穿给当前上场 5 人」)的散件分散穿法,在此环境下每轮战斗稳定吃 20% 罚——环境的边际代价把「均匀分配」系统性推向「凑 3 集中分配」。

### 1.2 额外打击(未处理)

> 真值:「我方队员每有1个空缺装备栏,受到敌人攻击后,额外受到本次攻击伤害8%的真实伤害。」

机制语义拆解:
- **判据是空栏数**,与软弱无力互为镜像(一个罚未穿满者的输出,一个罚有空栏者的承伤);
- 承伤侧:受击频率高的位(前排/嘲讽位)空栏最贵 → 穿满的**优先对象**与软弱无力(输出位)不同;
- 「本次攻击伤害 8%」是比例真伤,吃不到减伤,且与攻击力挂钩——对高攻敌(首领强化族在场叠加)罚更重。量化参考:一件空栏在一次攻击上多 8% 伤害,3 空栏 24%,量级与生锈滞留(+3% 伤/件)同域但直接上己方血线;
- 与库藏生锈的区别:生锈罚的是「owned 滞留不穿」(敌我双向),额外打击罚的是「穿得不满」(纯己方承伤)——两者共同把「穿戴覆盖率」从可选优化变成环境下的硬约束。

### 1.3 同域已处理两条(框架对照面)

| 效果 | 真值要点 | 现有处理 | 框架形态 |
|---|---|---|---|
| 库藏生锈 | 滞留装备每件敌 +3% 伤/−4% 承伤(≤10) | `equip_all._rust_release_active` hold 豁免(ADR-0461)+ registry 数据层 | **门**(修改 hold 过滤分支) |
| 变宝为废 | 每位面首次进阶合成 50% 变垃圾袋 | `kernel/cw_junk_first` 牺牲合成排序器(W861) | **排序器后处理**(重排/推迟) |

### 1.4 框架共性(本设计的立项根)

四条效果的共同结构 = **「基分配语义不变 → 读环境信号 → 做穿戴决策的变体修正」**:
1. 环境判据都是 `state.enemy_affixes` contains 词缀名(读取链:简报∪位面详情随采 → `session.briefing_affixes` → `state.enemy_affixes`;读不到 = 无环境,安全默认不启用——W861 已确立的保守降级语义);
2. 都不改 `equip_allocation` 基分配的固有语义(件给谁的 comp 意图),只在**门 / 序 / 量**三个接缝上做修正;
3. 都走 registry 开关 + 生命周期四态(W861/W875 范式)。

## 2. 框架合并设计:装备环境后处理管道(禁每环境各写一套)

### 2.1 现状盘点(合并的出发点)

当前四条效果的接入点分散在 equip_all 主流程的四处:
- 生锈:调用侧 `_rust_release_active(list(state.enemy_affixes), registry 开关)` → hold 过滤分支(equip_all.py:171/520/636);
- 变宝为废:`_junk_first_allocation(session, registry, comp, deployed, owned, occupied, enemy_affixes)` 内部**再判一次环境**(cw_junk_first.py:224)→ 排序后处理(equip_all.py:631);
- 软弱无力/额外打击:无(本批新增,若照旧例会各自再摸一次 `enemy_affixes` + 各写一段开关判定)。

问题:`enemy_affixes` 读取与开关判定在每个变体内部重复;第三个环境接入时会第四次散点。根在**环境信号读取没有单一源调用点**。

### 2.2 统一设计:`EquipEnvSignals` 单源读取 + 变体管道

**信号单源**(equip_all 调用侧一次读取,打包传递,变体函数不再各自摸 state):

```
@dataclass(frozen=True)
class EquipEnvSignals:
    enemy_affixes: frozenset[str]   # state.enemy_affixes(含简报∪随采,读不到=空集)
    plane: int | None               # state.plane(变宝为废位面记账用)
    round_num: int | None           # P1 开局 hold 窗口判定用
```

读取点唯一 = equip_all 决策调用处(现 :634 附近的 enemy_affixes 实参处);生锈豁免(:521)与 junk_first(:634)两处现有直读**迁到同一构造点**——纯接线重构,行为逐位不变。

**变体管道**(统一入口,替换现 `_junk_first_allocation` 直调):

```
apply_equip_env_variants(signals, registry, session, comp, deployed,
                         base_alloc, worn, owned, occupied)
    -> tuple[alloc', list[VariantTrace]]
```

变体按固定阶段注册,每阶段一类接缝,**每个变体 = 一个纯函数 + 一个 registry 开关**:

| 阶段 | 接缝 | 变体(现状/新增) | 开关 |
|---|---|---|---|
| ① 门 | hold/过滤条件修正 | 库藏生锈豁免(现状迁移) | `rust_wear_release_enabled` |
| ② 量 | 分配目标/填充追加 | **穿满向 fill-to-3(软弱无力+额外打击,合并立项)** | 新增 |
| ③ 序 | 序列重排/推迟 | 变宝为废牺牲合成(现状迁移) | `junk_first_sacrifice_enabled` |

- 阶段序的依据:门先裁掉不该穿的范围(生锈豁免放宽 hold),量再在范围内决定「穿满给谁」,序最后决定「先合成哪个」——序变体(junk_first)依赖 alloc 的合成事件语义,必须最后;
- 变体函数签名统一 `(signals, registry, session, comp, deployed, alloc, worn, owned, occupied) -> (alloc', action)`,action ∈ {inactive, <动作名>},统一打日志行 `[cw-equip] env-variant <名> action=...`(判读锚点,§4.3);
- 开关关 / 环境不在场 / session 缺失(离线旧栈)→ 该变体逐位原样返回,全关 = 基分配原样(零漂移锚,沿用 W861 锚语义);
- **禁**:变体内自查 registry 之外的任何全局;每个新环境不再新开调用点,只注册新变体。

### 2.3 合并判据(什么进管道、什么不进)

- 进:效果落在**穿戴决策**(门/量/序)的环境词缀;
- 不进:落在**评分/HP 模型/经济账**的环境(开局不利、区别对待族、成长的烦恼)——各自既有框架(cw_comps 评分、cw_effect_ledger、HP 模型),强行并入会造大杂烩;
- 判据一句话:**管道只修「这一帧把哪些件拖给谁、什么顺序」,其余归各自主框架。**

## 3. 逐效果处理方案

### 3.1 软弱无力 + 额外打击 → 合并为「穿满向 fill-to-3」变体(阶段②)

一个变体辖两条(环境词缀判据 = 任一在场即激活;两轴共同指向「提高单人穿满率」):

- **机制**:基分配产出后,统计各 deployed 角色当前穿件数(occupied 投影,同 `worn_basics_by_char` 手法);对 `< 3` 的角色,把本帧 alloc 中(或 owned 现有的)**非 key_equips 配方组件的散件**追加/改派给它,凑到 3 为止。
- **优先序**(额外打击轴的差异化):凑 3 的目标角色按「前排/预期承伤位优先」排(额外打击罚承伤),同位级下输出核心优先(软弱无力罚输出);判据用现有 `position_pref == 'front'` + comp core_chars,不引入新观测。
- **防护线**(防与攒件/合成冲突):
  1. 只动「非 key_equips 配方组件」的散件——key 凑件与主线凑件(RESERVED_COMPONENTS 主线对)不可挪,语义同 junk_first「不碰主线凑件」;
  2. 穿着件仍可被转移(C6 一次性拆卸成本已存在),故 fill 是**低风险**动作,但转移成本进日志留观测;
  3. 过渡期 hold 分支(非生锈豁免态)不激活 fill——hold 语义(攒给成型核心)优先级高于穿满向,防两套意图打架;生锈豁免 + 穿满同时在场 = 全量穿 + 凑 3,方向一致自然叠加。
- **参数**:穿满阈值 3 = 机制常量(真值「3件」),进 registry(如 `equip_fill_target=3`)供未来版本变更;无新增拍脑袋数值。
- **实现档位**:排序器后处理同档(纯函数,决策层,执行链 W849 拖拽/验穿零触碰)。

### 3.2 库藏生锈(已处理)→ 阶段① 归位迁移(纯接线)

- 方向:行为不变,把 `_rust_release_active` 的 contains 判定与 `enemy_affixes` 读取迁入 `EquipEnvSignals` 构造点与变体框架;
- 实现档位:**重构接线**(行为锁不变,`test_cw_w607` 族应全绿作为迁移正确性证据)。

### 3.3 变宝为废(已处理)→ 阶段③ 归位迁移(纯接线)

- 方向:同上,`junk_first_allocation` 内部的 `junk_first_env_active(enemy_affixes)` 改吃 signals;位面记账/推迟预算/牺牲对识别逻辑零改动(W861 真值语义原样);
- 实现档位:**重构接线**(其验证挂账四项,见 §4.2,恢复后照 W861 清单补跑)。

### 3.4 评分面后置项(本批不落码,挂账)

- 软弱无力/额外打击进 comp 评分需「装备依赖」tag 的 comp 携带面核查——W872 死映射防线确立「映射行须有 comp 携带 tag 才准入」;现 `AFFIX_MECHANIC_MAP` 仅变宝为废→装备依赖。挂账:comp 侧核查后按 W875 范式补映射行,禁先写映射。

### 3.5 方向汇总表

| 效果 | 方向 | 档位 | 本批动作 |
|---|---|---|---|
| 软弱无力 | 排序变体(fill-to-3,输出位向) | 决策层纯函数后处理 | 设计定案,待落码批 |
| 额外打击 | 同上合并(承伤位优先) | 同一变体共件 | 同上 |
| 库藏生锈 | 门(已有) | 接线迁移 | 行为不变重构 |
| 变宝为废 | 序(已有) | 接线迁移 | 行为不变重构 |

## 4. 开关与验证面

### 4.1 开关生命周期(合规设计)

- 新变体一个开关:`equip_env_fill3_enabled`,registry 字段,**默认关**(生命周期第 1 态);关 = fill 变体 inactive,基分配原样,零漂移锚;
- 开臂判据挂账(落码时写入 ADR):
  1. 环境通道:实机 ≥2 局含软弱无力/额外打击零漏采(state.enemy_affixes 命中,复用 W861 判据①);
  2. 行为对:fill 动作日志与画面穿戴事件对得上、误挪 key 凑件 0 次;
  3. sim A/B(同池配对)损血/出口指标正向 → 翻默认值 + 同步改写行为锁组(第 3 态义务);
- 验证不过 → 第 4 态清理(删码留 ADR),不悬置。

### 4.2 验证阶梯

1. **单帧锁**(sim 可测性核心):变体全是纯函数 → `sr-od-test/test/sr_od/app/currency_war/test_cw_w880_equip_env.py` 构造 GameState + deployed/occupied 直接调 `apply_equip_env_variants`,锁:全关零漂移/环境不在场 inactive/fill 只动非 key 散件/承伤位优先序/两条词缀任一激活/迁移后生锈与 junk_first 行为逐位不变(迁移回归锁)。锁引设计出处 = 本设计件 + ADR(落码时补号);
2. **迁移回归**:W607 生锈豁免锁组 + W861 挂账四项(真值版锁组/adr0293/受影响装备 8 文件/cw_quick L1)——迁移批必须全部复绿,绿即证接线重构无行为漂移;
3. **sim A/B**:落码后 `cw_sim batch` 同池对照(默认关 vs 开),指标 = 过程量(穿戴覆盖率:3 件角色占比/空栏总数)+ 验收量(hp/败轮);行为漂移首发点用 `cw_replay --diff`;
4. **实机锚点(事前写)**:含词缀局开跑前声明「预测变化 = fill 日志出现、空栏计数下降、损血下降」;跑完核对,没中 = 改动没生效或假设错,回查。

### 4.3 观测与判读面

- 每变体统一日志行 `[cw-equip] env-variant <名> action=<动作> <关键量>`,判读按行归因,不做隐式行为;
- 零穿戴哨兵(`_zero_wear_sentinel`)语义不变:fill 变体不开臂时哨兵基线不受扰;开臂后「owned 有可穿件却停手」的归因字符串需含 fill 推迟语义(防哨兵误报为故障);
- sim 注入面:enemy_affixes 已可注入(现有 GameState 字段),fill 变体不要求新增 sim 基建。

## 5. 结论

- 装备穿满族效果数:**4**(未处理 2:软弱无力/额外打击;已处理同域 2:库藏生锈/变宝为废);
- 框架方案一行:`EquipEnvSignals` 单源读环境 + 门/量/序三阶段变体管道,现有生锈(门)、变宝为废(序)行为不变迁移归位,软弱无力+额外打击合并为一个 fill-to-3 量变体(决策层纯函数,registry 开关默认关,生命周期四态);
- 逐效果方案见 §3,开关验证面见 §4;本批为纯设计件,未动任何生产代码与测试。

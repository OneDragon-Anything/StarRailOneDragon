## R70-1(中高)M6/r2/stockpile 的「金>50」阈值消费的是**息饱和线字面**,未随 cap_resolved 参数化——与 R8-4 自家裁决、P48 数学终态、canonical cap 枚举谓词三方不一致;resolved 变体局构成刷新面 fail-open 与义务侧价值损失

**位置**:
- `IMPL_DESIGN.md` §2.4 `r2_budget()` 行:「溢余段(>50)自由,g≤50 跨档需 V_gap 覆盖」;
- §2.5 辖域节:M6 存在性=「金>50 ∧ 无 S 目标」、stockpile 案①(金>50)/案②(金≤50)辖域分界;
- §3.1 M6 行:「M6 只动金>50 之上部分且留 S 预留([41] 推论)」;§3.4:「金>50 且无 S 目标必处置」;
- §2.10 第 7 条 cap 消费位 canonical 枚举表(无以上任何一行)。

**缺陷**:「金>50」的 50 不是独立裁定常数,它就是息饱和线 g*=10×cap_resolved 的默认局投影。证据链三重:
1. **注册表直调**:`cw_plane_table.GOLD_CAP_INTEREST=50`,注释「息封顶(10 金 1 息、5 档封顶)」——50 的机制身份=使息律满档的存量金下界;
2. **[41] 的语义**(P48 §2 直读引文):「利息在 50 已封顶,超额囤金无持币成本」——M6 溢余处置义务的全部理由系于「50 之上的金不生息」,该前提随 cap 移动;
3. **数学终态已参数化**:P48 §2 自己写明 `floor_resolved = 保息下限按 p47 A1 resolved 参数化——默认局 50(GOLD_CAP_INTEREST)、息律投资上调局 100(cap10)、开源节流局 90(cap9)、买断制局 0(息通道消解)`。P11/P13/P40/P46 的「溢余段=g−50 之上、d_eff=max(0,d−max(0,g−50))」全部是默认局书写形式。

设计件对**同一个 50** 已经做过一次完全同型的参数化并立为纪律——R8-4/L-R3-3(floor_eff 与 D 否决域的 50 均改 10×cap_resolved,登记 derived.py,并明确定性「硬编码 50 系默认 cap=5 特例,在 cap=9/10 变体局构成否决域漏报=fail-open」)。但 M6/r2/stockpile 辖域的 50 在 R3-R69 全链中从未被任何一批回扫:cap 参数化五连批(R61-1/R62/R63-1/R64-2/R65-3)扫了 streak、Δ息流̂、C_stay、C_int、N 账,全部落在「min(⌈·/10⌉,cap)/cap×轮数」形态族上;R65-3 自立的 canonical 枚举谓词=「比较式/上界式任一侧含 min(⌈·/10⌉,cap)/min(⌊·/10⌋,cap)/cap×轮数/cap 截断形态」——**「10×cap 的金位阈值字面」不匹配该谓词的任何分支**,机械扫描对这一族结构性失明(这正是 R65-3 自己诊断过的病根:「族定义由上轮攻击报告措辞反推」,本族是第五次漏一面的实例)。

**为什么错(逐变体推演,方向论证)**:
- **息律投资局(cap 5→10,饱和线 100)/开源节流局(cap=9,线 90)**:
  - r2/R1 面:字面「溢余段(>50)自由」把 50–90(–100)带的支出判为免 V_gap 覆盖的自由段,而该带真值息损 t≥1(每轮 1–5 金、跨档时按 L 递推为正)——付费刷新判据右端系统性偏松=**放行类 fail-open**,与 R1 门「V_gap🔴 前不付费刷新」的整条 fail-closed 链方向相反。P46 自己的「溢余穿透(54 花 8→46:t=1 物理息损为真,[17] 授权不覆盖)」在变体局整带成立而设计文本看不见。
  - M6 面:义务在 g∈(50,90) 帧即触发,把**仍在生息**的金转成压库卡(1★ 可退但有 fee=0 息差通道)——[41] 的授权前提(该带无息)在该带为假,义务侧价值损失 ≤(cap_t−5)金/轮量级 × R_剩,无任何账目承载;
  - stockpile 案①/②分界随金位错切,同卡在 50 两侧的辖域归类系统性错位。
- **买断制局(cap=0,饱和线=0)**:息恒 0 ⇒ 全部金都是溢余;字面「金>50」使 M6 对 g∈(0,50] 整段不触发(义务缺位,方向=漏动作)、r2 对跌破 50 的支出仍要求 V_gap 覆盖(过度保守)。R8-4 对 cap=0 字面 50 的定性原话——「无意义拖延……的语义错误」——逐字适用于 M6 的 50。
- **静态 import 修不好**:`GOLD_CAP_INTEREST=50` 是注册表静态常量,而 resolved cap 是投资购入后的**运行时覆写态**(R62-3:kernel 路径 cap 绝对覆写、win_mult 累乘)。实现者即便按 §2.10-1「禁字面量」import 该常量,变体局行为仍错——唯一正确形态=运行时 `10×cap_resolved`(与 floor_eff 的 R8-4 处置同款)。
- **默认局零漂移**(50=10×5 逐点还原),与 L-R3-3/R8-4 被立案时的形态完全同构。

**违反面**:公理 1/5(零调参/参数溯源——判据行为阈值以字面/静态常量存在,无审计归宿)、与 R8-4 自家裁决内部矛盾、与 P48 数学终态矛盾、R65-3 canonical 枚举谓词不完备(该族缺口)。

**修法方向**:①M6 存在性阈值、stockpile 案①②分界、r2 溢余段判据统一改 `g*=10×cap_resolved`(audit/derived.py,运行时 resolved 读数,R8-4 同款);②canonical 枚举谓词补第二族「10×cap 饱和线字面(金位阈值类)」并补登上述三消费位(此半边若按用户对「cap 消费参数化度量面」的宽读落入冻结族,可降级为冻结残余登记,但阈值参数化本体是主链行为判据,不随冻结);③§5.3 补一条变体局行为锚(升帽注入形态下 M6 触发金位随 cap 上移,字面 50 实现即红)。

**辖域备注**:R68 冻结残余第 7/8 项辖的是 §5.3 R6-8 行头与 §5.2 高侧预算两处「度量面」陈旧 cap;本项是 M6/r2/stockpile 的**行为判据**未参数化,对象不同,不与第 1-9 项重复。

## R70-3(低)C_stay① 资格谓词「旧线 ∧ 2★+ ∧ 不可卖」对 1★ 整类排除的隐含前提不真——边际>0 的滞留 1★ 件构成未定价的第五下偏通道

**位置**:登记表 R37-2 证明节步骤 1/2(「真滞留沉没的元素=窗口期内不可变现的旧线 **2★+** 件……fuel_sell 可卖的 1★ 不构成沉没」);R38-4 候选读规格。

**缺陷与论证**:排除 1★ 的依据是「fuel_sell 可卖」,但 fuel_sell 对象域=1★ ∧ 零重叠 ∧ **扩维边际≈0**(且 §2.2 行文含 bench 满语境)。切换线后仍部署在板上、作战边际>0 的旧线 1★ 件:边际门不过(fuel_sell 非候选)、窗口帧 line_switch_sell 首项=1 近闭(R31-2 连锁节自家申报)、凑息档序需凑息触发——三通道均可失效,该件在窗口内是真滞留,其沉没 κ=c(≤5 金/件)与板/bench 席位占用**不在 C_stay 任何科目**(①限 2★+、④board 席位冻结按 0 计入且申报的是「M1 部署被堵」叙事)。R40-5 把 C_stay 下偏通道穷举为「②③④ 0 计入」并挂了「③④实测 >①×β ⇒ 应急收紧」的机械触发——本通道是穷举外的第五条,同向下偏(换线门槛下偏=多换线,不可逆换线面 fail 方向)。R38-4 的候选读只把「候选-终未变现」子集交给 p_rec 期望形态承载,而 p_rec 承载范围又只在 Σκ 的 2★+ 集合内——1★ 非候选件两头落空。量级小(≤5 金/件、件数少),故立案为低。

**修法方向**:资格谓词的 2★+ 限定改「κ>0 件按候选读逐件判定」(1★ ∧ 非任何通道候选 ⇒ 入现算集合,κ=c),或至少在 R40-5 的下偏通道枚举补第五条并入「>①×β」机械触发条件。

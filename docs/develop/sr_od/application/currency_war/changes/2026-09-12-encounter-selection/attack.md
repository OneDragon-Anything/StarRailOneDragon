## 发现清单

### 中（1 项）

**M9-1｜D_enc 读值时点成分断言与代码事实不符：−4 修改器/连胜项不在该值内，Δ_t 语义双解未钉死**

- 位置：details §3 同源申报 :69（「D_win 与 D_enc 同为旗牌真值（含全成分、同读链）——无两侧口径差；−4 修改器等成分已含在真值内，无需显式建模」）+ 双值不等式段 :63（「D_enc(t) = 遭遇档 t 的节点难度」）+ 契约 3 :22；design §2.1 :42「同源零口径差」、§2.4 :64；README 机制事实 :18「含品质/连胜/特殊加成/−4 修改器全成分」；details §8 D_enc 行 :112「决策现读，不存」。
- 代码事实：①遭遇决策输入 = `board_state_of(session)`（cw_screen_encounter.py:284/:406，注释自注「overlay 时 board 不可读 → 用上次备战快照」）；②主循环 0 系覆盖层分发先于备战分支（cw_loop.py:1655-1663），遭遇节点在 bot 流程中**没有 prep_clean 观察帧**；③`enemy_difficulty` 仅 PHASE_PREP_CLEAN 相位读（cw_observation.py:1994-1998）→ 决策时该值 = **前一个普通战斗节点备战帧**的写入。
- 知识源事实：难度修改器（遭遇+首领节点 −4）只作用于遭遇/首领节点（economy.md:111）；伟大征服按当前连胜数加成、随每场战斗变（economy.md:107）。故「前一普战节点旗牌 + Δ_t」与「遭遇档 t 真实节点难度」之间恒差 ≈ +4（持伟大征服时另有连胜项变动，方向随前场胜负）；Δ_t 的【拟】值源 {0,10,20,30}（economy.md:107）是**原始档位加成**，不是「最近备战帧读值 → 遭遇档实际难度」的**净值**。
- 影响：D_enc 系统性高估 ≈4 → 比值 1.052^(D_win−D_enc) 低估 1.052⁴ ≈ 1.22 倍 → 可及性低估 = 保守向（fail-safe，不违开闸安全，不构成行为风险）。但：①同源申报「无需显式建模/无口径差」与契约 3「配对残差即可判」两处自相矛盾（前者断言零残差、后者预留残差定谳）；②若 E-3 按 Δ_t=原始档位加成语义配残差，−4 会被静默误归并进标定值，登记语义失真；③「含全成分」是承重断言（支撑「无需显式建模」），其前提（读值发生在遭遇节点帧）不成立。
- 修正方向：①同源申报拆两层如实写——D_win/D_enc 同为**普通战斗帧**旗牌（两值之间同口径零差）；「该值 → 遭遇节点实际难度」的换算含 −4 修改器与连胜项变动残差，并入 Δ_t 登记义务；②Δ_t 定义钉死为「决策时 BoardState.enemy_difficulty → 该遭遇档实际难度的**净值**（含 −4 与连胜项变动）」，{0,10,20,30} 改标「原始档位加成·仅作净值先验【拟】」，E-3 配对残差以净值语义定谳；③§8 D_enc 行「决策现读，不存」改「决策读 GameState 现存值（= 最近 prep_clean 帧写入；遭遇覆盖层帧无本节点现读）」。

## 一、新问题清单(严重度排序)

### F1(中)表驱动参考求值器的算子词表封闭性破缺——「四聚合型」封闭声明与自家实证的第五型算子共存矛盾,oracle 无可执行词表

**论断**:R92-1 把第三半边的判定机制钉死为「按分型表的算子规约(算子+哨兵约定+初值)机械驱动的最小参考求值器」,但分型登记的算子词表 canonical 定义仍是 R86-2① 的**四聚合型封闭集**(加法求和/取宽/概率补集合成/min 并宽,§2.12 分型登记载体行原文「分型登记内容=R86-2① 四聚合型」),R88-1/R90-1/R92-1 三批均未修订该封闭声明。而 R90-1/R92-1 的亲读实证已自证实现中存在词表外形态:
- `xp_buy_hp_cost` 系 `or` 聚合(cw_investments.py L616 亲读:`eff.xp_buy_hp_cost or e.xp_buy_hp_cost`),R90-1 原文自认「四型无一字面命中」;
- `interest_cap_override`/`win_reward_mult` 系「过滤谓词+后置作用」取宽(L623-630 亲读:`if e.interest_cap_override is not None: caps.append(...)` + 循环外 `replace(eff, interest_cap_override=max(caps))`;mult 侧还有 `!= 1.0` 过滤),R92-1 自己要求「算子规约须含『过滤谓词+后置作用』两要素」——该复合形态不在四型内;
- `gold_at_level` 族系常量映射语义(R90-1 自认「非 min/or」)。

**推理链**:oracle 是表驱动的 ⇒ 每个聚合型字段必须在词表内有可执行算子规约。`xp_buy_hp_cost` 是数值进账字段 ⇒ 正向断言①(消费集 ⊆ 登记∧各有定义聚合语义,R88-1)强制它登记。若登记为「取宽(max)」:R92-1 自家的区分力构造(双持 (6,8) → 实现取 6、取宽应得 8)令第三半边 oracle 与实现构造性红——设计件自家给出的 fixture 击穿自家词表的唯一候选登记;若无法登记:正向断言① 违例。两支都不可交付 ⇒ 词表封闭声明必须扩容,而 R92 批没有扩。这是落码批开工即死的规格缺口,且属于「R92-1 新面」本体(非冻结族)。

**修法建议**:分型登记载体行补算子词表扩容=四型 + 「or 首见者」+「过滤谓词+后置作用取宽」(复合算子形态)+ 常量映射(或划入不进 aggregate 断言型,与既有裁定对齐),登记=登记表 R92 对照表追加行;正向断言①的「有定义聚合语义」判据同步按新词表核读。

### F2(中)区分力 fixture「注册表外构造输入」无注入机制声明——参考求值器与生产实现的输入域不一致缺口

**论断**:R92-1② 要求每个聚合型字段的区分构造「须注册表外构造输入」(实证:xp_buy_hp_cost 注册表现状至多一策略持有,naive fixture 天然不区分),但 aggregate_economy 的公共输入域是**策略名列表**(`aggregate_economy(strategy_names: list[str])`,cw_investments.py L586 亲读),逐名经 `normalize_invest_name` + `INVESTMENT_STRATEGIES` 查表(L582),查不到返回默认 EconomyEffect 恒等元(L582-583)——**注册表外的构造效果值无法经名流入被测函数**。R92-1 未声明任何注入机制,三个候选各有未申报的代价:
1. 测试位 monkeypatch `INVESTMENT_STRATEGIES` 注册测试条目——可行,但未声明;且若测试条目绕开 normalize 键,normalize+miss→恒等元路径不被 fixture 覆盖(输入域一致性声明 R92 未含);
2. 重构 aggregate 签名收效果列表——生产代码变更,与 R92 批「零源码」文件面声明互斥,且改动公共 API 波及 cw_economy.py L118-120 消费链;
3. 测试内复制一份实现——被 R92-1「禁手写第二份聚合实现」明文封死。

**推理链**:落码批在三种机制间必须选一,而字面规格对三者同时「不禁止也不指定」⇒ 可交付「构造不出输入 → 区分力义务静默落空」或「绕开 normalize 路径构造 → 输入域与生产不一致 → oracle 断言对生产真实路径零检出力」的合规实现。这正是 R92-1 要封的「落码批可交付零检出力断言」病的机制层复活通道。

**修法建议**:R92-1② 补机制钉死=测试位 monkeypatch 注册表、测试条目按 normalize 键入册、构造集显式含一条经 miss 路径(未注册名)的恒等元用例;明文禁止重构生产签名;登记=登记表追加行。

### F3(中)R92-2「Σflat 消费时一次复核」的机制落点缺载——复核在离线判定者上机械不可执行,活体读数载体零声明

**论断**:R92-2① 把复核时点单义化为「Σflat 消费时(扣减式判定帧)一次复核,非 append 时」。但扣减式判定证据(R83-2)的判定者已被 R88-2 钉死=**落码后治理通道的批判读角色**(离线、事件触发节律),而复核载体自述为「策略回显/店面再读」(R92-2②)——这是**活体 OCR 读数**,其可行时点由 op 链画面可用性(回显面何时在屏)决定,不由离线判读时点决定。离线判读器在「判定帧」无法执行任何 OCR 读数;因此「消费时一次复核」按字面在现行判定者架构上机械不可执行。R92-2 未声明:活体第二读由哪个 handler/op 执行、何节律、写入哪个遥测字段、判读器如何消费该字段。这是 R73-5/R83-4/R88-2 三度封口的「行为规格有、载体无」同族病在 R92 新面上的复发(R88-2 封口句明文「禁复发」)。

**推理链**:规格无法照字面落码 ⇒ 落码批要么静默改语义(append 时复核,正是 R92-2 明文禁止的时点),要么悬空不实现(假名频度键恒 0=空窗未申报)——两支都是缺陷交付。

**修法建议**:载体钉死=持有集独立通道读数(回显面曝光帧 handler 或专设观察点)每备战期至多一次写入独立遥测键;「一次复核」重述为「判读器在判定帧恰消费一份独立通道读数、禁同事件边界内消费两份」;判读器缺席兜底按 R90-7 顺延纪律。sim 侧恒 0 空窗申报保持。

### F4(中低)R92-2③ 去污的反向残余(真持被误清)未申报——单向残余申报违 R42-3 双向分键先例

**论断**:R92-2③ 把复核不符条目的处置从「该帧不入 Σflat」扩为「自 active_strategies 清除并计假名频度」,辖域扩至全部消费面(held_strategy_fit 绑定/战力评估/换线判据持有态)。但复核通道与 append 读名**同 OCR 源**(R92-2② 亲口声明通道相关)⇒「真持有策略被复核误判不符而清除」的通道构造性非空;清除后该策略从经济/战力/换线全消费面消失,代价面大于原「只护触发器」形态。R92-2 只申报了假名漏报向的检出力上界(「独立通道误读率之积」级),**误清除向残余(方向、量级界、分键)零申报**。R42-3(窗口死亡监控双向分键)/R24-2(分键纪律)确立的双向申报先例被违。

**推理链**:清除语义改变了全消费面的输入集合 ⇒ 任何「清除正确」之外的分支都是新增行为面残余;残余只报一个方向 = 另一方向的暴露面无监督载体、判读时不可归因。

**修法建议**:补对称残余申报=误清除率 ≤ 复核读数误读率(同源相关须按 R92-2② 乘积口径修正)、独立分键(如 `flat_recheck_false_purge`)、量级界=被清条目数×其经济效果;超标回炉通道挂判停/回炉菜单。

### F5(中低)`s_line_cap_sup_unrealized` 键缺判定者/节律/输入存活形态声明——局终时点观测通道未钉死

**论断**:§5.2 新键行(R92-3)定义了联合计数公式(cap_sup_latched=真 ∧ 无升帽实名/批)与量级换算(50 金/受影响备战期帧 × 受影响帧数),但:①**判定者与节律未钉死**——同批 R88-2 为 `interest_overcap_check_closed` 钉死了批判读角色+事件触发节律,R90-7 补了判读者缺席顺延兜底,本键同族(触发→核查→计数)三件均无;②**输入存活形态未声明**——`cap_sup_latched` 是 R72-1 设计的 statefn 运行时不可逆锁存,现行代码零命中(grep 亲跑,src/sr_od/application/currency_war 全域);它到局终后判读通道的存活路径有两态:运行时键导出(需遥测字段声明)∨ 判读器离线从快照序列确定性重导出(可达性观测=投资池/店面快照现读、锁存谓词单调可重放——路径存在但未声明)。不声明则「局终联合计数」的输入在局终后的存活窗口无定义,键不可消费。

**推理链**:R73-5/R83-4/R88-2 封口纪律=观察键必须有载体+判定者+节律;本键有公式无量纲载体,是同族第四例(R92-3 自称「漏登封口同族纪律」却只封了「有键」这一层)。

**修法建议**:键行补三件=判定者(批判读角色)/节律(逐批判读或事件触发)/输入存活声明(推荐:离线重导出路径+重放确定性声明,或运行时锁存终态入 trace 末帧字段)。

### F6(中低)R92-6 治实例未治类——v6 门句对行 3/8/9/12 的同时序两读仍在

**论断**:R92-6 把行 15 从 v6 生效前置集排除,裁决理由②=「两读不消解则机械对账 reintroduce 人工裁量」,理由含断言「行 15 系清单**首条**『承载批在清单消费批之外』条目」。该断言不真:行 3(θ 标定批 ≤ p 开闸批时间戳)/行 8(η/θ ≤ p)/行 9(χ ≤ 换线判读锚批)/行 12(带宽标定批与 η 批同批时间戳一致)的落地判据全部是**未来标定批事件之间**的时序/同批约束——v6 声明时点若早于标定批,判据不可判,门句字面「任一行未落地 ⇒ v6 不得声明生效」同样阻死 v6 或引入人工裁量,与 R92-6 刚消解的行 15 两读同构。

### F7(低)R92-4 修码与 §5.2 sim 侧基线锚的口径耦合未申报——修码批落地即令 sim 侧三个基线锚跨口径失配

**论断**:R92-4 定谳 sim 收入侧 `interest_flat_per_node` 零建模为前置缺陷,修法=sim 利息行加 flat 分量(修码归落码批)。但 §5.2 `p2_sink_*` 三键的 sim 侧基线锚(D 桶 67.8%/死时金均值 107.7/支出收入比 0.464)全部系**染版 sim**(flat 缺失、含狸局金日程偏低 ≤2 金/轮)测得(R79-1/R81-4 口径),验收判据=B2 批死型占比相对该基线锚的下降。修码后 B2 批跑在修后 sim 上,锚跑在染版 sim 上——锚与被验批不同 sim 口径,死时金分布随 ≤2 金/轮收入上移整体位移,「相对基线锚下降」的判读被锚域断裂污染;R79-1 的「阈值与统计口径首批前预注册」未含「锚与修码批同口径」约束,R92-4 的影响面声明只覆盖了 A/B 差分与绝对指标染度,未覆盖锚复用。

**修法建议**:R92-4 影响面声明补一条=sim 侧基线锚的口径域声明(锚=染版口径;修码批落地后锚须同口径重测,或首批判读批声明在修码前完成、跨批则锚重测),登记=登记表 R92-4 行追加。

## 三、结论(含适用域限定)

R92 批六项修复的**登记与证明层面自洽**(引理对照表、打标不删史、双向断言结构均无内部矛盾),但**可执行性层面存在系统性缺口**:R92-1/R92-2/R92-3 三个新面均出现「行为规格钉死、机制载体悬空」的同族病(F1 词表/F2 注入机制/F3 复核落点/F5 键载体),其中 F1/F2/F3 任一不修,落码批对应断言位可合法交付零检出力或不可实现形态——恰是 R92-1 自己立项要封的病。F6 为 R92-6 裁决的类级残留,F4/F7 为残余申报的单向性缺口。

**适用域限定**:①本审查为设计件级(两文件+01 三节),全部代码证据限 `src/sr_od/application/currency_war/` 下 cw_investments.py/engine_p1.py/telemetry 索引的亲读行号,未运行 sim/实机;②F2/F3/F5 的修法建议均给出推荐案但最终裁决权在编排者(涉落码批任务书形态);③冻结边界按任务书裁定执行,本轮无边界模糊处需前置申报——七个新案全部位于明示攻击范围(①②③④⑥⑦ 面+残留交互)。

# 未达上限弹窗

**识别**：「可出战角色人数未达上限，是否确认出战？」+ 取消/确认。
**目标**：确认出战。
**能做的事**：
1. 点「确认」（实测 (1187,670)——2026-11-19 实机；建档「按钮-确认」，早期估算坐标 ≈1170,672 可作兜底，静态点击有效）。动作 op 不处理弹窗——弹窗确认是你的责任。
2. 「本局不再提示」勾选框（建档「勾选-本局不再提示」，约 912,589）：框架流程 op 处理本弹窗时会自动勾选再确认；玩家 skill 默认不代点（玩家偏好），勾不勾自行决定。
**坑**：「本局不再提示」勾选框不代点（玩家偏好）；区分另一相似弹窗「前台区域无角色，无法出战」= 还没部署任何角色，先买牌部署再出战。另：extras.bench_overflow=True（「备战席已满」红警横幅）时出战会被游戏直接忽略（无弹窗），必须先卖角色腾位。
**识别撞车（跨局复现，数据面无解）**：本弹窗在场时 `analyze_screen` 会被通用屏「战斗-退出确认弹窗」以 is_precise 抢命中。机理：两弹窗是同构游戏组件，「提示」标题与「确认」按钮同位同文（fixture 实测两帧「提示」同位），通用屏两锚按位置锚定（不依赖正文文案）在本弹窗帧上命中属画面事实；框架多屏命中裁决 = 遍历序 + 精准早停、多精准无裁决，通用屏在 loader 序中先于本屏恒先判先赢（精准命中回写 current 再强化 BFS 起点）。**修向「本屏建档 id_mark 增『未达上限』文本锚」已实测证伪（2026-11-20）：增锚不改变遍历序也不破坏通用屏 is_precise——运行时 analyze 仍被抢、test_id_mark 摘豁免即红，增锚已回滚**。人肉消歧口径不变：读到「战斗-退出确认弹窗」先看画面文本，出现「未达上限」即本弹窗，按本卡操作。根治归框架多精准裁决语义批（精准命中者间按锚特异性裁决或排除表机制），两屏建档数据面均无可行改动。

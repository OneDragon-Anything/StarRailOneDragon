# DD-018:商店牌费用徽章数字识别——cost 信源从 roster 查表翻转为画面直读,2星/3星直出缺口闭环

## Status
accepted(2026-09-02 修订:多位数支持 + 星级推算扩到 3★,见文末修订节)

## 背景
`read_shop_cards`(`sr_od/application/currency_war/obs/cw_observation.py`)的卡牌费用/星级从
roster 查表派生(SIFT 读名 → `cw_chars` 查 cost,star 恒 1)。机制上商店存在 **2星直出**
(同角色高星版本直接出现在商店,merge_mechanics §2.7 识别缺口登记):此类牌 SIFT 名字仍
读得对(肖像同画),但星级被按 1星 记 → 买价按 1星 费预算、合成计数错。用户确认
(2026-09-02):商店每张牌底部名字条右端有**金色费用徽章+白色单字数字**,徽章数字 =
该牌当前星级的实付费用(费用倍数体系 merge_mechanics §2.6:1★=原费、2★=×3)——
读画面数字即可同时得到费用与星级。

## 决策
1. **识别通道**:数字**模板匹配**(非 OCR)。选型依据:徽章字体固定、位置固定
   (screen_info「商店牌-N-费用」5 个 area,1080p 布局常量),白色字形可干净二值化
   (RGB 三通道最小值 ≥235,与蓝/绿/灰/紫各色卡条底零混淆);单字符 OCR 在小目标上
   det 天花板低(同屏小字失读先例见 `read_gold`/`read_level` 注),模板匹配是既有的
   更稳通道(同族:金星 `read_star`/升星预览 `read_merge_preview`)。
2. **模板资产**:数字 1-4 二值掩码模板,从存档开商店帧原 PNG 裁
   (`assets/template/currency_war/shop_cost/cost_digit_1..4.png`)。**数字 5 无样本**
   (5费档存档 13 帧未出现,基础概率 ~5%):读不到时走 roster 兜底——5费 1★ 仍读对
   (查表即真值),仅 5费 2星直出维持旧缺口,由金账对账兜底(§2.7 原免费探测器保留)。
3. **信源仲裁**(`resolve_cost_star`,纯函数):徽章 == roster 费 → 1★ 直读;
   徽章 == 3×roster 费 → **2星直出实锤**(star=2,cost=徽章值,`[cw!]` 留证);
   徽章失读/与两值均不符(如多位徽章「12」被单字模板误命中)→ roster 兜底。
   `ShopCard` 新增 `cost_source` 字段('badge'/'roster'/'roster_fallback'),
   金账对账可区分「画面直读」与「查表派生」。名字未识别但徽章可读的牌:费用信徽章
   (实付价真值),星级保守 1。
4. **坐标单一源**:徽章数字窗 = screen_info「货币战争-备战-开商店」屏
   「商店牌-1..5-费用」area(经 MCP upsert 建档;rect 自费用徽章金币圆右缘推导,
   13 帧跨局对拍位置逐帧一致)。

## Considered Options
- **维持 roster 查表 + 金账对账事后暴露**:2星直出的预算错误发生在**买前决策**
  (gold 是否够/值得买按 1星费算),事后对账不修决策,不取。
- **OCR 读徽章数字**:单字符小目标 det 失读先例多(见上),且需两级放大+二值化
  管线,复杂度高于固定字体模板匹配,不取。
- **读底部星排图标数**(§2.7 原设想):1星卡无星排,需「有/无」双态检测,且 2星
  图标与合成预览金星视觉相近;费用通道一次读取同时给出费用+星级,信息量更高,取。
- **模板 5 用渲染字体合成**:自造字形与游戏字体失配风险(conf 崩常见根因),等实机
  样本重裁,不取。

## 修订(2026-09-02,用户澄清费用体系后)
初版按「徽章单字数字、模板 1-5」实现;用户定稿费用倍数体系后修正:
1. **数字可两位**(6/9/12/15/18/27),识别改**两级管线**——一级字形分割+模板
   快路(数字 1-4 有样本,逐字形分类拼接,'1'+'2'→12),二级**黑字白底反转
   OCR** 慢路(覆盖 5-9 无样本字形与未采样的多位渲染);费用 area 加宽给
   多位数留窗(+60px,实拍右侧零白像素)。二级通道质量以已知单数字帧离线锁
   (40/40 与模板快路同真值)。
2. **星级推算 generalized**:读数 ÷ roster 原费,倍数 {1,3,9} → star 1/2/3;
   ×27=4★ 超 CW 3★ 星级域 → 兜底 + `[cw!]` 留证;非整数倍/倍数不在集 →
   按原费用记 1★ 兜底(用户定稿「识别不到这几个数字,就按原费用兜底」)。
3. **字段语义定稿**:`ShopCard.cost` = 读数(实付价真值——消费面 grep 实证:
   simulate 扣金 `card_cost`/buy_cards spend/arbiter 预算/economy 合成件费
   全按实付消费,而评分/概率侧本就直接读注册表 `ch.cost`,不受影响);
   `star` = 推算星级(复用既有字段);`cost_source` 区分信源。
4. 字段语义依据修订更新测试(倍数全集合 + 两位数 + ×27 兜底 + 慢路行为锁)。

## Consequences(修订后)
- 正面:2星/3星直出(倍数 3/9)买前即正确计价与记星;两位数与模板外数字由
  OCR 慢路覆盖,不依赖补模板;失读自动退旧行为,零回归面。
- 边界/失效:①多位数渲染无真样本(几何按 +60px 窗预留,渲染如与假设不符
  ——如徽章向左扩展——由慢路 OCR 兜,再不行落兜底留证);②×27 留证兜底是
  gameplay 异常信号;③阈值/白判据标定基线 = 13 帧 65 槽,版本改美术需重标定。
- 测试:`sr-od-test/test/sr_od/app/currency_war/test_cw_obs_chain.py`「商店牌费用
  徽章数字识别」节(倍数全集合/字形拼接多位数/fixture 真值/OCR 慢路行为锁/
  失读 fallback)。

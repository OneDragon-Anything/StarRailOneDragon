## 1. 节点域管什么

节点域回答「bot 现在打到第几个节点、是什么类型」。节点身份 = 节点序键
`node_ordinal = (plane−1)×9 + round_num`(基 1,跨位面连续 9→10;坐标系与效果账本
`advance_node` 同式)。类型(`node.kind`)是身份的载荷属性不入键;类型读法多源
(结算屏权威 > 台账现读 > 帧标签),也不入键防第二失真源。

## 2. 字段双层(单字段双值结构)

节点序是「同一事实的两个内容层」,**单字段双值结构**(迁移批修订·字段层次终极版;
符号=kernel/cw_game_state.py):

| 层 | 载体字段 | 写口 | 语义与纪律 |
|---|---|---|---|
| 观察层 | `top_bar_raw: Field[str]` | `observe()` | 备战帧顶栏**原文**(如「备战阶段 1-3」)如实上报,零计算;唯一写点=观察汇聚;原文缺读=不写,禁猜 |
| 逻辑层 | `node_ord: Field[int]` | `write_logic()`(渠道③ logic_hook) | 解析观察数据**算出的**序键;四条派生腿全部经 write_logic 写入,无 observe 写序键例外 |

配套载体:`node: Field[NodeKey]`(plane/round/kind 镜像与类型直定载体,顶栏权威链
遗产)、`node_hist_ord`(run 内已见最大生效序,见 §3)、画面上下文域
`prev_screen`/`current_screen`(两个独立事实的原始读数,非双值拆分;写点=观察汇聚
相位映射+开局链分支写点,未知禁猜不写)。

分层判例:备战腿「解析顶栏文本成序键」=派生计算,落逻辑层;观察层只存原文供事后
parse 对拍。节点域的**专用纠偏写点**已随「无 observe 写序键路径」退役;失配显影机制
**在位**——观察层与逻辑层值冲突时,经字段通用机制以 `observe_vs_logic_mismatch`
缺陷行显影(与 修正节、正本 §3.1.4、判定方案 R4 规则四③同源口径)。原文
事后 parse 对拍路径保留,不入 kernel 派生段。

## 3. 生效序读口与 hist 哨兵

- **生效序读口** `effective_node_ord()` = `max(node_ord 现值, node_hist_ord)`
  (派生计算,非存储字段;None 安全,双空=未定)。判定与比较域统一在该读口:
  字段现值=最近一次派生写入,hist=run 内高水位,两者之差仅存在于纠偏写序中间态。
  **读口定位 = 判定基准读口,非决策消费切换目标**(「node 逻辑态切换」工作项已作废——正本
  §3.1.4 现态申报;树上 docstring 残留修正归,原遥测设计件(已删,git 可溯) §3.7 申报行,
  v3.8-中-2 对齐)。
  > 术语注:逻辑态 = 动作执行后不经观察、按游戏规则推算并直写容器的预期状态;真值以下一帧观察为准(观察赢)。
- **hist 哨兵** `node_hist_ord`:跃迁去重键 `(run_id, effective_ord)` 的 run 内载体,
  每腿推进时占位(候选>hist 即越线推进,hist 置为候选)——同序恰一次推进由去重键
  保证;run 段随容器重基线。
- **消费面恒逻辑层**:序比较消费面取逻辑层现值/生效序读口;观察层是留证与对拍面,
  不参与序比较(决策读数现态 = `bs.node` 观察镜像合规现读,非逻辑层的逻辑态切换对象
  ——正本 §3.1.4 现态申报,v3.8-中-2 对齐)。

## 4. 守卫族

前驱守卫族 `SCREEN_CONTEXT_GUARD_PREV`(符号=kernel/cw_game_state.py)是弹窗腿的
判定输入,语义=「本节点备战帧未被分派过」的可操作判据。成员逐名清单与语义名属
判定本体,**单一源 = 场景一判定方案**(§5;判定方案 §3.3 规则四②逐名钉死;持久
裁定锚=迁移批修订·守卫族终版),本文不复写——守卫族成员清单的仓内书写面
收敛该单一处(双处书写=守卫族漂移根因,文档拆分裁定)。**0p(BOSS 简报)与
0q(位面过渡)出族**,理由=级联双推进:两者各有确定性专用腿(规则③/规则②)负责
自身推进,残留在族则专用腿推进后弹窗腿再 +1(守卫族缓存只是掩码,不是结构防线)。

## 1. 用户裁定登记(授权文号)

- **裁定内容(要点转述,原文以编排者登记为准)**:濒死绝对不是问题;无论什么 hp,金这么多都是要花的;不要搞错重点。

- **与宪法的对账**:宪法第一条(禁战力建模)不受影响——触发与分层全为结构/金账量;00 §3(hp 硬闸门)不受影响——本篇零 hp 消费;01 §8-2(发展优先默认)被本裁定**强化**:必花域内息线/停手族不得冻结消费(§3.4)。

## 2. 必花域形式化:G_must = 息帽金位(零新自由参数)

### 2.1 界的推导

```
必花域(帧) ⇔ g > G_must
G_must = 10 × interest_cap   【注】息账常量:每 10 金 1 息、息帽 5 档
                             (cw_state 息账族;P47 L 递推同一注册表基)
                             = 50(值在代码,文档只写常量名)
```

**为什么是息帽金位(零息边际论证,【推】)**:息 = ⌊g/10⌋ 且封顶 5 档 ⇒ g > 50 后**边际金的利息收益恒为 0**——必花域内持有金的边际收益恰为零,而任何期望收益非负的消费出口(§3 分层)严格优于持有。界取「边际收益归零点」是注册表结构给定的自然边界,非拟合值。

**s_reserve 倍数形态作废声明**:编排者令给的两个候选界 =「s_reserve 族 ∨ 其倍数」——倍数(如 2×s_reserve)引入自由乘数 k,撞零调参门(01 公理 1),**作废**;s_reserve 本身不可用作必花界:g > s_reserve 只说明「有可自由支配金」(17 号稿 B 支语义,观测条件),其上金仍在息帽内吃息、持有有正收益,不构成「必须花」。两界分工固定:**s_reserve = 可花(gate 观测面),G_must = 必花(义务面)**。

### 2.2 必花域的语义边界(防读偏)

1. **必花 ≠ 乱花**:义务是「域内至少一个合法出口发生消费」(§3.4 存在性义务),不是解除全部判据——各出口自身的资格门/硬闸(席位、垫件资格、围栏预检)照常辖;用户裁定授权的是「花」,负期望出口仍不选(分层内无在册正账的出口不因必花域解封,如实申报 §3.2-L3)。
2. **零 hp**:触发、分层、分键全链无 hp 项;hp 在本篇任何位置不出现(§1 裁定直接含义)。
3. **与 P21/P35 停手账的关系**:P35(lv9→10 特档摊还恒负)是**账面结论**不是授权文号——必花域内 L3 升级的授权文号 = 本条用户裁定(§1),P35 的摊还账作为该出口的**成本披露**随批报告,不作否决门(§3.2-L3);此为用户裁定层压过命题层的直接消费,如实登记供对抗轮攻击。

## 3. 旱期金出口分层(域内逐层尝试,至少一出口消费)

### 3.1 分层定义(触发 = 必花域;排序按在册账强度降序)

```
进入必花域(g > G_must)的帧,按序逐层尝试,任一层消费成功即止:

L1 既有授权面(现行判据直接消费,本篇零改动):
   线内件在售 → M2/臂①/M2b 照买;D_shop≠∅ → R1/R2 刷新门;
   EV 买/M6/dominance 各按现行门(U_X/T_search 标定开闸后自然激活)
   ——必花域不放宽任何 L1 门的资格语义,只保证它们被尝试且不被
   息线/停手族冻结(§3.4)

L2 non_line 补位买(17 号稿出口③扩触发源;两源并列,见 §4):
   触发 = 垫件/补位件在售 ∧ 资格单一源(fuel_sell_candidates 判据含
   P60 修法排除集)∧ bench_free ≥ 1 ∧ g−cost ≥ s_reserve ∧ 围栏预检
   放行(§7-N2/N3/N4 规格照用)
   ——Φ_stall 触发源下 = 出口③原样;必花域触发源下 = 同一消费位、
   第二触发源(∨ 合并口径同 17 号稿 §2.3 与 (b)2 的合并声明);
   差异仅在触发,判据/规格/分键完全共用,禁两套

L3 升级 XP(cap 扩位):
   授权文号 = 本条用户裁定(§1)——必花域内升级点级直接授权,
   U_L 式不作否决门(P35 摊还账作成本披露随批报告);
   硬闸照常:等级未到 cap、整批可负担、危机帧停付线?
   ——p1/p2_levelup_stop_hp 停付线是否让位于本裁定:涉 hp 族授权,
   本篇不裁,登记 §7.4(默认行为 = 停付线维持现行,即 L3 在停付帧
   不发射,由 L1/L2 兜底)

每层拒因独立分键(L1 不新增;L2 用 §7.4 七键;L3:level_cap/
batch_unaffordable/stop_hp_frame),零静默。
```

### 3.2 存在性义务与物理残量白名单

- **义务形态**:必花域帧上,分层走完若零消费 ⇒ 记 `must_spend_zero_consume` 分键(§6),**不作违规告警**——存在性义务的正确读法是「授权面全开 + 拒因全显影」,不是「强行制造消费动作」;但该分键计数入 sim 检查项(§6),持续非零 = 分层出口有结构性缺口,回炉分层设计。
- **物理残量白名单(预期恒定非零,不判失败)**:①店空且 bench 满(无买位);②等级已到 cap(XP 无处花,10 级顶);③金 < 全部出口最低单价(理论上必花域内罕见,登记防漏);④危机帧 L3 停付而 L1/L2 无对象(§3.2-L3 默认行为)。白名单帧带分键可观测,残量计数恒定即通过。

### 3.3 drought(供给干旱计数)怎么进入分层判据

- **定义(零新自由参数)**:drought streak = 连续 shop visit「无线内件在售」的结构计数;重置事件沿 ADR-0521 既有分键族(`shop_drought_reset_on_buy`/`..._on_churn_buy`)口径,新增 `..._on_line_member_seen`(店见线内件即重置)。
- **用途限定(防拍阈值)**:drought streak 在本篇**只作两用**——①**分键/观测维度**(必花域帧按 streak 分桶计数,给命题批与 sim 判读供给曲线);②**L1→L2 的排序信号**(streak ≥1 即允许 L2 尝试,不设 streak 阈值门)。**禁拍 streak 阈值**(如「streak≥3 才放宽」= 自由常数):若命题批证得干旱-购买期望账(弃购代价 [22]/P1 族的自然延伸)可支撑阈值,阈值由该命题给出;此前 streak=1 即入 L2(保守侧,早试不晚试)。
- 与 17 号稿 A 支的关系:Φ_stall 的 D=∅ 是「结构不可追」(refresh_prob=0),drought 是「统计不可得」(概率>0 但连续未现)——两信号正交,分层判据里 L2 不要求任一成立(垫件资格自足),streak 只作排序与观测。

## 5. 51 批「HP<40 放宽 pair」候选按裁定改写(零 hp)

- **原候选形态(作废)**:pair 选择在 hp<40 时放宽(以血量为放宽触发)——**作废依据 = 本条用户裁定**(消费/放宽授权与 hp 解耦,「濒死绝对不是问题」即否定以濒死为信号的设计方向;00 §3 红线下新 hp 直读点也无授权链)。
- **改写后判据(零 hp)**:pair 选择放宽 ⟺ **必花域 ∧ 供给干旱**:
  ```
  放宽 = g > G_must ∧ drought streak ≥ 1(§3.3,streak=1 即入,零阈值)
        ⇒ pair 候选选择从「严格 pair 最优成员」放宽为「允许买入 pair 的
        合格过渡成员/非首选成员」——放宽的是**选择域**,不是资格域
        (pair 成员资格判据、垫件资格单一源、硬闸全部照常)
  拒因/分键:pair 放宽帧打 `pair_relaxed_must_spend` 分键;放宽后仍
        未消费走常规拒因键
  ```
- 申报:放宽的收益侧 = 干旱期把金转成板面/备战结构改善(方向级,垫件/过渡件口径同 §3-L2);成本侧 = 非首选成员的机会成本(再遇窗口,[22] 方向),无点值——如实申报为方向级放宽,量化归命题批(若对抗轮要求)。

## 7. 红线自检与开放问题

### 7.1 宪法自检

①零 hp:全篇触发/分层/分键无 hp 项(裁定直接含义),00 §3 不受影响;②零战力建模:触发 = 金账结构量,分层出口全为在册资格判据,无强弱评分;③零新自由参数:G_must = 息帽金位【注】派生,s_reserve 倍数形态作废(§2.1),drought 零阈值(§3.3);④位面参数化:无位面字面量;⑤发展优先默认(01 §8-2):必花域 = 授权面全开,停手族不冻结消费——本裁定是该不变量的用户级强化,非违例。

### 7.2 与血线硬地板族的双计检查

血线硬地板 ≤15 族(00 §4 挂账:解锁包 = M3 破息批解锁 + 凑息禁令 + 转化优先)辖「血线触发的解锁」,本篇辖「金量级触发的义务」——触发面不同、出口面重叠(L3 升级)但授权文号不同(地板族 = 在册用户确认;本篇 = 新裁定)。**维持地板族原挂账不动**,两域并存不双计;若地板族确认批落地后发现出口语义重叠,由该批合并裁决(登记移交)。

### 7.3 14 号稿 §5.4 F1 授权文号变更候选(登记,不入本批范围)

F1(血线→支出反馈边)原合规路径 = 血线硬地板解锁包族;本裁定提供零 hp 路径后,F1 的死握病灶(金 86/82/66 持至死)可直接由必花域 L2/L3 承载——**F1 授权文号变更候选登记**(hp 路径 → 金量级路径),归 14 号稿 v5 并入批裁决;本批不改 14 号稿。

### 7.4 开放问题

①L3 与 p1/p2_levelup_stop_hp 停付线的关系(§3.2-L3:涉 hp 族授权,本篇不裁,默认停付线维持,登记候裁——若用户裁定意图含「停付线也让位」,需编排者向用户确认一句);②L3 的 U_L 核算挂账(授权已定,「何时升/升多少」核算形态归出口①命题批,合并处理);③drought streak 阈值命题(干旱-购买期望账,[22]/P1 族延伸)候选立项;④L1 层 EV 买/M6 标定开闸与本篇的发射序仲裁(17 号稿 §4.5 既有联动,并案不重立);⑤必花域与 sim 金通胀 4.07× 的交互:sim 侧必花域帧占比不可外推实机,验收只看行为形态计数(§6 锚)。

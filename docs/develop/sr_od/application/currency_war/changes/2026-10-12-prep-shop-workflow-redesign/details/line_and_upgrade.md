# 统一选线函数与升级判据（详设）

## 问题与约束

- 边界：本篇定义三件事——统一选线函数（方向状态唯一来源）、升级判据（概率主轴）、方向签名前置段。备战/商店两域对它们的调用时机见各自详设。
- 总纲契约引用：契约 B（方向状态读写接口）、契约 D（价值评估函数的统一口径归本篇 §3）。
- 现行被替代物：12 号篇换线机器全部组件（证据评估门、换线事件登记、回锁窗、塌缩卖出通道）——本篇函数落地时整体退役。

## 方案

### 1. 统一选线函数

用户裁定 2026-10-12：应有一个统一的函数计算应选哪个最终阵容，计算出新的（更好的）就更换目标；贯穿件是强信号之一（非一票定音）。

**1.1 函数形态**

```
f(局面状态) → 「未定型」 | 「目标线 X」
```

**1.2 每条候选线的评分（四维加权求和；权重形态见关键取舍）**

| 维度 | 内容 | 量化地基 |
|---|---|---|
| 完成度 | 该线下一成型档所需成员的持有比例（上阵+备战，按星级折算） | 阵容注册表分档表（`COMP_LIBRARY.form_tiers`，出处 = strategy-docs/10 §5）；完成目标态按下一成型档算（user_playstyle [37]） |
| 获取前景 | 缺的成员按当前等级刷新概率算补齐期望代价，缺得越便宜分越高；缺件此刻在商店牌面上可见 = 加分 | 期望刷新次数模型（`cw_shop_odds.expected_refreshes`，P40 数学件）；概率表 `REFRESH_PROB` |
| 专属资产 | 该线贯穿件在手上（强信号，大权重；user_playstyle [23] 与用户裁定 2026-10-12「强信号之一」）；该线关键装备已持有数 | 装备注册表 `key_equips` |
| 环境 | 投资策略/环境对该线的机制增益；boss 词缀克制 | 投资注册表（`cw_invest_data`）、词缀注册表；环境分化用机制知识不用热度数据（user_playstyle [38]） |

**1.3 输出裁决**

- 全部线分数低于定型门 → 「未定型」：两域按件级评估行动（买牌逐件评估、无目标名单概念；user_playstyle [36]），卖出资格门放全（只锁「现场证据明显服务的件」，即已过定型门前不产生「线内禁卖」约束——未定型期没有线内件）。
- 最高分线 ≥ 定型门 → 目标线 = 最高分线。
- **换目标判据（防摇摆核心）**：当前已有目标线 T，候选线 N ≠ T 更替的条件：
  ```
  score(N) > score(T) + 切换成本(T→N) + 滞后余量
  - 切换成本 = T 线专属持有资产的变现损失（2★/3★ 手续费、囤件再遇期权损失）
              + N 线缺件补齐的期望花费
  - 滞后余量 = 常量（防微弱优势触发换线；「四线摇摆全输」教训的制度化，
    出处 = user_playstyle [36] 注）
  ```
- 换目标生效时机：登记后下一备战期生效（沿用现行「换线登记不即时翻转」的节奏，防同帧反复）；旧线专属件进卖出候选池（按价值让位语义自然排出，无紧急清场动作——塌缩卖出通道废止）。
- 评估时机 = 方向签名变化（§3）；评估本身纯函数（读容器状态算分），无副作用。

**1.4 首次定型**

- 未定型 → 首次某线过定型门：直接锁定（无切换成本、无滞后余量——首次没有旧线资产）。此后适用 1.3 换目标判据。

### 2. 升级判据

用户裁定 2026-10-12：主轴 = 核心的刷新概率；一次性买齐，不只买一半。

**2.1 触发（两类并列）**

- **概率账（主判据）**：目标阵容（未定型期 = 各候选线加权后的期望缺件集）在当前等级 L 与 L+1 的补齐期望比较：升一级后「找到缺件的期望刷次下降量」折算的金价值 > 升级整级成本 + 期间息损 → 该升。量化地基 = `expected_refreshes`（P40）+ 概率表 + 升级门槛表（`XP_TO_NEXT_LEVEL`）+ 买经验单价（画面实读）。
- **人口位（并列）**：板上位置坐满 ∧ 有能进当前阵容羁绊体系的单位在备战席等待上场 → 升（战力当轮兑现；判定域 = 阵营相关单位不限星级，user_playstyle [33] 与其 2026-09-01 精确化）。人口位不受攒息约束（[12] 的明文例外）。

**2.2 支出形态：一次买齐**

- 满足触发且金 ≥ 整级成本 → 一次买齐到下一级的全部经验（批大小 = 门槛表差值折击数，现行 P48 整买引理形态保留）。
- 金不足整级 → 一击不买（等下节点收入；攒钱模式）。
- **血本位突变下的支付检查**（user_playstyle [40]②）：血余额 ≥ 下一级血成本才买经验，否则停。**修正现行缺陷**：现行实现「血够几击买几击」违反整买纪律（[41]），改为付不起整级一击不买。
- 升级执行位置两处：备战工序第 3 步（每轮全扫评估）；商店会话内（购买经验按钮能力面在役，实机帧确认）——会话内评估时机 = 每轮买入评估前（升级金优先于买牌金：等级决定概率档，先定概率档再花钱找牌）。

**2.3 删除的拦截层**

现行三层全部删除：调度守息门、支出预算闸（全段式账户比较）、危险顾问延迟（λ 顾问与血线解锁）。理由：主轴概率账本身含息损项（息损在账内，不需账外守息门）；HP 驱动的解锁违反 [39]；预算闸与整买的交互是「买一半」缺陷的伴生源。等级帽资格闸保留（注册表 `level_max`，机制硬闸）。

**2.4 与刷新判据的接口**

刷新判据（路径总账）消费本篇升级输出的 L* 选择：店内升级执行后，后续刷新提案按新等级概率求值（shop_session §2.4）。两处共用同一概率表与期望模型，禁第二份口径。

### 3. 方向签名前置段（契约 B 实现）

- 备战决策入口与商店决策入口各挂同一前置函数 `refresh_line_if_needed(gs)`：
  ```
  1. 拼证据签名 = 持有名单 + 装备持有 + 投资效果集 + 节点号
     （商店入口额外拼牌面 5 槽——用户裁定 2026-10-12：店里看到角色也要能更新方向）
  2. 签名 == 上次评估签名 → 直接返回现值（幂等跳过）
  3. 签名变化 → 调选线函数重算 → 更新方向状态与签名
     （换目标须过 §1.3 比较账；节点号变化时签名必变 = 节点边界重置的强制重算入口，
      见 prep_pipeline §3）
  ```
- 框架事实：策略器被动轮询无事件机制（用户指正 2026-10-12）——「信息到位就更新」以轮询 + 签名去重实现，语义等效且零新框架能力。
- 方向状态读接口：`line_members_view()` 返回当前方向下的目标名单视图（未定型 → 空名单 + 未定型旗标，两域据此走件级评估路径）。

### 4. 价值评估函数（契约 D 统一口径）

所有卖出场景的「手上牌价值」与本函数一致（单一口径，禁各场景自算）：

```
value(牌) = 线关系分 + 羁绊贡献分 + 合成进度分 + 星级费用分
- 线关系分：目标线名单成员 > 非成员（未定型期全按件级：与候选线集合的重叠计数）
- 羁绊贡献分：卖后当前板面羁绊掉档 = 负项（上阵位才有，备战席位天然零）
- 合成进度分：已有同名同星 2 张（差一张合成）显著 > 零散单张
- 星级费用分：2★ > 1★；高费 > 低费（再遇窗口查表折算持有期权——
  低费 7-15 轮自然回、5 费 60-180 轮，user_playstyle [22]③）
```

排序用途 = 候选评估器的让位序（价值低先让）；置换账用途 = 与店内新牌比较。分数各项的归一形态在实现批以纯函数落码，数值构造全部来自注册表与查表量，无自由拟合参数（定型门与滞后余量两个常量的产生方式见关键取舍）。

## 关键取舍

- **加权求和 vs 逐级字典序**：选加权求和。用户裁定贯穿件是「强信号之一」非一票定音，字典序把贯穿件钉死为最高优先级，与裁定冲突；加权求和下贯穿件是大权重项而非绝对项。代价 = 权重与定型门/滞后余量需要标定——按零调参宪法的显式模型路径处理：结构与量纲来自注册表查表（无自由拟合），标定批补置信区间；**标定完成前的缺省行为 = 定型门放最低 + 滞后余量取无穷（等效「首次锁线后不换」保守侧）**——缺省不摇摆（安全），标定后打开换线能力。定型门与滞后余量以【拟】形态登记，带 fail-closed 缺省与标定义务（strategy-work §1 数字三形态章程）。
- **换目标下一备战期生效 vs 即时生效**：选下一备战期。即时生效会让同帧内买牌判据与卖出资格集抖动；备战期边界是天然的决策一致性断点（现行换线登记同节奏）。
- **濒死破例升级不保留**：见 prep_pipeline 关键取舍同条；血本位支付检查保留（账户余额检查非质量信号，[40]②）。

# 终局线选择（候选-锁定制）与升级判据（详设）

## 问题与约束

- 边界：本篇定义三件事——终局线选择（候选管理与锁定规则，方向状态唯一来源）、升级判据（概率主轴）、锁定状态的载体。备战/商店两域对它们的调用时机见各自详设。
- 总纲契约引用：契约 B（方向状态读写接口）、契约 D（价值评估函数的统一口径归本篇 §4）。
- 现行被替代物：12 号篇换线机器全部组件——退役面逐项清单见 §1.6。
- 本版为用户裁定 2026-10-12（选线专题定稿对话）的候选-锁定制——替代本迭代早前的「统一加权评分函数 + 定型门 + 滞后余量」方案（该方案作废归档，git 历史可查；作废理由 = 加权评分需标定参数方可消费、购买力维偏置低费线、时间维难算不直观——用户裁定采纳候选管理 + 硬规则锁定的直观形态）。

## 与玩法口述正典的差分（对 user_playstyle 的语义替换申报；用户已确认）

本设计的方向语义与在册口述的差分，差分依据为用户裁定 2026-10-12（本迭代立项与选线专题定稿对话）：

- **对 [23]（终局线由贯穿件锁定）**：新方案的锁定条件（策略型/角色型，§1.4）即 [23]「拿到什么走什么线」的形式化与扩展——锁定信号从「单一贯穿件一票定音」扩展为「每线一条显式锁定条件（强关联策略 或 关键角色组合）」；贯穿件/CARRY 在手仍是角色型条件的构成主体。[23] 的「非 pivot」精神由 §1.5「锁定后不设主动换线」完整承载。
- **对 [36]（未定型期决策单位是件）**：保留 = 未锁定期决策单位为件（候选管理即件级买入加权，无方向级买入名单）；「不存在换线动作」与新方案一致（锁定后不换线）；修正 = 存在**首次锁定动作**（硬规则命中或时点兜底，一次性决策）。

## 方案

### 1. 终局线选择（候选-锁定制）

用户裁定 2026-10-12（选线专题定稿）：方向与板面执行分层——P1 板面恒过渡体系（等级人口压死终局羁绊的战力资源约束，与方向正交）；方向 = 全程线分数评估 + top3 候选管理 + 硬规则锁定；锁定后不设主动换线。

**1.1 机制形态**

```
f(局面状态) → 「未锁定（top3 候选在册）」 | 「锁定线 X」（一次性决策，锁后不换）
```

**1.2 线分数（两项 + 平分规则；零拟合参数）**

| 项 | 算法 | 数据源 |
|---|---|---|
| 持有证据 | 该线已有件计分：**CARRY 在手 = 大头、骨架件 = 次之、插件 = 小头**（三档序数分，非连续加权）；已有越多分越高——替换成本语义由此承载（囤得越多越不会换走） | `COMP_LIBRARY` 线库（CARRY/骨架/插件字段现成） |
| 环境分 | 投资策略/词条对该线的**明文机制加成**；强关联策略给高分（策略-线关联表） | 投资注册表（`cw_invest_data`）+ 策略-线关联表 |
| 平分裁定 | 按攻略热度定优先级（十类线帖子数降序）——[38] 修订版（用户裁定 2026-10-12） | 十类线帖子数（final_comps 在册） |

**不设项（用户裁定 2026-10-12）**：购买力项（按当前可购费用档打分会系统性偏置低费 CARRY 线——万敌 1 费早可买就早锁，但不代表最优）；时间预算项（期望等待 × 剩余节点的算式难算且不直观）。**商店货架不进线分数**——货架影响方向的通道 = 买入评估（候选件在售 → 买 → 变持有证据 → 下帧线分数上升），与 P77 零更新定理一致（差分节）。

- **贯穿件名单的注册表锚**：挂账新建 `COMP_LIBRARY` 每线 `key_items` 字段（贯穿件/骨架件名单单一源），建表任务归属 = 知识批（owner = 编排者，期限 = 本迭代落地 3.7 前；数据来源 = `final_comps/` 各线登记）。建表前持有证据分仅消费 CARRY 字段（骨架档缺省 0——fail 方向声明）。
- **策略-线关联表**：强关联策略 → 线的映射（概念股→对应线、黑塔纪元→黑塔线、圣杯契约→圣杯线等），数据源 = 投资注册表效果文本，知识批同批交付；建表前环境分仅消费通用加减（fail 方向 = 强关联分缺失，保守侧）。
- **未锁定期的升级概率账缺件集** = 候选 top3 线的缺件并集（用户裁定 2026-10-12：囤终局件是锁线准备）；此时无单一锁定线，概率账服务「候选集的补齐期望」。


**1.3 候选管理（未锁定期）**

- 每帧对全部线算分，**top 3 为候选**（用户裁定 2026-10-12：候选数量 = 3）；
- 候选变动：进榜线开始囤件；掉榜线已囤件**保留不再新增**（1★ 可全额退，不亏）；
- 囤积纪律：候选线成员照买照囤 + 全线路通用贯穿件（千冶·刃/三月七/花火/星期日，M3 早期核心层）恒囤 + **候选件没有而金有余时尽量买牌压库**（压库按费用档判据选，不限于候选线——用户裁定 2026-10-12 纠正「非候选的线不囤」：囤牌/压库有优先级，候选件优先，都没有时金有余照样买牌压库，[31]②/[34] 既有纪律）；
- P1 板面恒过渡体系（战力资源约束，与方向正交）；**过渡体系选与榜首候选重叠的**（转正不废件，transitions §5 角色重叠纪律）。

**1.4 锁定（双触发，先到先锁）**

| 触发 | 判据 | 时点 |
|---|---|---|
| **硬规则·策略型** | 该线强关联策略到手（策略-线关联表命中，如概念股/黑塔纪元/圣杯契约——策略定义线的形态） | 随时（含 P1） |
| **硬规则·角色型** | 该线关键角色组合到手——每线一条显式条件（CARRY + 核心骨架若干件），具体组合从线库数据逐条定义，**知识批交付**（owner = 编排者，期限 = 落地 3.7 前；建表前角色型锁定条件不可用 = fail 方向仅策略型可锁） | 随时（含 P1） |
| **时点兜底** | 位面 2 投资策略选定后仍无硬条件命中 → 锁定 top3 中分数最高者（平分按攻略热度） | P2 投资策略选定后的首个评估点（用户裁定 2026-10-12：时点定为 P2 投资策略后——策略分参与最后一次评估；**事件判定载体** = 投资策略三选一完成帧〔E1/E2/E15 通道在案〕） |

锁定效果：买牌、升级窗口（找谁的窗口）、装备定向、上场窗口全部围绕锁定线；装备合成材料开始定向留存。

**1.5 锁定后**

- **不设主动换线**（用户裁定 2026-10-12：自己玩都很少中途换——「搜不到→转线」类预案已被锁定前评估吸收：搜不到的线分数起不来，兜底锁定时自然不选它）；
- 唯一线内调整 = **星级 = 必要星级表驱动，无降档规则**（用户裁定 2026-10-12 刷新/升级专题）：每线每角色按攻略登记必要星级（COMP_LIBRARY `need_star` 字段，知识批交付——CARRY 按线攻略标 2★ 或 3★〔星级饥渴数据为源：千冶·刃 94%/万敌 90% 类标 3★，银狼 48%/DOT 52% 类标 2★〕，辅助标 1★）；**定义 3★ 就追到底**（目标未完成保持刷新，等级被动升高不改变判定，不考虑降档）；定义 2★ 的线 2★ 即完成。星级是刷新停留的自然积累（刷新判据 = shop_session §2.4 星级目标驱动），不是独立管理对象。

### 2. 升级判据

用户裁定 2026-10-12：主轴 = 核心的刷新概率；一次性买齐，不只买一半。

**2.1 触发（两类并列）**

- **概率账（主判据；fail 方向声明）**：目标缺件集在当前等级 L 与 L+1 的补齐期望比较。**未锁定期口径裁决（候选-锁定制下更新）**：锁定后概率账载体 = 锁定线缺件集（§1.2，明确可用）；**未锁定期**候选集求和为自认放大向（禁消费）——未锁定期概率主账不消费，升级触发仅剩 arm0（need > level 机制臂）+ 人口位 + 必花域-L3；锁定发生后概率账立即启用（无标定依赖——载体是锁定线缺件集，确定性查表）：升一级后「找到缺件的期望刷次下降量」折算的金价值（折算式 = 期望刷次下降量 × 单次刷价 c_eff，c_eff 画面实读）> 升级整级成本 + 期间息损 → 该升。期间息损 = P47 双轨迹递推 L 项（输入面 = 金/收入日程/剩余视界，与刷新账同源）；量化地基 = `expected_refreshes`（P40，data/cw_shop_odds.py）+ 概率表 + 升级门槛表（`XP_TO_NEXT_LEVEL`）+ 买经验单价（画面实读）。**双触发合并语义**：概率账与人口位同帧满足 → 单次授权并集发射（一次预授权，不重复）。**触发源并集**：arm0（need > level 升级不足，20 号稿 §3.5 在产臂）∨ 概率账 ∨ 人口位 ∨ 必花域-L3 触发源（20 号稿三源 ∨ 语义完整承继，含 arm0——域内 P21 让位与档位照 20 号稿）。**停留门（用户裁定 2026-10-12 刷新/升级专题）**：当前等级存在未完成的星级目标（必要星级表驱动，shop_session §2.4）→ **停留刷新、延迟升级**（即使金已攒够——「当前等级有值得刷新的内容就停留，没有就存钱一次性升级」）；人口位与 arm0 硬触发不受停留门辖（上阵人数硬需求优先于追星停留）；**优先级声明：停留门辖概率账**——星级目标未清空时概率账不触发升级（停留门在前，概率账仅在目标清空后参与「要不要升」）。**奖励帧抑制照旧**：reward_node_suppressed 闸照旧消费（抑制帧升级触发不发射，P80 候裁维持挂账申报）。
- **人口位（并列）**：板上位置坐满 ∧ 有能进当前阵容羁绊体系的单位在备战席等待上场 ∧ 该单位边际贡献 > 0（三元谓词完整保留，第三谓词出处 = strategy-docs/02 §3 M3 行与 P39 臂一——羁绊档已满的零贡献单位不触发）→ 升（战力当轮兑现；判定域 = 阵营相关单位不限星级，user_playstyle [33] 与其 2026-09-01 精确化）。人口位不受攒息约束（[12] 的明文例外）。

**2.2 支出形态：一次买齐**

- 满足触发且**攒批资金到位** → **整级预授权，一次买齐**到下一级的全部经验（批大小 = 门槛表差值折击数，现行 P48 整买引理形态保留；实付上界 = 授权批成本——执行形态见下行发射序列）。
- **攒批资金口径 = 裸金 + 非线内 1★ 活期卡退金**（备战席 1★ 全额退且非线内件按退金价计入——与升级变现场景资格面同源：常规面排除线内，卖自己人凑升级金不在语义内；user_playstyle [41]「把超 50 的钱换成压库卡……用时按卖回量最小化变现」的资产形态口径，与现行 P48 资产形态修正注同款）。
- **升级前变现步（跨帧两阶段，单动作契约逐动作发射）**：
  - **授权帧**：升级判据通过 → 置升级预授权键（含授权批成本/授权血成本上界）→ 进入**变现序列**：每帧一卖（评估器升级变现场景候选按序），直至缺口闭合或候选穷尽（中间态 = 键在 ∧ 缺口未闭合 ∧ 候选尚存 → 继续下一笔卖出，无其他域动作插入；候选穷尽 → 分支①）；
  - **执行帧**：缺口闭合后的下一动作 = 发购买经验整批（实付上界 = 授权值，**执行帧不再重闸**——防「买一半」复发的机制正是预授权跨帧携带）→ 清键。会话内变现序列与购买经验之间不插其他域动作（k > 1 笔时逐帧连续卖出，帧间无穿插）。**帧交错规则（整体视图）**：①备战域变现序列优先于第 7 步凑息（同池 1★ 全额退候选——**抑制条件 = 键在 ∧ 变现候选尚存**；变现穷尽后竞争消失、第 7 步凑息恢复——键保留至节点末不连带抑制凑息）；②「缺口闭合后的下一动作 = 发整批」归属 = 变现域序列内（不落第 4 步开店/会话内前置检查——序列内相邻性即其归属）。
  - **相邻性语义分域**：会话内（商店循环）严格相邻（卖 → 买，无穿插面）；备战域允许全扫回跳穿插**零金动作**（第 0-2/5/6 步均不花费，不影响预授权资金判断——穿插的买入动作在备战域不存在），预授权键保证穿插期间资金不被花掉。预授权键是唯一的跨帧授权状态（第 3 步「判据不过 = 零动作」指无预授权帧的常规评估；授权帧后由键驱动执行帧，血本位授权的实付上界同键承载）。**失效与异常分支**：① 变现不足（卖出候选穷尽后裸金仍不足整级差额）→ **键保留至本节点结束**、执行帧不发射——此后每帧幂等重评（判据过 → 键在；变现无候选 → 零动作），稳态无害；无抑制键——纯由判据与候选面决定，与「无试错计数」原则一致；② 变现候选被同 visit 排除/资格面排除尽 → 同①；③ 节点边界重置清键（prep_pipeline §3 清单——节点切换资金面全变，旧授权作废），**下一节点不跨节点兑现旧键**：资金面更新后判据重新过账则重新授权（新授权非旧键延续）。
- 攒批资金（含活期口径）不足整级 → 一击不买（攒钱模式，等节点收入；压库买入受整买预留约束不会吃掉攒批资金，shop_session §2.2 序 4；**②(b) 死金压库位次 = 序 4 内（现行「M3 后 M6/EV 前」明文位次继承）**；**预留口径 = 攒批资金含活期退金**——[41] 的压库卡形态即攒批资产本身（非预留的对立面）；1★ 压库卡净 0 变现不构成资金活锁（活锁堵的是净损失变现链：刷新/序 3/5 对高费活期的烧钱；**压库预留约束辖 2★+/非活期标的，1★ 活期卡不受限**——与 shop_session §2.2 序 4 同口径））。
- **血本位突变下的支付检查**（user_playstyle [40]②）：血余额 ≥ 下一级血成本才发整级授权，否则零购买。**现状缺陷修正申报**：现行部分购买的真实机理 = 逐帧单击发射形态 × 静态全量阈值逐帧重闸（血支付中血量跌回阈值之下即停止发射，留下部分级；`blood_xp_gate` 本体为全量击数口径，非截断源）——修法 = 整级预授权 + 实付上界（授权血成本），发射粒度整批化后闸本体语义不变（landing §3.4 同步消歧 as-built 表述）。
- **血本位局的资金口径分域（跨币种定义）**：血本位局（XP 以血支付）的攒批/变现语义换轨——金攒批与变现步不适用（变现卖出对血支付零贡献）；血本位「整级预授权」 = **血余额上界授权**（实付上界 = 授权血成本），发射条件 = 血余额 ≥ 整级血成本（无变现步；攒钱模式 = 等节点血收入）；「买一半」修法在血本位局同款生效 = 整批发射 + 实付上界（血余额为静态阈值，无逐帧重闸复发面）。
- 升级执行位置两处：备战工序第 3 步（每轮全扫评估）；商店会话内（购买经验按钮能力面在役，实机帧确认；前置 = 执行链接线批）——会话内评估时机 = 每轮买入评估前（§2.2 前置升级检查，shop_session）。


- 框架事实（as-built 修正）：现行已有**帧代次双槽**（`gs.frame_class_prep`/`frame_class_shop` + `_refresh_direction` 换向侦测）——「信息到位就更新」的收编形态 = 帧代次槽写点保留（operations 侧）、读侧逐步切方向 view（`_refresh_direction` 随意向层退役归 3.7）；3.3-3.7 过渡期双轨并行：写点不动、读侧分批切换（无协调缺口）。签名去重语义等效保留。

### 4. 价值评估函数（契约 D 统一口径）

所有卖出场景的「手上牌价值」与本函数一致（单一口径，禁各场景自算）。**量纲统一为金当量**（经济期望是统一标尺，user_playstyle [22]④），可直接参与置换账比较：

```
value(牌) = 变现价 + 再遇期权 + 合成进度   （金当量项）
           ⊕ 羁绊贡献                      （排序规则项，不折金）
- 变现价   = sell_refund(牌)（注册表现读；1★ 全额退、2★×3、3★×9，cost≥2 减 1）
- 再遇期权 = 再遇窗口折算金当量：reencounter_window_frames(等级, 费用档, 已持有数)——候选的费用档 = 注册表 cost 现读、已持有数 = 同名同星持有计数现读
             （参数序照代码；查表单一源 = data/cw_shop_odds.py 的 reencounter_window_frames，
             11 §6.7 P77 行）× 每轮息损（= 每息档边际率 1 金/轮【注·息档粒度定义值】；
             真值上限 = cap 金/轮【注·默认局 5、息律局 10，随 cap 查表】，消费口径 = 边际率）
- 合成进度 = 已有同名同星 2 张（差一张合成）→ 按该成员完成档的再遇期权 ×2 计
             （差一张 = 两张的再遇期权沉淀；×2 为结构近似系数【拟·owner = 编排者、期限 = 一个对局周期；**fail-closed 形态 = 标定对照完成前以 ×1 线性运行**——不放大持有期权 = 保守侧，标定后切 ×2】）；
             零散单张 = 自身再遇期权。
             未定型期「完成档」缺省 = 该成员自身下一星档（2★ 目标 k=3），
             无目标线依赖
- 羁绊贡献 = 排序规则项（非金当量）：卖后当前板面羁绊掉档的牌在让位序中排
   在全部不掉档牌之后（上阵位才有此代价，备战席位天然不掉档）。
   不折算金当量的原因：每档羁绊的金当量数值依赖 math_proofs P3，该命题
   已标「作废」状态（索引在案），禁引其数值。**处理取向（用户意向
   2026-10-12：失效的旧证明随其简化判据，不为保留证明而保留复杂度）**：
   羁绊项维持排序规则形态即为终态，P3 重证非义务——若将来新证明入册，
   可再评估升格为金当量项。
```

- 金当量三项全部为注册表查表确定式，**无自由拟合参数**（已标注项除外：合成进度 ×2 结构近似系数【拟·owner = 编排者、期限 = 一个对局周期】、每息档边际率 1 金【注·息档粒度定义值】）；置换账比较使用金当量三项（X 的价格与 Y 的 value 比较），羁绊规则项作为候选资格过滤（掉档牌不进置换让位候选——该过滤在仅备战席候选池下恒不触发，为场上候选预留规则；自救扩展面除外——自救场景排序仍由让位序承载）。
- 排序用途 = 候选评估器的让位序（先按羁绊规则二分：不掉档组在前；组内按金当量升序）；置换账用途 = 与店内新牌的价值比较（同口径金当量，摩擦项 = 手续费，已含在变现价差内）。**与 P41 卖面权威的关系（全文处置申报）**：P41 卖面主不等式（max(V_opt,·) 形态）全文保留在册——让位序是其场景化近似实现（价值让位序替代逐件主不等式求解，单动作场景贪心），偏差 = 组内金当量序 vs P41 全序的对照挂标定批。

## 结论

**打回（阻断）**。5 阻断 / 3 中 / 2 低：

- **D5-4 分组背包 DP 的「精确解」声明崩塌**：L2 层（sub_tiers，10⁶ 域）在搜索空间结构性不可达——段 1 骨架无 sub_tiers 形态 + DP 组得分只含 L3 单位序 + 锁定窗「sub_tiers 升 L2 抑制 L3」使该组在 DP 里 0 分，三层合成 L2 成评分有定义、搜索产不出的死层；且四轮 D4-4 处置给走查行加的「sub_tiers 件 > 万金油」前提声明已被五轮间「过渡条件两态」修订覆盖丢失——五轮报告复核通过项「D4-4 ✓」在当前文本下失实（D6-1）；DP 可分离性对多标签件不成立——unit_bond_tags 是多集（详设 :27 自引），「归属唯一组」使跨组标签贡献在 DP 模型无处安放，构造出 DP 漏最优板的具体反例（D6-4）。
- **意图槽级联差分接面断裂**：详设 §3 差分执行器 = 「画面 op 内循环一次识别连续多动作」与总纲级联「状态机逐帧驱动**而非多动作序列**」正面矛盾，级联的 diff 计算入口在详设零文——双源或断链二选一无解（D6-2）；级联待完成态唯一出口 = diff 空，无作废/超时/失败退出——diff 恒非空形态（拖拽未生效/未知件占槽）下第 4/5/6 步被永久挡住，唯环级守卫停机兜底（D6-3）。
- **备战工序步号三面失真**（文档同步第六犯）：详设「差分执行器替换第 5 步部署序」「卖出臂（0/2/4/8 步）零改」与现行代码工序（第 5 步 = 商店会话、部署 = 第 6 步、卖出臂 = 0/3/8 步）及总纲同迭代文本（第 4 步凑金臂删除、第 5 步开店）互斥——按详设字面替换第 5 步 = 把商店会话步替换掉（D6-5）。

## 发现清单

### D6-1｜L2 层在搜索空间结构性不可达：骨架无 sub_tiers 形态 + DP 组得分只含 L3 单位序 + 锁定窗抑制条款使 sub_tiers 组 0 分——「评分有定义、搜索产不出」的死层；四轮 D4-4 走查前提声明已被五轮间修订覆盖丢失
- 攻击点：三层证据合成——① **段 1 圈人候选族无 sub_tiers 骨架**：详设 :76 候选族全枚举（P1 过渡组合/P1 锁定窗「锁定家族 ∪ 过渡体系组合」/锁定「锁定阵容羁绊（优先核心、逐档）」/P2+ 候选三线）——「锁定阵容羁绊」按 form_tiers 主档逐档圈，sub_tiers（副档目标，cw_comps.py:128-130）无任何骨架通路文本；② **段 2 补人 DP 组得分 = 纯 L3 域**：详设 :83「用户裁定排序（buff/debuff ×3 > 万金油 ×2 > 其他 ×1，过渡条件两态）= 组单位权重，进 DP 的组得分函数」——L2 的 10⁶ 域档位完成度不在 DP 目标函数；③ **锁定窗抑制条款**：详设 :51「sub_tiers 键（升 L2，同键 L3 计分**抑制**）」——sub_tiers 键件（如姬子线护盾件、DOT 线减益件）在锁定窗的 L3 计分被抑制 → 在 DP 里 = 0 分 < 万金油 2 分 → **DP 永不选它们**。三层合成：锁定窗 sub_tiers 凑档板（L2 值 ≥ 5×10⁵，四轮核实口径，压倒 L3 满分 ~10² 三个数量级）在搜索空间不可达——评分函数对它有完整定义（层结构表 :36），但搜索产不出以它为最优的板，只有骨架成员顺带带 sub_tiers 标签的运气板。**DP「精确最优」是「L3 域补人的精确最优」，不是总选人分的精确最优**。④ **D4-4 处置被五轮间修订覆盖丢失**：四轮 D4-4（走查跳过 L2、sub_tiers 凑档帧板面序完全不同）处置 = 走查行声明 L2 前提「sub_tiers 凑档帧：sub_tiers 件 > 万金油 > 过渡件」；五轮报告复核通过项（round5 :32）还验证过该文本在 :122——当前详设该文本已不存在（grep 零命中，走查行 :130 被五轮间「过渡条件两态」裁定改写为保板相位表述时覆盖丢失）——**五轮自己的复核通过项「D4-4 ✓」在当前文本下失实**；且即使声明在，它也与 DP 正面矛盾（走查说 sub_tiers 件 > 万金油，DP 说万金油 2 分 > sub_tiers 件 0 分）——D4-4 揭示的行为面（L2 非零帧板面序）至今无解，只是从「走查缺前提」恶化成「走查不覆盖 + 搜索不可达」双重断裂。
- 证据：详设 :36（层结构表锁定行 L2 定义）/:49（L2 键集 = 仅 sub_tiers）/:51（抑制条款）/:76（段 1 候选族无 sub_tiers）/:83（DP 组得分 = L3 单位序）；round4 :47-49（D4-4 原发现）/round5 :32（失实的复核通过项）；cw_comps.py:128-130,597,1466（sub_tiers 实存 5 处）。
- 严重度：高（**阻断**：搜索算法与评分函数的层覆盖不一致——L2 是注册表实存 5 处副档目标的常态层；实现者按文本可实现出一个「L2 恒不生效」的搜索而不自知，验收用例按层结构表写会全面红）。
- 处置建议：三选一写死——补人 DP 组得分函数纳入 L2 域（锁定窗 sub_tiers 键组按档位完成度 10⁶ 域计分，组曲线仍可阶梯化）；或段 1 骨架候选族扩 sub_tiers 副档形态（锁定圈人含副档逐档）；或申报「L2 仅评分不作搜索目标、板面 L2 由骨架副作用产生」的近似边界并同步层结构表/走查行/验收清单。

### D6-2｜级联差分「谁算/怎么发」两文档正面矛盾：详设差分执行器 = op 内一次连续多动作 vs 总纲级联 = 状态机逐帧单动作（明文否定多动作序列）——级联的 diff 计算入口在详设零文
- 攻击点：详设 §3.5（:93）差分执行器执行形态 =「**备战画面 op 内循环**，逐动作提案 + 自上报推进（**一次识别连续多动作**，循环内零读屏）」；总纲 §2.2 第 4 项（design.md:69）级联待完成态 =「前置步**逐帧**发部署差分动作（统一拖动，**单动作契约照旧——每帧一动作**…）」+ 实现边界（design.md:70）「**禁动流程框架**（单动作契约不动，**级联经状态机逐帧驱动而非多动作序列**）」。矛盾实质：级联路径的统一拖动若调详设差分执行器（op 内一次连续多动作）= 总纲明文否定的多动作序列形态；级联若自建逐帧 diff（前置步每帧算 diff 取首动作发出）= 详设 §3 之外的第二 diff 实现——与详设自己的单一源纪律（:15「部署定型为…四处共用输入，替换 = 同步切全部消费端」同族精神）冲突，双源。详设全篇意图槽落点仅四外围引用（:92 收敛论证/:94 发出点②/:117 截断器动机/:136 走查），**级联态的 diff 计算（现板面 vs 什么的 target）、target 每帧来源（重跑无 X 搜索？复用待卖态定型？）、diff 空判定载体全部零文**。生产消费面单动作（bridge.py:253 只取 actions[0]）是事实——详设 op 内循环形态若被理解为策略帧内多动作直接撞 bridge；若被理解为画面 op 层内循环则策略层级联（前置步）根本不经它——两种理解都接不上总纲级联。顺带：详设 :117 给 truncate_frame_stable 登记义务写的动机 =「防**意图槽混合序列载体（[SellDeployed, 统一拖动…]）**断链」——该载体形态已被四轮 S4-1 定稿**作废**（design.md:67「三轮的 truncate_frame_stable 多动作载体认定作废」）——登记义务本身成立（统一拖动是词表动作、任何策略层序列经截断器都需分类），但处置行的动机引用了总纲已废止的机制 = D5-1 处置的动机表述失实（见 D6-9）。
- 证据：详设 :93（op 内循环）/详设 :92,94,117,136（意图槽外围引用，无 diff 入口）vs design.md:67,69,70（逐帧/非多动作序列/S4-1 作废）；bridge.py:210-253。
- 严重度：高（**阻断**：意图槽是总纲 §2.2 第 4 项的核心机制、详设把「跨画面意图槽执行位」列为 SellDeployed 在役发出点②（:94）却对其级联执行形态零定义——实现者必须在无审查语境下自决「级联差分怎么算怎么发」，任一选择都与另一文档冲突）。
- 处置建议：总纲↔详设同步写死级联差分的单一实现：推荐 = 级联复用详设 §3 的同一 diff 函数（diff 计算单一源），执行形态 = 总纲逐帧（前置步每帧重跑无 X 搜索 → target → diff → 发首动作），详设 §3 补「级联消费形态」小节并与 op 内循环形态（第 6 步部署路径）明确分域；或反过来总纲改级联为 op 内循环（需推翻 S4-1 定稿并重新论证 bridge 单动作兼容性）。

### D6-3｜级联待完成态无失败出口：唯一出口 = diff 空，diff 恒非空形态下第 4/5/6 步被永久挡住——开店/升级/部署全冻结，唯环级守卫停机兜底
- 攻击点：总纲意图槽生命周期（design.md:67）=「待卖 → 级联待完成 → **完成才清槽**」——级联态唯一出口 = diff 空（级联完成）。作废路径只在待卖态（重验不过 → 作废 + V 入节点黑名单）；**级联态零作废/零超时/零失败退出条件**。diff 恒非空的真实形态：① **机械拖拽零判效 + 拖拽未生效**（详设 :10 机制事实自认「执行层为机械拖拽零判效」）——拖出后游戏侧未生效，自上报按推演推进、下帧观察板面未变 → diff 不变 → 重发同一动作 → 再失效 → 无限循环；② **未知件占槽**（详设 :71 D3-13/D5-6 定稿「禁挤」）——目标落位槽被未知件占且落位规则禁选未知件槽 → diff 无法收敛；③ 谓词非单调实证时的 fail-closed 换下（:97）在 bench 满时不可达（换下需 bench 空槽）。后果链：design.md:69「槽在期间前置步优先于第 4/5/6 步（有动作要发 = 扫描到前置步即返回，**开店步被挡住**）」——第 5 步商店会话、第 4 步升级、第 6 步部署永久被挡 → 商店冻结 → X 永不买 → 槽永不清 → 环级无进展守卫触发停机。详设 §5.3（:123）「守卫本体零改，计数面不变」——守卫是停机兜底不是恢复路径；设计未申报「级联死循环形态的预期终态 = 守卫停机」这一行为语义，也无早期退出（如级联无进展 N 帧 → 作废 + V 黑名单）。对照：待卖态有黑名单防活锁（S4-3），级联态的同款防护缺失——同族机制半覆盖。

## 3. 子项 C · 流程账本第 45 行:词缀条件装备分配优先级

病灶(run_20260902_195720 F 条):敌人词缀「软弱无力」(未穿满 3 件装备的角色伤害只剩 80%)在场时,分配无「满 3 件优先 carry」约束——终态 7 件装备三月七(辅助)3 件、卡芙卡(主输出)1 件,全场仅辅助全额输出。

### 3.1 载体设计(对抗轮一已定案:方案 b,结构化谓词字段)

在用词缀效果注册表 `AFFIX_EFFECTS` 为原文文本 dict(效果原文),无结构化谓词载体——「谓词类型 N 与罚值直读原文」无实现路径,实现必造第二源。**选型 = 方案(b)改载体设计**,不选方案(a)登记待办;依据:①子项 C 的病灶(软弱无力局零约束)是已实证的胜负级缺口,只登记待办 = 缺口继续裸奔;②载体改动小且完全骑在既有静态数据采集通路上——新增按词缀名 keyed 的结构化字段族,原文文本行保留为真值出处,结构值为**带交叉核对义务的派生缓存**;③对账通路有现成先例:D-81 守卫(静态数据 divergent 不覆盖 + tooltip 保留证据)就是「原文文本↔结构值」交叉核对的既有机制,新增字段直接纳入其守卫域。

载体规格(值全部游戏定义【注】,实现零新自由参数):

- **落点 = 独立文件**(新增结构化词缀字段族文件,非 `affix_effects_data.py`)——理由:原文文本注册表由运行时采集整文件重写(修法形态),结构化条目混入其中会被下次重写冲掉;两文件**互不触碰**(采集批只写原文文本文件,结构文件只随结构批/交叉核对批更新);
- 结构化条目(按词缀名 keyed):`wear_predicate`(谓词类型 + 参数,如 `min_worn_per_char`, N)、`penalty_side`(罚则方向:`output` 输出侧 / `damage_taken` 承伤侧)、`penalty_value`(罚值)、`prose_ref`(**按词缀名对应**,指向原文文本注册表同名词缀行——行号随整文件重写下移不稳定,按名对应稳定);
- **互检显式告警(检测面一句)**:原文文本注册表命中穿戴/伤害衰减类关键词(「穿戴」「件装备」「伤害变为」族)但结构文件无同名条目 → 显式告警并保留证据,防新词缀漏建模静默;反向(结构条目在原文文本中无同名行,孤儿缓存)同警;值差异走 D-81 守卫拦截;
- **首次消费交叉核对锁**:结构值与原文文本逐条交叉核对(【注·交叉核对定案】先例:`01_math_framework.md` §6),交叉核对做成采集批常设项——游戏改罚值时,原文文本更新而结构缓存 divergent → D-81 守卫拦截报警,禁止静默沿用旧值;
- 已登记词缀集判定规则:结构化条目存在 ∧ `wear_predicate` 非空 ∧ `penalty_side == output` 才进本层(缺结构化条目的原文文本词缀不进,防解析原文文本)。
- **邻接排除族点名**(与「穿戴件数」谓词同族但谓词本体非穿戴的条目,显式排除防一般形误扫):「挫其锋芒」(谓词 = 伤害减免属性未达阈,属减益/装备效果面,非穿戴件数)、「形单影只」(谓词 = 未激活羁绊数;且现建模只含「免罚」半边,未成型侧衰减未建模,`cw_comps` MECHANIC_SYNERGIES 注记)——两者不进本层,候选载体建模候各自领域批(减益面/羁绊面)另案。

### 3.2 判据(一般形,限输出侧罚则族)

词缀效果注册表定义「穿戴条件谓词 + 输出侧罚则」条目(如软弱无力「未穿满 3 件 → 伤害 ×80%」)在场时,装备分配序在基分配序(`10_prep_decisions.md` §2:输出位优先 → 辅助核心装备 → 盈余,[9])之前插入**词缀条件优先层**:

1. 求满足谓词涉及的角色集合(在场角色全集,不限已锁定终局阵容成员——词缀罚则按角色个体结算,不按阵容资格);
2. 集合内按 [9] 既有优先序排(词缀层只重排,不造第二套角色评分);
3. 谓词未满足期间,向集合内最高优先角色的每件分配都指向「凑满谓词」(如凑满 3 件);谓词满足后回落基分配序。

**关键件绑定裁决(实现批回记)**:词缀谓词优先层可重排候选序使非 core 先拿功能性件凑谓词;key_equips 归属仍由 [9] 基序+M7 决定,谓词层只重排候选序不改关键件绑定(关键件接收者序在优先层下仍限于 carry∪core,非 core 凑谓词只走通用件吃满)。

**罚则方向分叉声明**:`penalty_side == damage_taken` 族(如「额外打击」:每空 1 个装备栏,受击后额外承受本次伤害 8% 真实伤害)**不入本层**——承伤罚的总空槽数与分配集中度无关,分配改变的是「谁挨打」不是「总共几个空槽」,§3.5 的集中优先论证对它不成立。承伤侧族的策略语义属生存/站位域,**明确不在本篇范围内**(如需消费,按生命周期第 1 态另立项)。

**反向条件形(库藏生锈,承伤侧但单列)**:词缀要求「无用件聚拢穿到指定工具人」——用户已裁支配条款,立足点只有「词缀罚归零」一条(流水-20260901 裁定,炉料穿着等是顺带形态非理由);配对安全谓词防自动合成带偏:该角色只穿需求向量外无用件。生锈不进优先层(它是「件的去向」约束,不是「分配次序」约束),只走 §2.1 豁免行。

### 3.3 与 M7 角色级分配的接口(对抗轮一已定案:扩签名)

代码真值:`equip_allocation(comp, deployed, owned, occupied=None)`(`cw_comps.py`)接收者顺序在函数内部派生(carry_anchor → core_chars,定义件 = core[0] 派生),无优先序输入。接口设计为**显式签名扩展**:

- 新增可选参数 `priority_order: list[str] | None = None`;`None`(缺省)= 现行内部派生序,零行为漂移;
- **comp=None 路径定义**:`comp` 为 None(无目标/意向未定型帧)时 `priority_order` 强制为 None——优先层的重排依据([9] 序 + 谓词集合)依赖阵容名单;意向未定型帧词缀谓词集合退化为「在场角色全集按现行内部派生序」,即零重排,与「词缀层只重排不造第二套评分」自洽;
- 语义保持声明(**措辞收窄**):配对守卫与唯一件(星徽 add-if-absent)守卫对候选对的判定与遍历次序无关,重排序下逐对语义不变;容量扣减(occupied)的**可穿件总数**与次序无关,而「落在谁身上」随次序变——这正是 `priority_order` 的语义本体(分配优先序),不属「语义漂移」,验收尾径 = 前两类守卫逐对不变 + 件总数不变 + 落点符合重排序;
- 决策/执行分层同既有裁定:优先级是决策层产物,`priority_order` 是唯一传入通道,执行层禁内嵌评分;
- 「M7 零改动」表述**作废**,更正为「M7 判据语义零改动 + 签名扩展一件(可选参数,缺省零漂移)」——签名扩展属接口面,实现批按普通签名变更走测试回扫。

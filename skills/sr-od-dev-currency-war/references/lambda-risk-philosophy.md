# λ_death 与战力数据消费纪律

> 改任何 λ_death/危险信号/战力建模相关内容前必读本页。λ/风险架构的语义权威版本住 [strategy/00_framework.md](strategy/00_framework.md) 与 [strategy/04_survival_budget.md](strategy/04_survival_budget.md);数学证明体系已整体废弃(2026-11-20 用户裁定,考古走 git 历史)。

1. **λ_death 表现状 = 查表基础设施**:死亡危险率的实机校准表(`statefn/lambda_death.py`,数据工件 git 追踪);原决策消费族(λ 顾问/exposure 比较/升档器排序键等)已随血线地板/λ 顾问/升档器删除链停用,现役消费只剩审计登记与濒死带阈值。
2. **硬闸门(用户裁定,仍然生效)**:hp/战力数据进策略,仅限逐项经用户确认的授权面;**其他任何战力相关内容进策略,须用户逐项确认**——hp 使用边界单一源 = strategy/00_framework.md §3。
3. **新增 λ 表消费须过使用纪律审查**:区间敞口比较 + 保守端 + 单调约束;禁边际引用、禁闸门。
4. **死因实证(存量事实)**:旧死局 68%=「该买不买+攥钱」同根(消费被姿态压制);验证判据基线=A1+B 塌向 C 地板(死因构型编号,出处 git 历史可溯)。
5. **数据通道纪律**:实机=点火器不是燃料;sim 与校准表同语料=循环,只当压力测试禁当来源;难度=局内读取为准+公式对账(对账偏差=漂移哨兵)。
6. **资源分配**:战力建模=机会性精修道(闲槽即做,不影响主体、新产出过硬闸门)——需求件 = docs 侧 sim/sim-power-model.md。

### ② W14 环完整性对账门可落码性：**按文本不可落码——计数来源是硬规则 2 意义上的语义空位**

- 设计文本（details §8 :119③、W14 :150）只说「已战斗节点计数 vs 环内行数核对，缺口 → 弃权暗装」。逐个核查既有候选计数源，全部结构性失效：
  1. **SettlementState.rounds_done**：唯一现役结算计数器，但只在挑战成功分支递增（cw_screen_battle_wait.py:648-654，C-1 新帧计数锚 = 挑战成功结算）——败局从不计数。环内行数 = 胜局行 + 败局行（1f 入环后），恒有 rows > count，缺口判定（count > rows）永不触发 → 门恒空转。
  2. **BoardState.node_hist_ord / effective_node_ord**（cw_game_state.py:2064-2070/2482-2493）：run 内已见最大节点序，坐标系 (plane-1)*9+round。它是**全节点**计数（含补给——补给零结算行），要换算成「应产结算行数」必须逐节点知类型：P1/P2 有地面真值表（plane_schedule_observed.md）但 P1 slot3/5/6 是变异位（类型随局变），P3 无在册节点表（7 局仅见前 1-2 节点）——P3 段计数不可计算，变异位换算错位即假缺口（如 P1 slot3 战斗变异为补给 → 环少一行而计数多一 → 永久假暗装），而 §4 明确把变异位列为本判据支持场景。
  3. **环自身派生**：循环论证，门空转。
  4. **口径歧义**：环行含奖励节点行（§8 :117 明文「奖励节点亦有结算屏、产行入环」），「已**战斗**节点计数」是否含奖励节点未定义——不含则比较对象口径不齐（环侧多出的奖励行不触发缺口、方向无害，但实现者需要明确答案而非自行裁量）。
- 可行的落码形态是存在的（如「结算序列闩锁计数器」——每场战斗首个结算帧 +1、按同键去重，与环行同口径比较），但它是需要新写的机制，设计必须指明：计数器载体、置位/复位事件、多页败局链按一场计的去重键、奖励行辖域、P3 段的处置（禁门 or 降级验证性量测）。在补齐前 W14 是不可开工的锁项，其锁测试也无法写出生产形态的用例。失效方向安全性（假缺口 → 暗装）不豁免该空位——门恒假触发 = 判据永久暗装 = 本迭代目标（解锁高难刮皮）静默失败。

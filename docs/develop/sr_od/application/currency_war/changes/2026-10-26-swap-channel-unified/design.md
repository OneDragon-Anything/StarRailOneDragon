# 转型域换人通道统一设计 迭代设计（总纲）

## 0. 元信息

- 迭代目标：用户裁定 2026-10-26（登记载体 = 本迭代进度账本 T-1 note）：换人策略按羁绊组双门 + 转型域统一收益-安全框架落地（治本方案）；净战力不证明（宪法第 1 条禁战力建模），行为锚点验收；P61 证明退役。
- 状态：对抗审中

## 1. 问题与动机

- 现状症状：sim 局 g_20261026_203023（seed=20261216）复盘立案 C1——2-1 买主线核心 Saber 后 4 个备战期换人卖出 0 发射，板面保持位面 1 过渡配方直到死亡（复盘报告 = `.debug/currency_war/deep_review/g_20261026_203023.md`）。历史同病：strategy-docs/02_mandate_layer.md §1 A/B 归因「没做占绝对主导（部署 0/934）」；2026-09-18 板满换入分支为同病第一件补丁（`kernel/cw_deploy_logic.py` `required_swap_arm_pending` docstring 出处行）。
- 根因归层：**语义层 + 架构层**。语义层 = 换入判据语义单位错置（单件「一步成型」对多成员多档位阵容结构性不可达）。架构层 = 同一换人动作帧上**多层独立判据**（触发/守恒/素材/放行/窗口）层层封堵，各自演化：判定对象不一致、守恒对象与口径不一、判据折法不一（✗→✓ 与 Δfp 并存）。**只修触发层不达效**——其余层照样封死同一批 victim。本迭代为同族病第二件，按跨件半问升架构级：公共根 = 各层缺统一「收益-安全」判定原则。
- 解决到哪：**转型域**的五层统一到单一判定原则（§2.0–§2.8）；P61 退役（§2.9）；现行转型分支机器（0534 注册项）归宿裁定（§2.3.1）。
- 明确不解决：**双轨域（P1 配方对锁期）换人行为——现行机器原样保留**（2026-09-18 配方完成件通道继续服务其域，本迭代不触碰，§2.3）；买入面（M2/商店判据）；sim 战斗结算与 hp 校准；净战力强弱证明；经济/升级判据本体（放行层复算接线与来金资格增补除外，§2.5/§2.8）。

## 2. 方案

### 2.0 统一原则（适用域 = 转型域）

**换人合法性 = 组换后板态 × 锁定终局阵容。**

- **转型域判别子（单一源，钉死，三合取全继承现行语义）**：①锁定线槽非空（`locked_comp`/`target_comp` 腿①，`cw_intention.py` 判定权威腿①）**且显式排除 p1_pair 腿②**——`committed_authority` 全值（含配方对锁腿②）在配方锁帧也返 True，不可作本判别子；②**板满**（现行换人只在板满帧发，`cw_deploy_logic.py` `:775`/`:1666-1668`——不继承则与 M1 直上通道抢活白卖）；③**fp < 1.00**（成型帧不进换人域，现行键集回全量语义 `:545-547`/`:991`——丢弃则成型帧行为差未申报）。现行 `ctx.locked`/`_swap_transition_domain` 混轨不可用，本迭代新增专用判别子并让消费位迁移（§2.3.1）。
- **组换后板态** = 板上单位集合 − 换出 victims + 换入组 的派生视图；档位与支撑计数按 §2.1 在该视图上现算。
- 转型域内五层全部消费同一判定函数（单一源），**禁各层自备第二套折法**。

### 2.1 支撑件与档位（口径定义）

- **支撑件 = 终局名单成员（k_members）∪ 羁绊标签命中终局键集的外部件**（并集）。名单成员无条件计入；外部凑档件按标签计入。
  - 依据：`data/cw_chars.py` 标签实测（吉尔伽美什/Saber=圣杯+能量；开拓者·记忆/藿藿=含能量；瓦尔特/符玄不含；停云=仙舟+**能量**；远坂凛=圣杯+战技点；**青雀=仙舟+战技点**（:112）——战技点档已激活事实的承重标签；爻光非圣杯非能量）；键集 = `kernel/cw_comps.py` 双王圣杯 `form_tiers` 的键集 {命运圣杯, 能量}。
- **档位语义源（显式切分，防值对标签错）**：`Comp.form_tiers` = **单阈值成型判据**（两键同时达标 = 阵容成型），**不是档位梯子**；本设计的「一阶/二阶/档位非降」语义源 = `data/cw_factions.py` 档位表**逐档计数**（命运圣杯 2/3/4/5 档、能量 3/5/7/10 档）。form_tiers 在本设计中承担三职：键集来源（支撑件判定）、成型判据（`readiness_form_ok` 现行，不动）、门 1④ 成品腿的 ✗→✓ 判据（§2.2）。
- **支撑件身份 ≠ 不可卖**：victim 资格由门 2 与 §2.7 victim 序独立裁定——终局标签过渡件（停云/远坂凛类）既是支撑件也可作 victim，序上二级deprioritize（§2.7）；来金/演进侧的排除见 §2.8。

### 2.2 触发层：羁绊组双门

- **门 1（收益门，满足任一，对组换后板态判定）**：
  1. 激活终局羁绊新档位（§2.1 档位梯逐档计数）；
  2. 支撑件数严格增；
  3. 同名升星横换（换入件星级 > 被换件星级）；
  4. **成品腿**：组换后成型判据达成（`form_progress` ✗→✓，折法单一源 = `cw_comps.form_progress` 现行契约含 OR 组承接/required 腿）。
- **门 2（安全门，逐被换件）**：现行 `swap_sell_exclusion_reason` 资格面——义务集、新鲜度排除、资格族（`merge_material_guard` 素材守卫 / `star_guard` / `fenced_arm_closed` / `target_keep` / `fp_unreadable` 等拒因面保留；其中 `target_keep` 判定口径按 §2.2.1 收窄）。**守恒面域切分**：`engines_guard` 的守恒职在转型域由 §2.3 终局档位非降（=门 1① 档位面同一函数）承接，双轨域原样——门 2 字面「全链零豁免」以本切分为准（交叉引用 §2.3）。

**§2.2.1 target_keep 判定口径收窄（转型域）**：现行按**阵营视图**命中判 target 单位（`cw_launch_admission.py` target_keep 谓词 + `cw_deploy_logic.py` 让位消费面），会把终局标签过渡件（停云/远坂凛类）恒拒出 victim 池。裁定：转型域 target_keep 的 target 判定口径收窄为**终局名单成员 ∪ 保护集**；标签命中但不在名单的外部件与过渡件不因此恒拒。双轨域 target_keep 口径不动。

### 2.3 守恒层：转型域统一、双轨域原样

- **转型域**：守恒判定 = **终局档位非降（组换后板态口径）**，与门 1① 的档位面同一函数，不设第二实现。
- **双轨域**：`engines_guard`（守恒对象 = `SWAP_GUARD_SYSTEMS` 四体系+护盾，victim 离场口径）、配方完成件分支、必需件分支**全部现行原样**。
- 效果：转型域解锁纯过渡件 victim（爻光/青雀类——其 `SWAP_GUARD_SYSTEMS` 守恒体系承载〔仙舟档〕的掉档由换入组的终局新档覆盖，即用户裁定的「拆掉过渡阵容的羁绊」）；C1 帧死局解除（情形 A，经 §2.7 两级序选纯过渡件为 victim）。

**§2.3.1 现行转型分支机器归宿（0534 注册项）**：`SWAP_TRANSITION_ARM_ENABLED`/`_swap_transition_domain`/五消费位键集收窄/transition_domain 快照——**转型域由双门取代**（该分支的 fenced victim 键集收窄与门 1 受让判定合并进 §2.2/§2.7，禁双轨并行双判据）；双轨域照旧。退役面（五消费位 + 快照）入 landing 3.1 文件面；§2.9 grep 词表补 `SWAP_TRANSITION_ARM_ENABLED`/`_swap_transition_domain`（P88 命题引用同谓词，随引用改写）。

### 2.4 素材层：零改动

`merge_material_guard` 绝对禁卖不变，不设转型豁免（其关切 = 合成进度的经济价值保护，成立）。C1 帧核验：远坂凛持续受保护（bench 有第二张，`same_star_count=2`），爻光/青雀解锁为合法 victim。

### 2.5 放行层：废弃第二折法，改复算统一门

现行 P79-3 三轴（`mandate.py` 部署执行放行门）在**转型域**废弃：轴② Δfp>0 与门 1②/④ 冲突（Δfp 折法已弃）；轴① bench∩membership 使「仅剩外部凑档件待上」帧结构性发不出。改为：**发射帧对现读板态按计划组重算门 1（门 2 已逐件过），门 1 通过即放行**——语义钉死：复算判据 = 门 1 现读通过，非「与生成时点结论一致」；若现读板面与生成期快照分叉（合成/卖出介入等）→ 组按现读重评，不可行即计划撤（零动作）。双轨域放行门不动。

### 2.7 组配对算法与执行形态

- **算法宿主 = kernel**：现行 `select_swap_plan` 为**单对计划形态**（`:1750-1755`），**多对组计划为本迭代新建形态**，宿主落 kernel（kernel→strategies 依赖方向禁反向，策略层只消费计划）。
- **最小充分组贪心**：候选换入序 = 名单成员先（星级降序）→ 外部支撑件（星级降序）；**victim 序两级**——一级：纯过渡件（终局键集零标签命中）先于终局标签支撑件；二级（同层内）= 现行机器 victim 序（档边际贡献, 星级, 槽位——`cw_deploy_logic.py` 现行排序处，实现批核符号锚；非 11 号稿金当量价值序）。逐个扩组：每入一个换入件从 victim 序配一个；每次扩组对组换后板态算一次门 1；**首个可行组即停**。锚帧复验：2-1 帧一级序首 victim = 青雀（纯过渡件，槽位序推导唯一），锚 ① 成立（Saber 换青雀双激活）。无可行组 = 本帧零动作（合法稳态）。
- **换入侧裁判权**：贪心只产「谁进谁出」的组；换入部署仍逐对过现行全套上序裁判（围栏/成对/点火序/配方底线/同名去重——`select_deployments` 裁判域单一源不动）。计划发射**不新增 admission 闸**（现行 launch admission 三元为观测面非闸，照常记录进遥测）。
- **执行形态（本迭代新机制，非现状）**：可行组按同帧原子序逐对（SellDeployed → DeployMove）连发。**中途失败语义**：任一对失败 → 帧内停发后续对，已完成对保留；下帧换人机器对剩余组重新现算续发（计划无跨帧状态，重算幂等）。**下帧竞速申报**：换出后空槽可能被同帧残余补部署（residual_fill）先行占位——下一对的换入部署按占位后板面重评，门 1 对新板态判定（组剩余成员若因此不可行即自然停，无强推）。
- 卖后上序底线照旧（`post_sell_req_missing`）。

### 2.11 行为差申报与关键取舍

**行为差申报**：
1. **完成品分支收窄至双轨域** = 终局锁定帧行为变化（现行 `ctx.locked` 含终局锁定、完成品换入在锁定帧也开）。覆盖性论证（四腿后成立）：现行锁定帧完成品换入 = 单件入板 fp ✗→✓（前提 fp<1.0）→ 门 1④ 对同动作必然成立（同一折法同一判据）；fp ✗→✓ 而档位梯不动的 OR 承接阵容（希儿量子静态套，SEELE_OR_LEGS 全承接形态）由 ④ 直接覆盖，无遗漏。

3. **同帧逐对连发** = 执行形态变化（现行先卖后续帧续发），失败语义与竞速申报见 §2.7。
4. **转型域判别子三合取** = 板满与 fp<1.00 两合取为现行继承（显式钉死，零新增行为差）；腿①排除 p1_pair 为修正混轨（双轨域行为由 §2.3 原样保证，无行为差）。

**关键取舍**：
- **Δfp>0 放宽（放弃）**：多档中盘 Δfp 与档位激活不同构；离散档位判据零调参，天然守护能量硬约束教义；成品语义由门 1④ 以现行 fp 折法承接（不引入 Δfp）。
- **登记 required_deployed（放弃）**：字段契约与双王圣杯不符；让位检验一步成型折法不动则通道照旧关死。
- **P61 扩展证明（放弃）**：新触发面下档守恒不成立；战力面证不了（宪法第 1 条）；用户裁定不证明。
- **守恒域切分（转型域统一、双轨域原样）vs 全域口径重裁（放弃后者）**：双轨域机器经实机验证，重裁 = 无必要的爆炸半径。
- **target_keep 收窄 vs 阵营视图口径保留（放弃保留）**：阵营视图口径把标签过渡件恒拒出 victim 池，转型不可达。
- **来金标签命中排除 vs 仅承载件排除（取前者）**：承载件版是 no-op（`is_field_irrelevant_unit` 已覆盖有档件），真实泄露在无档标签件；教义指向标签命中一律排除。
- **门 1 纳入成品腿 vs 独立保留完成品分支（取纳入）**：OR 承接阵容（希儿类）成型不跨档位梯，①②③全不中——独立分支=双判据并行（违单一源）；④以现行 fp 折法统一承接，语义零新增参数。
- **victim 两级序 vs 单层现行序（取两级）**：单层序在锚帧会选出终局标签件为 victim（停云支），能量收益归零；两级序保「先拆纯过渡」最小破坏。
- **贪心宿主 kernel vs 策略层（取 kernel）**：依赖方向禁反向；单对现行形态升格多对为本迭代新建（kernel 侧）。
- **放行复算 vs 独立放行判据（取复算）**：单一源原则。
- **支撑件并集口径 vs 纯标签口径（取并集）**：纯标签口径把零标签名单成员结构性排除出板。

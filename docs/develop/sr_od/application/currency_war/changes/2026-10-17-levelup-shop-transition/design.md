# 商店升级转场与商业间谍升级联动 迭代设计（总纲）

## 0. 元信息
- 迭代目标：用户裁定 2026-10-17 系列——①商店画面不买经验，升级转场关店不打已处理标记；②升级判据不受商业间谍影响，其升级联动（刷新商店+偷最贵3张）是额外收益；③升级凑金走统一卖出评估器、候选/锁定阵容外任意星级可卖、费用带外先卖。问题来源 = 本局复盘簇 A（`.debug/currency_war/telemetry/sim/sim_match_20261017_194657/strategy_problems_g_20261017_194700.md` 簇A）+ 20号稿 §1 用户裁定（富余金必花，`20_large_balance_must_spend.md` §1）。
- 状态：草案（对抗审中）
- 文档清单：无详设（单文档方案，本篇即完整设计）；对抗报告 = [attack.md](attack.md)

## 1. 问题与动机

- **现状症状**（证据 = 本局复盘 `review_g_20261017_194700.md` 节点 2-1/2-4/3-1 商店章 + 策略审查簇 A）：
  - 富余帧升级即收工：3 个溢金帧（金 61/73/75）店内前置升级检查命中 → 升级整批吞 20/48/56 金 → 关店置「本节点已处理」标记 → 刷新判据零到达。全局 24 节点付费/免费刷新 0 次，锁定线星级目标全零推进；死于 P3-R5 时金 53 ≥ 50（FM-1 死型：富余金没花出去）。
  - 商业间谍升级联动（升级时刷新商店+偷最贵3张）未建模：EffectSpec 已登记（`cw_investments.py` EffectSpec 300201）、应用缺位（kernel 效果应用层与 sim 均无升级回调实现）。
- **根因归层**（约定层为主）：
  - 约定层：11号稿 §2「升级执行即收工关店」语义继承进重做详设（`shop_session.md` §2.2/§2.4），升级收工路径置 handled 标记使本节点内刷新判据不可达；其「已知限界」申报只覆盖买入截断，漏刷新截断；收店理由前提（商业间谍/晋升名额联动未建模）已部分失效（商业间谍已建模 = EffectSpec 300201；晋升名额零命中未在池）。
  - 语义层：商店画面存在升级执行位（店内购买经验），与实机流程不符（用户裁定 2026-10-17：默认实现不应在商店画面买经验，升级在备战画面做）。
- **解决到哪**：升级转场（商店判据命中且可发射 → 关店不打标记 → 备战升级）、商业间谍升级回调建模、商店随机态重开信号、升级凑金放开任意星级并按费用带排序。
- **明确不解决**：刷新与升级同帧抢钱的预算细则细化（现役 R1/R2 预算门照旧；整级预留保护的「刷新不烧升级资金」语义保留，条件载体随 §2.5③ 迁移为判据命中帧并按其申报拓宽——攒息窗预留从无到有、R2 实质收紧、方向保守；是否需要专属「追星推送预算」看修后 sim 数据另批）；**满级段节末凑息停摆议题**（§2.5① 抑制面拓宽后,满级帧资格门恒 DEFER〔`lv9_stop` 等级帽拒发〕→ 节末凑息永久让位——T-5 批数据实测满级帧在本种子集不可达,无有害实例;设计层另议收窄〔如等级帽拒因帧不进抑制面〕,不在本迭代修）;晋升名额建模（零命中，留具名观察）；商业间谍之外的升级联动效果（出现先具名登记再议，禁静默扩名单）；**跨画面协调的零散状态键形态**（`shop_handled`/`shop_randomized_pending` 等）登记为架构级观察项——本迭代后同族病灶再现时，升「节点计划态」架构级设计件，禁第 3 件症状补丁。

## 2. 方案

系统级变化一句话：**升级从「商店内执行 + 终结会话」改为「商店判据命中且可发射即关店转场（不打标记）→ 备战画面执行 → 商业间谍在场时牌面随机化并显式重开」**；升级判据本体（criteria/levelup 五分支/停留门/保底金门/等级帽）零改动。

### 2.1 商店会话：升级检查改为「升级意图出口」

- 会话循环结构不变（方向评估 → 前置升级检查 → 买牌 → 刷新判据 → 收工）。前置升级检查（`shop.py::_session_upgrade_check`）改语义，三分支：
  - **判据命中 ∧ 本帧可发射** → 返回关店动作，**不置 handled 标记**（本次关店 = 升级转场，非「商店事情办完」）；
  - **判据命中 ∧ 不可发射（待付窗）** → 返回 None，会话照常进入买牌六序与刷新判据。「等节点收入」形态由此成立：会话经 §2.5 正常收工置标记 → 出店 → 战斗 → 节点收入——不存在「开店即关」环（转场只在可发射帧发生，收店只在 §2.5 正常条件发生）；
  - 未命中 → None，照常。
- **可发射资格门 = 现役发射门序全链，成员集完备清单（七道，全部通过方可转场）**：
  1. 奖励帧抑制不拦（`reward_node_suppressed`：奖励帧 ∧ 非扑满环境 → 不发）；
  2. 等级帽未到（`level_max` cap 感知，满级不发）；
  3. 五分支判据命中（arm0/概率账/人口位/富余段-L3/停留门升级优先臂——判据本体）；
  4. P21 危机带域判定（`level_spend_blocked`，富余段域内让位）；
  5. 血本位局血闸通过（血余额 ≥ 整级血成本；金本位局跳过）；
  6. 资金门：金 ≥ 整级成本 ∧ 花后守息线 ∧ 保底金门通过；
  7. 击数 > 0（clicks 推导前置）。
  成员集单一源 = criteria/levelup 判定函数，商店侧与备战侧（§2.2 第 4 步）同参消费，**禁商店侧子集化**——漏报任一门则转场后备战侧不能合法发射，开/关店环以新形态复活（attack F-1：等级帽富余帧/血本位血不足帧/奖励帧/P21 危机帧四个可达帧类）。资格门保证转场后零空转帧：店侧转场帧的后继（备战同参重评）必然命中且可发射，落店即执行。
- 升级判据本体零改动，两屏消费同一单一源（criteria/levelup；现状消费点即两处，11号稿 L82）。
- 语义要点：
  - 升级转场关店的上报走现行 leave_screen 通道（shop payload → None，结构事实）；
  - 「升级后同节点找牌」收益由重开双通道承接：非商业间谍路径 = 第 4 步执行帧清标记（§2.2）；商业间谍路径 = 随机态信号高优先级重开（§2.3/§2.4）；
  - 旧「升级金优先于买牌金，先定概率档」的排序语义保留：转场后升级先落地，重开会话时概率档已是新档，后续刷新/买牌按新档评估。

### 2.2 备战工序：随机态重开位 + 升级执行

- 优先级序（全序，插入一处、其余顺延）：

```
第 0 步  溢出告警自救                 （现状最高，不动）
第 1 步  商店随机态重开（新增）        ← 信号在：清 handled 标记 + 开店进店
第 2 步  点消耗品                     （原第 1 步顺延）
第 3 步  晶矿                         （原第 2 步顺延）
第 4 步  升级检查（原第 3 步）         ← 判据命中：凑金 → 买经验（见下）
第 5 步  商店会话（原第 4 步）         ← 标记未置 → 开店进店
第 6 步起 部署/接管/审计族            （现状不动）
```

  位次依据：随机态 = 商店有未处理的全新牌面（含商业间谍偷入备战席的 3 张），用户裁定「很高的优先级」；置于溢出自救之后（安全动作最高）、资源动作之前。
- **升级执行（第 4 步）**：判据每帧重评（无跨画面键，见 §2.5）。命中后凑金与发射：
  1. **发射资格门全链通过**（§2.1 七道成员集，同源消费）→ 发购买经验整批（现役备战域 `CwActionLevelUpParam` 通道，实付上界 = 发射时授权值）；发射 = **单帧原子整批**——「买一半」形态由发射原子性消解（授权不再跨帧携带，行为差如实申报）；发射完成 → **清 handled 标记**（升级前若经 §2.5 正常收工置位，升级后概率档已变，本节点找牌与刷新判据需重评——非商业间谍路径的重开通道）；
  2. 资格门未过因金不足 → 统一卖出评估器 `levelup_liquidate_prep` 场景凑金：候选/锁定阵容外**任意星级**可卖（场景参数 `one_star_refund_only` True → False，用户裁定 2026-10-17）。卖出排序键（该场景级覆盖，新增；按序，用户裁定 2026-10-17）：
     - ① **费用带外先卖**：目标费用 = 当前停留目标的费用档（**按策略目标锚定，非当前等级概率带**——例：目标是 3 费、当前等级已 4 费概率更高时，压牌库仍优先保 3 费；口径单一源 = 刷新判据的带归属绑定〔当前停留目标费用档，shop_session §2.4〕）；**无当前停留目标的帧（未锁定 ∧ 无星级目标）①键不分组**，直接进②③；
     - ② 同组内**低星先**（高星压牌库更深——2★/3★ 为合成体、对应更多池份额〔口径 = `POOL_COPIES_PER_CARD` 池副本数与合成规则〕——后卖，能不卖就不卖）；
     - ③ 兜底 = 统一价值函数金当量升序（与其他卖出场景同一口径，现役）。
     每帧一卖、重扫续卖（卖一张少一张，天然收敛）；
  3. 候选穷尽（含 P78-5 兜底腿尽；兜底腿保留照旧、随场景参数同步去 1★ 过滤）仍不足 → 本帧零动作等节点收入（不部分执行）。
  排除集（候选池 = 备战席 ∪ 场上无关角色，2026-10-13 裁定；常规资格面）与排序③为现役机制；排序键①②为本迭代新增的场景级覆盖（`criteria/sell_candidates.py` 契约 D）。

### 2.3 商业间谍升级回调（效果建模，新写）

- 触发点 = 备战域买经验动作的上报函数升级生效回调；在册判定单一源 = 效果注册表（EffectSpec 300201，`cw_investments.py`；官方文「购买经验的花费减1，升级时刷新商店，并偷取其中最贵的3个角色」）。
- 持有商业间谍时回调行为（依序）：
  1. **刷新商店**：抽 5 张新牌（费用档按升级后等级的概率表；sim = 发牌 RNG 真实抽；实机 = 游戏侧随机，引擎不可知）；
  2. **偷最贵 3 张**：从新抽 5 张按费用/价值取最贵 3 张 → 备战席。sim = 真实入席（席满溢出形态实机未证实：sim 先按「溢出件不入席 + 计数披露」处理，登记实机观察点后修正）；实机 = 引擎不可知，**不登记队列**——`pending_item_grants` 为环境定时道具队列（条目 schema = env/plane/round_num/item，写端唯一 = 获得链，fields.md §3.2.24），禁挪用承载角色偷取；3 张由备战完整观察自然入账；
     - **「最贵」判等口径（破并列键,编排者批准的设计细节补记,T-3 建议 3）**：费用降序 → 星级降序 → 槽位升序——费用并列时比星级,仍并列按抽牌槽位号小者优先（可复现、可对拍）;实机观察对拍以本三元组为比对基准,实机判等若与此不符（如并列随机）→ 按观察修正本行并同步 sim。
  3. **商店新牌面**：剩余 2 张 = 下次开店的牌面。实机 = shop 容器保持离屏 None，重开时入口观察读出真牌面；sim = backend 保存该牌面，下次开店呈现之（不重新发牌——刷新已在本回调发生）；
  4. **置随机态信号**（§2.4）。
- 无商业间谍：升级回调零商店副作用（牌面不变；第 4 步执行帧清标记承接重开）。
- 裁定重申（依据 = 用户裁定 2026-10-17）：升级判据不因商业间谍在场改变、不为其强行升级；其联动效果是额外收益，由继续的会话循环自然评估。
- **流键触发序号观察点（T-3 建议 1 登记持久载体；T-6 r2 括注更正与实现对齐）**：spy 抽牌流键（`M22/spy-deal`/`M22/spy-rotation`）无节点/触发序号分量——`stream_rng(seed, key)` 每次调用按键重建同种子实例（`cw_sim_streams.py`），**同键重复调用 = 同序列重放**：同节点连升两级时两次 spy 世界腿同流键，抽牌序列逐位相同，牌面差异仅可能来自容器牌库面漂移（`sample_shop_deal` 读剩余可抽池）；实机保真观察点 = 若实机侧两次升级的抽牌表现出流重放之外的独立性证据，按观察给流键补触发序号分量并同步 sim。

### 2.4 随机态信号与备战重开位

- 信号宿主 = **GameState 工程结构组非 Field 簿记槽** `shop_randomized_pending: bool`（宿主先例 = plane_node_sequences 台账「非 Field 簿记、非域字段、工程结构组单列申报」；选型理由 = 写入点在 kernel 上报函数，宿主必须 kernel 可写、策略可读——策略层状态键依赖方向不可达）。写端唯一 = §2.3 回调第 4 步；读端 = 备战第 1 步（策略，只读）；清位 = 重开位消费后 + 节点边界清扫。
- 备战第 1 步（重开位）：信号在 → 清 `shop_handled` → 发开店动作 → 清信号。进店后入口观察读真牌面，会话循环正常评估（含商业间谍偷入的 3 张备战新件）。
- 不用商店容器槽位 unknown 形态承载随机态：unknown = 「应为内容但识别失败，必携缺陷记录，决策跳过」（fields.md §3.3.1），且全 unknown 窗触发商店 op 入口停机留证（fields.md §3.3.1 全 unknown 窗行为）——语义与守卫均不兼容，禁挪用。

### 2.5 退役与迁移清单

- 店内升级执行位：`shop.py::_session_upgrade_check` 的执行分支（键驱动帧/授权帧/`_emit_batch`）随会话内升级语义退役；该函数收窄为「升级意图判定（§2.1 三分支）+ 返回关店动作」。
- `CwActionLevelUpShopParam` 词表 + 商店域升级动作注册与执行链接线（operations 层发射面随 §2.1 退役）；`sim/cw_replay.py` 对该类的功能性 import 改按动作名字符串分发（历史 journal 重放不依赖类型存在）。
- `levelup_preauth` 键退役，**三处在产消费面同步迁移**：
  - ① 节末凑息抑制（`entry.py` 变现待定态 → 节末凑息步）：抑制条件改「升级判据命中（同帧重评）」，键读删除；行为差申报——现役抑制面 = 授权态（键在）∧ 缺口未闭，新条件覆盖非金拒帧（等级帽/奖励帧拦截等判据命中帧也进抑制面），抑制面拓宽、方向保守；
  - ② 执行帧「不再重闸/实付上界 = 授权值」防买一半：授权跨帧携带废止，发射 = 单帧原子整批（实付上界 = 发射时授权值），部分购买由发射原子性消解（行为差申报，见 §2.2 第 1 条）；
  - ③ 刷新判据整级预留保护（shop_session §2.4 现读预授权键）：预留条件从「授权态 ∧ 缺口未闭」**拓宽为「判据命中帧」**——现役无键帧（判据命中但未进入授权/攒批的攒息窗）的刷新预留从无到有，R2 预算实质收紧，方向保守（升级资金完整性优先），行为差如实申报；「刷新不烧升级资金，防活锁」语义保留，载体从键改为判据现值。帧间抖动（判据随店内买入退出富余段 → 预留闪断）自收敛、非活锁，可容忍。
- `shop_upgrade_close_pending` 键退役（升级即收工标志）。
- `levelup_liquidate_shop` 卖出场景行（店内侧变现场景）退役；`levelup_liquidate_prep` 保留、去 1★ 过滤并接 §2.2 排序键。
- 测试面随退役适配（实测 7 文件含退役符号，逐个适配：`test_shop_session_loop.py`/`test_intention.py`/`test_levelup_prob_axis.py`〔判据语义重写非机械跟随〕/`test_sim_smoke_batch.py`〔动作白名单行〕等，以 sweep 实测为准）。

### 2.6 验证判据（预注册，sim 行为面）

- 富余帧：升级批照发，且升级后同节点刷新判据可达（刷新动作 > 0 或显式判据不通过拒因在册）；
- 人口位不饿死：deploy cap 推进不回退（升级义务不被刷新挤占）；
- 随机态闭环：商业间谍升级次数 = 随机态重开触发次数；偷取 3 张入备战席（sim 真实入席可断言）；
- 判据面禁 hp/胜率：星级不在 sim 结算键（结算键含板深/等级；星级属未建模面），hp/胜率不得用于评价星级与升级收益（sim-testing 边界）；
- 同 seed 重放确定性：验证通道 = sim 同 seed 双跑对照（现役批量驱动脚本）。

## 3. 关键取舍

- **纯序翻转（刷新先于升级，同会话内）——放弃**：刷新阶梯同样可能吞光溢金，把「刷新饿死」翻成「人口位义务升级饿死」；且店内买经验本身按用户裁定退役，翻转无从谈起。
- **预算并算（刷新阶梯上界 = 溢金 − 整级预留 − g\* − ρ）——放弃（本轮）**：转场后刷新判据现役自带 R1/R2 预算门；整级预留保护保留、条件载体随 §2.5③ 迁移为判据同帧重评（保护面按该条申报拓宽——攒息窗预留从无到有、R2 实质收紧、方向保守）；预算细则是否需要专属「追星推送预算」留待修后 sim 数据（簇 B 另批）。
- **维持 11号稿升级即收工——放弃**：本局实证刷新持续饿死 + FM-1 死型；收店理由前提（联动未建模）已部分失效；与 20号稿 §1 用户裁定（富余金必花）正面冲突。
- **商业间谍在场时仍收店——放弃**：商业间谍已建模（EffectSpec 300201），升级回调建模后牌面经随机态信号 + 入口观察闭环，无过期期望牌面可失配；无条件收店在本局实证为无的放矢（在场效果集不含任何升级联动）。
- **随机态信号宿主用策略层状态键——放弃**：写入点在 kernel 上报函数，策略层宿主依赖方向不可达（attack F-3）；改 GameState 工程结构组簿记槽（§2.4）。

# 用米哈游启动器更新星铁客户端

> 原则：客户端更新必须经米哈游启动器完成（增量下载 + 完整性校验 + 冗余清理），禁手动下整包覆盖、禁手改版本文件。先读启动器页面按钮状态再动手，按钮状态决定走哪条路。

没做完这 7 步不算完成：

1. ☐ 摸清环境：定位启动器 `launcher.exe` 与游戏 Game 目录，读出当前版本。判据：三个值都拿到（启动器路径 / Game 目录路径 / Game 目录下 `config.ini` 的 `game_version`）。
2. ☐ 确认目标版本：联网查星铁最新版本号。判据：明确本地落后几个版本；对账前把版本号归一为三段式（新闻口径「4.7」= config 里的「4.7.0」），避免字面比对误判不一致。
3. ☐ 检查磁盘空间：游戏所在盘剩余 ≥10GB 才继续；不足 → 停下向用户要空间决策，禁自行删文件腾地方（启动器更新途中会自己清理旧版本冗余，缺口通常比整包小，但下载+校验仍需余量）。余量刚过门槛时照常继续，但每轮轮询盯空间，并在报告显式声明余量偏紧。
4. ☐ 检查运行中的游戏：确认没有游戏客户端进程（如游戏本体的 exe）在跑；有 → 先问用户能否关，禁不问就杀启动器进程树——从启动器拉起的游戏是它的子进程，按树杀会连带关掉游戏。
5. ☐ 打开启动器到星铁页面，按主按钮状态路由（用自动化时读法见 references/automation.md）：
   - 「更新游戏」→ 未落后，直接进第 6 步；
   - 「开始游戏」→ 已是最新：与第 2 步查到的版本对账，一致则收尾，不一致（启动器数据滞后）→ 重启启动器再读一次；
   - 「获取游戏」→ 启动器没关联本机已有安装：先走关联流程（references/automation.md「关联本地安装」节），关联成功后按钮会变「更新游戏」。
6. ☐ 点更新并监控到结束。判据：进度经历「下载中」→「校验并修复」→ 进度消失，页面按钮回到「开始游戏」；期间每几分钟看一眼游戏所在盘剩余空间。
7. ☐ 验证并报告。判据：Game 目录 `config.ini` 的 `game_version` 等于目标版本；报告写明更新前后版本、磁盘空间变化、过程中出现的异常。

## 环境发现（第 1 步的做法）

- **找启动器**：搜 Windows「已安装程序」注册表项，`DisplayName` 含「米哈游」或「崩坏」，星铁游戏条目的 `UninstallString` 形如 `<启动器目录>\launcher.exe --uninstall_game=hkrpg_cn`，从中取启动器目录。
- **找游戏目录**：注册表 `InstallLocation` 只是启动器根目录，不是游戏目录；可靠来源是旧版启动器遗留的 `config.ini`（`[launcher] game_install_path`）或全盘搜 `StarRail.exe`。启动器关联后以启动器记录为准。
- **读当前版本**：`<游戏目录>\config.ini` 的 `[General] game_version`。注意 `StarRail.exe` 的文件版本信息是 Unity 引擎版本号，不是游戏版本，别用它判断。

## 操作方式

- **人在场**：按界面文字操作即可——星铁页面右上主按钮；「获取游戏」旁小字「已安装？定位游戏」是关联入口。
- **无人值守（agent 默认）**：用 CDP（Chrome DevTools 协议）驱动启动器界面——启动器是 Chromium 内核，带 `--remote-debugging-port` 参数启动后可脚本读写页面、点按钮；原生「文件夹选择」对话框用 Win32 消息驱动。工具已随 skill 自带（`scripts/`），启动参数、工具用法、关联流程、踩坑全集见 **references/automation.md**，执行前先读它。

## 收尾

- 更新完让启动器保持普通模式：带调试端口启动的实例，任务结束后正常重启一次启动器即可关掉端口。
- 大版本更新后，一条龙的画面识别建档（screen_info）可能与新画面有偏差：跑自动化前先抽一两个玩法验证，异常画面按 od-dev-screen-onboarding 重新建档。

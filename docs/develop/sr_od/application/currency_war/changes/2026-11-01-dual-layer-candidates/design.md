## 1. 问题与动机

- 现状症状:①方向感锁死——候选 = 全 20 线每帧字典序 top3 **无证据门槛**(零信号时 = 热度前三常驻),商店货架明文不进分(12 号稿 + P77 甲),商店牌对选线贡献 ≈ 0;②席满常态——候选三线并集 ≈20-22 人 > 容量 13-14(shop.py:903-910 告警 40 次/局);③过渡层单席——配方对(p1_pair)是在任单方向,不支持多候选并行。
- 根因归层:**语义层**——候选入选缺证据门(热度当入选理由);货架可达性信号的消费位缺失(P77 乙动机);过渡与终局共用「候选」概念但过渡无候选机制。
- 解决到哪:实候选证据门、货架信号装载、过渡层候选化、成员档双层装配。
- 明确不解决:①锁定后换线;②P2 桥;③刷新判据扩虚拟;④部署骨架空间(现行全枚举零截断不动,24 号稿口径);⑤稳态席满(观察后另裁)。

## 2. 方案(单文档完整设计)

### 2.1 系统级变化

1. **实候选证据门**(终局层入选制):候选快照入选门槛 = 该线证据维非零(CARRY/骨架/插件任一**持有** ∨ 环境分级命中);全零证据线不入候选(热度只作有证据线间排序,不再是入选理由)。开局零持有零环境 = 空候选(用户语义「无阵容入选」),买入/环境/发放逐步点亮。机制改动 = `compute_candidates` 加证据门参数(缺省关闭,候选快照消费开启版——其余调用方现行口径不变)。
2. **货架信号装载**(单张买入估值):商店帧货架牌若为某线 CARRY/骨架级成员且该线在**虚拟评估**(证据面 = 在手 ∪ 货架,字典序零改动)下进虚拟 top3 → 该牌获得买入资格(义务类,现行买入管线);买入写持有 → 签名变 → 实候选经证据门点亮 → 整线义务面跟进。虚拟评估只作单张资格器,不作买面名单源。
3. **过渡层候选化**:体系对组合空间(≤10)并行评估取 top3,先凑齐(板面两两组合)先锁(form_ok 冻结);`p1_pair` = 候选首位(派生态)。
4. **统一优先级**:十档结构零改动;过渡候选成员进成员档同构占位,`member_rank` 键改二元组(层,位次)同档垫底。

### 2.2 终局层:证据门 + 货架信号的单张买入估值

1. **证据门判据**:线 L 入选实候选 ⟺ `line_score_key(L)` 的证据维非零——`carry_hit=1 ∨ skeleton≥1 ∨ plugin≥1`(任一持有)∨ `env_tier=1`(环境命中)。零证据线不入,与热度无关;时点兜底(plane2_started ∧ P2 首策略)时候选空 → 锁全 20 线全序首名(热度首线,现行全序的退化情形——证据门下空候选可达,此兜底为真规则)。
2. **买入资格判据**(商店帧,按序):X ∈ 货架可见 ∧ X 是某线 L 的 CARRY 或骨架级(插件级不触发)∧ L ∈ 虚拟 top3(`compute_candidates(在手∪货架)` **不开证据门**——虚拟评估照现行全量排序,资格器消费排位)→ X 获买入资格。**序内子序**:序 1 层内 = missing 缺件循环之后、资格臂殿后,同帧多资格件按货架槽序(单动作契约下同帧序即行为)。
3. **资格臂管线裁定**:①reason 新键(如 `shelf_qualify_buy`)入 `LAUNCH_CAUSE_BY_ARM` 闭集(sell_gate A4 硬闸,注册即义务);②因果类 = **obligation**(τ=∞,义务账——资格件是方向投资件,与 m2 义务件同待遇,卖出资格走 P78 义务账期);③决策序 = 序 1 义务买入同层扩展臂(同金竞争序);④门链 = m2 义务臂同款(**无金线闸、见即买**——资格判据已是窄门〔CARRY/骨架 ∧ 虚拟 top3〕,过门即义务;席位检查照常走买入管线自带)。
4. **P77 对齐**(命题段):①甲修正 1 明文「反应式策略经买动作改进度不在零更新适用范围」——本设计纯反应式(零持久化,同帧兑现);②乙款动机同源(现货未充分利用的缺口面族),但本臂是结构资格门非数值溢价账,估值依据 = 丙主形态 a「购买估值加成」+ 甲修正 1;③丙 b 方向门(零互信息)不采用;④丁款合规:买面资格不加进阵容锁定判据(锁定链零改动,双计禁遵守),现货协议不变。
5. **轮岗偏差申报**:轮岗费档牌更常在架 → 资格触发频率被轮岗间接影响(P77 甲条件域①费档级效应,本设计不消费轮岗信息),sim 观察项。
6. **不进虚拟证据的消费面(逐面定版)**:候选快照 = 证据门版(真实持有);保护面/卖出资格/刷新缺件 = 快照源(证据门版);部署骨架 P2 现算(deploy_search.py:943)= **缺省全量版(现行口径,与快照分立)**——部署吃板上实物的骨架完备枚举,零持有线的 L1≈0 无行为面,双版本分立是设计而非疏漏,禁未来「对齐」误改;投资两屏 = 锁态派生缓存(现行)。整线授权只来自真实持有。
7. **重算时序(脏标记等价性)**:用户构想的脏标记由现行签名机制等价承载(买入即写持有 → 签名变 → 下帧重算),不新增变量。
8. **冷启动臂**:见 §2.3-8(双空窗完备性,防死锁环)。
9. **时点兜底空候选分支(机制改动申报)**:现行 `evaluate_lock` 的 `and candidates` 条件使空候选恒不锁(现行快照恒非空不可达);证据门下空可达 → 分支改「空候选 → 锁全 20 线全序首名」(line_select 改动项,§2.8)。

### 2.3 过渡层:体系对候选-锁定

1. **候选空间**(运行时组合):四体系 = 仙舟3 / 列车2 / DOT2(TRANSITION_TRAITS)+ 希儿系;体系对 = 单体系对(4)+ 双体系组合(6),≤10 对;物化器 = 现行 `pair_target_comp`。希儿系参选限制(渐进不参选、Q 门槛路径合法)保留。
2. **评估(只吃真实持有)**:对级支持度 = **min(两席各自体系支持度)**(木桶语义;单体系对 = 该席支持度)——席级函数现行零口径改动(希儿系分级公式:希儿 + 任 1 去重放大器即满 1.0,希儿自身双标签计入两池)。候选 = 支持度 > 0 的体系对按(对级支持度降序,对级声明序)取 top3,对级声明序 = 按各席体系在 `_P1_PAIR_PREF` 的索引组成元组的字典序(短元组同席补 ∞,零新常数)。**希儿系对入候选门槛 = 席级支持度 = 1.0**(与现行 Q 门槛 `cw_intention.py:673-675` 对齐:单卡希儿 0.5 不驱动买入;旧排序维星级当量选席随四层谓词族退役,§2.6-6)。开局:有羁绊开局(四人组含四体系标签)候选非空;**无羁绊开局存在**(sim 开局手牌 = 费用形状随机采样 `cw_sim_opening.py:81-116`;transition_combos.md:45「49 帖三羁绊都不含」直奔型旁证)→ 候选空 → 冷启动臂(§2.3-8)。
3. **并行候选与在任对(p1_pair 门控)**:`StrategyState` 新槽 `transition_candidates: tuple[tuple[str, ...], ...]`;写端单一 = 配方链重算(现行节拍)。**`p1_pair` = 门控候选首位**——对级支持度 ≥1.0 时写候选首位,否则空对(保持现行 `gate_first` 语义:支持度满才有在任对;committed ⟺ p1_pair 非空 ⟺ 首位支持度 ≥1.0,与现行**含支持度回落帧逐帧等价**,committed_authority 序②与 committed_from 消费面[攒息/装备环境/穿戴计划]零变化——scope 族 (0,1) 带翻转另申报 §2.6-5);物化链(`opening_recipe_comp`)读**无门控候选首位**(替代 p1_early_pair「空窗期同样有方向」职能——部署开局面恒有最强方向,不随门控变 None)。**收敛 = form_ok 冻结**(见 §2.3-4 冻结域)。
4. **锁定 = 先凑齐先锁(冻结域定版)**:「凑齐」= 两两组合板面成型(kernel 成型线)。**冻结评估域 = 全候选空间中对级支持度 ≥1.0 的双体系对,扫描序 = 候选排序键((支持度, 声明序) 降序)应用于全空间双对序列(枚举载体 = 候选机器同源排序函数不截断,超满对如 1.2 先于 1.0 对)**,取 form_ok(板面成型)首个;单体系对**不进冻结域**(「单体系锁停 65.6%」死锁结构性免疫);form_ok 冻结后 **transition_candidates 槽写单元素(冻结对)**(读端零特判,决策载荷导出读数稳定)。**判据消费面改动申报**:现行冻结机器只对当前在任对求值(:1218-1226)且超窗出口会冻结单体系对(test_intention :115)→ 新制扫描域 + 单对不冻结(现行单对冻结形态消亡,申报为死锁免疫改进);超窗解冻状态机对双对零改动。
5. **过渡成员星级要求**:统一 need = 1(不进 need_star 表,现行);2★ 完成品按成员档 4 同构受保。
6. **退役**:进 P2 清空(现行 flow.py 窗口谓词);**P1 内终局锁定后过渡层维持运行**(现行:锁定不辖配方);锁定帧 P1 买面配方支 = **过渡候选并集**(与保护面同源,保 12 号稿「义务面与成员档族名单同源」不变式;`opening_recipe_comp` 角色 = 部署物化单对,买面不读它)。
7. **相邻槽关系声明**:`transition_locked_systems`(体系点亮键集,只增不减)= 单体系满的观测记录(现行角色不变),点亮 → 对应单体系对支持度 = 1.0 入候选前列(p1_pair 非空 = committed);**锁定(form_ok)才收敛**——点亮 ≠ 锁定;`p1_early_pair` 无门槛面被候选首位取代后,`k_empty_window_fallback` 的 p1_lock_band 支(`p1_early_pair_members` 读点,定义 cw_intention.py:902-916,调用 :1372-1373)同源切换到候选首位(单一源,禁双源)。
8. **冷启动臂(双空窗完备性)**:实候选空(证据门)∧ 过渡候选空(无羁绊开局,**双空窗判定与退出判据均以三羁绊体系为准**——希儿系 0.5 单卡不算点亮,防希儿开局帧误判退出)的商店帧,买面 = 资格臂(§2.2-2)+ **冷启动臂**:货架上的过渡引擎件(标签 ∈ TRANSITION_TRAITS 三羁绊键(仙舟/列车同行/持续伤害)派生成员域。**as-built 申报**:现行 `ENGINE_FACTIONS`(cw_line_defs:27-28,P1 三桥 BRIDGE_POOL 派生)= {仙舟,持续伤害,列车同行},与 TRANSITION_TRAITS 键集**当前同集、不含护盾**(P2 桥 train4_shield3 不入派生)——冷启动限定三羁绊 = 与现行等集(命名/派生源显式化 = 前瞻防御桥池未来演进引入护盾,**禁工人改 ENGINE_FACTIONS 派生源**,P78-7 种子判定面零变化))∧ 1 费档 → 见即买(义务类,reason = `cold_start_buy`);**退出判据粒度 = 会话内现算**(以 `_p1_system_support` 三羁绊现算值判定——任一三羁绊支持度 >0 即停,不依赖轮粒度槽位;希儿系点亮不构成退出);**序位** = 序 1 层内 missing 循环之后、资格臂之前。**1 费档推导**:1 费 ⊆ 1★ 全额退集合(收窄取 1 费,保守向——全额退是 1★ 星级属性与费档无关,2/3 费 1★ 同样全额退;冷启动义务可逆,11 号稿 [11] 同源)。防「K 空 → 零买入 → 支持度永不涨」死锁环(12 号稿 §4:89 死锁防线由本臂承接);希儿系开局(希儿在手三羁绊全 0)= 不触发冷启动,希儿线靠资格臂点亮(§2.6-10 同族申报)。

### 2.4 统一优先级:成员档双层装配

1. **不分层前缀**:十档结构与键域 1..10 零改动;档 1/6/8/9/10 跨层身份档不分。
2. **成员档(2/3/4/5/7)双层名单**:终局成员 = 实候选(证据门版)三线并集;过渡成员 = 过渡候选各对成员并集;谓词同构(need/rank/完成品保护/等价群自愈/候选牌非保留张随档复制)。
3. **`member_rank` 键改二元组**:终局 `(0, 线内序数)`、过渡 `(1, 候选位次)`(位次 1 基 1..3);**缺省**(表外/非候选成员)= `(1, CANDIDATE_TOP_N)` = (1,3)(与第三候选并列,由后续键判别,复用现行常数);跨多候选对成员取最小位次;字典序同档垫底(用户裁定:「和终局阵容一样的位置,比终局阵容的低」)。**消费位全清单**:`PriorityContext.member_rank` 类型注解(:146)、**装配写点两处**(:237 锁定帧 `member_rank_of(comp)` 直写、:268-269 未锁帧逐线 min 合成——均改产二元组)、装配补缺(:285-286)、sort_key 五读点(:574/:580/:588/:592/:602 的 `.get(name, 1)` 缺省一律二元组化,防 int vs tuple 混型 TypeError)、decision_payload 新增导出。
4. **重叠归一**:终局身份判定序在前命中即出,rank 取终局值,零特判。
5. **凑息豁免/卖出资格面**:名单 = 实候选 ∪ 过渡候选(现行配方支由过渡候选支取代);豁免语义对过渡成员同构生效。

### 2.5 候选进出与保护语义

1. **实候选(证据门制)**:入选 = 证据点亮(持有/环境动作);退出 = 证据消失(卖出唯一副本)或被更高证据线挤出 top3;掉榜线已囤件保留不再新增(现行)。热度 = 有证据线间排序,不再是入选理由。
2. **过渡候选**:支持度驱动每轮重排;form_ok 冻结后收敛单对;解冻恢复竞争;进 P2 清空。
3. **保护滞回(措辞修正)**:进榜成员档**殿后**(排序靠后非卖出资格豁免——溢出/晶矿/获取让位场景成员仍可被取用,11 号稿 §4.0 场景表);掉榜件坠兜底可让位(1★ 全额退零沉没)。**证据塌缩通道申报**:席满常态下获取让位 victim 恒出成员池 → 卖出某线唯一持有 CARRY/骨架 → 线退候选 → 该线其余成员失档坠兜底 → 后续让位更易再卖该线件(塌缩级联,P60 换手同型)——1★ 全额退下成本有限,不设防(零新机制),sim 观察项补「候选退出原因分布/塌缩级联频次」。

### 2.6 行为变化申报(全量)

1. **实候选证据门(行为变化)**:开局候选空(现行 = 热度前三常驻);零信号期买面 = 过渡候选 + 货架资格臂(现行 = 热度三线并集)——开局义务面显著收窄;信号点亮后逐步扩至证据线;稳态宽度 = 观察项(§2.9)。
2. **过渡候选替换单配方(买面配方半边)**:开局配方半边收窄(单配方 6-10 人 → 过渡候选点亮体系件域);稳态可能放宽(≤3 对并集实测可达 20+,form_ok 冻结后收敛)——分轴如实申报。

### 2.10 关键取舍

- **单张买入估值(本设计)而非备选形态 A(虚拟 top3 驱动整线买面)**:A = P77 丙判死的证据门方向门变体(零互信息,货架证据直接授权整线);单张形态 = 丙主形态 a + 甲修正 1 的字面装载,整线授权仍由真实持有承载。用户三场景(货架核心→候选/双证据切换/热度切换)经「资格买入 → 证据门点亮 → 实候选竞争」完整实现。
- **实候选证据门**:用户裁定原意(「开场全 0、无阵容入选」);热度降为有证据线间排序——零信号期不再被热度前三绑架,与货架资格臂构成「信号进 → 买入 → 点亮」闭环。门槛 = 证据位非零结构谓词,零数值。
- **过渡层不吃货架虚拟证据**:配方链节拍 = 每轮备战贵段,货架生命周期 = 商店帧,节拍不匹配;过渡件全为低费高频牌,货架可见性边际信息价值低(义务面见即买已覆盖)。
- **对级支持度 = min(席级)**:木桶语义与「先凑齐」一致;和/均值使单席满的对虚高。
- **rank 二元组而非层前缀**:层前缀使过渡成员垫底到终局兜底之下(键域 11..20 > 10),过渡在建件比杂牌先卖,复活旋转门;二元组实现「同档占位、档内垫底」,键域零位移。
- **在任/收敛语义归位(备选形态 B「上岗收敛单对」被否决)**:形态 B(支持度满即收敛单对)使单体系满(DOT2/列车2 两件即满)后第二体系件失去全部买进通道——渐进第二席消亡,「单体系锁停 65.6% 局」死锁(kernel 成型线:两两组合=成型)回归;归位形态:p1_pair = 候选首位(派生态,committed 与现行含回落帧逐帧等价),收敛只在 form_ok 冻结(板面成型),渐进通道由候选并集承载。
- **committed 无变化(修正初判)**:p1_pair 派生态等价性推演(§2.6-4)取代「推迟」申报。

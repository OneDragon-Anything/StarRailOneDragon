## 三、专项议题裁决:段 2(黑板槽退役 L 级)可再分建议——**不再分**

- **再分形态考量**:按读写两半拆「批 A = 全簇切换+对账/装配缝改道(§2.4-1/2)」+「批 B = 投影写口+finalize 喂入+消点+槽删除+adapter 缝(§2.4-3/4/5+§2.3)」。可分性存在:批 A 可独立验收(prep 域行为锁族绿)。
- **裁决理由(四条)**:
  1. **先接后删链咬合**:消点前置 = 全簇切换完成(§2.3 前置条件);写侧改造(投影写口/finalize 喂入)是「视图死亡后沿用语义由容器写端承接」的组成半——拆批产生「视图零读者+容器写端未补全」的中间态跨批暴露,批间守护成本反升(§3 取舍二同构论证:拆开反而多付审查面)。
  2. **文件面高度重叠**:cw_screen_prep.py 是两半共同主战场(9 src 文件内占大头),分批收益仅单批审查面略减,代价多一轮完整派工+验收+记账循环。
  3. **锁族以段 2 整体为验收单元**:P3/P4(消点与槽删除的零引用锁)、P5(投影写口等价锁)分别只挂在两半完成后的整体态;拆后批 A 无独立锁凭据,完成判据退化为「行为锁绿」——低于设计件 §2.8 判据标准。
  4. **规模可控**:L 级 = 9 src 文件+测试锁,未超并行先例(波 4 段②约 44 文件在飞,判读报告 #16);编排者侧文件互斥已由依赖声明控制。
- **折中落地**:landing 段 2 小节补「段内执行序」申报(①全簇+对账改道→②投影写口+finalize 喂入→③消点+槽删除+adapter 缝),把先接后删纪律写死,防实现者乱序。

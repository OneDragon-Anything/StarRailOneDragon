# 货币战争策略设计 · 唯一现行入口（strategy-docs）

> 本目录是货币战争（CW）**策略设计的唯一权威文档**：每个画面结合哪些数学证明、怎么产出决策的设计语义都在这里，与代码现状保持一致。
> 读者 = 无会话历史的工程师/智能体。术语首次出现时给定义；集中速查见文末「术语表」。
> **职责分界（用户裁定）**：本目录只管"每个画面结合哪些数学证明、怎么产出决策"；**流程控制（画面路由/访问相位/动作发出/守卫）单独立文档 = `../flow/`**。

## 1. 这套文档回答什么问题

「两个工程师独立实现，会得到同一个策略」——这是全链合格线。为此本链做到：

- 每个机制规格无歧义（判据、触发、适用范围、边界逐条写明）；
- 每个进决策门的数字带**数字来源标注（四种）**：数字必须标来源，共四类——【注】= 游戏规则原始数值（读自代码注册表）；【推】= 由【注】推导（附证明编号）；【拟】= 从对局数据估计（须给置信区间，未标定时禁止触发动作）；【拍】= 用户决定指定的偏好值。没标来源的数值不得参与决策（完整章程见 01 §6）；
- 每条论断可回溯（命题号 → `proofs/math_proofs.md` 索引 → 单篇证明；命题集与各命题状态一律以该索引为准——编号有空洞、个别命题有停用/撤回状态，勿按编号连续性推断；或「文件:节」出处）。

## 4. 宪法：用户六条裁定（每篇都要过）

写任何一篇、采纳任何机制时逐条自检（详述与判读见 [00_framework.md](00_framework.md) §1）：

1. **禁战力建模**：决策依据 = 游戏定义值或核心已定义规则；经验拟合/采样分布不得作决策依据。hp 使用边界 = 合法消费面闭集（00 §3），出集须用户逐项确认。
2. **位面只作参数**：位面只允许作（节点数表/伤害基准表/档位表）的查表键进通用模型；任何机制谓词的适用范围条件中不得出现位面字面量。按位面枚举机制适用范围 = 设计缺陷。
3. **发展优先默认**：默认姿态 = 发展优先；hp 是对局结果不是策略决策输入（00 §3）；hp 维安全带消费面已删除（00 §4）；压制发展的机制不得出现。
4. **数学先行**：每个机制规格可证明或显式登记待证假设；数字带来源标注（四种：【注】/【推】/【拟】/【拍】，章程 = 01 §6）；无标注数字不进决策门。
5. **框架层/策略层所有权边界**：框架层（kernel）只留游戏原始真值（游戏定义的效果/概率/文案原文 + 答案唯一的机制事实判定 + 非打分共用基建）；一切衍生打分（评估表/定序/权重/估值模型/亲和表）与策略内容归策略层（strategies/）。判据线：换一套策略实现会不会要不同的值/序——会 → 策略层。
6. **策略层组织：一画面一策略文件、一画面一策略文档**：每画面的决策入口与打分单独一个文件、配单独的文档；多画面共用判据显式抽离共用文件/判据权威定义篇，画面文件单向依赖共用模块；迁移逐画面推进，一画面一迁移批（代码+文档+测试三同步）。

## 6. 术语表（全链保留术语速查）

> 以下术语为本链约定保留词（行业通用或经用户裁定保留）。各篇正文首次出现处另有语境定义；本表作集中速查。

- **逻辑态**：动作执行后不经观察、按游戏规则推算并直写状态容器(GameState)的预期状态。例：买牌后按规则推算金币 −40、备战席 +1；下一帧实际观察与此不符时，以实际观察为准。
- **对账**：两个独立来源的同一数值互相核对（例：动作上报推算的金币 vs 下一帧画面实读的金币）。
- **帧**：一次「观察画面 → 决策 → 发出一个动作」的循环时点；策略每帧至多产出一个动作。
- **帧代次**：观察帧的代次标注——入口全量重观察帧标 full（触发方向视图重算），同一访问内动作后的帧标 none；用于区分「这帧的观察是不是全新重读」。
- **零判效**：动作执行侧不做「是否生效」的判定；生效与否交由下一次画面观察核对。
- **id_mark 锚定**：用画面独有的稳定识别标志（id_mark，文本或模板元素）确认当前画面身份；id_mark 组合内全部命中才算精准匹配。动词「锚定」= 用 id_mark 确认画面。
- **单一源**：同一知识/数值只在一处权威定义与维护，其余地方只引用不复制。
- **权威版本**：某主题设计语义的权威版本文档；引用语义以权威版本为准。
- **fail-closed**：读不到数据/条件不满足时默认走保守分支、不产生动作（宁可不动作，不冒险）。
- **λ_death**：死亡危险率——在「当前难度带 × 血带 × 位面 × 节点」条件下打输下一场战斗、进而威胁存活的概率估计（详见 00 §2）。
- **M1-M7**：骨架义务七条——不做会输、无条件执行的动作清单（定义见 02 §3）。
- **E1-E18**：投资事件面 18 类决策点的目录编号（定义见 08/13 篇）。
- **S0-S3**：意向状态机的空窗·搜索·锁定等状态编号（定义见 12 篇）。

### 数字来源标注（四种）

进决策门的数字必须标来源；没标来源的数值不得参与决策（完整章程见 01 §6）。

- **【注】** = 游戏规则原始数值（读自代码注册表）；
- **【推】** = 由【注】推导（附证明编号）；
- **【拟】** = 从对局数据估计（须给置信区间；未标定时禁止触发动作）；
- **【拍】** = 用户决定指定的偏好值。

## 高-1 floor_eff 单投影的段分类取端在组-端表内自相矛盾(M3 行=CI 下端 vs arm2 行/λ≈0 判定界行=CI 上界 ≤0.1),CI 跨界带投影无定义

**位置**:IMPL_DESIGN §2.10 组-端对照表三行——「M3 破息批解锁(floor_eff=0)」行(取端=**CI 下端**)、「arm2 守息门(floor_eff=10×cap_resolved 侧)」行(取端=「段管辖边界(**CI 上界 ≤0.1**)」)、「λ≈0 段判定界」行(CI 上界 ≤0.1);叠加 R7-6「floor_eff 10×cap_resolved/0 **一个投影喂两扇门**」与 R8-4 引理「**健康段** floor_eff 值=10×cap_resolved」。

**缺陷**:同一 floor_eff 二值投影,两扇门(arm2 守息门与 M3 破息批解锁)在表内被指定了**两套相反的段分类规则**,且 R5-5 声称的「消中间带边界悬空」并未兑现。

**为什么错(数学论证)**:取 CI=[λ_L, λ_U]=[0.05, 0.2](跨界态:λ_L≤0.1<λ_U):

- 按 M3 行规则(判濒死用**下端**):λ_L=0.05 ≤0.1 ⇒ 不判濒死 ⇒ floor_eff=10×cap_resolved ⇒ 破息批锁定(不可逆 XP 支出不放行);
- 按 arm2 行/λ≈0 判定界行规则(判健康用**上端 ≤0.1**):λ_U=0.2>0.1 ⇒ **不判 λ≈0** ⇒ 非healthy 段 ⇒ floor_eff=0 ⇒ arm2 守息门失效(XP 批可破息放行)。

一个投影不可能同时等于 10×cap_resolved 与 0。R7-6 明文「一个投影喂两扇门」使实现无法同时满足两行——实现者无论选哪套规则,都直接违反另一行及其端点纪律论证(M3 行论证「λ 高估 ⇒ 误入 λ>0 ⇒ 不可逆破息 XP 支出=fail-open 向,取下端封死」;arm2 行理由栏论证「误判健康 ⇒ P51 §7-1 损失姿态」)。两套论证各自成立,恰说明它们针对的是**同一枚币的两面**,而二值投影只能落一面。

追溯:该矛盾由 R7-6 补行引入——R7 轮攻击报告(#「一个投影喂两扇门」)本意是让设计者**意识到并定谳**单一分类规则,但落位修法只是把守息门补进表里并沿用总纲段命名口径,没有定谳投影的分类输入,反而把两种取端并排写进了同一张「取端统一判据=使门放行更难的方向=保守端」的表里。R8-4 引理又用「健康段」(总纲定义=CI 上界 ≤0.1)定义投影取值侧,进一步把上界规则钉进引理层。R5-5 的「λ≈0 段判定界=CI 上界 ≤0.1,显式入本端点表,消中间带边界悬空」实际只定义了段**命名**,中间带(CI 跨界)的投影值仍悬空且被两行各拉一向。

**修法方向**:定谳**单一**分类规则供投影使用。建议:floor_eff=0 ⟺ **CI 下端>0.1**(确证濒死才解锁破息,XP 不可逆面保守);否则(含 λ≈0 段与中间带)floor_eff=10×cap_resolved——即 M3 行的下端规则成为投影的唯一规则,arm2 行改为「消费投影输出,非独立分类」;arm2 行理由栏的「误判健康代价=P51 损失姿态」由既有缓解(arm1 义务通道独立承载转化 + arm2 只延迟不否决)继续承载并在行内显式声明「中间带落守息=该代价的显式接受」;「λ≈0 段判定界」行降格为「段命名约定,非投影输入」或与下端规则对齐表述;R8-4 引理的「健康段」措辞同步改为「非确证濒死段」。§5.3 floor_eff 对拍须补 **CI 跨界场景(λ_L≤0.1<λ_U)两侧断言**(现只有 0.1 边界两侧行为,恰好测不到跨界带)。

## 中-2 V_gap 同时位列「类型上不暴露给闸门消费位」封印清单与 R1 门的合法输入——类型层机制与封印让位声明不可同时实现

**位置**:IMPL_DESIGN §2.10 第 3 条:「CI 对象不含闸门语义:凡标注『禁作闸门』的项(**V̄/V_gap 等**)在**类型上**就不暴露给闸门消费位」;同节 P1 对策段封印关系声明:「§2.10.3『V_gap 禁作闸门』封印盖的是 V̄ 拟合闸门族的未标定注入形态;**R1 门的 V_gap 是标定后经 provisional.py 显式注入的合法消费位**,封印条款在此让位」;§2.4 r1_start 行:`c_eff·E[refreshes|j]+Σ卡费+L ≤ V_gap`(R1 门,**以 V_gap 为闸门阈值**)。

**缺陷**:R1 门本身就是一个以 V_gap 为阈值的**闸门**;而 §2.10.3 把 V_gap 列入类型级封印清单。「类型上不可达」是编译期/接口期属性,不区分值的来源(未标定注入 vs 标定后显式注入)——封印声明说「让位」,但**类型不会让位**:provisional.py 按第 3 条实现后,R1 门的 V_gap 消费位在类型上写不出来;不按第 3 条实现,封印条款对 V_gap 就是假封(只对 V̄ 真)。R6 轮审查 #13 曾判「V̄ 封印与 R1 门让位关系声明成立」,本轮攻的是该声明与**机制句**(类型层)的冲突——叙述层让位不能消除类型层互斥,实现者面临二选一,二选一各违反一条明文规格。

**为什么错**:两条规格对同一消费位(r1_start 的右端 V_gap)给出相反的可表达性判定;§2.10.3 的句子是可执行的接口纪律(「类型上就不暴露」),不是可被声明覆盖的偏好。这是「实现后必错缺口」:照第 3 条写 provisional.py ⇒ refresh.py 的 R1 门无法消费 ⇒ 付费刷新面整体死规格;不照写 ⇒ 审计断言(按第 3 条核)必红。

**修法方向**:封印对象收窄——类型级不可达清单只保留 **V̄ 拟合族**(未标定且永不标定开闸的项);V_gap 从「禁作闸门」清单移出,改列为「标定后闸门合法输入、端点纪律管辖(CI 下端,§2.10 第 3 条 F6 段已有)」。或给 V_gap 建双类型(未标定态对象类型上不可达闸门位 / 标定 CI 对象可达),但那是为一句错列引入的机制复杂度,前案更简。§2.10 第 3 条括号清单同步改为「(V̄ 等)」。

## 中-3 §4.2.1 完备性全称破缺:criteria/refresh.r0_stop 缺行(R9-1 同型缺行,臂①形态未定)

**位置**:IMPL_DESIGN §4.2.1 臂①旁路集函数级枚举表 refresh 域仅三行(`r1_start`/`r2_budget`/`crisis_refresh_invariant`);§2.4 定义了 refresh.py 四函数,`r0_stop()`(R0 维持结构门/R0-2 结构判据)不在表内;表尾完备性口径明文「上表覆盖 criteria/* 与 proof/line_selector **全部函数位**,二分全称成立(每行有归属)」。

**缺陷**:r0_stop 是 §2.4 落码映射表中的正式函数位(fail 方向列明确写「无合格集刷新 fail-closed」),按类别系统它属**门**(结构判据,无发射)——而「旁路对象=发射位与发射门」,门在旁路对象域内 ⇒ r0_stop 必须有臂①形态(旁路/不旁路)。「全部函数位、二分全称」的声明与表的实体缺行直接互斥。这正是 R9-1 自己定性过的病:「唯一权威表缺行、真实规格散落别处」——r0_stop 的臂①行为现在只能从 §2.4/骨架层文字猜测(它辖的是刷新循环的停止判据,而臂①付费刷新两件套已旁路、免费刷新「骨架义务与免费刷新不受影响」,r0_stop 对免费刷新是否生效无明文)。

**为什么错**:完备性全称是 L-B5(a) 哨兵(臂① mandate=false 计数=0)与命题 A 归因的前置保证;缺行=存在一个无归属的发射门,臂①配置若错置它(旁路了本应保留的结构门,或反之),换线/刷新面的对照被污染而哨兵不报警(结构门不发射 mandate=false 动作,泄漏不可观测)。R9-1 修 should_switch 缺行时的定性原文「旁路集少关一项与多关一项同罪」逐字适用于本行。

**修法方向**:补行——`refresh.r0_stop` | 门(维持结构门,辖刷新循环停止判据) | **不旁路**(结构判据零参数、与 crisis 不变式同属结构位;臂①免费刷新照常走 R0 结构门)——并核对 r0_stop 与已旁路的 r1/r2 的辖域交叠(付费刷新旁路后 R0 的预算递推输入是否仍良定义,一句声明);或若裁决为旁路,须明文「臂① 无任何刷新循环 ⇒ R0 空转」的推理,不留给实现者猜。

## 次要-4 R9-4 仲裁先序「M6 > mandate 邻接位」与 §3.1 执行序相反,条款未指明仲裁机制,且该先序对 dominance↔M6 这一对是纯遥测归属

**位置**:§2.5 仲裁条款泛化:「同帧同卡任意两发射位辖域重叠/并出 ⇒ …层级先序=M6(骨架义务序位)>mandate 邻接位(dominance_buy/fuel_sell)>criteria EV 位」;§3.1 执行序:dominance_buy 为 **M2 前置**(先发射),M6 在 M3/M1′ 之后(后发射)。

**缺陷**:先序把 M6 排在 mandate 邻接位之上,但执行序里 dominance_buy 先于 M6 发射。按「并出 ⇒ 唯一归属=M6」执行,需要回撤已发射的 dominance 意图或预飞辖域检查,条款两者均未指明;而骨架 pass 是「生成意图→检查→执行」的单帧闭环,意图级回撤与逐位执行两种实现的行为一致性未被规格锁定。行为层面该对(1★ 燃料/可退件 ∧ 档内 ∧ 金>50 ∧ 无 S 目标)是同一物理买入、同为 mandate=true,仲裁只改遥测归属——先序排反徒增机制。注意 M6 档匹配 fail-closed(T_search🔴)时 M6 不发射 ⇒ 无并出 ⇒ dominance 照发,不存在「支配被未标定门吞掉」的行为洞(已推演排除,不升级为实质缺陷)。

**修法方向**:仲裁条款补一句机制定谳(意图批次预飞辖域检查,先到执行序为准的归属即「执行序先者=归属」),或把先序改为与执行序一致(M6 仅对 EV 位有优先权);并对 dominance/M6 对显式声明「同动作 benign 并出,归属仅遥测,不触发丢弃」。

## 次要-5 stop_flag 的锁存语义与谓词语义未钉死;成型→缺件(无换线)时锁存陈旧

**位置**:§2.7 stop_buy「成型判定=…;置位后…;换线事件重置」+ R9-2「登记帧与生效帧评估返回前保持旧值」。

**缺陷**:若实现为纯谓词(formed(K)),生效帧证明 pass 即自然归 0,R9-2 的「旧值在生效帧骨架 pass 仍生效」收益声明失效(行为反而更优但与引理/测试位③断言时序不符);若实现为锁存,则 K 不变情形下线成型后被外因破成型(如合成/装备消耗成员使「单位齐备」翻假)时 flag 恒 1、无重置事件,过渡件被压制至局终。两种读法都有可构造的意外面,规格未钉死哪一种。

**修法方向**:一句定谳——stop_flag=锁存(置位=成型谓词真;清零=仅 R9-2 评估返回)+ 补「锁存期内 formed(K) 翻假 ⇒ 记遥测」的观测位(或允许 formed 翻假同帧清零,二选一明文),§6.4 测试位③断言按钉死语义校对。

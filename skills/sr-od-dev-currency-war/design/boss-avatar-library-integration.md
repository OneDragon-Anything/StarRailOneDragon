# BOSS 头像模板库统一落位设计（boss-avatar-library-integration）

> 状态：已实施（as-built）。本批 = 新库目录制落位 + 旧库退役 + 识别链接线 + 验证。
> 用户最终裁定（不可违背，覆盖早期草案的「新库主匹配 + 旧库兜底」双库方案）：
> ① **只保留新库**：旧库 `assets/template/currency_war/boss_avatar/`（21 张平铺 PNG）随迁移退役删除——不做新主旧兜底、不做长期并存，回退走 git 历史 revert；
> ② **目录制**：`assets/template/cw_boss_avatar/<公司名>/`，对齐 character_avatar 库形态；
> ③ **带透明通道掩码**：每公司目录含 `mask.png`，为后续「忽略透明通道匹配」升级留能力——当前匹配链仍用实验验证过的合成图直匹配，mask 先归档不消费。

## 1. 背景与识别链现状

### 1.1 boss 头像识别链（各环节与库的关系）

boss 头像识别链（识别目标：认出「本位面 boss 是哪家公司」，公司名即 `cw_enemy_data.BOSS_MECHANICS` 规范名）：

| 环节 | 位置 | 语义 |
|---|---|---|
| 模板加载 | `cw_node_reader.py::load_boss_templates` | `glob('*/raw.png')` 目录制扫描 → 键 = 公司目录名 → 灰度 → SIFT 特征预提取 → `{公司名: (keypoints, descriptors)}`，特征 <4 关键点丢弃 |
| 消费点 A（懒加载全局） | `cw_observation.py` 两处（各自懒加载模块级全局 `_BOSS_TEMPLATES`） | 路径硬编码 `assets/template/cw_boss_avatar` |
| 消费点 B（节点条域） | `cw_node_reader.py::classify_node_row` boss 槽分支 | 备战节点条最右槽（首领=位面最后节点，位置先验）裁 ~56px patch 做 SIFT |
| 消费点 C（大图标域，主消费） | `cw_screen_plane_intel.py::_read_boss_big_icon` | 位面详情屏详情条「区域-boss大图标」~107px 裁片 SIFT，复用 `_cwo._BOSS_TEMPLATES`；前置「首领」标签验证 |
| 命中判据 | `cw_node_reader.py::match_boss_sift` | **断层门**：好匹配数第一名 ≥ `BOSS_SIFT_MIN_GOOD`(3) 且 ≥ `BOSS_SIFT_RATIO`(2.0)×第二名（含 tie 拦截）。**承重墙，零改动** |
| 测试面 | `sr-od-test/.../obs/test_cw_node_reader.py` | 12 条：既有 4 帧归档 fixture（正：深渊育种科技/不死者联盟；负：宝箱图标位、库外纹章变体）+ 语料持久化 6 帧（正 ×2、负 ×4）+ 库面契约×注册表一致性 |
| 监视面 | `skills/sr-od-dev-currency-war/scripts/cw_asset_sentinel.py` | `cw_boss_avatar` 目录级 critical 监视（丢失/清空即退），递归清点 21 目录内容 |

### 1.2 统一模板批（新库内容，实验已验证）

新库内容 = 「统一模板批」：21 家公司各一套模板，官方美术原图统一重制，透明底按 alpha 合成实机大图标域底色 RGB(34,30,61)，公司目录名 = 官方中文公司名 = `cw_enemy_data.BOSS_MECHANICS` 规范名。实验结论（60 帧实机语料：22 正样本帧 + 38 负样本帧）：

- **正样本 22/22 命中**，断层余量 4.7×~10×（实机正帧仅覆盖 2/21 公司；其余 19 家 = 同美术同源逐家目检 + 负样本族零误报背书）；
- **负样本 38/38 拒判**（补给图标 ×31、战斗图标 ×5、纹章变体 ×1、节点条域对照 ×2，含语料目录重复计数），零误报；补给族出现过第一名 10:10 平分，靠断层门 tie 拦截拦下——门常量是负样本防线的承重机制；
- 两候选方案被负样本否决禁用：**缩放到裁片尺度 94px**——补给/战斗图标 26 帧误报（同尺度圆形模板与域内任意圆形图标环对环系统性碰撞）；**合成非实机域底色**——战斗图标 2 帧误报。固化为落库红线：禁止把模板缩放到裁片尺度；禁止用非实机域底色；
- 附带复现旧库历史故障（混尺度病）：60px 不死者旧模板在实机大图标域被大尺度别家模板抢走次名余量（7 < 2×4 拒判）；同帧换统一模板批后 28 vs 6，余量健康。

### 1.3 被替换的旧库（退役动机）

旧库 21 张文件是三种来源混装：19 张 60px 图鉴小图 + 2 张实机大裁片（深渊育种科技 111×110、不死者联盟 94×96）。由此：19 家图鉴公司的实机大图标域得分从未统一验证，负样本族余量薄；混尺度竞争让别家大裁片吃掉小图公司的次名余量（§1.2 历史故障即此机理）。统一模板批以单一尺度域根治该病，旧库按用户裁定退役删除、不设兜底。

## 2. 落位形态：目录制三件套

```
assets/template/cw_boss_avatar/
├── 不死者联盟/
│   ├── raw.png    ← 128×128 统一模板(alpha 合成实机底色 RGB(34,30,61);识别链唯一消费件)
│   ├── mask.png   ← 透明通道掩码(原素材 alpha 灰度;备后续「忽略透明通道匹配」,当前链不消费)
│   └── src.png    ← 原始透明底素材存档(字节级原样,溯源)
└── …(21 公司各一目录;18 家 128×128,智识实验室/深渊育种科技/绘师家族产业 3 家 123×124)
```

落库纪律与一致性核对（落库批逐文件执行，21/21 全过）：

1. raw 与实验验证过的统一模板批文件**字节级一致**（diff=0，纯复制零重编码——验证按模板批字节跑，任何重编码都是未验证变量）；
2. 每张 raw 用其原始素材按同款 alpha 合成**逐像素一致**反查回源（映射真值不依赖任何声明表）；
3. mask 解码像素 = 原素材 alpha 通道；src 与原素材字节 diff=0；
4. 公司目录名 = `cw_enemy_data.BOSS_MECHANICS` 规范名（SIFT 命中名直接作 boss 读数与机制 tag 查表键）。

**mask 语义**：只归档、不参与当前匹配（识别链仍走 raw 合成图直匹配）。后续若升级「忽略透明通道匹配」（例如以 alpha 门控 SIFT 特征提取域），mask 与 src 已在库，无需再动素材面。

**框架扫描可见性**：`cw_boss_avatar/<公司>/raw.png + mask.png` 满足框架两级模板条目契约，GUI 开发工具会列出该类目 21 条模板（旧平铺形态不可见）——仅呈现变化，无任何 screen_info/框架匹配消费，行为零影响；`src.png` 为扫描器忽略的额外文件。

## 3. 接入语义：单库无兜底

匹配域 = 唯一的新库。每次 `match_boss_sift` 单域跑断层门，拒判 = `None`（现状失败语义）：

- **混尺度病根治于「匹配域单一尺度」**：域内只有统一模板批一种来源/尺度，别家抢次名余量与同公司双模板占次名在结构上不可能发生；
- **不设旧库兜底是裁定的核心**：兜底会把旧库的混尺度薄余量条目永久留在链上，与「根治」目标相悖；新库拒判 = 该公司/该渲染态不在库，走响亮失败防线（位面情报 node 重试、耗尽 op fail；无 None 占位/降级分支——把识别失败降级会违反对账真值纪律）；
- **回退靠 git**：整批回退 = revert 落位/接线 commit（恢复旧库文件与旧接线）；无运行时开关。

## 7. 设计裁决记录（why 收敛）

- **目录制而非平铺**：对齐 character_avatar 库形态（模板目录制是项目模板规范形态），目录名即公司键；代价 = 装载器从 stem 改父目录名（一行），收益 = 三件套可归档（mask/src 无处安放的平铺形态放不下）；
- **带 mask 但当前不消费**：忽略透明通道匹配是明确的后续方向（透明底素材直匹配的预备），素材到位后升级零素材改动；同时 mask/src 不进匹配域，不改变已验证的实验结论；
- **单库无兜底**：匹配域单一尺度是混尺度病的根治形态，兜底域会永久保留病源条目；失败语义走响亮暴露而非静默兜底，回退成本 = git revert（用户裁定）；
- **门零改动**：门常量是正负两侧实证承重墙（正样本最小余量 4.7×、负样本 10:10 靠 tie 拦截），任何调整同时动摇两侧已验证结论；
- **字节级落库**：实验验证对象 = 统一模板批的具体字节，落库复制不重编码使验证结论原样继承，复放分数逐位一致是落位正确性的端到端证明。

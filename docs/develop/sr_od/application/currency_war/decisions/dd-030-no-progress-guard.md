# DD-030:备战环无进展守卫——环级活性不变量

## 背景(问题)

三起实机卡死(M2 开店环 2fa50afb 前、M7 装备环 dd-027、选择伙伴遮罩死局 dd-029)共同形态:备战环连续多帧重发同一动作批而执行面零变换,每起烧 8–34 分钟才被会话外哨兵发现(架构反思:`.debug/temp/currency_war/redesign/ARCH_REFLECTION_3STALLS.md` 问三缺口 G3)。闩(dd-027)是逐发射位记账,只兜已登记位;新发射位/新遮罩画面漏网时无运行内防线。

## 决策

在备战环引入**环级无进展守卫**(闩模式从「逐发射位记账」升维为「环级活性不变量」,替代第 4 个逐位闩):

- 触发 = 连续 `PREP_NO_PROGRESS_ROUNDS=3` 个备战环满足「动作类型序列签名相同 ∧ 状态指纹零推进」;
- 状态指纹 = `(plane, round_num, last_node_type, gold, bench 身份串, deployed 身份串)`,全读 observe 现成字段,零新增识别;deployed/bench 用身份串非计数(防同数换人漏检);球/箱/vacancy 不进指纹(由动作签名腿覆盖,防识别抖动假计数);
- 动作 = 截图存证(prefix `prep_no_progress`)+ flag 三要素 → `stop_running`(停机钩子形态)→ `round_fail`;flag 写失败仍停机;
- **替换**旧 `PREP_STALL_EVIDENCE_ROUNDS` 留证线(旧线只留证不停机、state-only 签名),旧常量/旧状态/旧留证块删除,旧线独有的 expected 未覆盖线索收编为守卫触发日志诊断字段。

## 理由(Considered Options)

- 整合旧线 vs 替换:替换。旧线与新守卫职责重叠(留证)、语义不同(不停机),并存即双计数源;旧线独有诊断价值以字段收编保留。
- 环级守卫 vs 第 4 个逐位闩:环级。逐位闩已被证明依赖人肉清点发射位(dd-027 修订实证),环级不变量覆盖 G1/G2 漏网的全部活锁形态。
- 阈值 N=3:沿用旧线取值(多版本无误报记录),不另立新数。

## 后果

- 正面:活锁代价从 8–34 分钟压到 ~1 分钟+自动留证;三历史卡死签名重放(M2 重燃/M7 闩后跳过/遮罩 RunDeploy 环)全部触发,健康轮转/战斗等待/闩跳过三形态不触发(13 锁,`test_cw_no_progress_guard.py`)。
- 边界:守卫只兜「执行面零变换的重复同批」;席满破墙循环卡死会以破墙签名入计(可触发);接管补采/overlay 交回环不计数。未知画面降级语义(G2)与发射位准入机器门(G1)另案:G1 待激活行挂账,G2 在守卫落地后降级为留证事件。
- 运维:守卫触发后现场处理流程见 flag 文件内嵌说明(判画面→建档或查执行链→删 flag 重启 server)。

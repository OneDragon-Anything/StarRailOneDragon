# dd-013:删除 LOCKED_RESUME_ENHANCED 锁死续跑逃生机制

> 类名已随 2026-09-03 命名迁移更替,对照 NAMING.md(本文为带日期决策记录,类名保持当时事实,未改)。

- Status: accepted(2026-09-02,W970 批 A 实施时落;设计出处 = `docs/develop/currency_war/prereg/w970_layered_arch/DESIGN.md` §5 批 A「LOCKED_RESUME 删」)
- 关联: DD-011(操作完成自等动画规范)、W971(流程层重构,04-shop)

## 背景

`BuyShopCards.buy` 开店段旧有 `LOCKED_RESUME_ENHANCED` 类开关(默认 False):开店轮询超时后不判负,置续跑标记让流程以「店已开」假设继续读牌面——设计意图是离线测试环境无真实画面反馈时的逃生通道;实机语义 = **静默假成功**(超时即画面未达预期,继续执行等于把失败吞掉)。

## 决策

删除该开关及其续跑分支(W970 批 A commit `083fa48c` 前身,DD-011 判稳轮询改造后其「验按钮-收起」职责已由 fail-closed 验证取代)。判据:

1. 存在前提消失:原子化后开店逻辑收敛到 `open_shop.open_shop`(幂等:已开→成功;未开→点击+等待+fail-closed 验证),无「轮询超时仍继续」的分支形态;
2. 离线测试环境的逃生需求由测试桩承接(桩显式模拟收起锚状态转移),生产路径不携带逃生开关——与测试纪律「生产模块对外副作用缺省关」同向;
3. 静默假成功是实机事故形态(竞速误关后以「店已开」假设读牌面,W970 轮 3 β 实证),保留即保留事故面。

## Considered Options

- **保留开关(默认关)**:生产路径携带死代码,测试桩化后永真分支 = 维护面无收益 → 否决;
- **改为配置项**:同上,且配置面扩散 → 否决;
- **删除,fail-closed 验证取代**(采纳):超时即 `round_retry`,不假成功;离线由桩模拟状态转移。

## Consequences

- 开店失败一律显性化(round_retry),由调用方(编排壳/未来流程层)决定重试;
- 离线测试桩需状态化(模拟点击后的锚状态转移),`test_cw_shop_refresh` 桩已随批 A 改造。

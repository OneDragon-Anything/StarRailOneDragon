# ADR-0574 — 入口链星琼详情弹窗守卫与交替循环上界闭合(T-98)

- **Status**: accepted
- **Date**: 2026-09-07
- **关联**: match2 列车补给弹窗挂点先例(app 首节点前移 + start op 纵深,2026-08-31)、`cw_screen_state.LOBBY_STATE_SCREENS` 前缀自动收屏机制、ADR-0517(单动作循环——本批不动对局内决策环,只修入口链)
- **方案与审**: `.debug/temp/currency_war/t98_popup_guard/方案.md` v2(实施唯一口径;同目录方案审 + 定点复核两轮,定点复核总裁决「可进实施批」)
- **触发证据**: 2026-09-07 实机事故,`.log/mcp_server.log` 时间线 + 现场截图(`.debug/sr_od_mcp/screenshot/screenshot_20260907_061729_276507.png`):星琼详情弹窗在场 → 入口链全锚失明 → 兜底空烧 60 步 → `推进到备战阶段超时` FAIL(06:14:38→06:16:52,≈134s)

## 1. 背景与问题(归层:入口链抗干扰面·路由层)

上局结束后新 run 启动,入口链干扰级联:积分奖励页吞掉开始点击(守卫 A 接住)→ 大厅残留误判逃逸(守卫 B 按设计工作)→ 退出到世界撞上列车补给每日弹窗(守卫 C 接住)→ **领取点击落在弹窗中央徽章区,命中其中的星琼图标 → 游戏打开货币详情弹窗**(机制推断,待受控复现实锤;实施批活体采样已两次复现「点中央 = 只开详情不领取」,见 §5)→ 星琼详情为模态弹窗,压暗+模糊背景,入口链全部背景锚点(备战标识/创业指南/前进按钮/教程提示)同时失明 → 无分支命中走兜底 round_retry,`_advance_steps` 烧到 60 具名超时。

缺口不在决策层/策略层/遥测层:哨兵 PATTERNS 已含「执行失败」,具名失败自动报警。缺口有两处——①路由层:守卫面没有「星琼详情」识别分支;②执行层子项:列车补给领取点击目标(中央徽章区)有撞星琼图标的几何风险。另发现既有列车补给助手返回 `round_wait`,框架对 WAIT 不计 retry 且归零计数(`operation.py` 重试段),其 docstring「不会无限空转」不成立。

## 2. 决策(裁决)

### 2.1 星琼详情弹窗守卫(路由层)

- **识别**:双文本锚 AND——`标识-星琼标题`(text=星琼,lcs 0.5,管召回;2 字 @0.5 是全家族最弱配置,单锚触发误配面过大)+ `标识-稀有货币`(text=稀有货币,lcs 0.75,管精度);双 id_mark 全中才算画面精准匹配,守卫触发同判据。同帧 OCR 有缓存,第二锚近零增量成本。建档:`currency_war_stellar_jade_detail.yml`,3 area(标题/稀有货币/按钮-关闭X 纯坐标,中心 (1463,347))。
- **动作**:点右上角 X 关闭(禁键令,不用 ESC;点空白关闭未采样不作默认手段);返回 `round_retry(状态='星琼详情弹窗关闭中')` 计入节点预算。
- **挂点 4 处**(与列车补给助手完全同构,均在列车补给检查之后插入):app `_enter_lobby` 首节点、`cw_entry_enter.wait_lobby` 纵深、`cw_entry_start.click_start`、`cw_entry_start.advance_to_prep`(主线,先于一切状态分支)。
- **形状**:模块级共享助手 `try_handle_jade_detail_popup`(与 `try_handle_train_supply_popup` 同签名同调用形态),不做通用弹窗关闭器(无任意模态弹窗通用签名,误关有意义弹窗风险真实;项目先例全部逐弹窗建档+专支关闭);识别参数全走 screen_info,第三个同族弹窗出现时升级为注册表是一次函数重构。

### 2.2 交替循环上界闭合(列车补给助手 `round_wait`→`round_retry`)

最坏组合 = 星琼详情叠在未领取的列车补给弹窗上,且领取点击始终「只开详情不领取」。若列车补给分支保持 `round_wait`:每圈「守卫 retry(+1)→ 关详情露补给 → 补给 wait(**计数归零**)→ 领取再开详情」,`node_retry_times` 在 0↔1 振荡永远到不了预算——**四个挂点全部无界挂死,比事故现状更差**。修法:列车补给助手同步改 `round_retry(状态='列车补给领取中')`,两分支都计预算后交替循环每圈耗 2 次,任一节点预算(默认 3/30/3/60)内必具名 FAIL,S1 任何结局下上界闭合。

### 2.3 白名单补漏(误路由防线)

`LOBBY_STATE_SCREENS` 补 3 条:`货币战争-星琼详情`(本批新建档)、`货币战争-星徽详情`(已建档同族弹窗,处理分支属同族泛化待办)、`货币战争-积分奖励`(入口链 3b 分支处理的局末奖励页)。三者带 `货币战争-` 前缀会被自动收屏,在场即误判「已在对局中」跳过 enter 直交 loop——与 match2 误路由同型,先行入清单防复发。

### 2.4 显式不做(挂账)

- **列车补给领取点击目标修正**(§4.4 方案项:中央徽章区 → 底部提示文字区 `文本-领取提示`):受 S2 门控,方案允许本批只落守卫+助手改形。实施批 S2 活体采样结论(§5)**支持该修正**,挂账给后续批:落码时 `test_cw_screens_entry.py` 两条既有锁(断言领取点击必须点「按钮-领取补贴」)按锁的存在性纪律重推语义后同步改锁+重写注释——注释里「点中央徽章」固化的正是本次事故证伪的假设。
- 星徽详情弹窗处理分支:同族泛化项,登记 CW 进度树。

## 3. 验收(锁与红证)

- **新测试 8 条全绿**:op 级真帧锁(弹窗帧→点 X→恢复到备战)+ app 首节点锁(守卫分支→重跑导航恢复)+ 白名单锁 3 条(星琼详情/星徽详情/积分奖励各一)+ fixture 非对局锁 + id_mark 真阳性 + 邻屏无碰撞。
- **红证**:①守卫移除(模块函数短路)→ op 级+app 级两条守卫测试红;②白名单移除星琼详情 → 名单锁+fixture 锁两条红。恢复后全绿。
- **既有锁同步(F1)**:app 级列车补给测试的 WAIT 注释重写为 round_retry 语义(断言 `not is_success` 对 retry 仍绿,不动);`operation.py` RETRY/WAIT 语义实施批亲读复核(定点复核待补项 1 收口)。
- **最硬验收(实机)**:①从弹窗死局现场单跑 `开始货币战争对局`——交替循环(领取→详情→守卫关闭)×2 圈耗尽 3 次预算,**20.4s 具名 FAIL(`星琼详情弹窗关闭中`)**,对比事故现状 134s 无名超时,上界闭合活体证实;②S2 采样后场景清洁,进入 op 14s 回大厅 + `开始货币战争对局` 45.3s `到达备战阶段`,入口链全链恢复。

## 4. Considered Options

| 方案 | 裁决 | 理由 |
|---|---|---|
| 通用弹窗关闭器(任意模态弹窗识别+关闭) | ✗ | 无可靠通用签名——背景失明只说明「有东西挡着」;X 图标跨弹窗通用性未采样,误关有意义弹窗(难度确认)风险真实;项目先例全部逐弹窗专支 |
| 守卫返回 `round_wait`(镜像列车补给旧例) | ✗ | WAIT 不计 retry 且归零计数,与补给分支构成无界交替循环;RETRY 计预算是有界具名 FAIL 的前提 |
| 单锚触发(仅星琼标题 @0.5) | ✗ | 2 字 @0.5 = 含任一字符即命中,全家族最弱配置,误配面过大;双锚 AND 同帧缓存近零成本 |
| 只修新守卫不动既有列车补给助手 | ✗ | 留下「守卫 retry × 补给 wait 归零」的无界交替循环,比现状更差;一行改形同步闭合 |
| 本批落领取点击目标修正 | ✗(挂账) | 受 S2 门控是方案自身条件;S2 采样已支持修正,但属执行层独立变更,按方案允许口径另行挂账,避免本批面扩大 |
| ESC 关闭星琼详情 | ✗ | 禁键令(前向兼容手机模拟器);X 坐标点击已足够 |

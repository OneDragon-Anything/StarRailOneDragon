# ADR-0331:退出 op 投资策略屏卡点机制根修(分支顺序 + OCR lcs 收紧)

- 状态:accepted
- 日期:2026-08-25
- 决策:见下「决策」节;落点 = `operations/entry/exit_currency_war_match.py`
  (分支顺序重排 + 结算按钮/备战阶段 OCR lcs 收紧)+ 测试仓
  (`test_cw_r317_exit_op.py`)。背景与证据详见 `deep_read/W71_报告.md`。

## 背景(现象与根因)

第三次实录(2026-08-25 04:0x,第三局清场):`ExitCurrencyWarMatch` 卡投资策略屏
**141x「等待」循环(444s+)**,零分支推进;画面 OCR 每轮都识别到「返回备战界面」
「请选择投资策略」「确认」(conf≈1),W69 已修确认按钮坐标手动两击
((460,475)+(978,984)) 有效 → op 立即走完失败链回大厅。**不是识别问题、不是
确认按钮坐标问题**——是分支顺序 + OCR 匹配阈值两个机制层缺陷:

1. **`:76「备战阶段」裸 OCR(lcs=0.5)在投资策略屏误命中「返回备战界面」**
   (真实首卡点):`find_by_ocr` 直接对每个 OCR 结果做 LCS 匹配、无
   `difflib.get_close_matches` 前置过滤(与 `round_by_ocr_and_click` 不同)。
   「备战阶段」(4字)与「返回备战界面」LCS=「备战」2字 → 2/4=0.5 恰达默认阈值
   → 每轮走备战分支 `btn_tap('esc')`(投资策略屏非备战,esc 无效)→ round_wait
   死循环。141 轮日志零 `[cw-exit]` 分支日志(esc 分支无日志)与此吻合。
2. **`:73「返回备战界面」全屏 OCR 点击落空**:该分支在前版位于投资策略分支
   之前,若画面到投资策略屏,会命中其右上角按钮文字并点击 **OCR 检测框中心
   (1790,57)**——但按钮热区中心 ≈ (1850,60)(像素实测:OCR 框 1717-1863 仅为
   文字,按钮底框 1780-1920 偏右 ~60px)→ 点击落空 → round_wait 死循环,且
   短路正确的投资策略分支(选卡+确认)。
3. **结算按钮 OCR 阈值过松**:`:50「继续挑战」`(lcs=0.5)与战斗暂停屏「继续
   战斗」difflib ratio=0.75 ≥ 0.6 cutoff 且 LCS 3/4=0.75 ≥ 0.5 → 误匹配 → 点
   「继续战斗」恢复战斗 → 退局打转 2min(实录 03:59:35-04:01:35 段反复
   「胜利结算 → 继续挑战」但画面是战斗暂停屏)。battle_loop 3b 早已对「返回
   货币战争」用 lcs=0.8 防「返回备战界面」,exit op 未同步收紧。

三个根因都在**分支判定/OCR 匹配的机制层**,不是坐标精度问题(坐标已由 W69/
W62 件3 修过且手动实证有效)。

## 决策

1. **投资策略分支(round_by_find_area area 定位)移到「返回备战界面」
   (round_by_ocr_and_click 全屏 OCR)之前**:投资策略屏是独立屏(3.16 建档
   实锤),右上角确有「返回备战界面」按钮文字;其正确退出 = **选卡+确认**
   (area 定位 + bug#1 mouse_move 缓解,手动实证有效)。分支在前可保证先被
   area 定位命中,不再被全屏 OCR 分支短路。
2. **`:76「备战阶段」裸 OCR 收紧 lcs_percent=0.8**:
   「备战阶段」与「返回备战界面」LCS=0.5 恰达默认阈值,收紧到 0.8 后投资策略
   屏不再误命中;真备战屏「备战阶段」全等 LCS=1.0 不受影响。
3. **结算按钮 OCR 统一 lcs_percent=0.8**(与 battle_loop 3b 同款):
   `前往结算/继续挑战/下一步/下一页/返回货币战争` 全部收紧;「继续挑战」与
   「继续战斗」LCS=0.75 < 0.8 不再误匹配。`返回备战界面` 分支同样收紧(防与
   「返回货币战争」共享子序列 0.5 误匹配)。

## Considered Options

- **只调「返回备战界面」点击坐标(症状)**:把点击点从 OCR 框中心挪到按钮热区
  中心 (1850,60)——被否:① 这修不了首卡点(:76 备战阶段误命中,根本没走到
  :73);② 热区坐标本身是 VLM/像素估算,再调又引入新的脆弱点;③ 根因是分支
  顺序(正确分支被短路)与 OCR 阈值(误匹配),坐标是次要的落点问题。
- **给投资策略屏建「返回备战界面」area 用 area 定位(部分症状)**:即便建了
  area,投资策略屏的正确退出仍是选卡+确认(手动实证),点返回按钮在退局语境
  下没有独立价值;且遭遇/补给屏已有该 area,本屏缺失恰恰说明之前就没走这条
  路。核心修法是分支顺序,不是把全屏 OCR 换成 area 点击。
- **只收紧「备战阶段」lcs、不动分支顺序(半程)**:能停 :76 死循环,但投资策略
  屏仍会被 :73「返回备战界面」全屏 OCR 点击落空卡死(实录 04:01:35 后画面
  恒为投资策略屏、:78 从未执行的另一可能路径)——被否:两个卡点同屏,必须
  一起修(分支顺序 + 阈值收紧),缺一仍会卡。
- **结算按钮继续用默认 lcs=0.5(不收紧)**:「继续挑战」误匹配「继续战斗」在
  实录中实锤(battle_loop 3b 注释也早有同类教训)——被否:误匹配导致战斗暂停
  屏被当结算屏点「继续战斗」恢复战斗,退局打转 2min。

## 影响面

- 行为变化清单:
  - 投资策略屏(独立屏):先走选卡+确认(area 定位)回备战 → 下轮备战分支
    esc → 放弃并结算 → 大厅。**意图内**(修复 141x 卡死)。
  - 备战屏:esc 分支仍生效(「备战阶段」全等匹配 1.0 ≥ 0.8);行为不变。
  - 战斗暂停屏:不再被「继续挑战」误匹配点「继续战斗」;改走 r279 分支
    (战斗暂停 → 撤退)或后续兜底。**意图内**(修复 2min 打转)。
  - 结算页按钮:全等匹配不受 lcs=0.8 影响,逐页推进行为不变。
- 测试:新增 `test_cw_r317_exit_op.py` 4 条(顺序锁 / 结算 lcs 锁 / 备战 lcs
  锁 / 投资策略屏 fixture 集成锁),r279 既有 6 条保持绿。
- 未变:`HandleInvestStrategy` 生产路径(投资策略屏正常运行仍走它)、
  `_overlay_confirm`、战斗暂停分支(r279)逻辑。

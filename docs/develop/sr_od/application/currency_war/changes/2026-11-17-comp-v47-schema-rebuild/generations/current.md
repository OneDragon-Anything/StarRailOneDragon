# 当前方案(v2 终稿候选——2026-11-17 第二轮融合案,演化循环收敛)

> 演化轨迹:v0(编排者初稿)→ gen-1 独立稿六维全胜融合为 v1 → gen-2 知情变异四项变动经裁决全部落定为 v2。
> 裁决细节:[gen-1-review.md](gen-1-review.md) / [gen-2-review.md](gen-2-review.md)。收敛依据:两案 13/17 字段逐字趋同,分歧全部落定为有事实源的可判定项;建议停轮,以本案进入落库批,后续结构变更走增量修订。
> 建模目标(用户裁定):**覆盖大部分普通玩家可实现的阵容路线,不求全**。

## 设计原则

1. 阵容定义 = 状态条件触发的目标态快照序列;时间过程(搜牌节奏/经济纪律/降级止损)归策略层运行时,叙事与存疑归 final_comps 文档层。
2. 名单功能分层:core(拿掉检验不过)/support(引擎件或死穴解药,按机制判不按出场率判)/凑件(公共表派生,不点名)。
3. 阶段拆分判据(V8 机器化):**加法升级=阶段**(新阶段名单 ⊇ 旧名单[core 键集单调增]且档位非降,状态条件触发)/ **重构=拆条候选**(名单或档位实质减换;帖量双强才立,悬殊只登主形态);**辖域边界:阶段从「选定该线」起算,选线前打工板归过渡库**(A2 打工组案例);V8 拦截=显式裁决点(import 报错+落库批记录拆条/辖域归位/确认特例,禁止静默改数据)。
4. 计数口径按注册表 count_mode 分派:TOTAL=人数∪佩徽者;STAR3(唯千星)=三星数∪佩徽三星者[社区待实机];双龙吟=尾注召唤特例(成员+后台召唤物,饮月 1 人即 2 档)。
5. 证据纪律:[图鉴]/[米游社] 可进字段值;[社区] 只进注释与风险清单。
6. A/B 双套装备不进 schema,主套 only; EquipPool 只表达单槽位级候补。

## 构件类型(3)

- `Cond`(状态条件):`('char', 角色名)` 已购入可上场 | `('equip', 装备名)` 已合成/获得且可穿;一件到手即触发(D1「1-2 甲低配局也成立」)。
- `Gate`(成立门槛,统一元组):`('命座', 角色名, N)` 账号命座下限(每账号一次) | `('菜单含', 菜名)` 本局菜单含招牌菜(每局开局) | `('奇缘星魂', 角色名)` 账号持有(每局开局;效果细节[社区],字段只承载门槛存在性)。登记判据:不可从注册表派生 ∧ 帖间一致「没有就不玩/账号限定」;「没有则降级仍可玩」不登(H1 黄泉奇缘星魂=降级);可派生门槛不登(D2 反击星徽=算术,V4 提示)。
- `EquipPool`:`tuple[装备名,...]` 有序候选取一(A1 第三件四选一/F-遐蝶追加三选一)。

## 库级成文规则

1. 两库分立:COMP_LIBRARY 全字段 / TRANSITION_LIBRARY 恒单形态,装备/站位/星级/ceiling 恒空(V9),永不锁定;过渡→终局流向归文档层指针表。
2. V8 拦截=显式裁决点:违例 import 报错,落库批记录裁决(拆条/辖域归位/确认特例注明),禁止静默改数据。
3. **Q7 消费契约**:成型只停「定向搜牌与凑档采购」,星级/装备/商店投入不受门控——契约写进策略层消费文档;E 线为现实必要性案例(结构性成型开局即真,误当全面停手则经济线被杀)。
4. 建库校验 V1-V10:唯一名;键∈注册表;档位∈layers 且 ceiling≥core;成型可行性按 count_mode(含双龙吟尾注特例白名单、STAR3 佩徽计数标[社区]);配方/星级/站位键⊆合法载体域;唯一装备派生集约束;enter_when 结构不变量;**V8 加法不变量(名单⊇/档位非降/core 键集单调增,含 ceiling 行)**;过渡库恒空+engine/bond 完备+ECONOMIC_BONDS∩伤害线 bond 键集=∅;人口≤13;公共表一致性。
5. 落库流程:多阶段条目先写末阶段再向前复制裁剪(防复制漂移,N3)。

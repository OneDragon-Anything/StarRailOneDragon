# 0004. 多模态 vision 必需,不只靠 MCP(含 vision 不可信边界)

- **Status**: accepted
- **Date**: 2026-08-04(形式化;原始补强 2026-07-12 起)

## Context
第 2 步「主观理解」原仅"读图(Read / vision)",太弱 —— OCR 看不见:图形 / 图标按钮、布局结构、状态图标(选中态 / 已读 / 可领)、模态性(遮罩)、角色朝向 / 场景类型。三个实测反面:
1. `scratch_card`(刮刮卡)刮态 vision 返 400 没重试就跳过 → doc 漏刮层布局细节。
2. 误把「大世界-普通」当独立画面(实为报刊亭是大世界子态)—— 只靠 OCR 没看布局 / 模态性。
3. vision 状态推理不可信:实拍随便观游历,vision 看「剩余 20 时 00 分」猜「制造区 2 已派遣」,实际是 `choose_period` 选的时间**预览**(未派遣态),那时间不是进行中倒计时 —— 真已派遣显示「提前收获」按钮(`choose_period` 检测它 → `already_dispatch`)。
4. vision 第 3 人称追尾视角盲区:`suibian_temple` 入口建档时 vision 判「角色背对随便观入口」,实际是**第 3 人称追尾视角** —— 摄像机在主角身后,看到主角背部 = 主角**正对前方**(狮耶 / 入口),vision 不懂第 3 人称语义误判「背对」,差点误导走「跨地图朝向重置」弯路。

## Decision Drivers
- **不漏视觉信号**:OCR 盲区(图形 / 布局 / 状态 / 模态性 / 朝向)只能 vision 看。
- **不盲信 vision**:vision 不懂游戏,状态 / 作用推理会瞎猜。
- **可重复**:每张建档截图都过 vision,不只靠 MCP analyze。

## Considered Options
1. **只靠 MCP analyze 的 OCR / area**:漏图形 / 状态 / 模态性。
2. **vision 必需 + 客观描述边界**(选中):每张都看,但只信客观描述、不信状态推理。
3. **vision 全信**:状态 / 朝向推理被瞎猜误导。

## Decision
选 2:
- **必须用多模态大模型 / 工具看图**(`analyze_image` / vision),**不能只靠 MCP `analyze_screen` 的 OCR / area**。**每张建档截图都要 vision 看一遍**。vision 调用失败(如 400)**必须重试**(换图重传 / 重新 capture),不能跳过。
- **vision 状态推理不可信,只信客观描述**:vision「描述画面有什么」(元素 / 文字 / 标记 / 颜色 / 位置 / 布局)**可信**,但「判断状态 / 作用」(已派遣 / 未派遣、按钮作用、是否可点)**不可信**(会基于看到的文字瞎猜)。prompt 要**客观描述**(「有哪些文字 / 按钮 / 图标?各自位置(x,y)?哪个元素有三角形 / 高亮 / 颜色标记?」),**别问状态推理**;**状态判断结合代码自己做**(看 op 代码里的判定 area / 返回标志,如检测「提前收获」按钮 = 已派遣 / 检测 duration = 选时间预览,而非靠 vision 看「剩余时间」猜)。
- **角色朝向 / 视角判据(vision 盲区)**:vision 对**朝向 / 视角**推断不可信(不懂第 3 人称追尾语义)。判据:**朝向以 OCR 交互提示(如「前往 XX」)+ 实际 interact 结果为最终判据**,别轻信 vision 的朝向推断。

## Consequences
- **正向**:不漏图形 / 状态 / 模态性 / 子态边界;客观描述 vs 状态推理边界清晰。
- **负向**:vision 调用成本 + 失败重试耗时;状态推理要结合代码(多一步)。
- **边界**:计数 / 对齐 / 颜色推理也不可信(同「不懂游戏」根因);坐标以数值对拍 GT,不用 vision 当裁判。

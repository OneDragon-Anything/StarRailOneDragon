## 指定复核点专项裁定

### ① W14 对齐口径的完备性：**不支撑——`node_hist_ord` 实际结构不承载逐节点对齐**

W14（details :150）口径：「决策时 `node_hist_ord` 尾部与环行序列逐节点对齐：产结算屏节点应各有恰一行、补给零行」。逐子问对照代码：

- **含类型与否**：`node_hist_ord` 定义于 `cw_game_state.py:2070`，类型 `int | None = None`，注释（:2064-2069）明确语义 =「本 run 已见最大有效节点序 effective_ord」的**标量游标**，是派生推进去重键 `(run_id, effective_ord)` 的 run 内载体。它是单个整数：无「尾部」可言（序列才有尾部），不含任何节点类型信息。类型在 GameState 只有「当前节点」的 `node.kind`（经 `_write_derived_node_type` 直定），没有按序号的类型历史。「逐节点对齐」需要「每个已见节点的类型序列」做基准，GameState 中不存在该结构（全局 grep `node_hist|节点历史|node_sequence` 反查确认；`read_node_sequence` 是读屏 CV 函数，非持久状态）。
- **补给/奖励节点是否入序**：`node_hist_ord` 由四条派生腿推进（:2528/:2567/:2642/:2678），对补给/奖励/战斗一视同仁（序号 +1）；而环只收产结算屏行（补给零行）。即使把标量硬解成「应有一行的节点计数」，补给节点在序号序列里有、在环里没有——两个序列的节点集**不同构**，按「每序号恰一行」口径补给节点永远缺行 → 恒不对齐。
- **跨位面边界行为**：`node_hist_ord` 坐标系 = `(plane-1)*9+round`（:2064 明文）。P2 真值 7 节点（plane_schedule_observed.md 地面真值），P2 尾序号 = 16，P3 首序号 = 19——序号 17/18 从不存在，序号带洞。且该坐标系与 `node_t_of`（前序位面**实际长度**和 + round，cw_plane_table.py:88-107，同文件 :92-94 明言替代表的正是 `(plane-1)*9` 字面量）不一致——仓库里两套全局节点号并存。更进一步，弹窗腿推进 = `effective + 1`（:2560），位面切换时会产出 17 这类与下一顶栏直读（19）冲突的候选——这是现役派生腿自身的张力，W14 把对齐挂上去即全部继承。
- **对齐失败形态是否全部落入弃权暗装**：失败方向安全 ✓（不对齐 → 弃权暗装，fail-closed）。但基准缺失的实际后果是**恒不对齐 → 恒暗装**——判据结构性永不工作，与 design §1.1 点名废除的「冷启动死锁」同构的另一形态（那个死于样本为零，这个死于对账基准为空）。方向安全不等于设计目标达成。
- **结论**：M12-2「改对齐口径」的修复**修错**——第 12 轮修正方向给的四件套（计数器载体/去重计一场/奖励行辖域/P3 处置）里，本轮文本把「计数器载体」落到了一个不存在的结构假设上，违反 iteration-design 写作硬规则 2（实现者无需再设计：实现者拿到 W14 无法开工，必须自行发明对齐基准）。修正方向：对齐基准换源——第 12 轮自己建议过的「结算序列闩锁（每场战斗首个结算帧 +1 的计数器，环写点同步推进）」仍是可用候选；或改为环自身可验证的弱不变式（窗口两行的场键连续性 + 环行密度核对）；无论哪种，需与 M13-1 的类型集修正同批定稿。

**H13-2｜数量级核对与各档开闸判读线丢「遭遇 −4」：门槛数字按原始加成计算，与判据自身净值语义矛盾**

- 位置：details §3 :71「Δ=10 → g≈1.660（可及门槛 f_min ≤ 0.602）；Δ=20 → ≤ 0.363；Δ=30 → ≤ 0.219」「其三门槛 = f_min ≤ 0.363——标定批实测落入即开；其四门槛 ≤ 0.219」；同段自声明「以『窗口战斗与遭遇节点间旗牌零增长』为简化前提」。
- 内容：判据语义已定谳为净值 = 档位加成 + 遭遇 −4 + 连胜增量（契约 3 :22），判据式比值 = `1.052^(D_win − D_enc(t))`，其中 D_enc(t) 是**遭遇节点**难度（含 −4，economy.md:111）、D_win 是窗口普战（无 −4）。零增长前提下比值 = `1.052^−(tier−4)`——例证 Δ 应取 6/16/26，文档取了 10/20/30（对应净值=tier，即要求 Δq+Δs=+4 的特定场景，与「零增长」前提互斥）。实跑（`uv run python`）：其二净值门槛 `1.052^-6 = 0.7377`、其三 `1.052^-16 = 0.4444`、其四 `1.052^-26 = 0.2677`；文档线 0.602/0.363/0.219 全部偏严。
- 影响：①「其三门槛 = f_min ≤ 0.363——标定批实测落入即开」是承重的开闸判读线：标定产出 f_min ∈ (0.363, 0.4444] 时按现文错误维持其三不可及（保守向错，但数字错即错）；②f_min=0.5 的最大可及净值 13.67 →「其二可及、其三不可及」定性结论碰巧同向（6 ≤ 13.67 < 16），不受影响；③W1 锁为三常量注入测试语境，断言机制不依赖真实净值，不受影响。
- 修正方向：§3 :71 例证与门槛按净值重算（0.738/0.444/0.268），或显式声明例证 Δ 口径 =「净值在 Δq+Δs=+4 时的上界场景」并给零增长主线数字；「标定批实测落入即开」的判读线同步改；E-3 量测表加一列「净值口径门槛」防复用旧线。

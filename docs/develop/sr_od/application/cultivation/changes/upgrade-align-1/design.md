# 迭代1设计:角色/光锥升级 op 对齐移植(就地记名 + 幂等记账 + 补料优先级口径)

> 状态:草案 v2(吸收对抗审查 r1:B1/B2 两阻断 + S1-S9 建议)。范围:char/LC 两 op 文件 + character_ascend.yml 建档(经 MCP 同步合并缓存)。trace 全部对齐项归迭代2。

## 1. 背景与目标

三升级 op 同构性审查确认两处实质缺口落在 char/LC:

- **G1**:char 的 ALREADY_ASCEND 直入分支与 None 帧两条探针分支**均不读角色名**——手动刷取路线打完一场退回大世界后,重走入口链因无记名失败,白烧一场开拓力。LC 直入分支已修(c0dd8d2c6),但其 None 帧探针分支(标题-材料补全弹窗/标题-光锥详情→ALREADY_ASCEND)同样不读名——**G1 在 LC 有残留**,本迭代一并对齐。
- **G2**:LC 券确认**预记账**非幂等——确认点击未生效、重入轮弹窗+确认钮仍在场时重复计轮计次;开拓力拦截分支只回滚次数不回滚轮次(统计虚增)。char 已有事务式记账(幂等判据+成功证据 commit+拦截仅清判据位),LC 对齐。
- **口径**:负责人裁定三线统一补料优先级 = 通用材料补全 → 快速刷取券 → 手动战斗。char/LC 行为已符合,本迭代做 docstring 声明;trace 行为翻转归迭代2。

## 2. 改动设计

### 2.1 G1:char 就地起跑记名 + fail-fast(三支柱完整平移)

LC 就地读名能成立靠三件套(a2e043057 建档+双屏 helper、c0dd8d2c6 入口分支),char 三块都要:

- **支柱①建档**:character_ascend.yml(角色-等级提升)现无任何读名区——经 MCP 登记读名区-左上(rect 与 LC 先例同位 [95,40,330,105],先例=character_detail.yml:306-312 与 light_cone_ascend.yml:537-550 的同位矩形)。实机核验说明:全员满级导致该画面暂不可达(只能从详情页升级按钮进入),登记依据=同一名字条在角色详情/光锥页签/行迹面板三画面实测同位;待任一非满级角色出现时实机复核一次。
- **支柱②helper 双屏**:`_read_character_name`(upgrade_character.py:210)现硬编码单画面(角色-详情);平移 a2e043057 形状改为双画面迭代 `(_DETAIL_SCREEN, _ASCEND_SCREEN)`(常量名以代码实际为准),任一命中即返回。
- **支柱③入口闸,覆盖全部 ALREADY_ASCEND 出口**:直入分支(:289-291)、None 帧探针「标题-等级提升」(:306)、None 帧探针「标题-材料补全弹窗」(:307)——三处出口统一:先读名,读名失败且 `farm_dungeon and not use_fast_ticket` → `round_fail`(消息与 LC 对称);实现可提炼小函数供三处复用。char 详情 TAB 起点既有读名+fail-fast(:320-326)不动。

测试(`test_upgrade_character.py` 新增 2 条,镜像 LC :1133-1179):
- 就地起跑读名成功 → ALREADY_ASCEND 接管 + 记名 + 读名恰好一次;
- 就地起跑 + 手动路线 + 读名失败 → 入口快速失败(零消耗),消息含指引。
- **harness 前置**:char 桩 `_fake_char_name` 无读名计数,先给 harness 加 `char_name_reads` 计数(对齐 LC 桩形状)。

### 2.2 G2:LC 券确认记账对齐 char 事务式口径(删预记账,单一证据族)

- **删预记账**:upgrade_light_cone.py:612(`_farm_rounds += 1`)与 :616(`_farm_draws += ...`)删除——确认点击轮不入账。
- **幂等判据**:确认分支加 `_farm_times_set == 0` 判据(char :655 同款)——已设过次数的重入轮跳过设次数、只重发确认点击。
- **成功证据 commit**:提炼 `_settle_farm_accounting` 式辅助(char :668-681 同款:判据位非零才 `rounds+=1`/`draws+=times_set` 并清零);**唯一成功证据族 = 快速刷取结果框在场**(char :648-650/:664-665 同形——不引入「弹窗+确认钮均消失」证据,防确认框已关但领奖未完成的窗口期错账);两个 settle 调用点都在券确认刷取节点内(确认重发轮成功后/结果框轮),刷取返回分类节点的结果框分支保持只关闭不记账。
- **开拓力拦截 = 仅清判据位**(:601-607):POWER_BLOCKED 时**只做 `_farm_times_set = 0`**(char :642 同款「未成交未记账,本轮作废,不动历史账」)——删既有 `draws -= times_set` 回滚语句,预记账已删,无任何回滚。**禁止出现对 rounds/draws 的减法**(会抹历史账/出负数)。
- **LC None 帧探针读名残留一并修**(:238-242 两探针出口):与 G1 同款处理——出口前读名+手动路线 fail-fast。

测试(`test_upgrade_light_cone.py`):
- **扩展现有** confirm_farm_wait_rerun_guard(:484-552)用例:补账本断言(draws/rounds/times_set 终值),不新增近重复用例(测试要少);若核对发现「首点 miss 重发」场景未被既有用例覆盖,补一条(已覆盖则不重复——实现方按桩现况裁决并说明);
- **新增 1 条** 开拓力拦截整体作废:预置 `_farm_draws=3`/`_farm_times_set=3` → 触发拦截 → 断言 `draws==3、rounds==0、times_set==0`(镜像 char :689-702 全量断言——「不虚增」判据抓不住负数腐蚀,必须全量断言);
- **既有用例预期零红**(确定性预判)::484-552 用例1 `rounds==0` 因 settle 空判据仍成立;:407-451/:453-482 的 `rounds==1` 依赖 **helper success 记账点存在**——实现时漏挂该点这两条必红(天然绊线,复现 char「生产时序/桩时序」教训,不许为绿删断言);:961 手动路线不受本迭代触碰。
- **LC 探针出口用例 1 条**:None 帧探针命中 + 手动路线 + 读名失败 → 入口 fail-fast(LC harness 的 screen_utils.find_area 无条件 TRUE 桩即可触发探针分支;char 侧同理用 `_fake_check_screen` 设 screen_now=None 构造,两文件各 1 条)。

### 2.3 补料优先级口径声明(docstring,零行为改动)

char(:42-47)与 LC(:40-43)既有「补料路线与优先级」段就地修订,措辞按各自实际行为分写、共同引用同一裁定:

- 共同裁定句:**补料优先级(负责人裁定):通用材料补全 → 快速刷取券 → 手动战斗。通用材料非稀缺优先消耗;券免战斗次之;手动战斗场耗开拓力最后。**
- char 后缀:补全按钮在场=缺口可由合成覆盖,授权补全时优先补全、不刷取(刷取会被游戏以无可刷缺口拒绝);未授权补全时判停。
- LC 后缀:授权补全时优先补全;未授权补全时转刷取路线,由游戏的无可刷缺口 toast 探测兜底判停;券/手动为配置二选一,无自动降级。
- 用词规范:全文用「快速刷取券」「手动战斗」,不用简称。

# ADR-0452: 板面 SIFT 识别的位置感知裁决(中心归属门)与变体模板逐文件掩码

> **引用勘误(2026-09-04 ADR 存量 review)**:`.debug/` 归档 → 本目录(decisions/)同名 ADR。文内出现处按此对照读取。

- 日期:2026-08-28
- 状态:已采纳
- 关联:ADR-0385(布局选档)、ADR-0390(真窗口勘误)、2026-08-26 变体机制(W160 停机事故)、2026-08-26 live_only 定策

## 1. 背景与问题

33 帧板面基准(`.debug/temp/currency_war/w531_sift_benchmark`,33 帧/126 占用板面槽/480 空槽)实测板面 97.6%(123/126),三例病灶:

1. **大丽花→花火混淆**(后排7槽-P2开局局 后排-2):角色卡宽(~170px)> 槽窗宽(~142px),槽裁片左缘渗入邻卡 28px 残条;花火模板以 18 内点亮过真身大丽花(11 内点),其中 12 内点落在左缘渗漏带。既有相邻幽灵去重只管**同名**对(此案两角色异名,不触发)。
2. **那刻夏读空**(equipped_front1_feixiao_2 前排-3):真命中 19 内点被歧义比拒 —— 第二名 艾丝妲#1(board 变体模板)13 内点,经取证其内点全部落在**卡框/角标 UI 铬**(模板四角/右带/底带),非角色特征。根因:`load_avatar_templates` 只按 `mask.png`(尺寸只配主档 raw.png)加载掩码,变体 `raw_*.png` 形状必然失配 → **全部变体无掩码入库**,UI 铬特征进描述子(银枝的 `mask_plaza.png` 是该约定的既有资产,加载器从未读过)。
3. **开拓者·欢愉读空**(后排8槽-全位验证 后排-6):plaza 主档 73 内点强命中,但该角色存在现场变体(raw_shop)→ live_only 按「有变体即拒主档」拒收。变体在本帧仅 6 内点(商店卡域 vs 板面 3D 站立小人,不同域),门把强同域信号误杀。

## 2. 决策

三件根因层修法(全部经 33 帧基准全量重放验证):

### 2.1 变体模板逐文件掩码(`currency_war_char_id.load_avatar_templates`)

变体 `raw_<域>.png` 优先读同目录 `mask_<域>.png`,缺失退 `mask.png`(形状须一致,不一致仍按无掩码)。新增资产:`mask_board.png`×6(艾丝妲/风堇/卡芙卡/乱破/万敌/爻光)+ `mask_shop.png`×1(开拓者·欢愉)。board 掩码为几何标定(边框 8px/右上角标盒/底带 y≥122;逐像素 std 法因槽位亚像素偏移底噪高不可分),shop 掩码为 15 张商店牌裁片数据驱动(std<12)。

### 2.2 部署排中心归属门(`cw_identity_obs.identify_slots` 新参 `center_gate`)

部署排(前排/后排)识别改为:每槽在横向扩展窗(pad=35px)内取全库假设列表(新 `identify_hypotheses`,全扫描无剪枝),三重位置裁决:

- **中心归属**:homography 投影模板中心 x 落在本槽核(原 rect)内才认领 —— 渗漏假设的中心在邻槽,几何出局,与内点数无关;
- **核内内点计分**:裁决分数 = RANSAC 内点中场景点落在本槽核内的数目(证据落点须在本槽);
- **退化守卫**:内点场景坐标去重 < 8 的假设丢弃(RANSAC 可能把一片模板点塌缩到单场景点,内点数与投影中心均为伪值;佩佩局空槽 忘归人 21 内点中 19 点塌缩实证)。

认领后的假设表走与旧路径**同一套**决策语义(`_resolve_best`,自 identify_character 抽取共用:阈值/歧义比/色相仲裁);色相仲裁喂原槽窗裁片(扩展窗含邻卡会带偏同型异色对的色相符号,狸猫对实测翻案)。备战栏/商店卡窗与卡同宽无渗漏,保持旧路径不变。

### 2.3 live_only 强主档例外(`_LIVE_ONLY_PLAZA_STRONG = 40`)

live_only 拒主档的语义精化:主档内点 ≥ 40 时收。依据:跨域弱命中带实测上限 29(33 帧基准空槽全库最高内点;run20 时代 11-26),真命中中位数 ~45 → 40 居中,高于弱带 11、低于中位数;真命中 30-39 的变体角色仍被拒(漏读方向,对账可见)。

## 3. Considered Options

- 病灶1:①收紧槽 rect(波及多消费点,须单独立项,不采);②匹配后按内点位置过滤(位置信息生产现弃,方向对但仅剔花火不够 —— 大丽花本窗仅 11 内点 < 15,仍读空);③**扩展窗 + 中心归属 + 核内计分(采纳)**:渗漏带本来就是邻卡地盘,把窗开到能看全本卡、再按几何认领,内点数与归属同时治。
- 病灶2:①给该对做专项判别(打地鼠,不采);②降歧义比(禁);③**变体掩码补全(采纳)**:非判别性 UI 特征不该进库,一对治全库。
- 病灶3:①补板面变体模板(只治一角色,下个新角色复犯,不采);②关 live_only(禁);③**强主档例外(采纳)**:门的意图是拦「弱」跨域命中,73 内点不是弱命中,按带间隔立门槛。

## 4. 影响

- `read_deployed_chars` 语义变化:部署排识别走中心归属门;备战斗/商店不变。
- 变体模板入库特征变少(掩码剔 UI 铬)→ 全部变体命中内点数下降但判别性上升;全基准重放:板面 126/126、备战席 224/224、商店 15/15、空槽零误检。
- 生产语义注记:GT 逐开拓者形态标注 vs 生产「按排归一形态」(2026-08-16 用户裁定)存在口径差 —— 欢愉摆前排时生产报记忆(按设计);基准对拍按开拓者等价式计。

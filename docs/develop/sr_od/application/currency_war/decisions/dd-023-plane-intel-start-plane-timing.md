# DD-023 · 位面情报采集时序修正(备战帧先定起始位面)

- 状态:accepted
- 日期:2026-09-03
- 关联:DD-017(接管补采挂 PrepDirector 观察段)/ ADR-0398(徽章态)/ W901(位面级结论);第六局接管实录 `.log/mcp_server.log` 14:16:52-14:17:16

## 背景与问题

第六局接管补采 37s:接管链直接进位面详情逐位面盲采,位面1「节点条未读出
(切卡动画中)」经等待门间隔重试烧 7s+ 后记 None 放弃;位面2/3 各 ~5s。
用户领域知识裁决两点:

1. 中途接管的局,**前面的节点已经通过、节点条上会变暗**——已通过节点变暗
   导致详情条识别不出来是**正常态**,不是「切卡动画中」,不该反复重试等待;
2. **时序应该反过来**:进位面详情**之前**,先在外面(备战画面)识别当前
   节点(备战节点条可读,如「2-2」)→ 由此得当前位面与已通过位面 → 详情内
   **只采当前位面及之后的位面**(如当前 2-2 → 位面1 跳过,从位面2 开始采)。

## 决策

1. **起始位面裁剪**:接管链(cw_loop `_takeover_collect_if_needed` / 独立
   入口 `CwEntryPlaneIntel`)在备战帧稳定后先 `read_phase_round` 现读当前
   位面,以 `start_plane` 构造参数传给 `CwScreenPlaneIntel`;op 备战入口
   再现读兜底,仍无则全量采集(备战识别失败的保底语义,不发明跳过)。
2. **skip 判据翻新**:`decide_plane_skip(plane_no, start_plane)`——
   `plane_no < start_plane` 一律跳过(已通过位面不重采,session 侧这些位面
   本来就该有旧数据或不可知);**删除旧「台账缺值降级补采」分支**(变暗态
   低置信重采正是第六局浪费的来源)。
3. **删除「切卡动画中」重试等待**:采集循环内节点条读不出 → 直接
   `_conclude_plane_unreadable` 位面级结论(记 None 推进,保留对账语义),
   不经等待门;`_nonclean_read_gate` 收敛为备战入口路径专用(conclude_plane
   参数删除),保留帧稳定性提前放弃与宽上限。
4. **用户定值等待**:进位面详情开屏 ~3s(`_DETAIL_OPEN_WAIT_S`);详情内
   点位面卡切换后 2s 即读(`_PLANE_SWITCH_WAIT_S`)。若实测仍慢再排查
   识别效率,不预加等待。

## Considered Options

- **维持现状(等待门调参)**:拒——变暗是正常态,调等待参数治标,重试
  预算与耗时照旧浪费;根因是「采集范围未按当前位面裁剪 + 把正常态当动画」。
- **只删重试不裁剪**:不够——位面1 仍会被尝试并落 None,而当前 2-2 时位面1
  的 boss 本可从台账/不可知语义跳过,采集耗时白白多一位面。
- **裁剪 + 删重试(采纳)**:治本——范围与等待两处都按用户裁决的领域语义
  重排;备战识别失败保留全采回退,无真值不发明跳过。

## 后果

- 接管补采耗时:跳过位面零点击;当前位面读不出时结论耗时从 ~7s 降至一次
  读数判定;实测留待下一局实机数据。
- 旧锁改写:test_cw_plane_p2.py(legacy 桶)skip 真值表/详情侧结论锁随语义
  翻新;当前语义锁落 test_cw_plane_intel_start_plane.py(活跃桶)。

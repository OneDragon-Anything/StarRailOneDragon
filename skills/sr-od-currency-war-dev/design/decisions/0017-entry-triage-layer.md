# ADR-0017: 入口分诊层(任务轴→工作流轴的翻译器)

- **Status**: accepted
- **日期**: 2026-08-25

## Context

skill 触发场景多样(改策略/判读/实机运维/sim/收账/阵容/数据/编排/文档,九类都在 description 触发面内),但 SKILL.md 按工作流轴组织(ADR-0002),入口只有开发循环一条路——8 步 checklist 挂在最前,导读句「没做完 8 步不算一轮完成」语义含混。窄任务入口(新会话只判读一局/哨兵 exit 只需运维响应)要靠标题自推断落点,存在两类误用风险:①窄任务误把 8 步当万能门,或不知道自己的门(判读三问/重启四步/验收单)在哪;②非循环任务不知该不该走 checklist。

结构事实:SKILL.md 触发时全量注入——正文内分流的价值是**注意力路由**(当次主场在哪、该走哪个门),不是 token 路由;token 分流只发生在 references(按需读)。

## Considered Options

1. **任务型重组**(反转 ADR-0002):否决——开发循环是主场景,checklist 时序是历届漏步(漏判读/漏同步)的解药,任务分章拆散时序换回老病。
2. **现状不动**:标题已清晰,全文注入后 agent 大多能找到;但两类误用风险仍在,各任务的门无入口级可见性。
3. **入口分诊表**(选):任务→主节(含该任务的门)→细则 三列,~1KB;不动工作流轴,是任务轴到工作流轴的翻译层。配一行注:开发循环轮永远从 checklist 进(它内部已含各步),分诊主要服务窄任务与新会话入口。

## Decision

选 3。分诊表放导读句与 checklist 之间;导读完成门措辞收窄为「开发循环轮没做完 8 步不算完成」。门在分诊表只报名字,定义仍在各节(防双源)。**分诊行的归类判据 = 触发条件,不是内容主题**:带模式前提的行(如收 worker 账——worker 仅存在于编排者-worker 架构,即自主推进模式)归入该模式行,不按「验收」主题单列(首版曾误单列,用户点破;节标题同步标注模式前提)。第二实例(同日):哨兵报警消费协议本体在 autonomous-loop(正确——哨兵仅长时自主推进时武装,报警是编排事件通道的输入,与 worker 同构);但分诊表曾把「哨兵报警消费→autonomous-loop」挂在实机运维通用行的细则列——按触发条件应归自主推进行。保留的例外:实机运维节监控三层条目内的指针(武装→消费上下游互指,内容内部导航,非分诊归类)。

## Consequences

- 入口有三个互补路由器,查找键不同:**任务→节**(分诊表)、**步骤→节**(checklist 行内 §链)、**知识→位置**(单一源地图)——新增任务型入口须进分诊表(同地图「新增单一源须进表」规则)。
- 与 ADR-0002 不冲突:工作流轴仍是正文骨架,分诊表只是给任务轴入口装了指路牌。
- 各任务门的定义保持单一定义点(各节);分诊表条目与节标题漂移风险同 checklist §链,靠「改节名同步全链」纪律。

# 跃迁抽卡(消费路由)

> 画面建档细节走 MCP `get_screen_detail`(画面名:'跃迁'/'跃迁-星缘相邀');本档只管操作路由、端到端流程与消耗红线。2026-11-12 全链实机跑通(单抽/10连/兑换/四种展示形态)。

## 1. 机制速览(实机实证)

- **池子六类同页**:左侧列表切池——角色活动跃迁×2、光锥活动跃迁×2、联动跃迁(如 Fate[UBW],长期开放)、常驻跃迁(永久开启)。数量与顺序随版本变。
- **票种三色**:角色池/联动池 = 星轨专票(黄);光锥池 = 星轨专票·武意(暗红);常驻池 = 星票(灰蓝)。160 星琼可兑 1 张对应票,跃迁1次耗 1 票、10 次耗 10 票(不足票以 160 星琼/张抵扣,游戏弹确认)。
- **星缘相邀**:角色活动/联动池抽到 5 星角色时的自选补偿名单(玩家在「跃迁-星缘相邀」页编辑,bot 不代编辑)。
- **满魂 4★ 转化**:已满星魂的 4★ 角色再抽到时弹角色详情页并自动转化为 20 未熄的星芒/余烬(实测:艾丝妲满魂)。

## 2. 消耗红线(在通用红线之上加严)

1. **跃迁1次/10次按钮 = 消耗控件**:点击即扣票/扣星琼(抽卡无支付确认弹窗,一点就扣)。**agent 不得自行发起抽卡**;收到用户抽卡请求时,池子与次数(1/10)必须逐次获用户明确确认,确认后才调 WarpOp(抽卡决策评估归 sr-od-game-coach)。
2. **星琼兑换的授权口径(负责人裁定 2026-11-15)**:**用户说「抽 N 连/N 抽」= 专票+星琼合并够 N 张即为授权**——票不足时直接传 `allow_jade_exchange: true`,op 自动点游戏兑换弹窗(160 星琼/张),无需再逐次问「要不要用星琼补」。**古老梦华不在此口径内**(充值/月卡货币,囤皮肤玩家重灾区),仍每次单独确认。op 代码默认保持 false(自动化安全底线),授权语义由调用方按本口径赋值。
3. **古老梦华是三次消耗决策,默认保护**:星琼也不足时游戏弹「星琼不足,是否使用 X 古老梦华兑换」(1 梦华=1 星琼按需补;古老梦华官方英文 **Oneiric Shard**)——只有用户明确授权才传 `allow_oneiric_exchange: true`。**古老梦华只能充值/月卡类途径获取,部分月卡玩家专门囤它兑换皮肤**——默认全程不碰,每次单独确认。
4. **商店兑换专票是独立消耗决策**:余烬(月限 90/张×5)/星芒(不限量 20/张)渠道的兑换各自须用户授权才调 `ShopExchangeTicketOp`。**补票推荐优先级:限量(余烬,月度额度不用就浪费)→ 不限量(星芒,抽卡副产物)→ 古梦(真金白银,末选)**——向用户提供补票选项时按此排序并说明理由,拍板归用户。
5. 「查看详情」「星迹重温」等零消耗页面可自由探索,但见 §5 坑位清单。

## 4. 端到端流程(用户说「抽一发/十连」时的标准编排)

1. ☐ **获取卡池信息**(用户没指明池子时):米游社 gacha_pool 接口拿当期池子清单与 UP(§3 路由行,零游戏依赖);用户指明了池子则跳过。
2. ☐ **投入评估**(用户问「该不该抽」或拿不定主意时):交 sr-od-game-coach——读当期 UP 角色档(调研轮次)+ 断点表档位判定 + 账号名册查体系持有,产出「建议抽/不建议 + 理由 + 星魂路线」;**建议归 coach,拍板归用户**。
3. ☐ **对齐意图**:与用户确认池子与次数(1/10)。
4. ☐ **读资产对账**:跑 `ReadWarpStatusOp {back_to_world: false}` → data 里的 pool_type/special_pass/standard_pass/stellar_jade——确认当前池是目标池、票够不够。**按负责人裁定(2026-11-15),「N 连」请求下专票+星琼合并够 N 张 = 直接抽(`allow_jade_exchange: true`),不必逐次问兑换**;专票+星琼都不足时才停下,按推荐优先级向用户列出补票选项(顺序:限量→不限量→古梦),等用户选择,不得默认任何一种:①**商店余烬兑换(限量,优先推荐)**——90 余烬/张每月限量 5 张,月度额度不用就浪费,先读剩余次数与余烬数量;②**商店星芒兑换(不限量)**——20 星芒/张,抽卡副产物材料;③**授权古老梦华(末选)**——充值/月卡货币,囤皮肤玩家重灾区,每次单独确认;④放弃/攒票。
   - 补票选项的查看路径:用户确认「看看余烬/星芒够不够」后,跑 `EnterShopFromWarpOp` 进商店 → `ShopSwitchTabOp {tab: ash}` 切余烬兑换 → data 直接返回余烬数量与专票月限剩余(「可兑换:5/5」OCR 直读)——**在抽卡画面看不到转化材料数,必须打开商店才能确认**。
5. ☐ **选池**(如需):手动点列表 slot + 识别验证当前池名(§3 切池行)。
6. ☐ **执行**:`run_operation('WarpOp', {times: N, allow_jade_exchange: <按授权>}, block=false)` 后轮询 `get_run_status`——10 连全程 17-43 秒(跳过流,2026-11-15 实测两发)/90-150 秒(旧逐件翻页口径),仍建议非阻塞发起后轮询。**成功后停在「跃迁-结果总览」页**(单抽回跃迁页)。
7. ☐ **截图汇报 + 对账**:`capture_game_screen` 把总览页截图展示给用户,按三档口径汇报(§5);读数对账消耗(票数扣减/星琼扣减)——注意读数 op 会导航,等用户看完/明示收摊后再跑。
8. ☐ **收摊与消耗报告**:用户明示结束抽卡后跑 `ReadWarpStatusOp {back_to_world: true}` 回大世界;如实报告消耗(票/星琼/进度增量)。

## 5. 坑位清单(实证)

- **「查看详情」是内嵌网页**:实测点击后画面卡在模糊加载帧不动(网络慢时长时间不回),ESC 可退出——bot 不进此页,概率知识走文档。
- **「星迹重温」动画页的 × 直接回大世界**(不是回跃迁页)——误用会打断导航链。
- **UP 名/剩余时间位置随池型漂移**(信息卡两型布局):固定 rect 读数仅对部分池成立,通用读取需全屏 OCR。
- 光锥池无「角色试用」按钮;常驻池无活动标签、无剩余时间行、货币栏少进度条——判池时把这些 sub_state 当信号。
- 顶部「N/3200」进度条是商店「万象和鸣」活动入口(点击跳商店-推荐商店),不是星琼余额。
- **展示类画面普遍对极短点击不响应**(结果画面「点击任意处继续」/兑换弹窗按钮/角色详情页中央):controller.click 默认 press_time=0 点不动,必须带 0.1s 按压时长——WarpOp 已内置,复用时勿回退到 round_by_click_area/find_and_click(内部固定 press_time=0)。
- **框架 until 模式的假满足陷阱**:round_by_find_and_click_area 的 until 判据若依赖「文本消失」,OCR 偶发漏检会误判满足造成假成功——关键闸口(gate)用「显式按压点击 + 手动验证消失」替代框架 until(WarpOp 兑换闸已内置,复用时勿回退)。
- **画面判定 area 禁切割整行文本**:id_mark rect 只框整行正文中段片段时,裁切边缘识别必然失败(兑换弹窗实测)——文本锚 rect 框完整行。
- **货币数字读数的引擎边界**:全图 OCR 能检出多位数(「12183」「13」)但漏检孤立单字符(个位数票数);裁剪小图的 det 响应随输入尺寸浮动(对「12183」小图反而检不出),3 倍放大对单字符偶有检出但不稳定——ReadWarpStatusOp 用两层取数(全图过滤→3 倍放大兜底)已到 OCR 路线上限,**治本=数字模板匹配(0-9 模板×双区域)**,首次强需求时再建。货币 area 矩形已视觉校准且语义为「图标右缘→胶囊缘/符号前」(纯数字展示区),rect 不是嫌疑项。
- **10 连的转化卡面可点击、会误入角色详情页**:抽到满魂 4★(如艾丝妲 E6)再获得时,逐件展示的转化卡面在中央点击下会进入养成系统的「角色-详情」页(游戏不会自动弹,是误点进来的)——现行推进 = 未识别帧点右上角跳过,已不产生中央点击,坑源不触发;「角色-详情」屏检测+关闭自愈保留当防线。**跳过与总览页右上 × 同位异钮**:跳过点击只在「左上无「结果展示」标题(=非总览页)」的未识别分支发生,总览页被上方精确分支先行分流、永不进该分支;未识别帧点击前存图留证(同位误关的审计线索)。结果总览页的关闭归用户/收摊流程,op 不代点。
- **兑换弹窗文案随缺口数变化**:「消耗480个星琼购买3个」(缺 3 张)vs「消耗1600个星琼购买10个」(整连兑换)——判定锚用「星轨专票不足」文本,不锚数字。
- **兑换确认后件数 ≥2 会弹「获得物品」奖励展示**(点击任意处关闭;1 件不弹)。该弹窗关闭瞬间存在**穿透竞态**:遮罩销毁后释放事件可能落到下层商品卡上——关闭点击必须用安全空白点(左下角 100,1000,商品网格与左侧菜单之外),**严禁点确认按钮坐标关奖励弹窗**(2026-11-12 实测事故:盲点确认坐标穿透误开启迪之钥弹窗并连锁误购 558 余烬)。由此固化的**点击纪律**:所有重试点击必须有画面证据门(先 OCR 确认目标在屏才点,关键词语义匹配而非非空判断);弹窗重入放行前必须校验弹窗商品身份(读标题防把遗留的其他商品弹窗当专票弹窗接手)。ShopExchangeTicketOp 已内置,复用时勿回退到裸点击。
- **月限商品换光即从商品网格下架,列表整体左移一格**:专票月限 5/5 用完后专票卡消失,后续商品左移补位(角标跟商品走,不跟槽位走)——读月限角标/点商品卡都不能按固定槽位惯性推断,先 OCR 确认目标商品在哪个槽位。
- **资源不足是三级弹窗链**:①票不足→「星轨专票不足,消耗 N 星琼购买 M 张」;②确认后星琼不足→「星琼不足,是否使用 X 古老梦华兑换」;③古老梦华也不足→「缺少 N 古老梦华,是否前往购买?」(充值引导,第 ③ 级分支未探索)。WarpOp 兑换闸按授权逐级处理,未授权逐级点取消干净失败。
- **连续 10 连的循环授权**:用户授权「抽到 5★ 或资源耗尽」类循环时,每轮 WarpOp 完成后停在总览页——下一轮 WarpOp 的导航(BackToNormalWorldPlus)会自动关掉上一轮总览页继续,无需人工逐轮确认;每轮之间读数对账(星琼扣减/进度增量)并判读是否出 5★(金黄卡框),出 5★ 即停或星琼 <1600(不足一轮兑换)即停。
- 结果画面稀有度形态只实测过 4★(光锥/角色两样本);3★ 更简朴、5★ 有专属动画,闭环设计(循环点击至跃迁页回归)天然兼容,展示时长差异由节点预算兜底(10 连实测预算 80 轮)。
- **出货汇报用三档口径(确定/推测/沉默),固定附截图**:总览页不显示名称文本,视觉判读有实拍出错先例(漏报金黄 5★、把 UP 卡误判成「歪到常驻」)——因此分档汇报:①**确定**=画面有直接证据的(卡框颜色定 4★/3★、无金黄框=无 5★、「转化」二字=角色满魂转化);②**推测**=图案与历史卡面同款匹配、卡池成员推断(标注「推测」);③**沉默**=完全无依据的不编造。每轮 `capture_game_screen` 截图展示给用户自行核验,判断权在用户。

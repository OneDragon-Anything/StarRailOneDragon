# 货币战争-结算(挑战成功 / 失败 结算页)

每轮战斗(auto-battle)结束后的结算页:展示小队生命值 + 获得金币明细 + 掉落 + 数据统计,点「继续挑战」进下一轮备战。

## 何时出现 + 状态流转

- **入口**:备战点「出战」→(deploy<cap 则弹「未达上限警告」确认)→ 自动战斗 → 本屏(结算)。
- **出口**:点「继续挑战」→ 下一轮备战(或下个节点 intro,如「强敌来袭」)。
- **子态(标题变体,同布局 + 继续挑战)**:**挑战成功**(常规回合赢)/ **挑战结束**(回合结束态,如首领局存活/非常规结束 —— 2026-08-11 实测 D-65:挑战进度 14/20 + HP1 存活,「继续」在对局继续,非 match-over)。fixture:`win.webp`(挑战成功)+ `ended.webp`(挑战结束)。
- **⚠️ 挑战失败 ≠ 本屏变体(D-67 纠正)**:HP0 团灭的「挑战失败」是**独立 match-over 屏**(挑战失败 + 对局评价 + **「下一步」**,非「继续挑战」)→ 本屏(继续挑战 id_mark)`is_precise=FALSE` 不命中。失败态 fixture(screenshot_20260811_020714_489077.png)待独立建档(货币战争-挑战失败/对局结束)。本屏只覆盖**回合结算**(赢/结束,继续挑战)。

## 识别特征(稳定锚点)

- **「继续挑战」按钮**(画面下中,~(960,893))—— id_mark。CW 结算独有(他屏无此按钮),成功/失败态都在(赢/输都继续)。
- 标题「挑战成功」/「挑战失败」(上中,~(960,229))—— 子态判据(非 id_mark:成功文字与战斗/逐光捡金屏共有,但配合「继续挑战」+金币明细可唯一定位 CW 结算)。
- ⚠️ 勿单用「挑战成功」当锚(撞 battle/treasures_light 屏)。

## automation 要读信息

- **小队生命值(hp_after)**:结算时剩余 HP(`文本-小队生命值`,动态值)。recognizer 产 `hp_after`。
- **胜负(is_failed)**:标题「挑战成功」→ is_failed=false;「挑战失败」→ true。recognizer 产 `is_failed`。
- **获得金币总数 + 明细**(基础奖励/利息/连胜):本轮金币收益(`文本-获得金币总数`,动态)。
- **掉落晶矿**:本轮掉落(晶矿,动态;非穿戴装备 —— combat 掉晶矿,装备由补给节点出)。

## 备注 / 待查

- **失败态 fixture 待采**:本档有成功态(win)+ 结束态(ended)。**「挑战失败」态**(真输,标题/布局/奖励 待现场)待采 —— 补后调 recognizer(is_failed 判据)。
- **is_failed 判据(D-66 纠正 D-65)**:recognizer 用 `_FAIL_MARKER='挑战失败'` substring 判(`settlement_recognizer.py`,**非** `标识-挑战成功` area LCS)。故 挑战成功/结束 → is_failed=false ✓(结束≠失败,非误读),挑战失败 → is_failed=true ✓。**逻辑正确,无需修**。(`标识-挑战成功` area 确 LCS 匹配挑战结束,但该 area 非 id_mark、不参与 is_failed,命名瑕疵不影响。)
- screen_info:`按钮-继续挑战`(id_mark)+ `标识-挑战成功` + `标识-数据统计` + `文本-小队生命值` + `文本-获得金币总数`(区域,待 recognizer 读值校)。
- 奖励明细区(基础奖励/利息/连胜/掉落晶矿)暂未建 area —— bot 要读明细时增量加。
- 触发流:备战 → 出战 →(未达上限警告?)→ 自动战斗 → 本屏 → 继续 → 下一轮(见 `currency_war_deploy_warning.md`)。

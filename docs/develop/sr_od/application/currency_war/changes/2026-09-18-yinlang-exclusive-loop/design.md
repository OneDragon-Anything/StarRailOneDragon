## 2. 方案

### 2.0 总原则：记账归属先问确定性

外部授予记账归属判据 = `game_state/effect-domain.md` §6.3/§6.4（结果可准确计算 → 逻辑写；含概率/随机 → 不建逻辑写端，申报表 + 精确吸收）。本迭代所有记账设计先做同一道判定：

- **选择时点已知的事实**（planner 卡面装备名、腿型）= 确定性 → 逻辑写；
- **不可推算的形态**（随机到货件身份、条件腿触发）= 随机面 → 申报 + 吸收，且**采证定谳前不落任何写端或申报条目**。

两条禁令：①禁把确定性事实降级为随机形状（吸收面 pending 是放宽闸，放宽 = 虚额残留吞真投影 bug 的风险面）；②禁为未证形态预置「或然 +N」absorb 条目（方向：宁可响亮、不可静默吞——依据：`EXTERNAL_GRANT_EQUAL_OBS_LIMIT` 注释同取向）。

### 2.1 R1：planner 统一选择载荷 + 双腿记账

现状结构保留：`CwScreenPlanner._handle_overlay`（决策半：OCR 双卡 → 策略选卡）→ `PlannerPickOp`（机械半：点卡选中 + 确认，依据 `flow/action_ops.md` §4.4）。增量三件：

**① 载荷扩展（决策半）**：选卡时同步分类所选腿并解析件名，经 `OverlayPickExecEnv` 载荷字段上报（字段命名一次到位：`leg_type` ∈ {`upgrade`|`weaken`|`equip`|`unknown`}、`norm_item`（归一件名或空））：

- 腿型判定谓词与 `decide_planner` 分层同源（「提升费用」→ upgrade；「弱化/降低敌人」→ weaken；其余非空 → equip 候选；空/未识别 → unknown）（依据：`kernel/cw_events.py::decide_planner` 三层定序谓词）——判定函数落 kernel 单一源，决策半与记账同消费，防两处谓词漂移；
- equip 腿件名归一 = 卡面 OCR 文本 × `EQUIPMENTS` 注册表相似匹配（`one_dragon.utils.str_utils`；依据：项目 AGENTS.md §7「OCR 结果优先相似匹配」），**最长名优先**（候选按名长降序逐一匹配，防「分身墨镜Max」被短名「分身墨镜」截胡——前缀包含族的名对歧义治理）：唯一命中 → 归一件名；零/多命中 → 未解析（`norm_item=''`）。

**② 发出即记账（双腿，挂点 = 调用侧紧邻发射点）**：记账动作挂在 `_handle_overlay` 内 `action_op_for(pick).execute(env)` 返回后的同帧调用点。挂点放 handler 侧而非 `PlannerPickOp` 体内：五个 pick 类型共享一个 op 类，planner 专属记账进共享体会耦合；且与投资卡确认挂点（`latch_external_grants`，挂点在 `CwScreenInvestStrategy`/`CwScreenInvestEnv` 侧）同型。幂等 = op 实例闩（先例 = 本类 `_confirm_pending`：round_retry 重入同实例不重记账；外循环重派新实例重复记账 = 响亮失配，按「宁可响亮」取向不为它加复杂度）。weaken/unknown 腿 = 零记账（unknown 留台账行证未识别事实）。

- **装备腿·主路（确定性）**：`norm_item` 非空 → `grant_equip_item`（`kernel/cw_effect_inventory.py` 桥族，「选定后确定」面：装备库存 +1 逻辑写，窗口独占 = 选定回执 → 下一次装备区读数）。why 逻辑写不走吸收：件名在选择时点已知，按 effect-domain 确定性分支属逻辑写；吸收面为随机资产面设计（§6.4）。
- **装备腿·兜底路（未解析）**：`norm_item=''` → 不写逻辑，`exec_books.external_equip_grant_pending += 1` **且同帧置 `external_bench_grant_pending += 1`**（双 pending）+ 台账行（kind=`planner_equip_name_unresolved`），装备吸收走现成 `_absorb_external_grant`；bench 侧走既有纯超集吸收门（身份未知 → merge 期望不可算，纯超集为唯一可判形状；级联帧照真失配响停留行，与兜底性质一致，识别修因后走主路消失）。why bench 同置：planner 装备档选项池 = 银狼线专属装备族，未解析件是 R2 三件的概率不可排除，漏置 bench pending 时三件的授予单位必停（不对称：漏置 = 响停，误置 = 窗内多一枚可吸收额 + 台账行可查——误置代价严格小）；身份禁猜（不判它是哪件、不写单位名），数量 +1 是「至多一枚授予单位」的包络。残余面（显式申报）：未解析件若非三件，误置的 bench pending 在等值销闩窗内至多吞一枚真实 bench 正差——有行（`planner_equip_name_unresolved`）可归因，识别面修因后消失。不复用 `latch_external_grants`：其「一局至多一次授予」前提与第二卡告警面向投资卡，planner 一局至多两次事件且可与投资卡并存，复用会误触前提告警；共享 pending 使等值销闩窗口（`EXTERNAL_GRANT_EQUAL_OBS_LIMIT`）对 planner 腿同样生效 = 窗口语义一致。台账行保持响亮：归一失败是识别 bug，留行供识别面修因。
- **升费腿（定谳已出）= 升费吸收窗（merge_simulate 形状判定，静态裁决）**：对抗审裁决改吸收扩展——「原位变换桥」的原位假设无出处，废除；观测等价申报口径 = 容器多重集（char_id+star）**槽位无关**，落点槽位不建模不判定（槽位由观察为真值）。机制：
  - **置位端**：planner-upgrade 腿发射点（同 ② 记账点）置 `planner_upgrade_pending`（ExecBooks 新字段，单次窗语义）。置位前提硬校验：置位时容器观察态（bench ∪ front_row ∪ back_row 多重集）**恰含一枚**（银狼LV.999，2★）；零/多枚/未观察 = 不置 + 台账行留证（fail-closed 禁猜）。
  - **期望终态（纯函数）**：expected = 置位时快照 − {(银狼LV.999，2★)} + {(银狼LV.999，1★)}，经 `merge_simulate`（`kernel/cw_merge_simulate.py`，语义权威 = 模块头 §1–§5：同名同星全域 bench∪deployed 计数、满 3 升星连锁、恒成立不变量「场上同名同星 ≤1」出参断言）不动点推演——1★ 凑满即连锁升星的级联形状被同一引擎覆盖。费用档不建模（`cw_chars.py` 银狼LV.999 行注：cost=起始费，多档待策略层需要时扩）。
  - **判定器（吸收族新成员）**：宿主 = 失配分流吸收族（与 `_absorb_external_grant` 同层），下一备战帧 heavy 读的全域多重集 == expected → 吸收（台账行 kind=`planner_upgrade_absorbed`，观察赢）；不等 → 照真失配安灯响停。
  - **假吸收防线（论证）**：①置位前提硬校验（恰一枚 2★，非升级帧无置位源——planner-upgrade 发射是唯一置位端）；②形状判定 = 全多重集精确相等，非「任意 surplus 容忍」——多一只/少一只/错星级都失配响停；③窗 = 单次 pending，吸收或等值销闩即闭，不跨轮存续；④overlay 阻断局内操作 = 置位到读帧间板面无其他变更源（前提显式申报，前提破 = 失配行可见）。
- **升费连带「新费档银狼刷进商店」腿** = 零记账面：商店池无逻辑态（商店逐帧观察为真值），于吸收窗注释申报。

**③ 文档面**：`logic-updates/pick-planner.md`「容器 GameState 零写」声明由固定末阶段按正本更新清单改为双腿记账（装备腿主路 = 逻辑写通道、升费腿 = 吸收窗申报；「事件线选择非逻辑态通道」契约辖的是选择本身如 chosen_hack，二者不冲突）。

量级：中（载荷 + 记账双路 + 升费吸收窗 + 测试锁；1–2 天）。

### 2.2 R2：送角色腿落码（定谳已出，无需采证）

**定谳**（用户口述·权威 2026-09-18，编排者送达）：获得分身墨镜/分身墨镜Max/数据拷贝仪Max 时，赠送的银狼族单位**直接出现在备战席，效果与商店购买完全一致**——可触发合成、也可能触发新单位升星（数据拷贝仪Max 送的银狼LV.999 凑满 2 星即触发 planner 升星选择画面，与 R1 成链）。星级按卡文：分身墨镜→1星银狼 / 分身墨镜Max→2星银狼 / 数据拷贝仪Max→1星银狼LV.999。

**修法（申报表吸收，非逻辑写）**：

- **`EXTERNAL_BENCH_GRANTS` 补三件条目**（键 = 装备名，与既有卡名键域无碰撞）：三件各计 1（授予单位与星级记行注释）。表辖域注释同步扩：键域 = 卡规范名 ∪「获得即送单位」装备名，**混合键域隔离申报**（对抗审⑦）——卡名键专属消费端 = `latch_external_grants`（投资确认挂点），装备名键专属消费端 = 本节 helper，两端各查各的键族禁互串（防卡名撞装备名的假命中）。数值依据 = 卡文（分身墨镜「获得时解锁并获得1星专家【银狼】」/ Max 2星 / 拷贝仪Max「立即获得银狼LV.999」）+ 本节定谳。
- **置位端（获得回执，两通道汇入单一源 helper）**：新 kernel helper（建议名 `latch_equip_unit_grants`，装备名列表 → 命中三件表 → `external_bench_grant_pending` 按件数 `+=` + 台账行）：
  - **planner 通道**：3.2 的 R1 记账点（件名归一主路写 `grant_equip_item` 的同帧调 helper）——装备逻辑写与 bench pending 同帧同源；
  - **随机通道**（骇客专家改件等）：`_absorb_external_grant` 装备腿吸收命中时扫描差额多重集，命中三件 → 逐件调 helper（随机到货件的身份在吸收时点才可知，这是随机通道唯一可定的回执时点）。planner 通道走逻辑写、不触发装备吸收 → 两通道天然互斥不双置。
- **同帧双授予读序（对抗审击穿①，修法三选一裁决 = 装备吸收前置读序）**：击穿形状 = prep heavy 帧 bench 先读（`cw_screen_prep.py:682` 观察 write 端在装备库存 write 端 `:737` 之前）——骇客卡（bench 申报 2）+ 随机改件（若为三件则 bench 再 +1）同帧到货时，bench 吸收在 pending=2 下遇 surplus=3 → 拒收安灯，而装备读（身份定谳、补置 pending 的时点）在 bench 吸收之后才发生。修法 = **prep heavy 帧内装备库存观察写端（含其吸收链）前置到 bench 观察写端之前**：身份先定谳 → bench pending 补齐 → 同帧 bench 吸收 3/3 达成。裁决理由：读序调整是同帧形状的根因修法（bench 对账依赖授予身份，身份定谳必须先行）；备选「确认时按数量预置」不可行（改件身份确认时不可知，预置即或然 pending，违 §2.0 禁令②）；「显式申报残面」把可根因的确定性失配留给事故窗，不取。改动面 = 同一帧内两观察写端先后，不动识别本身；残余申报 = 若实装发现 bench 读还有本帧之外的独立入口，该入口同帧形状照响停并留行（bench 观察写端现役单一 = prep 本屏，预期零残余）。
- **幂等/窗口**：不复用 `latch_external_grants` 的「一局至多一次授予」前提与第二卡告警（装备授予一局可多次发生，前提不成立）；共享 pending 使等值销闩窗口（`EXTERNAL_GRANT_EQUAL_OBS_LIMIT`）对本腿同样生效（同 R1 兜底路口径）。
- **申报面读法统一**（同族双读法收口）：`EQUIP_REWRITE_DECLARATIONS` 三行改统一口径「获得送单位腿 = 申报表吸收（EXTERNAL_BENCH_GRANTS 三件），非逻辑写」；`EQUIP_WRITE_SIDES` 分身墨镜/分身墨镜Max 两行值 `bridge:spawn_equip_bench_unit` → `observation`（获得单位腿改辖申报表，两件无其余逻辑写面），数据拷贝仪Max 行保持 bridge（辖计数臂腿）+ 申报行文本拆双面（计数臂 = bridge；获得送银狼LV.999 腿 = 申报表吸收）。键集不变 → `scan_rewrite_equipments` 恰等锁不受影响。
- **下游语义**：授予单位入席后 = 普通备战单位——分配/W3 门/合成升星语义与商店购买单位同一套，零特殊建模（定谳「与商店购买完全一致」）。
- **bench 吸收形状 = merge_simulate 期望终态全等（对抗审⑤，级联残面静态裁决）**：授予单位可触发合成/升星（定谳），「纯超集」形状判定接不住级联帧（实读缺 1★、多 2★ = 子集违规）——裁决 = 三件的 bench 吸收形状升级为**期望终态全等判定**：helper 置位时以当时容器观察态（bench∪deployed）快照 + 授予单位（名,星）经 `merge_simulate` 推演期望终态（纯加件与凑满合成连锁同一引擎覆盖），bench 读帧全域多重集 == expected → 吸收（台账行，观察赢），不等 → 照真失配响停。假吸收防线与升费吸收窗同族（§2.1）：置位源唯一（装备吸收命中回执，身份已定谳）、全等多重集非任意容忍、单窗即闭、快照到读帧间板面变更源 = 授予本身（前提申报）。既有卡名键授予的吸收形状不动（现役纯超集门零改动，本裁决只辖三件 helper 路径）。

量级：中（三表条目/注释 + helper + 两通道 + merge 形状判定器 + 读序调整 + 测试锁；随 3.2 合批）。

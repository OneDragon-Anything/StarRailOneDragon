# 统一保护集(买卖身份同源) 迭代设计(总纲)

## 0. 元信息

- 迭代目标:修复「过渡引擎件在架拒买、且被卖出通道当废牌处理」的病灶(sim 复盘局 g_20261015_154239 缺陷候选 D1/D5 卖面侧),并将买/卖两侧的卡牌身份判定统一到单一「保护集」源。用户裁定口径(2026-10-15 会话):①位面 1 买面 = 过渡阵容 + 锁定/候选终局阵容,位面 2 起 = 锁定/候选终局阵容;②买卖决策依据统一——买面优先级即卖出让位序的镜像;③过渡阵容引入与终局同构的候选/锁定语义(候选 = 四体系全体,锁定 = 体系达成);④候选/选定阵容成员不能卖、不凑息;插件/杂件可卖可凑息。
- 状态:对抗审中
- 文档清单:无详设(本篇即完整设计)

## 1. 问题与动机

- 现状症状(sim 局 g_20261015_154239,journal 行锚见复盘报告;单局归因,精确拒因以落地批单帧复现为准):
  - 买面:四体系引擎件在架 ≥6 张次全部拒买(r3 爻光 1 费/r6·r8 饮月 2 费/r1 三月七 1 费);整局 5 笔买卡 0 笔引擎件;
  - 卖面:r3 卖椒丘(DOT 体系件)腾位买风堇(填充件),DOT 引擎归零;
  - 对照:同批 4 局 3 死(P1r6/P2r1/P2r2),死亡局带「死时带金/金尽」形态。
- 根因归层(**语义层**):
  1. **身份域缺失(主根因)**:买卖两侧的「自己人」判定域都只覆盖终局线——买面序 1 未锁定名单 = 方向读口(`direction_comp_of` → `opening_recipe_comp` = 配方对/早期对两体系全体成员,`session_scope.py` 方向读口段)∪ 贯穿件(+空窗回退全集,`cw_intention.k_empty_window_fallback`);**配方对未选中的体系成员不在任何买入臂射程**(M2 缺口腿只吃义务面,stockpile 腿要求同名已持 1,`shop.py` M2 循环;④转投通道是唯一买「未持有过渡件」的臂但放行集仅 10 人策展口径且门挂 `committed_from`)。卖面 `sell_line_membership` 同样只覆盖锁定/候选终局线——过渡体系(位面 1 的真实战力引擎,`transition_combos.md` 四体系定义)不在身份域,拼图件按金当量垫底被支配卖出(宪法 P41 ②「骨架件/跨阶段体系件不卖 fail-closed」失实现,`01_math_framework.md` §3.2)。
  2. **定型语义混淆(④通道的门错)**:④分支以 `committed_from` 为门,权威序②把「P1 配方对已物化」计为定型(`cw_intention.committed_authority` ②支)→ **配方对物化帧④恒不激活**;空窗帧(四体系支持度全 <1.0,配方对派生为空)与 P2 入口至兜底锁的双轨短窗 committed=False,④仍按 10 人策展口径激活——激活域与体系全域错位,且「定型」混用了「板面临时方向(配方对)」与「终局承诺」两个语义(违反 `12_line_and_intention.md` §1.2「P1 板面恒过渡体系,与方向正交」)。
  3. **静态策展名单与现算体系并存**:TRANSITION_PACK 13 人名单(放行集取 carry/partial 10 人)与注册表现算体系成员双源,策展收录标准(Early ≥8%)漏计合法拼图(桑博等),档位标签(carry/partial/drop)被买卖身份误用作「可否中途弃」的依据。
- 解决到哪:上述三层全部(过渡域候选/锁定状态、保护集单一源、买卖两侧接线含新增囤货臂、静态身份面退役)。
- 明确不解决(防范围外溢):D2 补给拾取工序缺位;D3/D4 升级时机(P85 域);D5 置换价值表「部署 carry 同名副本」高值项(飞霄类非四体系成员,不在保护集域,另批);`committed_authority` 其余消费点(装备/部署)的语义审查(本迭代结构上消解其在 shop 的消费,本体不动)。

## 2. 方案

### 2.1 方向状态模型(新增语义)

两个域、同一套候选→锁定语义,数据底座全部复用现有结构:

| | 候选 | 锁定 |
|---|---|---|
| 过渡域(plane2_started = 假) | 四体系**全体**注册表成员 | **已点亮**的体系(支持度达标;可多个) |
| 终局域(plane2_started = 真) | 候选 top3 线成员(现行候选快照) | 锁定线名单(现行锁定槽) |

- **体系键与成员集(复用现有单一源,零新建数据)**:体系键权威 = `knowledge/cw_engine_facts.TRANSITION_TRAITS`(三羁绊键:仙舟/列车同行/持续伤害)+ 希儿系;**守卫/保护类消费使用 `GUARD_SYSTEM_TIERS`**(`cw_deploy_logic` 已登记「守卫/保护类消费不再借 TRANSITION_TRAITS,一常量两语义根修」——保护集正属此类)。体系成员判定单一源 = 现役 `is_seele_system_member`(希儿系)与羁绊阵营∪流派注册表成员口径(与 `cw_intention._pair_members` 同式);**落地批禁止新写第四份希儿系判定**,复用 `seele_system_formed`/`is_seele_system_member` 现有单一源链。
- **点亮(过渡锁定)判定**:复用现役支持度链(`_p1_system_support`/`_seele_system_support`;`_seele_system_support` 首行已含希儿在场门,希儿本人计入计数——希儿 + 任一放大器即达标)。达标判据 = 三羁绊系支持度 ≥ 1.0;希儿系 = `seele_system_formed` 现役语义。
- **锁定状态槽(新增)**:`StrategyState` 新字段 `transition_locked_systems: frozenset[str]`(体系键集)。写点 = 策略层决策入口前置段(与 `refresh_line_if_needed` 同点,宿主 = `mandate_v1/bridge.py`;清空点 = 进位面 2,宿主 = `flow.py` 配方对退场同点)。**幂等只增不减**——达成过的体系不因掉档失去锁定(同构终局「锁后不换」,防「掉档→保护收缩→连锁卖」恶性循环)。
- **保护集函数(新增,全仓单一源)**:`protection_membership(gs, state) -> frozenset[str]`(角色名集):
  - 过渡域:四体系全体成员(候选)∪ 已锁定终局线成员 ∪ 候选 top3 终局线成员 ∪ 贯穿件(`CROSS_LINE_KEEP_NAMES`)。注:过渡锁定体系 ⊆ 候选全体,对保护集无增量;锁定状态的行为消费面在买面金约束分层(§2.2)。
  - 终局域:锁定线名单 ∪ 候选 top3 线成员 ∪ 贯穿件(与现行 `sell_line_membership` 两分支同构,加贯穿件)。
- **域切换**:plane2_started 翻真时过渡域关闭;过渡域成员若属终局域候选/锁定则自然延续保护,否则滑向非保护(可卖)——对齐 `stage_transitions.md` Q1/Q2 数据常态(非本路线过渡件位面 2 清场,本路线组件留存 0.7-0.8)。

### 2.2 买面接线(`mandate_v1/shop.py`)

- **序 1 未锁定名单**(`buy_members` 构建未锁定分支):在现行构成(方向读口两体系成员 ∪ 贯穿件 ∪ 空窗回退全集)基础上,并集 `protection_membership` 过渡域全体成员——消除「配方对未选中体系成员」的名单缺口。
- **义务面/囤货面拆分**(语义实体分层对齐既有 `locked_buy_membership`(义务)与 `locked_buy_scope`(约束)的形态):
  - 义务面(`obligation_members`,M2 骨架义务、免利息规则门)= 候选/锁定终局线成员 ∪ 贯穿件 ∪ **过渡锁定体系成员**(点亮在即 = [6]「店全是想要的」跌破利息档例外的策略载体);
  - 囤货面(增量)= 未点亮过渡体系成员的**未持有首副本**,新囤货臂承载(下条);`missing` 缺口推导只消费义务面。
- **新囤货臂(④退役的语义承接)**:位置 = M2b 升星合并完成买入之后、序 2 之前(继承④的位次);遍历店面卡,命中条件 = 未点亮过渡体系成员 ∧ **未持有首副本**(同名副本归现行序 4 压牌库/序 5 凑星,本臂不买);门序 = 1★ 全额退(`refund_full_star_ok`,[11] 零息损 + P46 豁免类「资产可逆」)→ 金可负担 → 席(席满走店内置换账,候选 = 非保护档垫件;候选穷尽 = 放弃并计数)。买因 = `protection_hoard`(登记 sell_gate 买因类 `hold`)。出口键闭集:`protection_hoard_hit` / `protection_hoard_no_fuel` / `protection_hoard_unaffordable`。
- **P60 容量告警对象面收窄**:告警检查对象从宽集改为**义务面**(囤货面是期权非义务,超容由置换账自然管理)。
- **④转投前瞻放行分支整条退役**(含 committed 门、`transition_release_names` 放行集、`transition_component_buy` 买因及出口键)。
- 锁定态买面(P1 锁定局 = 配方对 ∪ 锁定线;P2 = 锁定线单源)**不动**。

### 2.3 卖面接线(`criteria/sell_candidates.py` + 卖出资格装配)

- **身份面与义务基座显式拆分(F15 核心)**:`sell_line_membership` **保持现行口径不变**(锁定线/候选 top3 成员——它同时是装配 A 义务基座 base 实参、P78-5 兜底池减法②与 P96 释放判据 (b) 腿的基准,扩域会掏空兜底安全阀并灌死 P96),新增独立保护集消费口供资格/排序使用:
  - **保护集成员 = 绝对禁卖**(用户裁定语义):`protection_membership` 并入卖出资格装配 A 身份段(替换原静态持有两集中的 ④放行集;registry 核心集保留——万敌等单卡核心非四体系成员)。豁免通道照旧:溢出自救全通道豁免、部署换血(场上件唯一卖出场景)、P78-5 兜底豁免(其兜底池减法②的义务基座 base = 现行口径不变,**全场保护档帧兜底池仍含非义务保护件**——3.3 阶段对账断言)。
  - 评估器排序键结构 `(line_member, bond_drop, gold_value)` 不动,首维语义 = 现行线内身份(非保护集)。
- **凑息语义**(用户裁定):候选/锁定成员不凑息(由绝对禁卖结构性达成);插件/杂件可凑息。新增观测键 `interest_round_protected_block`:写点 = 节末凑息步(`entry.py` 节末凑息段,缺口语境在彼处),语义 = 存在可凑缺口但合格候选全为保护档而放弃的帧计数,供跨局量化(本迭代只落键,判读另案)。
- 场景参数表(`SCENE_SPECS` 八场景)结构不动。

### 2.7 关键取舍

- **锁定持久化 vs 派生**:选持久槽(幂等只增)。派生口径下「换血掉档 → 保护收缩 → 连锁卖」有恶性循环形态;终局侧「锁后不换」为既定架构原则,同构沿用。
- **保护 = 绝对禁卖 vs 排序垫底**:选绝对禁卖(进装配 A 身份段)。排序垫底在「全场保护档」帧仍会卖出候选成员,违背用户裁定语义;自救/换血/P78-5 兜底三豁免保安全阀;义务基座(base)保持现行口径与身份面拆分,兜底池不被掏空。
- **修④门 vs ④退役**:选退役。修门只救 10 人策展口径;退役并序 1 吸收 + 新囤货臂,身份域扩为四体系全体现算,且少一条需维护的邻位特批通道。
- **过渡池含高费框架成员**(银狼/瓦尔特等 3-5 费):纳入。位面 1 低等级下商店概率结构性刷不出,刷出时按 [22]① 稀有照囤/[21] 买而不上为正确行为;1★ 全额退门保证零息损。r100「Early 出现率」收录纪律是策展名单时代的防膨胀手段,现算范式下由概率结构与经济闸门自然承载。
- **TRANSITION_PACK 全退役 vs 保留配方对引用**:落地批按消费点 grep 实测裁决(§2.4),不预设。

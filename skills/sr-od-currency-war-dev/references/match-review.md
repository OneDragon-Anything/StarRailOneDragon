# 单局复盘协议(2026-09-07 用户定稿)

> **执行者 = 干净上下文的子 agent**(每次复盘新开,不带编排者偏见)。**触发 = 实机监控局终派单**(每局一单,后台异步;报告落盘 `matches/reviews/<game_id>.md`,45min 策略审查角色消费产出作病灶输入,不重做)。
> **尺子 = 玩法的恒常标准,与当期迭代目标无关**——迭代目标只排修复优先级,不参与「这局打得对不对」的判卷;A/B 验证当期改动才用当期目标行判据(telemetry-reading 判读流程步骤 0 的分界,两种活动别混)。

## 阶段 1 · 阅读理解(开工前提;任务书直接引用本清单)

- 玩法知识:`docs/game/currency_war/research/README.md` 玩家理解序全读(机制 → 纪律 → 过渡 → 终局);
- 游戏数据注册表通读:角色技能(`cw_chars`)、羁绊效果(`cw_factions`)、装备效果(`cw_equipment`)、投资策略/环境效果(`cw_invest_data`)、词缀效果(`affix_effects_data`)。

## 阶段 2 · 逐节点分析(每节点必出结论,不停留在位面级)

对一局每个节点依次:

1. **重建该节点观察到的游戏画面**:该节点的**全部观测数据**(板面/备战席/金/血/等级/商店/装备/投资/词缀/节点序列/连胜等——以 GameState 字段面为准,重建完整状态,不是摘要;数据 = 按局拆分的对局档案,查询入口 = 遥测 CLI `--match <game_id>` 档案直读,工具用法见 telemetry-reading「查询工具」节);
2. **玩家视角**:这个场面下,我应该做什么操作?——以期望最优解为基准(好玩家在算账:概率/期望值/机会成本,不赌感觉);
3. **代码视角**:它实际做了什么?
4. **裁决**:哪个更好——**以决策时点的信息与期望值口径判断最优性**;禁用「运气」作归因,禁用事后结果反推(牌后来没来,不构成当时不买的理由,也不构成当时买了的功绩)。

## 阶段 3 · 位面总结(三问收口)

- 位面 1:过渡阵容顺利凑出来了吗?
- 位面 2:阵容转型成功了吗?
- 位面 3:最终阵容顺利凑出来了吗?

## 产出形态与红线

逐节点结论清单(轮号/场面/最优操作/代码操作/裁决+依据)+ 位面三问总答 + 候选修复项(带证据链;单局归因=候选,跨局/sim 验证才定谳)。**复盘输出零条「可更好操作」= 复盘未完成。**

**机制归因的数据口径**(候选修复项要追「为什么」时):读档案的决策流程明细(带策略版本戳,按当版语义解读);要「按现行策略会怎样」→ 回放(当期代码对档案状态现算,单帧锁同款)——两者都不读决策日志流。

## 1. 背景

### 1.1 透传形态是什么

策略器决策输入的统一取值口是 `kernel/cw_bs_view.py` 的 `game_state_view`(消费切换调用面单一源 = `strategy_input_state`,全仓 41 处调用点,r5-migration-plan §1.1 清点)。它是「BoardState → GameState 消费适配器」:返回旧形状的 `GameState`(策略器签名不变),逐字段填充时分两轨:

- **已建模域**:值取自 BoardState 单例(经观察喂入口 `cw_observation._feed_board_state` 或 sim 合成口 `synthesize_from_game_state` 逐帧写入,每个字段带来源标记)——gold/level/xp/streak/level_up_cost/shop_refresh_cost/node/board/enemy_difficulty/active_strategies/selected_difficulty;
- **透传域**:值原样搬传入参帧(`session.last_state` 旧观察帧)——BoardState 上没有值可读,或当初申报了「不入记录模型」。

透传是迁移批次的**过渡形态**,不是终点:`cw_bs_view.py` 模块头自己申报「收敛前提 = 该域本身建模入 BoardState,归建模批」。直迁口径(不用影子开关、直接迁移并删除旧代码,r5-migration-plan 直迁五原则)下,W6 决策面切换(消费面签名与字段读全切统一容器、投影模块退役)的前提是**容器有字段可读**——透传域不建模,W6 切换后这些字段以缺省值/异常暴露,策略器静默拿到错误输入。这是 r5-migration-plan 风险 3「透传域建模缺口→决策断粮」的机制,也是透传域建模从影子口径下的候补批改为直迁关键路径的原因。

### 1.2 进入门状态

W5 进入门 = W1(写入面稳定)✓ + 候裁 5(ExpectedState 归一方案)先行。候裁 5 已由 **(字段来源两态制)** 定谳消解:BoardState 字段来源只保留 observation(观察)与 logic(逻辑)两种,expect/confirm 两步机制全套废除——不存在「ExpectedState 与 BoardState 双容器归一」问题了。本波设计按两态制口径展开:新域写入一律走观察写入(`observe`)、逻辑直写(`write_logic`)、失读沿用(`carry`)、载体中继(`relay`)、结构离屏(`leave_screen`)五通道,不引入预期挂账形态。

## 2. 改动设计

按对账结果分四组推进,外加 hp 专项与类型去重两个专项。总原则:值源切换逐位等价(常态帧),失读帧按记录模型语义改善并显式申报(§3.1)。

### 2.1 A 组:视图收编(容器值已产,只改视图取值)

`active_env` / `plane_bosses` / `enemy_affixes` / `shop` / `refresh_probs` 五域。视图取值序改为与其他已建模域同构:**BoardState 有值用之(含 carried 沿用值),无值透传入参帧**(开局首帧前容器未观察的引导窗)。

shop 域有独立的语义要点:payload 域语义 =「当前画面的 payload,非当前画面 = None」(设计正本 §2.2 显式例外)——离开商店画面时容器值是结构离屏(None),视图必须忠实返回空牌面,**禁用入参帧的旧牌面兜底**(残留会把离屏帧误读成「商店仍开着」,与 sim 合成口离屏分支同一条纪律)。refresh_probs 同属 payload,一并遵此。

类型注意:视图返回的 `GameState.shop` 元素类型是旧容器 `cw_state.ShopCard`(带点击坐标 x),容器 payload 元素是 `cw_board_state.ShopCard`(坐标不入存储)。转换经显式映射函数(单一源,放 `cw_bs_view` 或 `cw_board_state`),字段映射见 §2.5,禁散落内联转换。

### 2.2 B 组:写端补接(schema 在,喂入面接线)

**bench / deployed(席位模型)**:识别线全部在役,缺的只是把产出接进观察喂入口——

- 接线点 = `read_game_state` 备战帧路径读席位之后(PrepObservation 消费 SIFT 链 `read_deployed_chars` / `read_bench_chars` 的同环),spec 门加键(如 `bench` / `deployed`),`PHASE_FIELD_SPEC` 同步扩员;
- 容器形态与 sim 合成口既有写点同构(定长槽位表):bench → `BenchView`(9 槽 + capacity,容量唯一改写源=节省工位时限效果,经效果账本投影 `project_effect_capacity` 既有链);front_row/back_row → `list[Unit]`(char_id/star/equips/slot);
- 坐标系换算是映射层职责,规则进实施批任务书:现役 `deployed` 是 0 基定长槽位表(下标 0-3 前台 / 4-9 后台;1 基 `slot` 字段仅信息位),容器侧 front_row/back_row 分列存 `Unit`(其 `slot` 1 基,设计正本 §8.2);视图收编时按 下标重组回 `deployed` 形状(None 填充),保证消费形状零变化;
- 已知边界照抄设计正本在册申报:星级=read_star 在役;备战席装备图标=负探针在案(机制恒空,读只产噪声)→ 备战席 Unit 的 equips 子字段不填,不造假值;3 合 1 升星动画窗读数不可信,本帧观察不写。

**equips(装备库存)**:两层写端——

- 观察写端 = 备战屏装备区 OCR(设计正本 §3.2.15 在册);现役读通道的挂接点与缺口由实施批批首 grep 盘点(缺则接线,禁静默不建);
- 逻辑写端 = 设计正本 §3.2.15 已列清单(OpenBox 入区 / RunTools 冶金炉·拆装扳手 / SellBench 卖出回区),随 op 执行落地门走 `write_logic`,观察覆盖收口;
- 过渡兜底:接线完成前先经 `relay` 从 session 镜像 `last_owned_equips` 补写(与 relay 族同纪律:从未写过才补),保证视图收编后值不悬空;真写端接通后中继自然退位(relay 的「已有正式值跳过」语义保证无冲突)。

### 2.3 C 组:schema 扩员与残差定谳

**deploy_cap:入容器,新增 `deploy_cap: Field[int]`。** 写端 = 部署数区域 OCR 现读,写入闸沿用现役采信门(双帧一致采信:域外值重读一帧,两帧一致且 level≤cap≤上界才采信,域外冲突 `obs_conflict` 留证)。取舍理由(为什么不派生):

- 字段准入四问(设计正本 §8.8)过闸:①部署/换线决策直接消费(现役 `GameState.deploy_cap` 的消费面);②影响「还能不能继续上人」判定;③**不可从容器其他字段可靠反推**——容器有 `back_layout`(后台格数),理论关系 `back_layout = 6 + (cap − level)`,但 `back_layout` 在域外态是「8 格超集」近似值(带 superset 标记),反推 cap 会把近似当真值;④不是识别质量元数据。
- cap 与 back_layout 双存属设计正本 §8.8 在册例外形态(「识别口径与推导口径并存且各有消费面」,先例 = board、level_up_cost):cap=识别源(采信门输出),back_layout=三信号裁决结果(公式/CV/占用仲裁,`cw_back_layout.py`)。两者关系写进字段注释,冲突走缺陷台账,不互改。

**front_max / back_max:不入容器**(残差定谳):

- `front_max` 恒 4(现役常量 `DEPLOYED_FRONT_CAPACITY`),是常量不是观察事实——不入 schema,视图供数直接取常量;
- `back_max` 的动态真值就是 `back_layout` 字段(值域 6-9:平常 6,宝钻/召唤物扩展,上限 9——用户真值 2026-09-07/09-11,机制正本 = board_structure.md 量化公式节;6/7/8 已交互建档,9 档坐标未建档,建档前域外按 8 格超集 + evidence `superset` 标记运行)——不另立字段,视图供数读 `bs.back_layout`(无值时透传帧兜底引导窗);
- 视图继续供 `GameState.front_max`/`back_max` 两字段(消费面 W6 才切),值源从「帧静态默认」改为「常量 + 容器动态真值」,语义反而修正了旧 `back_max=6` 静态值与实局 7/8/9 格不符的偏差。

**dual_track_phase:不入容器**(残差定谳):它是策略侧派生旗标(值源 = 方向层权威派生 `committed_from(session)`,mandate adapter 装配时显式回填),不是游戏可观察事实——按设计正本「换一个策略实现就不存在的字段归 StrategyState/策略侧」的归属判据,不进 BoardState。视图不建模此字段;W6 消费切换时消费面改读派生函数。本条 + front_max/back_max = §1.3 注 4 残差的全部补申报。

### 2.4 hp 专项(单列验收)

目标链(r5-migration-plan W5 列原文):**容器存门前真值,新鲜度/门控施门迁消费侧;记录/消费分离不变**。

现状链与问题:

- 记录面(已达标):`BoardState.hp` = 门前真值——观察闸保证仅真读才 `observe`(商店开态该区不显示,旧 100 兜底假值结构性进不来),失读 `carry` 沿用,开局先验 `write_prior`(实证档),结算覆盖独立写端;
- 消费面(要改):决策视图透传 `fr.hp` = **过门后的消费值**——旧链在写侧施门(`cw_screen_prep` 环入口终饰写 `last_state.hp` 前过 `gated_hp`,单写者纪律,」教训),门函数 `gated_hp` 在策略实现层(`strategies/impl/cw_strategy.py`);消费侧 mandate adapter 现在**再施一次门**(输入是门后帧值,门幂等所以现状无错,但值源已经是二手)。

W5 改动(两步必须同批落地,中间态=消费拿到未施门真值,血线决策漂移——本专项的批内串行纪律):

1. **视图 hp 分支改读容器真值**:`st.hp = bs.hp 值`(有值含 carried;无值透传帧引导窗);`hp_readable` 映射 = `bs.hp.source == 'observation'`(真读)/否则 False(carried/prior 均非本帧真读);`hp_trusted` 的推导规则由实施批按现役语义对齐(现役透传 `fr.hp_trusted`,其等价容器信号 = 写点 sig.quality 词表,批首盘点后落注释,禁猜)。
2. **消费侧 hp 读点显式施门**:读点改为「取容器真值 → 调 `gated_hp(真值, session, t, readable)`」。现役消费读点形态已在(mandate adapter `decision_state` 即此形态),本波做的是**值源切换**(snapshot/帧值 → 容器真值)与读点全量清点(`shop.py` buy 前、`cw_screen_prep` 环入口写侧门保留至旧链删除,session 政策语义不变;全量清单实施批 grep 申报)。

**等价证明**(风险 4 缓解的落点):旧链决策 hp = `gated_hp(门后帧值)`;新链 = `gated_hp(容器真值)`。两者等价当且仅当:①门参数同源——门的输入是 `session.last_hp/last_hp_t`(结算真值+时点)与 gap 判定,新旧链完全相同,门不动;②真值同源——容器真值与旧链 `last_hp_real` 沿用值出自同一观察漏斗,失读沿用语义同构(容器 carry ≡ 旧链沿用),差异仅在「沿用值带来源帧标注」(更诚实,非更不同);③门幂等——门后值再过门不变(现状双门实证)。验证:回放语料 hp 轨迹逐位对拍 + `posture_release` 假帧守卫既有锁继续辖 + 血线决策(pivot/锁血)行为锁。

**为什么门不能进视图层**:`gated_hp` 是策略实现层符号,视图在 kernel——kernel 不可反向依赖策略实现(现架构依赖纪律,也是当初 hp 透传的根本理由)。收编不改这条约束,只是把「值预施门」换成「真值 + 消费侧施门」,session 政策语义(门窗口径 gap==1 / 不可信放宽 gap≤3)原样保留。

### 2.5 类型去重

**双 ShopCard 归一**:`cw_state.py:110` 旧容器版(带点击坐标 x、merge_preview)与 `cw_board_state.py:473` 统一容器版(name/faction/cost/star/cost_source;坐标不入存储——坐标单一真相源=screen_info;merge_preview=派生计算不入存储,✦ 读取器降级核对信号)并存。裁决:

- **唯一容器类型 = `cw_board_state.ShopCard`**(定居 kernel,与 P8 候裁 9「归一后唯一居所」衔接一致);`cw_state.ShopCard` 随 GameState 本体退役波(W8)消亡;
- 本波交付:kernel 内部零 `cw_state.ShopCard` 引用(观察喂入面转换点已立,本波补视图/合成口的显式映射函数单一源);策略器与执行面的旧类型引用随 W6 消费切换清零(过渡期两类型并存合法,转换只许在映射函数发生);
- 字段映射规则(实施批任务书附):`x`(点击坐标)转换时不填——决策消费不用坐标,执行侧 buy 发射从 screen_info「商店牌-N」区域现取;`merge_preview` 不转换(派生函数消费方自算);`cost_source` 原值透传不折叠(三值词表 badge/roster/roster_fallback,证据分级禁丢,消费侧归并走 `cost_source_group`)。

**BenchChar 居所定谳**(本波定谳,P8 执行):建议**留 `cw_state.py` 原地,随 P8 文件更名方案定居**(候裁 9 的「留原文件」案),不迁 kernel。理由:

- BenchChar 是**执行/tracking 域载体**(现役 tracking 链的星级维护、卖价 `sell_refund` 读它;SIFT 读取器产出形态;定长槽位表 0 基下标),不是容器词汇——容器侧席位载体 = Unit/BenchSlot/BenchView(1 基 slot 信息位、BenchView 统一槽位视图),两套坐标语义不同(设计正本 §8.2 注),强行归一会把执行域槽位语义塞进记录模型;
- 全仓 127 处 `cw_state` import 的主体是执行/装配链,装配源契约尚未到期重验,迁居 = 纯搬移税零语义收益;
- W8 切割 GameState 本体时 `cw_state.py` 以共享词汇库形态更名保留(候裁 9 附带项),BenchChar 随文件定居,与双 ShopCard 的「唯一居所在 kernel」不冲突——两者本就不是同域类型。

### 2.6 写入纪律、spec 门与 sim 同步

- **D1 写入口纪律锁扩面**:新增写点(deploy_cap 字段、bench/deployed/equips 喂入、视图与合成口转换)全部走写入口五通道(observe/write_logic/carry/relay/leave_screen),禁直摸 Field——D1 锁(写入口纪律锁,决策体系)断言随域扩面;
- **spec 门扩员**:`PHASE_FIELD_SPEC` 加 `bench`/`deployed`/`equips`/`deploy_cap` 键;渠道签名照显式签名制铺满;
- **sim 合成口同批扩**:`synthesize_from_game_state` 补 plane_bosses/enemy_affixes/active_env/equips/front_row/back_row/deploy_cap/back_layout(sim 侧 GameState 真值直写,observation+evidence=`sim:synthesized` 既有形态;末位 back_layout = back_max 值源切换语义裁决批增补申报项——裁决值源切 back_layout 后合成口须同域,域覆盖集对齐);encounter/supply 恒离屏口径不变;合成口与实机喂入口的域覆盖集对齐进逐域行为锁;
- **测试锁族**(对齐正本 W5 列验证列):①逐域行为锁——回放语料对拍,值源切换逐位等价;②hp 专项对拍(§2.4 等价证明的实证面);③D1 锁扩面;④kernel 内零 `cw_state.ShopCard` 引用静态锁(全仓零引用随 W6/W8 收口);⑤payload 域离屏语义锁(视图不透传旧牌面)。

## 3. 影响面与取舍

### 3.1 行为影响面

- **视图 41 处调用点**:透传域值源切换。常态帧(无识别失读)逐位等价——容器值由同一观察漏斗镜像而来;失读帧语义变化,显式申报:透传形态下失读帧拿到的是帧兜底值(raw 0/启发式/旧牌面残留),收编后拿到的是 carried 沿用值或诚实缺位——与已建模域同一「更诚实的输入」申报面(回放语料无失读,逐位零差)。
- **风险 3(决策断粮)的防线落点**:§1.3 逐域对账表 + §2 各域申报 = 正本 W5 列「逐域申报清单」的落地;W6 决策行为锁族全绿门(mandate_v1/intention/economy 既有锁)不减免;实机窗口 1 局备战/商店/结算帧字段核对照正本。

- **删除面(本波)**:各域旧「不入容器」豁免申报(`cw_bs_view.py` 模块头清单逐条核销,收编一条删一条申报)+ 双 ShopCard 在 kernel 的残留引用。投影内 frame 透传段本身随投影整体退役挂 W6,本波不删投影。

### 3.2 边界与不做(防范围蔓延)

- **shop_state_frame 商店黑板不属本波**:策略器商店决策读的是 session 黑板帧(`shop_state_frame`,GameState 形态,写者=商店入口观察段/单动作投影/sim 引擎),它是策略器内部投影载体,其容器化归 W6 决策面切换(sim 引擎真值直写同批)。本波只收编视图透传分支,last_state 侧的 shop 字段消费随之受益。
- **效果键落域不动**(`cw_effect_inventory.py` 虽在 P5 文件面):效果键的域归宿依赖候裁 8「效果域内容语义设计件」成文,归 P4/P5 键收编批,与透传域建模无耦合。
- **invest_cards 效果原文(候裁 2)不预设**:若裁「strategy_offer 域建模」,其载体可复用本波画面附加域 payload 同型机制(在屏 payload/离屏 None),裁决随裁随落,不阻塞本波。
- **dual_track_phase / focus_factions 不建模**:策略侧派生与回填字段(§2.3);视图残差补申报后,W6 消费切换处置其读点。
- **cw_expected_state.py 无残余动作**:已废两步机制,本波进入门据此解锁,无归一切换可做。

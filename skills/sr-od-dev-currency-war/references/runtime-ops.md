# 实机运维细则(单跑道 / 局间交接 / 监控 / 运行坑)

> 实机运维细则(单一源入口 = SKILL.md 分诊表「起局/停局/监控」行)。读者 = 智能体;操作对象 = 本项目的 CW MCP 工具链与游戏画面。

## 哨兵重新启动三步(单实例纪律的操作化;三次双实例事故反推)

重新启动任何 watcher(哨兵/早停/runs 断流)前,**必按三步走,禁直接 arm**:

1. **查旧**:查后台 job 列表看同类 watcher 是否还在 running;
2. **kill 旧**:在则停掉旧实例(双实例 = 重复报警 + 双倍 tail 开销);
3. **arm 新**:确认旧实例已终态(killed/completed)再发新。

事故形态(三次实证,最近一次为停局紧急交接连发两轮重新启动跳过查旧 → 哨兵/早停各双实例并存):**「重新启动」不是一条命令,是三步动作序列**——局间交接时最容易犯。

## 启动与重启

- 启动对局:MCP `run_standalone_app`(app=`currency_war`);进度 `get_run_status`(state/current_node/retry);停止 `stop_run`(信号式,当前节点完成后退出——发完信号游戏可能还在打,等自动战斗结算再动画面)。
- 改代码生效路径 = 重启 MCP server(办法见项目入口文件 §6 的启动脚本)。重启前先确认没有运行中的 run:对局运行中重启会丢对局,先 stop_run 等结算。重启后要确认 MCP 连接恢复(调一次 get_run_status,调通为准),步骤见 autonomous-loop.md §3.6「重启 MCP server」。模板文件改了以后,有的也要重启才生效:往立绘库、装备库加模板,或者改了已有的模板,都要;哪种要、哪种不要,见同一处的说明。
- 重启代价(针对 MCP server 自己在跑的对局):对局丢、session(target/信号/失败记忆)清零——重启后首局 target 重选是已知断档(位面 1),判读时别把首局异当回归。实机探索 agent 自己打的对局不受影响(见下一条「改动集中纪律」)。**位面 2 同样成立(经位面 2 事故扩档实证)**:中断恢复时重建的 StrategySession 策略方向数据缺失(target_comp=None、方向历史不可得)在位面 2+ 的中断恢复对局同样出现——该缺失曾与「动作发出-执行」的衔接缺口复合,造成 15 分钟无推进的卡死(run_20260908_210431;衔接缺口与守卫缺口已修,该形态降级为「出战推进、后续重评」的质量问题,方向数据缺失的治本修复已登记为策略批待办)。**中断恢复的对局 = 卡死类报警第一排查上下文**:NODE-DWELL/守卫停机/断流报警先核恢复态(判定基准 = 日志「已在对局中,跳过 start 交 loop」行 + 首条 state 行直接非 r1),遥测按下方「重启后中断恢复段的遥测不可信」节的口径判读。
- 改动集中纪律:局中不改代码;一局跑完(或早停)再重启加载,改动集中到局间一次重启生效。适用对象 = MCP server 自己在跑的对局;实机探索 agent 自己打的对局,它停下以后就可以改代码并重启(见 autonomous-loop.md §3.6)。
- **起局前核代码新鲜度(机械检查)**:起局前核 MCP server 进程启动时间晚于最新本地 commit 时间(`git log -1 --format=%ci` 对照进程 StartTime)——「重启 server 前起局」= 旧代码跑新局,复现已修 bug 还污染归因(停局-重启-起局序列中此步最易被跳);确认已重启过可跳过。
- 旧自主推进代码带 `# 未验证` 注释:进对应画面复审(重点补日志/截图让每步可观测)后删注释才能信——复审是义务不是可跳的。
- **重启前四步确认**(全过才动手):① `git status` 干净(或仅剩声明过的挂起件;自主推进场景一怎么判,见 autonomous-loop.md §3.6「重启 MCP server」);② 全量 pytest 0 failed(`uv run pytest sr-od-test/ -m "not slow"`,分层命令见 SKILL.md 单一源地图「测试分层」行;自主推进场景一测试有失败时怎么办,同样见 autonomous-loop.md §3.6「重启 MCP server」);③ `check_game_window` is_win_valid=true(无效先 open_game);④ `analyze_screen` 确认在货币战争-大厅(不在则先按下方残局清理序回大厅;例外:自主推进场景一不要求在大厅——对局可能停在半路,见 autonomous-loop.md §3.6)。server 本身挂了、连不上的时候,这里做的是救活它,不是为了加载新代码:①②照做,③④要靠 server 才能查,等 server 起来以后再补做。
- **早停判据**(无信息量局,满足任一即 stop_run + 判读 + 修复 + 重启跑新局):① 死局形态(连续多轮上场阵容缺核心成员,商店里出现了应买的目标成员却没买);② 验证已得(本轮要验证的行为已观察到,后续无新信息——自动化侧=`cw_early_stop.py` 判据表见下节);③ 已知未修问题主导(局是旧代码跑的、修复已 commit 待加载);④ **重大修复待加载=无条件早停重开**——重大策略/战力修复 commit 后,在跑的旧代码局素材价值趋零,继续跑=验证延迟。例外:对照局(A/B 交叉核对)与终验局不适用。

## 局间交接序(停局后到下一局开跑)

本节写给 MCP server 自己在跑的对局。实机探索 agent 自己打的对局不走这一节:对局留着,不清理残局(autonomous-loop.md §3.6)。

1. 停局(stop_run)→ 等自动战斗结算(游戏停后会打完当前战斗)。
2. 残局清理(**优先一键 op `CwEntryExit`(operations/cw_entry/,经 `run_operation` 调用,支持全入口态——备战/战斗中含暂停 X/投资策略等 overlay/胜负结算/失败链,放弃+结算 3 页+回大厅一次完成)**;op 不可用时手动链兜底:结算屏「继续挑战」→ 等自动战斗打完 → 备战态 ESC → 「放弃并结算」→ 失败页「下一步」×2 → 「返回货币战争」;遭遇/投资 overlay 多半要先进后出——「返回备战界面」→ ESC 中断；手动链=人工操作指引，不受 op 代码 ESC 绝对禁令约束）。判定每一步用 `analyze_screen`,认 screen 名不认感觉。
3. `analyze_screen` 确认**货币战争-大厅**精准命中。
4. 重启 MCP(有待加载代码时)→ 重连。
5. 哨兵重新启动:删旧哨兵位置文件(cw_sentinel.pos)再起新实例(单实例纪律——先查 job/进程列表确认旧的不在)。v5.1 起删 pos **可选**(武装一律从日志文件当前末尾起扫〔锚尾〕,水位值不再进读取位置游标,「不删=读旧水位误报」已结构性消除;保留删除步骤作 belt-and-suspenders)。重挂定时轮询时更新提示词里的当期判读重点(过期提示词会误导)。
6. **哨兵活性确认**:启动后 ≤60 秒确认哨兵真的在运行——检查 `cw_sentinel.pos` 心跳文件的修改时间是否持续推进(约 5 秒一跳),或后台任务出现武装行输出;没有回读确认 = 「启动了」不等于「在运行」(2026-09-03 实证:一对哨兵启动后 5 秒双亡,形式上像在岗,首局卡死 26 分钟零有效报警)。
7. **起局前落基准**:`git status` 干净或在飞批已 commit 才起新局——带未提交在飞批起局 = 新局代码态无基准,卡死/复盘无法 bisect(2026-09-03 同日三现)。在飞批未完又必须起局:`git diff > .debug/temp/tree_anchor_<时间戳>.patch` 快照 + 在进度追踪文件记基线 commit 与声明文件集。
8. 起新局。

## 残局画面清单(按 screen 名)

- 货币战争-结算(「继续挑战」按钮;战后 HP 以此屏读数为真值)
- 货币战争-备战(含开商店/装备详情子态;ESC 弹中断)
- 货币战争-中断挑战弹窗(「放弃并结算」)
- 货币战争-挑战失败(「下一步」;可能两页)
- 货币战争-遭遇节点(先点卡选择难度,再底部「选择」;「返回备战界面」右上)
- 货币战争-投资策略/投资环境(「返回备战界面」右上,别硬选)
- 未建档/不确定画面 → `analyze_screen` 先行;仍不明 → 按 od-dev-screen-onboarding 建档流程处理,别盲点。

## 监控栈(长时自主推进)

- 三层:①进程内哨兵 flag(`.debug/temp/currency_war/*.flag`,停机钩子按 od-dev-stop-hooks 处理);②后台哨兵脚本(tail 日志:关键词汇命中即 exit=推送,可自愈词汇走驻留续侦非退出[CONT 事件:只核对证据、不重启实例];只报需介入的事件;水位已停用,同一纪元内同签名去重);③定时轮询兜底(轮到必执行:run 状态+哨兵存活+进度对比+**事件哨兵 HIT 证据文件 `cw_hit_alert.md` 修改时间核对**——v5.1 起一般词汇报警走驻留续侦非退出,轮询核对是 CONT 事件消费延迟的上界)。
- 哨兵单实例纪律:重新启动前确认旧实例已退出;双哨兵 = 重复报警+双倍开销。
- 轮询提示词定期更新:提示词里写死的「当前局 N=某修复首验」会过期,误导后续判读。
- 用户要用电脑 = 全停实机(哨兵+定时+run),别抢鼠标。自主推进场景一(实机探索 agent 用鼠标打局)同理:用户要用电脑,就由用户叫停,按 autonomous-loop.md §3.8 走。

- **HIT 回退开关的停用条件**(防开关债):cw_sentinel.py 的 `CW_SENTINEL_HIT_EXIT_ALL`(环境变量置 1 = 恢复 v5「命中即退进程」旧世界)是分级 HIT 的试用期回退开关——分级通道试用期结束且无「CONT 通道漏掉本该退进程的事件」实录,即删该开关与分支;试用期内出现该形态,则开关转正当长期回退并补记启用判据,禁悬置默认关。

## 效率剖析与巡检阈值回填(「一局时间花在哪」的方法)

> 触发:复盘要回答「这局/这类局时间花在哪、哪段能压」、给监控巡检项定阈值依据、给病理段定量代价时读本节。**本文档不存任何时长/阈值数值**——数值单一源 = 哨兵脚本常量位(去向见本节「阈值回填机制」),本节只立方法。

### 剖析方法(四步)

1. **样本域门**:可分解的数据源 = server 主日志的 `[cw-op]` 行(dispatch 包装/仲裁段在每次画面 op **出口**落一行,格式 `[cw-op] op=<名> plane=<位面> round=<轮次> dur=<秒>s outcome=<ok|fail|error>[ detail=<摘要>]`;主日志 = `.log/mcp_server.log`,MCP 直跑场景 = `.debug/sr_od_mcp/main_server.log`)。**日志轮转窗限制**:证据在主日志,受轮转窗约束——剖析须在轮转前做(深度剖析在局终立即发起,远早于日志轮转窗口);窗口外声明「本局不可分解」。存量形态:2026-09-15(op_journal 流停写)前装配的旧档案 v12 切片仍内嵌 `op_journal.jsonl` 键(冻结只读,供历史查询,enter/exit 配对差分口径);新局档案切片单键无 op 行,一律走日志行口径——两类证据都可分解,报告引用注明证据来源(日志行原文/档案 JSON)。
2. **exit 行直读聚合**:`[cw-op]` 行 = 一次画面 op 调用的出口快照——`dur` 即单次时长(enter→exit 差分已在写入侧做完,无需配对),逐 op 聚合次数与总时长,行内 `plane`/`round` 定位轮次,`outcome` 分型 ok/fail/error。速查命令(直读日志;更复杂的聚合按 telemetry-reading「新复盘需求=新视图」纪律立项,不落盘一次性脚本):

   ```powershell
   Select-String -Path .log\mcp_server.log -Pattern '\[cw-op\]' |
     ForEach-Object { if ($_.Line -match '\[cw-op\] op=(.+?) plane=(-?\d+) round=(-?\d+) dur=([\d.]+)s outcome=(\w+)') {
       [pscustomobject]@{ op = $Matches[1]; dur = [double]$Matches[4]; outcome = $Matches[5] } } } |
     Group-Object op |
     ForEach-Object { [pscustomobject]@{ op = $_.Name; n = $_.Count; total_s = ($_.Group | Measure-Object dur -Sum).Sum } } |
     Sort-Object total_s -Descending
   ```

3. **op 间隙单独记一笔**:相邻 `[cw-op]` 行之间的日志时间戳墙钟差是独立时长来源(结算屏/位面过渡/过场动画)。**段间停机排除**:跨局段与超长间隙一律不计入活跃时长——判据优先用局界/段界硬信号(局终收尾、server 重启);同段超长间隙按停机嫌疑排除,并在报告声明排除量。
4. **bot 开销 / 游戏原生二分归类**:每个 op 与每笔间隙归两类之一——**游戏原生**(bot 只等待演出/结算,代码面无压缩杠杆,杠杆在游戏内速度设置)vs **bot 开销**(决策+点击+固定等待,bot 侧可压缩面);归不了的单列「混合」并写明混合机制。归类依据(该 op 在流程里做什么)写进报告接受复核;证据边界如实声明(如:等待类时长内含出口判定开销——判读战斗是否结束的截图轮询——未单独拆分)。

### 热点归因最小证据标准(缺一件 = 线索,不是热点)

- **量化证据**:次数+单次时长+时间窗,每项带样本局 id 与行内时间戳;时长构成表的每个数字同样带局 id+时间戳标记点,不带 = 不可复核,禁进结论。
- **健康对照**:与无病理局的同 op 分布并列(跨局对照;单局归因是判读大忌,见 telemetry-reading 核心原则);判「病理」必须答出健康局同位置长什么样;「健康局」候选要自证全程无病理段(长局≠健康局)。
- **代码锚点**:病灶定位到机制层(op 代码注记/画面建档/守卫语义),答得出「为什么反复/为什么慢」;机理陈述必须与量化证据相容(次数与单次时长都要被机理解释)。
- **证据分级**:实算构成 > 外推阈值(待健康基线)> 机理推测(标假设级);报告里混级时逐条标注。

### 阈值回填机制(剖析报告的数值去向)

1. **产出门**:报告给巡检阈值只能作**建议**,每条带依据列(健康分布形态+相对倍数的误报余量逻辑+样本局 id);健康基线不足时,显式声明是外推值及基线构成。
2. **落点**:阈值数值的唯一合法落点 = 哨兵脚本常量位(常量带环境变量覆盖便于运行时调参,如 `cw_sentinel.py` 的 `DWELL_SEC`/`CW_SENTINEL_DWELL_SEC`);健康基线攒够前用环境变量覆盖临时调参、不落死值,攒够后固化——固化时把依据摘要(健康基线构成+定标日,纯语义描述)写进常量注释。
3. **覆盖声明**:每条回填阈值在消费端(常量注释)声明三件:巡检项与判读口径(主日志 `[cw-op]` 行相位)、依据样本构成、定标日;注释后续修订时阈值语义必须随迁,禁只换措辞丢判据。
4. **复核门**:固化后遇误报/漏报,先回剖析方法重跑构成表核对分布,再改常量与依据注释——禁先改文档措辞(会造出与常量漂移的第二源)。

## 判读与建档的运维侧纪律

- **重启后中断恢复段的遥测不可信**:server 重启后新 run 段的首个战斗结算前,遥测 hp/gold 是**恢复帧错值**(session 真值丢失,画面恢复期血量 UI 不是战斗血条→会误读成满值)——**中断恢复段 hp 一律不可作判据,以首个真实战斗结算屏(extras.hp_after)为准**;「满血/满金开局」级结论必核上游局的 boss 结算真值(HP 跨位面继承非重置,用户纠错在案)。
- **中断恢复补采的采集时序**:恢复链由备战观察触发委派 `CwEntryPlaneIntel` 编排(game state 已有位面真值 → 零点击直通,不白开白关详情屏;委派失败透传走外循环失败链)→ `CwScreenPlaneIntel` 6 node 管线**恒全采位面1→2→3**(无 start_plane 裁剪;点开节点带详情条联动转移证据);识别失败 = node 重试,耗尽 = op 显式 fail——无「位面N 记 None」占位语义,判读时恢复段报 fail = 识别能力缺口暴露(含纹章风头像 boss:模板库缺该风格的预期失败),不是静默故障。细则 = docs/develop/sr_od/application/currency_war/screens/plane_intel.md。
- **布局/坐标类建档的交互实测确认纪律**:暗框检测/格点外推/VLM 计数都只是**假设级**证据——布局档案的**唯一终审 = 交互实测确认**(拖角色到目标槽看落位+点占位槽开详情面板锚定,用户定调);外推超出实测档位范围不得直接落档,只能登记为待验证假设。判读侧对偶:OCR 单帧读数(cap/部署数)可被同源污染——cap-level≥2 存疑(宝钻语义+1),先重读再采信;VLM 各输出维度可信度独立评价(坐标不可信不等于计数不可信),用户玩家经验与数据冲突时先核数据再动档案。
- **首局判读标记点模板**(重开/重启后首局,事前写跑完核对;条目按当期改动点裁剪):① 决策日志 strategy_id=当期预期栈;② 位面 1 第 1 轮备战 hp 起步值=当期基线;③ [cw] 决策日志流动;④ 本批改动点预期生效行为(新语义无崩溃/新检测触发);⑤ 有中断恢复对局的设计时:接手即直接出战。
- **常置 flag 处置**:`.debug/temp/currency_war/` 长期存在的 `.flag` 是既有登记项,别当新事故——按其登记时的步骤走;已被后续 ADR/revert 裁定取代的登记项,待顺手删(处置记录在进度追踪文件)。

## 运行坑(高频)

- 结算屏残留 → app 启动死循环:起新局前必须确认大厅态。
- **ESC 绝对禁令（op 代码）**：任何 op 不得发 ESC（含 `btn_tap('esc')` / `controller.esc()`）——ESC 语义随画面漂移（备战屏 ESC=误弹中断挑战弹窗，历史 bug）；关闭/返回/退出一律建档坐标点击，找不到可见控件报告等裁决；通用不变量与理由见 od-dev-write-operation 必守#3。
- 晶矿/补给箱占备战席:席满时晶矿点不动,先开箱腾位。
- **等级不足导致出战被拦**:bench 满警告阻塞出战 → 点购买经验升级后警告消失、出战解锁;无金币时卖角色(drag bench→左侧出售区)。
- **事件长尾**:肉鸽事件十余类(锁定备战/巨星强化/投资变体/遭遇/补给/详情弹窗),处理模式=边玩边重构(loop 卡→读屏→加 handler→再跑),别试图一次枚举全。
- **角色/阵营识别边界**:商店 OCR 角色名是主路径;SIFT 立绘库对脸部独特角色可靠、配饰/半身不可靠;阵营激活数以实机 OCR 左面板为准(别硬编码,跨版本会变)。
- 部署上限随投资环境/宝钻动态变(槽位档不固定):别信固定槽位数,读实际 cap;遇到未实测过的槽位布局档位触发采集信号时,按检测结论(verdict)处理——不要把报警静音。
- 画面识别结论有边界:`analyze_screen` 只返回已建档内容(未建档元素静默漏)——行为异常先查日志定位环节,再走画面入口序;VLM 只补漏,不当第一入口。

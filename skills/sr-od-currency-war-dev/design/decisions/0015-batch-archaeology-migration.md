# ADR-0015:批号考古抽象化迁移(SKILL.md 规范 4 债务清偿)

- **Status**: accepted
- **日期**: 2026-08-24

## Context

2026-08-24 review(按 `od-dev-writing-skills` 四硬规范)对本 skill 的 SKILL.md 裁决:规范 1-3 合格,规范 4 有债务——正文堆积「批号考古」:只有本项目当期会话能解码的批号/局号/run 号/commit 号叙事(如「批㉝拦指挥官符号误读」「0299/0300 双窗过线 anchor 窗 gap+5.65 翻车」「⑧拦⑦等级泄漏」「r354 改 LevelUp 门后三个旧锁全炸」「局47 教训 50min」)。对干净智能体(查不到批㉝是什么)这是噪声;「不可解码的具体例子」与规范 4 要防的「以偏概全」同害。

分类原则(review 给定,本次执行):
- **A 判据本体**(可迁移方法论)——保留不动;
- **B 证据强度标注**(「全部有实证」「三次同族事故沉淀」类)——保留,是采信度信息;
- **C 批号考古**(具体批号/局号/run 号叙事,删掉后判据仍完整)——抽象化为「历次批间互证出现过:X 类失败(实证见 design/decisions/)」,细节迁入本 ADR 存档。

## Considered Options

1. **整体重写 SKILL.md**——否决:违背「外科手术不是重写」红线,风险大且 A/B 类内容本就合格。
2. **只删例子不存档**——否决:考古细节含可复盘的证据链(数字/根因),丢失后不可追溯。
3. **抽象化 + ADR 存档**(选定)——判据留在 SKILL.md(干净智能体可执行),证据细节留在 design/(允许具体例子,规范 4 明文豁免)。

## Decision

1. C 类叙事一律抽象为「历次批间互证出现过:〈失败类〉(实证见 design/decisions/)」句式;判据链(为什么要这么做)一字不动地保留。
2. 被抽象掉的考古细节不丢:原文清单存档于本 ADR(见下),供后续维护者追溯证据链。
3. ADR-NN 指针、日期定调(用户权威标注)、B 类证据强度短语不算考古,保留在 SKILL.md。
4. 后续新增 SKILL.md 内容沿用本判据:写「历次出现过 X」不写「批 N 出现 X」。

## Consequences

- SKILL.md 对无会话历史的干净智能体自洽可解码(规范 4 达标)。
- 考古证据链集中在本 ADR 单点;新考古产生时按需新增 ADR 而非回填正文。
- 本 ADR 自身允许具体例子(规范 4 豁免 design/)。

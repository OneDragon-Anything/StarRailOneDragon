# 米哈游启动器自动化操作细则（CDP + Win32）

> 本文供无人值守场景使用。启动器（HoYoPlay）是 Qt + Chromium(CEF) 混合架构：页面是网页（可用 Chrome DevTools 协议脚本驱动），弹出的系统对话框是原生 Win32 窗口（用消息驱动）。两条链路的工具都在本 skill 的 `scripts/` 下。

## 1. 带 CDP 口启动启动器

1. 确认没有正在运行的游戏客户端进程（从启动器拉起的游戏是启动器子进程，后面若需重启启动器会连带杀掉它；发现游戏在跑 → 停下问用户）。
2. **必须以用户桌面上下文启动，严禁从提权 shell 直接启动**：提权上下文下启动器界面读不出已保存的游戏关联——列表缺游戏/显示「获取游戏」（本机实测：提权启动后绝区零不显示；换用户上下文启动，零操作即恢复「开始游戏」）。正确方式（explorer 委托）：
   - 不需要调试口时：`Start-Process explorer.exe -ArgumentList '<启动器目录>\launcher.exe'`
   - 需要调试口时：explorer 不转发额外参数，先写一个临时 wrapper.cmd（第一行 `@echo off`，第二行 `start "" "<launcher.exe>" --remote-debugging-port=9222`），再 `Start-Process explorer.exe -ArgumentList '<wrapper.cmd 路径>'` 委托执行。此组合已设计未实测——若端口未开，退化方案：请用户托盘退出一次，人工带口启动。
3. 若启动器已在运行：它是单例应用，直接再启动只会唤醒旧实例，需要先结束它。结束同样只能走用户上下文：托盘右键退出，或把 设置→通用→关闭设置→「关闭窗口」临时改为「退出启动器」后向主窗口（类名 `Qt51517QWindowIcon`、标题 米哈游启动器）发送 `WM_CLOSE`(0x0010)（实测 1 秒退出），结束后把设置改回用户原值。**严禁 `taskkill /F` 强杀**——强杀是异常退出，会诱发前端档案（Local Storage）重建。
4. 启动参数：`--remote-debugging-port=9222` 是 Chromium/CEF 标准参数，启动器未做屏蔽。等待 10~15 秒让页面加载完。验证口已开：HTTP GET `http://127.0.0.1:9222/json/version` 返回 JSON 即成功。
5. 用完收尾：「关闭窗口」设置改回用户原值，再不带参数经 explorer 委托正常重启一次，调试口即关闭。
6. 端口开不了（`/json/version` 连接失败/超时）：换一个端口（如 9223，`scripts/` 三个 mjs 工具内的 `BASE` 常量需同步修改）重试一次；仍失败 → 放弃无人值守，转人工按界面操作。

## 2. 页面读写工具（scripts/）

前提：CDP 口已开在 9222。工具用 Node（内置 fetch/WebSocket）直连 CDP 的 `Runtime.evaluate`。

- `node scripts/hyp_state.mjs` — 打印页面全部可见文本。用于判断主按钮状态与弹窗内容。
- `node scripts/hyp_click_btn.mjs "<按钮文本>"` — 按精确文本点页面按钮（匹配 `button`、`.button-message`、`.hyp-el-button`）。返回 `{"ok":true}` 才算点到。
- `node scripts/hyp_progress.mjs` — 只打印进度相关文本行（下载中/校验并修复/百分比/剩余时间），适合轮询。

常见文本与含义：`获取游戏`=未关联；`定位游戏`=关联入口；`更新游戏`=有待更版本；`暂停`=更新进行中；`继续`=更新被暂停；`开始游戏`=已是最新。

## 3. 更新主流程（页面已显示「更新游戏」时）

1. `hyp_click_btn.mjs "更新游戏"` 触发更新。部分版本会弹确认框，用 `hyp_state.mjs` 看新弹出的按钮文本并点确认。
2. 轮询 `hyp_progress.mjs`（间隔 30~60 秒），阶段依次为：`下载中`（百分比+剩余时间）→ `校验并修复`（此阶段耗时通常长于下载）→ 进度消失。
3. 每次轮询顺带看游戏所在盘剩余空间。校验修复阶段可能删除旧版本冗余文件，剩余空间可能大幅回升（属正常清理，不是异常）。
4. 结束判据：`hyp_state.mjs` 出现「开始游戏」且进度行消失；再读游戏目录 `config.ini` 的 `game_version` 与目标版本对账。
5. 剩余时间估计参考：下载速度取决于带宽；校验修复阶段会反复修正预估，不要按它判断卡死。连续 10 分钟百分比无变化才算卡住，此时先 `hyp_state.mjs` 找报错弹窗文本再对症处理。
6. 轮询中弹「磁盘空间不足」类报错 → 与空间预检同一原则：停下向用户要空间决策，禁自行删文件；空间处理完后点「继续」恢复，无需重头再来。

## 4. 关联本地安装（页面显示「获取游戏」时）

适用：游戏由旧版启动器安装、或启动器数据里丢了本机安装记录。目标：让启动器认领 `StarRail.exe` 所在目录，之后按第 3 节更新。

0. **先排除提权假缺失**：从提权 shell 启动的实例读不出已保存的游戏关联——表现为缺游戏/显示「获取游戏」，与后端记录无关（`gamedata.dat` 与注册表 `GameInstallPath` 完好）。先经 explorer 委托以用户桌面上下文重启一次再读状态：实测未做任何操作的游戏即恢复「开始游戏」；用户上下文下仍显示「获取游戏」的才是真未关联，走下方流程。

1. 点「定位游戏」→ 若页面弹「未查找到 StarRail.exe 文件，请重试」，点其中的「选择目录」。
2. 系统弹出原生「选择文件夹」对话框。优先用自带脚本完成：
   `pwsh -File scripts/locate_game.ps1 -GameDir "<StarRail.exe 所在目录>"`
   脚本会自动：关掉「位置不可用」报错弹窗 → 取消历史残留的叠加选择框 → 点「选择目录」→ 等选择框出现 → 填路径（写入后回读校验）→ 点「选择文件夹」确认。
3. 回到页面出现「定位本地游戏：为您找到以下游戏资源 崩坏：星穹铁道 <版本> <路径>」→ 点「关联游戏」→ 出现「关联成功」气泡 → 点「我知道了」。
4. 若脚本失败，人工路径相同：在对话框地址栏输入游戏目录回车后点「选择文件夹」。

## 5. 原生对话框 Win32 驱动的坑（自写代码前必读）

实测结论，全部踩过：

- **UIA（System.Windows.Automation）不可用**：此环境下 UIA 顶层窗口枚举被过滤，启动器的对话框完全不可见，别在这条路上花时间。直接用 Win32 API（`EnumWindows`/`EnumChildWindows` + `SendMessage`）。
- **「位置不可用」报错弹窗**：文件夹选择框会记住历史路径（可能是不存在的旧盘符），打开即弹此错误。处理：枚举到标题为「位置不可用」的 `#32770` 窗口，点其子控件中文本含「确定」的 Button，可能反复出现，循环关到没有为止。
- **叠加模态**：多次点「选择目录」会叠多层选择框，确认信号会被混乱的模态状态吞掉。开工前先循环取消所有「选择文件夹」窗口（点子控件「取消」Button），保证只有一个。
- **填路径**：对「文件夹:」标签旁的 Edit 控件发 `WM_SETTEXT`(0x000C)。**验证必须用 `WM_GETTEXT`(0x000D) 回读**——`GetWindowText` 跨进程读不到该 Edit 的内容，会误判失败。
- **P/Invoke 入口点**：`DllImport` 的方法名必须配 `EntryPoint = "SendMessageW"`（带 `CharSet.Unicode` 时封送器会找 `<方法名>W`，不配 EntryPoint 必然 `EntryPointNotFoundException`）。`scripts/locate_game.ps1` 是可用的完整参考实现。
- **定位目标目录**：填「直接包含 `StarRail.exe` 的目录」；启动器在所选目录里找游戏主程序 exe，填上层目录会报「未查找到」。

## 6. 版本信息与启动器自更新

- 游戏当前版本以 `<游戏目录>\config.ini` 的 `[General] game_version` 为准；启动器注册表项里的版本号滞后于更新时不可信。
- 启动器自身也可能有待更新（页面文本含「立即升级」类按钮）：先让启动器完成自更新再操作游戏，避免更新中途换内核。

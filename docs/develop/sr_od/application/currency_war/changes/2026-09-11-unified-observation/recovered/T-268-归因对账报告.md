## 3. 归层结论(必填)

- **根的层位:执行层**(部署 op `cw_op_deploy` 的落地判定决策点)——具体=拖拽后落点验证原语 `_wait_slot_occupied`(2s 纯像素轮询)与拖拽循环**不感知「部署本身会触发 decision overlay」这一游戏机制**;overlay 识别与处置的职责在分发层(0a 分支/CwScreenPartner,已在),但分发只能在 op 调用间隙看到 overlay,**op 执行中途出现的 overlay 无任何一方看管**。
- 首例当时的「混合码运行」归因(T-106 note 08:54:53)适用于**升级窗噪声**(08:52-08:53 的观测冲突群),不适用于 placed=0 本体——placed=0 机制(overlay 致盲)在二例(干净码、哨兵在案)完整复现,且 09-08 晚间第三发同机制,与混合码无关。
- 层位归属判据:像素判占用本身无错(1-1 事故防线),错在**判定规则缺一条「遮蔽域内像素判据无发言权」的前置**——这是执行层判定逻辑的语义缺口,修在执行层;不需要动分发/决策/识别层。

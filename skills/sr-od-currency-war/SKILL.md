# 货币战争游玩指导

通过项目 MCP server 的 `analyze_screen`（画面识别 + 结构化读数）与 `run_operation`（动作 op）玩货币战争。核心循环 = **观察（读 extras——extras 是 `analyze_screen` 返回里的读数字段，装着金币、血量、在场单位、商店在售牌等当前局面数据）→ 决策（花金币强化阵容）→ 执行（动作 op）→ 再观察对账**。

**每个 op 执行后，必做一次画面识别**：用 `analyze_screen` 确定新画面是什么（命中的画面名直接查 `references/screens/<画面名>.md`），再决定下一步。识别不命中只有两种解释：①上一动作的过渡还没结束（等几秒重新识别；各动作的典型过渡时长见对应画面文档）②进入了没见过的画面（识别库里没有它,自己读图判断当前状态）。

**玩法知识文档的阅读顺序**（第一次玩按序补课，详见 §3）:① `references/gameplay-basics.md`（机制地基，玩一局前读）→ ② `references/decision-guide.md`（对局决策，随阶段翻）→ ③ `references/comps-codex.md`（阵容图鉴，定方向/查参数用）。本 SKILL.md 只管操作；「买什么、升不升、什么时候搜牌」的判断依据在那三篇里。

## 1. 全局交互铁律（所有画面通用，先读这节）

1. **按钮点击失败时，先查状态再怪手势**：按钮点击无效几乎都是**状态问题**，不是点击方式——①引导气泡挡着（首见引导，完成引导动作即消失）②按钮置灰（前置条件没满足，如投资策略未选卡）③对局软锁（投资策略未选完时出战被抑制）④商店面板开着（第一下点击只收店）。逐一排除后默认 0.1 秒的静态点击对所有按钮（含长条胶囊形状的按钮）有效；**微距拖拽（按下→横移→抬起）仅作最后兜底**（MCP `drag` 工具，duration 0.35）。
2. **卡片选中点图标区**：投资策略（对局中不时出现的三选一卡，机制见 `references/gameplay-basics.md` §3.5）的卡片，点标题/文字区不选中，**点六边形图标区（卡片上部约 1/3 处）才选中**；选中态 = 卡片白框亮起。确认键置灰 = 还没选中。用 op `...actions.cw_pick_invest_strategy.CwPickInvestStrategy` 可跳过此坑（内部已按图标区实现）。
3. **游戏会偶发吞点击**：任何点击都有约 5% 概率被游戏侧吞掉（op 机械上正常发出，但画面没反应——实测商店开关 18 周期出现 1 次）。应对 = 核心循环的「再观察对账」：发现画面没变化就原样重发一次动作。这不是 op 缺陷，是游戏侧特性。
4. **拖拽部署前必须重读；点击晶矿后也要重读**：晶矿 = 备战画面上可点击的开箱物（点开掉落单位/奖励进备战席），开箱掉落的单位会插到备战席**非首空位**（实证：槽 1、2 占用时掉落物插进槽 4，跳过空槽 3）——旧读数不含新插入的单位，按旧槽号拖拽会扑空；点击晶矿采到奖励后同样重读一次再决策（奖励入席会改变备战席占用）。`DragCwChar` 的 from_idx 必须来自**最新一帧**的 extras.bench（备战席槽号 = 物理槽位，空槽以 empty 保留，不压缩）。
5. **analyze 的 board 字段只是面板可见行**：v4.7 羁绊面板会滚动+重排，OCR 只读到可视子集；羁绊计数决策以画面识别得到的 front_line/back_line 单位表为准，board 仅作快照参考。
6. **开商店画面不提供行读数（键都不出现）**：商店面板开着时，analyze 的返回里**没有** front_line / back_line / deploy_count / deploy_cap / hp / reward_ores 这几个键（商店牌行盖住计数、面板遮挡使角色识别不可靠——设计性省略，不是识别坏了）。要这几项就收商店后用备战画面读；商店画面自己的强项（shop_cards 商店牌、refresh_probs 刷新概率、bench 备战席、gold 金币、board 羁绊面板行、owned_equips 装备栏）照常返回。
7. **动作 op 只管机械执行**：出战/拾矿等 op 不做任何校验与特殊情况处理——收店前置、未达上限弹窗确认、部署未满/席满等状态前置全部由你负责（按各画面文档自查）。部署未满时点出战会弹「可出战角色人数未达上限」→ 点「确认」（约 1170,672）；「本局不再提示」勾选框不代点（玩家偏好）。
8. **extras 全 null = 识别器异常降级，别卡死等待**：识别器异常时 extras 可能为全 null（实测）——此时用存图 + 亲自读图 + OCR 散点顶替继续对局，不要卡死等待；对局结束后按缺陷上报。
9. **延迟弹窗会吞掉先前的点击**：点完出战等关键动作后，下一帧若发现弹窗（如银狼二选一），视为该动作被弹窗吞掉——先处理弹窗再重发动作（实测）。弹窗存在期间，「备战-开商店」这类模糊命中的 area 坐标会整体错位，不要按错位坐标点击。

## 2. 一局的标准流程

1. ☐ 进大厅：`CwEntryEnter {}`（全自动，约 15~30 秒）→ 完成判据：run_status「已在货币战争大厅」
2. ☐ 开局：点「开始货币战争」（胶囊，微距拖拽）→ 模式选择点「进入标准博弈」→ 职级难度点「开始对局」（胶囊）→ 简报点「下一步」翻页 → 位面过渡点空白 → 完成判据：analyze 命中 货币战争-备战
3. ☐ 节点循环（每位面约 9 节点）：备战画面按 `references/screens/货币战争-备战.md` 操作（拾矿→开店→买牌买经验→部署→出战；每个节点「买什么、升不升、搜不搜」的决策依据 = `references/decision-guide.md`）→ 战斗等约 90 秒 → 结算点「继续挑战」→ 循环
4. ☐ 位面末 BOSS：出战按钮变「选择主角」→ 按主角光环选择卡操作（选光环+拖主角+确认）→ BOSS 战 → 位面过渡点空白进下一位面
5. ☐ 终局（HP 归零或通关）：按结算卡走完四页结算回大厅
6. ☐ 自我验证：终局后 analyze 命中 货币战争-大厅（锚齐全）才算一局完整收尾；中途退出则确认停在安全画面

## 3. references

- **玩法知识文档（按阅读顺序）**：
  1. `references/gameplay-basics.md`——机制地基：怎么算赢/经济系统/战力三轴/版本环境。玩一局之前读。
  2. `references/decision-guide.md`——对局决策手册：一局时间轴/各阶段怎么花钱/风险管理/主角光环怎么挑。对局中随阶段翻。
  3. `references/comps-codex.md`——阵容图鉴：19 条阵容线的成员/目标等级/关键档位/装备，含「信号→路线」速查表。定阵容方向时对照识别信号，定向后查该线参数。
  静态数据（角色/羁绊/装备逐项详情）不在这三篇里，随查 MCP 工具 `cw_char_lookup` / `cw_trait_lookup` / `cw_equip_lookup`。
- **按画面查操作**：`analyze_screen` 命中的画面名（如 `货币战争-备战`）直接对应文档 **`references/screens/<画面名>.md`**——里面有该画面「能做的事」全清单（操作/用哪个 op/手势/验证/坑）。例外：职级难度画面已精准识别，画面名 `货币战争-难度确认`（实测），文档文件名仍为职级难度.md；其余无精准命中的画面（结算流、弹窗类）按 SKILL.md §2 流程位置对应的描述性文件名查（战斗结算/终局结算/奇遇对话/未达上限弹窗/强敌来袭横幅）。
- **op 定位符可用类名短名**：`run_operation` 支持直接用 op 类名短名（如 `CwToggleShopPanel`），不必写完整模块路径；短名冲突时才需写完整定位符（实测）。

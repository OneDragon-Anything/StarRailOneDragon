# 单局复盘协议(判定方法论 + 粒度=外层循环画面op调用,载体=渲染器画面章)

> **定位:本协议只做数据复盘**——重建画面、玩家打法对照、位面三问、候选修复项;**不管 bug 定位与修复路由**(复盘报告交给编排者分诊处置,口径=autonomous-loop 实机监控第 4 步)。
> **执行者 = 干净上下文的子 agent**(每次复盘新开,不带编排者偏见)。**触发 = 实机监控局终派单**(每局一单,后台异步)。**报告由渲染器生成**:`tools/cw/replay_to_md.py`(运行需 `PYTHONPATH=src`)——实机局 `--match <game_id>` 读档案切片,sim 局/未装配局 `--journal <journal路径>` 读裸 journal(配 `--game-id` 命名);缺省落盘 `.debug/currency_war/deep_review/<game_id>.md`(深评固定落点)。复盘点 = 在该报告上填逐决策面画面章的 `策略评价` 节与文末「复盘者附加」节;45min 策略审查角色消费产出作病灶输入,不重做。
> **判定尺 = 玩法文档 + 已登记用户裁定**(§判定尺,2026-09-07 用户裁定)——判「算法做得对不对」;迭代目标只排修复优先级,不参与判卷;A/B 验证当期改动才用当期目标行判据(telemetry-reading 判读流程步骤 0 的分界,两种活动别混)。

## 阶段 1 · 阅读理解(开工前提;任务书直接引用本清单)

- 玩法知识:`docs/game/currency_war/research/README.md` 玩家理解序全读(机制 → 纪律 → 过渡 → 终局);
- 游戏数据注册表通读:角色技能(`cw_chars`)、羁绊效果(`cw_factions`)、装备效果(`cw_equipment`)、投资策略/环境效果(`cw_invest_data`)、词缀效果(`affix_effects_data`);
- **已登记裁定面**:进度账本(`.debug/progress/` 当前迭代 `dag.jsonl`)的已登记用户裁定条目(如「经济纪律族」类条目)与 `docs/develop/sr_od/application/currency_war/strategy-docs/` 各篇的【已裁定】注记——判定前先取齐,引用时带条目号。

## 阶段 2 · 逐画面章复盘(按渲染报告章序;2026-09-07 用户裁定:粒度 = 外层循环画面 op 调用,报告中载体 = 渲染器画面章)

复盘基本单元 = **一次画面 op 调用**(架构依据:`docs/develop/sr_od/application/currency_war/screens/op-layer.md` §1.1「总则:一次画面 op 调用 = 一轮『入口观察 + 逐动作决策循环』」;分支序表 = `flow/outer_loop.md` §2.2)。报告中该单元的载体 = **画面章**:凡定义的画面 op 有 journal 行即成章(画面注册表 = 渲染器 `tools/cw/replay_to_md.py` 的 `ACTOR_REGISTRY`/`SCREEN_REGISTRY` 常量,注册同步义务锚 = `screens/op-layer.md` §3;零写入行的 op 自然不出现——数据不存在,非设计排除)。节点章 `## 节点 P-R 类型` 下逐画面开章,章内固定结构 = `#### 0 观察`(开章快照 ∩ 注册键集 + 本章观察道写入动态显影——画面 op 观察到什么本章显什么,首写定帧值)+ 动作节×N(一条回执一节,失败重发合并一节)+ `#### 策略评价` 空节(仅决策面画面章有);装配策略遥测时另铺「策略依据」渲染,决策面画面章按决策来源分两态——备战/商店域 = 动作节标题下依据块(渲染器按回执 `dtag` 关联决策记录,失败重发合并节内随节累积),选择族章(备战/商店外的其余决策入口,动作走上报函数族不产回执)= `0 观察` 后独立 `#### 策略依据` 小节(章级挂载,同键多章按记录序 FIFO 对章首现序分配):

```
## 节点 1-1 奖励
### 节点 1-1 奖励 画面-备战          ← 画面章 = 一次画面 op 调用
#### 0 观察                          ← 章首快照:金/血/等级经验/板面/持卡…(渲染器产出)
#### 1 买牌 藿藿(1金)                ← 动作节×N(渲染器产出:动作行 + 状态变化表)
#### 2 换位 …
#### 策略评价                         ← 复盘者填判定三槽
### 节点 1-1 奖励 画面-商店
### 节点 1-1 奖励 画面-战斗
```

**边界 = 渲染器画面章/动作节产物,复盘者不重建**:画面章怎么切(journal 行画面证据:current_screen 快照变化 + 弹层 actor 注册表)、动作节怎么切(回执行,同 op 失败重发合并一节;章归属锚 = 回执 screen = 动作发出画面,转移类动作归发出画面章)、策略依据块/小节怎么挂(动作级回执 `dtag` 关联,选择族章级映射挂载)都是渲染器管线行为,复盘者按报告已切好的章/节读,不回原始数据重拼——商店访问次数等逐类计数 = 对应画面章计数。旧边界口径(决策帧词表切分/outcomes 行定位/op_journal·`[cw-op]` 日志行三载体计数)依赖的旧流与日志载体已停写,随本迭代废止,不再作为边界判据。素材入口:实机局 = `--match <game_id>` 渲染(查询工具见 telemetry-reading「查询工具」节);sim 单局素材采集 = skill 脚本 `cw_sim_match_drive.py`(见 sim-testing「单局复盘素材采集」节)。报告文末「未归节/未归行」清单与章尾缺口注记(未注册画面 op、策略遥测两注记:「策略决策未落地」= 遥测有备战/商店决策记录而同帧回执未匹配、「策略 dtag 失配」= 回执带 `dtag` 但对应决策记录指纹不符等)= 渲染器如实申报的完整性缺口,复盘者逐项并入「复盘者附加」的完整性申报;应有动作而整章缺席也记申报,别当「没发生」。

**判定三槽承载面**:备战/商店/投资环境/投资策略/补给/遭遇等有策略选择的画面 = 决策面画面章,渲染器必铺 `策略评价` 空节,复盘者在此按原三槽作答(决策正确性/是否符合发展主线/备选与改进);战斗窗/BOSS 简报/位面转场/对局收口等非决策面章无评价节,只读观察(战前部署在 0 观察,结算变化在章内变化块)。

## 判定尺(2026-09-07 用户裁定:方法论)

- **判定尺 = 玩法文档 + 已登记用户裁定**,判「算法做得对不对」;**禁把算法内部自洽当合格判据**——「拒因存在/符合算法逻辑」不构成「决策正确」。
- 每个判定三槽先问「**玩法文档/已登记裁定说正确做法是什么**」,再对照算法实际决策;**偏离即算法缺陷候选**。
- **缺陷候选证据格式**:journal 字段锚/渲染报告章锚(当帧数据)+ 裁定/文档出处(file:line 或条目号)+ 已登记修复任务号(有已登记任务引任务号,无则立新候选标记)。
- 裁决口径沿用:以决策时点的信息与期望值口径判断最优性;禁用「运气」作归因,禁用事后结果反推(牌后来没来,不构成当时不买的理由,也不构成当时买了的功绩)。
- **判「某键异常」前先核该键的写入语义**(事件计数 vs 状态暴露/逐帧累加),单一源 = 写入点代码注释——逐帧累加型键禁按事件频度判读,绝对值只作跨局带对照,时滞类问题盯轮差分键;按事件频度误读状态暴露键 = 无中生有的排查立案。

## 回灌判据读数(必填;缺 = 复盘未完成)

逐章判定之外,固定读四组数作缺陷候选的**回灌对照基线**(修复后同口径复测比对用)。取数锚 = journal 字段——渲染器已按动作节/章内变化把行间差分算好,报告内直接读:
①**buys**——购买动作数与花金分布(锚 = `BuyCard` 回执行 + `gold` 写入链,动作节状态变化表已带金差分);
②**2★/3★ 到手与到位轮次**(锚 = `bench`/`board` 写入链,星级演进按单位「名★级」格式逐节差分);
③**hp 均值与区间**(跨局对照口径,单局只记值;锚 = `hp` 写入行 + `settlement` 写入行 hp_after;hp 判读口径 = telemetry-reading);
④**刷新带**——刷新次数与触发轮分布(锚 = `shop_refresh_cost` 写入行、刷新回执与 journal `shop` 写入行(内嵌 `refresh_probs` 键),免费刷新余量看 `free_refresh_left`)。
只读数不裁决(裁决归编排者);每个数字带局 id 与行锚(报告章/节或 journal 字段),不带 = 没读。

## 产出形态与红线

报告 = 渲染器产物 + 复盘者填空,两层别混:
- **渲染器产出**(`tools/cw/replay_to_md.py`):局头(meta 逐行键值:对局/运行段/策略版本 commit/注册表指纹/时间窗/终局/数据完整性/策略遥测——行 = 策略 id 与记录条数,未归属 > 0 行尾带条数)→ 开局章(BOSS 简报/投资环境等)→ 节点章×N(`节点 P-R 类型`)内逐画面章(`0 观察` + 动作节×N + `策略评价` 空节;「策略依据」装配面见阶段 2)→ 文末固定 `## 复盘者附加` 空节。策略遥测装配 = `--strategy-telemetry <jsonl 文件或目录>`(缺省探测 journal 同根 `strategy/`);无策略文件/空目录 = 功能关闭,报告零差异。**无收尾章;局况速览/候选清单/回灌读数/完整性审计/自检/计数器章节一律不输出**——这些属复盘者义务产物,落点 = 文末「复盘者附加」节(2026-10-16 用户裁定)。
- **复盘者填空**:逐决策面画面章 `策略评价` 节填判定三槽;「复盘者附加」节装四产出——候选修复项(带证据链;单局归因=候选,跨局/sim 验证才定案)、回灌判据读数(上节)、位面三问总答、完整性申报(未归节/未归行/缺口注记逐项处置 + 整章缺席申报)。**「复盘者附加」内零条「算法缺陷候选」= 复盘未完成。**

**机制归因的数据口径**(候选修复项要追「为什么」时):读 journal 写入行(行带版本 id v 号,按当版语义解读);要「按现行策略会怎样」→ 回放(当期代码对档案状态现算,单帧测试同款)——两者都不读旧决策日志流(已停写)。

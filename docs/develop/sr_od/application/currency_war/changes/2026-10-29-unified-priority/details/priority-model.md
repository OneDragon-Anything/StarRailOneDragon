# 角色统一价值序（详设）

## 问题与约束

本篇定义统一优先级排序的**唯一判据源**：输入（局面, 牌）→ 输出排序键；全部消费点（获取角色流程 / 溢出 / 凑钱凑位 / 补给选角色）只消费本篇定义的函数，禁第二排序实现（总纲 §2.9 接口契约 1）。

约束：
- 各档判定的数据源必须是注册表/既有单一源现查，禁新造名单（档 6 万金油名单与档 7 羁绊名单为用户拍板的既有常量/注册表查值，例外）；
- 排序必须确定可复现（随机尾键走局内随机流，同 seed 同序）；
- 手牌场景与获取场景共用同一函数（在手旗标区分），禁场景分支。

## 方案

### 1. 判据模块与函数形态

新文件 `src/sr_od/application/currency_war/strategies/impl/mandate_v1/criteria/priority.py`：

```python
def sort_key(unit: HeldUnit | ShopUnit, ctx: PriorityContext) -> PriorityKey
def sell_order(units, ctx) -> list   # 排序后序列：末位 = 最先让路
```

- `PriorityKey` = 有序元组 `(档位, 子键1, 子键2, …, 在手旗标, 随机尾键)`，字典序比较；**让路方向 = key 大者先卖**（档位编号大 = 优先级低 = 先卖，与总纲 §2.1 一致）。
- `PriorityContext` = 排序所需只读输入的装配体（一次性装配，禁散参）：**持牌全量快照（角色名 → 该名全部副本星级列表；读源 = 备战位 ∪ 前后台一次只读取，档 2/5/6/7 的聚合谓词——持有最高星/总星级数/名下有无副本——均消费此快照，与池子过滤无关：池子过滤只决定哪些牌进入排序输出，聚合判定永远看全量）**、部署在场名集（接口契约见 acquisition-and-sell §部署接口）、锁定线名单视图（`session_scope.line_members_view` 现读口）、候选快照（`StrategyState.line_candidates`）、**过渡配方对成员（未锁定帧档 2/3/5 名单的配方支来源——候选快照只承载三线、`line_members_view` 未锁帧返回空，配方成员读口单一源 = `opening_recipe_comp`/`direction_comp_of` 现读口）**、当前升星目标（`criteria/levelup.stay_target_of`）、必要星级表（知识卡 `need_star` 字段 COMP_LIBRARY 直查——`unfinished_star_targets` 仅锁定帧适用，见 §2 双帧态取值）、当前等级（概率查表键）、随机流。
- `HeldUnit` = 手持牌（场上/备战位统一形态：名、星级、槽位、是否在场）；`ShopUnit` = 商店候选牌（在手旗标恒 = 将获取）。

### 2. 档位判定（按序命中即出；每档给数据源与谓词）

| 档 | 谓词（按序） | 数据源（单一源） |
|---|---|---|
| 1 | 牌的角色名 ∈ 部署在场名集 | 部署接口输出（acquisition-and-sell） |
| 2 | ∈ 阵容成员名单 ∧ 持有最高星 < 该成员必要星级（need_star）。**成员名单两态**【拍】：未锁定 = 候选快照三线成员并集 ∪ 过渡配方对成员（配方成员在配方体系存续期（P1）属候选体系；**退出 = P2 进入 ∨ 锁定终局阵容，取先**——kernel 配方支 P1 即清空（进 P2 后永不再写，cw_intention.py:1228-1247），未锁定帧穿 P2 边界时非三线配方成员在 P2 进入帧退出本名单；锁后非新线成员按统一序列自然落位，不设 P1/P2 分支）；锁定 = 锁定线名单（`line_members_view.members`）。**need_star 取值**：锁定帧 = 锁定线知识卡 need_star（消费单一源 = `unfinished_star_targets` 现役，仅此帧适用）；未锁定帧 = 该成员命中的各候选线 need_star 取**最大值**（保守方向：按最高要求判定，未达标即受档 2 保护；`unfinished_star_targets` 未锁期恒空集不适用此帧，need_star 直查知识卡字段 COMP_LIBRARY）；**无表项成员**（过渡配方物化对象等不在 COMP_LIBRARY 的名字）= need_star 视为 1（无升星要求）→ 落档 3（未持）/档 5（已持未到两星）。「持有最高星」= 该名全部在场+备战副本的最高星（持牌全量快照） |
| 3 | ∈ 阵容成员名单 ∧ 名下无任何副本（仅商店牌可命中） | 同档 2 名单源 |
| 4 | **非阵容成员** ∧ 费用档 == 当前升星目标实费档（排除项 = 阵容成员整体——含已达标成员，其副本按总纲 §2.1 落档边界落档 8，不进本档）；当前升星目标为 None（未锁定窗口恒 None，`stay_target_of` 口径）时本档为空，全部落后续档 | `stay_target_of`（resolved 实费口径，变费卡随档）＋阵容成员判定同档 2 名单源 |
| 5 | ∈ 阵容成员名单 ∧ 名下有副本 ∧ need_star ≤ 1（无升星要求）∧ 未持有两星（名下最高星 < 2） | 同档 2 名单源 + need_star |
| 6 | ∈ 万金油名单（`CROSS_LINE_KEEP_NAMES`，protection.py 常量保留）∧ 名下最高星 < 2 | protection.py（单一源保留） |
| 7 | 角色 ∈ 档 7 羁绊（盛会之星/量子同频/护盾/减益，按角色自报 factions/flows 现查）∧ 名下最高星 < 2 | `cw_chars` CHARACTERS 自报 factions/flows（成员关系派生，单一真相源 = cw_factions.py 模块注释声明） |
| 8 | 兜底（任何未命中 above 者） | — |

**落档边界谓词**（总纲 §2.1 已拍板语义的实现形态）：
- 「名下最高星」以**角色名**聚合（同名跨星全部副本参与）——升星达标判定 = 持有最高星 ≥ need_star；达标后其低星副本因不满足档 2 的「< need_star」落入后续档（档 5 要求 need_star ≤ 1，达标成员 need_star ≥ 2 时直接落档 8）；
- 档 6/7 的「没到两星」= 名下最高星 < 2；升到两星后掉档 8；
- 「有星级要求」语义 = need_star ≥ 2（need_star = 1 即无升星要求）——与现行 `unfinished_star_targets` 的缺口判定同轴（其「当前星级 < 必要星级」口径）。

### 3. 档内排序键

| 档 | 子键（先到先定） |
|---|---|
| 2 | ①阵容内优先级序数（迁移期 = core 成员 0、其余 1；字段与迁移形态见总纲 §2.1.1。**取值规则**（此序数键为档 2/3/5 共用）：跨线成员取其命中各线中的最高优先（core 优先于非 core）；过渡配方成员迁移期统一取低优先级——配方对成员本为过渡件，精调随外溢迭代）②总星级数（该名全部副本星数相加，多者后卖）③**单卡星级（高者后卖）**——通用「同优先级优先保留高星」规则在本档的承载（跨星副本场景：追三星持 1★+2★ 时，2★ 副本更接近目标星，先卖 1★）；无此键则跨星副本落随机尾键，可能卖掉高星副本，与档 2 目标冲突 |
| 3 | 阵容内优先级序数 |
| 4 | 星级（高者后卖——两星压库牌 = 牌池已抽三张） |
| 5 | ①阵容内优先级序数 ②总星级数（该名全部副本星数相加，多者后卖；档 5 名下全为一星副本，总星级数即副本计数——「更容易到两星」） |
| 6 | **总星级数（该名全部副本星数相加，多者后卖）**——档 6 谓词保证名下最高星 < 2，全部副本皆一星，总星级数即副本计数（攒两张的比一张的离两星更近，先卖一张的——总纲 §2.1 的 6.1）；档内单卡星级键恒为一星常数、不判别，故不设 |
| 7 | **总星级数（同档 6）**——档 7 谓词同限名下最高星 < 2（总纲 §2.1 的 7.1） |
| 8 | 第一键：费用档的商店出现概率（`cw_shop_odds.refresh_prob(当前等级, 费用档)` 现查，概率高者先卖；同概率档并入同档——按概率值分档非按费用号；概率同值时按费用号升序稳定序，低费先卖。**口径注**：基线概率表，投资环境轮岗（每备战阶段随机一费用档概率翻倍）不感知——确定性不受影响，排序质量观察项）；第二键：星级（高者后卖——此键仅档 8 有判别力） |

### 4. 在手旗标与随机尾键

- 在手旗标：手持牌 = 0，商店/补给候选牌 = 1；同优先级下 0 先于 1（在手优先，总纲 §2.7 已拍板）——获取流程的虚拟局面中两类牌同池排序，旗标自然生效；纯手牌场景全部为 0，零影响。
- 随机尾键：仅当以上全部子键（含在手旗标）相等时参与——即**同一张手持等价牌群内部**的卖出顺序（如两张同角色的 1★ 副本）；跨星副本已被档内星级键区分、商店牌已被在手旗标区分，均不入随机域，随机结果无行为语义损失。实现 = 尾键位置放随机值；随机流实例 = **策略器自有随机流 `StrategySession.rng` 直用**（构造时按 strategy_seed 播种，`cw_strategy_session.py`——策略随机语义本就归它承载，同 seed 同序，不新增派生设施）【详设定案】。

### 5. 卖出取用形态（消费侧约定）

- `sell_order` 返回从「最不该卖」到「最先让路」的序列；各触发消费位从**末位**向前取用（让路一张 / 取到凑够为止）；
- 溢出触发：部署重排定型后消费整个序列末段（连续卖出直至不溢出）；上阵安置 = 部署补位自然承载（部署逻辑保证前后台无空位，现行 M1 补位机制），无特殊安置规则；
- **无场景专属池子**【拍】：卖出类触发（溢出/晶矿/凑钱/筹资）统一按部署重排后的全局面序列取用，不设「只看备战位」类过滤——部署定型内的牌 = 档 1，天然排序列最前端、永不先卖（行为上等价于只动备战位与部署外牌）；「资格面真全量豁免」指溢出场景的循环防线全通道豁免，非池子扩面；豁免保留。**例外：获取角色触发的排序池 = 备战位**（物理约束：店内只能卖备战位——该触发的比较仍看全局面，卖出动作只落备战位）。

### 6. 旧判据退役与本篇的边界

- 旧卖出价值函数（变现价 + 再遇期权 + 合成进度，`criteria/sell_candidates.py` 场景注册表内的价值口径）整体退役，被本序列替代；概率表保留为档 8 分档数据源，退金表为凑钱触发的目标算术数据源（非档位判定输入）；
- 旧「挂后台效果」资格谓词（`predicates.bench_effect_qualified`）的**四处**消费位退役去向：评估器（`criteria/sell_candidates.py`）、凑息档序与危局阀桶（`criteria/sell.py` 两处）随场景重写退役；`mandate.py` fuel_sell_candidates 内部一处由 dismantle 拆除项显式删除（dismantle §3）；
- `fuel_sell_candidates` / `sell_exclusions` 身份段 / `funding_hold_fallback` 退役清单见 dismantle 详设；物理谓词保留，迁移分层：占位件不可卖 → 池子过滤层；一星全额退口径 → 预算投影/凑钱目标算术（非卖出资格过滤——总纲 §2.4「不设仅一星代理过滤」）；合成素材守卫 → 循环防线层（与 design §2.4、dismantle §4 统一口径）。

## 关键取舍

- **档位结构 vs 连续价值函数**：用户裁定档位结构（可解释、查表确定、无连续权重）；旧函数的「再遇期权」连续值由档 8 概率分档近似承载，放弃连续精度换判定透明——已拍板。
- **候选三线成员同档 vs 按榜位分档**：同档（候选每帧重算，榜位抖动会让保护面震荡）——已拍板。
- **随机兜底 vs 槽位号兜底**：随机（用户裁定）；槽位号会让「先买的牌永远先卖」产生系统性偏差——随机消除该偏差。在手旗标加入后随机域收窄至手持等价牌，语义无害。
- **快照形态 vs 容器深拷贝**：归 acquisition-and-sell（部署接口契约的载体选择），本篇的 PriorityContext 装配体对两种载体均兼容（只读输入）。

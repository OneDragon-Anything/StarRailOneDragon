# 阵容知识工程方法论(提炼/深读/版本更新重跑)

> SKILL.md §阵容知识工程的展开。读者 = 智能体;适用于:从零提炼阵容体系、新增/修订单套 comp 知识、版本更新后重跑深读。

## 证据三层(核心纪律;缺层即盲区)

| 层 | 来源 | 给什么 | 缺失盲区 |
|---|---|---|---|
| **统计骨架** | plaza API 聚类(carry 聚类 n≥5/羁绊频次/装备频次,生成器 `tools/cw/gen_plaza_comps.py` 重跑) | 什么主流、什么是代表、量级分布 | **发现不了细节**——频次说「某角色常驻」不说为什么;单聚类混多形态;巧合被当规律 |
| **逐篇细节** | 攻略帖 description 全文**逐篇精读**(纪律:必须逐个看,不能偷懒;每看一篇记录一篇) | 作者运营思路/时序/条件判断/变体/降级路径 | 只有统计时:看不到「什么条件下这么打」,高频 ≠ 正确 |
| **机制解释** | 游戏数据本体:角色技能效果/羁绊效果/装备效果/投资策略·环境效果(注册表+图鉴+官方 config) | **玩法为什么是这样的**——因果链 | 只有攻略时:知其然不知其所以然,版本一变全部失效 |

**工作流**:统计给候选 → 逐篇读细节 → 游戏数据验证机制——「为什么」成立才收编为结论;机制不成立的高频做法标 [社区] 存疑,不进决策链。

**机制解释层的数据源细分**(读什么去哪读):
1. **角色技能说明**——⚠️ 两层数据源别混:官方 config API 的 skills 字段只有技能名无描述;BWIKI 货币战争/<角色名> 页有全文(含星级数值);游戏内图鉴同等权威。判例:角色「以更高速度行动」类技能只在技能层可见,羁绊层推不出——统计说它常驻,技能文本解释它为什么是引擎件。
2. **羁绊效果**——官方 config `role_list.trait_details` 程序可读(激活门槛在此层)。
3. **装备效果/投资策略·环境效果**——注册表(`cw_equipment`/`cw_invest_data`)为值单一源,人读对拍 `docs/game/currency_war/data/`。

### 经济期望方法论(r402;「货币战争」的玩法本质)

> 用户定调(2026-08-23):这个玩法叫**货币战争**是因为经济影响极大
> ——**有限的经济内发挥最大价值**。算经济期望是策略设计/评审的
> 核心手段,不是可选项。每笔支出问三笔账:

**三笔账框架(任何购买/刷新/升级决策都要过)**:

1. **本笔净成本** = 价格 − 可回收值。关键机制:`sell_refund`
   (1星=cost 全额退;1费各星净0;cost≥2 合星后卖才 −1 手续费)
   ——**囤件净成本≈0**,唯一稀缺资源是 bench 槽(9格)。
   → 推论:「有用就先囤」几乎恒优;囤>2-3 张才谈优先级
   (按稀有度排:5费>4费>低费,与出现率反序)。
2. **弃购期望损失** = 再遇窗口。不买这张,再遇它期望 1/q 轮
   (q=单店出现率=1-(1-p/n)^5,p=该费刷新率,n=同费种类数,
   查 `cw_shop_odds.REFRESH_PROB`/`DISTINCT_CARDS_PER_COST`);
   急需时主动 D 牌(=花钱刷新商店搜牌)的期望金 = 2/q。量级锚:2-3费 7-15轮/15-31金
   (弃购风险低);**5费在 7-8 级 = 60-180 轮(整局可能不再遇)
   /121-361 金**——稀有度越高越该囤;等级升到位(9-10)窗口
   才收窄到 8-18 轮。
3. **机会成本 = 这笔金不花能干嘛**——**凑息优先算**(口述[22]
   用户补点):50 金满息=5金/轮,每 10 金沉淀=0.5金/轮的永续
   收益;一笔支出若把金从 50+ 打到 40,损失的不只是这笔钱,
   还有**息档落差**直到回满。所以「囤件净成本≈0」的前提是
   **卖出时机自由**——金在息线上方时囤(不破息),贴息线时
   囤破息件要先算息差(口述[11]:金<20 的 1 息档内买过渡件
   不损息;[17]:>50 的每一分都没有存的意义)。

**评审姿势**:任何策略改动/参数调优,答得出「这笔账三项各是
多少」再动手;判读购买行为异常时,先算该决策的三笔账再定性
「乱买/漏买」——期望账是判读的标尺,不是事后装饰。

**决策总则(与口述体系的关系)**:[17] 息律(50金息律节点无关)
是第三笔账的基准;[15] 压缩牌库(1费净0)是第一笔账的应用;
[21]/[22] 买而不上/先囤是第二笔账的应用——三笔账是它们的
统一母框架。

### 判据序(筛选「什么羁绊能当过渡」)

1. **一级羁绊即有伤害**(机制层第一问):第 1 档激活就有真实
   伤害/召唤物的 combat 羁绊才配当过渡——位面 1 人口被等级压死
   (lv5-6≈5-6 人),高阶羁绊(7+ 人)做不到也不该做。判据读
   羁绊文本:召唤物(神君/星穹列车)/结算机制(超激发)=伤害源;
   拉条/资源/经济类(贝洛伯格拉条/学者经济)=不是过渡主体。
2. **组合验证**(统计层):过渡阵容=**体系两两组合**。验证口径
   = plaza Early 纯 1/2 费层(真 P1 阵容;含 3 费层会混入中期件)
   + 官方激活口径(`traits.layers[].is_activated`,别自己数人头)。
   判例:三体系两两组合 140/328 帖全有实证;「都不含」的 49 帖
   全是直通线——**通用羁绊组合过不了位面 1** 的实证。
3. **人员要求分层**(逐篇+口述层):羁绊达成 ≠ 阵容成型。
   - 无人员要求(凑出就能用):DOT2/列车2——羁绊文本「任意
     2 名队员触发」;
   - 有最佳班底:仙舟3=藿藿+饮月+爻光(95% 帖含全三人组;
     功能链各占一环:叠段发动机/仙舟∩治疗唯一/Front 输出);
   - **单卡依赖体系**:希儿系=希儿在场 AND(量子2 OR 贝2)——
     伤害在希儿技能层(斩决处决+迸发倍率),量子/贝只是放大器,
     **无核心单卡时放大器不独立成体系**(判例:28 帖希儿局 64%
     开量/贝;不含希儿的量/贝局全在「都不含」直通线堆里)。
4. **占比即可行性排序**(统计层):激活占比 29-36%=主力;
   2.6-9%=小众(待实机探索,别优先做——用户裁定「少人用可能
   就是不太实用,先做有把握的」)。
5. **升级路径 vs 过渡起点分开**(逐篇层):列车4(Early 5%
   /Final 41%)是升级层不是过渡起点——前置=3 费购买力+姬子·
   启行(33/33 帖同时开领航员)。列在体系表里的必须是「开局
   能起步」的东西。

## 阵容定义结构(2026-08-24 定稿;终局/过渡/插件三层的定义法)

> 定义产出物长什么样:终局=套装(名词),过渡=过程(动词),插件=池。
> 判定纪律先行:**「过半升格」必须在流派(子形态)内做,全类聚合数字
> 只用于看收敛/双峰**——聚合会把流派差异平均掉(判例:姬子线聚合看
> 减益58%+护盾50% 都过半,分层后各属一派,无派同要)。

### 终局阵容 = 套装自包含,六元素(每套独立成文,不搞共享层)

1. **骨架**:具名核心(不可替换的人+为什么=功能链)/羁绊档位目标
   (主档几档+副档)/自由槽(带标签即坐的位置);
2. **星级目标**:carry 按线定档(高饥渴线 3★/低饥渴线 2★即完成态)
   /辅助一律 2★(星级资源全砸 carry);
3. **装备配方**:每件**到人**(不是位置是具体角色);件与件的关系
   (铁三角链条/独立叠加);家族禁忌(机制冲突的装备类,如燃血禁盾);
4. **特殊系统件**:超出「人+羁绊+装备」的构件——领航员绑定/任务链/
   装备栏体系/升费链(养成路线本身是定义的一部分);
5. **达成路径**:从 P1 过渡怎么长过来(替班衔接/转型节奏)——
   **流向知识的唯一归属地**;
6. **外部条件**:词条吃怕(流派选择的前置输入)/counter boss/开局信号。

**不搞共享层的理由**:实战决策单位是整套装;共享层省的重复换来每次
拼装+抹掉流派间细微差异+改动牵连引用方。同族关系写一行「家族注」
(同源+分岔变量)仅作检索。

### 流派(子形态)判定

- **双峰检测**:装备分布/角色构成出现两个聚集带=流派迹象(单卡归属
  弹性/平缓分散=不是双峰,是池或时序决策);
- **分岔变量三位一体**:真流派通常装备方向+核心选择+副档同时分岔
  (只差一件装备的是配装切换槽,不是流派);
- **双强都定义**:两派均 ≥25% 且强度可信 → 各定义一套;占比口径
  统一用装备字段口径(描述口径偏高,两口径不可互换,引用带标签);
  长尾变体(≤15%)不入正式定义,挂一句。

### 过渡阵容 = 三块结构(与终局分层定义)

过渡是**动词**(生成过程),不是名词(一套名单):
1. **体系卡**:每个过渡体系一张卡(判据/引擎要求/机制/星级/词条)
   ——乐高块,场上阵容=两卡组合;
2. **组合规则**:两两组合怎么选(来牌主导+意向同向 tie-break)、
   空窗期行为、副产品羁绊认法;
3. **升级路径+成型停手**:站点序列(加法不换件,每站是完整能打的
   阵容+进站判据)+成型判据+停手后模式+出口状态(进下阶段带什么)。
**层次分离铁律**:过渡定义不写任何终局信息——「从 A 流到 B」的知识
归终局套装的「达成路径」元素(反向引用);两层衔接归策略层(意向
信号+转型触发),不在知识定义里。

### 晚到核心的替班结构

终局核心晚到(P2 后半/P3 才能买/产出)的线,定义**低费同族替班**:
替班者先当主 C 追星(就是这条线的 P2 核心进度,不是将就);真核心
到手后**替班者不卖**——降副 C/转身份(数据常态);「档位台阶」同理:
羁绊成员数贴档位走(第 6 人对 5 人档贡献为零,位置给插件开新档)。
判否兜底:核心再遇窗口期望 > 剩余节点数 → 弃追转结构补强。
扫遍战斗羁绊确认:**无「一级强但贵」的漏网体系**(首档 3 人系均有
1 费成员,贵不构成过渡门槛)——「2换1」规则无例外条款。

### 阵容演进通用法则(2026-08-24 定稿;任何档位规模的替换同构)

> **定位**:不是「过渡→终局」专用流程,是通用法则——大档换档(过渡1档
> →终局2档)、插件档换副羁绊档(列车4+量子2 的量子档→减益2)、插件换单卡,
> 全部同构:判断量级随档位变(2换1/凑够1级才换/谁弱谁下),结构不变。

**统一入口流程**(每次可上新羁绊——全新档或原有档升级):
1. **效果判断**:新羁绊成型效果 > 现状(「2换1」规则:目标核心羁绊到
   2 档才替换过渡 1 档;插件档替换需凑够 1 级——**羁绊档是战力单位,
   拆散=掉战斗力,所以替换的最小单位是组合不是单卡**;降幅非线性:
   3人档退1人=整档消失,不留半档残值);
2. **核心校验**:核心输出在场(或替班核心)——档是壳核心是引擎,
   没有引擎的档不上;核心与档互为前提,**最后到齐的是发令枪**
   (核心到手档没齐→bench 等;档齐核心没到→不拆旧档);
3. **替换羁绊:整个替换**——新档一次上齐+旧档整档解除,一轮完成;
4. **人口缺口按策略重新选择**——上新单卡还是小羁绊,走常规填位机制;
   被换下的件与其他候选按策略价值竞争空位(留场转身份/bench/卖出)。

**空位规则**(有空位时,与替换并行的常规动作):插件优先(全体增益
喂给现有战力;单上真核心可能发挥不出作用——她的引擎挂在自己的羁绊
上,羁绊没建成前是半残的);例外=替班核心(带自己的低档羁绊一起上,
那是她当家的时间段);真核心永远等替换条件齐了整组合上。

**完成判据的消解**:转型无专门完成仪式——替换三条件最后一次触发并
执行完毕即结束;之后是常规阵容估算(每位置:目标成员?不是→按插件
标准估,劣者卖)。P2 三件齐=「开始攒钱」信号,与转型完成解耦。

**决策与执行分层**:决策可分步(替换→填缺),执行是原子事务——bench
容量有限放不下全部换下件,上谁下谁谁卖谁进 bench 一次敲定,拖动上场
与换下同时完成,不留中间态(实现期约束,决策层不感知)。

**中断恢复**:替换是原子动作,冻结打断的是「还没开始的那次」——
恢复=三条件重校验;谷底回滚=回滚一件最弱替换位后放缓,不重演整组合。

### 通用插件池(两层名单+效果三查)

- **插件 = 小羁绊(2-3 人凑一档)+ 单卡(1 人即生效),不限费用——
  判据是「占用少的槽位发挥作用」**;费用只影响买不买得起(经济侧),
  不影响是不是插件(身份侧);要 4-5 人才有像样效果的羁绊不是插件;
- **效果审查三查(判定主体;统计只是佐证漏斗)**:①效果给谁
  (simple_desc 层:全队/仅本羁绊队员/角色特定——**羁绊效果=
  simple_desc+layers+remark 三层合读,layers 只有 % 无属性词条=
  必然角色特定**);②触发方式(被动光环/大招依赖/计数依赖——
  椒丘教训:效果类型相同≠生效方式相同);③量级口径(乘区不同不能
  直接比大小)。判例:巡海游侠1「8%伤8%速」是自 buff 被当全队件;
  贝洛伯格2「36% 全体伤害」实为仅贝队员;
- **单卡排序三维度**:效果强度/职能稀缺性(拉条/免死/推条/全体降防
  这类一家一份的排前)/效果稳定性——**费用不进排序**(1星卖出全额
  退,升星后卖才有 -1);**插件不升星**(过客不装修),唯一例外
  1费双标签件;
- **小羁绊按「效果给谁」分档**:全队通用(列车2/战技点2/量子2)>
  混合型(治疗2/护盾2——全队+队员双份)/减益2(敌侧收益超出队员
  字面)> 队员口径(对症才碰);角色特定型(星间旅人/盛会之星)
  按交集逻辑用(选谁=选效果);
- **四层过滤**:①机制冲突→禁用表(读双方机制原文,「无法/转化/
  互斥」字样直接禁);②该线出现率过半→已是骨架不是插件(插件池=
  副档的候补席,随流派统计刷新);③上场有位才买(bench 不囤插件
  ——占压库名额);④都过→台阶规则运行(买来即上,正料到位卖出);
- **压库模型**:压库买的是「当前目标件的费用带」(不是便宜件通则)
  ——同费池被买空一分,目标出货概率高一分;插件是压库过程自然刷出
  的顺路件,不是要凑的目标。

### 教义措辞规范:「门槛」还是「身份」(2026-08-25 用户裁定;M11 判例)

教义/知识文档写「X 优先/默认/必」时,必须写清性质,防实现层误读:
- **门槛**表述(「X 只需 2 件即激活,门槛最低」)→ 实现走统一评分
  维度(如 readiness=已有件数/激活所需件数),对所有候选生效,
  新候选加入零改动;
- **身份**表述(「铁三角功能链缺一不可」)→ 实现可专属判定,但
  判定依据**读注册表数据**(engine_required 字段),不是名字 if;
- **禁用身份化修辞描述门槛性质**(如「X 是 YY 的 YY」——「过渡的
  过渡」已全库清除):修辞会诱导实现层造特权分支;
- 判例(M11):「DOT2 默认首站」被实现成专属 +1.0 加成+铁三角直取
  例外条款——门槛低(2 件激活)被当成了身份特权;正解=readiness
  统一维度。配套代码审查判据见公共 skill od-dev-gameplay-automation
  strategy-craft T3「门槛 vs 身份」节(具名 if/手抄名单/新候选要改
  分支代码 = 代码味道)。

## 从零提炼流程(建整套阵容体系)

1. **采集**:`tools/cw/plaza_fetch.py`/`gen_plaza_comps.py` 拉全量高难帖(jsonl 落 `.debug/temp/currency_war/plaza/`),过滤版本/KOL 沙盒/过期。
2. **聚类**:按 Final 段官方 `is_carry` 标记分桶(统计候选);注意一帖可多 carry、一聚类可混多形态——聚类是候选不是结论。
3. **人判分类**:聚类 → 合并/定边界成类(判据:CARRY 主体优先、核心羁绊其次——羁绊大量作挂件存在);新类成立判据 = 样本量够且 CARRY/羁绊可辨识,长尾不硬分。
4. **逐类深读**:类内帖全文逐篇读(笔记落本地工作区),提炼子形态/装备体系/节奏/降级路径/类间关系——**结论进 research 知识层,深读底稿留本地**(工作过程不入共享 docs)。
5. **机制验证**:每条核心结论回游戏数据找「为什么」;找不到机制支撑的高频做法标存疑。
6. **成文**:结论按证据分级([口述]>[图鉴]>[米游社]>[社区])写进知识层,指回源。

## 版本更新重跑

赛季扩充会重划分角色定位/羁绊/费用/投资(版本公告为准)。顺序:
1. 重跑生成器(注册表/聚类/power_table 全家,见 tools/cw/ 各脚本;有内建 diff);
2. diff 驱动复核:变化条目逐个过证据三层(新统计→新帖逐篇→新机制);
3. 知识层各篇标版本重核;策略侧消费点(COMP_LIBRARY/桥池/引擎阵营)按 diff 同步;
4. 掉版本锚的数据(旧版本帖)不删——标时效,新版本另采。

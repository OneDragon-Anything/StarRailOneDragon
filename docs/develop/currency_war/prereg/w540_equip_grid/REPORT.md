## 2. 真值方法(亲读,不评口径如实标注)

- 每帧裁装备区 (1620,90,1918,710) → 2x 放大(`frames_zone/`)逐格亲读:位置(1080p 绝对坐标估计 ±15px)+ 身份 + 堆叠数量。
- 身份对照钥匙 = `sheets_cn/` 彩色中文模板拼图(`assets/template/currency_war/equip_plaza/`,155 模板,文件名即规范名)。**凡不能在拼图上指出唯一对应者的格子标「不评」**,本批不评 3 格(武器大师/极·白昼·武器大师 近似对 2 格、步步生花基础/特权变体 1 格);银扳手(拆装扳手)vs 金扳手(精密拆装扳手,数量 ∞)、员工投影仪(蓝)vs 完美投影仪(金)、随便骰子/特权(金框)可区分。
- 位置与数量是几何事实,全部格必标;数量数字(1-5、∞)图标右下角清晰可读。
- GT 数据:`gt.json`;逐格对拍明细:`metrics.json`。

### 4.4 数量识别现状

- **未识别。** `read_equips` 输出 `(name, 中心, inliers)`,无数量通道(无 OCR、无数字读取);一格堆叠 ×N 只返回 1 个命中,N 信息全丢。
- 对账含义:owned 件数清单**不可用**——漏检(重复格)+ 堆叠不展开双重低估。GT 中可见数量 1-5 及 ∞(精密扳手),数字清晰、可 OCR(小字、位置固定,是可行的补齐路径,本批未实现)。

### 4.5 读空/误检清单

- 误检:**0**。53 帧复跑中所有命中均落在真实格上(reward_panel_empty / char_detail / 补给节点 等遮挡/叠加帧也无假阳性)。
- 读空(漏检)65 格,机制单一:**同一模板在画面里有 ≥2 个实例时,SIFT+单应 RANSAC 只锁定一个实例**(同物重复格至多识别 1 格,有时 0 格,如 run26 电池×4 全漏);**幸运星模板系统性失败(0/7 格,含单实例的佩佩局)**,inliers 恒 <7,疑模板质量/图标光晕问题,待单独排查。
- 精度:命中中心与 GT 格心偏差目测 <15px(容差 38 内匹配 100% 成功,无邻格串扰)。

## 5. 合成相关观察(为期望态对账备料)

1. **合成基础件 8 件**(轮滑鞋/折叠小刀/以太钻头/光能电池/和平手枪/幸运星/生命之花/量产型装甲)在装备区**一格一件不堆叠**;row1 堆叠材料(扳手/炉/投影仪/骰子)不属合成图谱——画面已天然区分「材料区(row1,带数字)/装备区(下方网格)」。
2. **可合成形态的画面特征** = 两个组件格同时在场:自配对 = 同图标两格(双宝钻局/狸猫局 row3 电池+电池相邻同行 = 光能电池×2→永动机;满级局 R5 刀+刀);交叉对 = 同帧不同图标(奖励帧 电池+生命之花→绝对热量;P2开局局)。相邻(同行 ±75px)与同列两种邻接都出现。
3. 详情面板(`equip_detail_synth_target.webp`)展示官方合成公式 UI(轮滑鞋+轮滑鞋=反重力皮靴;交叉列表 火力风暴潮/电磁弹射器/追逐星辰/步步生花),与 `cw_synthesis.py` 派生图谱一致;`equip_detail_roller.webp` 为单项详情态。面板打开时遮挡装备区左列(本帧 row1 中列被压)——期望态对账需考虑详情面板遮挡态。
4. 「穿着即合成」(cw_synthesis.py 模块注释)与本批画面兼容:装备区只见合成后的进阶件,不会出现组件消失前的中间态帧证据。

## 7. VLM 盲区声明

- 身份判定依赖模板库:`weapon` 近似对(武器大师/极·白昼·武器大师)与 基础/特权 变体对(步步生花)在小图标上不可分辨 → 3 格「不评」;若模板库本身张冠李戴,本测法检不出(与 W531 同源循环依赖声明)。

## 8. 结论与建议(供裁决)

1. **识别方法方向正确但工程不完整**:零误检 + 身份全对证明 SIFT 模板路线可用;漏检是算法结构问题(单应变换天然单实例),不是阈值问题——调 `min_inliers` 救不了重复格。
2. 若 owned 清单要进对账/合成期望态,需补两件事:①**同模板多实例检测**(如对每模板做 k 实例 RANSAC 或改用 TM 网格法——格子是固定 75px 网格,几何先验极强,第 2.3 节格结构可直接建模);②**数量数字 OCR**(row1 堆叠)。幸运星模板需重制。
3. 代码注释层应修正:行距 98→75px、列坐标改为三列 1693/1768/1843 语义(修改属 src 改动,本批未动,仅在此记录)。

> 用户裁决(最高权威):金子只有两个正当去处——利息线以内的储备、即刻换成战力。**无论什么血量,都不应持有超过储备需要的金**;超额金=死钱。

## 0. 一句话总模型

把金账从「地板制」(只规定花后不得低于某下限,上不封顶)改为「**储备制**」:任何时刻金 g 与储备上限 R\* 的差 `(g − R*)+` 是**负有转化义务的死钱**,每轮必须经三条转化通道(升级/刷新/买牌)之一转成战力;转化通道的每轮吞吐量是唯一合法的滞留理由,滞留本身要在评估中被计罚。

### 1.2 转化通道(费用与边际收益语义)

| 通道 | 费用 | 边际收益语义 | 容量约束 |
|---|---|---|---|
| 升级 | `clicks_to_level(level) × XP_CLICK_COST_FLAT(4)`;XP 需求表 `cw_state.XP_TO_NEXT_LEVEL`(逐级表 🟡 ±20% 粗估挂账,economy.md §9) | 人口=deploy cap(机制),板强基线 `b_base(level)`;升级受「要找谁」驱动([33]) | 每轮单击次数受金与计划约束;DP 动作码 4-7 |
| 刷新 | `state.shop_refresh_cost`(默认 2) | 找件概率 `cw_shop_odds.REFRESH_PROB` / `expected_refreshes`(超几何模型);期望刷数=`expected_refreshes(k, p)` | DP 上限 6 刷/轮=12 金(`_ACTION_ROLLS`);**< P2 收入 13-19/轮** |
| 买牌 | 牌 cost;卖出退金 `cw_state.sell_refund`(1星=cost,2星=cost×3−[cost≥2],3星=cost×9−1 推测) | 成型完成度/星级跳变;D 牌期望账=math_proofs P5 系 | bench 9 槽/店 5 槽 |

**通道共同语义**:每笔转化必须过 EV 过滤(负 EV 件不买);义务改变的是「花不花」,不是「花给谁」。**每轮最大有效转化量(通道容量)**:

```
C_t = 升级计划费用(若本轮有排程) + min(可买正 EV 件账, bench 余量×cost) + 刷价 × min(6, 找件边际>0 的刷数)
```

C_t 是通道的结构上限,不是拍的值——由既有 DP/评分层逐帧算出;本设计不新增通道,只新增「义务压力必须灌进通道预算」的接口。

### 1.3 储备规则(R\* 的数学定义)

**定义(储备=有确定性购买义务的金)**:储备是「在可数决策窗口 h 内存在已排程确定性购买、且其转化路径不可替代」的金。形式化:

```
R*(t) = interest_floor                                    [利息引擎:50,满息线]
      + Σ_{k≤h} U_k · 1[升级排程_k 存在]                   [升级费储蓄:排程内各级费用]
      + 0                                                  [应战应急:不由储备承担,由地板+谓词承担]

窗口 h = min(到下一 boss 节点轮数, 3)   # h>3 时排程升级费应即时执行而非长期储蓄
```

- **为什么利息线是储备主体**:g<50 段每金每轮产生 0.1 金利息(上界收益率 10%/轮,无风险),远高于任何可证战力传导链(ADR-0443 标定:k ≤ 0.012 hp/金 × 0.5 金当量/hp ≈ 0.006 金当量/金/轮,差 ≥16 倍)——**息线以内,持有弱占优;这是破息被定谳否决(ADR-0443)的同一笔账,方向反过来用**。
- **为什么升级储蓄计入**:排程升级是价格已知、时点已知的确定性转化;为它持有的金不是死钱(将在 ≤h 轮内 100% 转化)。无排程而持金等升级 = 死钱(升级决策本身应在 DP 里即时做出,`cw_plan._want_level_up` 已有此语义:L498「金≥息线+单击价时 False→花」)。
- **应战应急不走储备**:hp 危急时的应对是花光提质量(economy.md §5「血危险锁血急救→花光」),方向与储备相反;boss 窗由既有 `boss_floor=10` 花后地板承担(ADR-0426 增补 C 边界保留)。
- **R\* 的运作上界**:`R* ≤ 50 + 一次最高排程升级费`。以 P1 末窗 L7 为例,7 级需 `clicks_to_level(7)×4`;即便按最贵单击 8 金估也 ≤ ~100,常态 R\*≈50-70,远低于实测死时带金 85-160(p11)/125@hp1(⑯ 局 run_20260828_143203)。

### 1.4 花钱义务公式(核心)

每轮买相位帧:

```
义务花销 obligation(g_t) = max( 既有各臂义务_t ,  f( (g_t − R*(t))+ ) )

既有各臂义务_t = release 泄息预算(FLIP 命中帧, ADR-0426) ∪ DP refresh_budget ∪ 升级计划费用 …(现有全部,不动)

f(r) = min( r , C_t )        # r = 溢余段 (g − R*)+
```

**f 的形状推导(为什么是 min 而不是线性比例或全额)**:

1. **溢余段强制转化是弱占优(参数无关确定性结论)**:设溢余 r>0,持有它一轮的期望损益
   `ΔV_hold = Δinterest × R̄ + ρ(r)·r = 0 × R̄ + ρ·r`,
   其中 Δinterest=0(息帽截断,g−s≥50 段每金边际利息恒 0——`min(g//10,5)` 的截断性质,`cw_horizon.GOLD_CAP_INTEREST=50`);ρ=携带影子价,p11 实证实现值≈0(W151:金 85-160 带着出局/死亡,⑯:P2 死时 125@hp1 存息至死——**携带金在死亡/出局时全额清零,ρ 的 realized 值为负不确定而期望≈0**)。而任一通道转化 1 金收益 `≥ 0`(EV 过滤保证只做非负账),存在正边际帧时 `>0`。故:
   `ΔV_convert ≥ 0 = ΔV_hold`,且在「店内/升级存在正 EV 转化」时严格占优——**强制转化弱占优,无需任何标定参数**。这正是 p11 命题 1(纯溢余段 C_dec 下界=0)与 ADR-0426 设计前提的复述;本设计只是把它的消费面从「FLIP 命中帧的 release 臂」扩大到「一切溢余帧」。
2. **息线以内(ripped 另一侧)持有占优**:g<R\* 段每金收益 = 0.1×R̄(R̄=剩余生息轮数,标定均值 2.26、条件 6.88,ADR-0443)≫ 0.006-0.012(战力传导链乐观上界)→ **义务公式只在溢余段激活,不新增破息例外**(与 ADR-0426「不新增破息例外」一致;ADR-0443 的否决域就是本公式的禁区)。
3. **为什么 f=min(r, C_t) 而非 f=r 或 f=α·r**:
   - f=r(全额强制)要求通道瞬时吞下全部溢余;当 r>C_t 时强制花满会把金推进负 EV 件(买散件垫底/盲刷)——转化收益的「≥0」下界被 EV 过滤的松弛打破(过滤是逐笔的,义务不能废过滤)。故有效义务 = 容量封顶。
   - f=α·r(比例)无任何机制来源:溢余持有边际恒 0 意味着**每一金溢余都等价**,没有「先转一半」的经济学理由;滞留的正当理由只有通道容量不足这一种。任何 α<1 都是对死钱的合法化,α>1 无定义。
   - 容量外的余量 `r − C_t` 结转下轮,并进入评估罚项(§3 判据),形成逐轮收敛 `g_t → R*` 的压力,而非一步到位的假达标。
4. **边界条件(等式取号)**:
   - `(g−R*)+ ≤ C_t`:义务=溢余全额,本轮清零死钱;
   - `(g−R*)+ > C_t`:义务=C_t(花满容量),余量结转;**连续多轮 C_t 饱和 = 通道结构缺陷信号**(如 P2 刷新帽 12<收入 13-19),应触发容量扩容评估(定向刷新帽/升级加速),不是死钱合法化。
   - 义务不覆盖既有臂时取 max(不缩水——ADR-0426「义务激活时义务优先」的推广)。

## 2. 缺位地图(现政策在哪允许了死钱堆积)

### 2.1 SPEND 相位:只有下限,没有义务

- **锚点**:`decision_v2/phase.py` L17-18(`SPEND := form_ok AND gold ≥ interest_floor`);`decision_v2/arbiter.py` `_active_floor` L114(HOARD/SPEND → interest_floor)与 gold_floor 段 L204-206(SPEND 帧破平台候选交 interest_rule EV 裁决)。

## 3. 候选规则 + 预注册 sim A/B 判据(给编排者;本批不实现)

### 3.1 候选规则 R1(主提案):溢余义务预算

```
每轮买相位帧:
  r = (g − R*(t))+                      # R* 按 §1.3
  若 r > 0 且存在正 EV 转化帧:
      obligation = min(r, C_t)          # C_t = 通道容量(§1.2)
      预算合并 = max(既有各臂义务, obligation)   # 复用 ADR-0426 三方合并结构
  消费顺序按既有 EV 层;义务不豁免 EV 过滤
```

实现形态建议:release 臂的谓词替换(FLIP 简化为溢余判定)+ DP 值函数溢余罚项,二者取一先做(谓词替换改动面小、结构已在;DP 罚项是治本但动 solve)。

### 3.2 预注册判据(A/B,同池同 seed 配对,n≥300/臂)

| 判据 | 定义 | 门 |
|---|---|---|
| **死时带金(主)** | 死亡/出局帧 gold 的均值与 `>50` 占比 | 显著下降(配对差 CI 不跨 0);⑯ 实证锚:死时 125 |
| **平均闲置金** | 逐帧 `(g−R*)+` 的时间积分均值 | 显著下降 |
| **单位金战力转化率** | (出口板深或 power 表口径增量)/(累计金收入) | 不劣(非劣性界 ±5%) |
| **出口 hp 不劣** | P1/P2 出口 hp 分布 | 非劣(P17 度量合法性:hp 是下游读数,只作守卫不作主门) |
| **息基达标率** | 常态帧(非义务帧)息基保住占比 | 不劣(义务只在溢余段,息线以内行为应零漂移——这是零漂移锚) |
| 形态达标/胜率 | 既有口径 | 冒烟不劣 |

### 3.3 金账守卫重设计(关键难点,正面解)

现守卫「出口金不劣」与强制花钱**方向相反**:强制花钱必然降低出口金,拿它当守卫会把正确行为判为回退。重设计:

- **废存量守卫**(出口金 ≥X 类),立**流量守卫**:①溢余滞留率 `mean((g−R*)+)/mean(g)` 下降;②义务帧兑现率 = `实际花销 / min(r, C_t)` 的分布(兑现不足=通道饱和或 EV 层拒花,可复算定位);③**息基守卫保留但换辖域**:只辖 `g≤R*` 常态帧(ADR-0426 增补 C 已有「release 帧不计入息基分母」的先例,推广到义务帧)。
- 守卫语义一句话:**「钱在死前变成了什么」替代「死时还剩多少钱」**。出口金的合法下界从守卫降级为披露面(结算屏字段照采,不进门)。
- 单帧锁组:溢余帧义务触发锁 / 息线以内零漂移锁 / 通道饱和帧结转锁 / boss_floor 花后下限保留锁。

### 3.4 策略开关:不需要(生命周期门结论)

按「策略开关的生命周期」门:唯一合法理由=行为输入未就绪。本模型的行为输入(息公式/费用表/收入表/地板组/EV 层)全部已标定且在产(§1.1/1.2 实读);溢余段弱占优是 p11 已证的参数无关结论,无「待验证假设」。**结论:不设新开关,直接作为行为变更走三同步**;A/B 对照用 sim registry 注入临时臂(不进生产代码,strategy-work §4 A/B 纪律)。既有 `release_enabled`/`release_spend_gate_enabled` 若被本模型吞并,按第 4 态(定谳清理)处理,不留默认关悬置。

## 4. 边界与风险:强制花钱真的亏的场景与豁免

| 场景 | 为什么可能亏 | 豁免设计(不重开死钱口子) |
|---|---|---|
| 攒升级费的关键轮 | 溢余全花在刷新,轮末付不起排程升级费,人口晚 1 轮=板强晚 1 轮 | **储备定义已内建豁免**:排程升级费计入 R\*(§1.3),该部分金不是溢余、无义务;豁免是「把钱记在确定用途上」,不是「允许无限攒」——上限=R\*≤50+排程升级费 |
| 换线过渡(裁决未定窗) | 新线目标未定时花溢余=买错件,负 EV 且不可退(cost≥2 卖亏手续费) | 换线裁决帧起义务挂起至多 K 轮(建议 K=1:线表在下一买相位前必出,`cw_line_tribunal` 同轮口径),挂起帧进披露面计数;K 是结构界(裁决窗长度),不是拍的容忍值 |
| 店面真空(无正 EV 件) | 强制买=负 EV | 义务=容量封顶已内建:C_t 计 0,余量结转+计罚;这是「花不出去」不是「不想花」,判据 3.2 义务帧兑现率可复算定位 |
| 应急带(hp≤25) | 保命优先级最高,义务花销可能挤占清仓/急救 | 应急谓词全权接管(ADR-0426 辖区不相交结构保留),义务冻结 |
| boss 窗已破息至 boss_floor | 再花穿地板=下一位面无重建金 | 花后 boss_floor 下限保留(ADR-0426 增补 C 语义不变);义务与地板相交时地板赢 |
| P3 末窗/通关出口 | 终局无下一轮,转化无收益 | 义务在终局 boss 帧自然失效(R\* 窗口 h 无下一节点);出口金披露不进门 |

**风险声明**:①C_t 的容量估计若系统性偏小(如 bench 满时买账计 0),义务会长期结转、滞留罚项误伤——判据 3.2 兑现率分布是探针;②EV 层的负账判据若有假阴性(把正 EV 件判负),义务花销会被过滤层架空——「通道活着但行为未兑现」的 ADR-0426 死分支教训,锁组必须锁行为面(tag/去向分项账)而非函数存在性;③P2 收入>容量的结构性差(12<13-19)意味着 P2 义务帧常态结转,若不同步扩容定向刷新帽,主判据死时带金在 P2 的改善有限——预注册判据分位面分层读。

## 5. 证据与推理链强度自检

- **最强环(参数无关证明)**:溢余段持有边际=0(息帽截断,p11 命题 1 表值)→ 强制转化弱占优。用户裁决同向(最高权威)。
- **次强环(标定)**:息线以内持有占优(0.1×R̄ vs k≤0.012,ADR-0443 双数);收入表 W440/W452 结案口径;死时带金实证(p11 W151 四局 85-160;⑯ 局 125@hp1)。
- **最弱环(设计假设,如实声明)**:C_t 容量可由既有层逐帧算出且不系统性偏小;换线裁决窗 K=1 的结构界。这两点是评审应重点攻击处;若 C_t 假设不成立,义务公式退化为「罚项驱动 DP 扩容」路线(§1.5 备选),模型本体不变。

# 商店会话模型（详设）

## 问题与约束

- 边界：本篇只管商店画面（画面档 `currency_war_battle_prep_shop_open.yml`）的会话组织与店内决策。升级判据见 line_and_upgrade；备战域的进出时机见 prep_pipeline 第 4 步。
- 总纲契约引用：契约 A（进出与标记）、契约 B（方向视图消费）、契约 C（节点键登记）、契约 D（评估器的店内场景）。
- 画面能力面（实机归档帧 `sr-od-test/screens/货币战争-备战-开商店/shop_open.webp` 确认；免费刷新标识 = 画面档 area「标识-免费刷新」，`currency_war_battle_prep_shop_open.yml`）：商店画面为全屏面板，可见商店 5 槽、场上前后台、备战席 9 格；bot 建模的可用交互 = 买牌、刷新（2 金【注·REFRESH_COST_BASE 注册表】，免费刷新次数另有标识）、购买经验、收起（关店）、出战；商店锁定按钮画面存在但 bot 不建模其交互（本迭代不引入，登记未来扩展）。
- **店内动作边界（用户裁定 2026-10-12 + 能力面）**：店内可做 = 买牌、卖备战席、刷新、购买经验；店内不做 = 卖场上角色、点消耗品、拖角色上阵（部署统一店外）。
- **执行链前置依赖**：现行商店域执行环境无执行器端口，卖备战席与买经验在店内发射会失败（as-built 依据 = `screens/README.md` §5.4「商店域执行链未接线」；代码面 = `cw_screen_shop.py` 分发注入的 `ShopExecEnv` 无 `executor` 字段）。启用店内两动作前必须完成执行端口接线（独立落地批，landing §3.5）。
- 单动作循环与零读屏规范不变：刷新维持「访问终结」（op 结束 → 外循环重识别 → 商店 op 重新入口观察读新牌面；出处 = strategy-docs/02 §7、11 §3 决策规则 4）。刷新导致的 op 重进仍是同一会话，不算新访问。
- 失读窗的退出形态 = **工程停机出口**：入口观察发现牌面含未识别槽时框架停机留证（`stop_running`，守卫规范出处 = flow/guards.md §3，用户 2026-08-24 裁决接受阻断代价）；决策侧「花钱动作全禁、只允许关店」仅为纵深第二线。停机后不存在自动恢复路径——人工恢复重跑后，凭「本节点已处理」标记缺失，从备战工序第 4 步重新进入会话继续处理（节点内牌面不变，economy §2.1）。

## 方案

### 1. 会话定义与生命周期

- **一次会话 = 开店动作到关店动作之间的全部商店域决策**。跨刷新重进（op 级）延续同一会话；会话终结 = 输出关店动作。
- **会话入口两条路径（契约 A）**：① 备战工序第 4 步的开店动作；② **游戏侧自动开店**（战斗结算/选卡类画面处理完后游戏自动弹出商店，实机在产，出处 = screen_flow_timing #14/#29；**辖域注（方向修正）**：as-built 在案事实 = 「boss 简报后商店不开」（screens/README §5.1、boss_briefing.md 开放设计注①）——boss 简报帧不属路径②触发面；口述 #14 的全场景自动开店与 as-built 不符，以 as-built 为准）——路径②下外循环直接进入商店画面 op。**入口统一行为（决策闸门策略侧自限——flow/README §1 分层铁律，流程侧只做画面分发不做决策）**：商店画面的策略决策函数首查两项——节点边界检测（节点号变化 → 边界重置，含清标记/清单）与 `shop_handled` 标记检查：未处理 → 正常会话决策；已处理 → 输出关店（同节点牌面未变，无新信息，零决策空转）。**例外 = 受限商店访问帧**（出战发射帧经 P70 仲裁授权的溢出段消费，契约 A 豁免条款）：授权帧不受标记辖，授权消费后返回；其消费后的关店**不置标记**（非正常收工路径，现时序无害）。两条正常路径同一会话语义。
- 生命周期：
  1. 入口（路径①或②）判定标记未处理 → 进入会话；
  2. 会话内决策循环（§2）；
  3. 正常收工（无可买且刷新判据不通过）→ 输出关店 + 置标记 + 写未消费机会清单（§4）。
- 异常退出不打标记。失读窗 = 框架停机留证（见 §1 边界段）；run 中断同理——两者都无「自动接着处理」，恢复入口 = 人工恢复重跑后标记缺失 → 重新走第 4 步进会话。**恢复局特例（辖域切分）**：重启后首节点若为恢复局形态（中断续局，商店交互被游戏禁用——economy §2.1 恢复局商店锁死机制）→ 第 4 步开店被游戏侧拒绝，行为 = 既有恢复局语义（只出战推进）、标记不打；恢复局结束回正常对局流后标记缺失 → 重新进会话。两段不矛盾：**恢复局 = 游戏侧禁店形态（按对局形态分流）；失读恢复 = 标记缺失的重新处理（正常对局形态下才适用）**。

### 2. 会话内决策循环

每轮按序评估，输出恰一个动作（现行单动作契约不变）：

**2.1 方向评估（契约 B 消费）**
- 入口调用 `refresh_line_if_needed(gs)`：证据签名含本节点牌面 5 槽（用户裁定 2026-10-12：在商店看到角色时也要能评估更新方向——店里刷出某线核心/贯穿件是该线的直接证据；**P77 确认前牌面维不生效**，fail 态 = 签名退化为备战签名同值，见 line_and_upgrade 差分节 P77 行）。签名未变 → 用现值；变了 → 重算（含换目标比较账，见 line_and_upgrade §1.3）。

**2.2 买牌（前置升级检查 + 调用统一买入策略，契约 E）**

- **前置升级检查**：每轮买入评估前执行会话内升级判据（仅在每轮买入评估边界执行——置换/筹资序列中间不插入升级检查，序列闭合后下一轮评估）（line_and_upgrade §2.2：概率主轴/人口位 → 整级预授权 → 变现步 → 店内购买经验整批发射）——升级金优先于买牌金，等级决定概率档，先定概率档再花钱找牌。升级动作执行后**直接收工关店**（§2.5：标记照写；商业间谍/晋升名额的升级联动商店效果两段未建模，牌面期望态失真——本会话终止买入规避 guard_proposal_vs_expected 误炸；该收工路径的标记与机会清单写法同 §2.5 规则（标记照写、清单照写）；升级的概率档收益下节点自然兑现；「升级后同节点找牌」收益放弃 = 已知限界，登记实机观察点）。

买牌策略是全局统一组件（用户裁定 2026-10-12）：类目与优先级序单一源，商店会话只是它的执行画面。序结构完整承继现行六序（判据本体 = strategy-docs/11 §1 逐序不动；未定型/定型两态仅变化序 1 的名单来源）：

1. **目标阵容件（序 1）**：定型后 = 当前方向视图名单成员；未定型 = **现行无目标态实收编**（候选集三源，全部在产：①P86 甲乙臂候选——方向囤货/枢纽件收编映射；②④转线件（TRANSITION_PACK，[20] 过渡配方）；③K 空窗回退集（`k_empty_window_fallback` 派生成员）——终局核心囤货由第 7 条 C1 未锁恒买腿独立承载（单一辖属，禁双头），终局件照买照囤（[21]/[22]），未定型期囤终局件正是后续锁线的准备，用户裁定 2026-10-12）。**挂账判据不引**：STRUCTURAL_REACH_OVERLAP_MIN（11 §1 序 1【拟，标定批】）未落码，不作为本判据载体。买或囤；席满时：满栏合成例外（merge_mechanics §2.5 原文口径 = 席满时凑合成的单张仍可买入）；凑不成合成 → 置换账（§3）。
2. **场况插件（序 2）**：板面羁绊差一人进下一档的件（user_playstyle [35]；判据本体不动）。**店内执行面约束 = 买入上限 = 当前上阵空位数**（计量口径 = deploy_cap − deployed 现读，买入帧实读；非判据改动，声明加入——保证部署步必有位可上，「买了即上、bench 不囤插件」纪律在店内不部署的前提下由此上限维持）。席满 → 置换账。
3. **通用插件（序 3）**：现行 PLUGIN_LIBRARY 判据照旧（座位价值 + 备战席稀缺性定序，出处 = 11 §1 序 3 行）。席满 → 置换账。
4. **压库件（序 4）**：金位超过息线的部分换成低费牌（活期资产，user_playstyle [41] 二次精确化「超 50 尽量压牌库」）。**压库受整买预留约束**：存在待执行整买目标（升级攒批）时，超息线资金优先囤到整买目标，压库只消费预留之外的部分（user_playstyle [41]「>50 也有场景要囤钱」联合口径）——压库不会吃掉升级攒批资金，杜绝「压库换卡 ↔ 升级永远凑不齐裸金」的资金活锁（升级的攒批资金口径 = 裸金 + 活期卡退金，见 line_and_upgrade §2.2）。席满 → 置换账。
5. **凑星件（序 5）**：板面同系单位凑 2★ 素材，稀缺性序（出处 = 11 §1 序 5 行）。席满 → 置换账。
6. **纯冗余（序 6）**：边际贡献 = 0 → 停买（出处 = 11 §1 序 6 行）。
7. **名单核心卡支（C1，邻位通道）**：非名单成员但为注册表核心的在售卡 → 维持现行支配买入支语义（出处 = 11 §1 C1 通道），席满 → **恒买豁免置换摩擦**（C1 支配语义 = 无条件优先保留：核心在售即买，腾位按价值让位自然发生——摩擦否决仅辖非核心让位候选，r15 行为变更申报）；非核心的凑星件类席满 → 置换账。

序 1/序 2 不走息律门的义务通道语义不变（现行 M2 通道收编）。**金约束门定义落点**（序 3/4/5 共用）= 现行 11 §1 判据：息线 `saturation_line(cap_resolved)`、P46 支出否决域结构、[11] 零息损口径——本迭代零改动，仅随序收编声明。**整级预授权的预留保护全序通用化**：存在待执行整买目标时，全序（序 3/5 亦然）的可花溢余 = 金 − 整级差额预留 − 息线带——序 3/5 溢余段买入同受预留约束（防序 3/5 买入吃掉整级资金，line_and_upgrade §2.2 同源口径）。

**2.3 筹资（金不足时的伴生卖出）**
- 想买的牌金不足：卖活期件凑（过滤 = 1★ 全额退的候选，评估器），凑够即买、不多卖（user_playstyle [41]「凑息需要时把备战里非上阵的卡卖掉筹资」；[11] 卖回量最小化）。筹资候选穷尽仍不足 → 该牌进「未消费机会清单」（拦因 = 金不足）。
- 筹资卖出与买入在会话内闭环，不关店。

**2.4 刷新判据**
- 判据本体不动：路径总账形式二（比较「留本级刷到齐」与「升级后刷到齐」两路径期望总花费，出处 = strategy-docs/11 §3；P40/P47/P54 数学件照旧消费）。**整级预留保护（r19 同族第二出现位堵法）**：R1 启动门与 R2 reserve 预算均含整级差额预留——存在预授权键/攒批目标时 reserve = g* + ρ + 整级差额（与买入序/压库同源口径）：刷新不烧升级资金、不变现卖活期供刷新。
- **未定型态供数源**：刷新合格集 = §2.2 序 1 search 态候选集（同源契约 B/E——未定型 = 三源候选 + C1 未锁恒买腿，定型 = 名单）——缺省恒未定型下刷新合格集 = **K 空窗回退集成员（现行无目标态实态，结构判据）**——非全候选集求和（求和 = 数值聚合，fail 态不消费，与概率账同 fail 纪律）；「照常活跃」 = 回退集结构可达帧照刷；定型后切换为名单供数。刷新 = 不可逆纯成本（与买牌的可逆性不同质）——fail 态以实态结构判据定界，非「照买照刷」无界形态。01 §3.4「无目标刷新 fail-closed」语义变更（fail 态从阻断改实态回退集定界）→ 正本更新清单 11 行登记。**供数源 = 判据输入面变更（逐项申报）**：R1 刷新账合格集随 3.6 对照测试（存在性门通道构成处置见 §5 P92 行，单一归属）。
- 店内升级与新等级概率：店内升级执行即收工关店（见 §2.2 前置升级检查限界申报）——下节点刷新账按新等级自然求值（刷新概率本就按当前等级查表，economy §2），无独立「新等级求值」改动项。
- 刷新 = 访问终结（规范，不动）。刷新后牌面更新 → 回 2.1（方向签名随牌面变，可能触发重算）。

**2.5 收工**
- 无可买且刷新判据不通过 → 关店动作 + 置标记 + 写机会清单。

### 3. 店内置换账（席满且凑不成合成时）

用户裁定 2026-10-12：腾位卖的本质是资产置换，比较「商店里新角色的价值」与「手上已有角色的价值」，值得换才换。

```
想买的牌 X（判据已通过，仅席满拦）：
1. 取候选评估器首位 = 手上价值最低的牌 Y（店内场景过滤 = 仅备战席 + 常规资格面：
   线内件不参与置换让位 + 卖后掉当前板面羁绊档的牌不进候选（line_and_upgrade §4 羁绊规则项；仅备战席池下该过滤恒不触发，登记为场上候选未来启用时的预留规则
   羁绊规则项）+ P78-1 同 visit 禁卖——本会话内刚买入的牌不作 Y，
   见 §5 承继清单 P78 行）
2. 置换条件：X 的价值 > Y 的价值 + 置换摩擦
   - 置换摩擦 = 卖 Y 的手续费（按注册表 sell_refund 差计：1★ 全额退 = 0；
     2★/3★ 且 cost ≥ 2 = 1 金；**1 费各星净 0**——手续费豁免，出处 = economy §3）
     + 再遇风险折价（折算式 = line_and_upgrade §4 统一口径；再遇窗口查表单一源
     = data/cw_shop_odds.py 的 reencounter_window_frames）
3. 条件成立 → 卖 Y（店内卖备战席，能力面在役，前置 = 执行链接线批（落地计划））→ 买 X
   不成立 → X 放弃（进未消费机会清单，拦因 = 席满）
```

- X 的价值评估与 Y 同口径（line_and_upgrade §4 统一金当量构成）。
- Y 候选穷尽（备战席全是高价值持有）→ X 直接放弃。此时备战席全是有用的东西 = 健康态，X 等下节点（牌面自动刷新）。
- 放弃的牌若只因席满拦（判据本身过）→ 必须进机会清单；若判据本身不过（价值低）→ 不进清单。

### 4. 标记、机会清单与正常重开

#### 4.1 「本节点已处理」标记

- session 固定键名 `shop_handled`，**值** = 最后处理的节点号（位面+轮次二元组；**键含局界作用域 = 对局 id**——跨局同节点号 (1,1) 不串局；载体口径与契约 A 一致）。仅正常收工时写。异常退出/失读停机不写。
- 判定语义 = 值 ≠ 当前节点号视为未处理；跨节点失效由节点边界重置统一清值（契约 C），值比对作为双保险保留。

#### 4.2 未消费机会清单

- session 键，内容 = 判据通过但被资源拦下的牌记录 `{牌名, 拦因: 席满|金不足, 注册表价, 序类}`（解拦判定所需字段：金位解除线=注册表价比对、序类=解拦后重评归属）（正常收工时写；新节点清空）。
- **解拦复核的统一触发点（用户裁定 2026-10-12：节点内重开允许，要求完备挖掘）**：复核唯一发生在备战工序第 4 步入口，**两段执行**：
  - **入口段（关门态）**：判金位 / 席位空出（两者均可由备战观察得到，不依赖牌面）——任一使某记录拦因解除 → 该记录置「待店内验证」→ 清标记，本步开店；
  - **店内段（开店入口观察后）**：验证「待店内验证」记录的目标牌是否仍在当前牌面——在 → 正常买入评估；不在 → 销项（刷新/消耗后已不在店），若清单空且无其他可买 → 正常收工再关店。
  - **方向变更不走清单解拦**（拦因枚举闭集 = {席满, 金不足}，与清单记录类型一一对应）：挂起目标提升为生效目标时直接清标记（line_and_upgrade §3 提升时序），下一轮第 4 步按新名单重开会话全量评估。
  - 不在部署、卖出等动作后单独挂钩子：所有改变买牌输入（金/席）的正常事件都经备战全扫回跳可见（全扫机制天然覆盖），第 4 步入口复核天然完备覆盖。当前已知场景 = 部署腾席解拦（席满类）、节末凑息及任何卖出退金解拦（金不足类）、方向变更（标记清除触发，见上）。
  - **牌面代次边界**：「节点内牌面不变」的前提 = 无主动刷新；会话内刷新（整店 5 槽全换，economy §2.1）后收工的清单以**收工时牌面**为准；店内段验证天然覆盖刷新导致的牌面代次推进。投资环境的强制刷新类效果（市场混乱等）由同一牌面代次机制覆盖（环境登记按牌面代次推进处理）。
  - **解拦复核规则（凑息↔重开仲裁）**：复核后重开买牌，买入判据照常全量执行（含息线门）——非义务件破息即拦，不形成「凑息→买破息牌→再凑息」震荡；义务类（序 1/序 2，不走息律门的现行 M2 通道语义）金不足入清单合法，其解拦购买允许破息（义务优先有例外理由，user_playstyle [6]；且 1★ 义务件为活期资产，破息为临时持有成本，[11] 动态无损语义覆盖）——该循环有限收敛（买一张少一张），用户裁定 2026-10-12 允许。
- 收敛保证：节点内牌面不变，判据通过的牌有限，买一张少一张，重开循环必然终止。

## 关键取舍

- **店内卖备战席（翻案）vs 维持店外腾位链**：选店内。店外链每腾一位要「关店→备战卖→重开」三轮画面切换且产生节点内重开语义复杂度；店内卖一步完成。能力面已确认可用。场上角色店内仍禁卖（能力面边界 + 用户裁定），换血场景留给备战域。
- **机会清单 vs 每次状态变化重开检查**：选清单制。备选是「金/席/方向任一变化就重开商店重评」，放弃原因：盲目重开产生大量空转开店动作；清单把重开限定在「确有被拦的判据过牌」时，收敛性显式。
- **筹资放会话内 vs 维持备战域**：选会话内。用户 [41] 原话语义即「买了凑息需要时卖备战线上的卡筹资」，与买牌同账同帧；放备战域会产生「关店筹资重开」的第三种重开场景，复杂度反向。
- **商店锁不建模**：现行未建模锁定交互，本迭代不引入（登记未来扩展；跨节点保牌对「一节点一会话」模型无冲突）。

# 货币战争 sim 体系设计

> 性质：**设计件（as-designed）**——定义 sim 的架构边界、驱动协议、随机性纪律、保真度分层与记录面；落地偏差 = 缺陷。数值一律不落本文（单一源在代码常量/注册表，正文只写常量名）。
> **双态标注纪律（全文）**：区分「已达成」（有代码/测试载体，可用现在时断言）与「在途」（目标态，显式标注在途批次）。凡未标注的现在时断言均指已达成；标注「目标态/在途」的小节在落地前**不构成对现状的描述**。在途与待办汇总见 §6。
> 结构分工（本目录三篇）：本文 = 体系总纲；[sim-wiring.md](sim-wiring.md) = GameState ↔ sim 引擎逐域接线 as-built 底账（域粒度，接线变更改对应行）；[sim-power-model.md](sim-power-model.md) = 战斗结算层战力模型设计件（需求定义，属 §6 deferred 面）。
> 读者 = 无会话历史的工程师。术语首次出现给定义。

## 0. 术语

| 术语 | 定义 |
|---|---|
| **live** | 实机运行的 bot（operations 逐动作执行 + 遥测落盘） |
| **sim** | 单局模拟器：给定局级输入与策略动作，按游戏规则推演一局的容器状态演化，产出观测帧序列与局结果 |
| **策略器** | 纯决策函数族（mandate_v1）：全函数 f(期望态)→动作，永不返回 None；「无动作」= 选终结动作 |
| **容器** | `kernel/cw_game_state.py` 的 `GameState`：局内已知事实的唯一状态类型，live 与 sim 同一类型；单例宿主 = session 旁表（`board_state_of(session)`），写入走带渠道签名的写入口（渠道族封闭集 obs/logic_action/logic_hook），frozen 帧替换（持旧引用的读者不被污染） |
| **逻辑态** | 动作执行后不经观察、按游戏规则推算并直写容器的预期状态；真值以下一帧观察为准（观察赢）。经单一转移函数推进该状态 |
| **单一转移函数** | `kernel/cw_game_state.py` 的 `apply_shop_action_logic(bs, action)`：把商店动作的字段转移就地应用到容器（logic_action 渠道），返回 `LogicOutcome` 结果出参，拒绝语义在动作族腿内。live 执行侧与 sim 引擎共用的状态转移函数 |
| **观测帧** | 容器 `GameState` 快照 + 相位；帧只读呈现 sim 真值，不含评判面。帧携带的选项载荷按相位填充（加相位 = 加观测帧字段，策略接口稳定） |
| **相位** | 与实机画面对应的交互状态机状态（枚举见 §1.3），策略器据此路由决策，与实机 flow 层同构 |
| **流键** | 随机子流的键 = 模块号 + 局内坐标（如 `M05/p1/r3` 发牌）；全部随机量按流键派生独立子流（§2） |
| **统计镜像** | 用 replay/语料统计分布充当机制概率的建模形态——sim 随机面禁用（§2 概率源三通道） |
| **sim-only 差异** | sim 存在而 live 无对应物（或行为不同）的语义面，判读时须显式声明不可外推（§5 申报清单） |

指路：板深/净星深/rung/Δ池/coarse 查表等战斗结算与池分层术语，定义在 sim-wiring「羁绊口径分层」节与 sim-power-model §2，本文按引用消费不重定义。

## 1. 架构与边界

### 1.1 sim 的职责

sim 是**游戏本体的单局模拟器**（「模拟实机环境」），不是策略评估器：按游戏规则转移状态、按机制概率产生随机量，对策略动作产出状态回应。策略效果的 A/B 评估、批量运行、评判检查器都**不在 sim 本体内**——它们是 sim 之上的外层（批量外层属 §6 deferred 面，重建时在 sim 外再包一层）。

这样裁定的理由：游戏与裁判分离，两者才能独立替换与演化。旧形态（把 sim 定义为「策略 A/B 评估器」，评判机器与批量 runner 长进引擎本体）已整体退役，考古走 git 历史。

### 1.2 驱动协议（reset/step 步进）

- `reset(seed, run_config) → 观测帧`；
- `step(action) → {LogicOutcome, 新观测帧 | 局结果}`；
- 策略器是外层驱动者：`while not done: act = policy.observe(frame); frame = sim.step(act)`；
- 局结果 = `{final_hp, plane_reached, rounds, hp_trail, unmodeled 披露面}`（纯结果，无评判）；
- `simulate_run` = 单函数薄包装（内嵌循环逐相位调策略接口），兼容单函数调用写法；
- 入口 = `sim/cw_sim_engine.py`。

选步进协议而非引擎内嵌循环的理由：与 mandate_v1「逐动作提案」天然同构，实机 flow 层与 sim 驱动层可共用同一策略函数；加相位只加观测帧字段，策略接口稳定；批量/评估将来包在 sim 外，不动 sim 本体。

### 1.3 观测帧与相位

相位枚举 = 实机画面对应的交互状态机：`opening_env`（投资环境选卡，环境在场时）/`prep`（备战：商店/买/升/部署/卖）/`invest_offer`（局中策略选卡）/`encounter_offer`（遭遇选档）/`supply_pick`（补给 3 选 1）/`box_pick`（补给箱）/`reward_ball`（奖励球）/`event_overlay`（巨星/伙伴/专家邀请/Fate/骇入等）/`settlement`（结算）/`plane_transition`（位面过渡）/`game_over`。相位与实机画面建档（`docs/game/screens/currency_war_*.md`）一一对应。

sim 是唯一的状态推进者与随机量产生者；策略器不消费 sim 的随机流、不感知 seed。

### 1.4 与 live 的同一性

- **同一容器**：局状态 = 容器 `GameState`，live 与 sim 同一类型、同一渠道架构——sim 真值写 obs 渠道，动作应用写 logic_action 渠道；sim 侧证据前缀 = `sim:engine:`（在容器失配抑制面登记，内核零特判）。逐域接线底账见 sim-wiring.md。
- **同一规则核**：sim 只换引擎壳，不动这些单一源——数据注册表（`data/cw_chars.py`/`cw_factions.py`/`cw_equipment_data.py`/`cw_synthesis.py`/`cw_shop_odds.py`/`cw_invest_data.py`/`cw_enemy_data.py` 等）、经济与规则核（`kernel/cw_economy.py` 息/连胜/退金/XP、`cw_merge_simulate.py` 合成链、`cw_exec_state.py` 槽位表、`cw_vocab.py` 动作词表、`cw_investments.py` 投资效果结构化层、`cw_plane_table.py` 节点日程）、决策核（`kernel/cw_events.py` 事件判定、`cw_encounter_selection.py`、strategies/impl/mandate_v1 全族）。

### 1.5 保真度分层（判读外推纪律）

| 层 | 内容 | 判读口径 |
|---|---|---|
| 真代码层 | 注册表/概率表/策略本体 | 可直接信 |
| 机制层 | 按游戏规则建模的转移 | 信机制文档（`docs/game/currency_war/research/`） |
| 校准层 | 不可复刻面（第一期战斗随机输出面） | 结论带免责，战力相关判读禁出 |
| sim-only 差异面 | §5 申报清单 | 禁外推 |

## 2. 随机性纪律

- **流键子流**：单局 = 一个 `seed: int`；全部随机量按 `random.Random(f'{seed}#{stream_key}')` 派生子流，流键 = 模块号 + 局内坐标。禁模块间共享 rng 实例；禁策略器读 sim 流（策略自带随机时用独立流键 `strategy/*`）。
- 动机：单 rng 实例按消耗序耦合时，任何模块加/删一次采样就扰动全流（回归门被迫锁「rng 消耗序不变」）；流键化后各模块随机序独立，模块规格可独立演化。
- **概率源三通道**（随机量的唯一合法来源）：
  1. 游戏内可读真值表（如 `data/cw_shop_odds.py` 的 `REFRESH_PROB`，来源 = 商店概率弹窗 OCR）；
  2. 已收案的机制口径（如牌池每卡副本数，依据 `research/economy.md`）；
  3. 已裁定的定案值（如开局手牌形状采样、第一期战斗随机输出面——裁定记录见对应代码行注释）。

  禁以 replay/语料统计分布充当机制概率（统计镜像）。
- **可复现承诺** = `(seed, 开局参数, 注册表指纹)`。开局参数（职级/难度档/词缀/环境在场等）是**局级输入**（`cw_sim_run_config.py` 的 `RunConfig`，正典字段清单唯一汇总面），由调用方给定——sim 内不猜开局条件分布。

## 3. 动作应用契约

- **玩家动作**（买/卖/刷/升级/部署/穿戴/选卡/点球/工具）→ 经单一转移函数 `apply_shop_action_logic` 及其动作族腿应用，拒绝语义在腿内（`LogicOutcome` 出参），禁引擎自判拒绝；部署 = `DeployMove` 经 `apply_prep_action_logic`（DeployMove 不入商店转移口）。
- **环境事件**（发牌/收入/结算/offer 生成/位面推进）→ sim 机制面按各模块规格执行，以 obs 渠道写容器。
- 各模块（开局/位面日程/商店/牌池/收入/战斗/装备/节点事件/offer/overlay/敌人难度/特殊角色）的模拟规格承载在 `sim/cw_sim_*.py` 模块 docstring（每模块写实机逻辑依据、sim 状态与转移、概率源与流键），本文不重复。

## 4. 记录与回放

- **记录** = 容器统一 state 流水（`kernel/cw_state_journal.py`，live/sim 同构）；sim 不自建第二账本、无批量落盘面（批量/评估归 sim 外层）。
- **决策回放**（`sim/cw_replay.py`）：对历史局的容器真值帧重放商店决策，秒级看到策略改动影响了哪些决策——策略改动的先导验证通道（实跑验证之前）。数据源 = state 流水按 (run, plane, round) 取每轮最后一次写入的状态快照。

## 6. 在途与 deferred（不得表述为已达成）

- **战斗结算机制化**（战力模型）：sim-power-model.md 需求定义在案（实机语料训练、sim 纯消费端、HP 出局铁律）；第一期随机输出面就位后，按策略评估需要另立批重建。
- **扣血数值表**：基础伤害逐节点表与「基础+进度」分项拆解（结构已留位，候实机结算帧采集回填）。
- **装备/试用 → 战力映射**：特征工程归战力模型批。
- **普通节点敌人名单**：候战力模型批需要再建。
- **批量运行外层**：A/B/批量/评估在 sim 外再包一层（只删不建的旧评判机器不在此列，不重建）。
- **P3 序列**：候实机补采。
- 开局补给名单分布等【拟】占位口径：候实机数据回填（逐处在代码行内标注）。

## 7. 守恒不变量

- **牌池守恒**：剩余牌库 = 固定牌库 − 手上持有副本总数（held 由 bench/deployed 星级派生，Σ 3^(star−1)；合成不销毁，2★ 计 3 张/3★ 计 9 张）。开局手牌是派生池的首个写端，先于任何商店发牌。
- 维护义务：新增机制不变量在此登记，由对应模块的行为测试锁承载。

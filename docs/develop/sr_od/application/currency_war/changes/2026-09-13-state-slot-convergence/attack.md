# 设计对抗审(窄口径重启版):状态收敛与画面 op 规范化迭代

> 审阅面(严格口径):design.md + details/sim-state-switch.md + details/shop-slot-model.md + landing.md;本提示「背景事实」按可信输入。未读其他文档/代码。
> 严重度:**blocker** = 定稿门未过、对应阶段不可凭设计开工;**major** = 实施者需临场再设计或范围清单不闭合;**minor** = 表述/归属歧义。
> 本文件为窄口径重启版,替代此前宽口径报告。

## 1. Findings

### F1 [blocker] R2:保真位 5 缺口的写入通道语义未答,3.1 写面不可开工
**位置**:sim-state-switch.md §2「缺口=保真位 5 个独立位…均有 observe/carry 分叉或写门替代语义…本迭代不新造容器字段」+ 关键取舍 5;landing 3.1(写面切换,「最重」批);design.md §2 渠道签名契约。
**攻击**:landing 3.1 范围=引擎内部状态**整体**切容器,而 5 位(enemy_difficulty_live/level_readable/gold_readable/board_readable/bench_readable)「不新造字段」→ 数据无处落;「有…写门替代语义」是断言非设计——任一位的替代落地(谁写/何时写/过什么闸)均未给出。渠道契约只定了「族」(obs 族),未定**写入闸条件**:sim hp 是引擎结算自算真值、非画面真读,若写门含「非真读不 observe」语义,引擎 obs 族直写是否放行、按什么条件放行,四份文档无一回答。3.1 验收线(fidelity 指纹+全量锁)恰依赖这些位的去向——实施即卡。
**修法**:总纲补「sim 写入闸语义」一条(actor=sim 引擎登记名即写门放行条件,或逐位申报豁免);3.1 范围内对 5 位逐一写明过渡处置(临时冻结引擎白名单至 W5,或按派生/写门落到具体写点)。

### F2 [major] R3:整帧失读窗无等待/重观察语义,短时失读致过早关店,且 empty 误判无告警
**位置**:shop-slot-model.md §2 判定表+§3 写入门(店开即写);design.md §2 契约 3(决策一律跳过 unknown);landing 3.5 判据(候选空→CloseShop 收工)。
**攻击**:现状失读→`[]`→falsy 不写→容器保旧牌面→决策继续试买;新契约「店开即写」下,过渡/动画帧整帧失读→5×unknown→候选空→与买光同路径直接 CloseShop——失读窗从「试买」变「关店」,该买的没买。更重:淡入帧亮度爬坡可 <50 → 误判 **empty**(「确定性占位带」,无告警)→ 静默放弃。§2/§3/§4 与 landing 3.5 均无失读窗等待/重观察语义(design.md §2 合法面「收工段防抖自愈重读」证明防抖先例在册,未被引用承接)。
**修法**:读链加稳定帧门——全 unknown/全 empty 载荷落盘前短等待重观察一次,二次仍失读才落;或决策层遇 unknown 全帧先触发一次重观察再收工。

### F3 [blocker] R1:安灯钩子「访问层披露」载体未定稿,且系停机谓词输入
**位置**:sim-state-switch.md §5③「载体 = receipts extra 或缺陷台账,落地批定谳」;landing 3.2 范围(安灯钩子数据源改 receipts+容器派生)。
**攻击**:plan_truncated/refresh_attempted/refresh_board_changed 三输入是谓词的豁免通道(判定方向「漏停不误停」),其载体二选一未定——两候选语义不同(发射行附加 vs confidence 面),数据通道需实现者临场设计,违「实现者无需再设计」;且这是误停/漏停高敏钩子。总纲自设定稿门(「草案,定稿前不派落地批」),待定点在 3.2 关键路径上=定稿条件未满足。
**修法**:详设定谳载体(建议 receipts extra:与访问窗键 (plane,round,unit_seq) 同源同生命周期;缺陷台账的 confidence 面与之语义错位)。

### F4 [major] R1:谓词输入映射不足以重放——发射/计划不对齐 + gold_open「开店首读」通道未定义
**位置**:sim-state-switch.md §5①(visit_actions→访问窗 receipts 发射行)、§5②(gold_open/gold_close→容器 gold 域开店首读/关店现读)。
**攻击**:①receipts=发射事实,计划序列与发射序列在截断/部分执行时不对齐——「计划花费>0」若由发射行合计派生,截断窗被低估,只能靠 ③ 披露走豁免,而 ③ 载体未定(F3),谓词重放正确性系于未定稿件。②容器 gold 域是现值语义、无历史面,「开店首读」的取数通道与时点(收起锚命中后首 observe?刷新扣金前?)未定义。
**修法**:定「开店首读」=访问窗首条 gold 值并随 ③ 载体落存;计划花费改由计划侧直供(详设 §3 已有「引擎计划值直供」先例)或明写「发射合计+截断披露」合成公式。

### F5 [major] 批4(bench/deployed/备战)无详设,凭现有文档不可开工
**位置**:landing 3.7(依据=design.md §2 变化 3+「audit A 项四域差距表」);design.md §0 详设划分表(仅两详设,批4 无详设)。
**攻击**:四域改造(bench「None 态申报化」/deployed 定长化/备战透传三态化)只有一句话级描述,语义、判据、消费点全无;唯一依据指向 `.debug/temp/` 临时审计件(不在定稿阅读面、寿命无保)。用户裁定「备战豁免撤销纳入改造」(design.md §0)缺承接设计。
**修法**:批4 开工前补详设(至少锁四域词表与判据表,粒度对齐 shop-slot-model.md §1-§2);landing 3.7 标注「详设候」并与 3.5-3.6 解耦排期。

### F6 [major] landing 3.3 设计依据悬空:「sim-state-switch.md C4 桶」不存在,序列化残留面清单无着落
**位置**:landing 3.3 设计依据行;sim-state-switch.md 无「C4」节(C 桶是其 §6 引用的来源盘点桶号,非本详设节)。

**修法**:把序列化切换面清单内联进 3.3 范围或 sim-state-switch.md 新增一节;依据改为存在的节号。

### F7 [minor] 「simulate 退役」三处表述需拼接才自洽,残留面与「src 零引用」判据关系靠暗通道

## 3. 规范遵循与裁定一致性

- 「依据就地标注」:总体良好(行号引用密集);违例=F6/F11/F12(标注悬空或寄存临时件)。
- 「实现者无需再设计」:违例点=F3(载体二选一)、F1(5 位替代语义)、F5(批4 全域)、F10(canonical 序)。
- 「无过程叙事」:基本干净;残留=F14。
- 用户四裁定:三态定长模型 ✓(shop-slot-model.md 全落实,None=unknown 告警语义有标注);备战豁免撤销 ✓ 承接但改造语义缺位(=F5);测试精简 ✓(3.5「只新增定长不变量/三态判据/单源锁」+「禁机械跟绿」);动作 op 机械执行零验证 ✓(阶段三拆 4 族+合法面在册)。
- 内部一致性:渠道契约/唯一转移入口/投影口归属,总纲-详设一致;小项见 F7/F8/F9/F13。

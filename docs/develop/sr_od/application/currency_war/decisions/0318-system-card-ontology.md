# ADR-0318: 体系卡本体论(SystemCard 实体模型:判据/引擎/星级/吃怕字段语义)

- 状态:accepted(补写;行为已随 W32 批 commit,本篇事后落档)
- 日期:原 commit 2026-08-24(1ece663f);补写 2026-08-25
- 背靠:教义 `p1_definition.md` 一·体系卡(四张乐高块)+ 二·组合规则;
  契约包 C2(签名冻结级,判据内部权重草案级);W32 落地。
  落点:`cw_system_cards.py`(+ 同批 `cw_win_model.py` C7 影子适配类)。
  **范围注**:组合选择打分的 readiness 统一化归 ADR-0311,本篇只记
  **实体模型**(字段为什么是这些、成员角色怎么分类)。

## 背景与动机

P1 过渡阵容的定义此前散在教义文档里(四张体系卡/组合规则/升级路径),
代码侧没有对应的实体模型——演进引擎(W33)、意向分层(W34)、
decision_v2 载体批(W35 层1 换源)都消费「一张体系卡」这个概念,
缺注册表则每处手抄一份判据(三处重复的实况见 ADR-0320 清理)。
本体论要回答:**一张体系卡由哪些字段构成、每个字段回答什么问题、
成员角色怎么分类**。

## 决策

**实体 = `SystemCard`(frozen dataclass),注册表 `SYSTEM_CARDS`
四张:仙舟3/DOT2/列车2/希儿系。** 字段按「判断一张卡需要回答的
问题」划分:

1. **`judge_factions`(判据阵营元组)**——回答「怎么判定这张卡
   激活了」。tier 阈值不存卡上,派生自 `FACTIONS` 注册表
   (tiers[0],单一源,版本更新自动传导);希儿系是双元组
   ('量子同频','贝洛伯格')= 双分支 OR,首位兼作演进目标锚。
   这是「卡→阵营映射」的单一数据源(W47 字段化的本体,见
   ADR-0320)。
2. **`engine_required`(引擎件名单)+ `star_goal`(星级目标)**——
   回答「激活之后离能用还差什么」。成员角色二分:
   - **档是壳,引擎是实体**:仙舟3 的档位判据是「仙舟≥3 人」,
     但缺铁三角任一人 = 空壳(功能链不可拆)——所以引擎名单 =
     `_CORE_TRIO` 注册表真值(cw_line_defs import 不复制),星级
     目标 = 铁三角 2★;
   - **无引擎卡**(DOT2/列车2):凑出即用,名单空、星级不追;
   - **单卡引擎**(希儿系):伤害全在希儿技能层(量子/贝是放大器
     不是独立伤害源,点2 卡4 语义)——引擎名单 = 希儿一人,星级
     目标 = 希儿 3★(高饥渴线,P1 就可开始追)。
3. **`affix_likes`/`affix_fears`(词条吃怕表)**——回答「这张卡
   在什么敌方词条环境下强/不能玩」。数据字段化(词缀名与
   affix_effects_data 对齐):DOT 吃敌方频动(多结算)、怕净化身心
   (羁绊注册表 note:该环境别玩 DOT);希儿怕量子熄火(重开级
   counter);仙舟/列车词条泛用(空表)。吃怕进组合打分
   (怕权重>吃,counter 警惕优先——教义对齐)。

**支撑类型**:`CardState`(件数/激活/引擎完备度的查询视图)、
`CombinationDecision`(组合建议+裁决记录,同分 tie-break 必非空,
C2 冻结要求「可审计」)、`BlankWindowDecision`(空窗期买侧建议:
引擎件见即买/来牌方向/费用带)。

**成员计数的表示纪律(踩坑存档)**:判定「一个角色属于哪个体系」
必须 **factions+flows 双看**——持续伤害/量子同频在 flows 不在
factions,单看 factions 则 DOT2 件数恒 0(W32 落地实锤踩坑,写进
模块 docstring);开拓者按当前 char_id 归一形态后再看。

**契约偏差声明(三条,落地时点显式记录)**:C2 伪码的
`board_by_row` 入参换源(W38 C6 落地闭环偏差①)/EngineState 返回
改 bool(包装留接线批)/cards_state 直读 GameState——判据语义
零偏离,均为接口面偏差。

## Considered Options

- **体系卡建成 FACTIONS 注册表的扩展字段(羁绊加 attach 字段)而非
  独立实体**——被否(事后重构补记;当时备选未记录):体系卡是
  「组合玩法概念」(多羁绊 OR、引擎名单、词条吃怕),羁绊注册表是
  「游戏数据实体」(成员/tier);混在一起则游戏版本更新(羁绊变)
  与教义演进(换体系卡)互相污染。判据:两类变更的驱动源不同
  (游戏改了它变 vs 我们教义改了它变)。
- **希儿系建为第五阵营计数(量子同频≥2 即激活,不点名希儿)**——
  被否(教义裁决,历史记录):W30 残差分析实证 P1 域「档是壳核心
  是引擎」——量子同频计数对判据是必要非充分,缺希儿 = 放大器
  空转;单卡判据(希儿在场 AND 放大器≥2)是教义本意,希儿系
  双重身份(P1 体系卡=终局希儿量子的 P1 形态)也要求点名。
- **词条吃怕写成函数(每卡一段判定逻辑)**——被否:吃怕是纯数据
  (词缀名集合×命中计数),函数化把数据问题变代码问题,新增词条
  要改代码;字段化后组合打分统一消费(`_affix_weight`)。
- **star_goal 全卡统一(都追 2★)**——被否:星级目标反映「这套
  体系的饥渴线」差异(铁三角 2★ 即成型不追 3★;希儿伤害线性
  堆叠值得 P1 就追 3★;DOT/列车档位本身即战力星级不追)——统一
  值抹掉教义差异。
- **DOT2 组合加成给专属特权(默认首站 if)**——原批曾如此实现,
  被用户裁定推翻(误解记录 M11),改 readiness 统一维度——**该
  决策归 ADR-0311**,本篇只注:本体论设计上 `_ACTIVATION_PIECES`
  (激活所需件数)作为卡的字段存在,正是 0311 统一维度能「新羁绊
  零改动」接入的结构前提。
- **引擎完备度(EngineState)本批就建包装类型**——被否(契约偏差
  声明②,历史记录):本批消费方只要 bool,包装属接线批接口面;
  缺件审计走 `engine_missing` 已覆盖。

# 备战画面工序流（详设）

## 问题与约束

- 边界：本篇只管备战画面（画面档 `currency_war_battle_prep.yml`）上的决策工序、溢出告警自救、节点边界状态重置。商店会话内部见 shop_session；升级判据与选线函数见 line_and_upgrade；本篇只定义它们的调用时机。
- 总纲契约引用：契约 A（商店会话进出）、契约 B（方向状态消费）、契约 C（节点边界键清单所有者）、契约 D（卖出评估器场景之一）。
- 全扫语义：每次回到备战画面，从第 0 步向下扫描，执行第一个满足条件的步骤，然后重新扫描（决策入口 `emit` 每帧被调一次，单动作循环不变——现行装配形态出处 = strategy-docs/02 §7）。九段（第 0-8 步）的回跳语义覆盖：腾位后回头点晶矿、买完牌回头部署。

## 方案

### 1. 工序九段（第 0-8 步，逐条判据）

**第 0 步：溢出告警自救。**
- 触发条件：`gs.overflow_warning` 为真。机制事实：告警在场 = 备战席 9 格全满且溢出位有一张卡（角色或占席道具），溢出卡阻断进入战斗（建档出处 = `kernel/cw_game_state.py` overflow 字段注释，实机 2026-09-15/2026-09-24 确认）。
- 解除方式唯一：腾出一个备战席空槽，溢出卡自动归位（游戏侧行为，卖出归位已实机实证）。
- 自救动作序（**按损失递增排列**：免费腾位在前、有损卖出最后；每帧重评取首个可行，无试错计数）：
  1. **上阵安置**（免费腾位）：场上 cap 有空位 ∧ 备战席有可上阵单位（**告警帧豁免窗口辖域**——上阵纯为腾槽保命，告警解除后下轮窗口辖域恢复正常；豁免行 = 自救对价段同源申报）→ 拖上阵（上阵腾出备战席槽 → 溢出卡归位；**免费且同时是有效部署**—— deploy 后下轮全扫自然继续）；
  2. **点开消耗品**（免费腾位）：候选评估为空 ∨ 无上阵安置可行 ∧ 备战席有已知占席物品（bookcard/supply_box/tome——tome = 星徽秘典〔「典籍」为已废弃旧名，正名 = 星徽秘典〕，board_structure 在案；**星徽秘典占席 = 待实机证实项，点开出路对其防御性纳入**）→ 点开腾槽（占席道具不可卖但可点开——补给箱不可卖为实机定谳；**告警帧冻结条款对此例外**：点消耗品本身就是自救动作）→ 下轮重评；
  3. **卖出**（有损腾位）：候选评估非空 → 按候选评估器（自救扩展资格面：**仅备战席**；**辖域 = 真全量持有**——P78 资格仲裁族豁免（P78-1 同 visit 线内禁卖、P78-4 M4/funding 通道核心④件禁卖、P78-7 种子全通道禁卖——豁免后线内件按价值序末位仍可卖、按价值序末位可卖：用户裁定「卖了目标件之后反而能取胜」与「零停机出口」优先于硬资格；豁免行登记通道对价段自救行）卖出首位候选；
  4. 以上全不可行（窗口豁免后态 1 仅受 cap 空位约束、态 3 全量可卖无守卫——**不可行仅剩：无 cap 空位 ∧ 无候选 ∧ 无占席物品**，结构不可达）→ 防御性分支（识别异常真实形态）：真全量可卖 + 守卫豁免下候选空结构性不可达（9 格 = 角色[可卖] ∪ 已知占席物品[可点]；清单完备性以 board_structure 后续增补为准——防御分支为增补滞后期的兜底），若仍到达 = 识别异常——零动作正常交回外循环轮转，持续无推进由外部哨兵留证暴露（工程层事实暴露，非策略「等待」语义）。**纯终局件唯一可上阵的限界申报**：该形态下免费腾位被窗口辖域排除（态 1 不可行）→ 阶梯降入卖出（有损）——「免费在前」在该形态让位于窗口辖域，偏差如实申报。
  **空板守卫 as-built 如实申报**：现行 `sell_gate.empty_board_sell_blocked` 为后态判定——**deployed = 0 帧全部卖出场景哑火（含备战席候选）**，此为 as-built 守卫语义，本设计不收窄。deployed = 0 帧的自救主路径 = 上阵安置（态 1，上阵非卖出、不受该守卫辖）；卖出路径（态 3）在 deployed > 0 帧可达。全程无试错计数（设计原则见关键取舍）；卖出未生效 = 执行层落地验证职责。
- 告警在场时，本工序其余步骤全部不执行（告警不消出战无效，其他动作无意义——现行收窄语义保留，出处 = `mandate.py` 溢出告警门注释；例外仅上列自救动作本身：上阵安置/点消耗品/卖出）。

**第 1 步：点开消耗品。**
- 触发条件：备战席槽位上有 kind 为 bookcard/supply_box/tome 的物品（现行容器 BenchSlot.kind 判定，出处 = `entry.py` 实体面段）。点开顺序：书册卡 → 补给箱 → 星徽秘典（依据 = 现行实体面臂序，入口清场旧全局序，`entry.py` 实体面段在案）。
- 点开产生的弹窗（武装箱选择等）由外循环画面分发接住，处理后回备战重新全扫（弹窗不是工序步骤）。

**第 2 步：晶矿。**
- 触发条件：`ore_click_targets_of(gs)` 非空（现行晶矿读口）。
- 席位未满：点全部晶矿（判据 = 全点；执行面按现行批式点击上界分批推进，出处 = `prep_actions._collect_ore`，飞行等待 2s 口径 = screen_flow_timing #16）。
- 席位满：**按候选身份直接判断值不值得腾位**（无试错计数）——评估器首位候选为**纯垫件**（1★ ∧ 非线内 ∧ 非合成素材 ∧ 非通用插件注册表成员 ∧ 非 registry 核心/④件/种子 ∧ 非 search 态候选集成员——囤货集排除防方向囤货候选被垫件卖出，与「囤终局件为锁线准备」缺省相承诺一致——垫件 = 卖出损失 ≈ 0 的持有；插件有座位价值不在垫件集、核心/转线件有再遇期权不在垫件集；**∪ P96 释放集【挂账不激活】**——P96 证明前提（被阻 M2 义务 EV>0）不随场景迁移至晶矿，复用需命题扩证明或新证明（命题处置登记：待证钩子挂账）；标定前 fail 方向 = 晶矿垫件不含释放集（仅纯垫件判据））→ 卖 1 个腾位，下轮全扫回来点晶矿；**晶矿场景消费 = 垫件谓词过滤后取价值最小**（非全池排序首位判断——价值函数无垫件身份维，1★ 插件可排 2★ 纯垫件之前）；过滤集空（首位候选为非垫件）→ 本节点放弃晶矿（直接的价值判断：确定的高价值持有不换随机产出）。判断天然自收敛：候选按价值升序让位，散件卖完后自动停在「无垫件可卖」——无需任何次数上限。
- 依据：确定损失换随机收益只在损失 ≈ 0 时成立（卖出纪律 = 不可逆动作按持有价值守门，弃购/囤积的真实代价 = 再遇窗口，user_playstyle [22]③）。

**第 3 步：升级检查。**
- 判据与发射形态见 line_and_upgrade §2（概率主轴 + 人口位并列 + 整级一次买齐；**资金口径 = 攒批资金（裸金 + 非线内 1★ 活期卡退金）**，非裸金单口径）。本步只定义调用时机与发射语义：每轮全扫评估一次；**判据不过 = 本步无动作、扫描继续到下一步**（授权帧后由预授权键驱动执行帧，见 line_and_upgrade §2.2——预授权键是唯一跨帧授权状态；血闸类拒发同落零动作语义，姿态授权对账随拦截层删除退役，拒发落点 = 本步零动作，见 shop_session §5 承继清单）。攒批资金不足整级时什么都不买（攒钱模式，等节点收入进账后自然满足）。

**第 4 步：商店会话。**
- 触发条件：入口先调用解拦复核判定（shop_session §4.2，判定函数由 3.6 交付）：清单有解拦记录 → 清「本节点已处理」标记；然后判标记 ≠ 当前节点号（标记格式见 shop_session §4.1）。满足 → 输出 `CwActionOpenShopParam`（契约 A）；不满足 → 跳过本步。

**第 5 步：部署调整。**
- 内容 = 现行部署面整体保留：目标线成员上阵/换位（发射门纪律与配方底线门出处 = strategy-docs/10 §1）、开局配方（过渡体系开局）、空槽凑人数补位（任意合法单位上阵优于空槽，P24 残余补部署）。判据本体不改动，仅调用时机移到商店会话之后（用户裁定 2026-10-12：先逛店再统一部署）。
- **上阵的窗口辖域（用户裁定 2026-10-12）**：**终局成员在其上线窗口前不上阵**——窗口 = 阵容知识声明的上线条件（核心等级/羁绊齐/变阵点等，[21] 窗口语义的形式化；窗口谓词表达而非位面字面量——位面字面量违宪法第 2 条）。**数据载体申报**：窗口信号字段 `entry_signals` 为 10 §5 在册**待建挂账项**（现行注册表无此字段），本迭代落地批随部署辖域建表（知识来源 = `final_comps/` 各线上线条件登记，landing 3.3 范围）；**建表前 fail 方向 = 窗口谓词恒假（纯终局件一律不上阵只囤）**——保守侧，与用户原意一致。窗口未到：纯终局件只囤不上（终局阵容战斗力未成型，硬上 = 较多战斗失败）；**纯终局件谓词 = 终局库成员 ∧ 非现行过渡配方成员**（缺省恒未定型下按全库知识判定——窗口闸消费此谓词，判定不空转）；**与 P24 残余补部署的优先序差分申报**：P24 无条件支配件优先为既有语义，窗口辖域为其新增例外约束，申报；过渡∩终局重叠件按过渡成员正常上阵（它们的上阵是过渡行为）。窗口到（信号命中）：按生效目标名单转型上阵。全局累积型角色例外（越早越好，[21] 例外语义）不动——例外判定载体 = entry_signals 的累积型信号类（[21] 在册待办，建表时一并登记口径）；**羁绊组齐信号 = 上线条件之一入表**（[21] 2026-08-26 定谳「羁绊组齐才上」语义，建表口径吸收）。
- 部署候选排除「场上已有同名同星」角色（游戏约束该状态不可达，出处 = merge_mechanics §3）。
- 部署产生的腾席效果由第 4 步入口的清单统一复核自然消费（契约 A；本步无独立重开钩子——见 shop_session §4.2 触发统一化）。

**第 6 步：装备与工具。**
- 装备穿戴 = 现行完整实现整体保留（用户裁定 2026-10-12），仅调用位置固定为部署之后。工具使用判据 = 现行 `kernel/cw_equip_env.evaluate_tool_actions` 不动。
- 现行「工具动作先于骨架动作发射」的排序取消，固定到第 6 步（用户裁定 2026-10-12 工序序）。

**第 7 步：节末凑息检查。**
- 与会话内筹资的分工（用户裁定 2026-10-12 问询「凑息与开店的优先级」的裁决）：「卖活期牌回金」有两种目的、两个位置——**为买而卖**（筹资：想买的牌缺金 → 会话内伴生卖出，shop_session §2.3，排在买牌账内）与**为息而卖**（本步：所有花费决策完成后的最终息线检查）。本步必须在出战前最后执行：息按节末金位结算，提前卖会被后续购买把金位吃回去，只有全部花费落定后的卖出才锁定息位。
- 触发条件：当前金位 < 息线（`saturation_line(cap_resolved)`，出处 = `kernel/cw_economy.py`；息律投资局 cap=10 ⇒ 息线=100，禁裸 50——口径出处 = strategy-docs/11 §1 金约束门）。
- 动作：卖 1★ 全额退件（候选评估器过滤参数 = 仅活期件）补缺口，卖到缺口闭合即止、不多卖一张（卖回量最小化，user_playstyle [11]；「发现凑息可能时将备战卖回去凑息」用户裁定 2026-10-12 保留本动作）。
- 本步卖出的退金由第 4 步入口统一复核（契约 A），可能解拦机会清单（义务件破息购买形态，用户裁定允许——shop_session §4.2）。

**第 8 步：出战。**
- 触发条件：以上全部步骤无动作。输出 `CwActionStartBattleParam`（备战环唯一完成态，现行语义不变）。
- **出战前置发射位机制保留不动**：现行出战的发射前判定（`kernel/cw_launch_admission.py::readiness_launch_decision` 宿主、P70 发射帧仲裁、受限商店访问）全部照旧，本工序的出战动作仍经该前置位发射（机制出处 = strategy-docs/26 号篇与 `flow.py` 发射仲裁段；本迭代零改动）。**受限商店访问帧不受会话标记辖**（P70 授权的溢出段消费照常进入商店执行，契约 A 豁免条款）。
- 出战点击后若长时间未离开备战画面且第 0 步告警已清 → 交外循环（已建档画面的轮转/哨兵留证，非未知画面分支）。

### 2. 卖出候选评估器（契约 D 的备战域消费）

- 候选池：场景参数全集唯一定义处 = design.md 契约 D（**候选池口径 = 八场景（契约 D 唯一定义处）：七个备战席候选场景仅备战席；部署换血场景含场上（羁绊规则项在该场景生效）**——自救场景场上支不设：告警在场 ⇔ 席满，角色/装备持有帧备战席候选非空，全占席道具帧候选空由点消耗品出路承接，场上支与告警帧动作收窄互斥）。
- **资格门按场景参数化**：场景参数全集 = design.md 契约 D（八场景：溢出自救/晶矿腾位/店内置换/会话内筹资/升级变现/节末凑息/部署换血/C1 恒买腾位，各带候选池/资格面/消费方式），本篇不重复枚举；资格门单一源 = 现行 `sell_gate` 排除集收编（含 P78 素材对释放子谓词 dead_pair_exit_release——在役通道场景照旧生效（塌缩已退役、晶矿挂账不激活）；**晶矿场景 P96 释放集 = 挂账不激活**（证明前提不随场景迁移，标定前晶矿垫件不含释放集），与其他三处口径一致）。

- 价值排序（从先卖到后卖；用户裁定 2026-10-12 语义 = 手上价值最低者让位；价值评估函数统一口径 = line_and_upgrade §4 金当量三项；**候选池 = 六备战席候选场景仅备战席 + 部署换血场景含场上**；「无上阵羁绊代价项」指上阵态不在候选池，板面掉档维度是价值排序的资格规则项，二者不同物）：

| 维度 | 价值低（先卖） | 价值高（后卖） |
|---|---|---|
| 与目标线关系（场景分层规则，非价值维度） | 无关（常规场景此维无操作，金当量直序） | 名单成员（自救扩展面：线内件整体置末层后仍按金当量序） |
| 板面羁绊代价 | 卖后不掉档（备战席件天然满足） | 卖后掉当前羁绊档 |
| 合成进度 | 零散单张 | 已有两张同名（差一张合成） |
| 星级/费用 | 1★ 低费 | 2★ / 高费（高费再遇 60-180 轮，持有期权值钱——user_playstyle [22]） |

- 各场景的消费方式：告警/晶矿场景直接取首位候选；店内置换场景由 shop_session 比较账裁决（shop_session §3）；节末凑息过滤为仅 1★ 全额退件。
- 每笔卖出记遥测（场景、卖出名、价值档），自救与腾位场景的卖出必须可判读归因。

### 3. 节点边界状态重置（契约 C）

- 触发点：备战决策入口与商店决策入口**各自**在节点号读取处调用同一边界处理函数，检测到（位面，轮次）变化 → 执行边界处理一次。**判重机制** = 函数内部上次处理节点号比对（键存储），相同节点号不重复执行（重置操作全部幂等，重复执行无害但以判重避免日志噪声）。
- 重置清单（键清单唯一所有者 = 本函数；其他详设把自己的键登记进来）：
  1. 「本节点已处理」标记 → 清值（新节点牌面全换，旧标记语义死亡；机制依据 = economy §2.1「节点切换自动刷新全店」）；
  2. 「未消费机会清单」→ 清空（牌面变了，旧机会作废）；
  3. 升级预授权键 → 清零（节点切换 = 金/血/收入日程全变，旧授权作废——执行帧在下一节点不再发射，防旧授权跨节点兑现；登记来源 = line_and_upgrade §2.2）；
  4. 方向证据签名 → 置失效（强制下帧重算——节点变动伴随结算收入与自然经验，资产面可能变化）；
  5. 方向状态本身（目标线/未定型）→ **不重置**（跨节点持续；换目标只由选线函数的比较账驱动，见 line_and_upgrade §1.3）；
  6. 挂起目标槽 → 清空（挂起 = 评估快照，跨节点过期——过期评估不作提升依据，登记来源 = line_and_upgrade §1.3 生命周期）。
- 登记扩展方式：其他模块的节点作用域键在边界处理函数的清单表显式登记（键名 + 初始值），禁各自散写重置逻辑。

## 关键取舍

- **全扫 vs 状态机步进**：选全扫。备选是记住「走到第几步」的严格状态机，放弃原因：腾位→回点晶矿、买牌→回部署等回跳在全扫下自然表达，且与现行单动作循环装配零冲突；状态机需额外维护步进位置且每个回跳条件都要显式建模，复杂度更高、漏分支风险更大。
- **溢出死局出口**：资格面扩展 + 每帧全量重评，而非停机报警或试错计数。用户裁定 2026-10-12：备战席有东西就能卖、能卖就有槽，死局在机制上不存在；把策略纪律（不卖自己人）当游戏限制是原设计错误。落地面 = §2 自救场景资格面扩展（全量持有可卖）——告警在场 ⇔ 席满 ⇔ 持有非空 ⇔ 扩展资格面候选非空，出口结构性存在。
- **策略层无试错计数（用户裁定 2026-10-12「好的策略方案应该考虑到各种情况，计数器治标不治本」）**：工序全部判据为每帧全量重评的纯判断——该不该做由价值/身份判断直接给出（如晶矿腾位 = 候选是否纯垫件），不做「试 N 次后放弃」形态；动作未生效归执行层落地验证，候选空等异常帧正常交回外循环、持续无推进由外部哨兵留证暴露，两类都不进策略判据。
- **对用户裁定「消耗品最先」的差分申报**：第 0 步溢出自救插入在前（告警帧机理优先——告警不消出战无效），消耗品点开次序 = 第 1 步；机理成立、序位后移一位，申报。
- **晶矿放弃出口**：纯垫件身份判断后放弃而非无限尝试。**对用户裁定「晶矿必拿」的差分申报**：垫件卖尽前的晶矿全拿 = 必拿达成；放弃仅发生在需要牺牲高价值持有时 = 「白拿的必拿」精神保留、有损拿取被价值门控否决——挂待玩家确认（对照 [23]/[36] 差分手续形态）。防「为点不开的矿卖光备战席」的结构化出口：垫件（价值 ≈ 0）卖尽即停，高价值持有（合成素材/2★+）不为随机产出让位——放弃损失（随机资源）远小于卖出高价值持有的确定损失。
- **升级判据的濒死破例不保留**：现行「血线硬地板解锁破息升级」依赖 HP 作决策输入，违反 user_playstyle [39]（HP 不作决策依据）与 [18]（血低是报警非 ALL IN 触发）。本设计删除该解锁层；血本位突变下的支付能力检查（[40]②）保留——它是账户余额检查，非质量信号。

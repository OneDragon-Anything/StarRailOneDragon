# ADR-0431:hp 下行守卫——「幅度 × 战斗事实」联合判据与复现确认通道

## Context(为什么)

派生式 `hp_trusted = 现读非 None ∨ last_hp_real 存在` 把「曾存在真值」等价于「当前值可信」;对账层(ADR-0282)只有**上行** ≥30 留证(仍采新),**下行无任何守卫**——OCR 读低(数字缺位/遮挡)直接采新写回 `last_hp_real`,此后所有帧 `hp_trusted=True`,毒值被 FLIP 持续臂(应急清仓)、C3 濒死带收窄、C1 当可信值消费。

根因分层:HP 的合法变化只有三种物理来源——败战损血(幅度 ≤ 单战损血谱上界)、胜战回血/零损、什么都没发生。**误读读低不属于任何一类**。误读与真掉血的区分变量不是幅度,是**帧间发生了什么**——纯幅度判据救不了「谱内误读」,事实判据才能。

## Decision(逐条)

1. **下行守卫(reconcile_hp 新分支,仅 node_t 非 None 且有旧真值且新读 < 旧值时介入)**:按帧间战斗事实三分——(a) 事实=win/零损节点(奖励/补给):胜战不损血是机制事实,任何下行一律拒信;(b) 事实=loss 且节点型已标定:Δ ≤ L_cap(node型) 采新,否则拒信;节点型未标定(精英/巨星等)不拍值,走拒信通道;(c) 无已观测战斗(结算漏采/telemetry 断):物理上不存在合法下行,一律拒信,无幅度豁免。`node_t=None`(离线/旧调用方)守卫不介入,ADR-0282 行为逐位零漂移;上行/持平分支不变。
2. **L_cap 取损血谱 p100,标定入注册表常量**(`decision_v2/registry.HP_LOSS_CAP_P100_BY_NODE`:普通战斗 23/遭遇 42/boss 39)。标定 = 887 行遥测 outcome 语料,只采 `hp_confidence>=1` 且按 (run,位面,round) 去重后的分位(去重是关键:误读行混入会把普通战斗 p100 虚高到 88)。取 p100 不取中低分位的论证:误报(真掉血被拒)的代价是「跳过应急带→死」,单局全损;p50/p75 档误报率 ≈50%/25% 完全不可接受,灵敏度不足的谱内读低交给事实判据补,不靠压幅度阈值。
3. **拒信 = 复现确认通道(自愈)**:拒信帧返回 `(旧值, False)`、不写 `last_hp_real`,留证 `direction='down'`(同 obs_conflict 通道,节流:同候选首帧 + 每 5 次一条);拒信值挂 `session.hp_suspect`。出窗二选一:后续真值帧读数回旧值 → 误读确认,丢弃 suspect;连续 `HP_SUSPECT_CONFIRM_FRAMES=2` 个真值帧读数与拒信值一致 → 真掉血确认,采新出窗。2 帧 = 最小独立复现数(实机遮挡是 shop 开态特有,结算/备战帧不复现同一遮挡);每节点至少一个真值帧,毒化窗 ≤ `HP_SUSPECT_WINDOW_NODES=2` 节点自愈。留证与拦解决策绑在同一分支,不存在「留了证仍采新」的形态——与上行分支「留证仍采新」刻意不对称(上行读高必是误读或特殊回复,物理读数优先;下行读低两种可能,事实核对说了算)。
4. **三态落对账层内部,GameState 公开面维持两位**:VERIFIED(真读过守卫)/STALE(沿用)/SUSPECT(拒信)在对账层区分,SUSPECT 帧对消费面就是一个普通沿用帧;`hp_trusted` 派生收紧为帧龄门(同节点内沿用才 True,ADR-0428 增补节),全部谓词消费面(`hp_readable or hp_trusted`)零改。
5. **sim 零漂移**:sim 帧 hp 恒真读、结算 outcome 恒已观测且自洽 → 守卫全过、帧龄门全过,逐位等价;源级锁钉住,不另跑对拍。

## Consequences

- 实机:误读下行不再毒化 `last_hp_real`/`hp_trusted`;真掉血在漏采场景最多延迟 ≤2 节点采信(复现通道),结算正常观测场景零延迟(loss 帧谱内直接采新)。
- 实机锚点(事前写):拒信帧的下一真值帧读数回归旧值带 = 误读确认,应占拒信事件 100%;每条 'down' 留证行应能在对应帧截图复判中指认误读形态(缺位/遮挡);复现确认每次触发应有完整 2 帧证据链。锚点没中 = 守卫没生效或判据错,两者都要查。
- 残留:P2 boss 谱外肥尾、精英/巨星节点型未标定(下行走拒信+复现通道,不拍值)——标定数据攒齐后扩 `HP_LOSS_CAP_P100_BY_NODE` 即可,无结构改动。

## 修订记录(2026-09-02:下行守卫判据按机制重推导,部分取代上文 Decision 1/3)

- **修订动因**:obs_conflict 存量冲突帧分诊(报告 `.debug/temp/currency_war/obs_conflict_triage_20260902.md`:80,142 行冲突台账全量机械聚合 + 198 张冲突截图配对 + 39 帧视觉抽样)实证本 ADR 守卫存在**自放大噪声环**——ADR-0490 恢复 hp 真读全路径后,「无战斗事实一律拒信 + 2 帧复现确认」把与画面真值一致的合法下行反复拒掉(抽样 6 帧中 5 帧新读数与画面一致仍被拒),拒信期间每帧留证直至双帧确认;hp 冲突行数 post-ADR-0462 前后 1,316 → 2,454,为全部字段中唯一暴涨项。
- **机制锚**:扣血只发生在节点结算的战败(`docs/game/currency_war/research/user_playstyle.md` 条目[27] 最高权威口述「掉血=战斗失败」+ gameplay 文档「未在行动值内取胜扣血」),即 hp 在节点内恒定、只在跨节点结算时变化。守卫锁的对象因此从「下行方向」修正为「机制不可能的下行」;原判据把观察回路的缺口(结算漏采/telemetry 断)当成「物理上没发生战斗」,是噪声环根。
- **新判据(五分支,一句概要)**:①同节点内下行一律拒信(hp 节点内恒定,原保护面);②跨节点且窗内最新结局为胜战/零损 → 拒信(不扣血是机制事实);③跨节点且窗内有战败行 → 谱内静默采新、超 p100 谱拒信、节点型未标定采新+幅度留证攒标定;④跨节点且窗内无任何已观测结局(观察缺口)→ 从「拒信」改「采新+留证」;⑤`node_t=None` 守卫不介入(逐位零漂移,不变)。
- **配套读数修复**:hp OCR 原生通道对笔画断续的美术字偶发丢十位(画面 47 读成 4,分诊帧离线复现实证),`read_hp_opt` 改为原生 + 3x 放大双通道常开对账——两通道一致才静默,不一致采放大值并 obs_conflict 留证(放大通道可信依据 = 本函数既有低血小数值失明回退先例 + 掉十位帧离线复现)。
- **代码指针**:`kernel/cw_reconcile.py` 的 `reconcile_hp` 下行守卫分支注释、`_battle_facts_between`、`_outcome_is_no_loss`;`obs/cw_observation.py` 的 `read_hp_opt`;`kernel/cw_registry.py` 的 `HP_LOSS_CAP_P100_BY_NODE` 注释。测试锁:`sr-od-test/test/sr_od/app/currency_war/test_cw_blood_crisis.py`、`test_cw_hp_trust_defense.py`。

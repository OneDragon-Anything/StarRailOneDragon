# 阵容知识工程方法论(提炼/深读/版本更新重跑)

> SKILL.md §阵容知识工程的展开。读者 = 智能体;适用于:从零提炼阵容体系、新增/修订单套 comp 知识、版本更新后重跑深读。

## 证据三层(核心纪律;缺层即盲区)

| 层 | 来源 | 给什么 | 缺失盲区 |
|---|---|---|---|
| **统计骨架** | plaza API 聚类(carry 聚类 n≥5/羁绊频次/装备频次,生成器 `tools/cw/gen_plaza_comps.py` 重跑) | 什么主流、什么是代表、量级分布 | **发现不了细节**——频次说「某角色常驻」不说为什么;单聚类混多形态;巧合被当规律 |
| **逐篇细节** | 攻略帖 description 全文**逐篇精读**(纪律:必须逐个看,不能偷懒;每看一篇记录一篇) | 作者运营思路/时序/条件判断/变体/降级路径 | 只有统计时:看不到「什么条件下这么打」,高频 ≠ 正确 |
| **机制解释** | 游戏数据本体:角色技能效果/羁绊效果/装备效果/投资策略·环境效果(注册表+图鉴+官方 config) | **玩法为什么是这样的**——因果链 | 只有攻略时:知其然不知其所以然,版本一变全部失效 |

**工作流**:统计给候选 → 逐篇读细节 → 游戏数据验证机制——「为什么」成立才收编为结论;机制不成立的高频做法标 [社区] 存疑,不进决策链。

**机制解释层的数据源细分**(读什么去哪读):
1. **角色技能说明**——⚠️ 两层数据源别混:官方 config API 的 skills 字段只有技能名无描述;BWIKI 货币战争/<角色名> 页有全文(含星级数值);游戏内图鉴同等权威。判例:角色「以更高速度行动」类技能只在技能层可见,羁绊层推不出——统计说它常驻,技能文本解释它为什么是引擎件。
2. **羁绊效果**——官方 config `role_list.trait_details` 程序可读(激活门槛在此层)。
3. **装备效果/投资策略·环境效果**——注册表(`cw_equipment`/`cw_invest_data`)为值单一源,人读对拍 `docs/game/currency_war/data/`。

### 经济期望方法论(r402;「货币战争」的玩法本质)

> 用户定调(2026-08-23):这个玩法叫**货币战争**是因为经济影响极大
> ——**有限的经济内发挥最大价值**。算经济期望是策略设计/评审的
> 核心手段,不是可选项。每笔支出问三笔账:

**三笔账框架(任何购买/刷新/升级决策都要过)**:

1. **本笔净成本** = 价格 − 可回收值。关键机制:`sell_refund`
   (1星=cost 全额退;1费各星净0;cost≥2 合星后卖才 −1 手续费)
   ——**囤件净成本≈0**,唯一稀缺资源是 bench 槽(9格)。
   → 推论:「有用就先囤」几乎恒优;囤>2-3 张才谈优先级
   (按稀有度排:5费>4费>低费,与出现率反序)。
2. **弃购期望损失** = 再遇窗口。不买这张,再遇它期望 1/q 轮
   (q=单店出现率=1-(1-p/n)^5,p=该费刷新率,n=同费种类数,
   查 `cw_shop_odds.REFRESH_PROB`/`DISTINCT_CARDS_PER_COST`);
   急需时主动 D 的期望金 = 2/q。量级锚:2-3费 7-15轮/15-31金
   (弃购风险低);**5费在 7-8 级 = 60-180 轮(整局可能不再遇)
   /121-361 金**——稀有度越高越该囤;等级升到位(9-10)窗口
   才收窄到 8-18 轮。
3. **机会成本 = 这笔金不花能干嘛**——**凑息优先算**(口述[22]
   用户补点):50 金满息=5金/轮,每 10 金沉淀=0.5金/轮的永续
   收益;一笔支出若把金从 50+ 打到 40,损失的不只是这笔钱,
   还有**息档落差**直到回满。所以「囤件净成本≈0」的前提是
   **卖出时机自由**——金在息线上方时囤(不破息),贴息线时
   囤破息件要先算息差(口述[11]:金<20 的 1 息档内买过渡件
   不损息;[17]:>50 的每一分都没有存的意义)。

**评审姿势**:任何策略改动/参数调优,答得出「这笔账三项各是
多少」再动手;判读购买行为异常时,先算该决策的三笔账再定性
「乱买/漏买」——期望账是判读的标尺,不是事后装饰。

**决策总则(与口述体系的关系)**:[17] 息律(50金息律节点无关)
是第三笔账的基准;[15] 压缩牌库(1费净0)是第一笔账的应用;
[21]/[22] 买而不上/先囤是第二笔账的应用——三笔账是它们的
统一母框架。

## 过渡阵容筛选方法论(r400 定稿;判例链见 transition_combos.md 头部)

> 过渡阵容(位面 1 用)与终局阵容的**筛选判据不同**,别用同一套。
> 2026-08-23 实战教训:曾沿用旧文档的「大引擎/中引擎」分层
> (旧词来自已删的 V4.0 攻略),被用户三次纠正后才重建——以下
> 每条判据都有判例,引用旧结论前先验它的证据源。

### 判据序(筛选「什么羁绊能当过渡」)

1. **一级羁绊即有伤害**(机制层第一问):第 1 档激活就有真实
   伤害/召唤物的 combat 羁绊才配当过渡——位面 1 人口被等级压死
   (lv5-6≈5-6 人),高阶羁绊(7+ 人)做不到也不该做。判据读
   羁绊文本:召唤物(神君/星穹列车)/结算机制(超激发)=伤害源;
   拉条/资源/经济类(贝洛伯格拉条/学者经济)=不是过渡主体。
2. **组合验证**(统计层):过渡阵容=**体系两两组合**。验证口径
   = plaza Early 纯 1/2 费层(真 P1 阵容;含 3 费层会混入中期件)
   + 官方激活口径(`traits.layers[].is_activated`,别自己数人头)。
   判例:三体系两两组合 140/328 帖全有实证;「都不含」的 49 帖
   全是直通线——**通用羁绊组合过不了位面 1** 的实证。
3. **人员要求分层**(逐篇+口述层):羁绊达成 ≠ 阵容成型。
   - 无人员要求(凑出就能用):DOT2/列车2——羁绊文本「任意
     2 名队员触发」;
   - 有最佳班底:仙舟3=藿藿+饮月+爻光(95% 帖含全三人组;
     功能链各占一环:叠段发动机/仙舟∩治疗唯一/Front 输出);
   - **单卡依赖体系**:希儿系=希儿在场 AND(量子2 OR 贝2)——
     伤害在希儿技能层(斩决处决+迸发倍率),量子/贝只是放大器,
     **无核心单卡时放大器不独立成体系**(判例:28 帖希儿局 64%
     开量/贝;不含希儿的量/贝局全在「都不含」直通线堆里)。
4. **占比即可行性排序**(统计层):激活占比 29-36%=主力;
   2.6-9%=小众(待实机探索,别优先做——用户裁定「少人用可能
   就是不太实用,先做有把握的」)。
5. **升级路径 vs 过渡起点分开**(逐篇层):列车4(Early 5%
   /Final 41%)是升级层不是过渡起点——前置=3 费购买力+姬子·
   启行(33/33 帖同时开领航员)。列在体系表里的必须是「开局
   能起步」的东西。

### 高频坑(本轮实付学费)

- **旧词考古**:文档里的分层词(「大/中引擎」)先查证据源——
  可能是过期攻略残留;用户问「这词哪来的」答不出=该重审。
- **统计 ≠ 理解**:组合的语义(副产品/直通/升级层/单卡依赖)
  统计看不出来——**先读精读笔记再跑统计**,统计只当验证。
  精读笔记位置:`.debug/temp/currency_war/plaza/reading_notes/`
  (663 帖逐篇,批次文件+主题归档)。
- **副产品羁绊误判**:战技点/护盾/学者/减益高频出现但构成与
  DOT 挂件同班底(椒丘=DOT+减益/艾丝妲=DOT+学者)——是买件
  顺带激活,不是被选中的体系。判别法:看该羁绊的成员是否
  同时是伤害体系件。
- **字段口径陷阱**:plaza 的 `rarity` 是字符串;`role_stages`
  在 `tourn_detail` 下;`game_data` 是互动数不是阵容——解析
  前先 dump 单篇核结构。

## 从零提炼流程(建整套阵容体系)

1. **采集**:`tools/cw/plaza_fetch.py`/`gen_plaza_comps.py` 拉全量高难帖(jsonl 落 `.debug/temp/currency_war/plaza/`),过滤版本/KOL 沙盒/过期。
2. **聚类**:按 Final 段官方 `is_carry` 标记分桶(统计候选);注意一帖可多 carry、一聚类可混多形态——聚类是候选不是结论。
3. **人判分类**:聚类 → 合并/定边界成类(判据:CARRY 主体优先、核心羁绊其次——羁绊大量作挂件存在);新类成立判据 = 样本量够且 CARRY/羁绊可辨识,长尾不硬分。
4. **逐类深读**:类内帖全文逐篇读(笔记落本地工作区),提炼子形态/装备体系/节奏/降级路径/类间关系——**结论进 research 知识层,深读底稿留本地**(工作过程不入共享 docs)。
5. **机制验证**:每条核心结论回游戏数据找「为什么」;找不到机制支撑的高频做法标存疑。
6. **成文**:结论按证据分级([口述]>[图鉴]>[米游社]>[社区])写进知识层,指回源。

## 单套 comp 修订(增量)

- 新增/修订单套知识 → 改对应类文档(final_comps 单一源);结构化字段(factions/form_tiers/level_plan/key_equips 等)单一源在 `cw_comps.py COMP_LIBRARY`,知识文档只写字段承载不了的叙事——**改 COMP_LIBRARY 不触发文档同步义务,反之亦然**(不是字段镜像)。
- 用户口述与攻略冲突时**以口述为准**;与统计数据冲突时,先查统计的口径(过滤/聚类方式)再下结论。
- comp 增删是策略行为变更 → 走 SKILL.md §文档同步(ADR + strategy 正文)。

## 版本更新重跑

赛季扩充会重划分角色定位/羁绊/费用/投资(版本公告为准)。顺序:
1. 重跑生成器(注册表/聚类/power_table 全家,见 tools/cw/ 各脚本;有内建 diff);
2. diff 驱动复核:变化条目逐个过证据三层(新统计→新帖逐篇→新机制);
3. 知识层各篇标版本重核;策略侧消费点(COMP_LIBRARY/桥池/引擎阵营)按 diff 同步;
4. 掉版本锚的数据(旧版本帖)不删——标时效,新版本另采。

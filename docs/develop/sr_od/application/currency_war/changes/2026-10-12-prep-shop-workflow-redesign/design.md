# 备战与商店工序流重设计 迭代设计（总纲）

## 0. 元信息

- **状态**：草案
- **文档清单**：
  - [details/prep_pipeline.md](details/prep_pipeline.md) —— 备战画面工序流：8 步全扫逐条判据、溢出自救阶梯、节点边界状态重置
  - [details/shop_session.md](details/shop_session.md) —— 商店会话模型：一节点一会话、买入序、置换账、筹资、刷新、节末凑息、正常重开触发

## 1. 问题与动机

### 1.1 现状症状

1. **备战动作优先序与用户打法错位**。晶矿在席位满时单探针确认后即放弃（`entry.py` 晶矿让路段，`ORE_DEFER_PROBE_K = 1`）；部署排在逛店之前（买了立即上阵）；工具消费排位过早；升级动作被多层闸推迟。用户给出的目标工序（用户裁定 2026-10-12）：消耗品最先、晶矿席满时卖 1 个腾位必拿、升级在逛店前、商店按节点一次处理、部署在逛店后、工具靠后、出战兜底。
2. **血本位局买经验截断成部分购买**。机理 = 逐帧单击发射形态（`cw_prep_level_up_action.py`）× 静态全量阈值逐帧重闸：血支付过程中血量跌回阈值之下即停止发射，留下部分级（`kernel/cw_economy.py::blood_xp_gate` 本体为全量击数口径，非截断源）。违反整买纪律（user_playstyle [41]：「需要升级的时候一次买齐，零散买 XP 完全无效益」）。用户裁定 2026-10-12：付不起整级就一击不买；修法 = 整级预授权 + 实付上界。
3. **升级判据主轴偏离**。现行存在多层外围拦截（调度守息门、全段式支出预算闸、危险顾问延迟、血线地板解锁），主轴被稀释。用户裁定 2026-10-12：升级主判据 = 目标核心费用档的刷新概率账（user_playstyle [3]/[7]），一次买齐；拦截层删除（已证保底语义的处置见 line_and_upgrade §2.3，逐件列名）。
4. **卖出语义缺位**。卖出候选池只有备战席（场上凑人数垫件遗漏——部署逻辑会让无关角色上阵占位，用户裁定 2026-10-12 卖出候选应含场上）；卖出无「价值比较」语义。用户裁定：店内席满买入 = 商店里新角色的价值与手上已有角色的价值比较，值得换才换。
5. **换线体系散装**。现行 12 号篇的换线机器（θ 滞回、D_min 驻留、证伪记忆分桶、换线第四触发、P84 可达性门、塌缩卖出通道）是多组件拼盘。用户裁定 2026-10-12：应为一个**统一的选线函数**——计算应选哪个最终阵容，算出新的就更换目标；贯穿件是强信号之一（非一票定音）。被替代物按组件逐项列名于 line_and_upgrade。
6. **节点变动无显式重置点**。节点作用域的策略状态（商店处理标记、尝试计数等）靠键失配隐式失效，无统一边界处理。用户裁定 2026-10-12：识别到节点变动时，策略层应显式更新相关标识。
7. **溢出告警死局出口违反自动化原则**。现行溢出告警强收窄为单笔卖出，若候选空则停摆。用户裁定 2026-10-12：策略工序不允许「停下来等人」的出口；卖出候选耗尽时按损失递增阶梯逐级下探（含目标件），必然可解。
8. **文档黑话密集**。strategy-docs 正本大量使用无定义自造词（用户裁定 2026-10-12：编号引用如 M1/P40 可保留，其余自造词改正常表述或首次出现给定义）。

### 1.2 根因归层

- **语义层**（主因）：判据主次颠倒（升级主轴、卖出语义、方向语义）；两域动作的时序语义（部署/升级/凑息相对商店的位置）未按用户打法组织。
- **流程层**：备战工序的优先级序错位。
- **架构层**：腾位、卖出、方向三块各自散装多组件，无统一原语。

### 1.3 解决到哪 / 明确不解决

- **解决**：上述 1-7 全部。载体面 = 策略层 `strategies/impl/mandate_v1/`、kernel 状态键，**以及店内动作的执行链接线**（`operations/` 商店执行环境补执行端口——现行商店域执行环境无执行器端口，卖备战/买经验在店内发射会失败；as-built 依据 = `screens/README.md` §5.4「商店域执行链未接线」）；8 在末阶段正本更新时一并执行。
- **明确不解决**：
  - 流程层画面**编排语义**不动：刷新维持「访问终结」（op 结束→外循环重识别→商店 op 重新入口观察，规范出处 = strategy-docs/11 §3 决策规则 4 与 02 §7「循环内零读屏」）；开店/关店动作链不变。**例外 = 上述执行端口扩展**（动作执行基础设施，非编排语义）。
  - 画面识别与建档不动（商店画面能力面已由实机归档帧确认，见 details/shop_session.md §1）。
  - 装备策略内容不动（用户裁定 2026-10-12：装备穿戴保留完整版现行实现——合成规划/分配/转移/工具判据照旧，仅其在工序中的调用位置移动）。
  - sim 基建不改（只消费：批跑 CLI 已随 sim-redesign 删除且无当期替代，strategy-work §4 在案——基线/对照批以 SimBackend 库驱动自建脚本实现，最小规格见 landing.md §3.0）。
  - 数学证明件不重推（选线函数的概率输入消费既有 P40 期望模型与注册表概率表）。

## 2. 方案

### 2.1 系统级变化（读一遍知全貌）

1. **备战画面 = 第 0-8 步九段全扫工序**：每次回到备战画面从第 0 步向下扫描，执行第一个满足条件的动作后重新扫描。顺序：溢出自救 → 点消耗品 → 晶矿 → 升级检查 → 商店会话 → 部署调整 → 装备与工具 → 节末凑息 → 出战。载体 = `entry.py::emit` 重写。
2. **商店画面 = 一节点一会话**：本节点未处理时进入会话；会话内循环「方向评估 → 买牌（席满走置换账）→ 刷新判据 → 收工」；正常收工打「本节点已处理」标记并记「未消费机会清单」；清单被后续正常事件（部署腾席、资产变现）解拦时清标记重开。**店内卖备战席与店内购买经验的启用，前置依赖执行链接线批**（landing §3.5）。
3. **卖出统一为「价值让位」语义**：一个卖出候选评估器服务全部卖出场景（告警自救/晶矿腾位/店内置换/筹资/节末凑息），候选池 = 备战席 ∪ 场上，按持有价值升序让位；店内场景（席满买入）额外过置换账（新牌价值 > 手上最差牌价值 + 置换摩擦才卖买）。
4. **升级判据重轴**：主判据 = 目标阵容缺件在当前等级与升一级后的刷新期望比较（消费 P40 期望模型）；人口位触发并列保留；一次买齐整级；硬闸保留 = 等级帽、血本位支付检查（整级预授权 + 实付上界）、P21 血预算线（已证负 EV 约束，出处 = proofs P21 与 04 号篇）；删除 = 调度守息门、全段式支出预算闸（其保底 floor 语义保留，见 line_and_upgrade §2.3）、危险顾问延迟、血线地板解锁。
5. **统一选线函数**：加权评分（完成度/获取前景/专属资产/环境四维）输出「未定型」或「目标线」；贯穿件为强信号之一；换目标过「切换成本 + 滞后余量」账防摇摆；评估以方向签名前置段形式挂在备战与商店两个决策入口（签名 = 证据源拼接，变了才重算）。**标定前缺省 = 恒未定型（search 态件级评估，含终局件囤货——囤终局卡为后续锁线准备；丢掉的只是锁定单一名单的 focus 态，随标定打开）**。
6. **节点边界重置**：策略入口检测到节点号变化时，显式重置节点作用域状态键（见 prep_pipeline §3）。
7. **溢出自救**：告警在场 = 按候选评估器（自救扩展资格面：全量持有可卖，线内件排末位）卖出首位候选，每帧全量重评、卖出即推进；候选池含场上。任何分支无策略性停机出口。
8. **策略层无试错计数（用户裁定 2026-10-12「计数器治标不治本」）**：全部工序判据为每帧全量重评的纯判断（如晶矿腾位 = 腾位候选是否纯垫件的结构判断，散件卖尽自然停止）；动作未生效归执行层落地验证，识别异常归外循环环级守卫，不进策略判据。

### 2.2 详设划分与跨详设接口契约

| 详设 | 范围 |
|---|---|
| prep_pipeline | 备战 8 步逐条判据、自救阶梯、节点边界重置 |
| shop_session | 会话模型、买入序、置换账、筹资、刷新、节末凑息、重开触发 |
| line_and_upgrade | 选线函数、升级判据、方向签名 |

**跨详设接口契约（唯一必须在总纲定死的深度内容）**：

- **契约 A（prep_pipeline ↔ shop_session：商店会话的进出）**
  - 备战工序第 4 步是备战侧开店意图的**唯一来源**；商店画面的实际进入有两条路径：① 第 4 步输出开店动作；② **游戏侧自动开店**（战斗结算/选卡类画面处理完后游戏自动弹出商店，实机在产，出处 = screen_flow_timing #14/#29）——路径②下外循环直接进入商店画面 op，op 入口行为 = 检查 `shop_handled` 标记：未处理 → 正常会话；已处理 → 立即关店收工（同节点牌面未变，无新信息）。两条路径进入的是同一会话语义，`CwActionCloseShopParam` 为会话终结，终结时置标记（session 固定键名 `shop_handled`，**值** = 最后处理的节点号二元组）并写「未消费机会清单」。
  - 标记与清单的读写、**解拦复核判定函数**的唯一所有者 = shop_session（shop.py）；备战工序消费标记与复核结论。
  - **重开触发统一化**：清单解拦复核的唯一触发点 = 备战工序第 4 步入口（每次全扫到达本步时调用复核判定：金位变化 / 席位空出 / 方向变更，任一使清单中拦因解除 → 清标记重开）。不在部署、卖出等动作后单独挂触发钩子——所有状态变化都发生在备战轮次之间，第 4 步入口复核天然完备（用户裁定 2026-10-12：节点内重开允许；场景枚举 = shop_session §4.2）。节点边界重置对该标记 = 清值（契约 C）。
  - 现行「备战期开店闩」（`cw4_shopped_phase`，同备战期吞第二次开店提案）退役，防活锁职责由会话标记承接（标记只在正常收工时写入，未收工帧开店意图不重复发射的语义由标记判定承载）；退役登记 = shop_session §5 承继清单。
- **契约 E（买入策略统一入口）**
  - 买牌策略是**全局统一组件**（用户裁定 2026-10-12「应该是统一的买牌策略……只是有优先级」）：类目与优先级序 = 目标阵容件 → 场况插件 → 通用插件 → 压库件 → 凑星件 → 纯冗余停买（核心卡支配支邻位），判据本体单一源 = 现行 11 §1 六序收编，未定型/定型两态只变化序 1 的名单来源（search 态候选集 / focus 态名单）。
  - 商店会话是买入策略的**执行画面**（买牌动作只发生在商店画面），不是买牌判据的所有者；备战域不买牌（无商店面）。价值评估（契约 D）与买入策略分别管「卖出让位序」与「买入优先序」，共同消费同一方向状态（契约 B）。
- **契约 B（line_and_upgrade ↔ 两域：方向状态）**
  - 方向状态 = session 上的「目标线名或未定型」单值 + 证据签名（字符串）。读写唯一所有者 = line_and_upgrade 提供的两个函数：`refresh_line_if_needed(gs)`（签名比对，变了重算）与 `line_members_view()`（当前方向下的目标名单视图）。
  - 备战工序（部署/凑息/自救）与商店会话（买入序/置换账）消费同一视图，禁各自维护第二份名单口径。
- **契约 C（节点边界重置：键清单唯一所有者）**
  - 节点作用域状态键的清点与重置逻辑唯一所有者 = prep_pipeline 的「节点边界处理」函数；shop_session 与 line_and_upgrade 把自己需要节点级重置的键登记进该函数的清单。触发点 = 策略决策入口检测到节点号（位面+轮次）变化。
- **契约 D（卖出候选评估器：单一入口）**
  - 一个评估函数，输入 =（场景, 当前容器状态），输出 = 排序后的卖出候选或空。五类场景共用同一候选池与价值排序（金当量口径 = line_and_upgrade §4）；**场景参数全集（唯一定义处，各详设引用不重复枚举）**：
    | 场景 | 资格面 | 消费方式 |
    |---|---|---|
    | 溢出自救（备战第 0 步） | 扩展面：全量持有可卖（线内件排末位） | 取首候选直接卖 |
    | 晶矿腾位（备战第 2 步） | 常规面（线内件禁卖） | 取首候选直接卖 |
    | 店内置换（会话内席满买入） | 常规面 + 仅备战席 + P78 同 visit 买入排除 | 比较账裁决（shop_session §3） |
    | 会话内筹资（会话内缺金买入） | 常规面 + 仅 1★ 全额退件 + 同 visit 买入排除 | 卖到缺口闭合即止 |
    | 节末凑息（备战第 7 步） | 常规面 + 仅 1★ 全额退件 | 卖到缺口闭合即止 |
  - 资格门单一源 = 现行 `sell_gate` 排除集收编（含 P78 素材对释放子谓词）+ P78 卖出资格仲裁族通道重映射（映射表 = shop_session §5 承继清单 P78 行）。

### 2.3 行为验证总则

- sim 批跑 CLI 已随 sim-redesign 删除且无当期替代（strategy-work §4 在案）：基线与对照批以 **SimBackend 库驱动自建脚本**实现——最小规格 = Python 入口直接构造 `SimBackend` 与策略注入、固定 seed 列表与池参数、逐局统计输出 JSON 归档、批头记录参数指纹；脚本属迭代工件（入迭代目录，不进生产代码）。对照纪律不变：改前基线批先行，全部行为批完成后同参对照；A/B 仅确认，采纳判据 = 本设计 + 对抗审收敛。
- 每个行为批配单帧锁（构造 GameState + 策略入口调用 → 断言动作序列），锁出处 = 本设计对应节。
- 实机验收判据线在行为批全部落地后、实机批开跑前预注册（载体 = proofs 目录单篇，先 commit 后跑批；必含既有验收线保全清单）。

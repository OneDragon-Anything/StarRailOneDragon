### P72(全段升级支出闸判据式)

升级支出 s 合法 ⟺ 四合取((1)(2)(4) 与 P71-b 逐字相同,(3) 全段化):

```
(1) P48 整买    s = U_L(不变)
(2) 兑现视界    存活到账 h > d·L_c(P21;ALL IN 位面末战豁免同先例;不变)
(3) 全段预算闸  (3a) ∨ (3b):
    (3a) 闭式预算支(全段):
         g − s ≥ 10·τ(g) + ρ + Σ预留
    (3b) 一般式完备账支(辖域 g ≤ g*,即非溢余段):
         ΔV_band + ΔV_pop ≥ s + L(g,s,R,Ī) + [10·τ(g) + ρ + Σ预留 − (g − s)]⁺
(4) 通道比较    EV_up ≥ EV_buy(P39-P40;不变)
```

**闸拒 = 整批推迟**(P71-b 同款语义:攒到 `10·τ(g)+ρ+Σ预留+U_L` 的帧一次买齐;禁按额截断击数)。收敛性:推迟目标随金位上移(τ 随 g 增),但 g 越过 g* 后切 P71-b 分支、目标固定为 `g*+ρ+Σ预留+U_L`——存在不动点,无「追着息档永远攒不够」的发散(实现批禁误读为移动靶)。

**(3) 的判定算法(实现批照抄级;两支显式语义,消解文字加总式的判定缝隙)**:

```
def gate_3(g, s, R, I_bar, cap, rho, sigma, dV_band, C_realize):
    tau       = min(g // 10, cap)
    shortfall = max(10*tau + rho + sigma - (g - s), 0)
    L         = loss_exact(g, s, R, I_bar, cap)
    if C_realize == 1:
        return PASS                        # 支 A:兑现链成立,支配放行(姿态声明,见下)
    return dV_band >= s + L + shortfall    # 支 B:数值完备账
```

**支 A 的语义地位 = 显式姿态声明,不是已证支配命题**:C_realize=1 时升级收益含「当帧可兑现的人口位增量」,其支配性沿 P39 ①臂「最高义务」既有先例(`schedule_upgrade` ①臂同款短路),但「w·1 支配任何有限右端」在 w 无界假设下才是真,w 未标定 ⟹ 本命题不把它证成定理,而是与 P39 ①臂同姿态的授权声明;若要降级为数值支,需先立 w 的标定模型(新命题,不属本批)。**支 B 中 w 项不出现**(C_realize=0 ⟹ ΔV_pop 项构造性为零,数值判据由 ΔV_band 独自承担)——这同时消解了「w 不入比较式」与「C_realize=0 帧仍可经支 B 放行」的表面矛盾:两句话说的是两支。

### P72-退化一致性(溢余段退化回 P71-b (3) 原式)

g > g* 时 τ(g)=cap,故 10·τ(g)=g*,(3a) 逐字等于 P71-b (3) 的 `g − s ≥ g* + ρ + Σ预留`。**(3b) 在溢余段不辖**(辖域显式限定 g≤g*):溢余段的穿线完备账已由 P71-b 边界 1(「穿线段必须回一般式」)承载,本命题不扩溢余段辖域。因此对 g>g* 帧,P72 ≡ P71-b,已落码行为零漂移。

## 2. 证明

### 2.1 判据式的统一原理:机会成本记账完整化

P71-b 的深层原理是「升级支出必须支付其完备机会成本」。溢余段内该成本有闭式:溢余金(g−g* 部分)的边际息产出为零(P70),故机会成本=「花后跌出满息档造成的息损 + 购买力挤占」,而闸用「禁止跌出」的 floor 形式表达(P71-b 必要性两子情形)。中间段该闭式失效——**每 1 金都有息产出**(档内金 10 金/档、每档 1 金/轮,`interest` 机制直读),不存在「免费可花的溢余」,floor 形式若照搬 g* 会给负闸值恒拒(P71 docstring 已警告的坑)。

P72 的做法:把「完备机会成本」显式写成两支:

- **(3a) 保守闭式支**:花后不低于「当前息档最低金位 + 一张命中卡 + 下帧窗口预留」。语义 = **息档零侵蚀 + 购买力保底**:升级不花「正在生息的钱」,只花「升档后仍留在本档内的冗余」。它是 P71-b floor 在中间段的自然映衬——两段同一句话:『花后金位不低于「当前息档的最低金位」+ ρ + Σ预留』;g* 只是「当前息档」在溢余段的特例(满档)。
- **(3b) 完备账支**:若收益侧愿意显式支付全部机会成本——整批成本 s、息蚀 L(P47 一般式,中间段严格 >0,见 §2.2)、以及花后跌档造成的储备缺口(尖括号项)——则允许破档。尖括号项 `[10·τ(g)+ρ+Σ预留−(g−s)]⁺` 把「花后低于保档线的缺口」计价为收益必须额外偿还的欠账,使 (3b) 不是「息蚀入账就随便破档」而是「破档全额还清」。

### 2.2 中间段息律项的精确形态(L 非常数)

中间段 g ≤ g*,interest 不饱和,`loss_exact` 双轨迹:

- 基线 B:守 g 不花(溢余即花语义下本帧无溢余可花),首轮息 = τ(g) 档;
- 支出 A:花后 g−s,首轮息 = ⌊(g−s)/10⌋ 档;
- 首轮息损 `t₀ = τ(g) − ⌊(g−s)/10⌋ ≥ 0`;后续轮两轨迹同收 Ī,息差随 A 轨金位回补而衰减、随 B 轨触顶而放大,精确值由 `loss_exact` 逐轮递推(P47 命题 2),**无闭式必要、禁在判据侧复写递推**(单一源纪律)。

界(用于量级论证,非判据消费):`t₀ ≤ L ≤ R·cap`。直调复算锚(§数字表):L(34,32,15,5)=23(帧 B 口径)、L(8,4,8,7)=4、L(24,20,7,7)=**13**。中间段 L 严格依赖 (g,s,R,Ī) 四元组——这就是「非溢余段息律项不是常数」的精确含义,与溢余段 L≡0(P70)形成分域。

**购买力下界**:ρ+Σ预留 的全段同一性由 P54 floor 语义直接继承——「满息档上至少一张命中卡可买」的资格在中间段同样存在(命中卡不挑你的金位在哪个段),且 P71-b 必要性子情形②(升级挤占买卡臂可行域)在中间段逐字成立:花后 < ρ+Σ预留 ⟹ 同轮买卡臂失去执行资格。故购买力下界进入 (3a) 与 (3b) 尖括号项,全段无豁免。

### 2.3 收益侧 EV 与到账延迟(开局/残局区分机制)

(3b) 左端两项的机制出处:

- **ΔV_pop(人口位,含兑现链)**:等级=可上阵人数(gameplay 机制直读,`max_units` = deploy_cap 真值优先/level 兜底,cw_state.py:288-295)。升级解锁 deploy_cap 增量的价值**不是**「增量×期望强度」——g_20260906_182456 实证兑现链会整段断:2r2 升级后 4 轮第 8 位空置。故收益按兑现链计,谓词精确形式:

  ```
  C_realize_① := 1[板满 ∧ bench 有 2★ 等待件]        # 链长 0:当轮可部署
  C_realize_② := ∃ c ∈ 部署面候补: deploy_eligible(c) ∧ (g − s) ≥ cost(c)
  C_realize   := 1[板满] · ( C_realize_① ∨ C_realize_② )
  ```

  两支都是**决策帧可构造判定的谓词**(≥ 非 >:g−s 恰等于最低候选价时②支取真),不是概率估计:①P39 ①臂谓词,同步锚对=`schedule_upgrade` ①臂/`_upgrade_ul_threshold_ok` :705-710;②**裁决位=`deploy_eligible`,真单一源=`kernel/cw_deploy_logic.has_deployable`(cw_deploy_logic.py:207-237,dd-037)**——部署面合格判据本尊。⚠ 单一源锚勘误:早稿锚 `pop_slot` 的 `buyable_candidate` 放宽支(criteria/levelup.py:216-217)是错的——该支实为「bench 在场 ∨ 买得起」的 OR,真实计算在 shop.py:853-857=「线内∧affordable」,**不含部署合格判据**;按它落码会把「线内∧买得起」当部署合格,恰好复活兑现链化要杀的虚记收益。pop_slot 放宽支降级为**融资腿**叙述:只保「买得起」(与 ρ 预留同侧的融资前提),不保「合格可部署」。②支金条件只是融资前提,裁决在 `has_deployable`;落码批应接 `has_deployable` 作闸与部署臂的**共用谓词**(该接线现不存在,见 §5 边界 3——两处说法由此统一:谓词真源已在,接线未落)。两支全断 ⟹ C_realize=0 构造性精确零。②支的融资由 (3a) 的 ρ 预留**结构性保障**:ρ 恰是「一张命中卡」的预留,守 (3a) 即守兑现链融资——预算闸与收益侧在这一点上是同一枚硬币。
- **ΔV_band(概率移位)**:升级对锁定线缺件费档的期望刷次移位,金计价 `c_eff·ΔE`(E 表直调,§数字)。**零标定**:c_eff=刷价真值(游戏定义 2 金)、E=池参数超几何精确。
- **到账延迟与血面口径(期望掉血 vs 本局掉血分布)**:升级收益兑现 ≥1 战之后——血面由 (2) P21 判据 h > d·L_c 独立管辖(P21 框架复用,零重推导);时面由 R=r_remaining 视界进入 L 与 (4) 比较承担。**已证边界(g_20260906_182456 实证)**:L_c = vd_p2_loss=20.05 是**全场期望**条件败局伤害,危机带线 41=ceil(2×L_c) 的分母是期望;词缀局单轮实际掉血远超期望——HP=45 帧血线门全过,但一场实际败战即跌穿 21 停升级线。数据源口径注(F11):本局 2-4 掉血有两个读数——对局档案 `loss_nodes` 直读 delta=**−19**(31→12 跨节点差),复盘文档 B2 的 **−33** 是「同轮补给 +14 与战斗净掉血并入同轮」口径(45 为补给后值),两者都对、口径不同,引用须注明,禁按 loss_nodes 复核 −33 判为伪造数。即「血线门未拦」≠「兑现无险」,P72 的血面合取在词缀局存在**系统性低估兑现风险**的口径缺口。本命题的处置:①判据式形态不变(换 L_c 口径需要「本局条件掉血分布」模型,是标定/建模项,不是判据结构项);②**合规修复路径(按 04_survival_budget §7 裁定分层)**:数据面——每战斗节点实测净掉血序列(结算屏 hp 分量)有 §7#2 授权,可作标定输入;判定面——「实测掉血 fail-closed 升档血线」属掉血趋势信号,掉血三臂判定(`BloodAlarmTracker.alarm_active`,≥20/≥30)已按 §7#8 **裁定退役**(阈值硬编码、源自作废式 11.32−0.37·rung,非注册表常数——本证明早稿「注册表常数单一源」声称有误,勘误),**禁搭车复用**,须按 §7#8 走 λ_death 概率侧硬闸门**新立项**;③正式挂账:词缀局 L_c 修正(条件掉血分布标定)进 sim 标定流程(登记形态见 §5 边界 8 指针),标定前 (2) 的口径边界如实声明。

**开局/残局的不对称是判据式的涌现性质,不是权重**:

1. **成本曲线陡度**(XP 表注册表直读):lv3→4=4金、lv5→6=20金、lv7→8=52金(携 XP 可折减)、lv8→9=72金——开局便宜、残局贵是 `XP_TO_NEXT_LEVEL` 的表值事实;

3. **血线**(P21 单一源):残局深血线帧被 (2) 先拦(hp≤21 恒拒、hp≤41 危机带让位),开局满血帧 (2) 恒过。

**标定参数 ≠ 自由参数的论证**:本判据式无任何待拟合常数进入决策位。w(ΔV_pop 量级)沿 P39 既有处置——量级裁决归 P39 双臂门与 sim 对拍,不进本闸:C_realize=1 帧走支 A 姿态放行(§1 支 A 声明),C_realize=0 帧 w 项构造性为零、支 B 由 ΔV_band 数值承担——**w 在两支中都不以数值出现,判据式行为在 w 全值域不变**,这是支配性论证消参数(P71 边界 4 同款声明),与「拍一个阈值决定做/不做」(无模型的替身,strategy-work §1 禁令对象)不同类。C_realize 两支是帧内可构造判定的谓词(0/1 构造值,非估计);E/c_eff/L/ρ/τ 全部注册表或其数学派生。

### 2.4 (3a) 的必要性与规范性

- **必要性(B3 反向构造)**:无 (3a) 时中间段大额支出把息档金整个转成 XP——Leontief 完美互补品(P48),XP 在升级完成前零收益零压库,而息档金每轮产出 τ(g) 金。花后金位 < 10·τ(g) ⟹ 首轮起息流断供,该损失在 M3 arm1 现行发射位未入账(只查可负担性)——与 P71-b 必要性子情形①同构,只是发生域从溢余段移到中间段。
- **规范性(零新自由参数)**:10·τ(g) = `interest` 档数分量×10(息律量化的机制事实,非拟合);ρ/Σ预留 = r2_card_reserve。无任何新数字。

## 5. 边界(什么情况不辖/失效,如实入册)

1. **溢余段穿线**:仍归 P71-b 边界 1(穿线评估回 loss_exact 一般式),本命题 (3b) 不扩溢余段辖域;
2. **ALL IN 豁免扩到 (3) 是新增交互**:P71-b 落码闸现无该豁免支;数学面已证必要性(R=0 ⟹ 机会成本零),实现与测试归落码批,本命题不改代码;
3. **支 A(C_realize=1)的兑现可靠性 + 部署接力是执行面事实**:①支谓词只验「bench 有 2★ 等待件」,但**部署臂是否实际接力是执行面行为**,判据不可证。本局存在反向样本(风险警示,弱于早稿表述):2r4 快照 bench 含 2★ 阮·梅(2r5 又全 1★,疑合并时点差/读数噪声)——**若该快照为真,则「①支前提疑似为真而部署接力仍未发生(deployed 恒 7)」被本局命中一次**,①支兑现可靠性须打折扣对待。②支金条件只保「买得起」,不保部署面会收。两支的执行面风险同挂:实现批须接 **`has_deployable`(cw_deploy_logic.py:207-237)作闸与部署臂的共用谓词**(该接线现不存在,见 §2.3 ②支勘误注),把「升级授权与第 N+1 位兑现前提同帧评估」落到它上;sim 对拍观察「升 cap 后 K 轮空置率」作兑现链的验收量(登记形态=sim-design §3 方向声明[宽松向:空置率不随闸版本下降即判罚]+ §4.2 登记四项[权威源=对局档案 deployed 轨迹/标定流程=sim 批/过期判据=决策面重构/申报面=判据层 sim 可见]);

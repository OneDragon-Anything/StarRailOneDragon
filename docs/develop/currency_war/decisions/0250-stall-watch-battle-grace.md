# ADR-0250 stall watch 战斗窗口宽限(局54 哨兵误报根治)

## Status

accepted(2026-08-24;诊断层行为)

## Context

局54(2026-08-22 18:39)停滞哨兵 `stall_watch` 对**战斗进行中的合法静止**误报:
P2 r1 遭遇战 18:38:20 出战 → 18:43:40 结算(hp 32→9),战斗 5min20s 期间画面
关键词集稳定 → watch 在 ≈2.5min 处触发(「疑似未处理 overlay」+ 截图 + flag)。
该误报曾引发两级误诊:

1. 局55 待办记为「简报屏 stall:分支 5 round_by_ocr_and_click('下一步') 对该
   帧失败」——**分支 5 从未运行也无需运行**(战斗中 loop 正确地只等待);
2. r374(位面简报头部优先分支)以「局54 哨兵实锤 stall」为动机——饥饿机制
   分析本身成立,但触发证据是本误报(r374 的实战验证至今为零,见 Consequences)。

误报根因(日志考古实证):watch 的战斗豁免是**关键词表**
`('战斗','胜利','挑战','结算','准备','倒计时')`,而战斗 HUD 该帧全缺——
OCR 集是 4 个词缀(净化身心/应激反应/决战在即/第三位面强化)+ 3 首领名 +
敌人难度(简报信息面板战斗期常驻)。**「决战在即」是敌人词缀名**
(competitors.md:首领节点倒计时 -30/遭遇 +20),不是战斗画面标语——按词补
豁免不可靠(词缀名空间开放,下个版本新词缀又漏)。

## Decision Drivers

- 哨兵的信命在精确度:误报稀释真信号(局47 的 50min 真卡死靠人晚发现,哨兵
  本该更早;若常态误报,值守方会习惯性忽略)。
- 战斗时长是**结构已知**的合法静止(实测 4-5.5min),loop 自己知道「刚出战」
  ——状态感知比关键词猜测可靠。

## Considered Options

1. **补豁免关键词**(「决战」「敌人难度」等):治标——词缀名空间开放,新词缀
   必再漏;且 briefing 类画面若真 stall 会被误豁免(削弱 r374 场景的兜底)。否
2. **加长 STALL_N/采样窗**:伤真卡死检出时延(30-41min 历史教训)。否
3. **战斗窗口宽限**(选):出战成功(备战环出口)→ `BATTLE_WATCH_GRACE_S`
   内 watch 不计数;结算观测(`_record_round_outcome`)或备战再入关窗;
   超时自动恢复正常判定(出战卡死类真挂死仍可检出)。判定提纯函数
   `_watch_in_battle_grace(ts, now)` 可单帧锁。

## Decision

选 3。`BATTLE_WATCH_GRACE_S = 600s`(> 实测最长 5.5min 留余量;≤ 15min 有界)。
窗口控制三点:开窗=PrepDirector 成功出口;关窗=结算屏进入 `_record_round_outcome`
与备战分支再入(`备战标识-购买经验` 命中)。

## Consequences

- 战斗期误报消失;真挂死检出时延上限 = grace + watch 窗 ≈ 12.5min(可接受,
  历史真卡死 30-50min 量级)。
- **局55 待办「简报屏 stall 排查」关闭(误诊)**:事件是战斗等待,非简报屏,
  分支 5 无失败;哨兵截图已删无法复核画面细节,但 hp 变化(战斗真实进行)+
  流程自然续行(结算→P2 r2)双证闭环。
- **r374(位面简报 0a0b 分支)的实机验证锚点保留**:其饥饿机制分析成立但
  自 18:54 落地后从未有位面过渡经过(局55-62 均未达 P2/P3 过渡)。实机恢复后
  首个位面过渡应见 `[cw-loop] 位面简报 → 点下一步` 日志——验证锚点,不是疑点。
- 锁测试 3 条:常量界(8-15min)/窗口语义(None·窗内·恰好超时)/误报根因
  存证(实测战斗时长 > watch 窗,宽限必要性)。

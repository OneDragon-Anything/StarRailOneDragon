# 羁绊组换人判据 迭代设计（总纲）

## 0. 元信息

- 迭代目标：用户裁定 2026-10-26「货币战争换人策略改为羁绊组语义」——部署换人判据从「单件一步成型」改为「羁绊组/支撑件」语义，保证转型期输出能力；P61 证明随批退役（裁定登记载体 = 本迭代进度账本，建账时补指针）。
- 状态：对抗审中
- 文档清单：无详设（单文档方案，本篇即完整设计）

## 1. 问题与动机

- 现状症状：sim 局 g_20261026_203023（seed=20261216）复盘立案 C1——2-1 买主线核心 Saber 后 4 个备战期换人卖出 0 发射，板面保持位面 1 过渡配方直到死亡，位面 2 转型零完成（复盘报告 = `.debug/currency_war/deep_review/g_20261026_203023.md`；单局归因=候选，本迭代按语义层根因处置）。历史同病：strategy-docs/02_mandate_layer.md §1 A/B 归因「没做占绝对主导（部署 0/934）」；2026-09-18 板满换入分支即同病上一代形态的补丁（`kernel/cw_deploy_logic.py` `required_swap_arm_pending` docstring 出处行）。
- 根因归层：**语义层**。换人触发判据的语义单位错置——以「单件入板即成型（form_progress ✗→✓ 补满）」为换入资格，对「多成员多档位」阵容结构性不可达：双王圣杯成型条件 = 命运圣杯 3 + 能量 5（`kernel/cw_comps.py` 双王圣杯 `form_tiers`；档位表 `data/cw_factions.py`：命运圣杯 2/3/4/5、能量 3/5/7/10），转型中盘不存在单张牌使两档同时补满。victim 让位检验与触发同折法（`_swap_victim_yields_for_swap_in` 同式），同被封死。
- 解决到哪：重定义换人触发与让位判据为「羁绊组/支撑件」语义（§2.2 双门），覆盖转型中盘；P61（B_t 支配命题）退役，其有限触发角色由结构计数注记承接（§2.6）。
- 明确不解决：买入面（M2/商店判据）；上阵窗口语义（方向线成员豁免照旧）；经济/升级判据；演进降级换人通道（准入三元照旧）；sim 战斗结算与 hp 校准；净战力强弱证明（宪法第 1 条禁战力建模，用户裁定按设计落地、行为锚点验收）。

## 2. 方案

### 2.1 核心语义：支撑件与终局档位

- **支撑件**：板上单位的羁绊标签命中终局阵容 `form_tiers` 键集（双王圣杯 = 命运圣杯 ∪ 能量）即计 1 个支撑件。终局名单成员天然全计；凑档外部件（如第 5 格能量的任一能量标签单位）按标签命中计入。计数口径延续 P61 的 B_t 计数面（只延续口径，不延续其命题）。
  - 依据：`data/cw_chars.py` 成员标签（吉尔伽美什/Saber=圣杯+能量；开拓者·记忆/藿藿=含能量；瓦尔特/符玄不含能量）；`data/cw_factions.py` 档位表。
- **终局档位**：板上各终局羁绊人数对照 `form_tiers` 现算激活态（命运圣杯 2/3/4/5 档、能量 3/5/7/10 档）。

### 2.2 双门判据

- **门 1（收益门，满足任一）**：
  1. 换入后激活终局羁绊新档位；
  2. 换入后支撑件数严格增；
  3. 同名升星横换（换入件星级 > 被换件星级）。
- **门 2（安全门）**：被换件过现行 `swap_sell_exclusion_reason` 全链（义务集 ∪ 新鲜度排除 ∪ 资格族：素材守卫/星级守卫/engines 守卫），判据本体不动、不豁免。
- 用户三触发条件的映射（换前组形态表述 → 换后板态判定，覆盖等价）：终局羁绊到二阶 → 门 1①；另一羁绊到一阶 → 门 1① 或 ②；一阶羁绊 + 终局散件 → 门 1②。
- 档位判定的羁绊范围 = 终局阵容 `form_tiers` 键集，不含其他羁绊。

### 2.3 换人单位与执行形态

- 换入组 = 备战席支撑件集合；|换入| = |换出|（板位守恒）；同帧原子序逐对（SellDeployed → DeployMove）连发；卖后上序底线照旧（`post_sell_req_missing`：卖后上序不含换入对象即计划拒）。
- 门 1 以**组整体换入后的板态**判定（非逐对）；门 2 **逐被换件**独立判定。
- victim 选择：过渡件按现行资格/价值序；约束 = 换出不得使终局档位下降（终局件受保护集禁卖，本条为冗余防线）。

### 2.4 与既有机器的接线

- 触发谓词：`required_swap_arm_pending` 的**必需件分支保留**（支配论证照旧：该件不在板该体系永远无法成型）；**完成品分支整体替换**——`_completion_swap_ins`（✗→✓ 折法）退役，新函数 `bond_gate_swap_ins` 承接门 1 判定（禁旧名装新义）。
- 让位检验：`_swap_victim_yields_for_swap_in` 的完成品 hold 替换为门 1 组态判定 + 门 2（新函数 `bond_gate_victim_yields`）；必需件 hold 保留（`_required_swap_victim_completion_holds` 照旧）。
- 演进降级分支（`evolution_swap_arm_trigger`）不动，门 2 共享。
- 上阵窗口：方向线成员豁免照旧（实现批核对 `strategies/impl/mandate_v1/entry.py` 符号锚）；外部凑档件无 entry_signals 登记 = 不受窗口辖（辖域定义 = 知识卡 `entry_signals`，22_prep_screen.md §1 第 5 步）。

### 2.5 与合成通道分工

- 同星三合（同名同星计数 = bench + deployed 全场合计；落点含场上 → 产物落场上位置）归合成引擎（merge_mechanics §2，载体 `kernel/cw_merge_simulate.py` 模块 docstring），换人通道不插手。
- 跨星级残局（板上低星、备战席高星同名，跨星不自动合成）归换人通道门 1③。

### 2.6 P61 退役与收敛注记

- 删除 `proofs/p61-bt-swap-arm-dominance.md` 与 `math_proofs.md` P61 行；引用点全量清点改写（已知 ≥：`14_p1_consume_arms.md` 推迟上界行、`kernel/cw_launch_admission.py` 收敛注释、`proofs/p88.md`、`proofs/p89.md` 交叉引用；实现批 grep 穷尽，禁留退役注记残迹）。
- 收敛注记（接替 P61 的有限触发角色）：门 1 三分支各带独立有界结构量——支撑数 ≤ 板位、档位组合有限、同名星级组合有限 ⇒ 触发次数有限、无死循环。纯计数论证，零参数。

### 2.7 净战力不证明（声明）

- 换人可能使过渡羁绊掉档，净战力账需战力建模（宪法第 1 条禁）。判据合法性来源 = 注册表档位数据（零调参）+ 用户立场（【拍】类，见 00_framework 章程）。
- 验收 = 行为锚点：同 seed 复测（seed=20261216）对照 2-1 至 2-4 换人动作面——缺席翻转为发生，Saber 换远坂凛 1 换 1 应发生且圣杯 2 不掉档、能量 2→3；另加单帧测试与既有验收线保全（landing 常规检查）。

### 2.8 关键取舍

- **Δfp>0 放宽（备选，放弃）**：form_progress 满锚 = 完全成型，多档中盘 Δfp 与档位激活不同构；羁绊组判据更简、零调参，且天然守护「哪怕下远坂凛都不能拆能量」教义（能量档硬约束——拆能量 = 掉档 = 门 1 不过；出处 = cw_comps.py 双王圣杯 branch_key 注记）。
- **登记 required_deployed（放弃）**：字段契约「缺它永不成型」与双王圣杯不符（Saber 有 Archer 替班形态，cw_comps.py special_systems.grail_quest）；且让位检验一步成型折法不动则通道照旧关死——治标不治根。
- **P61 扩展证明（放弃）**：新触发面下「五体系档守恒」不成立（过渡档可掉）；战力面证不了（宪法第 1 条）；用户裁定不证明、按行为锚点验收。
- **支撑件口径 vs 终局名单口径（取前者）**：名单口径会把外部凑档件的档位激活误判为「数量持平」而漏放（枚举 B 情形：阿格莱雅类外部能量件进板激活能量 5）。

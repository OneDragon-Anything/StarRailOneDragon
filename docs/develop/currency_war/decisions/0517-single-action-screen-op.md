# ADR-0517: 画面 op 单动作循环架构(一次调用 = 一轮「入口观察 + 逐动作决策循环」)

> 状态:**proposed(对抗审查中)**。用户 2026-09-04 口述九条为本文决策骨架,原样收录(见 §决策 1-9,各条标注「用户裁定 2026-09-04 口述」);其余分节为本文补的推导细节(映射/成本/盘点/迁移/权衡),与口述条目分列,审查时请分别攻击。对抗轮 1 七项发现经编排者裁决(2026-09-04)已落笔:合成投影边界注(决策 7 附)、机制裁定附注(决策 8 附)、复合动作类(盘点节)、P52 条件等价改写(映射节)、M3 权衡改写、开放问题节——各落点标注「对抗轮 1」。对抗轮 3 五项经编排者裁决(2026-09-04)已落笔:§2.5 适用域限定为满栏例外语境(决策 7 附)、读屏成本分析改事实+执行侧观测通道去向小节、spend_unified 定性改正与 M3 插花风险构造性消解(权衡节)、复合动作类合成建模义务(盘点节)、执行侧文件路径补全——各落点标注「对抗轮 3」。

## 背景

现行商店决策是**波批形态**:一次入口观察 → `decide_shop_wave` 一次性算出整波 `list[Action]` → 执行侧逐个执行、截断器在刷新/事务点截断重观察(`strategies/impl/mandate_v1/shop.py:497 decide_shop_wave`;截断语义 = `truncate_shop_frame_stable`,shop.py:248——BuyCard/LevelUpShop 可续,RefreshShop/CompTransaction 截断)。

波批形态的固有成本:**循环内每发一个动作,决策器算的不是「当前真态」而是「帧首快照 + 逐动作累积投影」**。投影口径出过一族 bug(ADR-0516 对抗修复批的**三修正/装配口径族**——金位买后投影/Σ卡费 (k−j) 粒度/cap 三源,见 §消灭的 bug 类),且修法都是「把投影再抠准一点」——只要波批结构在,每加一种动作就要多维护一条投影规则,投影 bug 类有存在空间。

用户 2026-09-04 口述新架构:把波批改为**单动作循环**——策略器每次只返回一个动作,动作执行后更新期望态,再问策略器要下一个;期望态更新对买/卖/升级是纯计算,零读屏。该结构让「波内口径记账」整族问题失去存在载体。

## 决策(用户口述九条,原样收录)

1. **画面 op 统一规范**(用户裁定 2026-09-04 口述):一次画面 op 调用 = 一轮「观察+决策」;入口做一次真实观察生成期望态,此后循环内不再读屏。
2. **决策循环**(用户裁定 2026-09-04 口述):循环调用策略器,每次返回**一个**动作 op;动作只做画面内合法性判定(合法即执行)并更新期望态。
   - 和解注(对抗轮 4 补,决策 2 × 决策 9):决策 2 的「合法性判定」**全部内化于策略器**(策略器以期望态为据只提合法动作,画面内合法性=策略器的提议约束);执行侧按决策 9 只余守卫断言(点击目标存在性等 op 框架既有的重试/等待语义属动作 op 的执行实现层,非决策合法性的第二道门)。两裁定的分工:合法性=提议侧约束,守卫=执行侧护栏。
3. **动作粒度**(用户裁定 2026-09-04 口述;2026-09-06 补裁):买一张 = 一个 op、卖一张 = 一个 op、升一级 = 一个 op、刷新 = 一个 op。
   - 补裁(玩家 2026-09-06 确认,方案 A):游戏机制满栏例外(merge_mechanics §2.5:板凳满时点合成槽位,一次点击自动多买至 3 的倍数张,每张原价)下,**一击多张 = 一个动作 op**——动作单位 = 点击,张数由游戏规则定,投影按实际张数计;普通买维持一击一张。
4. **终结 op**(用户裁定 2026-09-04 口述):每画面自定义终结动作集(商店 = 刷新、关闭等),执行即画面 op 结束、交回外循环;终结 op 是**一等动作**由策略器主动选择,不是循环逃生口。
5. **策略器 = 全函数**(用户裁定 2026-09-04 口述):f(期望态) → 动作,永不返回 None;「无动作可做」的表达 = 直接选终结 op(如关闭);动作空间无 no-op。
6. **不变量**(用户裁定 2026-09-04 口述):每个画面的动作空间至少含一个恒可用终结动作(全函数契约在所有画面成立的条件)。
7. **期望态投影**(用户裁定 2026-09-04 口述):买/卖/升 = 确定性纯计算(金/板凳/持有副本/等级),零读屏;刷新是唯一引入新事实的动作且它本身是终结 op(终结后外循环重观察 = 新牌面的天然输入点)。
   - 边界注(对抗轮 1 裁决补充,非口述原文;对抗轮 2 扩充):**合成(升星合并)落点规则并入投影纯计算**——合成是确定性机制,落点规则已有权威档(`docs/game/currency_war/research/merge_mechanics.md`:场上吸收/备战最左/连锁),按期望态纯计算投影的架构本意应进投影;规则模型误差由入口对账(决策 8)天然兜底。**粒度补全(对抗轮 3 裁决 scope 限定)**:§2.5 规则的适用域显式限定 = **满栏例外语境**(merge_mechanics §2.5 节标题即「备战栏满时的购买(满栏例外)」)——满栏例外语境下合成槽位买 = **一次点击自动多买**(min(店内同名, 3−已有 mod3) 张,原价);**非满栏常态时合成槽位买的一击张数 research 无记载**(merge_mechanics 通篇未载,禁从满栏例外外推)。「一个动作 op」在此画面语义 = **一次点击**,其投影按 §2.5 规则计算实际买入张数与金账(与决策 3「买一张=一个动作」不冲突:该条辖普通买的常规一击一张;满栏例外下合成槽位的一击多张是游戏规则,动作单位仍是点击)。**验证前置**:合成规则完备性(连锁/多路触发/边界,含满栏例外 §2.5 自动多买、该档自认的低置信项「栏满时商店语境合成落点」,及**非满栏常态合成槽位买的一击张数 = research 知识缺口**)须在 flow 实施批补档验证(先补 `docs/game/currency_war/research/merge_mechanics.md` 知识档,再以测试形式验证);**验证未过则 fallback = 合成触发买升格为终结 op**(重观察,新事实由终结后外循环入口重建)。
8. **期望态信任域**(用户裁定 2026-09-04 口述):本画面 op 生命周期;每次入口观察 = 事实重建,分叉天然归零(**入口观察本身就是对账**——非额外防线);识别质量归识别层既有遥测,不归决策循环;循环内无失败处理分支(动作 = 机械执行无判断,「动作无效」只可能源于入口误读,循环内不可检测也不需处理)。
   - 口述附注(2026-09-04 同场机制裁定,原样收录):商店槽位在刷新前静态(单人肉鸽),「牌被买走」不存在——期望态投影的前提之一;从多人游戏带入的直觉已被否。
9. **执行侧合法性检查退化为守卫断言**(用户裁定 2026-09-04 口述):策略器内部保证只提合法动作;执行侧检查 = 防 bug 路栏非控制流分支,非法返回 = 策略器 bug 响亮暴露。
10. **期望态更新在动作 op 里触发**(用户裁定 2026-09-06 确认;口述原文主语即动作 op):每个动作 op 自带其确定性投影——动作基类两方法 `execute(ctx)`(机械执行)+ `project(expected_state)`(纯计算更新:金/板凳/持有副本/等级/合成连锁);画面 op 只持有期望态状态对象与决策循环,不认识具体动作语义;策略器只读期望态。内聚理由:投影语义跟着动作定义走,新增动作类型零改画面层;投影函数可独立单测。投影=纯计算非判断,不违「动作无判断」。

## 与现行架构的映射(本文推导)

- **外循环** = 现行 `strategies/impl/flow.py`(CwFlowStrategy:生命周期/意向/备战主流程栈)+ `operations/cw_screen/` 各画面 op 的节点流转。新架构不改外循环形态,只改**画面 op 内部**从「一次算整波」为「循环问一次」。
- **画面 op 替换 decide_shop_wave 的波批形态**:商店侧 = `shop.py:497 decide_shop_wave` 返回 `list[Action]` 改为单动作接口(下述选择序不变,取逐帧最优首项);执行侧 `operations/cw_op/cw_op_buy_cards.py`(对抗轮 3 补全路径:在 cw_op/,不在 cw_screen/)的 `run_buy_waves` 波循环改为单动作循环;截断器 `truncate_shop_frame_stable`(shop.py:248)随之退役——截断点语义被终结 op 吸收(RefreshShop 本来就是截断点,shop.py:362)。
- **判据层(criteria/statefn 数学)零改动**:所有判据函数签名已经是「输入态 → 布尔/值」的纯函数形态(criteria/refresh、crit_levelup、crit_buy 等),单动作循环只是把「一次调用判 N 次」改为「N 次调用各判一次」,判据本体不动。
- **与 P52 的结构对齐(对抗轮 1 裁决改写;轮 2 降格措辞)**:单动作循环与 π_greedy **结构同型**——判据层零改动、逐动作贪心与 P52 的逐期贪心在「每期取判据集最优首项」的形态上一致(math_proofs P52,`docs/develop/currency_war/proofs/math_proofs.md` L62,单篇 `proofs/p52-greedy-epsilon-optimality.md`:安全域 D_ε 上 V(π*)−V(π_greedy) ≤ ε;单窗 ε_w 点估计 6.2/10.8/15.9 金(boss/encounter/battle),CI 上界 16.4/20.6/21.7——本文初稿写「6-22 金」系点估计与 CI 上界混读,已改正)。**申报边界(轮 2)**:P52 的「期」= 备战期(节点间),π_greedy 定义在期级,对画面内执行粒度沉默——本文不做「P52 背书单动作循环」的强声称,只主张结构同型与判据零改动。**与波批的输出等价是条件命题**,不是无条件结论:前提 = 波批投影无残差;而本文 §消灭的 bug 类自列的投影修法史(症3 卖出回金小账/R197 症9 支出后投影金/ADR-0516 装配口径族)证明投影残差是历史常态——前提不成立时两结构输出有真差异。由此推论:**迁移步 3 的帧级锁不预期保持绿**——锁红可能是真语义差(波批投影残差被单动作循环的真值更新消除),按「锁的存在性纪律」逐个重推语义,禁机械跟绿。
- **策略器单动作选择序 = 既有优先级**:按期望态逐帧取最优,序不变(shop.py ③/④ 段现序):M4 腾席 → M2 线成员(含 M2b 合并完成)→ dominance → M3 升级 → M6 溢余 → EV 买面 → R1 付费刷新 → 终结(关店)。R1 刷新按定义 4 是终结 op,发射粒度「每波至多 1 次刷新」(shop.py:875)在新结构下自然成立——刷新即本画面 op 结束。

## 消灭的 bug 类(本文推导)

波内口径记账族——**在新结构无存在空间**(期望态由动作纯计算直接更新,不存在「帧首快照 + 累积投影」的第二套账):

- **金位买后投影**:波批下 R1 门金基准必须用「买后投影金」而非帧首 `state.gold`(shop.py:889 注释:「用帧首金会高估预算」;R197 症9 同族,dominance/M6 金口径 = 支出后投影金)。单动作循环下每步金就是真值,无口径可言。
- **席位静态投影**:波批下 bench_free 是帧首快照逐动作加减;卖出回金入投影是后补的小账(shop.py:973「症3 小账:卖出回金入投影,后续买面金投影不再保守偏低」)。新结构下席位随动作更新,同族问题不存在。
- **Σ活期退金投影的帧级让渡**:liquid_refund 以帧首快照计、M4 卖出的活期件「即时从投影扣减」是专门修的非保守向偏差(shop.py:636-639)。新结构无快照,无此修。
- **j/c_taken 低估申报**:ADR-0516 轮 1 修复的装配口径「Σ卡费 = 每成员 (k−j)×cost(完成路径真实卡费)」族——波内已买副本数 j 靠发射列表回读,拆装两处;单动作循环下持有副本就是期望态字段,读一处。
- **同槽去重防线**(sold_idxs/ev_conflict_dropped,shop.py:609-614):波批下多发射位共享同一 bench 快照才会对同槽双 SellBench;单动作循环下第一笔卖出后期望态已更新,第二笔提案自然不指向已卖槽。

## 读屏成本分析(本文推导)

- **读屏点只剩两个**:画面 op 入口(期望态生成)与终结后交回外循环(外循环的下一次入口观察)。刷新 = 终结 op 的语义自洽性:**刷新是唯一引入新事实的动作**(新牌面),而期望态必须在新事实处重建——终结后外循环重观察正好落在这个点上,不需要为刷新设计任何循环内重读机制(现行截断器的「刷后重观察」语义被结构吸收,shop.py:273)。
- **节奏对拍(对抗轮 3 裁决改事实;轮 4 条件化)**:刷新帧的读屏次数与波批相同(波批:入口 1 次 + 每次截断重观察 1 次;单动作:入口 1 次 + 刷新终结后下轮入口 1 次)。初稿「买卖升级零读屏,与波批持平」所据事实有误:波批执行侧**本就逐动作读屏**(`operations/cw_op/cw_op_buy_cards.py` 卖出每笔两次 read_gold——L1022 拖前基数 / L1054 入账后实收;刷新后牌面+金重读 L882/L929——刷新有效性检测与免费刷新证据通道,见 §执行侧观测通道去向)。**改善面按条件式表述(轮 4)**:确定成立的改善 = **决策通道与读屏解耦**(决策只依赖期望态,识别抖动不进决策;波批整波重算的决策成本消失);物理读屏量则取决于 §执行侧观测通道的处置——三通道若全走候选 (a)(保留为逐动作执行遥测)则读数量与波批持平,若走候选 (b)(移至入口对账)则为严格净减。

### 复合动作类(对抗轮 1 裁决补充)

整档组合替换保留为**一个宏动作 op**(「换一档 = 一个动作」)——与粒度裁定 3(「买一张 = 一个动作」)不冲突:那条辖的是**普通买的粒度**,复合动作是另一类。复合动作类定义(三要素):

1. **一个 op**:CompTransaction 整体作为一个动作进入单动作循环,策略器一次提案、执行侧一次执行,不按子步(deploy/undeploy/sell/fill)拆为多个 op;
2. **原子投影**:期望态更新 = 全部子步一起纯计算,直接产出终态,不存在子步间的中间期望态;
3. **C1 前置合法性**:任一子步资源不足(金/槽)⇒ **整体不合法,不提案**——与契约 C1 的整批拒绝语义逐字对齐(`kernel/cw_state.py:696-714`:「任一子步资源不足(金/槽)则整个事务拒绝,不产生半档中间态」)。
4. **合成建模义务(对抗轮 3 裁决补充)**:CompTransaction 的 `fill` 路径含商店填位买入(`kernel/cw_state.py:713` 金校验含 card_cost:卖出收入 − shop 填位费用后 gold ≥ 0),该买入可触发合成与 §2.5 满栏例外规则——宏动作的**原子投影必须内含合成连锁 + §2.5 规则**(fill 买面的期望态更新与决策 7 边界注同源,CompTransaction 不是纯换位事务)。**fallback 定义**:合成建模验证未过时,CompTransaction 执行后保持现行「截断重观察」语义(`shop.py:273`:RefreshShop/CompTransaction = 截断点,事务后重观察重决策)——即宏动作**终结邻接**:执行后本画面 op 结束、交回外循环重观察,禁半档中间态(与 C1 一致)。

### 执行侧观测通道去向(对抗轮 3 裁决补充)

迁移到单动作循环时,波批执行侧的三个逐动作观测通道(读屏类)**禁静默删除**,逐一列处置候选,最终归属 flow 实施批裁:

| 通道 | 现况锚点(行号直调) | 处置候选 |
|---|---|---|
| 卖回金实收遥测 | `operations/cw_op/cw_op_buy_cards.py` L1022(拖前基数)/ L1054(入账后实收),`record_sell_income` 落盘 | (a) 归属 = 动作 op 执行实现层,保留为执行遥测(非决策输入);(b) 移至入口对账(下一画面入口观察对差) |
| 刷新有效性检测 | 同文件 L882(刷后 `read_shop_cards` 重读,与刷前名集比对出 `refresh_effective` 三值) | 同上二候选;刷新在新结构 = 终结 op,检测天然落在终结后重观察语境,与候选 (b) 近邻 |
| 免费刷新证据 | 同文件 L929(刷后 `read_gold`,ADR-0456 判定语义的组成部分) | 同上二候选 |

归属判据:三通道均为**观测/遥测职责**,不是决策读屏——与决策 1/8「循环内不读屏」**不冲突**(那条辖决策读屏:期望态生成与更新不得依赖读屏;执行实现层的留证读屏是另一回事)。

## 迁移路径(本文推导)

1. **装配层重写**:`shop.py` `decide_shop_wave` 波语义 → 单动作接口(`decide_shop_action(state) -> Action`,含终结动作);`operations/cw_op/cw_op_buy_cards.py` `run_buy_waves` 波循环 → 单动作循环;`truncate_shop_frame_stable` 退役(截断点语义归终结 op);`contracts.ensure_contract` 契约核验改挂在单动作决策入口(每动作核一次,频次升高但纯 dict 计数,成本可忽略)。
2. **契约/承诺账波内计数改逐动作**:`session.cw4_counters`、拒因遥测(`shop_unbought_reasons` shop.py:1048)、R1 波粒度申报等,计数键语义从「每波一次」改「每动作一次」;sim 侧 `engine_p1.py:917` 的「与生产 decide_shop_wave 同语义」快照锚同步重写。
3. **测试重锚面**:商店域全部波级锁(序列断言)改单动作锁(逐帧断言);`test_cw_vgap_frame_horizon`/`test_cw_zero_refresh_fix` 等帧级锁**不预期保持绿**(见 §与现行架构的映射·P52 条:与波批的输出等价是条件命题,波批投影残差是历史常态)——锁红可能是真语义差,按「锁的存在性纪律」逐个重推锁语义,禁机械跟绿。
4. **02/flow 文档集成**:`strategy-docs/11_shop_decisions.md`(商店决策)、`00_framework.md`(框架)按新循环语义重写;**标注 = 待本 ADR 收敛后另批**(本文档只定架构,不动 as-built 正文)。

## 权衡申报(本文推导)

- **节奏**:刷新帧读屏次数与波批相同(见 §读屏成本);买卖升级的改善面按条件式(见 §读屏成本·节奏对拍:决策通道解耦恒成立;物理读屏量取决于观测通道处置);代价是每动作一次策略器调用(纯函数判据,微秒级),远低于读屏成本。
- **M3「升级整批」原子性拆解(对抗轮 1 裁决改写;对抗轮 3 两处改正)**:现行 LevelUpShop 整批发射 `clicks` 个动作(shop.py:773-777),新结构按粒度 3 拆为逐次升级 op。**金侧无「发射后暴露」问题**:现行发射点已做整批可负担前置校验(`mandate.check_affordable(gold, 0, batch_cost=clicks*cost)`,shop.py:770-771),整批不可负担时旧结构同样不发射——「发射后执行侧才暴露金不足」的情景在现行代码不存在(初稿此句有误,删)。**spend_unified 定性改正(对抗轮 3)**:初稿称其「价值判据而非金校验」有误——`spend_unified` 就是**金校验**(criteria/levelup.py:51-59:clicks×cost ≤ gold 的整批可负担门,P48 整买纪律的放行判据),clicks 逐次化后金侧逐次判定仍逐次过(可负担面单调);「价值侧单调性未证」的申报随之失效。**M3 插花风险按粒度裁定 3 构造性消解(对抗轮 3)**:「升一级 = 一个动作 op」(决策 3,用户口述),clicks 序列是**动作内部步骤**而非多个动作——单动作循环的动作间边界在动作 op 外侧,外部买面在 clicks 之间**不可能**插花;散买 XP 形态(P48 拦截对象:买不够升级的零收益散买)在粒度裁定下无发生路径——一个动作 op 内部买齐到下一级。此消解是**粒度裁定的构造性保障**(结构上不可达),非等价论证(不依赖价值函数单调性推导)。
- **期望态信任域收窄的代价**:循环内不读屏 = 循环内无法发现入口误读(定义 8 的立场:这是识别层问题,归识别层遥测)。现行对账面(`cw_prep_expect` 的 compare_* 族、`cw_reconcile`)仍在入口观察处消费——入口观察本身就是对账,对账时机从「波内多处」收拢为「入口单点」,误读暴露延迟到下一画面入口,如实申报。

## 开放问题(本文推导,留 flow 实施批裁)

1. **无决策画面的规范边界**:遭遇/战斗等待/位面切换(盘点表「暂不适合」行)在统一规范推进到时,是建档为「空动作空间 + 恒可用终结」的形式画面,还是保持外循环直管——按成本裁。
2. **prep_phase 相位机的归属(对抗轮 1 深化)**:根本差异在**相位如何更新**——现行相位「出动作时前移、不读执行结果」(flow.py:795-798 docstring:「阶段位在出动作时前移(策略看不到执行结果)」),新架构期望态**由动作结果更新**;两者对「动作失败后相位是否回退」给出不同答案。候选处置:(a) 相位并入期望态作派生字段(动作结果驱动);(b) 显式化为画面子态(期望态外独立状态机)。判据 = **哪个不改判据层签名**(判据零改动是本 ADR 硬约束,处置不得迫使判据函数增加相位参数)。留 flow 实施批裁。
3. **补给画面刷新的终结语义**:补给刷新同样引入新事实(新装备面),按「刷新 = 唯一引入新事实的动作」原则应为终结 op,但补给刷新是否消耗资源/是否可循环,待建档核实后定。
4. **contract ctx 字段的逐动作取值语义(对抗轮 1 补)**:契约核验 `contracts.ensure_contract` 的 `ContractCtx`(gold/bench 等字段)在单动作循环下**逐动作取值**,其语义须显式定义——两粒度(波批帧首一次 vs 单动作逐次)下同一字段在前提判定中取到**不同值**(gold = 帧首快照 vs 动作后真值),这是契约核验频次变化之外的**语义面**,不定义则契约遥测在新旧结构间不可比。定义落点 = 迁移步 1(契约核验挂单动作决策入口时同步声明)。

## 备选(Considered Options)

- **保留波批 + 继续修投影口径**——被否:每新增动作族都要新增投影规则,投影口径族 bug 有再生土壤(用户口述九条即对此结构的否定)。
- **单动作循环 + 循环内轻量重读**(如每次动作后读金)——被否:违背定义 1/8(循环内不读屏),且重读引入识别抖动进决策循环,把识别质量问题搬进决策层。
- **策略器允许返回 None + 外层兜底关店**——被否:违背定义 5(全函数);None 通道会把「策略器漏 case」静默降级为关店,守卫断言(定义 9)失去暴露面。

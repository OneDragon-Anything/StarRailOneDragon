# 货币战争战力模型设计(sim 战斗结算层专用)

> 性质:**设计件(需求定义,未实施)**——落地后按 as-built 改写(判据规格化先例=同需求定义形态的 strategy-docs/10 §2.1 工具使用判据)。
> 裁定(原裁定档已退役):唯一消费者=sim 战斗结算层。
> 读者 = 脱离任何会话的开发/策略 agent。数值一律不落本文,单一源将来在代码注册表/校准表。

## 1. 定位与铁律

**战力模型 = 一个函数:输入「我方板面快照 + 战斗上下文」(全部精确可数的结构特征),输出「这场战斗的预测胜率 P(win)」。** 它只做一件事:让 sim 的战斗结算对板面结构与敌方上下文敏感。

三条铁律(违反任何一条 = 设计违规,对抗审查与测试都按此查):

| # | 铁律 | 内容 |
|---|---|---|
| 1 | 唯一消费者 = sim 战斗结算层 | 模型只接进战斗结算的 **sim 消费路径**(§6.1,注入契约 §6.2);任何策略模块(decision_v2 / ev / scoring / arbiter / intention / economy 等)禁止 import、禁止读它的遥测回显做决策 |
| 2 | 训练真值唯一来源 = 实机战斗语料 | sim 永不进训练集(§2 B0 循环 + §8.1 具名文件白名单守卫);模型每次迭代必须回实机对拍 |
| 3 | HP 出局 | 不作训练目标、不作特征、不作校验主量;二值胜负是唯一标签(HP Δ 只许作辅助校验量,如胜局余量分布) |

**决策层为什么不需要它**(认识论前提,裁定链):买/卖/升星/部署/装备/刷新/换线七个决策点已全部由「期望数学(经济常数+池概率)+ 结构计数 + 知识先验」解决。决策侧允许消费的是**实机真值统计**(如成型度×胜率阶梯这类已发生事实的分布,docs/develop/sr_od/application/currency_war/proofs/p03);禁止的是**模型拟合外推**。两层用「统计 vs 预测」这条线切开。

## 2. 为什么必须建(现状的结构性缺陷)

现 sim 战斗结算的胜负面有**四条路径**(符号见 `kernel/cw_battle_calib.py` / `kernel/cw_coarse_battle.py` / `sim/engine_p1.py`):

| 路径 | 胜负面来源 | 板面敏感度 | 默认可达性 |
|---|---|---|---|
| **粗模型主路径**(`sample_battle_delta` → `injected_win_p`) | 节点×位面×rung 查表(遥测平滑 + plaza Beta 收缩) | rung 四档(0-3,`_settle_rung` 板面派生键) | **默认主路径**(`BATTLE_ENGINE_MODE='coarse'`) |
| Δ池(`live_delta_for` 族) | 实机经验 HP 分布重放 | 桶键粒度(rung / 净星深 / 板深) | 仅 `delta` 对照臂的战斗类 + **两模式下**的 reward/supply |
| P2 参数层(`p2_combat_delta` → `p2_win_p`) | clip(p0 + β·form − γ·drift),form = 引擎数+等级折算+净星深 | 3 个聚合键 | P2 calibrated 臂 |
| 兜底阶梯(`node_win_p`) | 节点×轮次边际(旧语料) | 零 | **默认不可达**(engine_p1 注释明言「本路径不再消费」;仅对照臂池缺兜底语义保留) |

**B0 循环(本设计的第一决策依据)**:默认主路径的胜负面只吃 rung 四档、P2 参数层只吃 3 个聚合键——在现 sim 上采样训练「板面→胜率」模型,模型只能学回这几个聚合键的系数(rung 恰是 `_WIN_TABLE` 的表键),等于给现有查表换数学外衣,不产生新信息。故:**sim 不作训练源,只作消费端;训练真值只能来自实机语料。**

**v1 模型相对现结算层的增量(诚实口径)**:净星深连续化、上场−人口差、rung 以 4 档 one-hot 保留(基线唯一板面键的非单调形状不被单调先验压平,见 §4.3/§5.3)、敌方难度上下文(经 §6.7 生成器供给)。组 A/B/C 其余特征面(含敌 boss 身份)按 §4.3 冻结,随语料与映射覆盖放开。

**实机语料已存在且结构完整**:telemetry decisions 行已落 `state.deployed`(逐件 char_id/star)、`state.board_factions`、`level`、`gold`、`enemy_difficulty`、`enemy_affixes`、`plane`、`round_num`、`state.node_type`(注意:node_type 在 `state` 子键,实测 556 行缺省 None);胜负标签在 outcomes 行(§5.1)。

## 3. 建模目标

| 项 | 裁定 | 理由 |
|---|---|---|
| 预测对象 | **单场战斗胜负 P(win)**,二值 | 标签噪声低、可校准验证;HP 量高噪禁用(铁律 3) |
| 粒度 | 单场:我方板面快照 × 上下文 → 一次伯努利 | 与结算粒度对齐 |
| 上下文 | node_type / plane / round 序位 / enemy_difficulty / 敌 boss 身份;**词缀推迟到特征开放层**(§4.3) | 敌方可观测面按 §4.3 预算分批收编(边界见 §7-2) |
| 不预测 | HP 伤害量、余量、存活单位数 | 全部高噪;未来需要时独立二开,不混入本模型 |

## 4. 特征集(硬门:全部精确可数,无 HP)

### 4.1 特征全集(按组登记;首期实装面以 §4.3 分配表为准)

- **组 A 单位构成**:各费用档单位数(1-5 费分列);各星级单位数(1★/2★/3★ 分列);净星深 Σ(star−1)(= `deployed_star_depth` 单一源口径);上场数 − 人口等级。**空槽过滤**:`char_id` 为空的槽位条目(实测占 deployed 条目约 7.8%,槽位表)不计入任何单位计数。
- **组 B 羁绊激活态**:board 全集口径计数(`_recount_board` 单一源,含星徽贡献);**rung**(`_settle_rung` 单一源,四体系达成数——基线胜负面唯一板面键,首期以 4 档 one-hot 保留,见 §4.3);逐体系「已达成 one-hot + 连续计数」;逐羁绊有效档位。
- **组 C 核心与装备**:意向核心在场数/星级;装备逐件 one-hot + 「分配到核心/非核心」二元计数。
- **组 D 站位**(登记不实装):前后排粗分。
- **上下文**:node_type one-hot;plane **二值**(P1 vs 非P1;语料 plane=3 仅 8 行,并入非P1 低置信披露——3 值 one-hot 的第三位在 8 行上不可辨识,消费端 sim 亦不产生 P3);round 序位;enemy_difficulty(**缺失口径 = None ∨ 合理带 [20,300] 外**,复用 `cw_state` 既定约定;实测按此口径缺失 ≈10%——缺失指示进 §4.3 分配表;数值覆盖率 ≈90%);**敌 boss 身份 = `plane_bosses[plane−1]`**(decisions 侧 `state.plane_bosses` 与 sim 侧 `GameState.current_boss` 同式派生;**越界/None 元素 = 缺失标记**——None 元素率实测口径敏感(元素级/行级/键末帧各异,轮次间测量不一致),抽取批钉单一口径后回写;「保位勿滤」是现实质量不是理论风险)——**本特征 v1 冻结**(§4.3 冻结清单:one-hot 档位数超首期预算),规则先行登记供开放时直接用;**词缀**:经 `AFFIX_MECHANIC_MAP` 映射的机制 tag 聚合——**映射口径钉死**:生效表随 registry 开关漂移(生产默认关 = 23 种/34.3% 事件质量),抽取器在产物头部落**映射版本指纹**;本层推迟开放(§4.3/§7)。

bench(备战席)不进特征:结算只看上场;备战席的影响经部署动作传导,不直接进结算。

### 4.2 双侧同源

同一特征函数吃 sim 的 GameState 与实机 decisions 行(先例:`deployed_star_depth` / `_star_depth_from_rows` 同式对;boss 身份的 `plane_bosses[plane−1]` 与 `GameState.current_boss` 同式)。实现必须带双侧对齐测试(同输入 → 同特征向量)。

### 4.3 参数预算与首期实装面(小样本硬门,含测法/分配/冻结清单)

- **口径**:有效参数数 ≤ **少数类事件数/10,向下取整**(logistic 回归经验法则按稀有类计)。设计时语料快照:战斗类结局 886 行、有标签 ≈730、胜事件(少数类)≈128 → **首期有效参数 ≤12**。数字是快照参考,**抽取批按 §5.1 canonical 口径重钉实数**,预算随之滚动。
- **「有效参数数」的测法**(惩罚拟合下不是自由参数个数):**df = tr(Ĥ)**(帽矩阵迹),或「未惩罚系数计数 + 收缩后偏离当量」;验收按此口径执行。
- **首期实装分配表(12/12,满预算)**:

  | 块 | 参数 | 计数 | 备注 |
  |---|---|---|---|
  | 截距 | 1 | 1 | |
  | 净星深 / 上场−人口差 / 难度 / round 序位 | 各 1 | 4 | 连续量 |
  | **难度缺失指示** | 1 | 1 | 缺失 = None ∨ [20,300] 外;实测 ≈10% 行命中 |
  | **rung one-hot(4 档)** | 3 | 3 | **不加单调先验**——基线经验值沿 rung 非单调(battle 0.356→0.306→0.273),单系数+非负约束会压平该形状构成净降维;one-hot 保住非单调形状。**已知错定风险(如实声明)**:加性结构无法表示跨节点反向的 rung 梯度(实测 _WIN_TABLE:battle rung1→3 = −0.083、encounter +0.224、boss +0.173——符号相反,需要 node×rung 交互才能表示,超预算不做)——该风险由影子期的**非劣性门**(§5.3)拦截:加性近似若在任一节点类上系统性劣于现任查表,不接线 |
  | node_type one-hot(3 类) | 2 | 2 | |
  | plane 二值(P1 vs 非P1) | 1 | 1 | plane=3 并入非P1(个位数样本不可辨识,低置信披露;实数抽取批钉) |
  | **合计** | | **12** | |

- **首期冻结的特征组(全部收缩为零自由度,不在 v1 模型内)**——**触发线累计语义:任一次放开的判据 = 少数类事件 ≥ 10×(12 + 放开后累计参数总数),逐次评估;下表单组线为单独放开的示例,并列放开按合并总数计**(如组 A+组 B 同开 → 22 参 → 需 ≥220,而非各自线):
  | 冻结组 | 内容 | 单独放开示例线 |
  |---|---|---|
  | 组 A 分列计数(+6 参) | 费用档分列、星级分列(仅净星深实装) | 少数类事件 ≥180(18 参) |
  | 组 B 体系分列(+4 参) | 体系 one-hot/偏离/连续计数(rung one-hot 已实装) | 少数类事件 ≥160(16 参) |
  | 组 C 核心/装备 | 核心在场、装备逐件 | 少数类 ≥ 10×(12+组C参数数),组C参数数按开放时注册表逐角色/装备 one-hot 清点;现写 ≥1000 为按当前注册表规模的示例线 |
  | **敌 boss 身份**(one-hot,档位≈各位置出现过的 boss 名单) | `plane_bosses[plane−1]` 派生(§4.1 规则已登记) | ≥ 10×(12+档位数),按开放时实际档位重算 |
  | 词缀层 | 机制 tag 聚合组 + 未映射项 | **映射事件覆盖率 ≥80%(生产默认口径 34.3%)∧ 少数类事件 ≥ 10×(12+tag 组数)**;「未识别桶」单参数删除(当前语料 100% 带词缀帧含未映射项,恒 1 与截距共线) |
- **排除**(永不入模):任何 HP/血量类;对手板面逐件(不可得,§7-2);历史战斗过程量。

## 5. 训练与验证

### 5.1 数据集与行对齐口径(canonical spec)

- 训练集 = 实机战斗语料;每行 = 一场战斗:§4 特征 + 二值标签。
- **行对齐口径**(以 outcomes 为**权威驱动侧**,与代码侧既定对拍口径同键,`obs/cw_settlement_obs.py` 的 (run_id, plane, round_num)):
  1. **join 键 = `(run_id, plane, round_num)`**——round_num 按位面重置,两段键会跨位面撞(实测 886 行战斗结局只覆盖 772 个两段键;同键跨位面混叠会把 P1 战斗喂 P2 板面,系统性错分)。
  2. **node_type 词表映射**:outcomes 混用中文与 ASCII(普通战斗/遭遇为中文,**boss 恒为 ASCII `'boss'`**),decisions `state.node_type` 用英文——映射常量单一源落代码(中文→英文 + ASCII 恒等)。**战斗类的判定以 outcomes 为准**;帧的 node_type 不一致不构成丢弃条件(见 ③)。
  3. **快照 = 该键的最后一次 decisions 帧,不问帧的 node_type**——实测 830 键中:~16 键末帧 `node_type=None`(旧行缺字段)、2 键末帧为 supply/reward(**持卡改节点局**——策略效果把战斗轮改成了补给/奖励,这正是不能按帧类型过滤的原因:丢了它 = 丢掉恰好最会改节点的局,选择偏差)、~16 键 outcome 与帧类型不一致(以 outcome 为准)。**仅当该键无任何 decisions 帧(实测 13 键)才丢弃 + 计数披露。**(小数字随语料增长漂移,抽取批重钉后回写本节。)
  4. **outcomes 同键去重(带残余;带标签优先)**:三元键仍有少量重复(实测 56 键,形态 = 41 键两行皆带标签 + 15 键早行带标签/晚行 None,零反例)——规则:①剔除 `recovered` 行(schema 注释明言「训练侧可剔」);②**带标签行优先**(存在 killed≠None 的行时只在其中选——晚行 None 会系统性覆盖早行标签、且丢的偏向负局,「ts 最新」不作首选);③带标签行内按 source 档次:`''` 与 source 缺失(旧 schema 真值) > `loss_page`(败页回填) > 其余回填族;④同档并行取 `ts` 最新;⑤全行 None 才丢键。**降级自然吸收**:优先档行 None 而低档行有标签 → 低档标签行胜出(实测挽回 15 键,计数披露)。
  5. **标签 = outcomes `killed` 字段**(True=胜/敌方被击杀,False=负,None=缺标签且全来源链均 None 才丢弃)。
- **语料卫生(坏数据局排除)**:复用 Δ池生成器的既有排除清单 **`QUARANTINED_RUNS`**(`sim/cw_delta_pool_gen.py:97/226/243` 先例——事故局已被池生成物理排除,训练抽取若不排除同一批 = 吸入已被判定坏数据的局;当前清单内两 run 的行数已归零,规则为**未来事故局的常驻守卫**,非空操作即生效);**策略版本过滤口径钉死**(按 runs 行策略标识分层,口径常量落代码——沿池生成器「跨策略版本混杂」的同类处理)。
- **丢弃计数按 source × 位面分桶披露**,对照抽取批重钉的基线判异常;**引用数字钉分母与口径**:**canonical 口径 = §5.1 规则在语料上执行的输出**(实测:830 键 / killed=None 141 键(17.0%) / 有标签 689 键 / 带标签优先挽回 15 键 / 胜事件 128);raw 行口径(730 有标签/17.6% 缺失)为参考口径,文中引用一律标明所用口径。**语料是活文件**:设计期数字为快照(当前盘 source 分布 ''=622/缺源=153/loss_page=107/recovered=4),规则对行形态漂移稳健,数字以抽取批当期重钉为准。**敏感性检查(缺失非随机的风险)**:`killed=None` 缺失率按 source 显著分层(真值行 ≈20%、loss_page 行 0%、recovered 行 75%)——且 loss_page 回填机制说明缺真值与败局路径相关;抽取批须产出「丢弃率按 source/位面对比」的敏感性表,MNAR 方向入 §7 风险声明。
- **分布偏差与策略版本口径(如实声明)**:现存语料是旧策略病局镜像。**runs.jsonl 的策略字段存在但全空**(schema 有 `strategies_held`,当前 0 行填充;code_commit 仅 ≈5/227 稀疏)——「按策略版本分层」当前**不可执行**;v1 以「结构性特征系数可跨版本迁移」为**显式假设**在混合语料上训练并在验证中检验,不达标就等语料,不硬上。**激活条件已预定**:`strategies_held` 开始被填充(或 code_commit 覆盖率可用)时,抽取器按 runs 行分层并重验——届时 `runs.jsonl` 进入抽取白名单的**预定扩位**(§8-1,版本化修订而非开洞)。
- **语料增长受活动窗口约束**:活动停 = 语料冻结;模型按**语料里程碑**重训(如 ×2 增量),不以日历驱动。
- sim 不进训练集(铁律 2;工程落点 = §8.1 具名文件白名单守卫 + **抽取产物头部落源指纹断言**:输入两文件的行数哈希 + 词缀映射版本指纹,防「同目录旁路文件/映射漂移」两类静默污染)。

### 5.2 模型形态

- **带层级收缩的 logistic 回归**:可解释、系数可审计、小样本稳;系数语义直接对齐结构计数概念(星深边际/rung 档位/难度惩罚)。**「系数可审计/与 math_proofs 互检」限定为模型开发侧的离线单向活动**(给人看、给审计用)——不是决策侧的消费授权;决策侧引用系数 = §6.2-4 第四禁止形态。**v1 = 平面 12 未惩罚参数**(无层级结构——冻结组全收缩为零自由度,无可收缩对象);层级结构(共享系数+偏离)自放开首个冻结组起启用。
- 不选深度模型/GBDT:n 量级不支持;sim 只需要快(§6.4)与可解释。

### 5.3 校准验证

- **校准曲线**(分桶预测胜率 vs 实际胜率)+ ECE + Brier 分数。**校准只在实机语料上测**(LOCO)——sim 无真值标签,任何「sim 上的校准」表述都不成立(§7-1 边界的直接推论)。
- **分割 = 留一局交叉验证(LOCO)**:按局留出(canonical 有标签键覆盖 ≈140 run;raw 行分母 145——分母钉口径),防同局多场战斗的相关性泄漏;语料过千改「按局分层留出集」。
- **符号约束 = 拟合期性质,不是影子门判据**(约束域内拟合的「无违例」是同义反复,不构成验收):净星深 ≥ 0、难度系数 ≤ 0,拟合按系数域约束实现;**rung one-hot 不受符号约束**(基线经验非单调,one-hot 无单调先验——这正是弃单系数的原因);**构建时**附合成输入 sanity 检查(单特征 +1、其余不变 → 方向正确)作为管线体检项(非门);复合扰动语义 = 披露项。开放后的逐体系偏离同 rung 处理(不受符号约束,只披露)。
- **影子期验收门**(§6.3)= **双判据:① 非劣性 + ② LOCO 校准**:
  - **① 非劣性门**:LOCO log-loss 与 Brier 上,模型**不得劣于现任 `injected_win_p` 查表**(把查表当固定预测器,同折同口径对比)——§6.1 是无回退全域接管,接管者必须先证明不比被接管者差;加性近似在跨节点反向 rung 梯度上的错定风险(§4.3)由这道门拦截,且**分节点类披露**(battle/encounter/boss 各自的 LOCO 指标,防总量达标掩盖单类系统性回退)。**保守偏差披露**:现任查表拟合自冻结语料(≈417 战斗行),与 LOCO 评估语料重叠——现任带「主场优势」,本门对挑战者偏严;方向可接受(接管门槛宁严勿松),如实声明。**门失败的预定后路**(不是死局):v1 不接线、维持现任;下一步按预定参数重排(弃弱识别的难度/缺失指示/plane,换 node×rung 局部交互)后重走本门——**重走时换折或预登记重试上限**(同折多次重试构成多重比较,门会假性变松);**元级泄漏披露**:rung one-hot 的特征面设计本身消费了现任查表对重叠语料的拟合(rung 非单调形状来自它)——方向保守(门更严),如实声明;
  - **② LOCO 校准**:只辖样本量 ≥ 下限的桶(最小桶容量常量落代码;胜率 ≈17%(raw 行口径)的类不平衡下上半桶近空,空桶分位带极宽、判了等于没判——先例:`check_p2_win_rate_band` 的最小判据行数),不足下限的桶仅披露;阈值按二项重复抽样的分位带定。
  **已知覆盖缺口声明**:该门只在实机语料分布上有判据,sim 后期成型板可能落入训练分布外的高位段——影子披露补一张非门对照表(§6.3),使外推段至少可见。不过门不接线。

## 6. sim 接入设计

### 6.1 接线点(只换胜负面的掷定,幅度层不动)

| 现路径 | 处置 |
|---|---|
| **粗模型主路径**(`engine_p1` coarse 分支对 `sample_battle_delta` 的调用点) | **替换为模型,全域接管**:logistic 对其特征域恒可算,不设「覆盖不足回退」分支(不定义触发谓词的回退 = 死代码或任意解释的活代码,且会使检查器消费的胜率分布变成双机制混合、锚重记失去稳定基准) |
| **delta 对照臂的桶缺回退**(`engine_p1` 对 `sample_battle_delta` 的第二调用点,改接处) | **保持 `injected_win_p` 不换**——对照臂是基线载体,基线必须模型无关。**解冻现状**:Δ池快照再生已解冻(`_DELTA_POOL_FROZEN=False`;解冻与再生成经编排者裁决守卫,见 `cw_delta_pool_gen`),对照臂随池内容治理/再生演进(现行治理),不再是时点冻结基线——模型与对照臂的分歧解释须注明所比对的池版本(指纹见快照 META)。**退役判据(默认)**:模型转正后首次里程碑重训完成时,若对照臂分歧分布已无诊断消费方(检查器/分析脚本零引用),默认批配置移出该臂,落地 ADR 可覆写 |
| Δ池 | **不动**——对照臂(`delta` 模式)与 reward/supply 的既有路径 |
| P2 参数层(`p2_win_p`) | calibrated 臂同主路径**全域替换**(P2 侧表达由 plane 二值承载;P2 样本薄的低置信按 §5.3 披露,不设回退) |
| 兜底阶梯 | 默认不可达路径,不接线;supersede 见 §6.6。**死代码处置入落地 ADR**:替换后 engine 流中不可达的战斗分支(`node_delta` 战斗支/`boss_settle_delta`/`battle_delta`)声明「保留为对照语义」或「删除」,不滞留第二套胜负面 |

**注入物形态**:`sample_battle_delta` 签名(node/rung/hp_before)没有板面——**注入物 = sim 桶现算的 win_p 浮点**,由调用方算好传入;与 `P2CombatCalib` 注入先例同构但传值不传对象。

**模型只掷胜负;幅度(胜负各自的 HP 变化)继续走粗模型直方/Δ池/常量表**——模型对「赢多少血」无责任,这是铁律 3 的工程落点。

### 6.2 依赖方向锁(注入契约 + 断言集)

消费点在 kernel(`cw_coarse_battle` / `cw_battle_calib`)而 kernel/decision 桶又禁 import 模型——**同时成立的唯一形态是注入契约**(先例:`P2CombatCalib` 注入 `p2_combat_delta`):

1. **注入契约**:模型实参只由 **sim 桶调用方**提供;kernel 函数签名缺省值恒 `None` = 完整旧行为(kernel 无模型时零漂移)。
2. **模型产物的落点钉死**:权重/标度/特征规格等一切模型产物**与查询面同落 sim 桶模型模块(含其私有数据文件),data/ 桶不落任何模型产物**——项目「校准表落 data/」的既有惯例在此**不适用**:data/ 被 decision 侧大量合法 import,权重落 data/ = 「读权重自算点积」绕过整个锁的通道。
3. **导入检查测试的精确断言集**(实现口径 = **静态源码/AST 扫描,含函数体**——懒 import 在函数体内,运行时 `sys.modules` 检查对未执行路径不可靠;**断言形态 = 封闭枚举白名单 + 引用审计**):**全包扫描,「模型子包」的许可 import 方逐模块枚举 = 子包内部 + sim 结算调用点(engine_p1)+ 影子接线 + 测试模块**;decision/kernel/data/operations/obs/telemetry/strategies/包根一律禁止。**注意直连/传递的语义**:实施后 telemetry→runner→engine_p1→模型子包 的 import 链**必然存在**(runner 合法编排 engine_p1)——import 链本身不是威胁,威胁是**符号可达**;故断言除 import 白名单外,附三条引用审计:①**白名单外模块对模型子包的限定名/属性零引用**(AST 级扫 `power_model` 限定名的所有出现——含字符串常量形态的 `importlib`/`__import__` 参数,白名单外命中即红);②**重导出审计**(白名单内合法方不得把模型符号重导出给白名单外——engine_p1 的 `from ... import` 只限函数内使用位,不进模块级命名空间);③**残余风险声明**:动态反射(运行时拼接模块名)无法静态穷尽,以「模型子包不注册任何插件/工厂入口」的代码评审纪律补位。**sim/checks 的枚举位**:影子门检查器若需直接 import 模型子包(而非只读账本字段),将其显式列入许可枚举并注明用途;默认不列。
4. **禁止接口清单**(否决项,**四形态全收编**):`delta_win_p(state, action)` / `delta_value_gold(...)`(折算金当量)/ 直接调用 win_p 做候选比较或排序键 / **系数知识洗白**——把模型拟合系数(或其函数)抄写/转译为决策侧常量、评分权重或阈值(不 import 模块、不调接口,AST 审计不可见的**知识拷贝**;拟合系数外推正是「统计 vs 拟合外推」线禁止的形态)——一律不存在。**残余风险声明**:第四形态无法机械测试,以评审纪律拦截——决策侧常量/权重须有 ADR 或证明出处,**禁以模型系数为出处**;本清单声明本身即审计依据。
5. **遥测隔离**:模型披露字段只进 sim 账本(落 `SIM_RUNS_DIR`);**测试锁住 sim 目录与 replay 目录的隔离**(B0 的消费侧闭环)。

### 6.3 影子期(双写披露)

接入前:sim 账本**双写两个新字段**——`model_win_p`(模型预测)与 `injected_win_p` 的 coarse 路径披露位(现账本只写 `p2_win_p`,coarse 路径的对照值无披露位,需新增)——不改掷定。离线产出**分歧分布**(按节点/rung/位面分段的两者差值统计)——不是、也不可能是「sim 上的校准」(sim 无真值,§5.3/§7-1)。**外推段可见性(非门)**:补一张「sim 输入分布上模型 win_p 分位数序列 vs 语料边际胜率」对照表,使训练分布外的高位段至少可见。模型的校准评估只发生在实机语料 LOCO 上(§5.3)。**影子期语义 = sim 内并行披露,不是决策层影子**——决策层无消费点,无可影子。

### 6.4 性能与确定性

logistic ≤12 参数 = 纯点积,sim 万级调用无压力;同输入同输出(无随机性),seed 可复现。

### 6.5 输入分布监控(两类报警)

sim 板面分布 vs 训练分布的漂移监控(逐特征 PSI 类)。**报警分两类,不混判**:

- **结构性缺失/不可达**(已知、非漂移):sim 侧生成器尚未供给/特征组冻结/sim 不产生的域(如 P3、plane_bosses)——登记为常驻声明,不触发动作;**含**:生成器落定后 sim 难度缺失恒 0% vs 训练 ≈10%(生成器总是给出难度)——缺失指示在 sim 侧结构性为 0,属本类常驻声明;
- **分布漂移**(真信号):实装且可达的特征上超阈——报警披露、不静默外推。

已知差例(入 §7):3 费占比 sim 24% vs 实机 ≈13%(**口径:实机侧朴素分母下 ≈15%,按费用档过滤口径 ≈13%——引用钉口径**;发牌概率表修正前带免责);难度分布高度退化——**质量集中于 108 的比例历次口径内测量在 ≈73-80%(战斗键口径)至 ≈89%(全 decisions 口径)之间,口径-数字绑定不稳定**,以抽取批 canonical 实现的实测回写为准;**方向性结论(近点质量、系数弱识别)在全部口径下成立**——难度系数在现有语料上弱识别,带此披露;**难度缺失 × plane 共线披露**:缺失率 P1 ≈9% / P2 ≈12-14%,缺失指示与 plane 二值部分共线,两系数识别弱化如实声明。

### 6.6 与 0308 号件的 supersede 关系

本设计替换战斗结算胜负面的取值口(0308 决策 1「回退层胜负面统一走 node_win_p」在其辖域的默认主路径上被本设计取代)——**落地件声明 supersede 链**,0308 钉的 node_win_p 数字锁按「锁的存在性纪律」重推语义(锁红≠改动错),不机械跟绿;不可达战斗分支的处置(§6.1)同批声明。

### 6.7 sim 侧上下文生成器(消费端特征供给,本设计的配套交付)

**现状**:批量 sim(`cw_sim batch`)的 GameState 从不填充 `enemy_difficulty`/`enemy_affixes`/`plane_bosses`(`kernel/cw_state.py` 缺省 None/空表;`sim/engine_p1.py` 只读不写;`cw_replay` 的字段拷贝仅回放臂)——不补生成器,模型的敌方上下文特征在消费端恒缺失。

**现存物处置(单一源纪律)**:`telemetry/cw_win_model.py`(win_model M1,影子模式 P(win) 适配类 + 实机语料训练的 killed 分类器 + `corpus.py` 训练表检查族)与本设计是**两个并存的 P(win) 模型/两条训练表路径**——落地批同步处置:**M1 supersede 退役**(`cw_win_model.py` 及其特征/检查依赖面随落地 ADR 删除或迁移到新抽取表;M1 现状为影子不接线、模型产物 gitignored,退役低风险),防双源;在其退役前 M1 维持「predict 不接任何结算路径」现状。

**方案(与既有 sim 经验表+采样器同风格,先例 `sample_node_sequence`)**:

- **难度**:按 plane×round 的语料经验直方图逐战斗采样;**已知退化披露**:质量集中于 108(战斗键口径 ≈73-80%、全 decisions 口径更高;口径-数字绑定以抽取批 canonical 实现回写为准)——直方图近点质量,生成难度近似常数,该特征在 sim 内变化幅度小;v1 不建模难度-连胜耦合(伟大征服「难度+连胜数」),作为已知简化披露;
- **boss 身份:推迟**——v1 特征面不含 boss 身份(§4.3 冻结,one-hot 档位数超预算),生成器同步推迟到该特征开放,避免无消费者的生成面(与词缀层同款反模式);
- **词缀:推迟**——同上(§4.3 冻结);
- 生成器只写 GameState 的敌方字段,**不与板面/策略状态交互**(外生性),测试锁住单向性。

## 7. 边界与已知风险

1. **循环的消费面(B0 延续,最重要)**:sim 结算被模型替换后,sim 的战斗胜率证据全部来自模型——**sim A/B 只能验证策略层改动,永远不能验证模型本身**;模型真值 = 实机语料,每次迭代必须回实机对拍。
2. **对手板面不可得**:现观测面只有敌 boss 身份/难度数值/词缀清单;对方上场阵容无读取管线(实机画面是否展示也未验证)。模型把对手强度压缩为上下文协变量,同协变量下的胜负差异吸收为噪声——这是精度上限。若实机验证发现可读对方板面 → 特征组 E(敌方板面逐件计数)升级,接口不变。
3. **版本漂移**:游戏版本更新(角色数值/羁绊表变)或策略大改都会使分布漂移;校准曲线随版本重验,重采纪律沿 data-collection 既有流程。
4. **样本爬坡期结论弱**:按少数类 ≈128 胜事件,首期 ≤12 参数(实装 12,满预算)= 粗聚合级结论;各层放开触发线见 §4.3。
5. **sim/实机域差(双侧声明)**:装备效果数值、词条、boss 克制 sim 不响应——**装备/核心/词缀特征在放开触发线前双侧均不在模型内**(§4.3 冻结);3 费占比偏移带免责(§6.5);难度近退化(§6.7);P3 并入非P1 低置信;P2 分桶低置信披露。
6. **策略-模型共生**:策略朝模型认为好的方向演化 → 语料分布随之变化——对照机制的**操作定义**见 §8.9(指定模型外策略臂的对照局配额或周期性离线评估,触发与判据落地);语料冻结期(§7-7)叠加时这是唯一长期纠偏机制。
7. **语料冻结风险**:增长依赖实机局,活动窗口关闭即冻结(§5.1)——里程碑重训 + 冻结期只做校准复验,不做新训练。
8. **标签缺失的 MNAR 风险**:canonical 口径 `killed=None` 丢弃 141/830 键(17.0%;raw 行口径 17.6%),缺失率按 source 显著分层(真值 ≈20%/loss_page 0%/recovered 75%,设计期实测)且与败局路径相关——丢弃引入的选择偏差按 §5.1 敏感性表监控(含带标签优先挽回的 15 键),方向性结论(尤其低胜率带)带此免责。
9. **词缀映射覆盖不足且口径可漂移**:生产默认 23 种/34.3% 事件质量——词缀特征层开放的先决条件是映射补齐(§4.3 触发线);抽取产物钉映射版本指纹(§5.1);开放前模型的上下文敏感度不含词缀维,该局限如实声明。

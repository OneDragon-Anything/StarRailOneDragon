## 指定复核点专项裁定

### ① H10-1 修复闭环性：**未闭环——四个子问逐项裁定**

- **(a) fill 暂存消费顺序修复后 3b 败局行 fill 可得的代码可行性：可行，但收益面窄。**现状代码路径：暂存唯一清空点 = `_record_round_outcome` 内 ：416-417（`_st.settle_page1_settle = {}`），位于 ：418 `if not telemetry_only:` 门**之外**——把消费/清空挪进门内即实现「telemetry-only 行不消费」，改动局部、无结构性障碍。但收益面核查：能产出全写败局行的只有 3b「前往结算」帧（:812-818），而 3b 全写只在 1f 模板门失配的帧上才轮得到（1f 命中即 return，同帧到不了 3b）；1f 失配时该帧通常是败局页 1 本身，「点击空白加速」在场 → `read_round_outcome` 在 ：484-485 **直读** fill，根本不依赖暂存。暂存修复真正辖到的只有「3b 帧为非页 1」的少数形态。真正承重的缺口（败局行常态不入环）修复未触及——见 (c)。

- **(c) 修复方案引入新缺陷：跨场暂存污染（H11-1，本轮最高发现）。**「暂存由全写行消费后清、telemetry-only 行不消费」在常态败局流下没有消费点：败局链产不出全写行 → 页 1 暂存（fill / damage_base / damage_unfinished_progress / heal_longline / progress_delta）滞留到下一场战斗 → 下一胜局行的合并步（:406-417，注释明言「暂存值优先于页 2 同帧读数」）把上一败局的陈旧值灌进自己的行。伤害两分量是**确定性污染**（暂存写入是 first-write-wins，:736-737/:787-788，陈旧非 None 值永久挡住新值）；fill 与 progress_delta 是条件污染（败局值在胜局页 1 读缺时漏入，progress_delta 漏入叠加 ：384-387 符号判定可把胜局行 killed 翻成 False）。现状该污染已存在于窄路径（1f 失配 / killed=None 早退 ：372-375），修复使其成为**常态路径**。详见 H11-1。
- **(d) 败局行入环率作为开闸防线的充分性：fail-safe 成立，开闸充分性与度量语义不成立。**见 M11-3。

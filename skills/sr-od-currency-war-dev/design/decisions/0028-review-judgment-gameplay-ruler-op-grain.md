# 0028 · 复盘判定尺=玩法文档+在册裁定；粒度=外层循环画面op调用

## Status

accepted（2026-09-07）

## Context

2026-09-07 一份实机单局深度复盘暴露两类失守（实例：奖励节点开局轮，手握闲金、商店全廉价件）：

1. **判定尺失守**：复盘以「算法自身拒因存在、决策符合算法逻辑」判「合格」。而玩法文档与在册裁定（[40]①：奖励节点无需战力、买卡压制/精简卡池优于升级、非当前线组件禁一刀切拒买；出处 = `docs/game/currency_war/research/11_shop_decisions.md`）导出的正确做法是买入压池——该决策恰是当期立项要修的算法病。复盘成了给算法盖章，丧失发现算法缺陷的能力。
2. **粒度失真**：模板按「节点→静态画面类别（备战/商店/战斗/结算）」分组，把同一备战环里外循环的两次独立画面 op 调用（备战 op、开商店 op）揉进同一小节（商店内容混入「备战:观察」），与运行时结构不符——按 `docs/develop/currency_war/flow/outer_loop.md` §2.2（分支序 = 每分支一次画面 op 调用）与 `flow/screen_op.md` §1（一次 op 调用 = 入口观察 + 逐动作决策循环）。

## Considered Options

- **判定尺甲 = 算法自洽**（失守现状）：复盘只能验证「实现与算法一致」，永远发现不了「算法本身错」，复盘战略价值归零。否。
- **判定尺乙 = 玩法文档 + 在册用户裁定**：每个判定槽先问「文档/裁定说正确做法是什么」，再对照算法实际决策；偏离 = 算法缺陷候选。采纳。
- **粒度甲 = 节点-静态画面类别**：与运行时结构不符，组内混 op，观察数据归属失真。否。
- **粒度乙 = 外层循环调用序逐画面 op 记录**：与分支序一一对应。采纳。

## Decision

1. 复盘判定尺 = 玩法文档 + 在册用户裁定；算法内部自洽不构成合格判据。
2. 复盘粒度 = 外层循环调用序，每画面 op 单独一条记录（分支 + op 名 + 时间戳 → 入口观察 → 决策循环动作序列 → 判定三槽）；无决策行的纯路由迭代汇总披露。
3. 复盘核心产出含**算法缺陷候选清单**（证据 = 档案字段 + 裁定/文档 file:line；有在册修复任务引任务，无在册立新候选）。
4. 协议正文单一源 = `references/match-review.md`；本 ADR 只记 why。

## Consequences

- 复盘产出从「合规报告」变为「病灶弹药」，其质量上限受玩法文档与在册裁定完备度约束——判定引用过程本身成为玩法文档的查漏器（引用不到尺的决策面 = 文档缺口信号）。
- 派复盘单的任务书必须显式携带玩法尺出处（文档路径/裁定原文位置），禁只发协议文件不带尺。
- 与全局攻击纪律（审查禁只验内部自洽）同构；本条把适用面明确扩展到复盘。

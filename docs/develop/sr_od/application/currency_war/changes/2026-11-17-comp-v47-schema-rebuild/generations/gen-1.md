# gen-1 · 阵容定义数据结构建模方案（独立设计稿）

> 定位：迭代 `2026-11-17-comp-v47-schema-rebuild` 演化循环**第一轮独立生成稿**。基线 = 同目录 [current.md](current.md)（编排者 v0 初稿）；本稿从知识源独立推导，与 v0 的差异清单见 §8，供对比融合。
> 输入（全部已读）：`docs/game/currency_war/research/final_comps/` 19 篇（V4.7 重建）+ `transition_combos.md` / `stage_transitions.md` / `combat.md` + 三注册表（`cw_traits_data.py` / `cw_equipment_data.py` / `cw_chars.py`）。
> 建模目标（用户裁定）：**覆盖大部分普通玩家照攻略能抄出来的路线，不求全**；特例花活路线（13 人全羁绊挂机奖励流、极限低配单卡）不为它扭曲结构，留挂点即可。
> 证据标签：**[图鉴]** = 官方注册表原文（机制断言以此为准）；**[米游社]** = 攻略帖逐篇深读、帖间一致；**[社区]** = 多帖互证但官方数据未收录、待实机验证。字段登记只认 [图鉴] 与 [米游社]；[社区] 级知识最多进注释与风险清单，不进字段值。

## 0. 术语（全篇首次出现即定义）

- **阵容条目（Comp）**：一条可被策略层独立选择、独立判定成型的终局构筑路线。互斥的两条强路线 = 两个条目（见 P5）。
- **目标态快照**：一份「场上应该长什么样」的清单（哪些人在、哪些羁绊档亮、装备在谁身上、星级到几）——**不含**「什么时候做、按什么顺序长过来」。
- **阶段（Stage）**：目标态快照的一个版本。阶段之间的切换由**状态条件**触发（某人到场 / 某装备到手），不由时间或回合数触发。
- **档位**：羁绊激活层数（注册表 `layers[].layer` 的取值，如连击 2/4/6/8）。
- **点名**：在字段里直接写角色名（区别于按羁绊派生的凑件）。
- **凑件**：只为凑羁绊档位而上场的人，不承担该阵容的取胜机制；由公共凑件表按羁绊给候选，不在条目里逐个点名。
- **拿掉检验**：登记判据——假想把某人拿掉：取胜机制不成立 → 机制角色；机制仍成立但强度明显掉档 → 核心辅助；换个人羁绊照活 → 凑件。
- **让位序**：名单里的整数优先级，小值优先，同值平权。用途：人口紧张时先卖谁、先保谁。
- **成型**：策略层停止为该条目定向投入（搜牌/追星）的判据状态。
- **位面 1/2/3**：游戏的前期 / 中期 / 后期三段（Early / Middle / Final）。本 schema 不用它做任何字段值，只出现在叙事里。
- **载体**：装备的穿戴者。大多是购买角色，少数是不可购买实体（饮月的绑定随从腾荒、欢愉羁绊召唤的阿哈）。

## 1. 设计原则

知识切三层：**进数据（本 schema）** / **留给策略层运行时** / **归文档层（final_comps 各篇）**。判据如下。

### P1 数据 = 状态触发的目标态快照；一切时间过程归策略层

阵容知识里最大的一块是「过程」：搜牌节奏（5 级搜牌 / 速升 8 / 速 9）、经济纪律（卡 50 金利息、每轮至多 D 两次）、时序（2-7 速 8、3-3 搜昔涟）。这些**全部不进 schema**。理由：它们是「玩家/策略按当前状态做的决策」，不是阵容的属性；同样的那刻夏班底，追三线卡 5 级、速升线直拉 9，人没变——变的只有节奏。节奏由策略机制层（等级-经济骨架）+ 阵容目标态（星级目标、名单）组合涌现，手编时间表已被证明会整块死掉（`level_plan` 先例，见 comp-definition.md）。

**例外——阶段切换是状态条件，不是时间表**：同一套阵容里存在「骨架升级」的分叉点（商店刷出姬子才转型 / 三甲到手才把反击档立起来）。阶段用 `enter_when`（某人到场 / 某装备到手）表达，它描述的是**两个目标态之间的切换条件**，仍是快照语义，不是时间语义。

### P2 名单按功能分三层；第三层不点名（派生）

19 篇的骨架节都长一个样：**具名核心**（功能链角色，不可替换）→ **功能链常驻**（各占一环）→ **自由槽**（带标签即坐）。对应：

| 文档层语言 | schema 层 | 登记判据 |
|---|---|---|
| 具名核心 | `core`（机制角色） | 拿掉检验：拿掉后取胜机制不成立 |
| 功能链常驻 | `support`（核心辅助） | 拿掉后机制成立、强度掉档；或帖间高频在场的引擎件/解药 |
| 自由槽 | **不设字段**——由核心羁绊档位 + 公共凑件表派生候选 | 「带标签即坐」本身说明无人格依赖 |

不按「重要度」分层（主 C 和他的开局标记引擎同为核心），按功能拓扑分层。

### P3 派生优先：能推导的不登记

- 凑件候选 = 羁绊注册表成员 − 点名者，顺序由公共表给；不逐条目登记。
- 过渡班底 = 过渡羁绊成员 ∩ 费用 ≤ 2 − 引擎件（transition_combos 的班底全部可如此复现：连击线班底 = 刻律德菈/星期日/白露，DOT 线 = 黑天鹅/桂乃芬/海瑟音/娜塔莎，云五线 = 景元/白露——全是注册表可查的 1-2 费成员）。
- 巡海游侠任命目标 = 当前阶段 `core` 首位（19 篇里任命一律给主 C：那刻夏/遐蝶/黄泉/飞霄/雪衣，无一例外），不设字段。
- 反击王 = 装备最多的前台反击角色（注册表原文定义），由装备配方 + 站位派生。
- 过渡出口站 = 羁绊档达 + 引擎件 2 星 + 保值件 ≥ 1（三件套通用判据），由字段 + 库级常量派生，不设逐条目字段。
- 「6 反击必须有反击星徽」这类可行性事实 = 点名人数与档位差的算术（反击原生成员恰 5 人 [图鉴]），由建库校验与策略层推得，不设门槛字段。

### P4 消费先行：字段必须挂在一个真实消费点上

策略层对阵容库的八个消费问题（§5 逐一对账）：**选线 / 采购 / 卖人 / 装备合成与分配 / 星级停手 / 站位 / 成型判定 / 过渡出口**。没有消费面的知识不设字段——本稿据此**不设**：家族谱系字段（选线不需要家族查询，索引归文档）、降级路径字段（运行时按缺件自适应）、开局信号/词条吃怕/投资亲和字段（策略层已有线级吃怕表与选卡克制表，且多数属 [社区] 待实机）、过渡线静态优先级字段（选过渡线的主判据是来牌状态，静态占比随版本重跑变化快，归 transition_combos 文档）。

### P5 互斥拆条；变体与降级不拆

构成或羁绊骨架不同、且帖量双强 → 拆成独立条目（A3 景元双峰、H1 黄泉双峰、E 开拓三分支、F 饭店四线）。装备面/节奏面的变体（A1 巨人变体、追击转变体）、降级路径（三甲不齐→双甲+风暴潮）不拆，归文档层与策略自适应。判据实操：帖量悬殊时只登主形态，其余在 final_comps 篇内挂「待帖量增长立条」。

### P6 特殊系统默认不进 schema；例外只收两条门槛

拜师、改装树、白厄吃人、双龙吟复制、奇美拉招聘、阿哈装备栏、饭店星级成长——这些是「策略侧将来立项的执行知识」：要么可派生（任命目标 = 主 C），要么是运行时操作序列（吃谁、招哪只奇美拉），schema 不为它们设字段；需要近似时用「把对应角色的优先级抬高」承载（comp-definition 既有裁定）。
**例外**：不可派生、且直接决定条目成立与否的硬门槛收进 `entry_gates`（值域刻意收窄为两条：今日菜单含某菜、账号持有某角色的奇缘星魂——理由见 §2.1 字段 3）。

### P7 只登例外行

星级目标与站位只登「偏离默认」的行：未登星级的角色 = 无追星义务（来牌自然，1 星可用）；未登站位的角色 = 用角色注册表的 position 偏好（common 默认后排）。不为「描述性常态」（辅助一般 1-2 星）落字段。

### P8 装备到人不到位置；接力与代持 = 目标态归属 + 运行时执行

「装备是角色特定的」（到人），配方归属写目标穿戴者。打工代穿（万敌代穿甲→刃）、代持（知更鸟代持永动机→昔涟转交）、装备接力（景元代穿遐蝶装）都是**时间过程**：schema 只记最终归属（甲→刃、永动机→昔涟、输出装→遐蝶），「持有者未到场时由谁临时穿」是策略层通用规则（同线低优先辅助代持，到位即转移），不设字段。

### 三层归宿总表

| 知识 | 归宿 | 载体/理由 |
|---|---|---|
| 名单三层、羁绊档位、装备到人、星级例外、站位例外、阶段切换条件、账号与局内门槛 | **数据（本 schema）** | §2 全部字段 |
| 选线评分、采购优先、卖人让位、代持转移、降级自适应、搜牌与经济节奏、特殊系统操作（任命/吃人/改装/招聘）、词条与投资亲和 | **策略层运行时** | 消费 §2 字段 + 策略自有旁表；节奏由等级-经济骨架涌现 |
| 达成路径叙事、变体与降级清单、家族谱系、证据与存疑、[社区] 机制主张 | **文档层** | final_comps 各篇（唯一源），schema 不镜像 |

## 2. 字段定义

类型记法：`dict[K, V]` 键值表；`frozenset[T]` 无序集；`tuple[T, ...]` 有序元组。角色名/装备名/羁绊名一律用注册表规范名（`·` 归一口径）。

### 2.0 构件类型（3 个，被字段引用）

- **Cond（状态条件）**：`('char', 角色名)` = 该角色已购入并可上场；`('equip', 装备名)` = 该装备已合成/获得且可穿。用于阶段切换。
- **Gate（成立门槛）**：`('菜单含', 菜品名)` = 本局今日菜单含该招牌菜；`('奇缘星魂', 角色名)` = 账号持有该角色的奇缘星魂。用于条目级过滤。
- **EquipPool（装备候选池）**：`tuple[装备名, ...]`，有序候选、取一。表达「第四件按需：电锯 / 斩舰刀 / 斩首 / 动能剑」这类攻略明确给候选但不定死的槽位。

### 2.1 条目级字段（Comp，4 个）

**1. `name: str`**
- 语义：条目唯一名，人读标识 + 库键。
- 登记判据：一条按 P5 拆定的独立构筑路线；命名携带家族与形态语义（家族词 + 主 C + 形态词），家族组织本身不进 schema。
- 默认/空值：必填，无默认；库内唯一（校验 V1）。
- 案例：`'刃·三甲反击'`（D1）；`'那刻夏·连击'`（A1）。

**2. `account_req: dict[角色名, int]`**
- 语义：账号练度硬门槛——角色 → 最小星魂（命座）数；不满足则本条目对该账号不可选。
- 登记判据：帖间明写「满魂/高命限定」的行（[米游社]）。
- 默认/空值：`{}` = 无账号门槛，任何账号可选。消费：开局按本体 roster 一次性过滤候选（bot 账号固定，评估一次）。
- 案例：风堇马头流（F §11）`{'风堇': 6}`。

**3. `entry_gates: list[Gate]`**
- 语义：局内/局外硬门槛，**不满足即条目出局**——与「评分偏好」（开局信号、词条吃怕，归策略层）的分界就在这条线。
- 登记判据：①不可从注册表派生（可派生的门槛不登，见 P3——克拉拉线的反击星徽依赖可由「反击原生成员 5 人 < 6 档」算出，不登记）；②帖间一致认定为「没有就不玩/不建议玩」[米游社]。
- 默认/空值：`[]` = 无门槛。AND 语义（多条全满足才成立）。
- 案例：遐蝶线（F §3，p30 决策树）`[('菜单含', '蝶豆糕')]`；景元赌狗峰（A3 峰 A）`[('奇缘星魂', '景元')]`（奇缘星魂效果本身属 [社区] 待实机，但「刚需、没有不建议玩」是帖间一致 [米游社]）。

**4. `stages: list[Stage]`**
- 语义：有序阶段列表；执行语义 = 取 `enter_when` 已满足的**最末**阶段为当前阶段，策略只按当前阶段行动。
- 登记判据（什么时候拆阶段）：后一阶段相对前一阶段，**名单集合或核心羁绊档位目标发生结构性变化**，且切换由状态条件触发（[米游社] 明确的转型触发点）。仅装备件数增减、仅节奏不同、仅变体——不拆（归 P5 变体 / P8 归属）。
- 默认/空值：单阶段列表（大多数条目）。
- 案例：姬子线 2 阶段（E：商店刷出姬子转型）；刃·三甲 2 阶段（D1：三甲到手才把反击档立起来）。

### 2.2 阶段级字段（Stage，8 个）

**5. `enter_when: Cond | None`**
- 语义：本阶段的进入条件；`None` = 首阶段（条目被选中即生效）。
- 登记判据：帖间明确的转型触发（「商店刷出姬子就买，老杨退居后排」→ `('char', '姬子·启行')`；「拿到幻造巨铠再转反击」→ `('equip', '幻造巨铠')`）。
- 默认/空值：`stages[0]` 必为 `None`（校验 V8），后续阶段必非 `None`。
- 案例：`('equip', '幻造巨铠')`（刃·三甲阶段 2）；`('equip', '梦境交织星徽')`（那刻夏·连击阶段 2，锁轴形态——见 §6.1 讨论）。

**6. `core: dict[角色名, int]`（机制角色 + 让位序）**
- 语义：取胜机制的承担者，AND 全必要（缺一即机制不成立）；值为让位序（小值优先，同值平权）。
- 登记判据：拿掉检验（P2）；「具名核心（不可替换）」节 [米游社]。过渡 C 在换 C 型条目的早阶段以机制身份登记（姬子线阶段 1 的瓦尔特）。
- 默认/空值：必填非空（没有机制角色的条目不存在）；让位序无帖间证据时全员同值。
- 案例：那刻夏·连击 `{'那刻夏': 1, '刻律德菈': 2, '花火': 2}`（三人各是输出轴 / 标记引擎 / 舞伴，拿掉任何一个连击体系都缺一环）。

**7. `support: dict[角色名, int]`（核心辅助 + 让位序）**
- 语义：功能链常驻——放大机制的引擎件（拉条/充能/治疗）或机制死穴的解药；拿掉机制仍成立、强度掉档。值为让位序；人口紧张时大值先让位。
- 登记判据：「功能链」节帖间高频在场者 [米游社]；让位序登记帖间补位/卖出证据（「缺人口上藿藿，缺伤害上寒鸦」→ 寒鸦序小）。
- 默认/空值：`{}` 允许（极简凑档线）；同 `core` 一样跨阶段可变，**阶段名单差集 = 退役卖出候选**。
- 案例：刃·三甲 `{'风堇': 1, '昔涟': 2, '缇宝': 3, '符玄': 3, '千冶·刃': 3, ...}`。

**8. `faction_core: dict[羁绊名, int]`（核心羁绊 + 成型档位）**
- 语义：身份签名羁绊及成型档位；**AND 语义**——全档达标 + `core` 点名在板 = 该阶段成型。
- 计数口径（由羁绊注册表分派，不进字段值）：`count_mode='TOTAL'`（默认）= 上场人数 ∪ 佩该羁绊星徽者；`count_mode='STAR3'`（千星商会，全表唯一）= **场上三星**成员数 ∪ 佩徽的三星非成员；召唤型独立羁绊（双龙吟）= 成员 + 后台召唤物（饮月一人即达 2 档 [图鉴 layers 1/2 + v47_tenghuang_binding]）。
- 登记判据：帖间「标配 / 成型判据 / 身份签名」的羁绊档（遐蝶线「主流成型板 = 6 召唤 4 饭店」）；档位必须 ∈ 注册表 `layers` 档位集（校验 V3）。
- 默认/空值：必填非空。星徽可参与计数（「装备者加入【X】羁绊」[图鉴]，21 件星徽注册表实锤）；云上五骁与少女乐队无星徽条目（注册表级发现）——校验 V4 须知悉，凑档手段少一张。
- 案例：遐蝶线 `{'召唤': 6, '黄金大饭店': 4}`；砂金千星 `{'千星商会': 6, '欢愉': 3}`。

**9. `faction_bonus: frozenset[羁绊名]`（加层羁绊认可集）**
- 语义：该阵容认可其收益、但不算成型判据的羁绊；不登档位（「按来牌挂、档位随缘」）。
- 登记判据：帖间「副档 / 顺带激活 / 自由槽标签」[米游社]（A1 的小小巨人、云上五骁、治疗、梦境交织[阶段 1 口径]、追击）。
- 默认/空值：`frozenset()` = 无加层。消费：采购评分认可这些羁绊的成员（低权重），不进成型判定。
- 案例：那刻夏·连击阶段 1 `{小小巨人, 治疗, 云上五骁, 追击, 奇兽花园, 开拓银轨}`。

**10. `equip_assign: dict[载体名, list[str | EquipPool]]`（装备配方，到人）**
- 语义：目标穿戴者的配方清单；**列表内序 = 合成优先序**；同名重复 = 多件（`['幻造巨铠','幻造巨铠','幻造巨铠']` = 三甲）；`EquipPool` 槽位取一。跨阶段同件换主人 = 装备转移（P8）。
- 载体键域：本阶段名单（`core` ∪ `support`）∪ 库级非购买载体白名单（`OFF_ROSTER_EQUIP_CARRIERS`，见字段 17；腾荒是角色注册表 `is_hide` 条目，可直接引用，不经白名单）。
- 登记判据：帖间逐件到人且帖间一致的配方（「狼尊三件套」「三甲给刃」「永动机给昔涟」[米游社]）；「唯一装备」（注册表 effect 标注，如蓄能帆/未唱名面具/星航履/绝对热量）全条目至多一人一件（校验 V6）。
- 默认/空值：`{}` = 无登记配方（凑档线）；未列名单成员 = 无目标装备（捡漏归策略）。
- 案例：刃·三甲阶段 2 `{'刃': ['幻造巨铠','幻造巨铠','幻造巨铠'], '昔涟': ['永动机'], '风堇': ['绝对热量','生命之环','生命之环'], '缇宝': ['胜利之旗'], ...}`。

**11. `need_star: dict[角色名, 1|2|3]`（星级目标 = 停手线）**
- 语义：该角色达到此星级即「星级就绪」，停止为其定向刷新；**未列出 = 无追星义务**（来牌自然升星，1 星可用，策略不为它花刷新预算）。
- 登记判据：帖间明确的追星线（低费追三：云璃/绯英/流萤/海瑟音）、绑定线（云璃线的花火 3 星「不然坠机」）、到手线（姬子 2 命可用）、追三线全员行（千星成员逐个三星——与 STAR3 计数耦合，三星即羁绊层数 [图鉴+米游社]）。
- 默认/空值：`{}` = 全员自然来牌（装备/羁绊驱动线，如昔涟线——「装备地位远高于星级地位」）。
- 案例：云璃·追三 `{'云璃': 3, '花火': 3}`；砂金千星 `{'砂金·戏浪': 3, '真珠': 3, '爻光': 3, '知更鸟·晴歌': 3, '托帕&账账': 3, '翡翠': 3}`。

**12. `char_positions: dict[角色名, str]`（站位覆盖）**
- 语义：有机制语义的站位才登；值域 `'front' | 'back' | 'front@N' | 'back@N'`。**坐标系定义：`@N` = 行内第 N 位，N 从 1 起，与攻略阵容数据的 front_roles / back_roles 列表内序号同源（1 基位次，非几何像素槽位）；取值时机 = 终局目标态，运行时被占/超容由策略软回退。** 未列出 = 用角色注册表 `position` 偏好（front/back；common 默认 back，属无知识兜底）。
- 登记判据：位次带机制语义的帖间铁律（那刻夏固定前排 1 号位吃连击地格、刻律德菈后排 1 号位专属、万敌前排 1 号位吃军功、白厄放后排防踢人、昔涟固定前台）。
- 默认/空值：`{}` = 全员用注册表偏好。
- 案例：那刻夏·连击 `{'那刻夏': 'front@1', '刻律德菈': 'back@1'}`。

### 2.3 过渡条目字段（TransitionBond，2 个）

过渡库不复制终局库的字段族：过渡是**状态驱动的添件过程**（「加法不换件、无预设顺序」，transition_combos §8），不适用阶段；装备配方、站位、星级例外恒空（库级规则，校验 V9）；出口站三件套判据为通用派生（P3），不设字段。

**13. `bond: dict[羁绊名, int]`（过渡伤害线 + 出口档位）**
- 语义：这条过渡线的羁绊与出口站档位（连击线的出口站是 4 连击，不是首档 2）。
- 登记判据：transition_combos 判据序过卡的体系线（第 1 档就有伤害/改变攻击轮次 + 纯 1/2 费层组合实证）；经济线（开拓银轨）同样入库但无伤害档——它的出口由搭档伤害线给出，自身不参与出口派生（语义规则，不设字段）。
- 默认/空值：必填非空。
- 案例：连击线 `{'连击': 4}`；持续伤害线 `{'持续伤害': 3}`；银轨经济线 `{'开拓银轨': 2}`。

**14. `engine: dict[角色名, int]`（点名引擎/伤害件 + 让位序）**
- 语义：拿掉则该过渡线不成立的点名件（「点名件在板」语义 = `engine` 全员在板）；班底**不登记**——派生 = `bond` 成员 ∩ 费用 ≤ 2 − `engine`（P3，已对 transition_combos 全部体系线复现验证）。
- 登记判据：transition_combos「人员要求」列——单卡依赖线登该卡（大黑塔线），最佳班底线登引擎件（连击线登那刻夏），纯计数线留空（DOT 任意三件）。
- 默认/空值：`{}` = 纯计数线（无点名依赖）。
- 案例：连击线 `{'那刻夏': 1}`；大黑塔系 `{'大黑塔': 1}`（`bond={'群攻': 2}`）；DOT 线 `{}`。

### 2.4 库级公共表与常量（3 个）

**15. `FILLER_PRIORITY: dict[羁绊名, tuple[角色名, ...]]`（公共凑件表）**
- 语义：每羁绊一张凑件候选优先序；候选域 = 该羁绊注册表成员（终局库消费时再减去各条目点名者）。
- 登记判据：全程留用层统计（stage_transitions §2，1-2 费双标签通用件为主）+ 各篇「自由槽/第三人从谁补」的帖间证据；辅助/工具型优先，**输出大 C 不进表**（防凑件抢主 C 的位置与装备）。
- 默认/空值：某羁绊无表 = 该羁绊凑件按注册表成员顺序兜底。V4.7 需全量重定（羁绊大换血，旧表全弃）。
- 案例（示意）：`治疗: (藿藿, 白露, 罗刹, ...)`——具体排序归落库批按证据定，此处只锁结构。

**16. `CROSS_PHASE_KEEP_EQUIPS: frozenset[装备名]`（跨阶段保值件白名单）**
- 语义：过渡期**唯一允许主动合成**的成品集（「合成装只在跨阶段保值时提前合成，不为过渡特意合成一次性件」，transition_combos §7 [米游社]）。
- 登记判据：帖间公认的跨阶段保值件（火力风暴潮 / 永动机 / 蓄能帆类——终局多线共用、打工位可先用）。
- 默认/空值：非空常量；消费：过渡期合成闸 + 出口站派生的「1 件合成装」判据。
- 案例：`{'火力风暴潮', '永动机', '蓄能帆'}`（落库批按帖证增删）。

**17. `OFF_ROSTER_EQUIP_CARRIERS: frozenset[角色名]`（非购买装备载体白名单）**
- 语义：可作 `equip_assign` 键、但不在任何购买名单里的实体；封闭常量，新增需改此表。
- 登记判据：注册表无条目、但帖间存在独立装备栏的实体。V4.7 一例：欢愉羁绊召唤的阿哈（B1「阿哈时刻装备 3×火力风暴潮……与星神★阿哈单位是两个实体，装备栏各自独立」[米游社+图鉴欢愉 simple_desc]）。腾荒**不经此表**（他在角色注册表内，`is_hide=True`）。
- 默认/空值：`{'欢愉阿哈'}`；空集合法（无此类载体时）。

## 3. 库的组织

### 3.1 两库分立

| | 终局库 `COMP_LIBRARY` | 过渡库 `TRANSITION_LIBRARY` |
|---|---|---|
| 条目形态 | `Comp`（字段 1-4 + Stage 族 5-12） | `TransitionBond`（字段 13-14） |
| 阶段 | 允许多阶段（状态条件切换） | 恒单形态（状态驱动添件，无预设顺序） |
| 装备/站位/星级例外/加层羁绊 | 按登记 | **恒空**（库级规则，校验 V9） |
| 锁定语义 | 成型后锁定名单方向 | **永不锁定**（来牌主导，随时换线） |
| 成型判定 | 当前阶段 `faction_core` AND + `core` 在板 | 出口站派生：`bond` 档达 ∧ `engine` 2 星 ∧ 保值件 ≥ 1；经济线不参与 |

两库分立的理由：过渡的选择逻辑（来牌主导、意向同向、加法不换件）与终局的目标态逻辑（点名、AND 成型）是两种计算；硬塞一个 schema 会让终局字段在过渡侧大量恒空（v2 草案已有此结论，继承）。**过渡→终局的流向知识**（连击线出口通向 A 家族等）归 transition_combos §8 的指针表（文档层），不建库间引用字段——选终局线是策略运行时评分，不是静态图遍历。

### 3.2 公共表与常量的归属

`FILLER_PRIORITY` / `CROSS_PHASE_KEEP_EQUIPS` / `OFF_ROSTER_EQUIP_CARRIERS` 与两库同模块维护（阵容定义单一源，一个文件）；星徽→羁绊的映射**不建表**——从装备注册表 effect 原文派生（「装备者加入【X】羁绊」，P3）。

### 3.3 版本纪律

库数据随 final_comps 重建批次联动重跑（frontmatter `rebuilt` 对齐）；注册表（羁绊/装备/角色）先行重跑，库校验（§4）在 import 期自动拦截版本失配的名字与档位。挂机奖励流（13 人全羁绊刷星琼）按迭代裁定**独立立批**，本库不留半吊子字段，挂点 = 条目级不设、库外另立第三库的接口位（风险 §7.6 提及）。

## 4. 建库校验（import 期即可查出的数据错误）

- **V1 引用合法**：`name` 唯一非空；所有角色名 ∈ 角色注册表（含 `is_hide` 载体与白名单名）；装备名 ∈ 装备注册表（特权版独立条目，不与普通版混键）；羁绊名 ∈ 羁绊注册表；`Gate` 的菜品 ∈ 装备注册表「餐品改件」类；`account_req` / `entry_gates` 的角色 ∈ 角色注册表。
- **V2 名单互斥**：逐阶段 `core ∩ support = ∅`；跨阶段重复登记合法（同人不同阶段可变档）。
- **V3 档位合法**：`faction_core` / `bond` 的档位 ∈ 该羁绊注册表 `layers` 档位集（连击登 5 = 错，合法档只有 2/4/6/8）。
- **V4 成型可行性（按 `count_mode` 分派）**：TOTAL 口径 = 点名成员中该羁绊人数 + 星徽可补数（该羁绊有星徽条目才计；云五/乐队计 0）+ 公共凑件池 ≥ 档位；STAR3 口径 = 可追三的点名数 + 佩徽三星名额 ≥ 档位，且当 STAR3 羁绊档位 > `need_star` 三星行数时**警告**（耦合漏登嫌疑）；召唤型独立羁绊（双龙吟）走特例：成员 1 人即达 2 档（召唤物计数，注册表注记背书）。
- **V5 人口边界**：逐阶段 `|core ∪ support|` ≤ 13（V4.7 实测最大板面，财富宝钻扩容后上限）；过渡线 `bond` 档位所需人数 ≤ 5（位面 1 人口压死，transition_combos §1）。
- **V6 装备约束**：`equip_assign` 键 ⊆ 本阶段名单 ∪ 载体白名单（腾荒经注册表校验）；「唯一装备」类全条目至多 1 人 1 件；`EquipPool` 内无重复项。
- **V7 键域收口**：`need_star` / `char_positions` 键 ⊆ 本阶段名单。
- **V8 阶段结构**：`stages` 非空；`stages[0].enter_when is None`；其余阶段 `enter_when` 非 `None`；`('char', X)` 条件中的 X 必须出现在本条目某阶段名单（否则条件永无意义）；相邻阶段同条件 = 错误。
- **V9 过渡库恒空校验**：无阶段字段；`equip_assign` / `char_positions` / `need_star` / `faction_bonus` 恒空；`engine` ∪ 派生班底 ⊆ 注册表；经济线（无伤害档的 bond）标记为不参与出口派生。
- **V10 库间一致**：`FILLER_PRIORITY` 键 ⊆ 羁绊注册表且值 ⊆ 对应成员；`CROSS_PHASE_KEEP_EQUIPS` ⊆ 装备注册表进阶装备；载体白名单封闭。

## 5. 消费面对账（八个消费问题 → 字段供给）

| 消费问题 | 供给字段 | 策略层运行时补什么 |
|---|---|---|
| Q1 选哪条线 | `account_req` 过滤 → `entry_gates` 过滤 → 各条目当前阶段骨架匹配度评分 | 开局信号、词条吃怕、投资/门户亲和（策略旁表，多为 [社区] 待实机） |
| Q2 买哪些角色 | 当前阶段 `core` 缺员（必买）> `support` 缺员 > 核心羁绊剩余档位 × `FILLER_PRIORITY` 凑件 > `faction_bonus` 成员（低权） | 价格/利息纪律、已持有加权 |
| Q3 卖哪些角色 | 不在当前阶段名单 ∪ 凑件候选 ∪ 保值件载体者；**阶段名单差集 = 退役集**；让位序大者优先 | 备战席腾位、卖价时机 |
| Q4 装备怎么合成分配 | `equip_assign`（内序 = 合成优先序；Pool 取一；多件重复登记）；过渡期只允许合 `CROSS_PHASE_KEEP_EQUIPS` | 代持与转移（归属人未到场给同线辅助代穿）、组件囤积、选秀取件 |
| Q5 星级刷到几星停手 | `need_star` 达标即停；未列不为它花刷新 | 追三概率/费用档（游戏真值刷新率表） |
| Q6 站位怎么摆 | `char_positions` > 注册表 `position` 兜底；任命目标 = 当前阶段 `core` 首位（派生） | 被占/超容软回退、不重排已就位件 |
| Q7 什么时候算成型 | 当前阶段 `faction_core` 全档达标 ∧ `core` 点名全在板（装备缺口走 `equip_assign` 完成度，**不进成型判定**——装备驱动线的「装备不齐不转阵」由 `enter_when` 装备条件承载） | 完成度分级评分 |
| Q8 过渡何时停手转终局 | 出口站派生：`bond` 档达 ∧ `engine` 2 星 ∧ 保值件 ≥ 1 | 停手后利息纪律、插件按位买 |

## 6. 表达力自检（5 个结构上最不一样的阵容）

### 6.1 那刻夏·连击（A1）——**装得下**

落库：单 C 大宗线，2 阶段。
- 阶段 1（`enter_when=None`）：`core={'那刻夏':1,'刻律德菈':2,'花火':2}`；`support={'星期日':2,'昔涟':1,'风堇':2,'知更鸟':3,'寒鸦':3,'白露':3,'镜流':3}`；`faction_core={'连击':6}`；`faction_bonus={小小巨人,治疗,云上五骁,追击,奇兽花园,开拓银轨}`；`equip_assign={'那刻夏':['火力风暴潮', EquipPool('反螺旋舞步','火力风暴潮'), '梦境交织星徽', EquipPool('高周波电锯','碎星斩舰刀','斩首行动','动能激发剑')], '刻律德菈':['电磁弹射器'], '昔涟':['永动机'], '花火':['蓄能帆','连击星徽']}`；`need_star={'那刻夏':3}`；`char_positions={'那刻夏':'front@1','刻律德菈':'back@1'}`。
- 阶段 2（`enter_when=('equip','梦境交织星徽')`，锁轴形态）：`faction_core={'连击':6,'梦境交织':3}`；`support` 增补舞伴方向（大丽花/黑天鹅）；其余同阶段 1。
- 勉强点（已消化）：「追三线 vs 2 星即用线」是同 build 的节奏变体不拆条，`need_star={'那刻夏':3}` 承载主线口径，速升线由策略降级；知更鸟永动机代持→昔涟转交按 P8 归运行时。

### 6.2 砂金·戏浪·千星（B4）——**装得下（带注记）**

落库：单阶段。`core={'砂金·戏浪':1}`（收尾输出点）；`support={'真珠':1,'爻光':2,'知更鸟·晴歌':2,'托帕&账账':3,'翡翠':3,'星神★阿哈':2,'千冶·刃':3}`；`faction_core={'千星商会':6,'欢愉':3}`；`faction_bonus={幻月游戏,追击,小小巨人,守护,召唤}`；`need_star=六名千星成员全 3`（与 STAR3 计数耦合——每张三星直接兑换一层羁绊 [图鉴]）；`equip_assign={'砂金·戏浪':['火力风暴潮','高周波电锯','未唱名面具'], ...}`。
- STAR3 口径由 `count_mode` 分派承接（零三星全档不亮、佩徽三星非成员计数、开拓者佩徽凑第 6 档结构佐证）——校验 V4 的 STAR3 分支与耦合警告正好覆盖。
- 注记（接受损失）：B4-b 弃阿哈纯经济形态（4/9 局）按 P5 帖量不拆，归 final_comps 文档层；「千星 5 档特权卡换特权版装备」是运行时升级动作（Pool 语义都不必用——目标配方按普通版登记，特权版到手替换归策略）。

### 6.3 刃·三甲反击（D1）——**勉强**

落库：2 阶段，装备触发转型的正面案例。
- 阶段 1（`enter_when=None`，甲未成）：`core={'刃':1,'风堇':1}`；`faction_core={'小小巨人':3,'治疗':2}`（**注意：反击档位不在此阶段**——甲未到手时反击成员只有刃一人，档位未激活，这也解释了「三甲到手才转反击」）；`support={'缇宝':2,'千冶·刃':3,...}`。
- 阶段 2（`enter_when=('equip','幻造巨铠')`）：`faction_core={'反击':2,'小小巨人':3,'治疗':2}`（反击成员成为采购方向：符玄/万敌/克拉拉）；`equip_assign={'刃':['幻造巨铠','幻造巨铠','幻造巨铠'], ...}`。
- 勉强点（真实损失）：①阶段 1 的档位目标（巨人 3 + 治疗 2）是从打法叙事反推的，帖间没有明写「甲前板子的档位目标」——登记判据弱，落库时需人判定；②单核六壳只登主壳 A（反击+巨人标准壳），壳 B-F 的 `faction_core` 级差异（云五 5 / 旅人 8 / 梦境转）按帖量归文档层挂起——结构能装（再开条目即可），本批不装；③「甲齐 = 速 9 信号」是节奏知识，正确地留在策略层，但意味着 schema 读者看不到这条线的经济拐点。

### 6.4 遐蝶·黄金大饭店线（F-遐蝶）——**装得下**

落库：单阶段。`entry_gates=[('菜单含','蝶豆糕')]`（p30 决策树硬门槛：没有蝶豆糕不建议玩遐蝶）；`core={'遐蝶':1,'昔涟':2,'风堇':2}`；`support={'长夜月':1,'知更鸟':3,'万敌':3,'白厄':3,'不死途':3,'缇宝':3}`；`faction_core={'召唤':6,'黄金大饭店':4}`（两羁绊成员恰 6+4 人，点名覆盖大半，凑件压力小——校验 V4 易过）；`faction_bonus={奇兽花园,治疗,小小巨人}`；`equip_assign={'遐蝶':['蝶豆糕','高周波电锯','热血沸腾拳','未唱名面具', EquipPool('杀红眼','碎星斩舰刀','斩首行动')], '长夜月':['星航履', EquipPool('生命之环','追逐星辰')], '昔涟':['永动机','迷境烤红薯','信心注入器'], '风堇':['生命之环','生命之环','绝对热量'], '不死途':['行星钻地弹','黄金大饭店星徽']}`；`need_star={'遐蝶':3}`；`char_positions={'昔涟':'front'}`。
- 招牌菜体系装得下的原因：菜 = 装备注册表「餐品改件」类实体，按装备正常入配方（蝶豆糕给遐蝶、烤红薯给昔涟）；「仅供饭店角色穿戴」的资格由注册表原文承载；菜单门槛由 `entry_gates` 承载；饭店星级成长（追星级=喂强菜）是运行时正反馈，不进字段。装备分流规则（未唱名面具给遐蝶和昔涟）撞「唯一装备」校验 V6——按目标态只登遐蝶一人，正确。
- 勉强点（已消化）：白厄不当 C 时救世烩面代持、景元代穿遐蝶装——P8 运行时；治疗星徽流（p19）= 变体归文档。

### 6.5 开拓银轨·瓦尔特线（E）——**勉强**

落库：三分支拆条（瓦尔特 42 篇 / 姬子 21 篇 / 帕姆王 5 篇——引擎全同、成型标志不连续，帕姆王硬截止独立成段 [R11 归并裁定]）。
- 瓦尔特线单阶段：`core={'瓦尔特':1,'三月七':2}`；`support={'星期日':2,'花火':2,'知更鸟':3,'缇宝':3,'白露':3,...}`；`faction_core={'开拓银轨':2}`（商店开张档即身份档）；`faction_bonus={连击,小小巨人,群攻,能量,星核猎手}`；`need_star={'瓦尔特':3}`；`equip_assign={'瓦尔特':['火力风暴潮', EquipPool('火力风暴潮','高周波电锯','冷笑话引擎','碎星斩舰刀')], '知更鸟':['永动机'], ...}`。
- 姬子线 2 阶段（阶段 1 ≈ 瓦尔特线单阶段的复刻，阶段 2 `('char','姬子·启行')` 转型）：`faction_core={'开拓银轨':6,'能量':4,'双龙吟':2}`；`need_star={'姬子·启行':2}`。帕姆王线单阶段：`faction_core={'开拓银轨':10}`。
- 勉强点（真实张力）：①**经济引擎语义弱**——`faction_core` 在战斗线上是「质变档」，在银轨上是「商店档」，瓦尔特线的成型判据实际是三星瓦尔特+双拉条+风暴潮层数（星级与装备，不是羁绊档）；若策略层把成型判定统一押在 `faction_core` AND 上，本线会误判（登记银轨 2 可缓解为「过早成型」而非「永不成型」，但成长档 L4/L6 的知识无处放，只能归文档）。②双龙吟 2 档 = 饮月一人达成（召唤物计数特例），校验 V4 需特例白名单——结构性特例 +1。③姬子线阶段 1 复制瓦尔特线知识，双份维护。④「追星靠商店白嫖不靠 D 牌」的星级供给通道差异，`need_star` 只管目标不管供给——供给归策略（这条对 bot 行为差异不小，风险 §7.5）。

**汇总：装得下 3（A1 / B4 / F-遐蝶），勉强 2（D1 / E），失败 0。**两个「勉强」的根因不同：D1 是登记证据弱 + 拆条取舍损失；E 是字段语义（档位=身份）在经济引擎类阵容上天然不贴。

## 7. 结构风险（本方案最薄弱处，按危害排序）

1. **`faction_core` 的「成型档」语义在经济/成长型羁绊上失真**（E 线暴露，B 族幻月/欢愉同病）。字段把「身份档」与「成长档」压成一个数：登低档 → 高档知识丢失；登高档 → 成型误判。当前方案用「登身份档 + 高档归文档」缓解，但这意味着策略层对银轨 L6 专票、欢愉 5/6 档阿哈升星这类成长激励视而不见。若实跑发现策略因此卖错人/停错手，可能被迫加「成长档」字段——字段数膨胀的第一嫌疑。
2. **阶段拆分判据（「名单或核心档位结构性变化」）在边界案例上不硬**。A1 锁轴我拆了阶段 2（梦境 3 档入 core），但同样「装备到手、形态升级」的 B1 连击狼（峰 B，4 帖）却按 P5 归变体不拆——判据一致（帖量），直觉上仍会有争议。拆分标准需要对抗审裁出一个可执行的边界（例如「阶段切换条件必须出现在 ≥N 帖的转型叙述里」）。
3. **`core`/`support` 的让位序是手编弱标尺**。帖间证据常只给局部序（「回血顺位白露→藿藿」「空位优先序飞霄>花火>…」），全序是登记者的拼装；版本重跑时局部序变了，全序没人知道该改哪。缓解：默认同级平权，只在有帖证处分级——代价是人口紧张决策的分辨率低。
4. **挂着 [社区] 待实机机制的字段语义可能漂移**：菜-人映射与菜单门槛（config 无菜-人字段，逐帖零例外但待实机终证）、佩徽三星非成员计数（帖 6 结构佐证）、欢愉阿哈载体的实体身份、「奇缘星魂」门槛的存在性。实机取证后这些可能改语义或撤字段——建库校验拦不住语义级漂移，只有 sim/实机对拍能兜。
5. **`need_star` 未列出 = 自然来牌的默认口径，在「星级供给通道」上信息不足**：开拓家族的星来自商店、千星的星即羁绊、DOT 五费明确不追——这些都装下了；但「追三线在几级搜、搜不到何时止损」完全交给策略，若策略层没有等价的节奏骨架，`need_star` 会变成「永远刷不满」的死目标（A1 帖间原话「2-4 找不齐三星就停手」就是止损知识）。这是本方案对策略机制层的最大隐性依赖。
6. **拆条帖量门槛没有量化**：「双强才拆」在 B4（5:4 双形态）、E（42:21:5 三分支）上执行粗糙，低帖量形态归文档 = bot 识别不到该路线（挂点在，数据不在）。挂机奖励流整体独立立批（迭代裁定），本库不留接口字段——若该批落地，需回头检查库组织一节。
7. **过渡库的极简两字段把「组合规则」全部推给策略层**：先选伤害主体、意向同向、结构性组合对（双标签成员顺带激活）都是 transition_combos 的硬知识，本方案一概不落字段（理由：来牌主导的运行时逻辑）。若策略层的过渡选择器没有独立承载这些规则，过渡库两字段撑不起 Q8 之前的过渡期决策——这是「派生优先」原则的押注点。

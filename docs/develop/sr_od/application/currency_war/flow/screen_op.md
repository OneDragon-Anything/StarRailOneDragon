# 画面 op 统一规范(screen_op)

> 术语:**画面 op** = 负责一个游戏画面的一次访问的 Operation(如商店、备战);**外循环** = `cw_loop.py` 的画面识别分发循环;**期望态** = 画面 op 内部维护的「决策所依据的画面状态账」;**终结动作** = 执行后本画面访问即结束、交回外循环的动作。路径根 = `src/sr_od/application/currency_war/`。各画面的具体文档 = [../screens/](../screens/README.md)(一画面一篇);流程↔策略契约 = [README.md](README.md) §2。

## 1. 规范总则

**一次画面 op 调用 = 一轮「入口观察 + 逐动作决策循环」**:

```
画面 op 入口
  ├─ 入口观察(唯一读屏点之一):真实读屏 → 生成期望态(= 入口对账,见 §4)
  └─ 决策循环(循环内零读屏):
       action = 策略器(期望态)          # 商店恰返回一个动作;备战输出取首项
       action.execute(ctx)              # 机械执行,无成败回执(§2)
       落地且非终结 → 容器规则通道逻辑态直写   # game state 独占写(§3)
       if action 是终结动作: break       # 画面 op 结束,交回外循环
```

- **决策循环内不读屏**:期望态的生成与更新都不得依赖读屏;识别质量问题归识别层既有遥测,不进决策循环。
- **策略器全函数**:「无动作可做」的表达 = 直接选终结动作(如关店);None/空批通道不表达控制流(备战域空批 = 「本帧无动作」合法交回,与商店域「空批已由 CloseShop 终结取代」分域表述)。
- **外循环形态不变**:画面识别分发、轮次推进、停机/遥测钩子(`outer_loop.md`)不随本规范改动。

## 2. 动作基类与动作粒度

- **动作 op 基类单方法** = `execute`(机械执行 + 向 game state 上报动作事实;逻辑态由 game state 经 `apply_*` 族独占写入,动作 op 自身不记账)。执行无返回:发出即职责完成,落地判定归观察侧对账;执行异常上抛(框架异常路径,非验证)。动作基类不做任何验证,生命周期不设验证段、不设「验证失败→重试/恢复」分支。
- **动作粒度**:买一张 = 一个 op、卖一张 = 一个 op、买经验一击 = 一个 op(单击 +4XP;升级 = XP 过门槛表结果,非动作)、刷新 = 一个 op。**满栏例外**:板凳满时点合成槽位,游戏机制自动多买至 3 的倍数张(每张原价)——一击多张 = 一个动作 op,逻辑态直写按实际张数计。复合宏动作(整档替换)已全链退役。

## 3. 守卫断言与对账边界

- **合法性判定全部内化于策略器**(提议侧约束);执行侧只余**守卫断言**——防 bug 路栏而非控制流分支,非法返回 = 策略器 bug 响亮暴露(禁静默跳过或降级续跑)。op 框架既有的重试/等待语义属 execute 执行实现层,不算第二道合法性门。
- **两级分型**:`guard_proposal_vs_expected`(提案对象在期望态存在且未被消费——防策略器算术 bug,恒炸);`guard_expected_vs_tracked`(逻辑态 vs 执行侧 tracked 账——逻辑态建模缺陷的在环检测器;多集等价 = WARNING + 按 tracked 真值就地重播种,真分歧 = 炸出)。两守卫零读屏。
- **对账唯一发生点(硬规则)**:对账 = 观察 vs 逻辑的双态比对,唯一合法时点 = **画面 op 上报观察数据进入 game state 的观察边界**(入口观察/reconcile),由 game state 执行比对与仲裁(kernel `cw_reconcile.py`;锚定机制属 game state 层内部实现);**其余任何状态/op 层不做双态比对,也不做店内原地重建**——动作级「发射即登记 + 下一帧对账」不属于双态比对(归观察侧闭环)。

## 4. 终结动作集与恒可用不变量

- **终结动作是一等动作**(决策由策略器主动选择,不是循环逃生口);执行即画面 op 结束、交回外循环。
- **恒可用终结不变量**:每个决策画面的动作空间至少含一个恒可用终结动作——全函数契约在所有画面成立的条件(商店 = 关店、备战 = 开战、单选族 = 确认、等待/切换类 = 推进)。
- **刷新 = 终结的语义自洽**:刷新是唯一引入新事实的动作(新牌面),期望态必须在新事实处重建——终结后外循环重观察正好落在这个点;不需要任何循环内重读机制。
- **终结判定现值**:注册表 op 类 `terminal`/`terminal_wait` 属性,消费点经 `action_op_class_for` 读取(禁消费点私表);终结集总表 = [../screens/README.md](../screens/README.md) §6。

## 5. 期望态生命周期

```
入口观察(重建)──→ 逐动作逻辑态直写(纯计算)──→ 终结(失效)
  唯一真值源          期望态随每个动作落地推进      画面 op 结束,期望态作废,
  (入口观察即对账)    买/卖/升零读屏                外循环下一次入口重建
```

- **入口重建 = 对账**(见 §3 硬规则):对账时机在入口单点,误读暴露延迟到下一画面入口。
- **逐动作逻辑态直写**:买/卖/升 = 确定性纯计算(金/板凳/持有副本/等级),零读屏;转移函数腿逐动作规格 = [../game_state/logic-updates/](../game_state/logic-updates/README.md)。
- **字段未观察态**:在观察态/逻辑态基础上,tracked 账字段取值域含**「未观察」态**——语义 = 无任何观察锚定,值不可消费;与「已观察下的空」(备战席真空席,合法值)类型可分。进入 = 显式失效事件(接管/重置/锚缺失);退出 = 入口观察对账的屏幕真值写回。**策略消费口唯一 = game state**;执行侧 tracked 记录 = 执行簿记,与对账无关,不设面向策略的读口。策略默认实现 = 商店开遇未观察 → 返回关店(恒可用终结动作)→ 外循环全分支重判落回备战 → 入口观察锚定后再进店;未观察跳过的商店访问留遥测分键,「关店→备战→再进仍未观察」连续循环 = 锚定失败显式失败出口,禁静默重试。
- **信任域 = 本画面 op 生命周期**:循环内无失败处理分支——「动作无效」只可能源于入口误读,循环内不可检测也不需处理。
- **读屏点只剩两个**:画面 op 入口(期望态生成)与终结后交回外循环(= 下一次入口观察);决策通道与读屏解耦(识别抖动不进决策)。

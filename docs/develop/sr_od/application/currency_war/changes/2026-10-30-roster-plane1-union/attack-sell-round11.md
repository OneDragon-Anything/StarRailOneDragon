# 卖出场景块无前提对抗报告（第十一轮：十轮处置复核 + 推判鸭子面板/次末位流/launch_gate 实现面专项 + 全量一致性）

## 结论（阻断）

**阻断**：2 阻断 + 3 中 + 3 低。两个阻断项全部落在**十轮处置的核心交付物**上——推判的唯一判据（S10-1「完整重放的结果本身」）所依赖的鸭子面板构造（S10-2 处置定稿）在两个域上各有一个结构性错误，使推判对八轮 S8-2 白卖带的主路径实际测不出：

- **S11-1**——鸭子面板 **deployed 域**构造（席位语境 =「复用评估步 3 搜索结果」）与推演目标反事实（「售 V + 提位 + 购 X 后」）结构性矛盾：步 3 搜索的输入 = 快照 + X（design.md:62 步 2/3），victim 在步 6 才定——**步 3 定型不可能含售 V 效应**。同一括号里 bench 域按「售 V + 提位 + 购 X」虚拟、deployed 域按「+ X 未售 V」虚拟，**同一面板两个域取不同反事实基准（自相矛盾）**。S8-2 主场景（V 为最后线外件 → 售 V 翻 load_bearing_full）的翻转恰由售 V 触发——面板不含售 V 效应则翻转测不出 → 推判失效 → 白卖带主路径开放。修复陷入三难：复用步 3（板面错）/ 手搓提位（违 S10-1 刚立的「禁手搓」）/ 再跑搜索（违「零额外搜索」申报）。
- **S11-2**——鸭子面板 **bench 域**构造（「虚拟售 V + 提位 + 购 X 后」）把 X 放进 bench：plan_available = has_deployable(bench, …)（cw_launch_admission.py:190-192，has_deployable = select_deployments_reasoned 判空，deploy_plan.py:444-479）——**X 是要买的牌，主流形态可上（成员件、无同名、cap 有余）⟹ 含 X bench 恒有可上者 ⟹ plan_available 恒 True ⟹ ¬deploy_plan_available 恒 False ⟹ plan 翻转路径在重放中仍结构性不可达**。十轮 S10-2 处置「plan_available 重放由此可达」名存实亡——与它想修的 S10-2② 缺口（「真实 bench 有件可上 → plan 恒 True」）同构复发，只是把「真实 bench 的件」换成「虚拟加入的 X」。附带时点错置：armed 的真实消费时点 = 买 X 帧（flow.py:802 每帧现算 launch_restricted_session_active，该帧 X 未购入、板面/bench 均无 X），面板金位取「花后」（闸式口径，对）而板面/bench 取「购 X 后」——**同一面板两个维度取不同时点**，偏差方向一致指向漏拦。

另有十轮处置**虚报二连**（S11-3）：S10-6（跨批依赖登记）与 S10-7（半途板面申报）处置记录声称「已修」，design.md 全文 grep 零命中——同一申报（S9-8 → S10-7）三轮两虚报，十轮处置 9 项中 2 项虚报。

裁定不翻案（升级凑金删除 / 统一获取让位 / 意图槽全套 / 凑息豁免 / 等钱帧凑息照常 / 拦因分键 / 非受限前置 / bridge 让位谓词 / 推判 = 完整重放**方向** / victim 级拦截**方向** / launch_gate 双维解拦**方向**，均不再攻）；攻击面全部落在十轮处置的落文真伪、推判建模写法与实现面。

## 发现清单

### S11-1｜鸭子面板 deployed 域构造与推演目标反事实结构性矛盾：「复用评估步 3 搜索结果」不含售 V 效应（步 3 输入 = 快照 + X，victim 步 6 才定）——同一括号内 bench 域按「售 V + 提位 + 购 X」虚拟、deployed 域按「+ X 未售 V」虚拟；S8-2 主路径（售 V 翻 load_bearing_full）在重放中测不出，修复陷入三难
- 攻击点：十轮 S10-2 处置落文（design.md:65）：「重放输入 = 鸭子面板全列（……GameState 形状虚拟对象 = deployed〔虚拟完成板面〕+ bench〔虚拟售 V + 提位 + 购 X 后〕……）；构造按语境（席位 = 定型板面〔**复用评估步 3 搜索结果，零额外搜索**〕；纯金 = 当前 − V + X 虚拟购入）」。三个子面：
  **① deployed 域不含售 V 效应**。步 3 搜索的输入 = 步 2 虚拟阵容 = 「快照 + X 置入备战位；升星连锁模拟」（design.md:62）——**不含售 V**；victim V 在步 6 才判定。步 3 定型产出 = 「当前 + X」的最优板面：V 若为场上件，V 在部署候选池中，是否留在定型板由**部署评分**决定——而 V 的身份是**统一卖出序**末位，两序不同构（S8-2 场景的 V = 线外件，在部署评分下完全可能被保留上场或挤回 bench）。售 V 的三效应——V 从容器移除、退金、提位链（bench 件上移改变 deployed）——在步 3 产出中**全部缺失**。推演面板的括号自述目标却是「售 V + 提位 + 购 X 后」。
  **② 同一面板两域反事实基准自相矛盾**。bench 域括号明写「虚拟售 V + 提位 + 购 X 后」（承认提位发生——提位会改变 deployed，上移者进板）；deployed 域却复用不含售 V/提位的步 3 定型。同一 GameState 形状虚拟对象的两个域建立在互斥的反事实上：bench 假设了提位链、deployed 假设了无提位（且 V 未售）。这不是与外部真值的偏差，是**面板定义的内部矛盾**——实现者无法同时满足两域的字面构造。
  **③ S8-2 主路径测不出 + 修复三难**。八轮 S8-2 场景的 armed 翻转机制 = 「V 为最后线外件 → 售 V 使 occupied 单减 → line_weight ≥ occupied → load_bearing_full True」（cw_launch_admission.py:199；承重件被售 line_weight 与 occupied 同减不翻转，九轮封闭性推导）。面板 deployed 含 V（或 V 被挤回 bench 而板面维持含线外件的另形态）⟹ 板面线外件数不因售 V 减少 ⟹ load_bearing 翻转测不出 ⟹ 推判判 armed=False 放行 ⟹ 售 V 执行 → 级联 → 回店 armed=True 受限 → 花后 < g* 撞闸 → **V 白卖、X 丢货架（八轮阻断行为经推演输入缺口原样开放）**。修复三难（十轮 S10-2③ 三难在新定稿下再现）：复用步 3（板面错，本项）；手搓 −V + 提位（违 S10-1 处置刚立的「推判 = 完整重放、禁手搓单判据」精神——提位链本身是 select_deployment 的产物）；再跑「当前 − V」搜索（与「零额外搜索，成本申报修正」同句申报冲突）。正确形态（净腾同源的「当前 − V」搜索定型 + X 购入效应）需设计内重新裁定并同步成本申报，非落地批可自行裁定。
- 证据：design.md:65（鸭子面板句 + 构造按语境句）；design.md:62（步 2/3 虚拟阵容与定型定义）；cw_launch_admission.py:165-199（deployed/line_weight/occupied/load_bearing_full）；attack-sell-round10.md:61（S10-2 原文③ 三难）/ :135（处置记录）

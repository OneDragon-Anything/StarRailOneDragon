# T-1 交付报告:app 交接节点「退出收尾」(r1)

## 1. 结论

T-1 完成。`CurrencyWarApp` 在「对局循环到结束」后新增「退出收尾」交接节点:两段式(弹窗守卫段复用 `ENTRY_POPUP_GUARDS` 注册表 → exit 调用段 `CwEntryExit`),三形态判定载体 = `self._previous_round_result.status`(大厅完成 / `STATUS_HANDOFF_PREFIX` 前缀 → exit 后置 `ctx.cw_match=None` 兜底清理;max_rounds 停备战 / 假局守卫开局失败-中断 → 跳过退出);fail 形态不经节点(success 边才入,app 失败收尾现状语义)。守卫规格 `EntryPopupGuardSpec` 扩展「领后关闭」两段动作,积分奖励迁入注册表,进局链内联分支删除(守卫在一切状态分支之前,内联不可达)。出口文本常量落 cw_loop 模块级(`STATUS_LOBBY_DONE` / `STATUS_HANDOFF_PREFIX`),loop 大厅出口改用常量成单一源。打桩测试六用例全绿,CW 域回归 241 用例全绿。

## 5. 偏差与未尽事项

### 5.1 守卫迁移实现方案选择(任务书要求的申报项)

**选择:内联段删除,处置语义整体迁入注册表守卫**。备选是「内联段改调注册表守卫」,弃选理由:守卫调用点(`advance_to_prep` 顶部)先于一切状态分支,积分奖励迁入注册表后内联分支结构性不可达,保留即死代码兼第二测试面(cw_entry_start 既有注释同判据:「零调用死代码兼第二测试面,会遮蔽序位/收敛行为」)。行为等价性:内联版 = 识别→一键领取(可落空)→裸 sleep 1.5s→新帧点关闭→`round_wait`;守卫版 = 识别→一键领取(success_wait=2 覆盖领取动画,框架等待取代裸 sleep)→新帧点关闭→`round_retry`(计入节点预算,有界)。差异两点、均收窄不扩大:①等待从裸 sleep 改框架等待(可被测试加速/停机中断,语义等价);②出口从 WAIT 改 RETRY(WAIT 不计 retry 会无界空转,守卫规格 docstring 既有实证判 WAIT 禁用)。领完弹窗自关/留 X 两形态都由守卫循环重识别收敛(第二段点击落空无害,识别标志持续命中期间逐轮重清),与内联版语义一致。

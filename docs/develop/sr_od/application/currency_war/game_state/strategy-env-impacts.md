## 1. 本篇管什么

投资策略卡与投资环境卡的效果会改写 GameState 字段(金/席位/商店/节点序/免费刷新余额
等)。本篇**逐效果登记**该效果在 state 里的影响,供策略消费与对账。边界:

- 效果的**游戏机制原文**真值源 = 注册表 base 层 `cw_invest_data.py`
  (`PLAZA_AUGMENTS` 等官方文本;数据权限序=base 官方文本>手工 overlay>文档转述,
  先例)。本篇不复述全文,给条目指针。
- 效果的**运行时账本**(在场实例/计数推进)在 effects 域(inventory 方法域),其内容
  语义(计数器模型/生命周期/逐效果规格)归 [effect-domain.md](effect-domain.md);本篇只登记
  「效果 → state 字段」的写入面。
- 注册表与文档的冲突以注册表官方文本为准,漂移显式标注(先例=大裁员 burst 数值反转,按官方卡文口径反转)。

## 2. 条目形状(四槽)

每个已确认条目按四槽登记:

| 槽 | 内容 |
|---|---|
| 官方原文 | 注册表条目指针(卡名/品质/`cw_invest_data.py` 行位;必要时摘原文) |
| 机制 | 该效果在游戏里做什么(触发时点/确定性/随机面) |
| state 影响 | 改哪些字段、走哪个渠道与写入口(observe/write_logic/效果桥/账本方法)、随机面如何收尾 |
| 策略层消费 | 策略器/执行侧拿到该影响后做什么(重估/编排/禁买门等) |

**写入归属判据**([fields.md](fields.md) §5.3,玩家裁定):效果结果**可准确计算**(确定性公式+已知
输入)→ 逻辑写(`write_logic` 直写);含**概率/随机**、结果不可预知 → 不建
逻辑写入方,交由观察收尾(observe 覆盖)。每槽结论以最弱一环的证据强度为准。

   确定性。

## 0. 术语（全篇首次出现即定义）

- **阵容条目（Comp）**：一条可被策略层独立选择、独立判定成型的终局构筑路线。互斥的两条强路线 = 两个条目（拆条判据见 P5 与 §5 校验 V8）。
- **目标态快照**：一份「场上应该长什么样」的清单（哪些人在、哪些羁绊档亮、装备在谁身上、星级到几）——**不含**「什么时候做、按什么顺序长过来」。
- **阶段（Stage）**：目标态快照的一个版本。阶段切换由**状态条件**触发（某人到场 / 某装备到手），不由时间或回合数触发。阶段的辖域从「选定该线」起算——选线之前的打工板面归过渡库，不进任何终局阶段（见 P1）。
- **档位**：羁绊激活层数（羁绊注册表 `layers[].layer` 的取值，如连击 2/4/6/8）。
- **计数口径**：一条羁绊「档位怎么算出来」的判定方式。本方案按注册表分派四种（§2.0），是消费与校验的隐式契约，不进字段值。
- **身份档 / 追求档**：身份档 = 该阵容「是谁」的羁绊档（成型判据用，登 `faction_core`）；追求档 = 同一羁绊或副羁绊继续往上追、达到即停的档（不进成型判据、但有采购方向价值，登 `faction_ceiling`）。
- **点名**：在字段里直接写角色名（区别于按羁绊派生的凑件）。
- **凑件**：只为凑羁绊档位而上场的人，不承担该阵容的取胜机制；由公共凑件表按羁绊给候选，不在条目里逐个点名。
- **拿掉检验**：登记判据——假想把某人拿掉：取胜机制不成立 → 机制角色（core）；机制仍成立但强度明显掉档 → 核心辅助（support）；换个人羁绊照活 → 凑件（不登记）。
- **让位序**：名单里的整数优先级，小值优先保留，同值平权。用途：人口紧张时先卖谁、先保谁。
- **成型**：策略层停止为该条目做**定向搜牌与凑档采购**的判据状态。消费契约（Q7）：成型只停这两件事，星级、装备、商店投入不受此门控——防止经济线被「成型即躺平」误杀（§6 案例五）。
- **D 牌**：花金币刷新商店搜卡（社区叫法）。
- **打工**：过渡期临时顶输出位/装备位，后期卖出或交装。
- **星徽**：装备注册表「星徽」类（21 件），效果为「装备者加入【X】羁绊」[图鉴]——装备可参与羁绊计数。云上五骁与少女乐队无星徽条目（注册表级发现：21 件星徽覆盖其余 10 个阵营羁绊与全部 11 个流派羁绊，独缺这两个）。
- **载体**：装备的穿戴者。大多是购买角色；少数是不可购买实体（饮月的绑定随从丹恒·腾荒走角色注册表 `is_hide=True`；欢愉羁绊召唤的阿哈走库级白名单，与可购买的星神★阿哈是两个实体、装备栏各自独立）。
- **主套**：帖间主流的装备配方。A/B 双套装备（云璃充能带/攻击带、克拉拉攻击带/战技带）、特权版满配不进 schema——前者是变体或降级路径、后者是运行时升级动作，目标配方按主套普通版登记。
- **保值件**：跨阶段值得提前合成的成品装备（火力风暴潮/永动机类），库级常量承载。
- **出口站**：过渡线的停手判据（派生三件套：羁绊档达 + 引擎件 2 星 + 保值件 ≥1）。
- **位面 1/2/3**：游戏的前期/中期/后期三段（Early/Middle/Final）。只出现在叙事里，不作任何字段值。

## 1. 设计原则

知识切三层：**进数据（本 schema）** / **留给策略层运行时** / **归文档层（final_comps 各篇，唯一源）**。

### P1 数据 = 状态条件触发的目标态快照；一切时间过程归策略层

阵容知识里最大的一块是「过程」：搜牌节奏（5 级搜牌 / 速升 8 / 速 9）、经济纪律（卡 50 金利息、每轮至多 D 两次）、时序（2-7 速 8、3-3 搜昔涟）、梭哈点（B4「第 4 名千星成员三星时」）。这些**全部不进 schema**。理由：它们是「玩家按当前状态做的决策」，不是阵容的属性；同一套那刻夏班底，追三线卡 5 级、速升线直拉 9，人没变——变的只有节奏。节奏由策略机制层（等级-经济骨架）+ 阵容目标态组合涌现；手编时间表有整块死掉的先例（`level_plan`，方法论 comp-definition.md 第一原则）。

**例外——阶段切换是状态条件，不是时间表**：同一套阵容里存在「骨架升级」的分叉点（三甲到手才把反击档立起来 / 商店刷出姬子才转型 / 梦境星徽到手进锁轴形态）。阶段用 `enter_when`（某人到场 / 某装备到手）表达，描述的是**两个目标态之间的切换条件**，仍是快照语义。

**阶段辖域边界**：Comp 的阶段从「选定该线」起算。选线之前的板面（前期打工组、过渡羁绊壳）是过渡库的辖域——A2 镜流线的「1 费连击前台打工组（带镜流的装备打工，后期卖掉换钱）」不是镜流线的阶段 1，它就是连击过渡线本身。这条边界是校验 V8「名单只增不减」不误杀合法退役的前提。

### P2 名单按功能分两层；第三层不点名（派生）

19 篇的骨架节结构同构：**具名核心**（功能链角色，不可替换）→ **功能链常驻**（各占一环）→ **自由槽**（带标签即坐）。对应：

| 文档层语言 | schema 层 | 登记判据 |
|---|---|---|
| 具名核心 | `core` | 拿掉检验：拿掉后取胜机制不成立 |
| 功能链常驻 | `support` | 拿掉后机制成立、强度掉档；或帖间高频在场的引擎件/死穴解药 |
| 自由槽 | **不设字段**——由身份羁绊档位 + 公共凑件表派生候选 | 「带标签即坐」说明无人格依赖 |

不按「重要度」分层（主 C 与他的标记引擎同为核心），按功能拓扑分层。纪律：**拿掉检验按机制判，不按出场率判**——H1 千冶·刃 91% 出场但有例外帖（dot 特化流不带），登 support 不登 core。

### P3 派生优先：能推导的不登记

- 凑件候选 = 羁绊注册表成员 − 点名者，顺序由公共表给；不逐条目登记（少女乐队因恰好值计数禁用凑件，见 §2.0）。
- 过渡班底 = `bond` 成员 ∩ 费用 ≤ 2 − `engine`（本稿按注册表费用独立复跑三条体系线验证：连击线派生 {刻律德菈, 星期日, 白露}、持续伤害线 {黑天鹅, 桂乃芬, 海瑟音, 娜塔莎}、银轨线 {三月七, 瓦尔特, 星期日}，均与 transition_combos「人员要求」列吻合；其余六线沿用第二轮评审的全量复跑结论，仙舟线第 4 人需 3 费位为已知下界缺口，策略按商店等级补）。
- 巡海游侠任命目标 = 当前阶段 `core` 中让位序最小者（19 篇任命无一例外给主 C：那刻夏/遐蝶/黄泉/飞霄/雪衣/绯英），不设字段；为此立落库纪律：主 C 让位序必须全名单最小（双 C 制把终盘主 C 排更小，如 A4 阿格莱雅 1、那刻夏 2）。
- 反击王 = 装备最多的前台反击角色（羁绊注册表原文定义），由装备配方 + 站位派生。
- 唯一装备集 = 装备注册表 effect 含「（唯一装备）」的条目（蓄能帆/星航履/未唱名面具/绝对热量及各自特权版，共 8 件），校验期从注册表派生，不手编清单。
- 星徽→羁绊映射 = 装备注册表 effect 原文派生，不建表。
- 「6 反击必须有反击星徽」这类可行性事实 = 点名人数与档位差的算术（反击原生成员恰 5 人 [图鉴]：万敌/云璃/克拉拉/刃/符玄），由建库校验 V4 提示，不设门槛字段。

### P4 消费先行：字段必须挂在一个真实消费点上

策略层对阵容库的八个消费问题（§6 逐条对账）：**选线 / 采购 / 卖人 / 装备合成与分配 / 星级停手 / 站位 / 成型判定 / 过渡出口**。没有消费面的知识不设字段——本稿据此**不设**：家族谱系字段（选线不需要家族查询，谱系归 final_comps 索引）、降级路径字段（运行时按缺件自适应）、开局信号/词条吃怕/投资亲和字段（策略层旁表已有，且多数属 [社区] 待实机）、过渡线静态优先级字段（选过渡线的主判据是来牌状态，静态占比随版本重跑变化快）、上场时机字段（部署自适应的冗余约束，先例 `entry_signals` 已按用户终裁退役）。

### P5 互斥拆条；变体与降级不拆

**结构判据（机器化，校验 V8）**：切换前后名单或身份档位有实质减换（重构）→ 互斥拆条候选；名单只增不减且档位非降（加法升级）→ 同条目内拆阶段。
**帖量判据（登记带，本稿成文）**：结构判为重构的互斥形态——
- 双方簇内占比均 ≥ 1/3 → 都立条目（A3 景元双峰 10/14 帖、H1 黄泉双峰 20/15 帖、E 开拓三分支 42/21/5、C 击破双节奏线 20/18）；
- 一方占比 < 1/3 且帖量 < 5 → 主形态立条，其余在 final_comps 篇内挂「待帖量增长立条」（D1 单核六壳只登标准壳 A、B2 五峰只登主流峰）；
- 帖量 < 5 但占比 ≥ 1/3（小样本高占比，如 B4 双形态 5:4）→ 不静默挂起，列为落库批显式裁决点。
装备面/节奏面的变体（A1 巨人变体、云璃两条带）、降级路径（三甲不齐→双甲+风暴潮）不拆，归文档层与策略自适应。带子是默认值，落库批可人判偏离但须记录判读理由。

### P6 特殊系统默认不进 schema；例外只收硬门槛

拜师、改装树、白厄吃人、双龙吟复制、奇美拉招聘、阿哈装备栏、饭店星级成长、幻月规则局、升费链——这些是「策略侧将来立项的执行知识」：要么可派生（任命目标 = 主 C），要么是运行时操作序列（吃谁、招哪只奇美拉、选哪个改装），schema 不为它们设字段；需要近似时用「把对应角色的优先级抬高」承载。
**例外**：不可从注册表派生、且帖间一致认定为「没有就不玩 / 账号限定」的硬门槛收进 `gates`。门槛与偏好的分界线 = 帖间措辞：A3 赌狗峰「没有奇缘星魂不建议玩」= 门槛；H1 黄泉「有奇缘星魂直接锁轴，没有半永久锁轴」= 降级（不登，归策略）。

### P7 只登例外行

星级目标与站位只登「偏离默认」的行：未登星级的角色 = 无追星义务（来牌自然升星，1 星可用，策略不为它花刷新预算）；未登站位的角色 = 用角色注册表 `position` 偏好（common 默认 back，属无知识兜底）。不为「描述性常态」（辅助一般 1-2 星）落字段。

### P8 装备到人不到位置；接力与代穿 = 目标态归属 + 运行时执行

「装备是角色特定的」（到人），配方归属写目标穿戴者。打工代穿（云璃带甲打工→卖掉转万敌、景元代穿遐蝶装）、代持（知更鸟代持永动机→昔涟转交）都是**时间过程**：schema 只记最终归属（甲→刃、永动机→昔涟、输出装→遐蝶），「持有者未到场时由谁临时穿」是策略层通用规则（同线低优先辅助代穿，到位即转移），不设字段。主套 only（术语表）：特权版替换 = 运行时升级动作，目标配方按普通版登记。

## 2. 字段定义

类型记法：`dict[K, V]` 键值表；`frozenset[T]` 无序集；`tuple[T, ...]` 有序元组。角色名/装备名/羁绊名一律用注册表规范名（`·` 归一口径；知更鸟与知更鸟·晴歌是两个角色，近名混用会被校验 V1 拦下）。

### 2.0 计数口径（字段定义的前置契约）

羁绊档位的判定口径从羁绊注册表派生，共四种，是 `faction_core` / `bond` 语义的一部分（不进字段值）：

| 口径 | 羁绊 | 判定方式 | 出处 |
|---|---|---|---|
| 人数阈值（TOTAL，默认） | 其余 27 条 | 上场该羁绊人数 ∪ 佩戴该羁绊星徽者 ≥ 档位即激活 | [图鉴] count_mode='TOTAL' |
| 三星计数（STAR3） | 千星商会（全表唯一） | **场上三星**成员数 ∪ 佩徽的三星非成员 = 层数；零三星全档不亮（B4 帖 10 实证）；佩徽计数为帖 6 结构佐证 [社区 待实机] | [图鉴] count_mode='STAR3' + simple_desc「每上场1位3星【千星商会】角色，激活1级羁绊效果」 |
| 恰好值（EXACT） | 少女乐队（全表唯一） | **恰好** 1 或 4 人在场才激活；2/3 人无效，**超员同样失效**——档位是恰好值不是下限 | [图鉴] simple_desc「仅在上场恰好1/4名【少女乐队】角色时激活羁绊」 |
| 召唤复合 | 双龙吟（注册表尾注特例集） | 激活 = 成员 + 后台召唤物；饮月 1 人即达 2 档（腾荒由羁绊召唤、星级同步、`is_hide` 不占购买位）；其 layer2 语义是「星级决定可穿装备数」而非「凑 2 人」 | [图鉴] 双龙吟 layers + 文件尾注 + v47_tenghuang_binding |

EXACT 与召唤复合是本稿相对前代的显式化增量（前代只分了 TOTAL/STAR3 两种）：EXACT 直接改变凑件语义——G 家族希露瓦线（4 乐队 + 5-7 持续伤害）的真实打法是「火花/乱破先捏在手上，凑齐 4 人一起上」，凑件派生若推荐第 5 人上场会直接熄灭该羁绊。

### 2.1 构件类型（3 个，被字段引用）

- **Cond（状态条件）**：`('char', 角色名)` = 该角色已购入并可上场；`('equip', 装备名)` = 该装备已合成/获得且可穿。用于阶段切换；触发语义 = **一件到手即触发**（D1「1-2 甲低配局也成立」帖证——等三件才转会把低配局卡死）。
- **Gate（成立门槛，统一元组）**：`('命座', 角色名, N)` = 账号本体命座不低于 N；`('奇缘星魂', 角色名)` = 账号持有该角色的奇缘星魂（A3 篇 §7「账号有景元奇缘星魂」表明是账号级持有；效果细节 [社区] 待实机，字段只承载门槛存在性 [米游社]）——两类为**账号级**，每账号评估一次；`('菜单含', 菜名)` = 本局今日菜单含该招牌菜——**局级**，每局开局评估。用于条目级过滤。
- **EquipPool（装备候选池）**：`tuple[装备名, ...]`，有序候选、取一。表达「第三件按需：电锯/斩舰刀/斩首/动能剑」（A1）这类攻略明确给候选但不定死的槽位。只表达单槽位级候补，不表达整套 A/B 配方（主套 only，P8）。

### 2.2 条目级字段（Comp，3 个）

**1. `name: str`**
- 语义：条目唯一名，人读标识 + 库键。
- 登记判据：一条按 P5 拆定的独立构筑路线；命名携带家族与形态语义（家族词 + 主 C + 形态词），家族组织本身不进 schema。
- 默认/空值：必填，无默认；库内唯一（校验 V1）。
- 案例：`'反击·刃三甲'`（D1 刃·三甲反击）；`'连击·那刻夏'`（A1）。

**2. `gates: tuple[Gate, ...]`**
- 语义：条目成立门槛，AND 语义，任一不满足即本条目对该账号/该局出局——与「评分偏好」（开局信号、词条吃怕，归策略层）的分界就在这条线。
- 登记判据：① 不可从注册表派生（克拉拉线的反击星徽依赖可由「反击原生成员 5 人 < 6 档」算出，V4 自动提示，不登记；反击星徽本身是局内合成物——蓝钻+和平手枪 [图鉴]——「持有它」属运行时状态，归策略层开局信号）；② 帖间一致认定为「没有就不玩 / 账号限定」[米游社]；措辞为「没有则降级仍可玩」的不登（H1 黄泉奇缘星魂）。
- 默认/空值：`()` = 无门槛，任何账号任何局可选。
- 案例：遐蝶线（F 篇 p30 决策树「没有蝶豆糕不建议玩遐蝶」）`[('菜单含', '蝶豆糕')]`；风堇马头流（F 篇 §11「仅推荐满魂风堇」）`[('命座', '风堇', 6)]`；A3 赌狗峰 `[('奇缘星魂', '景元')]`；H4 连击循环流（「前提不满足=不玩，判据最硬的流派」）`[('奇缘星魂', '丹恒·饮月')]`。

**3. `stages: tuple[Stage, ...]`**
- 语义：有序阶段列表；执行语义 = 取 `enter_when` 已满足的**最末**阶段为当前阶段，策略只按当前阶段行动。无梦转局的 A1 停在阶段 1 成型，不会误杀。
- 登记判据（什么时候拆阶段）：**加法升级 = 阶段**——新阶段名单 ⊇ 旧阶段名单（core/support 只增不减，成员可降层 core→support 但不离名单）、身份档位目标非降、切换由状态条件触发 [米游社]；**重构 = 拆条候选**（P5）。辖域边界见 P1。
- 默认/空值：单阶段列表（大多数条目；如 B4/F-遐蝶/E-瓦尔特）。
- 案例：E 姬子线 2 阶段（商店刷出姬子转型，瓦尔特降层 support 仍在名单）；D1 刃·三甲 2 阶段（甲到手转反击）；A1 那刻夏 2 阶段（梦境星徽到手进锁轴）。

### 2.3 阶段级字段（Stage，8 个；每阶段完整登记，无跨阶段继承——差集由消费方现算）

**4. `enter_when: Cond | None`**
- 语义：本阶段的进入条件；`None` = 首阶段（条目被选中即生效）。
- 登记判据：帖间明确的转型触发（「拿到幻造巨铠再转反击」→ `('equip', '幻造巨铠')`；「列车商店刷出姬子就买，老杨退居后排」→ `('char', '姬子·启行')`）。多触发路径登主路径（A1 锁轴登梦境交织星徽；次路径「逐日光环」属投资层道具、不在装备注册表，值域是否扩投资系统待投资建模批次后再裁——待定问题，见 §8）。
- 默认/空值：`stages[0]` 必为 `None`（校验 V8），其余阶段必非 `None`。
- 案例：`('equip', '幻造巨铠')`（D1 阶段 2）。

**5. `core: dict[角色名, int]`（机制角色 + 让位序）**
- 语义：取胜机制的承担者，AND 全必要（缺一即机制不成立）；值为让位序（小值优先保留，同值平权）。
- 登记判据：拿掉检验（P2）；「具名核心（不可替换）」节 [米游社]。过渡 C 在换 C 型条目的早阶段以机制身份登记（E 姬子线阶段 1 的瓦尔特）。落库纪律：**主 C 让位序必须全名单最小**——巡海任命派生锚点；双 C 制把终盘主 C 排更小（A4：阿格莱雅 1、那刻夏 2）。
- 默认/空值：必填非空（没有机制角色的条目不存在）；让位序无帖间证据时全员同值。
- 案例：A1 那刻夏·连击 `{'那刻夏': 1, '刻律德菈': 2}`（输出轴 + 标记引擎；花火「低配局首个可舍弃位」帖证直接判 support）。

**6. `support: dict[角色名, int]`（核心辅助 + 让位序）**
- 语义：功能链常驻——放大机制的引擎件（拉条/充能/治疗/经济）或机制死穴的解药；拿掉机制仍成立、强度掉档。值为让位序；人口紧张时大值先让位。
- 登记判据：「功能链」节帖间高频在场者 [米游社]；让位序登记帖间补位/卖出证据（「缺人口上藿藿，缺伤害上寒鸦」→ 寒鸦序小；A1 白露「中期被风堇换掉」→ 白露序大）。
- 默认/空值：`{}` 允许（极简凑档线）；跨阶段可变，**阶段名单差集 = 退役卖出候选**（消费 Q3）。阶段内轮换（白露→风堇发生在阶段内部）不归名单管——名单是目标态并集语义，不是「全员必须同时在板」。
- 案例：D1 刃·三甲 `{'昔涟': 2, '缇宝': 3, '符玄': 3, '千冶·刃': 3, '罗刹': 3, '白露': 3, '藿藿': 3, '万敌': 3}`（昔涟 = 点火钥匙——永动机刚需；其余为反击层数成员与第二治疗轮换）。

**7. `faction_core: dict[羁绊名, int]`（身份羁绊 + 成型档）**
- 语义：身份签名羁绊及成型档位；AND 语义——全档达标 + `core` 点名在板 = 该阶段成型（Q7）。计数按 §2.0 四种口径分派。
- 登记判据：帖间「标配 / 成型判据 / 身份签名」的羁绊档（F-遐蝶「主流成型板 = 6 召唤 4 饭店」）；档位必须 ∈ 注册表 `layers` 档位集（校验 V3）。**身份档 ≠ 追求上限**——经济/成长型羁绊的高档知识（银轨 L4/L6、欢愉 5-8、追击 7）归字段 8。
- 默认/空值：必填非空。
- 案例：F-遐蝶线 `{'召唤': 6, '黄金大饭店': 4}`（召唤成员恰 6 人全部点名在板，凑件压力趋零）；B4 砂金千星 `{'千星商会': 6, '欢愉': 3}`（千星按 STAR3 口径 = 三星成员数）。

**8. `faction_ceiling: dict[羁绊名, int]`（认可与追求档上限）**
- 语义：该阵容认可其收益、值得继续向上追的羁绊档位上限——达到即停的采购方向；**不进成型判定**；键可与 `faction_core` 重叠（同羁绊「身份档之上继续追」，重叠时值必须更大，校验 V3）。
- 登记判据：帖间**实证追求**的成长档/副档（E 银轨 L6 专票、H2 追击 7 档天花板、B4 欢愉 5/6 档阿哈形态、A1 连击 8 顶配）；独立羁绊按 1 档登记（巡海游侠 1 = 认可买不死途任命、幻乐之主 1 = 认可阿哈升格方向）。**不登**：配置上限但无成型实录的档（DOT 9 档全批无人成型）；终局目标态不再维护的前期过程档（A1 前期的银轨 2 经济档）。
- 默认/空值：`{}` = 无登记（无追求方向或纯凑档线）。
- 案例：E-瓦尔特线 `{'开拓银轨': 6, '连击': 6, '小小巨人': 5, '群攻': 6}`（银轨 2 是身份、6 是追求，同一羁绊跨两字段各得其所）；H2-飞霄 `{'追击': 7}`（5 档成型、7 档天花板——官方原生成员恰 7 人，45 篇零 10 档实录，「追到 7 为止」有真实停手数据面）。

**9. `equip_assign: dict[载体名, list[str | EquipPool]]`（装备配方，到人）**
- 语义：目标穿戴者的配方清单；**列表内序 = 合成优先序**；同名重复 = 多件（`['幻造巨铠','幻造巨铠','幻造巨铠']` = 三甲）；`EquipPool` 槽位取一。跨阶段同件换主人 = 装备转移（P8：代穿/接力归运行时）。
- 载体键域：本阶段名单（core ∪ support）∪ 库级非购买载体白名单（`OFF_ROSTER_EQUIP_CARRIERS`，字段 16）∪ 注册表 `is_hide` 条目（丹恒·腾荒——双龙吟装备复制的合法载体）。「唯一装备」（注册表 effect 派生集，8 件）全条目至多 1 人 1 件（校验 V6）——F 篇「未唱名面具给遐蝶和昔涟」的分流规则正会撞这条，按目标态只登一人是正解。
- 登记判据：帖间逐件到人且帖间一致的主套配方（「三甲给刃」「永动机给昔涟」「阿哈时刻 3×火力风暴潮」[米游社]）；餐品改件（蝶豆糕/迷境烤红薯等 6 件，装备注册表「餐品改件」类实体）按装备正常入配方，「仅供饭店角色穿戴」资格由注册表原文承载。
- 默认/空值：`{}` = 无登记配方（凑档线）；未列名单成员 = 无目标装备（捡漏归策略）。
- 案例：D1 阶段 2 `{'刃': ['幻造巨铠','幻造巨铠','幻造巨铠'], '昔涟': ['永动机'], '风堇': ['绝对热量','生命之环','生命之环'], '缇宝': ['胜利之旗']}`；B1 银狼线 `{'欢愉阿哈': ['火力风暴潮','火力风暴潮','火力风暴潮'], ...}`（非购买载体白名单用法）。

**10. `need_star: dict[角色名, 1|2|3]`（星级目标 = 停手线）**
- 语义：该角色达到此星级即「星级就绪」，停止为其定向刷新；**未列出 = 无追星义务**（来牌自然升星，1 星可用）。登的是目标上限承诺，不是必达线；追三止损（「2-4 找不齐三星就停手」）归策略层等级-经济骨架。
- 登记判据：帖间明确的追星线（低费追三：云璃/绯英/流萤/海瑟音/那刻夏）、绑定线（D3 云璃线的花火 3 星「不然坠机」——全场唯一写死的辅助星线）、到手线（H4 饮月 ★2 = 腾荒可穿 2 件装备）、全员行（千星成员逐个三星——与 STAR3 计数耦合，每张三星直接兑换一层羁绊 [图鉴+米游社]）。
- 默认/空值：`{}` = 全员自然来牌（装备/羁绊驱动线：D1 不登刃——「一张刃三件甲下限即可 500 亿」；F-昔涟线不登——「装备地位远高于星级地位」）。
- 案例：D3 云璃·追三 `{'云璃': 3, '花火': 3}`；B4 砂金千星 `{'砂金·戏浪': 3, '真珠': 3, '爻光': 3, '知更鸟·晴歌': 3, '托帕&账账': 3, '翡翠': 3}`；H4 `{'丹恒·饮月': 2}`。

**11. `char_positions: dict[角色名, str]`（站位覆盖）**
- 语义：只登有知识依据的行；值域 `'front' | 'back' | 'front@N' | 'back@N'`。**坐标系定义：`@N` = 行内第 N 位，N 从 1 起，与攻略阵容数据的 front_roles / back_roles 列表内序号同源（1 基位次，非几何像素槽位）；取值时机 = 终局目标态，运行时被占/超容由策略软回退。** 未列出 = 用角色注册表 `position` 偏好（front/back；common 默认 back 是无知识兜底，非游戏定义）。
- 登记判据（两类）：① 位次带机制语义的帖间铁律（A1 那刻夏固定前排 1 号位吃连击地格、刻律德菈后台 1 号位专属、F 万敌前排 1 号位吃军功、F 白厄放后排防吃人踢人、F 昔涟固定前台）；② **实证推翻注册表默认的行**（F-遐蝶：注册表 common 默认 back，帖证她是「治疗体系喂出来的前台输出」——必须覆盖为 front；无此判据则注册表错值无人纠正）。
- 默认/空值：`{}` = 全员用注册表偏好。
- 案例：A1 `{'那刻夏': 'front@1', '刻律德菈': 'back@1'}`；F-遐蝶 `{'遐蝶': 'front', '昔涟': 'front'}`；D1 `{'刃': 'back'}`（帖间「刃全程坐后排」口径；与「反击王 = 装备最多的前台反击角色」的注册表张力归 final_comps D1 篇存疑条目，不进字段）。

### 2.4 过渡条目字段（TransitionBond，2 个）

过渡库不复制终局库的字段族：过渡是**状态驱动的添件过程**（「加法不换件、无预设顺序」，transition_combos §8），不适用阶段；装备配方、站位、星级例外、追求档恒空（库级规则，校验 V9）；出口站判据为全库统一派生（P3），不设逐条目字段。

**12. `bond: dict[羁绊名, int]`（过渡伤害线羁绊 + 出口站档位）**
- 语义：这条过渡线的羁绊身份与出口站档位（连击线的出口站是 **4 连击**，不是首档 2——transition_combos §8 实证「出口站=4 连击+2 星那刻夏+巨人 2-3+至少 1 件火力风暴潮」）；`ECONOMIC_BONDS`（字段 17）内的经济线同样入库，但出口由搭档伤害线给出、自身不作出口站主体。
- 登记判据：transition_combos 判据序（首档有伤害源 + 纯 1/2 费层组合实证 + 人员要求分层）立卡的体系线。
- 默认/空值：必填非空。
- 案例：连击线 `{'连击': 4}`；持续伤害线 `{'持续伤害': 3}`；银轨经济线 `{'开拓银轨': 2}`；大黑塔系 `{'群攻': 2}`（单卡线，配 `engine`）。

**13. `engine: dict[角色名, int]`（点名引擎/伤害件 + 让位序）**
- 语义：拿掉则该过渡线不成立的点名件（「点名件在板」语义 = `engine` 全员在板）；班底**不登记**——派生 = `bond` 成员 ∩ 费用 ≤ 2 − `engine`（P3，已验证）。
- 登记判据：transition_combos「人员要求」列——单卡依赖线登该卡（大黑塔线），最佳班底线登引擎件（连击线登那刻夏），纯计数线留空（持续伤害任意三件）。有最佳班底的线可不登（班底已被派生精确覆盖：云五线的景元+白露、反击线的万敌/云璃、能量线的绯英/知更鸟·晴歌）。
- 默认/空值：`{}` = 纯计数线（无点名依赖）。
- 案例：连击线 `{'那刻夏': 1}`；大黑塔系 `{'大黑塔': 1}`；持续伤害线 `{}`。

### 2.5 库级公共表与常量（4 个）

**14. `FILLER_PRIORITY: dict[羁绊名, tuple[角色名, ...]]`（公共凑件表）**
- 语义：每羁绊一张凑件候选优先序；候选域 = 该羁绊注册表成员（终局库消费时再减去各条目点名者）。
- 登记判据：全程留用层统计（stage_transitions §2，1-2 费双标签通用件为主：花火/星期日/刻律德菈/真珠/三月七/瓦尔特…）+ 各篇「自由槽/第三人从谁补」的帖间证据；辅助/工具型优先，**输出大 C 不进表**（防凑件抢主 C 的位置与装备）。EXACT 计数羁绊（少女乐队）**禁建此表**（§2.0——凑件推荐会熄灭恰好值羁绊）。
- 默认/空值：某羁绊无表 = 该羁绊凑件按注册表成员顺序兜底。V4.7 羁绊大换血，全量重定（排序归落库批按证据定，本稿只锁结构）。
- 案例（示意）：`'治疗': ('藿藿', '白露', '罗刹', ...)`。

**15. `CROSS_PHASE_KEEP_EQUIPS: frozenset[装备名]`（跨阶段保值件白名单）**
- 语义：过渡期**唯一允许主动合成**的成品集（「合成装只在跨阶段保值时提前合成，不为过渡特意合成一次性件」，transition_combos §7 [米游社]）。
- 登记判据：帖间公认的跨阶段保值件（终局多线共用、打工位可先用）。
- 默认/空值：非空常量；初值 `{'火力风暴潮', '永动机', '蓄能帆'}`，落库批按帖证增删。消费 = 过渡期合成闸（Q4）+ 出口站「1 件合成装」判据（Q8）。

**16. `OFF_ROSTER_EQUIP_CARRIERS: frozenset[角色名]`（非购买装备载体白名单）**
- 语义：可作 `equip_assign` 键、但不在任何购买名单里的实体；封闭常量，新增需改此表。
- 登记判据：注册表无条目（或非购买）、但帖间存在独立装备栏的实体。V4.7 一例：欢愉羁绊召唤的阿哈（B1「阿哈时刻装备 3×火力风暴潮……与星神★阿哈单位是两个实体，装备栏各自独立」[米游社]；欢愉注册表 simple_desc「备战阶段召唤【阿哈】……可从商店购买【阿哈装备】拖拽给【阿哈】」[图鉴]）。丹恒·腾荒**不经此表**（他在角色注册表内，`is_hide=True`）。
- 默认/空值：`{'欢愉阿哈'}`；空集合法（无此类载体时）。

**17. `ECONOMIC_BONDS: frozenset[羁绊名]`（经济开局线羁绊集）**
- 语义：无自身伤害源、以经济产出为主的羁绊集（transition_combos §5 判据①裁决：开拓银轨「不是伤害主体」，伤害由搭档线供给——统计 ×连击 189 = 经济+伤害的标准开局对）；集内羁绊的过渡条目不作出口站主体。
- 登记判据：transition_combos 判据①的文档结论落库为机器可判常量。伤害源有无**无法从注册表 layer 文本可靠派出**——仙舟舰队 layer2「变化1件简易装备」（无伤害）、layer4「【星槎】基于累计总伤害造成真实伤害」（有伤害）是同羁绊低档无伤高档有伤的注册表实证反例，故人工判定集是正解。
- 默认/空值：`{'开拓银轨'}`；幻月/千星为顺带激活的经济系副档，不立过渡条目、不入此集。消费 = Q8 出口派生的主体判定 + 策略「先选伤害主体」规则的机器依据。

## 3. 库的组织

### 3.1 两库分立

| | 终局库 `COMP_LIBRARY` | 过渡库 `TRANSITION_LIBRARY` |
|---|---|---|
| 条目形态 | `Comp`（字段 1-3 + Stage 族 4-11） | `TransitionBond`（字段 12-13） |
| 阶段 | 允许多阶段（状态条件切换，V8 加法不变量） | 恒单形态（状态驱动添件，无预设顺序） |
| 装备/站位/星级例外/追求档 | 按登记 | **恒空**（库级规则，校验 V9） |
| 锁定语义 | 成型后锁定名单方向 | **永不锁定**（来牌主导，随时换线） |
| 成型/出口判定 | 当前阶段 `faction_core` 全档达标 ∧ `core` 在板（Q7） | 出口站派生：`bond` 档达 ∧ `engine` 2 星 ∧ 保值件 ≥1（Q8）；经济线不作出口主体 |

两库分立的理由：过渡的选择逻辑（来牌主导、意向同向、加法不换件）与终局的目标态逻辑（点名、AND 成型）是两种计算；硬塞一个 schema 会让终局字段在过渡侧大量恒空。**过渡→终局的流向知识**（连击线出口通向 A 家族四篇等）归 transition_combos §8 的指针表（文档层），不建库间引用字段——选终局线是策略运行时评分，不是静态图遍历。

### 3.2 公共表与常量的归属

`FILLER_PRIORITY` / `CROSS_PHASE_KEEP_EQUIPS` / `OFF_ROSTER_EQUIP_CARRIERS` / `ECONOMIC_BONDS` 与两库同模块维护（阵容定义单一源，一个文件）；代码载体 = kernel 侧 comp 模块（`cw_comps.py` 的继任），`@dataclass(frozen=True)`，建库校验（§4）在模块 import 期执行、违例即抛。星徽→羁绊映射不建表（注册表派生，P3）。

### 3.3 版本纪律与挂点

- 库数据随 final_comps 重建批次联动重跑（frontmatter `rebuilt` 对齐）；注册表（羁绊/装备/角色）先行重跑，库校验在 import 期自动拦截版本失配的名字与档位。计数口径（§2.0）随羁绊注册表重跑自动更新——新版本若出现第二个 STAR3/EXACT 羁绊，口径表扩行即可，字段结构不动。
- 家族谱系：Comp 平铺 + 命名带家族语义，不为组织结构引入 schema 层级（P4：无家族查询消费点）。
- 挂机奖励流（13 人全羁绊刷星琼 / 十六羁绊星徽墙 / 翡翠速刷）：目标 = 解锁羁绊奖励非吃分，无成型判定、无搜牌、无装备分配，消费面与吃分线完全不同——按迭代裁定**独立立批**（第三库 REWARD_LIBRARY），本库不留半吊子字段。挂点 = 条目级不设，库外另立第三库的接口位。

## 4. 建库校验（import 期即可查出的数据错误）

- **V1 引用合法**：`name` 唯一非空；所有角色名 ∈ 角色注册表（含 `is_hide` 载体与白名单名；知更鸟/知更鸟·晴歌等近名混用在此拦下）；装备名 ∈ 装备注册表（特权版独立条目，不与普通版混键）；羁绊名 ∈ 羁绊注册表；Gate 的菜品 ∈ 装备注册表「餐品改件」类（6 件闭集）；`gates` 的角色 ∈ 角色注册表。星神★阿哈同名多费档（注册表 4/5/7 三条目）按名字级成员处理，费用档 = 采购知识不在库层区分（正式并键裁定待定，见 §8）。
- **V2 名单互斥**：逐阶段 `core ∩ support = ∅`；跨阶段同人可变层（core→support 降层合法，不离名单）。
- **V3 档位合法**：`faction_core` / `faction_ceiling` / `bond` 的档位 ∈ 该羁绊注册表 `layers` 档位集（连击登 5 = 错，合法档只有 2/4/6/8）；`ceiling[k] ≥ core[k]`（键重叠时）。
- **V4 成型可行性（按 §2.0 计数口径分派；硬查 `faction_core`，软警 `faction_ceiling`）**：
  - TOTAL 口径 = 点名成员中该羁绊人数 + 星徽可补数（星徽集从装备注册表派生；云上五骁/少女乐队/全部独立羁绊无星徽计 0）+ 公共凑件池 ≥ 档位；不足即报错（克拉拉线 6 反击缺星徽即被此条抓出）。
  - STAR3 口径 = `need_star` 中可追三的该羁绊行数 + 佩徽三星名额 ≥ 档位，且 **STAR3 档位 > 三星行数时警告**（耦合漏登嫌疑——B4 忘登翡翠 3★ 即被此条抓出）。
  - EXACT 口径 = 点名人数**恰等**档位（多了少了都报错；该羁绊凑件派生禁用）。
  - 召唤复合（双龙吟）= 档位 ≤ 2 且由成员 1 人达成，跳过人数算术（尾注特例白名单）。
- **V5 人口边界**：逐阶段 `|core ∪ support|` ≤ 13（V4.7 实测最大板面 + 财富宝钻扩容，[米游社] 推断，实机固化——待定问题见 §8）；过渡线 `bond` 档位所需人数 ≤ 5（位面 1 人口压死，transition_combos §1）。
- **V6 装备约束**：`equip_assign` 键 ⊆ 本阶段名单 ∪ 载体白名单 ∪ `is_hide` 条目；「唯一装备」类（注册表 effect 派生集，8 件）全条目至多 1 人 1 件；`EquipPool` 内无重复项。
- **V7 键域收口**：`need_star` / `char_positions` 键 ⊆ 本阶段名单。
- **V8 阶段结构**：`stages` 非空；`stages[0].enter_when is None`；其余阶段非 `None`；`('char', X)` 中的 X ∈ 本条目某阶段名单（否则条件永无意义）；相邻阶段同条件 = 错误。**加法不变量（P5 拆分判据的机器化）**：相邻阶段 i→i+1 满足 (a) 名单（core∪support）只增不减；(b) 每个羁绊的档位（core 或 ceiling 取最大）非降；(c) `faction_core` 键集单调增——违反 = 该处实为重构，应拆条。**V8 拦截 = 显式裁决点**：违例即 import 报错，落库批须记录裁决（拆条 / 辖域归位 / 确认特例并注明理由），禁止为过校验而静默改数据。
- **V9 过渡库恒空与完备**：无阶段字段；`equip_assign` / `char_positions` / `need_star` / `faction_ceiling` 恒空；`engine` ∪ 派生班底 ⊆ 注册表；`bond` 键 ⊆ 注册表；`ECONOMIC_BONDS ∩` 伤害线条目的 `bond` 键集 = ∅（条目级身份单一：一条过渡条目要么伤害线要么经济线；实战「连击×银轨标准开局对」是策略层组合两条条目，不是一条条目双身份）。
- **V10 公共表一致**：`FILLER_PRIORITY` 键 ⊆ 羁绊注册表且值 ⊆ 对应成员，且**键不含 EXACT 计数羁绊**（少女乐队禁凑件表）；`CROSS_PHASE_KEEP_EQUIPS` ⊆ 装备注册表进阶装备；`OFF_ROSTER_EQUIP_CARRIERS` ∩ 角色注册表 = ∅（封闭且不与购买名重叠）；`ECONOMIC_BONDS` ⊆ 羁绊注册表。
- **V11 让位序纪律**：每个阶段 `core` 的最小让位序 ≤ `support` 的最小让位序（主 C 让位序全名单最小——巡海任命派生锚点；双 C 制允许 core 内并列最小，但任命派生取 core 首键需落库注明终盘主 C）。

## 7. 结构风险（本方案最薄弱处，按危害排序）

1. **`faction_core`（身份档）与 `faction_ceiling`（追求档）的边界在证据灰区会摇摆**。两字段语义清晰，但具体某羁绊登哪边依赖帖证强度判读：D1 的治疗 6 档（「冲 6 层时治疗档本身就是全队增伤档」——机制事实，但追不追是另一回事）、B1 的千星 2/4/6 阶梯（副引擎还是成长方向）属灰区。版本重跑时灰区行漂移无人察觉。缓解：字段 8 的登记判据已成文（帖间实证追求 + 有消费面才登；灰区不登——登了没消费面就是死数据），落库批逐行过 + 实跑验证 Q2/Q7 是否真消费。
2. **计数口径是注册表派生的隐式契约，建库校验拦不住语义级漂移**。四种口径（TOTAL/STAR3/EXACT/召唤复合）的信息都在注册表 `count_mode`、`simple_desc` 与文件尾注里：版本更新重跑注册表时，若某羁绊的 simple_desc 文本变化引入新的计数特例（如第二个 EXACT），库层字段值不会报错，但消费方的判定已经错了。EXACT/STAR3/双龙吟特例各只有一例是当前幸运，不是结构保证。缓解：版本重跑时把「口径表 diff」列为库重建的前置检查步骤（流程性防线，非机器防线）。
3. **跨阶段全量快照的复制漂移**。A1 的 equip 两份、姬子线阶段 1 ≈ 瓦尔特线整条——V8(b) 能抓「有→无」漏改，抓不住「两份本该相同却不同值」；公共凑件表的候选域「减去各条目点名者」要求消费方逐条目现算，漂移无对账。缓解：落库流程先写末阶段再向前复制裁剪；终局靠版本重跑对拍。
4. **让位序是手编弱标尺**。帖间证据常只给局部序（「回血顺位白露→藿藿」「空位优先序飞霄>花火>千冶·刃>…」单帖），全序是登记者的拼装；版本重跑时局部序变了，全序没人知道该改哪。缓解：默认同级平权、只登帖证行分级；主 C 最小纪律有任命派生消费兜底；落库实测一轮再定收紧。
5. **挂着 [社区] 待实机机制的字段语义可能漂移**：菜-人映射与菜单门槛（config 无菜-人字段，逐帖零例外但待实机终证）、佩徽三星非成员计数（帖 6 结构佐证）、欢愉阿哈载体的实体身份、奇缘星魂门槛的存在性与效果、双龙吟「选连击分支计入连击数」（A2/A3/A4/H4 多帖标题口径）、命座继承乘区（风堇门槛的机制底座）、升费步进细则、星神★阿哈 4/5/7 三档并键。实机取证后这些可能改语义或撤字段——兜底 = 实机取证后的库重建联动（`rebuilt` 对齐机制）。
6. **`need_star` 的星级供给通道不建模**：开拓家族的星来自商店白嫖、千星的星即羁绊、DOT 五费明确不追——这些都装下了；但「几级搜、搜不到何时止损、商店怎么白嫖」全押策略层。若策略层没有等价的供给/止损骨架，`need_star` 会变成「永远刷不满」的死目标（A1 帖间原话「2-4 找不齐三星就停手」就是止损知识）。修复路径预算：给 need_star 行加「成型阻塞」标记（扩值域，字段数不变）。
7. **拆条帖量带是默认值不是定理**。「占比 ≥ 1/3 都立 / 帖量 < 5 挂起 / 小样本高占比列显式裁决点」在 B4（5:4）、B2（五峰 14/9/7）、E（42:21:5）上仍需人判：占比的分母（深读批 vs 聚类签名簇）不统一、长尾形态的帖量随版本波动。挂起形态 = bot 识别不到该路线（挂点在、数据不在）——这是知识覆盖度的系统性损失下限。
8. **过渡库两字段的押注**：先选伤害主体、意向同向 tie-break、双标签顺带激活这些组合规则全部推给策略层（理由：来牌主导的运行时逻辑；组合对大多可由注册表双标签成员派生解释）。若策略层的过渡选择器没有独立承载这些规则，两字段撑不起 Q8 之前的过渡期决策——「派生优先」原则的最大押注点。

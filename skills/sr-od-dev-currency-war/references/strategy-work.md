## 1. 策略是什么

CW 的策略 = **决策函数族**(买/上/装备/经济/刷新,`decide_*` 系列):每回合读 GameState(上场单位/金币/血量/轮次),输出要执行的动作列表。策略不是「配置参数」而是**行为代码**——改策略=改行为语义,要走文档三同步。

评判标准只有一条:**长期期望胜出**(多局分布)——sim 批量看分布变化,实机多局验收,单局胜负不构成证据。

由此得出唯一的方法论主线:**期望值是统一评判标准**。花钱决策的期望账(买/不买/刷新还是升级/压牌库——牌库中非目标牌越多,目标牌刷新概率越低,买非目标牌有代价;利息律也在其中)= compo-knowledge「经济期望方法论·三笔账」;其余决策(方向/上阵/装备/停手/切换终局阵容…)的判据住在 strategy/ 各画面篇与玩法文档——新阈值/分支的依据写进设计(§2 设计先行)。阵容结构等玩法约束在 §2 改前必读的文档里,不在此复述。

**数值来源口径(2026-11-20 用户裁定:只废证明义务)**。策略代码里出现的数字,来源三类:

1. **规则或机制推导**:注册表里的游戏规则数据(利息律、价格、退金),或从规则数据经推导得出的量(如超几何命中率)——查出来、算出来,不是人定出来的;
2. **存量经验数值**:证明体系时期的落码数值与实测校准值,一律视为存量合法,继续在用;
3. **新增经验数值**:证明义务已废,不设通用门——新增时的采纳流程届时议定(登记出处与依据仍走 §2 设计先行)。

无法推导的量若要建显式模型估计,质量纪律照旧:估计带置信区间;消费它的决策在该区间全域方向不变(区间内会翻转 = 数据不足,先补数据)。**拟合常数直接充当决策闸门仍是坏味道**(既无依据又随数据漂移),存在支配性论证(「无论该量取何值,A 都优于 B」类的结构性论证)时优先用论证消掉参数——能用论证消掉的参数不留数值。

## 2. 改策略前(不可跳)

1. **判读上局**:按 telemetry-reading「判读流程」找不合理处,结论写进进度追踪文件再动代码(单局数据≠结论)。
2. **读全部策略相关玩法文档**:基线清单与阅读顺序的单一源 = `docs/game/currency_war/research/README.md`「策略相关文档」节(全目录,唯一排除 screen_flow_timing)。不读全就无法预判改动波及面,「只读一篇=读局部」。
3. **改动先定位,再动手**:答两问——①这次改动牵涉哪条既有原则?②它落在 strategy 设计(`strategy/`)的哪一层?两问都答不出 = 改动在既有设计里没有位置:先停下问「为什么设计里没有它」,再决定改设计还是写代码,不许直接写。修复时重构优先于打补丁。
4. **设计先行,写清再动代码**:落点函数/影响消费点(含测试)/预期行为变化/验证法——「现象→定位函数→改」缺设计层是常犯病;新阈值/分支的推导出处写在这里(§1 方法主线)。**设计稿本身也要过 §6 对抗循环再写代码**(推导报告≠设计入册,入册+对抗零发现+符合策略核心后才碰代码)。~~玩家过目方向~~(2026-09-05 用户裁定变更流程:玩家过目删除,改为编排者自行发起无前提对抗子 agent 审查,符合策略核心即可写代码)。
5. **直觉假设 → 核对批,禁照抄直觉直接写进代码**(用户裁定 2026-09-04):玩家口述的直觉方向(如「等级锚定找缺件」)= **待检验假设**,不是规格——正确路径 = 通读全部玩法文档+游戏数据注册表,核对并推导最合适的机制形式(可推导的照常推导);直觉中对的部分保留、漏的机制补上、错的纠正,三差清单随设计稿呈报(先例:刷新决策形式二的升级费阈值/路径总账/利息线三修正)。
6. **口述被机制事实/实证纠正 = 当场修+登记待确认**(2026-08-31 用户裁定,细则承载=AGENTS.local 同名纪律行):核对证伪口述时立即按修正口径改,但必须同场留「待玩家确认」记录,玩家确认后回写结论归属。

## 3. 改动的落地:默认无开关(开关是例外;2026-08-31 用户裁定,取代旧「一律走开关」)

**行为改动默认直接写代码、不留开关**。旧「一律默认关开关」模式的实际代价:开关堆积成债、A/B 判正后裁决顺延形成悬置、每个开关多一轮注入重推+生命周期管理。新分野按「依据从哪来」分三档:

1. **机制可推导 → 直接写代码,无开关**:从注册表规则数据推导出的判据,写入代码即无条件生效;A/B 可作为落地后的确认性回填,不构成保留开关的理由。回滚靠 git revert(单操作者按局重启,等价速度)。
2. **经验性数值 → 存量合法、新增再议**(2026-11-20 用户裁定:只废证明义务):存量经验数值继续在用;新增经验数值不设通用门,采纳流程届时议定。sim A/B 的合法角色 = 落地后的**确认性交叉核对与实现验证**(发现实现 bug/量级意外可以);据此定数值的采纳与否,按新增数值的当期议定走,不设固定通则。经验性判据若能走支配性论证(§1)消参数,优先消。
3. **开关仅剩的合法形态**:行为输入真未就绪(外部数据/采集在途),且必须带裁决期限(超过一个对局周期未决=违规);「A/B 已判决却默认关挂起」在任何档都禁。

存量开关清理义务不变:定期盘点,已判正的翻正后进「除开关」清理批(硬编码settled态),判负的删码。

## 4. 验证(策略验证的纪律与阶梯)

测试分层命令(L1 快速集/L2 点名/L3 全量,~3/5min)= SKILL.md 单一源地图「测试分层」行。sim 工具怎么用 → [sim-testing.md](sim-testing.md);实机局怎么判读 → [telemetry-reading.md](telemetry-reading.md)。策略验证阶梯与纪律:

- **改进方向对准过程量,末端量只作验收与报警**:过程量(完成度/成型/经济纪律)是因果上游;hp/胜率/出口金是末端结果量,只用于验收与报警,拿它当改进方向=目标函数错。验收标准本身=当期目标行判据(A/B 判读标准,telemetry-reading 步骤 0)。达标线跑之前写死(载体=当期迭代设计/进度追踪文件判据行,先 commit 后跑批;禁独立 prereg 文件〔prereg = 预注册,跑批前把判据与达标线写死,防看完数据挪线〕);修复批另守 prereg 完整性硬门——必含既有验收线保全清单(§6)。
- **改前基线→改后对照(A/B)**:A/B 回答一个问题——这个改动让指标变好了吗。改前跑一次 sim 批记下基线 → 改后同参数(批跑 CLI 已删除——批跑/重放工具候补期间 A/B 挂起,见 sim-testing「先知道边界」末条;恢复后两侧同池指纹,跨日必核一致)再跑一次 → 对比:**与预期方向一致=确认通过;不一致=查清为什么**(实现 bug/机制理解错/声明该维度 sim 不可信,三选一;查不清=别上实机);**没变化=改动未生效或无效**。A/B 的角色与数值采纳的关系按 §3 第 2 档执行。没跑基线的「改后达标」不构成证据。指标=sim 统计脚本的输出(sim-testing 一、第 1 步)+**达标占比**——线来自当期目标判据,跑之前写死(载体=当期迭代设计/进度追踪文件判据行,先 commit 后跑批;禁独立 prereg 文件),防止看完数据挪线。仍然差的指标 → 回 sim-testing「找问题」三步下钻。新机制先验证它会触发(触发条件 0 次=输入死的,先补观测再测)。
- **改动影响面**:判据/策略层改动 = sim 可见面(§4 上条声明),漂移首发点看 A/B 对照与单帧测试(§5);digest/轨迹级两侧钉 `PYTHONHASHSEED=0`。(`cw_replay --diff` 已删除——`cw_replay` 是历史局 journal 重放,投资两屏帧不在其回放面。)
- **A/B 报告必带 sim 可观测性声明**(sim 决策下沉选型批,方案三混合裁决):报告须声明一行「本批改了什么层、sim 看不看得见」——判据/策略层改动 sim 可见(可 A/B);operations/app 执行层改动 sim 结构性不可见(不可作 A/B 判据,只可实机验证);单面批(planes=1/2 单位面)须声明批覆盖的位面,口径沿用 cw_batch_stats 批头位面披露(planes/plane_list)。缺声明的 A/B 报告 = 漏报风险高(动作发出被短路等行为消费缺位时 pre/post 逐位一致会被误读为「无影响」)。申报口径细则:「结构性无帧」= 生产代码根本不产生该决策帧的观测盲区(如动作发出被短路的帧 m1p 恒 None——生产无该决策帧,如实无帧)随本声明一并申报,禁止把盲区读数当零值证据。
- **参数精调用敏感度**:同策略扫参数,弹性大=值得实机精调;平坦=不花实机局数调它。
- **判读标记点事前写**:实机局开跑前写清「预测什么会变」,跑完核对——事后找解释不是验证。标记点没中 = 改动没生效或假设错,两者都要查。
- **实机验收=连续多局达标**(以当期目标为准),单局胜负不构成证据(§1)。险胜不算过——贴线通过是策略缺陷症状,与明显失败同权重分析;局后判读是必做项,异常条目当场定位,定位不了不进下一局。
- **实机/sim 分工**(用户裁定 2026-09-05):实机验**流程**(守卫/循环/对账/终结流转/识别),sim 验**算法**(判据质量/分布);sim 判读三步法(统计撒网→分诊排局→深读归因)细则 = sim-testing「找问题」;统计的角色=分诊定位,无裁决权。
- **阶梯终点=结论兑换(按 §3 依据档)**:机制可推导→写入代码生效(A/B 仅作落地后确认);经验数值→存量合法、新增按当期议定(§3 第 2 档)。A/B 对照手段(registry 注入/临时开关)不进生产代码;「默认关的悬置开关」=已判决未执行的悬案,禁(见 §3 开关生命周期)。

## 5. 行为的固化:单帧测试(验证过的行为变成回归资产)

验证确认的行为,固化成单帧测试才算回归资产——「模拟是发现工具,单帧测试是回归工具」:

- 位置与模式:`sr-od-test/test/sr_od/application/currency_war/test_cw_<主题>.py`;构造 `GameState`(plane/round/gold/level/board/bench/shop/xp_progress)+ `StrategySession` → 调被测方法 → 断言动作序列。测试的来源不问(sim 随机发现/实机判读/验证确认),钉住的都是策略决策行为。
- **断言写语义不写巧合**:断言写「配方缺件时,只买配方所需组件」而不是「买了卡 X」——换一副发牌断言就失效;钉住的是策略意图,不是当时的牌面。
- 维护:测试仓 gitignored 独立维护,提交在测试仓;语义演进时旧断言随改,docstring 记一句为什么旧语义过期。

**测试的存在性纪律**(通用条款单一源 = `sr-od-test/README.md` 测试纪律「写测试」节「改绿之前先判断」条;CW 因测试密度高——300+ 文件、registry 哈希锁 30 天被动更新 60+ 次——而两条倒退路径都实测走过:好改动被旧语义的测试否决而回退,坏改动靠直接改期望值保绿的测试更新混进仓库。故写测试/改测试额外守):

- **新增测试必须引设计出处**:docstring 写明出处(设计章/ADR),无出处=先补出处再落测试——引不出出处的测试,大概率钉的是偶然实现而非设计意图;
- **改测试=重推语义,不是机械改值保绿**:测试红了先问「被测语义还是当前设计意图吗」(引 ADR 对账),语义已被取代的测试走改写/删除,直接改期望值保绿 = 用测试更新洗白坏改动;
- **「老」不构成删测试理由**:判删必须引设计文档证被测行为已非设计意图。

## 6. 对抗循环(收尾硬门;用户裁定 2026-09-04「每次改后都要发起无前提子agent对抗,直到没有问题」)

策略/判据/装配/文档的**每批修改,提交前必须过无前提对抗审查,零发现才收尾**:

- **对象三档**:设计稿(入册前后)、实现(代码+测试)、体系全目录(跨篇一致性;周期性或大改后)。
- **无前提 = 干净上下文子 agent + 无预设焦点**:审查 agent 只给「对象文件面+判据源清单+攻击纪律」,不给结论、不给方向、不给上一轮发现——预设焦点会把审查带偏。
- **判据源**(任务书里开清单让 agent 自取):strategy/ 框架原则(00 号篇)、注册表(数值直调)、玩法 research、流水裁定(.debug/progress 迭代目录)、AGENTS.md 注释规范。
- **攻击纪律**:数值/口径/引文/代码引用一律**直调复核禁转述**(值对标签错是五犯实证错误类);「篇内/代码自洽」与「对得上游戏/框架原则/裁定」分开验;as-built 断言读代码体,docstring 仅线索,测试直调不算生产调用;结论=发现清单(编号/严重度/文件:行号/修正方向)或「零发现+实际检查过的面清单」,禁止模糊带过。
- **循环**:发现→修→再攻(新干净上下文),直至零发现;修复方不得只改被点名处不看同类(泛化步是义务)。
- **prereg 完整性硬门(用户裁定 2026-09-08)**:凡修复批,其 prereg(A/B 线与判据载体)必须**逐条列出受本批影响的已登记验收线**(出口金/[13]/通关门/存活等)并证明修复保住各线;保不住 = 设计缺陷非胜利,回设计层。新批 prereg 缺该清单 = 对抗审查直接打回,不进实现。盘点入口 = 当期迭代 criteria 行 + batch_stats/早停脚本读数行,不必新造登记簿(防第二源);载体纪律同 §4(先 commit 后跑批,禁独立 prereg 文件)。
- **轨迹现实**:收敛不是一两轮的事(实测十轮 55 项/四轮/两轮都出现过),修不动时回到设计层而不是软化标准。

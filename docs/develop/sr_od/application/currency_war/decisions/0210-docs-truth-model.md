# 0210 文档真值模型:develop=as-built 无状态 / game/research=证据层 / 进度外置

- **Status**: accepted
- **Date**: 2026-08-18
- **Context**: 第三刀(strategy/ 重建)前的方法论定调。strategy/ 22 个文件是三轮设计期的地质层(01-14 一轮 / 15-20 二轮 / economy_research 迁入),同一主题(经济)四份并行叙述(02/06/14/economy_research),其中 14 号整章描述 r69 已删除的 `_DEFAULT_NODE_PLAN` 却无人知晓——根因不是没维护,是**文档同时承担了描述现状 / 记录值 / 记录历史 / 记录进度四种职责**,四种职责变化频率不同(架构月级/调参周级/历史永不/进度天级),混排导致文档以最快频率腐化,且"系统现在是什么"反而读不出来。economy_research §6 曾自记"旧副本曾与本节 §2 漂移——双源教训"。
- **Decision Drivers**: 同一句话随系统演进会失效 → 该读者读到过期信息(r69 死表无人知);值写进文档必然与代码漂移(已实证);进度标记(✅/❌)在文档里随每次 commit 过期,维护成本高且必然漏更;用户裁定"ADR 是记录补充,不是关键信息存储"。
- **Considered Options**:
  1. **逐文件标状态头(current/superseded/partial)** —— 治标:状态头本身也是会过期的状态,只是把漂移从正文挪到头部;地层仍在,交叉叙述仍在。
  2. **保留原文件 + 定期同步** —— 承认双源再雇人肉纪律保持一致;已被 economy_research §6 事故证伪。
  3. **推平重写 + 四职责分家(采纳)** —— 以代码现状为唯一基准重写正文;值→代码、历史→ADR、进度→进度树、证据→game/research。文档只在架构变化时改,"同步状态"这个动作消失。
- **Decision**:
  1. `docs/develop/` 设计文档 = **as-built(竣工图)**:只写结构/语义/接口契约/数据流/边界;数值/权重/阈值只写常量名,单一源在代码。四禁:进度标记、变更叙述(只留 ADR 指针)、规划/实现状态位、会失效的现状快照。自检判据:这句话在系统继续演进后会变成错的或废话吗?会 → 不属于设计文档。已入 AGENTS.md「文档与测试要求」。
  2. **证据层归位 game 子树**:经我们提炼/核实的游戏知识(社区帖提炼、机制核实、用户口述)放 `docs/game/<玩法>/research/`,随游戏版本原地更新,证据分级权威序 = 口述 > 图鉴 > 米游社 > 社区;原始攻略转录在 guides/ 按版本冻结;变更驱动不同的信息不同居(game 子树随版本变、develop 随架构变)。细则在 docs/game/README.md。
  3. **进度外置**:实现进度只进玩法进度追踪(CW 为 cw_dev/进度.md),不进任何 docs;对拍快照属进度记录一并外置。
  4. prescriptive 职责由 ADR 承担:已定案待实现的规划写成 Status: accepted 的 ADR(正文注明接线批次),不占设计文档正文。
  - 方法论出处:as-built/prescriptive 二分(Rozanski & Woods;Rust RFC 冻结+tracking issue 外置进度)、Diátaxis 四类(reference vs explanation)、循证实践证据分级(GRADE)。
- **Consequences**: strategy/ 正文可整体重写而不欠债;版本更新只动 game 子树;文档引用的模块/函数/ADR 号可机器校验存在性(值和状态无机器锚,故必须清出)。旧文档删除前做窄口径 why 清点:仅补录「影响过代码设计且既不在 ADR 也不在代码注释」的权衡,讨论过程速记不补。

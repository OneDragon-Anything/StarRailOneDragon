# 批 C：装备到人补全与 key_equips 投影化（详设）

## 问题与约束

C4 契约（2026-09 冻结）确立 `equip_assign`（到人配方）为真源、`key_equips` 为投影。
现状 21 套中 **13 套已迁移、8 套 equip_assign 为空**（key_equips 仍是唯一真源、
投影语义悬空）：千冶减益、巡海击破、龙丹战技点、火花星间旅人、银枝群攻、昼神
阿雅、追击飞霄、景元仙舟。

**防线现状（如实）**：恒等约束 `key_equips == derive_key_equips(comp)` 仅有
docstring 声明——**全仓无任何测试或建库校验钉住它**（生产 docstring 三处指认
不存在的「恒等测试」：cw_comps.py 两处、proofs/p42 一处，属既有文档债，随本批
修正）。

约束：

- 总纲契约 §2.3-3：字段删除后 `comp.key_equips` 读法零改动（property 委托
  `derive_key_equips`）；`derive_key_equips` 保留为唯一实现体。
- **顺序硬约束**：property 化前必须 21/21 套 equip_assign 非空——现
  `derive_key_equips` 的 fallback 分支读 `comp.key_equips` 字段，字段改 property 后
  该分支自引用（死循环）；先补数据、再退役。8 套均已具备至少一件到人线索（§1 表），
  提取后全库非空由数据保证——「无出处单件不入册」是**单件级**纪律，不与 21/21
  非空冲突（套级允许零件入册）。
- 数据纪律（comp-definition）：值只在代码就地注释记「凭什么信」；教义级内容对
  final_comps 各篇原文，不自创。
- **数据方向裁定（attack.md A2，用户 2026-11-05 已确认）**：**教义为准重写**——8 套
  补全后 key_equips 派生集以新数据为准，允许与旧手编值不等（旧手编未到人、与教义
  矛盾处让位，典型 = 火花线「爻光三鞋」）。恒等测试第 0 步补建后即锁「旧手编 = 旧投影」，
  数据批逐套迁移时随套重锁为新值（恒等始终钉「字段 = 投影」，值随真值走）。

## 方案

### 0. 第 0 步：补建恒等测试（数据批前置防线）

新增测试：全库逐套断言 `comp.key_equips == derive_key_equips(comp)`（多重集口径）。
现状它应当全绿（13 套投影已恒等、8 套 fallback 返回原值恒等）——先证明防线本身
有效，再动数据。没有这一步，数据批的双源漂移无任何东西能抓住。

### 1. 八套 equip_assign 数据提取（知识工作，草案级 + 全量过目）

1. 条目内 plaza 校准注已到人的，直接取（最高置信）；
2. final_comps 各篇「装备公式/构造机理」节到人的，取之；
3. 条目内攻略直读注的装备序列，按角色教义归属（需在注释写清归属依据）；
4. 以上皆无的单件：**不入册**（套级允许零件；装备证据面变小的损失 < 假数据污染
   采购/穿戴决策的损失）。

### 2. key_equips 字段退役（机械批，数据补全后）

迁移四步（顺序不可倒）：

1. **第 0 步恒等测试**（§0）；
2. **数据批**：8 套补 equip_assign（键 ⊆ core∪shared，与 13 套既有纪律一致）；
   每套补完后手编 key_equips 同步改为与 `derive_key_equips` 恒等（恒等测试保持
   绿——值随真值走）；
3. **退役批**：`key_equips` dataclass 字段删除；同位置加

   ```python
   @property
   def key_equips(self) -> list[str]:
       """关键装备清单 = equip_assign 投影(汇总+去到人;C4 完成态)。
       实现单一源 = derive_key_equips;消费端读法零改动。"""
       return derive_key_equips(self)
   ```

   （property 定义置于类体、`derive_key_equips` 为模块级函数——类体内引用模块级
   函数名，dataclass 不会把它当字段。）旧手编 key_equips 数据行全删；
   `derive_key_equips` 的 equip_assign 空值 fallback 分支删除，docstring 更新为
   完成态语义。**连带修正三处「恒等测试」docstring 引用**：cw_comps.py 两处（C5
   契约注、derive_key_equips docstring）改指本批补建的测试→终态描述；proofs/
   p42-equipment-machine-ev.md 的「(C5 条测试)」引用同步。
4. **测试收尾**：恒等测试转终态断言「全库 equip_assign 非空且键 ⊆ core ∪ shared」
   （升建库校验 `__post_init__` 或库级校验——防未来新条目开空账回退双写形态）。

### 3. 行为变化申报（本批非零漂移，四方向）

- **增方向**：新登记到人装备持有点亮线证据（line_select `equip_evidence_bonus`）、
  进囤货采购面（`_line_hoard` 经投影）。
- **减/重写方向**：旧手编清单中无到人出处的单件（如火花线碎星斩舰刀/动能激发剑
  若核不出归属）从装备证据面/囤货面/合成规划面（key_equips 三消费：hoard_gaps
  缺口、recycle 判定、穿戴优先）**消失**；火花线整面重写（皮靴×3 入册）。fail
  方向裁定：装备证据保守化 = 线分证据略低（安全向）；穿戴/合成规划按教义执行
  （正确向）——两向均非危险向（危险向 = 假数据污染，已被单件级纪律排除）。
- **顺序方向**（已迁移 4 套，见 §1 末申报）：黄泉/大黑塔/反甲白厄/DOT队 退役后
  key_equips 序变投影序，equip_allocation 按序取件在容量紧张帧先后微变。
- 验证口径沿用项目近例（comp-structure-unification 3.3 用户裁定）：不做 A/B 模拟
  对照，行为退化发现通道 = 实机首局观察记录 + L1 测试全量（实机观察面含装备
  取件顺序帧）。

## 关键取舍

1. **教义为准重写 vs 守旧清单**（attack.md A2 裁定）：守旧（无出处旧件保留、只增
   不减）会把手编频次清单固化为真值——它本来就没到人、且与教义矛盾（火花线）；
   重写方向忠于教义，恒等测试锁的是「字段 = 投影」关系而非具体值。
2. **补数据 vs 永久双写**：C4/C5 本就是迁移契约而非终态；留在双写 = 无防线的双源
   （现状证明）+ 8 套到人知识真空。
3. **无出处单件宁缺毋滥（单件级）**：装备证据面变小的损失是线分证据略保守（fail
   方向安全），假数据污染的是采购与穿戴决策（fail 方向危险）。
4. **退役批独立于数据批提交**：数据批可逐套推进（每套独立过目），退役批是纯机械
   一刀切——分开提交让回滚粒度对齐风险粒度。

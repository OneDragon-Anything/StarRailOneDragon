## 1. 逐屏流程

### 1.1 盛会之星(megastar)

- **触发条件**:盛会之星羁绊**跨档激活**时弹,一局可多次(megastar.md §1)。计数 = 前后排盛会之星成员数(候选面含持星徽者)。
- **到达路径(选中型双面;deploy 两形态 = 空槽上场 / **替换**(拖到已占槽:新单位上场+被占位者回源 bench 槽,deploy_move.py:65-66 在册);换排(成员集合不变)= 游戏能力、bot 无动作;deploy 形态 = 用户裁定 2026-09-25 + deploy_move.py 现役语义)**:
  - **跨档面**:增计数 = deploy 盛会之星角色上场(含替换形态净+1);卖出/合成只减不增,不触发本面。
  - **重选面**(用户裁定 2026-09-25):被选为巨星的角色被卖/下场 → 再触发重选——与计数无关;**下场两形态** = 显式拖下场 + 替换下场;判据 = chosen 跌出资格集 ∧ 写后计数仍达首档(首档=2;场上只剩一个/零个盛会之星角色不弹,首个成员上场也不弹——用户裁定)。
  - **星徽路径(用户确认 2026-09-25)**:穿/卸「盛会之星星徽」改变阵营计数(两方向);候选与选择可为持星徽角色;穿戴跨档 → 弹;卸下选中者星徽致其失去资格(出身阵营与持徽**两者皆失**才失效)→ 重选弹。
- **bot 链**:deploy_move(两形态:空槽/替换——替换 = 被占位单位回源 bench 槽,deploy_move.py:65-66)/SwapDeploy(bench↔场上对调,词表在册、生产执行器未接线)/sell_deployed/wear_equip+工具腿;换排(前↔后)= 游戏能力,bot 无动作(接线时零新增判据,单写天然覆盖)。
- **弹窗时点(用户确认 2026-09-25)**:触发动作落地即弹,叠备战,挡后续动作。
- **簿记**:跨档面 = **无簿记,每次上穿档线即弹**(含降档再升档、合成继承星徽致跨档——用户裁定 2026-09-25);重选面 = 每次选中者跌出且写后达首档(无上限)。
- 跨档面边界:首个成员上场不弹(1 < 首档 2,tiers=(2,3,4,5,6),cw_factions.py:61)。

### 1.2 列车同行(partner)

- **触发条件**(用户裁定):姬子·启行在场 ∧ 另有列车同行成员 ∧ 本次变动 = 列车同行**资格集**增减(经典合成名集合不变,天然不弹;合成继承星徽获得新资格 → 弹,2026-09-25 裁定);一局可多次,每次重选。选中伙伴被卖/下场的重选场景天然含于「任意资格增减」。
- **到达路径**:
  - deploy 列车同行成员(三形态;两种首触:姬子+deploy 三月七 / 三月七+deploy 姬子);
  - sell_deployed 列车同行成员(含选中伙伴);下场两形态(显式拖下场 = 游戏支持、bot 现役无动作;替换下场 = deploy_move 同一上报);
  - 不弹:换排(集合不变,开拓者阵容除外) / 经典合成(名合成前后同名,集合不变) / 备战席买卖 / 卖到只剩姬子(前提不满足)。**弹**:合成继承星徽获得新资格(集合真变——用户裁定 2026-09-25,与巨星跨档同判)。
  - **星徽路径(用户确认 2026-09-25)**:穿/卸「列车同行星徽」同样改变成员资格 → 增减面同辖。
- **bot 链**:deploy_move / sell_deployed / wear_equip+工具腿(动作拓扑同 §1.1 注)。
- **弹窗时点**:动作落地即弹,叠备战;可与巨星同帧并弹(用户实测列车同行先出;顺序不枚举,不强断言)。
- **簿记**:无上限(每次合格变动)。

### 1.3 银狼升星(planner,「我来当策划」)

- **触发条件**:银狼 LV.999 升 2★ 且在前后台(用户裁定:备战席不触发);**每费用档首 2★ 一次**(用户裁定 2026-09-25;3费=升费选项、5费=双装备选项;错过不补)。**无→3 形态**(备战囤 3★ 直接上场,该档 2★ 从未上场)= 按会弹处理(用户裁定 2026-09-25:暂按会,待实机复核)。
- **到达路径(多轮序贯;游戏不变量:**场上同名角色唯一**(用户裁定 2026-09-25);合成载体规则 = merge_step_once:164「take 含场上 → 场上位置;全备战 → 最左」)**:
  - **序贯 A(场上1+备战1+买1)**:买狼①(备战)→ deploy → 买狼②③ → 3合1 载体=场上 → 2★ 落场上 → **触发@buy_card**(买腿直接三合进场上的唯一形状)。
  - **序贯 B(纯备战囤)**:三张全备战 → 载体=备战最左 → 2★ 落备战 → 不触发;此后 deploy 该 2★ → **触发@deploy_move**(触发时点 ≠ 状态达成时点——判据必须挂动作,不能挂状态)。
  - **序贯 C(奖励/工具补齐)**:奖励送狼/投影仪复制(gain 链,落备战/溢出)与场上狼凑齐三合 → 载体=场上 → 2★ 落场上 → sim/gain 链内触发(实机奖励为观察揭示,弹窗已在场,反应式)。
  - **序贯 D(升费链)**:3费 2★ 触发选升费 → 4费1★ → 再凑 3 张升 2★ → 再触发;5费 2★ → 再触发(双装备)。
  - 满栏例外:备战满点合成槽 → 游戏自动多买至 3 的倍数张(op-layer §1)→ 仍归 buy_card 一个动作 op。
- **bot 链**:buy_card(pre_bench/pre_dep + detect_merge_upgrade 现役已有,buy_card.py:161)/ deploy_move(2★ 上场,含替换)/ gain 链(载体落位在 merge_step_once 手里)。
- **弹窗时点(用户确认 2026-09-25)**:买腿触发直接**叠商店弹**;选完回商店还是备战待实机/遥测核(只影响 pick_planner 声明 next_screen 终值,非阻塞)。
- **sim 现役错误**:扫备战席(应只场上);planner_fired 全局一次性(应每费用档集合)。

## 2. 多轮横切

1. **触发时点 ≠ 状态达成时点**(序贯 B):备战 2★ 不触发、deploy 才触发 → 判据挂动作不挂状态。
2. **一动作多弹窗**:deploy 星期日 → 伙伴+巨星并弹;约定序登记 + 披露,不强断言。
3. **弹窗打断访问循环**:备战/商店都是多动作循环,弹窗在任意动作间插入 → 两宿主 op 都要查登记交回。
4. **弹窗时点 vs 商店(已定谳)**:planner 买腿直接叠商店弹 → 商店 op 是查登记交回宿主;残余 = 选完回商店还是备战(非阻塞,声明终值细节)。
5. **簿记多次语义各不相同**:巨星 = **无簿记,每次上穿档线即弹**(降档再升也弹,用户裁定)+ 重选无上限(门槛 = 首档);祈愿 = 首次达档一次(降档再回不弹,用户裁定);planner = 每费用档首 2★;占卜屋 = 每 2 场;伙伴 = 无上限。「已触发档位集合」是**两处**同型结构(祈愿/planner),可实现为通用簿记原语。
6. **奖励路径的双面性**(序贯 C):sim/gain 链内合成 = 判据点;实机奖励 = 观察揭示(弹窗已在场)= 反应式。
7. **选中型弹窗双面性**:巨星/伙伴 = 跨档/增减首选面 + 选中者离场重选面;伙伴重选面被成员增减规则包含,巨星重选面是独立判据(读 chosen_megastar);选卡写端与触发判据在 chosen 上闭环。

# ADR-0607 — 入口链弹窗守卫注册表化与领取目标修正(T-101/T-102)

- **Status**: accepted
- **Date**: 2026-09-09
- **关联**: ADR-0574(星琼详情守卫引入+交替循环上界闭合;其 §2.4 两挂账由本件显式闭环)、`cw_overlay_registry.OverlaySpec`(对局内侧注册表,生命周期不同不复用,见 §4)、`cw_loop.py` 1d 分支(对局内侧星徽 OR 判据,分叉调和见 §2.4)、`back_to_normal_world_plus`(supply 薄包装唯一外部消费方)
- **方案与审**: 设计方案 v2 = `.debug/temp/currency_war/attacks/t98_popup_guard/设计方案.md`(实施唯一依据,§7.3 审查后状态)+ 同目录 `方案审.md`(六项发现 F1-F6 零推翻级,轻改放行);批报告属易失产物,本 ADR 为其持久归宿
- **触发证据**: ①T-101——S1 两次活体复现「点中央 = 只开详情不领取」+ S2 实证点提示区 (960,910) 一次领取成功且不开详情(ADR-0574 §5),门已开;②T-102——星徽详情(第三发同族弹窗)落位触发 ADR-0574 §2.1 自设的注册表升级条件

## 1. 背景与问题(归层:入口链抗干扰面·路由层)

ADR-0574 落地后入口链有两具守卫(列车补给/星琼详情)在四挂点各自成对调用,同构骨架(识别→动作→具名 round_retry)复制两份;第三发(星徽详情)落位时按旧形状需第三份复制。同时列车补给领取点击目标(中央徽章区)被 S1/S2 证伪——其中内嵌星琼图标,点中央 = 开详情不领取,正是 T-98 级联事故的上游几何;S2 已实证正确目标 = 底部提示文字区。

## 2. 决策(裁决)

### 2.1 注册表化(不做第三份复制粘贴)

- **形状**:`cw_entry_start.py` 模块级 `EntryPopupGuardSpec`(frozen dataclass:screen_name / identify_area_names 全锚 AND / action_area_name / retry_status / wait_seconds)+ `ENTRY_POPUP_GUARDS` 元组(顺序 = 挂点执行序)+ 单函数 `try_handle_entry_popups`(按序逐 spec 识别,首个全锚命中者动作并返回具名 round_retry)。四挂点(app `_enter_lobby` 首节点 / `cw_entry_enter.wait_lobby` / `cw_entry_start.click_start` / `advance_to_prep`)收敛为单行调用;新成员 = 画面建档 + 注册表一行,挂点零改动。
- **兼容面**:仅保留 `try_handle_train_supply_popup` 薄包装(委托 supply spec,签名 `(op, screen)` 与「只管 supply」语义原样)——唯一保留理由 = CW 之外的真实消费方 `back_to_normal_world_plus`;`try_handle_jade_detail_popup` 包装删除(挂点收敛后零生产调用方,保留即死代码兼第二测试面,测试若打包装面会遮蔽序位/收敛行为)。
- **序位知识只住数据**:元组顺序即执行序(supply 在 detail 族前,领取优先;叠层语义下 supply 被 detail 盖住时其锚 OCR 不命中自然让位,序位无害),机械防线 = 守卫序位锁(§3 L6,元组重排即红)。

### 2.2 星徽详情守卫参数面(防御面)

- 画面档 `currency_war_star_badge_detail.yml` 已建(M53);识别 = 档内双 id_mark AND @0.9(`标识-流派星徽` + `标识-套组标题`,4 字近乎全等误配面趋零,跨锚共享子串「星徽」2/4=0.5 互不误中);动作 = 点 `按钮-关闭`(屏幕右上角 1815,35-1900,95——全屏遮罩层的 X 在屏幕角非弹窗卡角,同族泛化必须逐弹窗取档的实证);`round_retry('星徽详情弹窗关闭中', wait=1.5)` 同 jade。
- **变体风险裁决:维持 AND,不预建变体分支**。星徽详情已知触发场景全在对局内(点球误开,M53/T-163),入口链无已知触发路径——本守卫本质是防御面;变体帧(类型行非「流派星徽」)上 AND 漏接 = 有界具名 FAIL,可诊断不可自愈,不是无界风险。变体修复波及半径 = **4 处同改**(yml 锚文本 / 入口 spec / overlay registry `anchor_area` / 1d 内联双锚),单修入口侧则对局内继续漏;核验结论回填义务见 §6。

### 2.3 T-101 领取目标修正(执行 ADR-0574 §2.4 挂账)

- 识别锚不变(`标识-列车补给`);动作目标 `按钮-领取补贴`(中央徽章区,被 S1 证伪的假设,该「领取按钮」从未存在)→ `文本-领取提示`(850,885-1070,935,中心 (960,910) = S2 实证点;该 area W938 建档起坐标即正确,零改动)。附带语义升级:盲点坐标 → `round_by_find_and_click_area` OCR 验证后点击,提示文字缺失时有界具名失败,不再盲点中央。
- 旧中央徽章 rect **改名留档**为 `区域-中央徽章危险区`(pc_rect 不变,id_mark=false,text 空,经 MCP 工具改):旧名固化被证伪假设是给未来 agent 的活陷阱;保留 rect 作为测试负向断言的坐标单一源,名字自带禁用语义,生产永不点击。
- 返回语义不回退:仍 `round_retry('列车补给领取中', wait=3)`(ADR-0574 §2.2 改形)。

### 2.4 判据分叉调和声明(禁顺手统一)

星徽详情在 produce 侧已有三个处置面,T-102 入口注册表是第四面(多面并存是事实基线):

| 面 | 判据 | 定位 |
|---|---|---|
| `cw_loop.py` 1d 分支 | **OR**(任一锚命中即派发) | 召回优先,as-built 既有(M53 起生产里程) |
| `CwScreenEmblemDetailPopup` 专属 op | 被 1d 派发后执行 | 点同款关闭钮 |
| `cw_overlay_registry` OverlaySpec | 单锚 `标识-流派星徽` | 分类/清场表成员(变体同样漏;其「无 cw_loop 消费分支」陈旧注释随批修正为如实表述) |
| 入口链注册表(本件) | **AND**(is_precise 同判据) | 防御面,低误关优先 |

入口 AND vs 对局内 1d OR 是**有意分叉**:两层挂点拓扑、误关代价、召回需求不同(变体帧上 OR 免疫、入口 AND 漏接;入口侧后果 = 有界具名 FAIL 可诊断非无界)。未来 agent 见双判据不得无据统一。

### 2.5 测试与验收面

全部锁走 `try_handle_entry_popups` + 挂点集成路径(不打包装面),清单见 §3。

## 3. 验收(锁与红证)

fixture 全部复用既有归档真帧,零新增截图依赖(`sr-od-test/test/sr_od/app/currency_war/test_cw_screens_entry.py`):

| # | 锁 | 断言要点 | 红证 |
|---|---|---|---|
| L1 | op 级 supply(改写) | 点中 `文本-领取提示`;**弹窗相位窗口内零点击落入 `区域-中央徽章危险区`**(负向断言照残留逃逸测试「只锁关闭前点击序列」先例取前缀窗口);推进到备战 | 点击目标回退 → 负向+终态双独立红(实证:点 (960,540) 危险区中心,phase 卡 0) |
| L2 | app 级 supply(改写) | 首轮非成功 + 点中提示区 + 负向同 L1 + 次轮导航恢复 | 同 L1 |
| L3 | op 级 badge(新) | `燃血星徽.webp` 真帧 → 点中 `按钮-关闭` → 推进到备战 | 注册表移除 badge 项 → 帧无分支可推进 |
| L4 | app 级 badge(新) | 首轮非成功 + 点中关闭钮 + 次轮恢复 | 同上 |
| L5 | 白名单锁(已有) | 星徽详情不在对局屏集 | T-98 批已钉 |
| L6 | 守卫序位锁(新,单元级 mock) | stub `round_by_find_area` 全锚命中 → 返回首个 spec 具名状态(`列车补给领取中`);依次屏蔽前序 spec 锚 → 依次 jade/badge | 注册表元组重排 → 全命中场景返回值变化即红(实证) |

回归网 = 既有入口链锁原样绿(happy path ×2 / 残留逃逸 / jade 两锁),注册表化行为保持的机械证明;`test_id_mark.py` 全库扫描绿(三弹窗屏均在收集内)。变异打红两件均已实证后还原。**实机口径如实声明**:星徽详情入口链无已知触发路径,L3/L4 真帧锁即其验收;活体证据 = 机会性(日志 ever 出现 `星徽详情弹窗关闭中` 即实战命中)。T-101 活体验收路径(当日未领取窗口):构造 jade 详情 → 单跑 `开始货币战争对局` → 期望 `星琼详情弹窗关闭中` → `列车补给领取中` 且点击落提示区 → 无第二次详情守卫状态 → `到达备战阶段`。

## 4. Considered Options

| 方案 | 裁决 | 理由 |
|---|---|---|
| 第三份复制粘贴助手 | ✗ | 三处同构漂移风险;违反跨件半问(同族第 3 件 = 升级架构面的信号);ADR-0574 §2.1 自己预约的升级被倒退回症状补丁 |
| 复用 `cw_overlay_registry.OverlaySpec` | ✗ | 生命周期不同——入口链是固定 4 挂点的具名 round_retry 重试面,对局内注册表是优先级分发/恢复链机制;复用会把入口链耦合进对局内分发机制,比独立小注册表更差(方案审 F6) |
| 点空白关闭作 detail 族默认手段 | ✗ | 未采样(ADR-0574 §5 S3 挂账续);盲点空白恰是 supply 弹窗「点哪都领取」的反例警示,家族内没有可泛化的空白语义;证据采集不改默认,见 §6 |
| 删除危险区 rect、负向断言放弃 | ✗ | phase-exit 虽也能红,但失败信息退化成超时;`_clicks_in_area` 负向断言给出「点进了危险区」的直读诊断,值一个不参与生产的 rect |
| 变体帧预建分支(入口侧 OR 化) | ✗ | 入口链无已知触发路径,预建 = 为造不出的态扩误关面;漏接代价有界具名;对局内 OR 已天然免疫(§2.4 分叉各守其面) |
| 通用签名检测弹窗关闭器 | ✗ | ADR-0574 §4 已裁,注册表不改变该裁决——注册表仍是逐弹窗显式建档的 allowlist |

## 5. 非目标(残余面具名,不入本批)

1. **退局 op `CwEntryExit` 无守卫**:退局途中被弹窗盖场 → 全分支 miss → 有界具名 FAIL,下一 run 的 app 首节点守卫兜住;可诊断,挂点改造另批。
2. **大世界侧 detail 族弹窗不接**:`back_to_normal_world_plus` 只管 supply 维持(薄包装语义原样);它要不要也接 detail 弹窗是独立决策。附带收益已随本批自动发生:T-101 改点后,大世界侧领取同样改点提示区(共享同一 supply spec),「领取开详情」级联源头在两侧一并消除。

## 6. S3 空白遮罩关闭采样挂账(证据采集,不改默认)

jade(构造路径:补给弹窗在场 + MCP 点中央徽章)与 badge(对局内点星徽图标)两路采样协议见设计方案 v2 §2.4。**裁决规则先声明:无论结果如何,守卫默认仅 X 不变。**结论回填义务:①本 ADR 无回填表(采样批补 §6 各行:能否关/有无穿透副作用/锚核验结果);②各画面 doc「可交互元素」;③**锚不变性核验结论回填时同步核对并修全部四处锚面**(§2.2:①yml `标识-流派星徽` 锚文本 ②入口 spec identify 元组 ③overlay registry `anchor_area` ④1d 内联双锚)——只修入口侧则变体真出现时对局内继续漏。

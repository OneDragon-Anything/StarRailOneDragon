### 中

**R10-01 ｜ 中 ｜ 核一·表述与权威源不符（判据窗口两答案）｜ priority-model.md §2 档 2 :32 ↔ §1 :24 第九项读口 ↔ kernel 配方生命周期**
档 2 成员名单括注「配方成员在终局阵容锁定前一直属候选体系，**退出条件 = 锁定终局阵容**」与第九项
（R9-02 返工新增）声明的读口实际窗口不符：

- 读口实读：配方物化链的生命窗口 = **P1**——`clear_p1_recipe`（cw_intention.py :1228-1247）
  docstring「进 P2:配方锁退场……进 P2 **后永不再写**，不清则 P2 未锁窗读口消费过期 P1 配方」，
  进 P2 同点清空 `opening_recipe_comp`（:1243-1247）；`direction_comp_of`（session_scope.py
  :390-392）plane2 守卫恒 None（docstring :376「P2 起配方面明确不在设计范围内」、:382-385 防御
  双保险「P2 未锁窗恒走无方向」）；
- 因此未锁定帧穿过 P2 边界时，非三线配方成员**实际在 P2 进入帧即退出档 2/3/5 名单**（退出 = P2
  进入 ∨ 终局锁定，取先），并非括注字面的「锁定前一直属候选体系」。行为语义本身无争议——P2 清空
  与读口守卫是经审机制（session_scope :382「review-37 P1」），design :185 K 源切换的 p2plus 未锁
  带（「unlocked = 保利息缺省」）也以「配方支在 P2 自然为空」为前提——缺的只是括注的窗口表述；
- 两答案形态：按括注字面施工，实现者为兑现「锁定前一直在」需在 P2+ 未锁帧延续配方支，与第九项
  「现读口」+ 本篇 §问题与约束「禁新造名单」相抵；按读口施工则括注错误留存于定稿。「未锁定 P2 帧
  配方成员在不在档 2」这一语义选择在稿内有两个答案 = 表述可歧义（中）；行为风险被读口与约束夹住，
  不按接口缺口（高）计。
- 修正方向（一括注级）：括注改写为「配方支窗口 = 配方物化链现行生命周期（P1；进 P2
  `clear_p1_recipe` 清空、读口 plane2 守卫恒空）——未锁定装配仍单支不设 P1/P2 分支，配方成员
  实际退出 = P2 进入或终局锁定取先」。两态名单结构、第九项读口、design §2.7 申报①均不动，无翻案。

## 四、定稿判定

**判定：需继续返工（最后一轮微幅收尾返工，约 2–3 行级）——未达定稿门槛。**

理由：
1. **高阻断连续六轮清零，核心模型十轮未动摇；R9 清单 3 条中 2 条全过、R7-03 四轮残留终清**。
   申报集 8 项经本轮独立直调全数成立；档 7/档 6/档 8 数据源链与随机流锚全部实锚。
2. **但 R9 设定的定稿门槛「零新发现 + 回归全过」两项均未达成**。R9-03：点名对象（design :128）
   原文未动，返工采取「并存补定案句」而非「改写删旧句」，产出同节两答案（中）——恰是规范 §5
   规则 4「禁只改触碰段」要防的形态变体；R10-01：档 2 括注的配方成员退出条件与第九项读口的实际
   窗口（P1 生命周期）不符（中）。两处定稿试读（「凭这份能开工吗」）同一类失分：实现者在「虚拟
   局面载体」与「P2 未锁帧配方成员档位」两个语义选择上各得两个答案。
3. **剩余返工面全部单点化、纯文面**：R9-03 残留 = design :128 一句改写（原修正方向不变：首句改
   定案引用 + 删容器专属缓解句，或整条并入 :127）；R10-01 = priority-model :32 一括注改写。合计
   2–3 行，无结构性返工，无翻案。
4. **无硬性用户裁定项**。R10-01 按现行读口与 kernel 机制对齐括注即可（P2 清空与读口守卫是经审
   机制，两态名单结构与 §2.7 申报①均不变）；R9-03 残留纯文面同步。
5. **流程级备注**：本轮两条同属「落稿句与读口/定案的窗口、方向级失同步」，且 R9-03 的残留由
   修法方式（并存补句）自引入——建议返工侧固化「改写即删旧句」的执行纪律；失同步链本轮无新形态
   （一条为残留未清、一条为括注窗口表述，均非矛盾扩散型）。
6. **收敛预判**：本清单（2 条）完成后剩余面为零——核心模型稳定、申报集闭合、返工面行级化且均为
   文面同步，预期下轮（零新发现 + 回归全过）达定稿门槛。

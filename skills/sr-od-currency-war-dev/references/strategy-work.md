# 策略工作(怎么修改策略 / 怎么验收效果)

> CW skill 的策略专属说明。读者 = 智能体。入口:SKILL.md 分诊表「策略工作」行。
> **本文只记录两件事**:怎么修改策略(§1 策略是什么与骨架 / §2 改前 / §3 开关落地 / §5 锁纪律);怎么验收效果(§4 验证阶梯 / §5 单帧锁)。玩法知识在 game docs,sim 用法在 sim-testing,判读流程在 telemetry-reading,单局复盘在 match-review——不归本文。

## 1. 策略是什么

CW 的策略 = **决策函数族**(买/上/装备/经济/刷新,`decide_*` 系列):每回合读 GameState(板面/金/血/轮次),输出要执行的动作列表。策略不是「配置参数」而是**行为代码**——改策略=改行为语义,要走文档三同步。

评判标准只有一条:**长期期望胜出**(多局分布)——sim 批量看分布变化,实机多局验收,单局胜负不构成证据。

由此得出唯一的骨架:**期望值是统一标尺,尽量所有决策都要数学支持**。花钱决策的期望账(买/不买/刷新还是升级/压库,息律也在其中)= compo-knowledge「经济期望方法论·三笔账」;其余决策(方向/上阵/装备/停手/换线…)有证明的以 math_proofs 为准;还没有数学的,直觉只能当假设来源立命题去证(ADR-0482),不许长期停在拍脑袋——新阈值/分支的推导出处写进设计(§2 设计先行)。阵容结构等玩法约束在 §2 改前必读的文档里,不在此复述。

## 2. 改策略前(不可跳)

1. **判读上局**:按 telemetry-reading「判读流程」找不合理处,结论写进进度账本再动代码(单局数据≠结论)。
2. **读全部策略相关玩法文档**:基线清单与阅读顺序的单一源 = `docs/game/currency_war/research/README.md`「策略相关文档」节(全目录,唯一排除 screen_flow_timing)。不读全就无法预判改动波及面,「只读一篇=读局部」。
3. **改动先定位,再动手**:答两问——①这次改动牵涉哪条既有原则?②它落在 strategy 设计(`docs/develop/currency_war/strategy/`)的哪一层?两问都答不出 = 改动在既有设计里没有位置:先停下问「为什么设计里没有它」,再决定改设计还是落码,不许直接写。修复时重构优先于打补丁。
4. **设计先行,写清再动代码**:落点函数/影响消费点(含测试锁)/预期行为变化/验证法——「现象→定位函数→改」缺设计层是常犯病;新阈值/分支的推导出处写在这里(§1 骨架)。

## 3. 改动的落地:开关生命周期(行为改动一律走开关;堆积=债)

**行为改动一律先以默认关开关落地**(纯重构/无行为变化除外)——开关是改策略的常规形态,不是例外;落码时必须带出口,四态循环:

1. **落码(默认关)**:占位值不做生产决策,默认关时行为与改动前完全一致;开关带开臂判据挂账——什么数据、什么阈值才开。落码同时三同步:ADR(why)+ strategy as-built 正文(语义)+ 代码注释引 ADR。
2. **A/B 验证**:数据齐就跑;验证不过 → 直接到第 4 态清理,不是无限挂起。
3. **开臂**:验证通过 → 翻默认值,commit 记录;同时盘点断言旧默认行为的行为锁组(hash 锁之外的锁最易漏),随开臂同步改写。
4. **清理**:概念被数据否决 → 删码留 ADR(代码+开关+锁组都是死重);清理批逐项声明删了什么、ADR 记为什么否决。

盘点义务:定期盘点开关全景(开/待验证/待清理)——「开臂条件已消失或永不满足」且「概念已定谳」的开关,进清理批,不继续挂。

## 4. 验证(策略验证的纪律与阶梯)

测试分层命令(L1 快速集/L2 点名/L3 全量,~3/5min)= SKILL.md 单一源地图「测试分层」行。sim 工具怎么用 → [sim-testing.md](sim-testing.md);实机局怎么判读 → [telemetry-reading.md](telemetry-reading.md)。策略验证阶梯与纪律:

- **改进方向对准过程量,末端量只作验收与报警**:过程量(完成度/成型/经济纪律)是因果上游;hp/胜率/出口金用于验收与报警,拿它当改进方向=目标函数错。验收口径本身=当期目标行判据(A/B 尺子,telemetry-reading 步骤 0)。
- **改前基线→改后对照(A/B)**:A/B 回答一个问题——这个改动让指标变好了吗。改前跑一次 sim 批记下基线 → 改后同参数(`uv run python -m sr_od.application.currency_war.cw_sim batch --n N --pool snapshot`;两侧同池指纹,跨日必核一致)再跑一次 → 对比:**变好→采纳;变差→查清为什么**(定位机制,或声明该维度 sim 不可信;查不清=别上实机);**没变化→改动无效,不合入**。没跑基线的「改后达标」不构成证据。指标=sim 统计脚本的输出(sim-testing 一、第 1 步)+**达标占比**——线来自当期目标判据,跑之前写死,防止看完数据挪线。仍然差的指标 → 回 sim-testing「找问题」三步下钻。新机制先验证它会开火(触发条件 0 次=输入死的,先补观测再测)。
- **改动影响面**:改动后必跑 `cw_replay --diff`(秒级)看行为漂移首发点——分歧=漂移≠好坏;digest/轨迹级两侧钉 `PYTHONHASHSEED=0`。
- **参数精调用敏感度**:同策略扫参数,弹性大=值得实机精调;平坦=不花实机局数调它。
- **判读锚点事前写**:实机局开跑前写清「预测什么会变」,跑完核对——事后找解释不是验证。锚点没中 = 改动没生效或假设错,两者都要查。
- **实机验收=连续多局达标**(以当期目标为准),单局胜负不构成证据(§1)。险胜不算过——贴线通过是策略缺陷症状,与明显失败同权重分析;局后判读是必做项,异常条目当场定位,定位不了不进下一局。
- **阶梯终点=结论兑换**:跑完 A/B 不是终点——结论必须当场兑换为三选一:改行为(有效)/不合入(无效)/调常量(量级待定)。A/B 对照手段(registry 注入/临时开关)不进生产代码;「默认关的悬置开关」=已判决未执行的悬案,禁(见 §3 开关生命周期)。

## 5. 行为的锁定:单帧锁(验证过的行为变成回归资产)

验证确认的行为,固化成单帧锁才算回归资产——「模拟是发现工具,单帧锁是回归工具」:

- 位置与模式:`sr-od-test/test/sr_od/app/currency_war/test_cw_<主题>.py`;构造 `GameState`(plane/round/gold/level/board/bench/shop/xp_progress)+ `StrategySession` → 调被测方法 → 断言动作序列。锁的来源不问(sim 随机发现/实机判读/验证确认),锁的都是策略决策行为。
- **断言写语义不写巧合**:「配方 gap 时围栏内只买配方件」而非「买了卡 X」(换发牌就碎)——锁的是策略意图,不是当时的牌面。
- 维护:测试仓 gitignored 独立维护,提交在测试仓;语义演进时旧断言随改,docstring 记一句为什么旧语义过期。

**锁的存在性纪律**(通用条款单一源 = `sr-od-test/README.md` 测试纪律第 8 条;CW 因锁密度高——300+ 文件、registry 哈希锁 30 天被动更新 60+ 次——而两条倒退路径都实测走过:好改动被旧语义的锁否决而回退,坏改动借机械跟绿的锁更新洗白。故写锁/改锁额外守):

- **新锁必须引设计出处**:docstring 写明出处(设计章/ADR),无出处=先补出处再落锁——引不出出处的锁,大概率锁的是偶然实现而非设计意图;
- **改锁=重推语义,不是机械跟绿**:锁红了先问「被锁语义还是当前设计意图吗」(引 ADR 对账),语义已被取代的锁走改写/删除,直接改值保绿=洗白通道;
- **「老」不构成删锁理由**:判删必须引设计文档证被锁行为已非设计意图。

# 27 过场与推进型画面策略面(transit screens)

> 画面 = 货币战争-简报 / 货币战争-BOSS简报 / 货币战争-位面过渡 / 货币战争-位面详情 / 货币战争-大厅(回大厅收口);**能力面** = [../flow/screens-actions-capability.md](../flow/screens-actions-capability.md) §3.1/§3.8。本篇 = 这些画面的**策略面**——结论先行:全部为**无策略决策面**(推进为流程义务),本篇是该「无决策」的显式申报,防后续误挂策略判据。

## 1. 策略思路/算法概述

- **无决策面**:简报点「下一步」、BOSS 简报/位面过渡点空白、位面详情关闭、回大厅收口——全部为空决策形态 op(`../screens/op-layer.md` §1.5),推进即画面终结,零策略器问询、零逻辑态账(逻辑态 = 动作执行后不经观察、按游戏规则推算并直写容器的预期状态,真值以下一帧观察为准(观察赢))。
- **与策略链的三个衔接点**(衔接归邻接画面,不在本画面决策):
  1. BOSS 简报关闭后自动开商店(多触发源之一,`docs/game/currency_war/research/screen_flow_timing.md` #14)→ 商店期接管([23_shop_screen.md](23_shop_screen.md));
  2. 位面过渡进入下一位面后照常自动开商店(唯 1-1 例外)→ 同上;跨位面 HP 继承与开局 HP 先验 = 观察供数(`kernel/cw_opening_hp.py`),非本画面决策;
  3. 恢复局(进过战斗后异常重启)商店交互被游戏禁用(只能出战,`docs/game/currency_war/research/economy.md` §2.1)→ 外循环锁定态直通出战(`operations/cw_loop.py::locked_resume_sync_and_battle`),策略面无补丁位。

## 3. 能力 vs 策略

本画面族策略面恒空:能力面(推进/关闭,能力矩阵篇 §3.1/§3.8)与策略面(无)的差异是画面性质使然,非策略收缩结果(收缩判例仅在商店期,[23_shop_screen.md](23_shop_screen.md) §3)。

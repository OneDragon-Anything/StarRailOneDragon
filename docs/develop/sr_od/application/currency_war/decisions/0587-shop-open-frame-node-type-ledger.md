# ADR-0587: 店开帧 node_type 台账制——无条件滞后拷贝退役

- 状态: Accepted(方案审零阻断后实施批落地;落地审轻阻断四项文档补丁+站点 2 收编随批)
- 关联: ADR-0580(②(a)/②(b) 奖励帧经济纪律与 None 语义)、ADR-0462(阶段字段规格,`prep_shop_open` 不含 node_type)、ADR-0583(帧代次/黑板契约)、ADR-0414(接管补采)/dd-023(位面情报时序)、ADR-0234(节点台账语义族);**取代声明**:ADR-0173 所依赖的「node_type 经 `session.last_node_type` 携带(shop.py 拷入)」携带链被本修结构性取代(其 boss 帧判定意图由台账 'boss' token 供硬节点补强门的更优实现承接),ADR-0173 历史文件不改写,后来者勿按其 §依赖声明找回旧链。

## 背景

实机局复盘立案的 C2 缺陷:`dead_gold_press_buy`(②(b))在 p1r3 **普通战斗**节点发射(买入爻光),而 ②(b) 帧型判据要求 `node_type=='reward'`。根因裁决 = **帧态滞后**,归层 = **流程组装层**(非识别层、非谓词层):

- 店开帧(`PHASE_PREP_SHOP_OPEN`)节点行被遮,node_type 结构性恒 None(ADR-0462 字段规格不含该字段);
- 组装代码把无键会话标量 `session.last_node_type` **无条件拷入帧**;
- 该标量唯一写点 = 备战环 heavy 观察(shop 关态节点行可读才写),正常轮节拍下写点晚于本轮店开 → 店开帧拷到的**结构性为上一轮值**。p1r3 上一轮恰为奖励,滞后 'reward' 落进战斗帧,同时误开 ②(b) 并误抑制 M3 升级。

识别层全程无罪(备战屏标签 OCR 两读「战斗」、nodeseq 探针正确命中 r3);谓词层按规格行事(None fail-open、'reward' 放行),输入错误值不是判定语义缺陷。

## 决策

店开帧组装(`operations/cw_op/cw_op_buy_cards.py` 商店 visit 段顶入口观察)的 node_type 供值改为**台账查表**:`ledger_node_type(session, state.plane, state.round_num)`(键 = 本帧 `phase_round` 现读的位面/轮次)。台账按键 (plane, round) 存储,查表**结构上不可能滞后**——与关店帧(prep_clean)既有台账优先链同构(`cw_observation.py` 节点类型段),执行层同层先例 = `cw_op_equip_all.py` 装备判定直查台账。查不到(台账缺档/续局未随局建/位次越界/该位次未识别)→ **保持 None fail-open**,不猜。

**第二拷贝点删除**:买后重估回退分支(`operations/cw_screen/cw_screen_prep.py`,prep_clean 全量读之后)曾用 `last_node_type` 无条件覆盖帧 node_type——该全量读已走台账优先链拿到新鲜值,覆盖只会把对的改错的(独立缺陷级),直接删除。**增量路径同批收编**(落地审裁决):`build_post_buy_incremental_state` 的 `last_node_type` 参数与函数内覆盖一并删除——垫底帧 state 经站点 1 修复已带本轮台账值,deepcopy 透传即为真值,旧实参(`session.last_node_type`)在非 None 时会把 deepcopy 已带的台账值盖回跨轮滞后值;该路径唯一消费链(方向视图刷新)虽不读 node_type(方案审定谳:半活性,残余风险限遥测/留证帧污染),同根同型一并归零,不留第二通道。

### Considered Options

| 方向 | 裁决 | 理由 |
|---|---|---|
| A 台账查表制 | **采纳** | 键查表结构上不滞后;关店帧同链在案;执行层先例在案;附带修复 M3 误抑制与硬节点门(见下) |
| B 写点锚定门((plane,round) 不等 → 不拷) | 过渡可选,**禁与 A 平行存活** | 归零能力成立,锚语义健全;但 A 落地后以平行门形式存活 = 死代码+双源。本批选 A 一步到位,B 不落地 |
| C 开店前强制轻观察 | 否决 | 备战入口 heavy 观察本来就是「开店前的读」,滞后之所以存在是该读常产 None;C 只是把同一个会失败的读挪到更紧张的时间窗(开店点击竞态)再付一次 OCR 预算,不提供新信息源 |
| 三票校验扩消费到店开帧 | 否决 | 三票(ROI OCR/位置推断/高亮 Hu)全部依赖节点行,店开帧行被遮 → 全票弃权空转;关店帧已在跑三票,对台账错误的监视已覆盖 |

### 前置件(续局台账)与残余缝

续局/接管场景的台账冷建补写**消费既有通道,零新增写点**:①入口图通道(位面序真值缺失 → 委派 `CwScreenPlaneIntel` 实采);②接管补采(`_takeover_collect_if_needed`,ADR-0414,两次失败放弃);两者经 `close_and_report` → `ledger_update_plane` 落账。台账与 `briefing_bosses` 同宿 session、同生命周期(新局同空 → 补采触发;继承局同在)。残余缝(接管补采两次失败;0n 外循环店已开直入,ADR-0562)下查表返回 None → ②(b) fail-open 不发射,**与 None 语义同向,不构成正确性洞**,仅奖励帧纪律在该窗口弱化(由 ②(a) 节点无关承载)。

## 行为面申报(四条,含一条负向)

1. **负向申报(有意变化)**:连续硬节点段(相邻轮遭遇/boss 同型)中,旧滞后值「恰好上一轮同型」会侥幸打开硬节点补强门(`hard_node_reinforce_gate`);台账制后该形态变 None 关门——**旧 = 碰巧对,新 = 诚实不猜**。
2. **正效应①(M3 误抑制同步校正)**:滞后 'reward' 落进战斗帧时,M3 规则①(`reward_node_suppressed`)把战斗帧的升级错误抑制(方向 = 人口停滞,与 C2 同根、先于 C2 显形的隐性病灶);修复后战斗帧 fail-open,M3 恢复正常求值。
3. **正效应②(硬节点补强门首次拿真值)**:店开帧把 `state.node_type` 传给硬节点补强门,今天因滞后值长期误关;台账制后该门在店开帧首次可辨真实节点型。
4. **遥测面申报(扑满标记刷新收窄)**:`v3_piggy_reward` 遥测真值的刷新触发面(`shop.py` 每可辨奖励帧刷新点)从「滞后值伪装的奖励帧」收窄到台账背书的合法奖励帧——修复前非奖励帧会被滞后 'reward' 错误触发刷新(标记失真),修复后非奖励帧不再触发;纯遥测面,无行为读者,如实申报。

②(b) 面:台账含本轮 'reward' → 值进帧 → 合法奖励帧发射照旧;None 帧 → ②(b) 沉默,死金域「禁死囤」义务由节点无关的 ②(a) 备战凑息承载(其触发 = gold<g*,ADR-0580 已接受的失效方向,非本修引入)。

## 验证口径

本修属 **operations 执行层帧组装**,sim 决策核由 engine/adapter 自行装配帧——**缺陷与修复对 sim 双重结构性不可见,禁 sim A/B 作验收**。验收 = 单帧锁(`test_cw_node_type_ledger.py`:战斗帧+滞后 reward → ②(b) 不发射且 M3 不误抑制;台账含 reward → 值进帧;None 帧 → ②(a) 照常 ②(b) 沉默)+ ruff + 既有相邻锁(test_cw_op_journal / test_cw_dispatch_wrapper 只读参照)。实机锚点(事后验证):① ②(b) 发射帧的 (plane, round) 与该轮结算屏 node_type 全量一致;② 战斗帧 `reward_node_defer` 计数归零;③ 压库买入发生在奖励帧。**回归监视**:关店帧三票 defect 台账(`record_defect('node_type','perception_conflict')`)持续零恶化——台账成为店开决策源后,关店帧三票记账是台账错表的唯一既有安全网,列为本批验收的持续监视条款。

## 后果

- 正面:C2 形态(战斗节点误发射 ②(b))归零;M3 误抑制与硬节点门误关两个同根隐性病灶同步修复;店开帧与关店帧接入同一权威节点源,无键会话标量不再充当帧真源。
- 代价:台账缺档窗口内 ②(b) 与硬节点门从「侥幸可用」降为「诚实关闭」(见行为面申报 1);补采通道既有,无需新增识别成本。

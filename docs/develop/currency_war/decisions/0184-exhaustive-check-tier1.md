# ADR-0184: Tier-1 穷举检查器 v0 落地(redesign 28 号处置:金零进展死锁 absence 证明)

## Status

Accepted(2026-08-17,策略优化会话;Tier-2/常数区间扫描/反例回流语料为 v1 增量)

## Context

28 号主张一/二:13 号 56 违约中 38 例金零进展 = 门族挡死全部进展动作的状态死锁,
判定只需精确机制(收入/利息/升级价/刷新价),不依赖掉血先验;采样结构上给不出 absence
证明。J2 判据二选一:①控出语料外违约类 ②证明现行门族下全空间不可达。

## Decision Drivers

- 修复验收标准升级:「语料全绿」(弱)→「全空间死锁不可达」(强证明)
- 纯离线零实机,不与实机窗口项抢资源

## Considered Options

1. **Tier-1 档先行(选)**:进展可达性判定(progress_feasible)+ 全空间扫描
   (gold×level×hp×bench 9200 态),含收入下界;
2. 全量 DP 反演(违规可达性最大化)——工程量大且抽象间隙风险高,Tier-1 已覆盖 J1 的
   82% 骨架档主体;
3. 只跑 fuzz(13 号 v0b 既有)——无完备性。

## Decision

选 1:`cw_exhaustive_check.py` v0——

- ``progress_feasible``:买/升/刷三类进展动作的纯机制判定(价来自精确机制与注册表
  实测:刷新 2[ADR-0177 verified]、升级 clicks×4、买 ≥1 费);门骨架与现行硬门同语义;
- ``deadlock_states``:9200 态扫描,收入下界(base 5+息)纳入(金零进展实锤 = 收入也断
  的自持态;现行机制收入恒在 → 结构性不可达);
- **J2② 结果:absence 证明成立** —— 现行门族+精确机制下金零进展死锁**全空间不可达**
  (n=9200,零死锁);
- 判定器灵敏度测试防恒真:纯零金态(不含收入)死锁被检出;收入下界救活对比;bench 满
  仍有刷/升出边。

## Consequences

- 38 例金零进展类骨架 bug 的验收标准升级为 absence 证明(修复后不会复发于任何状态);
- 划界诚实:hp 毒化 10 例(感知层)显式出界;Tier-2(钉死不 pivot,line 维)与常数区间
  扫描(主张 3,消费 23 bracketed)为 v1;
- 28 号处置完成(v0),提案文件删档;测试 +4。

# ADR-0320: 特权逻辑统一化续记(泛化清除:注册表派生五处+停手裁决;ADR-0311 的落地续篇)

- 状态:accepted(补写;行为已随 W47 批 commit,本篇事后落档)
- 日期:原 commit 2026-08-24(d86d4494);补写 2026-08-25
- 背靠:用户指令「看看还有没有其他类似的特殊处理」→ W45(教义侧:
  扫「优先/默认/必/恒」措辞)+W46(代码侧:grep 具名特判模式)
  双视角审查报告 → leader 合并裁决;W47 执行 5 处落地+2 处停手。
  主决策(readiness 统一维度、删 DOT2 专属加成/铁三角直取例外)
  归 **ADR-0311**(W44,commit 9c7717a8)——本篇是**续篇**:记
  0311 之后对全仓「同类特权处理」的系统性清点与泛化清除。

## 背景与动机

ADR-0311 修的是组合选择打分里最刺眼的两个特殊 if;但「教义措辞
被实现成专属特权」是**一类问题**(用户单点指出的泛化纪律:具体
问题=样本)。W45/W46 双视角扫出 7 处候选:5 处判「应统一」落地,
2 处判「正当/停手」。判据(W45/W46 裁决框架):**身份差异正当
(注册表条目/动作分派/测试构造),门槛差异误实现(该读数据/该变
统一维度)**——误解记录 M11 的判别式推广到全仓。

## 决策(5 处落地)

1. **engine helper 注册表派生**:`decision_v2/scoring.
   _shop_has_engine_card` 原手抄五阵营字面量+`c.name == '希儿'`,
   改读 `cw_system_cards` 派生 helper(`system_judge_factions`/
   `engine_char_names`,ADR-0301 找件判据与诊断口径同源靠 import
   不靠手抄)——**第五张体系卡加入自动传导**;`engine_char_names`
   函数本体从 discipline 上移至 cw_system_cards(注册表旁),消费
   点零变化。
2. **卡→阵营映射字段化**:`SystemCard.judge_factions` 成为单一
   数据源(ADR-0318 本体论字段),消除原先 `_card_factions`/
   `card_active`/`cw_evolution._CARD_FACTION_TIER` **三处各写
   一遍**的同值映射——加卡要改三处 → 零散 if 消除。
3. **win_model 三字面量 import/派生单一源**:铁三角 =
   `cw_line_defs._CORE_TRIO`(注册表 import 不复制)/DOT 件池 =
   `FACTIONS['持续伤害']` 成员 ≤2 费子集(过渡件口径:海瑟音4/
   黑天鹅5 是终局件不进池)/希儿 = `SYSTEM_CARDS['seele'].
   engine_required[0]`(卡注册表)。
4. **`Comp.bond_signal` 数据化**:②类专属羁绊信号 crosswalk 从
   `cw_intention.FAMILY_BOND_SIGNALS` 手编表迁移进 COMP_LIBRARY
   各条(值原样迁移)——判断层手编数据化,COMP_LIBRARY 演进时随
   家族条目走不再双源;按设计无②信号的家族(希儿量子:量子/贝是
   放大器;白厄反甲:独立羁绊绑死单卡)= None。
5. **TRANSITION_TRAITS 派生+恒真死条件清理**:三羁绊对改从
   SYSTEM_CARDS 派生(排除 seele——希儿系是 deployed 单卡判定非
   阵营计数),tier 阈值经 FACTIONS 注册表;cw_sim 侧同值常量改
   alias import(原先两模块各写一份、注释互指——漂移窗口=任一侧
   单改);`candidates._buy_tag` 的 `has_direction or no_direction`
   (两互斥变量取或=恒真)死条件删除,语义不变。

**一致性保障**:派生值与原手编逐项相等的一致性断言锁(10 条);
TRANSITION_TRAITS 派生==原值快照锁。

## 决策(2 处停手,显式裁决记录)

- **条2 CROSS_LINE_SKELETON(跨线骨架件)停手**:当时判「选数据
  入注册表」归 W50——已由 W50 落地:派生自 `W16_MAJORITY_LINES`
  (≥3 线过半 8 张+边界 2 张,ADR-0312),手写快照脱锚风险消除。
- **条3 FALLBACK(绯英兜底线)维持具名+注释改写**:「绯英门槛全
  游戏最低」教义措辞存在**维度歧义**(误解记录 M12:注册表数据
  绯英 minT=3 并非人数最低、core 费用也不是最低;低的真实维度=
  **资源锚**——6 级就能搜 2 费 carry,狼尊要 9 级)。在教义标清
  维度前派生必错,故维持具名;判据沉淀:教义写「门槛低/高」类
  措辞必须标维度(人数/费用/资源锚/等级窗),不同维度的 argmin
  指向不同对象。

**新卡零改动收益**(泛化清除的验收口径):第五张体系卡/新过渡
羁绊/新家族加入时,上述 5 处消费端**零改动**——判据/名单/信号
随注册表数据自动传导;这是 0311「未来加过渡羁绊零改动」承诺从
组合打分单点推广到全仓消费面的兑现。

## Considered Options

- **7 处全统一(条2/条3 也立即派生)**——被否(停手裁决,历史
  记录):条2 缺「哪张注册表」的数据归属(需 W16 统计先入表);
  条3 维度歧义未解时派生=把错误教义固化成代码——**停手也是裁决**,
  显式记录理由而非漏网。
- **一致性靠 review 而非锁测试**——被否:10 条一致性断言锁是
  「派生==原手编」的回归资产,防后续改派生规则时静默漂移;纯
  review 一次性。
- **TRANSITION_TRAITS 双份常量加注释互指(维持原状)**——被否:
  注释互指不是机制,任一侧单改不报错(漂移窗口敞开);alias
  import 单一源。
- **bond_signal 留在 cw_intention 本地表(注释标数据来源)**——
  被否:COMP_LIBRARY 演进(新家族/改档)时本地表脱锚——判断层
  手编数据化是 W45 裁决框架的正解。
- **DOT 件池取 FACTIONS 全成员(不按 ≤2 费过滤)**——被否(事后
  重构补记;口径来自 win_model 原手编对照):海瑟音(4费)/黑天鹅
  (5费)是终局件,进过渡件池会把「终局件在手」误判为「过渡引擎
  就绪」——派生必须携带口径(过滤条件入派生式并注释)。
- **恒真死条件保留(怕语义变化)**——被否:双向触发锁测试证明
  删除前后语义不变;死条件留着会伪装成「有约束」误导后来读者
  (W45 措辞扫描正是被它误导的实例)。

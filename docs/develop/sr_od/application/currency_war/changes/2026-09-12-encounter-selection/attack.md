## 二、指定复核点专项裁定

### ① 残留判定与 telemetry_only 解耦后的行为闭环：**不成立（修复申报面不全 + 手法陷阱未警示）**

代码事实（`cw_screen_battle_wait.py` 直调）：`:304` `_residual = False if telemetry_only else self._mark_relaunch_residual()`——1f 路径（`:534` 唯一 telemetry_only=True 入口）residual **恒 False**；`:564-570` `_mark_relaunch_residual` 真实判定且带副作用（首调置 `first_settlement_seen=True`）。三路调用：胜局 `:640`、3b `:811`（均 telemetry_only=False，取真实判定）、1f `:740→:534`（恒 False）。

1. 解耦义务（让 1f 也取真实判定）只在 details「阶段 E-2」行出现（「残留判定与 telemetry_only 解耦」）；**§8 ⑥（数据通路正典、实现者必读面）只写「relaunch 残留判定（`_mark_relaunch_residual` 返回值）传入环写入位作排除判据」**——照现状返回值接线，relaunch 后首帧恰为失败结算页的残留 1f 行照旧入新局环，与该行自己的目标句「跨局污染消除」矛盾。
2. **副作用陷阱**：正确解耦手法 = 修 `:304` 三元式；若实现成环写位处对 `_mark_relaunch_residual` 二次调用，同帧第二次因 `first_settlement_seen` 已置位恒 False = 假修复。文档未定手法归属、未警示禁二次调用。
3. 生效位置成立：环写位（「W239 守卫 `:372-375` 之后、观察半直写 `:421` 之前」）与 `_residual` 同函数作用域可达；解耦完成后 1f/3b 两路 residual 值语义一致，排除判据在环写位生效。

### ② 对账不对齐率（缺行/多行/序错）作为开闸门成员的可操作定义：**不完备（缺三件）**

1. **无数值验收线**：§9/W14 均为「不对齐率可忽略 → 否则维持暗装」，「可忽略」无判定规则。观测环完整性是**结构不变量**（每场产结算屏的节点应恰有一行），不是统计量——「率 + 可忽略」的统计措辞迫使 E-3 执行者人拍阈值，恰违反本迭代自守的零调参纪律。修法：明示「任一类不对齐 > 0 即不可忽略（结构 bug 信号）」，或给显式容差 + 已知无害形态豁免清单。
2. **「环行序列」离线来源未定义**：运行时环深度 10 截断且随局生灭——直接 dump 运行时环对账，长对局必产生大量「假缺行」（早于窗口的行已被截断），开闸门永不满足。应明确对账对象 = **环写位同点 hook 的全量落盘序列**（landing 3.3 已有「自备采集脚本」但未绑定此语义）。
3. **对账基准侧类型归一口径缺失**：基准 = 「归档对局节点推进记录」，而 `plane_schedule_observed.md:71` 在册「node_type 三源混写属已知历史脏区」（frame 来源英文 token/采集缺口按位置推断）；对账判读前需先定档案侧类型归一规则，否则缺行/序错判定被脏数据噪声淹没。
4. 已到位（核实通过）：对账类型集单一源申报成立——生效词表 `cw_settlement_obs.py:49-50`（战斗/奖励/遭遇/补给/首领/巨星）∖ 补给 ∪「精英」（`cw_screen_battle_wait.py:572-580` `_normalize_node_type` 映射表实含「精英」）；缺行/多行/序错三类语义可操作；运行时上游同缺残余（三调用位均未命中 = 结算处理未运行）已如实申报。

## 三、发现清单

### 高

**高-1｜fill 读数语义方向未定谳，定谳设计存在盲区**
- 位置：details §2（1/2 阈值论证、边缘/不足划分）、§9（进度条语义定谳义务）、代码 `cw_settlement_obs.py:387-418`；知识源 combat.md:38-39。
- 事实：`parse_progress_fill_ratio` 读「红色填充列」，注释只说「条体为红填充，槽底为暗色」，**未声明红色段语义上是「已推进进度」还是「未完成进度」**。而 combat.md:38-39 在册游戏 UI 语义「进度条打够最低进度（**红→黄**）」——红黄分工与读数器「红 = 已推进」隐含假设的关系从未对账。判据把 fill ≥ 1/2 解释为「已推进进度 ≥ 剩余进度」，据此划分边缘（≥1/2，天花板其二）/不足（<1/2，最低档）。若红色实为「未完成段」（已推进段达标后变黄），fill ≥ 1/2 实为「推进未过半」，**边缘与不足系统性互换**：推进不足半的更差败局被归边缘态、获其二天花板 = 乐观向偏差——恰是本设计在解析合成、其五/六现势性、负证据时效处处设防的那类方向。
- 盲区：§9 的 E-3 前置判别式只定谳「节点内归一 (a) vs 位面累计 (b)」，**不覆盖方向维度**。「方向反 ∧ 实为 (a)」形态（每节点独立起落、方向相反）判别式辨不出，将带着互换后的分级开闸；「条为连续填充已定谳——读数器 C2」的已定谳声明也不含方向。
- 修正方向：E-3 前置义务追加「fill 方向定谳」，手段现成：①胜局页 1 帧 fill 经暂存合并可采（契约 1 自述），胜局/败局 fill 分布对比即辨向；②已知 ±N 结算帧（economy.md:137 在册 P2r1「挑战进度+2」）实帧像素直读目视红段位置，一帧即决。定谳前 κ_S 判据维持暗装（并入 §9 开闸门条件），回写面 = §2 状态表。

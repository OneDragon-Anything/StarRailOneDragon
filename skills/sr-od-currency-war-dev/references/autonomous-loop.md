## 2. schedule(四角色;间隔按 CW 节奏定,其他玩法按自己的节奏)

四角色**创建时刻错峰,间隔互质**;**队列纪律:进度树是唯一队列源**——积压局判读/采信未攻的对抗结论/素材消费等都是进度文件显式条目,提醒只做「到点看一眼」的触发器,不造第二队列。提醒触发后无活可派=一行记账,不硬造工作。

### 2.1 实机监控

- **分类**:状态监控(实机跑道状态会自发劣化,不看就烂)
- **间隔**:10min
- **职责**:只管实机——哨兵脚本存活、对局/空窗、局中卡死巡检、推进对比。
- **提示词模板**:

> 【实机监控】看一眼实机:①哨兵脚本还活着吗?②在打局还是空窗?③打局中:最近 10 分钟日志里同一句警告反复出现、又没有买卖上阵动作 = 卡死,停局处理;④跟上一次比,这局有推进吗?汇报说板面和轮次,别只报血量(血量看不出运营好坏)。实机默认一直跑,别为了等模拟停局。

### 2.2 进度处理

- **分类**:积压盘点(队列会积,槽会空)
- **间隔**:15min
- **职责**:只管一件事——**按进度派活,尽量派满**。
- **提示词模板**:

> 【进度处理】看一眼进度树的待办队列,把活派满:①有待办、worker 槽位空着 → 马上派;②定期该做的事到点了吗(积压局判读/没被攻过的结论/新截图和新样本)→ 到点的记进队列;③队列空了别闲着,发散想想还有什么可做;④实在没有 → 记一行「无需派」。

### 2.3 回顾

- **分类**:反思校准(注意力窄化,固定问题)
- **间隔**:20min
- **职责**:主 agent 自己回头检查最近的工作,三问(通用骨架,CW 专属门靠问 2 路由到 CW skill 各节)。
- **提示词模板**:

> 【回顾】问自己三个问题:①最近的工作,有实质推进吗?还是在浪费时间等结果?②最近的工作,和哪些 skill 相关,有遵循按 skill 规范吗?③最近的工作,有打补丁的情况吗?是否存在更好的治本方案?

### 2.4 子 agent 审计

- **分类**:第三方审计(主 agent 自审有偏见,须干净上下文)
- **间隔**:2h(派 agent 型)
- **职责**:把「自己评自己不可信」的条目交给子 agent 干净上下文做。
- **提示词模板**:

> 【review·子agent】派一个子 agent(干净上下文)做审计,对象从这些里挑当前在积压的:①skill 反馈队列里待裁决的条目(第三方判「真通用还是特例」);②可晋升进公共 skill 的候选做法;③自己最近拍板但没被攻过的结论/方案(给攻击型指令:设法推翻它);④采信未攻的存量结论清单。审计结论回来后按 od-dev-agent-autonomous-mode 审查分层收账。

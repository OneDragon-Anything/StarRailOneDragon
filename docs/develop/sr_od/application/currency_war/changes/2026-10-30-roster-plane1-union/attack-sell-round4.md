## 发现清单

### S4-1｜S3-1① 执行载体认定错误：truncate_frame_stable 是截断器不是执行载体，单动作契约下混排序列尾部被静默丢弃，级联补位饿死复现——「饿死环消除」不成立
- 攻击点：三轮处置钦定「执行载体点名 = `truncate_frame_stable` 现行机制，entry.py:187-263 可整序列放行 SellDeployed+部署移动混排…同一画面 op 循环内连续执行完才离开备战」，并明令「禁读成『下轮 op 循环跑差分』」。逐层核实执行链后该主张不成立：
  ① **截断器 ≠ 执行载体**。`truncate_frame_stable` 只做逐动作分类截断并返回列表（entry.py:236-263）；生产消费面 `decide_prep_screen` **只取首项**（bridge.py:253 `return actions[0] if actions else CwActionObsParam`，docstring :217-218「输出 = 决策核发出序列的首个动作」、DESCRIPTION :198「单动作循环发射…非流程侧契约」）。`[SellDeployed(V), 统一拖动…]` 通过截断器后，只有 SellDeployed 被执行，级联拖动在 bridge 被静默丢弃（`emitter_post_truncation_dropped` 只计截断器内部丢弃，bridge 层丢弃零计数零观测）。
  ② **饿死环经尾部丢弃路径原样复现**。卖 V 帧执行后，画面 op 循环下一动作再走全扫 decide（cw_screen_prep.py:801/:805 每动作一次 decide）：§3 :135 设计自证「校验通过 → SellDeployed + **清槽**」——槽已清，第 0.5 步无意图可执行 → 第 5 步 `_step4_shop_session_pending`（意图路径「关店不置会话标记」恒 True，entry.py:546-547/:984-999）先于第 6 步部署拦截 → OpenShop 终结 op 结束本次备战访问（cw_screen_prep.py:783）→ **级联补位在 X 买入前永不执行**——这正是设计自己引用的 S2-1 机制，只是从「下轮 op 循环跑差分」换成「序列尾部被 bridge 丢弃」，被禁的读法经载体缺口原样回魂。若改读「槽保留至序列完成」，下一帧校验「V 仍在场上」必失败（V 已卖）→ 意图作废回商店重评——级联同样中断，且触发 S4-3 的作废循环。
  ③ **席满语境行为破坏具体化 = 逐件卖光场上部署外件**。纯席满（金足）帧 victim = 场上件：卖 V₁ 后板面留洞但 bench 未腾（补位饿死）→ 重开店重评 → 排序输入不变（V₁ 已出池）→ 末位 = 下一场上件 V₂ → 再写槽再卖……循环至场上部署外件卖光才轮到 bench 件（店内卖才真腾位）。这正是 S3-1③「作废不卖（防逐件卖光场上件伤压牌库）」要防的行为，经 ① 的载体缺口重新引入；且商店侧评估的动作面（买/卖/刷新/关店）表达不出「部署补位腾位」这一非卖出路径，评估器唯一杠杆是卖——无中途出口。金不足 ∧ bench 空闲语境级联延迟到商店会话收工后兑现，行为面尚可接受，但帧数放大与「紧接执行」的申报不符。
  ④ **修复路径被设计自身封死**：改流程层（decide_prep_screen 返回整序列 / act 循环消费列表）撞「禁动流程框架」实现边界（:66）；策略层每帧重推导级联需要全扫到达第 6 步，被「关店不置会话标记」（重开店承重前提，:66/:99）结构性挡死。机制在现行架构内无合规落法，设计未提供任何一种。
- 证据：design.md :66（意图槽条载体句 + 禁读令）、:99（不置标记承重）、:135（§3「SellDeployed + 清槽」）；bridge.py:198/:217-218/:253；entry.py:422、:546-547；cw_screen_prep.py:776-777/:783/:801-805；flow/projection_contract.md:92；flow/action_ops.md:56；attack-deploy-round4.md:99（四轮部署审查只对 op 形态、未下钻本层的旁证）
- 严重度：高｜阻断级：**是**（实现者按设计落 = 行为破坏〔逐件卖光场上件 + 级联饿死〕；不按设计落 = 需自行再设计载体，「实现者无需再设计」不成立）
- 处置建议：三选一在设计内定死并改写申报——① 放开实现边界，改 bridge/act 循环消费整序列（动流程框架，需明示豁免）；② 意图槽加「级联在途」策略层状态：卖 V 后同访问内后续帧由第 0.5 步持续发剩余拖动（需定义在途态的校验豁免与收尾条件）；③ 承认级联由第 6 步在商店会话收工后兑现，如实重写级联论证与 §2.5 申报（含席满语境「先卖光场上件才轮到 bench 件」的实际行为或配合作废机制阻断）。

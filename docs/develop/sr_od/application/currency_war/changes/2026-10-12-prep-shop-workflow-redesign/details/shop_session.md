# 商店会话模型（详设）

## 问题与约束

- 边界：本篇只管商店画面（画面档 `currency_war_battle_prep_shop_open.yml`）的会话组织与店内决策。升级判据见 line_and_upgrade；备战域的进出时机见 prep_pipeline 第 4 步。
- 总纲契约引用：契约 A（进出与标记）、契约 B（方向视图消费）、契约 C（节点键登记）、契约 D（评估器的店内场景）。
- 画面能力面（实机归档帧 `sr-od-test/screens/货币战争-备战-开商店/shop_open.webp` 确认）：商店画面为全屏面板，可见商店 5 槽、场上前后台、备战席 9 格；可用交互 = 买牌、刷新（2 金，免费刷新次数另有标识）、购买经验、收起（关店）、商店锁定（未建模，本迭代不引入）、出战。
- **店内动作边界（用户裁定 2026-10-12 + 能力面）**：店内可做 = 买牌、卖备战席、刷新、购买经验；店内不做 = 卖场上角色、点消耗品、拖角色上阵（部署统一店外）。
- **执行链前置依赖**：现行商店域执行环境无执行器端口，卖备战席与买经验在店内发射会失败（as-built 依据 = `screens/README.md` §5.4「商店域执行链未接线」；代码面 = `cw_screen_shop.py` 分发注入的 `ShopExecEnv` 无 `executor` 字段）。启用店内两动作前必须完成执行端口接线（独立落地批，landing §3.5）。
- 单动作循环与零读屏规范不变：刷新维持「访问终结」（op 结束 → 外循环重识别 → 商店 op 重新入口观察读新牌面；出处 = strategy-docs/02 §7、11 §3 决策规则 4）。刷新导致的 op 重进仍是同一会话，不算新访问。
- 失读窗的退出形态 = **工程停机出口**：入口观察发现牌面含未识别槽时框架停机留证（`stop_running`，守卫规范出处 = flow/guards.md §3，用户 2026-08-24 裁决接受阻断代价）；决策侧「花钱动作全禁、只允许关店」仅为纵深第二线。停机后不存在自动恢复路径——人工恢复重跑后，凭「本节点已处理」标记缺失，从备战工序第 4 步重新进入会话继续处理（节点内牌面不变，economy §2.1）。

## 方案

### 1. 会话定义与生命周期

- **一次会话 = 开店动作到关店动作之间的全部商店域决策**。跨刷新重进（op 级）延续同一会话；会话终结 = 输出关店动作。
- 生命周期：
  1. 备战工序第 4 步判「本节点已处理」标记 ≠ 当前节点 → 开店（契约 A）；
  2. 会话内决策循环（§2）；
  3. 正常收工（无可买且刷新判据不通过）→ 输出关店 + 置标记 + 写未消费机会清单（§4）。
- 异常退出不打标记。失读窗 = 框架停机留证（见 §1 边界段）；run 中断同理——两者都无「自动接着处理」，恢复入口 = 人工恢复重跑后标记缺失 → 重新走第 4 步进会话。

### 2. 会话内决策循环

每轮按序评估，输出恰一个动作（现行单动作契约不变）：

**2.1 方向评估（契约 B 消费）**
- 入口调用 `refresh_line_if_needed(gs)`：证据签名含本节点牌面 5 槽（用户裁定 2026-10-12：在商店看到角色时也要能评估更新方向——店里刷出某线核心/贯穿件是该线的直接证据）。签名未变 → 用现值；变了 → 重算（含换目标比较账，见 line_and_upgrade §1）。

**2.2 买牌（买入判定序沿用现行六序，定型前后仅「序 1 名单来源」变化）**

序结构完整承继（出处 = strategy-docs/11 §1，逐序判据本体不动；未定型期的序 1 名单来源 = 现行 search 态语义）：

1. **目标阵容件（序 1）**：定型后 = 当前方向视图名单成员；未定型 = 与候选体系重叠计数达标的结构可达件（现行 search 态判据收编，出处 = 11 §1 序 1 行与 `transition_combos` 体系表）。买或囤；席满时：满栏合成例外（点击一次自动买足凑合成的张数，机制出处 = merge_mechanics §2.5）；凑不成合成 → 置换账（§3）。
2. **场况插件（序 2）**：板面羁绊差一人进下一档的件（user_playstyle [35]）。**买入上限 = 当前上阵空位数**（买入帧硬顶——保证部署步必有位可上，「买了即上、bench 不囤插件」纪律在店内不部署的前提下由此上限维持）。席满 → 置换账。
3. **通用插件（序 3）**：现行 PLUGIN_LIBRARY 判据照旧（座位价值 + 备战席稀缺性定序，出处 = 11 §1 序 3 行）。席满 → 置换账。
4. **压库件（序 4）**：金位超过息线的部分换成低费牌（活期资产，user_playstyle [41] 二次精确化「超 50 尽量压牌库」）。席满 → 置换账。
5. **凑星件（序 5）**：板面同系单位凑 2★ 素材，稀缺性序（出处 = 11 §1 序 5 行）。席满 → 置换账。
6. **纯冗余（序 6）**：边际贡献 = 0 → 停买（出处 = 11 §1 序 6 行）。
7. **名单核心卡支（C1，邻位通道）**：非名单成员但为注册表核心的在售卡 → 维持现行支配买入支语义（出处 = 11 §1 C1 通道），席满 → 置换账。

序 1/序 2 不走息律门的义务通道语义不变（现行 M2 通道收编）。

**2.3 筹资（金不足时的伴生卖出）**
- 想买的牌金不足：卖活期件凑（过滤 = 1★ 全额退的候选，评估器），凑够即买、不多卖（user_playstyle [41]「凑息需要时把备战里非上阵的卡卖掉筹资」；[11] 卖回量最小化）。筹资候选穷尽仍不足 → 该牌进「未消费机会清单」（拦因 = 金不足）。
- 筹资卖出与买入在会话内闭环，不关店。

**2.4 刷新判据**
- 判据本体不动：路径总账形式二（比较「留本级刷到齐」与「升级后刷到齐」两路径期望总花费，出处 = strategy-docs/11 §3；P40/P47/P54 数学件照旧消费）。
- 本迭代唯一改动 = **店内升级后刷新按新等级概率求值**：会话内若执行了购买经验（见 line_and_upgrade §2.2 店内升级时机），后续刷新提案以新等级概率表重算（机制依据：刷新概率按当前等级查表，economy §2）。
- 刷新 = 访问终结（规范，不动）。刷新后牌面更新 → 回 2.1（方向签名随牌面变，可能触发重算）。

**2.5 收工**
- 无可买且刷新判据不通过 → 关店动作 + 置标记 + 写机会清单。

### 3. 店内置换账（席满且凑不成合成时）

用户裁定 2026-10-12：腾位卖的本质是资产置换，比较「商店里新角色的价值」与「手上已有角色的价值」，值得换才换。

```
想买的牌 X（判据已通过，仅席满拦）：
1. 取候选评估器首位 = 手上价值最低的牌 Y（店内场景过滤 = 仅备战席 + 常规资格面：
   线内件不参与置换让位 + P78-1 同 visit 禁卖——本会话内刚买入的牌不作 Y，
   见 §5 承继清单 P78 行）
2. 置换条件：X 的价值 > Y 的价值 + 置换摩擦
   - 置换摩擦 = 卖 Y 的手续费（2★ 亏 1 金）+ 再遇风险折价（折算式 = line_and_upgrade §4
     统一口径；再遇窗口查表单一源 = kernel cw_shop_odds.reencounter_window_frames）
3. 条件成立 → 卖 Y（店内卖备战席，能力面在役，前置 = 执行链接线批 landing §3.5）→ 买 X
   不成立 → X 放弃（进未消费机会清单，拦因 = 席满）
```

- X 的价值评估与 Y 同表（line_and_upgrade §3 给出价值评估函数的统一口径：目标关系/羁绊贡献/合成进度/星级费用）。
- Y 候选穷尽（备战席全是高价值持有）→ X 直接放弃。此时备战席全是有用的东西 = 健康态，X 等下节点（牌面自动刷新）。
- 放弃的牌若只因席满拦（判据本身过）→ 必须进机会清单；若判据本身不过（价值低）→ 不进清单。

### 4. 标记、机会清单与正常重开

#### 4.1 「本节点已处理」标记

- session 固定键名 `shop_handled`，**值** = 最后处理的节点号（位面+轮次二元组；载体口径与契约 A 一致）。仅正常收工时写。异常退出/失读停机不写。
- 判定语义 = 值 ≠ 当前节点号视为未处理；跨节点失效由节点边界重置统一清值（契约 C），值比对作为双保险保留。

#### 4.2 未消费机会清单

- session 键，内容 = 判据通过但被资源拦下的牌记录 `{牌名, 拦因: 席满|金不足}`（正常收工时写；新节点清空）。
- **解拦重开触发**（正常场景，用户裁定 2026-10-12 问询确认存在两类）：
  - 场景 1（席满解拦）：备战域部署完成后备战席空出槽位 → 清单中拦因=席满的记录解拦 → 清标记，下轮全扫第 4 步重开；
  - 场景 2（金足解拦）：任何卖出退金（备战域腾位/节末凑息）后金位变化 → 清单中拦因=金不足的记录按当前金位复核 → 解拦则重开。
  - **解拦复核规则（凑息↔重开仲裁）**：场景 2 解拦后重开买牌，买入判据照常全量执行（含息线门）——非义务件破息即拦，不形成「凑息→买破息牌→再凑息」震荡；义务类（序 1/序 2，不走息律门的现行 M2 通道语义）金不足入清单合法，其解拦购买允许破息（义务优先有例外理由，user_playstyle [6]；且 1★ 义务件为活期资产，破息为临时持有成本，[11] 动态无损语义覆盖）——该循环有限收敛（买一张少一张），设计接受并如实申报。
  - 触发检查函数由本篇提供（契约 A），备战域在部署完成与卖出后调用。
- 收敛保证：节点内牌面不变，判据通过的牌有限，买一张少一张，重开循环必然终止。

## 关键取舍

- **店内卖备战席（翻案）vs 维持店外腾位链**：选店内。店外链每腾一位要「关店→备战卖→重开」三轮画面切换且产生节点内重开语义复杂度；店内卖一步完成。能力面已确认可用。场上角色店内仍禁卖（能力面边界 + 用户裁定），换血场景留给备战域。
- **机会清单 vs 每次状态变化重开检查**：选清单制。备选是「金/席/方向任一变化就重开商店重评」，放弃原因：盲目重开产生大量空转开店动作；清单把重开限定在「确有被拦的判据过牌」时，收敛性显式。
- **筹资放会话内 vs 维持备战域**：选会话内。用户 [41] 原话语义即「买了凑息需要时卖备战线上的卡筹资」，与买牌同账同帧；放备战域会产生「关店筹资重开」的第三种重开场景，复杂度反向。
- **商店锁不建模**：现行未建模锁定交互，本迭代不引入（登记未来扩展；跨节点保牌对「一节点一会话」模型无冲突）。

# 32 统一让位序列判定规格（正本）

> 本篇 = 统一让位优先级序列（卖出让位排序）的**判定规格单一源（正本）**：输入（局面， 牌）→ 输出排序键的判定表、档内键口径、输入契约与消费侧约定全部在此，与实现逐档 as-built 一致（实现单一源 = `src/sr_od/application/currency_war/strategies/impl/mandate_v1/criteria/priority.py` 的 `sort_key`/`sell_order`，下文代码锚 `priority.py:NNN` 均指该文件）；十档判定表自 2026-11-01 起生效。全部卖出/获取消费点（商店获取让位评估、溢出紧急处理、采晶矿腾位、节末凑息、补给选角色）只消费该实现，禁第二排序实现（§1 接口契约）。
> 术语（首现定义）：**让位** = 为买入/腾席/凑金让出资源而卖出的一张牌；**victim（牺牲者）** = 统一序列中被选中卖出的那张牌；**保留张** = §4 定义的单张牌身份；**成员档族** = 名单同源于阵容成员名单的档 2/3/4/5/7；**聚合谓词** = 以「角色名 → 名下全部副本星级列表」为单位计算的判定位（持有最高星/总星级数/名下有无副本）；**实费档** = 牌面当前费用档（变费卡升费后取现值）。**帧/单一源/正本/fail-closed** 等全链术语见 [README.md](README.md) §6。
> 数字来源标注（四种）：【注】/【推】/【拟】/【拍】（章程 = [01_math_framework.md](01_math_framework.md) §6）。本篇判据全为序数结构与既有注册表现查，零新数值（十档全为序数）；用户拍板的立场结构随文标注【拍】。

## 1. 定位与接口契约

- **单一判据源**：`sort_key(unit, ctx) → PriorityKey` + `sell_order(units, ctx)`（`priority.py:526`/`:633`）；全部消费点只消费本实现，禁第二排序实现——各场景自写资格/排序的旧形态是买卖空转的病灶，已随卖出身份段退役收敛。
- **PriorityKey** = 有序元组 `(档位, *档内子键, 退金损失, 在手旗标, 随机尾键)`，字典序比较；同档子键定长，跨档比较在档位分量即分出（元组比较短路，无跨型比较，`priority.py:51-53`）。
- **让路方向 = key 大者先卖**（档位编号大 = 优先级低 = 先卖）；档内「后卖」类属性（总星级数多/单卡星级高/core 成员/退金损失大）取小键（负号），「先卖」类属性（概率高/低费）取大键。
- **部署先行**：部署算法定型档 1，排序作用于部署定型后的局面，回答「手里这些牌谁该让路」；本序列不承载部署域判定（部署定型 = [24_deploy_segment.md](24_deploy_segment.md) §1）。
- **三条硬约束**：①各档判定的数据源必须是注册表/既有单一源现查，禁新造名单（档 8 万金油名单与档 9 羁绊名单为用户拍板的既有常量，例外）；②排序确定可复现（随机尾键走局内随机流，同 seed 同序，§7）；③手牌场景与获取场景共用同一函数（在手旗标区分，§7），禁场景分支。
- **观测载体** = `sell_order_with_keys`（`priority.py:617`）：返回 `(单位, 排序键)` 升序列表（末位 = 最先让路）；消费位从键分量直读档位（键首）与随机尾键命中（池内存在另一件键去尾后全同），禁消费位自算第二份键。

## 2. 排序输入：PriorityContext 与两态名单

`PriorityContext`（`priority.py:100-160`）= 排序所需只读输入的装配体（一次性装配，禁散参；字段容器按装配后只读约定使用）。生产装配 = `assemble_priority_context`（`priority.py:181`），虚拟重算（获取让位/补给评估统一入口）= `assemble_candidate_eval`（`priority.py:307`）。十项字段：

| 输入 | 语义与读口 |
|---|---|
| ① `held_copies` 持牌全量快照 | 角色名 → 该名全部副本星级列表；读源 = 备战位 ∪ 前后台一次只读取（`held_copies_of`，`priority.py:163`）。**聚合口径**：档 2/3/4/5/7/8/9 的聚合谓词（持有最高星/总星级数/名下有无副本）均消费此快照，**与池子过滤无关**——池子过滤只决定哪些牌进入排序输出，聚合判定永远看全量 |
| ② `deployed_names` 部署在场名集 | 档 1 判定输入；读源 = 部署接口 `mandate.select_deployment` 输出；获取让位评估装配时减候选名（§5-5） |
| ③ `line_view` 锁定线名单视图 | `session_scope.line_members_view` 现读口；锁定帧成员档名单 = `members`，未锁定帧 = 空名单 |
| ④ `candidate_members` 候选快照成员并集 | `StrategyState.line_candidates` 三线经 COMP_LIBRARY 成员展开 core ∪ shared；锁定帧恒空集（锁定写入连带清空停算） |
| ⑤ `recipe_members` 过渡配方对成员 | 读口 = `StrategyState.opening_recipe_comp` 槽位直读 + **读前判窗**（见下「配方支判窗」） |
| ⑥ `stay_target` 当前升星目标 | `(角色名, 必要星级, 实费档)`；读口 = `criteria/levelup.stay_target_of`（resolved 实费口径，变费卡随档）；None = 未锁定窗口/无未完成目标 → 档 6 为空 |

**成员档族名单两态**（`_member_names`，`priority.py:424`；档 2/3/4/5/7 谓词共用的名单源，消费位禁自拼第二份名单）：

- **锁定帧** = 锁定线名单 ∪ 过渡配方对成员（P1 锁定局并集；锁定不是配方退出条件；进 P2 后装配侧配方支恒空集，判定端无需重复判窗）；
- **未锁定帧** = 候选 top3 三线成员并集 ∪ 过渡配方对成员。

**配方支判窗**：配方成员属配方体系的存续期（P1）；退出唯一判据 = `plane2_started` 窗口谓词（进位面 2 即退出），**锁定不是退出条件**——kernel 配方支进 P2 即清空且永不再写（写点 = `cw_intention.clear_p1_recipe`），未锁定帧穿 P2 边界时非三线配方成员在 P2 进入帧退出名单；锁后非新线成员按统一序列自然落位，不设 P1/P2 分支。

**need_star 两态取值**（⑦）：

- 锁定帧 = 锁定线知识卡 `need_star` 字段**全量照录**——达标成员不缺省。缺省 1 会让档 2 谓词（need≥2）在锁定帧永不命中、达标完成品错落无星级要求档；装配在 priority 装配支内直读知识卡字段，`criteria/levelup.unfinished_star_targets` 本体不动（其「未完成目标」原始语义与升级触发/停留目标等其余消费位不受影响）；
- 未锁定帧 = 候选三线知识卡 `need_star` 字段 COMP_LIBRARY 直查，命中各线取**最大值**（保守方向：按最高要求判定，未达标即受成员档保护）；
- **无表项成员**（过渡配方物化对象等不在 COMP_LIBRARY 的名字）= need_star 视为 1（无升星要求；判定端缺省）。

**member_rank 序数键取值规则**（⑧；档 2/3/4/5/7 ①键）：知识卡 `member_priority` 字段单一源（`cw_comps.py::Comp.member_priority`），装配读口 = `cw_comps.member_rank_of`（空表/旧数据回退 core 两档派生 = core 0/其余 1）；装配 = 各活性线知识卡字段直读，跨线成员取各线**最小序数**（最高优先，core 优先于非 core）；过渡配方成员不入表（统一低档，经判定端缺省 1 承载）；表外成员判定端缺省 1。序数小 = 优先级高 = 后卖。

## 4. 保留张定义与身份域（排序单位 = 单张牌）

- **排序单位 = 单张牌**，不是角色名：同一名下的不同副本可落不同档。核心判定位 = 保留张谓词 `is_kept_unit`（`priority.py:503`；档 2/档 4 共用）：**本张是该名保留张 ⟺ 本张星级 == 名下最高星 ∧ 该最高星在名下仅此一张**（`unit_star == max_star ∧ copies.count(max_star) == 1`；`copies` = 该名全部副本星级聚合快照）。
- **等价群自愈**：同星多张时全部不属保留张（全落兜底档 10——等价牌概率/退金全同，先卖哪张无差别）；任何一次卖出后名下张数变化，剩余最高星张自动恢复保留身份。真实生效例 = 名下 [2,2]（两星等价群）：双双落兜底，卖一张后剩张 `count == 1` 恢复档 4（need≤1）或档 2（need≥2）保护。（1★×2 不是自愈的有效例：1★ 副本由档 7 过程保护承载，不消费保留张谓词。）
- **身份域**：仅 `HeldUnit`（在手牌）可为保留张；`ShopUnit`（候选牌）**恒非保留张**。获取让位评估的虚拟语境下，将获取的 X 不享受完成品保护，「末位 = X → 放弃买入」分支保持可达——与 X 不进档 1 部署保护同构（`priority.py:561-564` 装配注释）：保护的对象是**已入手的资产**，「这张候选值不值得买」仍由让位试探回答，不由排序身份预支。
- **虚拟语境存量件现算**：升星连锁模拟产物进入虚拟聚合快照后，同名聚合重算，存量件按虚拟快照现算保留张身份（§5-5）。

## 5. 落档边界（全量）

1. **need≥2 未达标名**：全部副本（含中间态多张）留档 3 升星主线——合成需要，不算多余（多余判定只在达标后生效）。
2. **need≥2 已达标名**：保留张（最高星唯一张，含超额完成如 3★）档 2；其余副本（低星 1★、超额同星 2★）自然落档 10——档 2/3/4/6/7/8/9 谓词全不命中，零新增显式判定路径。本档在锁定帧成立的前提 = `need_star_by_member` 锁定帧全量照录（§2）。
3. **need≤1 名（底线两星口径）**：`max_star<2`（凑两星过程，含 1★×1 与 1★×2 中间态）全部副本留档 7；`max_star≥2` 后保留张档 4（2★ 本体与超额 3★ 均按实际最高星），名下多余副本（1★ 与超额同星 2★）落档 10。同星等价群（如 [2,2]）双双非保留张同落档 10，卖一张后自愈恢复档 4（§4）。
4. **万金油/羁绊到 2★**：非成员身份者掉兜底档 10；**兼为线内成员者**（身份可叠加）按 §5-2/3 以成员保留张身份落档 2/4 受保——成员档族谓词在判定序中先于万金油/羁绊档命中，语义统一。
5. **虚拟获取语境**（获取让位/补给评估）：虚拟置入 X + 升星连锁模拟后，连锁合成产物进入虚拟聚合快照重算——**存量件**按虚拟快照现算保留张身份（X 获取后 X 名下已有的完成品张，如 1★ 喂食合成出的 2★，按档 2/4 受保）；**X 自身恒非保留张**（§4 身份域）——1★ X 按其名下状态落既有保护档（need≥2 未达标名 → 档 3；凑两星名 → 档 7；无星级要求已两星名 → 档 10），2★ 直出 X 落档 10——「末位 = X → 放弃」对一切候选牌保持可达。虚拟聚合读口 = `assemble_candidate_eval` 段 1 v_copies（`priority.py:350-357`）。

## 6. 档内键口径注

**档内合成序**：统一序档 → 档内键（§3 表列）→ 退金损失 → 在手旗标 → 随机尾键【拍】（现行约定，档内键不删）。

- **退金损失键**（`_refund_loss`，`priority.py:452`）：口径 = 再购同件成本 − 卖出退金。再购成本 = 实费档 × 同名 1★ 基础副本折算（合成链重建价，折算单一源 = `cw_merge_simulate.star_base_copies`）；退金 = `cw_economy.sell_refund` 单一源。1★ 全额退损失 0 最优，2★+ 折价（合成手续费）损失 1——同档并列时选不亏的卖，保住已付手续费的资产；键内取负号（损失大 = 后卖），仅档内键全部并列后参与定序。
- **成员档序数键**（`member_rank`，档 2/3/4/5/7 ①键）：取值规则见 §2；小 = 优先级高 = 后卖。
- **档 2/3/4 键**：`-total_star`（总星级数多者后卖；跨星副本场景先卖低星——追三星持 1★+2★ 时 2★ 更接近目标星，无此键则跨星副本落随机尾键、可能卖掉高星副本）+ `-unit_star`（单卡星级高者后卖；档 2/4 有判别力，§3 注）。
- **档 5 键**：仅序数 + 通用尾键——未持副本名下 `total_star` 恒 0，星级键无判别力，不设。
- **档 6 键**：`-unit_star`（两星压库牌 = 牌池已抽三张，高星后卖；压库牌可跨星，键有判别力）。
- **档 7/8/9 键**：`-total_star`——档 7/8/9 谓词均限名下最高星 < 2（档 7）或到两星前（档 8/9），名下全部副本皆一星，总星级数即副本计数（攒两张的比一张的离两星更近，先卖一张的）；档内单卡星级恒一星常数、不判别，故不设。
- **档 10 概率分档口径注**：①第一键 = `refresh_prob(当前等级, 实费档)` 商店出现概率，概率高者先卖（容易再遇）；②**按概率值分档非按费用号**；③同概率并入同档，概率同值按费用号升序稳定序（低费先卖）；④`refresh_prob` 缺键返 0——低等级帧 2-5 费撞值时低费先卖有真实判别语义；⑤基线概率表，**投资环境轮岗**（每备战阶段随机一费用档概率翻倍）不感知——确定性不受影响，排序质量观察项；⑥后续键 `-cost`（低费先卖）、`-unit_star`（星级高者后卖，兜底档有判别力）。

## 7. 在手旗标与随机尾键

- **在手旗标**：`HeldUnit` = 0（手持），`ShopUnit` = 1（将获取）；同优先级 0 先于 1（在手优先【拍】）。获取流程的虚拟局面中两类牌同池排序，旗标自然生效；纯手牌场景全部为 0，零影响。
- **随机尾键**：仅当以上全部子键（含在手旗标）相等时参与——即**同一张手持等价牌群内部**的卖出顺序（如两张同角色 1★ 副本）；跨星副本已被档内星级键区分、商店牌已被在手旗标区分，均不入随机域，随机结果无行为语义损失。
- **随机流实例**【拍】：策略器自有随机流 `StrategySession.rng` 直用（构造时按 `strategy_seed` 播种，`cw_strategy_session.py`——策略随机语义归它承载，同 seed 同序，不新增派生设施）。读口 = `priority.py::priority_rng_of`（`priority.py:397`）：session 宿主自带 rng 槽直用；终态契约过渡形态（session = gs 容器、零参 decide 管线传容器本体）按 `config.strategy_seed` 播种局级流并挂策略器状态 scratch（键 `priority.tier_rng`，`priority.py:304`），config 缺席帧 None→0（与策略器构造段缺省播法同值）。
- **复现语义**：逐牌调 `sort_key` 会推进随机流——同 seed 下同输入同序，跨次调用不保证逐位复现（随机域限等价牌群，无行为语义损失）；观测面随机尾键命中 = 池内存在另一件键去尾后与本件全同。

## 8. 卖出取用形态（消费侧约定）

- `sell_order` 返回从「最不该卖」到「最先让路」的升序序列；各触发消费位从**末位**向前取用（让路一张 / 取到凑够为止）。
- **溢出触发**：部署重排定型后消费整个序列末段（连续卖出直至不溢出）；上阵安置 = 部署补位自然承载（部署逻辑保证前后台无空位），无特殊安置规则。
- **无场景专属池子**【拍】：卖出类触发（溢出/晶矿/凑钱/筹资）统一按部署重排后的全局面序列取用，不设「只看备战位」类过滤——部署定型内的牌 = 档 1，天然排序列最前端、永不先卖（行为上等价于只动备战位与部署外牌）；「资格面真全量豁免」指溢出场景的循环防线全通道豁免，非池子扩面。
- **获取让位评估的池子形态**：排序池 = 部署外全集（虚拟备战位 ∪ 虚拟场上部署外件，`assemble_candidate_eval` 段 3，`priority.py:365-393`——场上部署外件入池，victim 落位决定执行路径）；物理约束不变：店内卖出动作只落备战位，victim = 场上部署外件走跨画面计划在备战工序执行（[11_shop_decisions.md](11_shop_decisions.md) §4.0）。

## 9. 边界申报

- **凑息豁免与统一序列正交**：利息动机卖出场景（节末凑息）的候选池过滤谓词 `interest_exempt_member`（`priority.py:478`；豁免集 = 线内成员 ∧ 手持 ∧ `max_star < max(need, 2)`）是场景参数非排序键；被迫类卖出（溢出/晶矿/获取让位）全员参与统一序列，禁挂本谓词。
- **概率表/退金表的其他用途**：概率表同时是兜底档分档数据源（排序内）与压牌库买面 EV 判据的量化地基（P49，排序外）；退金表是凑钱触发目标算术数据源（节末凑息跨档缺口/让位前缀退金），非档位判定输入。
- **序列不承载资格判定**：卖出资格（占位件/系统召唤件/合成素材守卫/循环防线）与排序正交，归评估器与资格装配（[11_shop_decisions.md](11_shop_decisions.md) §4.0/§4.1）；本序列只回答「谁先让路」。

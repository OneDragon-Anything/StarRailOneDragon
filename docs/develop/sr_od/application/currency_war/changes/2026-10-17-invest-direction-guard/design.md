## 1. 问题与动机

- **现状症状**(语义锚 `active_strategies=['黑塔纪元'] 写行 @v237`):P1r3 三选一,黑塔纪元当选;本局 r0 已选命运圣杯邀请(`active_env='命运圣杯邀请' 写行 @v45`)。黑塔纪元服务银河学者线(216 张黑塔入池+追击转圈,`cw_comps.py:446`),与圣杯方向完全无关——策略槽浪费,且圣杯线的策略型强化(命运圣杯契约 = 圣杯 2 档开任务得 Archer,Archer 无商店购买通道,`cw_comps.py:696`)失去该窗口。同帧琼玉专家:青雀(送仙舟组件青雀)同理与圣杯冲突。
- **根因归层(语义层)**:两张选卡判据(策略 `invest_strategy`/环境 `invest_env`,29/28 号稿评分模型)的竞争域构造里**没有「候选卡阵容指向 × 已持有投资阵容指向」的冲突维度**。定义型分区(`invest_strategy.py:405-407`)无条件域收缩;环境选卡的方向分只做加分(`invest_env` env_fit),异线候选不被排除。
- **解决到哪**:持有指向非空帧,与全部持有指向都冲突的候选出域;无指向持有帧选卡行为零变化。
- **明确不解决**:
  - 锁定裁决端(12 号篇 §1)不改——选卡端掐断冲突卡后,「异线定义卡抢锁定」结构上不再发生;
  - **选卡信号→买面转化断裂(外溢立项,不在本迭代)**:方向一致的信号也存在买面通道错位(seed-20261016 r2 远坂凛 = 圣杯线成员仍走 dead_gold 压库通道,语义锚 `BuyCard 远坂凛 reason=dead_gold_press_buy` receipts 首现 @v209)。本护栏为战术件;根治 = 信号仲裁层架构件(选卡→锁定→买面全链一致性),验证 = 复盘报告结语的「选策略卡→买面转化率」批量 sim,按 iteration-design §1.1 自成新迭代,排期由编排者定;
  - 终局 CARRY 恒囤集(registry 扩容)另行专题;
  - 已到手策略不追溯(策略无卖出/移除建模,handler 只 append——既有申报 `cw_economy.py::cap_resolved_of_session` docstring 边界节);
  - 环境的「蓝海」(进入随机环境)类非选卡通道不受辖。

## 2. 方案

### 2.1 阵容指向集(kernel 新判据,单一源派生,零手抄登记)

三类对象的阵容指向集(阵营名集合),落 `cw_investments.py`(与 STRATEGY_BINDINGS/环境表同址;COMP_LIBRARY 经函数内延迟 import——`cw_comps.py:48` 模块级引 cw_investments,反向模块级即成环,`cw_comps.py:465` 先例):

- **环境** `env_faction_scope(env_name)`:①faction 腿:`INVESTMENT_ENVS[env_name].faction`(`cw_investments.py:73`「对应阵营」;盘点:概念股/邀请/契约全量登记,专家类例外特邀专家:加拉赫→击破 `_ENV_FACTION_EXCEPTIONS`,`cw_investments.py:766-768`;时代/经济/规则类为空);②亲和腿:`ENV_COMP_AFFINITY[env_name]` 值键 = 线名,取各线 `factions` 并集(特邀专家:桑博 faction 空但亲和专家桑博DOT 1.0,`cw_comps.py:433`,单 faction 腿会误判通用)。**副阵营随线带入**:命运圣杯邀请亲和含双王圣杯(其 factions 含能量,`cw_comps.py:1022`)→ 该环境指向集 = {命运圣杯, 能量}——能量组件卡可服务双王线的能量副羁绊,判兼容是语义本意。
- **策略** `strategy_faction_scope(strategy_name)`:STRATEGY_BINDINGS(`cw_investments.py:1134`)三腿并集——阵营腿 f 直接入集;角色腿 ch 两源:①`CHARACTERS[ch].factions`(tuple 可多阵营,`cw_chars.py:28`)**全集入集**(用户裁定「从角色去关联对应的阵容」;多阵营角色例:丹恒·饮月 = 仙舟/列车同行);②**成员腿**:ch ∈ c.core_chars ∪ c.shared_chars 的线,该线 `factions` 全集入集(依据:角色是某线登记成员 = 卡服务该线——装备党绑飞霄,飞霄是追击飞霄线 core 首席(`cw_comps.py:1371`),该卡必须对锁定追击飞霄帧判兼容);ch 不在 CHARACTERS → 跳过不炸。**查询归一口径**:策略/环境名入表前一律经 `normalize_invest_name`(全仓同问消费点先例:`strategy_lock_hit` `cw_comps.py:1693`、env_fit `:2042`、augment_affinity `:458-468`;持有名 OCR 形变不归一 = 查表 miss → basis 弱化漏拦)。
- **终局阵容(锁定线)**:锁定 Comp 的 `factions` 字段(`cw_comps.py:104`)。
- 指向集空 = **通用卡**(无阵容指向:纯经济/纯战力/随机角色族/时代规则类环境),无冲突可判。

### 2.2 冲突基准(未锁定 = 已持有投资指向并集;锁定 = 锁定线阵营)

```
if 锁定线槽非空(locked_comp 入参非空):
    basis = set(locked_comp.factions)            # 锁定后:与终局阵容比对
else:
    basis = env_faction_scope(active_env)
            ∪ ⋃ strategy_faction_scope(s)        # 未锁定:与已有环境/策略比对
              for s in active_strategies
if basis 为空: 护栏不辖(无冲突基准)
```

- 未锁定帧基准 = **已持有投资的指向并集**——持有任意带指向的环境/策略即成立;纯无指向持有(如只持打捞人才库)不成立(不辖)。不依赖锁定写入时序、不依赖候选线重算、无信号帧/配方帧形态之分(seed-20261016 的 r2 远坂凛通道滞后、r0 环境先于策略点等时序问题在本模型下不存在——基准只看「现在手里有什么」)。全部持有名查指向集经归一口径(§2.1)。
- 锁定帧基准 = 锁定线阵营,**不含历史持有**(锁定 = 终局方向裁定完成;历史误选不再扩大基准——例:误持黑塔纪元后锁定圣杯,基准 = 锁线 factions,银河学者卡照排)。**降格帧**(`demoted_endgame`,现全库不可达,前瞻语义)锁线不入基、基准回持有并集——与模块既有 demoted 语义(`locked_comp and not demoted_endgame`)同构,降格 = 终局方向暂席。
- 与 `committed_authority`/锁定机制的关系:本护栏不读、不写方向层状态,只消费「锁槽是否非空 + 锁线 factions + 持有投资名」三样现值——方向层单一读口约定(12 号稿 §2)不受影响;P2 兜底锁定(`line_select.py:186-190`)后锁槽非空,基准自动切换,无失明形态;**P1 配方对链刻意不参与**:配方物化的伪阵容 `factions = sorted(bonds)`(`cw_intention.py:992`/`:1043`)是羁绊键逐帧重派生值,非注册表阵容语义,且配方是过渡板面(与终局选线正交)——配方期帧基准 = 持有投资指向(通常为空或仅环境指向),护栏按 §2.3 照常工作,无配方失明形态。

### 2.3 护栏规则(两张选卡判据同款)

对齐判定 = **候选指向集 C 与基准 basis 的集合交**:

| 帧 | 候选指向集 C | 处置 |
|---|---|---|
| basis 空(无指向持有 ∧ 未锁定) | 任意 | 现行评分,零变化 |
| basis 非空 | C 空(通用卡) | 正常评分 |
| basis 非空 | C ∩ basis ≠ ∅(与任一持有同阵容/与锁定线同阵营) | 正常评分 |
| basis 非空 | C 非空 ∧ C ∩ basis = ∅(与全部持有指向都冲突) | **出域**(off_direction 标记) |
| basis 非空 | 全部候选出域 | 回退全候选 argmax(tag 归因;不制造空选) |

- 排除语义 = 域收缩(不可选)非负分——自含论证:29 号稿「全部零拍值」纪律(§2.4 立场分表【拍】形态),负分方案须拍「多大负分压得过各类正分」的自由参数;排除后剩余域 argmax 照常。
- **定义型分区保持**(29 号稿 §3):basis 空帧定义型秒选保留(定义新方向 = 正收益面,如无指向环境局拿黑塔纪元即转大黑塔线);basis 非空帧异线定义型已出域,对齐定义型(如大黑塔方向局再遇黑塔纪元同族)照常进分区。管线序 = off_direction 过滤 → 禁选排除 → 自拆台 → 血本位三态 → 定义型分区 → argmax。
- **基准演化申报**:持有投资只增不减(handler append-only)→ 未锁定期间 basis 单调不减,出域判定只收紧不放松。**锁定切换 = 换基语义**(非单调点,双向皆可能):新基 = 锁线 factions——收紧 ⟺ 锁线 factions ⊊ 旧并集(例:持圣杯邀请 basis {命运圣杯,能量},硬规则锁红A → 新基 {命运圣杯},能量星徽由兼容指出域);放松 ⟺ 锁线 factions 含旧并集外阵营(例:兜底锁追击飞霄 → {追击},狼狩星徽由出域变兼容)。切换帧的选卡结果变化属锁定裁决语义,非护栏抖动;回归对照(§3)在锁定切换帧不适用逐位一致,以切换后语义为准。
- **reason 文法**:`_pick_domain` tag 按管线序拼接、空格分隔——`off-direction` → `all-excluded-fallback` / `blood-forced` / `defining-zone`(现行集)→ `pick total=...`。既有契约如实申报:测试断言 `startswith('pick total=')`/tag 恒等(`test_invest_strategy.py:1134/1157/396/438`)——护栏生效帧 reason 必然改形;既有测试跑在 basis 空帧不触发故不红;新行为测试按本文法写。

### 2.4 接线点与影响面(流水线位置与刷新交互)

- **策略侧** `invest_strategy.decide` / `decide_pick`:评分帧保留全量候选(逐卡 `off_direction` 标记,不前置过滤——帧级门「候选恰 3」(`invest_strategy.py:509`)与刷新分类全量可见);排除在 `_pick_domain`。**刷新侧出域卡按 29 号稿 §4「E-豁免」同款**:不入帧级顶级判定(`invest_strategy.py:513` 现式扩 `not c.off_direction`)、不计 max_N、**恒入刷新动作集**(被禁槽恒入同款类推;动机:出域卡占槽应刷掉换本线卡机会)。F2 唯一 L1 槽守卫不变。
- **环境侧** `invest_env.decide` / `decide_pick`:出域槽并入**既有 excluded 槽位表通道**(`invest_env.py:365-377` forbidden 同路)——forbidden_slot ∧ 次数闸过 → 先建议刷新;闸尽落 pick 时出域已排除,全出域帧走既有 all-excluded 回退(`invest_env.py:311-316`)。「回退」仅在不可刷时可达,可刷先刷。
- 影响面量化(catalog-snapshot.md):方向持有帧,策略 87 张绑定卡(定义型 7+非定义型 80)中与持有指向异阵营的多数出域;环境阵营指向约 44 张中异阵营的出域。basis 空帧(无指向持有)与通用卡全帧零变化;现有测试全部 `_fresh_gs` 无环境/策略写入 → basis 空 → 回归面干净(`test_invest_strategy.py` 全量核过)。

### 2.5 关键取舍(正本化时进动机段)

| 取舍 | 选 | 放弃 | 为什么 |
|---|---|---|---|
| 基准 = 已持有投资指向 vs 方向线判定(硬规则首线/锁槽三级) | 持有指向并集 + 锁槽切换 | 方向线三级判定 | 方向线模型有三类结构性失明/时序问题(P1 配方帧、P2 兜底锁、锁写入滞后),每类都要补丁;持有指向模型下三者不存在(基准只看现值),且与用户语义逐字对齐(「未锁定看和其他环境、策略有没有冲突;锁定后看和终局阵容有没有冲突」) |
| 排除 vs 负分 | 域收缩排除 | 大负分 | 29 号稿「全部零拍值」纪律,负分须拍自由参数;排除语义 = 裁定「不可选」非「不优」 |
| 阵营集交 vs 线集交 | 阵营层判定 | 指向线集 ∩ {方向线} | 线集口径在散件阵营卡(公司/狼狩/盛会之星,无对应终局线)上恒空 → 永判通用失明;阵营层判定下散件阵营卡对持有指向异阵营即出域,且未锁定期的双王圣杯(含能量)方向摆动不产生判定翻转(锁定换基另见 §2.3 基准演化申报) |
| 宽口径指向 vs 复用方向分触线集 | 独立宽推导 | `_touched_line_comps` 窄口径(角色腿只认线 core) | 窄口径下琼玉专家:青雀触线为空,护栏失效;两套分野:方向分问「对锁定线值几分」,护栏问「与持有阵容冲不冲突」 |
| 派生 vs 手补登记 | 角色腿经 CHARACTERS factions 现查 | 逐卡手补绑定阵营腿 | 零登记、版本重采自动跟(PIGGY_ENV_NAMES 先例,`cw_reward_node.py:30-38`) |
| 锁定端联动 | 选卡端掐断,锁定端不动 | 锁定裁决改 | 选卡端排除后异线定义卡不入手,抢锁定结构消失 |

### 2.6 边界申报

- **指向集单调性**(§2.3):持有 append-only → basis 单调不减,出域只收紧不放松;唯一非单调点 = 锁定切换(换基双向语义:收紧/放松均可达,§2.3 基准演化申报),属锁定裁决语义非护栏抖动。
- 绑定角色改名/未进 CHARACTERS → 该角色腿跳过(指向集收窄 → 可能漏拦)——OCR 缺名 fail 方向一致(缺读宁放行);版本重采检查单已含投资表比对,角色表随盘。
- 「乱成一锅粥」(备战席随机变形,引擎卡)无绑定 → 通用不受辖;变形结果与方向一致性不归本护栏。
- 误持冲突卡后的帧:basis 并入该卡指向(append-only)→ 后续候选对它兼容即合法——已发生的错误不放大也不追溯(与「明确不解决」一致);锁定后基准切锁线,历史误持出基。

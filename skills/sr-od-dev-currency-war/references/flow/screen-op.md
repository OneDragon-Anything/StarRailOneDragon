# 画面 op 与观察域(screen-op)

> 组件 = `operations/cw_screen/`(一画面一 op)+ `obs/`(一屏一解析器)。路径根 = `src/sr_od/application/currency_war/`;代码定位一律用 `文件::符号名`。

## 1. 画面 op(职责四段 · node = 1 + N + 策略器按需)

- **一画面一 op**,每屏独立类直继承框架 `SrOperation`(无共享基类)。职责按四段组织:识别 → 上报 → 特殊画面流程处理 → 正常画面的策略器处理。

1. **识别**:本屏身份判定(门);
2. **上报**:显式读屏〔唯一读屏点〕→ CwScreenXxxObs → `report_screen_*_obs` 落状态容器(`kernel/cw_screen_report/` 每屏一文件)——**上报先于处理**,特殊流程与策略器消费同一份观察;子态分支例外(备战特殊流程段,见「备战(CwScreenPrep)特殊」行):非常规子态帧的子态识别前置(段 1 先于读屏上报,命中即跳过全量读屏与上报),段 2 语义扩展 = **子态流程事实写**(Match 流程态字段配对写 + 接管失效写)非 obs 上报——流程事实不进状态容器(真值域不混流程事实);
3. **特殊画面流程处理**:弹窗/锁定态/按钮换形态这类**答案固定**的状态——画面 op 自己的流程反射(识别 + 点击 + until 验证),不问策略器;
4. **正常画面的策略器处理**:需要判断的交策略器——决策(状态容器零参读;本帧无动作 = Obs outer_loop 口径)→ 动作〔零读屏〕→ round_wait 循环无防御上限;**终结动作返回主循环**。

- **分段判据**:答案固定的 → 特殊流程;需要判断的 → 策略器。
- **node 结构 = 1 + N + 策略器(按需)**:识别+上报合并一个 node(门 → 读屏 → 上报);特殊流程每类一个独立 node(按需 0..N,**禁多个特殊流程挤在一个 node**);策略器循环一个 node——**有判断需求才有**:处理方式全固定的屏无策略段,画面 op = 1 + N(启示 = 敌人信息浮层待建形态)。特殊流程 node 的本段识别(标志判定/确认定位)= 决策环读屏例外第三类(§2)。「识别+上报合并一个 node」的线性序在子态分支例外:备战子态识别四查落观察 node 最顶部(先于读屏上报,命中即跳过读屏上报),三处置共享决策动作 node 顶部特殊流程分流位(不按每类一 node 拆)——豁免见「备战(CwScreenPrep)特殊」行。
- **弹窗归宿形态三分**:
  - **有独立 id_mark 身份的弹窗屏** → **独立画面 op**:四段只走「识别 → 上报 → 特殊流程」即交回主循环,无策略段(先例 = `CwScreenDeployNotFull` / `CwScreenNoFrontHint`——出战单击后渲染的两类真弹窗,经主循环阶段一身份分发接管);
  - **无独立档但经阶段三规则派发的独立 op**(消耗品浮层/阿哈装备)= 合法现役形态——归宿细化(判定的宿主与 op 门形态)随下批迭代裁;
  - **无独立身份的浮层/子态** → **宿主画面 op 的特殊流程段**。
- 备战(CwScreenPrep)特殊:heavy 观察+接管补采+审计留在观察侧的观察 node;决策动作 = 单动作 while 循环;商店编排(`_open_shop_phase`)。**特殊流程段消费首批实例 = 备战交互三段链**(自主循环备战分支迁入,迭代 2026-11-18-prep-special-flow;宿主表述 = `operations/cw_screen/cw_screen_prep.py`):观察 node 最顶部**子态识别四查**(先于 match 缺席门/清场/收店探针/heavy/补采/审计;优先序 0 > a > b > c)——0 锁定确认态(`Match.locked_resume`,含段3b retry 耗尽后主循环重派发的重入帧,直达段3b)/ a 返回按钮子态(OCR「返回投资策略选择」lcs 0.9 防线)/ b 恢复候选探针子态(候选过判即接管失效写 → 点「按钮-商店」试探〔识别性点击,读屏例外 §2④〕→ 判定 → 候选无条件撤回;非锁定收店后按序跑齐全部既有前置段走常规)/ c 补给分流子态(nodeseq current=supply ∧ 补给未确认);子态命中即跳过全部既有前置段,查全否走现行全量路径零变化。决策动作 node 顶部(段序号置位之前)**三处置**:a 点返回〔成败均交回,计数 = `cw4_counters` 分键 `back_to_strategy_symptom`〕/ b `locked_resume_sync_and_battle` 同步步+出战〔成功 = 锁解除+交回;未执行 retry 保锁,每访问 4 次,耗尽 → 访问 fail → 外环 fail-streak〕/ c 点「返回补给阶段」〔成败均交回〕;交回 = round_success(wait 2/3/2),战斗窗置位由外循环回调统一承载。三子态不拆独立 op(宿主同 = 备战画面,派发依据双识别标志无独立身份)、不按「每类一 node」拆分——三类处置共享决策动作 node 顶部特殊流程分流位,本行为本行豁免。
- 行为规范、上报接口、形态分型、obs 工具箱的完整设计 = `docs/develop/sr_od/application/currency_war/screens/op-layer.md`(画面 op 层设计)+ `screens/README.md`(一画面一文档,能力矩阵与画面文档模板)——该目录后续批次迁移。

## 2. 观察域(obs/)

- **唯一读屏点**:画面 op 观察 node 的显式读屏(备战入口 heavy 观察 `obs/cw_observe_full::observe_full` 为其重型形态);已登记读屏例外四类——①策略显式发出 Obs(in_place) 触发的重观察;②终结分支返回前机械保留证据读(零决策零判效,读数只进缺陷台账);③特殊流程 node 的本段识别(§1 段 3:答案固定状态的标志判定与确认定位,先例 = `CwScreenDeployNotFull` 落地复查位与 `CwScreenNoFrontHint` 确认后的标志复测);④段 1 子态识别的识别性点击(备战特殊流程:探针点击〔点「按钮-商店」试探商店可开性〕与非锁定收店恢复点击——点击 = 识别手段非策略动作,裁决结论经段 2 流程事实写上报)。
- 观察 node 上报 = `report_screen_*_obs` 落状态容器(`kernel/cw_screen_report/` 每屏一文件)。
- **坐标伴随域(观察必须产出坐标)**:观察域识别的「可选/可交互实体」(选项卡/备战栏条目/装备栏条目/晶矿/浮层按钮等),其上报事实一律携带画面坐标(cx/cy 或等价定位)——状态容器字段与 MCP extras 同源可得,坐标不得只存在于 extras。用途 = 动作原语参数面③类(动态坐标显式传参,见 SKILL.md §1.4)的坐标来源:动作 op 按坐标/idx 自取,零内部识别。写端 = 观察上报单点整表覆盖,随帧刷新;**禁逻辑写端**(动作后回填坐标——实体获得时点无画面读数),坐标缺席语义 = 发出面跳过自愈、下帧重派,禁回填猜值。先例:pick 族坐标伴随域(事件线选卡动作按 idx 自取坐标)、`owned_equip_xy`。
- **观察层失约抛错**:决策入口消费的 payload 槽离屏 None = 观察层失约(如 shop payload 离屏)——显式报错,禁策略侧兜底。
- 识别器(`obs/recognizers/`)注册为 `analyze_screen` 的 extras 扩展,MCP 读数与画面 op 观察同一实现(双消费面,见 SKILL.md §1.4)。
- **识别不到就是 bug 停机闸**(与动作域「点完即写」同族规范):商店未识别卡、召唤物/物品未识别等观察域停机见 [guards.md](guards.md)。

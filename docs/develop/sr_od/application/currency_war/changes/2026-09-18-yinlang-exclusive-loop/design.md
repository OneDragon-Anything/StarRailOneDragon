## 2. 方案

### 2.0 总原则

- **动作 op 规范**（正本 = `flow/action_ops.md` §1）：动作 op = 机械执行 + **发出即记账**；禁验证、禁重试；**禁偶发结案**——每个未生效必有确定性根因，修法落根因层。
- **两态制容器写**：确定面（结果可准确计算 + 输入已知）→ `write_logic`；随机面（含概率/随机采样）→ `write_logic_rand` 采样链（值 = 猜测；观察覆盖差异 = 预期内 `logic_rand_outcome` 行不响安灯；策略消费前必须重观察，查询口 = `logic_rand_fields`/`any_logic_rand`）。未建模且无法猜测的形态 = 不写 + 台账行留证，失配响停即采证信号（禁猜）。
- **合成级联单一引擎**：一切 bench/deployed 增员与变换的连锁合成经 `merge_simulate`/`_merge_bench(on_step=...)`（`kernel/cw_merge_simulate.py`，语义权威 = 模块头 §1–§5；每级合并后受影响域各落一行，board 派生随行写自动继承来源态）。**跨档合并已定谳，级联正常推演**（原对抗审②禁猜面，降级已撤）：merge 身份键 =（char_id, star）无费用维度，而银狼LV.999 有 3/4/5 三费档（`cw_chars.py:148`）——定谳 = **容器内费用档不同时存在**（升星选择升费后商店只出新费用档、赠送单位也只给该费用档，同名即同档；口述·权威 2026-09-18）→ 分组键无跨档歧义，涉 LV.999 的合并级联与普通单位同语义正常推演（共享体 = `cw_effect_inventory.merge_cascade_write`，`lv999_merge_undecided` 降级体已随 commit `c466b0235` 退役）。
- **动作报告形态**（用户定稿）：每动作一文件（`kernel/cw_action_report/` 包规约），上报函数分步更新 game state、每字段更新各落一行遥测（单次动作报告多次写遥测 = 预期行为，逐字段追加、分步可对账）。

### 2.1 R1：planner 统一选择 op（选卡 + 确认一 op 完成带载荷上报）

现状结构（实名，对抗审⑥勘误）：`CwScreenPlanner`（统一观察架构 observe/act 节点）→ 注册表分派 **`CwActionPickPlannerOp`**（`operations/cw_op/cw_overlay_pick_action.py:340`，域 env = `OverlayPickExecEnv`；旧名 `PlannerPickOp` 仅存于 `cw_screen_planner.py:197` 过期注释，随 3.4 注释同步清偿）。增量：

**① 载荷上报**：所选选项内容 = 入参随发射上报（`leg_type` ∈ {`upgrade`|`weaken`|`equip`|`unknown`}、`norm_item` 归一件名或空）：

- **腿型判定单源（对抗审①，批内第一交付）**：判定函数落 kernel 独立单一源，**装备域优先**——先对银狼专属 10 件名单/件名锚匹配（含 longest-match 归一），命中即 equip（破解芯片卡文含「弱化」而实为装备例的碰撞由此消除，`cw_equipment_data.py:62` + gameplay 升星选项例）；不命中才降级「提升费用」→ upgrade、「弱化/降低敌人」→ weaken；空/未识别 → unknown。**禁复用 `decide_planner` 决策关键词当记账分类器**（决策打分关键词与记账分类谓词职责不同，混用 = 装备授予被误判零记账 → 失配停）；
- equip 件名归一 = 卡面 OCR 文本 × `EQUIPMENTS` 注册表相似匹配，**最长名优先**（防「分身墨镜Max」被短名「分身墨镜」截胡；`one_dragon.utils.str_utils`，依据项目 AGENTS.md §7）；唯一命中 → 归一件名，零/多命中 → 未解析；
- **效果腿幂等 = 证据闩（对抗审③⑦，非 op 实例）**：op 每派发新建实例，实例闩不设防——闩绑**「overlay 已关」落地证据**（重入裁决出口：入口词不在 = 上轮确认已落地，效果腿在该时点应用一次；重走不重复）。发射时仅登记意图遥测行，落地证据后应用效果（与现役 `active_strategies` 追加写点同位语义）。

**② 装备腿 = 获得后果应用（确定性，`write_logic`）**：件名归一命中 → 查装备数据行的获得后果（§2.2）并应用——装备入栏 → 后果链（命中三件则 bench += 银狼族单位）→ `_merge_bench(on_step)` 级联逐步落行。**未解析**（`norm_item=''`）→ 不猜名，equips 域**值不变翻来源**（`write_logic_rand` 标记，collect_ore 步2 同款）+ 台账行留证（kind=`planner_equip_name_unresolved`）——观察覆盖差异 = 预期内收口自愈，识别修因后走主路。

**③ 升费腿 = 变换窗（确定性优先，三态判定）**：定谳 = 变为下一个费用档的 1 星银狼LV.999、身份保持（§1.2）。前置硬校验对发射时容器观察态（bench ∪ front_row ∪ back_row 多重集）的（银狼LV.999，2★）计数：
- **恰一枚** → 工作副本变换（−2★ +1★，槽位无关——落点槽位不建模，观察为真值）→ `_merge_bench(on_step)` 级联（新 1★ 凑满连锁升星同一引擎）→ 受影响域各落一行（`write_logic`）；
- **多枚**（二次升费现实可发——场上 2★ + 备战再凑 2★，对抗审⑦）→ 触发单位不可辨（禁猜）→ 受影响域**值不变翻来源**（`write_logic_rand` 标记）+ 台账行留证（kind=`planner_upgrade_ambiguous`）——观察覆盖差异 = 预期内收口自愈，留证行即二次升费落位形态的定谳数据；
- **零枚/未观察** → 不写 + 台账行留证（真异常，照真失配响停，fail-closed 禁猜）。

费用档不建模（`cw_chars.py` 银狼LV.999 行注：cost=起始费，多档待策略层需要时扩）。「新费档银狼刷进商店」连带腿 = 零记账面（商店池无容器字段，逐帧观察为真值），注释申报。

**④ weaken/unknown 腿** = 零记账（unknown 留台账行证未识别事实）。

**⑤ 后续迁移契约（不强制本批）**：本批记账函数按动作报告形态写（分步更新 + 逐字段遥测）；迁入 `kernel/cw_action_report/pick_planner.py`（现零写委托退役）与点球 op 同构推广 = 推广批。

### 2.1A 上阵变换窗（3★ 银狼LV.999 拖上场变费）

机制定谳（`docs/game/gameplay/currency_war.md`「银狼LV.999 升星升费」条）：3 星拖到场上 → 变下一费用档的 1 星（备战栏不升费，拖上场才触发；4 费升满同理再变 5 费）。现役 `deploy_move.py:63-66` 恒等搬运星级 → 失配响停，银狼线终局必经。

**修法 = deploy 侧变换窗（与 planner 升费变换窗同构三态）**：`report_action_deploy_move_param` 的 bench → 场上落位腿，落位单位身份 = （银狼LV.999，3★）时——

- **恰此一枚为源**（拖拽载荷唯一指定，无歧义）→ 落场写（下一费用档的 1★银狼LV.999，非 3★原样）+ bench 摘除源，`write_logic`；
- 目标费档（4/5 费）不建模（同 §2.1③ 费用档口径）；升费是否再触发连锁（场上同名同星不变量）经 `_merge_bench(on_step)` 常规覆盖；
- 非（银狼LV.999，3★）单位 = 现行恒等搬运不变（零行为差）。

落场星级与费档变换的实机形态（原 3★ 是否保留随队装备继承等）= merge 引擎既有继承语义覆盖（§2.0 单引擎），异常形状照真失配响停（禁偶发结案）。

### 2.2 R2：三件送角色腿 = 装备数据行的获得后果（全渠道统一）

**定谳**（用户口述·权威 2026-09-18）：获得分身墨镜/分身墨镜Max/数据拷贝仪Max 时，赠送的银狼族单位**直接出现在备战席，效果与商店购买完全一致**——可触发合成、也可能触发升星（数据拷贝仪Max 送的银狼LV.999 凑满 2 星即触发 planner 升星选择画面，与 R1 成链）。星级按卡文：分身墨镜→1星银狼 / 分身墨镜Max→2星银狼 / 数据拷贝仪Max→1星银狼LV.999。

**修法**：送角色腿建模为**装备数据行的获得后果**，全渠道统一——后果应用函数（件名 → 三件命中 → bench 增员（名,星）→ `_merge_bench(on_step)` 级联），由「装备入栏」应用点统一触发：

- **确定性通道**（planner 装备腿、选择装备屏、补给确认等件名已知入栏）：随 `write_logic` 入栏同链应用后果（同源 `write_logic`）。**通道宿主迁移（对抗审⑤）**：选择装备屏/补给确认现役零写零挂点（两 pick 均零写族，审查实证）→ 迁出零写族接后果应用；好运令牌既有 `grant_equip_item` 渠道（`cw_effect_inventory.py:1047`）同纳后果链锚；
- **随机通道**（骇客专家改件等采样到货）：在采样链内应用（§2.4），随链 `write_logic_rand`；
- **下游语义**：授予单位 = 普通备战单位（分配/W3 门/合成升星与购买单位同一套，零特殊建模——定谳「与商店购买完全一致」）；

### 2.7 R5：随机态路线下重审

- **特邀专家：银狼(143)——触发锚修正（对抗审⑤）**：真触发帧 = **容器内首次出现银狼LV.999 时**（获得回执，容器派生可判），非确认帧——v0「确认时采样」时点错位会让真触发帧落在模型辖域外照响停。修法 = **状态触发后果建模**（确定面）：获取后应用链挂「首次 LV.999 入册」判定（容器派生，一次性闩）→ 触发帧 bench += 银狼（1★，同句式先验）+ 商店池腿遥测申报，`write_logic`（触发与后果均定谳/先验明确）。**张力申报**：bench 腿为单例先验（同句式骇客专家实证）、与特邀专家族「入商店」旧口径相斥——错则观察覆盖差异响停，实机一次对拍即定谳修因（确定面响停语义，非 logic_rand 自愈——先验错属建模 bug 不属随机）。
- **欢愉契约(1201) 条件腿——采证期运行协议（对抗审⑥）**：触发者 = 头号玩家选项（触发时点/频率无观察锚、无采样模型）→ 正式建模候 3.1① 采证。**纯响停采证不可接受**（头号玩家常态在场/高频触发 = 每触发帧停局，单局数据无法累积）——采证期临时协议 = **临时翻来源通道**：欢愉契约在册（portal 环境判定）期间，条件腿可能受影响域（bench/equips）值不变翻来源（`write_logic_rand` 临时标记，披露键 kind=`joy_contract_provisional`）→ 触发帧收口自愈留证（行 = 采证校准数据），多局拼数据不停局；3.1① 定谳后撤临时闩换正式采样模型（3.3）。临时闩 = 有界显式测量仪表（在册可审计），非吞错——定谳后必须撤。

## 问题清单(严重级降序)

### S1(高)§2.1 `ev_buy_veto` 的真破息谓词与 P33 原式不符,且不感知 resolved 息 cap

- **位置**:§2.1 买表 `ev_buy_veto()` 行,判据式 `D = 真破息(⌊(g−c)/10⌋ < ⌊g/10⌋,双条件合取,R1-9) ∧ 无当轮兑现 ∧ 非豁免`。
- **缺陷**:三个口径偏差叠加:
  1. **缺 P33 的域条件 `g−c<50`**:P33 原文「否决域=真破息(g−c<50 ∧ ⌊g/10⌋ 下降)∧ R≥1 ∧ 无当轮兑现 ∧ 非豁免类」。设计件只写了 floor 下降一项。反例:g=85、c=10 → ⌊75/10⌋=7 < ⌊85/10⌋=8,按设计件式判「真破息」,但 g−c=75≥50(溢余段)、息损为 0——注记文字写了「g−c 跨 50 档为溢余段自由」,可判据式本身不含该条件,式与注脱节,落码以式为准时否决域误扩。
  2. **缺 `R≥1`**:P33 明文 R=0 不入域(剩余平台轮为 0 时息档损失恒 0),设计件 D 未含;horizon.py 已算 R 却没接进 D。
  3. **不感知 cap_resolved**:息函数是 min(g//10, cap)。买断制局 cap=0,L≡0,P46 的 P1 基判据(L>0)恒假、否决域应空;但设计件的裸 floor 比较在买断制局对一切买入都报「真破息」——在无息游戏里跑出一个全效的破息否决域,是结构性错域。
- **为什么错**:P33 是条件定理,其「已证」状态精确绑定这组合取域;削掉两个域条件后,定理的期望净损论证(息档损失>0)在被误扩的区域不成立——veto 一个零息损的买入没有数学背书,反而制造「该买买不进」的新损失面。
- **修法方向**:D 改为 `(g−c<50) ∧ (min(⌊(g−c)/10⌋,cap_resolved) < min(⌊g/10⌋,cap_resolved)) ∧ R≥1 ∧ 无当轮兑现 ∧ 非豁免`——cap 感知的息档真降测试同时消掉 1、3 两缺陷(R 由 horizon 现成注入)。

### S2(高)臂①「criteria/* 整层旁路」与 M3/M4 对 criteria 判据的依赖自相矛盾(命题 A 被实验配置自毁)

- **位置**:§4.2 臂①行「EV 面全关(criteria/* 整层旁路,经 entry 的模式开关)」 vs §3.1「M3 触发信号来自 arm1_existence」、§2.2/§1(fuel_sell 在 criteria/sell.py,总纲§5.1 明文「M4 燃料件卖出判据 = P41 分类表第一行,与 M4 判据逐字对齐」)。
- **缺陷**:`arm1_existence` 落位 criteria/levelup.py(§2.3),M4 的支配性卖出判据(fuel_sell)落位 criteria/sell.py(§2.2)。臂①把 criteria 整层旁路后:M3 失去触发信号、M4 失去卖判据 → §5.2 为臂①立的预期(升级金回填 ≥5000、SellBench ≥200、拒买 <100)被开关配置直接关闭,命题 A 检验的不是「骨架-only」而是「缺了一条腿的骨架」。设计件只对 M6(档匹配 fail-closed 不买)和 crisis 不变式(R1-11 豁免)做了显式豁免,M3/M4 两处同等依赖未豁免、未记载。次生问题:若为救臂①让 executor 自行实现 M3 触发与 M4 卖判据,则与 criteria/levelup.py、criteria/sell.py 形成同判据双源,违反本设计自己立的「单一源防双计」纪律(§1 状态函数层纪律)。
- **修法方向**:把旁路边界写死为「criteria 层只关 EV **追加动作**的发射;义务的触发信号与判据(arm1 三元、M4 支配卖出、M6 档匹配)归 mandate/executor 单一落位(谓词从 statefn/predicates 取),criteria 层不得重复实现」——同时消除双源与臂①残废两个问题。

### S3(高)总纲「λ>0 段否决域自动松」在买面无实现载体

- **位置**:§2.1 `ev_buy_veto` 三段管辖列「λ>0 段由 floor_eff=0 投影自动松(P39(c))+ P51 转化优先接管」;§1 模块表 statefn/interest.py(P47 递推)。
- **缺陷**:逐载体核查全空——①`ev_buy_veto` 的 D 式无 λ 项;②P47 的 L(g,d,R,Ī) 递推无 λ 项(死亡风险不缩短其计息视界);③floor_eff 是升级臂二的金下限概念,对买面无任何作用通道;④buy.py 函数清单(dominance/ev_buy_veto/stockpile/p2_lock)无 P51 转化优先函数。即 λ>0 段的买面否决域实际**全效**,「自动松」是一句没有公式承载的断言。
- **为什么错**:总纲§1.1 明文 λ>0 段「息票随死清零,否决域自动松——由 floor_eff=0 投影与 P51 转化优先承载」;P51 站住结论「濒死带其余格转化下界 5.8 金/轮 ≫ cap=5」——濒死段持币不转化是每轮 ≥5.8 金的确定性方向损失。设计件在该段维持全效否决域 = 与被引证明的方向性结论相反,重演「门在劣化态下正确地关门」的静默螺旋(骨架层§1.4 修正二自己诊断的病)。
- **修法方向**:三选一并写明:①L 递推按 λ_death 加权缩短有效计息视界(改 statefn/interest 契约);②D 增加显式 λ>0 旁路(触发判据=floor_eff 投影为 0 时 D 不成立);③buy.py 立 P51 转化优先追加函数。默认(λ_death 分层表未标定)时的 fail 方向须同步声明(见 S4 同族张力)。

### S4(中高)「双臂门」合取/析取未定义,错读即复活 r3 事故;λ 未标定的全局 fail 方向与 P51 濒死结论反向

- **位置**:§2.3 `batch_form`「触发 iff 双臂门 ∧ g ≥ S」;§2.3 arm2 行「只延迟不废除…臂二无权否决 M3 存在性」;§2.3 R1-6「分层表槽位 None → floor_eff 保守 = 50」。
- **缺陷一**:「双臂门」全文未定义是 arm1∧arm2 还是 arm1∨arm2。若按字面合取读:arm2 的任一 fail 缺省(R1-6 的 floor_eff=50、ΔV_band 数据异常、窗口预留未标定)都能拦下 arm1 已触发的 M3 整批——这正是 r3「p39 臂二被当成整局不升级的理由」的复刻,与设计件自己引的骨架层§3.5(3) 直接矛盾。
- **缺陷二**:λ_death 分层表是【拟】(总纲§3.3#11),槽位 None 时设计件把所有三段消费位缺省到「视作 λ≈0」(floor_eff=50、S1 否决域全效、ΔW_trunc 按 0)。这在濒死局是数学上可证的反向:P51 濒死带转化支配,守息姿态每轮损失下界 5.8 金。「XP 不可逆、缺输入默认不做」的单动作论证不能推广到「整段管辖缺输入」——段的误判是系统性方向错,不是单笔保守。
- **修法方向**:①把 M3 执行门写成显式析取:`(arm1_existence ∨ arm2_schedule) ∧ g≥S`,arm2 的延迟只作用于 arm2 自己触发的批;②λ 未标定时的段缺省要么给出「不可分类→按可观测代理(板面战力桶×节点类型的保守桶)」,要么在判前锁里声明「首版三段管辖仅健康段生效,濒死段行为与旧侧同责」,不能默认一个与 P51 反向的方向而不留痕。

### S5(中)验证计划两处:EV 降权裁决未条件化于判据实际开闸;R1-7「作废 ≥80% 线」越界到目标②判据

- **位置**:§5.2 末两行;§5.1 R1-7 段。
- **缺陷一**:V_ms/u/V_gap 全部🔴未标定时,臂②≈臂①+支配族+免费刷新——「EV 增量无 → EV 层降权」的裁决会把「判据从未运行」误判为「判据无价值」,这是构造性必然的零增量,不是 EV 层的证伪。骨架层§4.2 的降权语义以「EV 全开」为前提,设计件把它搬到「多数 fail-closed」的成熟度上未做条件化。
- **缺陷二**:R1-7 把骨架层§4.1 的「≥80% 证伪线」整行作废,但骨架层同节的**目标②达成判据**(P1 末 ≥2 体系局占比 ≥80%)用的是同一个成型率锚——它是用户目标②的产品门,不是臂①实验阈值。设计件以「实验判前锁源单一化」的名义作废,未与目标②判据切割:若臂①只按 ≥50% 起判通过,目标②是否达成的账就没有判据可依了。
- **修法方向**:①降权裁决改为按 `mandate=false` 遥测分面对账,只裁「实际发射>0」的 EV 面,并把标定成熟度写进判前锁作分层因子;②R1-7 补一句「目标②的 ≥80% 成型率锚不受本变更影响,作为产品达成门另行保留」,把实验阈值与产品目标两本账分开。

### S6(中)R1-5 血本位安全带论证缺「支付后 hp 下限」边界

- **位置**:§6.2 血本位安全带相容性论证(R1-5)。
- **缺陷**:支付本位检查写成 `hp 余额 ≥ ⌈need/xp_per_buy⌉×rate`,允许把 hp 恰好花到 0。玩家裁定(总纲§0)「首次 0hp 保底 1hp,再次归零结束」——奋斗协议支付致 0 会消耗一次性保底、再犯即终局。这不是「够不够本币支付」的语义,而是「花光本币触发死亡机制」的语义,恰好落进 [39] 处死口径想隔离的「hp 影响局终」通道。三条相容性论证均未覆盖此边界。
- **修法方向**:支付本位检查补下限条款(支付后 hp≥1,或保底未耗尽),作为硬约束①在 hp 本币域的同构扩展,随 ADR 落地。

### S7(中)迁移与处死两漏项:旧 cw3 包无处置;总纲§4 五钩子只落了 P25

- **位置**:§4 全节、§6.3 处死表。
- **缺陷一**:设计件以全新包 cw4 + 冻结 decision_v2 建三臂,旧 cw3(strategy/ 八台机器)不在任何臂里、处死名单也无其行——成为无归属代码。骨架层§5.1 的迁移路径是「改 cw3 机器」,设计件改成了「另起 cw4」,两条迁移叙事并存且都未交代 cw3 的终点(保留可跑?删除?何时删?),依赖关系悬空。
- **缺陷二**:总纲§4 要求五个待证钩子「结构背书形态」占位;设计件只落了 P25(p2_lock_buy 默认关)。P8 重推后的零参数结构(扑满禁深花,refresh 变体⑥的约束)、P12 的方向注记与「battles 禁 9」、P26 的同构门接口、P29 的 E_rev 线内侧预留——四处无落位记载。变体①-⑩「全部=参数替换」一句会把 P8 的禁深花结构约束也一起「替换」掉,而它是零参数支配级结论,不是参数。
- **修法方向**:①处死表补 cw3 包处置行(建议:三臂判读过线后随批 1b 删,与 legacy 删除同批);②§2 增「待证钩子占位」小节,P8/P12/P26/P29 各一行写默认行为与消费位。

### S8(中低)Φ(未来纯金流)无在线估计器、无 fail 方向

- **位置**:§1 模块表 horizon.py 行(只有名字);总纲§2 Φ 行「实现轨迹净额估计」。
- **缺陷**:Φ 是轨迹(离线/A/B)量,实机决策时如何现算无设计;W_floor=λ×(g+Φ) 的消费位(line_switch_sell 的保守端、ΔW_trunc)在 Φ 缺省时取什么没写。若 Φ 缺省 0,W_floor 系统性偏小 → 对不可逆卖出比较项偏小 → 卖出面 fail-open,与「不可逆缺输入默认不做」相反。
- **修法方向**:给 Φ 一个注册表推导下界(剩余节点×败轮底金之类,【推】口径),或显式声明 Φ 缺省 0 时 line_switch_sell 强制走「不新增卖出」护栏。

### S9(低)硬约束③「拦截对象 M2 序 3-5」是旧架构残留;EV 追加支出未挂 S 预留检查

- **位置**:§3.2 检查点③。
- **缺陷**:新设计 M2 只辖序 1/序 2(§2.1 mandate_buy 行「不走本模块」),序 3-5 在 EV 层。检查点③仍写「M2 序 3-5」,拦截对象指向不存在的通道;而真正会吃 S 预留的 EV 追加买(stockpile 等)只在 §3.4 以「剩余预算内追加」带过,未与硬约束③显式挂钩。
- **修法方向**:拦截对象改为「EV pass 全部支出 + M6」,并把「剩余预算」定义为「扣除 S 预留后的余额」写进 §3.4。

### S10(低)换线跨帧的一帧旧线买入损耗未消

- **位置**:§2.7 接线义务段(只论证了同帧不自损)。
- **缺陷**:设计件用「K 变更下一备战期生效」消掉了同帧「按旧 K 买、按新 K′ 卖」的自损,但登记帧本身仍按旧 K 执行 M2(可买入仅属旧线的件),下一备战期塌缩卖出付 2★+ 手续费;θ/D_min 驻留期内更是持续按旧 K 买入。这部分损耗是真实的,只是比同帧版本小。
- **修法方向**:换线事件登记后,对「∈K∖K′ 且非共享/种子件」的 M2 买入加一帧冻结(买入可逆、冻结近零成本);或给出驻留期买入由 P1 再遇账对冲的论证。至少应在 §2.7 声明该残留损耗的量级假设。

### S11(低)对拍清单两缺 + PLANE_LENGTHS_TRUTH 溯源口径

- **位置**:§5.3 对拍表;§6.1。
- **缺陷**:①对拍清单无 E_rounds/p̄(`line_selector` 消费 p16/pbar_exact,换线判据的核心数值无锚)、无 V_comp 表生成对拍(P49 脚本锚);②§6.1 把 PLANE_LENGTHS_TRUTH=(9,7,9) 标【注】「16 局实证」——公理 5 的【注】口径是「注册表直读(机制真值)」,16 局实证是经验估计,按公理应入【拟】带 CI 或给出「机制上位面长度为定值」的文档依据。
- **修法方向**:对拍表补两行;PLANE_LENGTHS_TRUTH 要么补机制依据维持【注】,要么改【拟】并登记进 provisional.py。

## 判决

# 武装箱选卡价值升级 迭代设计（总纲）

## 0. 元信息

- 迭代目标：武装箱 4 选 1 装备卡（`decide_box_card`，事件面 E18）价值模型升级——①未锁线时按「输出最需要」通用先验选卡（用户指令 2026-09-12：「没有目标阵容的时候，应该选更普遍用于输出的」）；②打分接入装备库存账的序数感知维（用户质询 2026-09-12：「打分不读当前装备库存——我们 state 里有记录装备的」）；③选装逻辑通用化——打分核心抽为共享机器的通用选装入口（用户指令 2026-09-12：「这个选装备的逻辑，是不是可以做成通用的」）。
- 承接出处：`2026-09-12-supply-selection` 迭代 §1.3 装备层两态（裁定 5/6）迁移表中 `decide_box_card` 行的终态提前落地；库存维（组件缺口）的序数切片与通用选装入口为**本迭代新增语义**，超出源迭代 §4 v1 结构版范围。
- 状态：**草案**（对抗审未过，不可派落地批）

## 1. 问题与动机

### 1.1 现状症状（依据 = flow.py:654-702 直读 + 2026-09-12 本会话全链盘点）

现行 `decide_box_card` 打分（CwFlowStrategy 默认实现，mandate_v1 未覆写）：

```
score(name) = 100 if name ∈ target_comp.key_equips        # key 直击
            + 30  if name ∈ key_equips 的 recipes 材料    # 两跳材料
            + material_value(name)                        # 材料通用性手表 0-7
            （effect_pick_bias 恒 0，占位）
argmax，无信息 fallback idx=0
```

四个 gap：

1. **未锁线盲选**：`target_comp` 为 None 时只剩材料通用性分——通用输出装（火力风暴潮，mv 0）排在任何 mv>0 件之后（含纯材料幸运星 3），输出先验完全缺位；四张全 mv 表外件恒选第 1 张（该子情形见 §2.6 行 2/2b 的两制对照）。
2. **锚定错位**：key 消费 `state_of(session).target_comp`——P1 期过渡配方对物化的伪 comp（源迭代详设 §1.3 自证同款辖域错位，T-155 判例；P1 配方锁帧 locked_comp 恒空，flow.py:405-410 注）。过渡线的关键装备被当终局关键装备 +100 提权。
3. **库存维零感知**：打分不读装备库存——库里有某 key 配方的另一半材料时，选这张卡 = **立即合成拿到 key 装备**（近兑现），与「单纯一件原料」价值档位不同，现行打分不可区分。库存数据本身在册（见 1.2）。
4. **材料通用性梯度无数据根基**：现行 `MATERIAL_VALUE_TABLE`（cw_prep_expect.py:32-35，花7/鞋6/电池6/钻头5/刀5/装甲5/枪4/星3）自注出处 = `docs/game/currency_war/data/equipment.md`；注册表直调（2026-09-12 实跑 `EQUIPMENTS` 全量 recipes）：**简易材料域内** 8 件每件恰 10 条配方引用（成员槽 11，完全合成图）完全同值——注册表下无梯度；手表梯度数值出自过期局部文档，属虚构序。现行打分靠它产生的序（含「简易件优先于无表值进阶件」的跨域序）是建立在虚构值上的序。

### 1.2 「为什么以前不读库存」——归因（回答用户质询）

库存账一直在：`session.last_owned_equips`（cw_strategy_session.py:167，装备区**备用库存账**）由两类写端维护——①观察采集写端全量重写（prep_actions.py:411、:571-577，`read_equips` SIFT 逐件实名）；②建模效果增量：开箱选卡 +（cw_exec_state.py 经 apply_op_effect）、确认到账 +（_overlay_confirm.py:61-63）、穿戴 −（cw_op_equip_all.py:152-155，同函数 ：158-161 同步部署位穿戴账 tracked_deployed[*].equips +1）、卖角色装备返还 +（cw_exec_state.py 卖返效果），并有期望态对账网审计（compare_equip_expect）。**不读的原因不是数据缺失，是打分形式缺失**：

- 「囤了 k 件后这件材料还值多少」的数值边际模型 = P42 组件缺口参数化（近兑现距离 × 边际），现只有序级结论，绝对值等 λ 标定（源迭代详设 §4 直读 P42_VALIDATION：④门未检验、λ 🔴）。零调参宪法禁拍值（strategy-work §1：每个数字要么规则推导要么显式模型估计）——没有模型就给库存感知定数值 = 违宪，所以旧打分干脆不读。
- 源迭代把这个维度立了案（组件缺口维度，v1 只入结构半部「key 材料 +3」，数值半部挂账双前置 = λ 标定批 + owned 读数接线）。
- **本迭代补第三条路**：序数形式。库存感知里真正可零参数推导的部分（近兑现 = 立即拿到 key 装备，见 §2.3 推导）用**档位升格**表达——档序可证、不需要绝对值、不需要 λ。数值半部维持挂账，不因本迭代解锁。

### 1.3 根因归层

语义层：价值模型缺「库存序数维」（近兑现与原料不可分档）+「统计先验 vs 锁定契合」未分态 + 锚定错位继承自 target_comp 伪 comp。表示层伴生事实：材料通用性梯度 = 过期局部文档的虚构序（§1.1 gap 4），随本迭代一并退役。

## 2. 方案

### 2.1 共享机器（前置，吸收源迭代 P-1 + 本迭代扩展）

打分依赖 `kernel/cw_equip_value.py`（源迭代 landing.md §3.1 全量范围照执：`EQUIP_GENERIC_VALUE` 逐值平移 + `equip_material_generality` 注册表化 + `key_fit_names` + 六消费位重接）。本迭代对机器**追加**：

```python
def equip_generic_value(name: str) -> int:
    """装备名 → 通用输出先验（EQUIP_GENERIC_VALUE 查表；表外 0）。
    同形先例 = cw_events._equip_value（退役迁入）。"""

def key_recipe_pairs(key_equips) -> dict[str, tuple[tuple[str, str], ...]]:
    """key_equip 成品名 → 其全部合成材料对（EQUIPMENTS.recipes 平移，缺名 → 空对）。
    【注·注册表】recipes = 配方元组的元组，每条 = (材料a, 材料b)（flow.py:675-680 r130 修正注）。"""

def equip_tier(name: str, *, key_equips: Sequence[str] = (),
               owned_spare: Sequence[str] = (),
               owned_total: Sequence[str] | None = None) -> int:
    """装备名 → 档位 3/2/1/0（定义见 §2.2/§2.3）。
    owned_spare = 装备区备用库存账（近兑现对数判定输入，栏内合成的输入面）；
    owned_total = 总持有账（备用 + 已穿戴，需求守卫输入）；None → 取 owned_spare。"""

def pick_equipment(names: list[str], *, key_equips: Sequence[str] = (),
                   owned_spare: Sequence[str] = (),
                   owned_total: Sequence[str] | None = None) -> int:
    """装备名列表 → 选中索引（(tier, base) 字典序 argmax，并列取输入序先者）。
    key_equips 空 = 未锁态（全体 tier 0 → 纯 base 排序）；names 空 → 返回 0。"""
```

- **key_equips 参数 = 可含重复序列（Sequence[str]），禁 frozenset**：需求件数语义 = 原序列 `.count(K)`（注册表注「可含重复，如阿雅需 2 反重力皮靴」，cw_comps.py:107；实跑 COMP_LIBRARY 20 套中 5 套存在重复 key_equips——昼神阿雅 2×反重力皮靴、狼尊欢愉 2×反重力皮靴、命运圣杯红A 2×动能激发剑、追击飞霄 2×火力风暴潮、专家桑博DOT 2×火力风暴潮），frozenset 构造即去重且无 count，按其落码 = 这 5 套在「已持部分」帧丢 key 提权（行为表行 8c 锁钉住）；成员判定（X ∈ key_equips）机器内部自建 set，不改变入参形态。

- `key_fit_names` 改为由 `key_recipe_pairs` 派生（keys ∪ 全部材料对成员）——同一推导单一源，源迭代消费位（supply +10/+3、equip_pick 子串集）签名与语义不变。V4 锁 = **独立第二构造对拍**：机器派生结果 vs 直查 `EQUIPMENTS.recipes` 遍历结果逐元素相等。
- `equip_material_generality` = 注册表配方引用计数（诚实派生）。直调现状（2026-09-12 实跑）：**简易域内** 8 件每件 10 条配方/11 槽完全同值，蓝钻/红钻 12 槽，进阶类 0 引用——该函数在**同质 offer 内**为常数不产生序；跨简易/进阶域的旧序（手表梯度）为虚构序（§1.1 gap 4）。**箱打分不消费它**（§2.2/§3）。源迭代 V2 原文「== 旧 `MATERIAL_VALUE_TABLE[n]` ∀8 名」与注册表真相互斥（手表梯度出自过期局部文档），**修订为独立构造对拍锁**（机器计数 vs 直查注册表计数逐名相等）+ 当前注册表形态快照锚（**简易域**全体等值 10 配方/11 槽；蓝红钻 12；进阶 0），修订归口本迭代 landing 3.1。
- 打分语义（档位、近兑现、base 构成）唯一住机器第四件，消费位只做锚定解析与传参。**消费位全集**：①箱选卡主路径（decide_box_card 薄壳）；②执行器局外回落（`_default_box_card` match=None 分支，现按 material_value 排序的第二套打分——随本迭代统一改薄委托 `pick_equipment`（空 key = 纯 base 排序），禁第二套实现落地；行为变化见 §2.6 行 10）。后续任何「候选全部为装备的多选一」场景优先接本函数。

### 2.2 选装器总形：序数分档制（档位优先，档内基分）

**档位字典序取代加法制**——打分核心即 `pick_equipment`：输入装备名列表，按 `(tier, base)` 字典序取最大，返回选中索引（并列取输入序先者，武装箱场景输入序 = OCR 从左到右，即现行取先语义）；`decide_box_card` 退化为薄壳（解析两态锚 + 两本库存账 → 调 `pick_equipment`），自身不再有任何打分实现。

```
tier(X) = 3  若 X ∈ key_equips 且 持有数_total(X) < 需求件数(X)     # key 直击（需求未满足）
        = 2  若 near_redeem(X)（近兑现，已锁态限定，定义见 §2.3）
        = 1  若 X ∈ key_fit_names(key_equips) 材料（两跳原料）
        = 0  其余（未锁态全部落此档）

base(X) = equip_generic_value(X)        # 通用输出先验，值域 0-6（cw_events 平移表）
```

- **base 只含通用输出值**。材料通用性项移除，依据链（F4 修正后口径）：①注册表化后该维在**简易域内**恒值——同质 offer 内无序；②跨简易/进阶混合 offer 下现行手表梯度产生的旧序（简易优先于无表值进阶件）建立在虚构值上（出处过期文档），被输出先验序**有意取代**——依据 = 用户指令 + 裁定 5 同构；这是一次声明的行为反转（§2.6 行 1），不是无行为影响的清理。
- **输出先验覆盖边界**：base 的区分力限 `EQUIP_GENERIC_VALUE` 表域；表外件（特殊类钻/财富宝钻、工具等）base 恒 0——若箱面出现此类件，新旧两制皆 0 分、排在全部有值件之后，与裁定 1 对钻「单件价值高」的定谳存在潜在倒挂。箱池是否含特殊类无在册证据（board_structure.md:61 只证「4 选 1 装备」）——定价不入本迭代，§1.4 不解决清单登记，箱池构成实采钩子后重裁。
- **需求件数(K)** = `key_equips.count(K)`（key_equips 为可含重复的列表，注册表注「可含重复，如阿雅需 2 反重力皮靴」，cw_comps.py:107）。**持有数_total = 备用库存账 + 穿戴账合计**（`last_owned_equips` + 部署位 `tracked_deployed[*].equips`，后者经 `exec_state_of(session)` 读）：穿戴把 key 件移出备用账是常态，只数备用账会把「已穿」误判为未满足。需求已满足的 K（含其材料对）不再吃 key 提权——依据 = 需求向量超配对锁定线成型零边际（模型假设：comp 需求即装备获取目标，超需求件不再服务成型），冗余件落 tier 0 按 base 参与排序（不打负分）；辅助佐证 = 唯一件族第二件死库存（equipment_mechanics.md §4，**证据分级：【口述·印象级】未实测 + 【推断】，仅电光履/蓄能帆/绝对热量 3 组在册唯一标记**——不作守卫的主依据）。
- **未锁态**：key_equips 空 → 全体 tier 0 → 纯 base 排序 = 通用输出先验。这就是「更普遍用于输出的」：火力风暴潮(6) > 反重力皮靴(5) > 以牙还牙甲(4) > 幸运星(0)。
- **加法制 → 序数制的漂移面精确陈述**：
  - **档间序零漂移**（命题成立，标准帧）：现行加法三档值域 = 直击 [100,107]（key∩材料双中叠加分支结构上存在——三个加分项为独立 if 无 elif，结构上限 137；现行 COMP_LIBRARY 无「key 互为另一 key 材料」实例，值域以现行库为域）、材料 [30,37]、通用 [0,7]，三段分离 → 「每一直击 > 每一材料 > 每一通用」；新制档位支配同序。R1 锁对象（§2.6 行 5/6）。
  - **档内序 = 声明变化**（非漂移）：现行档内序 = material_value 手表梯度序（虚构值，§1.1 gap 4；如已锁态材料档 [生命之花 7, 轮滑鞋 6] 现行选花）；新档内序 = 通用输出值序（[生命之花 0, 轮滑鞋 4] 选轮滑鞋）。变化意图 = 档内仲裁改用与裁定 5 同源的输出先验（注册表下唯一有据的可排序信号），§2.6 行 3/4 显式申报并落锁。

### 2.3 近兑现档（tier 2）定义与推导

**定义（意图锚定：选卡解锁首对）**：`near_redeem(X)` ⟺ 已锁态 ∧ ∃ key_equip K（需求未满足，持有数_total 口径）∧ ∃ 材料对 (A,B) ∈ `key_recipe_pairs(K)`：**选前 K 的该材料对可用对数 = 0 ∧ 选 X 后 ≥ 1**（= 这张卡使 K 从「不可合成」变为「可合成第一个」）。

**操作条件**（与定义逐条对齐）：

```
对数(A,B) = min(cntA, cntB)   （A ≠ B，cnt = owned_spare 计数）
          = cnt(A) // 2       （A == B，自对配方 ×2 合成）
交叉对（A ≠ B）：cnt(X) == 0 ∧ cnt(另一侧) ≥ 1        # 选前 min=0，选后 min≥1
自对（A == B）：cnt(X) == 1                            # 选前 0 对，选后 1 对
```

- 自对**排除** cnt ≥ 3 的帧（持 3 只时第一对早已可合，再得 1 只解锁的是第 2 对——增量兑现，归数值半部挂账，不进序数档）；「对数净增加」的更宽定义（交叉 `cnt(X) < cnt(另一侧)` 帧）同此理由不采纳——近兑现档的语义 = 解锁首件，增量件价值属 P42 数值化辖域。
- 近兑现对数判定用**备用账**（栏内合成的输入面在装备区库存）；**需求门用总持有账**（§2.2）——两账分工显式，禁混用。

**档序推导**（三段，全部零参数）：

1. **直击(tier3) > 近兑现(tier2)**【推·严格支配】：两档结局同为「K 入库」，直击额外保留伙伴材料（近兑现消耗它），结局集严格包含 → 直击恒不劣。字典序 + 档位分离使该支配**结构成立**（不受 base 干扰——这正是弃加法制的原因：若近兑现并入 +100 加法，base 项可把它顶到直击之上，破坏支配方向）。
2. **近兑现(tier2) > 原料(tier1)**【推】：近兑现 = 立即拿到锁定线 key 装备（从不可合成变为可合成），立即交付 ≥ 延后交付（发展优先默认，00_framework）。方向注记：P42 ①③「近兑现张最贵，绝不喂」（math_proofs P42 行 / 01_math_framework §3.6）为**保留面**结论，本档序为获取面的同构应用——引作方向佐证，不作为在册权威直接引证（证据强度取最弱一环）。
3. **原料(tier1) > 通用(tier0)**：现行 +30 > 通用上界 7 的既有语义，序数化平移，非新裁。

**边界情形裁决**（实现者无需再设计）：

- 自对配方（注册表在册 **10** 条：简易 8 条——轮滑鞋×2→反重力皮靴、光能电池×2→永动机、折叠小刀×2→碎星斩舰刀、以太钻头×2→虫洞掘进钻头、和平手枪×2→天基轨道炮、幸运星×2→随便骰子、生命之花×2→生命之环、量产型装甲×2→很硬的甲；钻 2 条——红钻×2/蓝钻×2→财富宝钻）：按操作条件 `cnt(X)==1` 判 tier 2；持 0（不成对）与持 ≥2（已可合成）不升档；
- X 同时是另一 key 的成品与某 key 的近兑现材料 → 取 max tier（直击优先）；
- 需求已满足的 K（总持有 ≥ 需求件数）：其直击与全部材料对退出 key 提权（§2.2 守卫）；
- 账失真的失效方向如实声明：空账 → key 件落 tier 3（= 现行行为）；**欠计数**（获得未记账通道，如令牌/炉产物）→ 冗余 K 吃 tier 3 = 错提权（复现行冗余形态，非保守）；**过计数** → tier 2 误升。计数判据（==0/==1/≥1）敏感度高于 m7 存在性谓词先例（mandate.py:1653-1654）——如实承认差距；缓和事实：穿戴 −1 两件简易各减、产物上身的路径已正确建模，栏内合成现无生产发射位（仅期望层建模）。新鲜度门维持非目标，**失真观测键挂账**（实机判读发现失真致错选 → 立项新鲜度门）；
- 多个近兑现并列（不同 K 的材料对）→ base 仲裁，再并列取先。伙伴通用性最小化等更细仲裁**不做**——「伙伴材料的机会成本 ≈ 其通用性」是代理假设，无推导背书，做了即拍序。

### 2.4 锚定两态化

- 锁线布尔与锚：单源 = 源迭代详设契约 3——锁线 ⇔ `ist.locked_comp` 非空；锁定 comp 解析 = `get_comp(ist.locked_comp)`；key_equips = 锁定 comp 的 `key_equips`。flow wrapper 内 `self._ensure_intention(state_of(session))` 解析（decide_invest 先例 flow.py:507-513），strategy 契约签名不变（cw_strategy.py:206-208）。
- **target_comp 伪 comp 项移除**：现行 ①③ 项（+100/+30）的锚从 `state_of(session).target_comp` 切到 locked_comp 两态。P1 配方锁帧 locked_comp 恒空 → 自然落未锁分支（ADR-0357，源迭代契约 3 注）。
- fail-closed：locked_comp 非空但 `get_comp` 解析失败（注册表漂移）→ 按未锁态打分 + 日志哨兵（保守向：漏提权非错提权；源迭代详设 §1.4 同款）。

### 2.5 库存数据源 = state，直接消费

近兑现与需求守卫读 state 账，**用最近读取的数据**，决策时点不引入新采集。两本账：①备用库存账 `session.last_owned_equips`（近兑现对数判定）；②穿戴账 = 部署位 `tracked_deployed[*].equips`（`exec_state_of(session)` 读，需求守卫与备用账合计）。账的构成：全量 SIFT 重写（观察采集写端，prep_actions.py:411、:571-577）+ 建模效果增量（开箱选卡/确认到账/穿戴/卖返，§1.2 清单），并有期望态对账网持续审计。既有决策消费先例 = mandate.py:1647 m7 可穿面谓词、entry.py:665 持有快照——本设计与先例同源；**敏感度差异如实声明**：本判据消费精确计数（==0/==1），高于 m7 的存在性谓词，容忍度更低（§2.3 边界清单已列失真方向与挂账）。

防御注记（对抗审预防，非决策障碍）：在册裁定「发射位吃 last_owned_equips 陈旧快照 = 把陈旧数据源合法化」（prep_actions.py:211-216）辖的是**穿戴计划产出位**场景——那里执行帧可以现读（read_equips 对装备区可见），现读严格不劣，故禁发射位吃快照。开箱场景：**面板全屏覆盖型 overlay，装备区读取无在册通道（候实证）**——决策输入契约 = OCR 卡名行，装备区现读需新增识别面，非本批辖域；且决策与点卡在同一执行函数链内闭环（`_open_box` :986-1031 于 ：1014 内联调 `_pick_box_card` :1062-1099，双锚；entry.py 发射位只发空动作 PickBoxCard），该裁定针对的「发射后执行前漂移」失效面在此结构不存在——本消费不与裁定冲突。失真退化方向见 §2.3 边界清单（欠计数 = 错提权，如实非保守）；新鲜度门为非目标、失真观测键挂账。

### 2.8 通用化边界（后续消费位接入契约）

`pick_equipment` 是「候选全部为装备、多选一」形态的通用入口，但**不是一切装备决策都能走它**：

- **纯选装形态**（候选 = 纯装备列表：武装箱、装备三选一类）→ 直接接 `pick_equipment`，禁自写打分；
- **bundle 加性形态**（补给节点 = 角色分 + 装备分合成总分再比大小）→ 字典序不可加，**不能**用本选装器，只共享价值件（数值表 / `key_recipe_pairs` / 近兑现判据）；补给装备维是否接近兑现档 = 源迭代（2026-09-12-supply-selection）辖域的设计增量，本迭代不代裁；
- **equip_pick（装备三选一）**：现行通用信号 =「泛用关键词 +1」启发式，与数值表不同源；接 `pick_equipment` 意味着换轨其通用信号与档位结构（材料将降至直击之下），行为变化需单独裁定——非本迭代辖域，挂后续裁定，本迭代只保证机器接口对其可及。

# 24 部署段策略面(统一部署搜索·评分制)

> 定位 = **备战画面内部署执行段**(无独立 screen_info 建档画面):部署 = 备战决策环动作——统一部署搜索定型目标板,差分执行器产统一拖动/换星直卖动作序,经 `cw_op/cw_move_unit_action.py::CwActionMoveUnitOp` 机械拖拽在货币战争-备战上执行(部署机画面 op 已停用删除);未达上限确认弹窗(货币战争-未达上限警告)由流程层推进;**能力面** = [../screens/README.md](../screens/README.md) §5.3。本篇 = 该段的**策略面**:评分函数/三段搜索/差分执行器/消费端 + 形式判据指针。

## 1. 策略思路:组合评分搜索

「谁上场、去哪一排、选哪颗星」由**单一搜索**回答:枚举手牌组合、按评分取最优(评分形状 = 乘法合成 + 圈人羁绊驱动增量)。判据与搜索单一源 = `strategies/impl/mandate_v1/deploy_search.py`(评分/搜索代码归属策略层,消费同层常量与 kernel 注册表);定型口 = `mandate.select_deployment`(生产/虚拟两路径共用,输出 target_board)。**场上去留 = 部署算法单属**:卖出/优先级面只消费定型结论(档 1 名集 = target_board 名集)——部署零卖出概念,被换下者到备战席后按统一让位序参与卖出评估(部署与卖出两套独立算法);换下场上单位后的板面缺位由部署补位自然承载。

### 1.1 评分函数(总键 = (选人分, 站位分, 稳定键, 随机尾键) 字典序)

- **两个核心量**:**档位完成度** = 已达整数档 / 该体系目标档(终局线与过渡条目同构,均 = `Comp.core_faction_reqs`(羁绊要求档 0)单阈值端,显式选端禁读梯末);**角色完成度** = 该羁绊族已上场角色数 / 该羁绊族目标档激活阈值所需角色数(阈值 = `FACTIONS.tiers`)。
- **分族计分**:羁绊体系 = f = 角色完成度 × 档位完成度(乘法合成——残缺高层自动压 0,防拆板);空羁绊线(反甲流类) = 角色完成度单独承载(分母 = `core_chars ∪ shared_chars` 总数);选边双羁绊(布洛妮娅) = 计数统一消费现成 `side_pick_bond` 单边化。
- **羁绊计数口径 = 角色数量 + 星徽**(羁绊不按位置,只按角色数量和星徽):计数单一源 = `cw_bond_equips.unit_bond_tags`(注册表出身 + 开拓者排形态归一 + 选边单边化 + 装备贡献四合一)——评分直接消费,零新建口径;评分粒度 = 排级,槽位维度零羁绊消费(boss「相邻目标」属战斗结果侧,不入评分)。
- **层结构(按窗口分域)**:未锁定窗(P1/P2+)= L1 主目标羁绊层(P1 = 过渡条目羁绊骨架;P2+ = 候选线羁绊)> L3 普通层;锁定窗 = L1 锁定线核心羁绊层 > L2 锁定线非核心羁绊层 > L3 普通层(过渡件降 L3 普通计分)。
- **分值域(隔离常量 = 结构编码非标定:层间隔 10³ 数量级,语义 = 「高层任意正分 > 低层满分」,区间内变动行为零变;常量 = `_L1_NAMED_SCALE`/`_L1_TIER_SCALE`/`_L1_SCALE`(空羁绊线 members 承载支)/`_L2_SCALE`)**:L1 = **两层支配编码**(点名件层 ×10⁹ + 档位层 ×10⁸)——点名件在场率(named_rate = |点名件 ∩ 板|/|点名件|;点名件 = 锚/core 统一表达式,与 `form_progress` 同式)×10⁹ 严格支配档位层(加权平均 of f,权重 = 目标档激活人数)×10⁸,层间 10 倍域差保证**任何满点名件板恒压任何缺点名件板**(原 `required_deployed` 灭零特判的防形态,2026-11-06 随字段退役改评分承载——判例 = required-deployed-retirement;层间严格性数据边界 = 过渡 core 规模 ≤9,建库断言钉住),层内各留连续比较面,L1 域顶 = 1.1×10⁹;L2 = 加权平均 of 档位完成度(键集 = **仅加分层**〔`Comp.bonus_faction_reqs`,羁绊要求档 ≥1 全档合并〕;`flex_factions` 归 L3——注册表语义「板面不罚但完成度不数」正是 L3 语义);L3 = 计数制,单位序 = buff/debuff 羁绊(×3,键源 = `TIER7_BOND_NAMES`)> 万金油角色(×2,键源 = `CROSS_LINE_KEEP_NAMES`)> 其他(×1)。
- **过渡羁绊档 = 条件两态(换防形态 = 相位切换)**:锁定窗且锁定线 L1 = 0(一档未成)期间 → 过渡档 ×4(常量 = `_L3_TRANSITION_KEEP`,临时压过 buff/debuff——保板相位,过渡板维持在场);锁定线第一档成型(L1 > 0)→ 加分消失回落 ×1,L1 压倒 + 剩余席位按单位序填充——过渡件自然退板,下板后在 bench 按统一让位序处置(换防点 = 锁定线第一档成型,结构化可预测,换防形态 = 渐进混合)。
- **一键单归属(取当前评估上下文的最高层)**:L1 键组 = 条目档 0 每键一组(终局候选/终局锁定/过渡条目同构,键 = `core_faction_reqs`;锁定窗取锁定线键,未锁窗取当前候选线/过渡条目键)> 加分层键(升 L2,同键 L3 计分抑制)> 其余 L3 单位序;未锁窗其余键一律 L3(他线 L1 键在评估候选 A 时同样落 L3 计分,跨线同键不冲突)。
- **星级 = 落场后形态**:同键多副本取最高星参与评分,「星」按上场后实际形态取(银狼 3★ 上场即变换为下档 1★——评分消费上报层同一变换纯函数,评分板面 ≡ 执行后板面)。
- **站位分** = 锁定阵容站位完成度(`char_positions` 符合数)+ 前后台符合度(排偏好三级路由输出为判据,单一源 = `deploy_plan.deploy_row_pref`:阵容站位覆盖 > 注册表 position_pref 派生 > back 兜底,前排保证随迁;后排上限 = `back_layout` 现值)。
- **稳定键** = 与现板面一致数(名 + 排粒度;星维不进——星变更本该动板;结构化滞回)。**随机尾键** = rng 局面哈希播种(同一状态容器状态 → 同一目标板,跨帧稳定防并列板帧间翻转致级联 diff 恒非空;同帧多次搜索共享同序 rng → 同帧判定确定、局面不变跨帧可复现)。
- **金币维零交互**:CW 部署免费(上/下场/换位不花金币),金币不进任何评分维度(金币维全局核查过,非漏项)。
- 评分函数纯函数(消费状态容器状态,sim 可跑,禁 IO);虚拟面板字段域 = 状态容器读口全列(含环境发放上场锁 + uid;虚拟件 uid=None 名命中锁名单按 fail-closed)。

### 1.2 三段搜索(`search_deploy_target`)

- **段 0 枚举准备**(`build_deploy_panel` 装配,枚举硬约束——违反即产出不可执行目标):枚举基本单位 = 唯一性键;召唤物/系统单位(cost=0)固定后台末位、剔除出枚举,占 K 按 `max_units_of` 口径(真人可上场数 = K − 场上召唤物 − 场上未知件);**未知身份件**(识别失败,char_id 空)保留现位、不入枚举、不被移动(其槽对落位规则视同已占用,禁挤);上场锁(`deploy_lock_block_reason`)到期前不入目标板;开拓者 = 前后排两形态变体互斥(形态选择与排可行性绑定)。**无上阵窗口约束**(entry_signals 整体退役,2026-11 用户终裁——上场时机 = 骨架/L1 完成度自适应)。
- **段 1 圈人**:对每个候选羁绊按「填入下一档」可行性(所需角色数 ≤ 剩余空位 ∧ ≤ 剩余可用角色)逐档推进,产出每羁绊的**档位形态集合**(t ∈ {0..可达档} 各一套形态,t=0 = 不填该羁绊)——空骨架合法(全 L3 散件板 = P1 早期全散牌帧载体);候选族按窗口分域:未终局锁定帧(任意位面)= **过渡层条目骨架**(过渡候选/锁定条目的羁绊骨架,与终局锁定窗同构;条目域单一源 = `cw_intention.transition_active_entries`,锁定条目在前——终局锁定帧过渡层退役恒空);锁定 = 锁定线羁绊骨架(L1 键组 = 条目档 0 每键一组;**锚**(锁定线 `carry_anchor` 单名)在骨架选件序最前——「引擎不可拆」类形态由成员序承载,圈人分层仅锁定窗生效;P2+ 未锁 = 候选三线。**全枚举零截断**(手牌约束下组合不多;上限截断需要额外规则保最优性,规则本身即特殊逻辑)。
- **段 2 补人(候选生成器,近似)**:手牌剩余件按 `unit_bond_tags` 标签归属唯一组(组 = 核心羁绊键组/加分层键组/buff/debuff 键组/万金油组/其他羁绊键组),分组背包 DP + 贪心/组取舍变体并列生成候选——组得分 = 层归属全域 × 域缩放(跨组求和与最终选人分同一数值空间)、**增量口径**(组得分 = 含补件的组分量 − 不含的,骨架成员贡献一律归基线;L1/L2 完成度组 = Δ完成度,L3 计数组按计数口径:羁绊键组按已达档计、万金油按件计);**线内件优先占席**缓解(凡携带锁定线 L1/L2 键标签的剩余件 → 生成占席扩展候选,取至容量上限);**相位枚举**(过渡组按 ×4/×1 两相位各生成一套候选,终评按板面实测定相位——消除骨架固定判的相位高估)。近似只影响候选覆盖面:多标签件的次标签贡献 DP 内不可见、终评全量兜底。
- **段 3 评分取优**:全候选集按 §1.1 评分函数**全量终评**(DP 组分只是候选生成的内部度量,段 3 重算——单归属近似不影响终评正确性)→ 最高分组内排分配(`char_positions` 强制 → `deploy_row_pref` → 兜底 + 前排保证 + 后排容量扣场上召唤物 ∧ 未知件占格,小型分配问题精确解)→ (站位分, 稳定键, 随机尾键)定序取一。排分配的牺牲序(前排保证与全员 back 偏好冲突时)= 站位分损失最小者。
- **成本口径**:单次全搜索 ≈ 0.1s 级(can_deploy_single 每张店内牌一次,帧内 × 商店槽数;评估帧 = 步 3 定型 + 净腾校验定型 2 次搜索;sim 实测定参);备战常规执行零搜索(差分与落位是执行算术)。

### 1.3 差分执行器(统一拖动;单一源 = `mandate_v1/deploy_diff.py`)

- diff = 现板面 vs target_board(**就位判定粒度 = 名 + 排 + 星**,槽不进判定);diff 空 = 显式零动作。与第 6 步(常规部署)、前置步(计划游标驱板)、出战链共用本执行器——**target 来源不同**(第 6 步 = 当前帧搜索定型;计划游标 = 商店写端定型的固定 T,备战执行零搜索),执行器逻辑同一。
- **动作序** = 换星直卖(同名异星对两步之一:场上低星副本 `SellDeployed` 直卖,reason `deploy_star_swap`——低星不经 bench 中转,否则名字 ∈ target 名集 → 档 1 备战位同名牌永不先卖 → bench 席位死锁;1★ 全额退 = 换星零成本,2★ 以上直卖手续费损失 = 罕见帧边界)→ 缺位者上场(bench → 场上,目标槽空 = 统一拖动直落、被占 = 交换交互——被占者回 bench 源槽,bench 占用不变,「席满挡换人」形态不存在;**落位槽选择** = 同排内取「多余者 > 错位者」的槽,禁占已就位者的槽)→ 错位者排修正(场上直拖一步,无 bench 中转两步形态)→ 多余者下场(场上 → bench 空槽)。
- **收敛**:非卖步每步至少一名字就位且不被挤回(落位槽选择规则保证);卖步不减少已就位名字集(卖的是部署外多余者或低星副本);排错修正一步到位;星分量两步收敛(低星下场后高星上场即就位)。
- **新鲜度守卫**(`fresh_buys` 账本):下场/交换步涉及本帧刚买件 → 跳过该步挂起(防同帧买入即被换下抖动);不拦卖出(卖出归卖出场景/计划变量,卖侧自有新鲜度排除)。
- **执行形态**:第 6 步常规差分 = 零读屏多动作循环 + 入口 heavy 对账(无卡死判定需求,收敛由下一入口对账兜底——常规纯移动可逆,假收敛最坏 = 带误差板打完当前节点、战后对账纠回);计划执行期 = **拖动与重观察交替**(每发一个统一拖动后下一帧发 `Obs(in_place)` 环内重观察对账——自上报推演 vs 实读板面,不符则 diff 重算;连续 2 次重观察无进展〔含无动作帧〕= 级联卡死 → 失败出口);溢出告警帧 = 搜索与差分执行器全跳过(卖出走第 0 步强收窄单动作路径;态 1 上阵 = 告警帧专用特例:bench 真单位直落场上空槽,载体 = 统一拖动)。
- 上报推演矩阵单一源 = `kernel/cw_action_report/move_unit.py`(源域 × 目标域 × 目标槽占用态写分支:直落/交换/纯换位/下场/席内挪位;锁校验辖「新单位入场上」全形态,银狼变换窗只 bench→上场触发,开拓者按目标排定形态)。

### 1.4 消费端与接口契约

## 2. 会执行的动作清单

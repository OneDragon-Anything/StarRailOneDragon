### D4-4｜锁定窗「保过渡板」走查跳过 L2：sub_tiers 可凑档帧的板面序完全不同，走查行与分值表不自洽
- 攻击点：场景走查「P1 锁定、1 核心在手、过渡对成型 → L1 乘法零分（未成档）→ **L3 定序**：万金油（×2）优先于过渡件（×1）」——该行从 L1 直落 L3，隐含「该帧 L2 = 0」；但锁定窗层结构 = L1 > **L2** > L3，锁定线 sub_tiers 凑得出档的帧（手有 2 护盾/减益/击破/战技点件——sub_tiers 键都是 2 人低门槛档）L2 ≥ 5×10⁵ ≫ L3（≤ ~70），板面序 = sub_tiers 凑档件 > 万金油 > 过渡件——「万金油优先于过渡件」的裁定语义只在 L2 = 0 帧生效，走查未声明该前提也未覆盖 L2 非零分支。D3-10 处置只改了 L3 内部平分的定序说法（「真实承载 = 稳定键」），没处理 L2 存在性对保板判定的影响；用户裁定「过渡类一律其他档」后，sub_tiers 凑档件（非万金油非过渡件）反而成为锁定帧最高优先散件——保板判定的真实序 = 「锁定线 sub_tiers 凑档 > 万金油 > 过渡」，与走查行的「L3 定序：万金油 > 过渡件」相差一整层。
- 证据：详设 :36（层结构表锁定行）/:44（L3 行）/:49（L2 键集）/:120（走查第 2 行）；cw_comps.py:597,1199,1399,1466。
- 严重度：中（走查覆盖缺口——判定依据漏分支，验收用例按走查写会漏 L2 非零帧）。

### D4-5｜D3-5 构造式补人两个完备性缺口：多羁绊重叠件容量核算未定义；「排序」与「构造式枚举」的关系歧义 + 剩余羁绊候选域未定义
- 攻击点：a) 「对每个剩余羁绊枚举『取 0..可达档件数』（枚举对象 = 档位形态）+ 万金油在场数枚举」——羁绊共享成员是常态（unit_bond_tags 为**多集**，一件角色自带 factions+flows 多标签，cw_bond_equips.py:107,144）：羁绊 A、B 共享件 c 时「A 取档 1 形态 + B 取档 1 形态」的实际占用 = |A∪B| < |A|+|B|。档位乘积枚举若按形态件数**相加**核算容量 = 保守漏板（可行组合被判超容丢出枚举空间——正是 D2-9 攻击过的凑档组合不可见形态在构造式里的翻版）；按并集核算则需写明重叠件归属与去重规则——设计两字未提。b) 「补人排序（用户裁定）：buff/debuff 羁绊档 > 万金油角色 > 其他」与「构造式枚举」的关系未定义：若排序 = 填充序（贪心按序占席）则与构造式枚举矛盾（枚举不需要填充序）且单类贪心重演 D2-9（buff 羁绊差 1 件凑不成时席位浪费 vs 其他羁绊已凑档的取舍）；若排序 = 枚举后并列 tie-break 则与 L3 系数 ×3/×2/×1（同一序已数值编码）冗余——何时裁决未写。c) 「剩余羁绊」的候选域（全部 FACTIONS 键？锁定线相关键？TIER7 在不在内？）未定义——buff/debuff 键在不在补人候选域直接决定「骨架外 buff/debuff 凑档」路径的存在性。
- 证据：详设 :75（段 2）；cw_bond_equips.py:107,144；对照详设 :73（段 1 全枚举零截断仅覆盖圈人）。

### D4-8｜L3 单位序（×3/×2/×1）只在「同档数边际」成立：跨档数堆量可平/翻序，平分走向未申报

# comp-schema-v2 迭代设计（总纲）

## 0. 元信息

- 迭代目标：用户裁定（2026-11-06）——core/shared 两档定义语义混杂、派生优先级表达力不足，**完全重设计阵容定义**；先定义方法、验证表达力，迁移另立批次。
- 状态：草案
- 文档清单：无详设（单文档方案）。
- **范围声明**：本设计只包含 ①阵容定义方法（schema 结构）②终局阵容定义规范 ③过渡阵容定义规范 ④表达力验证。**不含**：现有 21 套数据迁移、策略消费面（评分器/采购/部署）改造、A/B 双套装备登记、板凳/备战席特殊行为、圣杯 Saber 版补数据（数据工作随版本重跑）——以上均另立批次。

## 1. 问题与动机

### 现状症状

1. **core/shared 语义混杂**：同一个 core 档里混着「机制必要项」（三月七之于反震姬子——拿掉机制不成立）和「高价值万金油插件」（瓦尔特 7 线 core——任何线都不是定义角色），两者拿同一档身份行为包（证据/保护/装备/gift）。
2. **登记口径双轨**：圣杯红A/希儿按「功能链定义环才 core」（窄 core），千冶/巡海/反甲白厄按「常驻即 core」（宽 core）——同一注册表两种口径，版本重跑无法机器复现。
3. **优先级表达力不足**：member_rank 两档派生（core 0/shared 1）要同时伺候四个正交消费面的序——证据分要「独占性」维度、装备分配要「线内全序」、卖牌要「反向序」、星级要 per-角色目标；两档装不下，每个消费面都在别扭（平权关系无法表达是典型症状）。

### 根因归层（语义层）

阵容的知识层解剖是**功能拓扑**（核心机制角色/羁绊支撑/核心辅助/凑羁绊——final_comps 十类构造机理各篇「槽位构造」节的语言），旧 schema 把它压成「重要度两档」——**身份层缺失**是全部症状的共同根。证据维度的「独占性」缺陷（持一张万金油牌等权点亮 7 条线）也是同一根因的投影：身份层若存在，瓦尔特天然落「辅助」档而非「机制」档。

### 解决到哪 / 明确不解决

- 解决：schema v2 结构（三层名单+两层羁绊+挂人配方）、终局/过渡两库定义规范、建库校验、消费面映射、表达力验证走查。
- 不解决：见 §0 范围声明。

### 2.2 Comp v2 字段定义

```python
@dataclass
class Comp:
    """一条阵容的定义 = 有序阶段列表（终局库与过渡库共用本结构，见 2.4/2.5）。
    大多数条目仅 1 个阶段（=纯终局形态）；高费核心线可登 2+ 阶段
    （动机:核心机制角色 4/5 费晚到,构建期存在过渡C 代穿/工具人等中间形态,
    圣杯红A(凛/希儿代穿+闪闪/Saber 任务工具人)、DOT(卡芙卡→黑天鹅)为实证案例）。
    执行语义:策略侧每个决策点重估当前阶段(按序扫描,取 enter_when 已满足的
    最后一个),只按当前阶段的字段行动——旧阶段有而新阶段无的角色按新阶段
    优先级卖掉;装备配方换了归属人的(同配方跨阶段换主人)从旧主身上拆下转给
    新主。卖牌/转移全部是「按当前阶段执行」的隐式结果,不设显式交接字段。
    """

    name: str
    stages: list[Stage]


@dataclass
class Stage:
    """一个阶段的目标态快照。"""

    # ── 进入条件 ──
    # 进入本阶段的条件;None=起始阶段(开局即当前)。
    # 值域初定={'成员到场'}单条件(如 'Archer'=Archer 到手时切本阶段)——
    # 482 篇正文实证的所有形态切换均为「某成员到场」单触发
    # (Archer/符玄/姬子/黑天鹅/瓦尔特);等级/位面类触发暂不收,出实证再扩。
    # 挂进入条件而非退出条件:阶段自包含(何时进+是什么在一处),
    # 中间插阶段不动相邻阶段。
    enter_when: str | None

    # ── 名单层（三层；值=层内优先级，小值优先，同值=平权）──
    # 核心机制角色：机制必要项（拿掉检验：拿掉→机制不成立）。AND 全员必要。
    # 过渡阶段的机制角色=过渡C 本身(如红A 线阶段1=远坂凛)。
    core_mechanism: dict[str, int]

    # 核心辅助：**服务于本线机制的最适配者**（用户重申 2026-11-07，取代早前
    # 「线内偏好人选/拿掉强度掉档」宽松版——宽松版导致超编名单，作废）。判据两类：
    #   a. 放大机制（引擎件：拉条/充能/羁绊计数件——如红A 线花火/刻律=战技点
    #      引擎直接放大出手次数）;
    #   b. 保障机制运行（机制死穴解药——反震姬子线瓦尔特延后倒计时;或与机制
    #      双挂的服务位——能量队生存位优先藿藖(治疗+能量双挂)、反震姬子线
    #      生存位优先腾荒(护盾挂凑 L4),一人双职而非任意强力生存件）。
    # **名单=采购指令：写谁买谁——单坑位只写一个锚**（生存位/兜底位各一锚，
    # 写两个=教策略层买两个,占双坑——用户判例 2026-11-07）。零适配通用位
    # （符玄型:强力但与本线机制零挂载)不进名单,走公共凑件表按局面取;
    # 变体绑定对象（输出姬子线的饮月战技点流,约 5-8 帖)与终局高退役率过渡件
    # （饮月 Early→Final 保留仅 38%）不进终局名单。
    # 过渡阶段的工具人(圣杯任务人闪闪/Saber 等)登在此层——阶段名单差集即退役集。
    core_support: dict[str, int]

    # 凑羁绊覆盖：{羁绊名: [有序名单]}——对本线相关羁绊的公共凑件表覆盖；
    # 默认空=全用公共表（FILLER_PRIORITY，见 2.3）。
    filler_override: dict[str, list[str]]

    # ── 羁绊层 ──
    # 核心羁绊：必选 AND；值=成型档位（进成型判定+采购硬目标）。
    # 档位登记判据=质变点（该羁绊强度曲线的非线性跳变档，如欢愉5=阿哈3装备栏、
    # 燃血4=1000% 倍率）；可以是多条（希儿量子4+贝4 双修，final_seele_quantum）。
    # 过渡阶段按本阶段目标登（如红A 阶段1=命运圣杯:2——任务激活线）。
    # 绑定白送档也登记（用户裁定 2026-11-06:送的是零采购成本,不是恒真——
    # 过程监控缺席期+缺员替代路径,见 2.4）。
    faction_core: dict[str, int]

    # 加层羁绊：认可集（不进成型判定；凑件槽选人与采购优先级的参考）。
    # 不登记档位、不登记互斥选择关系——攻略自身按来牌灵活（B5 规律），
    # 选择=凑件槽选人的运行时投影（如 DOT 副羁绊四选实为名单成员变化的投影）。
    faction_bonus: frozenset[str]

    # ── 挂人配方层 ──
    # 装备配方：角色→装备列表（主套）。键域=本阶段两层名单并集 ∪ {'阿哈'}（具名单点
    # 豁免:欢愉羁绊召唤物的装备栏,终局配方有真实消费面——合成优先序「优先做阿哈的
    # 风暴潮再到银狼的」,final_yinlang_joy §4;用户裁定 2026-11-06）。
    # 配方内顺序=合成/分配优先序。
    # 跨阶段同配方换主人(凛/希儿→Archer)=装备转移的表达,无需显式交接字段。
    equip_assign: dict[str, list[str]]

    # 星级目标：只登偏离库级默认的行（默认见 2.4/2.5 库级常量）。
    # 语义=追星停手线（花金刷新的星级目标），非自然来牌上限。
    need_star: dict[str, int]

    # 站位：角色→排级+排内位次。值域={'front','back','front#n','back#n'}
    # （n=排内第几位，列表序号口径；用户裁定值域选「排+位次」2026-11-06——
    # 主C前排第1位为跨线铁律+星期日技能点名「后台1号位」+三月七「相邻目标」
    # 覆盖，位次有真实机制语义；位次不稳的角色退化写排级）。
    # 旧 front@n/back@n（board_index 口径）已废（2026-11-06 勘误）。
    char_positions: dict[str, str]
```

**范围声明**：本设计只定义上述字段结构本身。派生概念与消费面接入方法不在本设计范围（§0）；§2.7 仅做「字段能否伺候消费面」的对账，不定义接入方法。

### 2.3 凑件公共优先级表（跨阵容公共表，不在 Comp 内）

```python
# 挂注册表层（cw_factions 旁或独立模块）；阵营/流派羁绊各一张（独立羁绊无凑件语义，不建）。
FILLER_PRIORITY: dict[str, list[str]]   # {羁绊名: [角色名, ...]} 有序，前=优先
```

- **收录判据**：辅助/工具型角色（治疗/护盾/辅助/低费工具）；**输出大C 不进表**——他们只作为某条线的核心机制角色/核心辅助被点名，轮不到当凑件。同一角色与阵容内身份并行不冲突：阵容点名优先，已点名者不占凑件评估位。
- **序的综合维度**（登记时人脑综合，不建多维评分）：功能价值（治疗/护盾/增益）、羁绊挂载数（佩拉=贝洛伯格+减益双挂——选她一人开两层）、费用（低费灵活 vs 高费自带面板）、站位兼容（back 不占前排保证位）。
- **阵容覆盖**（`filler_override`）：本线对某羁绊凑件序有特殊要求时出现，默认空——消费先行：无真实需求不硬造数据。
- **校准源**：攻略出场统计（如希儿线佩拉/娜塔莎留到终局，final_seele_quantum §2）+ 实机。
- **定稿数据（用户逐羁绊裁定 2026-11-06）**：见附录 A。

### 2.4 终局阵容定义规范（COMP_LIBRARY）

**结构**：Comp v2 全字段（name+stages；大多条目 stages 长度=1）。配方层（equip_assign/need_star/char_positions）按知识登记，允许为空字典（无知识=运行时用默认，见下）。多阶段登记判据：核心机制角色 4/5 费晚到、正文存在代穿/工具人中间形态才登阶段 2+（红A 线两阶段为首个案例，见附录 B.4）；通用前期过渡（仙舟3/DOT2）是跨阵容共享知识，登在过渡库不逐线复制。

**星级默认（库级常量）**：核心机制角色=3★、核心辅助=2★、凑件=1★（不追）。依据=A4 星级饥渴统计批（高饥渴线核心 3★ 80-94%、辅助普适档 3★ ≤30%——身份层与饥渴档强相关）；例外只登偏离行（如反震姬子三月七=2★：机制角色但绑定身份足矣；Archer=2★：低饥渴线常态完成态，final_grail_dual A4/D1）。

**登记判据链**（从攻略知识落到字段）：统计给候选（plaza 聚类频次）→ 拿掉检验分层（P3）→ core_support 双判据审定（放大机制/保障机制运行，见 2.2 字段注；单坑单锚、零适配通用位出名单走公共表）→ 档位按质变点（2.2 faction_core 注）→ 例外登记（星级/站位偏离默认）→ 机制叙事（领航员绑定/饲饵充能泵/为什么是他）归 final_comps 文档层，不进 schema。**faction_core 白送档也要登记**（用户裁定 2026-11-06）：由机制位成员自动达成的羁绊档（如绑三月七→护盾 2）仍写进 faction_core——过程视角下成员有缺席期（监控达成状态）且缺员时需凑件表替代路径；「送」指的是零采购成本，不是恒真。

**默认值兜底**：char_positions 未登记者用注册表 `position_pref()`（既有契约：common 默认 back 是无知识兜底）；equip_assign 未登记者无配方（装备按通用价值分配）；need_star 未登记者按库级默认。

### 2.5 过渡阵容定义规范（TRANSITION_LIBRARY）

**核心结论：过渡阵容=同一 schema 的低密度实例，不另立结构。** 密度谱系（从知识层验证，final_comps 各篇 Early 节）：

| 形态 | core_mechanism | core_support | faction_core | 例 |
|---|---|---|---|---|
| 纯计数（任意成员） | 空 | 空（或仅偏好序） | {持续伤害: 2} | DOT2 构造块（「任意 2 人即用」，四陷阱第 4 条） |
| 偏好班底 | 空 | 班底序（饮月>藿藿>爻光…） | {仙舟: 3} | 仙舟3（换青雀机制仍成立=班底是偏好非必要；「最佳班底」依据 final_jizi_train §3） |
| 单卡点名 | {希儿: 1} | 空 | {量子同频: 2} | 希儿量2（单卡即战力/过渡=终局同体，final_seele_quantum §3） |
| 组合条目 | 各构造块并集 | 各构造块并集 | 两羁绊 AND | DOT2+希儿量2={持续伤害:2, 量子同频:2}——「一批牌三挂」的自然表达 |

**组合条目制沿袭**（既有裁定，comp-definition「过渡层不复制分层」节）：单羁绊构造块不是条目、永不锁定；条目=构造块两两组合，建库期生成。构造块本身用 Comp v2 表达（空 name 或块名），生成器合并名单与羁绊（同名成员取更深层——机制层覆盖辅助层）。

**库级差异**（终局库 vs 过渡库的消费语义边界）：

| 面 | 终局库 | 过渡库 |
|---|---|---|
| 星级默认 | 机制3/辅助2/凑1 | **全员自然来牌**（过渡=攒钱期，无追星行为；need_star 恒空） |
| 装备配方 | 按知识登记 | **恒空**（装备材料意向锁定即留给终局，D7 规律；过渡阵容不消费装备知识） |
| 站位 | 按知识登记 | 恒空（默认 position_pref） |
| 锁定语义 | 可锁主线 | 永不锁定（策略层既有消费差异，库类型即载体） |
| filler/faction_bonus | 按知识 | 恒空（过渡期「顺手开层」=运行时边际评估，无预登记价值） |

**两库分立**（不合并为单表带 kind 字段）：消费语义差异大（校验规则不同——过渡库配方层必须为空）、既有命名沿袭、锁定语义天然隔离。

### 2.6 建库校验（build-time）

终局库与过渡库共用 1-5，过渡库附加 6-7：

1. `core_mechanism ∩ core_support = ∅`（同一人不双层）。
2. 名单成员 ∈ CHARACTER_ROSTER；装备名 ∈ EQUIPMENT_ROSTER；羁绊名 ∈ FACTIONS（faction_bonus 的羁绊需有成员注册）。
3. **成型可行性**：`faction_core` 每条羁绊，点名成员自带计数（含开拓者形态归一、布洛妮娅选边）+ 该羁绊可用凑件池 ≥ 档位（防登记错误：如量子4 但点名+全池只凑得出 3）。

6. （过渡库）equip_assign/need_star/char_positions/filler_override/faction_bonus 恒空。
7. （过渡库）faction_core 档位 ≤ 过渡期人口可达（构造块档位 2-3 为宜，组合条目人口 ≤ 6）。

### 2.9 关键取舍（备选方案与放弃理由）

1. **两档重要度（旧案） vs 三层功能拓扑**：两档已证伪（§1 症状）；四层（载体/触发器/插件/填充）被合并——载体与触发器同为机制必要项（用户框架），且子分类信息已被配方分布编码（输出件挂谁=输出端），显式建模=冗余。
2. **凑件阵容内点名（早案） vs 羁绊级公共表+覆盖（定案）**：凑件价值是角色自身属性（佩拉在任何线当贝凑件同值），逐线点名=冗余登记；公共表与候选生成员（羁绊成员集）同粒度。
3. **互斥 OR 组 vs 拆条**：OR 表达力引入整层复杂度（成型判定/证据/配方都要处理分支）；拆条与流派分条先例同构，代价只是条目数+1（圣杯）。
4. **faction_bonus 带档位 vs 纯集合**：档位价值可运行时按注册表强度曲线评估；纯集合登记简单。实机发现评估不准再引入目标档（消费先行）。
5. **统一单库+kind 字段 vs 两库分立**：消费语义与校验规则差异大（过渡库配方层恒空），分立更清晰；命名沿袭现状。
6. **need_star 全量登记 vs 默认+例外**：A4 统计证明饥渴与身份层强相关（默认命中率极高，案例4 零例外）；例外行=登记量数量级下降，且「谁是例外」本身是知识（三月七 2★/Archer 2★ 有攻略依据）。

# strategy-env-impacts.md —— 投资策略/环境逐效果的 state 影响

> 本文档所属 = game_state 设计目录,总纲见 [README](README.md)(含 GameState/BoardState
> 命名对应注)。

## 1. 本篇管什么

投资策略卡与投资环境卡的效果会改写 GameState 字段(金/席位/商店/节点序/免费刷新余额
等)。本篇**逐效果登记**该效果在 state 里的影响,供策略消费与对账。边界:

- 效果的**游戏机制原文**真值源 = 注册表 base 层 `cw_invest_data.py`
  (`PLAZA_AUGMENTS` 等官方文本;数据权限序=base 官方文本>手工 overlay>文档转述,
  ADR-0620 先例)。本篇不复述全文,给条目指针。
- 效果的**运行时账本**(在场实例/计数推进)在 effects 域(inventory 方法域),其内容
  语义(计数器模型/生命周期/逐效果规格)归独立效果域设计件(候成文);本篇只登记
  「效果 → state 字段」的写入面。
- 注册表与文档的冲突以注册表官方文本为准,漂移显式标注(先例=大裁员 burst 数值反转,
  ADR-0620)。

## 2. 条目形状(四槽)

每个已确认条目按四槽登记:

| 槽 | 内容 |
|---|---|
| 官方原文 | 注册表条目指针(卡名/品质/`cw_invest_data.py` 行位;必要时摘原文) |
| 机制 | 该效果在游戏里做什么(触发时点/确定性/随机面) |
| state 影响 | 改哪些字段、走哪个渠道与写口(observe/write_logic/效果桥/账本方法)、随机面如何收口 |
| 策略层消费 | 策略器/执行侧拿到该影响后做什么(重估/编排/禁买门等) |

**写入归属判据**(容器正本 §5.3,玩家裁定):效果结果**可准确计算**(确定性公式+已知
输入)→ 逻辑写(`write_logic` 或两步机制);含**概率/随机**、结果不可预知 → 不建
逻辑写端,观察收口(observe 覆盖)。每槽结论以最弱一环的证据强度为准。

### 通用模式申报(2026-09-10 定稿,横切本篇全部条目与后续逐条确定)

两条横切读数/归位规则,消费 §3 条目时一律适用(规则全文 = 效果域设计件
§2.5/§2.6,本节为消费侧申报;两处互指,细则以设计件为准):

1. **观察优先、兜底逻辑**(定稿首例=买经验费用):一切画面有显示的数值,以观察为
   准(备战画面直接读显示价),观察不到才逻辑兜底——买经验费用 = 基准 4−折扣
   (max 0;基准恒 4=用户口径,非按等级)。与节点序键同款单字段双值结构
   ([node-domain.md](node-domain.md) §2)。商业间谍在场时显示价即折后价(游戏已
   算好),显示价优先即天然含折扣。
2. **state 内部惰性读口 vs swap 急算**(派生值归位三件套):①随事件必须落账 →
   _swap 效果域段急算(计数器/发放/倒计时基数);②消费时才被问 → state 内部惰性
   读口(首两个实例:`effective_node_ord()` [node-domain.md](node-domain.md) §3;
   `xp_buy_cost()` = 商业间谍被动腿,见 §3 商业间谍条);③_swap 前只放原始读数
   整理,依赖 state 内部知识的派生禁放。

| state 影响 | 选卡时点(渠道② logic_action):①前台/后台/备战席三域**清场重写**(出售清空面=确定性,按归属判据走逻辑写/两步机制;退款金入 `gold`,双倍价=`sell_price_mult=2` 施于退款,×2 施于净额还是基础价待实机实证——容器正本 §4 SellBench 修饰行);②免费刷新余额 +6(计数域 `free_refresh_balance`,经 burst 桥 `apply_effect_burst_grant` 在选卡时点单次授予;落码前注册表 overlay 现值实发 5,差 1=已裁注册表漂移(ADR-0620),注册表改 6 落地前以 5 为现行行为)。效果账本面:大裁员暂无 `STRATEGY_EFFECTS` 条目(注册表仅 sell_price_mult/burst 结构化),出售动作载体=缺口登记(容器正本 §5.2/§5.3 卖全场族行);批内接线前未覆盖增量一律走观察覆盖兜底 |

## 5. 逐条确定流程

1. **取真值源**:读 `cw_invest_data.py` 该卡官方原文全文(逐句;卡文效果无结构化字段
   者照登,防「结构化效果各有归属、卡文效果无人看管」的假全覆盖——容器正本 §7 同
   判据)。
2. **拆效果腿**:按句拆出每条效果腿(给金/发牌/改写/计数/时点),逐腿定触发时点与
   确定性。
3. **归属判定**:按 §2 归属判据逐腿定写口(逻辑写候选/观察收口/缺口登记);结构性
   缺口(注册表无载体)登容器正本 §5.2,不在本篇造第二登记源。
4. **确认**:确定性结论经用户或实机采证确认(实采以对局档案/画面采证为锚,口述按
   待证假设对待);随机面与待证面如实标注,禁拍死。
5. **回填**:四槽填全后条目移入 §3;进度事件记进度账本(不在本文留痕)。

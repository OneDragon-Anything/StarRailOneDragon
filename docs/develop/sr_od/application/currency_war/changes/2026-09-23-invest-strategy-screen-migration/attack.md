## 流程教训（已制度化进后续轮任务书）

1. **否定性断言（「不在册」「不可解析」「零命中」）必须亲核后才可吸收**——R22 两起假发现（「110>105 非在册原文」「screens 残留不可解析」）均被原样吸收进设计稿，R23 才由下一轮审查翻案。审查发现与设计稿同等对待：发现报告也是「稿」。
2. **修复引入的新内容须做 as-built 核实**——R21-F8 建议补「cw_replay --diff」验收义务时未核工具 as-built，产出不可执行验收门（R23-F1 翻出）。
3. **引用的文件先确认存在再引其内容**——「sim 六处 isinstance」跨五轮传播，直到 R12 才有审查者实际打开 sim 目录。
4. **同文件自相矛盾的注释以代码体裁决**——R18-F1 的根因（op :34 模块注 vs :214 observe docstring）。

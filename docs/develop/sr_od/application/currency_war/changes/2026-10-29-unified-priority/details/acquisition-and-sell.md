# 获取角色流程与卖出判据件（详设）

## 问题与约束

本篇承载总纲 §2.9 接口契约 2：**部署虚拟重算接口**（部署判据本体零改动）+ **三触发卖出判据件**（全部消费 priority-model 的统一序列）。约束：
- 副本零遥测：状态流水（journal）、策略遥测、决策帧三通道在虚拟重算中零写入（总纲 §2.3，验收 = 虚拟重算执行前后遥测流水字节数不变）；
- 物理约束不变：店内只能卖备战位；
- 消费点改造必须逐场景对照总纲 §2.6 映射表，禁漏禁增。

## 方案

### 1. 部署虚拟重算接口

**契约**：

```python
def select_deployment(frame: MandateFrame, prep: PrepContext) -> frozenset[str]:
    """输入局面快照 + 部署选人上下文装配，返回「部署算法定型的在场角色名集」（目标态）。

    生产路径（_step5_deploy 动作生成）与虚拟路径（获取角色流程）消费同一函数。
    """
```

**PrepContext 字段面**（部署选人所需只读上下文的显式装配——现行选人核心消费 session/gs 读口（`_make_windowed_select_up(session, gs)`、`_deploy_window_blocked(session, …)`、session_scope 各读口），抽取后这些读口的取值由本装配承载；字段清单按选人核心实际读面反向枚举，落地批抽取时冻结）：
- 锁定线名单视图 / 候选快照 / 过渡配方对（现行 `session_scope.line_members_view` / `direction_comp_of` / `opening_recipe_comp` 读口）；
- 上阵窗口信号与 entry_signals（现行 `_deploy_window_blocked` 消费面）；
- 部署缺口与容量（`deploy_vacancy` / `deploy_cap` 现算输入）；
- M1″ 换阵的 up 候选选择输入（现行 `_make_windowed_select_up` 装配面）。

**语义定案（板满换阵的收敛问题）**：虚拟重算只回答**目标态**（「部署定型后谁在场」的名集），**不模拟换阵路径**——现行板满换阵是多帧单对发射（`emit_swap_redeploy` 选组、每帧一对、下帧幂等续发），该迭代过程仍归现行 M1″ 机制；虚拟重算消费的只是目标态名集（档 1 判定输入 = 「谁是被部署需要的」），换阵执行与本流程解耦。接口语义 = 「目标态求取」，非「换阵过程模拟」。

**载体定案：局面快照纯计算，禁容器深拷贝**。理由：
- `MandateFrame` 本身是纯数据载体（gold/level/bench/deployed/deploy_cap/node_type/k_members/round_num 等字段，`mandate_v1/mandate.py`，entry 十段的判据输入即由它装配——entry.py 装配段现读），快照 = 构造一个虚拟 MandateFrame，零容器接触、零遥测风险；
- 容器深拷贝需处理懒加载服务、观察链、journal 写端静默化，静默失败面大（总纲遥测隔离段的红线）。

**实现形态：结构抽取，判据本体零改动**。现行部署选人逻辑驻 `entry._step5_deploy`（M5 开局配方 / M1 空槽补位 / M1″ 换阵补部署，判据 = 24 号稿）与 `mandate.emit_swap_redeploy`（选 up/down 的核心 `select_swap_plan`/`select_deployments_reasoned`）。重构：
1. 把「选谁在场」的判定核心抽取为纯函数 `select_deployment(frame, prep) -> frozenset[str]`（内部复用现行 `_deployable`/窗口谓词/配方围栏，零判据改动；现行实现消费的 session/gs 读口改为从 prep 取值，取值语义逐一对齐现行）；
2. `_step5_deploy` 的动作生成改为消费该纯函数（现行为 → 动作 diff 生成）——生产路径行为不变（抽取 = 结构重构，回归由现行部署测试守）；
3. 虚拟重算 = 构造虚拟 MandateFrame（置入新牌 + 升星模拟后）→ 调 `select_deployment`。

**虚拟置牌与升星模拟**（总纲 §2.3 第 1-2 步）：
- 快照上的轻量合成模拟：按「角色名 × 星级」分组计数，计数达 3 → 合成为高一级单位一张（机制全集口径 = 同名同星档计数 == 2 时买第 3 张合成；含场上+备战混合计数、2★ 档合成向 3★ 推进——与 11 号稿 §1 M2b 口径一致）；合成后重查（连锁合成到不再触发为止）；
- 合成释放的备战位计数回虚拟局面；其余联动（效果/装备/羁绊重算/环境回调）不模拟【拍】；
- 快照构造输入 = 当前容器读口的一次性读取（bench/deployed/level/gold/持卡等——只读，零写入）。

### 2. 获取角色流程（席满买入的六步，总纲 §2.3）

**挂点**：商店买入序的席满分支（现行「店内置换账」位置，11 号稿 §4.0——评估器首位 + value 直比的代码段）整体替换为：

```
1. 快照 = 当前局面只读快照
2. 虚拟局面 = 快照 + 新牌置入备战位
3. 虚拟局面内升星连锁模拟（上节）
4. 部署定型 = select_deployment(虚拟局面, prep)
5. 部署外的全部持牌按 priority.sell_order 排序（在手旗标：存量 = 在手，
   新牌 = 将获取；排序池 = 备战位——场上件不入卖出池，被部署挤下件的
   离场归后续备战环节，见总纲 §2.3 物理约束）
6. 末位 = 新牌自己 → 放弃买入（零动作，拒绝语义与现行席满拦一致）；
   末位 = 存量牌 → 发出卖旧（CwActionSellBench）→ 下帧重入买入（单动作契约：
   一帧一动作，卖与买分两帧——与现行置换账的执行节奏一致）
```

- 遍历状态切换：同一次商店访问内首次「卖旧买新」完成后，备战位有空位 → 后续商店牌走有空位买入态（不再走本流程）——状态由容器逻辑态自然承载（卖后位空），无需额外标记；
- 拒绝语义：末位 = 新牌 → 本牌进未消费机会清单（现行拦因形态保留，拦因键改为「优先级不足」类新键，详设 key 表随落地批登记）。

### 3. 三触发卖出判据件

**单一入口**：现有场景注册表结构保留（`criteria/sell_candidates.py` SCENE_SPECS——场景参数化的现行骨架），场景参数表重写为统一序列消费。下表「场景」列为语义标签，注册表键名以现行 SCENE_SPECS 键为准，键名映射随落地批键表登记：

| 场景（语义标签） | 取用 | 循环防线 |
|---|---|---|
| 溢出紧急处理 | 部署重排定型 → 序列末位起连续卖出至不溢出（无特殊池子：部署外的牌自然排后；上阵安置 = 部署补位自然承载——部署逻辑保证前后台无空位，现行 M1 补位机制，无特殊安置规则） | **豁免**（保命优先，现行豁免保留） |
| 采晶矿前空位 | 序列末位一张 | 照常 |
| 凑钱买经验（升级凑金） | 末位起卖至「现金 − 批 ≥ 利息线」 | 照常 |
| 卖牌保利息（节末） | 末位起卖至跨过下一利息档（退金不足跨档的不卖——跨档止盈语义保留） | 照常 |
| 店内筹资 | 末位起卖至差价闭合 | 照常 + 同轮禁卖 |

- 各场景的排序 = `priority.sell_order`；**无场景专属池子**——统一按部署重排后的全局面序列取用（总纲：不要场景特殊逻辑，部署重排后自然知道卖谁）；
- 「目标达成」谓词参数化（金额缺口闭合 / 空位达成 / 不溢出），判据件内统一实现；
- 现行各场景的专属资格面处理：跨档止盈与同轮禁卖保留为场景参数；填充牌过滤、凑息身份排除、筹资身份过滤**全部删除**（身份过滤退役，序列天然排序）。

### 3.1 补给选角色（虚拟全局评估形态）

补给选项中的角色 = 按**获取角色流程的评估形态**逐个判定（与商店牌同一逻辑，总纲「补给、商店里的多个角色先自己过一遍逻辑」）：每个候选角色虚拟置入局面 → 升星模拟 → 部署重排 → 统一序列定位——**被虚拟阵容淘汰的（排序末位 = 自己）排除**；不被淘汰的按其虚拟优先级赋值；多个不被淘汰的补给角色，按虚拟优先级选最高。判据出处 = 30 号稿正本随正本更新批修订（三级字典序中间级退役）。

### 4. 锁定瞬间的转型清算（无独立触发）

`write_line_lock` 现行连带动作不变（清商店会话标记、候选快照清空）；旧线成员在后续任何卖出触发的序列中**按序列落位渐进流出**（万金油/羁绊角色未到两星期间居档 6/7 保护期内不流出，其余落档 8 末位）——不新增清算动作、不加标记。换人动作本体仍归部署环节（M1″ 现行）。

### 6. 遥测与观测键

- 新增观测键（键名登记单一源 = 落地批键表）：获取流程的置换成功/拒绝（末位=新牌）、各触发取用的档位分布、随机尾键命中计数；
- 删除观测键：`target_unbuyable`、core_* 出口键族（dismantle 详设清单）；`shop_refresh_blocked_memory_skip` **保留**（金线不足的记忆分支仍在役，跳过计数继续服役——见 dismantle §1）。

## 关键取舍

- **快照纯计算 vs 容器深拷贝**：快照胜（遥测零风险天然成立；MandateFrame 纯数据形态现成；深拷贝的静默失败面不可控）。
- **部署接口 = 结构抽取 vs 判据复制**：抽取（生产路径与虚拟路径消费同一选人核心，防两份判据漂移）；抽取批由现行部署测试守护行为不变。
- **卖旧与买新分帧**（单动作契约）vs 同帧原子：分帧（现行单动作契约不动；置换的中间态由下一帧的买入完成，访内状态切换自然承载）。
- **场景注册表保留 vs 推倒**：保留骨架重写参数（SCENE_SPECS 场景参数化结构仍适用——变化的是资格面与排序源，不是场景框架）。

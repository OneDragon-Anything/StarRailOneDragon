## 0. 术语与对象(首次出现给定义)

- **两文件模型**(retirement.md §4):全局落盘目标 = ①流程侧统一 state 自足快照流
  `state/journal.jsonl` + ②策略侧决策行文件。本文设计②。
- **决策行**:策略侧文件的一行,记录**一个决策帧**(决策循环的一次完整回合:入口观察→
  策略求值→动作计划产出;推进型画面 op 零决策行)。现役 `DecisionTrace`
  dataclass(telemetry/schema.py)是历史 decisions.jsonl 流的行 schema,**生产写端已随
  删除波 1 整体退役**(telemetry/recorder.py 模块头),本类保留作 schema 底稿;
  sim 侧 `sim/runner.py` 仍以同类 schema 写自有 decisions.jsonl(sim 内部测试载体,非
  12 条旧遥测流之一)。
- **四要素**(retirement.md §4,决策行的内容骨架):①state_ref 版本钉 + ②策略自身记忆 +
  ③决策函数关键记录 + ④动作 op。**瘦身判据**:凡统一 state 可算的内容不存。
- **容器**:策略器状态对象 `StrategyState`(strategies/impl/mandate_v1/mandate_state.py;
  历史名 MandateState 为同对象别名)的 `cw4_counters: dict` 字段——策略行为观测计数
  的**写入侧累计器**,由策略求值与执行代码 40+ 写点直接下标累加,一局(局段)冷建、
  局终随 session 销毁。
- **局终聚合**:局终域行载荷 `MatchFinal.cw4_counters`(kernel/cw_game_state.py;
  写口 = `write_match_final`,cw_loop 两收口点现读容器浅拷贝传入)。None = 无策略载体 /
  空 dict = 局内真实零计数,两型可辨。
- **封闭锁**:键全集登记单一源 = 测试仓 `test_cw4_key_closure`(三层:字面键全集对齐 +
  参数化族登记 + 豁免清单反向锁),底稿 = W4 审计交付报告 v3(§2)的逐键枚举。
  **键账口径**(本文沿用):256 字面键 + 16 闭族 80 实例 = 336 键实例,
  另 9 开放域族(域申报、不设实例上界)。
- **四查**(消费判定面,W4 审计 §2.1):①实机判读(复盘渲染)/②sim 红则判据 /
  ③轮差分 / ④预注册披露。
- **金量 / 帧数累计器**:累加金额或帧数而非事件次数的计数键(现役 4 键,其中
  m6_s_reserve_remeet_frames_sum 为帧数累计;见 §3.2)。
- **门簿记账键**:被策略行为**读回**的计数键(不是只写遥测;现役 3 键,见 §3.3)。

## 1. 背景与现态(过渡态的精确定性)

W4 定谳(retirement.md §3):cw4_counters 全部键(336 实例 + 9 开放族)归属 = 两文件
模型②的**策略自身记忆要素**;决策行文件落地前由容器承载;流载体 cw4_counters.jsonl
已退役,局终级全键聚合由局终聚合携带(retirement.md §3 定谳落码形态)。

现态的**可见性载体三分**(过渡态定性;**定谳 C1 = 确认本三分表**):

| 载体 | 角色 | 生命周期 | 是否随本设计终结 |
|---|---|---|---|
| 容器 `StrategyState.cw4_counters` | 写入侧累计器(唯一写点面) | 一局段 | **否,永久保留**——40+ 写点零迁移(落地审已裁),sim 三消费面直读本容器 |
| 局终聚合 `MatchFinal.cw4_counters` | 权威聚合面(局终级全键) | 一局段一行 | **否,永久保留**——行语义不变量下唯一能覆盖「末决策行之后、收口之前」窗口的载体(§5.2 降格主张) |
| 决策行(缺位) | 归因面(帧级窗口增量) | 每决策帧一行 | 本设计补齐的正是这一载体 |

「过渡态」终结的是**判读可见性只有局终一档**这一状态(实机侧无轮级/帧级载体,W4 审计
§2.1③「实机侧无轮级载体……降格在案」),不是容器与局终聚合两个载体本身。

## 2. 总体设计:行五段结构与 schema 演进契约

### 2.1 行结构(四要素阅读格 + 行头)

决策行文件每行 = 一个决策帧,JSONL 追加写,行内字段按**五段**组织。四要素是**阅读格**
(把字段归入要素来理解),不是结构嵌套——行仍是平铺键值,沿用现役 schema 稳定契约
(「新字段末尾追加且可选」,schema.py `DecisionTrace` 类契约):

| 段 | 要素归属 | 字段(现役名沿用) | 本设计处置 |
|---|---|---|---|
| 行头 | —(身份与 join key) | schema_version / ts / run_id / difficulty / plane / round_num / strategy_id / ev_arm | 字段集沿用;**schema_version 取新文件自带独立版本常量**(定谳 C7:初值 1,命名随落地批惯例对齐 `*_SCHEMA_VERSION` 先例,不动 telemetry/schema.py 模块级共用常量,见 §9) |
| 钉 | ① state_ref 版本钉 | state_ref | 沿用(R4 已在产语义;历史档案钉面标记判读见 §8-2) |
| 策略记忆 | ② 策略自身记忆 | **cw4_counters(新增,本设计核心)** + sess_* 披露族(成员封闭清单 = §2.4)+ v2_mode / v2_locked_line / v2_bridge / form_ok / b_t / formed_stop / piggy_reward / xp_expect_ledger / expected_paths / p26_prep_obs / shop_rejects / supply_pick | cw4_counters 新增(§3-§5,**首批发射**);披露族沿用现役字段语义、不改名不搬位,**首批发射不含、按消费需求逐批接线**(定谳 C4,§2.4);其余沿用现役字段语义,不改名不搬位 |
| 决策记录 | ③ 决策函数关键记录 | target_comp / candidate_scores / eval_breakdown / v3_intention / handoff / sess_p1_pair / dp_posture / posture_unfulfilled | 沿用 |
| 动作 | ④ 动作 op | actions(逐项附 reason,归因键序单一源 = ACTION_REASON_SOURCE_KEYS) | 沿用 |
| 退役面 | —(不入新文件) | state(全量快照 dict)/ hp / gold / hp_readable / gold_readable / level_readable / active_strategies / refresh_trigger / form_score / phase | 不发射(§2.3 逐项判据) |

### 2.2 类演进契约与发射契约分离

`DecisionTrace` dataclass 保持**只追加**演进(现役契约不变);新文件的**发射契约**单独
声明:落地批的新写口对每个字段声明「发射 / 不发射」。不发射 ≠ 删类字段——旧数据
(decisions.jsonl 历史档案 + sim 产物)的读取面按缺键容忍(既有惯例),类字段保留缺省值
即兼容。schema 正本 = 类字段集 × 发射契约的笛卡尔中「发射=True 子集」。

## 3. 策略记忆要素:计数键字段族映射(W4 正本核心)

### 3.1 载体形态:单 dict 字段,键名恒等

新增行字段:

```
cw4_counters: dict[str, int] | None = None
```

**映射规则 = 恒等映射**:审计底稿的每个键名(字面键 256 + 16 闭族参数化实例 80 + 9
开放族实例)在新字段中以**同名同值语义**出现,零改名、零翻译层、零按族拆字段。理由:

1. **字面迁移的字面性**:W4 列要求的「策略键→决策行字段」以键名恒等兑现——键名即
   字段内键,审计底稿 §2.2 逐键行直接成为该字段的内容清单,迁移批无键名对照工作。
2. **族结构不进 schema**:16 闭族 / 9 开放族的族登记唯一源 = 封闭锁(已存在)。行
   schema 若按族拆 16+ 个子字段,则族清单出现第二登记(族增员要改 schema),且开放族
   (域不封顶)无法拆字段。单 dict + 键registry 是族演化的零成本形态。
3. **跨载体名一致**:容器字段名 / 局终聚合字段名 / 决策行字段名三者同名,四查消费面
   与复盘渲染(按键名子串三分组,replay_to_md `_render_counters`)在任一载体上按同一
   键名空间工作,无第二命名。

### 3.2 键语义类四分(值语义的判读契约)

dict 值统一为 int,但键按语义分四类(分类唯一源 = 封闭锁registry扩展;行载体不做区分):

| 语义类 | 现役成员 | 增量值语义 | 判读注意 |
|---|---|---|---|
| 事件计数(缺省类) | 336 实例 + 9 开放族的绝大多数 | 带符号差,通常 +1 / +n;单调不减 | 常规频次判读 |
| 金量 / 帧数累计器 | launch_frame_idle_gold / t1_interest_gap_total / t1_interest_sellback_total / m6_s_reserve_remeet_frames_sum | 金额或帧数累加(一窗口内可 ±大值);单调不减 | 读「累计量」不读「次数」;差分语义与事件计数同构 |
| 门簿记账(行为读回) | sphere_defer_streak(可清零)/ sphere_defer_progress_sig(签名快照,覆写)/ sphere_defer_yield(让路帧计数) | streak 清零窗口 = 负差;sig 覆写窗口 = 无意义的差值 | **三键被策略行为读回**(entry.py 门簿比较与清零,§3.3),非只写遥测;sig 键的差分值不作判读量,前缀和还原的**绝对值**才是其语义 |
| (预留) | — | — | 新语义类入封闭锁registry时增行,不改载体 |

### 3.3 行为读回键的声明(禁当纯遥测处置)

`sphere_defer_streak` / `sphere_defer_progress_sig` / `sphere_defer_yield` 三键在
mandate_v1 entry.py 席满搁浅门内被**读回做行为判定**(进度签名相等比较、streak 清零与
续计、让路帧累加)。schema 层面的两个义务:

1. 这三键不得被任何「遥测纯观测、禁决策消费」类守卫误伤(它们是容器上的行为记忆,
   与 `_telemetry_` 前缀披露字段不同类);
2. 判读面读这三键的**行级窗口增量**无意义(负差/签名差),读**前缀和绝对值**才有语义
   (§5.2 恒等式保证前缀和精确还原)。

### 3.4 豁免名单排除声明(七名不入字段)

W4 审计 §2.4 七名**非容器键**不入本字段,归属不变:launch_arbitrage_budget_blocked
(拒因常量串)/ funding_support_stall_convert、funding_hold_liquidated(SellBench
convert_reason 值域成员)/ f7_contingency_armed、depsilon_advisor_violation、
f7_exempt_emission、f7_uncovered_interest_sell(schema.py 判读面键名声明,行为载体 =

同一豁免清单为反查面。

### 3.5 逐族映射表(族 → 字段内键形态)

## 4. 字段类型与语义

```
cw4_counters: dict[str, int] | None
```

- **语义 = 行间窗口增量**(带符号差分):键 → 本行收口窗口内的内容变化量。
- **None** = 无策略载体(无 match 注册 / 离线构造)或发射面未接线(旧读面按缺键读)。
- **空 dict** = 本窗口零变更(显式发射,与 None 可辨——沿用局终聚合 None/{} 分型契约)。
- **键域** = 容器键域的子集(只出现本窗口有变化的键;零差省略,未触键缺席)。
- **值域** = 整数,允许负值(清零键);不允许其它类型(签名快照键也是 int)。
- **浅拷贝边界**:写口对容器只读快照后差分,行内 dict 与容器无共享引用(后写不串;
  与局终聚合写口的浅拷贝声明同纪律)。

## 5. 写入时机与生命周期(含数学契约)

### 5.1 窗口定义与捕获时点

- 决策行写入时点 = **决策帧收口**(策略求值完成、动作计划产出、执行未开始)。求值过程
  自身产生的计数写点落入**本行**窗口(该决策自身行为的归因)。
- 窗口 = (上一决策行收口时点, 本行收口时点];本局段首行窗口起点 = 局段起点(容器冷建,
  空 dict)。跨窗的执行侧写点(部署 held、仲裁、耗尽臂等)归入**其发生后的下一行**窗口。
- 捕获机制:写口持有**锚**(上一行收口时点的容器内容快照,按局段重置);本行收口时点
  现读容器 → 与锚逐键求差 → 发射 → 更新锚。写口不读状态流水(决策输入禁读 journal,
  同纪律的写侧镜像:行内容只来自容器现读与调用方传入)。

### 5.2 数学契约(主张强度与证据匹配)

设局段内决策行收口时点序 t_1 < … < t_n,容器内容函数 C(键→值),C(t_0) = ∅
(t_0 = 局段起点),收口时点 T(局终,≥ t_n)。行 i 载荷 Δ_i[k] = C(t_i)[k] − C(t_{i-1})[k]
(对差非零的 k)。

**恒等式(望远镜和,对所有键精确成立,含清零/覆写键)**:

```
对任意 m ≤ n、任意键 k:Σ_{i=1..m} Δ_i[k] = C(t_m)[k]
```

即:**前缀和精确还原容器在任意行收口时点的内容**——窗口增量载体信息无损,行级累计
快照(可由前缀和算出)按瘦身判据不入行。

**终局对账不等式(仅单调键)**:记单调键集 M = 全键 − {sphere_defer_streak,
sphere_defer_progress_sig}(其余键写点均为 get+inc 累加形态,单调不减)。对 k ∈ M:

```
Σ_{i=1..n} Δ_i[k] = C(t_n)[k] ≤ C(T)[k] = MatchFinal.cw4_counters[k]
```

**单调键集 M 的演化纪律**(对抗审 F-9):「其余键写点均为 get+inc 累加形态」为全称
断言,其机器验证面 = §10-L3 终局对账锁;**新登记键缺省入 M,非单调键(覆写/清零形态)
移出 M 须随封闭锁 registry 申报**——防未来新增键静默破坏 L3 前提。

**残差归属**(定谳 C1,按降格主张落文,不称数学全称证明):C(T) − C(t_n)(逐键)=
末决策行之后、收口之前的窗口写入,无行归属,由局终聚合承载。承载唯一性按以下
**降格主张**陈述:「**行 = 决策帧**」是消费面语义不变量——望远镜恒等式、前缀和还原、
轮差分与归因消费面、「推进型画面 op 零决策行」纪律均以该不变量为前提;
JSONL 追加写约束下存在行内替代方案(局终收口时点追加「尾行」携带残差),但尾行行型
**破坏该不变量**(行不再都是决策帧,上述消费面全部须行类分型)且**代价大于收益**
(局终聚合已是现成权威面,无需再造行类分型);**在此不变量下,局终聚合是 (t_n, T] 窗
唯一承载**——决策行行序止于 t_n,而写点不保证止于 t_n(耗尽臂等收口前写点)。

**局段边界**:锚、行序、前缀和、局终聚合全部以局段为界;恢复局跨段 = 多行多段各自
自洽,无跨段账务耦合(容器每局冷建天然保证)。

### 5.3 体积量化(行膨胀上界;量级论证)

按删除波 1 前生产数据,决策行 ~40-80 行/局。窗口内新增写点典型 0-8 键(键目序列化
~35 字节/键目)→ 行均增量 ≤ 0.3 KB,全局段新增 ~12-25 KB。对照:逐行累计快照形态
行均 ~2 KB × 80 行 ≈ 160 KB(存了前缀和可算的冗余,违反瘦身判据);局终聚合单行全量
展开 ~3.5 KB 不变。结论:增量形态全局开销一个量级小于累计形态,行膨胀不构成设计约束。

> 体积基底为**量级论证**(对抗审 F-10:基底数据无持久索引),落地批以 §10-L2 恒等式
> 锁的实测行数与行宽复核。

### 5.4 生命周期

- **容器**:局段冷建 → 40+ 写点累加 → 收口时点被局终聚合与决策行写口现读 → 局段销毁。
  写点面零迁移(本设计不改任何 `_count`/`_bump`/下标累加写点)。
- **锚**:写口进程内状态,按局段重置(与容器同界);写口无锚(如离线直构)= cw4_counters
  发射 None(诚实缺省,不猜)。
- **文件**:策略侧决策行文件与 journal **按 run 段同批淘汰**(寿命契约耦合,retirement.md
  §6-5;两文件禁单件淘汰)。文件名 / 目录位(**定谳 C2**):`strategy/decision_trace.jsonl`
  ——镜像 `state/journal.jsonl` 布局(两文件模型①②对位);名取自 schema 类名
  `DecisionTrace`(持久索引);**禁复用 decisions.jsonl**(历史档案与 sim 产物以该名为键,
  双载体同名 = 读面歧义)。落地批三面按此名接线:match_archive 切片登记(§7-T1-3)、

# ADR-0423: 战斗过程细节不采集(观测面拒绝决策)

## 背景

战力断层归因的粒度瓶颈:对局判读只能检测到「轮间血量大跌」(如 run_20260827_194456 的 p1r6 71→45 与 p1r9 37→3),但**无法归因到战斗内部**——是敌方词缀强、板面太弱被打穿、还是新机制(贪饕侵蚀:侵蚀怪致死不灭+回血)拖垮了节奏,轮间差分说不出来。

候选采集点盘点(2026-08-27):

| 采集点 | 现状 | 增量成本 |
|---|---|---|
| 敌情预览(备战时节点条敌人类型) | **已采**——W283 情报画面族敌人信息浮层+boss 双域 SIFT 模板建档,state.enemy_affixes/enemy_difficulty/plane_bosses 均已落盘 | 零 |
| 结算结果 | **已采**——killed known/unknown 权威口径(ADR-0306),streak/hp_after 齐 | 零 |
| 战中 HP 序列 | 未采,但 battle_loop 已有 stall 检测采样点(cw_stall)可扩展 | 中 |
| **敌方波次组成**(小怪类型逐只) | **未采**——需战斗中 CV/VLM 数怪分类 | **高且持续** |

## 决策

**不采集战斗过程细节**;同时明确两个层次的区分(用户裁决 2026-08-27):

- **Boss 类型 = 保留的决策输入**:state.plane_bosses / outcome.boss_names 数据通道本就存在,boss 识别(boss 双域 SIFT 模板,W283 建档)稳定可靠——策略侧基于 boss 身份做对策(如针对特定 boss 调整构筑优先级)**属于既有能力,不在拒绝范围内**,且欢迎后续批消费。
- **小怪类型 = 本次拒绝的对象**:理由:

1. **数据量大**:全量逐秒采样会让 shots 目录爆炸(一场战斗数百帧),数据密度难以消费;
2. **不便采集**:战中画面识别噪声大,可靠提取需要持续投入;
3. **机制各异维护吃力**:boss 之外的小怪类型机制各不相同,处理成本与维护负担过重——这是拒绝的核心理由,不是采样技术问题,而是**长期维护经济学**问题;后期有条件了再考虑。

## Considered Options

1. **拒(本决策):全量战斗过程遥测**——见上三条理由。
2. 暂缓(预留升级路径):**断层触发式二次采集**——仅当发生战力断层(轮间血量跌幅超阈值)时,下一场战斗自动加挂详细采样(HP 序列+敌情帧)。性价比形状优于全量,但当下不实施:断层非每局皆有,先立「触发条件」的复杂度不划算;若未来归因需求增强(如引入节点规避类策略),从这条路径重开。
3. 维持现状(事实采纳):结果三元组(hp_after/killed/streak)+备战敌情预览字段已覆盖判读的主干归因需求——这是本决策实际生效的状态。

## Consequences

- 战力断层的归因粒度永久停留在**轮间差分**:能定位「哪一轮输了」,不能定位「输在敌方哪个机制/哪个波次」。判读时遇断层按「板面战力不足 vs 敌方强度异常」两分法处理,不再深挖。
- **Boss 类型决策维度保留开放**:plane_bosses/boss_names 通道持续有效,策略批可以(且欢迎)基于 boss 身份做对策设计;这是与「小怪不采」并列的显式结论,不是附带允许。
- sim Δ池(battle_rung 经验分布)**不做敌方构成维度的条件化**——池保真度维持成型度一维分桶(W285 谱系),已知局限如实接受。
- 若未来出现对敌情精度敏感的策略杠杆(节点规避、enemy-conditioned 出牌等)重开此决策,入口为断层触发式路径(选项 2);**小怪类型识别在后期具备条件时单独再议**(用户裁决原文)。

## 判据与验证

- 判据:用户口述裁决原文(2026-08-27):「战斗过程这个还是不采集了,量很大,而且不方便采集,我们现在只能看到 boss 类型,还能处理小怪类型的话太麻烦了,而且小怪的机制还不一样,这个维护起来太吃力了」。
- 验证:纯文档决策,无代码改动;护栏=运行时任何新增 save_screenshot/OCR 采样不得进入战斗中画面(观测面审查时核对)。

# 遗器筛选弹窗(relic_filter_rule)

> source_image: sr-od-test/screens/遗器筛选弹窗/{背包侧-隧洞列表,背包侧-已勾选,替换侧-默认,替换侧-已勾选}.webp(1080p 四态 fixture)
> 识别模型:assets/game_data/screen_info/relic_filter_rule.yml

## 1. 何时出现

遗器筛选面板点「套装」点击选择条弹出的套装勾选弹窗(居中大弹窗,背景暗化)。两个入口语境:

- 背包侧:「背包-遗器-筛选」面板点套装选择(消费链 SelectBagRelicOp)
- 替换侧:「遗器-替换-筛选」面板点套装选择(消费链 FilterRelicReplaceOp)

结构:标题「筛选规则」+「隧洞遗器/位面饰品」双 TAB + 双列套装行(图标+套装名+点赞数+复选框)+ 底部「全部清除/确认」。

## 2. 单档合并(重要)

背包侧与替换侧的弹窗是**同一游戏组件、像素级同构**(2026-11-23 四帧 fixture 模板互配实证:分数 0.999-1.0、定位同点,弹窗本体零偏移;弹窗内不存在任何可区分文本,弹窗外背景暗化不可读)。历史上按宿主各建一档、id_mark 必然双命中,靠测试豁免 + 消费 op 流程上下文点名消歧;已按用户裁定合并为单档「遗器筛选弹窗」,全局识别在本弹窗态精准命中本档。op 在弹窗内的操作仍用屏名取 area(round_by_find_and_click_area / 区域级 until 锚)——弹窗是流程中间态,进出由消费链上下文与区域锚验证,不经通用导航。

## 3. 行为事实(2026-11-12 摸底帧实证)

- **套装行勾选 = 点行文本中心**;勾选态 = 复选框橙色 ✓ + 行橙边框 + TAB 图标橙色角标
- **重复运行同参数会反选**:行已勾选时盲点 = 取消勾选——**先点「全部清除」清残留勾选再点目标行**(幂等依据;清除范围含套装勾选以实机验证为准)
- 点「确认」后的宿主差异(同一按钮、两种归宿,与确认钮 goto_list 双出口对应):
  - 替换侧:弹窗收起、**筛选面板保持打开**、列表已按筛选刷新
  - 背包侧:弹窗与筛选面板**同时收起**、列表按筛选刷新、漏斗出现「筛选中」角标
- 弹窗记忆 TAB 状态未实测——操作位面套装前显式点「TAB-位面饰品」,操作隧洞套装前显式点「TAB-隧洞遗器」(两 TAB 均已建档,不赌记忆)

## 5. 注意

- 套装列表内容随 TAB 切换,行文本 OCR 找目标套装时先确认在正确 TAB(位面套装在隧洞 TAB 里找不到)
- 「全部清除」只清当前 TAB 的勾选还是双 TAB 全清未实测——需要双 TAB 全清时逐 TAB 各点一次
- 弹窗右缘有滚动条,目标套装不在首屏时先在「区域-套装列表」内拖拽再 OCR 定位
- 列表区下缘 y≈722 起有提示文案「隧洞遗器与位面饰品同时复选后会在对应页签显示」,在「区域-套装列表」rect 之外,不参与套装行扫描

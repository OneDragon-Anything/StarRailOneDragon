# 货币战争 sim 体系设计

> 性质:**设计件(as-designed)**——定义 sim 的架构边界、动作语义契约、检查器体系分类、保真度纪律、复盘通道与守恒不变量;落地偏差 = 缺陷。数值一律不落本文(标定值单一源在代码常量/校准表,契约见各参数行)。
> **双态标注纪律(全文)**:区分「已达成」(有代码/测试载体,可用现在时断言)与「在途」(目标态,显式标注在途批次)。凡未标注的现在时断言均指已达成;标注「目标态/在途」的小节在落地前**不构成对现状的描述**。在途与待办汇总见 §7.2。
> 结构分工(本目录三篇):本文 = 体系总纲;[sim-wiring.md](sim-wiring.md) = GameState 逐字段接线 as-built 底账(字段粒度,每接一个字段改一行);[sim-power-model.md](sim-power-model.md) = 战斗结算层战力模型设计件(单子系统需求定义,ADR-0512)。
> 读者 = 无会话历史的工程师。术语首次出现给定义。

## 0. 术语

| 术语 | 定义 |
|---|---|
| **live** | 实机运行的 bot(operations 逐动作执行 + 遥测落盘) |
| **sim** | P1/P2 模拟器:`sim/engine_p1.py` 的 `simulate_p1` 决策循环,用于离线批量评估策略 |
| **投影** | `kernel/cw_state.py` 的 `simulate(state, action)`:给定状态与动作,返回执行后的状态。live 执行侧与 sim 转移侧共用的状态转移函数 |
| **单一源** | 某语义只有一处权威实现,其他出现处一律调用或引用它 |
| **严格检查器** | 产生 violations / 告警的检查项 |
| **宽松向** | 只写披露键不判罚(violations 恒 0)、阈值软、或触发条件极窄的检查项——漏报是它的默认失败形态 |
| **机会错失** | 目标/核心卡出现在商店面板上却未买(与「有金没花」是两种不同病灶) |
| **sim-only 差异** | sim 存在而 live 无对应物(或行为不同)的语义面,判读时须显式声明不可外推 |
| **归因域** | 一条 sim 指标能唯一归因到策略决策的语义范围 |
| **围栏** | 部署围栏:轮末自动决定「哪些备战件被认可上板」的选择机制,与 live 部署共用 `select_deployments` 单一源 |
| **skip_fence** | 显式动作轮的围栏配对标记:该轮策略已显式给出动作,围栏跳过自动部署、只补残余部署;账本上 skip_fence 标记与显式动作必须恰配对(§6.2 围栏配对不变量) |
| **池指纹** | 牌池快照(构成+参数版本)的哈希标识;指纹不同 = 牌池构成不同,跨批指标**不做换算直接比较(下称「裸串比」)禁用** |
| **幻影再买** | 商店槽已被本轮消费后,策略基于过期牌面对同一槽再次提案买入(引擎以幻影计数披露,账本归零锁辖守) |
| **宝钻** | 游戏内提升部署上限的道具(cap=等级+宝钻数);其 sim 侧参数化通道见 sim-wiring deploy_cap 行 |

指路:板深/净星深/rung/Δ池/coarse 查表等战斗结算与池分层术语,定义在 sim-wiring「羁绊口径分层」节与 sim-power-model §2,本文按引用消费不重定义。

## 1. 架构与边界

### 1.1 sim 的职责

sim 只做一件事:**在 shop 决策面上评估策略 A/B**——同 seed 同输入下,比较两个策略版本在「买/卖/刷新/升级/部署意向」等经济决策上的结果分布差异。它是策略迭代的先导验证器(实机之前发现问题),不是执行层验证器。

### 1.2 归因域限定(硬边界)

- **shop 决策面 = sim 的归因域**:发牌概率、牌池、经济收入、升级 XP、部署意向这些决策输入在 sim 有实体,涉它们的指标可归因到策略。
- **prep 编排域(部署/装备/收球/开箱的逐动作执行)sim 无实体真值源**:这些在 sim 是**结算期代理**(轮末围栏自动部署、装备批量分配、奖励节点以「+1 基础件+事件金」代理),不是逐动作执行;live 是 prep 画面逐动作拖拽+验证。因此:**「某动作在 live 执行层对不对」的结论 sim 给不出**;prep 域的 sim 指标(部署欠载、装备覆盖等)只有记账意义,判读时按各参数的申报面降权。
- **执行成功面 sim 不建模**:sim 假设每个决策必然理想执行(点了就买到、刷了就换牌)。live 的执行失败面(点击落空、浮层竞态、识别失败重试)造成的病灶,sim 只能以结果分布异常间接暴露,不能复现机制——执行面修复的收益也证明不了(sim 修前本来就是理想执行)。

### 1.3 与 live 的对应关系

```
            ┌─ 策略决策层(单一源:live/sim 共用同一套策略代码)─┐
            │                                                    │
   live 侧: 动作执行(op 拖拽/点击 + 执行验证)                    sim 侧: 决策循环(理想执行假设)
            │   ↘ 投影:cw_state.simulate(state, action)  ↙      │
            └────────────── 状态转移单一源(见 §2 硬规则)──────────┘
                     ↙                                    ↘
        live 遥测(telemetry/ 分键)                sim 账本(waves/actions/checks)
                     ↘                                    ↙
                  检查器对账:live 分键 ↔ sim 检查覆盖须显式对账(§3.5)
```

判读外推三档(细则单一源 = `sr-od-currency-war-dev` skill 的 references/sim-testing.md「先知道边界」):**真代码层**(注册表/概率表/牌池/策略本体,可直接信)/ **校准层**(参数注入,带误差,结论带免责)/ **不可外推**(sim-only 差异面,结论禁止外推到 live)。

## 2. 动作语义契约

### 2.1 单一源纪律(硬规则)

**目标态:全部动作的 GameState 字段转移必须经 `kernel/cw_state.simulate` 调用完成;禁止在执行引擎内为 GameState 字段另写一份转移逻辑(下称「内联重实现」)。**

- **现状(如实,ADR-0561 已实施)**:动作 v2 族(SellDeployed/SwapDeploy/CompTransaction)与商店四动作中的 BuyCard/SellBench 已走投影(已达成;防回漂三锁在册,载体 = sr-od-test `test_cw_sim_shop_single_source.py`);LevelUp/RefreshShop 仍引擎内联 = **显式申报保留面**(ADR-0561 决策 2:LevelUp 切源会连带「cap10 + 攒够即升即时升级」双重行为变更,破零漂移门;RefreshShop 的 simulate 分支只扣金不重采样,切源丢免费刷注入/重采样/刷后 break-redecide 三重行为)——保留面放开前置归 LEVEL_CAP 行为变更批(§2.3-3)。涉保留面的 sim 行为判读以 §2.3 申报清单与引擎注释为准;§2.2 表格中已切投影动作的行为 = 现状契约,保留面两动作与契约的差异 = 申报差异,非契约偏离。
- why:历史审计(逐动作 sim/live 对照,方法=同输入下比对 sim 引擎与 simulate 投影的逐字段结果)曾实测 13 条语义分歧,系统性根因即四动作内联双源——同名动作两套代码,每处分歧都要逐点人工对账,且 simulate 修 bug 时 sim 侧不自动跟。
- **可判定边界(什么叫违规)**:投影辖「GameState 字段转移」(金/池/bench/deployed/XP 等字段怎么变);引擎辖「账本转录 + 投影 deepcopy 域外对象」——simulate 返回 deepcopy 后引用不跨界(`engine_p1.py` v2 路径头注自证),因此引擎在调用投影后补做的**池登记(ret/take)、买入 XP 转录、金出入转录不属于内联重实现**,列为显式白名单;理由=deepcopy 所迫,且这些对象不随 GameState 投影。白名单之外,引擎代码直接改写 GameState 字段以实现动作语义即违规。
- 伴随纪律:**逐动作语义对拍**——已切投影动作(BuyCard/SellBench)由 ADR-0561 防回漂三锁承载(锁1 spy 结构锁:执行必经 `_simulate_state`;锁2 桩行为锁:带装卖出装备回池;锁3 grep 锁:禁内联特征式回潜;载体 = sr-od-test `test_cw_sim_shop_single_source.py`);**sim-only 白名单数据结构仍未建**(§7.2 待办),建成前白名单面 = §2.3 申报清单文档承载;建成后白名单外出现 diff = 缺陷。

## 3. 检查器体系分类

sim 检查器(`sim/checks/`,注册表在 `checks/runner.py`)按**回答什么问题**分四类。新检查器必须先归入一类再实现;归不进任何一类的,先质疑该不该存在。

### 3.1 一致性类(账本守恒)

回答:「sim 自己有没有算错」。账本金守恒、资产守恒(§6)、schema 形状、不变量违反、观测键面完整。现状主体,要求:**全部严格方向**(守恒类检查器宽松=失明,见 §3.5)。

### 3.2 机会错失类(设计已定,载体在途,§7.2)

回答:「策略该买的买了没有」。历史审计实锤:此类在全体系中不存在——最接近的只有「有金没花」族(金溢余零花费判据),不判「目标/核心卡出现在面板上却没买」;两者是不同病灶(前者是花钱纪律,后者是目标识别/优先级错误)。

- **原料(全部在案)**:波账本 `waves[]` 的拒因串(rejects)、引擎的面板-买入对账集合、商店费用分布。
- **设计要点**:①判红键=目标线核心件在售帧被拒或未买(与核心件名册 join);②豁免显式化:金不足/席满拦截/成型停手是合法拒因,豁免链须逐条可对账,禁无条件放行;③同时清理同类死代码(定义后零调用的面板枚举函数)——留下会被误以为有消费方。

### 3.3 决策质量类(规划)

回答:「当时有没有更好的候选」。逐帧对照候选配方、逐动作 EV 复算对照(账本原料:升级授权快照、买入渠道/理由字段)。规划项,落地前置=EV 上界复算有独立载体(禁与决策器共用同一函数自证,防同义反复)。

### 3.4 保真/校准类

回答:「sim 分布对不对得上 live」。校准漂移哨兵(金分布对拍、末金锚比值、商店费用曲线披露)归本类——它们既不判 sim 算错、也不判策略,判的是模型保真度漂移;与 §4 标定流程互为表里(哨兵报警=复测触发,§4.2)。**边界声明**:报告措辞纪律类检查(A/B 结论叙述辖,如白名单外方向性 claim 判罚)物理驻留 `checks/` 但**语义归批报告层纪律**,不属于 sim 检查器四类辖域——它检查的对象是产出的叙述,不是 sim 或策略本身。

### 3.5 判定方向纪律与覆盖对账

- **方向声明强制**:每个检查器 docstring 必须声明方向(严格/宽松向)与判罚条件;纯披露项(不判)必须在批报告层显式标「无判据」,不许以「绿」的形态出现在结论里。
- **宽松向漏报风险(历史教训)**:一次检查器审计发现一族近期新增检查器「近似全宽松向」——纯披露恒 0、小样本不判、锚取当前交付值(语义降级为漂移哨兵)、多处近似全指向少报、一处逐帧计数后硬编码返回 0 违规。教训固化为规则:①宽松向项必须有**升格触发条件**(什么落地后转严格),落 docstring;②「判据暂时不判」与「判了且绿」在报告里形态必须可区分;③新增检查器批次做**方向自检**,采用登记制:在检查器注册表批注字段登记本批严格/宽松向分布,纯宽松向批必须附逐项升格时间表——**不设统一比例数值线**(无依据的阈值=假精确)。
- **升格复核机制**:升格触发条件除落 docstring 外,登记进检查器注册表结构化字段,批报告层扫描「升格条件已满足仍宽松向」的项作事前拦截(载体待办,§7.2)。
- **live 遥测分键对应要求**:live 遥测每新增一个分键面(计划-执行偏差、卖出证据、投资牌、金分渠道、双源观测冲突等),须显式裁决 sim 侧:**补对应检查器** 或 **显式豁免声明**(豁免理由=归因域外或 sim 天然无此偏差面,写进本节并给复核条件)。未裁决的覆盖洞 = 缺陷;既有覆盖洞清单见检查器审计登记,逐个走「补/豁免」收敛。
- **n 地板显式化**:小样本不判的项,其样本量下限用命名常量(单一源在代码),并在报告披露当前 n 与地板差值——「n 不够所以没判」必须可见。

## 4. 保真度要求与标定流程

### 4.1 保真度参数账

每个校准层参数(§1.3 分档)必须登记四项:权威源、标定流程、过期判据、当前申报面。登记底账随代码头注维护,本文只锁纪律与流程:

### 4.2 标定流程纪律

1. **权威源优先序**:live 实测 > 代码注册表 > sim 自身。**sim 自身分布不得作为校准靶**(循环论证);锚取「当前交付值」即语义降级,必须显式声明降级并另立真值锚计划。
2. **校准值只落代码**:常量名是文档唯一合法引用形态;标定过程、实测数字、复测结论归校准报告(落批产物目录),不进本文与接线表正文。
3. **复测周期与触发**(无日历驱动):① **live 行为变更/执行面修复落地**——感知主体与通道 = `sim-wiring.md` as-built 接线底账:改动执行面/行为语义的批次必须同步更新接线表(文档三同步),**接线表更新动作即触发受影响参数复测**,责任落点=改行为的人;只改代码不更新接线表=三同步违规,改了接线表不触发复测=本条违规。② 注册表/游戏版本更新后必复测其辖域参数(信号=注册表生成器重跑)。③ 漂移哨兵(如末金锚比值)报警即触发复测。复测最小规格:n≥40 的多帧批对拍金分布对拍项 + 末金分布 vs 实机近期局。
4. **校准层结论免责**:校准层参数辖域内的 A/B 结论,报告必须带「校准层,带误差」标注(分档依据=sim-testing 边界节)。
5. **降级期结论可用性口径**:锚降级(锚=当前交付值)期间——降级哨兵辖域内**禁出绝对值结论**(锚已无独立真值语义);同批内 A/B 相对比较仍可用(同批共享同一基准);跨批绝对值比较禁用。降级态是现实而非假设(末金锚现状即降级态,见 sim-wiring「已知接线缺口的影响面」节)。

## 5. 复盘通道(异常局自动深度复盘)

### 5.1 触发标准

**状态:设计件(载体在途)**——批末复盘钩子尚未落地(sim/runner.py 无此
钩子;现有人工先例 = P35 局回放脚本 `replay/p35_replay_p2handoff.py`,

sim 批 runner 在批末对满足任一判据的局触发复盘包生成:

1. **低血败局**:终局 HP 高位带却败局(暴露结算/策略错位候选);
2. **未成型局**:局末意向达成度低于设计预期(候选:目标识别失败/经济链断裂);
3. **检查器违规局**:任一严格检查器产生 violations 的局;
4. **统计离群局**:批级统计的极端分位局(空转轮占比 p90 以上、幻影再买>0 等——判据键随批统计面演进,以批统计脚本的分位面为准)。

### 5.2 产出物(复盘包,四件不可缺一)

1. **重放三元**:seed + 池指纹 + 重放命令行(`cw_sim replay` 语义,缺一不可——sim-testing 边界节的重放契约);
2. **决策预摘录**:该局 decisions 账本的 rounds/economy 视图直查摘录;
3. **复盘骨架**:按单局复盘协议(skill references/match-review.md)裁剪——该协议为实机局设计,sim 局无画面/节点序列面,骨架裁剪为「逐轮决策对拍」节;
4. **归因链入口**:该局命中的触发判据 + 关联检查器 violations 原文。

### 5.3 载体与先例

- 载体:批 runner 批末钩子 + 独立复盘脚本(消费批目录,模式仿批统计脚本);单局人工回放已有先例脚本(`replay/p35_replay_p2handoff.py`),通道设计=把历史上人工执行的「挑最差局+决策账本直读+归因链」流程脚本化。

## 6. 双源禁令与守恒不变量

### 6.1 双源禁令

§2.1 单一源硬规则在不变量层面的表述:**同一动作语义在代码里只允许一个转移实现**。违例形态包括:引擎内联重实现(历史 P0 根因)、检查器自带一份「应当如此」的转移复算而不调权威源、文档描述与代码常量双源(数值只写常量名的纪律即为此设)。

### 6.2 守恒不变量清单

以下不变量违反 = sim 缺陷(不是噪声、不是可豁免近似),各自由对应检查器辖守:

| 不变量 | 语义 | 辖守(符号) |
|---|---|---|
| **C6 装备资产守恒** | `equips` 多重集:装备只会经发放获得、经卖出/合成转移,不凭空生灭;卖出必回收(`equips.extend(sold.equips)`) | `check_ledger_consistency` 族 + EquipsLedger 对账 |
| 金守恒(行内+链式) | 逐笔金账 `gold_before/after` 恒等;跨行链式金恒等 | `check_ledger_consistency` / `seg_check_gold_identity` |
| 金非负 / HP 上界 | `gold ≥ 0`(轮末口径);`hp ≤ 100` | `check_gold_nonneg_invariant` / `check_hp_upper_bound_truth` |
| 备战席容量 | bench ≤ 容量常量 | `check_bench_capacity_invariant` |
| 池构成 | 4/5 费不入池(硬断言,非检查) | `check_sim_pool_no_cost_truncation` |
| 商店槽消费 | 波内同名买入 ≤ 供给槽位 | `check_shop_slot_consumption` |
| 围栏配对 | skip_fence 与显式动作恰配对 | `check_skip_fence_pairing` |
| 动作原子性 | 显式动作后 board 一致、拒绝必带 reason | `check_comp_tx_atomicity` |

**对账门完备性要求**:部分守恒对账门(如 EquipsLedger)只在走 simulate 投影路径时生效——因此任何绕开投影的引擎自有路径(历史 P0 之前的内联块形态)同时破坏「不变量有对账门」这一性质;引擎侧若因性能等原因保留自有路径,必须自带等价对账,否则即双源+失守双缺陷。

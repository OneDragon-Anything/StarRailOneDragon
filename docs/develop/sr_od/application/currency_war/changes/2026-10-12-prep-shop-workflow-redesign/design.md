## 1. 问题与动机

### 1.1 现状症状

1. **备战动作优先序与用户打法错位**。晶矿在席位满时单探针确认后即放弃（`entry.py` 晶矿让路段，`ORE_DEFER_PROBE_K = 1`）；部署排在逛店之前（买了立即上阵）；工具消费排位过早；升级动作被多层闸推迟。用户给出的目标工序（用户裁定 2026-10-12）：消耗品最先、晶矿席满时卖 1 个腾位必拿、升级在逛店前、商店按节点一次处理、部署在逛店后、工具靠后、出战兜底。
2. **血本位局买经验截断成部分购买**。机理 = 逐帧单击发射形态（`cw_prep_level_up_action.py`）× 静态全量阈值逐帧重闸：血支付过程中血量跌回阈值之下即停止发射，留下部分级（`kernel/cw_economy.py::blood_xp_gate` 本体为全量击数口径，非截断源）。违反整买纪律（user_playstyle [41]：「需要升级的时候一次买齐，零散买 XP 完全无效益」）。用户裁定 2026-10-12：付不起整级就一击不买；修法 = 整级预授权 + 实付上界。
3. **升级判据主轴偏离**。现行存在多层外围拦截（调度守息门、全段式支出预算闸、危险顾问延迟、血线地板解锁），主轴被稀释。用户裁定 2026-10-12：升级主判据 = 目标核心费用档的刷新概率账（user_playstyle [3]/[7]），一次买齐；拦截层删除（已证保底语义的处置见 line_and_upgrade §2.3，逐件列名）。
4. **卖出语义缺位**。卖出候选池只有备战席（场上凑人数垫件遗漏——部署逻辑会让无关角色上阵占位，用户裁定 2026-10-12 卖出候选应含场上）；卖出无「价值比较」语义。用户裁定：店内席满买入 = 商店里新角色的价值与手上已有角色的价值比较，值得换才换。
5. **换线体系散装**。现行 12 号篇的换线机器（θ 滞回、D_min 驻留、证伪记忆分桶、换线第四触发、P84 可达性门、塌缩卖出通道）是多组件拼盘。用户裁定 2026-10-12：应为一个**统一的选线函数**——计算应选哪个最终阵容，算出新的就更换目标；贯穿件是强信号之一（非一票定音）。被替代物按组件逐项列名于 line_and_upgrade。
6. **节点变动无显式重置点**。节点作用域的策略状态（商店处理标记、尝试计数等）靠键失配隐式失效，无统一边界处理。用户裁定 2026-10-12：识别到节点变动时，策略层应显式更新相关标识。
7. **溢出告警死局出口违反自动化原则**。现行溢出告警强收窄为单笔卖出，若候选空则停摆。用户裁定 2026-10-12：策略工序不允许「停下来等人」的出口；卖出候选耗尽时按损失递增阶梯逐级下探（含目标件），必然可解。
8. **文档黑话密集**。strategy-docs 正本大量使用无定义自造词（用户裁定 2026-10-12：编号引用如 M1/P40 可保留，其余自造词改正常表述或首次出现给定义）。

### 1.2 根因归层

- **语义层**（主因）：判据主次颠倒（升级主轴、卖出语义、方向语义）；两域动作的时序语义（部署/升级/凑息相对商店的位置）未按用户打法组织。
- **流程层**：备战工序的优先级序错位；血本位升级的发射形态机理（逐帧单击 × 静态阈值逐帧重闸，症状 2 的机理层）；节点重置缺位（症状 6 = 节点作用域状态键无统一重置的流程缺口）；溢出死局（症状 7 = 卖出语义 + 流程序双层）。
- **表示层**：腾位、卖出、方向三块各自散装多组件，无统一原语（信息表示分散，同族判断多处各写一份）；文档黑话密集无定义（症状 8 的表示面）。

### 1.3 解决到哪 / 明确不解决

- **解决**：上述 1-7 全部。载体面 = 策略层 `strategies/impl/mandate_v1/`、kernel 状态键，**以及店内动作的执行链接线**（`operations/` 商店执行环境补执行端口——现行商店域执行环境无执行器端口，卖备战/买经验在店内发射会失败；as-built 依据 = `screens/README.md` §5.4「商店域执行链未接线」）；8 在末阶段正本更新时一并执行。
- **明确不解决**：
  - 流程层画面**编排语义**不动：刷新维持「访问终结」（op 结束→外循环重识别→商店 op 重新入口观察，规范出处 = strategy-docs/11 §3 决策规则 4 与 02 §7「循环内零读屏」）；开店/关店动作链不变。**例外 = 上述执行端口扩展**（动作执行基础设施，非编排语义）。
  - 画面识别与建档不动（例外：商店画面档备战栏/出售区 area 增补 = 落地执行链批）（商店画面能力面已由实机归档帧确认，见 details/shop_session.md §1）。
  - 装备策略内容不动（用户裁定 2026-10-12：装备穿戴保留完整版现行实现——合成规划/分配/转移/工具判据照旧，仅其在工序中的调用位置移动）。
  - sim 基建不改（只消费：批跑 CLI 已随 sim-redesign 删除且无当期替代，strategy-work §4 在案——基线/对照批以 SimBackend 库驱动自建脚本实现，最小规格见 landing.md §3.0）。
  - 数学证明件不重推（选线函数的概率输入消费既有 P40 期望模型与注册表概率表）。

## 2. 方案

### 2.1 系统级变化（读一遍知全貌）

1. **备战画面 = 第 0-8 步九段全扫工序**：每次回到备战画面从第 0 步向下扫描，执行第一个满足条件的动作后重新扫描。顺序：溢出自救 → 点消耗品 → 晶矿 → 升级检查 → 商店会话 → 部署调整 → 装备与工具 → 节末凑息 → 出战。载体 = `entry.py::emit` 重写。
2. **商店画面 = 一节点一会话**：本节点未处理时进入会话；会话内循环「方向评估 → 前置升级检查 → 买牌（席满走置换账；含筹资伴生卖出）→ 刷新判据 → 收工」；正常收工打「本节点已处理」标记并记「未消费机会清单」；清单被后续正常事件（部署腾席、资产变现）解拦时清标记重开。**店内卖备战席与店内购买经验的启用，前置依赖执行链接线批**（landing §3.5）。
3. **卖出统一为「价值让位」语义**：一个卖出候选评估器服务全部卖出场景（告警自救/晶矿腾位/店内置换/筹资/升级变现/节末凑息/部署换血/C1 恒买腾位，八场景——「七个场景」均为本表误计，以此为准），候选池构成按场景定义（契约 D 唯一定义处：七个场景——七个备战席候选场景仅备战席 + 部署换血场景含场上），按持有价值升序让位；店内场景（席满买入）额外过置换账（value(X) > value(Y) 同口径直比——摩擦已含 value 各项，无独立摩擦项，shop_session §3 统一口径）。
4. **升级判据重轴**：主判据 = 目标阵容缺件在当前等级与升一级后的刷新期望比较（消费 P40 期望模型）；人口位触发并列保留；一次买齐整级；硬闸保留 = 等级帽、血本位支付检查（整级预授权 + 实付上界）、P21 血预算线（已证负 EV 约束，出处 = proofs P21 与 04 号篇）；删除 = 调度守息门、全段式支出预算闸（其保底 floor 语义保留，见 line_and_upgrade §2.3）、危险顾问延迟、血线地板解锁。
5. **统一选线函数**：加权评分（完成度/获取前景/专属资产/环境四维）输出「未定型」或「目标线」；贯穿件为强信号之一；换目标过「切换成本 + 滞后余量」账防摇摆；评估以方向签名前置段形式挂在备战与商店两个决策入口（签名 = 证据源拼接，变了才重算）。**标定前缺省 = 恒未定型（search 态买牌，含终局件囤货——囤终局卡为后续锁线准备；丢掉的只是锁定单一名单的 focus 态，随标定打开）**。术语定义（两态候选集的实态 = shop_session §2.2 序 1 收编，单一口径）：search 态 = 未定型期按实态候选集（三源；终局核心囤货由 C1 未锁恒买腿独立承载——单一辖属）买牌；focus 态 = 定型后按名单买牌。
6. **节点边界重置**：策略入口检测到节点号变化时，显式重置节点作用域状态键（见 prep_pipeline §3）。
7. **溢出自救**：告警在场 = 自救动作序（上阵安置 → 点消耗品 → 卖出，免费手段在前有损在后），每帧全量重评。（术语注：**fail 方向** = 判据未验证或输入缺失时缺省行为取保守侧的约定——保守侧 = 不产生新行为约束/不花钱/不上阵新单位的方向。**收编** = 现有判据并入新统一入口的申报术语；**承继** = 退役清单逐项处置的申报术语；**让位** = 按价值序卖出；**告警帧冻结条款** = 溢出告警在场时工序其余步骤不执行。）**自救扩展面为真全量**：P78-4 全通道禁卖（registry 核心/④转线件/种子）在自救场景豁免——按价值序末位可卖（用户裁定「卖了目标件之后反而能取胜」「零停机出口」优先于硬资格；豁免行登记通道对价段）。场上候选不设（告警帧动作收窄互斥）；候选空仅在全占席道具帧可达，由点消耗品出路承接。**防御性分支声明**：真全量可卖下候选空结构性不可达；若仍到达 = 识别异常交外循环轮转（工程层事实暴露，非策略「等待」语义——与「无策略性停机出口」不冲突：全量可卖下该分支不可达）。
8. **策略层无试错计数（用户裁定 2026-10-12「计数器治标不治本」）**：全部工序判据为每帧全量重评的纯判断（如晶矿腾位 = 腾位候选是否纯垫件的结构判断，散件卖尽自然停止）；动作未生效归执行层落地验证，识别异常归外循环环级守卫，不进策略判据。

### 2.2 详设划分与跨详设接口契约

| 详设 | 范围 |
|---|---|
| prep_pipeline | 备战第 0-8 步九段逐条判据、溢出自救、节点边界重置 |
| shop_session | 会话模型、买入序、置换账、筹资、刷新、节末凑息、重开触发 |
| line_and_upgrade | 选线函数、升级判据、方向签名 |

**跨详设接口契约（唯一必须在总纲定死的深度内容）**：

- **契约 A（prep_pipeline ↔ shop_session：商店会话的进出）**
  - 备战工序第 4 步是备战侧开店意图的**唯一来源**；商店画面的实际进入有两条路径：① 第 4 步输出开店动作；② **游戏侧自动开店**（战斗结算/选卡类画面处理完后游戏自动弹出商店，实机在产，出处 = screen_flow_timing #14/#29；**辖域注**：boss 简报后商店不开 = as-built 在案事实（screens/README §5.1、boss_briefing.md 注①），口述 #14 的「boss 简报关闭后自动开店」一支被 as-built 废除（其余触发源与 #29 在产）——boss 简报帧不属路径②触发面）——路径②下外循环直接进入商店画面 op，op 入口行为 = 检查 `shop_handled` 标记：未处理 → 正常会话；已处理 → 立即关店收工（同节点牌面未变，无新信息）。两条路径进入的是同一会话语义，`CwActionCloseShopParam` 为会话终结，终结时置标记（session 固定键名 `shop_handled`，**值** = 最后处理的节点号二元组）并写「未消费机会清单」。
  - 标记与清单的读写、**解拦复核判定函数**的唯一所有者 = shop_session 详设定义的模块族（判定逻辑落 mandate_v1 criteria 族共用模块——备战第 4 步与商店入口两画面消费同一函数〔宪法第 6 条，非画面文件互 import〕；存储 = 策略器状态基建模块，landing 3.1/3.6 分工）；备战工序消费标记与复核结论。标记/清单载体 = 策略器私有状态键（StrategyState/MandateState，归属口径与 flow/session.md 一致）。
    - **重开触发统一化**：清单解拦复核的唯一触发点 = 备战工序第 4 步入口（每次全扫到达本步时调用复核判定：金位变化 / 席位空出，任一使清单中拦因解除 → 清标记重开；**方向变更不走清单解拦**——挂起目标提升为生效目标时直接清标记，下一轮按新名单重开会话全量评估，见契约 B）。不在部署、卖出等动作后单独挂触发钩子。节点边界重置对该标记 = 清值（契约 C）。
  - **受限商店访问豁免**：出战发射帧的受限商店访问（P70 发射帧仲裁授权的溢出段消费，机制出处 = `cw_launch_arbitrage.py` 与 prep 第 8 步前置位）**不受会话标记辖**——授权访问帧进入商店执行授权消费，不触发「已处理即关店」。豁免帧判别 = `bridge.launch_restricted_session_active` 现算谓词（现行每帧实算，无授权帧记录存储——载体如实申报）。除此之外 op 入口行为照下行条款。第 4 步 = **常规**开店意图唯一来源；受限访问帧的开店由 P70 仲裁直接驱动（豁免，非常规来源）。
  - 现行「备战期开店闩」（`cw4_shopped_phase`，同备战期吞第二次开店提案）退役——**时点 = 落地 3.6 批**（过渡期 3.3-3.6 之间闩保留：第 4 步标记判定激活但标记写端未诞生，闩防开店活锁；3.6 交付收工写端后闩退役）。防活锁职责由会话标记承接（标记只在正常收工时写入）；退役登记 = shop_session §5 承继清单。读数开商店第二形态随腾席链废止退役（其唯一消费场景已消失，shop_session §5）。
- **契约 E（买入策略统一入口）**
  - 买牌策略是**全局统一组件**（用户裁定 2026-10-12「应该是统一的买牌策略……只是有优先级」）：类目与优先级序 = 目标阵容件 → 场况插件 → 通用插件 → 压库件 → 凑星件 → 纯冗余停买（核心卡支配支与 dominance_buy 结算线口径段 = 邻位通道，位次 = 纯冗余停买判定之后——详设 §2.2 第 7 条与 §5 dominance 行单一口径，相对序 = C1 先、dominance 段后），判据本体单一源 = 现行 11 §1 六序收编，未定型/定型两态只变化序 1 的名单来源（search 态候选集 / focus 态名单）。
  - 商店会话是买入策略的**执行画面**（买牌动作只发生在商店画面），不是买牌判据的所有者；备战域不买牌（无商店面）。价值评估（契约 D）与买入策略分别管「卖出让位序」与「买入优先序」，共同消费同一方向状态（契约 B）。
- **契约 B（line_and_upgrade ↔ 两域：方向状态）**
  - 方向状态 = 策略器私有状态上的方向状态**两槽**（生效目标 + 挂起目标，载体 = comp 对象；两槽语义与提升时序 = line_and_upgrade §1.3/§3）+ 证据签名（字符串）。读写唯一所有者 = line_and_upgrade 提供的两个函数：`refresh_line_if_needed(gs)`（签名比对，变了重算）与 `line_members_view()`（当前方向下的目标名单视图，恒读生效槽）。
  - 备战工序（部署/凑息/自救）与商店会话（买入序/置换账）消费同一视图，禁各自维护第二份名单口径。
- **契约 C（节点边界重置：键清单唯一所有者）**
  - 节点作用域状态键的清点与重置逻辑唯一所有者 = prep_pipeline 的「节点边界处理」函数；shop_session 与 line_and_upgrade 把自己需要节点级重置的键登记进该函数的清单。触发点 = 策略决策入口检测到节点号（位面+轮次）变化。
- **契约 D（卖出候选评估器：单一入口）**

# 0003. 矩形/卡牌阵列用 squares 几何检测(免疫颜色变化)

- **Status**: accepted
- **Date**: 2026-08-04

## Context

带边框 / 底色对比的图标阵列 / 卡牌(角色卡 / 头像框 / 装备槽 / 商店牌)是程序绘制的简单几何
形(矩形 / 圆角矩形),边缘锐利。硬编码坐标(单张截图推断)脆弱:不适配滚动、易截断
(猜浅砍底 / 猜高切顶)。需选一种鲁棒的 CV 定位法。

实测某 auto-chess 角色图鉴卡牌阵列(7 列 × 3 行,费用分色:蓝=1费 → 金=5费,滚 4 屏)对拍
vision grounding GT,8 法对比(2026-08-04,统一后处理):

| 方法 | 结果 | 说明 |
|---|---|---|
| **squares**(多阈值 `threshold` 扫 40~220 + `approxPolyDP` 4 顶点 + `isContourConvex` + 面积/比例) | **21/21** | 判几何不判颜色,最鲁棒 |
| 单亮度阈值 >110 **+ 填洞**(`drawContours FILLED`) | 21/21 | 不填洞只 20/21 |
| Canny 边缘 / MSER | 20/21 | 次优 |
| 自适应阈值 / 饱和度(S+V)/ HSV 逐费用色并集 | 0/21 | 失败 |
| kmeans 背景互补 | 11/21 | 把常见卡色误判成背景 |

关键发现:
- **判别量是亮度 V**(卡间背景暗、卡牌任意费用色都更亮);不是饱和度(背景是饱和暗紫)。
- 卡牌**费用分色**→ 颜色阈值法在某费用卡(深色立绘那档)上漏检 → **几何法(squares)免疫**。
- 曾误判「费用色致单阈值失效」,真因是**没填洞**:卡的亮边框成环、内部深色立绘是洞 → 不填洞
  环碎裂被面积过滤 → 漏检。

## Decision Drivers

- **颜色鲁棒**:游戏元素颜色常随等级 / 星级 / 费用 / 稀有度变(低阶冷色 → 高阶暖色);法应挑
  **不随该属性变的恒定特征**。
- **可移植**:硬编码坐标不适配滚动 / 不同内容。
- **实测驱动**:8 法量化对比,非凭感觉。

## Considered Options

1. **squares 几何检测(多阈值 + 4 顶点)**:判几何不判颜色 → 免疫颜色变化,最鲁棒(选中)。
2. **单亮度阈值 + 填洞**:卡牌内部亮度均匀且判别量是 V 时简单好用;但颜色变化更脆,需先确认
   目标颜色不随属性变。次选。
3. **HSV 颜色 inRange / kmeans 背景互补**:颜色随属性变时脆;kmeans 簇数 / 背景定位不稳时把
   元素色误判成背景 → 大面积漏检。慎用。
4. **硬编码坐标**:单张截图推断,不适配滚动 / 易截断。不选。

## Decision

选 1:squares 几何检测(多阈值扫描 + `approxPolyDP` 4 顶点 + `isContourConvex` + 面积 / 长宽比
过滤)作**首选**;单阈值 + 填洞是更简单的次选;kmeans 背景互补慎用。判据写进 `../../SKILL.md`
「CV 路径二:形状轮廓检测」。颜色随属性变时优先几何(形状)而非颜色阈值。

## Consequences

- **正向**:跨颜色变化 / 跨屏最稳;不依赖具体颜色,可移植;副产品:每个检测出的元素是独立
  区域 → 标签与模板同源(消除行×列错标)。
- **负向**:多阈值扫描有计算成本;圆角 / 抗锯齿致 >4 顶点时需先 `drawContours FILLED` 填实再判
  (多一步)。
- **follow-up**:阈值 / 填洞是阈值法的关键后处理,SKILL.md 已记(漏检先查是不是没填洞,别急
  着归咎颜色变化)。

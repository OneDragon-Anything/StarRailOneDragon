### [R9-2] major | design.md §2.3(「路由屏取值」vs「绕行路径无害性」两定义互相矛盾;挂点辖域两读) | 未识别/未知兜底帧「清全部十槽」与「绕过挂点本轮不清」不可同真,插入点句无法消歧,其一读法破 §2.3 效果申报且 3.1 判据拦不住

**发现内容**:§2.3 三个定义组合后自相矛盾——①「插入点 = 画面识别结果产出后、`cw_loop.py::_dispatch_identity_screen` 调用之前」:该位置在代码里是 `:1818`(识别)与 `:1821`(分发)之间,是**每轮必经的无条件位**(未识别时 `_match_name=None` 同样先流经此处,再落阶段三 :1823+/阶段二 :1861+/循环尾未知兜底 `_handle_unknown_fallback` :2095-2125);②「路由屏取值」规定「非身份臂语境(阶段二备战双锚、阶段三特殊规则臂)/未识别 = 清全部十槽」——要执行这句,挂点必须在无条件位上运行;③「绕行路径无害性」却写「**未知兜底停机绕过挂点——本轮不清、下轮路由补清**」——未知兜底帧恰是未识别帧,按②它在本轮已清,按③它本轮不清:**②与③对同一批轮次给出相反的机制陈述,且按①的插入点③为假**。若实现者按③反推「挂点放在分发分支内(仅 `_match_name` 非 None 时运行)」以自圆其说,则②的「非身份臂语境/未识别 = 清全部十槽」永不执行——overlay 消失后的整个备战阶段(最常见态)十槽保持陈旧非 None,**直接破 §2.3「效果」申报的「dump gs 审计面无陈旧非 None 槽」**;而 landing 3.1 完成判据(「10 个被清槽的属屏映射与 §2.3 表逐行一致/豁免在位/已 None 跳过单测/路由清点剧本单测」)没有任何一条钉死挂点的**调用辖域**(无条件位 vs 分支内),两种实现都能判过——阶段可验收性缺口。硬规则 1(自相矛盾的等价性论证即攻击目标)+ 硬规则 2(实现者撞上二义需再设计)。

**修正方向**:一句话定死辖域并消矛盾——建议:明确「挂点无条件位于 :1818 识别产出与 :1821 分发之间,未识别(含未知兜底帧)一律清全部十槽」,并把「绕行路径无害性」中「未知兜底停机绕过挂点——本轮不清」改为「未知兜底帧经挂点按未识别取值清全部十槽(无 decide 消费,仅审计行)」(stop_at_prep 早退是唯一真绕行,保留原表述);3.1 完成判据补一条「未识别轮清全部十槽」的剧本断言,使辖域可验收。

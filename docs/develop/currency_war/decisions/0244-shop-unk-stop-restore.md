# ADR-0244 shop 未识别卡恢复停机留证(撤销 r34 降级)

## Status

accepted(2026-08-24;用户裁决「shop 未识别不能降级,恢复回来」;撤销 r34)

## Context

r34 把「商店未识别卡 → 停机留画面建档」(方案 D)降级为「warning+截图留证不停机」,理由:原停机连续两局阻断实跑,主开发不在场时纯阻断。该降级自 hook 审计(2.8)起挂「待用户确认」——有证据结论但用户点头记录缺失,skill 双条件缺一。

2026-08-24 用户裁决:**不能降级,恢复停机**。降级的隐性代价大于阻断:未识别卡按非 target 跳过 = 带病跑——新版本新卡/昔涟诗篇类内容的建档窗口被错过,且买牌决策在残缺牌面上做。阻断是显性代价(一局停机),错过建档是隐性代价(识别盲区长期存活),用户明示接受前者、拒绝后者。

## Considered Options

1. 维持 r34 降级(留证不停机):实跑连续性好,但建档窗口依赖离线补做,新内容识别盲区在实机持续存在——用户否决。
2. **恢复停机留证(选)**:防抖重读 2 帧后仍 miss → 截图+flag(三要素)+stop_running+round_fail 保画面;接管者按 flag 处理步骤建档。
3. 折中(首次停机/重复降级):状态机复杂化,r34 的教训正是这类折中在自主跑长局里不可靠;停机语义要单一。

## Decision

选 2。`operations/prep/shop.py buy` 未识别分支恢复方案 D:截图(prefix=shop_unk_slotN)+ flag 三要素(`.debug/temp/currency_war/shop_unk.flag`:[HOOK-STOP] 头/触发/处理步骤/删除条件)+ `[cw!]` warning + `stop_running()` + `round_fail` 保画面。保留 M35 防抖(重读 2 帧自愈不误停)。

## Consequences

- 实机遇真未知卡会停机阻断(用户已知会接受);接管流程按 flag 步骤(analyze_screen+SIFT 对拍→建档→删 flag→重启 server)。
- 删除条件:连续多局零触发(未知内容建模收敛)后按 od-dev-stop-hooks 生命周期判据评估;不设自动删。
- 「待用户确认」待办闭环:本 ADR 即用户裁决记录(skill §2.3 双条件补齐)。

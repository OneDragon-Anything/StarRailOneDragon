## 一、新问题清单(严重度排序)

### R74-1(中高)【工程裁量+证明】R73-1 锁存置位谓词的输入未钉死——三种读法两病一死,其一复活 R71-1 已落选形态

**论断**:R73-1 修法句「HandleInvestStrategy OCR 读三卡名时即时置位锁存 `cap_sup_latched`」与可达性
谓词本体「息律/开源节流在店面或投资池可选集」之间存在未闭合的谓词输入缺口,设计文本三种可读法
各自致病,落码批按任一字面读法实现都会翻车。

**证据**(注册表直调):
- `cw_investments.py` L153-155:注册表升帽策略名 = **`开源节流`(override=9)/ `利息上调`(override=10)**
  (另 `买断制` override=0 系降帽,须排除)。**「息律」不是注册表策略名**——全仓 grep,「息律」只出现于
  `cw_registry.py` L17 注释(50 金利息规则 interest_rule 约束)与 `cw_deploy_seat.py` L281 注释,
  属用户口述概念非可购策略。
- `handle_invest_strategy.py` L131/L151:三卡名经 `_read_options` OCR 获得,过滤带 y∈[465,505]、
  字长 2-8、排除集;OCR 全 miss 时 `names=[]`(L141-142 走 `pick=None` + 盲点 fallback)。
- IMPL_FIX_LEMMAS R73 对照表 R73-1(b):「OCR 读三卡名时即时置位」;R72-1:「本局任一帧观测到
  息律/开源节流在店/池 ⇒ 置真」。

**推理链(三读法)**:
1. **无条件读**(overlay 在场即置位,按修法句字面「读三卡名时」=读到了就置,不做名字匹配):
   三候选全非升帽策略的局也被置真 ⇒ g*=10×cap_sup=100 而该局真值饱和线恒 50 ⇒ 对真值自由带
   「有罪推定」——这正是 R71-1 论证节步骤 4 用不等式级比较**显式落选**的备选形态
   (「不可达局阈值 100>真值饱和线 50/0,对真值自由带有罪推定=口径错非保守化,违默认局零漂移」)。
   按禁翻案纪律,修法文本不得含与 R71-1 落选裁决同形态的读法而不断言排除。
2. **名字字面匹配读**(按谓词语义句「息律/开源节流在可选集」匹配名字):「息律」在注册表零条目,
   字面匹配**构造性不触发**(只命中开源节流、漏利息上调=10 档主力升帽),锁存购入前近恒假——
   R73-1 自己修的「死代码病」以匹配键形式复发。
3. **属性匹配读**(get_strategy(name).interest_cap_override∈{9,10}):唯一正确读法,但设计文本
   未钉死为此形态;且此读法下 OCR 漏读/误读(如「利息上调」读缺一字被 2-8 字过滤或落排除集)
   ⇒ 真 offering 帧不置位 ⇒ 「暴露=首见前的备战期帧」残余账失真(真实暴露延伸过首见帧,
   账面按首见截断=申报偏低)。

**修法方向**:R73-1 落位面补一句置位谓词规格钉死 = 属性匹配读(匹配键=注册表策略名
`{开源节流,利息上调}` 或等价属性 `interest_cap_override∈{9,10}`,禁名字字面「息律」),
并声明 OCR 漏匹配帧的暴露账形态(要么并入「全程零观测」自有量级界 ≤135 金,要么补 OCR 置信度
门槛+漏匹配分键观察)。同时补一行为锚:三候选全非升帽策略的 overlay 帧断言锁存不变。

### R74-2(中低)【工程裁量】观测载体迁移的写入端跨层路径与共享 handler 文件面未申报

**论断**:R73-1 把观测点迁入 `HandleInvestStrategy`(operations 层共享生产 op),但写入端路径
(op handler → statefn `cap_sup_latched`/derived)与该 handler 的共享波及面在 §1 模块结构与
文件面声明中均缺位。

**证据**:
- IMPL_DESIGN §1:依赖方向单向「入口 → 判据/义务 → 状态函数 → 数据注册表」;`HandleInvestStrategy`
  在 cw4 包之外的 operations 层,R72-1 规定锁存「登记入口=audit/derived.py 与 cap_resolved 同源段,
  判据模块禁自持、禁回写」——**写方向**(op 层写、判据层读)与 §1 单向图的关系未声明,也无数据流图。
- `handle_invest_strategy.py` 是现行生产策略(cw3/legacy 臂)共用的 op:三臂 A/B 期间给共享 handler
  嵌入 cw4 专属锁存写入+候选名持久化,对非 cw4 臂是代码共享面与遥测面增量,R73-1「本批零源码改动」
  把文件面推给落码批但未预登记波及面(违任务书「文件面声明」精神的前置缺位)。
- handler 的局外独立跑分支(L140,`match is None`)下 `session` 不存在,锁存写路径在该分支未定义
  (静默跳过需显式声明,防落码期 AttributeError 或漏写两读)。

**修法方向**:R73-1 落位面补:①写入端归属声明(候选名与锁存的持久化载体字段、session 生命周期、
局外分支行为);②落码批文件面预登记(共享 handler 改动的波及面=cw3/legacy 臂,三臂可比性影响
按 R44-5 同款申报)。

### R74-3(低)【证明】R73-4 态①「≤2 备战期」可加性隐含未申报前提 + §5.2 观察键对金缺因子无载体

**论断**:态①推导「金补齐帧 ≤1 + 目标件在店帧 ≤1 ⇒ ≤2 备战期」隐含「金补齐后到目标件在店帧之间
金不被其他义务动作动用」,该前提在义务先行(M1-M7 每备战期花金)经济里不结构成立;且 §5.2
`funding_support_shortfall_open` 行把「未成交」操作化为「(目标件离店)」,金缺导致的顺延不入键。

**证据**:R73 对照表 R73-4(b)(两帧各 ≤1 的推导只给时间上界,无金保持前提);§5.2 L539 行
(计数对象括号注「目标件离店」);R73-4(c) 自己承认义务「fail-closed 留待下帧」=下帧重发射
依赖金与件两条件同时满足。

**推理链**:金补齐于帧 t、件在店于帧 t+1 但金已于 t+1 被更高优先级义务花掉 ⇒ 闭合需第三帧再筹资,
≤2 上端被「金-件交错错帧循环」击穿;观察键在此形态下(件在店、金缺、无新卖出事件时)不计数,
永久顺延判入条件「连续 ≥2 备战期未闭合(件离店)」对该子态失明。**严重度限低**:方向=发展延迟
非不可逆卖出,量级有界且超标回炉通道对主流子态仍可达。

**修法方向**:态①补显式前提申报(金保持假设或改「期望意义 ≤2」)+观察键计数对象扩「支付义务
未成交」全因(金缺∨件离店),分键辨因。

   grep 证实设计件头部两处+登记表两处「≤125」均已同步打 R73-3 标改 ≤135,同步完整性过。推导自洽。

   确认帧、判据/batch_form 门消费于备战期——时序上锁存恒先于购入、购入恒先于下帧判据消费;

   R70-1 定罪方向核对无误)。交错面零新症。

# 退出链（返回大世界 × 货币战争对局退出）

> as-built：描述系统现状的结构/语义/契约；数值与名单单一源在代码（本文只写位置与语义）。

## 1. 三层结构与职责

```
一条龙/各应用开场
  └─ BackToNormalWorldPlus（sr_od/operations/back_to_normal_world_plus.py）
     职责：任意画面 → 普通大世界的通用兜底。逐帧认画面分支：
     货币战争-大厅 → 点右上角关闭；对局中画面 → 委托 CwEntryExit；
     其余弹窗/菜单分支各自接管。
       └─ CwEntryExit（cw_entry/operations/cw_entry/cw_entry_exit.py）
          职责：退出对局调度器——只做画面识别与分发，不内联画面处理
          （画面处理单一源 = 各画面 op / CwLoop，2026-09-13 重写定下的分工）。
            └─ 委托 CwLoop(stop_at_prep=True)（operations/cw_loop.py）
               职责：对局内画面统一处理器——0 系锚表分发到各画面 op，
               处理到可交还备战态即停机交还（`PREP_DIRECT_EXIT_SCREENS`）。
```

对局中画面判定单一源 = `cw_screen_state.get_in_match_screen_name`（建档全集：
「货币战争-」前缀 − `LOBBY_STATE_SCREENS` 大厅态白名单）。新对局画面建档即自动
进入识别与委托域，无需登记任何清单。

## 2. 退出路由分发序（CwEntryExit.route，判定序即优先序）

| 序 | 判定 | 去向 |
|---|---|---|
| ① | 全集建档识别 → 屏名 | None 走⑥ |
| ② | 屏名 ∈ `ROUTE_BY_SCREEN`（退出过程画面：中断挑战弹窗/结算/结算-失败/挑战失败/结算-对局详情/结算-战报） | 跳对应退出链节点 |
| ③ | 屏名 ∈ `PREP_DIRECT_EXIT_SCREENS`（cw_screen_state；={备战, 备战-免战}） | 备战退局发起（点门形图标；免战复用备战档纯定位区） |
| ④ | 认「货币战争-大厅」白名单 | 大厅确认（op 成功终点） |
| ⑤ | 屏名非 None 且未命中②③④ = **默认委托** | 委托对局循环（唯一特判：敌人信息浮层 → 内联点「按钮-关闭」） |
| ⑥ | 屏名 None（未建档/过渡帧） | 数拍重试 → 连续计数判战斗中 → 右上 X 兜底 |

- ③⑤的判据基础是「识别屏名」，不依赖任何锚子集判定：锚子集会穿透浮层误判
  （事故根因：选伙伴引导态下「购买经验+出战」双锚可见，被误判为可退出备战，
  而引导态游戏禁用退出图标 → 点击无响应死循环）。
- `ROUTE_BY_SCREEN` 本义 = 可走退出流程后续节点的画面分发表；表外画面默认
  委托（⑤），缺项无害化——新画面建档即被⑤覆盖，表不膨胀。
- 战斗暂停无建档 id_mark，不经②路由；实际入口 = 「战斗中点右上X」节点的
  until 直边（战斗暂停档「标识-战斗暂停」单锚）。

## 3. 关键契约：A 类名单与停机位同源

`PREP_DIRECT_EXIT_SCREENS`（cw_screen_state.py）= 「可点门形退出的备战态」名单，
被两处共用、禁各自另写：

1. 路由③（判定直接退出）；
2. `CwLoop` stop_at_prep 停机位（委托处理到可交还态即停）。

两侧判定恒一致 ⇒ 委托后对局循环处理浮层到 A 类态立即交还，路由接手直接退局，
无「一侧说到、一侧说没到」的往返。停机位语义 = 可交还备战态（含免战），与
发射链的「穿透底图判定」（`_prep_anchors_hit`：购买经验+出战，浮层穿透形态
可见即命中，服务 0e 复探门/发射仲裁预检/C3 确认）是**两种语义**，后者三处
调用点有意穿透，禁与前者混用。

## 5. 边界与已知局限

- 备战-免战点门形图标弹中断挑战弹窗：与干净备战同款交互（推测成立），实机
  未在免战态构造验证。
- 备战-角色信息提示/装备详情浮窗无关闭交互 area（建档仅 id_mark），清场注册
  表未登记：委托 CwLoop 兜得住（非死循环），「补关闭 area + 登记」为后续卫生项
  （登记处 = kernel/cw_overlay_registry.py）。
- 备忘档 3 屏走⑥战斗兜底：其页面对右上 X 的响应未逐一验证（低频 + 有界失败）。
- 决策型画面 op（选伙伴/选卡等）内含策略决策与 session 写入，依赖
  `ctx.cw_match` 对局上下文；孤儿对局场景 session 残缺时的行为以画面 op 内部
  兜底为准（实证：2026-09-15 事故帧残留对局上委托链全程走通）。

## 6. 动机

分发反转（默认委托 + 穷举归档）治的是「识别结果被手工清单丢弃」的结构病：
此前清单外画面落穿透双锚误判 → 点被禁用的退出图标死循环（2026-09-15 事故，
「按钮-退出对局」状态 966 次）。反转后识别、分类、处理三段各自单一源，新画面
建档即全覆盖。

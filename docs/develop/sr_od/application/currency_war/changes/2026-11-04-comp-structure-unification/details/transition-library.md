# 过渡阵容库与配方决策层退役（详设）

## 问题与约束

- 本主题边界：P1 开局过渡方向的产生机制（候选/锁定/花钱方向/部署圈人）从「体系配方机器」切换为「结构化过渡阵容库 + 终局同构机器」；不涉终局阵容机器本体（line_select/evaluate_lock 不动）、不涉统一让位序结构（十档不动）。

## 方案

### 1. 过渡阵容库（新注册表，cw_comps.py）

```python
TRANSITION_LIBRARY: list[Comp] = [ ... ]   # 条目 = Comp 结构、最小字段
```

条目字段口径（**三型条目**，用户 2026-11-04 裁定「DOT 不限定人」「希儿+任意一名量子/贝即可」引入）：

- **点名型**（core_chars 非空、羁绊半边不计）：计分基准 = 持有点名成员数；见即买 = 点名集。适用「引擎不可拆」（仙舟铁三角——引擎缺失的仙舟凑数不构成该过渡）与「线定义件引导」（列车骨架——姬子在场才值得朝列车走）。
- **羁绊型**（core_chars **空**）：计分基准 = 持有的档 0 键羁绊成员数（不论是谁）；见即买 = 该羁绊任意成员（低费件自然先刷到，符合「廉价」本义）。适用「无引擎、凑出就能用」（廉价 DOT）。
- **混合型**（core_chars 点名引擎件，放大器走羁绊半边）：计分基准 = |持有点名成员 ∪ 持有的档 0 键羁绊成员|（**按角色去重**——一名角色同时命中点名与多个羁绊阵营（希儿 = 量子同频 + 贝洛伯格双阵营）只计 1 分，杜绝跨 roster 重复计分）；见即买 = 点名集 ∪ 档 0 键羁绊全体注册成员。适用「单卡引擎 + 任意放大器」（希儿引擎——引擎点名希儿，放大器不限定人，量子/贝成员经羁绊半边自然覆盖）。
- **硬约束：点名型/混合型的点名件费段必须位面 1 商店可刷**（费段解锁真值：lv1-3 仅 1 费 / lv4 起解锁 1-3 费 / lv5 起 4 费 / lv7 起 5 费，`cw_shop_odds.REFRESH_PROB`；位面 1 的等级覆盖区间真值 = `cw_economy` 位面-等级骨架（`get_node_goal`/`_expected_level`），落地批以该骨架核对「位面 1 可刷」判定的等级前提）——违反即降型或换件（黑天鹅 5 费因此出局）。羁绊凑人数**不限点名成员**（成型判据读板面羁绊计数，三型同规则）。

**faction_reqs 数值口径（两源冲突裁定）**：现行存在两个过渡知识源且数值不同——体系卡判据档（`FACTIONS[...].tiers[0]`：仙舟 3/DOT 2/列车 2）与配方伪阵容完全体档（cw_recipe 的列车 4）。**取体系卡判据档**（过渡语义 = 低门槛快锁；完全体档归终局线 faction_reqs 自己承载，不进过渡条目）。

**条目表（4 条；知识源 = SYSTEM_CARDS 判据 + `cw_line_facts._CORE_TRIO`；费档已核 `CHARACTERS.cost`）**：

| 条目名 | 型 | core_chars（点名件） | faction_reqs 档 0 | or_reqs / required_deployed | need_star |
|---|---|---|---|---|---|
| 仙舟铁三角 | 点名 | 爻光(1费)、藿藿(1费)、丹恒·饮月(2费) | {仙舟: 3} | — | 三人各 2★（数值取自体系卡 star_goal，就地复制非引用迁移——体系卡数据层保留，条目自带值） |
| 廉价 DOT | 羁绊 | **空（不限定人，任意持续伤害成员）** | {持续伤害: 2} | — | — |
| 列车骨架 | 点名 | 姬子·启行(3费,lv4起)、三月七(1费) | {列车同行: 2} | — | — |
| 希儿引擎 | **混合** | **希儿(3费,lv4起)——引擎单卡**；放大器不限定（任意量子同频/贝罗伯格成员，经羁绊半边覆盖） | {量子同频: 2, 贝洛伯格: 2} | ((量子同频,2),(贝洛伯格,2)) / (希儿,) | 希儿 3★ |

（校验注：or_reqs 值与档 0 同键值一致——希儿条目两键均被承接，必齐账恒空，成型判据 = 希儿在板 ∧ 量2∨贝2，与体系卡判据逐字一致。**档 0 空而 required_deployed 非空的条目为合法形态**（`form_progress` 的 required 逐名折条独立于羁绊账，现行实现天然支持）；现库 4 条无此形态。**点名型/混合型条目的锁定引擎条件**：建库自动填 `required_deployed = core_chars`（点名件全部在板才算成型）——用现有机制承载「引擎不可拆」语义，杜绝「持 1 点名件 + 凑数板面即锁出缺引擎过渡」（锁定判据 form_progress 含 required 折条，天然生效）。）

### 2. 候选机器（落位 cw_intention.py——槽写端同宿主，import 方向零新增）

**函数 = `update_transition_candidates(gs, ist, st)`**（新函数；调用位 = 现行 `update_p1_recipe` 的调用位置原位替换——外层流程每 game-round 恰一次调用，调用位置不变）：

- **计分（用户 2026-11-04 裁定：与终局线分同构的统一评分——证据 + 词缀减分 + boss 减分三面，纯减分制无特殊逻辑）**：
  - **持有分**：点名型 = 持有点名成员每名 +1；羁绊型 = 持有的档 0 键羁绊成员每名 +1；混合型 = |持有点名 ∪ 持有羁绊成员|（按角色去重，一名角色跨点名与多阵营只计 1 分）；持有 = 在场 ∪ 备战席（`held_chars_of` 同口径）；开局全 0。
  - **词缀/boss 减分面（统一减分制，用户 2026-11-04 裁定）**：与终局线分同构——**纯减分、不设排除特殊逻辑**（量子熄火等词缀实际效果是暂时性削弱（前 4 次攻击 1 点伤害后解除，affix_effects_data:25），终局「重开级」登记是终局成型语境的评级，过渡期战斗强度低下不构成不可玩——过渡层按效果给普通减分，不一票否决；减分足够大时条目自然排不进前 3，评分体系自然涌现软排除）。数据 = `TRANSIT_AFFIX_PENALTY: dict[str, list[str]]`（键 = 词缀名或 boss 名；值 = 被克制的羁绊名；宿主 cw_intention.py）。**行集（逐行判读，依据 = cw_affinity_table 线级登记的羁绊投影）**：


    减分常量单一档（命中一条克制 → 固定负分，量级与终局怕档一致，数值落标；不设重开级天文数字档）。开局简报已观察的克制源（`enemy_affixes` ∪ 位面 1 boss）命中条目档 0 键 → 减分进排序；简报未观察帧自然不触发（fail-closed = 输入缺失时取「不动作」的保守分支）。终局线分的词缀/boss 面不动（线级登记更细，与本表数据同源、粒度分工）。

### 3. 冷启动与回退（死循环防线的承接）

现行「候选槽为空的买面回退」（现行函数 `k_empty_window_fallback`）的存在理由（函数注释明示）：消「候选空 → 零买入 → 计分来源永不增长」的死循环。新机器同构风险：开局候选槽空 → 无方向 → 零买入 → 持有（计分来源）只靠免费送。承接设计：

- **候选槽为空的帧，买面回退目标 = 过渡库全体条目的见即买并集**（点名型贡献点名集；羁绊型贡献其档 0 键羁绊的全体注册成员；混合型贡献两者并集——新见即买集，替代旧回退带的四体系羁绊成员并集（`_pair_members` 展开，cw_intention:1148））；
- 冷启动买入分支（shop.py `_COLD_BOND_KEYS`）与保护集（protection.py 体系键）的键域**改读过渡库见即买并集**（单一源派生，不再手抄体系键）；
- 死循环在新机器下闭环：见即买 → 持有 → 计分 > 0 → 候选形成 → 方向确立。

## 关键取舍

- **放弃「过渡层直接复用终局线（取消独立过渡阵容）」**：用户 2026-11-04 裁定两套库独立——过渡形态（廉价、低费、可弃）与终局形态（成型定义、知识全量）是不同的知识域。

- **放弃「过渡层多维证据分」**：一维成员持有分先行，扩展另立（消费先行判据）。

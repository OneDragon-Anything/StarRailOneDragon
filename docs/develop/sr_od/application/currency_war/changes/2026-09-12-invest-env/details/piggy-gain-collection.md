## 1. 目标量与两条路线的本质分工

C 类环境(经济过热 id105 / 经济严重过热 id119)的估值参数 =
`reward_node_bonus_{normal,super}`(每奖励节点期望增益,金等价)。
把它拆成两个独立的数据面,选型就清楚了:

| 数据面 | 内容 | 唯一可行来源 |
|---|---|---|
| **识别面**(哪些轮是扑满奖励帧) | 帧分布 / 逐(位面,轮)槽位 / 变体分键 | sim 注入(立即)+ 实机遥测字段(积累) |
| **真值面**(每节点增益多少金) | 战利品折金分布的均值与区间 | **只能来自实机对局档案**——sim 不建模扑满战利品金流,注入臂收入 = 普通奖励节点注册表值,两臂收入面结构性零差;游戏研究在册结论 =「掉落是否以金/物资/装备为主未知」(invest_effects.md P8 前置行) |

据此,两条候选路线的实测权衡(数据就绪速度 × 工程量):

| | A. 遥测字段(战利品独立落账) | B. sim 注入受控对照 |
|---|---|---|
| 识别面样本 | 零(实机门未开 + 过热局自然频率 ≈5.5%,super ≈0.7%) | **立即**(本批验证批 18 局 1.4s,36 确认帧) |
| 真值面样本 | 有潜力,但**前置一批**:扑满局战利品流的画面采集点未观察定谳(ClickSpheres/OpenBox 无逐件金额;战利品金在哪一屏可见未实采),且自然采集点在 prep_actions.py(当批用户域禁碰) | 永远为零(见上表真值面行) |
| 本批可验证性 | 字段可落,但写点建在未观察的画面语义上 = 凭猜地基,实机首验前不可证 | 端到端可运行、可锁、可证 |
| 工程量 | schema+装配器+活体采集点(禁碰面/未定谳采集语义) | 注入机制已在册(W162/ADR-0364),补批入口+锁 |

**选型 = B(sim 注入)为主交付**,理由:①就绪速度——B 本批即产识别面样本
(P8 §4 兑现判据「sim 注入过热环境后 `piggy_reward: true` 样本 >0」当场兑现);
②工程量与风险——A 的真值写点必须先观察扑满局战利品画面流才能设计,现在动工
= 凭猜建采集点,实机首验后大概率返工;③A 并未被放弃——真值面终归要实机档案,
其字段落地 = 实机门开后的后续采集批(本批 §4 判据①的口径前提)。

**与 T-129「二选一即可解锁落参」的偏差申报**:经目标量拆解,sim 注入
解锁的是识别面(及 P8 前置 #1),真值面仍须 A 路线的档案字段——「解锁落参」
的完整路径 = B(本批)+ A 的字段批(后续),不是单路线。此为设计-现实对账
结论,非改设计意图;已按独立判据成文(§4)。

## 2. 识别面写点失联缺陷(本批修复申报)

实施验证时发现:**`piggy_reward` 遥测写点在两条决策栈上全部或部分失联**,
这是 P8「全部语料 true 计数=0」的代码侧根因(此前归因为「扑满局零样本」,
实为「有局但标记恒 False」):

- **shop 栈写点(`strategies/impl/mandate_v1/shop.py`)**:帧型判读用旧
  `CwWorkFrame.node_type` 属性(`getattr(bs, 'node_type', None)`),bs 实为
  容器 `GameState`,该属性不存在 → getattr 恒 None → 写点从不执行。
  容器化迁移遗留(same 族 = T-7 sweep 的 GameState 正名迁移面)。
  修复 = kernel 单一源 `node_kind_of(bs)`(与 mandate 栈写点同 API)。
- **跨轮滞留**:两栈写点都只在奖励帧刷新、非奖励帧不复位 → 奖励轮之后
  的战斗/补给轮账本行滞留 True。修复 = 可辨非奖励帧复位(不可辨帧(None,
  店开节点行被遮的结构性常态)维持最近真值,与 `reward_node_suppressed`
  的 None 失效方向同族)。
- **零行为面论证**:engine_p1.py 写点注释明示「两者均无决策分支消费」;
  全局检索 v3_piggy_reward 消费位 = engine 轮快照(账本行 piggy_reward)
  与 telemetry schema,无任何决策输入读它。修复只增加遥测布尔写,
  `reward_node_suppressed`(抑制决策判据)调用面一字未动。

## 3. sim 注入批口径(采集机制)

- 入口:`sr_od.application.currency_war.sim.cw_sim_piggy.run_piggy_batch`
  (缺省三臂 baseline/normal/super,同 seed 段受控对照;种子段纪律 =
  sim-testing「种子段分配分配纪律」,seed_base 由编排者统一下发,
  manifest.json seeds 键 = 占用段对账锚)。

  + manifest(目录名 `sim_piggy_<variant>_…`,滚动清理窗口与普通批一致;
  证据批用 `anchor_reason` 锚定免清理)。
- 统计口径:**确认帧 = `piggy_reward=True` ∧ 账本行 node='reward'**。
  已知滞留形态 = 该轮首段无商店决策时,引擎轮入口快照读到上一奖励帧旧值
  (引擎侧快照机制辖域;引擎文件当批在飞禁碰,聚合侧以奖励节点容器为准
  并单列 `piggy_leak_rows` 披露,不静默洗数)。
- 变体表:`PIGGY_VARIANT_ENVS` 与 `cw_env_economy._REWARD_BONUS_VARIANTS`
  双向对齐锁(test_cw_sim_piggy,防单侧改名 = 参数查询恒 miss 的哑臂)。

## 4. C 类落参数据就绪判据(成文面,持久载体 = 重采入口头注)

三件同时满足(缺一 = 继续在册 fail-closed):

1. **档案面**:每变体可用「扑满奖励节点」样本 ≥ 20 轮(变体分键;
   经济严重过热自然到局频率 ≈0.7%,约需 140+ 完成局或加速到局),
   且增益分解口径成文——战利品金对应字段(新遥测字段,采集批落地)、
   与基础/息/连胜的分离规则、失败轮(打不过 = 零奖励)处置;
2. **统计面**:增益均值 bootstrap 95% CI 下端 > 0(与注册表 fail-closed
   门同语义:方向不闭合不落);
3. **对拍面**:sim 注入批识别面分布与实机 piggy_reward 字段方向一致
   (变体分键无结构性矛盾——两变体样本面混淆 = 采集点错)。

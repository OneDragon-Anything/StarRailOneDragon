# ADR-0025: 领域版派单模板的重读锚点=CW skill 自身(细则源不回指通用层)

- 日期:2026-08-28
- Status:accepted

## 背景

派发盘点 CW 领域版模板(autonomous-loop.md §2)尾部沿用通用版的细则源指针(通用仓 od-dev-agent-autonomous-mode 的 orchestration.md「派发节奏」节),用户裁决改为锚定 CW skill 自身。问题根源:领域版与通用版的结构已分叉——第 2 步整读进度文件(通用版为状态词 grep)、CW 多第 4 步 sim 兜底与第 5 步找活兜底、封条多实机等待禁令。执行者(尤其上下文压缩后凭指针重读时)回读通用层,会被通用版的步骤结构与措辞带偏,把已领域化的流程又执行回通用版。

## 决策

- 派发盘点 CW 领域版 prompt 的细则源=本文件「派发盘点·CW 领域版」节+references/sim-testing.md,不回指通用仓(2026-08-28 生效,见改动说明第 6 条);
- 本决策成立的地基:领域版块内每步自带完整执行判据与证据要求(实扫/留痕/封条均内联),重读领域版即可恢复执行,无需通用层补充——若某步判据将来写不够用,正确修法是**把判据补进领域版块内**,而不是加回通用层指针;
- 同判据推广到 CW skill 全部提醒模板:提醒词内的重读指针一律锚定领域侧文件(实机监控细则源本就=runtime-ops.md,符合),不回指通用层;
- 对表清单(改动说明第 6 条)已登记此差异:通用版演进重放时,不把通用指针带回领域版。

## Considered Options

1. **细则源保持回指通用层**(通用层=基线,细则单一源)——否决:单一源原则管的是「内容不复制」,管不住「重读者被异构结构带偏」;领域版各步判据已内联,通用层细则对执行者是第二结构源而非补充。
2. **CW 侧复制通用层细则进来**再指向复制品——否决:双源,通用层演进即漂移,违反领域叠加规范(只写差异,不复制通用原文)。
3. **细则源=领域版自身+领域细则文件,判据内联在领域版块内**(选中)。

## 后果

- 正:执行者压缩后重读锚定同构结构,不再被通用版带偏;CW 模板自包含度提高,建网照抄后可独立运转;
- 边界:通用层的横向细则(如派发节奏的多来源深扫手法)不再经 prompt 指针触达——领域版块内的来源清单与判据是执行者的唯一重读面,维护时须保证它持续完整。

## 关联

## 一、发现清单

### B1【应修】victim ③级（名单末位桶）层内序未钉死——与自身「预测表确定性要求全序钉死」冲突

- 位置：design.md:100（两级 victim 序段）、:102（名单让位=末位）。
- 事实（代码体直调）：①②级层内序与换入序三层 tie-break 全部钉死，③级只钉了**位置**（「①② 级无 victim 可配而分支 hold 通过时进入候选」）与**准入**（3(a)/3(b)），未钉**层内取序**。`_swap_victim_yields_for_swap_in`（cw_deploy_logic.py:871-894）是逐件谓词——多个名单成员可同时 hold-pass（required 件按已换入计的假想面板 :807-825 逐个独立成立），3(a) 亦可有多同名对；多候选取谁 = 实现者须自行拍板。而 §2.7 自己写明「3.5 预测表确定性要求全序钉死」——③级不钉则全序有洞，锚②（2-2..2-4 逐帧对照）在这些帧不可复算。
- 修正方向：钉死③级层内序（建议 = ①②级同款现行序键〔贡献/星级桶/槽位〕或名单注册序，任一写死即可），并随批同步 landing 3.1 组算法测试判据。

### B2【应修】来金资格增补的通道点名清单漏 `session_funding`（会话内筹资）

- 位置：design.md:109（§2.8）；landing.md 3.3。
- 事实（代码体直调）：`SCENE_SPECS`（criteria/sell_candidates.py:172-198）实际 FACE_REGULAR 闭集 = **六**通道：`ore_make_room`/`shop_swap`/`session_funding`/`levelup_liquidate_prep`/`node_end_interest`/`c1_make_room`。设计点名五个、漏 `session_funding`（POOL_BENCH_ONLY, FACE_REGULAR, legacy='funding'）。落点机制（装配 A 身份段共用）保证其自动覆盖，但 landing 3.3 的测试锚义务写明「申报粒度=逐通道点名于 landing 3.3 测试锚」——按设计枚举执行会漏一通道的逐通道测试。
- 修正方向：补点名，或改述为「按 `SCENE_SPECS` FACE_REGULAR 闭集逐通道枚举」。

### B3【应修】枚举表 C 与组生长语义「首个可行组即停」在示例构造下不相容，单帧测试构造未定

- 位置：design.md:59（枚举表 C 行）与 :100（组生长语义）。
- 事实（按注册表真实牌面推演）：C 例「开拓者·记忆+藿藿 进、**两纯过渡件**出」——首对（开拓者·记忆←爻光类）单独即过门 1②（支撑 +1：入为名单成员、出为非支撑件）与门 1①（能量 2→3 一阶；开拓者·记忆含能量 cw_chars.py:168、藿藿含能量 :122 直调），按「累积组门 1 通过即停」组 = **单对**，表中「支撑数 +2」的双对形态无法同帧作为单组发射。多对合取组只在「单对全败」形态可达（victim 亦为支撑件使②持平、档位不跨、仅 ④ 型合取达成——如希儿系放大器对换）。§2.7 的生长理由句「只试单对会使情形 C 不可达」对 ④ 型成立，对表列 C 例（②①型）不成立——理由句与其引用的情形互相错位。
- 影响：landing 3.1「单帧测试覆盖枚举表 …C… 全情形」——C 测试的构造形态（④ 型多对单组 vs 跨帧两单对续发）未定，测试与算法语义二选一错。
- 修正方向：在 C 行或 §2.7 钉死一句：枚举表 = 组换后板态假设检验语义；C 的发射形态按组生长语义分型（②①型 = 跨帧单对续发 / ④ 型 = 同帧多对组），landing 3.1 测试按此构造。

### B4【存疑】pair 帧路由第 1 面文案「skip 守恒门 → 资格族」自相矛盾，判据分支仅可间接恢复

- 位置：design.md:78（§2.3.1 pair 帧路由第 1 条）；cw_deploy_logic.py:979/:986-991/:1025。
- 事实：现行 `:990-991`（`if not _trans: return ''` 成型帧早退）与 `:1025`（fenced 分支 `elif not _trans:`）共吃同一 `_trans` 局部变量（:979 单点取值）。本轮（轮13）新增的五面路由段钉死了「路由键 = p1_pair 分支②非空、禁引退役符号」与 fenced 分支的混轨真值表，方向正确；但第 1 面的括号文案「pair 帧照现行通路（**skip 守恒门 → 资格族**）」字面自相矛盾——旧资格族 fall-through **包含**守恒门（engines_guard :1038-1044），「skip 守恒门」与「落资格族」不能同真；若「守恒门」指 §2.3 新守恒（终局档位非降）则语义可通，但该读法只能靠读者自行消歧。若实现者不按「路由键=p1_pair」而按「统一换判别子」实现，pair 帧 off-target 释放件将在 :990 早退跳过旧资格族（engines_guard/star_guard/素材守卫）= 双轨域静默行为差，违反本面自己的「零行为差」申报与 §2.11④「无静默收窄」（五面回归测试可兜底，但预期值来源仍是这段歧义文案）。
- 修正方向：第 1 面改写为可执行真值：「:990-991 早退仅限混轨 locked ∧ fp≥1.00（成型帧）；pair 帧不早退，落旧资格族（engines_guard/star_guard/素材守卫照走）；pair 帧 skip 的是 §2.3 新守恒（终局档位非降，辖域仅转型域）」。

### B5【存疑】§2.5 轴② as-built 论证失真：中梯 D 帧在实现级会**误过**轴②（假想面板双计），真实实现级冲突仅在键封顶形态

- 位置：design.md:91（§2.5）；mandate.py:806-835。

### B6【存疑】§2.8 段一收敛论证未把 §2.7 中途失败语义的瞬态纳入正式前提

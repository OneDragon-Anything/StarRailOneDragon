# ADR-0012 实机暴露问题的分诊与回灌闭环

## Status

accepted(2026-08-24;用户问「很多策略问题实机才发现,能否更好利用模拟测试提前发现」)

## Context

ADR-0009 把 sim 深度挖掘方向成文,但闭环仍缺一半:0009 回答「sim 能做什么」,没回答「实机暴露的问题如何分诊、如何强制流回 sim」。2026-08-24 复盘实证:

- 局49 的 r1 桥期清金(无方向种子时 5 金全买杂卡)在 sim 批次里**每批都在发生**,但 sim 只评终态分布(hp_trail/dir_round/refreshes/depth_trail),无判读视图可查过程——「找不合理指纹」只能查遥测、不能查 sim 局;
- 局46/49 同款「治疗伪档」病(羁绊档位够但核心角色不在场)的本质维度是阵容质量,Δ 池只按 {节点×深度桶} 分键,看不见该维度;
- 同时 gate/import 类感知 bug(局35-38 五个半)sim 永远测不出(不执行观测层/op 框架),为它扩 sim 属方向错误。

三个 B 类病没被提前发现的根源可归纳为:过程不可观测 / 指纹未回灌 / 校准层缺维度。

## Considered Options

1. 只把实现任务(判读同构记录/回灌断言/Δ 池扩阵容质量键/种子化)记进度树:实现会做,但「分诊 A/B 类」「为什么 sim 没发现」的判据不落 skill → 下个会话仍靠临场重新推导,且无纪律强制新实机病回灌。
2. **分诊判据 + 判读同构原则 + 回灌纪律成文**(选):方法论进 verification.md(延续 ADR-0009 的落点——验证工作台是 sim 的家),SKILL.md 只做三处轻接线(checklist 第 6 步挂回放对拍 diff、验证工作台 sim 层指针、防坑清单一条),防坑清单不载局号(规范 4);实现任务归进度树待办(skill 不载进度状态)。
3. 待判读同构基建建成后再写成文:先实现后判据——同构/回灌是纪律不是工具,基建没建时纪律就应生效(约束「别假装 sim 已能判读过程」「缺口记待办」),等建成才写会漏掉这批学费的教训。

## Decision

选 2。进 skill 的核心三条:

1. **分诊**:A 类感知/运行时 bug 归 fixture 帧锁/回放对拍/哨兵线,sim 永远测不出,别为它扩 sim;B 类策略行为病 sim 本可发现,没发现时按三根源逐一对照(过程不可观测/指纹未回灌/校准层缺维度)。
2. **判读同构原则**:sim 局产出与遥测 jsonl 同构的逐轮记录,判读视图直接可查 sim 批次——实机判读手法秒级扫几百局 sim。
3. **回灌纪律 + 自检问句**:实机定位的 B 类病必须固化 sim 检查项 + 可单帧化的单帧锁;修完问「sim 要有什么检查项才能在实机之前发现它」,答不上来 = 缺口记待办。

## Consequences

- 判读同构基建(sim 同构逐轮记录 + telemetry 视图接线)落地后,verification.md 该节「基建未建成时先记待办」句可收敛为工具用法;落地状态归进度树,不回填本文。
- 与 ADR-0009 互指:0009 是 sim 侧挖掘方向(出航),本文是实机→sim 的回流纪律(返航),合并构成闭环。
- 若日后分诊/回灌判据被验证跨玩法成立,升格进 od-dev-gameplay-automation(公共仓,走该仓确认流程)。

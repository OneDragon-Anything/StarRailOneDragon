# 实机运维细则(单跑道 / 局间交接 / 监控 / 运行坑)

> SKILL.md §实机运维 的展开。读者 = 智能体;操作对象 = 本项目的 CW MCP 工具链与游戏画面。

## 哨兵重武三步(单实例纪律的操作化;三次双实例事故反推)

重武任何 watcher(哨兵/早停/runs 断流)前,**必按三步走,禁直接 arm**:

1. **查旧**:查后台 job 列表看同类 watcher 是否还在 running;
2. **kill 旧**:在则停掉旧实例(双实例 = 重复报警 + 双倍 tail 开销);
3. **arm 新**:确认旧实例已终态(killed/completed)再发新。

事故形态(三次实证,最近一次为停局紧急交接连发两轮重武跳过查旧 → 哨兵/早停各双实例并存):**「重武」不是一条命令,是三步动作序列**——局间交接时最容易犯。

## 启动与重启

- 启动对局:MCP `run_standalone_app`(app=`currency_war`);进度 `get_run_status`(state/current_node/retry);停止 `stop_run`(信号式,当前节点完成后退出——发完信号游戏可能还在打,等自动战斗结算再动画面)。
- 改代码生效路径 = 重启 MCP server(经 daemon 的 restart 工具;**对局运行中它按守卫拒绝重启**——先 stop_run 等结算)。重启后客户端按 harness 约定重连(项目级 servers.yml strip/restore toggle,见全局工作指令)。
- 重启代价:对局丢、session(target/信号/失败记忆)清零——重启后首局 target 重选是已知断档,判读时别把首局异当回归。
- 改动攒批纪律:局中不改代码;一局跑完(或早停)再重启加载。

## 局间交接序(停局后到下一局开跑)

1. 停局(stop_run)→ 等自动战斗结算(游戏停后会打完当前战斗)。
2. 残局清理(SKILL.md §实机运维 的清理序;遭遇/投资 overlay 多半要先进后出——「返回备战界面」→ ESC 中断)。判定每一步用 `analyze_screen`,认 screen 名不认感觉。
3. `analyze_screen` 确认**货币战争-大厅**精准命中。
4. 重启 MCP(有待加载代码时)→ 重连。
5. 哨兵重武装:删旧哨兵位置文件(cw_sentinel.pos)再起新实例(单实例纪律——先查 job/进程列表确认旧的不在);**不删 pos = 读旧水位误报**(历次实证:命中 2 小时前旧局 ERROR;root cause = 没按本条走)。重挂定时轮询时更新提示词里的当期判读重点(过期提示词会误导)。
6. 起新局。

## 残局画面清单(按 screen 名)

- 货币战争-结算(「继续挑战」按钮;此屏 HP 为战后台作真值)
- 货币战争-备战(含开商店/装备详情子态;ESC 弹中断)
- 货币战争-中断挑战弹窗(「放弃并结算」)
- 货币战争-挑战失败(「下一步」;可能两页)
- 货币战争-遭遇节点(先点卡选择难度,再底部「选择」;「返回备战界面」右上)
- 货币战争-投资策略/投资环境(「返回备战界面」右上,别硬选)
- 未建档/不确定画面 → `analyze_screen` 先行;仍不明 → 按 od-dev-screen-onboarding 建档流程处理,别盲点。

## 监控栈(长时自主推进)

- 三层:①进程内哨兵 flag(`.debug/temp/currency_war/*.flag`,停机钩子按 od-dev-stop-hooks 处理);②后台哨兵脚本(tail 日志,命中高信号事件即 exit=推送;只报需介入的事件,水位去重);③定时轮询兜底(轮到必执行:run 状态+哨兵存活+进度对比)。
- 哨兵单实例纪律:重武前确认旧实例已退出;双哨兵 = 重复报警+双倍开销。
- 轮询提示词定期换血:提示词里写死的「当前局 N=某修复首验」会过期,误导后续判读。
- 用户要用电脑 = 全停实机(哨兵+定时+run),别抢鼠标。

### 哨兵脚本组(可重建;脚本都在 `.debug/temp/currency_war/`)

| 脚本 | 角色 | 武装时机 |
|---|---|---|
| `cw_sentinel.py` | 事件哨兵(高信号 pattern+卡死+静默双窗确认+局后空窗判 IDLE 不误报) | 随局武装,pos 水位清;**空窗期不武装**(必报);`--selftest` 内置回归 |
| `cw_early_stop.py` | 早停(判据=口述[28] 框架:P1 出口金<50 或 HP=1 才候选;HP<70 降观察报警不停局) | **首条遥测落后**再武装(早武装=自愈退出) |
| `cw_runs_gap.py` | runs 断流 | 随局 |

- **武装命令口径**:三件统一 `$env:PYTHONUTF8='1'; uv run python .debug\temp\currency_war\<脚本>.py` 后台起(退出码即警报);**「起」永远走会话后台任务信道**(编排者 job 机制)——**禁 DETACHED/脱离会话的自起**:进程在但退出码无人接收 = 报警链自断,哨兵哑了(2026-08-25 用户纠正,run 15 P2 投资策略误报经信道送达并处置实证了信道价值)。查旧/杀净/核岗/打印武装命令用 `tools/cw/rewatch.py`(它不自起);查旧 = job 列表 + `Get-Process` 按 CommandLine 匹配 `sentinel|early_stop|runs_gap` 双查;事件哨兵重武前删 `cw_sentinel.pos` 旧水位(rewatch 杀净时顺手删);job id 记进度树「点名册」节。
- **重武三步(硬序,防实例堆积)**:查旧(rewatch)→ kill 净(rewatch,含上一局残留)→ 编排者经会话后台任务信道 arm 新;起完 `rewatch --verify N` 核岗。**值守兜底定期核:哨兵实例数应=3(每脚本恰 1),多杀少补**。
- **试用期纪律**:哨兵/早停脚本前几跳 = 试用期——报警先核时间戳与归属(旧行重放/中途武装无上下文/局后空窗三类误报实证),再信内容;watcher 上线不算完,前几跳逐一复盘。

## 判读与建档的运维侧纪律

- **重启接管段的遥测降权**:server 重启后新 run 段的首个战斗结算前,遥测 hp/gold 是**接管帧错值**(session 真值丢,画面恢复期血量 UI 非战斗血条→误读满值)——**接管段 hp 一律不可作判据,以首个真实战斗结算屏(extras.hp_after)为准**;「满血/满金开局」级结论必核上游局的 boss 结算真值(HP 跨位面继承非重置,用户纠错在案)。
- **布局/坐标类建档的交互实锤纪律**:暗框检测/格点外推/VLM 计数都只是**假设级**证据——布局档案的**唯一终审 = 交互实锤**(拖角色到目标槽看落位+点占位槽开详情面板锚定,用户定调);外推超出实测档位范围不得直接落档,只能登记为待验证假设。判读侧对偶:OCR 单帧读数(cap/部署数)可被同源污染——cap-level≥2 存疑(宝钻语义+1),先重读再采信;VLM 各输出维度可信度独立评价(坐标不可信不等于计数不可信),用户玩家经验与数据冲突时先核数据再动档案。
- **首局判读锚点模板**(重开/重启后首局,事前写跑完核对;条目按当期改动点裁剪):① 决策日志 strategy_id=当期预期栈;② P1 r1 备战 hp 起步值=当期基线;③ [cw] 决策日志流动;④ 本批改动点预期生效行为(新语义无崩溃/新检测触发);⑤ 有恢复局设计时:接手即直接出战。
- **常置 flag 处置**:`.debug/temp/currency_war/` 长期存在的 `.flag` 是既有登记项,别当新事故——按其登记时的步骤走;已被后续 ADR/revert 裁定取代的登记项,待顺手删(处置记录在进度树)。

## 运行坑(高频)

- 结算屏残留 → app 启动死循环:起新局前必须确认大厅态。
- CW op 无条件 ESC 禁忌:备战屏 ESC=中断挑战弹窗;关面板用面板内控件。
- 奖励球/补给箱占备战席:席满时球点不动,先开箱腾席。
- **升等级破墙**:bench-full 警告阻塞出战 → 点购买经验升等级清警告解锁;无 gold 时卖角色(drag bench→左出售区)。
- **事件长尾**:肉鸽事件十余类(锁定备战/巨星强化/投资变体/遭遇/补给/详情弹窗),处理模式=边玩边重构(loop 卡→读屏→加 handler→再跑),别试图一次枚举全。
- **角色/阵营识别边界**:商店 OCR 角色名是主路径;SIFT 立绘库对脸部独特角色可靠、配饰/半身不可靠;阵营激活数以实机 OCR 左面板为准(别硬编码,跨版本会变)。
- 部署上限随投资环境/宝钻动态变(槽位档不固定):别信固定槽位数,读实际 cap;未实拍槽位档触发采集信号时按其 verdict 处理(别静音)。
- 画面识别结论有边界:`analyze_screen` 只返回已建档内容(未建档元素静默漏)——行为异常先查日志定位环节,再走画面入口序;VLM 只补漏,不当第一入口。

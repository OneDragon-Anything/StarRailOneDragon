# 0398 CollectPlaneIntel boss 节点定位改特征判:详情条「首领」标签验证 + 徽章态分流(W221)

- 状态: accepted
- 日期: 2026-08-27
- 关联: ADR-0397(W219 实采通道,本 ADR 修其定位/结论环节)、test_cw_node_boss.py
  (头像态 boss SIFT 锁)、run 29/30 同夜实证(2026-08-26 23:46/23:52)

## 背景(run 29/30 同夜实证,证据=.debug/sr_od_mcp/screenshot/screenshot_20260826_235229_827926.png
+ main_server.log 23:46/23:52 段)

W219 落的 CollectPlaneIntel 采集循环假设「点最右节点 → 详情条大图标 SIFT 必能认出
boss」(头像态)。run 29 三位面 SIFT 断层命中(11/13/5)证实头像态成立;**run 30 位面 1
同一点击路径 SIFT 未命中 12 次 retry 耗尽停机**。取证(离线帧分析 + 逐圆 SIFT + VLM):

- run30 位面1 节点带 9 圆**逐圆** SIFT 对拍 boss_avatar 20 库全拒(最高 5:4 无断层,
  正确拒)——带内**没有 boss 头像圆**;
- 点最右圆后详情条显示「1-9 **首领节点**」+「当前位面的首领挑战,请小心应对。」,
  左侧大图标=**通用金色徽章**(VLM 客观描述:对称放射纹样,非人脸;放大 6× 确认)。

**结论:boss 节点有两种渲染态**——头像态(节点=红框头像,大图标 SIFT 可认)与
**徽章态**(节点=通用金色徽章、详情条只有「首领节点」+通用描述,**本屏无任何 boss
身份信息**)。何时出现哪种态未探明(run30 局=投资策略「财富造物主」+A8 中局,run29
同夜即头像态;用户预警过节点排布随投资策略/局随机变)。关键澄清:**位置先验
「最右=首领」在 run30 并未被证伪**——点最右圆详情条即「1-9 首领节点」;被证伪的是
「最右节点必带头像可 SIFT 认身份」。

另发现旧代码连锁缺陷:battle_loop 实采写 session 时 `[n for n in ... if n]` **滤掉
None** ——徽章态位面采得 None 后,后续位面名字左移错位(与 ADR-0397 修的按序错位
同病,只是来源从「简报序」变成「滤 None」)。

## 决策

1. **定位 = 位置先验(最右)+ 详情条「首领」标签验证**:点击最右圆后 OCR 详情条
   「文本-节点类型名」(run30 实锺「首领节点」全字命中):含「首领」→ 确是 boss
   节点;不含(节点带误读/布局变)→ retry 兜底,位置先验失效有出口。
2. **结论分流 `conclude_plane_boss(label, sift_name)`**(纯函数):
   - 标签=首领 + SIFT 命中 → record(头像态真值);
   - 标签=首领 + SIFT 未命中 → **skip:记 None 跳过该位面**(徽章态是确定性渲染,
     重点也不会变,retry 是空转);op 层加一帧零点击复读防「标签已更新而大图标
     未换」的半更新帧误跳;
   - 标签未读出 → retry(过渡帧/OCR 失败,不得当徽章态误跳)。
   修复后 run30 型局每位面 ~2 次点击即过,不再 12 retry 耗尽;三位面尽力采,缺失
   位面在完成日志披露(`位面N boss 未取得…boss_fit 走中性`)。
3. **保位传递**:session.briefing_bosses / state.plane_bosses / ScoreContext.bosses
   类型放宽 `list[str | None]`,battle_loop 保位写 3 槽(None 原样);boss_fit 跳过
   None 项、全 None 返 None(=无信息,动态权重剔除,与空表同形)——缺失位面
   boss_fit 自然中性,有效位面照常参与。
4. 候选方案取舍:
   - A(带内逐圆 SIFT 特征判定 boss 位)——拒:run30 带内本就无头像圆,特征判
     定不了身份;且定位环节位置先验+标签验证已闭环,带内 SIFT 只剩佐证价值
     (classify_node_row 保留,零假阳已被锁①钉死);
   - B(详情条标签定位)——**采纳一半**:标签作**验证锚**而非定位锚(定位仍点
     最右,因为不点开节点详情条不显示该节点类型;标签验证点对了没有);
   - C(A+B 双保险)——实质即本决策 1+2 的组合(位置点击+标签验证+SIFT/徽章
     分流),带内 SIFT 不再单独跑(大图标特征 70+ vs 小图 ~17,严格更优)。

跨玩法影响:无——改动全在 `sr_od/` CW 域。

## Considered Options

- O1(采纳):位置先验点击 + 详情条标签验证 + SIFT/徽章分流 + None 保位传递。
- O2(拒):弃位置判改纯特征判(带内逐圆 SIFT 找头像圆)——徽章态带内无头像圆,
  特征判无从命中;且多圆 SIFT 成本高于单大图标。
- O3(拒):徽章态位面换通道采身份(如敌人信息浮层读 boss 波次)——浮层是否含
  位面序 boss 身份未探明(画面档「待探」),属新通道立项,不是本缺陷的修复;
  记进度树挂账。
- O4(拒):SIFT 未命中继续 retry(现状)——徽章态确定性渲染,retry 空转已由
  run30 12retry 实证。

## 后果

- run30 型局(≥1 位面徽章态):采集 ~17s 内完成,缺失位面 None;boss_fit 对应
  位面中性(与无数据同形,安全侧不变)。
- session.briefing_bosses 可能含 None:消费方(boss_fit/current_boss/遥测)已适配;
  判读注意 `开局 boss 实采完成(位面序保位…)` 日志里 None=徽章态,非采集失败。
- 待探(下次遇徽章态局补):徽章态出现条件(投资策略?局随机?);徽章态 boss
  的身份是否有别的显示位(敌人信息浮层/战斗内)。
- sim 不建模 briefing_bosses(既有缺口,ADR-0219/0233 同类),本决策不扩。

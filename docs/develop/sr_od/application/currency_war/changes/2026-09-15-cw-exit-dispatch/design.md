# 货币战争退出链分发结构重排（cw-exit-dispatch）迭代设计（总纲）

## 0. 元信息

- **迭代目标**：修复退出对局操作（`CwEntryExit`）在「画面已认出却无处理去处」时的死循环；把退出链的画面分发改为穷举归档的三类结构。出处 = 2026-09-15 退局卡死事故排查（用户逐屏裁定清单，本文 §2.2）。
- **状态**：草案（待对抗审）
- **文档清单**：无详设——单文档设计，本篇 §2 即完整设计。

## 1. 问题与动机

### 1.1 现状症状

- 2026-09-15 两次独立运行（07:05 / 09:55）在同一点卡死：「备战退局发起」节点返回状态「按钮-退出对局」累计 966 次，一条龙原地空转（日志实证 `.log/mcp_server.log`）。
- 直接原因：卡死时画面为「货币战争-列车同行」（选伙伴强制引导，建档 id_mark=选择伙伴+购买经验）：游戏在该态下禁用左上角门形退出图标，点击无响应，「中断挑战弹窗」永不出现。

### 1.2 根因归层（表示/约定/流程/语义）

**流程层（消费结构）**。画面识别每一轮都正确（全集建档识别返回「货币战争-列车同行」，建档层经 60 屏全量交叉审计 + 事故帧逐屏实证为干净，排查报告 `.debug/temp/cw_idmark_audit_report.md`）；`ROUTE_BY_SCREEN` 本义 = 「可走退出流程后续节点的画面」分发表，语义正确；故障在表外：列车同行不在表内，而表外画面没有定义去处——识别结果被丢弃，落到手写「备战双锚」（购买经验+出战，设计意图为穿透底图判定）——双锚恰好穿透选伙伴弹窗，误判为可退出的干净备战。

同族史：T-163 事故（复制判据漂移）为第一次，重写出调度器但保留了「清单外即丢弃」骨架；本次第二次（跨件半问）→ 升级结构级修复，不做第三处症状补丁。

### 1.3 解决到哪 / 明确不解决什么

- **解决**：①分发结构反转——认出的对局中画面穷举归档（直接退出 / 委托处理 / 战斗兜底），无「丢弃」去处；②「可交互备战」判据统一为框架建档判定（替换两处穿透双锚误用）；③五张对局前/大厅态画面移出对局中名单（前缀误收修正）。
- **明确不解决**（各归在册/另行）：武装箱弹窗档死区「按钮-开箱点击」清理（M19「点箱开箱」误建模残留，核查实证零消费，可经 MCP 安全删除；待运行腾空后执行，避免运行中热更新建档）；一条龙调度层对应用失败的止损行为（另行核查，本迭代只保证退出 op 自身有界失败）；无 id_mark 屏（战斗/战斗暂停/战斗结算/补给锁定/道具详情弹窗）的建档识别能力（维持现状：排除法与单锚 area 判定路径不变）。

## 2. 方案

### 2.1 分发结构（路由节点判定顺序）

画面路由（`CwEntryExit.route`）每轮截图按序判定，**认出的画面必有去处**：

| 序 | 判定 | 去向 |
|---|---|---|
| ① | 全集建档识别（`get_in_match_screen_name`，单一源 `cw_screen_state`） | 得屏名或 None |
| ② | 屏名 ∈ `ROUTE_BY_SCREEN`（7 张退出过程画面） | 跳对应退出链节点（现状不变） |
| ③ | 屏名 ∈ 直接退出名单（§2.2 A 类） | 跳「备战退局发起」（点门形图标） |
| ④ | 认「货币战争-大厅」白名单 | 大厅确认（现状不变） |
| ⑤ | 屏名非 None 且未命中②③④（= 全部非退出流程的对局中画面，**默认委托**；§2.2 B-1 清单为设计对照与审查底账，不落运行时名单） | 跳「委托对局循环」节点（`CwLoop(stop_at_prep=True)`），处理到干净备战交还，回 ①。唯一特判：屏名 = 敌人信息浮层 → 「敌人信息关闭」内联节点（loop 无该分支；点建档「按钮-关闭」，until 标识消失，回 ①） |
| ⑥ | 屏名 None（认不出） | 未建档画面/过渡帧——穷举清单已覆盖全部建档画面，能落到此的只剩清单外：重试数拍等画面稳定，连续仍认不出按计数判战斗中 → 右上 X 兜底（保留现有连续计数与战斗兜底；**删除现有 miss 链中「委托一次 CwLoop」步骤**——已建档画面在⑤全部有去处，落到⑥的未建档画面委托对局循环同样无力，该步骤纯冗余） |

与现状的两处结构差异：

1. **②与③之间不再落任何「穿透双锚」判定**——「能不能点退出」由③的屏名名单表达，双锚退出分发判定删除。
2. **①的识别结果不再丢弃**——⑤为表外画面定义默认去处（委托），`ROUTE_BY_SCREEN` 保持本义（可走退出流程画面的分发表）不变，缺项无害化。

**直接退出名单（A 类）的判定与共享**：A 类 = `{货币战争-备战, 货币战争-备战-免战}`，判定 = ①返回的屏名属于该名单（屏名白名单，非备战档全锚判定——免战画面「出战」标志被「跳过」替换，备战档四锚判定对免战恒 False，依据 = 归档帧 `sr-od-test/screens/货币战争-备战-免战/跳过态.webp` 实拍：布局同备战，仅右下按钮不同，门形退出图标照常在）。该名单定义为一处常量（放 `cw_screen_state`，对局中态判定同模块），路由节点③与对局循环停机位（下条）共用，禁两处各写一份。退局发起的点击坐标复用备战档「按钮-退出对局」纯定位区（左上角门形图标，免战画面同位同图标，归档帧实证），免战无需独立 area。

**对局循环停机位判据同步**（`CwLoop` stop_at_prep，现 `cw_loop.py:1693` 用穿透双锚 `_prep_anchors_hit`）：改为「识别屏名 ∈ A 类名单」（同上常量）。语义从「底图是备战（穿透）」收紧为「可交还退出 op 的备战态（含免战）」。穿透双锚本体保留——其余三个调用点（发射仲裁预检 `cw_loop.py:680`、0e 复探门 `:904`、C3 确认 `:570`）语义为「底图判定」，有意穿透，不动（依据 = 各处 docstring 明文）。

**互踢推演（同源成立性）**：委托后对局循环置顶停机位与路由③用同一常量同一判定 → 两侧对「是否已到可交还态」结论恒一致：B 类浮层在场时双双判否（对局循环继续用 0 系分支处理浮层），处理完双双判是（交还 → 路由③直接走退局）。不存在「一侧说到了、一侧说没到」的往返。

**已知的未验证假设（实机验证项登记）**：免战画面点门形图标会正常弹出中断挑战弹窗（与干净备战同款交互，推测成立、未实测）。落地批实机验证必须覆盖；若证伪，免战移出 A 类单列处理，禁静默。

### 2.2 逐屏归档清单（对局中全集 47 张 + 移出 5 张，用户逐屏裁定）

**移出对局中名单（5 张，加进 `cw_screen_state.LOBBY_STATE_SCREENS`）**：货币战争-难度确认（对局开始前选难度画面，归档帧图证）、货币战争-数据银行、货币战争-装备图鉴、货币战争-竞争对手图鉴列表、货币战争-竞争对手图鉴详情（图鉴查询页，与已排除的攻略系同类）。效果：全集识别不再返回它们，「返回大世界」与退出链都不再当对局画面处理。

**A 类：直接退出（2 张）**：货币战争-备战、货币战争-备战-免战。

**B-1 类：默认委托对局循环（28 张，全部有现成分支，括号为 `CwLoop` 分发分支号；此清单为设计对照底账，运行时为「非②③④即委托」，见 §2.1 ⑤）**：列车同行(0a)、选择装备(0a0)、骇入策划(0a2)、命运卜者强化(0a3)、位面详情(0a4)、盛会之星(0b)、遭遇节点(0c)、未达上限警告(0d)、投资策略(0e)、补给(0e1)、武装箱弹窗(0f,节点发箱的获得说明弹窗)、备战-武装箱选择(0f2,开箱后装备四选一)、商店刷新概率表(0e2)、祈愿试炼(0h)、星徽秘典弹窗(0i)、备战-专家邀请函(0k)、商店卡牌详情(0t)、备战-角色详情(1b)、备战-策略锁定(0m)、备战-遭遇锁定(0m)、提示-前台无角色(0j)、BOSS简报(0p)、简报(0r)、投资环境(0s)、位面过渡(0q，委托 `CwScreenPlaneTransition`)、备战-开商店(0n 收起)、备战-角色信息提示、备战-装备详情浮窗（后两屏无关闭交互 area——建档仅 id_mark，清场注册表无法按屏登记；**裁决维持委托现状**：⑤委托 CwLoop 兜得住且非死循环形态，退出场景仅观察采集模式可达、基本不可触；「补关闭 area + 清场派生集登记」降级为后续卫生批，登记处 = `kernel/cw_overlay_registry.py` OVERLAY_REGISTRY）。

**B-2 类：退出链内最小处理（1 张）**：敌人信息浮层——新节点点建档现成「按钮-关闭」，`until_not_find_all=[(货币战争-敌人信息浮层, 标识-敌方信息)]` 验关闭，回路由。触发场景 = 观察采集模式（自动对局不打开，低频）。

**备忘档（3 张，无 id_mark = 识别层结构性不可达，不占屏名分发，走⑥兜底，局限如实申报）**：备战-补给锁定、战斗结算（过渡帧通常自动推进离开，停留即异常态；其页对⑥战斗兜底右上 X 的响应未验证——局限申报）、道具详情弹窗（对局内由 loop 0e3 单锚分支接住；退出场景 bot 不会主动打开它，真出现走⑥兜底，同上局限申报）。

**C 类：认不出 → 战斗中兜底（1 张在册 + 任意未建档帧）**：货币战争-战斗（无 id_mark）→ 连续未识别判战斗中 → 右上 X → 战斗暂停 → 撤退（现有节点不变）。

**退出过程画面（7 张，`ROUTE_BY_SCREEN` 既有，不经分发）**：中断挑战弹窗、结算、结算-失败、挑战失败、结算-对局详情、结算-战报、战斗暂停。其中战斗暂停无 id_mark，路由表该项为不可达死项——实际路径 = 「战斗中点右上X」节点的直边（until 单锚命中「标识-战斗暂停」）；本次将该死项从 `ROUTE_BY_SCREEN` 移除并注释说明真实入口，防后来人误依赖。

对账：5（移出）+ 2（A）+ 28（B-1 对照底账）+ 1（B-2）+ 3（备忘）+ 1（C）+ 7（退出链）= 47 ✓。

### 2.4 关键取舍（备选与为何放弃）

- **把列车同行等浮层屏逐个补进 `ROUTE_BY_SCREEN`**：放弃——该表辖退出流程自身画面，浮层屏若逐个入表，每张还需配专属处理节点，新增画面仍需人工同步，漏登即复发；默认委托让表外画面零维护，表保持本义不膨胀。
- **仅给「选择伙伴」加排除特判（双锚命中前查选伙伴锚）**：放弃——逐浮层打补丁，下一浮层复发；穷举归档 + 默认委托对新建档画面结构性生效（全集识别建档即收）。
- **B 类直接调用各画面 op（不经 CwLoop）**：放弃——需在退出链维护「屏名→op」第二张映射表且复制 loop 的分发序；委托 CwLoop 复用其既有 0 系分发与停滞看门狗，单一出口。
- **停机位维持穿透双锚**：放弃——穿透语义下委托「选择伙伴」帧会被立即交还（双锚穿透弹窗可见），与路由③互踢死循环（推演见 §2.1）。

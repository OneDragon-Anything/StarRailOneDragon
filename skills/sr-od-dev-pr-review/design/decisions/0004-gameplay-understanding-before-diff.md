# 0004. 游戏流程 PR 先建玩法理解再看 diff

- **Status**: accepted
- **Date**: 2026-08-04(形式化日;决策本身随 skill 创建 ~2026-07)

## Context
直接读 diff 容易「见树不见林」—— 不懂玩法目标与画面流转,难判断改动合理性、识别流程缺失/画面未建模。先建玩法理解再看代码,审查更准更快;它也是 L2 背景核实的前置(L2 核实 PR 描述的 bug/行为是否属实,需先懂玩法)。踩坑:#2300 review 时中途用户提醒「先了解玩法」才去查以太电池机制(60 电量/储值电卡合成);若 skill 有这条,开审就查,不必中途补。

## Decision Drivers
- **审得准**:带着玩法理解看 diff,能判改动合理性 + 识别流程缺失。
- **前置 L2**:L2 背景核实需先懂玩法。
- **避免中途补查**:开审就查,比审到一半发现不懂再补高效。

## Considered Options
1. **直接读 diff**:见树不见林(实测 #2300 中途补查)。
2. **每个 PR 都先建玩法理解**:非游戏流程 PR 无必要(浪费)。
3. **L0 判「继续」的游戏流程类 PR,L1 前先建玩法理解**(选中):仅游戏流程类,非游戏流程跳过。
4. **等 L2 再查玩法**:L2 已是核实 bug,前置理解应更早(L1 前)。

## Decision
选 3:L0 判定「继续」的游戏流程类 PR,L1 静态审查前先查 `docs/game/gameplay/`(玩法机制)+ `docs/game/screens/`(画面建档)有无相关玩法/画面建档 —— 有则先读,建立「这玩法是什么、目标/资源/循环、走哪些画面」的初步理解;无则先查玩法(网络攻略/wiki/实玩)。带着玩法理解再看 PR 代码。非游戏流程 PR 跳过本步。

## Consequences
- **正向**:审查更准更快;识别流程缺失/画面未建模;作 L2 前置。
- **负向**:对无建档且攻略稀缺的玩法,建理解耗时;判「游戏流程类」靠 L0 人判。
- **follow-up**:无。

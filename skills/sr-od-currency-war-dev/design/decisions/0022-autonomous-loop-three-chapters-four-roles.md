# ADR-0022: autonomous-loop 三章节化与提醒网四角色(修订 0021 落位表)

- 日期:2026-08-26
- Status:accepted(supersede ADR-0021 的落位表;0021 的「只被读一次/再注入通道」原则不变)

## 背景

ADR-0021 定的重构方向(过程纪律迁再注入通道)在实施中经用户多轮裁决演进:七角色→三职责(实机监控/进度处理/review)→四角色(review 拆自省与子 agent 审计;review 间隔定 20min)。文件结构也从「编排资产罗列」改为**三章节框架**:①AGENTS.local 写入内容(待定)②schedule(每节=分类/间隔/职责/提示词模板)③哨兵脚本位置。

## 决策

- **文件只留三章**:AGENTS.local 候选 / schedule 四角色 / 哨兵位置。派单硬规范①-④迁入 SKILL.md「派单规范」节(每轮必读锚);数学期望标尺并入 strategy-work.md(策略通用面,非自主推进专属);「做事按 skill 来」删除(AGENTS.local 六字段已承载);编排架构/授权边界/goal-schedule 消费描述删除(ADR-0020,授权边界后补回公共 skill §2)。
- **四角色**:实机监控 10min(状态)/进度处理 15min(按进度派活尽量派满,进度树=唯一队列源)/回顾 20min(主 agent 三问:实质推进?遵循 skill?打补丁?)/子 agent 审计 2h(偏见敏感条目)。间隔互质,创建错峰。
- **提示词纯度原则**:提醒词只写通用骨架,不内联领域判据例示——回顾三问是通用问句,CW 专属门靠问 2「和哪些 skill 相关」路由到 skill 各节(判读三问/交付验收/派单规范)。依据:例示即第三源,skill 改门提醒词就是僵尸;提醒词=最小完整单元(与 ADR-0009 互补)。
- **C 源(同族第 2 件问同根)归 review+交付验收泛化步**(用户裁:review 层),不进进度处理行;E 源归 skill 遵循回看面。

## Considered Options

1. 七角色保留加厚——否决:职责混乱(事件时刻纪律与周期兜底混装、检查项分行重复面);
2. 三角色(review 合并)——否决:自省高频轻量、子 agent 审计低频重开销,合并则审计被 20min 频率绑架或自省被 2h 频率饿死;
3. 四角色+三章节(选)。

## 后果

- autonomous-loop.md 定位=入场建网配置说明书+事件节(哨兵消费),「只被读一次」声明入导语;
- strategy-work.md 新建(策略统一说明:思路/核心/改前/验证/裁决)——策略从 checklist/滤网的寄生状态升为实体文档,单一源地图/分诊表接路由;
- SKILL.md 玩法疑问分流节并入策略工作节;判读节路由直指 research/README 任务路由(消双跳);
- research/README 新增「策略相关文档」节(基线=research 全部+data 未建模全部,唯一排除 screen_flow_timing;单一源在此,消费方指本节);data/README 已删文档行收敛为「已入注册表别再造」+注册表全景指 06_input_model。

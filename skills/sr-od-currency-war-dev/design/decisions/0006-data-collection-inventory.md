# ADR-0006 采集全景含运行时钩子清单(不止静态来源)

## Status

accepted(2026-08-22;用户指令「采集全景沉淀进 skill,还有连胜金币、节点类型等,看看有没有采集 hook」)

## Context

游戏数据来源不全是静态采集(生成器/图鉴实采)——部分域靠**运行时钩子**积累(连胜档金/节点奖励明细的临时采集钩子、词缀效果的常驻自写、未识别卡/图标的兜底停机)。只记静态来源的清单会让人误以为数据齐了,或忘了临时钩子的存在与删留条件。

## Considered Options

1. 只记生成器族+图鉴实采(静态):覆盖大头,但运行时钩子散在代码注释里,无人盘点即积压(实证:shots 目录里 obs_conflict_* 四个前缀各 300-400 张)。
2. **静态+运行时+派生四节全录**(选):plaza API 族/图鉴实采/运行时自采(每钩子带状态与删留条件)/派生层。
3. 钩子清单交给 od-dev-stop-hooks 管:那边管**生命周期纪律**(临时 vs 常驻/删留/停机分流),本 skill 管**数据域盘点**——职责交叉但视角不同,各自保留(交叉处互指)。

## Decision

选 2,与 3 的边界:本文件 §采集钩子纪律只留一段判据+指针到 od-dev-stop-hooks;钩子逐个的现状(在/删/采了多少样本)归本文件,因为「数据还缺什么」是数据视角问题。

## Consequences

- 钩子状态是**快照**,会过期——本文件记钩子的「域名/机制/删留条件」(稳定),样本数等易变量不写进(用时不查快照,查 shots 目录现状)。
- 新增采集钩子时同步补表(否则清单失效);删钩子时同步标记。

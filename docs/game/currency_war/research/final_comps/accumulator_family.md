# 全局累积型角色族(判据 / 成员 / 形式化;W127;2026-08-27 定稿)

> **来源**:用户定谒 2026-08-26(user_playstyle [21] 定谒注)——「万敌可能是个例外,因为他的技能,
> 是全局货币战争不断累积的,肯定是越早上越好……类似的全局累积的角色应该还有其他的,也可以一起考虑一下。」
> 本篇 = 该待办的交卷:判据定义 + 全量扫描 + 形式化落点(COMP_LIBRARY `global_accumulators` 字段)。
> 证据等级标注:用户口述(最高权威)> 机制文本(高)> 攻略叙述(中)> 推测(低)。

## 1. 判据定义(什么算「全局累积型」)

**四条全满足才是本族成员**:

| # | 判据 | 说明 |
|---|---|---|
| ① | 累积载体是**角色自身的属性/计数/费用档**(生命上限、伤害增幅、层数、费用),非仅场面状态 | 排除「羁绊层/装备层的场面成长」 |
| ② | 累积**跨节点持久**(节点切换/新战斗不清零),或用户口述确认为全局 | 区分「永久(局内)」歧义:技能文本的「永久」本身不证明跨节点,**必须口述或实测背书** |
| ③ | 累积**直接转化为战力或经济**(伤害/面板/费用档/经济产出) | 排除纯计数不产出的状态 |
| ④ | 累积速率与**场上事件/上场时间正相关**(受击、行动、开大……) | 这条决定「有空位就上」是否适用——**早上场=更多累积窗口**只在④成立时有意义 |

**与「局内瞬时成长」的边界**(判据②反向):仅本节点战斗内叠层、节点结束清零的成长——
火力风暴潮叠强度、燃血角斗场记录池、风堇小伊卡治疗记录、远坂凛宝石、Saber 炉心共鸣、
黑天鹅奥迹、白厄聚合、反重力皮靴速度叠层——**全部不是本族**。它们解释的是「战斗越长越强」,
不解释「越早买越早上越好」。

**判据④把族再分两类**(形式化需要,见 §4):

- **场上驱动型**(①②③④全满足):适用「有空位就上」部署例外——唯一确认成员:万敌。
- **购买驱动型**(①②③满足、④不满足):累积持久但速率与上场无关,由买/D 驱动——
  「早买早 D」适用(已被 [22] 囤件纪律与 level_plan 建模),「早上场」**无增益证据,不豁免**。
  成员:银狼LV.999(升费链)。

## 2. 全量扫描结果(cw_chars 75 名 + final_comps 十类机制叙述过筛)

扫描方法:`cw_chars.py` 全角色 + `cw_chars_data.PLAZA_ROLES` 技能名过一遍 → 对 final_comps
各篇「机制原文」节里含「永久/叠加/成长/累积/升费」语义的条目逐一过判据。

### 2.1 确认成员(场上驱动型)

**万敌**(1费,夜之半神+燃血)——累积类型 `hp_charge_stack`

- 机制原文(wandi 篇内嵌技能文本,高):star1「行动时施放战技进行攻击并积攒充能以施放
  【弑神登神】,且**永久提高生命上限**」;star2/3「施放【弑神登神】时生命上限永久提高,
  **生命上限使【受伤充能】额外提高**」——正反馈环:挨打→受伤充能→弑神登神→生命上限↑→
  充能效率↑(且上限本身喂记录池)。
- 跨节点证据:用户口述(最高权威,2026-08-26)——「他的技能是全局货币战争不断累积的,
  肯定是越早上越好」。
- 累积什么:生命上限 + 受伤充能效率;清零条件:无记载(口述语义=跨节点不清零)。
- 部署含义(口述原文):「先上过渡羁绊,有空位就上万敌」;万敌篇攻略语料互证
  (#14「2dot2学者加后台奶瓶万敌过渡」——Early 即在场,56% 局 P1 板上,plaza 数据)。

### 2.2 辨析后成员(购买驱动型,不豁免部署)

**银狼LV.999**(3/4/5 费三档,星核猎手+欢愉)——累积类型 `cost_escalation`

- 机制原文(yinlang 篇,高):星3 天赋「【隐藏分】档位上限额外提高 N 阶,普攻获得【阿哈】
  的属性加成」——升费链:3费2星→4费→5费,费用档**永不清零**,直接转化为面板
  (普攻吃阿哈属性,5费完全体)。
- 判据过筛:①费用档=角色自身载体 ✓;②持久 ✓(备战不升费、上场保留档位);
  ③转化为战力 ✓;**④✗——升费由 D 牌升星驱动(#22「7级D牌找2星3费银狼变4费」),
  速率与上场时间无关**。
- 结论:**不适用「有空位就上」例外**;「早买早 D」已由 [22](弃购期望账)与狼尊欢愉
  level_plan 建模,无需新规则。形式化上仍标注类型(与万敌区分),防止后续策略批
  把两类混同处理。
- 「欢愉星魂分流」候选辨析:银狼线的欢愉羁绊叠的是**阿哈的装备栏/星级**(羁绊层,
  场面状态),非角色自身累积载体(判据①✗)——不构成银狼的第二个累积维度。

### 2.3 存疑候选(机制文本有「永久」字样,跨节点未证实——标存疑,不进形式化)

证据三层纪律:机制解释不成立的/未证实的高频做法标存疑。以下两条**技能文本含
「永久提高」但无跨节点证据**(攻略叙述均描述为「随战斗时长上升」= 局内曲线),
待实测(跨节点后面板是否保留)后升降级:

- **绯英**(2费,欢愉):「施放终结技时获得【阿哈】的属性加成,**并永久提高伤害增幅**」
  (feiying 篇,机制文本=高;但同篇解读「一条随战斗时长单调上升的曲线」= 局内口径;
  cw_comps 攻略注「绯英大招永久+2%伤害(无限成长)」同歧义)。若实测跨节点保留,
  升格为场上驱动型成员(类型 `permanent_amp`)。**存疑原因**:局内成长与全局累积在
  技能文本上不可分,只有节点切换后面板能仲裁。
- **黑塔**(1费,群攻):「敌人被消灭后**永久提高前/后台强度**」(daheita 篇,机制文本=高;
  同篇解读「可成长弹药」为局内口径)。同上待实测。

### 2.4 明确排除(说理由)

| 候选 | 排除理由 |

## 3. 启用环境条件(「特定环境才选」约束)

定谒原文:「但这个阵容,应该有特定环境再使用,不然有点弱。」族内成员的环境条件:

| 成员 | 启用环境(强) | 弱/避环境 | 证据 |
|---|---|---|---|
| 万敌 | **敌方多动/反伤类词条**:正当防卫、忍无可忍、应激反应、一鼓作气、灼热轰炸(成型后)、反伤类(受击=燃料;cw_comps `MECHANIC_SYNERGIES['反伤']→燃血` 已建模) | 永久创伤(掉血削上限,重开级)/红绿灯(机械 counter)/贝洛伯格加血机器/低攻频怪(#28) | 万敌篇词条矩阵,高 |
| 银狼LV.999 | 升费资源链可支撑(等级 7→9 + D 牌经济;骇客专家:银狼策略/欢愉星徽信号) | 正当防卫/能量逃逸/时间刺客/忍无可忍(克多动+大招频率) | yinlang 篇,中-高 |
| (存疑)绯英 | 同欢愉族 counter 面;若升格,环境=大招频率友好(能量体系) | 正当防卫/能量逃逸类 | 中 |
| (存疑)黑塔 | 敌方数量多(击杀驱动叠层)+ 黑塔纪元策略 | 坠入陷阱/正当防卫/冰之熄火 | 中-高 |

**环境不满足时**:该 comp 选线降权(万敌线无敌方多动类词条=受击引擎缺燃料,不选);
这不是对「早上累积型」例外的取消——例外只在**已选该线且环境成立**时才生效。

## 4. 形式化方案(COMP_LIBRARY 字段 + 部署例外规则翻译)

### 4.1 已落地(本批,数据层,零行为改动)

`Comp` 新字段 `global_accumulators: dict[str, str]`(角色名 → 累积类型):

- `'hp_charge_stack'`:场上事件驱动的全局叠层(万敌)——适用「有空位就上」例外;
- `'cost_escalation'`:购买驱动的升费链(银狼LV.999)——**不适用例外**,仅类型区分。

已标注:`万敌单C` → `{"万敌": "hp_charge_stack"}`;`狼尊欢愉` → `{"银狼LV.999": "cost_escalation"}`。
存疑成员(绯英/黑塔)**不标注**,实测升降级后再进字段(证据纪律)。

### 4.2 部署例外规则的形式化翻译(设计,**不实现**——归后续策略批)

「先上过渡羁绊,有空位就上累积型」翻译成部署判据:

```
前提(target 线已选定):
  comp = 当前 target;acc = comp.global_accumulators 中值为 'hp_charge_stack' 的成员
豁免条件(全部满足):
  ① acc 角色在手(已买,bench 上);
  ② 启用环境成立:当前/将遇敌方词缀 ∈ 该成员的强环境集
     (万敌 = MECHANIC_SYNERGIES 命中 '反伤'/'多段惩罚' 类,经 ScoreContext.mechanics 判);
  ③ 「有空位」= deployed < cap(人口有余量),或场上存在边际羁绊贡献低于
     累积期望的填充位/散件位([31] 梯队底端可被顶替)。
豁免效果:
  acc 的部署优先级提升到填充位之上——绕过 [21]「羁绊组齐才上」窗口约束
  (通用规则:final 件单上无用等羁绊齐;累积型例外:单上也在攒全局层)。
不豁免:
  'cost_escalation' 类型;环境不满足;未选该线。
```

**与现有 deploy 逻辑的接口**(消费点,实现时的落点):

- `decision_v2/candidates.py::_deploy_candidates` / `decision_v2/scoring.py::_deploy_pipeline`:
  部署候选生成/排序处读 `comp.global_accumulators` + `ScoreContext.mechanics`,给豁免成员加权;
- 现有 [21] 窗口语义(羁绊齐才上)的实现处需识别「累积型豁免」分支;
- sim 侧需同步建模(新字段三消费面纪律:策略/遥测/sim——遥测侧可加「累积型早上了几次」
  观察位,sim 侧至少让 deploy 代理透传该字段,防 sim 与实机分叉)。

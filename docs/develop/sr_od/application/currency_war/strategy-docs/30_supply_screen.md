# 30 补给画面策略(supply screen)

> 画面 = 货币战争-补给(补给节点的动态 N 选 1 选卡屏:每张卡 = 角色 + 自带装备,通常 4 选 1,可刷新重掷;**能力面** = [../screens/README.md](../screens/README.md) §5.2/§5.5)。本篇 = 该画面的**策略面**(宪法六「一画面一策略文件、一画面一策略文档」)。
> 决策本体 = `strategies/impl/mandate_v1/supply.py::decide`(纯值出口);动作包装与意向解析 = `strategies/impl/flow.py::decide_supply`(零参口);画面 op = `operations/cw_screen/cw_screen_supply_node.py`(观察 + 决策动作两 node,能力细节 = [../screens/supply.md](../screens/supply.md))。pick 族接口规格 = [13_pick_family.md](13_pick_family.md) §1 `decide_supply` 行,本篇不复制;数值单一源在代码(本篇只写常量名)。
> 术语:**锁线**(`locked_comp`)= 最终阵容已确定、此后围绕它买牌的状态(flow 解析意向状态后传入);**降格帧**(`demoted_endgame`)= 终局锁线已放弃的帧,一律按未锁口径;**凑星** = 同名同星角色集齐 3 张合成更高星级;**fail-closed** = 读数缺失时取不放行/不动作的保守分支。

## 1. 裁定登记(用户 2026-09-24)

本画面判据结构由四项用户裁定定死;立场序合法性 = 裁定本身(同 28 号稿立场分形态,数字三形态扩展【拍】的裁定来源):

1. **三级优先**:裁定原文「钻 > 角色 > 装备」——选卡比较序为三级字典序(§2)。
2. **终局名单**:裁定原文「想要的角色只为终局考虑,不按过渡阵容选」——角色级名单只取锁线阵容的核心成员与共享成员;未锁线帧角色级空转,降格帧按未锁口径。
3. **溢出席**:裁定原文「备战席满时选角色卡 → 角色入溢出席(不会失败)」——按机制事实登记(实机建档:溢出位 = 固定单槽),选卡侧无需席满特殊分支(§5)。
4. **刷新「三级全空才刷」结构**:裁定原文「存在任一非末级项 = 值得拿」(字典序下,手牌存在任一非末级项即值得拿、不建议刷)。**读法 A 确认记录**:该引文兼容两读——「末级」读作装备轴序数末档(tier 0,只看档位)或全序末项(tier 0 ∧ 通用值 0),两读在 tier 0 高通用值帧上行为相反;**用户确认取前者**(2026-09-24)——三级全空判定只看 `equip_tier` 档位、不看通用值,tier 0 内含高通用值件的帧仍属三级全空、仍建议刷(§3)。

## 2. 决策结构:三级字典序(零自由参数)

比较序 = **钻 > 角色 > 装备**(裁定①)。字典序而非加法合分:三轴量纲不可通约(人口位 / 终局阵容成员 / 装备),加法需新拍跨轴权值;字典序 = 裁定偏好的直接编码,零自由参数。代价:轴间不可补偿(终局成员卡永远压过高价值装备卡)——裁定本意。

决策入口(`supply.py`,纯值出口):

```
decide(options, gs, locked_comp: Comp | None, demoted_endgame: bool)
    -> SupplyDecision(idx, reason) | SupplyRefreshSuggestion(reason)
```

- `locked_comp` 由 flow 解析后传入(套名经 `get_comp` 解析:空串 = 未锁 None 无告警,解析失败 = None + 告警);`demoted_endgame` 为意向状态直通(True → 角色级与 key 参照一律按未锁口径;防御位)。
- **空候选帧**:`options` 为空 → `SupplyDecision(idx=0, reason="no-options")`(现役观察层/op 守卫下不应到达,纯函数定义须完备)。

**第 1 级 钻**:∃ `option.has_diamond` → 选;多张带钻 → 带钻候选集内依次进第 2/3 级比出一张。检测集 = {红钻, 蓝钻, 财富宝钻}(单一源 = `cw_node_obs.DIAMOND_EQUIP_NAMES`)。依据【注】游戏定义值:财富宝钻 effect 原文「团队规模上限+1,无论是否被角色穿戴」(人口位价值,与是否穿戴无关),红钻/蓝钻 = 星徽合成材料。
- 边界申报:「带钻压过角色/装备级一切候选」是裁定序(裁定①),不是已证支配论证——支配性论证挂 §6 数学挂账。

**第 2 级 角色(只为终局)**:激活 = `locked_comp` 非 None ∧ 非降格帧(裁定②;降格帧按未锁口径空转)。名单 = `Comp.core_chars ∪ shared_chars`(不含 `transition_chars`——过渡成员按裁定②不入名单);`char` 读缺(OCR 未命中,空串)的选项不进角色候选、仍参与装备轴(读缺不猜)。候选非空 → 在候选内选;多候选 tiebreak:①能凑星者先(§2.1);②仍并列 → 第 3 级装备比。角色级空转(未锁线 / 降格帧 / 全部 char 读缺)→ 全体进第 3 级。

**第 3 级 装备**:打分单一源 = 直调共享机器 `cw_equip_value.pick_equipment`((tier, base) 字典序,并列取输入序先者 = 画面列序;模块头「候选多选一禁第二套打分」裁定)。tier = `equip_tier`:3 = key 直击且需求未满足 / 2 = 近兑现 / 1 = key 材料 / 0 = 其余;`key_equips` 可含重复,需求按计数(已持够数的重复成品不再高分)。三参:
- `key_equips` = `locked_comp.key_equips`(与角色级同源;未锁 / 降格 → 空序列,全体落 tier 0);
- `owned_spare` = `gs.equips` 现值(备用库存账);
- `owned_total` = spare + 行域/备战席穿戴账(`deployed_rows_of` + `bench_units_of` 成员 equips 透传;照 `flow.decide_box_card` 两账先例,decide 内自 gs 构造)。

排序:tier 高者先 → 同 tier 按 `EQUIP_GENERIC_VALUE`(通用价值表,**降格为 tier 内定序常数**,16 号稿处置)高者先 → 仍并列输入序先。

### 2.1 凑星 tiebreak(第 2 级排序细则)

「能凑星」= 选入该角色后与全场(上阵行域 ∪ 备战席)同名 1★ 恰成 3 张(合成 2★)。判据 = `cw_merge_simulate.same_star_count(char, 1, bench, deployed) == 2`(全场域同名同星计数单一源);布尔判据零梯度(恰 2 张者先,count 1 与 0 不分档)。结构依据:同名合成升星是终局成员战力成长的既有通道,完成态优先、其余同列(设计细化,用户保留否决权)。

入参形状申报:
- `deployed` **须为行域展平的扁平 Unit 序列**——`deployed_rows_of` 返回 (front, back) 行域二元组,须展平拼接;直传二元组会被条目身份协议 fail-closed 静默跳过 = 上阵域漏计、凑星只数备战席。
- `bench` = `bench_units_of(gs)` 槽序裸 Unit(与 `same_star_count` 注解形状不同层——运行时经条目身份协议对裸 Unit 正确、计数等价,形状差在此申报)。

边界:补给入席单位恒 1★,3★ 合成不入判据(2×2★ + 1×1★ 不满足同名同星 ≥3 合一规则);`gs.board` 是上阵羁绊计数派生量(键 = 羁绊名),非本判据数据源;席满帧溢入单位不入 gs → 凑星漏计(§5 失真申报)。

## 3. 刷新判据

- **建议刷 = 且仅 = 手牌三级全空 ∧ 次数闸放行**(裁定④):
  - 三级全空 = 无带钻 ∧ 角色级无候选(或未激活)∧ 装备级全体落 tier 0(**只看档位不看通用值**——裁定④读法 A,tier 0 内含高通用值件的帧仍属三级全空);
  - 次数闸 = `gs.supply_refresh_left` 读数 ≥ 1,**闸内嵌 decide**(读数 None = 未观察 → 不建议刷,fail-closed;left 缺/尽 → 直接落第 3 级选卡)。
- **闸拒绝帧的产出语义**:闸内嵌后「三级全空 ∧ 建议刷但次数闸拒绝」的组合不存在(decide 只在读数 ≥ 1 时才可能返建议)。op 侧对照闸(容器剩余真值 + 刷新锚点)仅剩一种重调触发面:建议刷但刷新锚点缺失——重调同输入同输出(纯函数)仍返建议 → 零点击终结交回。
- **P1 配方锁帧边界形态**(开局配方锁局,`locked_comp` 恒空):角色级不激活、装备级无 key 参照(全体落 tier 0)→ 无钻帧三级全空恒真:有次数即建议刷,刷尽后按「钻或通用值定序」落选卡。
- 刷新只是建议——是否真刷由画面 op 按现读次数裁决(失败安全);重刷期权的期望账不进判据:钻石出现概率实采前任何期望式都是占位(§6 挂账),现行判据是裁定结构,不声称期望最优。

## 4. 输出契约与接线

- 纯值 dataclass:`SupplyDecision(idx, reason)` / `SupplyRefreshSuggestion(reason)`,不含动作词表(与 `invest_env`/`deploy_plan` 同构,便于直测与 sim 复用预留)。
- flow 零参口 `decide_supply`:候选自 `gs.supply` payload;意向同源自意向状态(`locked_comp` 套名经 `get_comp` 解析、`demoted_endgame` 直通);`RefreshSuggestion` → `CwActionRefreshSupplyParam`,`Decision` → `CwActionPickSupplyParam`。词表、op handler、观察写槽、终结链零判据逻辑(对照闸语义见 §3)。

## 5. 席满与溢出席

- **选卡侧无席满特殊分支**(裁定③):席满帧照常选角色卡,游戏侧角色入溢出席(机制事实:实机建档溢出位单槽)。
- **记账失真申报**:记账层不建模溢出席——补给角色腿席满拒落零写,溢入单位对 `gs` 不可见,§2.1 凑星判据对该单位系统性漏计;溢出位已被占的实机语义未核。失真归观察/记账批;触发器 = 实机席满补给帧判读(该帧凑星漏计不判为异常)。

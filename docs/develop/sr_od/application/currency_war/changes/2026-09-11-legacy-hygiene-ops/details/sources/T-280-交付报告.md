## ① 结论(归层)

**2 例降级 WARNING 的分叉根 = bench 布局真相双源:`tracked_bench_chars` 的「列表下标布局」(mutate/simulate 动作面消费)与「BenchChar.slot 字段」(投影播种与 guard 构造消费)脱节;脱节的持续制造者 = `reconcile_tracking` 写回紧凑列表(L231,形状契约破坏点)。buy 落洞动作(`bench_place` 首空槽)在两域各按自己的布局找洞,洞位置不同源 → 新卡落槽不同 → 槽序排列分叉(成员集不变 → 多集等价 → guard 降级 WARNING)。**

归层判定(按任务卡五层):**执行域双账状态建模缺陷**(与 T-182 所修 tracked 账同族,为其姊妹面),**触发器在对账域**(reconcile 写回),**跨域接缝缺失**(对账 churn 事件不广播、投影只在段顶播种+guard 炸点两个硬点接 tracked)。任务卡预告的「跨 reconcile/投影两域」判定成立;但诊断比任务卡口径更深一层:**两例实证的分叉不是「churn 发生后投影未跟随」,而是「对账写回制造的布局双源让两域在 seed 播种时刻就读出不同布局」**——因此治本不只是「churn 事件接投影链」,必须先消灭双源(见 ③ 方案 S1+S2),事件通道(S3)是防复发的结构补全。

守卫(`guard_expected_vs_tracked` 多集等价分支)按设计工作无责:降级不炸+按 tracked 重播种是任务卡申报的症状治理;但其 tracked 构造同样消费 slot 字段(L239 `bench_from_compact`),Warning 消息里 tracked 值本身已是双源显影后的第三种布局,判读时不可当画面真值。

## ③ 变更面(方案稿;本批零代码)

### 方案正本:布局真相单一源化 + churn 事件接投影链(三层,主张 S2 为充分主修、S1 为结构防御、S3 为任务卡正题的结构通道)

**数学先行**:

- 不变量 I:∀ 商店 visit 内动作帧 t:`layout(state.bench) == layout(tracked_bench_chars)`(下标布局逐槽相等)。
- 引理 1(转移同构,已由代码单一源保证):两域动作转移全部经同一 helper 家族——buy=`bench_place`+`_merge_bench`、sell=`bench_clear`、deploy=`bench_clear`+`deployed_place`(mutate 与 simulate 同源,T-182 已同构化满栏分支)。相同输入布局 → 相同输出布局。
- 引理 2(播种同构,方案目标):seed 时两域起点为同一列表布局。
- 定理:引理 1+2 ⇒ I 归纳成立 ⇒ guard 多集等价分支(Counter 相等而序列不等)前提结构性不可达,守卫回归纯断言职责。
- 现状反例:seed 时刻两域起点即不同构(引理 2 不成立)——投影=slot 重构布局,tracked=紧凑演化布局,故 I 恒假,每次落洞动作放大一次差异。

**S2(主修,充分条件):对账写回恢复形状契约+重建布局。** `reconcile_tracking` 写回前把 SIFT 读经 `bench_from_compact` 转**槽位表**(画面槽号→下标,定长 9)再写 `tracked_bench_chars`。效果:写回后列表布局=画面布局(洞在真实位置),slot 字段与下标天然一致(下标+1),紧凑态从写入端消失;消费端 `bench_from_compact(pad 态且 slot 健康)` 退化为恒等,两域播种自动同源。

- **同构先例(方案审正面核实采纳)**:同函数 deployed 侧写回已是此形态——cw_reconcile.py:236-237 `deployed_from_compact` 转槽位表(ADR-0392 单一源适配);bench 侧是同构修法的漏网侧。**S2=补齐既有模式,非发明新机制**;落码批 ADR 须引用此对照。
- **前提锚定(要求-3,落码批义务)**:S2 正确性依赖「SIFT slot=画面槽位真值」。两条锚定:①落码验证设计补 SIFT 读链 slot 写点亲读(read_bench_chars 的 slot 赋值来源)并写入 ADR;②写回前置**槽号健康门**(与 `_reseed_bench_layout` cw_shop_action_ops.py:180-196 同式:占用槽号唯一 ∧ 全在 1..BENCH_CAPACITY,违者**拒绝写回**+defects 台账留证)——把 `bench_from_compact` 对无效槽号的静默 fallback(cw_state.py:391-397)在写回点升级为显式拒绝,防脏读数固化为形状自洽的槽位表(布局错而守卫恒过,比现状更难发现)。

**S1(结构防御,单一源收口;清单按应修-1 收窄):tracked 输入域消费点改「下标直拷」。** 改造清单恰 4 点(输入恒 = tracked):投影播种 cw_op_buy_cards.py:783、买牌期望态基座 cw_op_buy_cards.py:349、guard tracked 构造 cw_shop_action_ops.py:239、卖出侧 tracked 归一 cw_shop_action_ops.py:488——`pad_bench(deepcopy(tracked))` 替代 `bench_from_compact`。**cw_screen_prep.py:548/702 禁改**:该两点输入是 `obs.bench_chars`(SIFT 现读)非 tracked——SIFT 读的 slot 字段与自身读序同帧同源,是 SIFT 域唯一布局真相(画面有中间洞时读序≠槽位序,槽号优先放置正是正确适配);改下标直拷会把画面布局扭曲为占用挤前,族 A 动作 bench_idx 在错误布局上发射=卖错人/拖空格。tracked fallback 分支在 S2 后恒等,可改可不改。「S2 后行为逐位等价」主张**限定到收窄后 4 点清单**(对 obs 分支不成立,防误导落码批)。附加动机(低-5①):guard 现构造(239-241)无 deepcopy,`bench_from_compact` 冲突分支经 `bench_place` 就地改 `bc.slot`——守卫读路径存在写副作用,deepcopy 直拷后自然关闭,写入点注释。`_reseed_bench_layout` 已是下标回写,不变。

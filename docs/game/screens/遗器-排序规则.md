# 遗器-排序规则(relic_sort_rule)

> source_image: sr-od-test/screens/遗器-排序规则/{建议排序开,建议排序关,等级已选中}.webp(1080p 三态 fixture)
> 识别模型:assets/game_data/screen_info/relic_sort_rule.yml;判态模板 assets/template/relic_sort_rule/

## 1. 何时出现

「遗器-替换」屏点左下「遗器建议排序」按钮(relic_replace「按钮-遗器建议排序」,[95,975,425,1010])打开的设置弹窗。浮层形式(背景为替换列表虚化,透见但不可交互),screen_info 独立建档。弹窗内容:标题「排序规则」+「遗器建议排序」开关组 +「基础排序」单选组 + 底部「全部清除 / 确认」按钮带。

## 2. 状态流转

```
遗器-替换 点「遗器建议排序」→ 本弹窗
点「确认」→ 关弹窗回「遗器-替换」,列表按所选基础排序静态排布
重进替换列表 → 排序设置重置回「建议排序」开(实机实证,见 §5)
复用已开列表(不重进)→ 排序设置保持不变
右上关闭 X → 关弹窗;bot 未使用,不点确认时的生效语义未实测
```

## 3. 识别特征

- id_mark「标题-排序规则」[425,296,580,346],lcs_percent=0.7(text 区)
- 三枚判态模板(`assets/template/relic_sort_rule/<id>/raw.png`,阈值 0.9):
  - `switch_on`:开关橙色 ON 态(ON 帧 conf 1.000 / OFF 帧 ≤0.032);OFF 无独立模板,模板不命中即 OFF
  - `level_radio_idle`:等级灰 radio(未选中态)
  - `level_radio_selected`:等级橙 radio(选中帧 conf 1.000 / 未选中 ≤0.346)
- 弹窗上部浅灰面板、底部深色按钮带,文字对比度高,OCR 稳定

## 5. 交互要点

- **建议排序 ON 时基础排序组灰置不可用**,弹窗底部出现灰条提示「遗器建议排序开启后,基础排序、属性排序不可使用」;提示提及的属性排序分区在首屏可视区之外(弹窗右缘有滚动条),未建档
- **建议排序 ON 的列表行为**(替换屏):列表按建议匹配度动态重排,重掷动画期间评分持续变化 → 持续重排 + 滚动自动回顶,「识别 → 点击」间隔超 2 秒即落空——静态列表是替换扫描可靠性的前提
- **确认后列表转静态排序**:按所选基础排序(等级)固定排布,不再动态重排
- **重进替换列表排序重置回建议排序**(实机实证,EquipRelicOp.check_entry 注释):重新进入替换界面时排序设置被游戏重置回「建议排序」开,故每次重进后须重跑排序前置;快速路径复用已开列表时排序保持静态,不重复执行
- 建议排序 ON 时开启说明文案为「开启此选项后将按照与遗器建议中的套装、主属性、副属性匹配度进行排序」

## 6. automation 关联

- **EquipRelicOp 扫描前置**(src/sr_od/operations/equip_relic.py):重进路径在扫描前执行四节点链「打开排序弹窗(点 relic_replace「按钮-遗器建议排序」,until=本屏标题出现)→ 关建议排序 → 选等级排序 → 确认排序规则」;每步 round_by_find_and_click_area + until 转移证据;快速路径(IN_REPLACE_RESET_TOP)不经前置链
- **测试**:三态 fixture 帧被 test_equip_relic.py 流程测试(重进全链逐节点点击断言/复用路径零前置)与 id_mark 全量测试消费
- **光锥侧同构**:「光锥-替换」屏左下「光锥建议排序」按钮同语义(见其 doc),光锥排序弹窗未独立建档

## 7. 注意

- 弹窗判定以标题 id_mark 为准;背景替换列表透见不可作为画面证据(两屏标题同框只在本弹窗出现)
- 判态模板只收「等级」一对;稀有度/获得顺序的选中态模板未建——需要操作这两个选项时先补模板再写 op(同构裁片:行右端 radio)
- 开关/radio 判态语义 = 「模板命中即该态」,点击前先判态防呆(已关/已选中则跳过),不要盲点

## ① 结论(判定方案一句话版)

节点推进判定 = **四规则组**(统一 state 内部派生逻辑,实现 = kernel
`observe_screen_context` 派生管线,纯 `_swap` 内无 hook 框架——触发模型终裁 +
单版本模型销案 hook 时代机制):①**备战腿**(规则①,原腿 A):干净备战帧 ∧
顶栏可读 → 顶栏原文落 `top_bar_raw` 观察层(observe(),原始读数留证,缺读不写
禁猜),解析原文成序键 → `write_logic(node_ord)` 逻辑层;②**位面过渡腿**
(规则②):0q 采到 → 推进 **(位面+1, 1)**,位面源三源(phase_round 直读→
观察层现值→hist 反解)全缺禁猜,禁 plane=1 常量兜底;③**BOSS 简报腿**(规则③):
0p 采到 → 推进 **当前+1**(禁写死 9),类型=BOSS 随简报自带,**幂等锚**防简报屏
多 pass 重入双推进;④**弹窗腿**(规则④,原腿 B):弹窗族画面 ∧ prev∈守卫族
逐名{结算窗 token,简报,投资环境,等待1-1}(语义名{结算窗,开局链};0p/0q
出族 = 专用腿②③)∧ 缓存守卫 c==hist → 推进 last+1(开局首节点 = 1;恢复局
禁用)。四腿统一写 `node_ord` 逻辑层(生效序读口 = `effective_node_ord` =
max(node_ord, node_hist_ord),派生计算非存储),共用**单调推进判定**(候选 ≤
hist 不写不锚;去重键 = (run_id, effective_ord),同序恰一次推进)——同节点恒
恰一次推进。节点身份 = 节点序 `(plane-1)*9+round_num`(与效果账本
`advance_node` 同坐标系)。载体规范(单版本事务/渠道签名/行型)单一源 = 遥测
正本 v3.7,本文不复写。

### ① R2 退役错误勘误申报(用户令③;R3 修订根因)

R2 依据 currency_war_prep.md:32「先渲染备战画面,再弹 overlay」退役段首推断,犯了两类错误:

- **错误一(机制混淆):渲染顺序 ≠ 采样顺序。**「先渲染备战再弹窗」是游戏侧渲染时序;bot 侧采样由轮询节奏决定——弹窗自动弹出快于 bot 轮询时,干净备战帧可能一帧都采不到(loop 首帧即弹窗帧,0 系分支接管)。R2 §3.3 规则五「不漏论证」(「消化后备战帧必在后续某轮被分派」)在**事件层面**成立,但 R2 同时把弹窗分支排除出触发窗口,导致触发时点推迟到弹窗消化后——选卡(本节点动作)发生在触发前,违反裁定 2「分派前:先完成计数推进,再做本节点动作」。
- **错误二(真漏形态):补给类弹窗「确认即完成节点」。**补给节点无战斗无结算,补给屏先被采到时(自动弹形态),选完即完成节点、直接进下一节点——本节点再无备战帧,纯腿 A 对该节点**真漏触发**(R2 §3.6 S3 走查只走了 divert 形态,漏了自动弹形态,走查不完备)。
- **修复(R3)**:触发恢复双腿(§3.3 规则一/二)——腿 B 在弹窗首帧分派前触发,修复时点违反与真漏两缺陷;两腿同一行锚(规则三)。R2 的「单窗口/零推断」结论整体作废,R1 的段首推断机制经守卫精化后回归。

### ② 裁决保留面(用户令②)

## 结论（阻断）

**阻断**：2 阻断 + 5 中 + 2 低。两个阻断项均落在四轮 S4-1 状态机修法本体（本轮第一重点）：

- **S5-1**——待卖态重验判据（**无 X** 当前搜索下 V 仍部署外）与商店侧 victim 选择判据（**含 X** 虚拟定型部署外）结构性相斥：X 挤位形态（V 仅因 X 加入虚拟阵容而被挤出定型——虚拟搜索与现行搜索唯一差异就是 +X，故「virtual-out ∧ current-in」⟺「X 的加入挤掉了 V」，这正是场上件 victim 的构成性形态）**必然作废**。后果：意图槽核心能力（场上件 victim 跨画面卖出）对该形态系统性失效，每 victim 烧一轮「写槽→关店→备战作废→黑名单→重开」3-4 帧，§2.5「场上件收窄解除」申报对该形态失实；设计未裁定商店侧预滤 / 重验改虚拟口径 / 申报排除任何一条。
- **S5-2**——级联待完成态两条异常路径无定义：① **无进展无上界**——diff 恒非空（拖拽未生效重复重发 / 目标板帧间翻转）时前置步逐帧有动作 → 第 1-9 步全被挡（**含第 9 步出战**——节点不结束 → 节点戳永不失效 → 节点边界兜底失效；备战决策节点零超时 + 决策循环无防御上限）= 整局停摆无设计内出口；② **无动作帧破除级联独占**——「有动作要发 = 扫描到前置步即返回」的条件句反面 = 无动作帧扫描继续 → 第 5 步开店（意图路径不置会话标记恒 pending）→ 买入臂重评 → 同节点新意图**覆写**级联态 → 级联状态丢失。「级联饿死结构消除」申报只覆盖正常路径。

分键主链（S2-3/S3-3/S3-4/S4-4/S4-6 系）终核通过；四轮处置 11 项复核 9 项落地属实，**S4-7 处置未落文**（S5-4）、**S4-4 处置半落地**（S5-5）。裁定本身（升级凑金删除/统一获取让位/跨画面意图槽策略层实现边界/凑息豁免/等钱帧凑息照常/拦因分键）不翻案；攻击面全部落在四轮修法的语义真伪与文档同步。

## 发现清单

### S5-1｜待卖态重验（无 X）与 victim 选择（含 X 虚拟定型）判据结构性相斥——X 挤位形态必然作废，意图槽核心能力对该形态失效且未申报
- 攻击点：步 4 排序池 = **虚拟定型**（含 X）部署外件全集（design.md:63；步 3 部署定型 = select_deployment(虚拟阵容)）；待卖态重验第二条 = 「**当前搜索〔无 X〕**下 V 仍部署外」（design.md:68），安全性句自证「执行校验基于无 X 的当前搜索」（:70）。两搜索的唯一差异 = +X（详设 :57 虚拟面板字段域，无 X 与含 X 搜索共用签名——两判据确实可分）。故「V virtual-out ∧ V current-in」**精确等价于**「X 的加入把 V 挤出定型」（X 直接占位或涟漪换位）——这正是「场上件 victim」的构成性形态：场上件成为 victim 的前提就是虚拟定型不再要它，而唯一能把新 victim 挤出定型的增量就是 X。该形态下重验第二条**恒失败** → 作废 → V 入黑名单 → 重评取次末位。后果三连：① §2.5（:115）申报的「victim 选择域扩为部署外全集、victim 为场上件时走意图槽——现行收窄解除」对该形态失实（实际 = 烧一轮跨画面往返后回落到卖次末位件，多为例行 bench 件——与现行六步 bench-only 池行为等价，意图槽对该形态净贡献为负）；② 「排末位是谁就卖谁」的统一优先级语义被重验静默改写为「卖次末位」（黑名单排除后）——若此为设计意图（无 X 自证 = 压牌库保守化），设计未申报；③ 每个该形态 victim 烧 3-4 帧（写槽/关店/备战作废/重开），池尽时拦因记 `gold_short`（:65）语义污染（实际拦因是「挤位 victim 不可执行」非金不足）。设计未提供任何一条出路：商店侧预滤（victim 选择同用无 X 口径）/ 重验改虚拟口径（弃「X 消失亦不亏」安全性）/ 申报排除该形态，三选一缺失。
- 证据：design.md:63（步 4 池口径）/:68（重验第二条）/:70（安全性句）/:115（§2.5 申报）/:65（池尽记 gold_short）；详设 unified-deploy-order.md:13（契约③）/ :57（虚拟面板，两搜索可分）
- 严重度：高｜阻断级：**是**（机制两半对真实输入类互斥，落地任一半都静默作废另一半的申报行为；修复需设计裁定）
- 处置建议：三选一进设计——①商店侧 victim 选择加无 X 预检（挤位形态当帧转「末位 = 次末位」或直接放弃，零烧帧）；②重验第二条改虚拟口径并撤回「X 消失亦不亏」安全性声明（接受 X 消失时已卖件的敞口）；③维持现状但申报「X 挤位 victim 恒作废、实际卖次末位」为设计行为 + §2.5 改写 + 池尽拦因另立键。

### S5-2｜级联待完成态两条异常路径无定义：无进展无上界（挡出战 → 节点不结束 → 兜底失效 → 整局停摆）+ 无动作帧破除级联独占（开店 → 覆写 → 级联态丢失）
- 攻击点：状态机退出级联态的唯一条件 = 「diff 空（级联完成，bench 已腾）→ 此刻才清槽」（design.md:69）。两条异常路径均无定义：
  **① 无进展无上界**。diff 恒非空的形态实存：统一拖动执行未生效（机械拖拽落空，下帧观察对账板面未变 → 同一 diff 重发；详设 :9「执行层为机械拖拽零判效，失败形态由动作自上报逻辑推演 + 下帧对账暴露」）——逐帧重发同一动作，前置步每帧「有动作要发」→ 扫描到前置步即返回 → **第 1-9 步全部被挡，含第 9 步出战**。节点不结束 ⟹ (plane, round_num) 节点戳永不推进 ⟹ 节点边界兜底（槽失效/黑名单清空）永不触发；备战决策节点零超时（详设 :152 待核实节已核「cw_screen_prep 现役节点零 timeout_seconds = 默认无超时」）+ 决策循环无防御上限（cw_screen_prep.py:788-789，四轮已引）= **整局停摆，无设计内出口**。对照：现行第 6 步部署差分同有拖拽失效理论缝，但第 5 步商店会话在它**之前**（不挡开店）；级联态把开店步也挡进去——停摆面比 as-built 更宽。目标板帧间翻转（rng 帧级播种的随机尾键在稳定键平局时跨帧变序，详设 :59）是 diff 不收敛的第二来源。
  **② 无动作帧破除级联独占**。「槽在期间前置步优先于第 4/5/6 步（**有动作要发** = 扫描到前置步即返回）」的条件句反面 = 前置步无动作可发时扫描继续——级联帧发不出动作的形态：窗口/锁校验照常执行而 fail-closed 拒发（:69「窗口谓词/锁校验照常」——校验失败时发什么未定义）、diff 首步涉及被跳过步（详设 :95 fresh 守卫/未知件禁挤 :71 的同族挂起语义）等。该帧扫描继续 → 第 5 步 `_step4_shop_session_pending` 恒 True（意图路径不置会话标记，entry.py:984-999）→ **开店** → 买入臂在级联未完成（bench 未腾）的状态下重评 → 若新末位为场上件则写新意图 → 「同节点新意图覆写旧意图」（:70）→ **级联待完成态被覆写丢失**，板面停在级联中途。「槽在期间前置步优先于开店步」的独占保证只在「每帧都有动作」的前提下成立，该前提无保证也无失败处置。
- 证据：design.md:69（退出条件/优先级条件句/窗口锁校验照常）/:70（覆写句）；entry.py:546-547、:984-999、:587；详设 :9（拖拽零判效）/:59（rng 帧级播种）/:95（fresh 挂起）/:152（零超时核实）；cw_screen_prep.py:788-789
- 严重度：高｜阻断级：**是**（活界缺口——本轮修法宣称「级联饿死结构消除」，实际引入两条新停摆/中断路径且无出口定义）
- 处置建议：①级联态加无进展上界（连续 N 帧板面零变化 / 同一 diff 动作重发 M 次 → 作废清槽 + V 入黑名单 + 机会清单），出口写进状态机；②定义级联帧发不出动作时的返回（建议：返回 obs 挡帧保持独占，或显式作废清槽——二选一，禁「扫描继续」的隐式中断）；③申报第 9 步出战被级联挡住的结构事实与停摆风险边界。

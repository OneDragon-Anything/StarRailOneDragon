## 发现清单

### D3-1｜D2-6 处置半修：L2 键集含 flex_factions，但 flex 无档值无分母无权重，且注册表语义「完成度不数」与处置正面相反
- 攻击点：L2 计法 =「加权平均 of 档位完成度，权重 = 目标档深」。sub_tiers 值 = 人数（5 处全 int），分母权重可算；**flex_factions 是 `list[str]`，无档值**——既不在 form_tiers（注释明写「不进 form_tiers」）也不在 sub_tiers → 档位完成度的目标档端与「目标档深」权重**双无源**，重演 D-3/D2-3 的「分母无源」形态。更决定性：反甲流注册行注释白纸黑字「巡海 3 属 A 流、现仅在 flex_factions(**板面不罚但完成度不数**)」（cw_comps.py:1201）——D2-6 处置引用「注册表白纸黑字的非核心羁绊载体」把 flex 拉进**完成度层**，与注册表白纸黑字的语义（完成度不数）**相反**；sub_tiers 侧依据（「注释明写参与完成度」）也是未实现的意图声明（form_progress 不消费，二轮核实轨迹自知）。行为面：flex 是 6-7 键宽集（如 :584 七键、:652/:1473 等含量子同频/星间旅人等 2 人即激活的便宜键），锁定后场上随手凑 1 档 flex 键 → L2 数十万分恒压倒 L3 成型过渡板（8 分）→ 场景走查「P1 锁定、过渡对成型 → L3 定序保过渡板」的 ✓ 判定隐含「该帧 L2 = 0」，对 flex 非空锁定线（注册表 20 处 flex 赋值，绝大多数线有）系统性不成立。另 sub_tiers 与 flex 键可重叠（DOT 队：sub_tiers{减益:2} ∧ flex 含减益）——并集键集在重叠键上取哪端值未定义。
- 证据：详设 §1「L2 键集」行/分值表 L2 行/场景走查第 2 行；cw_comps.py:88-89,111,128-130,584,1199-1202,1466,1473。
- 严重度：高（**阻断级**：L2 对 flex 键不可计算 = 不可派工；行为缺口 = 保过渡板走查失效）。
- 处置建议：L2 键集收窄为 `sub_tiers` 单源（flex 显式申报落 L3），或给 flex 定义档位端读口并把「flex 凑档压过渡板」申报为预期行为同步修场景走查——三选一并给重叠键取值规则。

### D3-2｜「k_members 装配点随消费方消亡」失实（D-9 处置两轮维持后的复发实锤）：保留面活消费至少两处，按清单删 = 运行时断裂
- 攻击点：收编清单 k_members 行断言「其消费方 = 围栏/swap 机器/不可逆护栏 `check_irreversible`，均随批删——读口自然消亡」。全仓 grep 实况：①**溢出告警门卖出装配**（mandate.py:971 `k = frame.k_members` → :994-1004 sell_exclusions/dead_pair_exit_release/fuel_sell_candidates）——溢出告警门是详设 §3.8 明文保留面（「卖出走现行强收窄」）；②**`cheapest_member_cost(frame)`**（mandate.py:2009-2022）消费 frame.k_members，消费面 = 硬约束①金需求侧（entry 支付支撑通道）——非部署机器；③supply.py:194 虚拟 frame 透传 + shop.py:1141 六步 frame 构造（获取让位现行载体）；④装配点本身**两处**（mandate.py:1882 snapshot_frame + entry.py:467-489 emit 主装配，后者还有 K 空窗回退专段），详设只列前者。围栏/swap/护栏删除后 k_members 仍有保留面消费者——「自然消亡」不成立，落地按清单删装配点 = 溢出帧卖出防线（exclusions/release 装配断粮变全池裸卖）与升级/支付通道运行时断裂。
- 证据：详设 §4 k_members 行；mandate.py:971,994-1004,2009-2022,1882；entry.py:467-489；supply.py:194；shop.py:1141；design.md §2.6。
- 严重度：高（**阻断级**：按清单执行即运行事故）。
- 处置建议：k_members 行改为「装配点保留、消费方逐一登记改接/保留」，或把溢出告警门与支付通道的名单供给显式改接新读口。

### D3-3｜D2-1 两步换星的卖出处置链断裂：bench 低星副本撞档 1「同名牌永不先卖」死锁 + 总纲 §2.7 档 1 语义与契约②输出形态三面矛盾
- 攻击点：a) 两步换星 bench 有空分支 = 低星副本**下场进 bench**。此后其名 ∈ target 名集（搜索已选同名高星）→ 卖出评估器档 1「按角色名命中……**备战位上的同名牌同受保护**、永不先卖」（sell_candidates.py:250-252,301-303,317,335——target 名集过滤先于一切场景面，含自救面）→ 低星副本**永不进任何卖出池** → bench 席位被锁死，仅同名同星满 3 自动合成可消化（异星不并，cw_merge_simulate 分组键同名同星）——详设 §3.6「换下到 bench 的多余者进 bench 卖出池，按统一让位序处置」对该形态**不成立**；b) 总纲 §2.7 原则「定型内（部署要他上场，**按角色名命中，含同名牌**）= 档 1 不先卖」与详设发出点③（差分执行器对场上同名低星直接 SellDeployed）正面冲突——同一单位按总纲「定型内不可卖」、按详设被部署面直卖，档 1 保护被部署面绕过且无豁免声明；c) 契约②「部署定型输出 = target_board（**角色名 → 排**），卖出面档 1 按名集消费（接口形态与现行一致）」装不下星维度——就位判定粒度「名+排+星」需要 target 星通道（搜索结果副产物），契约未同步修订：要么扩形（接口形态不再一致）要么执行器重跑搜索取星（双源）。另「bench 满/低星该卖」的「该卖」判据（与卖出场景资格面 fresh/档 1/循环防线的关系、归谁判）未定义。
- 证据：详设 §3.1/§3.3/§3.6/接口契约②；总纲 design.md §2.7/§2.2 第 4 项/跨详设接口契约②；sell_candidates.py:250-252,301-303,317,335；cw_merge_simulate.py:455-466；cw_vocab.py 与现行 bond_gate star 通道（mandate.py:1560）对照。
- 严重度：高（**阻断级**：行为破坏——bench 席位锁死 + 买面系统性受阻；契约级定义缺口）。
- 处置建议：两步换星首选 SellDeployed 直卖（对齐现行 bond_gate star 形态）或显式申报「同名低星副本的档 1 豁免键」；契约②同步扩星维或声明星通道来源；「该卖」判据落卖出场景资格面。

### D3-4｜溢出告警帧态 1 上阵路径三处文本互斥，无一致解
- 攻击点：详设三处对同一问题的处置互相矛盾——§3.8「`frame.overflow_warning` 在场帧 = 搜索与差分执行器**全跳过**」；§4 收编清单「entry 备战工序部署面（**第 0 步态 1 上阵 :356-383**……）**切差分执行器**」；§5「第 0 步态 1 上阵 = 告警帧特例（**窗口豁免照旧**）」。现行态 1 = `_emit_deploy_moves_scoped(window_scope=False)` 上阵腾槽（entry.py:363-367「上阵纯为腾槽保命……22 号篇第 0 步态 1 豁免行」）——自救序按损失递增排列的**免费档**。切差分执行器后：告警帧差分执行器被 §3.8 跳过 → 态 1 死路（每次溢出直接跳态 2/3 有损动作 = 自救序免费档被结构性砍掉，行为劣化）；或态 1 保留旧 `deploy_plan_moves`（§4 又要删）→ 部署选人双源残骸；或差分执行器在告警帧特例放行 → 与 §3.8 全跳过矛盾。「窗口豁免照旧」尤其无所依——豁免的是旧机器的 window_scope 形参，机器已删。

### D3-5｜全枚举规模上界失算：「全枚举零截断」×「每张店内牌一次全搜索（毫秒级）」两个数量级以上的矛盾
- 攻击点：手牌上界 = BENCH_CAPACITY 9（cw_exec_state.py:184）+ 场上 K_max = 4+9 = 13（cw_game_state.py:4902-4914）= **22 个真实单位**；段 2 补人空骨架路径 C(22,13) ≈ 5×10⁵ 组合/次搜索（后期高压牌局可达：压牌库策略 bench 常满 + 宝钻满扩 K 大）。调用频次：商店帧 = can_deploy_single 每店内牌一次（5）+ 获取让位虚拟（1）≈ 6-7 次/帧；备战帧主搜索 + 意图槽重验 ≈ 1-2 次。纯 Python 评分（多羁绊完成度 + unit_bond_tags 全标签 + 加权聚合）单组合 μs 级 → 最坏帧级秒-十秒级。D2-14 处置申报「每张店内牌一次全搜索（**毫秒级**，申报）」与全枚举最坏上界矛盾两个数量级以上；D2-9 处置「手牌约束下规模可控」无上界数字；D-17 时长申报只覆盖拖拽 2s 睡眠未覆盖搜索计算时长；备战/商店画面 op 决策节点无超时（详设待核实节自认）、决策循环无防御上限——卡帧 = 外循环 stall 防线杀局。
- 证据：详设 §2 段 2/§4 can_deploy_single 行/§3.5；cw_exec_state.py:184；cw_game_state.py:4881-4914；cw_screen_prep.py:713-790。
- 严重度：高（**阻断级**：实现者拿到互相矛盾的指令（全枚举零截断 vs 毫秒级）不可派工；落地即运行事故面）。
- 处置建议：给出规模上界表（K × 手牌数的 C 值 + 每帧搜索次数）并申报最坏帧时长预算，或给出带最优性论证的截断/分层求值设计；「毫秒级」申报撤回或限定适用域。

### D3-6｜上报推演矩阵漏「目标槽占用」维度；场上→bench 被占槽的锁归属歧义
- 攻击点：矩阵四支按源域×目标域写分支（bench→场上/场上→场上/场上→bench/bench→bench），但统一拖动的全域游戏规则是「**目标有角色 = 交换**」——场上→bench **被占槽** = 场上件与 bench 件交换（bench 件上场 + 场上件下场），不是矩阵声明的「下场」；矩阵未交叉目标空/占维度，该格推演未定义。且「锁校验只辖『目标入场上』的移动」在该格歧义：交换上去的 bench 件「入场上」但移动目标域是 bench——被锁 bench 件经此格换上场是否过锁未定义（锁绑 uid 的判定现仅在 bench→上场支，cw_env_grants.py:956-973；被锁件若漏校验上场，执行层游戏侧拒绝 = 计划外失败帧）。

- 严重度：中（非阻断——单格推演可由实现者补，但锁歧义有失败帧面）。

### D3-7｜随机尾键与契约④纯函数矛盾；稳定键粒度未定义

### D3-10｜不等式③示例数值在 P1 锁定帧 K 约束下不可达：「保过渡板」实际依赖平分后的次级键
- 攻击点：不等式③「锁定后成型过渡对（如 2 档+2 档 = 4×2 = 8）> 万金油×4（= 4）」——2 档+2 档过渡对需仙舟 5 + DOT 4 = 9 人；场景走查第 2 行的语境是 **P1 锁定**帧（等级人口小，K = 4-7），9 人过渡对 + 锁定线核心装不下 → 实际可达形态 = 1 档+1 档（如仙舟 3 + DOT 2 = 5 人）= **4 分 = 万金油满员 4 分平分**，「成型过渡对胜万金油」在该帧不成立，定序落站位分/稳定键/随机尾键——「保过渡板」结论的数值基础在示例自己的语境里不可达。
- 证据：详设 §1 区分度不等式③/场景走查第 2 行；cw_factions.py:53,88（仙舟 5 人 2 档 / DOT 4 人 2 档）；cw_game_state.py:4902-4914（K 口径）。
- 严重度：中低（结论方向靠次级键兜住，非事故面，但设计验证的示例失真）。
- 处置建议：不等式③按 P1 锁定帧可达形态（1+1 = 4 平分）重写，并申报平分后的定序走向（稳定键偏好现状 → 过渡板因在场一致数占优，结论可保但依据要换）。

# v1-initial 设计总纲:每月合成(monthly_synthesize)

## 1. 动机

游戏内存在「每月限量合成」资源(当前唯一:自塑尘脂——合成遗器指定主词条的月限道具,单价遗器残骸×800),每月不合成即浪费额度。材料(分解废弃遗器)对常规玩家溢出,额度天然该每月拉满,适合进一条龙自动化。参考既有两件套:奇巧零食(trick_snack,合成开关+通用合成 op)与每月余烬兑换(monthly_embers_exchange,MONTHLY 周期 app 结构)。

## 2. 范围

- 新 app `monthly_synthesize`(每月合成):MONTHLY 运行记录,一条龙默认组,通知开启;
- 配置:唯一开关 `self_modeling_resin_enabled`(默认开,用户裁定 3);数量不可配全部拉满(用户裁定 1);
- 扩展通用 op `Synthesize`:数量策略按物品分流(`max_btn` 零食原路径不动 / `plus_monthly` 月限新路径:+ 逐次点满、置灰判顶、额度 0 跳过、材料不足判失败);
- 画面建档补全:材料合成分类页签、数量 + 按钮(亮/灰两态模板)、月额度读数区;
- 明确不做:遗器合成(自定义主词条)、消耗品日常合成(零食领地)、真实货币、具体个数读数留痕(用户裁定 1)。

## 3. 关键设计决策

| 决策 | 内容 | 依据 |
|---|---|---|
| 数量拉满手法 | 滑条手柄拖到轨道右端取**精确**上限,置灰判顶(用户裁定:参考零食合成用拖动,沉淀为购买/兑换/合成类通用最佳实践,示例见 write-operation skill) | 实测:上限 1031 与 2 两种规模一拖即精确归位;亮/灰模板区域限内交叉得分 1.000 vs ≤0.2;无「最大值」按钮可用 |
| 匹配区域限制 | + 按钮模板只在 [1490,845,1640,895] 局部匹配 | 实测:全图裸匹配亮态模板以 0.877 误命中形近「−」按钮 |
| 额度用完判据 | **首屏判定**:物品首屏未见即本期不可合成,不拖拽深扫;成因按当月锚(`resin_quota_confirmed`)裁定——已锚=额度用尽(完成),未锚=材料不足/被人手用尽(失败重试) | 实测:额度归零后物品沉底消失于首屏(「可合成排前、不可用沉底」排序律,与兑换商店月限同款),深扫不可达;两种成因只有锚能区分 |
| 入口置灰歧义态 | 点过 + = 已拉满;入口即置灰读「本月还可合成」消歧:0=跳过,≥1=已到顶合成当前数量,读不出=失败 | 防御分支(正常流走不到,物品已沉底),保留 |
| 额度 0 / 首屏未见的节点图 | `QUOTA_EXHAUSTED` / `ITEM_ABSENT_FIRST_SCREEN` 各挂**精确状态边**接终止节点 | 兜底边在无精确边命中时接管——缺边会把「跳过合成」误送进数量/合成节点,对自动选中的无关物品执行合成(真实消耗风险) |
| 材料不足 | 失败,不标本月完成(用户裁定 2) | 一条龙日批重跑补做,残骸攒够的当次跑成 |
| 周期口径 | MONTHLY(自然月) | 画面文案「本月还可合成」+ 沉底排序律随额度刷新 |

## 4. 验收判据(2026-11-15 实机全部通过)

1. ✓ `list_applications` 可见 `monthly_synthesize`,`describe_config`/`get_config`/`set_config` 开关读写往返实测;
2. ✓ 首跑实机合成 2 个自塑尘脂(额度拉满,13→15,残骸 -1600)→ 回大世界 → 运行记录标本月完成;
3. ✓ 额度用尽再跑:物品沉底 → 首屏未见 + 当月锚 → 不点合成 → 标完成(核销核对项 1);
4. ✓ 开关关掉再跑:跳过合成 → 标完成(途开开关需手动单跑,已记录为接受边界);
5. ✓ 失败路径实测:op 判失败 → 失败收尾尽力回大世界 → app FAIL 不标本月完成(用户裁定 2 语义生效)。

# 统一保护集(买卖身份同源) 迭代设计(总纲)

## 0. 元信息

- 迭代目标:修复「过渡引擎件在架拒买、且被卖出通道当废牌处理」的病灶(sim 复盘局 g_20261015_154239 缺陷候选 D1/D5 卖面侧),并将买/卖两侧的卡牌身份判定统一到单一「保护集」源。用户裁定口径(2026-10-15 会话):①位面 1 买面 = 过渡阵容 + 锁定/候选终局阵容,位面 2 起 = 锁定/候选终局阵容;②买卖决策依据统一——买面优先级即卖出让位序的镜像;③过渡阵容引入与终局同构的候选/锁定语义(候选 = 四体系全体,锁定 = 体系达成);④候选/选定阵容成员不能卖、不凑息;插件/杂件可卖可凑息。
- 状态:草案
- 文档清单:无详设(本篇即完整设计)

## 1. 问题与动机

- 现状症状(sim 局 g_20261015_154239,journal 行锚见复盘报告):
  - 买面:四体系引擎件在架 ≥6 张次全部拒买(r3 爻光 1 费/r6·r8 饮月 2 费/r1 三月七 1 费);整局 5 笔买卡 0 笔引擎件;
  - 卖面:r3 卖椒丘(DOT 体系件)腾位买风堇(填充件),DOT 引擎归零;
  - 对照:同批 4 局 3 死(P1r6/P2r1/P2r2),死亡局带「死时带金/金尽」形态。
- 根因归层(**语义层**):
  1. **定型语义混淆**:④转投前瞻放行通道(`mandate_v1/shop.py` ④分支)以 `cw_intention.committed_from` 为门,而 `committed_authority` 权威序②把「P1 配方对已物化」计为定型(`cw_intention.py` `committed_authority` ②支);配方对物化链的设计语义是「P1 目标不空窗」(`strategy-docs/12_line_and_intention.md` §3),未锁定局整个位面 1 恒非空 → ④通道恒不激活。
  2. **身份判定源分裂**:买面序 1 未锁定名单 = 候选 top3 终局线成员 ∪ 贯穿件(`shop.py` 未锁定分支),不含过渡体系成员;卖面线内身份集(`criteria/sell_candidates.py::sell_line_membership`)同样只覆盖锁定/候选**终局**线——过渡体系(位面 1 的真实战力引擎,`docs/game/currency_war/research/transition_combos.md` 四体系定义)不在任何一侧的身份域内。
  3. **宪法条款失实现**:`strategy-docs/01_math_framework.md` §3.2 P41 ② 分类表「骨架件/跨阶段体系件不卖 fail-closed」在实现中无对应判定(燃料件判定 = 与终局线零重叠 ∧ 边际贡献≈0,过渡件被划入燃料)。
- 解决到哪:上述三层全部(过渡域候选/锁定状态、保护集单一源、买卖两侧接线、静态名单退役)。
- 明确不解决(防范围外溢):D2 补给拾取工序缺位;D3/D4 升级时机(P85 域);D5 置换价值表「部署 carry 同名副本」高值项(飞霄类非四体系成员,不在保护集域,另批);凑息成功率的批量量化(本迭代只落观测计数,跨局判读另案);`committed_authority` 其余消费点(装备/部署)的语义审查(本迭代结构上消解其在 shop 的错误消费,本体不动)。

## 2. 方案

### 2.1 方向状态模型(新增语义)

两个域、同一套候选→锁定语义,数据底座全部复用现有结构:

| | 候选 | 锁定 |
|---|---|---|
| 过渡域(plane2_started = 假) | 四体系**全体**注册表成员 | **已点亮**的体系(支持度达标;可多个) |
| 终局域(plane2_started = 真) | 候选 top3 线成员(现行候选快照) | 锁定线名单(现行锁定槽) |

- **体系键与成员集(复用,零新建数据)**:四体系键 = `TRANSITION_TRAITS` 三羁绊键(仙舟/列车同行/持续伤害)+ `SEELE_SYSTEM` 哨兵键(单一源声明见 `cw_intention.py` 体系键段);体系成员 = 该羁绊阵营∪流派注册表全成员(`cw_intention._pair_members` 同款口径,希儿系 = 希儿 ∪ 量子同频/贝洛伯格成员)。**动态现算,不维护静态名单**。
- **点亮(过渡锁定)判定**:三羁绊系 = 该体系支持度 ≥ 1.0(支持度 = 羁绊计数/体系档,`cw_intention._system_support` 现役口径);希儿系 = 希儿在场 ∧ (量子同频计数 ≥ 2 ∨ 贝洛伯格计数 ≥ 2)(依据 = `transition_combos.md:27-32`「没有希儿时量子/贝不能独立当过渡」)。⚠️ 实现注意:现役 `_system_support` 的希儿系公式不含「希儿在场」前提,复用时须在外层补此门或新写判定,一致性由单帧测试钉住。
- **锁定状态槽(新增)**:`StrategyState` 新字段 `transition_locked_systems: frozenset[str]`(体系键集)。写点 = 备战/商店两决策入口前置段(与 `refresh_line_if_needed` 同点调用),**幂等只增不减**——达成过的体系不因掉档失去锁定(同构终局「锁后不换」,防「掉档→保护收缩→连锁卖」恶性循环)。清空时机 = 进位面 2(域关闭,与 `clear_p1_recipe` 同点)。计数来源 = 容器现读(bench ∪ deployed)。
- **保护集函数(新增,全仓单一源)**:`protection_membership(gs, state) -> frozenset[str]`(角色名集):
  - 过渡域:四体系全体成员(候选)∪ 已锁定终局线成员 ∪ 候选 top3 终局线成员 ∪ 贯穿件(`CROSS_LINE_KEEP_NAMES`)。注:过渡锁定体系 ⊆ 候选全体,对保护集无增量;锁定状态的行为消费面在买面金约束分层(§2.2)。
  - 终局域:锁定线名单 ∪ 候选 top3 线成员 ∪ 贯穿件(与现行 `sell_line_membership` 未锁定/锁定两分支同构,加贯穿件)。
- **域切换**:plane2_started 翻真时过渡域关闭;过渡域成员若属终局域候选/锁定则自然延续保护,否则滑向非保护(可卖)——对齐 `stage_transitions.md` Q1/Q2 数据常态(非本路线过渡件位面 2 清场,本路线组件留存 0.7-0.8)。

### 2.2 买面接线(`mandate_v1/shop.py`)

- **序 1 未锁定名单**(`buy_members` 构建未锁定分支):在候选线成员 ∪ 贯穿件基础上,并集 `protection_membership` 的过渡域全体成员。同时**义务面/囤货面拆分**(复用 T-307 锁定态两面拆分先例):
  - 义务面(`obligation_members`,M2 骨架义务、免利息规则门)= 候选/锁定终局线成员 ∪ 贯穿件 ∪ **过渡锁定体系成员**(点亮在即 = [6]「店全是想要的」跌破利息档例外的策略载体);
  - 囤货面(`buy_members` 增量部分)= 未点亮过渡体系成员,买入过 **1★ 全额退门**(`refund_full_star_ok`,[22]① 活期资产口径)——2★ 及以上不享免息,过 P46 支出否决域。
  - `missing` 缺口推导只消费义务面(过渡期权件不入 M2 缺口)。
- **④转投前瞻放行分支整条退役**(含 committed 门、`transition_release_names` 放行集、`transition_component_buy` 买因及出口键):其语义(未定型期照买照囤过渡件)被序 1 候选态吸收且放行集从 13 人策展名单扩为四体系全体现算。
- 锁定态买面(P1 锁定局 = 配方对 ∪ 锁定线;P2 = 锁定线单源)**不动**——并集语义已是双目的形态(`12_line_and_intention.md` §1.2)。

### 2.3 卖面接线(`criteria/sell_candidates.py` + 卖出资格装配)

- **保护集成员 = 绝对禁卖**(用户裁定语义,非排序垫底):`protection_membership` 并入卖出资格装配 A 身份段(替换原静态持有两集中的 ④放行集;registry 核心集保留——万敌等单卡核心非四体系成员,仍需独立保护)。豁免通道照旧不动:溢出自救全通道豁免、部署换血(场上件唯一卖出场景,判据本体不动)、P78-5 兜底豁免(funding 最后手段,安全阀)。
- **凑息语义**(用户裁定):候选/锁定成员不凑息(由上条结构性达成);插件/杂件可凑息。新增观测键 `interest_round_protected_block`(节末凑息因候选非空但全为保护档而放弃的帧计数),供跨局量化(本迭代只落键,判读另案)。
- 评估器排序键结构 `(line_member, bond_drop, gold_value)` 不动;`sell_line_membership` 的未锁定分支改为消费 `protection_membership`(函数名保留,语义域扩展,消费面零改)。
- 场景参数表(`SCENE_SPECS` 八场景)结构不动。

### 2.4 静态身份面退役

- `TRANSITION_PACK` 名单及档位标签(carry/partial/drop):买卖身份消费面全部迁移至保护集后退役(模块保留配方对评估数据表用途的引用面申报给落地批核减——`12_line_and_intention.md` §3「TRANSITION_PACK 候选体系表保留为未锁定期判据输入」,该引用若存在则名单本体保留、身份消费面删除;落地批以 grep 消费点清单为准并在交付报告申报)。
- `kernel/cw_card_identity.line_identity_tier`:④分支退役后仅剩拒因遥测(D7 键序)消费——该函数退役,拒因判定改消费保护集(`transition_char`/`non_line` 等键语义:保护集成员被拒 = 硬闸拒,非成员 = 非保护)。
- Z1 凑息排除集(`mandate.sell_hold_exclusions`):静态持有两集替换为「保护集 ∪ registry 核心」。

### 2.5 行为变化申报

1. 修复本体:引擎件在架必买(1★ 全额退随买/点亮体系成员免息义务级);椒丘类拼图件不可被置换/筹资/变现/凑息卖出。
2. 凑息/筹资/变现成功率在「全场保护档」帧下降(升级变现失败 = 预授权键保留至节点末,现行稳态无害语义;凑息少 1-2 金/轮,观测键量化)。
3. 位面 2 换血更果断:非终局线过渡件从受保护变为可卖(对齐 Q1 数据)。
4. 买面总量上行(P1 买入笔数增加,压牌库收益同步)——出口金/[28] 双指标在 prereg 对照中验证不劣化。
5. sim 可观测性声明:本迭代全部改动在判据/策略层,sim 可见(可 A/B 对照)。

### 2.6 验证设计

- **单帧测试**(测试仓,docstring 引本设计节):
  - r3 复现牌面(风堇/藿藿/青雀/佩拉/爻光,金 22/席 8/9)→ 必发 `BuyCard 爻光`;
  - r6 牌面含饮月(金 14/席 7/9)→ 必发 `BuyCard 饮月`;
  - 置换场景:席满 + 手上椒丘 + 店内杂件 → 置换卖杂件,椒丘在卖出候选中不出现;
  - 凑息场景:缺口 3 + 手上只有保护档(退金足)→ 零卖出 + `interest_round_protected_block` 计数;
  - 点亮锁定:仙舟 3 人在场 → `transition_locked_systems` 含仙舟;卖退 1 人不掉锁定(幂等只增);
  - 希儿系门:量子 3 件在手但无希儿 → 不锁希儿系。
- **复现局对拍**:seed 20261012 改前后逐轮买卡序列对比(锚 = 决策帧)。
- **sim 小批**:主过程量 = 四体系点亮率/引擎成型率;hp/出口金只作验收报警(sim-testing 边界);凑息观测键频率采集。
- **prereg 保全清单**(strategy-work §6 硬门):出口金基线/[28] 双指标(利息基数 × 形态达标)/[13] 成型停买线/通关率——改前基线批先跑先记,改后对照不劣化;保不住 = 回设计层。

### 2.7 关键取舍

- **锁定持久化 vs 派生**:选持久槽(幂等只增)。派生口径下「换血掉档 → 保护收缩 → 连锁卖」有恶性循环形态;终局侧「锁后不换」为既定架构原则,同构沿用。
- **保护 = 绝对禁卖 vs 排序垫底**:选绝对禁卖(进装配 A 身份段)。排序垫底在「全场保护档」帧仍会卖出候选成员,违背用户裁定语义;自救/换血/P78-5 兜底三豁免保安全阀。
- **修④门 vs ④退役**:选退役。修门(门改「终局线未锁定」)只救 13 人策展名单口径;退役并序 1 吸收,身份域扩为四体系全体现算,且少一条需维护的邻位特批通道。
- **过渡池含高费框架成员**(银狼/瓦尔特等 3-5 费):纳入。位面 1 低等级下商店概率结构性刷不出(概率表),刷出时按 [22]① 稀有照囤/[21] 买而不上为正确行为;1★ 全额退门保证零息损。r100「Early 出现率」收录纪律是策展名单时代的防膨胀手段,现算范式下由概率结构与经济闸门自然承载。
- **TRANSITION_PACK 全退役 vs 保留配方对引用**:落地批按消费点 grep 实测裁决(§2.4),不预设。

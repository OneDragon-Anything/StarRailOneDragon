## 4. 跨项共性(根源两问框架)

根源两问:①现象的根在哪一层(表示/约定/流程/语义)?②修的是根还是症状?跨件半问:同族修法出现第 2 件时,先问是否同一更高层架构根。

**共根组 1:部署链的「黑板现读」输入契约(表示/接口层根)**
- 成员:D-C44(买后部署断链)+ dd-016 的 cap 空槽补部署 + D-dup(场上 dup 估值)+ 195720-G②(计划超 cap)。
- 判断:**同一根**。三件的共同根 = 部署意图的输入不是「当前黑板真值」而是某个快照/旧集/错误估值:44 是快照(进店前 bench)、dd-016 是漏补(残余不进计划)、dup 是估值口径错(把不可部署件算战力)。逐件修=三张补丁;治本=新核部署发射器定一条输入契约:**每轮部署计划以买入结算后的 bench/cap/dup 黑板全量现读重建**。这正是换核的接口设计内容,批1 应把它写成发射器输入契约条目而非三个独立修复。回答两问:根在表示层(黑板→发射器输入的时效与口径);修输入契约=修根。

**共根组 2:威胁/生存语境未进决策输入(语义层根)**
- 成员:D-D(硬节点补强)+ D-F1(生存折现)+ D-B 的③强敌释放 + D-FM1 的濒死孤注 + D-lv7(OPEN)+ sim0903-P1/P2idle/F2(危局囤金)。
- 判断:**同向同根族**——决策面各自不同(买牌/选卡/装备/升级),但缺的是同一个输入:**「节点威胁 × 血线 × 敌词缀」的环境语境没有作为一等输入进发射器**。旧层用无差别门(成型门/血预算门/opening 布尔)替代了这个语境,门在错误条件下全关=囤金死,门全开=散买。治本=新核把这些语境做成显式输入(节点类型、hp 带、词缀、位面),让同一批发射器在不同语境下自然改变意图强度——而非每面各打一个门补丁。回答两问:根在语义层(决策输入缺环境维度);修语境输入=修根。

**共根组 3:线级状态机的事件与滞回语义(语义层根)**
- 成员:D-A45(干旱计数不认买入)+ D-P4(切线摇摆)+ (195720 #4 漏买与撤线互为因果)。
- 判断:**同一根**——线级(p1_pair/target_comp)状态机的转移事件不完备:计数器不认「买入」事件(A45)、判据无滞回导致回锁(P4)。治本=换线机器一次定义完整事件集(买入/卖出/干旱步进/撤线/回锁禁止窗),各计数器与判据共用。两问:根在语义层;修状态机事件集=修根。

**共根组 4:成型语义的位面失义(生命周期层根)**
- 成员:D-FM4 + sim0903-P5(成型后仍买,反向)+ F4 度量饱和 + D-F9 部分(引擎堆积不收核心)。
- 判断:**同一根**——「成型」是 P1 过渡语义被全局复用:停手线停在过渡里程碑,无 P2/终局承诺。P5 与 FM-1/FM-4 是同一枚硬币两面(该停不停 / 停了没下文)。治本=目标机生命周期分档(换线机器位面边界触发),非买卡门上加拦截。两问:根在语义层(生命周期缺 S3);修目标机=修根。

**非共根项**:D-F46(词缀装备分配)是独立的新语境输入(归入共根组 2 的词缀维度可部分吸收);D-FM2 承接是共根组 2 的位面边界子案;sim0903-P7(key 装备零激活)需先对账:若 key 需求口径合法恒空,则 D-B 的「key_equips 攒穿」通道本身可能是死代码——**批1 应先对账 P7 再定 D-B 的实现深度**(发射器按分层规则穿 vs 按 key 需求穿,取决于该口径)。

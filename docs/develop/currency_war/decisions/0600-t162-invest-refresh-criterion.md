## 1. 背景与裁定

ADR-0519 C10 退役了事件面刷新建议(旧判据 `EVENT_REFRESH_SCORE_FLOOR=50` 是拍定的评估分阈值,违反零拍定纪律),退役动作 = `decide_event` 返回 `refresh` 恒 False + handler 刷新执行段删除 + screen_info 刷新 area 不存在。T-155(ADR-0597)已建立零拍定的选卡分类体系(S1 定义型/S2 经济引擎/S3 终局对齐 D*/S4 常规评估)。本批在该分类谓词上**重立刷新判据**:触发 = 「顶级类不存在」这一注册表可验证的结构事实(存在性,非分值阈值),推导链无任何人定的数;同时重建观察通道(逐卡计数 reader)与执行链(逐卡刷新)。

## 3. 已实施架构

### 3.1 判据本体(kernel/cw_events.py `decide_event` 尾段)

分类存档:评分循环内顺手记逐槽 (exact=策略轴归一后精确命中, s1=定义型, engine=S2 引擎, align_n=对齐档 N, blood, forbidden)——不二次评分;**G8 消费序依赖**:存档量只在帧级触发(三卡全精确分类)前提下消费,精确 miss 槽的存档值(如 LCS 兜底的 blood)禁止下游消费,先帧级闸后取分类,改序即静默击穿 fail-closed。

帧级触发(全部满足才继续):
1. **候选数恰 = 3**(J3:注册表存在 9 字卡名超 `2≤len≤8` 读带,读缺/同名碰撞帧构造可达;≠3 整帧阻断,顺带使「按 x 就近配对三槽」从 OCR 碰运气变为结构保证);
2. **全部候选可精确分类**(fail-closed + G7 轴钉死:分类轴 = 策略注册表归一后精确命中;LCS 形变名/未注册名/精确命中环境名均不可分类 → 整帧阻断——评分错只排错序,刷新错会弃掉真顶级卡,不对称取严);
3. **无一达 S1/S2**(非被禁卡口径,P5①:被禁卡不参加达档判定,不阻断触发);
4. **max_N ≠ 1**(J6:N 档 = 非被禁候选的绑定∩D\* 绑定数;帧内最高对齐档 = 1 → 整帧不刷——N=1 价值地位未决挂账 T-155/16 号稿批,与 S4 抽样的交换不可比 → 保守缺省;max_N=0 或 ≥2 继续)。

槽级动作集 = 全部槽 − 顶级槽(顶级 = S1∨S2∨[非血非禁 N≥2 对齐];被禁槽顶级判定恒取否 → 恒入可刷集,P5② 含被禁∧N≥2 对齐槽;血∧N≥2 现行不可达——两血卡 STRATEGY_BINDINGS 双空恒 N=0,注册表演化致可达时按 J7 申报裁:保护无对象 → 不保护)− **唯一 L1 槽**(F2 kernel 静态口径:L1 = 非血∧非禁,恰一个时该槽不可刷——刷掉唯一 L1 且新卡为血/禁 → 三态序强制血选,确定损失分支;执行期逐步重估由 handler 槽序循环承载,kernel 单次调用不可表达,单帧锁 14)。

返回:`refresh_slots`(升序槽位元组,空 = 不建议)+ `refresh=bool(refresh_slots)` + 归因后缀 `+refresh-suggest`(仅观测)。

### 3.2 判据推导(逐槽弱占优;完整版同步登记 math_proofs P81)

前提五条 + welfare 声明,全部为在册裁定或注册表/机制事实:
- **P1 优先序(编码可兑现口径)**:用户裁定 2026-09-08「优先经济、然后是终局阵容」的编码实现为 S1(120) > S2(域带 111-119) > S3 对齐 N=2(110) > S4 评估分(≤75),N=1 对齐(65)压不过 S4 上界——判据取 N≥2 才算「已达终局对齐档」;S4 内部差异不构成可比较价值量(定序实现常数禁读基数,ADR-0524)。
- **P2 无代价**:事件面刷新免费且不消耗选卡权(实证挂 V2,唯一前提杀手项;证伪 → 判据停用回退恒不刷,不预建开关)。
- **P3 改进存在性(p>0)**:注册表在池有 38 条引擎卡 + 7 条定义型卡(直调在案)+ 重掷分布 = 发牌分布(机制前提,实证挂 V3;p 的量级不需要估计,优势论证只用 p>0)。
- **P4 血本位回避**:存在可替代(非血∧非禁,L1)时永不选血卡(声明性偏好,可比较非定价,ADR-0578)。
- **P5 被禁卡统一规则**:被禁卡永不被选 → 不参加「达档/顶级」判定,被禁槽恒入可刷集(保护无对象)。
- **Welfare 声明**:S4 内部评估序、L2(全血非禁)/L3(全禁)帧的域内评估序同为选择机制不承载福利——「换掉帧内当前 argmax」不构成可证损失。

逐槽弱占优(F2 四支 + G4 的 L1=∅ 补全):帧级触发成立 ∧ 槽 i 可刷时,刷新槽 i 的结局按新卡分类分四支——①新卡达 S1/S2 → 按 P1 严格优(限定子域 J1:对齐卡命中 user priority 时 140 > 120,选卡仍落对齐卡,刷新白耗一次计数无损失,弱占优不变);②新卡为血/禁 → 槽 i 已过唯一 L1 守卫,兜底 = 其余 L1 卡或域内 argmax(L1=∅ 帧,welfare 延拓),与不刷同域可交换;③新卡非顶级非血非禁 → 同②;④原卡血/禁 → 新卡非血非禁 → 按 P4 声明优(L2 帧此支 = 逃出血强制)。①④为改进分支、②③无确定损失分支 → 弱占优成立;刷新免费(P2)、上界由游戏授予计数封顶。

S3 边界(max_N 分档):max_N≥2 帧 → N≥2 对齐槽保护不刷(刷它 = p×跳档 对 (1−p)×确定优先级跌档,双侧无定价,优势论证不成立 → 保守缺省),其余槽照刷(刷后顶级出现选它,没出现对齐卡照选与不刷完全同局——110 压过任何非顶级新卡,fallback 恒等);max_N=1 帧 → 整帧不刷(N=1 价值未决,交换不可比);混合档帧(N≥2 与 N=1 并存)→ 可触发,N≥2 载体恒压非顶级新卡(105 < 110),N=1 槽按槽级规则可刷。

### 3.3 执行链(operations/cw_screen/cw_screen_invest_strategy.py)

### 3.4 观察通道与次数语义

- reader(`obs/cw_node_obs.py`):`read_invest_refresh_counts(ctx, screen, kind)` 走 **get_ocr_result_list 形态**(map 按文本为键,三卡同文「刷新次数1」×3 会收敛成一 entry 丢位——三槽计数齐读的前提)+ 正则族「剩余次数\s*[：:]\s*(\d+)」(env,全/半角冒号)∪「刷新次数\s*(\d+)」(strategy,无冒号);`pair_refresh_counts_to_slots` 按 x 就近配对、一条文本只配一槽、超半槽距容差 `_PAIR_X_TOL=250`(槽距 ~500 布局推导)落 None = 读缺(fail-closed:防邻槽文本误配颠覆计数闸)。screen_info 两档 area(`区域-刷新次数行`/`区域-剩余次数行`)为 OCR 量裁剪带,不承点击坐标真相;刷新钮不建固定 area(文本锚定偏移,遭遇屏先例)。env 屏观察写入一处(handler 稳定帧读数落 log,供 V5/V6 与 BoardState §2.5 写入端),零点击零决策。

# 运行时迭代深度细则(阶段 8 + 调试)

> 本文件是 SKILL.md 阶段 8(事件长尾)与「调试纪律」的 situational 深度细则。bot 跑起来后遇卡死/意外屏时按需读。

## §事件长尾 —— 边玩边重构(阶段 8)

肉鸽/多分支玩法**事件类型巨多**,没法一次写全。方法论:
- **loop 跑,卡在哪个事件,就读屏 + 加一个 handler,再跑。**
- 兜底:任何匹配不到的状态走 fallback(点空白/ESC),避免死循环。
- 每跑深一点冒新事件是常态,别指望一次覆盖。

## §调试纪律(深化)

bot 卡死/死循环/op 失败时,**先读日志再动手**,别凭猜改或盲点坐标:

1. **读日志**(`.debug/sr_od_mcp/main_server.log`):看卡住时**实际 OCR 到什么、走到哪个节点、决策状态**(等待/重试/失败)。日志常直接暴露根因(OCR 没读到关键锚点/节点循环/命中错屏)。
2. **日志解释不了 → 工程缺日志,补日志**:若日志只记 OCR、没记「点了什么坐标/click 是否成功/走了哪个分支」,就在**决策点补日志**(记 OCR 摘要 + 点击坐标 + click/分支结果)+ **临时存图**(`screenshot()` 落盘到决策点)。否则下次同样卡住还是黑盒,改了也不知道为什么好/坏 —— **不可观测 = 不可维护**。
3. **结合日志 + 搜/合理猜玩法**:日志给客观事实,玩法知识给假设方向(「会不会要多次确认」「会不会有前置条件没满足」「会不会是 bug #1 吞 click」),两者结合形成假设再验证。

**反例(别这样)**:bot 卡住 → 不看日志,直接盲点坐标试,没成又换坐标 —— 既定位不了根因,改了下次还卡。

## §意料之外的画面 → 调研"怎么交互进来的" + 建档

bot 跑到一个**代码没预期/没 handler 的画面**(如点卡开出详情、误点进设置、过渡叠层)时,**别只 ESC/handle 掉它就完事** —— 先**调研"代码哪个动作交互进来的"**:

1. **回溯入口**:看日志/截图,定位**上一步代码点了什么**导致进这个屏(哪个 click/nav、点的是 UI 的哪个元素)。典型:bot 想点某张卡选中,却点中了卡上**会触发别的交互的元素**(如立绘/图标)→ 游戏打开详情页(对该元素的固有交互)。
2. **建档该画面**:记**入口(从哪来:什么动作/条件触发)+ 出口(怎么回/推进)+ 为何出现**(游戏机制)。进 screen doc/insights,后续一见这屏就知道根因 + 代码怎么修(避开误触元素)。
3. **修代码不再误触**:根因是"代码的 click 落到了会触发别的交互的元素上" → 调 click 目标(避开该元素,点同卡的非触发区),或调整交互顺序。

- **判据**:遇未建档/未预期的屏 → 先问"代码上一步点了啥 → 落到哪个 UI 元素 → 游戏对该元素有什么交互" → 建档 + 改 click 避开。只 ESC 不调研 = 同样的误触下次还发生(黑盒)。
- 这是「事件长尾」的深化:长尾不只是"遇新事件加 handler",而是**搞清每个意外屏的入口链**(代码动作 → UI 元素 → 游戏交互),建档后从源头修(改 click 不误触),而非 endlessly 加 ESC handler。

## §运行时不确定性 → 开发时预留日志 + 截图开关

自动化开发(游戏交互)比普通软件**不确定性大得多**:UI 变/时序抖动/加载延迟/bug #1 → **TDD 锁不住运行时问题**(TDD 只能锁纯逻辑)。故功能开发时:

- **关键决策点预留充足日志 + 临时截图开关**(OCR 摘要/点击坐标/分支结果/前后截图)→ **前期跑失败一次就能定位根因**,不用反复重跑猜。验证通过后**逐步去掉**(减运行时开销)。
- **初期接触玩法时尤其要堆满日志 + debug 截图(信息密度论)**:刚接触一个玩法、对机制/画面/时序理解最浅的阶段,每次实跑的"信息密度"必须拉满 —— 每个决策点(买/选/升/deploy/事件分支)都记:OCR 到什么、评估了哪些选项、选了哪个、为什么、点了哪、结果如何,关键分支**存 debug 截图**。目的不只是"失败时定位根因",更是**让一次实跑暴露尽量多的问题**(策略漏洞/OCR 误读/坐标漂移/漏事件),而非每次只测一种情况 —— 否则「跑一次只为找一个问题」极浪费时间。**判据:实跑后看日志就能复盘整局每个决策点发生了什么**(不用重跑猜);做不到 = 日志不够,补。
- **等待时别闲着**:bot 跑/等加载/等刷新期间,**同时做别的事**(自检类似坑/预写日志/补画面建档/沉淀经验),别纯 sleep。
- 日志编码:Windows server stdout 可能用 locale(GBK)→ 日志 mojibake → 强制 UTF-8(`sys.stdout.reconfigure`);详见 `framework-pitfalls.md` 第 7 条。

## §重复的手动操作 → 尽早建成 op

开发/测试中**手动做了 2+ 次的导航序列**(如退出对局:Esc→放弃→结算多页→大厅;或进入某玩法入口),**尽早建成 op**(放 `operations/`,用 `run_operation` 一键调用)。好处:① 不用每次手动点 N 个按钮(省时省力);② 可复用(bot 刷开局/测试/回滚都用);③ op 有重试/超时/日志(比手动可靠)。

**判据:同一个手动操作做了 2 次 → 第 3 次前建成 op**。

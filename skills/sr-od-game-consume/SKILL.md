# 游戏内消费路由（sr-od-game-consume）

真实货币消费的操作路由知识：怎么走到付款、bot 在哪止步、怎么读消费状态。

## 消耗红线（任何消费项通用，不可协商）

1. **bot 永不代付**：真实货币支付的终点 = 摆好付款码，扫码由用户完成；支付确认类控件(「继续支付」/二维码本身)bot 不触碰，唯一例外是「确认放弃本次支付？」(收尾清理用)。
2. **开付款码 = 发起购买**：调用前必须已获用户明确同意(用户开口要求买 = 已同意；agent 主动建议后须等用户点头)；浏览商品页/读规则/查剩余天数零消耗，无此限制。
3. **止步即成功**：付款码摆好就收尾并转告用户扫码，不轮询支付结果、不自动关弹窗(除非用户要求收摊)。

## 路由表（按消费项）

| 消费项 | 路由 | 状态 |
|---|---|---|
| 小月卡(列车补给凭证)购买/续订/查剩余天数 | [references/月卡充值.md](references/月卡充值.md)——op `BuyExpressSupplyPassOp` 一键到付款码，细节(机制/入参/状态/失败去向)全在该档 | 可用 |
| 大月卡(无名勋礼)查购买状态/导航 | [references/大月卡充值.md](references/大月卡充值.md)——op `BuyNamelessHonorPassOp(open_pay=False)` 判未购/已购态,零消耗 | 可用 |
| 大月卡(无名勋礼)购买 ￥68 档(荣勋)到付款码 | 同上档——op `open_pay=True, pay_channel=...` 全链到扫码弹窗(档位页自动选 ￥68;￥128 奖章档只识别不点击);2026-11-12 实机走通 | 可用 |
| 跃迁(抽卡，星琼消耗) | 未建设；收到此类请求:抽卡属高消耗决策，先引导用户过 sr-od-game-coach 的投入评估，操作路由待补 | 待建 |
| 其他未收录消费项(礼包/皮肤/星琼直充等) | 未建档未收录——如实告知未支持，勿凭猜导航；值得做则挂账待建 | 未收录 |

## 各消费项通用的验证纪律

- 付款码摆好后，用画面截图确认「扫码支付」弹窗在、渠道正确(支付宝态=「其他支付方式」按钮可见；微信态=「返回支付宝扫码」按钮可见)，再转告用户。
- 消费状态读取(剩余天数等)以画面建档的 area 为准，别凭记忆报数字。

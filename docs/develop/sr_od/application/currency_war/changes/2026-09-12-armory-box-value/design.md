# 武装箱选卡价值升级 迭代设计（总纲）

## 0. 元信息

- 迭代目标：武装箱 4 选 1 装备卡（`decide_box_card`，事件面 E18）价值模型升级——①未锁线时按「输出最需要」通用先验选卡（用户指令 2026-09-12：「没有目标阵容的时候，应该选更普遍用于输出的」）；②打分接入装备库存账的序数感知维（用户质询 2026-09-12：「打分不读当前装备库存——我们 state 里有记录装备的」）；③选装逻辑通用化——打分核心抽为共享机器的通用选装入口（用户指令 2026-09-12：「这个选装备的逻辑，是不是可以做成通用的」）。
- 承接出处：`2026-09-12-supply-selection` 迭代 §1.3 装备层两态（裁定 5/6）迁移表中 `decide_box_card` 行的终态提前落地；库存维（组件缺口）的序数切片与通用选装入口为**本迭代新增语义**，超出源迭代 §4 v1 结构版范围。
- 状态：**草案**（对抗审未过，不可派落地批）
- 文档清单：无详设（单文档方案，本篇即完整设计）

## 1. 问题与动机

### 1.1 现状症状（依据 = flow.py:654-702 直读 + 2026-09-12 本会话全链盘点）

现行 `decide_box_card` 打分（CwFlowStrategy 默认实现，mandate_v1 未覆写）：

```
score(name) = 100 if name ∈ target_comp.key_equips        # key 直击
            + 30  if name ∈ key_equips 的 recipes 材料    # 两跳材料
            + material_value(name)                        # 材料通用性手表 0-7
            （effect_pick_bias 恒 0，占位）
argmax，无信息 fallback idx=0
```

四个 gap：

1. **未锁线盲选**：`target_comp` 为 None 时只剩材料通用性分，四张全表外件（值 0）恒选第 1 张——通用输出装（火力风暴潮 6 分档的乘区件）与纯垃圾件同分，输出先验完全缺位。
2. **锚定错位**：key 消费 `state_of(session).target_comp`——P1 期过渡配方对物化的伪 comp（源迭代详设 §1.3 自证同款辖域错位，T-155 判例；P1 配方锁帧 locked_comp 恒空，flow.py:405-410 注）。过渡线的关键装备被当终局关键装备 +100 提权。
3. **库存维零感知**：打分不读装备库存——库里有某 key 配方的另一半材料时，选这张卡 = **立即合成拿到 key 装备**（近兑现），与「单纯一件原料」价值档位不同，现行打分不可区分。库存数据本身在册（见 1.2）。
4. **材料通用性梯度无数据根基**：现行 `MATERIAL_VALUE_TABLE`（cw_prep_expect.py:32-35，花7/鞋6/电池6/钻头5/刀5/装甲5/枪4/星3）自注出处 = `docs/game/currency_war/data/equipment.md`；注册表直调（2026-09-12 实跑 `EQUIPMENTS` 全量 recipes）：8 件简易材料**每件恰 10 条配方引用（成员槽 11，自对配方双槽）完全同值**——梯度在注册表下不存在，手表数值出自过期局部文档。该维在箱打分里是虚构序。

### 1.2 「为什么以前不读库存」——归因（回答用户质询）

库存账一直在：`session.last_owned_equips`（cw_strategy_session.py:167）由两类写端维护——①观察采集写端全量重写（prep_actions.py:411、:571-577，`read_equips` SIFT 逐件实名）；②建模效果增量：开箱选卡 +（cw_exec_state.py:278-282 经 apply_op_effect）、确认到账 +（_overlay_confirm.py:61-63）、穿戴 −（cw_op_equip_all.py:152-155）、卖角色装备返还 +（cw_exec_state.py:335-337），并有期望态对账网审计（compare_equip_expect）。**不读的原因不是数据缺失，是打分形式缺失**：

- 「囤了 k 件后这件材料还值多少」的数值边际模型 = P42 组件缺口参数化（近兑现距离 × 边际），现只有序级结论，绝对值等 λ 标定（源迭代详设 §4 直读 P42_VALIDATION：④门未检验、λ 🔴）。零调参宪法禁拍值（strategy-work §1：每个数字要么规则推导要么显式模型估计）——没有模型就给库存感知定数值 = 违宪，所以旧打分干脆不读。
- 源迭代把这个维度立了案（组件缺口维度，v1 只入结构半部「key 材料 +3」，数值半部挂账双前置 = λ 标定批 + owned 读数接线）。
- **本迭代补第三条路**：序数形式。库存感知里真正可零参数推导的部分（近兑现 = 立即拿到 key 装备，见 §2.3 推导）用**档位升格**表达——档序可证、不需要绝对值、不需要 λ。数值半部维持挂账，不因本迭代解锁。

### 1.3 根因归层

语义层：价值模型缺「库存序数维」（近兑现与原料不可分档）+「统计先验 vs 锁定契合」未分态 + 锚定错位继承自 target_comp 伪 comp。表示层伴生事实：材料通用性梯度 = 过期局部文档的虚构序（§1.1 gap 4），随本迭代一并退役。

### 1.4 明确不解决 + 族级清点（跨件半问应答）

- 数值边际（计数加权、通用件边际递减）：维持源迭代 §4 挂账，双前置不变；
- `decide_planner` / `decide_supply` 的 target_comp 锚定：源迭代 OQ-3 / P-3 辖域；
- 装备穿戴面（cw_screen_equip_pick）stash 移除：源迭代 P-1 S13 辖域；
- `effect_pick_bias` 偏置通道：维持恒 0 占位；
- 未锁态消费材料通用性的去留：裁定 5 辖域已裁「box 消费不变」（源迭代 §7）——本迭代以 §1.1 gap 4 的注册表事实收窄其含义：该维在箱候选域是常数，**保留与否不影响序**；设计取移除（§3 取舍），源迭代迁移表 box 行 ② 的消费语义随本设计修订（V2 修订见 §2.1）。

**族级清点（跨件半问：同族「target_comp 伪 comp 锚 → 两态化」第三件）**：flow.py 内仍消费 `state_of(session).target_comp` 的 pick 族剩余消费位 = `decide_encounter` / `decide_megastar` / `decide_partner` / `decide_star_tome` / `decide_wish_trial` / `decide_planner`。已修轨迹：decide_invest（T-155/ADR-0597）→ decide_supply（源迭代 P-3）→ 本迭代 decide_box_card（第三件）。**处置声明**：两态锚定契约（源详设契约 3：锁线 ⇔ `ist.locked_comp` 非空）已是族级底座，剩余六位各自的价值语义不同（遭遇难度/巨星/伙伴/典籍阵营匹配），逐位换轨**归口源迭代 OQ-3 扩容或后续族级迭代统一处置**，本迭代不第四件盲修——同族问题已升格为族级清点 + 归口，非逐件补丁延续。

## 2. 方案

### 2.1 共享机器（前置，吸收源迭代 P-1 + 本迭代扩展）

打分依赖 `kernel/cw_equip_value.py`（源迭代 landing.md §3.1 全量范围照执：`EQUIP_GENERIC_VALUE` 逐值平移 + `equip_material_generality` 注册表化 + `key_fit_names` + 六消费位重接）。本迭代对机器**追加三件**：

```python
def key_recipe_pairs(key_equips) -> dict[str, tuple[tuple[str, str], ...]]:
    """key_equip 成品名 → 其全部合成材料对（EQUIPMENTS.recipes 平移，缺名 → 空对）。
    【注·注册表】recipes = 配方元组的元组，每条 = (材料a, 材料b)（flow.py:675-680 r130 修正注）。"""

def equip_tier(name: str, *, key_equips: frozenset[str] = frozenset(),
               owned: Sequence[str] = ()) -> int:
    """装备名 → 档位 3/2/1/0（定义见 §2.2；owned = 库存账，近兑现判定输入）。"""

def pick_equipment(names: list[str], *, key_equips: frozenset[str] = frozenset(),
                   owned: Sequence[str] = ()) -> int:
    """装备名列表 → 选中索引（(tier, base) 字典序 argmax，并列取输入序先者）。
    key_equips 空 = 未锁态（全体 tier 0 → 纯 base 排序）；names 空 → 返回 0。"""
```

- `key_fit_names` 改为由 `key_recipe_pairs` 派生（keys ∪ 全部材料对成员）——同一推导单一源，源迭代消费位（supply +10/+3、equip_pick 子串集）签名与语义不变。V4 锁 = **独立第二构造对拍**：机器派生结果 vs 直查 `EQUIPMENTS.recipes` 遍历结果逐元素相等（两构造独立实现，防派生链自身 bug 静默）。
- `equip_material_generality` = 注册表配方引用计数（诚实派生，definition 不变）。**直调现状（2026-09-12 实跑）**：简易材料全体每件 10 条配方引用（成员槽 11，完全合成图：9 交叉对 + 1 自对），蓝钻/红钻 12，进阶装备 0——该函数值在箱候选域（同质档位 offer）内为常数，不产生任何序，**箱打分不消费它**（见 §2.2/§3）。源迭代 V2 原文「== 旧 `MATERIAL_VALUE_TABLE[n]` ∀8 名」与注册表真相互斥（手表梯度出自过期局部文档，§1.1 gap 4），**修订为独立构造对拍锁**（机器计数 vs 直查注册表计数逐名相等 + 当前注册表形态快照：简易全体等值），修订归口本迭代 landing 3.1。
- 打分语义（档位、近兑现、base 构成）唯一住机器第四件，消费位只做锚定解析与传参——后续任何「候选全部为装备的多选一」场景优先接 `pick_equipment`，禁第二套打分实现（裁定 6 同旨）。

### 2.2 选装器总形：序数分档制（档位优先，档内基分）

**档位字典序取代加法制**——打分核心即 `pick_equipment`：输入装备名列表，按 `(tier, base)` 字典序取最大，返回选中索引（并列取输入序先者，武装箱场景输入序 = OCR 从左到右，即现行取先语义）；`decide_box_card` 退化为薄壳（解析 locked_comp 两态锚 + owned 账 → 调 `pick_equipment`），自身不再有任何打分实现。

```
tier(X) = 3  若 X ∈ key_equips 且 ledger.count(X) < 需求件数(X)      # key 直击（需求未满足）
        = 2  若 near_redeem(X)（近兑现，已锁态限定，定义见 §2.3）
        = 1  若 X ∈ key_fit_names(key_equips) 材料（两跳原料）
        = 0  其余（未锁态全部落此档）

base(X) = equip_generic_value(X)        # 通用输出先验，值域 0-6（cw_events 平移表）
```

- **base 只含通用输出值**。现行材料通用性项移除：注册表直调证其在箱候选域为常数（§2.1），常数项不产生序，保留即死重；且其现行梯度值（7/6/5/4/3）出自过期局部文档，属虚构序（§1.1 gap 4）。
- **需求件数(K)** = `key_equips.count(K)`（key_equips 为可含重复的列表，注册表注「可含重复，如阿雅需 2 反重力皮靴」，cw_comps.py:107）。需求已满足的 K（含其材料对）不再吃 key 提权——唯一件族第二件即死库存（equipment_mechanics.md §4），零战力增益的冗余件必不优于任何有用件（序级：未满足需求件 > 冗余件，冗余件落 tier 0 按 base 参与排序，不打负分）。
- **未锁态**：key_equips 空 → 全体 tier 0 → 纯 base 排序 = 通用输出先验。这就是「更普遍用于输出的」：火力风暴潮(6) > 反重力皮靴(5) > 以牙还牙甲(4) > 幸运星(0)。
- **加法制 → 序数制的漂移面精确陈述**：
  - **档间序零漂移**（命题成立）：现行加法三档值域 = 直击 [100,107]、材料 [30,37]、通用 [0,7]，三段分离 → 「每一直击 > 每一材料 > 每一通用」；新制档位支配同序。此为 R1 锁的对象（标准帧，见 §2.6）。
  - **档内序 = 声明变化**（非漂移）：现行档内序 = material_value 梯度序（虚构序，§1.1 gap 4；如已锁态材料档 [生命之花 7, 轮滑鞋 6] 现行选花）；新档内序 = 通用输出值序（[生命之花 0, 轮滑鞋 4] 选轮滑鞋）。变化意图 = 档内仲裁改用与裁定 5 同源的输出先验（注册表下唯一有据的可排序信号），行为变化表 §2.6 显式申报并落锁。

### 2.3 近兑现档（tier 2）定义与推导

**判定**：`near_redeem(X)` ⟺ 已锁态 ∧ ∃ key_equip K（**需求未满足**：`ledger.count(K) < 需求件数(K)`）∧ ∃ 材料对 (A,B) ∈ `key_recipe_pairs(K)`：

```
X ∈ {A, B}  ∧  选 X 使 K 的该材料对可用对数增加
# 对数(A,B) = min(cntA, cntB)          （A ≠ B）
#            = cnt(A) // 2             （A == B，自对配方，×2 合成）
# 增加条件：A ≠ B → cnt(X) == 0 ∧ cnt(另一侧) ≥ 1
#           A == B → cnt(X) 为奇数（持 1 补第 2 只即成对；持 2 已成对不再增）
```

`ledger` = `getattr(session, 'last_owned_equips', []) or []`（list[str] 含重复，`.count` 取件数）。

**档序推导**（三段，全部零参数）：

1. **直击(tier3) > 近兑现(tier2)**【推·严格支配】：两档结局同为「K 入库」，直击额外保留伙伴材料（近兑现消耗它），结局集严格包含 → 直击恒不劣。字典序 + 档位分离使该支配**结构成立**（不受 base 干扰——这正是弃加法制的原因：若近兑现并入 +100 加法，base 项可把它顶到直击之上，破坏支配方向）。
2. **近兑现(tier2) > 原料(tier1)**【推，在册权威 = P42 ①③】：math_proofs P42 行组件保留分层「最近兑现距离 × partner 到位率——**近兑现张最贵，绝不喂**」（01_math_framework §3.6 引），R4 对抗收口的序级结论；本档序即该结论在选卡面的应用。同向自推注记：近兑现 = 立即拿到锁定线 key 装备，立即交付 ≥ 延后交付（发展优先默认，00_framework）。
3. **原料(tier1) > 通用(tier0)**：现行 +30 > 通用上界 7 的既有语义，序数化平移，非新裁。

**边界情形裁决**（实现者无需再设计）：

- 自对配方（×2 合成，注册表在册 8 条：轮滑鞋×2→反重力皮靴、光能电池×2→永动机、折叠小刀×2→碎星斩舰刀、以太钻头×2→虫洞掘进钻头、和平手枪×2→天基轨道炮、幸运星×2→随便骰子、生命之花×2→生命之环、量产型装甲×2→很硬的甲）：按对数公式 `cnt(X)` 奇数判近兑现——持 1 补第 2 只 = tier 2；持 0（选后仅 1 件不成对）与持 2（已成对）不升档；
- X 同时是另一 key 的成品与某 key 的近兑现材料 → 取 max tier（直击优先）；
- 需求已满足的 K：其直击与全部材料对退出 key 提权（§2.2 守卫）——含唯一件族第二件死库存方向；
- ledger 空/失真 → 自然落 tier 1/0，**等于现行行为**（保守向退化：漏提权非错提权，同源迭代详设 §1.4 fail-closed 口径）；
- 多个近兑现并列（不同 K 的材料对）→ base 仲裁，再并列取先。伙伴通用性最小化等更细仲裁**不做**——「伙伴材料的机会成本 ≈ 其通用性」是代理假设，无推导背书，做了即拍序。

### 2.4 锚定两态化

- 锁线布尔与锚：单源 = 源迭代详设契约 3——锁线 ⇔ `ist.locked_comp` 非空；锁定 comp 解析 = `get_comp(ist.locked_comp)`；key_equips = 锁定 comp 的 `key_equips`。flow wrapper 内 `self._ensure_intention(state_of(session))` 解析（decide_invest 先例 flow.py:507-513），strategy 契约签名不变（cw_strategy.py:206-208）。
- **target_comp 伪 comp 项移除**：现行 ①③ 项（+100/+30）的锚从 `state_of(session).target_comp` 切到 locked_comp 两态。P1 配方锁帧 locked_comp 恒空 → 自然落未锁分支（ADR-0357，源迭代契约 3 注）。
- fail-closed：locked_comp 非空但 `get_comp` 解析失败（注册表漂移）→ 按未锁态打分 + 日志哨兵（保守向：漏提权非错提权；源迭代详设 §1.4 同款）。

### 2.5 库存数据源 = state，直接消费

近兑现判定读 `session.last_owned_equips`（备战观察维护的装备库存账），**用最近读取的数据**，决策时点不引入新采集。账的构成：全量 SIFT 重写（观察采集写端，prep_actions.py:411、:571-577）+ 建模效果增量（开箱选卡/确认到账/穿戴/卖返，§1.2 清单），并有期望态对账网持续审计。既有决策消费先例 = mandate.py:1647 m7 可穿面谓词、entry.py:665 持有快照——本设计与先例同源同风险位。

防御注记（对抗审预防，非决策障碍）：在册裁定「发射位吃 last_owned_equips 陈旧快照 = 把陈旧数据源合法化」（prep_actions.py:211-216）辖的是**穿戴场景**——那里执行帧可以现读（read_equips 对装备区可见），现读严格不劣，故禁发射位吃快照。开箱场景 overlay 物理遮挡装备区，决策时点不存在现读通道，选择集是 {state 账, 盲选}；且决策与执行同一瞬间（`_open_box` 同动作选卡闭环，prep_actions.py:986-1031），该裁定针对的「发射后执行前漂移」失效面在此结构不存在——本消费不与裁定冲突。账失真的退化方向保守（§2.3 边界清单：漏提权非错提权）；新鲜度时间戳门（只信全量重写后的账）列为本迭代非目标，实机判读发现失真致错选再立项。

### 2.7 sim 可见性：结构性不可见（直调定谳）

sim 侧三事实（2026-09-12 直调）：①`FakeMatch._pick_box_card`（fake_match.py:757-788）无任何策略调用，card_idx None 恒取第 1 张；②假游戏箱选项 = 商店角色池名、落 BenchChar 入备战（fake_match.py:751-754/780-784、rules.py:176-186）——与实机箱「4 选 1 装备」（board_structure.md:61 实机采证）不同物；③`sim/` 全域无 OpenBox/PickBoxCard 决策发射（引擎不发箱动作）。结论：**本批判据层改动在 sim 结构性不可见，A/B 不可作本批判据**；验证 = B 组单元锁 + 实机判读。「假游戏箱改发装备牌并接策略路由」如需补齐，另立 sim 侧迭代，不入本批。

### 2.8 通用化边界（后续消费位接入契约）

`pick_equipment` 是「候选全部为装备、多选一」形态的通用入口，但**不是一切装备决策都能走它**：

- **纯选装形态**（候选 = 纯装备列表：武装箱、装备三选一类）→ 直接接 `pick_equipment`，禁自写打分；
- **bundle 加性形态**（补给节点 = 角色分 + 装备分合成总分再比大小）→ 字典序不可加，**不能**用本选装器，只共享价值件（数值表 / `key_recipe_pairs` / 近兑现判据）；补给装备维是否接近兑现档 = 源迭代（2026-09-12-supply-selection）辖域的设计增量，本迭代不代裁；
- **equip_pick（装备三选一）**：现行通用信号 =「泛用关键词 +1」启发式，与数值表不同源；接 `pick_equipment` 意味着换轨其通用信号与档位结构（材料将降至直击之下），行为变化需单独裁定——非本迭代辖域，挂后续裁定，本迭代只保证机器接口对其可及。

## 3. 关键取舍

| 备选 | 为何放弃 |
|---|---|
| 材料通用性保留在 base（渐变序） | 注册表直调：简易材料全体等引用（每件 10 条配方/11 槽，完全合成图），箱候选域内恒常数不产生序；现行梯度值（7/6/5/4/3）出自过期局部文档 = 虚构序（§1.1 gap 4）。机器保留诚实计数函数与快照对拍锁供非箱消费位/审计用，箱打分不消费 |
| 近兑现并入 +100 加法档（复用直击常数） | base 项可把近兑现顶到直击之上，破坏「直击 ⊇ 近兑现」严格支配的序（§2.3 推导 1）；字典序分档制使支配结构成立 |
| 近兑现设独立常数（如 60，ADR-0524 定序族） | 字典序制下档位即序、无需常数载体；(tier, base) 在档间与加法制同序（§2.2 漂移面精确陈述），改写仅档内有意变化且零新数 |
| 库存感知采用计数加权（k 件递减边际） | 数值边际模型 P42 绝对值等 λ 标定（源迭代 §4 双前置未决），任何计数系数 = 拍值违宪；序数切片已捕获零参数可证的全部收益 |
| key 提权不加需求守卫（维持现行无条件 +100） | 唯一件族第二件 = 死库存（equipment_mechanics §4），零增益冗余件提权必挤占有用项；守卫零参数（需求件数 = 注册表 key_equips 件数），同族适用于直击与近兑现（泛化义务） |
| 未锁态纯输出先验之外再保留材料通用性 | 注册表下该维在箱域为常数（§2.1），保留不影响序只剩死重；「box 消费不变」裁定（源迭代 §7）的事实前提（梯度存在）已被直调推翻，本设计按证据收窄并申报修订 |
| 选卡时现读装备区 | overlay 遮挡，物理不可读（§2.5）；state 账 + 保守退化是当前唯一合法信号源 |

| 通用化做成「一个入口包打一切」（supply bundle 也走字典序选装器） | bundle 价值 = 角色分 + 装备分，须加性合成后比大小，字典序不可加（§2.8）；硬捏成单函数 = 一个函数承载两种组合语义。通用边界 = 价值件与选装器共享、组合形态各消费位自持（裁定 6 辖「表禁第二套」，不辖组合形态） |

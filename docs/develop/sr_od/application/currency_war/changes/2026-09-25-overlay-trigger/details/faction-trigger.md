# 羁绊类触发:mutator 与值变更回调(详设·阶段B)

## 问题与约束

- 总纲契约 C-回调:四个回调(`on_units_changed`/`on_equips_changed`/`on_qualification_changed`/`on_star_changed`),固定位置参数(用户裁定:函数禁 `*` 参数);挂点 = deployed 逻辑写路径的派生维护;观察写不回调。签名以总纲为准。
- 依据:trigger-inventory §1.1/§1.2/§1.4(判据事实)、§2(横切)、§3(形状 S1a/S1b/S2 + 星徽全域)。
- 前置:deployed-merge(DeployedView 单字段,「一次语义变更 = 一次写」,本篇回调无中间态问题)。

## 方案

### 值域回调级联(用户裁定 2026-09-25)

回调挂在 **deployed 值变更**上(不挂在动作上——部署/卖出/替换/合成落场/穿戴,凡改场上名单或装备,同一套回调;判据只看"值从什么变成什么")。每个值域一个专门回调,携带变更前后值;回调内部按情况触发下游值域变更与对应回调,并各自判自己的 overlay:

| 回调 | 签名要点 | 里面做什么 |
|---|---|---|
| **角色变动回调** `on_units_changed(gs, added_units, removed_units, source)` | 按名 diff 的增/减单位 | 事件通知(喂资格集);overlay 判据不住此 |
| **装备变更回调** `on_equips_changed(gs, changed_pairs, source)` | 同名存活单位的 (旧单位, 新单位) 对中 equips 有差者 | 事件通知(喂资格集);其他装备消费面留位(未来) |
| **资格集变更回调** `on_qualification_changed(gs, old_sets, new_sets, source)` | 盯的三阵营资格名集旧/新(派生存值) | 判据:S2 伙伴、S1b 重选、S1a 档位跨越(**全部资格集判据**,见下) |
| 星级回调 `on_star_changed(gs, old_star, new_star, source)` | **场上银狼星级**(派生存值;场上同名唯一 → 至多一只,值域 = 无/1/2/3;同名唯一 = 现役入口守卫在册:W43 裁决 1,char_id 级,cw_deploy_logic.py:1769-1781 `board_unique_key` + deploy/swap 入口同守卫(cw_vocab.py:1117/:1162);「同名同星≤1」仅为 merge 工作表内部不变量(cw_gain_chain.py:169),非板上身份不变量) | S3 planner 判据:**新值 ≥ 2 ∧ 该费用档未弹过**(旧值无关——覆盖无→2/1→2/无→3[用户裁定:暂时按会弹处理,待实机复核]/2→3 不弹[档已弹];无→3 形态 = 备战囤 3★ 直接上场,该档 2★ 从未上场)→ register;费用档读现役容器字段 `gs.lv999_cost_tier`(cw_game_state.py:2380,写端 = deploy_move 升费分支/pick_planner 选升费分支);簿记 = 已触发费用档集合(3/4/5 各一次,用户裁定:银狼专用) |
| (非回调)**羁绊计数字段** | 现役 `board` 多集口径维持(策略消费口不变) | 与资格集分立:卡带系多计(星核猎手无条件+1/欢愉双计,cw_bond_equips 单一源)使计数 ≠ 名集合大小;盯的三阵营无卡带,判据集合语义不受影响;增量口径保留(环境授徽面板真值不被全量重算抹掉,2026-09-18 实锤)——环境授徽跨档 = 派生资格集假阴面,反应式兜底接 + 对账行暴露 |

### 资格集语义(判据公共基础)

- **成员资格**(角色对某阵营 F)= **出身阵营 F ∨ 持 F 阵营星徽**(装备贡献单一源 = `kernel/cw_bond_equips.py` + 星徽注册表 22 枚;开拓者按所在排,形态随排)。**资格集族 = 派生存值**(dict[faction → set[名]],盯的三阵营),一次 deployed 写提交一次(old/new)。**羁绊计数字段(board)与资格集分立**:计数 = 多集口径(卡带系多计),非名集合大小;策略消费口不变,判据只读资格集。
- **一次 deployed 写按名分解三类事件**:成员增(名新现)/ 成员减(名消失)/ 存活单位变更对(同名,单位变:星/装备/排面)。三类事件全部喂资格集,提交时回调一次。
- **S2 伙伴**(住资格集回调)= 列车同行**资格集**元素增减即弹——**无来源排除**(用户裁定 2026-09-25:合成继承星徽获得新资格也弹,与巨星跨档同判)。经典"3合1 不触发"成立的原因 = 名集合不变(三月七合成前就在集合、合成后还在),集合语义天然覆盖,非排除规则。三来源全覆盖:成员增减(上场/卖出/替换)、存活单位徽变化(穿/卸/合成继承星徽)、存活单位排变化(开拓者形态切换)。
- **S1a 档位跨越**(住资格集回调,两阵营簿记分立)= 资格集**大小上穿任一档线** → 弹,单写至多一次(注册表驱动:阵营→弹窗映射小表 + FACTIONS 档位表)。**盛会之星:无簿记、无来源排除**(用户裁定 2026-09-25:降档再升档也弹;合成继承星徽致跨档也弹——纯上穿检测,与伙伴的合成排除分立);**命运圣杯:首达档一次簿记**(用户裁定:降档再回不弹,更高档仍弹)。
- **S1b 巨星重选**(住资格集回调)= chosen_megastar **跌出盛会之星资格集** ∧ 写后资格计数**仍达首档**(盛会之星首档 = 2,tiers=(2,3,4,5,6)——用户裁定:场上只剩一个/零个盛会之星角色不弹,首个成员上场也不弹)。两形态都接住:名消失(卖出/替换下场);名存活但资格丧失(卸徽且非出身,出身 ∨ 持徽两失)。合成安全:选中者被消耗时产物同名落原位且装备 = 三方并集(徽在并集内),资格不丢。

数据流:deployed 行写(单字段,一次完整语义)→ 派生维护按名分解 diff(成员增/减 + 存活对按装备/星级/排面分类)→ 事件回调(on_units_changed/on_equips_changed,通知层)→ **资格集一次提交**(成员 + 装备 + 排面贡献合并)→ 资格集回调一次(三判据)→ 羁绊计数视图同步。**场上银狼星级同为派生存值**:合成入口(存活对 1★→2★)与上场入口(成员新增 2★)都汇到它的值变更 → 星级回调一次。bot 现役动作拓扑(deploy_move.py:57-70 实证):deploy_move 载荷恒 bench 源,两形态 = 空槽放置 / **替换**(目标槽被占 → 被占位单位回源 bench 槽,装备随对象);SwapDeploy = bench↔场上原槽对调(词表/sim 在册,生产执行器未接线);**换排(前↔后)无 bot 动作**(游戏能力,接线时零新增判据——单写天然覆盖)。

**星级判据的天然边界(零特判)**:2→3 不弹(该档已弹过);升费 deploy(3★ 上场变 4费1★)新值 1 < 2 不弹;卖掉 2★ 银狼星级值降不弹,再合回/再上场该档已弹过不弹;无→3 弹(用户裁定:暂时按会弹处理,待实机复核)。

**按名分解的结构性收获(零排除规则)**:全部判据无来源排除——经典"3合1 不触发"由集合语义天然覆盖(同名合成,名集合不变);合成继承星徽获得新资格 → 集合真变 → 弹(用户裁定 2026-09-25,与巨星跨档同判);换排 = 存活对仅排面变(资格集仅开拓者形态可变,其余阵容天然零差);卖出 = 名消失 → 成员减。原「同帧 2×低星消失+1×高星出现」签名匹配特判自始不存在于本设计。

### 判据归位

| 判据 | 住处 | 逻辑 | 簿记 |
|---|---|---|---|
| S2 伙伴 | 资格集变更回调 | 列车同行资格集元素增减(无来源排除,合成继承同弹)∧ 写后前提现读(姬子在场 ∧ 另有成员) | 无上限 |
| S1b 巨星重选 | 资格集变更回调 | chosen_megastar 跌出盛会之星资格集(名消失 或 卸徽致出身∨持徽两失)∧ 写后计数仍达首档(首档=2) | 无上限 |
| S1a 档位跨越 | 资格集变更回调 | 有弹窗的阵营资格集大小上穿任一档线,单写至多一次;阵营→弹窗映射注册小表 + FACTIONS 档位表,零硬编码 | **分立**:盛会之星无簿记(每次上穿即弹,降档再升也弹);命运圣杯首达档一次(降档再回不弹) |

簿记归宿:容器 sidecar(总纲 C-簿记);「已触发档位集合」为**两处**同型结构(祈愿档位/planner 费用档),可实现为通用簿记原语;巨星无簿记(纯上穿检测,用户裁定 2026-09-25)。

### 递归正确性(获得链一边递归一边改状态)

- **merge step 的行写是一次写**(受影响域各落一行)——按名分解后:名字前后都在 → 无成员事件(经典合成资格集不变 → S2/S1b 静默;继承星徽获新资格 → 集合真变 → S2 弹,用户裁定);存活单位对(载体,星+1、equips=三方并集)→ 星级/装备面事件(资格/羁绊贡献含并集徽差,可为正——备战持徽 copies 合上来)。**级联每步独立触发,每步语义完整。**
- 备战落位不改 deployed → 无回调;效果回调内嵌套发卡 → 嵌套自己的值变更与回调,同套判据。

### 边界

- **观察写不触发任何回调**:观察 = 重锚已发生的事实(弹窗已在场,反应式接)与纠偏;值等无变更,漂移采新静默(2026-09-18 在册)。回调只挂逻辑写路径。
- **mutator 零记忆义务**:写值函数(上报函数/获得链/穿戴/工具)只管写对值;回调与判据在值维护点结构性必经——buy_card 漏 star_up 一类缺口失去存在形式。

### 星徽装备变动链路(经代码全量核实)

**装备变更方式全集与行写收敛**(凡行写 = 进板面 tag 计数 = 羁绊回调数据源):

| 方式 | 写形 | 行写? |
|---|---|---|
| WearEquip 穿戴(含**穿着即合成**——worn 集两两配方,红钻+幸运星可在身上直接合成出星徽) | 目标域整表重建单笔写(wear_equip.py `_locate_unit` 全域定位:bench/前排/后排) | 目标在行域 ✓;备战席 ✗ |
| 扳手族(拆装/精密) | 库存合并写 + 行域穿戴清空写(`_write_row_equips_cleared`) | ✓(全拆) |
| 冶金炉·拖角色 | 库存 rand 写(穿戴全拆+白名单采样替换)+ 行域穿戴清空写 | ✓ |
| 冶金炉·拖装备 / 特权赋予卡 | 仅库存写 | ✗(未穿不计数) |
| 卖出回收 | 行写(成员移除)+ 库存写(sold.equips 全量回库存,sell_deployed.py:71/sell_bench.py:114) | ✓(成员+徽一次行写) |
| 合成装备继承 | merge step 行写:被消耗两只装备全量并入载体(产物 equips = 三方并集) | ✓(载体在场上) |
| 库存获得面(gain_equipment/pick_supply/collect_ore/投影仪/pick_planner) | 库存/bench 写 | ✗ |

- **判据数据源完整性**:装备变更收敛到行写的 5 类**全部是单笔完整语义写**(旧单位表→新单位表一次写完)——容器纪律"凡改场上单位必经行写"使回调零遗漏;库存/备战面天然无回调,与游戏语义一致(只有穿在场上单位的星徽计数)。
- **diff 粒度**:键级 diff(键含装备集,`_rows_unit_key` 现役口径)→ 装备变化 = remove(旧单位)+add(新单位)同名 → 归入「存活单位变更对·装备面」事件,喂资格集/羁绊差(S2 的星徽增减面与 S1b 的卸徽失格面由此进判据,S1a 的 tag 计数同理)。
- **S1b 资格输入**:回调时点读 deployed 现值(已含新装备态),出身 ∨ 持徽现读——冶金炉把选中者星徽拆走 = 行写清空,现值资格判定当场正确。
- **备战席持徽**:bench 写不进行写 → 无回调(正确,备战不计数);上场时单位**带 equips 进 deployed**,deploy 行写 diff 含装备,资格计数首次上场即正确;溢出归位 = bench/overflow 域,零行写。

## 关键取舍

- **值变更回调(取)vs 动作出口评估(弃)**:出口评估 = 每个写方记得在正确边界调判据,buy_card 漏 star_up 的病灶原样复发;回调 = 结构性覆盖。
- **值变更回调(取)vs 写边界逐写回调(弃)**:两字段时代换排双写中间态误判(单字段合并后该物种灭绝,写边界=语义边界,弃批量机制)。
- **羁绊值维护增量口径(保留)vs 全量重算(弃)**:观察基座含左面板真值的装备贡献(环境卡授予星徽只在面板、行单位 equips 为空,2026-09-18 run 实锤),全量重算抹掉基座真值;增量只施加本次差。
- sim `_board_truth`/`_refresh_board` 当场合算(弃):羁绊值单一源 = 容器存值;sim 消费面统一改读。

# sr-od-game-update 设计

## 定位

星铁客户端版本维护的方法 skill：怎么用米哈游启动器（HoYoPlay）把本机客户端更到最新，以及 agent 无人值守时的自动化操作链路（CDP 驱动页面 + Win32 驱动原生对话框）。

**边界**：不管一条龙项目代码更新（git 层面）；不管游戏内玩法、画面建档（归 od-dev-screen-onboarding / docs/game）；不管官方数据查询（归 sr-od-dev-official-api）。更新中撞到陌生游戏画面不归本 skill 处理——先完成更新，画面问题转建档 skill。

## 背景（为什么会有这个 skill）

2026-10 星铁 4.5 → 4.6 更新时实测发现本机环境的两个结构性问题，任何「打开启动器点更新」的天真路径都会卡死：

1. **启动器没关联本机安装**：游戏是旧版启动器装的（且安装目录从 G 盘迁到 F 盘、G 盘已不存在），HoYoPlay 打开星铁页面只显示「获取游戏」，直接点会往默认路径全新下载（约 100GB，磁盘根本不够）。必须先走「定位游戏 → 选择目录 → 关联游戏」认领流程。
2. **自动化基础设施缺失**：UIA 在本环境被过滤（顶层枚举只剩 7 个元素，启动器对话框完全不可见）；截图+坐标点击对网页式界面脆弱。可行链路是 CDP（启动器为 Qt+CEF 架构，接受 `--remote-debugging-port`）+ Win32 消息驱动原生对话框。

## 关键决策与动机

- **更新必须经启动器**：增量包 + 完整性校验 + 旧冗余清理都是启动器内建能力（4.5→4.6 实测更新中自动清理约 45GB 冗余，磁盘从 6.9GB 回到 47GB）。手动下整包覆盖或改版本文件会破坏校验链，禁。
- **CDP 而非截图点击**：HoYoPlay 页面是 DOM，按文本点按钮精确且抗分辨率/窗口位置变化；CDP 口用官方标准参数 `--remote-debugging-port` 即开，无需改启动器。负面代价：启动器要以非默认参数重启，且任务后要重启恢复普通模式——换取的是可无人值守。
- **Win32 消息而非 UIA 驱动对话框**：UIA 不可用（见背景）；Win32 `EnumWindows + SendMessage` 链路完整可验。核心坑全部沉淀在 references/automation.md §5（「位置不可用」记忆路径弹窗、叠加模态吞确认信号、`GetWindowText` 跨进程读不到 Edit、`DllImport` 缺 `EntryPoint` 必抛异常）。
- **脚本随 skill 提交（scripts/）**：首次探索的脚本散落在 gitignored 的临时目录，等于没有沉淀；把验证过的实现收进 skill 才能复用。脚本内的机器特异值（游戏目录）参数化为 `-GameDir` 必填参数，仓库保持机器无关。
- **按钮状态机驱动流程**：启动器页面主按钮三态（获取游戏/更新游戏/开始游戏）精确对应「未关联/待更新/已最新」，SKILL.md 的路由以它为准，不依赖界面布局猜测。

## 实测参考数据（4.5 → 4.6，2026-10）

- 下载：约 6 分钟（千兆带宽），「校验并修复」阶段约 12 分钟，慢于下载属正常。
- 全程磁盘占用峰值：剩余空间最低降到 4.9GB（下载+写盘并行），更新结束回落到 47GB。
- 更新完成后 `config.ini` 的 `game_version` 立即变为新版本，可作为完成标志。

## 踩坑记录（2026-10-10 实机事件）

- 现象：agent 从提权 shell 启动的启动器实例里，游戏列表缺绝区零（显示「获取游戏」）；当天早些时候星铁/原神也在 agent 实例里显示过「获取游戏」。用户自己从桌面启动的实例三个游戏全部正常。
- 根因（对照实验确认）：**提权上下文启动会让启动器界面读不出已保存的游戏关联**——与调试口无关（无调试口的提权启动同样缺游戏），与 `--game` 无关（两种组合对照均复现），与数据无关（后端 `gamedata.dat` + 注册表 `GameInstallPath` 三游戏路径全程完好；绝区零未做任何操作，用户上下文启动即恢复「开始游戏」）。当日 18:32:53 前端 Local Storage 还发生过一次整体重建（SafeMode 链 + 强杀进程树诱发），其独立影响无法与提权效应区分，但用户上下文启动可完整恢复，说明持久层从未损坏。
- 沉淀规则：automation.md §1 —— 启动必须经 explorer 委托到用户桌面上下文，禁从提权 shell 直接启动；SKILL.md 第 5 步「获取游戏」先切用户上下文重启再判断；优雅退出（设置关闭行为→退出启动器 + WM_CLOSE）与强杀禁令同条沉淀。
- 对「背景」前提 1 的修正：当时显示「获取游戏」的直接原因更可能是提权上下文读取失败而非「未关联」——两条恢复路径（切上下文 / 定位关联）都已沉淀，遇到时按此顺序排查。

## 已知局限

- `--game` / `--remote-debugging-port` 参数与按钮文案来自当前版本（启动器 1.18.0.380）实测，米哈游改版可能失效——失效时优先回退人工操作路径，再更新本 skill。
- 未覆盖：启动器自身大版本更新的迁移流程、跨大版本（>1 个版本差）的更新差异、国际服（biz 后缀不同，方法同构）。

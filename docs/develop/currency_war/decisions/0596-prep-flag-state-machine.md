## 1. 背景与决策 why

### 1.1 用户九步初稿(机制化的规格来源)

每轮备战按序自问,配三旗标(商店已检查=0 / 商店需买但缺备战=0 / 节点升级检查=0),节点结束恢复旗标干净:

1. 有奖励球先点;有球且备战满 → 先卖
2. 开备战的消耗品
3. 节点升级检查=0 → 看该不该升级:该→升;不该→置 1
4. 商店已检查=0 → 开店进店;4.1 只要买了东西 → 节点升级检查=0
5. 店回:商店需买但缺备战=1 → 部署上场或卖角色;两者都不行=没得买了;能行(腾出了槽)=重进店
6. 卖备战凑息
7. 部署
8. 装备;若需卖角色拿装备 → 商店已检查=0
9. 出战;恢复节点干净状态留给下一节点

### 1.2 为什么是旗标状态机而非固定 pass

备战环的「序」已经存在(emit 编排序 + 骨架执行序 = 九步的现行形态),缺的是**跨画面复查义务的载体**:单动作环 + 终结 op 截断使「店内段发生的事」回备战后无记录。现行备战期开店闩(同 (位面,轮次) 一次)把店内席满残差锁死成结构性流失(猎点 10,本批核心缺口):商店域 M2 席满残差(店内腾席候选空)产生后回备战,闩命中挡住一切重开——即使 M1 部署腾出了槽,M2 重评也发不出 OpenShop,义务买入机会丢失至下节点(牌面全换后大概率失效)。

旗标语义 = **「自上次状态变更以来未复查」的脏标记**,不是「做过一次就永久跳过」的一次性闩;重置规则 = 约束解除事件。裁决:闩不退役(其活锁防治价值真实——同帧状态不变重发同一动作 = 2026-09-03 实机 1-1 卡死根因),改为**重置判据**(§3.3 白名单),重开有界(§6 三支柱)。

### 1.3 三旗标裁决

| 旗标 | 裁决 | 载体 |
|---|---|---|
| S1 商店已检查 | 现行 `cw4_shopped_phase` 闩**改造**(不退役):加重置白名单,三条清键路径封闭枚举 | 键式 (位面,轮次) |
| S2 商店需买但缺备战 | **新增** `cw4_shop_wanted_pending`:义务残差载体(置位=商店域残差点,消费=备战端闭环臂) | 键式 + 买因类 + 残差名单 |
| S3 节点升级检查 | **不立变量**(猎点 11):纯函数每帧幂等求值的重评触发集 ⊇ 用户字面重评集(单向上位,多查零负作用);独立变量与期望态构成双源,失步即错裁决 | 期望态新鲜度 + `test_s3_no_variable` 墓碑 |

S2 类型学复用现役买因分类学 `sell_gate.LAUNCH_CAUSES`(猎点 14,禁第二分类学):线名单缺员 = obligation 类置位;EV 席满拒因 = press 类属 discretionary,按 [13] 成型精确化注排除在重进之外、不置位。

## 3. route_tag 治理对表(T-153 立场;编者裁断要求的显式申报)

- **tag 定位 = 策略内部路由键**(发射分支的构造事实,不随时间漂移、不维护状态),只回答「这次落地该不该清 S1 键」的环路控制路由问题——**非证明、非放行证据**。卖出资格面仍由 `sell_exclusions` 统一装配 A 单一源判定,零触碰。
- **与 T-153 病灶的范畴差**:T-153 排查令打击「可漂移的策略状态字段被当放行证据」的自证循环;tag 是构造事实且**不被检查器消费**(grep 证 sim/ 检测器零 route_tag 消费点),自证风险面远低于检查器豁免形态。
- **误标损失上界**:该清不清 → wanted 滞留一拍(下帧臂重评,自愈);不该清乱清 → 一次无信息量重开店(安全阀 + G3 兜底,有界)。均非正确性损害。配套遥测:`s1_reset_by_*` 与卖出通道计数交叉对账 + 商店域 `s1_reset_mischannel` 防御位。
- **与 2026-09-08 归因遥测删除令的边界**:删除令拆除的是 SellBench.reason 的通道归因遥测(数值面禁第二源);route_tag 是环路控制路由,分属两个治理范畴——SELL_BENCH_REASONS 闭集不动,不构成删除令复活。

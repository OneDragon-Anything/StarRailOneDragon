# 货币战争版本适配(CW 域)

> 版本更新的总流程(确认客户端 → 清点新内容 → 对齐范围 → 汇总验证 → 分阶段提交)单一源 = `sr-od-version-update-adaptation` skill,其适配项路由表指向本篇。本篇 = 总流程第 3 步「逐项适配」在货币战争(CW)域的展开:判型、按域适配顺序、各域采集入口与验收判据。读者 = 智能体。

## 1. 场景判型(先判型再定深度)

拉一次官方配置(命令见 §3 角色/装备行,产物含全部域)就能判型,**判据两条**:

- **赛季号变化**:配置顶层 `season_id` 与上季不同 = 换赛季重做;`sub_season_id` 变化 = 同季扩充。
- **名单重合度**:角色名单与现有注册表大面积不重合(费用/站位/羁绊成片变化)= 换赛季重做;名单基本重合、只增不减 = 扩充。

| 判型 | 特征 | 适配深度 |
|---|---|---|
| **赛季扩充** | 名单只增不减,机制沿用 | §2 全走,判断层字段**复核**(diff 驱动),知识层**增量重跑** |
| **换赛季重做** | 角色赋能/费用/羁绊/前后台定位重做,名单大换血 | §2 全走,判断层字段**重建**(不是复核),知识层**全量失效重跑**(要等攻略沉淀,时间缓冲),识别模板按新名单重建 |

判型错了代价不对称:把换赛季当扩充 = 判断层残留旧口径带病运行;把扩充当换赛季 = 无谓重做。两条判据都指向重做才算重做,拿不准问用户。

1. ☐ **确认客户端在线且能截画面**(项目 MCP `check_game_window` / `analyze_screen`);没更新按 od-mihoyo-launcher 更新【必做】

3. ☐ **角色域**——§3.1【必做】
4. ☐ **羁绊域**——§3.2,依赖角色注册表就绪,顺序不可倒【必做】
5. ☐ **装备域 + 投资域**——§3.3/§3.4,与 3/4 无依赖可并行【必做】
6. ☐ **识别模板面**——§3.5【必做】
7. ☐ **版本敏感常量实机重采**——刷新概率表/升级经验门槛表/牌池副本数(方法见 data-collection.md §二);换赛季后**默认全变**,扩充按官方公告判【必做】
8. ☐ **测试回归**——`uv run pytest sr-od-test/test/sr_od/application/currency_war -m "not slow"`;红测逐条判断代码过时还是测试过时【必做】

10. ☐ **知识层与策略消费点**——§4.3;扩充=复核,换赛季=等攻略沉淀后重跑,**允许跨日收尾但要在进度账本登记**【必做】
11. ☐ **提交**——按域分阶段 commit,git add 逐文件点名【必做】

## 3. 各域明细

### 3.1 角色域

- 入口:`skills/sr-od-dev-currency-war/scripts/gen_plaza_chars.py`(产出五件:注册表段片段 `registry_chars_v<版本>.py` / 人读角色文档 / 立绘模板 `character_avatar/` / 掉出名单 diff 报告 / `--check-only` 对拍)。
- 注册表 = `src/sr_od/application/currency_war/data/cw_chars.py`。官方段生成片段按两侧标记注释**整段替换**接入(标记与 `cw_chars.py` 官方段标记逐字一致,零人工补逗号);`SYSTEM_UNITS` 系统单位段为实机采集人工维护,生成器不触碰。字段全官方镜像(cost/position/category_tags 多标签/羁绊三字段 factions+schools+independent/is_expert/is_hide 从配置照抄),角色名经 `canon()` 归一(U+2022→U+00B7;产出段含 • 直接报错)。
- 验收:`--check-only` 片段 vs config 对拍归零——**无需例外清单**:注册表为官方多条 1:1 镜像(同名多档各一条),旧单条注册表形式下的 `CHECK_EXCEPTIONS` 例外机制已随重建作废删除;`DISTINCT_CARDS_PER_COST` 从注册表派生自动跟上。

### 3.2 羁绊域

- 数据源 = 阵容帖接口:每帖 `role_stages[].traits[]` 条目自带官方成员名单(`role_ids`)、激活门槛(`layers`)与分层效果全文——拉若干页帖子聚合即得全量,**不用按羁绊逐个筛采**。
- 对拍:`gen_factions.py`(tiers/成员/效果三对拍)。**成员对拍依赖角色注册表先建**(官方名单 vs 注册表自报),角色域没闭环前必红——这是顺序耦合,不是缺陷。
- 注册表 = `cw_factions.py`(category 四分类/tiers/desc 为人判层)。

### 3.3 装备域

- 入口:`gen_equip_registry.py`(多源分层:骨架=官方 API,效果=图鉴 OCR 校正);产出 `cw_equipment_data.py` + 装备模板。
- 换赛季注意新装备类别(如队伍规模类、专属装备绑定映射 `intrinsic_equip_role_map`),消费点(equip_fit/合成/补给选择)按 diff 复核。

### 3.4 投资域

- 入口:`gen_plaza_invest.py`(生成 `cw_invest_data.py` 数据层 + 人读版,内建 diff 报告)。
- 人工建模增量(经济效果结构化/评估分/分类)在 `cw_investments.py`,diff 后逐条重审;换赛季 = 大面积重建模,量大可分期,但**注册表 base 数据必须先行落库**。

### 3.5 识别模板面

- 生成器自动产:角色立绘模板(`assets/template/currency_war/character_avatar/<规范名>/`,与主游 `assets/template/character_avatar/` 同构命名;多档同名共用一目录,费用底色取起始档官方费用字段,不依赖注册表)、装备模板(字节比对幂等,官方换图自动跟上)——都在 `gen_plaza_chars.py` 内。
- **掉出名单的旧模板不自动删**:生成器产掉出名单 diff 报告(`.debug/game_data/currency_war/plaza/dropped_v<版本>.md`,分「纯角色掉出(文档删除清单)」与「系统单位迁出」两类,掉出方向唯一出口),模板删除留给人工裁定(防误删换皮重出单位的识别资产)。
- 新画面元素(新 UI/新交互)实机冒烟时按 od-dev-screen-onboarding 建档。

## 4. 换赛季重做的特有面

### 4.1 判断层字段是「重建」不是「复核」

角色定位分类、羁绊分类评级、装备分类、经济效果建模这些人判字段,换赛季后旧值整体作废——逐条对照新效果原文重新判定,禁「旧值没变就保留」的惯性(diff 就算全红也属预期)。

### 4.2 掉出名单的三层处理

| 层 | 处理 | 理由 |
|---|---|---|
| 注册表条目 | 随官方段标记整段替换自然移除(重建即替换,无单独删除动作) | 带着旧条目跑 = 策略消费过期名单 |
| 角色文档 | 删(git 历史可溯) | 生成物,重跑不再产出 |
| 识别模板目录 | **暂留**,实机确认无换皮重出再清 | 特殊单位可能以新形态回归,误删 = 识别断档 |

### 4.3 知识层与策略消费点(时间缓冲期)

阵容知识(final_comps/过渡体系/聚类)、万金油名单、桥池、引擎阵营全部依赖攻略广场新版本帖沉淀——赛季初帖量不足,**不硬跑**。缓冲期策略:

1. 数据面/识别面先闭环(§2-1~9),bot 具备进局能力;
2. 知识层重跑等帖量够(约 1-2 周)后按 compo-knowledge「版本更新重跑」执行;
3. 缓冲期内是否安排实机跑局、跑局用什么策略知识,与用户对齐。

**最易漏项 = 万金油角色名单**(策略「恒囤名单」,常量 `CROSS_LINE_KEEP_NAMES`,单一源 = `strategies/impl/mandate_v1/protection.py`):它的数据依据 = `docs/game/currency_war/research/stage_transitions.md` Q1 表(三阶段阵容统计的「全程留用层」),换赛季后留场率排序必然重排——重跑 = 用新版本帖重算三阶段统计 → 对照新旧「全程留用层」 → 更新常量并同步文档依据描述。凡从 `stage_transitions.md` 派生的其他策略立场常量同批重核。

### 4.4 版本敏感注册表(扩充也要核)

升级经验门槛表、牌池副本数(判据:同费种类数必须是 3 的倍数,3合1 机制决定)、刷新概率表(行和=100% 校验)——换赛季默认全变,扩充按公告判,采集方式见 data-collection.md。

## 5. 已知坑

- **羁绊采集器要跟数据源走**:帖内 trait 条目结构带全所需字段;若发现字段缺失,先查帖子结构是否变更,别按旧流程重建「按羁绊逐个筛采」。
- **角色技能全文已在官方配置里**(含星级数值)——不再需要外部 wiki 补技能描述;若某条目 `skill_stars` 为空,按缺数据上报,别脑补。
- **官方配置的 `trait_info_list` 是空骨架**(名字/门槛/成员全空)——羁绊数据从帖子聚合,不从它读。
- **生成物内嵌的生成器路径指针**(`generated_by`/`GEN_CMD`)在重跑时自动更新;手改生成物无意义。
- **`--check-only` 片段 vs config 对拍非零退出 = 生成段待重产/待接入的正常信号**,不是生成器坏了;先看 diff 分型(新角色/费用变/羁绊变)再重跑生成器、按标记整段替换官方段。

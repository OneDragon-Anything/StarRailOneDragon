# 五相位屏迁移详设(投资环境/投资策略/战斗等待/简报/BOSS 简报)

## 问题与约束

- 本篇辖域 = 账本 T-8 五屏;总纲划给本篇的接口契约 = design.md §2.1-1 迁移手法五件套、§2.2 契约 1-5(内聚转录规则/sim 腿登记/断言集模板/零变更红线)。实现者先读总纲 §2,再读本篇逐屏节。
- 五屏现状全部直继 `SrOperation`(单 `@operation_node` 节点 + `handle`/`wait` 单方法体);迁移 = 改继 `CwScreenOpBase` + start 节点方法顶部装配点分流(投资两屏/简报/BOSS 简报 = `handle`,战斗等待 = `wait()`)+ 五段钩子转录,`cw_loop` 外循环分派与构造签名零改动(架构设计 §5.2「基类化不动外循环」)。
- **重入裁决归属 = 总纲 §2.2 契约 6 单一定谳,本篇五段表与适配器①申报均按此写**:投资环境/投资策略/简报三屏的裁决留守 `handle` 装配点分流判据之前、两路径共享段(裁决出口写端随段共享);**不进 `lifecycle_observe` 段形态、不进实机适配器①**。先例锚 = `cw_screen_encounter.py` :241-251(裁决)/:252-258(分流,注释明文「两路径共用(分流前挂,先于五段 lifecycle 的 observe 门)」)。战斗等待/BOSS 简报无「已发」旗标裁决,不涉本定谳。
- 行为零变更红线(总纲 §2.2-5)在本篇的落地面:节点预算、重入裁决位序、稳定期等待时长、判别锚全部逐字保真。

## 关键取舍

1. **战斗等待结算写端拆 reconcile 段 vs 内聚 act 体**:内聚。`_record_round_outcome` 与分支时序(读点前 1.5s 等待/页间暂存合并/残局标记)强耦合,拆到 reconcile 段必改执行时序,撞 D-94「结算即写禁惰性化」红线;五段形状让位于零变更红线(总纲 §2.2-2 内聚转录规则的适用实例)。段迹如实申报:本屏 reconcile 恒空。
2. **投资策略登记件收编 vs 留守内联**:收编。架构设计 §6.4 在册两件②明文指定「策略屏迁移批其写端入本面接线」,`EMIT_TRIGGERED_DECLARED` 申报位已预留在册;留守 = 申报面悬置(与「默认关的悬置开关」同形态,strategy-work §3 禁)。
3. **简报写端切 BoardState observe vs 留守 session 写**:留守。写端切换 = 相位 1 深度统一辖域(总纲 §1 不解决面①),前置「对局类型」建档缺口未补(架构设计 §4.4 as-built 缺口);§2.2 简报行明文允许「统一前现役形态 = session 写 + relay 载体中继」。
4. **五屏分流位置**:start 节点方法顶部、重入裁决**之后**(遭遇先例锚:`cw_screen_encounter.py` :241-251 重入裁决、:252-258 装配点分流,注释原文「两路径共用(分流前挂,先于五段 lifecycle 的 observe 门)」——裁决在分流前,两路径共享该段,避免转录两份;总纲契约 6 同源)。战斗等待例外:其无重入裁决旗标,分流在 `wait()`(`cw_screen_battle_wait.py:507`)首行出口判定之前。

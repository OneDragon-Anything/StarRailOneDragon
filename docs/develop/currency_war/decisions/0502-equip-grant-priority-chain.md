# ADR-0502: 装备合成发放辖域优先链——可行性守卫 > 承伤序 > core-first > 集中度

## 状态
accepted

## 背景
装备发放链上并存两套各自成立的设计:

- **ADR-0391 防误合成配对守卫**(`kernel/cw_comps.py::_pairing_guard_ok`,
  判定单源):分配**合法性**辖域——任何路径给角色发基础件前,拦下
  「穿着即触发非预期合成」的配对(不可逆消耗两件组件、无确认无日志)。
  保护性约束,无条件生效。
- **W880 fill-to-3 量变体**(`kernel/cw_equip_env.py::apply_fill3`):
  改派**优先序**辖域——多个同 gap 候选中谁先凑满 3 件(排序启发,无
  期望值证明),轴序为承伤序(前排先)→ core-first(输出罚 80% 最实)
  → 集中度(已穿多者先)。

两套设计从未对账,冲突在锁 `test_same_row_core_first` 上实证(仲裁
简报 `.debug/temp/currency_war/w911_w878_w880/REPORT.md` §2):同排
并列时 core 首选阿雅因「已穿以太钻头 × 改派幸运星 → 合成产物 ∉ key
集」被守卫拦下,改派自然落到次选丹恒;锁却把偏好序写成无条件断言
「必落阿雅」,落成即红(该锁组离线落码时声明未跑,从未绿过)。

**冲突本质**:守卫是「能不能发」,core-first 是「先发给谁」。偏好序
候选被可行性约束淘汰后落到次选,是约束优先于偏好的正常结果,不是
回归;且实证帧中阿雅与丹恒同为 2/3 同 gap,80% 罚差分在两者间为零,
core-first 在该帧本就无收益可兑现,守卫让位没有实际行为损失。

## 决策

确立装备合成发放的辖域优先链(**可行性守卫(ADR-0391)> 承伤序 >
core-first(W880)> 集中度**),即排序轴只在「该件对该候选守卫可行」
的候选内生效;守卫判定单源在 `_pairing_guard_ok`,排序轴不做任何
「为偏好候选绕过守卫」的逻辑。

配套三件(同批落地):

1. **锁按新辖域语义改写**:`test_cw_w880_equip_env::test_same_row_core_first`
   改为断言「守卫让位行为」——core 首选被守卫拦时改派落到可行次选,
   并在用例 docstring 披露让位场景与本 ADR 出处(锁语义单一源)。
2. **让位披露日志**:fill3 改派循环内,守卫拦下目标时打一行 debug
   日志(core 首选被让位场景),供实机判读挂账「让位事件频次与
   差分代价」——该数据是未来评估「是否值得为 core 破例」的唯一依据。
3. 本 ADR 即两处改动的语义出处;W880 设计文档(`.debug/temp/
   currency_war/w880_equip_env_design/DESIGN.md`)轴序描述由本链取代。

## Considered Options

- **③ 辖域切分 ADR + ① 锁按让位语义改写(采纳,② 的披露行顺手带上)**:
  两边设计文本都支持「守卫辖域(合法性)天然高于排序轴(偏好)」,
  不需要新数据裁决;锁组「落成即红、从未对账」按锁的存在性纪律
  (`sr-od-test/README.md` 测试纪律第 8 条)属「锁语义未被设计出处
  支撑」,改写有据。
- **② 改实现(目标序生成时预过滤守卫可行性 + 显式披露)**:行为与
  采纳项同结果(仍落次选),但排序预过滤是把「静默跳过」变「显式
  披露」的实现侧重构;披露价值由采纳项的 debug 日志行以近零成本
  兑现,预过滤本身无额外行为收益,不采纳。
- **改实现为 core 绕过守卫(让 core-first 无条件成立)**:拒——那
  需要推翻 ADR-0391 的保护性纪律(误合成=无价值销毁风险,P14 定理),
  证据门槛完全不同;当前无任何 sim/实机数据显示 core-first 在守卫
  约束下有非零差分收益,开关 `equip_env_fill3_enabled` 默认关尚未
  开臂。
- **机械跟绿(直接把锁期望值改成丹恒)**:拒——按锁的存在性纪律,
  不重推语义直接改值保绿 = 洗白通道。

## 后果

- 行为零变化:实证场景中改派本就落到次选(守卫行为先于本 ADR 存在)。
- `test_same_row_core_first` 新语义断言守卫让位;W880 锁组恢复
  「落码即对账」状态。
- **开臂判据挂账**:`equip_env_fill3_enabled` 开臂前,若实机让位
  披露日志显示「core 差一件、守卫却拦」的差分非零场景频次可观,
  需先评估为 core 破例的期望账(那是对 ADR-0391 的修订,另立 ADR),
  不得静默绕过守卫。

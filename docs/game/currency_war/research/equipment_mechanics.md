## 机制事实

### 1. 穿着即合成与装备栏合成(两条路径)

- **穿着触发**【口述·权威 + run 26 实锤】:两件简易装备穿到**同一角色**身上时游戏自动合成,无确认无日志(实证:量产型装甲×2→很硬的甲;光能电池+生命之花→绝对热量)。
- **装备栏内主动合成**【口述·权威】:两件也可在 owned 装备栏里直接合成,产物留在栏内再拖给角色——**想精确控制配对时走此路径**(穿着触发会被角色身上的残留件带偏,可能合出非预期产物)。
- **合成不耗金**【口述·权威,2026-08-28】:两条合成路径均不消耗金币(此前文档无记载,用户裁决补齐;sim 装备链 A/B 按此口径建模)。
- **卖出角色=装备全量回装备区**【口述·权威,2026-08-28】:任何装备(简易/进阶/核心不分)在角色身上时,角色被卖出一律回到 owned 装备区——穿戴是可逆暂借,唯一不可逆承诺是合成方向;与「装备可循环」(plaza_methodology §纪律)同机制的全量化表述。

### 1.1 穿戴与合成的完备语义(2026-08-28 口述·权威 + 注册表实证)

- **不存在合成不了的对**【注册表实证 2026-08-29】:8 件基础件两两 28/28 全部有配方(含文档化同名自合:量产型装甲×2、光能电池×2)——任意两件简易拖到一起必然合成。
- **两件简易不能共存,必合成**:简易拖到已穿简易的角色身上 → 立即自动合成,无共存态。
- **角色装备上限 = 3 件**。
- **合成落点(角色身上,从左到右)**:产物占**最左简易槽**——例:槽1 简易、槽2 进阶时,拖新简易进来 → 合成进槽 1。
- **装备不堆叠**:右侧装备栏每格一件,无数量堆叠(唯一例外=扳手);冶金炉同(不堆叠)。
- **唯一件归属**:倾向「全场唯一」=**待确认项**(验证路径:①用户下次实机测试;②停机 hook——出现 2 组简易装备配置时停下人工核验;hook 批已排队,⑳+2 之后执行)。
- **冶金炉**:效果见本文档「冶金炉回收流水线」节与 P14(死库存转抽卡机会)。

**代码出处**【代码实锤】:

- 配方数据层:`cw_equipment_data.Equipment.recipes`(`cw_equipment_data.py:30`,官方 API compose_list 采集生成)——每件进阶恰好一条组件名组配方(自配 `a×2` 或交叉 `a+b`);
- 图谱派生层:`cw_synthesis.py:41-44` `_ADVANCE_RECIPES` 按 `category=='进阶' and recipes` 全量派生;K8 闭合结构事实(`cw_synthesis.py:25-26` docstring):8 件基础件(7 标准简易+光能电池)C(8,2)=28 交叉 + 8 自配 = 36 件进阶全量;
- 合成判定纯函数:`cw_synthesis.synthesize_target()`(`cw_synthesis.py:101-110`,交叉配对反查)、`self_advance()`(`cw_synthesis.py:113-122`,×2 自配);
- ⚠️ 游戏内「穿着自动合成」的**触发本身没有代码建模**(执行链不拦截、不模拟)——bot 侧后果由对账策略消化:`equips 对账须认「账面 2 组件 == 画面 1 进阶」合法态`(`cw_synthesis.py:19-23` docstring 明文)。

**光能电池系勘误存档**(2026-08-26,防复发):曾把光能电池系 7 件误记为「合成不可达独占件」——错误读解「0 交叉≠不可合成」。真相(注册表实锤):8 件进阶以光能电池为基础件——电光履(`cw_equipment_data.py:71`)、战场进化手册(:78)、蓄能帆(:84)、冷笑话引擎(:89)、绝对热量(:93)、光能盾牌(:96)、行星钻地弹(:98)、永动机(:99,自配 光能电池×2),完整配方在各自 `recipes` 字段。

**后果**:①给同一人穿两件可合成组件 = 隐性消耗决策(联动口述 [29]「定阵容前不浪费合成/穿着」;P1 阶段 8 基础件不入穿戴池,常量=`cw_synthesis.RESERVED_COMPONENTS`,`cw_synthesis.py:78-82`);②装备遥测全链需知悉此机制。

### 2. 前后台限定装备

部分装备的主效果仅在前台**或**后台生效,穿错排=主效果全废(run 26 希儿案例:后排装穿前排)【口述·权威+run 26 实锤】。

**代码出处**【代码实锤】:

- 注册表**无独立站位限定字段**——限定语义只活在 effect 文本的「若位于前台/后台」字样与 `props` 结构化数值中。典型件(effect 出处均为 `cw_equipment_data.py` 对应 `_eq` 行):
  - 仅后台生效:电磁弹射器「装备者若位于后台,战斗开始时行动提前50%」(:66);反卫星狙击枪「若位于后台…幸运一击伤害提高10%」(:80);
  - 仅前台生效:步步生花「若位于前台且血量>70%…伤害增幅提高30%」(:68);高周波电锯「若位于前台…幸运一击伤害提高10%」(:74);
  - 双向异效:自适应外骨骼(前排减伤+嘲讽/后排强度+速度,:82);光速螺旋桨(按速度换算前/后台强度,:70);
  - 特权版继承同限定:电磁弹射器·特权(:136)、步步生花·特权(:138)、反卫星狙击枪·特权(:150)。
- 消费端现状【推断】:分配器(equip_allocation/cw_comps.py:1547 起)**未按站位过滤候选装备**——错排防护目前只靠部署侧(position_pref 选排,cw_chars `position` 字段:`cw_chars.py:27`)间接成立;显式「装-位匹配」校验是待办(见文末缺口节)。

- 标记形式【代码实锤】:`（唯一装备）` 后缀出现在注册表 effect 文本,共 6 条进阶系 3 组(普通+特权成对):电光履(:71/:141)、蓄能帆(:84/:154)、绝对热量(:93/:163)。其余类别(星徽/命运等)**未见**唯一标记。

### 6. 星徽与卡带的羁绊计数分流(add-if-absent vs 无条件 +1)

### 7. 银狼 2 星升费(升星升费与商店费用档解锁)

【口述·权威,2026-08-28;经 W362 审查批核实】银狼是「升星升费」机制的代表件:
**2 星银狼的费用按 3 费档重计,且开局商店只刷出其 1 星的基础费用档(3 费)、

①上场面板费用变化(升星即升费);②**商店可见性**(升费前高费档不进商店池,
这是「开局买不到 4 费银狼、升星后才可能再遇高费副本」的机制原因)。

## 装备转移机制:不能直接角色间拖拽(2026-09-02 口述)

  1. **卖掉角色(免费,主力)**——装备自动回装备区(全额返还);「过渡持有→后期转移」的常态:卖工具人→装备回区→核心重买/重穿;

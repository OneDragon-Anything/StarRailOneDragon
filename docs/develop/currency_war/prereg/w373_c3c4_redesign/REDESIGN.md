## 0. 总原则(三条,先立后展开)

1. **滤网只删「可证明 Δp=0」的支出,比较交给已有 EV 层。** C3/C4 的过滤/门都不再自建「期望账」——账在 candidates 评分层( crisis D 先例:候选在场由滤网管,放行由 V_D>0 决定,filters.py L199-201 注释即此语义)。滤网负责的是把**数学上可证明零收益**的候选摘掉,这不需要 V_continue 真值。
2. **两个时钟必须同一把尺。** rounds_alive 与 E_rounds 都按**日历轮**(每节点一格)计量(A4.1),实现=剩余节点序列逐节点投影,废除「ceil(hp/常数)」。
3. **标定从双源取,不信置信度过滤。** 死亡真源=runs.jsonl(W350 §1 v1 陷阱的正面教训);帧级差分与 run 级聚合互校,删失方向显式声明(W350 §1:置信<1 过滤=系统性剔死亡局,反保守)。

## 2. C3 重设计:濒死带支出收窄的 Δp 代理

### 2.1 语义定位(先纠措辞)

濒死带=**纯收窄**(只删不增,W363 A1 已证),设计文档与 registry 注释措辞从「支出授权细化为期望账的保守上界」改为「**支出收窄:删除下一战部署增量为零的支出**」;「期望账上界」表述删除,直至 §2.3 的比较式真的被枚举。辖域不变:plane≥2 ∧ hp_readable ∧ is_emergency ∧ hp≤下一战期望损血(四条件原样保留)。

### 2.2 Δp 代理判定式(逐动作)

**核心量:`Δp_board(s)` = 本轮采纳支出 s 后、下一战开打前可完成的「上场位增加数」。**

输入(全部已有观测,零新增读链):

- `deployed` = 当前上场数(现有观测单一源:read_deployed_count / board 计数,实现批取现行消费点同源);
- `cap` = `max_units(state.level)`(现行 deploy cap 语义单一源);
- `free` = max(0, cap − deployed);
- `bench_n` = bench 件数;
- `可上件` = bench 中非空、非正在合成动画态的普通战力件(bench_capacity 现行计数口径同源);
- 店牌 c「可上」= free ≥ 1(买下后即可部署;部署动作本身不受濒死带辖,filters.py 现状保留)。

逐动作判定(濒死帧命中时):

| 动作 | Δp_board 判定式 | 去留 |
|---|---|---|
| **R1 BuyCard(c)** | `Δp_board = 1 if free ≥ 1 else 0`(买后可部署,部署由既有 deploy 候选免费完成) | Δp_board=1 → 放行(由 EV 层按 g 定夺);=0 → 删,原因 `hoard_buy`(本轮不可能上场的纯 hoard 买:bench 满且无空位) |
| **R3 LevelUp** | `Δp_board = min(bench_n, free+1) − min(bench_n, free)`;等价于 `1 if (bench_n ≥ 1 ∧ free < bench_n) else 0` | =1 → 放行(升完立刻多上 1 件);=0 → 删,原因 `levelup_no_deploy`(bench 空,或空位已够上完所有 bench 件——升级本轮不产生任何新上场) |
| **R2 RefreshShop** | `Δp_board = 1 if ∃c ∈ shop: c 可被本轮买+上(free≥1) else 0`;「可买+上」的名集=放行向名集(目标件∪engine_seed∪高费可上强件,评分层语义,滤网只判存在性) | =1 → 放行(定向刷新);=0 → 删,原因 `blind_refresh` |
| 卖(for_gold)/部署 | 非支出 | 不辖(现状不变) |

**名单退居评分层**:原 `_target_names` 名单不再做濒死带的放行门槛,只进 R2 的存在性判据与候选排序(EV 层本就按 V_D 定夺买谁)。名单语义从「授权边界」降为「评分先验」——A1-β(off_target 强件是最高 Δp/g 选项)与 A2 方向一(final 件买而不上 Δp=0)同时被堵:前者因 free≥1 而放行,后者因 free/部署约束自然落进删除集。

### 2.3 授权集/删除集的期望比较式(替代名单枚举)

授权判据 = **`Δp_board(s) > 0`**,即:

```
授权集 = { s : deployed_after(s) − deployed_now ≥ 1 }
删除集 = { s : deployed_after(s) = deployed_now }
```

推导链(为什么 0/非0 二分是合法的期望比较,不需要 V_continue 真值):

1. 下一战胜率 p 对上场战力单调不减(机制事实:每多一名上场成员,羁绊计数与输出有非负边际;实证底座=W346 §3.2 P2 battle 分 rung 胜占比 0.34→0.65 单调,registry L195 h3 阶梯 0.139/0.416/0.778 同形)。
2. 因此 `Δp_win ≥ 0`,且 `Δp_win = 0 ⟸ Δp_board = 0`(板面不变则胜率不变——战斗结算只吃板面,不吃金)。
3. 于是删除集内支出满足 `Δp_win·V_continue − g ≤ −g < 0`,**对任意 V_continue ≥ 0 成立**——这是可证明零期望,不是「保守上界」;删除无需求出 V_continue。
4. 授权集内支出 `Δp_win > 0` 但 `Δp_win·V_continue` 与 g 的大小未知 → 交给既有 EV 层(V_D/预算仲裁)定价,滤网不越权。这就是「期望比较式」的完整形态:滤网做**符号判定**(可证明负 → 删),EV 层做**数值判定**(正但值多少 → 排序定夺)。

**与 ADR-0302/0303 反模式不复发的结构保证**:LevelUp 的删除判据不再是动作类型黑名单,而是 §2.2 R3 的可部署性谓词——谓词为真(有可上件)时 LevelUp 数学上不可能进删除集(Δp_board≡1)。防复发锁见 §6.3 锁 C3-L1/A1-α。

**显式边界声明**(设计内意图,不是疏漏):final 线目标件「买而不上」([21])在濒死带内被删——濒死带的辖域语义是「再输一场即死」帧的当轮生存,买而不上对下一战 Δp=0,按 [21] 的正常兑现节奏(羁绊组齐才上场)在濒死帧来不及兑现;该收窄与 [21] 不冲突([21] 管的是成型后的正常囤,濒死带是嵌套应急深带的例外辖域)。

### 2.4 与危机囤金态的交互(判读须分通道, A6.1)

濒死带收窄发生在 `_allowed_tags` 危机解锁**之后**(链序:应急集→crisis +refresh→濒死再收窄)。净效应=濒死帧金留存升高 → `crisis_hoard_active`(金≥40)更易翻转 → refresh 解锁面扩大,但濒死带把 refresh 再收窄为「店内有可买+上件」——D 的金只可能花在有直接 Δp 的帧。A/B 判读按 §6.2 分通道记账,防「买被拦、D 照花」的归因混杂。

### 2.5 复杂度(效率约束合规)

Δp_board 每动作 O(1)(计数比较);R2 存在性 O(|shop|)=O(5);无重算/IO/import。符合用户效率裁决(决策热路径只许 O(1) 公式/查表)。

## 3. C4 重设计:rounds_alive 改剩余节点序列逐节点投影

### 3.1 单位语义先纠(A4.1)

`rounds_alive` 的语义改为「**从当前节点起、按日历轮走,到 hp 耗尽为止还能行动的节点数**」。E_rounds(超几何到货时间)本来就按日历轮走(奖励轮 D 照常推进);投影后两边同为日历轮,A4.1 的比较对象不一致消除。

### 3.2 投影算法(可落码,伪码级)

输入:`state`(hp/plane/round_num)、`session.plane_node_table`(本位面槽序,prep 帧实时权威)+ `session.plane_node_table_plane`(表归属锚,ADR-0368)、registry 节点损血表 `line_switch_node_loss`(§4 注入)。

```python
def rounds_alive(state, session, registry) -> int:
    """剩余节点序列逐节点投影(设计=w373 REDESIGN §3.2;除数口径废除)。"""
    if not state.hp or state.hp <= 0:
        return 0
    seq = _remaining_nodes(session, state)   # 本位面 round_num..末节点的节点型序列
    h, ra = state.hp, 0
    for kind in seq:
        loss = registry.line_switch_node_loss.get(kind, 0.0)
        h -= loss          # 战斗节点扣条件损血;reward/supply 表值=0
        ra += 1            # 日历轮 +1(死在结算也先行动过这一轮)
        if h <= 0:
            break
    return ra              # 走完全表仍 h>0 → ra=剩余节点数(截断边界 §3.5)
```

- `_remaining_nodes`:节点型来源=`session.plane_node_table`(r306 开局帧实读,每备战帧重写=权威);表缺/位面锚不符 → 回退 economy §10.2 位面模板(P2: `[battle, battle, encounter, reward, encounter, reward, battle, boss]`;**P2 r7 实测表为「?」占位,未知节点按 battle+normal 档处理**——未知多算一的一场损失=存活估计更短=门更紧,保守方向显式声明,挂账多局开局帧复核后改)。节点型判定复用 `filters._next_battle_loss` 的同名映射(boss/encounter/其余→normal)单一源化。
- `line_switch_node_loss.get(kind, 0.0)`:**缺档=0(白给轮),与旧实现「缺读=normal(最大战斗档)」方向相反且各自声明**——投影里把未知战斗节点按 normal 档(上面 `_remaining_nodes` 层处理),把未知**非战斗**节点按 0,两类缺读不再共用一个兜底。
- 遭遇回血(W350 实证 hp=1 可被补给/遭遇回血):**投影取 0 下界**(回血量未标定,禁拍死值;registry 留 `encounter_heal_est` 标定接口,值=W350 后继观测回血量标定后注入,注入前恒 0)。
- 复杂度 O(剩余节点 ≤ 9)×O(1) 查表,效率约束合规。

### 3.3 损血注入形式与 W370 M1 的耦合(禁拍死值的关键)

`line_switch_node_loss` 的**数值与形式都延后注入**,与 W370 定稿同构,二选一:

- **W370 取 M1a(无条件常数口径回退)**:每节点 loss=常数 → 投影即 §3.2 伪码原样。
- **W370 取 M1b(两态 (1−p)·L_cond)**:loss = `(1 − p_rung) · L_cond(kind)`,p_rung 取 W370 M3 的 P2 胜率表;**p_rung 缺省=1**(每战全损)时两态退化为条件常数——即本批结构在 M1b 落地前后**同一份代码**,行为由 registry 注入切换,无过渡态拍死。

M1b 同时是死锁反例的深层解(§3.6):板面越强 → p 升 → 每节点期望损血降 → 投影轮数升,「强板换线能活到兑现」由胜率通道进入门判据,不再被「每战必输」的常数锁死。

### 3.4 与 E_rounds 的比较式

门判据(替换 cw_line_switch.survival_gate 内 ra 计算,其余结构不动):

```
放行 ⟺ rounds_alive(state, session, reg) ≥ E_rounds(alt)×(1+δ) + margin
```

δ(p̄ 乐观先修偏)、margin(兑现余量)沿用 registry 现字段;margin 语义扩一条:**投影的近似残差也由 margin 承载**(§3.5),注释同步。e_alt=inf / gate 关 / plane<2 分支不变。

### 3.6 死锁反例(hp=29 + E_cur=inf + drought inf)的新行为,逐帧重算

取 P2 r1 满表 `[b, b, e, r, e, r, boss]`,现 registry 条件常数(L_cond:normal 20.05 / encounter 16.67 / boss 26.71,终值以 §4 重标定为准):

- **常数口径(M1a,每战全损)**:r1 后 hp=8.95 活、r2 结算死 → ra=2。E_rounds(新线)=2 时 need=3,**仍拦**。诚实裁决:hp=29 买两场每场期望损 20 的仗本就活不下来,W363 A3 表中「全节点口径 ra=3」是把损失摊到奖励轮得到的平滑假象——**死在 r2 结算的帧拿不到 r3 的行动权**;投影给出的是严格口径,该帧被拦不是 bug 是真相。
- **两态口径(M1b,p_rung 进场)**:新线前 2 件可上场 → 板面 rung 升 → p 升 → 每节点期望损血降。以 W346 §3.2 rung2 胜占比 0.65 为例量级:p=0.65 时 normal 节点期望损 ≈ 20.05×0.35 ≈ 7.0,encounter ≈ 5.8 → hp=29 投影:r1→22, r2→15, r3(e)→9.2, r4 奖励, r5(e)→3.4, r6 奖励, r7 boss 结算死 → **ra=7 ≥ need → 第一轮放行换线**。W363 死锁反例的解锁由 shared W370 M1b 承载,本批提供投影结构使该通道可达。
- **结构性残余**:本批**不加**防死锁 latch——hp 真值可升(胜利 +2/场 ADR-0241、遭遇/补给回血),ra 并非严格单调不增,「永久拦死」在投影口径下只剩「血真的不够」一种成因,该区域由 drought bail 旁路承接(或-并存不变)是设计内归所;残余的「门拦→驻留膨胀→更低血 bail」链路列为观察项(§6.3),不造第二机制。

## 4. 标定重做(A5.4)

### 4.1 死亡局低置信帧的修正口径(核心教训=W350 §1 v1 陷阱)

**死亡真源=runs.jsonl(`result/plane_reached/final_hp`),不信 hp_confidence 过滤。** hp≤1 行**不再删失**(W350 hp=1 语义探针:非死亡,23 局有后继观测);hp_after=0 的战斗行=真死亡事件,**其损失=hp_before 全额计入**(恰是旧口径剔掉的肥尾)。

双源取数:

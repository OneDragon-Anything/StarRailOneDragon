## 1. 三个名词

- **GameState**(正名兑现;原暂名 BoardState,符号 = `kernel/cw_game_state.py`)——当前仍为
  真的局内已知事实快照。单例,每局新建,只描述「此刻」,不是「本帧画面」;跨画面
  保留的字段与不经画面写入的账本也在其中。历史序列一律归遥测。画面 op 与决策 op
  写,策略器读。
- **StrategyState**——默认策略实现的私有状态(配方方向、义务账本、信号、旗标),
  归策略实现层、框架层不感知(符号 = `strategies/impl/mandate_v1/mandate_state`;
  基类 = `CwStrategy(Generic[_TState])` 仅泛型携带)。归属判据:换一个策略实现就
  不存在的字段放这里;游戏里能观察、框架按游戏逻辑能算的,放 GameState。
- **遥测**——整局历史,每帧每动作照旧落盘。复盘/回放/统计从遥测拼,不从容器读。

## 2. 通用规则

### 2.1 一份数据,来源标记到字段

每个字段 = `{值, 来源, evidence?}`(结构 = `Field[T]`,符号 = cw_game_state.py)。
来源两态 + 两个子模:

- **observation(观察)**:亲眼看到的——用本帧识别结果覆盖旧值。sim 侧以 GameState
  真值合成时同样记 observation,evidence 恒带 `sim:synthesized`。
- **logic(逻辑)**:决策动作按游戏规则推算的预期效果,经 `write_logic` 直接写字段
  (两态制);字段值之后仍受观察覆盖辖(§2.3)。
- **carried(沿用值,子模)**:这一帧没读到、保留上次好值时写入,evidence 必带
  `carried:<来源帧>`——防旧值在遥测里被当成「本帧真读」。
- **prior(先验,子模)**:来自历史遥测调查的先验写入(如开局 hp 先验,§3.1.6),
  evidence 必带 `prior:<来源>`;仅限显式申报的条目,禁扩散。
- **载体中继(session_carrier 约定)**:接管/初始化时把会话已知事实补写进从未写过
  的字段——不设第五来源类:中继经 `GameState.relay`,source=logic
  (evidence=session_carrier),已有正式值的字段一律跳过。**空值=未知态禁中继**:
  会话默认空值('''/[])不是已知事实;**五镜像字段封闭集** = `active_strategies`/
  `active_env`/`plane_bosses`/`enemy_affixes`/`selected_difficulty`(锁锚 =
  sr-od-test test_cw_game_state_batch4);新增第六镜像喂入点必须同步扩本集与该锁。

evidence 为可选来源注记,记录证据分级(帧标签稳定范围、当场读还是开局恒值、
`superset` 标记等,随各字段申报)。

### 2.2 识别质量是写入闸门,不是字段

读不到/不可信就不写,保留上次好值;容器里只有「当前最好的已知值」。无质量位:
`None` 只表示**这一帧没读到**,不表示「未建模」——未建模的字段根本不进 schema,
缺域由 gs_schema 的域版本键表达(§3.7.1)。「机制性 None」(该画面机制上读不到)
按字段显式申报(§6.3 同源申报面)。**失读帧的字段处置二选一(统一口径)**:
①字段已有正式值 → 写 carried(沿用+来源帧标注);②字段从未读过(机制性不可读态
+新局)→ 字段保持 None。硬边界:字段一旦有过正式值,任何失读都不得把它清成 None。
**画面附加域显式例外**:shop/encounter/supply payload(§3.3/§3.4/§8.4)语义=
「当前画面的 payload,非当前画面=None」——离开画面置 None 是结构事实非失读,不适用
carried、不受本硬边界辖;在屏失读不写、沿用旧值,在屏与否由分类子态判定(§3.2.17)。

### 2.3 观察与逻辑冲突:观察赢

观察覆盖 logic 值 + 来源改回 observation + 失配记入缺陷台账
(`observe_vs_logic_mismatch`)。失配 = 推算代码 bug:留证后修推算代码,不做运行时
挂账对账兜底(错误哲学)。

### 2.4 写入规则与两个关键结构

写入点以**写入时刻的单例现引用**为基底构造新帧(frozen 帧替换),禁止拿旧帧跨时段
写回。**读不分域**:按画面分组只是方便组织写入,读取时不分区域。两个关键结构:

1. **帧观察完整度标注**(full/view/none)——消费即清;停更检测哨兵用只增不减的
   写点序号 `write_seq`,不用该标注现值。
2. **gs_schema**——域粒度版本映射(域全集 = `DEFAULT_GS_SCHEMA`,§3.7.1)。

### 2.5 逻辑写入:直接写字段(两态制)

决策动作生效后,按游戏规则推算的预期效果经 `write_logic` 直接写入字段(来源=logic),
策略器立即可读——「在观察态到来之前供决策使用」是逻辑态的全部职能。
> 术语注(首次出现):逻辑态 = 动作执行后不经观察、按游戏规则推算并直写容器的预期状态;真值以下一帧观察为准(观察赢)。推算不是免检
通道:字段值之后仍受观察覆盖辖,失配 = 推算代码 bug。原「先记预期、核对转正」的
两步机制(expect/confirm)已随两态制裁决废除。

## 3. 字段清单(按画面组织)

> 组织规则:字段写在「能写入它的画面」小节里。一个字段能在多个画面写入,主条目写
> 完整语义(None 含义/边界/效果修饰),其余画面条目互引不复制。画面切换不重置字段:
> 没有新写入就是保留值(跨画面沿用标 carried,§2.1)。各画面上的决策操作写入规则
> 见 §4,各画面小节尾有指引。

### 3.1 开局序列(难度确认 → 简报 → 位面过渡)

> 开局只写初值;之后整局由各画面自己的写端接管(各字段主条目)。

#### 3.1.1 职级 selected_difficulty

开局写定,恒稳,之后整局不再变化、不再需要画面。可见画面=难度确认屏(建档在案:
标识-当前难度职级);开局简报是否显示职级未建档采证,接线前先补档(§3.1.2 同款
纪律)。

#### 3.1.2 对局类型 game_mode

标准 / 超频博弈。可见画面=难度确认屏 + 开局简报(开局写定);**两屏均无建档区域**,
接线前先补档。边界:超频=更快/奖励略少/难度按标准最高职级;其节点结构/收入日程
差异无文档支撑,登记为知识边界。

#### 3.1.3 位面 boss 与敌人词缀(主条目)

**语义**:位面级字段(三位面 boss 名、当前词缀名单)。
**写端**:初值写端=开局简报屏(建档区域:区域-词缀行/区域-首领行);现读通道=
位面详情屏(词缀横条/boss 大图标)与敌人信息浮层(从备战屏「按钮-敌人难度」打开)。
**运行时登记**:词缀读链产出点接 `cw_affix_effects.register_affixes_from_names`
(简报屏/位面详情屏两链)→ 词缀源效果实例入效果账本(source='affix',见
[effect-domain.md](effect-domain.md) §7 词缀源节)。
**边界**:敌人词缀≠投资环境(后者=active_env,§3.4.3)。持卡改写源在册:退化
(策略卡)、敌后破坏(环境卡,开局失效一个已生成词缀)——词缀核对把改写源列入
归因输入,禁按「两屏独占写端」把改写后的合法态记失配。

#### 3.1.4 敌人难度(简报初值)

开局简报写恒值初值;逐节点现场读值与完整语义见主条目 §3.2.14。

#### 3.1.5 节点序列台账(初值)

**P1 开局过渡屏写初值**(quality=`transition_row`,链观察落地批在役);回退序
`transition_row > plane_detail > prep_row_first` 以最先落档者为准——位面详情屏有建档
锚(区域-节点条/区域-节点详情条/文本-节点编号,接管局补采通道),简报屏未建档采证。
**权威写端=备战帧 node_path 现读**(quality=`prep_row`;P2/P3 入口基线=位面内首帧
回填 `prep_row_first`,diff 观察窗较 P1 收窄,链正本 §3 申报),完整语义见主条目
§3.2.2 与 [chain-observation.md](chain-observation.md) §3。

#### 3.1.6 hp 开局先验

开局 hp 不等首个备战帧观察:对账层按**遥测先验**写入——实证档=**82/开局不利 62**
(`_AFFIX_HP_DELTA`,`kernel/cw_opening_hp.py`;经 `cw_reconcile.reconcile_hp` 开局
分支接线);其余难度档维持 None。来源 evidence=`prior:adr-0559`。

### 3.2 干净的备战画面(商店关闭态)

> 全文档唯一能看到**完整阵容/席位/羁绊面板**的画面——画面档案仅此屏建了前排/后排/
> 备战栏/羁绊面板区域(金币/血量/等级区域亦在此屏,但非排他,见 §3.5.1/§3.2.13)。

#### 3.2.1 当前节点 node

**语义**:位面 + 轮次 + 节点类型(kind),坐标系=NodeKey(跨位面 round 重启,plane
必在键内)。
**写端**:本屏节点条=台账权威现读;kind 走三源仲裁序——**结算屏权威>
节点序列台账现读 > 帧标签 OCR**(结算屏条目见 §3.5.2);帧标签仅 battle/boss 两类
稳定,采信时折 evidence。三源仲裁语义单一源 = [node-domain.md](node-domain.md)。

#### 3.2.2 节点序列台账 node_path

**语义**:本位面节点**类型序**链(逐格载体 = TokenCell{token, channel, hu_dist};现行链
= 最新权威读数**整帧覆盖**不按位合并,基线链 `node_path_baseline` = 位面入口写定)。
**写端(链观察落地批在役)**:过渡屏观察段(P1 基线 `transition_row`/离场快照
`transition_snapshot`)+ **备战帧 node_path 现读=权威写端**(`prep_row`;P2/P3 基线
回填 = `prep_row_first`)。开局初值见 §3.1.5。链观察
双源(现行链/基线链)的对接面见 [chain-observation.md](chain-observation.md)。
**边界(可被效果中途改写)**:环境/策略效果均可中途改写节点序。已知改写源=环境:
人身意外险(所有首领节点前加一个额外补给阶段)、战争边疆(第三位面战斗节点全替换
为遭遇节点);策略:决议:娱乐星球(拥有 180 金时剩余非首领节点替换为奖励节点)。
**节点内容主题替换族(类型序影响未采证)**:经济过热/经济严重过热(奖励节点替换为
(超级)次元扑满主题)只改节点内容语义——节点行图标与结算 kind 在扑满局的表现
无观察锚,本台账以类型序为真值的表述禁写进测试断言;接线前按归因输入预登记,
实机采证后定口径。改写证据 = `chain_diff` obs_event 行(基线 vs 现行,链正本 §4/§5)。

#### 3.2.3 前台角色 front_row

**语义**:前排成员列表,成员=Unit(角色 char_id、星级、装备、槽位)。**阵营不是
Unit 的存储字段**——阵营是角色的静态属性,由 char_id 查角色注册表(cw_chars)派生;
唯一例外=开拓者形态随排(前台=记忆/后台=欢愉),由 char_id+当前排推导(
详见 §3.2.18)。观察只存识别出的 char_id,禁在 Unit 另存阵营(防与注册表双源)。
**写端**(完整清单):
- 观察写端:本屏观察覆盖(唯一观察画面)。
- 逻辑写端(op,§4.2):RunDeploy 部署=前台 +该牌;SellBench 卖场上角色=前台 −该牌。
- 效果写端(§5.3,选卡时点、非 op):出售清空面(人力重组/大裁员/降本增效/现金为王,
  确定性)=逻辑写——**全员晋升替换面=随机,走观察覆盖不建逻辑写**(§5.3 归属判据)。
- 不记预期值的变化:3 合 1 合成场上吸收升星、同行换位——后果全部等本屏下一次观察
  覆盖(§4.1 豁免)。

#### 3.2.4 后台角色 back_row

同 front_row,后排。写端清单同构(观察覆盖/RunDeploy ±/SellBench −/效果出售清空面
逻辑写、全员晋升随机面观察覆盖)。**边界(cost=0 系统单位)**:佩佩/狸狸/Gemi 狸等
cost=0 系统单位落在后台——不可拖动、恒占最右槽(们)、deploy 重排候选剔除,但
**可携带装备**(槽位语义锚=备战屏画面档案 docs/game/screens/currency_war_prep.md;
注册表锚=cw_chars)。**注册表覆盖缺口(显式申报)**:Gemi 狸与泛称「狸狸」无
Character 条目——识别库与「deploy 剔除 cost==0」按注册表运行兜不住其占位;条目
补建归注册表建模批(或显式申报「不建」及理由,禁静默)。

#### 3.2.5 备战席 bench

**语义**:统一槽位视图(载体 = `BenchView`:slots+capacity)。**容量默认恒 9**
(常量 `BENCH_CAPACITY_DEFAULT`),不随等级/职级变化——随等级变化的是后台格数

补给箱 | 星徽秘典(占席待实机证实——画面档案只有弹窗、无席位区域锚)| 空。
**占位真值只有这一份**。
**写端**(完整清单):
- 观察写端:本屏观察覆盖(含星级观察消费:备战屏 read_star 链经观察喂入口写
  gs.bench,零新增 OCR,§3.2.18)。
- 逻辑写端(op,§4.2):OpenBox 开箱(箱槽→空/新内容);BuyCard 买牌(落位)与
  **合成升星逻辑态直写**(BuyCard 执行落地门 `detect_merge_upgrade` 检测同名最高星
  抬升 → `write_logic(gs.bench, 逻辑态推算 BenchView)`,两态制,下一备战帧实读覆盖);
  RunDeploy 部署(备战席 −该牌);SellBench 卖备战席角色(−该牌)。
- 效果写端:板面重写桥 `apply_board_rewrite` 全场出售面(人力重组/卖全场族,清空
  备战席+退款,§5.3;生产挂点=选卡登记点);效果改写源在册:乱成一锅粥/+(最左 6 槽
  逐节点重掷)、公司人才流动(最右 3 槽逐节点改写)、狸职手续(每 2 节点随机 1 狸
  离场留装备)、愚者恶作剧(离场产金——进席走买牌域)、打捞人才库/+(进补给阶段发
  未选角色进席)、发牌进席族(节节高升/天降救兵/价值投资/援军族/全都要等,按归属
  判据逐卡分面,§3.2.18/§5.3)。
**边界**:**容量唯一改写源=节省工位**(官方原文「在接下来3个节点只有3个备战席位置。
随后,获得3件简易装备」)——时限效果,激活期间 capacity=3、3 节点后自动回 9,经
效果账本容量逻辑态桥 `project_effect_capacity` 逻辑写入(桥声明契约=payload 鸭子属性
capacity_limit;当前注册表零条目携带=恒默认 9 幂等 no-op;**首批容量条目入册须同批
补观察构造器容量感知**,防观察覆盖 logic 刷缺陷台账)。**奖励球不占席**——它是点击
目标不是席位居民(角色/补给箱才落席占 1 槽、席满点不动)。席空数=**策略器侧派生
计算,不入容器**(字段准入四问③):没读到=不确定、禁猜 0;sim 合成帧「箱不占席」
=sim 内部口径约定(sim 无箱实体),记录模型按实机真值。**席满判定=同源派生**
(`bench_is_full`,席空数==0,含商店开态满栏买牌判定);「备战席已满」警告 OCR 不做
识别——出现太短暂、无法可靠采样(玩家裁定 2026-09-09,现役 read_bench_full 通道
退役)。

#### 3.2.6 board(上阵羁绊计数)

**语义**:当前上阵单位的羁绊计数(dict:羁绊名→人数)。
**写端**:双源——聚合计算底座 + 本屏左面板 OCR 覆入。**聚合输入含装备授予成员资格**:
星徽=add-if-absent(非成员才计 1)/卡带=无条件 +1——单一源=
`cw_bond_equips.unit_bond_tags`。史实勘误两条各带出处:①星徽局档位系统性低估的
成因=装备羁绊贡献整维缺失(在册);②星徽误按卡带「无条件 +1」语义=分表勘误

#### 3.2.7 部署容量与后排布局档 back_layout

**语义**:上场单位站两排——前台恒 4 格;**后台一排的格子数会变**(正常 6 格,实拍
最多 9 格)。本字段=「当前这一局后台实际画了几个格子」,决定部署/拖动用哪套槽位
坐标(选错坐标=往不存在的格子上拖)。
**机制(终判)**:后台格数 = 6 + (cap − 等级),**值域 6-9、上限 9**;与
等级无关(旧「等级≥7→8 格」模型已被三帧实拍推翻);等级只进 cap 板满门、不进布局
选档。备战席容量也不随等级变(恒 9,唯一例外=节省工位,§3.2.5)。
**识别(三信号+裁决序,`cw_back_layout.py`)**:
1. **公式通道**:OCR 读「部署数」区域得 cap(防抖;**域外处置=双帧一致
   采信**:域外值重读一帧,两帧一致且 level≤cap≤`DEPLOY_CAP_ABS_MAX` → 采信+
   obs_conflict 留证;cap<level 恒拒、超绝对上界拒、两帧不一致拒)− 等级 → 差值 →
   格数=6+差值(`back_slots_from_cap_diff`:差值<0 按 0;>3 封顶按 3;裁决值与坐标
   档分离,9 档坐标未建档由调用侧运行档退 8 格超集)。
2. **CV 通道**:后台那一排直接看图,按灰度差逐位判「有没有格子」(`cv_back_slots`,
   标定阈值在册)。
3. **占用一致性仲裁**:部署人数−前台人数=后台应有人数,逐候选档比对占用最吻合档。
裁决序:两通道一致→采公式;冲突∧部署数可读→仲裁;冲突∧不可读→CV 结构证据;
CV 不可判/未建档→各自兜底(公式/防抖+8 格超集留证)。冲突必 obs_conflict 留证,
留证时把当局已选投资环境名单(active_env)列入归因输入。**环境扩槽通道**:投资
环境扩槽 6→7(实测+用户确认在册)。
**画面识别基础**:画面档案建了三套后排槽位区域——6/7/8 格各一套(7 格整排居中重排,
排中心恒 960);选中哪档就读哪套(坐标单一真相源=screen_info)。
**写入规则**:布局档字段写**运行档真实槽位数**——6/7/8 档直读;实拍出现过 9 格
(可达真实档位,坐标建档待办提级),域外一律按 **8 格超集**读全扩展带,evidence 补
`superset` 标记(防超集近似被当精确值消费)。写端两处:实机 = 三信号裁决链
`resolve_back_slots` 收尾 observe(未知态帧不写);sim = 合成口直写(evidence=
`sim:synthesized`,缺席不写)。已观测最大 cap=13。
**回归测试断言约束**:禁按未截断形态(线性外推)算预期、禁按 level 驱动表写。
**挂账**:召唤物张力——钻石使 cap>level,召唤物是否经 cap 起效在案未解(挂账件 10);历史 8 格实证与公式差 1 的张力,双通道对账天然覆盖、不硬解。

### 5.1 在场效果激活账本 effect_inventory

「当前正在生效的持续型效果」及其**进展状态**的登记表——实例=(效果规格引用、来源、
登记时点、计数器),记录的是**历史累积量**(还剩几节点/计数到几),从当前局面推

## 9. 与推演内核帧(CwSimFrame)的映射对账

### 9.1 两个表示,平行不镜像

系统里有两个「局面」表示,分工不同、长期并存:

- **GameState(本容器)= 实机真值记录模型**:记录「当前仍为真的局内已知
  事实」。它只承载实机会产生的观察与按游戏规则推算的逻辑值;sim 内部
  机制需要的表示,凡实机不产生(或刻意不入记录),容器一律不建(§8.6
  透传残差申报的收口口径)。
- **CwSimFrame(推演内核帧,符号 = `kernel/cw_vocab.py`)= sim 侧局面帧
  类型**:sim 转移/检查/离线重建面载体(引擎内部工作态已切本容器,
  写入契约见 §9.2)——环境真值(无失读态)、机制
  完整表示(含商店牌位 x、备战排位偏好、动作账),值语义可变
  (copy-on-write 试探:动作被拒时返回原帧副本续用,帧级回滚原语 =
  `CwSimFrame.copy()` 深拷贝)。

两者是平行表示,不存在「谁合并进谁」。内核帧机制本体为推演内核长期
构件,不做物理删除退役。

### 9.2 写入契约:引擎直写容器

- **生产写入 = 引擎直写**:sim 引擎内部工作态即本容器(推演内核不维护
  平行工作帧),经渠道签名写入口落字(obs/logic_action 渠道族封闭集,
  §3/journal.md);策略与引擎决策谓词在容器读口上消费。
- **帧 → 容器合成口 = `synthesize_from_game_state`**(`feed_sim_truth`
  为其正式入口包装;observation 渠道,evidence 恒带 `sim:synthesized`):
  现役消费面 = 离线/测试构造(生产引擎零调用);域覆盖增删只改该函数,
  禁散落第二写点。
- **容器值禁回写帧字段**:帧的真值来源 = 环境剧本构造(开局采样/重放
  档案/段落进场态),不是容器;回读会把记录模型的缺读态(None/carried)
  污染进机制真值。策略与引擎决策谓词经容器读口读值为合法——信息流
  单向成环:帧 →喂入→ 容器 →读口→ 策略 →动作→ 帧;禁令辖的是把
  容器值写进帧字段,不是禁读。
- **不入同步面(内核独占表示,容器刻意不建)**:商店牌 `ShopCard.x`
  (购买点击位)/`merge_preview`(升星预览)、备战侧 `position_pref`
  (排位偏好)、动作账 `action_log`(§9.3)、帧本体 copy-on-write 语义。
- **实机观测保真位不入同步面**:`hp_readable`/`hp_trusted`/`gold_readable`/
  `board_readable`/`level_readable`/`enemy_difficulty_live` 是实机观测域
  字段;sim 帧恒真读(缺省 True 即 sim 恒真读帧约定)。容器侧质量语义
  由 `Field.source`/evidence/渠道签名承载,与这些位互不映射。
- **快照边界**:容器快照(`full_state_snapshot`/`restore_state_snapshot`
  往返)仅服务离线判读面,**禁用作推演内核回滚**——快照往返丢帧侧表示
  (备战排位偏好/阵营原值/牌位 x/动作账/保真位族)。

### 9.3 两本账:动作账与执行回执

- 帧字段 `action_log` = **推演内核动作账**:机制判定(applied/rejected +
  reason)逐条记录,随帧存留、随 `copy()` 回滚;消费面 = 检查族与 sim
  账本转录。
- 容器域 `receipts` = **实机执行回执**:记录「实机执行层发出了什么」
  (发出即簿记,非验证;滚动窗,唯一写点 = `note_action_receipt`)。
  此后金动作行携结构化 `gold_delta`(extra 机制,执行点金差;备战帧
  LevelUp 花金/卖出回金的逐动作归属键),金账本体直推走
  `cw_exec_state._advance_gold` 容器通道(logic_action 渠道)。
- 两本是不同语义世界的两本账,**禁互写**:sim 侧不写 receipts(模拟动作
  不得污染实机执行回执);容器不承载 sim 拒绝记录。sim 账本的可见性走
  既有转录面(sim ledger 的 actions 序列化 + SimResult)。

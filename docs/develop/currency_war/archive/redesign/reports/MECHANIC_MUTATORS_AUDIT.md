# 机制修改器全景审计(MECHANIC_MUTATORS_AUDIT)

> 触发:用户质询「会改游戏机制的数据效果,不止 comp,都要纳入设计考虑」——新设计三文档(IMPL_DESIGN / NEW_MATH_FRAMEWORK / DESIGN_MANDATE_LAYER,下称「设计」)消费面自查发现投资策略环境已消费但数据资产零验证、优势布局三文档零提及、词缀/难度零提及。
> 本报告**只读不改**:全景清点 docs/game/currency_war/(data + research)+ 代码注册表(`cw_invest_data.py` / `cw_investments.py` / `cw_effect_ledger.py` / `cw_shop_odds.py` / `affix_effects_data.py`),逐系统裁决设计覆盖状态。
> 审计口径:「机制修改器」= 会改变**判据输入**(cap_resolved / 刷价 / λ / 池参数 / 收入日程 / 节点结构 / 候选空间)的任何游戏系统,不论它叫不叫 comp。

**F0(最重的架构级发现)设计指针错位:IMPL §2.4/总纲§2 声称 resolved 投资状态的单一源 = `cw_invest_data.INVEST_MUTATIONS`——该符号在代码中不存在**(全仓 grep 零命中)。实际突变态是 `kernel/cw_effect_ledger.py:MechanismMutation`(12 字段)+ `cw_investments.py:STRATEGY_ECONOMY`(~90 条 overlay)。且 `cw_invest_data.py` 是生成文件(头部明文「勿手编」),把 INVEST_MUTATIONS 落在那与生成器工作流冲突。**落地前必须定谳登记址**(建议 overlay 层 cw_investments.py 或 effect_ledger),否则「注册表直读」审计(IMPL §2.10.1)无从核对。

**F1 概率事件(45% 免费刷新)**:总纲§1.4 列为 P40 变体,invest_effects §2 记「期望刷价 1.1」——但 STRATEGY_ECONOMY 无此条,MechanismMutation 无刷价折扣概率字段。变体「参数替换」缺参数载体。

**F2 奋斗协议**:IMPL §6.2 声称「rate=6【注】注册表」——STRATEGY_ECONOMY 无条目,数值只存在于 cw_invest_data 效果原文文本里,无可直读的结构化字段(与「数值判据必须可溯源到注册表字段」的总纲§3 纪律不符)。

**F3 市场干预**:invest_effects §2 写「与采购专员同构,已有字段」——**overlay 实际无 '市场干预' 条目**(含 5 免费刷也未建)。文档与资产不符。

**F4 STRATEGY_ECONOMY 逐值核对(抽样全对)**:开源节流 9/利息上调 10/买断制 0+4xp/伟大征服 ×3+难度+连胜+12xp/简单模式 −3/难度修改器 −4 遭遇+首领/退化 −5+8金/远见棱彩+豁免/成长基金 9级40金/超发货币 +70@5/狸财经狸息+2——与 invest_effects/economy §10.1 原文一致 ✓。**漏项**(有文档知识、无资产):概率事件(F1)/奋斗协议(F2)/市场干预(F3)/晋升名额/飞光·映月(变费)/控制规模(等级 cap 7)/免战牌/免费升舱/武装突入(遭遇奖励改写)。

**F5 环境经济资产极薄**:ENV_ECONOMY_EFFECTS 仅 3 条(增发货币下界 6/长线利好价降/蓝海占位)。策略大师(~40-70 金,invest_effects 批5 自评「被低估的环境」)/二手市场(+30 金)/人身意外险等结构类全部无资产。

**F6 EffectLedger 节点锚与位面真值冲突**:`boss_node` 落 calendar 的锚写死 (8,17,26)、`plane_start_gold` 用 (plane−1)×9——**与 schedule_of 真值源(P1 boss@r9、P2 boss@r7,ADR-0366/0368)直接冲突**。这正是 IMPL §6.1 处死「写死 9」的同族病灶在台账层的残留;新设计 horizon 用 schedule_of,但台账侧若不重生成,特战资金系 boss 金/位面晶矿日程会错位。

**F7 轮岗/变宝为废/扑满**:ROTATION_CHANCE=0.2 在 cw_shop_odds ✓(【注】声明成立);变宝为废数值在 affix_effects_data ✓;扑满 P8 结构消费+ADR-0348 ✓。此三项资产-文档-设计三方一致。

**F8 职级难度对 λ 表的语境未声明**:总纲§3.3#11 λ_death 分层表(P51 §4-B-2,直测带 CI)是「板面战力桶×节点类型」二维——**采集自什么职级难度、词缀如何混入,设计无声明**。若跨难度复用(如 A8 表用在低职级局),λ 系统性偏移,而 λ 是三段管辖/卖面 V_power/濒死转化的共同地基。economy §9 已证难度随节点逐帧变化(实测 39-211),词缀~50 个独立作用于胜率——两者都是 λ 的未条件化混杂变量。

## 六、一句话结论

设计的经济判据输入(cap/刷价/XP 流/日程/轮岗/扑满/变宝为废/装备)覆盖良好且资产大体可溯源;**系统性盲区三个**——①优势布局/职级难度/局类型这些「局外或半局外」改机制系统零声明(其中 λ 表的标定语境不声明是数学风险);②池构成族(专家顾问/变费/黑塔纪元)是 economy §1 已有知识但设计未接的硬池突变;③设计引用的注册表符号 INVEST_MUTATIONS 不存在、概率事件/奋斗协议/市场干预三项「已消费却无资产」——落地 cw4 前需先补数据层(F0-F6),否则「注册表直读」审计线从第一行就断裂。

## 阻断级发现（8 项，含重叠）

1. **carry 第六处漏口（A1）**：`cw_loop.py` `_allocator_update` 读 `plaza_carry` 换算
   分配器 arm 键，不在批 B 范围。深挖：allocator arms 键空间来自 `from_plaza
   (family_share)` 键——「阵容→arm 键」换算散在初始化侧与 update 侧两处，57-A1
   修过的「键不配对恒 no-op」正是该散落的病灶。→ 批 B 增「分配器键换算单一源」节。
2. **批 C 行为申报单边 + 21/21 冲突未裁决（A2）**：8 套线索覆盖不满（6 套缺件）、
   火花线「爻光三鞋（皮靴×3）」不在旧 key_equips 内 → 补数据 = 装备面重写；
   「宁缺毋滥」与「21/21 非空」硬约束冲突无裁决（景元核不出出处即停手）。
   → 裁定：教义为准重写（旧手编未到人、与教义矛盾处让位）；「宁缺毋滥」降为
   「单件级」纪律（套级允许零件，建库校验要求 21/21 非空由提取优先序保证——
   8 套均已具备至少一件到人线索，零件不违反非空）。
3. **key_equips 恒等测试虚构（B-1）**：设计引用的「恒等测试长期钉双源一致」不存在
   ——全仓测试零命中，C4/C5 生产 docstring 三处（cw_comps ×2、p42 证明）指认不
   存在的测试（既有文档债）。→ 批 C 第 0 步补建恒等测试（数据批前置防线）；
   三处 docstring 引用随批修正。
4. **「零鸭型桩」不实（B-2）**：test_sell_window_launch.py:105 `SimpleNamespace`
   桩经 shop 决策链消费 `predicates.line_members`——薄委托后 AttributeError 必红。
   → 桩改造（补 members 属性）入批 A 文件面与完成判据。
5. **阶段 3.5 未定夺三处口径矛盾（A3）**：design/members 详设/landing 三种说法。
   → 裁定：从 landing 删节，DI 退役 = 独立后续迭代（design「明确不解决」二值化）。
6. **完成判据含「查缺定夺」（A4）**：序契约用例「落地时查缺定夺」不可预注册。
   → 裁定：不补序契约用例（members 实现一行 fromkeys + docstring 序语义声明；
   边际价值低于测试纪律成本），判据改为确定性表述。
7. **正本路径/落点失真（A-B2 / B-R1 / B-R2）**：skill 路径词序颠倒（junction 名
   `sr-od-currency-war-dev` vs 仓库名 `sr-od-dev-currency-war`）；10 号篇存留表
   **无 key_equips 行**（既有表缺口，措辞改「补行」非「改行」）。→ 已修正。
8. **design 含已删字段 or_reqs（A-B3）**：写作期基线被并行迭代 or-reqs-retirement
   （提交 9a1fc0cf8）推翻——字段已符号级删除。→ 图删 or_reqs；design 增基线声明
   （多 agent 并行期，落地批开工前须复核基线漂移）。

## 发现清单

### F-1 【阻断 · 核一】升级「待付窗」战斗饥饿死锁：`等节点收入` 机械上不可达

- **位置**：design §2.1（前置升级检查改语义段）、§2.2（第 4 步 item 3「候选穷尽仍不足 → 本帧零动作等节点收入」+ 第 5 步行）。
- **问题**：§2.1 把店侧检查定义为「五分支判据命中 → 返回关店动作」，未声明资格/发射门序（血闸、P21、保底金门、spend_unified 是否保留、命中但未发射时返回什么）。按字面读法，凡触发命中而升级未发射的帧：备战第 4 步零动作 → 全扫落到第 5 步 → 标记未置（转场关店不置标记）→ 开店进店 → 店内检查再命中 → 立即关店 → 回备战 → 无限 open/close 循环。部署（第 6 步）、节末凑息、出战（末步）全部不可达 → 节点收入不可达 → 「等节点收入」的前提（打仗拿钱）永不成立，且循环内金/板面零变化，触发判定状态被冻结、自永不解。若改读为「零动作返回主循环不出战」（第 0 步防御分支同款），则是备战帧零动作死循环，同样饿死出战。
- **可达性**：非边角。①五分支中人口位/arm0 为义务分支、判据无金条件（`criteria/levelup.py::upgrade_trigger` L437-456；人口位三元谓词 L50-52），低金帧照常命中；②概率账/停留门分支的现役语义就是「攒息让位、不足整级一击不买等节点收入」（`22_prep_screen.md` L30；`entry.py` L1110-1114 stockpile_wait）——攒息窗内触发命中∧发射条件不满足是常态帧型；③血本位局无凑金步（`entry.py` L863-866「不足 = 零购买，攒钱模式 = 等节点血收入」），触发命中∧血不足即进循环。现役代码同状态不饿死：旧店侧检查发射条件不满足时返回 None 落回买牌六序，会话正常收工置标记 → 出战可达（`shop.py` L893-936）。
- **依据**：`entry.py::emit` 步序（商店步 L516-520 先于部署 L522-526/出战 L556-560）；`entry.py::_step4_shop_session_pending`（L1174-1189，判定 = 标记 ≠ 当前节点即开店）；`shop.py::decide_shop_action` 标记门（L994-998）；转场关店不置标记（design §2.1）；`criteria/levelup.py::upgrade_trigger`（触发与可付性解耦）。
- **建议**：设计须二选一并写明——①店侧检查保留完整门序，仅当「本帧升级将真实发射」（花后守息线/保底金门/血闸全过）才返回关店动作，否则返回 None 照常买牌；同时补「命中∧未发射窗内升级资金保护」的真实机制（现役整级预留读预授权键，随 F-2 退役，见 F-2③）；②或 prep 侧引入「升级待付」节点态：第 4 步零动作帧抑制第 5 步开店、放行部署/凑息/出战。并补 §2.6 判据：触发命中∧未发射窗内出战帧可达（无 open/close 环）。

### F-2 【阻断 · 核一】`levelup_preauth` 按「跨画面键」单义退役，漏 prep 域自有三处在产消费

- **位置**：design §2.5（退役清单第 3 条）、§2.2（「判据每帧重评（无跨画面键）」）、§3（取舍 2）。
- **问题**：该键并非只有跨画面用途，prep 域自身以它承载「授权帧 → 变现序列每帧一卖 → 执行帧」的跨帧授权态（`11_shop_decisions.md` §2 L54-58 支出形态；`22_prep_screen.md` L30「键是唯一跨帧授权状态」）。§2.2 的「每帧重评」替代授权闩后，三处现役消费未获处置：
  1. **节末凑息抑制**：`entry.py::_step3_liquidation_pending`（L1117-1130）读该键，`_step7_node_end_interest`（L1434）消费——键退役即「变现序列优先于第 7 步凑息」语义静默死亡（同池候选竞争，`22_prep_screen.md` L41），§2.5/§2.2 均未提。
  2. **执行帧「不再重闸」语义**：现役「实付上界 = 授权值，执行帧不再重闸」是防「买一半」复发的机制载体（line_and_upgrade §2.2；11号稿 L56）；每帧重评后授权帧判过的门逐帧重开，闸翻转的行为差（如重评时 floor/spend_unified 新拒）未申报、是否等价未论证。
  3. **刷新门整级预留保护**：`shop.py` L2147-2154 读预授权键决定 reserve 是否含整级差额（shop_session.md §2.4 L58「存在预授权键/攒批目标时」）——§3 以「现役自带整级预留保护，同帧抢钱已被现役门覆盖」为预算并算放弃的理由，引用的恰是本迭代退役的机制；键亡则该保护失载体，§3 的取舍依据失效。
- **依据**：`entry.py` L887-967（键驱动帧/授权帧全链）、L1094-1098（prep 侧置键）、`session_scope.py` 节点边界重置表（L92）、`mandate_state.py` L346-349。
- **建议**：①为凑息抑制声明替代判据（如「触发命中 ∧ 缺口未闭 ∧ 变现候选尚存」派生，或新增 prep 域内在途键）；②逐帧重闸行为差显式申报（或保留 prep 域内授权闩、仅退役跨画面段）；③§3 改述真实依据（prep 先序消费金 + R1/R2 门），不得引用被本迭代退役的机制。

## §4 三点自报关注点的结论

1. **§4.1 pending_item_grants 条目形态**：真缺口，结论 = F-3。条目 schema、写端声明、宿主、sim 到点键、席满规则均须在设计内闭合后才可定稿。
2. **§4.2 重开与溢出自救次序**：设计自答——§2.2 步表已置重开于自救之后，告警在屏帧重开永不执行，「溢出告警在屏时开店是否合法」不成立为开放问题；建议把该句显式写进步位依据，消除悬置。
3. **§4.3 两屏重评一致性**：良性——关店终结动作不改任何判据输入（金/等级/板面/锁定态均容器承载），两屏读同一容器，同帧必然同判；节点收入入账发生在节点边界、不在转场间。真正相邻且未覆盖的风险 = F-1 的「命中∧未发射」窗，建议 §4.3 扩为该问题。

### F-2 `levelup_preauth` 三处在产消费面 —— **修订引入新问题（三处迁移载体均已闭合；①③语义漂移未如实申报）**

# sr-od-official-api · 设计概览(what + why)

## 为什么做

游戏内容的动态数据(当期卡池/图鉴原文/大地图点位/版本动态)没有 MCP 工具覆盖,直连官方接口是唯一实时路径;接口知识(端点/入参/出参/坑)探索成本高,沉淀成单一索引池,玩家查询与开发管道共用。定位为游戏玩家 skill:调接口只需要 HTTP 能力(web 读取工具即可),不需要克隆仓库。

## 结构

- SKILL.md:与 MCP 查询工具的分工 + 平台目录 + 公共技巧(反向找接口/详情比列表富/retcode 约定/webview 富矿等)
- `references/米游社/`:国内官方 wiki 系(角色/卡池/大地图/货币战争)
- `references/国际服wiki/`:HoYoWiki(官方英文名唯一来源)
- `references/BWIKI/`:第三方社区 wiki,补官方 wiki 没有的数据(光锥晋阶材料)
- `references/平台互连.md`:两平台 id 不互通,归一化中文名连表

## 立场与裁定台账(维护者视角)

- **玩家/开发者分工**:本 skill 只收 API 契约(端点/入参/出参/示例/id 映射/坑)与调用技巧;采集器、生成器、常量固化流程归各 sr-od-dev-* 数据 skill——它们是本手册的消费者,引用方向 = 开发者引玩家 skill(白名单允许)。
- **平台目录按内容所属站点分**(米游社/国际服 wiki/BWIKI),跨平台知识(互连)独立成档;探索过的新接口往这里放一份是维护纪律——散在脚本 docstring 或维护文档里的接口知识会随脚本沉没,索引池让它们可检索、可复用。
- BWIKI 非官方源,仅用于官方 wiki 缺失的数据(光锥晋阶材料),不做首选源。

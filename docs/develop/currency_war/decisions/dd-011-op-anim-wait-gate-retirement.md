# DD-011:操作完成自等动画规范——稳定门(gate)进入退役
> 类名已随 2026-09-03 命名迁移更替,对照 NAMING.md(本文为带日期记录,类名保持当时事实,未改)。

- Status: accepted(用户裁定 2026-09-02:「稳定门是旧时代的产物,慢慢去掉;op 完成后必须等待其动画时间,主循环基本不去关心画面稳定」;**amended 同日,用户裁决方案①**:完成判定扩为两种合法形态——固定时长自等 ∨ 识别到目标态才结束)
- 关联: DD-010(装备区识别纯化,同一哲学:识别器/op 不做画面状态判断)

## 决策

**操作完成自等动画规范**(amended 2026-09-02,方案①):

1. 每个会改变画面的操作,op 在动作完成后必须给出**完成承诺**,两种合法形态
   (按「有没有可靠时长值」二选一):
   - **固定时长自等**:时长有口述/实测值(知识档 `screen_flow_timing.md` 条目)——
     声明在动作调用的等待参数或 sleep 处,注释带出处。等待结束 = 完成承诺,
     零验证。适用:收起 1.0s(#15)/卖 1.0s(#21)/部署 2.0s(#10)等。
   - **画面身份确认轮询**:时长**无**可靠值、但有**目标画面独有判稳标志**——
     op 内轮询标志出现即完成(识别间隔与轮数上界显式声明)。适用:开补给箱
     (判稳标志 = 「标识-请选择」overlay 锚,#28)。轮询判定的是「操作是否
     生效」(标志出现 = 游戏 确认了操作生效),不是「画面稳不稳」。
2. **判稳标志纪律**:标志必须是**目标画面独有锚**(建档 area;与操作前画面
   共用的元素无判别力——开店竞速勘误:两按钮同址,误点反义按钮后共用标志
   会假成功,独有锚下表现为标志消失 → 轮询超时 → retry,不假成功)。
3. 主循环与识别层**不再等待/验证画面稳定**:op 返回成功后直接在当前帧上识别。
   两种完成形态都封闭在 op 内部——调用方视角相同:op 返回成功 = 从稳定画面出发。
4. 动画偶发拖长/未知 overlay 的兜底 = 既有 retry/fail-closed 机制(轮询超时 /
   识别不中预期画面 → round retry / bail / 对账缺陷),不预判。
5. **稳定门退役**:`wait_stable_frame`/`preset_stable_baseline`/三 profile(ADR-0213
   引入,ADR-0264 融合加速)进入退役流程——调用点逐个替换为「op 完成承诺」,
   全部清完后删除模块(含指纹/fast_confirm/基线预置机制,删除前机制文档化存档)。
   **判稳轮询不算 gate 残留**(其判据是建档 area 的操作生效标志,非指纹测量),
   不阻塞批 D 的 gate 模块删除。

### 条款澄清(原「不设第二道稳定验证」的边界)

原文第 3 条的「不设第二道稳定验证」针对的是:**op 完成承诺之外**,再叠加一层
「画面稳了吗」的测量确认(即 gate 的指纹/时间窗语义)——那层被本规范废除。
画面身份确认轮询**不在禁令内**:它是 op 完成语义本身(形态②的「等」就是
「等到标志出现」),不是完成后追加的第二道验证。形式近似(轮询+识别)但
职责归位:标志判据来自用户口述与建档,不是指纹测量;消费方是 op 自己,
不是主循环。

## Why

稳定门是「画面身份识别不成体系」年代的测量驱动产物:用截图+全图 OCR 锚定+像素
指纹+时间窗来回答「画面稳了吗」。现在建档识别(id_mark)已能一步判定画面身份,
gate 的确认价值与建档判定重复;而其结构成本(每点 1.6-2.2s 的预睡+确认窗,读数
还被 poll 的全图 OCR 量化)是备战阶段主要等待源之一。「画面稳了吗」的知识本来
就属于产生动画的操作(它知道自己做了什么、动画多长),不属于观察者——归属归位
后,主循环只管「识别→决策→动作」,稳定问题在动作侧闭合。

**为什么 amended(方案①)而非死守单一固定时长**:开店动画是「时长无可靠值、
但完成标志明确」的场景(「~3s」系记录推断已勘误;判稳标志是用户口述 #7/#14)。
单一形态会把这类操作逼成拍脑袋时长(短了半开帧读数靠防线反复重读,长了白等)。
两种形态的判据都来自用户口述与建档事实——规范覆盖两类真实场景,而不是让场景
迁就规范。判稳轮询与原文字面冲突的裁决记录:用户 2026-09-02 倾向方案①并给出口述
口径「一个 op,要么拍一个最后等待多久,要么识别到目标态才结束」。

## Consequences

- 完成承诺声明值错(时长偏短/标志选错)→ 收尾识别采到尾帧或假成功 → 由既有
  防线暴露:字段级 sanity bounds/新鲜度门(hp)、期望态对账(equip/buy)、
  round retry(画面不中)。**标志选择纪律**(独有锚)是假成功的根治线:共用
  元素作标志的假成功不触发 retry,是静默错误——新增完成承诺时先查标志唯一性。
- 完成承诺是新的维护面:游戏版本改动画时长/标志位置 → 值过期 → 表现为偶发
  retry 上升,由 retry 计数与缺陷台账暴露后校准。
- op 间既有固定间隔(success_wait 之外)若与完成承诺等待叠加,迁移时顺手收敛,
  不保留双份。
- gate 模块删除属破坏性变更,须在迁移清单清零后单独批执行(含测试仓 gate 测试
  同步退役);判稳轮询不随 gate 删除(它是 op 完成语义,常驻形态②的实现)。

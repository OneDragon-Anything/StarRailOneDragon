## 背景与问题

[31] 口述:top4 引擎羁绊(仙舟/列车/DOT 等)是胜率保证,但**没有时不能
躺平——用手上已有的其他羁绊先凑数,有总比没有厉害**;商店压库采购同理
降级:**无 top4 目标件时,优先买能与当前板面凑羁绊的其他件,纯散件基本
不买**(「一堆散件基本不可能胜利」,压测批② S1:死体系 22% 局板深卡 5-6
散扛,终局 hp 10.7)。

现行谓词结构:`_line_wants` 锁线分支只认 carry/opportunistic/桥 core/
P2 precache——目标件全缺的波,买通道对非目标卡全关(只剩 pair 的方向门
残通道,r350 后锁线时只放行线形态羁绊)。指挥官澄清架构:**无互斥,
是谓词 else 分支**——主通道全不收时,凑档降级兜底。

## 决策

1. **买侧 `_bond_fallback_wants`**(line_strategy,`_want_label` 链末
   else 分支,reason=`bond_fallback`):锁线且线库可查、战斗轮(r≥3,
   P3 口径)、**本波目标件全缺**(carry/opportunistic/当前位面桥 core
   均不在店——与 _line_wants 主通道目标定义同源)、[30] 成本带 cost≤2
   (P1 过渡带)、凑 2 档(card.faction ∈ board∪bench 已有阵营,同阵营
   ≥1 入后 ≥2)。bench 满由 _buy_guards(容量)+ 既有腾位卖通道协同辖
   (carry 腾位门同款最弱件逻辑,**不重复建**);副本/无效换卡守卫同
   _buy_guards;同轮买卖由 _round_sell_blocked(ADR-0267)辖。
   不进 _maybe_refresh/_sell_for_gold 的目标判据(降级件不是「目标」,
   不拦刷新——刷到目标件仍是正道)。
2. **部署侧**(cw_deploy_logic.select_deployments):配方围栏 hold 支
   加例外——**无目标件可上**(tgt 空集)时,凑档件(主阵营计数 ≥2,
   含自身=board 已有 ≥1)不被围栏拦;tgt 非空时围栏照旧(降级件排序
   在 tgt 之后,**不挤占目标件位置**——r404-A1 桶序既有语义)。
3. **检查项 bond_fallback_purchase_validity**(cw_sim_checks,0 容忍):
   每笔 bond_fallback 买入按账本重放验谓词五门(锁线/r≥3/波内槽消费后
   目标全缺/cost≤2/决策时点阵营——轮末 bench∪board∪本轮卖出/更早买入
   件重构,方向只放宽不收紧)。目标集与阵营口径同源镜像(检查模块不
   import 策略,依赖方向纪律;漂移由双向锁暴露)。

## Considered Options

- **塞进 _line_wants 锁线分支末级**(任务原文措辞):落点调整——_line_
  wants 的返回值被 _maybe_refresh/_sell_for_gold 当「目标在店」消费,
  内嵌会让降级件拦刷新/触发腾金买;独立谓词 + _want_label 链末 else
  才是无互斥的 else 分支语义(行为等价于「锁线分支末级」,消费面干净)。
- **pair 通道放宽 r350 方向门**:拒绝——r350 是局38 boss -34 的根因修
  (线外挂件占部署位);凑档是**目标全缺时**的降级,不是常态放宽方向门。
- **成本带不限费**:拒绝——[30] 判据=「成本带×阶段」矩阵;降级件追
  高费 = 散买翻版(批② S1 死体系形态),1-2 费是 P1 过渡件主成本带。
- **部署侧无 tgt 才放行 vs 恒放行凑档件**:选前者——tgt 非空时凑档件
  本就有 pair 计数通道可上(围栏只拦 recipe_starved+非富余态),恒放行
  会稀释配方深度(r288 配方底线门的既有权衡)。

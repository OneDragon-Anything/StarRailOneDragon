## 1. 问题与动机

### 1.1 现状症状（本局实证）

- 刷新被前置预测门卡死：位面 2 的 2-4/2-6 四次商店会话全部「开店即收店」，金 87→119 一路滞留到死亡；拒因 = 「目标可买三腿」预测失败（证据 = 复盘报告 2-4/2-6 商店章 + 策略遥测 dseq 134-137/141-144）。
- 备战位 9 张全部落在不许卖名单上，无一可卖：连带 8 座晶矿放弃（少 18 金 + 3 件装备）、追星无空位通道（证据 = 复盘报告 2-3/2-6 备战章、`sell_gate.py` identity_exclusions 排除集）。
- 单卡核心囤积规则花 9 金买 3 张牌（银狼LV.999×2+希儿），全部滞留备战位到死，无任何价值出口（证据 = dseq 109/121/129；与 12 号稿 §1.4「锁定后不换线」架构冲突——囤的换线期权已无兑现通道）。
- 同一局内，卖出相关的三处判据（部署换人、节末保利息、采晶矿前的填充牌过滤）各自一套口径，无统一的「谁该让路」判据。

### 1.2 根因归层（语义层）

三个结构性设计问题，都在判据语义层，不在流程层：

1. **刷新前置预测门**（`criteria/refresh.py` target_buyable）：刷新前预测「目标牌刷出来买不买得到」。预测在刷新时点信息不足、精确不可算（该函数 docstring 自认「需重采样预测不可算」），三腿只是粗糙近似；用信息最少的时点否决决策，是本局刷新卡死的直接机制。
2. **静态不许卖名单**（identity_exclusions 身份段）：把「通常不该卖」固化成「绝对不能卖」。名单在买入侧不断扩张（囤货判据持续买进受保护的面）、在卖出侧绝对刚性，当最高优先级需求（升星目标）需要位置时，体系被自己的名单锁死——「全场无牌可卖」是名单自己制造的状态。
3. **单卡核心囤积规则与锁后不换线冲突**：囤积的换线期权在锁定后无兑现通道，规则本身失去存在依据。

### 1.3 解决到哪 / 明确不解决

- 解决：删刷新预测门；作废单卡核心囤积规则；退役静态不许卖名单；建立统一的让位优先级体系（§2）；本次迭代触及的文档与代码同步清理内部黑话（§2.8）。
- 明确不解决：sim 世界模型的节点窗口缺失（补给/遭遇/BOSS 节点无备战窗口，另会话跟进）；部署算法本体（保持阵容目标驱动，只加虚拟重算接口，见 §2.3）；装备分配优先级（另一套对象）；投资卡选卡价值分（28/29 号稿，对象不同）。

## 2. 方案

### 2.0 核心模型一句话

**部署先行，优先级服务于让位**：部署算法（阵容目标驱动）独立决定谁上场；优先级序列作用于部署定型后的局面，回答「手里这些牌谁该让路」；商店买牌在备战位满时走「将要获取角色」流程——新牌进来、重算部署、全量排序、末位让路。

### 2.1 角色统一价值序（完整定义）

一个序列同时给**手里的牌**和**商店里的牌**定位：手里牌按它排序决定让路顺序；商店牌按它排序决定买谁/是否值得置换。按序判定，命中即出；档位编号小 = 优先级高 = 越后卖 / 越先买：

```
档 1  前后台需要出战的 —— 部署算法定型后在场服务的角色
档 2  候选/锁定阵容中，有星级要求但还没升到目标星的（升星主线，为星级目标服务）
        2.1 档内按阵容内优先级（见 2.1.1）
        2.2 同优先级的，保留总星级数更多的（所有副本星数相加，
            更容易到下一个星级）
        2.3 仍同序的，保留单卡星级更高的（通用「同优先级优先保留
            高星」规则；跨星副本场景 = 更接近目标星的副本后卖）
档 3  候选/锁定阵容中，还没获取任何副本的 —— 为阵容完整度服务
        （商店见到 → 高优先买入；档内按阵容内优先级）
档 4  当前等级所追费用档的牌 —— 为星级目标服务（压牌库价值：
        买走同档牌 = 牌池抽稀，目标刷出概率上升；依据 = math_proofs P49 线性律）
        4.1 优先保留高星的（一张两星 = 牌池里已抽走三张同档，抽稀贡献更大）
档 5  候选/锁定阵容中，已获取、没有星级要求、且还没到两星的 —— 为阵容强度服务
        5.1 档内按阵容内优先级
        5.2 同优先级的，保留总星级数更多的
档 6  万金油四角色中还没到两星的（全线留用层，数据依据 =
        docs/game/currency_war/research/stage_transitions.md Q1 表；
        名单常量 CROSS_LINE_KEEP_NAMES，复核流程 = sr-od-dev-currency-war
        skill 的 references/version-update.md）
        6.1 同优先级的，保留总星级数更多的
档 7  buff/debuff 羁绊的成员中还没到两星的 —— 羁绊名单【拍】=
        盛会之星（巨星独特加成）、量子同频（敌人受伤提高+同频）、
        护盾（护盾强度+伤害增幅）、减益（敌人挂离火：造伤降+真伤），
        成员从注册表现查（factions/flows 自报，单一真相源）
        7.1 同优先级的，保留总星级数更多的
档 8  其他 —— 8.1 按费用档的商店出现概率从高到低分档（概率高 = 容易
        再遇到 = 先卖；概率表单一源 = data/cw_shop_odds.py 按等级现查；
        已在档 4 收走的当前所追费用档不重复进本档；概率同值时按费用号
        升序稳定序、低费先卖——refresh_prob 缺键返回 0，Lv1-3 的 2-5 费
        概率全 0 撞值，此稳定序在低等级帧有真实判别语义）
        8.2 同费用的，保留星级数更多的
```

**落档边界语义**（由各档限定词自然导出，落地批写判定谓词时逐条落）：
- 成员升到目标星后，其低星冗余副本不再命中档 2（要求已满足）、不命中档 5（限「没到两星」的是无星级要求成员；有要求已满足的成员副本直接落档 8）——达标成员的冗余副本 = 占位，先让路；
- 万金油/buff 角色升到两星后掉出档 6/7（限定「没到两星」），落档 8；
- 同一张牌只会命中一个档（按序判定，先命中先出）。

**完全同优先级兜底**：以上规则全部走完仍同序时，先比「**在手优先**」——手上的牌优先于将要获取的牌（获取角色流程中虚拟置入的新牌视为「将获取」），即同优先级不换手；仍同序（两张都在手上的完全等价牌）才**随机定序**【拍】——实现用局内随机流（同 seed 可复现）。

「在手优先」的统一消解效果（不设任何场景补丁）：席满时商店出现与手上同优先级的牌（如当前追费用档的压库牌 vs 手上已有的同档压库牌）→ 在手优先胜出 → 不买 → 「卖同档买同档、牌池净抽走不变」的换手形态被序列自然禁止；有效的压牌库增量 = 商店牌优先级严格高于手上末位（卖其他档、买目标档）。

#### 2.1.1 阵容内优先级（阵容定义改造）

现状：阵容注册表里每个角色只有「是否核心」的二元标记（core_chars / shared_chars，`kernel/cw_comps.py` COMP_LIBRARY）。本迭代改为**每个阵容成员带一个优先级序数**（线内全序），替代核心/共享二元标记。

- **迁移期形态【拍】**：本迭代先按旧标记映射两档——原 core 角色 = 相同的高优先级、其余成员 = 相同的低优先级；逐角色的精细优先级（线内全序）**外溢下一迭代**设置（见 §2.11 外溢登记）。
- 数据源 = 阵容知识（`docs/game/currency_war/research/final_comps/` 各线 + 知识卡字段扩展）；消费面 = 档 2/3/5 的档内排序；
- 版本联动：阵容重跑时随知识层重核（compo-knowledge 版本重跑流程已覆盖知识层重核，本字段纳入其清点范围）。

**与旧卖出价值函数的关系**：旧函数三项（变现价、再遇难度、合成进度）在本序列中全部由档位结构承载——变现价与合成进度由「星级 + 总星级数」规则承载、再遇难度由档 8 概率分档承载。旧函数不再作为独立排序键保留，概率表保留为档 8 分档数据源，退金表为凑钱触发的目标算术数据源（非档位判定输入）。

### 2.2 优先级的边界（不消费的域）

| 域 | 判据来源 | 与优先级的关系 |
|---|---|---|
| 备战部署（补位/换人/上线窗口） | 阵容目标驱动，24 号稿现行机制全部保留 | 部署算法定型档 1；优先级不反向影响部署 |
| 位面 1 过渡配方换席 | 配方对链驱动（kernel 配方物化与单席易手现行机制） | 属部署域，不消费优先级 |
| 商店刷新 | 还没升到目标星时、等级处于该角色最优概率带的三分派判据（P1 恒不刷 / P2 未锁候选缺件 / 锁定星级目标；`criteria/refresh.py`）+ 独立金线闸（`r2_budget`） | 完全不消费优先级；删预测门后常开（金线照旧） |
| 商店买入（备战位有空位） | 买入六序判类（11 号稿 §1；六序之外的 C1 邻位支删除，dominance 段保留） | 商店牌面内部排序决定先买谁；手上的牌不参与 |

**免费刷新行为声明**（删预测门的连带）：免费刷新（概率事件与每节点免费次数，现行判定位于 shop.py 免费刷新分支——现行免费腿只查「目标可买」）改为**无条件刷**【拍】：分支内无阶段/带/目标/目标可买任何判据门，刷新提案的统一外层保险丝（负结果记忆：金线不足置位帧不刷，shop.py:2018-2023——免费与付费同闸，无特殊逻辑）照旧生效；刷新负结果记忆中「目标不可买」置位分支随预测门删除，金线不足的置位与记忆机制照旧。**行为申报**：唯一变化 = 「目标可买」门删除——目标不可买（备战位满）帧从「拦下不耗次数」变「照刷耗次数」（免费不耗金，次数每节点重置/概率补给，低价值接受）；金线不足置位帧不刷与现行一致。

### 2.3 「将要获取角色」流程（备战位满时的买入）

```
商店某牌 X 通过买入序判类与金约束，但备战位满：
  1. 虚拟局面 = 当前前后台 + 备战位 + X（X 置入备战位）
  2. 虚拟局面内模拟升星合成（唯一模拟的联动）：X 与持有牌凑满同名同星档
     即合成，机制全集口径（场上+备战混合计数、向三星推进，与现行合成
     买入机制同一规则；依据 = 11 号稿 §1 M2b 机制全集口径）——合成释放
     的备战位计入虚拟局面；可能合成后不再满位 → 无需让路直接买
  3. 其余联动（效果触发/装备/羁绊重算/环境回调）一律不模拟（复杂度不
     成本比，且不影响「谁让路」的判定主轴）【拍】
  4. 对虚拟局面调用部署算法（纯函数现算，阵容目标驱动）→ 部署定型
  5. 部署外的全部持牌按 §2.1 序列排序——**排序池 = 备战位**（场上件不入
     卖出池；若部署重算把某场上件挤出定型名单，该件的离场归后续备战环节
     的部署换人，不在买入时点卖出）
  6. 排序末位的牌让路卖出；若末位 = X 自己 → 放弃买入 X
```

- 部署算法新增**纯函数形态接口**（输入局面快照 → 输出部署结果），供买入决策虚拟重算；算法本体判据不改动（依据 = 24 号稿选人围栏/换人机制现行）。**载体定案：局面快照纯计算，禁容器深拷贝**（详见 acquisition-and-sell §部署接口——副本零遥测三通道）。
- **虚拟局面载体与遥测隔离**：载体定案 = **局面快照纯计算，禁容器深拷贝**（详设已定案，acquisition-and-sell §部署接口——MandateFrame 纯数据形态现成，快照零容器接触、遥测零风险天然成立）。**副本上的全部写入必须零遥测**——状态流水（journal）、策略遥测、决策帧三通道都不落；该项验收 = 虚拟重算执行前后遥测流水字节数不变。
- 物理约束不变：店内只能卖备战位；若部署重算导致场上角色被挤下，挤下动作发生在后续备战环节（部署换人现行机制），买入时点的卖出只落备战位。
- M2 缺件义务（终局还没到手的成员、或还没升到目标星的成员在店必买）在本流程下自然成立：这类成员是档 2/3，通常不在末位；极端态（全局面皆高档牌）买不进 = 语义自洽（手上全是高价值牌时不硬塞）。【拍】不设义务豁免特权。

### 2.4 卖出触发（三触发，一个动作）

| 触发 | 场景 | 动作 |
|---|---|---|
| 获取角色 | §2.3 流程的末位让路 | 卖末位一张，完成买入 |
| 溢出 | 备战位超载警告 | 部署重排定型后，按 §2.1 序列末位起连续卖出至不溢出（上阵安置 = 部署补位自然承载：部署逻辑保证前后台无空位，无需特殊安置规则） |
| 需要金或位置 | 凑钱买经验（守利息线）、卖牌保利息（跨档）、店内筹资补差价、采晶矿前空位 | 按序列从最低优先级卖，卖到目标（金额/空位）达成为止 |

- 「凑钱」类场景合并为**一个卖出判据件 + 参数表**（目标语义：守线金额 / 跨过利息档 / 差价 / 一个空位——见 §2.7 无场景专属池子拍板），不写四份逻辑。
- 卖出退金是序列的组成部分（星级档 + 概率分档已表达），**不设「仅一星」类代理过滤**【拍】——轮到两星就说明一星不够，正是统一逻辑的形态。
- 保留的循环防线（与优先级正交，防操作空转，非价值判断）：同轮买入禁卖（防买后即卖差价自旋）、种子年龄豁免、合成素材守卫（防卖断差一张合成的对子）。
- **溢出紧急处理的豁免保留**：溢出是保命态，现行自救场景对循环防线的豁免（全资格面放行，含同轮禁卖豁免）保留不动——保命优先于防自旋（依据 = 11 号稿 §4.0 自救场景扩展面现行）。

### 2.7 立场值与待决项（审稿焦点）

已拍板【拍】：
- 未锁定时前三候选成员同档（候选每帧重算会抖，不分榜位）；
- 万金油四角色单独一档（档 6）；
- M2 缺件买入不设豁免特权（走 §2.3 流程）；
- 凑钱场景无「仅一星」代理过滤；
- 同优先级完全等价时**随机定序**（局内随机流承载，同 seed 可复现）；
- 虚拟局面只模拟升星联动，其余联动不模拟；
- 阵容内角色定优先级序数，替代「是否核心」二元标记；迁移期按旧标记映射两档（core = 同高优先级、其余 = 同低优先级）；

- **凑钱场景统一按优先级**（部署定型后场上全部是档 1，序列自然永不先卖）——现行「凑金/凑息可卖场上无关角色」形态废止，行为变化已申报（**凑息与升级凑金两个场景的候选池都收窄**：凑金在途帧若唯一可行件为场上无关角色，凑不齐 → 整批推迟，现行 `levelup_fund_line_defer` 语义承接）；
- **无场景专属池子**【拍】：全部卖出触发（溢出/晶矿/凑钱/筹资）统一按部署重排后的全局面序列取用，不设「只看备战位」类过滤（部署内牌 = 档 1 天然永不先卖，行为等价）；

- **K 空窗回退集退役，K 目标未锁期源切换**【拍，按裁决模式推导可翻案】：未锁 P2+ 无目标帧的囤货方向不再取 kernel 机器判活方向（甲分支兜底）——**K 目标未锁期来源切换为候选快照三线成员并集 ∪ 配方成员**（与档 2/3/5 名单同源，买面与优先级面统一）；机器判活方向 ∉ 候选 top3 的分歧帧不再囤货。**行为申报（双向）**：收窄——弱势局未锁无目标帧从「按机器方向囤」变「保利息缺省」（候选都不够强的局面不强行囤）；宽放——未锁期义务买入面从「机器判活的单方向成员」扩为「候选三线成员并集」（三线成员都进入序 1 义务面，金约束门与统一序列兜底卖出共存）；kernel 三分支判据的甲分支路径退役（乙分支已定退役），丙分支保利息保留；

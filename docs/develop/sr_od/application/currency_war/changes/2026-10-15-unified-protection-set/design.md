# 统一保护集(买卖身份同源) 迭代设计(总纲)

## 0. 元信息

- 迭代目标:修复「过渡引擎件在架拒买、且被卖出通道当废牌处理」的病灶(sim 复盘局 g_20261015_154239 缺陷候选 D1/D5 卖面侧),并将买/卖两侧的卡牌身份判定统一到单一「保护集」源。用户裁定口径(2026-10-15 会话):①位面 1 买面 = 过渡阵容 + 锁定/候选终局阵容,位面 2 起 = 锁定/候选终局阵容;②买卖决策依据统一——买面优先级即卖出让位序的镜像;③过渡阵容引入与终局同构的候选/锁定语义(候选 = 四体系全体,锁定 = 体系达成);④候选/选定阵容成员不能卖、不凑息;插件/杂件可卖可凑息。
- 状态:定稿(对抗八轮收敛:15/18/14/9/13/10/7/5,零阻断连续五轮,试读全通过)
- 文档清单:无详设(本篇即完整设计)

## 1. 问题与动机

- 现状症状(sim 局 g_20261015_154239,复盘报告 = `.debug/temp/currency_war/sim_review_1/review_g_20261015_154239.md`,journal 行锚见其内;单局归因,精确拒因以落地批单帧复现为准):
  - 买面:四体系引擎件在架 **5 张次**全部拒买(r1 三月七 1 费/r3 爻光 1 费/r4 希儿 3 费(席满帧)/r6·r8 饮月 2 费;排除注:飞霄×2 为终局囤货语义、千冶·刃非四体系、卡芙卡 r9 属 D3 零动作帧 boss 备战(零动作账),均不计入引擎件拒买口径);整局 5 笔买卡 0 笔引擎件;
  - 卖面:r3 卖椒丘(DOT 体系件)腾位买风堇(填充件),DOT 引擎归零;
  - 对照:编排者对照局(2026-10-15 采集,seed 20261013/20261016/20261020 统计行)3 局死亡(P1r6/P2r1/P2r2),死亡局末金 12/42/1——金尽与死时带金两种形态并存。
- 根因归层(**语义层**):
  1. **身份域缺失(主根因)**:买卖两侧的「自己人」判定域都只覆盖**配方对/终局线**,不覆盖四体系全域——买面序 1 未锁定名单 = 方向读口(`direction_comp_of` → `opening_recipe_comp` = 配方对/早期对两体系全体成员)∪ 候选 top3 线成员(core ∪ shared)∪ 贯穿件;**配方对未选中的体系成员不在任何买入臂射程**(M2 缺口腿只吃义务面,stockpile 腿要求同名已持 1,`shop.py` M2 循环;④转投通道是唯一买「未持有过渡件」的臂但放行集仅 10 人策展口径,且在配方对物化帧被 `committed_from` 门关死)。卖面 `sell_line_membership` 同样只覆盖锁定/候选终局线——过渡体系(位面 1 的真实战力引擎,`transition_combos.md` 四体系定义)不在身份域,拼图件按金当量垫底被支配卖出(宪法 P41 ②「骨架件/跨阶段体系件不卖 fail-closed」失实现,`01_math_framework.md` §3.2)。
  2. **定型语义混淆(④通道的门错)**:④分支以 `committed_from` 为门,权威序②把「P1 配方对已物化」计为定型(`cw_intention.committed_authority` ②支)→ **配方对物化帧④恒不激活**;空窗帧(配方对派生为空)与 P2 双轨短窗 committed=False,④仍按 10 人策展口径激活——激活域与体系全域错位,且「定型」混用了「板面临时方向(配方对)」与「终局承诺」两个语义(违反 `12_line_and_intention.md` §1.2「P1 板面恒过渡体系,与方向正交」)。
  3. **静态策展名单与现算体系并存**:TRANSITION_PACK 13 人名单(④放行集取 carry/partial 10 人)与注册表现算体系成员双源,策展收录标准(Early ≥8%)漏计合法拼图(桑博等),档位标签(carry/partial/drop)被买卖身份误用作「可否中途弃」的依据。
- 解决到哪:上述三层全部(过渡域候选/锁定状态、保护集单一源、买卖两侧接线含新增囤货臂、静态身份面退役)。
- 明确不解决(防范围外溢):D2 补给拾取工序缺位;D3/D4 升级时机(P85 域);D5 置换价值表「部署 carry 同名副本」高值项(飞霄类非四体系成员,不在保护集域,另批);`committed_authority` 其余消费点(装备/部署)的语义审查(本迭代结构上消解其在 shop 的消费,本体不动)。

## 2. 方案

### 2.1 方向状态模型(新增语义)

两个域、同一套候选→锁定语义,数据底座全部复用现有结构:

| | 候选 | 锁定 |
|---|---|---|
| 过渡域(plane2_started = 假) | 四体系**全体**注册表成员 | **已点亮**的体系(支持度达标;可多个) |
| 终局域(plane2_started = 真) | 候选 top3 线成员(现行候选快照) | 锁定线名单(现行锁定槽) |

- **体系键与成员集(单一源收口)**:protection 模块的体系键 import 面唯一指向 `knowledge/cw_engine_facts.TRANSITION_TRAITS`(三羁绊键:仙舟/列车同行/持续伤害);保护集成员判定只需成员集不需档位表,**不消费 `GUARD_SYSTEM_TIERS`**(该表 = cw_deploy_logic 的守卫档位面,非本模块依赖)。成员枚举:将 `knowledge/cw_line_facts._bond_members` **公开化为 `bond_members`**(零行为,消除跨层「同式复写第 N 份」的授权形态),protection 模块消费该公开口。希儿系成员判定单一源 = 现役 `is_seele_system_member`。
- **点亮(过渡锁定)判定**:复用现役支持度链。**判定域 = 持有域(bench ∪ deployed,即 `_p1_system_support`/`_seele_system_support` 现役口径)**——保护集的语义是「持有的拼图算数」,与配方对/支持度链同域。希儿系达标 = `_seele_system_support` ≥ 1.0(首行含希儿在场门;希儿本人计入)。复用面**不含 `seele_system_formed`**(板面域,成型停手语义,与本判定的持有域选定相反;其现役消费不动)。落地批注:两支持度函数为 kernel 私有形态(下划线),跨模块消费若遇访问限制,公开化随批申报(同 bond_members 先例)。⚠️ 双源差异申报:`seele_system_formed`(板面域)与锁定槽(持有域)在「bench 满持未上阵」帧异判为本设计选定行为。⚠️ 支持度链的逐副本计数口径申报:同名多张(未合成素材)在 bench 时支持度按张数累计,存在「素材堆叠伪点亮」形态——本批锁定槽无行为消费面(仅语义与后续扩展),该形态仅入观测面,不构成行为风险;若未来锁定槽接入行为消费,须先钉素材计数修正。
- **锁定状态槽(新增)**:`StrategyState` 新字段 `transition_locked_systems: frozenset[str]`(体系键集)。写点 = 策略层决策入口前置段(与 `refresh_line_if_needed` 同点,宿主 = `mandate_v1/bridge.py`;清空点 = 进位面 2,宿主 = `strategies/impl/flow.py` 配方对退场同点)。**幂等只增不减**——达成过的体系不因掉档失去锁定(同构终局「锁后不换」,防「掉档→保护收缩→连锁卖」恶性循环)。锁定槽消费面 = 语义完备与部署/后续扩展;买面消费的锁定态是**终局锁定态**(`line_members_view.locked`,囤臂守卫),非过渡锁定槽。
- **保护集函数(新增,全仓单一源)**:`protection_membership(gs, state) -> frozenset[str]`(角色名集):
  - 过渡域:四体系全体成员(候选)∪ 已锁定终局线成员 ∪ 候选 top3 终局线成员 ∪ 贯穿件。注:过渡锁定体系 ⊆ 候选全体,对保护集无增量。
  - 终局域:锁定线名单 ∪ 候选 top3 线成员 ∪ 贯穿件(与现行 `sell_line_membership` 两分支同构,加贯穿件)。
- **宿主**:新模块 `strategies/impl/mandate_v1/protection.py`——函数需消费策略层符号(`session_scope.line_members_view`/贯穿件常量),kernel(`cw_intention`「kernel 输入纯度」)与 knowledge(`cw_engine_facts`「不 import 决策符号」)均不可宿主;贯穿件常量 `CROSS_LINE_KEEP_NAMES` 自 `shop.py` 迁入本模块(单一源搬家,shop 回导)。
- **域切换**:plane2_started 翻真时过渡域关闭;过渡域成员若属终局域候选/锁定则自然延续保护,否则滑向非保护(可卖)——对齐 `stage_transitions.md` Q2 数据(换血保留率均值 0.59-0.74,非本路线过渡件位面 2 清场、本路线组件留存居高端)。

### 2.2 买面接线(`mandate_v1/shop.py`)

- **序 1 未锁定名单**(`buy_members` 构建未锁定分支):在现行构成(配方对/早期对两体系成员 ∪ 候选 top3 线成员 ∪ 贯穿件)基础上,并集 `protection_membership` 过渡域全体成员——消除「配方对未选中体系成员」的名单缺口。
- **义务面/囤货面拆分**——**现行成员待遇零变化,仅新增成员设级**:
  - 义务面(`obligation_members`)= **现行口径不变**:配方对/早期对体系成员 ∪ 候选/锁定终局线成员 ∪ 贯穿件(免息 + 筹资 + 置换全待遇,零回退);
  - 囤货面(本次新增进名单的成员,即「非在对体系的四体系成员」)= **期权级**:
    - 首副本走新囤货臂(下条);
    - **同名副本(第二张)不设专用臂,走现行 M6 压牌库(费用档判据,过息账)与序 5 插件凑星(板面同系判据)**——为此,**五处**遍历/排除面的比对域从宽集收窄为**义务面**:m2_stockpile 循环(含 `_fund_or_none` 筹资腿)、M6 压牌库排除、press_buy_deployable 排除、垫件补位支排除、`criteria/buy.py::ev_buy` 入参——囤货面成员退出义务类买入(含筹资),恢复压牌库/凑星通道。`M2b` 合成完成买入遍历域保持宽集(已持 2 张的合成完成购语义不变)。**②(b) 死金压牌库的 prio0 缺口集(`_dg_gap`)推导域同步随义务面收窄**(与 `missing` 是两个独立推导,两者同收)。**伴生申报**:M6 的 P91 合格费用带输入(`qualified_member_costs(buy_members)`)随宽集扩员而扩——带内判定面变化为预期行为(方向集成员进入带内判定域),P91 观测键读数漂移预期内;**P92 拦刷门同族申报**:`_p92_stockpile` 从宽集推导,囤货面成员计入已被收窄的 stockpile 通道 → 拦刷判据方向为少拦刷(反保守),随义务面收窄同步修正(与 P91 同批)。
    - 申报:注册表扩员成员(如桑博)在②(b) 死金压牌库的优先档自 unrelated(prio2)位移保护档(prio1)——本批预期行为(身份升格)。**P92 拦刷门通道集伴生申报**:`_p92_stockpile` 拦刷判据随义务面收窄后,囤货臂可达帧(未锁定)会被 P92 拦刷——保守向偏差(少刷),申报接受。
- **新囤货臂(④退役的语义承接)**:位置 = M2b 之后、序 2 之前;命中条件 = **保护集成员 ∧ 未持有首副本 ∧ 未锁定帧**(`line_members_view.locked = False`;不限未点亮——已点亮但不在配方对体系的成员同臂承接;锁定局过渡件采购由配方对并集承载,囤臂不聚焦)。门序 = 1★ 全额退(`refund_full_star_ok`,[11] 零息损 + P46 豁免类「资产可逆」)→ 金可负担 → 席(席满走店内置换账,候选 = 非保护垫件;穷尽 = 放弃并计数)。买因 = `protection_hoard`(sell_gate 买因类 `hold`)。出口键:`protection_hoard_hit` / `protection_hoard_no_fuel` / `protection_hoard_unaffordable`。
- **P60 容量告警对象面收窄**:检查对象从宽集改为义务面(囤货面超容由置换账自然管理)。
- **④转投前瞻放行分支整条退役**(committed 门、`transition_release_names`、`transition_component_buy` 买因与出口键)。
- 锁定态买面(P1 锁定局 = 配方对 ∪ 锁定线;P2 = 锁定线单源)**不动**。

### 2.3 卖面接线(`criteria/sell_candidates.py` + 卖出资格装配)

- **身份面与义务基座显式拆分**:`sell_line_membership` **保持现行口径不变**(锁定线/候选 top3 成员——它同时是装配 A 义务基座 base 实参、P78-5 减法②与 P96 (b) 腿基准,不扩域)。
- **保护集成员常规通道绝对禁卖**(用户裁定):`protection_membership` 并入卖出资格装配 A 身份段(替换原静态持有两集中的 ④放行集)。豁免通道:
  - 溢出自救全通道豁免(现行);部署换血(场上件唯一卖出场景,判据本体不动)——两者不动;
  - **P78-5 兜底豁免 = 唯一可卖保护件的通道(裁决)**:其兜底池判定集改挂「保护集 ∪ registry 核心」全域——最后手段(受 P78-5′ 两分支必要条件约束)在全场保护档死锁帧必须可通;条款本体不动,构成随身份源迁移。registry 核心(`CORE_SINGLE_CARD_REGISTRY` = 希儿/银狼LV.999)保留的缘由 = 银狼等单卡核心非四体系成员,不在保护集域。
- **`cw_card_identity.sell_hold_exclusion_names` 五消费面逐点迁移**(函数随④退役;退役判据 = **src 代码符号消费面 grep 清零**——kernel 注释/正本/proofs 单篇的符号名引用归正本更新清单,不在代码清零域):
  | 消费点 | 迁移目标 | 归属阶段 |
  |---|---|---|
  | hold 登记名字腿(`sell_gate.py`) | 「保护集 ∪ registry 核心」(hold 类买入 = C1 核心 + protection_hoard,两类的登记资格面) | 3.2 |
  | funding 兜底池判定集(`sell_gate.py`) | 「保护集 ∪ registry 核心」(上条裁决) | 3.3 |
  | 垫件谓词(`sell_candidates.py`) | 非保护集成员(垫件 = 非自己人) | 3.3 |
  | P78-5′ 腿②(`entry.py`) | 「保护集 ∪ registry 核心」口径(对象级无损判定域,静态保护含银狼等核心) | 3.3 |
  | 会话内筹资腿②(`shop.py`) | 「保护集 ∪ registry 核心」口径(常规筹资不卖保护件与核心;最后手段走 P78-5 通道) | 3.3 |
- **凑息语义**(用户裁定):候选/锁定成员常规通道不凑息(结构性达成);插件/杂件可凑息。观测键 `interest_round_protected_block`,写点 = `entry.py` 节末凑息段,判定式(定死):「存在非零凑息缺口 ∧ **无可行件(退金 ≥ 缺口的常规合格集为空,且集内无保护档)** ∧ 被排除的保护成员中存在退金 ≥ 缺口者」三合取 → 计数(第二/三合取同粒度:同一「退金 ≥ 缺口」筛选下,常规集空 + 保护集非空)。反事实支枚举域 = 凑息候选池同域(备战席 ∪ 场上无关角色,节末凑息无店面)、星级域 = 1★(与凑息资格面同域,不外推)。
- 评估器排序键结构 `(line_member, bond_drop, gold_value)` 不动(首维 = 现行线内身份)。场景参数表(`SCENE_SPECS`)结构不动。
- **D7 拒因键序迁移**:改保护集口径后,调用点(`shop_unbought_reasons`)的 k_members 实参面从宽集收窄为**义务面**(保护集成员全部落线内分支的现状消除);`transition_component` 键随策展退役**删除**(其「策展过渡件被拒」语义由 `protection_member_rejected` 取代);`transition_char` 键**保留**(判定源 = `Comp.transition_chars` 注册表字段,与④/策展无代码耦合;可辨性申报:非保护打工件拒因落 `non_line` 桶的形态照旧);新键 `protection_member_rejected` = 非义务面成员(囤货面)被席/金/星级硬闸拒时落;其余键保留。

### 2.7 关键取舍

- **锁定持久化 vs 派生**:选持久槽(幂等只增)。派生口径下「换血掉档 → 保护收缩 → 连锁卖」有恶性循环形态;终局侧「锁后不换」为既定架构原则,同构沿用。
- **保护 = 绝对禁卖 vs 排序垫底**:选绝对禁卖(常规通道进装配 A 身份段)。排序垫底在「全场保护档」帧仍会卖出候选成员,违背用户裁定语义;自救/换血豁免 + P78-5 兜底(构成改挂保护集全域)保最后手段;义务基座(base)保持现行口径与身份面拆分。
- **修④门 vs ④退役**:选退役。修门只救 10 人策展口径;退役并序 1 吸收 + 新囤货臂,身份域扩为四体系全体现算,且少一条邻位特批通道。
- **新增成员期权级 vs 义务级**:选期权级(首副本 1★ 全额退囤货,第二副本 M6/序 5)。义务级(免息+筹资+置换特权)给「配方对/终局线/贯穿件」——新增成员(非在对体系)是期权非承诺,[22]④ 囤货过账口径;现行成员零回退。
- **过渡池含高费框架成员**(银狼/瓦尔特等 3-5 费):纳入。位面 1 低等级下商店概率结构性刷不出,刷出时按 [22]① 稀有照囤/[21] 买而不上为正确行为;1★ 全额退门保证零息损。r100「Early 出现率」收录纪律是策展名单时代的防膨胀手段,现算范式下由概率结构与经济闸门自然承载。
- **TRANSITION_PACK 符号删除 vs 保留配方对引用**:身份消费面清零后删符号;非身份活消费由末阶段清点裁决(§2.4),不预设。

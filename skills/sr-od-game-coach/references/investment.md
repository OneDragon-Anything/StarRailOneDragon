# 练度评估标准（星魂视角）

> 用途：配队/养成决策的练度判据——「够不够格进队」「这支队伍练度成色如何」类问题的统一口径。评估对象以**主力输出**为先——辅助/生存位的星魂收益通常是次要项。适用于米哈游系五星级角色，任何玩法场景通用（逐光捡金/货币战争/日常养成）。

## 分层标准（账号主人裁定）

- **0 魂 = 平民配置**。分两类，评估前先定性：
  - **0 魂机制完整型**：星魂只提升数值，0 魂即可当主C 用；
  - **0 魂机制残缺型**：关键机制锁在星魂里，0 魂强度打折——硬凑不如换体系。
- **2 魂 = 小康玩家水平（公认线）**：普遍适用于各角色——通常就是性价比最高、体验最好的档位（数值与体验的甜蜜点）；个别角色的关键魂位会偏移（E1/E4 等），以角色断点表为准。
- **高魂（4/6）= 重投**：配队按「有则按实测强度用，无不强求」。

## 金数记法对接（攻略通用）

攻略标注「21」= 2魂+1叠影、「2+1」= 2魂+1专。对比参考阵容金数时，**先比主C 魂数，再比光锥**。

## 评估优先级与遗器层

- **第 1 点：主力输出的星魂**（分层见上）。
- **等级/技能**：默认满级，基本不参与评估。
- **第 2 点：遗器**——社区通用口径 = **命中了多少个有效词条**（副词条经强化落在角色需要的属性上才算「有效」）：
  - 每角色的「有效词条」判定口径 = 角色档（`references/characters/<角色>.md`）的「副词条」节（含显式「不堆」负面清单，如遐蝶不堆攻击/充能/速度/命中/击破）；
  - 毕业线 = 角色档「转化上限」（转模收益封顶线，如海瑟音效果命中 120%、流萤击破 360%）；
  - 数据源：`mys_get_roster_detail` 的 relics/ornaments 明细（主/副词条 name/value/强化次数），据此逐条数命中。
  - **口径依赖场景**：同一角色在不同阵容的不同定位要求不同（如速度阈值随排轴、效果命中随队伍需要）——口径一律在评估时按角色档+阵容上下文现定，不写死在任何工具里；工具只做「口径参数化」的确定性计数（口径为入参，见下方设计决定）。
- 评估输出沿用配队决策第 5 步格式：「够格 / 短板+差多少数值」。

## 有效词条计数工具的设计决定

MCP 不内置默认口径（口径是活知识，写死必与角色档漂移且定位场景给错数）；也不做「默认值+提醒」（错数比缺数更糟）。方向：MCP 提供**口径参数化**的计算工具——入参为名册明细 + 每角色口径参数（有效词条清单/阈值线，由调用方从角色档与阵容上下文得出），输出命中数与毕业线对照；口径的特殊情况=调用方改入参。

**已实现**：工具 `mys_evaluate_relic_substats`（工具协议与信封语义见 `docs/develop/sr_od/backend/mys.md`；计算层 `src/sr_od/backend/mcp/relic_eval_tools.py`）。入参 = `criteria`（每角色 `character_name` + `effective_substats` 有效词条清单，元素为词条标准名/别名/口径包名，清单补集一律无效；可选 `main_stat_expectations` 主词条核对、`stat_thresholds` 毕业线）+ 可选 `roster_data`（缺省自拉名册）；输出 = 命中数/浪费分布/主词条核对/毕业线对照/最弱件。「不堆」清单不进工具入参（有效清单的补集已覆盖无效判定）。速记归一表（别名表 + 口径包表——词 → 标准名/集合的机械展开，不含「该角色该堆什么」的判断）定义在计算模块常量（`src/sr_od/backend/mcp/relic_eval_tools.py` 的 `STAT_NAME_ALIASES` 别名表与 `STAT_PACKS` 口径包表）。角色档「副词条」节的机器可读口径行 = 「有效口径: <口径包名或枚举>」（验收名单 12 人已落档，其余角色随本档维护流程铺开）。

## 数据源（项目 `sr_od` MCP server 直拉，无需中间层）

- `mys_get_characters` = **概况**（等级/星魂数/命途/光锥摘要）——配队选人、练度成色初判；
- `mys_get_roster_detail` = **全量**（遗器词条/星魂解锁状态/行迹等级/属性面板）——缺口分析、毕业面板对照；
- 会话管理：`mys_login` / `mys_logout`。⚠️ `mys_login` 的密码作工具参数会经过模型上下文（泄露风险），调用前必须向使用者转达知情、由使用者决定是否继续。
- 会话失效时按工具返回的 `session_expired` 重登即可；状态分支在工具描述里自足，会话备份/恢复与验证环节的坑见 `docs/develop/sr_od/backend/mys.md`（账号数据能力随 MCP 工具走，不设独立 skill）。

## 发现清单

### D2-1｜diff 就位粒度（名+排）重演「同名升星对停摆」——现行代码注释实锤过的事故形态被重新设计回来
- 攻击点：接口契约② target_board = 角色名→排（星不在接口）；差分执行器「就位判定粒度 = 名 + 排，槽不进判定」；而 §1 星级条「同键多副本取最高星参与评分」。三者组合：场上 1★ 白名 + 手上 2★ 同名（合成产出/高级店直购，星异不并——见核实轨迹）时，评分板按 2★ 计，diff 却判该名「已就位」→ 零动作 → 2★ 永远上不去、1★ 永远下不来，**评分板 ≢ 执行后板**（违反详设自己的 D-6 处置原则与场景走查「银狼……评分板 ≡ 执行后板」行的适用精神）。这不是假想边界：现行体系有专门一等通道承载它——entry.py 第 6 步 docstring 明写「目标态名集对『同名升星对』形状不敏感（换出换入同名不同星，名集相等而星级不等；同名离场 = kernel bond_gate star 分支一等设计通道），名集相等 ≠ 无发射」并记载历史实锤「无条件早退曾吞同名升星对的 SellDeployed，升星换人通道停摆」；bond_gate star 分支（`_bond_gate_same_star_up_available`）随 kernel swap 机器整链删除后无任何承接。总纲 §3 验收清单的部署搜索测试也无同名升星对用例。
- 证据：entry.py:1013-1021；cw_deploy_logic.py:954；mandate.py:1560；cw_merge_simulate.py:206-207；详设 §2 段 0/§3 第 1 条/接口契约②。
- 严重度：高
- 处置建议：target_board 与就位判定补星级维度（含统一拖动的换血序：下场低星+上场高星），或显式申报升星换人场景的新承载路径并补验收用例。

### D2-2｜「SellDeployed 唯一在役发出点 = 意图槽执行位」与总纲 §2.3 直接矛盾——溢出自救卖场上件能力被砍
- 攻击点：详设 §3 第 6 条断言 SellDeployed 唯一在役发出点 = 跨画面意图槽执行位。但总纲 §2.3「存留卖出场景取用零改动」：场景 1 溢出自救池 = 备战席 ∪ 场上部署外（连续卖至不溢出）、场景 2/3 同池——场上件卖出经 entry.py:661-696 deployed 支（总纲 §2.3 动作载体行白纸黑字）。溢出帧 bench 满，被换下通道全部不可用（纯下场需 bench 空槽；交换 bench 占用不变不腾位）——场上部署外件**必须**原地 SellDeployed。按详设字面实现（删除 deployed 支）= 溢出自救停摆；不删 = 详设「唯一」失实误导实现者砍掉它。
- 证据：详设 §3 第 6 条 vs design.md §2.3（场景表第 1 行 + 动作载体段）；entry.py:647（备战第 0 步溢出自救）。
- 严重度：高
- 处置建议：改「唯一发出点」表述为「部署换人路径的发出点 = 意图槽；卖出场景 deployed 支照总纲 §2.3 保留」。

### D2-3｜反甲流（form_tiers={}）「角色完成度」无计算式——D-10 处置没有真修
- 攻击点：D-10 处置写「空羁绊线 = L1 由角色完成度单独承载（b≡1）」，但角色完成度的定义 = 「该羁绊族已上场角色数 / 该羁绊族**目标档激活阈值**所需角色数（阈值 = FACTIONS.tiers 档位激活数）」——反甲流 form_tiers={}、factions=[]，无羁绊族、无目标档、FACTIONS 无对应键，分母与分子口径双无源；「b≡1」只定义了乘法的另一个因子。场景走查「无阵营锁定线（反甲流）」行判 ✓，但其 L1 计算式不存在——锁定反甲流帧（plane_end 后窗口开）评分不可实现。另外该线 sub_tiers={护盾:2} 的层归属同时悬空（见 D2-6）。
- 证据：详设 §1 两量定义/分族分支/场景走查末二行；cw_comps.py:1182-1183,1199。
- 严重度：高
- 处置建议：给空羁绊线显式分母读端（如 required_deployed/core_chars 口径）或申报其 L1 恒 0、由 L3+站位分定序。

### D2-4｜L3「buff/debuff 羁绊」闭集在代码域不存在，万金油名单单一源未指——第一轮补问 4 被错误降级
- 攻击点：L3 = Σ(buff/debuff 已达档 × 3) + Σ(其他羁绊已达档 × 2) + 万金油在场 × 1。FACTIONS 分类闭集 = combat/economy/support/independent，无 buff/debuff 概念；全仓 grep 仅命中 EffectKind.UNIT_BUFF（效果类别，与羁绊分类无关）。「buff/debuff」与「万金油」（= mandate_v1/protection.py CROSS_LINE_KEEP_NAMES，策略层）两集合是 L3 公式的直接输入——×3 与 ×2 的分档直接改变 L3 定序。第一轮补问 4 已指出，处置记录归为「落地批工程细节」——**公式引用了不存在的分类概念**不是工程细节，是可实现性缺口；且评分函数（详设契约④：纯函数、deploy 域、sim 可跑）消费策略层名单的跨层依赖也未声明。
- 证据：cw_factions.py:14-18；protection.py:1,41-46；详设 §1 L3 行；attack-deploy.md:185（补问 4 处置行）。
- 严重度：高
- 处置建议：为两集合定注册表级单一源读口（或改用 FACTIONS.category 现有四类重写 L3 分档）并声明名单的层归属。

### D2-5｜契约①「族成员 ⊆ 名单成员」与段 1「P1 = 4 过渡体系组合」内部矛盾，严格读下漏最优板
- 攻击点：接口契约①「候选族 = 名单的羁绊投影……族成员 ⊆ 名单成员展开」。P1 名单（总纲 §2.1）= 候选三线成员 ∪ 配方对成员——配方对仅 2 件；过渡体系成型（仙舟 3 人 1 档）的**第 3 张**同体系件若非候选线成员、非配方对成员（顺买/压牌库常态），则不在名单 → 仙舟族按名单投影只有 2 人 → 段 1「按填入下一档可行性逐档推进」判定 t=1 不可达 → 「3 仙舟成 1 档」的过渡组合骨架不生成；段 2 补人按**单件** L3 计数分排序，未成档时仙舟件计 0 分排不进 → 最优板漏出枚举空间，P1 主目标层（L1 过渡组合）系统性偏低。这与段 1 自己的「P1 = 4 过渡体系组合（含希儿系单卡分支）」（来牌主判据语义，消费手牌全集）直接冲突——同文两处候选族定义不一致。锁定窗/P2+ 行与名单自洽，唯独 P1 行被契约①掏空。
- 证据：详设 接口契约①/§2 段 1 候选族行；design.md §2.1；cw_system_cards.py:334-345（pick_card_combination 来牌主判据 = 手牌全集语义）。
- 严重度：高
- 处置建议：明确 P1 过渡族成员域 = 手牌全集（契约①对 P1 限定为窗口分域同谓词、不限成员域），或逐窗写明族的成员域来源。

### D2-6｜L2「锁定线非核心羁绊层」键集未定义——sub_tiers/flex_factions 悬空，同一羁绊差 4 个数量级
- 攻击点：L2 满分 10⁶ vs L3 ≤ ~10²。Comp 的「非核心羁绊」天然载体有两处：flex_factions（「弹性次要羁绊(不进 form_tiers)」）与 sub_tiers（「副档目标档深(**参与完成度**)」）——详设全文未定义 L2 键集（第一轮补问 10，处置降级「落地批工程细节」）。反甲流 sub_tiers={护盾:2}、DOT 线 sub_tiers={减益:2}、姬子线等——锁定后这些羁绊凑档进 L2（档位完成度加权，10⁶ 域）还是 L3（计数 2 分/档，10² 域），板面行为完全不同。场景走查「P1 锁定、1 核心在手、过渡对成型 → L3 定序保过渡板」的 ✓ 判定隐含「该帧 L2 = 0」——L2 键集未定则该判定不可证。键集是锁定窗层结构的组成部分，不是落地批工程细节。
- 证据：详设 §1 层结构表/分值表/场景走查第 2 行；cw_comps.py:111,128-130,1199,1466；attack-deploy.md:185。
- 严重度：高
- 处置建议：L2 键集显式定义（如 sub_tiers ∪ flex_factions，或声明恒空并让全部非 form_tiers 羁绊落 L3）并同步修正场景走查的隐含前提。

### D2-7｜过渡体系「体系成型档」无注册表符号；仙舟引擎空壳约束（铁三角）评分致盲未申报
- 攻击点：档位完成度定义「过渡体系 = 体系成型档」——SYSTEM_CARDS 无「成型档」字段：激活是 card_active 单点判据（仙舟≥3/DOT≥2/列车≥2/希儿系单卡），最接近的 `_ACTIVATION_PIECES` 是 readiness 分母（草案级权重配套）。按单点激活读，「已达整数档/目标档」对三阵营过渡体系实为 0/1 二元——详设未写明这个退化，也未指注册表符号。更重：仙舟3 的引擎约束「铁三角功能链不可拆(缺一=空壳)」（engine_required + CardState.engine_complete/`engine_missing` 现行显式建模）在评分中零消费——任意 3 张仙舟与铁三角 3 件评分逐位相同；现行 P1 组合机器的该建模面随收编删除，行为退化（P1 战力近似变粗）未在行为变化申报。
- 证据：cw_system_cards.py:48-67,102-111,234-264；详设 §1 两量定义/§1 分族分支。
- 严重度：高
- 处置建议：过渡体系档位完成度写明二元语义与符号源；引擎完备度进评分（或申报放弃并注明空壳近似边界）。

### D2-8｜召唤物「占 K」有处置、「占后排格」无处置——排分配容量未扣系统单位
- 攻击点：段 0「召唤物/系统单位固定后台末位、剔除出枚举，占位/占 K 按 max_units_of 口径」——max_units_of 只表达总 K（min(人口, 4+back_capacity)），不含后排格子级扣减。召唤物恒占后排格：排分配的「后排容量」约束若读 back_capacity_of 全量，会把真人分配进召唤物占用的格；执行落位拖向被占槽 = 交换交互（把系统单位换回 bench——系统单位下场语义无定义）或拖放失败。K 扣减写了、格扣减漏了，两个维度只处理了一个。
- 证据：详设 §2 段 0/段 3 排分配行；cw_game_state.py:4881-4914；详设 §1 机制事实节。
- 严重度：中

### D2-9｜段 2 补人「按 L3 计数分排序，枚举补法」完备性未定义——凑档组合对单件排序不可见
- 攻击点：单件 L3 分对「两件合起凑成新羁绊 1 档」的组合价值不可见（各自 0 分、合起 2 分）。若「排序」= 贪心取优则系统性漏板（补人面没有圈人面「全枚举零截断」的对等声明——组合软上限删除只覆盖骨架生成）；若全组合枚举则补人组合量（C(剩余手牌, K−骨架)）未申报。反例：骨架 3 人、K=5、余牌 = 1 张独立件（单件 2 分）+ 2 张同羁绊 Y 件（各 0 分、合起 1 档 2 分）——贪心补独立件，最优板补 2×Y。
- 证据：详设 §2 段 2；对照段 1 组合软上限删除行的「全枚举零截断」仅限圈人。
- 严重度：中
- 处置建议：补人枚举闭包写明（含凑档组合）或申报贪心近似及其漏板边界。

### D2-10｜L1 权重「目标档深」量纲两可；希儿系（单卡）无档深——含希儿系的 P1 组合权重无定义

- 严重度：中

### D2-11｜统一拖动动作的参数 schema 未设计——退役两套坐标系、新动作「源/目标全域」无字段定义

- 证据：cw_vocab.py:303-328（含 :321-323 注释后排 1-6）,419-446,445-446；详设 §4 末行。

### D2-12｜上报推演「扩为全域同款」未声明三新域的分支矩阵——锁/变换窗/形态归一在新域的行为不明
- 攻击点：现役 deploy_move 推演是 bench→场上专用：上场锁校验（deploy_lock_block_reason(gs, unit)，拒 = applied=False）、银狼变换窗（仅上场支触发，「现档=5 恒等搬运」）、开拓者形态归一（按 to_row）。扩展到「场上→场上」（排错修正：已上场单位换排，锁判定是否误拒？银狼不重触发？开拓者按目标排换形态 ✓ 有现核）、「场上→bench」（纯下场：开拓者 bench 无排，char_id 归一形态取什么？变换窗不触发？）、「场上→场上被占槽」（两人对调，双形态归一？）——每个分支 × 三个新域的行为未逐一声明，「扩为全域同款（消费现有 deploy_move report 推演逻辑扩展）」一句话让实现者自行拍板。
- 证据：cw_action_report/deploy_move.py:91-149；cw_env_grants.py:956；详设 §2 段 0 机制事实节。
- 严重度：中
- 处置建议：动作域 × 推演分支（锁/变换窗/形态归一/交换）矩阵表进详设。

### D2-13｜锁定后希儿系过渡件在 L3 计零分——「保过渡板」对单卡体系失效

- 严重度：中

### D2-14｜shop「可上场买」改接搜索定型谓词的语义漂移未申报

### D2-15｜分值不等式的「≥ 2×10⁸」不是下界——数字口径不严谨（隔离结论本身成立）

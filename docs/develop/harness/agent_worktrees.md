# 并行开发的 worktree 批隔离

> 本文是「多批并行开发怎么互不干扰」的设计正本（as-built）：写系统现在的结构、语义、接口契约与边界。
> 术语：**change** = 一次迭代主题，就是 `docs/develop/<模块>/changes/<change-id>/` 那个目录名（例：`2026-09-11-unified-state`）；**树** = 一棵 git worktree 检出；**集成分支** = 主工作区当前检出的那条分支（本迭代即 `feat/mcp-backend-sync2`）。

## 1. 动机

自主推进模式下同时有多个批次在改代码。若它们共用一个工作树：未提交改动混在一起、提交时容易卷进别人的文件、跑测试会看到别批的半成品、切分支还得先 stash。改成「一个 change 一棵树」后，每批在自己的检出里干活，靠分支合并回主线，冲突在合并那一刻才暴露且可定位到具体批次。

## 2. 命名与布局（一个 change 一个键）

| 东西 | 取值 | 例 |
|---|---|---|
| 设计目录 | `docs/develop/<模块>/changes/<change-id>/` | `changes/2026-09-11-unified-state/` |
| 主仓树 | `<仓库根>/.debug/worktrees/<change-id>/` | `.debug/worktrees/2026-09-11-unified-state/` |
| 主仓分支 | `wt/<change-id>` | `wt/2026-09-11-unified-state` |
| 测试仓树 | `<主仓树>/sr-od-test/`（配对检出） | `.debug/worktrees/2026-09-11-unified-state/sr-od-test/` |
| 测试仓分支 | `wt/<change-id>`（同名） | 同上 |
| 审查档案 | `.debug/change-reviews/<change-id>/` | 攻击报告、验收结论、合并报告 |

`change-id` 是全部路径与分支名的唯一键——检索时用一个名字串起设计、代码、审查证据。

**一个 change 一棵树**，该 change 的多个任务在树内**串行**叠提交（同一检出不能两批同时改；顺序由任务依赖边保证）。并行度来自**跨 change**：不同 change 各占一棵树。

## 3. 生命周期

**建**（编排者做，派单前置动作）
```
dag.py --file <账本> add <标题> --worktree wt/<change-id>
tools/wt.ps1 new <change-id>          # 幂等：已存在则跳过并回显既有路径
```
建树时机 = 派**第一个会改动既有文件的实现批**时。只写新目录的设计批、对抗批，以及不派子 agent 的活，都不建树（新目录与他人零重叠，共享树上提交是安全的）。

**用**（worker）
- 一切文件与 git 操作限本树内；例外只有共享记账（账本、交付报告走主仓路径）。
- **子 agent 会话的工作目录恒为主工作区**：树内命令必须显式定位到本树（`cd <本树绝对路径>` 后执行，或 `git -C <本树路径>`、`uv run --directory <本树路径>`），文件读写用树内绝对路径——裸命令落在主仓，隔离就失效了。交付前自查：本批提交必须出现在 `git -C <本树> log` 里。
- 树内禁 `git add sr-od-test`（主仓只认那个 gitlink 指针，测试改动在测试仓自己那层提交）、禁 `git clean`（会删掉树内 `.debug` 遥测）。
- 测试在树内跑：`uv run pytest sr-od-test/`（配对检出已就位）。

**并**（合并者，见 §6）：验收通过 → 任务进 `pending_merge` 泊位 → 合并者 rebase、跑全量测试、分诊、快进并入、抢救遥测 → 收敛 `done`。

**删**：该 change 名下再无未终态任务后 `tools/wt.ps1 remove <change-id>`。

## 4. 共享与隔离边界

- **树内不 junction / 不 symlink 任何目录**。共享目录在删除时会被连带穿透，风险不值得；需要共享的东西用「建树时硬链接单个文件」解决。
- `.env`：建树时以硬链接放进树根（同盘同 inode，主仓改了树里跟着变）；硬链接失败退化为复制并告警。它让 `uv run --env-file .env` 这套既有命令模式在树内原样可用。
- `.debug`：**不共享**。树内执行产生的遥测写在树自己的 `.debug`，由合并者在并入时搬回主仓对应路径（重名报错，不覆盖）。并行期间各树的新档案互相不可见，以各批交付报告为准。
- `models/`：不共享（运行时下载的模型文件，开发与测试树不需要）。`config/`：不共享（测试用仓库内的 sample 配置，依赖本机运行时配置的测试属于环境依赖缺陷）。
- Python 环境：每棵树各自 `uv sync --group dev`（uv 从本机缓存硬链安装，边际磁盘开销很小）。

## 5. 工具接口 `tools/wt.ps1`

| 动词 | 语义 |
|---|---|
| `new <change-id>` | 幂等建两仓树 + 分支 + `.env`；回显两树绝对路径与分支名（供任务书【工作区】段） |
| `check <change-id>` | 判两仓工作树是否干净；有不干净项 = 非零退出并列出清单 |
| `rebase <change-id>` | 两仓各自把集成分支最新重放到 `wt/<change-id>`；冲突 = 非零退出并列出冲突文件 |
| `land <change-id>` | 前提=全量测试已跑绿；两仓 ff-only 并入集成分支（禁合并提交、非快进拒绝）+ 遥测抢救 |
| `remove <change-id>` | 走守卫后删两仓树与两仓分支 |
| `list` | 列出登记中的树：change-id、两仓路径与分支、脏/净状态 |

约定与守卫：
- 仓库路径、测试仓路径、集成分支名**可参数化**（默认取真实仓库与主工作区当前检出的分支）；`land` 会前移集成分支并改写主工作区文件，端到端冒烟必须在一性次 scratch 仓库里做。
- `remove` 两道守卫：树内 `.debug` 非空 = 拒绝（先合并抢救遥测）；任一仓工作树不干净 = 拒绝。`--force` 才放行。
- 任何 reparse point（junction / symlink）一律拒绝删除并报错。
- 全部动作幂等；任一步失败即停，不静默继续。

## 6. 合并者契约

合并者是**单例**子 agent（全局至多一个），只做合并与集成验证，不做代码 review。取活来源 = 账本 `pending_merge` 段。

1. **查干净**：`wt.ps1 check`——两仓有未提交/未跟踪项就足够打回（作者忘了 `git add` 的新文件在这里现形）；禁代提交、禁自行清理现场。
2. **rebase**：`wt.ps1 rebase` 把集成分支最新重放到批分支；冲突 = 打回，报告附冲突文件清单。
3. **全量测试**：批树内 `uv run pytest sr-od-test/`（串行、含慢桶、不过滤）。rebase 后的批树内容就等于「合并之后的世界」。
4. **红的用例逐条分诊**：
   - 不是本批引起的（改动面之外的老红）→ 记入合并报告；本批照常合并；修复由编排者另立任务承接。
   - 是本批引起的 → 打回。原 worker 先在自己树里 rebase 集成分支最新（解冲突）再修，修完从第 1 步重走。
5. **全绿则并入**：`wt.ps1 land`（两仓 ff-only 前移集成分支 + 树内 `.debug` 新增内容搬回主仓）。
6. **清场**：该 change 无未终态任务时 `wt.ps1 remove`。
7. **记账**：`pending_merge → done --criteria <合并报告路径>`；打回则 `pending_merge → rejected --why <合并报告路径>`（返工派工归编排者）。

硬约束：只 commit 不 push；主工作区被存量未提交改动挡住 ff 时，记「受阻：文件面相交」并留待重试，**禁** stash / reset / 强行 checkout 主工作区。

## 7. 账本集成

- `dag.py add --worktree wt/<change-id>` 声明该任务在树内做（未声明的任务走老流转）。
- 新增状态 `pending_merge`（待合并泊位）：`pending_review → pending_merge`、`doing → pending_merge`；`pending_merge → done`（必带合并报告凭据）或 `→ rejected`（必带原因）。
- **worktree 任务的 `done` 唯一入口 = `pending_merge`**：从 `todo`/`doing`/`pending_review`/`wait` 直达 `done` 一律被脚本打回。免审档只免验收，不免合并。
- `check` 体检在重放侧同规则把关：worktree 任务的 `done` 必须有 `pending_merge → done` 合并事件背书，且合并报告文件真实存在。

## 8. 禁止事项

- 树内 `git add sr-od-test`、`git clean -x/-fdx`。
- 绕过 `wt.ps1` 手工删树目录（可能静默丢掉树内遥测，按事故处理）。
- 把树内该做的事做到主仓（或反过来）——批次的一切代码改动只发生在自己的树里。
- 主工作区承接批次改动：它只用于**合并**与**只读**；批次的实现工作全部在树内。

## 9. 边界与过渡期约束

- **实机链路**：主 MCP server 与 GUI 跑主工作区代码，树内改动要**经合并进集成分支**才影响实机（必要时重启 server 加载）。
- **合并受阻**：主工作区当前可能躺着本机制上线前的存量未提交改动；与批改动面相交时 ff 会被 git 拒绝。处理 = 记录受阻、留待重试，等存量按既有流程清退后自然消解。
- **存量不追**：机制上线前遗留的手工 worktree 与脏工作树不做迁移，归既有对账流程处置；本机制只保证「新批次不再新增共享树污染」。

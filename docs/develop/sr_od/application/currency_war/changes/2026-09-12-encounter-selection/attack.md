## 二、指定复核点专项裁定

### 复核点①：D_enc 读点两假设定谳义务的完备性

**裁定：不完备——判别式机制可执行、双线族数字全部正确，但「定谳后回写面」不闭合，且文档多数承重位未按两假设立场改写（高-1）。**

- **判别式可执行性**：判别式本体（「归档遥测 difficulty 逐帧序列对节点边界对账——遭遇备战区间出现新写入 = (i)；无新写入（carry 延续）= (ii)」）机制上可判：逐帧写入链在册（读链 cw_observation.py:2168-2188 → 写入半 :2565-2572，live 真读走 `bs.observe`、miss 走 `bs.carry`，observe 行与 carry 行在 state/journal 流可辨）。但**数据源流未指认**（低-2）：历史 decisions.jsonl 行曾携带 `enemy_difficulty`+`enemy_difficulty_live` 键（sim/checks/corpus.py:439-440 的判读检查器正吃该键集，批 37 语料实证），而该流生产写端已随删除波 1 退役；现行 decision_trace.jsonl 行的 `difficulty` 字段是职级字符串（cw_decision_trace.py:319），无数值键。判别式只能吃存量档案语料（翻转 commit 09cf8296 之后～删除波 1 之前的窗口）或 state/journal.jsonl 行——设计未申报选流与语料边界，存量语料是否含足量遭遇节点备战区间帧未论证。
- **双线族数字正确性**：脚本复算全部相符——原始口径 {1.000, 0.602, 0.363, 0.219}、净值口径 {0.738, 0.444, 0.268}、g 幂表 {1.660, 2.756, 4.576}、交叉对账 1.052^18 = 2.4905、f_min=0.5 最大净增量 13.67≈13.7（覆盖其二净值 6、不及其三净值 16）、W1 的 1.052^-10 = 0.6023。**零数字错误**（第四节逐项）。
- **定谳后回写面：不闭合（高-1）**。契约 2 义务清单「据定谳回写本条/§3/线族」三处；实际需要回写的承重位至少九处：README:18、design §2.2 表行、design §2.4、契约 3 净值段、§8 数据通路表两行（含遭遇行 `difficulty_node` 装配规则——该规则按 (ii) 硬编码「取前一普战写入值」，定谳为 (i) 时必须反转为「取遭遇自身备战帧值」，是落码指令级回写）、§9 Δ_t 行、landing 3.2、线族。**仅前述三处在清单内**。定谳为 (i) 时 Δ_t 退出判据、线族换原始口径，其余位置全部悬空。
- **附加不一致**：§9 开闸门成员缺「D_enc 读点定谳」（E-3 把它列为「开闸前置」，自称单一源的 §9 清单没有它，中-1）。

### 复核点②：页 1 暂存同场标签匹配与去重合并的交互

**裁定：修复方向正确、主路径自洽，但标签键来源口径是定义缺口（中-2），四个边界情况两向都有暴露。**

- **主路径自洽**：同场匹配修复的现状缺陷属实——现状 progress 合并（:377-382）在**每行**执行且消费后置 None，跨场滞留的负 progress 会经 :384-387 符号判定把下一胜局行翻转成败局（文档断言与代码逐位相符）；「页 1 写入恒先于本场首行」的时序断言成立（页 1 动画帧/失败页先于「继续挑战」行 :640 与 3b 行 :811）。1f 行（过 W239 守卫者后入环）与 3b 全写行同键去重合并、后到缺字段不覆盖，与三路调用拓扑（:640/:740→:534/:811 汇聚 read_round_outcome 唯一构造点 :487-499）自洽；W239 抑制行在 :375 return、不达暂存消费点与环写位，与 §8①「对账 hook 上游括守卫两臂、抑制行留痕不入环」一致。
- **边界情况（中-2）**：
  1. **标签来源口径未定义**：暂存写入点（1f :715-737、分支 2 :763-788）处没有现成行键——行键在 `_record_round_outcome` 内经 read_phase_round + W239 校正产生；暂存写入时须另行解析（parse_settlement_round 屏面真值）或取 loop 缓存，设计未规定用哪个。
  2. **兜底键误匹配（毒化向）**：relaunch 残留结算屏场景（run 启动首帧即残留屏，last-known 被 reset → read_phase_round 兜底 (1,1)，W23 定因在册 cw_settlement_obs.py:68-80），残留屏页 1 暂存若按兜底值打 (1,1) 标签，与新局首场真实 (1,1) 同键 → 同场匹配误通过，残留屏 fill 灌入新局首场行。
  3. **校正失配（安全向）**：暂存标签用写入时点值、行键经 W239 校正后两者可能失配 → 同场 fill 被误弃，败局行 fill 删失——不破坏安全，但拉低 E-3 的 fill 读取率与遭遇败局行入表率量测。
  4. **「弃」语义未定义**：异场即弃是「本次不取用、暂存保留」还是「物理清除」未定义；建议一锤子清除，防后续行重复判定。
- 去重合并键（plane + round_num，行键）与同场匹配键（(plane, round)，标签键）**必须同源同解析器**，否则同场匹配退化为随机匹配——设计未写键域一致性要求。

### 复核点③：全量扫尾——二十轮修复后剩余承重断言

**裁定：主结构站住；剩余问题 = 高-1 七处残留、中-1 闸门成员集、中-3 简报通路叙述、低组 5 项；无其他承重断言与代码/宪法/知识源冲突。**

重点复核过且站住的：判别子四态（Field 默认 (None,'observation')、carry 对 None 早退不写、observe 是唯一非 None 入口、write_logic/relay 来源被拒）逐条与 cw_game_state.py:407-408/:2255-2293 相符；「页 2 矩形罩心形恒假值」与 cw_settlement_obs.py:396-399 相符；prep_clean spec 含 `enemy_difficulty` 键（cw_observation.py:1999-2003）——假设 (i) 的机制基础成立；ADR-0536 退役三件套与三文件引用计数（3/10/4）逐一清点相符；outcomes 实机写端退役两锚相符（sim 域 runner.py 的 outcomes.jsonl 写端仍在，属 sim 判读域，与「实机跨局持久化缺位」申报不冲突）。

## 三、发现清单

### 高

**高-1｜H-1 修复融合不彻底：七处承重位残留 (ii) 单一立场（两处含自相矛盾断言）+ 定谳回写面清单不闭合**
- **位置**：①README.md:18「遭遇决策读点 = 前一普通战斗节点写入值，Δ_t 取净值」；②design.md §2.2 数据源表「遭遇决策 D_enc 读值」行；③design.md §2.4「D_enc = 决策时 `BoardState.enemy_difficulty` + Δ_t，同源零口径差」（Δ_t 无条件在场，无两假设）；④details 契约 3 净值段；⑤details §8 数据通路表「遭遇决策 D_enc 读值」行与「遭遇行无本节点备战帧」行；⑥details §9 Δ_t 行「（契约 3：读点事实已定谳可加性）」；⑦landing.md 3.2「D_enc = 决策时读 GameState 现存值（前一普通战斗节点写入）+ Δ_t 净值」。
- **内容/代码事实**：契约 2 明文「读点归属 = 两假设未定谳【拟·E-3 前置义务】」。假设 (i) 的机制基础本轮直调核实成立：遭遇屏流程文档明文「入口：备战 →（地图节点为遭遇时）→ 本屏」（实文件 `docs/game/screens/currency_war_encounter.md:14`）+ 遭遇节点备战期 prep_clean 全量观察 spec 含 enemy_difficulty 键（cw_screen_prep.py:511 → cw_observation.py:1999-2003）。而上述七处均按 (ii) 写死为唯一事实。其中两处**事实断言被契约 2 证伪**：契约 3「**遭遇节点无备战帧**，读值必然不含档位加成与遭遇 −4，**可加性前提已由读点事实定谳**」——前半句与假设 (i) 及 prep_clean 机制矛盾，后半句与契约 2「未定谳」直接矛盾（同一文档内同一事实同时「未定谳」与「已定谳」）；§8「遭遇行无本节点备战帧」同款，且该句是 E-2 落码指令（遭遇行 `difficulty_node` 装配规则），定谳为 (i) 时该指令直接错误。
- **危害定位**：landing 3.2 是阶段唯一源，落码者按其单口径落码会结构性漏掉 (i) 分支；契约 3 的矛盾断言会误导 E-3 判别式设计与净值标定方案。
- **修正方向**：七处统一改为两假设并置口径（或显式标注「暂按 (ii) 落码、定谳后回写」）；契约 2 回写面清单扩为穷举（README / design §2.2 / §2.4 / 契约 3 净值段 / §8 两行 / §9 Δ_t 行 / landing 3.2 / 线族），并单列 §8 遭遇行 `difficulty_node` 装配规则的定谳反转变体。

### 中

**中-1｜§9 开闸门（自称单一源）与 E-3 开闸门成员集不一致**
- **位置**：details §9 开闸门清单 vs details E-3 段开闸门清单；关联契约 3 真值缺失分支末句。

- **位置**：details 契约 3 真值缺失分支（「简报恒值（≈108）经 carry 路径写入、source 非 observation，同样被拒」）。

## ① 结论

1. **链观察三件(基线/现行/diff)全部有现状基座,本设计是正式化,不是从零发明**。
   备战帧链识别已在产:`cw_node_reader` 纯 CV(HoughCircles 动态定圆 + HSV 三态 +
   Hu 矩模板 + boss SIFT,`obs/cw_node_reader.py`)+ `read_node_sequence` 包装
   (`obs/cw_observation.py:497`)+ 备战帧落账段(`cw_screen_prep._probe_node_type`
   :2510,含左移推断/轮位对齐门/变异窗豁免/台账合并)。本设计把它升格为统一 state 的
   正式观察写端;位面过渡画面(三位面球+底部节点链)已建档 is_precise 但**无 op、
   无链读**,新增过渡相位 op 补上「链观察」这唯一缺口;diff = kernel 纯函数 +
   obs_event 新登记项。
2. **过渡屏链归属定谳(本版核心修订,F1)**:过渡屏底部节点链 = **刚离开位面的链**
   (「离开位面链」读法;开局形态无离开位面,链 = 即将进入的 P1 默认链)。定谳依据
   四条(全文见 §3.1.1):①格数判据——归档帧 `plane_1to2.webp`(1→2 过渡)显示
   **9 格**,而 P2 = 7 节点三源一致(`plane_schedule_observed.md:19/:67`、
   `sim/engine_p1.py:286` P2_ROUNDS=7、`economy.md:132` boss@r7),9≠7 排除「进入
   位面」读法;②逐位吻合——该 9 格链与 P1 默认序列逐位一致
   (`plane_schedule_observed.md:18`、`cw_battle_calib.py:216-219` 众数表);
   ③亮度结构旁证——1-2 格暗(past 态渲染)、第 8 格金底+定位针+「奖励」标签
   (已到达样式),进度渲染只对「刚打完的位面」有意义;④v1 默认读法(进入位面)
   在库无任何证据支持,系设计自释。**P1 基线 = 开局过渡屏读数**(投资环境选择前,
   改型前真值);**P2/P3 无过渡屏入口**,基线 = 回退源(§3.1.1 失读处置),diff 观察
   窗较 P1 收窄,如实申报。
3. **字段面**(统一 state 载体 = BoardState,遥测 v3.3 §3.1.3):`node_path`(现行链,
   已声明未接线,`kernel/cw_board_state.py:1070`)值形态精化为 `NodeChain` 载体;
   新增 `node_path_baseline`(基线链)。NodeChain = `{plane: int, seq: list[TokenCell]}`,
   TokenCell = `{token, channel, hu_dist}`(v1.2 M-1:逐格通道/残差随读数落载体并持久化,
   §3.2);seq 下标 0-based = 该位面第 i+1 轮(与 as-built 台账 `PlaneNodeLedger.seq_by_plane`
   同下标语义,test_cw_node_type_ledger.py:182 在册)。
4. **类型词表 = 登记式封闭集 + 通道分层**:核心四 Hu token `battle / supply /
   encounter / reward` + boss(位置判+SIFT+标签)+ 仅标签通道 token(`elite /
   megastar / invest`,OCR 标签关键词已在册 `cw_observation.py:387`,无 Hu 模板)
   + `None = 本帧未辨`。**通道分层是 diff 判据的输入**(F3):仅标签通道 token 与
   Hu 通道 token 的差按「通道受限差异」单列,不入改写证据(§3.3)。新 token
   (如任务书提及的「事件」型)经未识别采集钩子(`_capture_unrecognized_node_icons`)
   采样后 onboarding 入注册表,禁散点扩词表。
5. **写端三处**:①位面过渡 op——开局形态写 P1 基线(quality 源标 `transition_row`),
   跨位面形态写**离场快照**(基线已在 → 写该位面现行链终值并触发 diff 终笔;基线缺
   → 补基线,诚实申报 diff 窗为零);②备战帧写现行链(源 `prep_row`,最新帧覆盖,
   已通过段=None 由流水历史补);③既有两写点保留(位面详情采集 `plane_detail` /
   投资环境选择后重读)——基线缺席时的回退源与「变异窗后权威刷新」语义原样。
6. **diff 触发条件与载荷**:现行链每次写入后与同位面基线逐位比对(双方非 None 且不等
   = 改写候选;**通道受限差不入改写**,F3;**备战帧写入需连续两帧读数一致**,离场
   快照豁免两帧门),长度不一致 = 增删 → obs_event 行型 2(event=`chain_diff`,
   承接批 = 遥测 M1 登记面/M2 接线,「候 H2」指认作废,F6);投资环境变异窗内豁免
   (沿 `env_grace_until` as-built 语义),基线缺席 = diff 关闭(诚实缺失)。
7. **接口(与件 A 唯一交汇)**:`chain_node_type(view, plane, round_num)` 按序键查
   **现行链原值**(零内建回落;None = 现行链不知道,调用方按自己的仲裁序兜底,F2);
   基线经显式独立接口 `chain_baseline(view, plane)` 读取(带「可能已被改写」申报),
   改写位集 `chain_rewritten(view, plane)` 供消费侧禁用基线值判据(§3.4/§3.8);
   冲突留证走既有 obs_event event=`arbitrate`(遥测 v3.3 §3.2.3 词表在册,零新机制),
   载荷 {chain, direct} 双值并陈。
8. **sim 域适配(注明)**:链在 sim 引擎有真值——`sample_node_sequence`
   (`kernel/cw_battle_calib.py:213`,P1=9)与 `P2_NODE_SEQUENCE`/P2_ROUNDS=7
   (`sim/engine_p1.py:295/:286`)逐位面段拼版,格数按位面与实机地面真值一致
   (F4);sim 适配器①按段边界把引擎序列映射进两字段(evidence 恒带
   `sim:synthesized`),映射即可、零新逻辑。现役引擎无节点替换建模(观察架构 §8.0
   节点替换未建模在案)→ sim 基线恒等于现行,**sim diff 结构性恒空**,如实申报不伪造。
9. **防双源**:`PlaneNodeLedger`(ExecState 判读侧合并视图,kernel/cw_state.py:1862)
   与 session 三载体(store_plane_table/upcoming_types/node_type_current,F10)
   现状不动、不新增职责;链查询**不读**它们。目标态 = 「全序列」类判读消费由流水
   历史承接,收编/退役候遥测 M 批裁决(OQ6,本版扩范围含三载体)。

### 3.1 观察面设计

#### 3.1.1 位面过渡 op(新增)

**生命周期归属**:观察架构 §3.4 过渡相位表**新增一行**(收编对象 = cw_loop 0q 分支的

**写端语义(两形态,基线归属=刚离开位面)**:

| 形态 | 触发 | 读数归属 | 写入 |
|---|---|---|---|

- 设计动因:离场快照写现行链(而非基线)保住「基线=改型前入口值」的时间语义——
  P1 的投资环境/策略改型全史可由「开局基线 vs 备战帧现行链 + 离场终笔」完整观察;
  若按 v1 把跨位面读数写成「进入位面基线」,则既写错位面(P2 得到 P1 的 9 格链),
  又会以离场值覆盖真正的入口基线,diff 通道结构性自毁(攻击 R1-F1 的幻影证据场景)。
- **P2/P3 基线拓扑(定谳后的新事实,如实申报)**:过渡屏不给 P2/P3 的入口值
  (1→2 显示 P1、2→3 显示 P2),P2/P3 基线 = 回退源接管:P2/P3 首个 clean 备战帧
  现行链读数回填(`prep_row_first`)或位面详情写点(`plane_detail`,接管局),
  以**最先落档者为准**。申报:**P2/P3 的 diff 观察窗较 P1 收窄**——位面内发生在
  首帧之前的改型不可观察(首帧基线已含改写后值);P1(基线=改型前)是全窗观察,
  P2/P3 是首帧窗观察。诚实缺失:回退源全缺的位面 = 无基线,diff 关闭,不伪造。

### 3.3 diff 证据设计(基线/现行 = 环境改型的直接观察证据)

**比对主体 = kernel 纯函数**(数学单一源,两域共用):

```text
chain_diff(baseline: NodeChain, current: NodeChain) -> ChainDiff | None
  # 前置:双方 plane 相同,否则 None(跨位面不比对)
  # rewrite 位集 = {i | 双方 seq[i].token 均非 None 且不相等,且 token 差不属通道受限差}
  #   (通道受限差见下;逐格通道/残差取自入参载体 TokenCell——v1.2 M-1,入参自带标注,
  #   基线侧 = 首写时持久化通道,非 diff 时点现读)
  # 长度差 = len 差(baseline 9 → current 10 = 增格,如人身意外险首领前+补给)
  # first_diff_pos = 最小 rewrite 位(增删形态下 = 首个错位)
  # baseline_coverage = 基线 token 非 None 位集(位掩码语义,F11:消费侧可见比对域)
  # 全空(无 rewrite 且等长)→ None
```

**通道受限差(channel_limited,F3)**:基线格通道 `hu`、现行格通道 `label` 且现行
token ∈ 仅标签集(`elite/megastar/invest`)——该 token 基线通道**不可能产出**,
差异属两写端识别能力集不同,非环境改写 → **不入 rewrite 位集**,单列
`channel_limited[]` 入载荷(留证不判改写)。是否升级为改型证据挂 B-1 红圈采证
(OQ2:红圈标记 = 精英节点实锤 → 过渡屏被标记格可产 elite,通道闭合,该项自然
消解)。反向差(基线 `label` 产、现行 `hu` 产,如回退源基线含 elite、备战帧
upcoming 槽 Hu 近似)同型同列。

**触发条件**(现行链每次观察写入后,同一 reconcile 段内执行):

1. 基线在场(plane 一致)∧ chain_diff ≠ None → 记 obs_event 一行;
2. **两帧确认(F3 新增)**:备战帧写入触发的 diff,须**连续两个 clean 备战帧读数
   在该位一致**(token 逐位同)才记行——单帧翻转(Hu 邻类距离谱近,supply 1.83 /
   encounter 0.58 在案)不产行,等下一帧;离场快照(过渡帧)写入豁免两帧门
   (位面已结束无下一帧,单帧即终审,载荷带 `snapshot=departure` 供消费侧权衡);
   变异窗关后首个稳定帧只作确认序列的候选帧(半变异帧不入确认),即窗关后需两个
   完整稳定帧。取舍申报:确认延迟一行 obs_event(至多一个备战相位),换噪声查准率。
3. **变异窗豁免**:投资环境/策略选择到节点行重读之间链合法变异(既有 env_grace_until
   语义,cw_state.py:1887-1891)——窗内不触发,窗关闭后按两帧确认流程补比对;
4. 基线缺席 → diff 关闭(诚实缺失);三回退源补写基线的时点**不**触发 diff(基线 :=
   现行,自证无差)。

### 3.4 接口(与件 A 唯一交汇;判定规则本体归件 A,本件只供查询语义;本节按 F2 重设计)

```text

  token  : str | None   # 现行链该位**原值,零内建回落**(F2):None = 现行链不知道
                        # (链缺/位越界/本帧未辨/past 位),语义是「现行链不知道」,

  hu_dist: float | None # 现行链该位 TokenCell.hu_dist(v1.2 M-1:载体持久化读数残差;

                        # 基线链**显式独立读**(不并入 chain_node_type):返回值可能
                        # 已被位面内改写(diff 的 baseline 比对域),仅作入口参照,

                        # 同构的 NodeChain(含逐格 TokenCell 元数据,v1.2 M-1)
```

- **回落废除 rationale(F2)**:v1 内建「现行 None 回落基线」= 把全链最旧的观察
  (位面入口值)当补位真值返回,恰是 diff 系统自己定义为「已被改写的旧值」的那种
  数据;而持有改写后真值的源(PlaneNodeLedger 合并视图、journal 历史)被「不读
  台账」红线排除在外——回落 = 用最差源截胡较好源,与裁定②「最新观察=真相」相悖
  (攻击 R1-F2)。修订:查询只供现行链事实;兜底序是件 A 的规则本体辖域
  (记录模型 §3.2.1 三源仲裁序是其既有锚)。
- **查询纪律**:只读;**不读 PlaneNodeLedger 与 session 三载体**(防双源,§3.6);
  past 位经本查询诚实 None——past 位值 = 流水历史行直读(journal 行行自足)或
  件 A 自行的台账兜底,非本查询职责(v1「past 位经 layer='baseline' 可得」随回落
  废除移除;layer 字段废除,无独立语义可申报)。
- **冲突留证**:件 A 的直定值(结算屏/遭遇屏/补给屏等专属画面)与链值不一致时,
  证据走既有 obs_event event=`arbitrate`(词表已在册遥测 v3.3 §3.2.3):
  `field='node_type'`,`observed={chain: X, direct: Y}`,verdict 沿现役
  obs_conflicts 词表。仲裁**谁赢** = 件 A 规则本体,本件不定义。
- **性能面**:查询 = 内存 Field 读,零读屏零 OCR——「商店类查链」的调用频次无成本

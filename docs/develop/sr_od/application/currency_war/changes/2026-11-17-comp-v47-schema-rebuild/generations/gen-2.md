## 0. 术语（全篇首次出现即定义）

- **阵容条目（Comp）**：一条可被策略层独立选择、独立判定成型的终局构筑路线。互斥的两条强路线 = 两个条目（见 P5）。
- **目标态快照**：一份「场上应该长什么样」的清单（哪些人在、哪些羁绊档亮、装备在谁身上、星级到几）——**不含**「什么时候做、按什么顺序长过来」。
- **阶段（Stage）**：目标态快照的一个版本。阶段切换由**状态条件**触发（某人到场 / 某装备到手），不由时间或回合数触发。Comp 的阶段从「选定该线」起算——选线之前的过渡板面归过渡库，不进任何阶段（见 P1）。
- **档位**：羁绊激活层数（注册表 `layers[].layer` 的取值，如连击 2/4/6/8）。
- **身份档 / 成长档**：身份档 = 该阵容「是谁」的羁绊档（成型判据用）；成长档 = 同一羁绊继续往上追的档（银轨 L6 专票、欢愉 5-8 档），不进成型判据、但有采购追求价值。两者在本方案分属两个字段（§2.2 字段 7/8）。
- **点名**：在字段里直接写角色名（区别于按羁绊派生的凑件）。
- **凑件**：只为凑羁绊档位而上场的人，不承担该阵容的取胜机制；由公共凑件表按羁绊给候选，不在条目里逐个点名。
- **拿掉检验**：登记判据——假想把某人拿掉：取胜机制不成立 → 机制角色（core）；机制仍成立但强度明显掉档 → 核心辅助（support）；换个人羁绊照活 → 凑件（不登记）。
- **让位序**：名单里的整数优先级，小值优先保留，同值平权。用途：人口紧张时先卖谁、先保谁。
- **成型**：策略层停止为该条目做**定向搜牌与凑档采购**的判据状态（消费契约见 §1 消费八问 Q7——星级、装备、商店投入不受此门控）。
- **星徽**：装备注册表「星徽」类（21 件），效果为「装备者加入【X】羁绊」[图鉴]——装备可参与羁绊计数；云上五骁与少女乐队无星徽条目（注册表级发现）。
- **count_mode**：羁绊注册表的激活计数控。`TOTAL` = 按上场人数计（默认）；`STAR3` = 按场上三星人数计（全表唯一特例：千星商会）[图鉴]。
- **载体**：装备的穿戴者。大多是购买角色，少数是不可购买实体（饮月的绑定随从腾荒走注册表 `is_hide` 标记；欢愉羁绊召唤的阿哈走库级白名单）。
- **主套**：帖间主流的装备配方。A/B 双套装备（如云璃充能带/攻击带）、特权版满配不进 schema——前者是变体或降级路径、后者是运行时升级动作，目标配方按主套普通版登记。
- **保值件**：跨阶段值得提前合成的成品装备（火力风暴潮/永动机类），库级常量 `CROSS_PHASE_KEEP_EQUIPS` 承载。
- **出口站**：过渡线的停手判据（派生三件套：羁绊档达 + 引擎件 2 星 + 保值件 ≥1），见 §2.3。
- **位面 1/2/3**：游戏的前期/中期/后期三段（Early/Middle/Final）。只出现在叙事里，不作任何字段值。

## 1. 设计原则

知识切三层：**进数据（本 schema）** / **留给策略层运行时** / **归文档层（final_comps 各篇）**。

### P1 数据 = 状态触发的目标态快照；一切时间过程归策略层

阵容知识里最大的一块是「过程」：搜牌节奏（5 级搜牌 / 速升 8 / 速 9）、经济纪律（卡 50 金利息、每轮至多 D 两次）、时序（2-7 速 8、3-3 搜昔涟）、梭哈点（B4「第 4 名千星成员三星时」）。这些**全部不进 schema**。理由：它们是「玩家按当前状态做的决策」，不是阵容的属性；同一套那刻夏班底，追三线卡 5 级、速升线直拉 9，人没变——变的只有节奏。节奏由策略机制层（等级-经济骨架）+ 阵容目标态组合涌现；手编时间表有整块死掉的先例（`level_plan`，方法论 comp-definition.md 第一原则）。

**例外——阶段切换是状态条件，不是时间表**：同一套阵容里存在「骨架升级」的分叉点（三甲到手才把反击档立起来 / 商店刷出姬子才转型 / 梦境星徽到手进锁轴形态）。阶段用 `enter_when`（某人到场 / 某装备到手）表达，描述的是**两个目标态之间的切换条件**，仍是快照语义。

**阶段的辖域边界（本稿成文）**：Comp 的阶段从「选定该线」起算。选线之前的板面（前期打工组、过渡羁绊壳）是**过渡库的辖域**，不进任何终局阶段——例：A2 镜流线的「1 费连击前台打工组（后期卖掉换钱）」不是镜流线的阶段 1，它就是连击过渡线本身。这条边界让「阶段名单只增不减」（P-拆分判据）不被打工组出场/退场破坏。

### P2 名单按功能分两层；第三层不点名（派生）

19 篇的骨架节都长一个样：**具名核心**（功能链角色，不可替换）→ **功能链常驻**（各占一环）→ **自由槽**（带标签即坐）。对应：

| 文档层语言 | schema 层 | 登记判据 |
|---|---|---|
| 具名核心 | `core` | 拿掉检验：拿掉后取胜机制不成立 |
| 功能链常驻 | `support` | 拿掉后机制成立、强度掉档；或帖间高频在场的引擎件/解药 |
| 自由槽 | **不设字段**——由身份羁绊档位 + 公共凑件表派生候选 | 「带标签即坐」本身说明无人格依赖 |

不按「重要度」分层，按功能拓扑分层。边界裁定纪律：**拿掉检验按机制判，不按出场率判**——H1 千冶·刃 91% 出场但有例外帖（dot 特化流不带），登 support 不登 core。

### P3 派生优先：能推导的不登记

- 凑件候选 = 羁绊注册表成员 − 点名者，顺序由公共表给；不逐条目登记。
- 过渡班底 = `bond` 成员 ∩ 费用 ≤ 2 − `engine`（已对 transition_combos 全部 9 条体系线复现验证：连击线班底 = 刻律德菈/星期日/白露、DOT 线 = 黑天鹅/桂乃芬/海瑟音/娜塔莎、云五线 = 景元/白露、击破线 = 忘归人/波提欧/流萤、奇兽线 = 那刻夏/长夜月/万敌/海瑟音、能量线 = 绯英/知更鸟·晴歌、反击线 = 万敌/云璃——全部与文档「人员要求」列吻合；唯一已知缺口：仙舟线第 4 人是 3 费位[椒丘/飞霄]，派生是下界，策略按商店等级补）。
- 巡海游侠任命目标 = 当前阶段 `core` 中让位序最小者（19 篇任命无一例外给主 C：那刻夏/遐蝶/黄泉/飞霄/雪衣/绯英，逐篇核实成立），不设字段；为此立**落库纪律：主 C 让位序必须全名单最小**。
- 反击王 = 装备最多的前台反击角色（注册表原文定义），由装备配方 + 站位派生。
- 唯一装备集 = 装备注册表 effect 含「（唯一装备）」的条目（蓄能帆/星航履/未唱名面具/绝对热量，及各自特权版），校验期从注册表派生，不手编清单。
- 「6 反击必须有反击星徽」这类可行性事实 = 点名人数与档位差的算术（反击原生成员恰 5 人 [图鉴]），由建库校验 V4 提示，不设门槛字段。
- 星徽→羁绊映射 = 装备注册表 effect 原文派生，不建表。

### P4 消费先行：字段必须挂在一个真实消费点上

策略层对阵容库的八个消费问题（下表逐条对账）。没有消费面的知识不设字段——本稿据此**不设**：家族谱系字段（选线不需要家族查询，谱系归 final_comps 索引）、降级路径字段（运行时按缺件自适应）、开局信号/词条吃怕/投资亲和字段（策略层旁表已有线级吃怕表与选卡克制表，且多数属 [社区] 待实机）、过渡线静态优先级字段（选过渡线的主判据是来牌状态，静态占比随版本重跑变化快）、上场时机字段（部署自适应的冗余约束，先例 `entry_signals` 已按用户终裁退役）。

| 消费问题 | 供给字段 | 策略层运行时补什么 |
|---|---|---|
| Q1 选哪条线 | `gates` 过滤（命座类每账号一次、菜单/奇缘类每局开局）→ 各条目当前阶段骨架匹配度评分 | 开局信号、词条吃怕、投资/门户亲和（策略旁表） |
| Q2 买哪些角色 | 当前阶段 `core` 缺员（必买）> `support` 缺员 > 身份羁绊剩余档位 × `FILLER_PRIORITY` 凑件 > `faction_ceiling` 方向（低权；成型后转主力方向） | 价格/利息纪律、已持有加权 |
| Q3 卖哪些角色 | 不在当前阶段名单 ∪ 凑件候选 ∪ 保值件载体者；**阶段名单差集 = 退役集**；让位序大者优先 | 备战席腾位、卖价时机 |
| Q4 装备怎么合成分配 | `equip_assign`（内序 = 合成优先序；Pool 取一；多件重复登记）；基础件需求从配方全表派生；过渡期只允许合 `CROSS_PHASE_KEEP_EQUIPS` | 代持与转移（归属人未到场给同线辅助代穿，到位即转移）、选秀取件 |
| Q5 星级刷到几星停手 | `need_star` 达标即停；未列不为它花刷新 | 追三止损节奏、星级供给通道（商店白嫖/低费池概率表） |
| Q6 站位怎么摆 | `char_positions` > 注册表 `position` 兜底；任命目标 = 当前阶段 core 最小让位序者（派生） | 被占/超容软回退、不重排已就位件 |
| Q7 什么时候算成型 | 当前阶段 `faction_core` 全档达标 ∧ `core` 点名全在板。**消费契约：成型只停「定向搜牌与凑档采购」**——星级、装备、商店投入不受此门控（防经济/质量驱动线被误杀，见 §5.5） | 成型质量分层评分（装备完成度/星级完成度/ceiling 进度） |
| Q8 过渡何时停手转终局 | 出口站派生：`bond` 档达 ∧ `engine` 2 星 ∧ 保值件 ≥1；`ECONOMIC_BONDS` 内羁绊不作出口主体 | 停手后利息纪律、插件按位买 |

### P5 互斥拆条；变体与降级不拆

构成或羁绊骨架不同、且帖量双强 → 拆成独立条目（A3 景元双峰、H1 黄泉双峰、E 开拓三分支、F 饭店多线、C 击破双节奏线）。装备面/节奏面的变体（A1 巨人变体、H2 七形态、云璃两条带）、降级路径（三甲不齐→双甲+风暴潮）不拆，归文档层与策略自适应。判据实操：帖量悬殊时只登主形态，其余在 final_comps 篇内挂「待帖量增长立条」——挂点在（随时可开新条目），数据暂不在。

### P6 特殊系统默认不进 schema；例外只收硬门槛

拜师、改装树、白厄吃人、双龙吟复制、奇美拉招聘、阿哈装备栏、饭店星级成长、幻月规则局、升费链——这些是「策略侧将来立项的执行知识」：要么可派生（任命目标 = 主 C），要么是运行时操作序列（吃谁、招哪只奇美拉、选哪个改装），schema 不为它们设字段；需要近似时用「把对应角色的优先级抬高」承载（comp-definition 既有裁定）。
**例外**：不可从注册表派生、且直接决定条目成立与否的硬门槛收进 `gates`（值域收窄为三条：最小命座 / 今日菜单含某菜 / 持有某角色的奇缘星魂，理由见 §2.1 字段 2）。门槛与偏好的分界线 = 帖间措辞：A3 峰 A「没有奇缘星魂不建议玩」= 门槛；H1「有奇缘星魂直接锁轴，没有半永久锁轴」= 降级（不登，归策略）。

### P7 只登例外行

星级目标与站位只登「偏离默认」的行：未登星级的角色 = 无追星义务（来牌自然，1 星可用）；未登站位的角色 = 用角色注册表 `position` 偏好（common 默认 back，属无知识兜底）。不为「描述性常态」（辅助一般 1-2 星）落字段。

### P8 装备到人不到位置；接力与代持 = 目标态归属 + 运行时执行

「装备是角色特定的」（到人），配方归属写目标穿戴者。打工代穿（万敌代穿甲→刃）、代持（知更鸟代持永动机→昔涟转交）、装备接力（景元代穿遐蝶装）都是**时间过程**：schema 只记最终归属，「持有者未到场时由谁临时穿」是策略层通用规则（同线低优先辅助代持，到位即转移），不设字段。主套 only（术语表）：特权版替换 = 运行时升级动作，目标配方按普通版登记。

### 三层归宿总表

| 知识 | 归宿 | 载体/理由 |
|---|---|---|
| 名单两层、身份/成长档位、装备到人、星级例外、站位例外、阶段切换条件、成立门槛 | **数据（本 schema）** | §2 全部字段 |
| 选线评分、采购优先、卖人让位、代持转移、降级自适应、搜牌与经济节奏、成型质量评分、特殊系统操作（任命/吃人/改装/招聘/升格）、词条与投资亲和、星级供给通道 | **策略层运行时** | 消费 §2 字段 + 策略自有旁表；节奏由等级-经济骨架涌现 |
| 达成路径叙事、变体与降级清单、家族谱系、证据与存疑、[社区] 机制主张 | **文档层** | final_comps 各篇（唯一源），schema 不镜像 |

## 2. 字段定义

类型记法：`dict[K, V]` 键值表；`frozenset[T]` 无序集；`tuple[T, ...]` 有序元组。角色名/装备名/羁绊名一律用注册表规范名（`·` 归一口径；知更鸟与知更鸟·晴歌是两个角色，混用会被校验 V1 拦下）。

### 2.0 构件类型（3 个，被字段引用）

- **Cond（状态条件）**：`('char', 角色名)` = 该角色已购入并可上场；`('equip', 装备名)` = 该装备已合成/获得且可穿。用于阶段切换；触发语义 = **一件到手即触发**（「等三件才转」会卡死低配局——D1「1-2 甲低配局也成立」帖证）。
- **Gate（成立门槛）**：`('命座', 角色名, 最小星魂数)` = 账号本体命座不低于 N（开局按本体 roster 一次评估）；`('菜单含', 菜品名)` = 本局今日菜单含该招牌菜（每局开局评估）；`('奇缘星魂', 角色名)` = 账号持有该角色的奇缘星魂（每局开局评估；效果细节 [社区] 待实机，字段只承载门槛存在性 [米游社]）。用于条目级过滤。
- **EquipPool（装备候选池）**：`tuple[装备名, ...]`，有序候选、取一。表达「第四件按需：电锯/斩舰刀/斩首/动能剑」这类攻略明确给候选但不定死的槽位。**只表达单槽位级候补，不表达整套 A/B 配方**——整套装属于变体/降级（P8 主套 only，归文档层）。

### 2.1 条目级字段（Comp，3 个）

**1. `name: str`**
- 语义：条目唯一名，人读标识 + 库键。
- 登记判据：一条按 P5 拆定的独立构筑路线；命名携带家族与形态语义（家族词 + 主 C + 形态词），家族组织本身不进 schema。
- 默认/空值：必填，无默认；库内唯一（校验 V1）。
- 案例：`'反击·刃三甲'`（D1）；`'连击·那刻夏'`（A1）。

**2. `gates: tuple[Gate, ...]`**
- 语义：条目成立门槛，**AND 语义，任一不满足即本条目出局**——与「评分偏好」（开局信号、词条吃怕，归策略层）的分界就在这条线。
- 登记判据：① 不可从注册表派生（可派生的门槛不登——克拉拉线的反击星徽依赖可由「反击原生成员 5 人 < 6 档」算出，V4 自动提示）；② 帖间一致认定为「没有就不玩 / 账号限定」[米游社]；措辞为「没有则降级仍可玩」的不登（H1 黄泉奇缘星魂）。三类门槛的评估时机不同（命座 = 每账号一次；菜单/奇缘 = 每局开局），由 Gate 值类别区分。
- 默认/空值：`()` = 无门槛，任何账号任何局可选。
- 案例：F-遐蝶线 `[('菜单含', '蝶豆糕')]`（p30 决策树硬门槛：没有蝶豆糕不建议玩遐蝶）；F-风堇马头流 `[('命座', '风堇', 6)]`（「仅推荐满魂风堇」）；H4 连击循环流 `[('奇缘星魂', '丹恒·饮月')]`（前提不满足直接不玩）；A3 赌狗峰 `[('奇缘星魂', '景元')]`。

**3. `stages: tuple[Stage, ...]`**
- 语义：有序阶段列表；执行语义 = 取 `enter_when` 已满足的**最末**阶段为当前阶段，策略只按当前阶段行动。
- 登记判据（什么时候拆阶段，机器可查版见校验 V8）：
  - **加法升级 = 阶段**：新阶段名单 ⊇ 旧阶段名单（core/support 只增不减，成员可降层 core→support 但不离名单）且身份档位目标只增，切换由状态条件触发 → 同条目内拆阶段。验证：D1（阶段 2 增反击档，巨人 3/治疗 2 保留）、A1 锁轴（增梦境 3，名单增补舞伴）、E 姬子线（瓦尔特降层为 support 仍在名单，增姬子与能量/双龙吟档）均过此判。
  - **重构 = 拆条候选**：切换前后名单或身份档位有实质减换（构筑骨架不同）→ 互斥拆条，帖量双强才立（B4 双形态 5:4、A3 双峰、H1 双峰、E 三分支、C 双节奏线）；帖量悬殊只登主形态。
  - 辖域边界：阶段从「选定该线」起算，选线前的打工板面归过渡库（P1）。
- 默认/空值：单阶段列表（大多数条目）。
- 案例：E 姬子线 2 阶段（商店刷出姬子转型）；D1 刃·三甲 2 阶段（甲到手转反击）；A1 那刻夏 2 阶段（梦境星徽到手进锁轴）。

### 2.2 阶段级字段（Stage，8 个；每阶段完整登记，无跨阶段继承——差集由消费方现算）

**4. `enter_when: Cond | None`**
- 语义：本阶段的进入条件；`None` = 首阶段（条目被选中即生效）。
- 登记判据：帖间明确的转型触发（「拿到幻造巨铠再转反击」→ `('equip', '幻造巨铠')`；「列车商店刷出姬子就买，老杨退居后排」→ `('char', '姬子·启行')`）。多触发路径登主路径（A1 锁轴登梦境交织星徽；次路径「逐日光环」属投资系统未建模，归文档层，投资建模批次后再裁值域）。
- 默认/空值：`stages[0]` 必为 `None`（校验 V8），其余阶段必非 `None`。
- 案例：`('equip', '幻造巨铠')`（刃·三甲阶段 2）。

**5. `core: dict[角色名, int]`（机制角色 + 让位序）**
- 语义：取胜机制的承担者，AND 全必要（缺一即机制不成立）；值为让位序（小值优先，同值平权）。
- 登记判据：拿掉检验（P2）；「具名核心（不可替换）」节 [米游社]。过渡 C 在换 C 型条目的早阶段以机制身份登记（姬子线阶段 1 的瓦尔特）。**落库纪律：主 C 让位序必须全名单最小**——巡海游侠任命目标派生锚点（P3）。
- 默认/空值：必填非空（没有机制角色的条目不存在）；让位序无帖间证据时全员同值。
- 案例：那刻夏·连击 `{'那刻夏': 1, '刻律德菈': 2}`（输出轴 + 标记引擎，拿掉任何一个连击体系缺一环；花火不进 core——「低配局没梦境转时是首个可舍弃位」的帖证直接判 support）。

**6. `support: dict[角色名, int]`（核心辅助 + 让位序）**
- 语义：功能链常驻——放大机制的引擎件（拉条/充能/治疗/经济）或机制死穴的解药；拿掉机制仍成立、强度掉档。值为让位序；人口紧张时大值先让位。
- 登记判据：「功能链」节帖间高频在场者 [米游社]；让位序登记帖间补位/卖出证据（「缺人口上藿藿，缺伤害上寒鸦」→ 寒鸦序小）。
- 默认/空值：`{}` 允许（极简凑档线）；跨阶段可变，**阶段名单差集 = 退役卖出候选**（Q3）。
- 案例：刃·三甲 `{'风堇': 1, '昔涟': 2, '缇宝': 3, '符玄': 3, '千冶·刃': 3, ...}`（风堇 = 燃料泵，与刃并列 8 级成型共同触发件；昔涟 = 点火钥匙；其余为反击层数成员与第二治疗轮换）。

**7. `faction_core: dict[羁绊名, int]`（身份羁绊 + 成型档）**
- 语义：身份签名羁绊及成型档位；**AND 语义——全档达标 + `core` 点名在板 = 该阶段成型**。
- 计数口径（由羁绊注册表 `count_mode` 分派，不进字段值）：`TOTAL`（默认）= 上场人数 ∪ 佩该羁绊星徽者；`STAR3`（千星商会，全表唯一）= **场上三星**成员数 ∪ 佩徽的三星非成员（[社区] 待实机，帖 6 结构佐证）；召唤型独立羁绊（双龙吟，注册表文件尾注特例集）= 成员 + 后台召唤物，饮月 1 人即达 2 档 [图鉴]。
- 登记判据：帖间「标配 / 成型判据 / 身份签名」的羁绊档；档位必须 ∈ 注册表 `layers` 档位集（校验 V3）。**身份档 ≠ 追求上限**——经济/成长型羁绊的高档知识（银轨 L4/L6、欢愉 5-8、追击 7、幻月 5）归字段 8，不在此字段登高。
- 默认/空值：必填非空。
- 案例：遐蝶线 `{'召唤': 6, '黄金大饭店': 4}`（主流成型板；两羁绊成员恰 6+4 人，点名覆盖大半，凑件压力小）；砂金千星 `{'千星商会': 6, '欢愉': 3}`。

**8. `faction_ceiling: dict[羁绊名, int]`（认可与追求档上限）**
- 语义：该阵容认可其收益、值得继续向上追的羁绊档位上限——达到即停的采购方向；**不进成型判定**；键可与 `faction_core` 重叠（同羁绊的身份档之上继续追，值必须更大）。
- 登记判据：帖间**实证追求**的成长档/副档（E 银轨 L6 专票、B4 幻月 3-5、H2 追击 7 档天花板、A1 连击 8 顶配）；独立羁绊按其 1 档登记（巡海游侠 1 = 认可买不死途任命、幻乐之主 1 = 认可阿哈升格方向）。**不登**：配置上限但无成型实录的档（DOT 9 档全批无人成型）；终局目标态不再维护的前期过程档（A1 前期的银轨 2 经济档）。
- 消费：Q2 成型后采购方向 + Q7 成型质量评分的档位上限（「什么时候算彻底毕业」的追求视野）。
- 默认/空值：`{}` = 无登记（无追求方向或纯凑档线）。
- 案例：开拓瓦尔特线 `{'开拓银轨': 6, '连击': 6, '小小巨人': 5, '群攻': 6}`（银轨 6 = 专票成长档——银轨 2 是身份、6 是追求，同一羁绊跨两字段各得其所；连击/巨人/群攻 = 三支副档方向）；飞霄追击 `{'追击': 7}`（5 档成型、7 档天花板，官方原生成员恰 7 人）。

**9. `equip_assign: dict[载体名, list[str | EquipPool]]`（装备配方，到人）**
- 语义：目标穿戴者的配方清单；**列表内序 = 合成优先序**；同名重复 = 多件（`['幻造巨铠','幻造巨铠','幻造巨铠']` = 三甲）；`EquipPool` 槽位取一。跨阶段同件换主人 = 装备转移（P8：代持/接力归运行时）。
- 载体键域：本阶段名单（core ∪ support）∪ 库级非购买载体白名单（`OFF_ROSTER_EQUIP_CARRIERS`，字段 16）∪ 注册表 `is_hide` 条目（腾荒，双龙吟装备复制的合法载体）。「唯一装备」（从注册表 effect「（唯一装备）」派生，P3）全条目至多 1 人 1 件（校验 V6）。
- 登记判据：帖间逐件到人且帖间一致的主套配方（「三甲给刃」「永动机给昔涟」「阿哈时刻 3×火力风暴潮」[米游社]）；餐品改件（蝶豆糕/迷境烤红薯等）按装备正常入配方（注册表「餐品改件」类实体；「仅供饭店角色穿戴」资格由注册表原文承载）。
- 默认/空值：`{}` = 无登记配方（凑档线）；未列名单成员 = 无目标装备（捡漏归策略）。
- 案例：刃·三甲阶段 2 `{'刃': ['幻造巨铠','幻造巨铠','幻造巨铠'], '昔涟': ['永动机'], '风堇': ['绝对热量','生命之环','生命之环'], '缇宝': ['胜利之旗']}`；B1 银狼线 `{'欢愉阿哈': ['火力风暴潮','火力风暴潮','火力风暴潮'], ...}`（非购买载体白名单用法）。

**10. `need_star: dict[角色名, 1|2|3]`（星级目标 = 停手线）**
- 语义：该角色达到此星级即「星级就绪」，停止为其定向刷新；**未列出 = 无追星义务**（来牌自然升星，1 星可用，策略不为它花刷新预算）。登的是目标上限承诺，不是必达线；追三止损（「2-4 找不齐三星就停手」）归策略层等级-经济骨架。
- 登记判据：帖间明确的追星线（低费追三：云璃/绯英/流萤/海瑟音/那刻夏）、绑定线（云璃线的花火 3 星「不然坠机」——全场唯一写死的辅助星线）、到手线（H4 饮月 ★2 = 腾荒可穿 2 件装备）、全员行（千星成员逐个三星——与 STAR3 计数耦合，每张三星直接兑换一层羁绊 [图鉴+米游社]）。
- 默认/空值：`{}` = 全员自然来牌（装备/羁绊驱动线：刃线不登刃——1 星可用；昔涟线不登——「装备地位远高于星级地位」）。
- 案例：云璃·追三 `{'云璃': 3, '花火': 3}`；砂金千星 `{'砂金·戏浪': 3, '真珠': 3, '爻光': 3, '知更鸟·晴歌': 3, '托帕&账账': 3, '翡翠': 3}`。

**11. `char_positions: dict[角色名, str]`（站位覆盖）**
- 语义：只登有知识依据的行；值域 `'front' | 'back' | 'front@N' | 'back@N'`。**坐标系定义：`@N` = 行内第 N 位，N 从 1 起，与攻略阵容数据的 front_roles / back_roles 列表内序号同源（1 基位次，非几何槽位）；取值时机 = 终局目标态，运行时被占/超容由策略软回退。** 未列出 = 用角色注册表 `position` 偏好（front/back；common 默认 back，属无知识兜底）。
- 登记判据（两类）：① 位次带机制语义的帖间铁律（那刻夏固定前排 1 号位吃连击地格、刻律德菈后台 1 号位专属、万敌前排 1 号位吃军功、白厄放后排防吃人踢人、昔涟固定前台）；② 实证推翻注册表默认的行（遐蝶「治疗体系喂出来的前台输出」——注册表 common 默认 back 是错的，必须覆盖为 front）。
- 默认/空值：`{}` = 全员用注册表偏好。
- 案例：F-遐蝶线 `{'遐蝶': 'front', '昔涟': 'front'}`；A1 `{'那刻夏': 'front@1', '刻律德菈': 'back@1'}`；刃·三甲 `{'刃': 'back'}`（帖间「刃全程坐后排」口径；与「反击王 = 装备最多的前台反击角色」的注册表张力归 final_comps D1 篇存疑条目）。

### 2.3 过渡条目字段（TransitionBond，2 个）

过渡库不复制终局库的字段族：过渡是**状态驱动的添件过程**（「加法不换件、无预设顺序」，transition_combos §8），不适用阶段；装备配方、站位、星级例外、追求档恒空（库级规则，校验 V9）；出口站判据为全库统一派生（P3），不设逐条目字段。

**12. `bond: dict[羁绊名, int]`（过渡伤害线羁绊 + 出口站档位）**
- 语义：这条过渡线的羁绊身份与出口站档位（连击线的出口站是 **4 连击**，不是首档 2——transition_combos §8 实证）；`ECONOMIC_BONDS`（字段 17）内的经济线同样入库，但出口由搭档伤害线给出、自身不参与出口派生。
- 登记判据：transition_combos 判据序（首档伤害源 + 纯 1/2 费层组合实证 + 人员要求分层）立卡的体系线。
- 默认/空值：必填非空。
- 案例：连击线 `{'连击': 4}`；持续伤害线 `{'持续伤害': 3}`；银轨经济线 `{'开拓银轨': 2}`；大黑塔系 `{'群攻': 2}`（单卡线，配 `engine`）。

**13. `engine: dict[角色名, int]`（点名引擎/伤害件 + 让位序）**
- 语义：拿掉则该过渡线不成立的点名件（「点名件在板」语义 = `engine` 全员在板）；班底**不登记**——派生 = `bond` 成员 ∩ 费用 ≤ 2 − `engine`（P3，9 条体系线复现验证通过；仙舟线 3 费第 4 人为已知下界缺口）。
- 登记判据：transition_combos「人员要求」列——单卡依赖线登该卡（大黑塔线），有最佳班底的线可不登（班底已被派生覆盖：云五线的景元+白露、反击线的万敌/云璃、能量线的绯英/知更鸟·晴歌均由派生精确给出），纯计数线留空（DOT 任意三件）。
- 默认/空值：`{}` = 纯计数线（无点名依赖）。
- 案例：连击线 `{'那刻夏': 1}`；大黑塔系 `{'大黑塔': 1}`；DOT 线 `{}`。

### 2.4 库级公共表与常量（4 个）

**14. `FILLER_PRIORITY: dict[羁绊名, tuple[角色名, ...]]`（公共凑件表）**
- 语义：每羁绊一张凑件候选优先序；候选域 = 该羁绊注册表成员（终局库消费时再减去各条目点名者）。
- 登记判据：全程留用层统计（stage_transitions §2，1-2 费双标签通用件为主）+ 各篇「自由槽/第三人从谁补」的帖间证据；辅助/工具型优先，**输出大 C 不进表**（防凑件抢主 C 的位置与装备）。
- 默认/空值：某羁绊无表 = 该羁绊凑件按注册表成员顺序兜底。V4.7 羁绊大换血，全量重定。
- 案例（示意）：`'治疗': ('藿藿', '白露', '罗刹', ...)`——具体排序归落库批按证据定，此处只锁结构。

**15. `CROSS_PHASE_KEEP_EQUIPS: frozenset[装备名]`（跨阶段保值件白名单）**
- 语义：过渡期**唯一允许主动合成**的成品集（「合成装只在跨阶段保值时提前合成，不为过渡特意合成一次性件」，transition_combos §7 [米游社]）。
- 登记判据：帖间公认的跨阶段保值件（终局多线共用、打工位可先用）。
- 默认/空值：非空常量；初值 `{'火力风暴潮', '永动机', '蓄能帆'}`，落库批按帖证增删。消费 = 过渡期合成闸（Q4）+ 出口站「1 件合成装」判据（Q8）。

**16. `OFF_ROSTER_EQUIP_CARRIERS: frozenset[角色名]`（非购买装备载体白名单）**
- 语义：可作 `equip_assign` 键、但不在任何购买名单里的实体；封闭常量，新增需改此表。
- 登记判据：注册表无条目、但帖间存在独立装备栏的实体。V4.7 一例：欢愉羁绊召唤的阿哈（B1「阿哈时刻装备 3×火力风暴潮……与星神★阿哈单位是两个实体，装备栏各自独立」[米游社+图鉴欢愉原文]）。腾荒**不经此表**（他在角色注册表内，`is_hide=True`）。
- 默认/空值：`{'欢愉阿哈'}`；空集合法（无此类载体时）。

**17. `ECONOMIC_BONDS: frozenset[羁绊名]`（经济开局线羁绊集）**
- 语义：无自身伤害源、以经济产出为主的羁绊集（transition_combos §5 判据①裁决：开拓银轨「不是伤害主体」）；集内羁绊的过渡条目不作出口站主体，出口由搭档伤害线给出。
- 登记判据：transition_combos 判据①的文档结论落库为机器可判常量（伤害源有无无法从注册表 layer 文本可靠派出——仙舟舰队同羁绊 2 档无伤害 4 档有伤害，即反例）。
- 默认/空值：`{'开拓银轨'}`；幻月/千星为顺带激活的经济系副档，不立过渡条目、不入此集。
- 消费：Q8 出口派生的主体判定 + 策略「先选伤害主体」规则的机器依据。

## 3. 库的组织

### 3.1 两库分立

| | 终局库 `COMP_LIBRARY` | 过渡库 `TRANSITION_LIBRARY` |
|---|---|---|
| 条目形态 | `Comp`（字段 1-3 + Stage 族 4-11） | `TransitionBond`（字段 12-13） |
| 阶段 | 允许多阶段（状态条件切换，V8 加法不变量） | 恒单形态（状态驱动添件，无预设顺序） |
| 装备/站位/星级例外/追求档 | 按登记 | **恒空**（库级规则，校验 V9） |
| 锁定语义 | 成型后锁定名单方向 | **永不锁定**（来牌主导，随时换线） |
| 成型/出口判定 | 当前阶段 `faction_core` AND + `core` 在板（Q7） | 出口站派生：`bond` 档达 ∧ `engine` 2★ ∧ 保值件 ≥1（Q8） |

两库分立的理由：过渡的选择逻辑（来牌主导、意向同向、加法不换件）与终局的目标态逻辑（点名、AND 成型）是两种计算；硬塞一个 schema 会让终局字段在过渡侧大量恒空。**过渡→终局的流向知识**（连击线出口通向 A 家族等）归 transition_combos §8 的指针表（文档层），不建库间引用字段——选终局线是策略运行时评分，不是静态图遍历。

### 3.2 公共表与常量的归属

`FILLER_PRIORITY` / `CROSS_PHASE_KEEP_EQUIPS` / `OFF_ROSTER_EQUIP_CARRIERS` / `ECONOMIC_BONDS` 与两库同模块维护（阵容定义单一源，一个文件）。代码载体 = kernel 侧 comp 模块（`cw_comps.py` 的 v2 继任），`@dataclass(frozen=True)`，建库校验（§4）在模块 import 期执行、违例即抛。

### 3.3 版本纪律与挂点

- 库数据随 final_comps 重建批次联动重跑（frontmatter `rebuilt` 对齐）；注册表（羁绊/装备/角色）先行重跑，库校验在 import 期自动拦截版本失配的名字与档位。
- 家族谱系：Comp 平铺 + 命名带家族语义，不为组织结构引入 schema 层级（P4：无家族查询消费点）。
- 挂机奖励流（13 人全羁绊刷星琼 / 十六羁绊星徽墙 / 翡翠速刷）：目标 = 解锁羁绊奖励非吃分，无成型判定、无搜牌、无装备分配，消费面与吃分线完全不同——按迭代裁定**独立立批**（第三库 REWARD_LIBRARY），本库不留半吊子字段。

## 4. 建库校验（import 期即可查出的数据错误）

- **V1 引用合法**：`name` 唯一非空；所有角色名 ∈ 角色注册表（含 `is_hide` 载体与白名单名；知更鸟/知更鸟·晴歌等近名混用在此拦下）；装备名 ∈ 装备注册表（特权版独立条目，不与普通版混键）；羁绊名 ∈ 羁绊注册表；Gate 的菜品 ∈ 装备注册表「餐品改件」类；`gates` 的角色 ∈ 角色注册表。星神★阿哈同名多费档（注册表 4/5/7 三条目）按名字级成员处理，费用档 = 采购知识不在库层区分。
- **V2 名单互斥**：逐阶段 `core ∩ support = ∅`；跨阶段同人可变层（core→support 降层合法）。
- **V3 档位合法**：`faction_core` / `faction_ceiling` / `bond` 的档位 ∈ 该羁绊注册表 `layers` 档位集（连击登 5 = 错，合法档只有 2/4/6/8）；`ceiling[k] ≥ core[k]`（键重叠时）。
- **V4 成型可行性（按 `count_mode` 分派；硬查 `faction_core`，软警 `faction_ceiling`）**：TOTAL 口径 = 点名成员中该羁绊人数 + 星徽可补数（该羁绊有星徽条目才计，星徽集从注册表派生；云五/少女乐队计 0）+ 公共凑件池 ≥ 档位；STAR3 口径 = 可追三的 `need_star` 行数 + 佩徽三星名额 ≥ 档位，且 **STAR3 羁绊档位 > need_star 三星行数时警告**（耦合漏登嫌疑——B4 忘登翡翠 3★ 即被此条抓出）；召唤型独立羁绊（注册表文件尾注特例集，现仅双龙吟）走白名单：成员 1 人即达 2 档。
- **V5 人口边界**：逐阶段 `|core ∪ support|` ≤ 13（V4.7 实测最大板面 + 财富宝钻扩容，[米游社] 推断，实机固化）；过渡线 `bond` 档位所需人数 ≤ 5（位面 1 人口压死，transition_combos §1）。
- **V6 装备约束**：`equip_assign` 键 ⊆ 本阶段名单 ∪ 载体白名单 ∪ `is_hide` 条目；「唯一装备」类（注册表 effect 派生集，含特权版）全条目至多 1 人 1 件（F 篇「未唱名面具给遐蝶和昔涟」的分流规则正是会撞这条的现实案例——按目标态只登一人是正解）；`EquipPool` 内无重复项。
- **V7 键域收口**：`need_star` / `char_positions` 键 ⊆ 本阶段名单。
- **V8 阶段结构**：`stages` 非空；`stages[0].enter_when is None`；其余阶段非 `None`；`('char', X)` 中的 X ∈ 本条目某阶段名单（否则条件永无意义）；相邻阶段同条件 = 错误。**加法不变量（P5 拆分判据的机器化）**：相邻阶段 i→i+1 满足 (a) 名单（core∪support）只增不减；(b) 每个身份羁绊的档位（core 或 ceiling 取最大）非降；(c) `faction_core` 键集单调增——违反 = 该处实为重构，应拆条，落库批裁决。
- **V9 过渡库恒空与完备**：无阶段字段；`equip_assign` / `char_positions` / `need_star` / `faction_ceiling` 恒空；`engine` ∪ 派生班底 ⊆ 注册表；`bond` 键 ⊆ 注册表；`ECONOMIC_BONDS` ∩ 过渡库伤害线条目集 = ∅（经济线条目必须且只能由 `ECONOMIC_BONDS` 内羁绊构成身份）。
- **V10 公共表一致**：`FILLER_PRIORITY` 键 ⊆ 羁绊注册表且值 ⊆ 对应成员；`CROSS_PHASE_KEEP_EQUIPS` ⊆ 装备注册表进阶装备；`OFF_ROSTER_EQUIP_CARRIERS` ∩ 角色注册表 = ∅（封闭且不与购买名重叠）；`ECONOMIC_BONDS` ⊆ 羁绊注册表。

## 6. 结构风险（本方案最薄弱处，按危害排序）

1. **`faction_core`（身份档）与 `faction_ceiling`（追求档）的边界在证据灰区会摇摆**。两字段语义清晰，但具体某羁绊登哪边依赖帖证强度判读：D1 的治疗 6 档（「冲 6 层时治疗档本身就是全队增伤档」——机制事实，但追不追是另一回事）、B1 的千星 2/4/6 阶梯（副引擎还是成长方向）属灰区。版本重跑时灰区行漂移无人察觉。缓解：字段 8 的登记判据已成文（帖间实证追求 + 消费 = 成型后采购方向；灰区不登——登了没消费面就是死数据），落库批按判据逐行过。
2. **成型判据的结构性口径与攻略的质量性口径错位**（§5.5 注记①的推广）。经济线（E/银轨）、质量线（D3 云璃「3 星+满装=成型」、B4「8 级追三星砂金」）的攻略成型判据含星级/装备成分，schema 成型只含档位+名单。当前用 Q7 消费契约（成型只停定向搜牌）化解，但这只是一份写给未来消费方的约定——消费方违反约定时，结构上无防线。若实跑出现「成型即躺平」，第一修法是把成型判据扩为「档位 ∧ 名单 ∧ 指定 need_star 行达标」，需要给 need_star 行加「成型阻塞」标记（字段值域变，字段数不变）。
3. **阶段全量快照的跨阶段重复**。A1 的 equip 两份、姬子线阶段 1 ≈ 瓦尔特线整条——V8 拦得住结构违规，拦不住「两份本该相同却不同」的内容漂移（改了 s1 忘改 s2）。缓解：落库流程先写末阶段再向前复制裁剪；漂移最终靠版本重跑对拍。
4. **让位序是手编弱标尺**。帖间证据常只给局部序（「回血顺位白露→藿藿」「空位优先序飞霄>花火>千冶·刃>…」单帖），全序是登记者的拼装；版本重跑时局部序变了，全序没人知道该改哪。缓解：默认同级平权、只登帖证行分级；主 C 最小纪律有派生消费兜底（任命目标）。
5. **挂着 [社区] 待实机机制的字段语义可能漂移**：菜-人映射与菜单门槛（config 无菜-人字段，逐帖零例外但待实机终证）、佩徽三星非成员计数（帖 6 结构佐证）、欢愉阿哈载体的实体身份、奇缘星魂门槛的存在性与效果、双龙吟「选连击分支计入连击数」（A2/A3/A4/H4 多帖标题口径）、命座继承乘区（风堇门槛的机制底座）、升费步进细则。建库校验拦不住语义级漂移，兜底 = 实机取证后的库重建联动（`rebuilt` 对齐机制）。
6. **拆条帖量门槛没有量化**。「双强才拆」在 B4（5:4 双形态）、B2（五峰 14/9/7/…）、C（双节奏线 20:18）上执行粗糙，低帖量形态归文档 = bot 识别不到该路线（挂点在，数据不在）。落库批需人判并记录判读理由。
7. **`need_star` 的星级供给通道不建模**（§5.5 注记②的推广）：开拓家族的星来自商店、千星的星即羁绊、DOT 五费明确不追——这些都装下了；但「几级搜、搜不到何时止损、商店怎么白嫖」全押策略层。若策略层没有等价的供给/止损骨架，`need_star` 会变成「永远刷不满」的死目标。
8. **过渡库两字段的押注**：先选伤害主体、意向同向 tie-break、双标签顺带激活这些组合规则全部推给策略层（理由：来牌主导的运行时逻辑；且组合对大多可由注册表双标签成员派生解释——transition_combos §7 判读）。若策略层的过渡选择器没有独立承载这些规则，两字段撑不起 Q8 之前的过渡期决策。

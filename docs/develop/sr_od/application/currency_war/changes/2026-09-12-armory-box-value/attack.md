### A3【次要】§2.3「已知的结构性欠计数通道」枚举不全：商店角色自带装备的入队期不入两账

- 位置：`design.md` §2.3 边界情形裁决「已知的结构性欠计数通道（申报）」、§2.5。
- 事实（直调）：需求守卫的总持有账 = `last_owned_equips`（装备区格现读全量重写，prep_actions.py:411-416/:571-584）+ `tracked_deployed[*].equips`（cw_op_equip_all.py:158-161 写、cw_op_deploy.py:1010 部署快照画面真值覆盖）。**备战席角色身上的装备不入任何一本账**：装备区读数不含（不在格上）、tracked_bench_chars 无 equips 写端（全仓 `.equips =` 写点仅 cw_op_equip_all.py:160 与 cw_op_deploy.py:1010 两处，均辖 deployed）。而「买商店角色附带已穿装备」是在册实证机制（equipment_mechanics.md §3，run 26 希儿案例【口述·权威 + 实锤】）。key 件经该通道骑在待部署角色身上时，total 计数漏 1 → 守卫漏判已满足 → 冗余 K 吃 tier 3 错提权（与设计已申报的欠计数失效方向同向，非保守）。
- 发作场景：锁线后补给/商店取得带 key 装备的角色入备战席 → 同帧武装箱再出同名 key 件 → 该件仍被 tier 3 提权挤占有用件；直至角色部署后才被部署快照纠正。
- 修正方向：§2.3 通道清单补列该通道（与「穿着即合成产物不入账」同批归「穿戴/持有账写端域」挂账，共用同一观测键或分立），并注明 SellBench 效果推进无装备返还面（apply_op_effect 仅 SellDeployed 推 equips 返还）为同域盲区。失效方向已声明故不阻断，但「已知通道」的枚举主张应完备。

### A4【次要】近兑现对数判定的备用账口径漏「穿着触发合成」完成路径，两账分工依据表述不完整

- 位置：`design.md` §2.3「近兑现对数判定用备用账（栏内合成的输入面在装备区库存）」。
- 事实：合成有两条在册路径（equipment_mechanics.md §1：装备栏内合成 + 穿着触发自动合成），且穿着合成路径生产可达且被分配器明文允许（`_pairing_guard_ok` 例外①「core 上穿着合成 = 快路径」，cw_comps.py:1912 直读）。材料对一侧已穿在角色身上、另一侧在库存时，拖库存件上身即可合成——spare-only 口径判「可用对数 = 0」会漏该完成机会 → tier 2 漏提权（漏提权 = 保守向，无错误动作，但档位收益系统性少拿）。设计以「栏内合成的输入面在装备区库存」作两账分工唯一依据，未覆盖第二路径。
- 修正方向：§2.3 该句补「穿着合成路径的对侧可为已穿件，spare 口径对其漏判，漏向保守、与 A3 同域挂账观测」；或把穿着账组件并入对数判定（则须先解 A3 的账真值问题，挂账更稳）。

### A5【次要】§2.6 行 7a/7b/7c/9 的帧不含完整 offer（对照件与顺序缺失），「逐行对锁」不可直接落锁

- 位置：`design.md` §2.6 行 7a/7b/7c/9。
- 事实（复算）：行 7a「持量产型装甲，offer 幸运星」裸帧下新旧取卡一致（幸运星现行 30+3=33、新制 tier 2，均胜通用件）——行为反转只在对照件入帧时显形（如 [幸运星, 生命之花]：旧 33<37 取花，新 tier2>tier1 取星）；行 7b/7c 同理（裸帧下与通用件对照新旧同选）；行 9 的「同值通用件」在并列时改后归属由 offer 序决定，行文未给序。这些行锁的对象（tier 判定）语义明确，但作为「逐行对锁」的帧规格欠「实现者无需再设计」——锁哪个 offer、断言什么索引存在自由裁量。
- 修正方向：各行补全 offer 全集与期望索引（7a 建议对照件 = 同 comp 另一 mv 更高材料），或显式声明「行 7a-7c/9 的锁打在 `pick_equipment` 纯函数 tier 判定上（输入全参自定）+ 一条含对照件的 box 集成帧」，与 landing 3.2「tier 2 判定语义锁打在纯函数上」的既有安排对齐。

### A6【次要】值域标签错：直击「[100,107]」实为 {100}、材料「[30,37]」实为 [33,37]（以现行库为域）

- 位置：`design.md` §2.2「加法制 → 序数制的漂移面精确陈述」。
- 事实（实跑）：COMP_LIBRARY key_equips 全部 ∈ {进阶, 特权, 白昼}（20 套逐套核），与 MATERIAL_VALUE_TABLE（8 简易名）交集 = ∅ → 直击实现值恒 100，上界 107 需「key ∈ mv 表」不可达；key 材料全部为 8 简易名（进阶 recipes 全为双简易对），mv 最小 3 → 材料实现值域 [33,37]。设计自称「精确陈述」却给了结构上界（超集界）。
- 影响面：三段分离结论不受影响（100>37>7 在超集界下同样成立），纯数值口径标签错，按「值对标签错」错误类记录。
- 修正方向：改为实现值域 {100}/[33,37]，或保留原区间但标注「结构上界（含不可达段）非实现值域」。

### A7【次要】需求守卫的主依据为声明性模型假设且无观测键；「超配零边际」对可叠加 key 件存在反面信号

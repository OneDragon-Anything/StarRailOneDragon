# 阵容定义方法论(Comp schema 设计:字段准入与分层判据)

> 单一源入口 = SKILL.md 分诊表「阵容定义」行。读者 = 智能体;适用于:给
> COMP_LIBRARY 新增/修订字段、评审字段提案、把阵容知识落库为结构化定义。
> 姊妹篇分工:知识怎么从攻略提炼(证据三层)→ `compo-knowledge.md`;
> **提炼出的结论怎么落成结构化字段(字段该不该有、什么语义、什么不进)= 本文档**。

## 第一原则:Comp = 目标态快照,不含时间过程

**结论(2026-11-04 用户定谳):阵容定义不抄攻略的位面 1/2/3(前/中/后期)
三阶段——直接按终局形态定义。**

攻略侧的阶段分段(plaza Early/Middle/Final 聚类;各篇「成型路径」节的
「位面 1 开 X / 位面 2 追 Y / 位面 3 完全体」叙事)是**人读知识**,归
`final_comps/` 各篇;不进 COMP_LIBRARY 结构化字段。

时间维度在本系统的架构归属(结构化字段为什么不需要它):

| 机制 | 层 | 给什么 |
|---|---|---|
| 位面-轮节奏骨架(`cw_economy.get_node_goal`/`_expected_level`) | 策略机制层(阵容无关) | 何时升级/停留/花金 |
| 游戏真值刷新率(`cw_shop_odds` 随等级)+ 自适应找牌(`_core_miss_q`) | 游戏真值层 | 几级能刷到几费卡 |
| 阵容目标态(`core_chars`/`need_star`/`form_tiers`) | 阵容定义层(Comp) | 刷到之后要什么 |

三者组合,「X 线 7 级停 D 三星主C」这类攻略节奏指令自动涌现(P2 曲线
2-1 即升 7 + 主C need_star 3★ + P1 找牌 core 通道),无需按阵容手编曲线。

位面坐标仅两处合法出现(都不是节奏):

- **辖域闸门**:`session_scope.plane2_started`(进位面 2 的单调布尔)——
  切换策略行为域(配方清除/各辖域开关),消费面在策略层;
- **形态信号**:`entry_signals` 的 `plane_end` 类(白厄 B 套类「满编后期
  特权形态」)——**形态切换信号,非节奏**;其他线出现同类需求时扩展
  `entry_signals`,不开新字段。

**准入硬判据:凡「何时/过程」性质的字段都是层次违规。** 判例:
`level_plan`(等级→动作手编曲线,20 套 ×~7 级 ≈ 800 行)——消费路径
(P1 找牌窗)被「core 通道 + 节奏骨架」取代后整块成为死数据;死因不是
维护疏忽,是**手编曲线 vs 自适应推导的机制淘汰**。

## 字段准入判据(新增/修订字段前逐条过)

1. **消费先行**:先有明确消费它的策略行为,再落字段。「知识完备性」
   不是理由——把攻略知识尽量结构化进注册表的五批叠加史(v2 十字段/
   知识卡/形态端口…),产出的字段随策略演化消费面收窄后成批死亡
   (v2 十字段死 6、level_plan 整死、评分器族 4 字段随评分器整删)。
2. **派生优先**:能从既有字段或游戏真值派生的不手编。判例:
   `factions` ≡ `form_tiers` 键集(20/20 恒等,纯冗余);
   `member_priority` 恒等于 core/shared 两档派生(20/20 无手编)。
3. **名单多胞胎警惕**:成员名单字段(core/shared/transition/key_items/
   lock_rules 角色型/need_star 键/entry_signals 键)语义高度重叠——
   新增名单前先问能否挂到既有名单的属性上;名单间关系必须有校验
   (判例:key_items 曾有 5 阵容含 core∪shared 外成员——多表无校验
   的维护病)。
4. **目标态快照**:见第一原则——过程性知识(何时/怎么长过来)不进
   schema,归 final_comps「达成路径」叙事 + 策略机制层。
5. **攻略口径→结构口径的翻译**:攻略说「X 优先/默认」时,分清**门槛**
   (统一维度实现,新候选零改动)vs **身份**(专属判定,依据读注册表
   数据非名字 if)——与 `compo-knowledge.md`「教义措辞规范」同款
   纪律,防实现层造特权分支。

## schema 分层语义(字段族边界;字段清单与值单一源 = `cw_comps.py`)

- **身份**:阵容是谁、聚类锚;
- **成型**:终局形态判据(AND 档 + OR 组 + carry 在板;`form_progress`
  唯一折法,禁消费位内联判定);
- **成员**:谁在名单(core/shared/transition 三档,送卡档位与终局成员
  集的原料);
- **知识卡**:选线证据/上线窗口/星级目标(lock_rules/key_items/
  entry_signals/need_star);
- **装备**:到人配方(equip_assign 真源 + key_equips 投影 + 禁忌);
- **过程性知识不进 schema**(何时/怎么长过来)——归 final_comps 叙事
  与策略机制层。

字段族的具体成员随迭代增减,本表只锁语义边界;「现在有哪些字段」查
`cw_comps.py` 的 Comp dataclass(单一源,不镜像)。

## 2. 五门逐门判定

### 门① 内部推导健全性 —— **不过**

- P2 的「证明」全文一句:引用 plaza_methodology M16 装备-经验耦合推导。**该推导原文已不存在**:M16 现行文本是「用户修正版」,原「我方每件简易装备 +1 经验 → 早期铺满全队是正期望」的推导被**封存并改写**(2026-08-24 用户裁定,狼狩体系封存),现文只留一句指针式存档。
- 判定:推导链断裂——定义/引理/量化推导均不可复算,无脚本、无 CI、无样本量声明。P2 自身诚实标注「边界受限的已证/强度待重验」,但按五门标准,这不是「已证」,是**「源体系内曾推导、推导文本已灭失的封存命题」**。门①判:不可复算,不过。

### 门② 数值锚点 vs 注册表直调 —— **机制存在✓ / 定量锚缺失🟡**

- 机制直调实锤:`cw_factions.py:59-60` 狼狩效果原文「召唤【步离人】协同战斗,其在参与战斗后可以获得经验并升级。**我方队员携带更多装备会使其额外获得经验**。」——装备→经验耦合机制**真实存在且注册表在册**,但为**狼狩羁绊专属**(全注册表 grep「步离人/额外获得经验」仅此一处+其消费件,其余 25 阵营无此机制)。
- 定量值「每件每战 +1 经验、进阶算 2」:落在 `cw_survey19_hooks.py:32/43`(批,用户修正裁定产物),**不在注册表文本**(cw_factions 只写定性「额外获得经验」)。+1/+2 的原始出处=狼狩语料/口述,无实测采点、无 CI。

### 门③ 建模对象 vs 玩法文档机制 —— **命题表述已被用户修正版取代(核心发现)**

- **建模对象核对**:P2「铺满全队 > 集中给核心」建模的机制 = 狼狩「队员携带装备 → 步离人多得经验」。铺满的收益通道是**经验**,不是战力——这正是它与 [9]「不是有装备就用(角色特定优先级)」并存不悖的原因:**[9] 管战力分配域,P2 管狼狩局的经验产出域**,两者在不同局类型下各辖一方。粒度轴:P2 的比较对象是「穿着件数总量」(受 3 件/人×上场人数槽位约束),不是「给谁」——「集中给核心」在经验机制下并不减少件数,真正的对立项是「躺在物品栏(0 经验)」。口径核对结论:**P2 命题的表述本身不准**——机制真形态是「穿着 > 积压」(每多穿一件多一份经验流),「铺满 vs 集中」的二分没抓到机制变量。
- **文档演化链**:现行 M16(用户修正版)已把该纪律改写为——装备可循环(卖出回收/扳手拆),**不为任何阵容牺牲合成规划;唯一纪律 = 物品栏积压报警**(无空槽可穿的真积压才算)。落地件 `wear_discipline_alert` 与此一致:狼狩局积压量化为步离人经验损失,合成规划(key_equips 优先序)不受影响。**即:P2 作为「规划规则」已被用户裁定降格为「防积压报警」**——「早期铺满」不再是决策倾向的授权命题。
- **现行体系的直接反例面**:非狼狩局中,装备-经验通道不存在,「铺满」只剩余战力效应;而 equipment_mechanics 囤积原则明文「无用简易**不穿着、囤装备栏**」(等冶金炉回收),`RESERVED_COMPONENTS`(P1 阶段 8 基础件不入穿戴池,[29]/A2G)与 `recycle_qualified` 准入更是把「有可穿就穿/铺满」从现行执行面**显式移除**。门③判:命题在现行文档体系下已被取代+辖域封存,原表述与现行机制面存在方向性冲突(仅由「狼狩局条件化」豁免)。

## 0. 判据框架(所有工具共用的三道门)

任何一件工具在被自动消费前,须依次过三道门。这三道门将 [9]/[22]④/〔P14〕的口述与数学合并为一个统一账:

### 门 A:到货不规划(有才有资格谈)

工具一律来自投资策略牌/门户/奖励节点发放(〔机制篇·工具 7 件全量·获取通道〕,码源 `cw_invest_data.py:50-364`)。**到货随机 → 有炉才考虑刷什么、有扳手才考虑拆谁,不做「攒到最优时机再用」的规划**(〔机制篇·经济账框架〕引口述权威;与 P14 定理 4「令牌命中 R(c) 时 0 轮支配一切但不可规划」同一结构性理由:发放时刻不受控制,规划无从附着)。实现含义:工具决策只在「读板发现工具在 owned」的那一拍评估一次,不进入跨轮计划。

### 门 B:账怎么算([9] 装备价值 × [22]④ 凑息账 的合并口径)

这是本设计的核心记账问题:**冶金炉回收是否合格,以及一切工具动作,要不要过凑息账?** 结论分两层:

1. **金面(凑息账 [22]④)对工具动作本身几乎恒空转**:工具动作(拖炉/拖扳手/拖令牌/拖特权卡)**不花金**,因此不产生息差损失,不需要像买牌那样过「这笔会不会破息」的门〔口述 22④〕。例外仅两处金流,各自归位、不算工具账:
   - *获得工具的那笔钱*(买发工具的投资策略牌)——那是投资牌选择账(`cw_investments`),按既有一套评;
   - *操作派生金*(持有精密扳手后再获普通扳手改得 1 金,〔机制篇·全量表〕)——所得金按息律通则处理〔口述 17:≤50 攒息、>50 该花花〕,不影响该不该做操作本身。
2. **价值面([9])才是工具账的全部**:〔口述 9〕「不是有装备就用」+〔口述 29〕「定阵容前不浪费合成组件」,机械化为一条判据——**一件装备对当前目标的价值 = 它是否在目标需求向量里**:
   - 进阶层:名字命中 `target_comp.key_equips`;
   - 基础件层:展开为组件需求向量 `component_demand(key_equips)` 后是否有正份额,差集由 `hoard_gaps(key_equips, owned)` 给出(〔码〕`cw_synthesis.py:131-150/:171-193`);
   - 「连组件都当不上」的判定生产化 = `recycle_qualified(key_equips)`(〔码〕`cw_synthesis.py:153-168`,P14 定理 3 准入)。
   
   **合并成一句话:工具动作的经济审只查一件事——被操作的装备(或由此产出的装备)在不在目标需求向量里;金面默认不管,仅在上述两处派生金流出现时按息律通则搭车处理。**

### 门 C:不可逆性分级

四件工具一次性消失(冶金炉/员工投影仪/好运令牌/特权赋予卡/普通扳手),精密扳手无限次〔机制篇·全量表,〔码〕`cw_equipment_data.py:182-188` 效果文本〕。一次性工具的证据要求更高(判据错一次赔整件);实证层面「穿着即合成无确认无日志」已经演示了误操作的隐蔽性(〔机制篇 §1〕),自动消费的实现必须带执行后验证(sim 行为锁 + 实机遥测各一道,见 §6)。

## 1. 冶金炉(取下并转化)

**效果**:拖到一件装备上 → 变同类型随机装备;拖到角色上 → 取下其所有装备并各自变同类型随机;用后消失(〔码〕`cw_equipment_data.py:182`)。

**何时用**:
- **单件用法**:owned 里某基础件 b ∈ `recycle_qualified(K)` ——它是任何目标进阶都合不出来的死库存,烧掉换 1/36 抽卡机会严格不亏(P14 定理 3:能当合成原料的件回收必亏——销毁的是确定性期权,换来 m/N 概率事件)。
- **角色用法(回收流水线终段)**:攒够 3 件无用进阶穿在一个**死库存工具人**(无待迁资产的角色)身上,拖炉一次完成「三件同刷+全拆」,吞吐 3:1(P14 定理 2;流程见〔机制篇·回收流水线〕)。准入 = 三件逐一过 门 B 的价值判(b ∉ 需求向量),外加 [22] 囤件语义的持有价值判——「刷完再囤」必须先确认新产出确有缺口(`hoard_gaps` 为正)〔机制篇·经济账框架〕。
- 触发频率预期极低:E[炉次→首中] ≥ 9 炉(m≤4),**炉不是获取通道,只做转化**〔P14 定理 2/4〕。

**何时不用**:
- b 在任何目标进阶的配方里(含 RESERVED_COMPONENTS 全体保留组件的口径之外——具体即 `component_demand` 有正份额)→ 留着合成,永不进炉;
- `key_equips` 为空(无目标/未定型)→ `recycle_qualified(None)` 返回空集,一律不动(保守侧,〔码〕`cw_synthesis.py:165-166`);
- m=1(只有一个可接受缺件)时 0.083 件/炉 ≈ 不值得专留原料喂炉〔P14 定理 2 表〕;
- 被拖角色身上有 [24] 待迁资产(key_equips 类穿着)→ 先扳手取下再炉,禁止连资产一起刷掉;
- **凑息账不拦**:炉动作不花金,门 B 第一条适用——不存在「这轮破息所以别用炉」的理由。

## 2. 拆装扳手(取下全部)

**效果**:拖到角色 → 取下其所有装备,用后消失(〔码〕`cw_equipment_data.py:186`)。

**何时用**:**扳手的重摆去向 = 「被拆者不再需要的装备,原样转移到需要它们的人」**。使用门槛只有一句(〔机制篇·经济账框架〕:零损耗纯移位,不看磨损不看品级,只看「还需不需要」):
- 过渡阵容退场、输出装要迁给成型核心([24] 装备转移是常态);
- 同一角色换排(前后台限定件装错排的纠正,〔机制篇 §2〕——批量取下后重穿,普通版本因稀缺通常不值得为此用,见不用条款)。

**去向登记(实现须回答「拆下来的去哪」)**:每件取下物必须落位之一——①立即重穿给需求向量内的角色(分配器 `equip_allocation` 消费);②回 owned 囤待合成/待发([22] 囤件);找不到去向 = 不拆(拆完散落 owned 无主是负操作)。

**装备合成排序与「变宝为废」环境(ADR-0498)**:分配序即拖拽序即合成事件序。环境词缀「变宝为废」在场(`state.enemy_affixes` contains,读不到=不启用;机制真值=affix_effects_data 游戏内原文「每个位面开始时,首次合成的进阶装备会有50%的概率变成垃圾袋」)时,排序器 `kernel/cw_junk_first.py` 对分配序列做纯后处理:有牺牲对(非 core 的回收合格配方对,P14 定理 3 判据,不碰主线凑件)→ 牺牲合成先行消耗**该位面**的首次合成垃圾化判定;无牺牲对 → 高价值合成完成件推迟一帧(每位面预算 1 帧,`session.junk_first_done_plane` 位面记账,耗尽放行)。开关 `junk_first_sacrifice_enabled` 默认关(开臂判据见 ADR);执行链(drag/验穿)零改动。

**何时不用**:
- 被拆者是当前核心、身上有 key_equips(r70 过渡持有语义,key 命脉件应留在上场的人;〔码〕`equip_all.py:112-124` `_transition_hold_active`);
- **直拖可达时不兜圈**:单人→单人的一件迁移走现有 C6 转移遍直拖即可(〔码〕`equip_all.py:370-396`,付一次性拆卸代价的语义与 [24] 一致);扳手的不可替代性在**批量**(一人全身迁多人)场景,单件直拖更省且不烧消耗品;
- 无剩余去向核对(上文登记制不满足)。

## 3. 精密拆装扳手(无限次)

**效果**:同扳手但无限次;持有后再获普通扳手改为得 1 金(〔码〕`cw_equipment_data.py:188`)。

**何时用**:普通扳手判据的**超集**——取下成本 ≈ 0 之后,普通扳手唯一稀缺性带来的节约顾虑失效,**宽用**:凡满足 §2「何时用」即做,不必权衡消耗品稀缺。典型新增面:错排纠正(§2 案例)从「不值得」变「随手修」;迭代型重摆(每次演进后大范围装备搬家,02_comp 演进事务执行段)全程免费。

**何时不用**:同样以「还需不需要」为唯一闸——被拆装备仍是持有者所需(核心/key 持有)就不动。1 金红利不构成任何使用或不使用的理由(门 B 第 2 条)。

## 4. 员工投影仪(≤3 费复制)/ 5. 完美投影仪(任意费复制)

**效果**:拖到角色 → 备战席创造其 1 星复制;前者限 ≤3 费,后者任意(〔码〕`cw_equipment_data.py:183-185`)。

**何时用**(两者同构,差异只是费用域):
- 配方对上的低费缺件([20] 过渡配方/[31] 目标优先):该卡商店再遇期望太高时,复制是最便宜的定向获取——这正是 [22]③ 弃购账的镜像应用:低费自然回 7-15 轮可等,复制意义不大;3 星线的关键低费(如过渡核心冲 3 星)再遇 q 低则复制赢;
- 高费核心(完美版专用)[21]/[23]:贯穿件已被锁线需求点名但本人未刷出——复制一份进 bench 合「买而不上」的囤位语义,提前吃升星/羁绊线进度;
- **前提三件**:bench 有槽([22]② 唯一稀缺;[32] 腾席优先级约束)、复制目标在需求向量内(门 B)、角色星级未满(满星复制 = 纯销毁)。

**何时不用**:
- bench 满(或腾挪后将挤掉更有价值的囤件);
- 商店常见(q 高)的低费散件——买了还能顺手压库([15]/[30]),复制不压库;
- 目标不在需求向量内(复制一个散件 = 制造死库存,污染回收流水线的准入账)。

## 6. 好运令牌(定向四选一)

**效果**:拖到角色 → 从其四件推荐进阶选一获得,用后消失(〔码〕`cw_equipment_data.py:184`)。

**何时用**:缺件 y ∈ 目标需求 ∧ y ∈ R(c)(该角色推荐表)——此时 **0 轮定向白拿,支配一切其他通道**(P14 定理 4 支配序之首;Q5:等效价 = 合成的全部轮期望 13.3-23.3 轮)。⚠️ R(c) 结构待实测(〔机制篇·待实测边角〕/p14 Q5)——实测前的实现姿态:**不自动拖**,保持「人工/哨兵提醒核对」档,或在采集批拿到 R(c) 表后再启用(保守侧由 门C 不可逆性推出:四选一选错整件报废)。

**何时不用**:y ∉ K(拿来的也是死库存,还封死了日后 target 变化时这张票的价值);R(c) 未建档时宁不用不猜。

## 7. 特权赋予卡(进阶→特权进化器)

**效果**:拖到进阶装备 → 变对应特权装备;拖到角色 → 从其已穿进阶选一变特权;用后消失(〔码〕`cw_equipment_data.py:187`)。

**战略定位**:特权/白昼类 key_equips **没有常规获取通道**(P14 Q4:合成、炉、令牌均不可达),特权卡是把「不可规划项」变「可规划项」的**唯一通道**。

**何时用**:target_comp.key_equips 显式含特权件(如光速螺旋桨·特权类)且对应进阶成品已在手(装备栏拖法,精确控制配对——与装备栏主动合成同理,避免穿着触发被残留件带偏,〔机制篇 §1〕);或角色已穿的目标进阶就地升特(角色拖法)。

**何时不用**:key_equips 无特权目标(留着,道具不衰减);在阵容定型前进化的非目标进阶(〔口述 29〕同源:锁路线前不耗不可再生资源)。

## 6. sim 佐证面:哪些判据可被 sim 验证,哪些只能实机

**边界声明**:cw_sim **不建模装备的战斗效果**(W212 收账结论「终态不动=装备效果未建模边界」,策略池行;装备在 sim 中只是 owned/deployed 的名单流转,`cw_sim.py:2087-2117` 装备层执行代理)。另注:**sim 的装备发放池不含任何工具**——补给采样池 = `_EQUIP_VALUE` 键 ∩ `EQUIPMENT_ROSTER`(`cw_sim.py:2032-2052`;`_EQUIP_VALUE` 十二名全是战力装,`cw_events.py:344-352`),工具永远不会自然出现在 sim 局内。

据此对本设计的判据分级:

| 判据组 | 可验性 | 说明 |
|---|---|---|
| 炉的准入(`recycle_qualified` 口径:需求向量外才烧;None→不动) | **可 sim**(逻辑层) | 判据全部落在纯函数(注册表+K+owned),不依赖装备效果。做法:sim 注入式发放工具(需一处基建改造:发放候选并入手工工具名单)+ 挂决策代理,验**行为分布**(该烧没烧/误烧率/回收流水线触发次数),回归口径 = 单帧锁(`test_cw_tools_*.py` 构造 GameState 断言动作序列,strategy-work §4) |
| 扳手「还需不需要」闸(key 持有者不动/去向登记制) | **可 sim**(部分) | 「谁该持有」可与 equip_allocation 同源推演,sim 可验;「去向落位正确」依赖分配器输出,亦可 sim 断言 |
| 投影仪(费用域/bench 槽/q 再遇比较) | **可 sim**(q 面近似) | q 取 `REFRESH_PROB` 结构,sim 可断言分支选择;注意 sim 补给伪影(策略池行:sim 补给恒 idx0)若未修,涉供给节的对照降权 |
| 令牌 y∈K∩R(c) 支配序 | **可 sim / 数据未到位** | 逻辑可 sim,但 R(c) 表未采集前无法实例化——先锁「R(c) 缺档时禁用」的保守分支 |
| 特权卡唯一通道定位 | **可 sim**(分支存在性)/ 结局不可 | 「key 含特权→持有不泄」可锁;「升特后战力提升多少」依赖装备效果建模,属 W248/W212 明示边界,**永不出现在 sim 结局指标** |
| 一切「拖曳落点/UI 交互/执行后验证」 | **只能实机** | sim 无执行层;工具 op 属 UI 建档依赖件(与装备统裁批「工具 op 需 UI 建档」同一前置,策略池行已记) |
| 随机转化结果的收益(炉刷出了什么) | **只能实机统计** | 转化结果分布属游戏随机性 + 装备效果双层,均不入 sim;P14 数学(36/m)已替代其对决策的作用 |
| R(c)/λ/唯一件语义/电池在池 | **只能实机采集** | 〔机制篇·待实测边角〕与 p14 检验点 3 已列,非本设计重复 |

**sim 红线提示**:装备效果未建模 ⇒ sim 上验证工具件的一切成功判据只能是**行为/账面指标**(是否按判据动、动了之后 owned 名单流向是否符合去向登记),**严禁**用 hp/胜率/出口金的变化评价工具件(sim 中这些指标对装备操作天然无感,会产出假阴性)。

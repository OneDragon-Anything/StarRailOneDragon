# 收尾屏迁移详设(位面过渡/武装箱/未达上限/等待1-1/位面情报采集)

## 问题与约束

- 本篇辖域 = 阶段三:剩余 5 个直继 `SrOperation` 的画面 op 直迁 `CwScreenOpBase`(目标形态判定见总纲 §2.1-2:本篇五屏**均不重挂变体**,理由 = 总纲关键取舍 2——变体节点预算 2 与各屏现役预算不同,重挂 = 行为变更)。
- 总纲划给本篇的接口契约 = design.md §2.1-1 迁移手法五件套、§2.2 契约 1-6。
- **重入裁决归属 = 总纲 §2.2 契约 6 单一定谳**:位面过渡/武装箱/未达上限三屏的裁决留守 `handle` 装配点分流判据之前、两路径共享段,不进 observe 段形态(裁决位序红线随裁决段保真)。
- 五屏共性:单/双节点、无策略消费、无 on_outcome 收编面(全篇 on_outcome = 无登记件,注册表缺席 = 零动作);分派点全部在 `cw_loop` 0 系分支/战斗窗口/接管链(迁移不改分派)。

## 验收(本篇各屏共用,细则见 landing.md 阶段三)

- sim 腿:五屏全部不适用(F11 例外清单逐屏落测试 docstring;位面详情/敌人情报 sim 无对应画面段,架构设计 §3.4 sim 侧申报)。
- L1 快速集全绿;`ruff check` 仅对本篇改动文件。

## 关键取舍

1. **重采集型并入本篇 vs 单独成阶段**:并入。位面情报采集虽体量大,但迁移手法 = 薄转录(体原位共享),风险集中在「不改采集时序」而非「新形态设计」;单独成阶段无独立设计面。
2. **双节点图并入单 lifecycle vs 保留节点图**:保留。`collect`→`close_and_report` 的显式边是首跑教训落码(:624 注:「无显式边时采集 success 被当 op 终点,关闭节点漏跑,画面留在位面详情」);并入单节点 = 复活该事故形态。
3. **五屏不重挂变体**(总纲关键取舍 2 的本篇落地面):直迁后四弹窗/过渡屏与变体形态并存是**既定事实不是分叉复发**——它们继承同一机制基类,骨架差异(预算/重入位序)是各屏实证语义;统一骨架留给旧路径退役批之后再评估(届时行为等价门已有双路径对账数据)。

# 备战访问编排 op 化迭代设计（总纲）

## 0. 元信息
- 迭代目标：用户裁定（2026-09-15/16）——cw_loop 备战分支编排迁入备战访问 op；**发射决策迁入策略层 mandate_v1**（用户裁定：必须到策略里，实现可以从简）；建立出战交回契约；发射执行器合一。
- 状态：定稿（三轮对抗收敛）
- 文档清单：无详设（单文档方案）

## 1. 问题与动机
- 现状症状：cw_loop 备战分支持约 150 行编排——达标臂四段（判定消费/浮层闸/发射帧仲裁/发射调用）+ 交回处理。其中达标判定消费与仲裁决策属策略语义（「成型了要不要立即开打」「开打前钱多先花掉」），住框架层，与 op-layer.md §2.6「判据在策略器」相悖；**两套点出战执行并存**（cw_loop `readiness_battle_launch` vs prep_actions `_start_battle`/StartBattleOp，C1 单一化未竟）；出战交回外循环无契约（战斗窗置位靠分支内副作用）。
- 根因归层：流程层历史宿主。达标臂落码时（W971 时代）备战环还是外循环内的动作链，发射位只能落 loop；内环拆解后宿主未跟进。发射决策的治理缺位同理——策略侧动作词汇已有 StartBattle 终点（entry.py），达标臂的发射决策却独立实现在 loop。
- 解决到哪：发射决策进 mandate_v1（简单实现，见 §2 方案 3）；备战编排与达标臂执行进备战访问 op；交回契约建立；发射执行器合一。
- 明确不解决：
  - mandate_v1 深度重构（发射决策与三遍化编排的结构性整合）——**简单实现许可**（用户裁定：策略默认实现后续重做，届时精化）；
  - `cw_launch_admission` 迁层（kernel → mandate_v1）与 L256 宿主分层裁决的重审——判定核本迭代留 kernel（策略决策消费 kernel 读口），迁层挂策略重做批；
  - 恢复局面策略化——锁定局不走策略的直通形态保持；
  - cw_loop 备战分支最终收敛评估（本迭代后剩余 = 派发/交回/恢复局面/失败环，候策略重做后复盘）。

## 2. 方案
- 系统级变化：
  1. **交回契约**：CwScreenPrep 结果携带「出战已发射」事实（实现 = op 实例 `launch_fired: bool`，act 段发射成功即置位；loop 在 `execute()` 返回后读取）。战斗窗置位（`_battle_ts`/`_battle_wait_active`）仍归外循环——start-battle.md §3-1「战斗窗口置位归外循环」不变，改的只是事实传递通道（分支内副作用 → 结果事实）。**两处钉死**：①`launch_fired` 优先于 round outcome——发射已落地则战斗必在打，outcome=fail 不覆盖置位（帧锚兜底语义照旧申报）；②置位点 = 统一执行器返回成功时由 op act 段落——属 op 层状态，非动作返回值，与 op-layer §2.5 动作端口契约（动作无返回）不冲突。
  2. **发射执行器合一**：审计 `readiness_battle_launch`（屏态复验/失败计数复位）与 `_start_battle`（重发长按/连败停机）+ StartBattleOp 逐项差异 → 合一为单一出战执行器，落 `prep_actions.py`；`readiness_battle_launch` 退役；恢复局面从 cw_loop 调统一执行器（C1「单一底层发射函数」完成形态）。**执行器内部序与分轨（钉死）**：屏态复验（双锚）→ 浮层安全检查（原达标臂浮层闸整建制内嵌：锚表扫描 + 遭遇 OCR 兜底，捕获面与判据原样——两调用面同保，恢复局面同样受防误触保护）→ **部署原子序（RunDeploy 组合）**→ 出战点击链 → 失败语义按调用面分轨——分轨原则钉死，**具体失败语义以 3.1 审计实测现存实码为准**（start-battle.md §1 正本有漂移，禁据漂移文本立规格），两套计数**不静默统一**（语义异源，合并 = 行为变化未授权）。**宿主宪章张力申报**：prep_actions 宪章「不含玩法判断」——内嵌项均为画面态安全检查（浮层/复验 = 画面知识）与动作编排（RunDeploy 组合），非玩法判断，合宪；审计清单复核此界。依据：14_p1 C1（「RunDeploy 组合 + StartBattle 的执行核」原文含部署半边；禁各写一套发射位）、start-battle.md §3。
  3. **发射决策入策略层（简单实现）**：mandate 决策入口三遍编排函数（entry.py）**入口最前**新增前置发射位（任何 pass 之前——旧达标臂「短路动作链」位次的直译；armed 帧连 boxes/spheres 实体面一并短路，与旧位次一致。前置位依赖序：op 五段 observe/入口清场先于 decide，armed 帧编排前置为既有五段时序）：
     - 消费 kernel 判定核 `readiness_launch_decision`（kernel 不动，策略经读口消费——判定核迁层挂策略重做批）；
     - 帧级金判定**直调 kernel `in_launch_spend_zone`**（帧级「金>息线」单一源现址，cw_economy.py；禁内联比较，新增消费点按金出口族 DESIGN §5 对账表登记。`launch_arbitration_gate` 为逐动作闸非帧级判定，不作本判定源）；
     - 命中 → 产出**受限商店访问意图**（形态 = OpenShop 意图扩展受限字段，先例 = OpenShop 既有 read_only 字段；**词表契约变更按 op-layer §2.5 两适配器同批**，登记同步禁子类漏册）。**每武装段至多一次**：段 = armed 连续期（StrategySession 段旗承载，先例 = cw4_reopen_armed_phase），失武装复位——复位后若再武装且仍命中，**允许新段再访**（合法形态例：访问内升级抬息帽 → 息线抬升 → 失武装 → 段复位 → 金仍超线 → 新段再访）；段内已访问则次帧无条件产 StartBattle（与旧形态「访问后照发、无金复条件」跨帧等价——闸拦一切可购的金不回落形态由「次帧无条件发射」消解，无死循环）；**访问意图不经 S1 开店闩与 OpenShop 节流**（旧仲裁直调 open_shop 不过闩，同形态；空转防护由段旗承载）；
     - 未命中 → 产出 **StartBattle 终点意图**（词表现成，entry.py 终点动作）；
     - 非 armed → 原三遍编排零变化。
     依据：strategy-work.md §1（策略 = 决策函数族，读 GameState 输出动作列表——发射决策即决策函数）；14_p1 §9.6（发射位规格与位次）；op-layer.md §2.4（decide = 策略消费 → 意图）；kernel `in_launch_spend_zone`（帧级判定单一源现址）。
  4. **备战访问 op 接管执行面**：受限商店访问执行 = op 既有受限访问机器按意图预算闸执行，**保留 `[cw-op]` 第三载体行 op='发射帧仲裁商店访问'**（op 内受限访问出口落行，口径不变——防 ADR-0584 误归病灶复发）。浮层闸**不退役**：整建制内嵌统一执行器（见方案 2），原判据与捕获面（锚表扫描 + 遭遇 OCR 兜底——清场注册表不收交互类浮层、遭遇面板无关闭钮，二者只有旧闸能防）原样保留。
  5. **cw_loop 备战分支收敛**：达标臂块删除后，备战分支剩余 = 双锚守卫 → 恢复局面分支（调统一执行器）→ 派发 CwScreenPrep → 读交回事实置战斗窗 → 失败 streak 环 → 环让位契约（分支序按实码：恢复局面分支先于派发）。`_prep_anchors_hit` 发射帧仲裁预检随仲裁意图化退役（其双锚单一源职能由 op 入口双锚守卫承接）。
- 行为变化申报：
  - 发射决策宿主：cw_loop 分支 → mandate_v1 前置发射位（判定核与判据值零变化，宿主更换）；
  - 仲裁形态：单帧复合（仲裁+发射同轮，切屏后弃射）→ 跨帧意图序（访问帧 + 次帧发射帧）——对外行为等价（受限访问恰一次、发射恰一次），内部时序变化；
  - 浮层闸：整建制内嵌统一执行器（锚表 + 遭遇 OCR 兜底捕获面原样；弹窗帧不发射——误触防护保留，非退役）；
  - 发射执行器合一后的日志标签审计随 3.1 交付（哨兵词汇表对照为落地判据）；
  - mandate_v1 非 armed 帧编排零变化；
  - **遥测分键申报（逐键宿主映射随 3.1 审计清单交付）**：`launch_arbitrage_*` 8 键——策略判定宿主键随前置发射位迁写，执行器/操作工宿主键（复验/发射面）写点留统一执行器；`KEY_PRECHECK_SKIP`/`KEY_ABANDONED_LAUNCH` 两键随预检退役与达标臂拆除**退役申报**（形态消亡，非静默丢键）；`[cw-op]` 第三载体行 op='发射帧仲裁商店访问' 保留（出口改 op 内受限访问处）。
- 接口契约（唯一必须定死的深度内容）：
  - 交回事实：`CwScreenPrep.launch_fired: bool`（统一执行器返回成功置位，优先于 round outcome；loop 消费）；
  - 仲裁意图 = OpenShop 意图扩展受限字段（字段名与类型落码时钉，先例 read_only；sim 适配器映射同批，申报 sim 可见性）；
  - 统一执行器：单一函数，输入 = （op 上下文, 调用面标记），内部序 = 屏态复验 → 浮层安全检查 → 部署原子序 → 出战点击链，失败语义按调用面分轨（以 3.1 审计实码为准）；调用面（op 面、loop 恢复局面面）禁各自包装；
  - 仲裁意图：OpenShop 意图携带受限标记（预算闸 = 息线，值源 = kernel 派生），执行机器按闸收口。
- 关键取舍：
  - 备选「发射决策留 op（宿主更换即止）」：放弃——用户裁定发射决策必须进策略层（策略内容不住框架）。
  - 备选「发射决策同步深度整合进三遍化」：放弃——策略默认实现将重做，深度整合的投入会随重做报废；直线前置位是最小正确形态（用户裁定：实现可以从简）。
  - 备选「仲裁保持 loop 侧单帧复合形态」：放弃——复合形态正是策略决策住框架的成因；跨帧意图序对外行为等价（受限访问恰一次、发射恰一次、总耗时同量级）。
  - 备选「浮层闸退役、由清场+零判效承载」：放弃——清场注册表白名单自身声明不收交互类浮层（cw_screen_prep.py 清场集）、遭遇面板无关闭钮清不了场、弹窗上的点击是误触非未落地（start-battle §3-3 零判效不覆盖误触）；闸整建制内嵌执行器才是等价保真。
  - 备选「`cw_launch_admission` 同批迁 mandate_v1」：放弃——它有 kernel 内（cw_deploy_logic）与 op（cw_screen_deploy）消费面，牵动 L256 宿主分层裁决；判定核留 kernel 期间本迭代无 L256 冲突（策略消费 kernel 读口方向合法），迁层挂策略重做批一并处理。

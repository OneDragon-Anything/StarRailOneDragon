# ADR-0568: 祈愿试炼圣杯采集钩子退役——删 B1 钉屏停机/B2 被动采集,恢复自动选卡实跑

- 状态:已实施
- 关联:ADR-0529(投资策略入口复探窗——祈愿 op 无复探为同型挂账 D3)、`sr-od-currency-war-dev` skill data-collection 节(钩子纪律单一源)、方案全文与对抗审查报告 `.debug/temp/currency_war/wish_trial_branch/`(本地,2026-09-07,不入 git)

## 1. 背景与问题

2026-09-01 起为圣杯任务采集批接入两枚临时钩子:

- **B1 `grail_pin_stop_hook`(钉屏停机)**:祈愿试炼 overlay 出现即存截图 + flag 并停机保画面,拦在 0h 分支派发之前——等 AI 现场建档;
- **B2 `grail_passive_collect`(被动采集)**:随备战观察帧整帧哈希去重落盘,零决策影响。

钩子期的实际后果:圣杯线对局走到祈愿试炼就停机(2026-09-07 实停一次),圣杯线零推进;B2 采到的帧从未分拣,积累成无消费数据(§4)。而画面「货币战争-祈愿试炼」建档已完成(3 areas),分支本体 2026-08-08 起实跑闭环(D-87~89),钩子自声明的删除条件(采集清单建档确认后删整段,不留开关)已满足——钩子从「采集工具」变成了「唯一拦路点」。

## 2. 决策

删钩子恢复既有分支直连,零新增逻辑:

- `cw_loop.py` 0h 分支删 B1 接线段(8 行:注释 2 + 局部 import 3 + 调用判 None 3)→ 恢复「决策帧留证 → `CwScreenWishTrial(self.ctx).execute()` → 成功清 bail → round_wait(2)」;
- `cw_screen_prep.py` 备战观察帧删 B2 接线段(7 行);
- `grail_collect_hooks.py`(113 行)与 `test_cw_grail_collect_hooks.py`(133 行)整文件删除;
- flag 产物 `.debug/temp/currency_war/grail_pin.flag` 删除;
- `flow/outer_loop.md` 0h 行去「停机钩子」字样,直连 CwScreenWishTrial。

**行为变更声明**:删钩子后,祈愿试炼 overlay 出现 → bot 按 `decide_wish_trial` 词表(金币/阵营/刷新购买打分,失败兜底第 1 张)自动选卡并确认推进,不再停机。这是**恢复 r104-r116 时代已实跑的行为**;钩子期(2026-09-01 起)才是异常态。

## 3. 接受风险(本决策最重的一条)

**自动选卡可能选中惩罚型/毁灭型任务(过期攻略存档所载样本:「令咒协议」-88 小队生命+清空金币、「诅咒圣杯」清除此前全部任务链),最坏后果 = 输掉该局。**显式接受,理由三条:

1. **停机代价更大**:B1 不删 = 圣杯线零对局推进,智能选择升级永远等不到真实采样;
2. **智能选择需要真实选择数据**:钩子期 handler 从未跑过,`record_event_choice('wish_trial')`(选项全文 + pick_idx)零产出;删钩子后它首次真正落数,正是 objective 全集(S3)的主采集通道;
3. **惩罚型存在性未采样,禁写规避词表**:样本全部来自已被部分推翻的过期攻略存档(V3.7/V4.4),识别特征与真实代价无实机帧——现在写规避逻辑 = 凭过期资料拍值,违反「机制不明处禁拍脑袋」。

暴露有界:每局圣杯试炼 ≤4 次接取,崩盘面限于单局;选错不挂死流程(overlay 必关、对局必继续,点卡未选中还有 retry×8 自愈)。

## 4. 采集面处置(方案审 P2-1 折入)

- **B2 积压**:`.debug/temp/currency_war/shots/` 下 `grail_obs__*.png` 576 帧 + B1 补帧 `grail_pin_frame2__*` 1 帧,共 577 帧 / 约 902MB(2026-09-02 21:45 → 09-07 03:20),**保留未分拣,不删任何帧**——绝大部分为普通备战帧(金币/回合/席位微变),圣杯瞬时帧(完成提示/奖励发放/契约计数器)可能混在其中。处置候智能选择批:该批升级需实机采样,开工时先对本语料做离线视觉分拣,再补新采样。
- `.debug/images/cw_grail_pin_*.png`(B1 停机主帧 + 补帧)同保留。
- B1 实际只完成 S0(停机主帧)一项;S1-S7 采样清单未完成即收尾,**透明转挂账**(§5),非静默绕过。
- B2 提前退役的理由:被动采集本零停机零决策影响、保留成本近零,但「只存图无人读」已实证产出 902MB 无消费数据——删生产者、处置存量,方向正确;继续采集只增无主数据。

## 5. 挂账(智能选择相关,自方案 D1-D5 + S1-S7 摘取)

| # | 项 | 内容 | 前置 |
|---|---|---|---|
| S3 | objective 类型全集 | 操作型/条件型/惩罚型/等级门槛型的措辞模式;词表升级必须建在全集上 | 删钩子后 wish_trial 遥测自然采集 + shots 积压分拣 |
| S2 | 难度色标形态 | 红难/蓝易在卡上的位置与呈现;惩罚规避策略的前提输入 | 下次自然触发时留证(与 S1 同帧可采) |
| S4 | 卡底横条语义 | 「宝石女王」类横条是奖励名/任务名/事件名未确认,影响选卡信息面 | 采样帧 + 悬停行为验证 |
| S5 | 卡位坐标稳定性 | 候选卡 objective 中心与硬编码桶 660/960/1260 的容差曾薄至 2px;超差退化 fallback 首项(不崩但选卡失效);多档位布局未知 | 多档位对局各采 1 帧 |

## 6. Considered Options

- **A(否决)保留 B1 钩子直到 S1-S7 采齐**:S1-S7 多数需要自然触发多次或人工交互验证,停机采集成本不可控;圣杯线零推进期间,智能选择与策略迭代同步停滞——采集工具反成路线阻塞。
- **B(否决)只删 B1、保留 B2**:B2 唯一产出是无消费的帧堆积,「先存后分拣」的离线语料已够智能选择批起步;删生产者、处置存量比继续堆积正确。
- **C(采纳)删双钩子 + 挂账**:恢复已实跑闭环的分支行为,采样通道从「停机钉屏」换成「遥测全量自动落数 + 存量语料分拣」。

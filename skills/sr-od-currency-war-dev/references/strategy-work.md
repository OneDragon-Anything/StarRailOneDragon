## 1. 策略是什么

CW 的策略 = **决策函数族**(买/上/装备/经济/刷新,`decide_*` 系列):每回合读 GameState(板面/金/血/轮次),输出要执行的动作列表。策略不是「配置参数」而是**行为代码**——改策略=改行为语义,要走文档三同步。

评判标准只有一条:**长期期望胜出**(多局分布)——sim 批量看分布变化,实机多局验收,单局胜负不构成证据。

由此得出唯一的骨架:**期望值是统一标尺,尽量所有决策都要数学支持**。花钱决策的期望账(买/不买/刷新还是升级/压库,息律也在其中)= compo-knowledge「经济期望方法论·三笔账」;其余决策(方向/上阵/装备/停手/换线…)有证明的以 math_proofs 为准;还没有数学的,直觉只能当假设来源立命题去证,不许长期停在拍脑袋——新阈值/分支的推导出处写进设计(§2 设计先行)。阵容结构等玩法约束在 §2 改前必读的文档里,不在此复述。

**终极目标:零调参策略**(与「数学支持」同级的骨架原则)。策略代码里出现的每一个数字,来源只许两类:

1. **规则或推导**:注册表里的游戏规则数据(息律、价格、退金),或从规则数据经数学推导得出的量(如超几何命中率)——查出来、算出来,不是人定出来的;
2. **显式模型的估计**:确实无法推导的量(如战斗产出类)必须建显式模型、从数据估计,并满足两条——估计带置信区间;消费它的决策在该区间全域方向不变(区间内会翻转 = 数据不足,先补数据,禁用该判据)。

**禁止**:拟合常数直接充当决策闸门(一个拍定的数决定做/不做)——这类常数都是「没建的模型的替身」,既无推导依据,又会随数据漂移,还掩盖模型缺口。存在支配性论证(「无论该量取何值,A 都优于 B」)时必须用论证消掉参数,不许保留数字。**新增任何数字前先答:它属于上面哪一类?答不出 = 不许落码。**

**未证即退役(处置通则;用户裁定 2026-09-04)**:已在决策位上的存量数值,过同一道门——①可证 → 立命题进 math_proofs(数值落码等证明完);②游戏定义量误标 → 改【注】补出处;③经验拟合/拍定 → **退役**(注册表墓碑注+消费端改保守缺省),不是「挂账待标定」无限期保留。处置流程 = 全量清点表(项/现状/证据/建议处置)→ 逐项执行;「证明或退役」二选一,无第三态。

## 2. 改策略前(不可跳)

1. **判读上局**:按 telemetry-reading「判读流程」找不合理处,结论写进进度账本再动代码(单局数据≠结论)。
2. **读全部策略相关玩法文档**:基线清单与阅读顺序的单一源 = `docs/game/currency_war/research/README.md`「策略相关文档」节(全目录,唯一排除 screen_flow_timing)。不读全就无法预判改动波及面,「只读一篇=读局部」。
3. **改动先定位,再动手**:答两问——①这次改动牵涉哪条既有原则?②它落在 strategy 设计(`docs/develop/currency_war/strategy/`)的哪一层?两问都答不出 = 改动在既有设计里没有位置:先停下问「为什么设计里没有它」,再决定改设计还是落码,不许直接写。修复时重构优先于打补丁。
4. **设计先行,写清再动代码**:落点函数/影响消费点(含测试锁)/预期行为变化/验证法——「现象→定位函数→改」缺设计层是常犯病;新阈值/分支的推导出处写在这里(§1 骨架)。**设计稿本身也要过 §6 对抗循环再落码**(推导报告≠设计入册,入册+对抗零发现+符合策略核心后才碰代码)。~~玩家过目方向~~(2026-09-05 用户裁定改门:玩家过目删除,改为编排者自行发起无前提对抗子 agent 审查,符合策略核心即可落码)。
5. **直觉假设 → 推导批,禁照抄直觉落码**(用户裁定 2026-09-04):玩家口述的直觉方向(如「等级锚定找缺件」)= **待检验假设**,不是规格——正确路径 = 通读全部玩法文档+游戏数据注册表,推导最合适的数学形式;直觉中对的部分保留、漏的机制补上、错的纠正,三差清单随设计稿呈报(先例:刷新决策形式二的升级费阈值/路径总账/息线三修正)。
6. **口述被数学证伪 = 当场修+挂确认**(2026-08-31 用户裁定,细则承载=AGENTS.local 同名纪律行):证明证伪口述时立即按修正口径改,但必须同场留「待玩家确认」记录,玩家确认后回写结论归属。

## 3. 改动的落地:默认无开关(开关是例外;2026-08-31 用户裁定,取代旧「一律走开关」)

**行为改动默认直接落码、不留开关**。旧「一律默认关开关」模式的实际代价:开关堆积成债、A/B 判正后裁决顺延形成悬置、每个开关多一轮注入重推+生命周期管理。新分野按「证据从哪来」分三档:

1. **数学可证 → 直接落码,无开关**:先按 §2 数学先行立命题并证明(P36-a 为范本:证明后 A/B 仅是确认不是发现),落码即无条件生效;A/B 可作为落地后的确认性回填,不构成保留开关的理由。回滚靠 git revert(单操作者按局重启,等价速度)。
2. **经验性(数学证不了)→ 按「未证即退役」处置,A/B 无裁决权**(用户裁定 2026-09-04):数值的合法性来源只有两个——**证明**,或**退役**(§1 处置通则);sim A/B **不构成数值的合法性来源**(「A/B 无裁决权」),其合法角色 = 落地后的**确认性对拍与实现验证**(发现实现 bug/量级意外可以,据此定数值不行)。经验性判据的处理:先走支配性论证(§1)消参数;消不掉且不可证的,按退役处置换保守缺省;确需保留的经验量必须建显式模型+区间+fail-closed(§1 第 2 类)。「A/B 判正 → 落码」的旧流程作废。
3. **开关仅剩的合法形态**:行为输入真未就绪(外部数据/采集在途),且必须带裁决期限(超过一个对局周期未决=违规);「A/B 已判决却默认关挂起」在任何档都禁。

存量开关清理义务不变:定期盘点,已判正的翻正后进「除开关」清理批(硬编码settled态),判负的删码。

## 4. 验证(策略验证的纪律与阶梯)

测试分层命令(L1 快速集/L2 点名/L3 全量,~3/5min)= SKILL.md 单一源地图「测试分层」行。sim 工具怎么用 → [sim-testing.md](sim-testing.md);实机局怎么判读 → [telemetry-reading.md](telemetry-reading.md)。策略验证阶梯与纪律:

- **改进方向对准过程量,末端量只作验收与报警**:过程量(完成度/成型/经济纪律)是因果上游;hp/胜率/出口金用于验收与报警,拿它当改进方向=目标函数错。验收口径本身=当期目标行判据(A/B 尺子,telemetry-reading 步骤 0)。达标线跑之前写死(载体=proofs 单篇/ADR 判据节,先 commit 后跑批;禁独立 prereg 文件);修复批另守 prereg 完整性硬门——必含既有验收线保全清单(§6)。
- **改前基线→改后对照(A/B)**:A/B 回答一个问题——这个改动让指标变好了吗。改前跑一次 sim 批记下基线 → 改后同参数(`uv run python -m sr_od.application.currency_war.cw_sim batch --n N --pool snapshot`;两侧同池指纹,跨日必核一致)再跑一次 → 对比:**与预期方向一致=确认通过;不一致=查清为什么**(实现 bug/机制理解错/声明该维度 sim 不可信,三选一;查不清=别上实机);**没变化=改动未生效或无效**。A/B 结果不构成采纳裁决(§3:数值合法性来源=证明或退役),采纳判据在此之外。没跑基线的「改后达标」不构成证据。指标=sim 统计脚本的输出(sim-testing 一、第 1 步)+**达标占比**——线来自当期目标判据,跑之前写死(载体=proofs 单篇/ADR 判据节,先 commit 后跑批;禁独立 prereg 文件),防止看完数据挪线。仍然差的指标 → 回 sim-testing「找问题」三步下钻。新机制先验证它会开火(触发条件 0 次=输入死的,先补观测再测)。
- **改动影响面**:改动后必跑 `cw_replay --diff`(秒级)看行为漂移首发点——分歧=漂移≠好坏;digest/轨迹级两侧钉 `PYTHONHASHSEED=0`。
- **A/B 报告必带 sim 可观测性声明**(sim 决策下沉选型批,方案三混合裁决):报告须声明一行「本批改了什么层、sim 看不看得见」——判据/策略层改动 sim 可见(可 A/B);operations/app 执行层改动 sim 结构性不可见(不可作 A/B 判据,只可实机验证);单面批(planes=1/2 单位面)须声明批辖域位面,口径沿用 cw_batch_stats 批头位面披露(planes/plane_list)。缺声明的 A/B 报告 = 假阴性高危(发射短路等行为消费缺位时 pre/post 逐位一致会被误读为「无影响」)。申报口径细则:「结构性无帧」观测盲区(如发射短路帧 m1p 恒 None——生产无该决策帧,如实无帧)随本声明一并申报,禁把盲区读数当零值证据。
- **参数精调用敏感度**:同策略扫参数,弹性大=值得实机精调;平坦=不花实机局数调它。
- **判读锚点事前写**:实机局开跑前写清「预测什么会变」,跑完核对——事后找解释不是验证。锚点没中 = 改动没生效或假设错,两者都要查。
- **实机验收=连续多局达标**(以当期目标为准),单局胜负不构成证据(§1)。险胜不算过——贴线通过是策略缺陷症状,与明显失败同权重分析;局后判读是必做项,异常条目当场定位,定位不了不进下一局。
- **实机/sim 分工**(用户裁定 2026-09-05):实机验**流程**(守卫/循环/对账/终结流转/识别),sim 验**算法**(判据质量/分布);sim 三步漏斗(统计撒网→分诊排局→深读归因)细则 = sim-testing「找问题」;统计的角色=分诊定位,无裁决权。
- **阶梯终点=结论兑换(按 §3 证据档,禁第三态)**:数学可证→落码生效(A/B 仅作落地后确认);经验不可证→按 §1 处置(退役换保守缺省,或显式模型+区间+fail-closed)——**「调常量(量级待定)」挂账形态已废**(未证即退役=无第三态,2026-09-04 用户裁定)。A/B 对照手段(registry 注入/临时开关)不进生产代码;「默认关的悬置开关」=已判决未执行的悬案,禁(见 §3 开关生命周期)。

## 5. 行为的锁定:单帧锁(验证过的行为变成回归资产)

验证确认的行为,固化成单帧锁才算回归资产——「模拟是发现工具,单帧锁是回归工具」:

- 位置与模式:`sr-od-test/test/sr_od/app/currency_war/test_cw_<主题>.py`;构造 `GameState`(plane/round/gold/level/board/bench/shop/xp_progress)+ `StrategySession` → 调被测方法 → 断言动作序列。锁的来源不问(sim 随机发现/实机判读/验证确认),锁的都是策略决策行为。
- **断言写语义不写巧合**:「配方 gap 时围栏内只买配方件」而非「买了卡 X」(换发牌就碎)——锁的是策略意图,不是当时的牌面。
- 维护:测试仓 gitignored 独立维护,提交在测试仓;语义演进时旧断言随改,docstring 记一句为什么旧语义过期。

**锁的存在性纪律**(通用条款单一源 = `sr-od-test/README.md` 测试纪律第 8 条;CW 因锁密度高——300+ 文件、registry 哈希锁 30 天被动更新 60+ 次——而两条倒退路径都实测走过:好改动被旧语义的锁否决而回退,坏改动借机械跟绿的锁更新洗白。故写锁/改锁额外守):

- **新锁必须引设计出处**:docstring 写明出处(设计章/ADR),无出处=先补出处再落锁——引不出出处的锁,大概率锁的是偶然实现而非设计意图;
- **改锁=重推语义,不是机械跟绿**:锁红了先问「被锁语义还是当前设计意图吗」(引 ADR 对账),语义已被取代的锁走改写/删除,直接改值保绿=洗白通道;
- **「老」不构成删锁理由**:判删必须引设计文档证被锁行为已非设计意图。

## 6. 对抗循环(收口硬门;用户裁定 2026-09-04「每次改后都要发起无前提子agent对抗,直到没有问题」)

策略/判据/装配/文档的**每批修改,提交前必须过无前提对抗审查,零发现才收口**:

- **对象三档**:设计稿(入册前后)、实现(代码+测试)、体系全目录(跨篇一致性;周期性或大改后)。
- **无前提 = 干净上下文子 agent + 无预设焦点**:审查 agent 只给「对象文件面+判据源清单+攻击纪律」,不给结论、不给方向、不给上一轮发现——预设焦点会把审查带沟里。
- **判据源**(任务书里开清单让 agent 自取):strategy-docs 宪法(00/01)、math_proofs 索引与单篇、注册表(数值直调)、玩法 research、流水裁定(.debug/progress 迭代目录)、AGENTS.md 注释规范。
- **攻击纪律**:数值/口径/引文/码点一律**直调复核禁转述**(值对标签错是五犯实证错误类);「篇内/代码自洽」与「对得上游戏/宪法/裁定」分开验;as-built 断言读代码体,docstring 仅线索,测试直调不算生产调用;结论=发现清单(编号/严重度/文件:行号/修正方向)或「零发现+实际攻击过的面清单」,禁和稀泥。
- **循环**:发现→修→再攻(新干净上下文),直至零发现;修复方不得只改被点名处不看同类(泛化步是义务)。
- **prereg 完整性硬门(用户裁定 2026-09-08)**:凡修复批,其 prereg(A/B 线与判据载体)必须**逐条列出受本批影响的在册验收线**(出口金/[13]/通关门/存活等)并证明修复保住各线;保不住 = 设计缺陷非胜利,回设计层。新批 prereg 缺该清单 = 对抗审查直接打回,不进实现。盘点入口 = 当期迭代 criteria 行 + ADR 判据节既有线 + batch_stats/早停脚本读数行,不必新造登记簿(防第二源);载体纪律同 §4(先 commit 后跑批,禁独立 prereg 文件)。
- **轨迹现实**:收敛不是一两轮的事(实测十轮 55 项/四轮/两轮都出现过),修不动时回到设计层而不是软化标准。

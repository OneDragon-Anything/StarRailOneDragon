# BOSS 头像模板库落位与接入设计（boss-avatar-library-integration）

> 状态：设计定稿（本批只设计不实现，实现归后续批）。
> 范围：货币战争（Currency War）boss 头像识别模板库的新库落位、与现役旧库的接入语义、加载器改动面、迁移回退、验证设计、以及 `cw_` 前缀整改的边界划分。
> 约束（用户裁定，不可违背）：① 现役旧库 `assets/template/currency_war/boss_avatar/`（21 张平铺 PNG）沿用不改，识别现役不因本设计被破坏；② 新库落位 `assets/template/cw_boss_avatar/`（用户指定路径），内容 = 统一模板批 21 公司模板（下文 §1.2）；③ 先设计后实现。

## 1. 背景与现状

### 1.1 现役识别链（改动面事实基础）

boss 头像识别链全貌（识别目标：对局中认出「本位面 boss 是哪家公司」，公司名即 `cw_enemy_data.BOSS_MECHANICS` 规范名）：

| 环节 | 位置 | 语义 |
|---|---|---|
| 模板加载 | `cw_node_reader.py::load_boss_templates` | 自定义加载器：`glob('*.png')` 平铺扫描 → 灰度 → SIFT 特征预提取 → `{公司名: (keypoints, descriptors)}`，特征 <4 关键点丢弃 |
| 消费点 A（懒加载全局） | `cw_observation.py` 两处（`_classify_node_row` 与 `read_plane_detail_nodes` 内，各自懒加载模块级全局 `_BOSS_TEMPLATES`） | 路径硬编码 `assets/template/currency_war/boss_avatar` |
| 消费点 B（节点条域） | `cw_node_reader.py::classify_node_row` boss 槽分支 | 备战节点条最右槽（首领=位面最后节点，位置先验）裁 ~56px patch 做 SIFT |
| 消费点 C（大图标域，主消费） | `cw_screen_plane_intel.py::_read_boss_big_icon` | 位面详情屏详情条「区域-boss大图标」~107px 裁片 SIFT，直接复用 `_cwo._BOSS_TEMPLATES`；前置「首领」标签验证 |
| 命中判据 | `cw_node_reader.py::match_boss_sift` | **断层门**：好匹配数第一名 ≥ `BOSS_SIFT_MIN_GOOD`(3) 且 ≥ `BOSS_SIFT_RATIO`(2.0)×第二名（含 tie 拦截语义）。**承重墙，本设计零改动** |
| 测试面 | `sr-od-test/test/sr_od/application/currency_war/obs/test_cw_node_reader.py` | 4 帧归档 fixture（正样本：深渊育种科技/不死者联盟；负样本：棋盘格图标位、库外纹章变体），加载路径硬编码旧库目录 |

### 1.2 统一模板批（新库内容，已验证）

新库内容 = 「统一模板批」：21 家公司各一张 128×128 模板，官方美术原图统一重制，透明底按 alpha 合成实机大图标域底色 RGB(34,30,61)，文件名 = 官方中文公司名（与现役命名惯例一致）。验证结论（实验批报告，私有侧归档不入 git；实测跑批器与生产 `load_boss_templates`/`match_boss_sift` 判定口径逐位同构）：

- **正样本 22/22 命中**，断层余量 4.7×~10×（实验只覆盖 2/21 公司的实机正帧；其余 19 家 = 同美术同源逐家目检 + 负样本族零误报背书）；
- **负样本 38/38 拒判**（补给图标 ×31、战斗图标 ×5、纹章变体 ×1、节点条域对照 ×2），零误报；其中补给族出现过第一名 10:10 平分，靠断层门的 tie 拦截语义拦下——门常量是负样本防线的承重机制；
- 另两个候选方案被负样本否决禁用：**方案 B**（缩放到裁片尺度 94px）在补给/战斗图标上 26 帧误报——同尺度的圆形模板与域内任意圆形图标发生环对环系统性碰撞；**方案 C**（合成非实机域底色）战斗图标 2 帧误报。两条教训固化为红线：禁止把模板缩放到裁片尺度；禁止用非实机域底色。
- 附带复现了旧库历史故障（「混尺度病」，定义见 §4）：60px 不死者模板在实机大图标域被大尺度别家模板抢走次名余量，7 < 2×4 拒判；同一帧换统一模板批后 28 vs 6，余量健康。

### 1.3 现役旧库的已知缺陷（为什么要有新库）

旧库 21 张文件是**三种来源混装**：19 张 60px 图鉴小图 + 2 张实机大裁片（深渊育种科技 111×110、不死者联盟 94×96，历史故障后的补采）。由此：

- 19 家图鉴公司的实机大图标域得分从未被统一验证，负样本族上的余量很薄（补给帧 4:3、战斗帧 6:5，靠断层门勉强拒判）；
- 混尺度竞争：尺度接近实机域的模板分数系统性偏高，别家大裁片会把小图公司的次名余量吃掉（§1.2 的历史故障即此机理）；
- 节点条 boss 域（~40px 锁态小图）两库都过不了门（小图 SIFT 特征坍缩），生产行为 = 保守拒判 `NodeSlot.boss=None`，与库无关，本设计不改变该预期。

## 2. 问题一：落位形态 —— 结论：平铺 `<公司名>.png`

**推荐案：`assets/template/cw_boss_avatar/<公司名>.png` 平铺 21 张，原样复制统一模板批文件（字节级一致），不做目录制、不转 webp。**

理由（对照项目模板规范与框架语义）：

1. **消费方唯一且已适配平铺**：boss 库的唯一消费方是 SIFT 链自定义加载器（`glob('*.png')` + 文件名 stem 即公司名）。平铺形态与该加载器零改动兼容——新库加载器只需要换目录路径。
2. **字节一致性即验证继承**：全部验证数据（§1.2）是按这 21 个文件的字节跑出来的。目录制（条目目录 + `raw.webp`）需要重编码转换，任何重编码都是未验证变量（灰度化结果可能逐位漂移，验证结论作废）。落位必须是纯复制。
3. **目录制会被框架看见，而框架不需要看见**：框架模板体系（`one_dragon/base/screen/template_loader.py`）按两级扫描工作——`assets/template/<一级类目>/<二级条目>/`，条目目录内存在 `raw.webp`/`raw.png`/`mask.png`/`config.yml` 任一即被 `get_all_template_info_from_disk` 收录为可编辑模板。若新库采用条目目录制，21 家公司会以 `cw_boss_avatar:<公司名>` 出现在开发工具（模板编辑器等）里——但 boss 库不进 screen_info、不走框架匹配栈，框架可见性 = 纯增的误改面与列表噪音，零收益。
4. **平铺 PNG 对框架完全不可见**：两级扫描对二级条目做 `isdir` 过滤，平铺文件直接跳过——根级新类目 `cw_boss_avatar` 对框架工具是空气，无任何副作用。这是「框架工具能否看见」问题的答案：看不见，也不需要看见。
5. **形态对照不构成改判依据**：单发模板（screen_info 消费）用条目目录制 `raw.webp`，是因为框架匹配栈需要 mask/config；`character_avatar` 立绘库用条目目录制（88 角色目录、raw+mask+src 三件套），是因为立绘裁切语义需要 mask。boss 库无 mask 需求（SIFT 全图特征），且自定义识别链已有先例（`character_avatar` 同为框架外自定义读链），平铺 PNG 不违反规范。

## 3. 问题二：接入语义（核心）—— 结论：案①新库主匹配 + 旧库兜底（匹配域隔离）

**术语**：「匹配域」= 一次 `match_boss_sift` 调用里参与排序的一组模板。「混尺度病」= 同一匹配域内混入多种渲染来源/尺度的模板后，尺度接近识别域的模板分数系统性偏高，表现为别家模板抢走次名余量（拒判真命中）或抬高自身形成自匹配垄断。「抢分」即此竞争的俗称。

三案裁优：

### 3.1 案②（旧库主匹配 + 新库补充）—— 否决

两库公司集完全相同（各 21 家同名文件），「新库补充未暴露公司」没有增益对象；该案等于把已知有缺陷的旧库留在主路、新库闲置。唯一排序优于案③之处是无合并语义问题，但被「不解决问题」一票否决。

### 3.2 案③（双库合并统一断层门）—— 否决

- **朴素合并（42 条模板进同一分数表排序）会复发抢分病**：SIFT 对尺度鲁棒，同一公司的旧模板对真帧同样得分（同美术跨尺度仍强匹配）。某图鉴小图公司 X 的真帧上，新 X≈28、旧 X≈15~20 同时在场——次名是 X 自己的旧模板，28 < 2×15 → 拒判。这正是本设计要修的故障以新形态复发，且发生在新库本已修复的公司上。
- **按公司取 max 去重的合并可以修掉上述形态**（每公司只留两库最高分；数学上可证「合并后过门 ⟹ 至少一库单独过门」，即合并不产生任何单库都不会产生的命中），但仍然：① 匹配域保持混尺度，旧库薄余量负样本条目（4:3、6:5 族）持续参与次名竞争，侵蚀边缘帧的断层余量；② 需要在匹配热路径新增逐公司聚合逻辑（新代码 = 新错误面）；③ 回退只有整体粒度（撤库即全撤，无法单独停用旧库）。
- 两库并存于一个分数表，与「同域混尺度会抢分」的教训在结构上同型——教训要求的是隔离，不是更聪明的合并。

### 3.3 案①（新库主匹配 + 旧库兜底）—— 推荐

**语义**：每次 boss SIFT 按域序先后跑两遍断层门——先新库（主匹配域），过门即返回；新库拒判再问旧库（兜底域），兜底过门返回兜底结果；两域皆拒 → None（现状失败语义）。**推荐理由一句话：域隔离让每次匹配都是单一尺度域，混尺度抢分与同公司双模板占次名在结构上不可能发生，且兜底命中集严格 ⊆ 现役命中集。**

支撑论证：

- **单调安全**：兜底域的计算与今日现役链逐位相同（同库、同门、同裁片），只是从「无条件跑」变为「主域拒判后才跑」。对任一帧：主域命中 → 返回主域结果（行为差异面，见风险 R1/R2）；主域拒判 → 兜底结果 = 今日结果；两域皆拒 → None = 今日结果。新链的误报面 = 主域误报（语料验证为零，38/38）∪ 兜底误报（= 今日误报面），不存在第三种新误报来源。
- **断层门零改动**：`BOSS_SIFT_MIN_GOOD`/`BOSS_SIFT_RATIO` 常量与 tie 拦截语义原样保留；门在每个域内独立生效，tie 拦截对新库负样本（10:10 平分族）仍是承重机制。
- **覆盖修复**：主域给全部 21 家公司统一的已验证识别能力（旧库只有 2 家有大裁片强余量）；兜底保留 2 张实机大裁片的强匹配作为保险（若某实机渲染态主域意外拒判，兜底仍可能按现役行为命中）。
- **节点条域无行为变化**：实验证明两库在该域都拒判，新链在该域 = 主域拒 → 兜底拒 → None，与现状逐位一致。
- **回退粒度**：主域与兜底域可独立停用（§6 回退开关 A/B）。

**风险**：兜底引入了一条「主域拒 → 兜底过」的新路径，其输出继承今日全部已知缺陷（薄余量拒判在边缘帧翻转的不确定性）；语料上该路径无实例（38 负样本两域皆拒），实机期按 §7 观察项监控（R3）。

## 4. 问题三：加载器改动面

实现批的改动清单（本节给契约，不给实现代码）：

1. **`load_boss_templates(templates_dir)` 原样保留**：单域加载器语义不变（glob 平铺、stem 命名、特征 <4 丢弃），新库旧库共用同一加载函数；顺带把其 docstring 里过时的「图鉴 20 公司」描述修正为与两库现状一致。
2. **新增域列表装载函数**（建议名 `load_boss_template_domains(template_root: Path) -> list[dict[str, tuple]]`）：按优先级序依次装载 `template_root/cw_boss_avatar`（主域）与 `template_root/currency_war/boss_avatar`（兜底域），空目录/缺失目录跳过，返回非空域的有序列表。**优先级 = 列表序；无跨域去重**。
3. **同名公司裁决规则**：公司名在两库都存在时（当前 21 家全部同名并存），不做描述子合并、不做逐公司去重——主域先答：主域内该公司过门即整体命中返回；主域拒判（含该公司在内的全域拒判）才问兜底域。语义上「谁先过门谁赢」，每次命中的来源恒为单一库的单一验证行为，可回溯。
4. **`match_boss_sift(patch_gray, boss_templates)` 签名扩为 `dict | list[dict]`**：dict = 单域（向后兼容，现有调用与测试零改动）；list = 按序逐域跑现行单域逻辑，首个过门即返回。建议把单域匹配抽成内部纯函数，域序逻辑可独立单测（§7 T1-3）。
5. **全局懒加载缓存改名**：`cw_observation.py` 的 `_BOSS_TEMPLATES` 改为 `_BOSS_TEMPLATE_DOMAINS: list[dict] | None`，两处懒加载点换装域列表函数；`_read_boss_big_icon` 的 `_cwo._BOSS_TEMPLATES` 同步（含 `if not ...` 空判与懒预热调用）。类型变化是响亮的（漏改 = AttributeError 立即暴露，无静默风险）。
6. **`classify_node_row` 的 `boss_templates` 参数类型同步放宽**为 `dict | list[dict] | None`（真值判断不变）。
7. **日志带域来源**：`_read_boss_big_icon` 与 boss 槽命中的日志增加「命中来自主域/兜底域」标记——实机回归期这是「兜底路径是否被走到」的唯一观察窗（§7 实机回归点 3）。
8. **测试 fixture 同步**：`test_cw_node_reader.py::_boss_templates()` 换装域列表（保持 skip-if-missing 纪律）。

改动文件合计：`cw_node_reader.py`、`cw_observation.py`（两处消费点）、`cw_screen_plane_intel.py`、`test_cw_node_reader.py`，共四个文件；`boss_avatar` 旧库文件零触碰。

## 5. 问题四：迁移与回退

### 5.1 分步迁移（实现批按步提交，每步可独立验证与回退）

1. **落位步（仅资产）**：统一模板批 21 张 PNG 原样复制到 `assets/template/cw_boss_avatar/`（复制命令逐字节拷贝，禁重编码/改名/转格式；commit 核对 `git diff --stat` 应为 21 个新增二进制）。此步落位后对新库零消费，识别行为不变——天然安全的独立 commit。
2. **接线步（四个文件，一次改净）**：§4 全部改动 + T1 测试扩展（§7）。改代码须重启项目 MCP server 才生效；重启须避让运行中对局（改代码集中到局间）。
3. **验证步**：§7 三层验证全绿才算接线完成。
4. **并存期（默认长期）**：两库并存；旧库冻结（不再新增模板文件，新公司/新赛季模板只进新库）。
5. **退役批（独立立项，须用户裁定）**：旧库退役改「现役沿用不改」约束，本设计只给判据建议不执行——建议判据：接线后累计实机局中主域全覆盖三位面 boss 命中、零兜底命中、零误报，持续 N 局（N≥3 起议）后，删除旧库目录 + 兜底域装载 + 相关测试分支。退役批同时是 boss_avatar 目录消亡的出口（§8 口径）。

### 5.2 回退开关（三段独立，按故障面选用）

| 开关 | 操作 | 效果 | 适用 |
|---|---|---|---|
| A（退新库） | 删除/改名 `assets/template/cw_boss_avatar/` 目录 | 域列表只剩兜底域 = 今日现役行为逐位一致，零代码改动 | 主域实机误报/漏报 |
| B（退兜底） | 模块级常量（建议 `cw_node_reader.BOSS_TEMPLATE_FALLBACK_ENABLED: bool = True`）置 False，域装载跳过兜底域 | 纯新库链 | 兜底路径实机异常 |
| C（全退） | `git revert` 接线步 commit | 回到今日链（落位步资产可留在库内，无人读即无行为） | 接线本身引入工程问题 |

## 6. 问题五：验证设计

1. **语料复放（一次性，接线步验收）**：私有侧实验语料 60 帧（22 正 + 38 负，真值表随实验批归档）对接线后链路复放，验收判据 = 22 正样本全部命中且断层余量与实验报告一致、38 负样本两域皆拒、无「主域拒→兜底过」实例。复放脚本与结果归迭代目录（易失区），不入 git。
2. **语料持久化子集归档（实现批内做）**：从私有语料挑代表性负帧（补给图标 2~3 帧 + 战斗图标 1 帧）复制进 `sr-od-test/screens/货币战争-位面详情/`（测试仓本地私有，既有 4 帧 fixture 同库），把负样本覆盖从 2 族扩到 4 族并跨会话存活；私有语料本体（私有侧临时目录，易失）不得作为任何测试的依赖。
3. **T1（`uv run pytest sr-od-test/test/sr_od/application/currency_war -m "not slow"`）扩展清单**：
   - T1-1 现有 4 帧 fixture 测试换装域列表链路（断言不变：命中公司名、门通过、负帧不命中）——天然变成新库主匹配的实帧回归；
   - T1-2 新库装载完整性：21 文件全部可加载且特征 ≥4；新库目录缺失时的退化语义（域列表只剩兜底域）；

## 9. 设计裁决记录（why 收敛）

- 落位平铺不目录制：字节一致性即验证继承；框架可见性零收益（§2）。
- 案①域隔离不合并：混尺度病与同公司双模板抢分的根都在「两库同场」，隔离是治本，按公司 max 合并是带新代码的缓解（§3.2）。
- 兜底而非替换：旧库 2 张实机大裁片是现役唯一被实机强验证的模板，保留为兜底以最小代价继承其能力，同时不放弃「识别现役不破坏」的用户约束；彻底退役另走用户裁定（§5.1 步 5）。
- 门零改动：门常量是正负两侧的实证承重墙（正样本最小余量 4.7×、负样本 10:10 平分靠 tie 拦截），任何调整都会同时动摇两侧已验证结论（§1.2）。

## 1. 件一 · 根11 定谳:RunEquip 穿戴语义残余

### 1.1 病灶原形态与已闭部分

第9局(g_20260903_183142)原形态:①「装备全局脱落」(p2r2 起 7 人板仅 1 件在穿,3 件滞留)与「穿戴零上身无行为兜底」;复盘候选 R2 =「板面扩员导致在穿装备整体脱落」新形态。其中:执行侧零上身(拖拽落空/坐标偏差)已由 L1 5/5 连穿证伪为存量形态;每帧空发射已闭(装备转移发射门+闩);模态期金对账、D1 欠录两条件已各自闭账(账本行条件②③)。

### 1.2 残余语义缺口(本件裁定)

残余收敛为两条,**均属策略语义,无执行层缺口**:

1. **hold 触发权归策略侧**:穿不穿、什么时候穿的判据(=件二,§2)是策略决策;执行层 `_transition_hold_active`/`_opening_hold_active` 只是该判据的载体。设计契约 = 执行层持布尔释放位,判据变更只改判据源,禁在执行层内加第二套时机判断(与 ADR-0461 裁定 3「不在执行层造第二套评分」同理由)。
2. **零上身帧的辖域二分**:`equip_zero_wear` 哨兵是观察面不停机,其 stop_reason 须按辖域分流裁定:
   - `过渡期hold` → 策略 by-design,由件二判据解释,非缺陷;
   - `分配方案空` → 策略语义缺口,归件三(§3)与工具消费空缺评估;
   - `drag 落空` / `pool_empty` / `分配对全部拉黑(拖拽连败)` / `槽位坐标缺失` / `画面非干净备战` → 执行链,归执行层修复批,不入本篇辖域;
   - `装备计划失效(计划步件两次现读不可定位,交回重派重算)` / `工具计划失效(首件消费后 reflow,剩余计划作废)` → 执行链(ADR-0601 §4 判读分键纪律:计划已产出、执行期状态漂移打空,恢复动作走分发/执行链;装备行经执行面哨兵入台账(执行面挂点仅辖 m7 主路径,front_only 回退分支的计划失效/屏漂移不入台账——与计划面同口径,ADR-0601 §4-9),工具行当前哨兵双挂点均不产生、按判读分键纪律先行登记,消费面 = run_record/日志判读);
   - `装备计划空(合法稳态,无穿戴步)` → **不入哨兵(防御分支)**:空计划直接构造面的 `round_success` 合法稳态出口,非停手归因、不进哨兵输入、无归域语义,故无分流归域;登记仅按 ADR-0601 §4 具名常量纪律供判读分键,不入哨兵词表;
   - **兜底行:枚举外的一切 stop_reason 一律暂归执行链待分诊**(防判读 checklist 遇无归可分帧;新枚举值出现时回本表补行)。
3. **「穿上后脱落」形态(原 R2)语义声明**:分配器为 **fill-only**(occupied 仅作容量扣减,不触碰任何已穿件,key 与否同判);执行层无角色间取下通道(装备不可直拖,取下仅扳手/炉/卖角色三条路,工具消费自动化为零,10 号稿 §2.1.8)——故「分配器不取下已穿件」自动成立,不另立约束。真正待裁定的语义 = **词缀凑满谓词遇到「错位已穿的非 key 件」**(件在错误角色身上、谓词角色空等):现行只能填空槽绕行,纠错依赖扳手批(10 号稿 §2.1.2 去向登记制),**挂账候扳手消费批,本篇不出辖**;每备战期 owned↔equipped 对账已由期望态通道覆盖(L1 验证「装备位移/覆盖」零发生);实机复发确认依赖阶梯 L2「已穿非空局样本」,随对局被动采集。

## 2. 件二 · 流程36:opening 窗口/非 key_equips 释放判据

### 2.1 判据(收编既有设计,零新参数)

本件不新造机制,收编既有权威为一张释放判据表(前三行 = 既有语义收编,后两行 = 本篇补裁的同构豁免行):

| 状态 | 非 key_equips 处置 | 判据源 |
|---|---|---|
| opening hold 活跃(r≤2 ∧ 节点非战斗类) | 扣留(囤) | ADR-0461 H3:`opening_hold_battle_nodes` 词汇表 + node_type 缺省回查节点序列台账;node_type 缺失(None)→ 维持 hold(观察缺失不改既有行为) |
| 已定型扣留(committed hold)活跃 | key 命中件随时穿;非 key 件扣留 | r70 过渡持有语义(10 号稿 §2 [24];`_transition_hold_active`)。激活条件 = **已定型(committed)侧**,非未锁线:定型权威 = `cw_intention.committed_from`(位面 2 起恒定型 ∨ 意向已锁 ∨ P1 配对线非空)∧ `0 < form < COMMIT_FRAC` ∧ 非双轨。**方向声明:未定型(双轨)帧扣留不激活**——「攒给成型核心」只在目标核心已定时保留;第十六局 P2r5-r7 三条 hold 帧(已 pivot,恒 committed)即该语义的实机形态 |
| 战斗类节点(r≤2 内) | 释放:全量穿,按 M7 既有分配序 | ADR-0461 H3 收窄语义(opening hold 不辖战斗节点);r≤2 帧零穿戴本就不入零穿戴哨兵(哨兵 expected 自带 round≥3),与释放判据无冲突 |
| 库藏生锈词缀在场 | 豁免一切扣留,分配序列全量穿戴 | ADR-0461 H2②:`rust_wear_release_enabled` + `cw_comps.RUST_AFFIX_NAME`;理由 = 滞留边际代价在计件封顶(注册表 cap=10)内单调上升,封顶内单调已足以压倒「攒给成型核心」的机会成本 |
| 穿戴条件词缀(输出侧罚则族)在场 | 豁免已定型扣留,同生锈同构对称 | 谓词未满足角色的下一件装备边际价值 = 消除该角色的罚则(如软弱无力第 3 件 = 找回 20% 伤害),同为封顶内单调的确定性收益,压倒囤积;豁免只解除「能不能穿」,穿给谁仍由 §3 优先层决定(carry 先凑满,不散穿) |

**row4/row5 不对称的理由(非遗漏)**:生锈豁免辖「一切扣留」而输出侧词缀豁免只辖已定型扣留(不辖 opening hold)——差异来自罚则**结算时点**:生锈按 owned 滞留件计罚,装备躺在包里同样承罚,opening 窗口内亦然,故豁免须全域;软弱无力族只对「在场且未满」角色在战斗结算时点施罚,r≤2 奖励轮无罚结算点(H3 已把 r≤2 战斗节点放出 opening 辖域),该窗口内穿戴无即时收益差,豁免不扩至 opening。

**多行命中合并规则(一句)**:判据表按行序评估,扣留行「任一命中即扣留」,豁免行「命中即解除其对应扣留域」(豁免取并集);多豁免行同帧命中时行为一致(全量释放),无次序依赖。

**释放动作的次序**:释放帧的穿戴序列 = M7 角色级分配(`equip_allocation`)既有输出,含件三的词缀优先层(§3)重排后的输入序;执行层 drag 链不变。

## 3. 件三 · 流程45:词缀条件装备分配优先级

病灶(run_20260902_195720 F 条):敌人词缀「软弱无力」(未穿满 3 件装备的角色伤害只剩 80%)在场时,分配无「满 3 件优先 carry」约束——终态 7 件装备三月七(辅助)3 件、卡芙卡(主输出)1 件,全场仅辅助全额输出。

### 3.1 载体设计(对抗轮一定谳:方案 b,结构化谓词字段)

现役词缀效果注册表 `AFFIX_EFFECTS` 为散文 dict(效果原文),无结构化谓词载体——「N 与罚值直读散文」无实现路径,落码必造第二源。**选型 = 方案(b)改载体设计**,不选(a)挂账;依据:①件三的病灶(软弱无力局零约束)是已实证的胜负级缺口,挂账 = 缺口继续裸奔;②载体改动小且完全骑在既有静态数据采集通路上——新增按词缀名 keyed 的结构化字段族,散文行保留为真值出处,结构值为**带对拍义务的派生缓存**;③对账通路有现成先例:D-81 守卫(ADR-0081,静态数据 divergent 不覆盖 + tooltip 留证)就是「散文↔结构值」对账的既有机制,新增字段直接纳入其守卫域。

载体规格(值全部游戏定义【注】,落码零新自由参数):

- **落点 = 独立文件**(新增结构化词缀字段族文件,非 `affix_effects_data.py`)——理由:散文注册表由运行时采集整文件重写(ADR-0081 修法形态),结构化条目混入其中会被下次重写冲掉;两文件**互不触碰**(采集批只写散文文件,结构文件只随结构批/对拍批更新);
- 结构化条目(按词缀名 keyed):`wear_predicate`(谓词类型 + 参数,如 `min_worn_per_char`, N)、`penalty_side`(罚则方向:`output` 输出侧 / `damage_taken` 承伤侧)、`penalty_value`(罚值)、`prose_ref`(**词缀名锚**,指向散文注册表同名词缀行——散文行号随整文件重写下移不稳定,名锚稳定);
- **互检显警(检测面一句)**:散文注册表命中穿戴/伤害衰减类关键词(「穿戴」「件」「伤害变为」族)但结构文件无同名条目 → 显警留证,防新词缀漏建模静默;反向(结构条目在散文中无同名行,孤儿缓存)同警;值差异走 D-81 守卫拦截;
- **首次消费对拍锁**:结构值与散文原文逐条对拍(【注·对拍定谳】先例:01 §6 / ADR-0456),对拍做成采集批常设项——游戏改罚值时,散文更新而结构缓存 divergent → D-81 守卫拦截报警,禁止静默沿用旧值;
- 在册词缀集判定规则:结构化条目存在 ∧ `wear_predicate` 非空 ∧ `penalty_side == output` 才进本层(缺结构化条目的散文词缀不进,防解析散文)。
- **邻接排除族点名**(与「穿戴件数」谓词同族但谓词本体非穿戴的条目,显式排除防一般形误扫):「挫其锋芒」(谓词 = 伤害减免属性未达阈,属减益/装备效果面,非穿戴件数)、「形单影只」(谓词 = 未激活羁绊数;且现建模只含「免罚」半边,未成型侧衰减未建模,`cw_comps` MECHANIC_SYNERGIES 注记 + ADR-0500)——两者不进本层,候选载体建模候各自领域批(减益面/羁绊面)另案。

### 3.2 判据(一般形,限输出侧罚则族)

词缀效果注册表定义「穿戴条件谓词 + 输出侧罚则」条目(如软弱无力「未穿满 3 件 → 伤害 ×80%」)在场时,装备分配序在基分配序(10 号稿 §2:输出位优先 → 辅助核心装备 → 盈余,[9])之前插入**词缀条件优先层**:

1. 求满足谓词涉及的角色集合(在场角色全集,不限已锁线成员——词缀罚则按角色个体结算,不按阵容资格);
2. 集合内按 [9] 既有优先序排(词缀层只重排,不造第二套角色评分);
3. 谓词未满足期间,向集合内最高优先角色的每件分配都指向「凑满谓词」(如凑满 3 件);谓词满足后回落基分配序。

**key 件绑定裁决(落码批回记,ADR-0526)**:词缀谓词优先层可重排候选序使非 core 先拿功能性件凑谓词;key_equips 归属仍由 [9] 基序+M7 决定,谓词层只重排候选序不改 key 件绑定(key 件接收者序在优先层下仍限于 carry∪core,非 core 凑谓词只走通用件吃满)。

**罚则方向分叉声明**:`penalty_side == damage_taken` 族(如「额外打击」:每空 1 个装备栏,受击后额外承受本次伤害 8% 真实伤害)**不入本层**——承伤罚的总空槽数与分配集中度无关,分配改变的是「谁挨打」不是「总共几个空槽」,§3.5 的集中优先论证对它不成立。承伤侧族的策略语义属生存/站位域,**显式出辖**(如需消费,按生命周期第 1 态另立项)。

**反向条件形(库藏生锈,承伤侧但单列)**:词缀要求「无用件聚拢穿到指定工具人」——用户已裁支配条款,立足点只有「词缀罚归零」一条(流水-20260901 裁定,炉料穿着等是顺带形态非理由);配对安全谓词防自动合成带偏:该角色只穿需求向量外无用件。生锈不进优先层(它是「件的去向」约束,不是「分配次序」约束),只走 §2.1 豁免行。

### 3.3 与 M7 角色级分配的接口(对抗轮一定谳:扩签名)

代码真值:`equip_allocation(comp, deployed, owned, occupied=None)`(`cw_comps.py`)接收者顺序在函数内部派生(plaza_carry → core_chars),无优先序输入。接口设计为**显式签名扩展**:

- 新增可选参数 `priority_order: list[str] | None = None`;`None`(缺省)= 现行内部派生序,零行为漂移;
- **comp=None 路径定义**:`comp` 为 None(无目标/未定型帧)时 `priority_order` 强制为 None——优先层的重排依据([9] 序 + 谓词集合)依赖阵容名单;未定型帧词缀谓词集合退化为「在场角色全集按现行内部派生序」,即零重排,与「词缀层只重排不造第二套评分」自洽;
- 语义保持声明(**措辞收窄**):配对守卫与唯一件(星徽 add-if-absent)守卫对候选对的判定与遍历次序无关,重排序下逐对语义不变;容量扣减(occupied)的**可穿件总数**与次序无关,而「落在谁身上」随次序变——这正是 `priority_order` 的语义本体(分配优先序),不属「语义漂移」,验收口径 = 前两类守卫逐对不变 + 件总数不变 + 落点符合重排序;
- 决策/执行分层同 ADR-0461 裁定 3:优先级是决策层产物,`priority_order` 是唯一传入通道,执行层禁内嵌评分;
- 「M7 零改动」表述**作废**,更正为「M7 判据语义零改动 + 签名扩展一件(可选参数,缺省零漂移)」——签名扩展属接口面,落码批按普通签名变更走锁回扫。

### 3.4 豁免组合

生锈豁免(H2②)/输出侧词缀豁免(§2.1)与优先层可同帧生效——豁免解除 hold 决定「能穿多少」,优先层决定「穿给谁」,判据正交,禁合并为一个复合开关。

### 3.5 证明状态(数学先行门)

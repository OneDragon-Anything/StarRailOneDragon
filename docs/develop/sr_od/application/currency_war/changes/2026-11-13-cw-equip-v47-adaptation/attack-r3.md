### N2 门键集第二消费面（cw_events 装备识别锚名单）未入行为影响申报——申报完整性缺口

- **位置**：design.md §2.3.1 行为影响申报段「门清空 → 银狼专属装备防误拖保护失效，影响趋零」；wear_rules 文件头「消费位」声明（:14，只列 cw_comps._wearable_gate_ok——代码注释自身也不完整，非本迭代产物）；§2.6 穿戴规则门重建行（影响面 = 「穿戴分配保护」）。
- **攻击**：门键集实际有两个消费面。`cw_events.py:261-266` `_PLANNER_EQUIP_ANCHORS = tuple(sorted(ITEM_WEAR_GATES, key=len, reverse=True))` 消费件级门键集作**事件卡文装备识别锚名单**（longest-first 防短名截胡），注释自证「同一名单的第二个消费面，名单收窄/扩圈自动跟随」。门清空后该名单构建为空元组 → `_similar_equip_hits`（:273-279）恒返回空 → 事件卡文的装备域优先判定不再命中 → 相关卡文落 unknown 分支（零记账、留存证据——注释 :255-256 申报的响亮兜底）。影响评估：①非静默错（unknown 兜底响亮申报，可发现可回放）；②随门重建自动恢复（名单单一源自动跟随）；③消费方域文件不在本迭代文件面。故不构成阻断。
- **但申报完整性有缺口**：§2.3.1 行为影响申报只覆盖「防误拖保护」一面，读者会以为门清空只影响分配保护；门重建挂账条目（§2.6）影响面列「穿戴分配保护」也未含「事件装备识别记账」——挂账清偿时按现条目验收会漏识别功能的恢复确认。
- **建议修法**（二选一或并行，一句话级）：①design §2.3.1 行为影响申报段补「门键集第二消费面（cw_events 装备卡文识别锚名单）随门清空自动退化为空名单，卡文装备识别落 unknown 响亮兜底，门重建后自动恢复」；②§2.6 穿戴规则门重建行影响面补「含 cw_events 装备识别锚自动跟随面」。
- **分级**：建议（申报完整性；不影响判据可执行性与收敛）。

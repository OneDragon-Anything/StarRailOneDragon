# sim 战斗结算机制化(战力模型 v1)迭代设计(总纲)

## 0. 元信息

- 迭代目标:用户 2026-10-19 立项「sim 战斗结果预估重建」;方案骨架 = 阵容达成度+难度的预估函数,经评审扩为「双轨达成度 + 核心/总拆分星深 + 人口差 + 难度」12 参数胜负层与「条件化经验直方」幅度层。需求定义正本 = [sim-power-model.md](../../sim/sim-power-model.md)(设计件,未实施),本迭代 = 其首期落地。
- 状态:草案
- 文档清单:无详设(单文档方案,本文件即完整设计)

## 1. 问题与动机

- 现状症状:sim 战斗结算 = 随机输出面——胜负 = 均匀伯努利 P(win)=0.5,败局扣血 = 区间 [23,70] 均匀采样,单一源 `sim/cw_sim_battle.py`;结算面不消费任何板面/战力/敌人特征,按 sim-design.md 校准层申报「战力相关判读禁出」。实证:2026-10-19 sim 局复盘(g_20261019_142001,seed 777,报告在 `.debug/currency_war/deep_review/`)——5 场结算战斗 1 胜 4 败,公平硬币下该结果出现概率 18.75%,属普通方差,死亡通道零策略信息量。
- 根因归层:语义层——战斗输出面是「诚实随机」而非「机制化预测」。机制化需求已定义(sim-power-model.md,现状注记 = 设计件未实施);前代实现 `cw_coarse_battle` 随 sim 重做整删(commit 8c9e8aafc,2026-09-15),sim-design §8.2 现值行明写「机制化重建需求件 = sim-power-model.md」,重建路径已裁定,非新立项。
- 解决到哪:①胜负层 12 参数 logistic(§2.2);②幅度层条件化恢复(§2.4);③训练与校准管线(§2.3);④sim 接入与隔离护栏(§2.5);⑤采集通道 journal 增量抽取(§2.7)。
- 明确不解决:词缀/boss 身份特征(首期冻结,放开触发线见 sim-power-model §4.3);对手板面读取管线(实机无此观测面);hp 类读数解禁(幅度层过校准验收前,A/B 判据仍以实机为准);P3 位面细分(并入非P1,低置信披露);策略层对模型的任何消费(sim-power-model 铁律 1,永久禁止);实机局自身行为(本迭代改动纯 sim 侧 + 离线管线)。

## 2. 方案

sim-power-model.md = 需求定义(判据与护栏的权威源);本文件 = 其首期的实施设计。差异三处,其余(铁律/LOCO/注入契约/影子期/依赖方向锁)照正本执行,本文不复制全文,冲突时以正本为准并回改本文:

1. 特征面缩减聚焦:正本 §4.3 v1 分配表(12 参数,含逐费用档计数/装备/核心意向)缩减为下表 12 参数——达成度双轨(用户 2026-10-19 裁定)+核心拆分星深(同)+人口差+难度;费用档细分/装备/核心意向特征随语料增长按正本触发线放开。
2. 新增幅度层条件化交付(§2.4):正本 §6.1「模型只掷胜负,幅度层走直方/常量表」——现行载体 U01 把幅度压扁成了全局均匀区间,本迭代按前代形态恢复条件化。
3. 新增 journal 增量抽取通道(§2.7):正本 §8.1 抽取器吃旧流文件(2026-09-15 停写,语料冻结),本迭代补「新实机局进训练集」的通道。

### 2.1 数据

- 训练真值单一源 = 生产档案旧流:`.debug/currency_war/telemetry/` 下 decisions.jsonl(64 文件,152,657 行,含每场战前 `state.deployed`/`board_factions`/`level`/`enemy_difficulty` 快照)× outcomes.jsonl(64 文件,96,316 行,胜负标签)。设计期口径(sim-power-model §2/§4.3):战斗类结局 886 行、有标签 ~730、胜事件 ~128;抽取批按 canonical 口径重钉实数。
- 三铁律(sim-power-model §1,全文照搬为准):唯一消费者 = sim 战斗结算层(策略模块禁 import、禁读遥测回显、禁系数知识洗白);训练集永不掺 sim 对局(B0 循环——模型接管结算后 sim 无法自证);HP 不作胜负模型的标签/特征/校验主量(幅度层自身是 HP 的经验分布层,但其输出不回喂胜负模型,见 §2.4)。

### 2.2 胜负层特征面(12 参数,顶格)

目标函数 = 逻辑回归 `P(win) = sigmoid(w·x + b)`。选型依据:sim-power-model §3(单场二值预测,标签噪声低)+ §6.4(点积确定性、万级调用无压力、同输入同输出)。

| # | 特征 | 参数数 | 定义与单一源 | 依据 |
|---|---|---|---|---|
| 1-4 | 过渡达成度分档(one-hot 四位) | 4 | 四体系(仙舟3/列车2/DOT2/希儿系)达成档数,单一源 = `kernel/cw_battle_calib.py::_settle_rung`(现存,本会话 2026-10-19 核实在位) | sim-power-model §4.1 组 B「rung 四档 one-hot」;四体系定义 = transition_combos.md(用户口述定调,最高权威) |
| 5 | 终局阵容达成度(连续 0~1) | 1 | `max(form_progress(comp, 板面)) over COMP_LIBRARY`(全注册表取大,见下「取大定义」) | 用户 2026-10-19 裁定(达成度须含终局阵容);form_progress 纯函数单一源 = `kernel/cw_comps.py`(消费先例 = p59/17 号篇) |
| 6 | 总星深 Σ(star−1) | 1 | 全队星级深度,单一源 = `kernel/cw_battle_calib.py::deployed_star_depth`(现存) | sim-power-model §4.1 组 A |
| 7 | 核心星深 Σ(star−1)(仅计核心名单内单位) | 1 | 核心集合 = 取大线的 `core_chars` 注册名单(见「取大定义」) | 用户 2026-10-19 裁定(星深须区分核心);core_chars = `kernel/cw_comps.py` Comp 注册字段 |
| 8 | 上场数 − 人口等级 | 1 | 板面利用差 | sim-power-model §4.1 组 A「上场−人口差」(v1 增量清单项) |
| 9 | 敌方难度 | 1 | enemy_difficulty 数值;**弱识别预期**:语料难度质量 73-89% 集中于 108(sim-power-model §6.5),系数预期为弱校正 | sim-power-model §4.1 上下文组 |
| 10 | 难度缺失指示 | 1 | 实测缺失 ≈10%(§6.5);缺省行为 = 指示位置 1、数值按 0 载入 | sim-power-model §4.3 分配表含缺失指示 |
| 11 | 位面二值(P1 vs 非P1) | 1 | P3 语料仅 8 行并入非P1,低置信披露 | sim-power-model §3/§7-5 |
| — | 截距 b0 | 1 | — | — |

**取大定义**(特征 5/7 的形式化,双侧同源的关键):对任意板面 B,`best_line(B) = argmax_{comp ∈ COMP_LIBRARY} form_progress(comp, B)`;终局达成度 = 该最大值;核心集合 = `best_line(B).core_chars`。COMP_LIBRARY 与 form_progress 均为注册表纯函数(kernel/cw_comps),实机 decisions 行与 sim GameState 两侧同构可算,满足双侧同源(sim-power-model §4.2);对齐测试 = 同一板面输入 → 两侧同一特征向量。不采用策略器锁定线(target_comp/`ist.locked_comp`):锁定线是策略内部状态,实机 decisions 行无此字段,引入即破坏双侧同源。

**砍单候补序**(抽取批重钉预算实数后不足 12 时,按序砍):①难度缺失指示(缺失行整行丢弃+披露丢弃率)→ ②上场数−人口。过渡/终局双轨达成度与核心星深**不可砍**(用户 2026-10-19 裁定,信息量主体)。

**符号约束注意**:方向约束(系数非负)只施加于单调特征(过渡分档/总星深/核心星深/难度);终局取大完成度**不加单调约束**——取大线可中途切换,存在合法的小非单调段。

### 2.3 训练与验收

- 参数预算:有效参数数 ≤ 少数类(胜)事件数/10,向下取整,抽取批重钉实数;测法 = df=tr(Ĥ)(帽矩阵迹),非系数个数。依据 = sim-power-model §4.3。
- 验证:LOCO(留一语料源交叉验证)防泄漏;校准曲线只在实机语料上做;样本量不足下限的桶只披露不判(分位带按二项重复抽样);外推段可见性对照表(sim 输入分布上 P(win) 分位数 vs 语料边际胜率)。依据 = sim-power-model §5.3。
- 标签缺失:killed=None 丢弃率按 source 分桶披露(MNAR,缺失与败局路径相关,设计期实测 17.0%);低胜率带结论带敏感性免责。依据 = sim-power-model §7-8。
- 影子期门(转正前置):sim 批双写「模型预测 win_p」与「现行常量」两个披露字段 → 分歧分布(按节点/达成度分段)+ 外推段对照表产出,人工判读无结构性异常方可转正。依据 = sim-power-model §6.3。

### 2.4 幅度层条件化

- 现状:U01 败局扣血 = 全局均匀 [SIM_HP_LOSS_MIN, SIM_HP_LOSS_MAX] = [23,70](cw_sim_battle.py;区间界锚自实测散点 P2r1 −23/遭遇 −28/P3 遭遇 −70——散点跨度本身即上下文规律的实证)。
- 恢复形态(前代 cw_coarse_battle 同构,见 `git show 8c9e8aafc~1` 的直方/_LOSS_FIT/boss 钳制段;系数从现存语料重估):
  1. 位面×节点类型离散直方(保留伤害谱离散/双峰形状;boss 行截断观测单独钳制,不入直方);
  2. 达成度线性均值匹配:直方采样 + (fit(达成度) − 池均值) 偏移,每节点类型一组 (intercept, slope, 池均值);斜率 CI 含 0 退常数(小样本守卫);
  3. 伤害地板与伪影伤害档剔除纪律照前代(语料治理递增纪律,版本常量随重估递增)。
- 辖域与红线:幅度层与胜负模型互不喂——P(win) 不见任何 HP 量;扣血分布不以模型输出为条件;幅度层系数入版本常量表(CALIB 语义版本随重估递增);hp 类读数继续禁作 A/B 判据,直至幅度层过校准验收(sim-testing 在册裁定,本迭代不解禁)。

### 2.5 sim 接入与隔离护栏

- 接线点:`settle_battle` 的胜负常量 0.5 换为调用方注入的 win_p 浮点(注入物 = sim 桶现算,先例 = P2CombatCalib 传值形态;查询函数签名缺省 None = 完整旧行为);**全域接管,不设覆盖不足回退分支**(不定义触发谓词的回退 = 死代码或双机制混合,依据 sim-power-model §6.1)。胜负掷点仍走 `M13/{plane}/{round}` 流键,seed 可复现性与随机量消耗序不变(sim-design §7 随机性纪律)。幅度层接线同批(§2.4 采样器替换区间采样),伤害随机量消耗序的重排按流键纪律申报。
- 模块落点:sim 桶 `power_model/` 子包(查询面+抽取器+训练脚本+权重常量表);权重入库形态 = 代码常量表(先例 `cw_battle_tables`);**data/ 桶禁落任何模型产物**(data/ 被决策侧合法 import,落那里 = 绕过隔离的通道);AST 静态白名单断言集 + 重导出审计 + sim/replay 目录隔离测试。依据 = sim-power-model §6.2。
- 配套生成器:sim 侧 enemy_difficulty 按 位面×轮次 语料经验直方图采样写入 GameState 敌方字段(v1 仅难度;boss 身份/词缀推迟到各自特征开放,避免无消费者生成面);生成器只写敌方字段、与板面/策略状态无交互(外生性,单向性测试锁定)。**硬序:生成器先于影子接线**——否则难度特征在 sim 侧 100% 缺失(训练分布 ≈10%),分歧统计被伪影主导。依据 = sim-power-model §6.7/§8。
- 输入分布监控:结构性缺失(已知不可达)与真漂移(超阈报警)两类分开,不混判。依据 = §6.5。

### 2.6 边界与已知风险(照正本 §7 承载,本文只列首期新增)

- 取大定义的换线噪声:取大线中途切换时终局达成度有小幅跳变,弱化「完成度单调积累」的解释性——首期接受(无锁定线语料的约束下最干净的双侧同源定义);journal 通道起量后可登记 locked_comp 字段,新语料逐步换真值锁定线。
- 双轨达成度的统计支持不均:过渡分档腿在 P1 语料厚、终局取大腿在 P2/P3 语料薄(P2 低置信/P3 仅 8 行)——预期终局腿首期学出弱系数,如实披露;「分档×P1、完成度×非P1」交互项为语料增长后第一个放开候选(参数预算翻倍,首期不做)。
- 首期 12 参数顶格零余量:若语料重钉后少数类事件少于设计期,按 §2.2 砍单候补序执行并在校准报告申报。
- 其余(B0/对手板面/版本漂移/样本爬坡/域差/共生/冻结/MNAR/词缀映射)照 sim-power-model §7 全文适用。

### 2.7 采集通道(journal 增量抽取)

- 动机:旧流 2026-09-15 停写,训练集冻结;新实机局只写 kernel journal。本通道让模型随实机局持续演进(重训里程碑/版本重验的前提)。
- 形态:journal 写行 → 训练样本行抽取器。已实证可用的字段(本会话 sim 局判读全程消费):`field=hp` 写行(含 same_value 标记——胜负判据 = 结算 hp 写行差分,负 = 败、等值 = 胜,含 hp_floor 首保底语义)、`field=streak`、`state.values.deployed`/`board_factions`/`level`/`node` 上下文。实机局与 sim 局同构(journal 唯一源,渲染器 tools/cw/replay_to_md.py 同源消费)。
- 阶段交付含「字段映射规格」小节(随抽取器入库):对局边界切分(run_id/局 id 水位)、多局文件幂等、标签推导与 hp_floor 交互、丢弃分桶——规格是验收对象之一,不是实现自由裁量区。
- 产物带源指纹(journal 文件集哈希 + 抽取器版本),与旧流产物同表结构,训练脚本无差别消费。

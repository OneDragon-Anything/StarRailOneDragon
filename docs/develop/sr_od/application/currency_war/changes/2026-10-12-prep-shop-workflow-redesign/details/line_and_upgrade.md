# 统一选线函数与升级判据（详设）

## 问题与约束

- 边界：本篇定义三件事——统一选线函数（方向状态唯一来源）、升级判据（概率主轴）、方向签名前置段。备战/商店两域对它们的调用时机见各自详设。
- 总纲契约引用：契约 B（方向状态读写接口）、契约 D（价值评估函数的统一口径归本篇 §4）。
- 现行被替代物：12 号篇换线机器全部组件——退役面逐项清单见 §1.5。

## 与玩法口述正典的差分（对 user_playstyle 的语义替换申报；用户已确认）

本设计的方向语义与两条在册口述存在差分，差分依据为用户裁定 2026-10-12（本迭代立项裁定），**用户已确认差分并同意回写正典（2026-10-12 对话裁定「1. 确认」）**：

- **对 [23]（终局线由贯穿件锁定）**：保留 = 线选择由发牌驱动的精神、贯穿件的强信号地位；修正 = 贯穿件从「锁定本体（拿到即唯一钥匙）」降为「强信号之一（评分大权重项）」——线选择改由统一函数的加权评分承载。
- **对 [36]（未定型期决策单位是件；不存在换线动作）**：保留 = 未定型期件级评估、「四线摇摆全输」防摇摆精神（制度化为本篇 §1.3 切换成本 + 滞后余量账）；修正 = 「不存在换线动作」修正为「存在受切换成本与滞后余量严格约束的换目标动作」——依据用户裁定 2026-10-12「应该有一个统一的函数来计算应该选哪个最终阵容，当计算出一条新的最终阵容的时候，就更换目标」。
- 正典回写 = landing 末阶段（正本更新清单 user_playstyle 行），回写内容含本确认记录。

## 方案

### 1. 统一选线函数

用户裁定 2026-10-12：应有一个统一的函数计算应选哪个最终阵容，计算出新的（更好的）就更换目标；贯穿件是强信号之一（非一票定音）。

**1.1 函数形态**

```
f(局面状态) → 「未定型」 | 「目标线 X」
```

**1.2 每条候选线的评分（四维加权求和；权重形态见关键取舍）**

| 维度 | 内容 | 量化地基 |
|---|---|---|
| 完成度 | 该线下一成型档所需成员的持有比例（上阵+备战，按星级折算） | 阵容注册表分档表（`COMP_LIBRARY.form_tiers`，出处 = strategy-docs/10 §5）；完成目标态按下一成型档算（user_playstyle [37]） |
| 获取前景 | 缺的成员按当前等级刷新概率算补齐期望代价，缺得越便宜分越高；缺件此刻在商店牌面上可见 = 加分 | 期望刷新次数模型（`cw_shop_odds.expected_refreshes`，P40 数学件）；概率表 `REFRESH_PROB` |
| 专属资产 | 该线贯穿件在手上（强信号，大权重；user_playstyle [23] 与用户裁定 2026-10-12「强信号之一」）；该线关键装备已持有数 | 装备注册表 `key_equips` |
| 环境 | 投资策略/环境对该线的机制增益；boss 词缀克制 | 投资注册表（`cw_invest_data`）、词缀注册表；环境分化用机制知识不用热度数据（user_playstyle [38]） |

- **缺件集构造**：各线缺件集 = 该线下一成型档成员 − 已持有（每成员按完成档张数口径，k∈{3,9}）；获取前景的期望代价对该集**逐成员求和**（与 P40 消费限制注「多类合格集 DP 待办」的关系 = 取逐成员求和保守带，与现行实现口径一致，不新造 DP）。
- **贯穿件名单的注册表锚**：现行注册表无独立「贯穿件」字段（SIGNAL_REGISTRY 属 10 §5 新建挂账项）——本设计挂账新建 `COMP_LIBRARY` 每线 `key_items` 字段（贯穿件名单单一源），标定批建表；建表前该维取值 None = 未定型 fail 方向（不产生分数）。贯穿件只计持有与否（1★ 即信号），不做星级折算。
- **未定型期的升级概率账缺件集** = 与当前板面羁绊重叠的过渡体系成员缺件（现行四体系过渡语义，出处 = `transition_combos` 与现行 TRANSITION_PACK）；此时无单一目标线，概率账服务「手上过渡阵容的补齐」。

**1.3 输出裁决**

- 全部线分数低于定型门 → 「未定型」：两域按统一买牌策略的 search 态行动（商店域序 1 = 现行 search 态候选集判据，shop_session §2.2 与 §5 P86 收编行；备战域资格面无线内项）。
- 最高分线 ≥ 定型门 → 目标线 = 最高分线。
- **换目标判据（防摇摆核心）**：当前已有目标线 T，候选线 N ≠ T 更替的条件：
  ```
  score(N) > score(T) + 切换成本(T→N) + 滞后余量
  - 切换成本 = T 线专属持有资产的变现损失（2★/3★ 手续费、囤件再遇期权损失，
    折算式 = §4 统一口径）
              + N 线缺件补齐的期望花费
  - 滞后余量 = 常量（防微弱优势触发换线；「四线摇摆全输」教训的制度化，
    出处 = user_playstyle [36] 注）
  ```
- **换目标的两槽语义（中间态定义）**：方向状态分**生效目标**与**挂起目标**两槽。签名重算只更新评分快照与挂起目标；`line_members_view()` 恒返回**生效目标**的名单——会话内/备战帧内的买牌、置换账、卖出资格全部消费生效目标，无中间态抖动。挂起目标在**下一备战期入口**提升为生效目标（理由 = 备战期边界是买入名单与卖出资格集的一致性断点；与现行 12 号篇滞回/驻留组件无承继关系，见 §1.5），同时清挂起槽。
- 换目标登记时旧线专属件进卖出候选池（按价值让位语义自然排出，无紧急清场动作——塌缩卖出通道退役）。
- 评估时机 = 方向签名变化（§3）；评估本身纯函数（读容器状态算分），无副作用。
- **标定前缺省（fail 方向声明）**：定型门取最高、滞后余量取无穷 → 恒未定型 → 两域全程 search 态件级评估。买牌行为面与现行「K 空窗回退帧」的 search 态行为等价（现行在产回退同款判据）；相对现行的行为差 = 锁定态（focus 态名单）整体不再发生，延后到标定后打开——「未验证权重不锁线」的 fail 方向选择，如实申报。

**1.4 首次定型**

- 未定型 → 首次某线过定型门：直接锁定（无切换成本、无滞后余量——首次没有旧线资产）。此后适用 §1.3 换目标判据。

**1.5 退役面清单（现行组件 → 本函数的映射）**

| 现行组件（12 号篇/代码实有） | 处置 |
|---|---|
| θ 滞回、D_min 驻留、证伪记忆分桶 | 退役（防摇摆职责由切换成本 + 滞后余量账承接） |
| 换线第四触发、P84 可达性门 | 退役（线选择收拢进统一评分函数） |
| 证据门影子评估（`evaluate_evidence_gate`） | 退役（评分函数为显式版，无影子面） |

### 2. 升级判据

用户裁定 2026-10-12：主轴 = 核心的刷新概率；一次性买齐，不只买一半。

**2.1 触发（两类并列）**

- **概率账（主判据）**：目标缺件集（定型后 = 目标线缺件集；未定型期 = §1.2 未定型缺件集）在当前等级 L 与 L+1 的补齐期望比较：升一级后「找到缺件的期望刷次下降量」折算的金价值 > 升级整级成本 + 期间息损 → 该升。量化地基 = `expected_refreshes`（P40）+ 概率表 + 升级门槛表（`XP_TO_NEXT_LEVEL`）+ 买经验单价（画面实读）。
- **人口位（并列）**：板上位置坐满 ∧ 有能进当前阵容羁绊体系的单位在备战席等待上场 ∧ 该单位边际贡献 > 0（三元谓词完整保留，第三谓词出处 = strategy-docs/02 §3 M3 行与 P39 臂一——羁绊档已满的零贡献单位不触发）→ 升（战力当轮兑现；判定域 = 阵营相关单位不限星级，user_playstyle [33] 与其 2026-09-01 精确化）。人口位不受攒息约束（[12] 的明文例外）。

**2.2 支出形态：一次买齐**

- 满足触发且**攒批资金到位** → **整级预授权，一次买齐**到下一级的全部经验（批大小 = 门槛表差值折击数，现行 P48 整买引理形态保留；实付上界 = 授权批成本——发射形态为整批，无逐帧单击重评，杜绝中途断流）。
- **攒批资金口径 = 裸金 + 活期卡退金**（备战席 1★ 全额退件按退金价计入——user_playstyle [41]「把超 50 的钱换成压库卡……用时按卖回量最小化变现」的资产形态口径，与现行 P48 资产形态修正注同款）。
- **升级前变现步**：授权发射时若裸金 < 整级成本差额 → 先卖活期卡变现（候选评估器，凑息参数面，卖回量最小化、不多卖一张）补足差额 → 一次买齐。变现步是发射链内动作（同帧完成），不做跨帧「先卖后买」拆分。
- 金（含活期口径）不足整级 → 一击不买（攒钱模式，等节点收入；压库买入受整买预留约束不会吃掉攒批资金，shop_session §2.2 序 4）。
- **血本位突变下的支付检查**（user_playstyle [40]②）：血余额 ≥ 下一级血成本才发整级授权，否则零购买。**现状缺陷修正申报**：现行部分购买的真实机理 = 逐帧单击发射形态 × 静态全量阈值逐帧重闸（血支付中血量跌回阈值之下即停止发射，留下部分级；`blood_xp_gate` 本体为全量击数口径，非截断源）——修法 = 整级预授权 + 实付上界（授权血成本），发射粒度整批化后闸本体语义不变（landing §3.4 同步消歧 as-built 表述）。
- 升级执行位置两处：备战工序第 3 步（每轮全扫评估）；商店会话内（购买经验按钮能力面在役，实机帧确认；前置 = 执行链接线批）——会话内评估时机 = 每轮买入评估前（升级金优先于买牌金：等级决定概率档，先定概率档再花钱找牌）。

### 3. 方向签名前置段（契约 B 实现）

- 备战决策入口与商店决策入口各挂同一前置函数 `refresh_line_if_needed(gs)`：
  ```
  1. 拼证据签名 = 持有名单 + 装备持有 + 投资效果集 + 节点号
     （商店入口额外拼牌面 5 槽——用户裁定 2026-10-12：店里看到角色也要能更新方向）
  2. 签名 == 上次评估签名 → 直接返回现值（幂等跳过）
  3. 签名变化 → 调选线函数重算 → 更新方向状态与签名
     （换目标须过 §1.3 比较账；节点号变化时签名必变 = 节点边界重置的强制重算入口，
      见 prep_pipeline §3）
  ```
- 框架事实：策略器被动轮询无事件机制（用户指正 2026-10-12）——「信息到位就更新」以轮询 + 签名去重实现，语义等效且零新框架能力。
- 方向状态读接口：`line_members_view()` 返回当前方向下的目标名单视图（未定型 → 空名单 + 未定型旗标，两域据此走件级评估路径）。

### 4. 价值评估函数（契约 D 统一口径）

所有卖出场景的「手上牌价值」与本函数一致（单一口径，禁各场景自算）。**量纲统一为金当量**（经济期望是统一标尺，user_playstyle [22]④），可直接参与置换账比较：

```
value(牌) = 变现价 + 再遇期权 + 合成进度   （金当量项）
           ⊕ 羁绊贡献                      （排序规则项，不折金）
- 变现价   = sell_refund(牌)（注册表现读；1★ 全额退、2★×3、3★×9，cost≥2 减 1）
- 再遇期权 = 再遇窗口折算金当量：reencounter_window_frames(费用档, 等级)
             （查表单一源 = data/cw_shop_odds.py 的 reencounter_window_frames，
             11 §6.7 P77 行）× 每轮息损上限（= 1 金/轮，息档粒度）
- 合成进度 = 已有同名同星 2 张（差一张合成）→ 按该成员完成档的再遇期权 ×2 计
             （差一张 = 两张的再遇期权沉淀）；零散单张 = 自身再遇期权
- 羁绊贡献 = 排序规则项（非金当量）：卖后当前板面羁绊掉档的牌在让位序中排
   在全部不掉档牌之后（上阵位才有此代价，备战席位天然不掉档）。
   不折算金当量的原因：每档羁绊的金当量数值依赖 math_proofs P3，该命题
   已标「作废」状态（索引在案），禁引其数值——待 P3 重证或替代命题入册后
   再升格为金当量项（【拟】挂账，owner = 编排者，期限 = 一个对局周期）。
```

- 金当量三项全部为注册表查表确定式，**无自由拟合参数**；置换账比较使用金当量三项（X 的价格与 Y 的 value 比较），羁绊规则项作为候选资格过滤（掉档牌不进置换让位候选，自救扩展面除外——自救场景排序仍由让位序承载）。
- 排序用途 = 候选评估器的让位序（先按羁绊规则二分：不掉档组在前；组内按金当量升序）；置换账用途 = 与店内新牌的价值比较（同口径金当量，摩擦项 = 手续费，已含在变现价差内）。
- 定型门与滞后余量两个常量的产生方式见关键取舍。

## 关键取舍

- **加权求和 vs 逐级字典序**：选加权求和。用户裁定贯穿件是「强信号之一」非一票定音，字典序把贯穿件钉死为最高优先级，与裁定冲突；加权求和下贯穿件是大权重项而非绝对项。代价 = 权重与定型门/滞后余量需要标定——按零调参宪法的显式模型路径处理：结构与量纲来自注册表查表（§4 各式，无自由拟合），标定批补置信区间。**标定完成前缺省 = 定型门取最高 + 滞后余量取无穷（恒未定型）**：行为面与现行封印缺省等价、零新增约束（§1.3 fail 方向声明），不存在「缺省更危险」的问题；标定后打开定型与换线能力。
- **【拟】三要素登记**：定型门、滞后余量、四维权重——owner = 编排者，期限 = 一个对局周期（超期未决回炉，01 §6 章程）；登记处 = `strategies/impl/mandate_v1/audit/provisional.py`（现行 provisional 注册表，fail-closed 槽位 None 形态沿用）。
- **换目标下一备战期生效 vs 即时生效**：选下一备战期。即时生效会让同帧内买牌判据与卖出资格集抖动；备战期边界是天然的决策一致性断点。
- **濒死破例升级不保留**：见 §2.3 血线地板解锁行；血本位支付检查保留（账户余额检查非质量信号，[40]②）。

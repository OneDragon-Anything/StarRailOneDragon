# 武装箱选卡价值升级 迭代设计（总纲）

## 0. 元信息

- 迭代目标：武装箱 4 选 1 装备卡（`decide_box_card`，事件面 E18）价值模型升级——①未锁线时按「输出最需要」通用先验选卡（用户指令 2026-09-12：「没有目标阵容的时候，应该选更普遍用于输出的」）；②打分接入装备库存账的序数感知维（用户质询 2026-09-12：「打分不读当前装备库存——我们 state 里有记录装备的」）。
- 承接出处：`2026-09-12-supply-selection` 迭代 §1.3 装备层两态（裁定 5/6）迁移表中 `decide_box_card` 行的终态提前落地；库存维（组件缺口）的序数切片为**本迭代新增语义**，超出源迭代 §4 v1 结构版的范围。
- 状态：**草案**（对抗审未过，不可派落地批）
- 文档清单：无详设（单文档方案，本篇即完整设计）

## 1. 问题与动机

### 1.1 现状症状（依据 = flow.py:654-702 直读 + 2026-09-12 本会话全链盘点）

现行 `decide_box_card` 打分（CwFlowStrategy 默认实现，mandate_v1 未覆写）：

```
score(name) = 100 if name ∈ target_comp.key_equips        # key 直击
            + 30  if name ∈ key_equips 的 recipes 材料    # 两跳材料
            + material_value(name)                        # 材料通用性手表 0-7
            （effect_pick_bias 恒 0，占位）
argmax，无信息 fallback idx=0
```

三个 gap：

1. **未锁线盲选**：`target_comp` 为 None 时只剩材料通用性分，四张全表外件（通用性 0）恒选第 1 张——通用输出装（火力风暴潮 6 分档的乘区件）与纯垃圾件同分，输出先验完全缺位。
2. **锚定错位**：key 消费 `state_of(session).target_comp`——P1 期过渡配方对物化的伪 comp（源迭代详设 §1.3 自证同款辖域错位，T-155 判例；P1 配方锁帧 locked_comp 恒空，flow.py:405-410 注）。过渡线的关键装备被当终局关键装备 +100 提权。
3. **库存维零感知**：打分不读装备库存——库里有某 key 配方的另一半材料时，选这张卡 = **立即合成拿到 key 装备**（近兑现），与「单纯一件原料」价值档位不同，现行打分不可区分。库存数据本身在册（见 1.2）。

### 1.2 「为什么以前不读库存」——归因（回答用户质询，治本核验对象）

库存账一直在：`session.last_owned_equips`（cw_strategy_session.py:167）由两条写端维护——①观察采集写端全量重写（prep_actions.py:411、:571-577，`read_equips` SIFT 逐件实名）；②效果增量（买牌 +、开箱选卡 +、穿戴 −、卖角色返还 +，cw_exec_state.py:279-282 / cw_op_buy_cards.py:1170 / cw_op_equip_all.py:139-171 / _overlay_confirm.py:42），并有期望态对账网审计（compare_equip_expect）。**不读的原因不是数据缺失，是打分形式缺失**：

- 「囤了 k 件后这件材料还值多少」的数值边际模型 = P42 组件缺口参数化（近兑现距离 × 边际），现只有序级结论，绝对值等 λ 标定（源迭代详设 §4 直读 P42_VALIDATION：④门未检验、λ 🔴）。零调参宪法禁拍值（strategy-work §1：每个数字要么规则推导要么显式模型估计）——没有模型就给库存感知定数值 = 违宪，所以旧打分干脆不读。
- 源迭代把这个维度立了案（组件缺口维度，v1 只入结构半部「key 材料 +3」，数值半部挂账双前置 = λ 标定批 + owned 读数接线）。
- **本迭代补第三条路**：序数形式。库存感知里真正可零参数推导的部分（近兑现 = 立即拿到 key 装备，见 §2.3 推导）用**档位升格**表达——档序可证、不需要绝对值、不需要 λ。数值半部维持挂账，不因本迭代解锁。

### 1.3 根因归层

语义层：价值模型缺「库存序数维」（近兑现与原料不可分档）+「统计先验 vs 锁定契合」未分态 + 锚定错位继承自 target_comp 伪 comp。

### 1.4 明确不解决（防范围外溢）

- 数值边际（计数加权、通用件边际递减）：维持源迭代 §4 挂账，双前置不变；
- `decide_planner` / `decide_supply` 的 target_comp 锚定：源迭代 OQ-3 / P-3 辖域；
- 装备穿戴面（cw_screen_equip_pick）stash 移除：源迭代 P-1 S13 辖域；
- `effect_pick_bias` 偏置通道：维持恒 0 占位；
- 未锁态消费材料通用性的去留：裁定 5 辖域已裁「box 消费不变」（源迭代 §7），本迭代不翻案。

## 2. 方案

### 2.1 共享机器（前置，吸收源迭代 P-1）

打分依赖 `kernel/cw_equip_value.py` 三件套（源迭代 landing.md §3.1 全量范围照执：`EQUIP_GENERIC_VALUE` 逐值平移 + `equip_material_generality` 注册表化 + `key_fit_names` + 六消费位重接）。本迭代对机器**接口扩一项**：

```python
def key_recipe_pairs(key_equips) -> dict[str, tuple[tuple[str, str], ...]]:
    """key_equip 成品名 → 其全部合成材料对（EQUIPMENTS.recipes 平移，缺名 → 空对）。
    【注·注册表】recipes = 配方元组的元组，每条 = (材料a, 材料b)（flow.py:675-680 r130 修正注）。"""
```

`key_fit_names` 改为由 `key_recipe_pairs` 派生（keys ∪ 全部材料对成员）——同一推导单一源，源迭代消费位（supply +10/+3、equip_pick 子串集）签名与语义不变。对拍锁 V4 防两路漂移。

### 2.2 打分器总形：序数分档制（档位优先，档内基分）

**档位字典序取代加法制**——`decide_box_card` 打分改为按 `(tier, base)` 字典序取最大（并列取 OCR 从左到右序，即现行取先语义）：

```
tier(X) = 3  若 X ∈ key_equips（锁定阵容关键装备直击）
        = 2  若 near_redeem(X)（近兑现，已锁态限定，定义见 2.3）
        = 1  若 X ∈ key_fit_names(key_equips) 材料（两跳原料）
        = 0  其余（未锁态全部落此档）

base(X) = equip_generic_value(X) + equip_material_generality(X)
        # 通用输出先验 0-6（cw_events._EQUIP_VALUE 平移表）+ 材料通用性 0-7
```

- **未锁态**：key_equips 为空 → 全体 tier 0 → 纯 base 排序 = 通用输出先验 + 材料通用性。这就是「更普遍用于输出的」：火力风暴潮(0+6) > 反重力皮靴(0+5) > 以牙还牙甲(0+4) > 幸运星(3+0)。材料通用性保留 = 裁定 5「box 消费不变」（源迭代 §7 在册裁定）。
- **已锁态**：base 照算，档位表达契合层级。
- **加法制 → 序数制的等价性**（零行为漂移的改写）：现行加法三档的值域 = 直击档 ≥ 100+0 = 100、材料档 ∈ [30, 30+13] = [30, 43]、通用档 ≤ 0+13 = 13——三段区间互不重叠且按 100 > 43 > 13 分离，故「每一直击 > 每一材料 > 每一通用」在加法下恒成立；同档内加法分 = 常数 + base，随 base 单调，序同 base 序。因此对**现行全部档位组合**，`(tier, base)` 字典序与加法 argmax 逐点同序。此等价性由回归帧锁钉住（R1，landing 阶段 2）。tier 2 为本迭代新增档，无对应加法旧值。

### 2.3 近兑现档（tier 2）定义与推导

**判定**：`near_redeem(X)` ⟺ 已锁态 ∧ ∃ key_equip K、∃ 材料对 (A,B) ∈ `key_recipe_pairs(K)`：

```
X ∈ {A, B}  ∧  ledger.count(X) == 0  ∧  ledger.count(另一侧) ≥ 1
```

`ledger` = `getattr(session, 'last_owned_equips', []) or []`（list[str] 含重复，`.count` 取件数）。

**条件语义**：`count(X)==0` 保证选 X **新创造**一对材料（若 X 已持有且另一侧 ≥1，配对已可合成、选 X 只是第二份 → 留在材料档）；`另一侧 ≥1` 保证确实只差这一件。

**档序推导**（三段，全部零参数）：

1. **直击(tier3) > 近兑现(tier2)**【推·严格支配】：两档结局同为「K 入库」，直击额外保留伙伴材料（近兑现消耗它），结局集严格包含 → 直击恒不劣。字典序 + 档位分离使该支配**结构成立**（不受 base 干扰——这正是弃加法制的原因：若近兑现并入 +100 加法，base 项可把它顶到直击之上，破坏支配方向）。
2. **近兑现(tier2) > 原料(tier1)**【推·单调性】：近兑现 = 立即拿到锁定线的 key 装备；原料 = 向该目标推进一件。立即交付 ≥ 延后交付（发展优先默认，00_framework；同族锚 = 裁定 3「角色 > 装备质量」的强形态推导式）。
3. **原料(tier1) > 通用(tier0)**：现行 +30 > base 极值 13 的既有语义，序数化平移，非新裁。

**边界情形裁决**（实现者无需再设计）：

- X 同时是另一 key 的成品与某 key 的近兑现材料 → 取 max tier = 3（直击优先）；
- ledger 显示配对已完整（两侧各 ≥1）→ 不升档（K 本已可合成，选卡不新增 K）→ 留 tier 1；
- ledger 空/失真 → 自然落 tier 1，**等于现行行为**（保守向退化：漏提权非错提权，同源迭代详设 §1.4 fail-closed 口径）；
- 多个近兑现并列（不同 K 的材料对）→ base 仲裁，再并列取先。伙伴通用性最小化等更细仲裁**不做**——「伙伴材料的机会成本 ≈ 其通用性」是代理假设，无推导背书，做了即拍序。

### 2.4 锚定两态化

- 锁线布尔与锚：单源 = 源迭代详设契约 3——锁线 ⇔ `ist.locked_comp` 非空；锁定 comp 解析 = `get_comp(ist.locked_comp)`；key_equips = 锁定 comp 的 `key_equips`。flow wrapper 内 `self._ensure_intention(state_of(session))` 解析（decide_invest 先例 flow.py:507-513），strategy 契约签名不变（cw_strategy.py:206-208）。
- **target_comp 伪 comp 项移除**：现行 ①③ 项（+100/+30）的锚从 `state_of(session).target_comp` 切到 locked_comp 两态。P1 配方锁帧 locked_comp 恒空 → 自然落未锁分支（ADR-0357，源迭代契约 3 注）。
- fail-closed：locked_comp 非空但 `get_comp` 解析失败（注册表漂移）→ 按未锁态打分 + 日志哨兵（保守向：漏提权非错提权；源迭代详设 §1.4 同款）。

### 2.5 库存数据源 = state，直接消费

近兑现判定读 `session.last_owned_equips`（备战观察维护的装备库存账），**用最近读取的数据**，决策时点不引入新采集。账的构成：全量 SIFT 重写（观察采集写端，prep_actions.py:411、:571-577）+ 建模效果增量（买/开箱/穿/卖/确认入账），并有期望态对账网持续审计。既有决策消费先例 = mandate.py:1647 m7 可穿面谓词、entry.py:665 持有快照——本设计与先例同源同风险位。

防御注记（对抗审预防，非决策障碍）：在册裁定「发射位吃 last_owned_equips 陈旧快照 = 把陈旧数据源合法化」（prep_actions.py:211-216）辖的是**穿戴场景**——那里执行帧可以现读（read_equips 对装备区可见），现读严格不劣，故禁发射位吃快照。开箱场景 overlay 物理遮挡装备区，决策时点不存在现读通道，选择集是 {state 账, 盲选}；且决策与执行同一瞬间（`_open_box` 同动作选卡闭环，prep_actions.py:986-1031），该裁定针对的「发射后执行前漂移」失效面在此结构不存在——本消费不与裁定冲突。账失真的退化方向保守（2.3 边界第三条：漏提权非错提权）；新鲜度时间戳门（只信全量重写后的账）列为本迭代非目标，实机判读发现失真致错选再立项。

### 2.7 sim 可观测性声明（A/B 纪律前置申报）

本批改判据层。生产路径 sim 可见性**取决于 sim 武装箱选卡是否走 `match.strategy.decide_box_card`**——FakeMatch 的 PickBoxCard 分支（fake_match.py:592-593）与选项抽选池（rules.py:178）在库，选卡决策路由实现期核实：若 sim 内嵌默认选卡不经策略，则两态化/近兑现档在 sim 结构性不可见（须如实申报「结构性无帧」，禁把盲区读数当零值证据）；若经策略，还须确认 sim 会话的 `last_owned_equips` 与 `st.equips` 同步在场，否则近兑现档在 sim 恒退化（同样构成盲区）。A/B 仅作落地后确认，不构成数值裁决权（strategy-work §3）。

## 3. 关键取舍

| 备选 | 为何放弃 |
|---|---|
| 近兑现并入 +100 加法档（复用直击常数） | base 项可把近兑现顶到直击之上，破坏「直击 ⊇ 近兑现」严格支配的序（2.3 推导 1）；字典序分档制使支配结构成立 |
| 近兑现设独立常数（如 60，ADR-0524 定序族） | 字典序制下档位即序、无需常数载体；(tier, base) 与加法制在既有档位上逐点同序（2.2 等价性），改写零漂移且零新数 |
| 库存感知采用计数加权（k 件递减边际） | 数值边际模型 P42 绝对值等 λ 标定（源迭代 §4 双前置未决），任何计数系数 = 拍值违宪；序数切片已捕获零参数可证的全部收益 |
| 未锁态纯输出先验（去材料通用性） | 裁定 5 辖域已裁「box 消费不变」（源迭代 §7）；材料是唯一进合成系统的物件，囤料维在箱场景仍有真实价值；翻案需新裁定非本迭代职权 |
| 近兑现仲裁加「伙伴通用性最小化」次序 | 「伙伴机会成本 ≈ 通用性」是代理假设无推导；多个近兑现并列时任意确定性取先可接受，禁拍序 |
| 选卡时现读装备区 | overlay 遮挡，物理不可读（2.5）；效果维护账 + 保守退化是当前唯一合法信号源 |
| 把 box 行为变化塞回源迭代 landing 的 P-1/P-3 | 源迭代 P-1 明文「box 行为等价」、P-3 辖 decide_supply——box 行为变化在源阶段划分中无归属（盘点结论），外溢面自成新迭代（iteration-design §1.1），禁改源迭代收尾清单 |

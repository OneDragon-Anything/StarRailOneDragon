# 遭遇选档简化 迭代设计（总纲）

> **状态：对抗审中**——总纲留骨架与裁定汇编，数学单一源 = details/encounter-criterion-spec.md。哲学锚 = 用户裁定「发展为主，只要发展好了必然通关」——HP 的未来影响不进遭遇决策（README 裁定 3）。

## 0. 元信息

- 迭代目标：遭遇节点选档（事件面 E3）判据简化——废除「胜率 × λ 复利」框架，改「输出估计 vs 需求线」比大小；顺带解锁未成型期高难刮皮收益（现行恒低难系统性放弃）。
- 状态：对抗审中
- 文档清单：details/encounter-criterion-spec.md —— 判据数学（能力态分级/双值可及性不等式/经验档层）/数据通路/EV 核处置/锁表 W1-W14/阶段 E-1..E-4
- 依赖：判据同会话闭环零外部依赖（读源 = GameState 结算观测环 + 遭遇经验表，E-2 新建，details §8）；跨局标定/经验持久化为新增采集面（如实申报）

## 1. 问题与动机

### 1.1 现状

生产判据 = mandate EV 核（ADR-0536 双 provisional 槽 None 期）→ **恒选最低难度、零刷新**。其设计前提 = 把每场掉血折算成「对未来死亡风险的影响」（λ 复利）再与奖励定价比较——该前提被用户裁定否定（README 裁定 3：发展为主，发展好必然通关；HP 是下游表征非决策面，[39] 同哲学）。且 EV 核的胜率标定存在冷启动死锁（恒低难 → 高难样本永远为零），机器事实上永远无法开闸。

### 1.2 根因归层

语义层：遭遇的真实机制是**伤害进度达标制**（[27] + 外部攻略互证，combat.md 已录）——奖励看「输出够不够得着低保线」，掉血罚金看「差多少」。而现行判据建模的是「二元胜负概率」——**建模轴与游戏机制轴错位**，这才是需要胜率表和复利的根因。换轴后概率机器整体不需要。

### 1.3 解决到哪 / 明确不解决

解决：§2 判据换轴 + mandate EV 核处置 + 奖励预览补采。

明确不解决：①低保线数值定义的定谳（实采批，采集点在册）；②decide_planner 等同病灶（OQ-3 已登记于补给迭代）。

## 2. 方案

### 2.1 判据骨架

```
窗口 W = 按节点类型过滤的最近两场已结算普通战斗
能力态 κ_S ∈ {足量, 边缘, 不足}（敌方通道标尺：killed + 进度填充率，零自由常数 + 删失归态）
可及(t) 分域（判据本体单一源 = details §1 分域式）：
  Δ 有源档（其一~其四）⟺ κ_S ≠ 不足 ∧ (κ_S ≠ 边缘 ∨ t ≤ 其二) ∧ scaling(D_win)/scaling(D_enc(t)) ≥ f_min ∧ 经验档层裁决（空证据弃权不否决）
  Δ 无源档（其五/其六）⟺ κ_S = 足量 ∧ 经验档层该档过线正证据
选档 = 可及集内 (档位主序, 奖励 tiebreak) 最大者；可及集 = ∅ → 最低档 + 刷新逃生阀
暗装态（= §9 开闸门未全过 ∨ D_enc 无现场真读 ∨ 窗口无可用 D_win 行；触发全集单一源 = details §9）→ 恒最低档 + 零刷新（暗装锚，与现行行为逐位一致）
```

判据数学 = details/encounter-criterion-spec.md §1-§5：能力态三分级（**敌方通道标尺**——裁定 2 字面「敌方血量消耗」，killed + 进度填充率对称中点，零自由常数；删失归态仅统计败局帧；P/B 掉血分量已授权（裁定 6）但 v1 不消费，契约 5 宪法对账）、可及性双值不等式（D_win/D_enc 同为备战帧**现场真读**旗牌读值——D_enc = 决策时 GameState 现存值 + Δ_t〔读点归属两假设未定谳——判 (i) 遭遇自身旗牌 / (ii) 前一普战写入 + 净值，定谳义务 details 契约 2〕，同读链口径一致；真值缺失 → 弃权暗装，**不经 cw_difficulty_account 解析合成**）、值域其一~其六（其五/六仅经验通道）、经验档层交集语义（v1 局内 scope，数据点产出端锁 W13；空证据 = 弃权不否决——冷启动死锁不复存）、窗口规则（type-based + 案例走查）。

### 2.2 数据源

| 量 | 来源 | 状态 |

| 窗口两场结果（killed/进度填充率） | GameState 结算观测环（E-2 新建，深度 10；写端 = RoundOutcome 构造唯一点三路过守卫者入环，同场去重合并） | 新增状态结构；跨局持久化缺位（写端退役）→ 收窄局内 scope，跨局挂账 |
| 窗口战斗难度值 D_win | RoundOutcome 扩字段 `difficulty_node`（E-2 补，备战帧旗牌快照） | 新增字段 |
| 遭遇决策 D_enc 读值 | 决策时读 GameState 现存值（前一普通战斗节点备战帧写入；净值语义见 details §3） | 现役 |

### 2.3 mandate EV 核处置（单一接线方案）

- **接线 = kernel 新函数 + bridge 改投**：新判据落 `kernel/cw_encounter_selection.py`；`MandateV1Strategy.decide_encounter` 改投新函数；`cw_events.decide_encounter` 基线核原样保留为历史对照；EV 核保留禁删 + 模块头搁置注释（指针 = 13_pick_family E3 行正本 + 替代语义，**禁引 changes/ 路径**；ADR-0536 已退役删除——用户命令 2026-09-12，现存代码注释引用随本批清理）；
- 死分键（encounter_ev_*）消费面盘点 + f_min 注入通道与 EV 核双 provisional 槽物理隔离 = E-2 交付义务。

### 2.4 零调参对账（宪法第 4 条自查；深化批逐数执行）

- 方案内**无任何调参量**（人拍校准值零个）；
- 输出估计 E = 观测量（结算屏三项已采直读），零参数；「窗口 = 前两场」为判据结构选择，深化批给论证（非可调旋钮）；
- 需求线判定 = 双值比 `scaling(D_win)/scaling(D_enc(t)) ≥ f_min`：D 两值同为备战帧旗牌真值（D_enc = 决策时 `BoardState.enemy_difficulty` + Δ_t，同源零口径差，无解析合成）；f_min = 单标定常量【拟】（01 §6 登记 + owner/期限 = E-3 义务）；g 底数 1.052【拟·旧口径，CI 缺口如实申报】，配置表落定升【注】；Δ_t =【拟·外部攻略互证】，其五/其六无源 fail-closed——**开闸门 = 三常量 ∧ 进度条语义（两假设+方向维度）∧ D_enc 读点归属定谳 ∧ 环完整性对账不对齐 = 0 ∧ fill 读取率达标 ∧ D_enc 现场读命中率达标（单一源 = details §9）：任一不满足 → 维持暗装**；
- 奖励 tiebreak = 选卡屏奖励预览 OCR 直读（游戏定义内容）；
- 深化批义务：每个进决策门的数标注三形态（【注】/【推】/【拟】），答不出出处的按未证即退役处置。

## 关键取舍（初稿已定）

| 备选 | 为何放弃 |
|---|---|
| λ/EV 核继续等标定开闸 | 冷启动死锁（高难样本永远为零）+ 前提被裁定否定（HP 未来影响不作决策面）——等也等不来 |
| 保留 λ 核做「可选精细化」 | 与 [39] 哲学冲突的复杂度不该留着诱惑后人重启；代码搁置保留、文档挂「前提被否」，重启需用户新命令 |
| 判据轴继续用「二元胜负 + 胜率」 | 与游戏真实机制（进度达标制）轴错位——根因（详 §1.2） |
| 未成型期恒最低难度（现行） | 系统性放弃外部攻略明示的合法收益（未成型也可刮皮拿高难奖励） |
| 挑战进度增量 ±N 进判据 | 两份战败样本符号相反（M41 −22 vs P2r1 +2，economy.md:137），语义未定谳——只随行采集不进判据；填充率为另一归一通道（details §2），已进判据 |
| 缺口用绝对阈值分级 | 拍值；填充率对称中点零常数（details §2） |
| P/B 掉血分量进 v1 判据 | 授权已获（裁定 6，例外扩大程序完成），v1 选型不用：敌通道胜局帧覆盖更优、填充率归一零漂移；P/B 入环保存作升级量——details 契约 5 |
| D_enc 解析合成（cw_difficulty_account） | 合成机制在册但成分缺口 + 零现役接线；待接正成分漏计 = 乐观向偏差不可控；与 D_win 不同源——真值路径零缺口（details §3） |

# 实机运维细则(单跑道 / 局间交接 / 监控 / 运行坑)

> SKILL.md §实机运维 的展开。读者 = 智能体;操作对象 = 本项目的 CW MCP 工具链与游戏画面。

## 启动与重启

- 启动对局:MCP `run_standalone_app`(app=`currency_war`);进度 `get_run_status`(state/current_node/retry);停止 `stop_run`(信号式,当前节点完成后退出——发完信号游戏可能还在打,等自动战斗结算再动画面)。
- 改代码生效路径 = 重启 MCP server(经 daemon 的 restart 工具;**对局运行中它按守卫拒绝重启**——先 stop_run 等结算)。重启后客户端按 harness 约定重连(项目级 servers.yml strip/restore toggle,见全局工作指令)。
- 重启代价:对局丢、session(target/信号/失败记忆)清零——重启后首局 target 重选是已知断档,判读时别把首局异当回归。
- 改动攒批纪律:局中不改代码;一局跑完(或早停)再重启加载。

## 局间交接序(停局后到下一局开跑)

1. 停局(stop_run)→ 等自动战斗结算(游戏停后会打完当前战斗)。
2. 残局清理(SKILL.md §实机运维 的清理序;遭遇/投资 overlay 多半要先进后出——「返回备战界面」→ ESC 中断)。判定每一步用 `analyze_screen`,认 screen 名不认感觉。
3. `analyze_screen` 确认**货币战争-大厅**精准命中。
4. 重启 MCP(有待加载代码时)→ 重连。
5. 哨兵重武装:删旧哨兵位置文件(cw_sentinel.pos)再起新实例(单实例纪律——先查 job/进程列表确认旧的不在);**不删 pos = 读旧水位误报**(2026-08-22 局47 实证:命中 2 小时前旧局 ERROR;root cause = 没按本条走)。重挂定时轮询时更新提示词里的当期判读重点(过期提示词会误导)。
6. 起新局。

## 残局画面清单(按 screen 名)

- 货币战争-结算(「继续挑战」按钮;此屏 HP 为战后台作真值)
- 货币战争-备战(含开商店/装备详情子态;ESC 弹中断)
- 货币战争-中断挑战弹窗(「放弃并结算」)
- 货币战争-挑战失败(「下一步」;可能两页)
- 货币战争-遭遇节点(先点卡选择难度,再底部「选择」;「返回备战界面」右上)
- 货币战争-投资策略/投资环境(「返回备战界面」右上,别硬选)
- 未建档/不确定画面 → `analyze_screen` 先行;仍不明 → 按 od-dev-screen-onboarding 建档流程处理,别盲点。

## 监控栈(长时自主推进)

- 三层:①进程内哨兵 flag(`.debug/temp/currency_war/*.flag`,停机钩子按 od-dev-stop-hooks 处理);②后台哨兵脚本(tail 日志,命中高信号事件即 exit=推送;只报需介入的事件,水位去重);③定时轮询兜底(轮到必执行:run 状态+哨兵存活+进度对比)。
- 哨兵单实例纪律:重武前确认旧实例已退出;双哨兵 = 重复报警+双倍开销。
- 轮询提示词定期换血:提示词里写死的「当前局 N=某修复首验」会过期,误导后续判读。
- 用户要用电脑 = 全停实机(哨兵+定时+run),别抢鼠标。

## 运行坑(高频)

- 结算屏残留 → app 启动死循环:起新局前必须确认大厅态。
- CW op 无条件 ESC 禁忌:备战屏 ESC=中断挑战弹窗;关面板用面板内控件。
- 奖励球/补给箱占备战席:席满时球点不动,先开箱腾席。
- **升等级破墙**:bench-full 警告阻塞出战 → 点购买经验升等级清警告解锁;无 gold 时卖角色(drag bench→左出售区)。
- **事件长尾**:肉鸽事件十余类(锁定备战/巨星强化/投资变体/遭遇/补给/详情弹窗),处理模式=边玩边重构(loop 卡→读屏→加 handler→再跑),别试图一次枚举全。
- **角色/阵营识别边界**:商店 OCR 角色名是主路径;SIFT 立绘库对脸部独特角色可靠、配饰/半身不可靠;阵营激活数以实机 OCR 左面板为准(别硬编码,跨版本会变)。
- 部署上限随投资环境/宝钻动态变(槽位档不固定):别信固定槽位数,读实际 cap;未实拍槽位档触发采集信号时按其 verdict 处理(别静音)。
- 画面识别结论有边界:`analyze_screen` 只返回已建档内容(未建档元素静默漏)——行为异常先查日志定位环节,再走画面入口序;VLM 只补漏,不当第一入口。

# 货币战争开发·维护·自主推进

> 读者 = 无会话历史的干净智能体。本 skill 是 CW 的操作手册:知识在哪、按什么纪律改、用什么验证、实机怎么运维。**没做完下面 8 步不算一轮完成。**

## 必做 checklist(每轮开发循环)

1. ☐ **读进度树 + 确认运行前提**:`.debug/temp/currency_war/cw_dev/进度.md`(运行时状态单一源,本 skill 的操作对象)对齐当前焦点;会话起点再确认 CW app 在应用列表、游戏窗口有效。**必做**
2. ☐ **查钩子痕迹**:`.debug/temp/currency_war/*.flag` + 哨兵/后台通知——有停机 flag 先按 `od-dev-stop-hooks` 处理并删 flag,再继续。**必做**
3. ☐ **判读上局遥测**:CW 遥测 CLI(§判读)找**不合理**处;判读结论写进进度树再动代码——单局数据≠结论,跨局对照+声明数据边界。**必做**
4. ☐ **改策略前读文档**:user_playstyle 全文 + strategy/README 入口序 + 相关 as-built 篇(§单一源地图)——回答「改动违反哪条既有原则/落在哪一层」。**必做**
5. ☐ **设计先行**:落点函数/影响消费点(含测试锁)/预期行为变化/验证法,写清再动代码——「现象→定位函数→改」缺设计层是常犯病。**必做**
6. ☐ **按反馈梯度验证**:ruff → 单帧锁测试 → 全量(**= `uv run pytest sr-od-test/` 根级,含根级 test_cw_*.py 旧锁;`sr-od-test/test/` 子目录不算全量**——曾因子目录冒充全量致多条锁漂移长期存活,实证见 design/decisions/) → sim 批量对照+回放对拍 diff → 实机(§验证工作台)——**禁止跳到实机试错,禁止 sleep 等实机**。**必做**
7. ☐ **行为变更三同步**:ADR(why)+ strategy as-built 正文(语义)+ 代码注释引 ADR-NN——commit 前完成(§文档同步)。**必做**
8. ☐ **实机局判读锚点事前写**(预测什么会变),跑完核对;无信息量局按早停判据停(§实机运维)。**必做**

## 判读(遥测 CLI,数据判读同源)

**判读前置三问(硬门,2026-08-25 五局误判教训;答不出不判读)**:
1. **该位面的目标是什么?**——P1=[28] 50 金通关+形态白名单内+过渡核心 2★([13] 成型停手线);**HP 从来不是 P1 验收**([2] 可卖血/[18] hp=报警)——拿 HP 当验收=目标函数错,过程指标再准都是精确地错。
2. **这局锁的什么线?**——四体系过渡(transitions 开局分级:拿到逆天投资策略才配锁直通线)or 直通终局线?锁直通却没直通条件=P1 板面零伤害引擎([27] 罚款吃满)。
3. **板面在不在白名单?**——power_baseline P1 形态表(仙舟3+DOT2/列车4 等,784 篇验证);不在表内的形态(如纯经济凑数位)不是「体系长成了」。

**任务→文档组合路由**(判读/策略工作的必读组合,单一源与完整表=research/README「任务路由」节):判读一局→playstyle[28][18][27]+power_baseline+transitions §1;改买入/锁定→playstyle 全文+transition_combos+transitions+economy;改评分/经济→playstyle+economy;掉血归因→playstyle[27]+combat;换阵/装备→playstyle[21][24][29]+combo_methodology;终局设计→final_comps/+plaza_methodology;阶段转型→transitions 换血点+playstyle[26]。**只读一篇=读局部**(五局误判实证)。

```
uv run python -m sr_od.application.currency_war.cw_telemetry query --recent N [--run ID] --view rounds|supply|anomalies|hp|economy|all
```

- rounds=逐轮 hp/gold/买/board;supply=全波牌面 vs 购买;hp=掉血×板深;economy=金轨迹/滞留;anomalies=异常标记。
- **生产局秒级自检**(checks 子命令):`cw_telemetry checks --recent 5`——逐局判栈(v2 栈跑 coldstart 检查,default 栈跳过),违规带 run_id 溯源;sim 批次侧等价物 = simulate_p1_batch 默认内嵌的 checks_violations。检查器自身由测试仓变异自检锁钉死(去门变异必须涌现违规)。
- **别为复盘写一次性脚本**——新复盘需求 = 新视图/查询参数;确需脚本用完即删。
- 每局跑完**必做**局后判读:异常条目当场定位根因(查 log + supply),定位不了不准进下一局——异常跨局存活 = 回归在累积。
- 结论必须声明数据边界(如「基于进店帧,refresh 波不可见」);边界不够先补遥测字段再下结论。
- **数据源注释 > 采样凑证(2026-08-23 三次同族事故沉淀)**:任何「X 是什么/有没有 Y」的疑问,**先查注册表/常量文件的 docstring 与采集溯源注释**(如 cw_shop_odds.REFRESH_PROB 的 L16 写明「游戏内概率表实机 OCR,无位面维度」),答案已在则直接引用——**不要**先跑采样/派 worker/提「待实机核实」。历次批间互证沉淀的实证(明细见 design/decisions/):①真值表早已在档仍派 worker 重采白跑;②本可 docstring 一步出答案的疑问,先跑了两局采样凑证吻合;③机制归因未先查 docstring,压测官自查后自纠。**消费侧对偶**:派单规格里的每个「现状是 Y」断言、压测报告的每个「待核实」建议,同样先过 docstring 这道门。
- **数据治理(读侧边界声明的写侧对偶;用户定调 2026-08-23:发现旧数据是错的——能修复就修复,不能修复就删掉,免得误导未来的自己)**:①先定界污染窗口(从采集 bug 引入的第一局起,不是发现日);②判修复/删除——真值可从别的源重算(如 decisions 逐轮行重算终值/日志回填)→修复,真值从未被捕获→删除,判不了先隔离标注别在判读里裸奔;③派生物必须再生(replay 语料变了→Δ池快照重跑生成器、依赖它的 sim 基线作废重记);④留证≠留语料(事故证据=日志/截图/sentinel 保留;删的是分析语料行;删除动作与理由记进度树);⑤防再犯——修复落写端 schema,别靠一次性手工回填(手工回填漏网=下一轮伪值)。动手前先核语义:`loss+final_hp=100` 可能是放弃局合法值(中断保留当前 HP),不是伪值——把合法数据当脏数据删,比留着脏数据更糟。
- 改动效果对照:改策略后下一局 `--recent 5` 并列对比(测试绿≠实跑行为对)。
- 日志跨 run 累积(append+轮转,重启不销毁证据):查旧局按时间窗 grep;需关注行检索 `grep [cw!]`(漏检/未建档/顺序异常);格式标准单一源在 strategy/05 §6。
- 旧自主推进代码带 `# 未验证` 注释:进对应画面复审(重点补日志/截图让每步可观测)后删注释才能信——复审是义务不是可跳的。
- **阵容质量 = 三维**(羁绊档位 × 角色构成 × 装备分配)——只看羁绊 = 空壳盲判(羁绊够但核心不在场/装备乱用都看不见;数据在 state.deployed[].star/equips 里,别被视图边界限制)。
- **复盘要全面,观察面是全量**(用户定调):站位/经验节奏/商店供给/投资策略环境等 32 个 GameState 字段各对应决策消费点——按 telemetry-reading 的观察面清单逐主题过,不是只看最显眼的维度;视图没显示的直查 jsonl,采集恒空的字段按缺口清单心里有数。
- 反例论据(为什么严):历届单点断层各自存活 3+ 局才被抓、把单帧牌面当全序列误判健康线弃线——详见 design/decisions/ 对应 ADR。

## 验证工作台(反馈梯度,按成本升序;分层验证:L1 快速集=`uv run pytest @sr-od-test/cw_quick.txt`(~3min,CW 域)/L2=L1+受影响域点名/L3 全量=`uv run pytest sr-od-test/`(~5min,**仅 commit 前一次**))

实机一局按数十分钟计,是**最后一步**;实机运行期间 = 做 1-4 的窗口,不是等结果:

1. **文档对照**(零成本):设计里预期是什么,行为偏离了哪条。
2. **sim 批量**(秒级):`cw_sim.py` 的 P1 批量入口(基线/对照显式 `pool='snapshot'`,跨日对照核池指纹一致),A/B 对照同参数分布(达标占比/败场≤2 占比/均值/方向建立率)。sim 有粒度边界(见下),差异必须解释。**sim 是可深度挖掘的基建**(真代码层同源 + 校准层可注入 + 实机 Δ 池重放):遥测回放对拍/稀有态扫描/参数敏感度/校准层逐维升级——细则见 verification.md「深度挖掘方向」;**实机暴露的策略病按「分诊与回灌」纪律变现成 sim 检查项**(见 verification.md 同名节)。
3. **telemetry 跨局对照**(分钟):历史局同类证据聚合(如「配方满线局才过线」的跨局表)。
4. **单帧锁测试**(分钟):构造 GameState → 断言 decide_prep 输出,进 `sr-od-test/test/sr_od/app/currency_war/`。模拟发现的情况**固化成单帧锁**才算回归资产。
5. **实机**(局级):判读锚点事前写;验收 = 连续多局达标(以当期目标为准)。

**sim 已知边界**:Δ池按深度分桶,±2 深度量级测不出;「散面 vs 集中」维度 sim 战斗层不敏感、可能与实机方向相反——此类维度以实机判读为准,并把偏差记录在案;「sim 上实机前必核代理语义」(曾因代理错位——bench 计数≠上阵——得出数倍级增益伪影,实证见 design/decisions/)。**真实性演进方向(2026-08-23 用户定调)**:校准层逐步换真机制——胜负用真实 outcomes 按成型指标分桶拟合(胜率=f(引擎数));连胜金/利息已接实测真值(cw_economy 单一源)。**「识别噪声注入」不做**:识别漏检/空名槽/误读是实机代码 bug——**噪声来自我们的代码→修,随机来自游戏→建**;sim 假设完美观测是正确终态。

### sim A/B 与多批并行的验收纪律(2026-08-24 战役沉淀,全部有实证)

- **符号先核**:worker 报的「配对差」必须先核**符号定义**(gap=A−B 还是 B−A)再作叙述——历次批间互证拦下过「首超」实为 gap 符号反了的误读(拦的是指挥官转述;实证见 design/decisions/)。
- **三窗纪律**:标定/验收的 seed 窗必须含 **anchor 异族窗**(如 0-29)+两个相邻窗(900000 族)——相邻同族双窗防不住窗族过拟合(相邻同族双窗过线、anchor 异族窗显著反向翻车的实证见 design/decisions/)。
- **v1 臂同进程重跑**:v1 在演进(engine_seed 豁免有实证,见 design/decisions/),跨批引用旧 v1 数字=给移动靶标定;每次配对当次同进程跑两臂。
- **合流总验必做**:多批并行改同一框架时,单批各自验收(底内)≠合流不劣化——历次各批各自微劣、合流劣化放大数倍的批间交互实证见 design/decisions/;每轮并行批收尾后跑合流 n=100。
- **残差逐层下移法**:框架调优的通用路径——通道矛盾→形态域→仲裁→买入面→生成层,每层「诊断归因→定向打→双窗验」;**诊断先排除再打**(攻坚批用「金不够 0 轮/bench 满 0 轮」两零直接排除经济域,省掉盲调)。
- **单源直通不复制判据**:通道迁移(pair/copy/engine_seed)一律 import v1 判据函数,零复制——双源漂移免役;语义迁移时旧锁必须同步语义化(应急锁锁骨架初版副作用、扩集时更新的实证见 design/decisions/)。
- **里程碑叙述纪律**:超越失败者≠成功(「首超 v1」时 v1 本身 P1 不及格)——里程碑只说「架构迁移安全垫做成/行为面持平」,战力目标线另行盯死(hp_ge_60 类)。
- **「无杠杆/等实机」结论必须穷举式**(2026-08-24 两次被拆):「档内细分需实机交叉表」被拆——outcomes.board_before 语料全量在,离线可做;「sim 侧见顶」被拆——转化洞/金充裕/口径耦合全没打。判据:宣布前自问「我是穷举了所有数据源,还是只是想不到下一步」。
- **校准层天花板意识**(战役级发现,实证见 design/decisions/):策略杠杆可能被 Δ 池样本贫困封死(曾见低档桶样本极稀、拟合胜率与实机实测显著背离,高档桶无覆盖)——「策略生效但指标不动」时先查池桶覆盖再改策略;Δ 池扩容是 hp 类一切杠杆的总闸。
- **连环证伪是常态**:历次批间互证拦下过小窗口数字直信、口径伪影(轮数口径错位,实测对不上叙述)——任何批的数字(包括诊断结论)都是下一批的可推翻假设,不是地基。

### sim 压力测试官(常设角色,2026-08-23 定调;同日用户批评升级职责)

派子 agent 对着玩法自由发挥+**系统面清单驱动**(不只随机域:决策架构/数据链/结算层/供给层/观察层逐面过,主动想未出现的问题)。**交付完整性 = 指纹 + 可运行的检查项**(2026-08-23 用户定调「问题较大的应该留下回归」——压测官自己把检查项写进检查网,「设计归 worker」曾致设计大量积压的实证见 design/decisions/;测改分离边界=检查网可改,策略/sim 语义仓不可改)。**框架级症状纪律**:同类问题出现 ≥3 次(如振荡族/通道互踩族)= 必须上升为架构审查立案,不再点修。排程纪律:常设在飞,批间零空窗;心跳=点名制(进度树点名册节)。**压测官的另一职责=批间互证**(历次拦下过前批错误裁决:等级泄漏/死路径/单击价误读/符号误读/「店里没有」类论断——明细见 design/decisions/;**没有批次的结论是不被检验的**,指挥官转述 worker 数字前先核原始口径)。**worker 论断=可推翻假设**(轮数断言、杠杆域断言都被后续批推翻过):压测官选题优先审计前批的主导性论断,推翻与确认同等有价值。

**模拟测试要灵活使用(2026-08-24 用户定调,工作纪律)**:模拟的价值=**在实机之前发现更多问题**——不是等批次的被动回归,是主动的、多样式的进攻武器。灵活体现在:
- **用法灵活**:A/B 对照只是入门——回放对拍(真实局关键帧喂当前策略找行为漂移)/稀有态扫描(构造实机难遇的边界输入)/参数敏感度(哪些参数值得实机精调)/经济对账(sim 模型 vs 实机 gold 差分找未建模收支)——按当期问题选武器,不只会跑 `simulate_p1_batch`;
- **对象灵活**:不只测策略——校准层(Δ池桶覆盖/胜率拟合)、检查网自身(变异探针验证检查非空转)、遥测写端(回放对拍发现写坏的数据)都值得测;
- **时机灵活**:任何改动(策略/校准/检查/遥测)落地后、上实机前,问「模拟里能不能先暴露它」——能模拟到的就模拟,**别拿实机试错**;
- **边界自觉**:sim 已知边界(散面 vs 集中等)以实机判读为准并记录偏差——灵活≠越界,是不浪费时间在 sim 测不出的维度上,把 sim 能测出的维度全部榨干。
判据:实机跑一局发现问题 = 模拟阶段的失职自问——「这件事 sim 里能不能提前暴露?」能而没做=流程缺口,记待办补检查项(「实机暴露问题的分诊与回灌」,verification.md)。

### schedule 体系(自主推进时的提醒网;2026-08-24 定调)

schedule = **提醒,不是指令**——收到后按当期并行度(剩余额度)与任务优先级自行安排派发/串行/暂停,不机械执行提醒文字。七角色提醒网(**创建时刻错峰,间隔互质**;CW 节奏版间隔——局均 40min 定的值守 10min/盘点 15min,其他玩法按自己的节奏定):

| 提醒 | 间隔 | 内容(写角色不写当期细节) |
|---|---|---|
| 值守兜底 | 10min | 监控栈第 3 层(哨兵的哨兵):值守脚本存活+对局/空窗状态+进度对比——最小动作,事件通道(job 通知/哨兵 exit)是主路径,本提醒只兜底 |
| 派发盘点 | 15min | 该用子 agent 干什么了:压测官批间空窗?worker 队列有件+槽空?对抗积压(audit/adversarial*.pos 去重+采信未攻结论)?知识工程机会(逐篇精读/math 待证命题)?积压局未判读?——**产出=派单动作或明确"无需派"记账** |
| 行为校准 | 40min | 反漂移三问(找问题 vs 等结果/轨迹达标/goal 条款违反)——内容固定,防注意力窄化(长轮空转实证见 design/decisions/) |
| 文档对照 | 40min(与行为校准错峰) | 上次判读/方案/调研立项后对照过口述权威吗?**凡对玩法行为做判断/出方案/立项调研/写策略代码——先过 user_playstyle,产出物要能回答「对照了哪条原则/违反了哪条」**;子 agent 派单涉及策略行为面的,检查 prompt 带没带「前置阅读」节(文档路径),没带=不合格派单补发——「不看文档乱改是方法论最大问题」(用户定调,实战反例见 design/decisions/) |
| skill 遵循回看 | 50min | 最近操作映射回 skill 辖域(判读过了三问?派单带前置阅读?)——重点扫「没想到有 skill 管」的操作 |
| 进度对表 | 45min | 迭代入口 vs 实况(下一个待派/判据起数/健康线)+交付验收清单过期项——当场改文件 |
| 深度巡检 | 2h(派 agent 型) | 反馈队列第三方裁决+晋升候选扫描(主会话自审有偏见)——提醒只做触发器 |

判据:提醒预算有限,状态查询不进 schedule(主会话自主查);提醒触发后无活可派=一行记账完事,不硬造工作。**schedule 使用原则(提醒≠指令/错峰/提醒派发不查状态)以个人本地入口文件为准,本文不引用不复述**(skill 与个人入口可能不同 reader,别造跨文件依赖);本文只辖 CW 的七角色编排与间隔。**派单模板硬规范(2026-08-24 用户定调)**:涉及策略行为面的 worker/压测官/调研批,prompt 必含「前置阅读」节(相关 user_playstyle 条目/strategy 篇/ADR 路径)——子 agent 是干净上下文,文档在它世界里不存在,派单不带=它只能凭猜乱来;无前置阅读节=不合格派单。**判定类批加「判据来源」节(2026-08-25)**:任务产出物是判定/分档/取舍的(什么好用/该进哪个池/按什么分档/什么留什么删),prompt 必含「判据来源」节——以效果/机制审查为主体(逐对象过决定资格的机制属性,如技能独立性/触发条件/预热),统计量只作佐证列;倒置(统计主体+效果一句带过)=不合格派单——统计只是快一点的筛选方式,不是知识本体(单卡插件池任务书、fixed/core/flex 按出现率分档两次同根实证)。

## 防坑清单(高频犯过的)

- **逐局打补丁陷阱**:连续多局每局修一个新卡点 = 发散信号(缺的是成型进度类的控制变量,不是又一个单点修)——连续 3 局以上不同根因时,停下来做架构层反思(读 redesign + 三份文档),别修 r(N+1)。
- **测试锁锁旧行为**:改门/常量前 grep 全部消费点含测试断言——很多「不买/不做」断言是旧路径的副作用,不是真语义;预判行为变化清单,逐项判「意图内还是副作用」。
- **叙述≠证据**:「轨迹最佳」「修复链收敛」是故事;真证据 = sim 分布变化 + 锁断言 + 判读锚点事前预测事后核对。
- **生成器分层**:改注册表前查 `tools/cw/` 是否有该文件的生成器(`*_data.py` 数据层勿手编;判断层文件反向标注);改错层 = 被覆盖或双源。
- **新字段进 GameState 查三消费面**:策略(谁读它)/遥测(视图有没有)/**sim 代理**(sim 建没建)——曾见核心维读 deployed 而 sim 不建模 → 恒折扣 → sim 行为与实机分叉(ADR-0219 纪律多次命中,ADR-0233)。
- **新读点查写入端**(对称纪律,死码教训实证见 design/decisions/):加任何「读 session/state 某字段」的代码前,grep 该字段的**写入端是否存在**——曾见槽序表兜底读全仓无写入者的表 = 死码(审计实锤)。读不存在的字段 = 永远走兜底路径,与「字段恒空」同病。
- **局中卡死巡检 = 日志重复度,不是遥测新鲜度**(曾见卡死近小时级才停的教训):遥测只在结算落盘,备战卡死时 hp 视图恒旧——巡检必 grep 近 10 分钟日志,同特征行(「备战席已满」/同一警告)≥10 次且无 buy/deploy/出战 推进行 → 按卡死处理(停局+判读),**不得以「推进慢」合理化**(曾见数十次警告被误判为正常)。
- **修消费端前先验生产端点火**(ADR-0239,同型三轮修不好根因):给某字段加 fallback/修读链前,grep 运行期日志确认**生产路径执行过**(曾见 probe 挂在当前流零执行的节点上=全链死数据)——生产者不点火,修消费端全是安慰剂。配套:**跨天 append 日志的 grep 必须带日期锚点**(日志时间戳无日期,曾把昨日行当今日证据追出「双进程」鬼影;用重启点行号/日期事件分隔)。
- **临时采集钩子会积压**:钩子必须带删留条件;盘点时查 `.debug/temp/currency_war/shots/` 前缀分布与代码内「采完删」标记——样本攒够就离线判读→进真值→删钩子,别让临时变常驻(详 references/data-collection.md)。
- **改完不验旧锁就提交**:提交前三步 = ①grep 消费点与锁值 ②ruff+直接影响测试 ③耦合模块全量一次通过(子集绿是伪安全)。
- **实机学费不复盘 = 重交学费**:实机定位的策略行为病只修代码、不回灌 sim 检查项/单帧锁 → 同类病下次仍靠实机暴露(数十分钟/局);感知/运行时 bug 则相反——归 fixture 帧锁/回放对拍/哨兵防线,别为它扩 sim(分诊判据见 verification.md「实机暴露问题的分诊与回灌」)。

## goal / schedule 自我校准(自主推进时的元纪律)

goal 与 schedule 注入的消息是**行为校准输入,不是背景噪声**——收到即先对照本节自检再动手:

1. **goal 轮开始 → 先过 8 步 checklist**,尤其步骤 4(读文档)与步骤 5(设计先行)——「现象→定位函数→改」缺中间层是最常犯的;焦点漂移(跳过地基直奔策略/全局重构)是 goal 长对话的固有风险,checklist 是锚。
2. **schedule 提醒 → 回答三问**:此刻在「找问题」还是「等结果」(连续观测动作无产出 = 干等)?当前轨迹还达标吗(中期掉血注定不达标 → 早停)?goal 条款哪条在被违反?
3. **做事按 skill 来**:碰 CW 任何工作先调本 skill;画面建档/停机现场/进度记录各走对应 od-dev-* skill——**别凭记忆和惯性干**(长对话里旧 skill 内容会被稀释,重新调用成本远低于偏离成本)。
4. **保持代码架构**:改动落在 redesign 定义的既有层(战力表/线库/规则集/观测/遥测);自创新层 = 偏离设计,停下问「为什么设计里没有这个」;重构优先于打补丁(负责人视角:长期最优)。
5. **文档同步不欠账**:行为变更三同步(ADR/as-built/代码注释)在 commit 前完成——攒 ADR = 漂移,事后补的成本远高于顺手写。
6. **子代理对抗**(ADR-0010):分析类方案/归因结论在采信前起子代理攻击(攻击型指令+实测数据+逐条裁决实验);大改动 review 同理。**对抗的两种触发形态(2026-08-23 用户补全)**:①后置闸门=产出结论后采信前攻;②**决策时对抗=岔路口主动发起**——多方案均能自圆其说/证据不足以裁决/改动影响面大/或自己心里有未验证假设时,把「倾向 X 因为 Y」扔给新鲜上下文攻击(便宜:一次对抗几分钟 vs 错误决策一轮返工);没把握就发起,别硬拍。
7. **每 goal 轮收尾自检**:产出是什么(修复/分析/回归资产,不是「检查了」)?进度树更新了吗?临时文件/钩子清了吗?下轮焦点明确吗?
8. **实机事故修复的对抗审查豁免与补偿**:live 卡死/崩溃的修复可先落地(时间压力),但**下一批 review 必须补攻击**(曾见死锁修复未前置审查——其进展保证的设计点本应被攻击过;实证见 design/decisions/);豁免不豁免验证。
9. **指挥官-worker 执行架构(2026-08-23 定型;防「顺手自己干」偏移)**:主会话=判读/设计规格/派发/证据指针审查/裁决;实现(码+测试+sim A/B)=worker 子agent(自包含 prompt 必含:判读依据文件路径+设计规格+声明文件集+验证梯度+「sim 无改善如实报告」);行为变更采信前过对抗审查。主会话**不写实现代码**——同型偏移两次被用户纠正的实证;「策略线会话已停」时**在场会话即责任人**,别等幻觉中的接手人。
10. **goal 战役化**:goal 目标=带明确完成判据的战役(如「样本≥50 且各桶≥10」),完成即 complete 开新战役;禁开放式「推进 CW」长跑(长轮上下文稀释教训,实证见 design/decisions/)。round 预算耗尽≠战役失败——edit 续轮次或开新战役,完成判据不降。goal 文本只锁不变式,战役状态/判据单一源=进度树「当前状态」节。
11. **空转轮守则(2026-08-23)**:真工作在事件通道(worker 通知/哨兵 exit/schedule 提醒)时,goal 轮醒来无新事件=**最小动作收口**(一次状态查询+必要记账),不重复观测不抢跑;goal 轮是队列空档兜底,不是节奏器。
12. **worker 薄切流水线(2026-08-23)**:厚任务(实现+全量+sim+ADR)反馈回路过长——拆成「实现+锁测试」→指挥官审查→「sim A/B+ADR」两段,每段 10 分钟级;并发预算内(≤2 worker)可并行异文件集任务。段间裁决点=审查颗粒化,进度可见性↑。
13. **哨兵报警消费协议(2026-08-23)**:哨兵/早停的每次 exit 都**不是结论而是待验证事件**——①先判报警与近期自操作的相关性(「人工结束/执行失败」回显=自己 stop_run 的传播尾巴,同型见过即降级消费,不当中断响应);②异常型报警立即核窗口日志+画面再定;③**哨兵自身输出异常(刷屏/格式怪/离谱值)也是哨兵 bug 线索**——读完输出再收口,监控工具的噪声会污染 reviewer 信噪比(曾见刷屏把真警报淹没)。
14. **实机常跑=素材泵(2026-08-23 用户定调)**:实机不只做验收——**持续跑局积累素材,暴露只有实机才遇的问题**(未建档画面/新物品/时序边角/停机钩子触发)。sim 主迭代与实机常跑**并行不悖**:sim 秒级验证策略假设,实机持续产出真问题流+真值样本。判据:「实机暂停等 sim 就绪」仅适用于「实机行为会污染数据/抢修复窗口」的场景;默认态=实机一直跑,指挥官轮转消费实机产出(局后判读/新问题建档/样本点账),值守栈(哨兵+早停+runs 断流)常伴。
15. **数学期望是策略争议的统一标尺(2026-08-23 用户定调:「数学是不会骗人的」)**:策略分歧(该不该买/多激进/收紧还是维持)**不靠直觉吵——指向 `docs/game/currency_war/research/math_proofs.md` 的对应命题条目**:已证的直接引用结论裁决;没证的立项去证(命题+证明路径+数据源标注,进证明集的「待证明」节),证据到位才裁决。口述直觉是命题的来源(用户给方向),数学是裁决的依据——**先证后裁,不先裁后证**。

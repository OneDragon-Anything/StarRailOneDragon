# key-items-retirement 迭代设计（总纲）

## 0. 元信息

- 迭代目标：`Comp.key_items` 整字段退役（用户裁定，2026-11-05 字段冗余排查会话：过渡体系已统一承载 P1 过渡知识后，终局条目不应再夹带过渡逻辑；本篇为该裁定的完整设计）。
- 状态：定稿（对抗第 1 轮 11 攻击点全数处置——处置明细见 attack.md 与本篇修订；收敛判定沿 attack.md「修订后可定稿」）
- 文档清单：（无详设——单文档方案，本篇即完整设计）

## 1. 问题与动机

- 现状症状（三条，均为可复核的存量事实）：
  1. **88% 数据行零行为**：全库 66 行 key_items 数据中 58 行的成员 ∈ `carry_set`（= `carry_anchor` ∪ `core_chars`），在全部三个消费点被集合运算减光——证据分 `skeleton_hits = (key_items ∩ held) − carry_set`（line_select.py `line_score_breakdown`）对 core 成员恒空；插件档排除（`− key_items`）对已被 carry 排除者无效果；货架资格并集（`carry_set ∪ key_items`）对已在 carry_set 者零增量。复核方式：任取一条 core∩key_items 行代入三式即证。
  2. **8 行活数据经全局对照：7 行趋零/可替代 + 1 行实质损失**：与过渡体系（`TRANSITION_BONDS` 五块计分基准集）和跨线 core 身份双路对照（实测，复核脚本口径见 §2.4）：6/8 行成员被过渡体系覆盖（饮月/藿藿=仙舟3 点名件、花火∈希儿量2 羁绊全员、椒丘∈DOT2 羁绊全员），7/8 行成员在其他终局线是 core（饮月→龙丹、花火→5 线、藿藿→双王、刻律德菈→3 线、远坂凛→红A/龙丹）——这 7 行的 P1 经手与方向证据各有既有承载。例外 = 椒丘（黄泉线）：全库唯一无任何 core 身份者，且过渡侧承载只作用于过渡候选机器（`transition_scores` 只消费 `TRANSITION_LIBRARY`，过渡证据不进终局线分）——终局侧无替代承载，**纯损失**（§2.2 如实申报）。
  3. **知识三性质混装**：同一字段里混着 P1 过渡知识（饮月/花火/椒丘）、终局特殊系统知识（远坂凛=圣杯任务链、藿藿=绯英能量环）、跨线通用件身份（刻律德菈）——comp-definition「不进实现层的面」表对任务链类已有明确归属裁定（文档层 + 策略侧将来立项）。
- 根因归层：**语义层**。字段是过渡体系建成前的旧知识形态——统一过渡库（or-reqs-retirement 3.2，`TRANSITION_LIBRARY`）落地前，终局条目只能靠 key_items 夹带「这条线前期要经手谁」；过渡库建成后该批知识未并入过渡体系清算（与 faction_reqs 迁移时 flex_factions 同键残留同类：新体系落成、旧载体未退）。次生根因是登记口径错位：docstring「线核心输出位以外的结构成员」诱导按知识结构登记（58 死行的来源），而消费公式只认「core 外成员」。**战术权衡声明**：本迭代对 key_items 是清算式根治（字段删除），但族级防复发仍停留在 comp-definition 判例补录（文档层 review 关卡）——「名单间关系必须有校验」判据在 key_items 存续期从未对该字段落实（对照 core∩shared 双列回声有 `__post_init__` 建库校验——同库两种纪律）。同族整字段退役已是第 3 件（lock_rules→entry_signals→key_items），防复发机制（登记↔消费一致性建库校验族）**根治排期见 §1 外溢立项行，不在本迭代**。
- 解决到哪：`key_items` 整字段退役——字段、两处消费点、建库校验、测试断言、正本文档全链清除；行为变化逐行申报（§2.2）。
- 明确不解决（外溢面，禁并入本迭代）：
  - 过渡块→终局线衔接通道（若将来需要「持有过渡块点名件给某终局线方向分」的显式映射，另行立项——现行裁定为不需要，方向证据由各线 core 身份承载）；
  - 圣杯任务链特殊系统（远坂凛知识归还文档层后，策略侧任务链立项时按特殊系统重做）；
  - 绯英线藿藈进 shared 评估（「Final 帖 18/25 常驻」若裁定为终局依赖，进 shared 是独立行为变化——改变采购/保护/部署面——自成小裁定，不与字段退役混批）；
  - **字段族「登记↔消费一致性」防复发机制**（同族整字段退役第 3 件，见根因段战术权衡——自成新迭代：名单/知识卡类字段登记口径与消费口径的建库期校验族或年检机制）；
  - flex_factions 同键残留清算（6 处 flex∩bonus 重叠，faction_reqs 迁移遗留；同族病现存件——归上行的防复发设计件同批处置，不在本迭代单独清算）。

## 2. 方案

### 2.1 系统级变化

1. **`Comp.key_items` 字段删除**（实例字段 13 → 12）。Comp 类体内「知识卡字段」注释块（cw_comps.py 类体 docstring 区）同步收窄（知识卡 = need_star 单字段）。
2. **证据分四档 → 三档**（line_select.py）：
   - `LineScore` 删 `skeleton` 分量；`total` 与 `gate_positive` 相应收窄（证据门 = env ∨ carry ∨ 插件 > 0，骨架项删除）；
   - `line_score_breakdown` 删 `skeleton_hits`；`plugin_hits` 的 `− key_items` 排除项删除（`= (members ∩ held) − carry`）；
   - 数量级标尺（cw_line_scales.py）`SKELETON_BONUS` 常量删除（分量删除后该常量无消费，随之清除；docstring 消费面声明同步）；
   - line_select.py 模块头与 `LineScore`/`line_score_breakdown` docstring 的「骨架」措辞、cw_comps.py 各数据行「# 骨架=…」注释、`carry_set` docstring「与 key_items 骨架档/插件档三分」句——随批清理。
3. **货架资格窄门单源化**（shop.py）：资格集 = `carry_set`（骨架级通道删除；插件级本来就不触发，无变化）；资格臂注释「CARRY/骨架级」措辞同步。
4. **测试与校验同步**：
   - test_faction_derivation_locks：`assert comp.key_items` 非空断言删除；`(*comp.need_star, *comp.key_items)` 注册表校验循环去 key_items 半边；
   - test_line_select：骨架档断言改写（skeleton 分量断言删除、证据门断言去骨架项、key_items 构造样例清理）；
   - **test_shop_session_loop**：`test_skeleton_card_on_shelf_qualifies`（骨架级货架资格买入行为测试）改写为反向断言——资格域外件（原骨架级单卡）不触发 `shelf_qualify_buy` 买入；`:1505` 附近 `_f_qual |= set(_c.key_items or ())` 复刻断言删 key_items 半边；「CARRY ∪ key_items」注释同步；
   - **test_no_target_three_arms**：`:203` 附近 `carry_set(c) | set(c.key_items or ())` 复刻断言删 key_items 半边；注释同步；
   - sim 正项上界自算测试：上界含骨架档贡献的推导随分量删除自动收窄（自算口径即自证，如断言值写死则按新上界更新）。

### 2.2 行为变化申报（8 行活数据逐行）

统一验证口径（沿 comp-structure-unification 3.3 先例）：不做 A/B 模拟对照；行为验证 = 落地批测试全绿 + 实机首局观察记为**遗留待办**（沿 or-reqs-retirement 先例用法，不设为完成判据——骨架分量无遥测读口；观察点 = 货架资格买入 reason `shelf_qualify_buy` 案例中骨架级单卡零出现）。
统一行为语义（门翻转）：8 活行中 5 行（饮月→列车 A/B、花火/刻律德菈→圣杯、藿藿→绯英、远坂凛→双王）成员 ∉ 对应线 members——删除后「持该单卡、线无其他证据」的构局下该线从点亮变熄灭（退出候选）。这是设计意图（无核心不点亮），非意外损失。二阶效应：货架资格臂的虚拟 top3 为不开证据门的全量排序，skeleton 分量删除后虚拟 top3 构成同步收窄（同向），该线 carry_set 内其他成员的资格可能随线出局——方向同向、量级小，如实申报不逐构局枚举。

| 行 | 变化 | 边际损失评估 |
|---|---|---|

### 2.4 复核脚本口径（供落地批重跑验证）

死行/活行统计与过渡覆盖对照的判定式（与 §1/§2.2 同口径，落地后重跑应得「字段不存在」）：

```
死行判定: 成员 ∈ carry_anchor(comp) ∪ comp.core_chars
过渡覆盖判定: 成员 ∈ ∪{named} ∪ (hybrid 块的 bond_members(bond))
```

（本迭代不把一次性脚本入仓；判定式即持久口径。）

### 2.5 接口契约（对消费方的破坏面）

- `Comp.key_items` 属性消失：全库生产消费仅 line_select.py（2 处）与 shop.py（1 处），随本迭代同批改写；grep 清零为验收判据。测试消费另有两文件四处（§2.1 第 4 条已点名处置：test_shop_session_loop 行为测试改反向断言 + 复刻断言删半边、test_no_target_three_arms 复刻断言删半边）。
- `LineScore.skeleton` 分量消失：消费方 = line_select 内部（`gate_positive`/`total`）与测试断言；无外部读口。
- `SKELETON_BONUS` 常量消失：消费方 = line_select 独占（cw_line_scales docstring 的消费面声明同步）。

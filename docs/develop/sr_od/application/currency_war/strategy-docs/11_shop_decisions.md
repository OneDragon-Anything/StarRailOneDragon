## 2. 升级决策（arm1/arm2 双分支；路径总账判据，形式二）

- **存在性（arm1，阵容驱动）**:谓词三元「板满 ∧ 等待件（阵营相关单位不限星级，玩家裁定）∧ 边际贡献>0」+ 硬可负担——骨架义务 M3，arm2 无权否决存在性（P39 ② 分支一；ΔV_pop = w·1[板满 ∧ 等待域非空 ∧ 边际贡献>0]，w 待标定禁计值 ⇒ 分支一只用指示方向）。
- **等级帽资格闸（硬闸，先于双分支账）**:等级达注册表 `level_max` 即拒发升级——单一源 = `kernel/cw_registry.level_max`(live 机制真值,`kernel/cw_economy.xp_apply_clicks` 封顶同源——live 与 sim 同一规则核,无第二套标准)。判据历史键名 `lv9_stop`(cap=9 旧语义时代命名,键串保留);lv9 是 live 正常付费档,资格过闸后按整买/血预算/预算闸逐帧判。消费位四处（shop M3 批/shop 富余段 L3/mandate 备战 M3/entry posture 镜像）全量传上下文注册表 `.level_max`,判据参数必填,禁裸缺省消费位(接线收尾已完成)。
- **升级支出量闸（预算闸，P72 全段式）**:M3 批与富余段 L3 发出前过闸,判据 `g − s ≥ 10·τ(g) + ρ + Σ预留`(τ = kernel `interest` 利息档数分量单一源直消费;ρ/Σ预留 = `criteria/refresh.r2_card_reserve` 同参两语义角色,多数帧同值禁删一;g > g* 帧逐字退化回 P71-b (3));拒绝原因恒 `levelup_budget_gate_blocked`,富余段细分键 `budget_gate_must_spend_defer`;拒 = 整批推迟(P48 整买适用范围,禁按闸值截断击数;推迟目标存在不动点无移动靶发散)。豁免支两件在判据体内自判（两件详见下节「豁免支保底金门」）。
- **调度门（arm2，搜牌驱动）**现行形态 = **arm2 结构保利息门 g\* = 10×cap_resolved**(零 λ 依赖的结构安全阀)+ λ 顾问分位触发帧收紧(只延迟调度类批);「只延迟不否决」权限语义不变。
- **② 分支 U_L 阈值检验（写入代码 = cw_economy.schedule_upgrade ② 分支）**:升级 iff c_eff·(E(D|L) − E(D|L+1)) + ΔV_pop > U_L + C_int——全部游戏定义量:c_eff=刷价现读;E=expected_refreshes_for_card(REFRESH_PROB 池参数);U_L=clicks_to_next_level×xp_click_cost(XP 表/OCR 实读);C_int=利息损失 P47 L(g,U_L,R_剩余,Ī),cap 参数 = cap_resolved 现读(session resolved 链单一源,cap 三源归一——裸缺省 5 在利息规则投资 cap=10 局低估 C_int)。ΔV_pop 按 P39 式指示项(w 禁计值:指示=1 视为翻转项、指示=0 时纯概率账须独自过阈)。**单核代表降级申报**:规格的 E 为缺件集 ΣE_i,实现取单目标核心代表(缺件集装配在 strategies 侧,kernel 判据禁 import strategies)——多成员同受升级受益帧检验偏严(保守向);成员在 L+1 概率回落帧单核可能高估净受益(边界注)。**反例（推导批，写入正文的直觉修正）**:希儿 lv7 概率侧省刷费 28 < 升级金 40,纯概率账亏 12——裸「峰值级>当前级」直觉缺此检验会在小移位带过度升级,靠人口位 ΔV_pop 才翻转(数字锚:2 费 lv5→6 benefit≈9.9 < U_L=5击×4金=20;4 费 lv7→8 benefit≈103 > U_L=13击×4金=52。**锚口径（2026-09-06 亲验，production 函数直算）**:三锚均系代码消费档(2★,k=3,ts=2)真值——benefit=c_eff·(E(L)−E(L+1)),E=期望刷次数(未含刷费):2费 E(5)=28.6/E(6)=23.7 ⇒ 2×(28.6−23.7)=9.9;3费 E(6)=38.1/E(7)=23.9 ⇒ 28.4;4费 2×(94.9−43.3)=103.3;3★ 档(k=9)**benefit** 参考:2费 lv5→6 ≈33.7、4费 lv7→8 ≈741.8(同 2★ 锚的 benefit 形态与级对,非 E 值);j 按成员现值入账(j=2 时 3.4,距阈更远,方向不变))。

## 3. 刷新决策（路径总账·形式二，V̄ 链退役）

> 判据规格（已裁决 = 形式二「路径总账比较」；用户裁定禁胜率建模——旧 V̄_net/V_GAP 比较项整链退役,+ P53 修订单 R2;判据权威定义 = criteria/refresh.r1_commitment_account,账项装配 = `shop.py _r1_ledger_terms`(docstring 载口径申报);消费时机(as-built)= 每次刷新提案以期望态现算(判据层纯函数零改动,从一次判 N 次改逐次各判一次)。

**输入面(全为游戏定义量)**:等级 L / 金 g / 缺件集 D(每卡 → (cost, k, j):费用档、目标张数 k ∈ {3, 9, 1}(2★ 完成档 / 3★ 完成档 / 下一张单卡档;代码消费位取 2★ 档)、已有张数 j;c_taken=同费非目标已拿走数,缺则 0)/ R_剩余(horizon 现算)/ Ī(收入日程现算)/ 语境参数(c_eff 变体 = 免费额度折抵/轮岗翻倍档,池突变 resolved 后整表重生成)。**Σ卡费口径**:每成员按完成路径真实卡费 = (k−j)×cost(k=3 完成档张数)——与 E 的 (k−j) 张折算同档,非单张 cost(单动作语境:账在决策入口现算,持有副本 j 即期望态字段、单处读取——杜绝 j 低估 bug 类;screens/op-layer.md §1)。**金基准口径**:R1 刷新提案在买面动作之后评估(单动作选择序:EV 买面 → R1 付费刷新 → 结束本次访问),金基准 = 期望态当前值——先前买入已由逐动作纯计算逻辑态直写扣减,与 R2 同基准;不存在「帧首快照金」口径(「波首金」〔一波开头的金位快照〕口径已随利息线双侧修正退役为买后逻辑态金;单动作架构下「帧首快照金」属结构性不可达,消灭的 bug 类、已写入代码;screens/op-layer.md §1)。

**公式(路径总账)**:

```text
T_stay = c_eff·E(D|L)   + Σ卡费 + L(g, spend_stay, R_剩余, Ī)
T_up   = c_eff·E(D|L+1) + Σ卡费 + U_L + L(g, spend_up, R_剩余, Ī)
E(D|L)   = Σ_{卡∈D} expected_refreshes_for_card(L, cost, target_star, owned=j)
L        = loss_exact(P47 双轨迹递推;g* = 10×cap_resolved)
U_L      = clicks_to_next_level × xp_click_cost(XP 表/OCR 实读)
L* = argmin(T_stay, T_up)        # 形式二的等级选择输出
启动门(R1) = T(L*) ≤ 可用预算 = g − g*
```

**完成账语义（用户裁定 2026-09-04「对整个目标阵容……是不是合适的」读法;装配承载已修正）**:E(D|L) 服务的是**整套缺件集**的补齐——E 与 Σ卡费都对合格集整体求和（每成员 (k−j) 张折算 / 真实卡费 (k−j)×cost）,与旧「逐成员取 min」账相反:旧账只问最优成员可追与否,完成账把等级视为服务阵容整体的资源。合格集 = 未达 2★ ∧ 该级可追（refresh_prob>0）的成员;该级不可追成员剔出本级合格集（continue 过滤,与 R2 的 r2_card_reserve 同款过滤——ρ 与总账同帧同集合口径）,跨级追法由 T_up 承载（L* = T_stay/T_up 取小,T_up 在 L+1 级重估同一成员集,「升 7 搜 5 费」跨级追账结构不受影响）。装配承载勘误:旧文「不可追成员记 inf、不因其余成员可追而豁免;峰级混杂推向更高可齐级」是 inf 污染缺陷的病理记录而非设计——污染实现里可齐级推不出（lv3-6 的 T_up 在 L+1 仍有 5 费档空缺、同被打 inf）,刷新分支 3-6 级结构性恒关（g_20260907_021326 实证位面 1 全部 9 个刷新评估帧 0 刷店）;修正后 inf 仅由「合格集空」承载（P40 R0-1,边界声明见判据函数 docstring;单成员 j/c_taken 低估的保守向申报同处）。

**决策规则（四条）**:

### 6.3 P56：买面可变现利息线下界（姊妹缺口收尾）

**核心构造**：discretionary 买入支出的金位约束不按纯现金、不拍 0：

```
gold − x + Σ(活期卡退金) ≥ g*
活期卡 = 备战席中 1★ 全额退件（资格谓词与 funding_support_sell 同一：
```

## 8. 机制突变层（resolved input 原则）（原 03 §4.10 并入）

**原则**：决策机器**禁止直接读基础机制事实**——一切机制输入经「基础值 ∘ 已激活突变」解析后消费（**resolved input**）。突变登记 = 知识层注册表 INVEST_MUTATIONS。

- **登记三分态**：resolved（可解析）/ abandoned（用户裁定放弃建模——desc 无数值一律放弃不实机查，保可见性不进 resolved input）/ 未登记（=知识缺口，采集后入表，不静默忽略）。
- **解析语义结构**：每突变登记为（操作数，合成律[min/max/add/互斥]，状态依赖[计数器/条件]，时效[永久/计数窗/条件移除]）；同操作数多突变按合成律合成；互斥型登记位声明（首个生效，后续 suppressed）；异构操作合成序按操作数分层（override 先于 multiply，层内按注册序）；未登记态运行时检出 = 保守降级（按基础值消费 + 告警，不静默）；消费点读合成后的单一 resolved 值，禁止各机器自选合成方式。
- **多源声明**：突变源不止投资卡——角色固有技能（银狼升费）、任务奖励皆可改状态；INVEST_MUTATIONS 为多源效果突变登记，适用范围不限于投资。
- **突变分类框架**（按改写的操作数）：经济参数族 / 收入与利息规则族 / 概率表族 / 池构成族 / 板面谓词族 / 商店行为族 / 难度与节点族 / 阵容定义族 / 任务系统族 / 工具发放族 / 战力族（~155 条——不进经济 resolved，E1 定价走权重/克制通道）/ 资产发放族（~60 条——非金流，E1 定价走组件缺口通道）。

# v3.3 审计 errata（W786 攻击批裁决,编排者落）

> 攻击证据链:w786_v33_attack/REPORT.md。数字勘误不改结论方向,机制叙述更正如下。

## 勘误三条

1. **死亡窗人群**:v3.3 审计 §〇C「346 窗」实为含 108 存活局的混合人群——**真死亡窗 238 窗**,窗级累计收入 med **82**（非 93）。核心数字(单帧可达率 7.5%/rn 分层/3751/4532 帧)经 W786 全量复算逐位吻合,确认有效。
2. **lv9 XP sink「耗尽」为假**:lv9→10 sink 满格 ≈**84 金**(P2 2232/2253 帧在 lv9)——sink 容量充足,**是被 P21/停升级线/概率窗门关住,不是没容量**。bench 容量真值 = BENCH_CAPACITY=9(审计用 6-7 错值)。此更正反而**强化 XP sink 授权化的价值**:门关着→授权开闸=正解。
3. **XP 通道粒度**:4 金/帧、窗级上限 ~12 金——定位为**小通道/观测性开闸**(裁决见下)。

## 编排者裁决:XP 粒度=小通道定位

依据:①4 金/帧粒度+窗级 ~12 金上限,物理上非大额通道;②P27(买经验 EV)未证,数学先行硬门下不宜按大通道进开臂主链;③M0b-v4(水位不升≥50%)达标路径由 L1×L2 耦合独立承载(W786 确认耦合有效),XP 为增量辅助。
处置:XP sink 维持观测性开闸(不进开臂判据主链);P27 证明挂采集账(实机 deployed×outcome ≥30 场/格,P25 模式);若 P27 证成且水位不足,升格多击粒度=v3.4 议题。

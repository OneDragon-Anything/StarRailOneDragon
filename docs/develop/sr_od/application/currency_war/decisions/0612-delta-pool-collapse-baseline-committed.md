# ADR-0612: Δ池塌缩守卫基线来源修正（git HEAD 提交版优先，盘面兜底）

日期: 2026-09-09
状态: 已采纳（Δ池塌缩守卫失效核查批〔编排者台账 T-178〕定谳后实施）

## 背景（穿透定谳）

ADR-0595 的塌缩守卫（源行数账 < 现快照行数账 × 0.5 拒绝再生覆写）在 2026-09-08
事故后仍被穿透：工作树快照从全量（460e6031，16391/2246 行账）塌缩为微语料件
（0e091d4d，286/48 行账、3 run）。核查定谳为两段叠加，守卫条件方向与入口收口
均无错（行为复现：全量基线 vs 微源必 raise；CLI 壳与局终钩子两写入点都走
`regenerate_snapshot` 唯一入口，`git log -S` 证明塌缩指纹从未入库）：

1. **时序穿透（首次塌缩）**：2026-09-08 11:54/11:57/12:05 三次静默覆写发生在
   守卫入库（76ca4f4b，当日 13:14:13）之前——假游戏局 fake_20260908 触发局终
   再生钩，用 T-125 迁移后仅剩微语料的新 live 根覆盖提交快照。守卫对该批写盘
   不存在，无从拦截。
2. **基线自我延续（守卫在场下的持续放行）**：守卫基线读「即将被覆写的盘面
   文件」而非 git 提交版。盘面已被第一段改成塌缩件后，任何微语料再生都满足
   「微源 ≥ 塌缩基线 × 50%」→ 放行 → 塌缩件被反复重写（现行工作树件含
   2026-09-08 16:54 后 run 且带 v14 note，即由带守卫生成器产出；末次写盘
   09-09 03:48:02）。这与 ADR-0595 自身申报「提交快照（460e6031）持续受保护」
   矛盾——守卫保护的是盘面现状，不是提交真值。

连带实证（同批核查，污染面处置归编排者）：2026-09-08 23:51 的 n300 重锚批把
校准锚登记表重钉到塌缩指纹（`sim/checks/calib.py` ANCHOR_REGISTRY_N300，
漂移归因写作「池语料前移」），与台账 09-08 12:10「Δ池四还 HEAD + 锚无失配
零重推」裁决及 ADR-0595「锚重推禁令：禁止把微型池统计值登记为语料真值」冲突。

## 决策

`_committed_source_rows` 基线来源改为 **git HEAD 提交版优先**（新增单函数
`_head_data_py_text`：只读 `git show HEAD:<相对路径>`，仓外写目标/未跟踪/
无 git 一律返回 None），HEAD 版不存在时退回盘面文件（旧行为，首次再生与
测试仓 tmp_path 写目标不受影响）。守卫语义自此与 ADR-0595 申报对齐：
**不许比提交真值少**。生成器守卫常量块与 `regenerate_snapshot` docstring
同步登记基线来源语义。

## Considered Options

- **a) 退役申报（守卫承认失效改流程约定）**：否决——守卫条件方向、唯一入口
  收口、测试锁均经核查无误，失效仅在基线来源一处，可修且修复后即时止血
  （真文件终验：基线回到 16391/2246，微源再生即拒）。
- **b) 基线取 max(盘面, HEAD)**：否决——两种语义混合后「显式清洗（10-30%
  裁剪）未提交窗口」的行为不可解释；单一语义「提交真值」可判可锁，清洗批
  先 commit 再继续再生即自洽。
- **c) META 记录历史峰值行数账（max_seen）作基线**：否决——需改生成产物
  格式，且首次塌缩同样会抹掉记忆（塌缩后的再生以塌缩值为新峰值起点），
  治标不治本。
- **d) 维持盘面基线 + 依赖还原纪律**：否决——「守卫在场下持续放行」已实证
  （2026-09-08 16:54 后多次重写），纪律约束不能替代防线语义。

## 后果

- 锁：test_cw_delta_pool「pool_data_defense」段新增基线来源锁
  （test_collapse_baseline_reads_committed_head_not_disk：盘面塌缩基线 6 行 +
  HEAD 版 24 行桩注入 + 微源 6 行 → 必须 SourceCorpusCollapse 且盘面字节
  保留），变异亲证（基线退回盘面-only → 锁红，还原绿）；既有 7 防线锁全绿
  （tmp 写目标走盘面兜底通道，语义不变）。
- 修复后局终再生在 live 语料跨过 9318 行（提交基线 × 50%）前持续被拒并记
  warning——ADR-0344 best-effort 纪律既有申报，不影响对局。
- 工作树塌缩件（0e091d4d）处置：本批不改其内容（多批在飞，池内容切换须批间
  进行）。还原到 HEAD（460e6031，全量语料唯一存世副本）= 编排者 git 动作，
  还原后 ci_smoke（battle_rung_pool_bucket_lock）与 5 条快照内容锁即回绿；
  还原后需按 ADR-0582 工序另批重推 n300 锚（替换 T-169 批钉在塌缩指纹上的
  ANCHOR_REGISTRY_N300）。
- 边界：若塌缩件被 commit，HEAD 基线随之变为塌缩件，守卫转而保护塌缩件——
  塌缩件禁入 commit 的分账纪律是本防线的互补约束（对账正本 = 台账 T-126 note
  2026-09-08 与 T-178 核查批报告）。

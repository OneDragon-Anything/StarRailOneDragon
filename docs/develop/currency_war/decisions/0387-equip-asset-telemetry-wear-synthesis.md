# 0387 装备资产遥测影响面(run 26 追加取证三件)+ 穿着合成对账等价豁免

- 状态: accepted
- 日期: 2026-08-26
- 来源: 编排者 run 26 崩坏现场追加取证(用户点名「希儿装备不对」挖出);
  姊妹条目 ADR-0385(布局)/0386(off-target 熔断)同批

## 背景(三个新实证)

1. **装备分配池干涸+装备随人丢失链**:M7 分配日志「无穿戴候选(count=2,
   全工具/空)→停」;简易装备全穿在卡芙卡/千冶·刃/风堇身上 → 这批人被
   off-target 卖掉 → 装备随人消失(owned 5 件 → 2 工具)。**off-target
   卖出通道不查装备价值、不留装备去向**——装备资产遥测在该通道全盲。
2. **穿着触发自动合成(游戏机制实锤)**:穿着的两件基础件恰为某进阶配方
   组件(自配同件×2 / 交叉两件)→ 画面自动合成:风堇 量产型装甲×2→很硬的甲
   (SELF_RECIPES 精确对应);卡芙卡 光能电池+生命之花→绝对热量
   (GUANGNENG_CROSS 精确对应)。cw_synthesis 图谱正确,但 tracking 不建模
   「穿着即合成」→ 两次 EquipsInconsistencyError 误报。
3. **进阶装备来源不可追溯**:希儿穿 斩首行动+电磁弹射器(进阶),日志零来源
   (我们的合成 op 未实现、从未给希儿穿件)——最可能 = 商店购买自带
   (游戏存在装备着进阶的单位进商店机制,cw_invest_data 加拉赫 augment 实锤
   同类);且电磁弹射器(后排装备)穿在前排希儿 = 效果全废(非我们分配,
   分配器无管辖权)。

## 决策

1. **(件②实装)穿着合成对账等价豁免**:`cw_bench_equips.
   wear_synthesis_equivalent(ledger, visible)` —— 账面多重集经任意次配方
   替换(每次 两组件→一进阶,件数−1;图谱单一源 cw_synthesis,闭包搜索,
   ledger ≤6 件空间极小)能到达画面多重集 → 视为一致不 raise;
   `assert_equips_consistency` 接入(等价豁免后调用方的画面真值覆盖逻辑
   照常把账面纠正为画面形态——合成不可逆,画面即最新真值)。**方向单向**:
   反向(账面进阶、画面组件)不等价。
2. **(件①观测)off-target 卖出装备去向留痕**:`_sell_offtarget_deployed`
   卖出携带装备的角色前记 `[cw!]` warning(角色+装备清单+去向语义)——
   装备资产流失从全盲变可判读。**装备价值进卖出决策**(穿装件少卖/先扒装
   再卖)是更大的决策面:卖出回收语义(装备是否真回 owned 池)先由观测
   数据钉死,再裁——记后续批。
3. **(件③记档)自带装备两问不辖**:①买卡读自带装备(价值评估输入)——
   商店卡面装备 icon 可读性未建档,读面成本与价值权重是策略层决策面,记
   意向谱系;②M7 对自带装备的适配检查(后排装备穿前排=效果全废)——
   分配器对非自有装备无管辖权(不可脱),记观察(run 27+ 判读时注意:
   自带装备的错排不是 M7 的回归)。

### 追加(W209g,编排者三断点定位——用户追问「装备采集代码怎么会没采集到」)

4. **断点①对账纠漂清零装备字段(主通道,实装)**:`cw_reconcile.reconcile_
   tracking` 原整批替换(`session.tracked_deployed = list(deployed)`),新读
   对象 equips=[] 默认 → `_snapshot_equips_into_tracking` 写入的装备在下次
   对账即被冲(run 26 布局错乱→纠漂狂刷→反复清零;decisions.jsonl 希儿装备
   闪烁实证:round6 三条快照仅一条有装备)。修 = `_merge_equips` **合并
   语义**:按 char_id 把旧 tracking 的 equips 续接到新读对象(同名多副本
   逐个配对消耗);新读自带非空 equips(画面真值)优先;离场自然丢弃。
5. **断点②工具在采集层被过滤(实装)**:`equip_all` 两处写端
   (M7 主循环 L412 / 旧 front-only 路径 L491)原把 `_TOOL_CATEGORIES`
   过滤后的 wearable 写 `last_owned_equips` → 冶金炉/扳手从不进决策快照
   (owned 恒空实证)。修 = 写端**全量 hits**(工具进快照;采集层无权丢
   数据),过滤只留穿戴决策层(wearable 不变)。消费端 default_strategy
   拷入 state.equips 仅遥测/特征可见,含工具无决策副作用。
6. **断点③装备读槽硬编码(实装)**:`equip_all` M7/C6 转移重读原硬编码
   `'后排', 10`(deploy_bench 侧已由 W209c 修)——与布局档自相矛盾
   (deploy 拖 8 格坐标、装备读固定槽)。修 = `_row_specs` 接
   `select_back_layout` 双通道单一源(ADR-0385)。
   三断点同属**遥测完整性修法域**(非策略设计):①修「采集到的数据被
   自己冲掉」、②修「采集层丢数据」、③修「读面与布局失配」——装备使用
   策略本体(件5 工具策略等)仍归独立策略设计件,不因数据通了就扩辖。

## Considered Options

- **A.(件②)对账告警降级为「已知形态」忽略(不判图谱)**:拒绝——无图谱
  判定的降级 = 把一切真漂移也静默掉(C6「禁静默用账」冻结决定);等价
  判定精确到配方闭包,只放行可解释差异;
- **B.(件②)tracking 建模合成(穿着时主动改账)**:方向正确但更大——需要
  穿着动作后主动跑图谱(分配器/购买自带/游戏自动合成三入口都要接),
  本批先修对账误报(观测面),账面建模随「卖出回收语义」一起进后续批;
- **C.(件①)装备价值直接进 off-target 卖出决策**:拒绝(本批)——卖出回收
  语义未钉死(装备随人消失是 tracking 盲区还是游戏真回收?),先观测;
- **D.(件③)M7 强制重排自带装备**:拒绝——非自有装备不可脱/不可换(分配器
  无管辖权),硬动只会白拖;记观察即可。

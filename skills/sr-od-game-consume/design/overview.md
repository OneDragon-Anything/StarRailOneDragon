# 消费指导 skill 设计总览(sr-od-game-consume)

## 定位

指导 agent 执行崩坏:星穹铁道**游戏内真实货币消费**的操作路由:怎么走到付款、
bot 在哪止步、怎么读消费状态。范围:小月卡(列车补给凭证)已建;大月卡(无名勋礼
￥68 荣勋档)已建(2026-11-12 全链实机走通;￥128 奖章档只识别不点击);跃迁
(抽卡)读资产 op `ReadWarpStatusOp` 已建(2026-11-12 活动/常驻两态实机验证;
星琼/专票/星票/当前池),抽卡执行 op 未建设——跃迁按钮是消耗控件,bot 永不
代点,建设须带用户确认闸。

## 边界(与其它 skill 的分工)

- **消费决策**(该不该买/性价比/何时续)归 `sr-od-game-coach`——本 skill 默认
  用户已决定要买,只管怎么买。
- **画面建档事实**(锚点/子态/坐标/交互行为)归 `docs/game/screens/store.md`——
  本 skill 引用不复制,防双源漂移。
- **单条 op 的实现/调试**归 `od-dev-write-operation`——本 skill 只消费 op 的
  对外契约(入参/状态/失败语义)。

## 关键设计动机

- **止步付款码而非「尝试完成支付」**:支付渠道是扫码制,bot 无代付通道;把
  「摆码」定为成功终点,天然形成消耗红线(用户扫码 = 用户授权),无需额外的
  确认弹窗拦截逻辑。
- **红线写 SKILL.md 本体、机制细节进 references**:红线是跨消费项不变式且是
  纠正型约束(agent 默认倾向「帮用户点到底」),必须常驻注入;机制/坐标类
  细节按需加载(progressive disclosure)。
- **op 放 `cultivation/account` 包**(账号养成):与 cultivation 既有分类一致
  (character/light_cone/relic/account 各管一类养成对象),消费类 op 后续
  (大月卡/跃迁)同包扩展。
- **路由表带「未建设/未收录」去向**:消费项会随版本增长,表必须回答
  「请求了没收录的东西怎么办」——如实告知未支持 + 勿凭猜点击,防幻觉导航
  摸到真实货币入口。

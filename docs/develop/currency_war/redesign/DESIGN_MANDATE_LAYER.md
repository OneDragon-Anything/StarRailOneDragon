## 一、假设批判性复核:「义务静默蒸发」假设成立,但需三处修正

### 1.1 「没做」形态的量化占比(三轮合并)

三轮 A/B(新 cw3 vs 旧 decision_v2,同 seed 0-39、同池指纹)的失败形态逐一归类:

| 失败面 | 新侧 | 旧侧 | 归类 |
|---|---|---|---|
| 部署/换位(s0 批) | **0 次** | 934 次 | 没做(机器整块缺失) |
| SellBench(r2) | **0 笔** | 287 笔 | 没做(卖闸 fail-closed 在发散板面上恒关) |
| SellBench(r3) | 43 笔 | 287 笔 | 没做(通道部分接通,量差 ~7 倍) |
| bench 满拒买(r3) | **1163 笔 / 3114 金**(≈全批收入 26%) | 13 笔 / 44 金 | 没做的现金流影子(腾席义务缺位 → 席满 → 买不进) |
| P1 升级投入金(r3) | **1940** | 5792 | 没做(升级义务被 EV 门拦死,见 §1.3③) |
| 花费率(r3) | 0.384 | 旧侧 ~0.68(r2 口径 0.683) | 没做的汇总表征 |
| 空转轮占比(r3) | 0.194(87 轮零花且金≥50) | 24 轮 | 没做的汇总表征 |
| 危局空转(r2) | 102 轮 / 34 局,血预算门拦 0/0(旧 229/230) | — | 没做(无任何机器接管危局) |
| 零动作轮(s0) | 35%(162/461) | 25/554 轮 | 没做 |

**量化结论:三轮失败形态中「没做」占绝对主导**——上述每一个 headline 差距(部署 0/934、卖 0→43/287、升级金 1940/5792、席满拒买 1163/13、空转 19%/低)全部是「义务未执行」的方向,没有一项是「执行了但方向错到造成显著损失」的方向。

### 1.2 有没有「做错」反例?——有三处,但无一处是 EV 门的错

批判性复核要求找反例,找到了,但逐一检验后**都不支持「义务执行了反而更糟」**:

1. **刷新早退 × 引擎段上限联锁(s0 批,323 笔已批准买入被推迟/丢失)**——这是「义务已判定、执行序列把它挤掉了」,属实现层接口口径 bug(两段语义各自成立、组合互相破坏),不是「做错方向」。
2. **LevelUpRejected 1264 笔(r2,等级到 cap 仍点击)**——伪动作,消耗决策段但金上无实损;属实现缺 cap 感知,不是 EV 判错。
3. **部署选错体系(r3,6/40 局 form_score=0.0:板大而体系不对)**——这是三轮中唯一的「做了但选错」,占比 15%,且规模远小于「没做」簇(29/40 未成型)。

**补充一处真正的 fail-open 事故(r2 审计 H1)**:refresh.py 在 V̄/V_gap 未标定时对攒息域散刷完全无门放行——s0 批新侧 RefreshShop 253 笔、部分轮 8 段全被刷新耗尽。这证明:**该 fail-closed 的动作(刷新)若 fail-open 会真烧钱**。它反过来说明假设的表述要修正:不是「fail-closed 一律错」,而是「fail-closed 装错了动作」(详见 §3.5)。

### 1.3 金约束门是不是凶手?——不是,门几乎没拦过人

s0 批探针数据:金约束门合计 0 次拒(「金位<S 恒 defer」「[41] 囤 S 门」「满息金锁」全为 0),唯一拒因是序 2 两资源合取 144 笔——而那个门**按设计原文就是对的**([35]/[31]③),错在没有机器去创造 board 空位。r1 归因原话:「门本身没错——错在没有机器去创造 board 空位」「正确地什么都不做」。

r3 的升级金差距同理:旧侧血预算门拦 levelup 229 次仍花出 5792 金,证明旧层的顺序是「先执行升级义务、后过血预算」;新侧把 p39 臂二(L6→7 3 费窗 EV 为负,按证明口径该 defer)当成了「整局不升级」的理由——**p39 作为「何时升级」的调度证明是对的,被错当成了「是否升级」的存在性门**。这是义务与优化器权限混淆的直接证据。

### 1.4 假设的三处修正

原假设「cw3 把约束做成门、把义务做成 EV 为正才执行的选项,输入缺失时义务静默蒸发 → 默认不动」**主干成立**,修正如下:

1. **修正一(失活的机理不止 fail-closed)**:输入缺失/标定 None 的 fail-closed 只是失活机理之一。三轮实际的主失活机理还有两种:①**机器整块缺失**(部署机不存在,义务无处发生);②**权限错位**(义务被降级为某个 EV 证明的从属品——升级被 p39 臂二否决整局;卖出被 p41 分类器与发散板面耦合后恒不卖)。「EV 为正才执行」不是唯一病因,「义务没有独立的存在性」才是。
2. **修正二(约束做成门基本无害,因为门很少拒)**:三轮数据一致显示息律/囤 S/否决域这些约束门拦人次数≈0。它们是正确的但**不起作用**——真正杀人的是义务缺位后,资产形态(席满/血薄/等级低)劣化,让约束门在劣化态下「正确地」继续关门,形成「不动→更差→更不动」的静默螺旋。所以修复主向不是拆门,是**把义务立起来**。
3. **修正三(fail-closed 有对有错,按动作可逆性分)**:卖出线内件、无目标刷新这类**不可逆/纯成本**动作,fail-closed 是对的(§3.5);买线成员、升级整批、腾席卖杂件这类**可逆/有正期望保底**的义务动作,fail-closed 是错的——[11] 零息损与 [22] 囤积判据从文档层面就保证了这些动作有「活期资产」属性,不会因执行而受损。

## 二、文档对照:义务与约束的原始边界,文档里本来就有

01 §4.1 六序的金约束门写的是「**先判类,再按该类的价值函数过金约束门**」——六序表本身是**件级分类与行为律**(什么该买、买了怎么处置),金约束门只是共用过滤器。逐条核 [N] 原文,义务不受息律拦截的依据**文档里已齐**:

| 义务 | 文档依据(原文口径) | 边界(约束的合法辖域) |
|---|---|---|
| 早期买过渡阵容 | **[2]**:「前期可以卖血;少刷新;优先凑息(50 金);**但也要买过渡阵容**」——买过渡与攒息在文档里是并列义务,不是「攒息约束下 EV 为正的选项」 | 息律只约束「刷新」与「破档大额」,不约束过渡件买入 |
| 零息损购买 | **[11]**:「金<20 买过渡件**不损息还压缩牌库**——**攒息不该拦无损购买**」(动态口径:1★ 全额退=活期资产,含卖回恢复通道) | 残余非零项:2★+cost≥2 手续费、贴档线按 [22]④ 算 |
| 破档例外 | **[6]**:「偶尔可掉到 40/30 金少要点息——前提是商店全是想要的」——息律自带例外条款,不是绝对禁令 | 例外需「店全是想要的」这一场面事实 |
| 过渡成型=通关义务 | **[13]**:「过渡阵容 lv5-6+羁绊凑够+过渡核心 2★≈能过位面 1」;**[28]** P1 验收=**双指标**(息基保住 × P1 形态达标)——形态与息基**平权**,不是息基的从属 | 停手线:成型后停买过渡件(辖域=第三类纯冗余) |
| 升级为人口位服务 | **[33]** 例外明文:「人口位升级([33],有框架单位等着上场)**不受本条([12] 息引擎前提)约束**——上场单位立即产生战力/羁绊收益」 | [41] 整批纪律(一次买齐)+[3] 刷新/升级择取按概率表 |
| 腾席卖出 | **[32]**:「bench 满 → **先卖杂件**」——这是全程通用纪律,无条件式,不是 EV 选项 | 「升级腾席」才需要「强单位等待」前提 |
| 超 50 溢余的处置 | **[17]**:「>50 的每一分都没有存的意义,该升级升级、该买牌买牌」;**[41]** 二次精确化:「把超 50 的钱**换成压库卡**」——花钱义务的默认形态是买入,不是持币 | 存在待执行整买目标 S 时优先囤到 S([41] 推论) |

**结论**:文档的原始边界本来就画了三层——①**行为律**(六序/S0 三级降级/腾席纪律:什么必须做);②**过滤器**(息律/席位/整批:什么时候允许做);③**线级选择**(证据门/换线/停手线:为谁做)。cw3 的实现错在把第①层整体降格进第②层的判定式里,让「该做」变成「EV 算出来正才做」,而 EV 计算的输入(标定值/池参数/板面收敛度)在早期局恰恰最不可靠 → 义务在最有价值的时机最容易蒸发。[11]/[6]/[2] 三条合起来,已经构成「义务不受息律拦截」的完整文档依据:**攒息不拦无损购买([11])、破档有例外([6])、买过渡与攒息并列([2])**。

## 三、骨架行为层设计

### 3.1 三层权限模型

```
┌─ 证明层(线选择与终局)──────────────────────────┐
│ 证据门(01 §4.2)/ 换线机器(§4.3)/ 停手线([13]) │
│ 职权:决定骨架为哪条线服务;给 [41] 供给目标线 S   │
│ 无权:否决任何单笔骨架动作                         │
├─ 骨架层(义务,mandate)────────────────────────┤
│ 每备战期无条件生成动作,只受硬约束(§3.3)拦截     │
│ 输入缺失 → 保守默认执行(§3.4),禁静默跳过        │
├─ EV 层(优化器)───────────────────────────────┤
│ 刷新/压库/连胜金/装备/事件决策;只增不减:        │
│ 可在骨架之上追加动作,无权否决或改写骨架动作      │
└──────────────────────────────────────────────┘
```

权限判据一句话:**「不做会输」的是骨架(义务),「做了更赚」的是 EV(优化),「做给谁看」的是证明(线选择)**。三轮失败全部落在第一格被掏空。

### 3.3 硬约束的封闭定义(唯一合法拦截集)

骨架动作只被以下条件拦截,此外任何门(EV、标定、息律、血预算)**无权拦截**:

1. **可负担**:金≥动作成本;
2. **席位存在**:board/bench 槽位、等级 cap、同名同星≤1;
3. **S 预留保护**([41]):待执行整买目标线 S 的预留金不被非 S 组成的骨架动作吃掉——但 M3 升级本身与计入 S 的 M2 买不受此限;
4. **不可逆护栏**:见 §3.5,卖出线内件、无目标刷新不属于骨架动作集。

注意:**HP 不在硬约束里**([39]/01 §4.7 已裁定:HP 禁作决策输入)。r2/r3 归因都建议加「危局接管门(hp≤40 越权)」——本设计**不采纳该形态**:它违反 §4.7,且是症状位补丁。骨架常开后,危局的两个成因(席堵不动、等级落后)被 M1-M4 直接消解,「危机」不再需要独立触发器。这是骨架层对危局接管需求的架构级回应:**义务常开使危机态不可达,优于危机态特设出口**。

**【R-SYNC 2026-09:本段部分修订】**「HP 不进硬约束/不作骨架动作拦截输入」**不变量保持**(IMPL_DESIGN §3.2 注照引本节)。但「危机不再需要独立触发器、义务常开使危机态不可达」的论断已被姿态架构修订:实机死亡复盘(DEATH_POSTMORTEM A1)证明骨架常开下濒死转化通道仍可结构性为空(R28-2:三合取使真值濒死 ∧ g<饱和线 ∧ 板未满帧 M3 转化通道=∅),R26-H1/R28-2 增设**升档器独立薄层**——①血线硬地板(hp<阈值【拟】触发「解锁包」:M3 破息批解锁+F7 凑息禁令+转化优先姿态);②λ 顾问(PL 键查表相对分位,只升不降)。边界钉死:hp 在新架构中仅作**风险路由键与解锁触发**,**仍不作骨架动作的拦截输入**——本节「不采纳危局接管门」按「不采纳 hp 拦截/接管骨架」核读,非「禁止任何 hp 观测层」。权威=IMPL_DESIGN §2.0(姿态架构权威节)/§2.0-3 规格②/R28-2。

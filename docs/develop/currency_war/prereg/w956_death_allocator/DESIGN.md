## 1. 根因形式化:定价链与失效点

### 1.1 定价输入-输出链(表达式级)

分配器每辖域帧构造分配问题 `P_t = ⟨Π_t, R_t, O, D⟩`(allocator.py 模块头),决策链五段:

```
(state, session)
   │ ①辖域谓词 D:alloc_domain() → DEATH | STOP_WINDOW | None
   ▼
②提案供给 Π_t:_supply_impl() 三渠道臂(升级/买卡/刷新)
   │    买卡臂过滤:_salvage_ok(部署完备式) ∧ _w_only_rejected(死亡域 dwin≤0 拒供)
   ▼
③逐提案计值:V(π) = m_eff · Δp_eff(π) − (c + I)
   │    Δp_eff = max(0, Δwin_eq) · L_c · hp_to_gold + w      ←板面价值唯一通道
   │    m_eff(DEATH) = min(兑现长, battles_left_plane)        ←视界截断(1~3 场)
   ▼
④出清:allocate() 只保留 V > 0 的提案(V≤0 出局)
   ▼
⑤预算:E_t = max(0, gold − reserve_cap) → 组合选择 → chosen
```

其中板面价值函数:

```
win_eq = h3_win_rate[e] + frac · (h3_win_rate[e+1] − h3_win_rate[e]),
         e = _engines_formed(成型档,钳制 [0,2]),frac = 引擎成型小数进度
```

**win_eq 是「引擎成型进度」的分段线性函数**——板面战力在模型里只经「羁绊引擎成型档位跳变」显影。

### 1.2 失效点标注(逐点带表达式证据)

**F1(供给侧结构性拒供——主失效点)** `_w_only_rejected`(allocator.py L274-288):

```python
if domain is not AllocDomain.DEATH: return False
return _win_eq(after) − _win_eq(state) <= 0.0   # dwin ≤ 0 → 死亡域不供给
```

死亡域内,凡不使引擎成型档跳变的买/升提案 dwin ≡ 0 → **提案根本不进 Π_t**。death 帧的典型购买对象(1-2 费可上阵填充件、非目标线散件、未闭合引擎的进度件)几乎全部落在 dwin=0 面。这是 W933 §3「分配器的拒出清条件(V>0 ∧ 非 w-only)在危机帧结构性恒不满足」的机制本体:**不是 V 算出来是负,是提案压根不被供给**。W955 955102 的 `proposals=1 ∧ chosen=[]` 即此:唯一提案是 refresh,买臂已全数被 F1/F2 拒在门外。

**F2(候选集过滤——锁线脱节)** Π_buy 继承 `generate_candidates` 的线/目标集过滤;death 帧常伴锁线(如 g_082322 p2r2 锁「希儿量子」),店中 5 卡无一属核心/共享集 → 合法购买集为空,分配器**从未见过这些卡**。复盘候选#2 的「5 卡全拒 0 执行」= F2 在管线层、F1 在分配器层的双闸串联。

**F2′(执行侧缓存线名脱节——F2 的同族扩展;W954 移交并入,`w954_transform_impl/REPORT.md` §5)** 同局 p2r1:evolve `CompTransaction` 理由串「→仙舟3」与 locked_comp=希儿量子脱节。W954 已裁定此属**意向状态机下游的执行消费层**既有缺陷(转型臂只辖「方向假设何时改判」,其降级帧 hoard 即时撤供半边已落锁 `test_stagnate_downgrade_hoard_detaches_from_line_immediately`),不属转型臂,归分配器/演进执行域批——即本设计。**同根形式化**:F2 与 F2′ 是同一缺陷的两个消费面——执行侧(购买过滤与 evolve 理由串)消费的是**自身缓存的线名**而非意向层当前权威状态(v3_hoard / locked_comp / weak_comp;W954 已在 update_intention 触发分支落消费契约注释:执行侧只读 v3_hoard/hoard mode,禁读自身缓存线名)。与 F1 合看,death 帧出清失败是**一处根、三个面**:①定价侧拒供(F1);②购买集按陈旧线名过滤(F2);③执行理由串按陈旧线名生成(F2′)。②③是纯一致性缺陷(断言可证,§3.4),①才是定价缺陷——治本件须同时收口,否则兜底集修好过滤、evolve 理由仍指向死线,断言会立刻抓到另一半。

**F3(计值式失效——即便供给也出不了清)** 假设 F1/F2 放行,填充件提案:

```
V = m_eff · (0 · L_c · hp_to_gold + w) − (c + I) = m_eff·w − (c + I)
```

m_eff(DEATH) 被视界截断到 battles_left_plane ≈ 1~3,w ∈ [0,3](连胜金表相邻档差)→ m_eff·w ≤ 9,而 c+I 对任何 ≥1 费件 ≥ 2~5,多数帧 V ≤ 0 → 出清负判先行出局。刷新臂更死:`_refresh_dpeff_estimate` 在板满/deploy 满帧直接 `return 0.0`(L378-380),且该式**不含 w 项** → V = −(c+I) < 0 恒成立——分配器自己的刷新臂在 death 帧恒为负值提案。

**F4(预算侧,g_082322 p2r1 型)** E_t = gold − reserve_cap,R* 含窗口内排程升级费(hp3/金89/R*=90 帧 E_t=0)。**此点已被 P36-a′ 治理**:危机臂 `crisis_overflow` 已落 R*_crisis≡0(posture_release.py L195-206)。但注意**降档辖域只在危机臂**——分配器的 E_t 仍走全局 reserve_cap,death 帧分配器预算侧与危机臂不同源,这是划界时要对账的点。

### 1.3 根因陈述(哪条假设失效)

定价函数的核心假设是:**板面件的价值 ≈ 它对引擎成型进度的边际贡献**(win_eq 通道)。该假设在常规帧成立(长期博弈中非引擎件不改变终局胜率分布);**在 death/emergency 帧失效**,因为:

- **收入侧失效**:濒死帧的真实边际价值是「本场生存概率增益」——任意可上阵件(哪怕 1 费填充)都直接加板面战力,与引擎成型无关;win_eq 对这类增量测得 0(量化盲区)。
- **成本侧已改、收入侧未改的错配**:ADR-0493 已把死亡域金按面值计(W810 证伪「金必死」全面折扣),W907/P36-a′ 进一步在应急带把金生存价值压到 ≈0(R*_crisis≡0)。即**成本侧已认定「攥金≈零价值」,收入侧却仍认定「非引擎件=零价值」**——两侧同时趋零,V 恒 ≈0,出清结果完全由 F1 的结构性拒供裁决 → chosen=[] 恒空。这就是「并联缺位」的完整机理:危机臂(P36-a 不变式车道)在刷新通道部分兑付,分配器在买/升通道结构性哑火,两层并联、互不接力。

**W907 对账**:W907 证明了「金的一侧」——hp≤25 帧类的金全通道生存价值≈0,搜索/支出占优。但 W907 只证了成本侧;分配器缺的**另一侧**是收入侧的「非引擎板面件在濒死帧的生存价值定价通道」——现模型里这条通道不存在(F1 拒供 + F3 量化盲区)。

**频次上行(7→15/300)的机理**:W935 记账修复 + P36-a 不变式使危机臂把预算真花出来(帧中位 37 金),危机帧的刷新搜索拉长死亡态存活(hp 在 1~5 徘徊更多轮),death 域帧数随之变多 → 结构性哑火的分配器暴露面变大。**频次上升不是新病灶,是病灶观测窗被危机臂的改善放大了**——治本对象不变。

### 1.4 W958 轮 2 新面核对(编排者补充输入;`w958_sim_hunt5/REPORT.md` §4)

**面②末窗板位缺口(late_deploy_full,85 实例:件进 bench 不上板)→ 并入,立 F5。**
与 match4 p2r2 购买集空的「同族」判断准确,但同族不同点:F2/F2′ 是**陈旧线名消费**(读错方向);F5 是**部署候选层供给不完备**——bench 件未被 `_deploy_candidates` 供给 deploy 动作(top-K 截断 / 围栏序无末窗紧迫感 / 同名禁双),与 F1「模型测不出价值=不供给」同构。执行消费层失效点家族至此四件:F1(定价拒供,已修)/F2·F2′(线名来源,已修)/F5(部署供给,未修)。辖域归 §5 P2(swap/equip/deploy 供给扩展通道)并升级其优先级依据——「末窗 ∧ 板缺 ∧ 有金」帧是紧急定价(方案 A 机会成本重定价)的供给面半边,应与重定价同批设计,拆开则任一半边单独无效(有授权无提案,或有提案无授权)。

## 2. 修法方向候选(三案 + 一条否决基线)

### 方案 A:death 带分配器换紧急定价函数(分配器内换 O)

**核心**:在 DEATH 域内再分「必死子带」(判据见 §3 前提带),子带内把计值式从 win_eq 通道换为**紧急生存定价**:

```
V_em(π) = m_eff · Δs(π) − c·V_gold(band)
  Δs(π) = 部署面板直接战力增量代理(星级×费用当量 + 装备数差,
          经既有 _apply_with_pipeline 显影链取 after−before)
  V_gold(band) = 必死子带内金的终端价值(前提证得 ≈0 → 机会成本只剩 c 面值)
```

配套:子带内解除 `_w_only_rejected` 拒供(F1 的辖域收窄)、Π_buy 加「任意 ≤2 费可上阵件」兜底集(F2 的分配器侧补偿)、刷新臂估计器在子带保底正估值(F3)。

- **辖域**:DEATH 域 ∧ 必死子带;非子带 death 帧(如 W810 那类「hp 低但带金进 P2 有用」的帧)维持现 ADR-0493 面值语义不动。
- **与在飞臂划界**:见 §4 矩阵。分配器只辖「管线本帧没花出去 ∧ 危机臂未接管」的残金帧(`pipeline_spent` 门已有,零重叠结构保留)。
- **可验证性**:触发面(decisions 帧 `domain=death ∧ 子带`)帧级可查;行为面 = death 残留局数、终局攥金、alloc_gold>0 帧数三个 sim 指标;单帧锁可锁「子带帧 dwin=0 填充件被选中」语义。
- **实现代价**:中。O 换函数 + 供给过滤辖域化 + Δs 代理新造(需零新常数纪律审查——代理量全部从既有注册表符号推导);D2 入口帧/d2_entry 语义复用。

### 方案 B:危机臂扩大辖域吃掉分配器职责(单通道化)

**核心**:承认「death 帧分配器不接手」为既定设计(W933 两案之二),把残金兑付全部交给危机臂:crisis_release_open 辖域内(应急带 ∧ R*_crisis≡0 已落),在既有刷新搜索之外**加买侧兜底通道**——crisis 帧购买过滤放宽到「任意 ≤2 费可上阵件」(复盘候选#2 的 crisis_buy_tags 扩集),预算仍走 release 账(P36-a 记账链)。

- **辖域**:is_emergency 带 ∧ 危机臂开;非应急带的 death 帧(terminal_release 但 hp>emergency)仍归分配器现状(或明确同样不接手,见方案 C 残面)。
- **与在飞臂划界**:危机臂自身扩权,无新增层;与 P36-a 同臂自然衔接(不变式车道管刷新 floor,兜底集管买侧 floor)。
- **可验证性**:同上三指标 + release 账 spent 逐笔(记账修复后可信);A/B 尺子现成(W951/W955 危机面基线 97.2%/37 金/4318 金)。
- **实现代价**:**低**。单点改管线过滤谓词 + 兜底集常量,无第二定价函数。
- **风险声明**:危机臂是「指令-预算」结构(无逐提案 EV),兜底买谁需要排序策略(如「可合成 2★ > 最低费可上阵」)——该排序是启发式,数学证不了(§3),需 A/B。且单通道意味着 death 帧的 stop_window/death 非 emergency 子带仍无出口——**方案 B 只治应急带,治不了 DEATH 域全域**(W951 951322 的 r5-r7 是 flip/release 帧非纯应急带,分配器 budget 41/47 挂空发生在这里)。这是 B 相对 A 的辖域缺口。

### 方案 C:death 帧分配器按设计不接手(声明既定设计)

W933 §3 给出的第二案:不改任何行为,把残留面改记为「已解释项」。**否决理由**:①残留面在恶化(4→7→15/300 越噪声带);②终局攥金 97~180、死时持金 100 = 全场最高(g_082322),「金零价值已证一侧却全额攥进坟墓」与 P23.4(i) 直接矛盾,不是可辩护的既定设计;③危机臂刷新通道已部分兑付,说明「death 帧该花」已被设计接受,只差买侧通道——半途声明不接手是逻辑不自洽。保留本条仅作 A/B 的 off 基线。

### 补充通道(并入 A/B 实施,不单立):death 帧供给面扩展

g_082322 p1r9 复盘显示 death 帧「可花而未花」不只在买卡:装备 idle>0 未穿、备战 2★ 未换板面弱件。Π_t 可加 **swap/equip 类提案**(卖出弱件腾位 + 换上强件;装备上身),计值走同一紧急定价。实现代价更高(新提案 kind),列为二阶段。

### 正式范围扩充(W954 移交,编排者补充令并入)

以下两件原为复盘候选#2,经 W954 §5 对账裁定归本域批,正式纳入本设计范围——它们就是「分配器无法为危机帧出清」的**执行侧半边**(F2/F2′):

1. **alloc 一致性断言**(治 F2/F2′):断言式(沿 W954 §5 建议)= `CompTransaction`/买侧 reason 线名 ∈ {locked_comp, weak_comp} ∪ hoard mode 语义集;落点 = 检查器或 alloc 域单帧锁(先断言后修行为:断言先行零行为改动,可与兜底集同批或先落)。数学地位:一致性命题,**可证/可锁**(§3.4),不属定价问题。
2. **危机带购买兜底集**(治 F2 的行为面):= 方案 B 主体(§2),辖域 is_emergency 带内危机帧,「任意 ≤2 费可上阵件」;互斥谓词沿用 §4 声明(合法购买集非空 ⇒ 兜底不启用),排序启发式归 A/B(§3.3)。

**排期依赖(硬)**:转型臂开臂使「锁线→弱意向」成为可达状态,执行侧若继续按缓存线名过滤购买,脱节从偶发变**结构性**(W954 §5 原文)——即 F2/F2′ 在 W948 开臂后触发频率必然上升。故转型臂开臂判据依赖本设计批的先行件落地(先行件最小实现边界见 §5)。

### 裁决建议

**主推 B + A 的分带组合**:应急带(is_emergency)内走 B(危机臂兜底集,单通道、代价低、记账现成);DEATH 域非应急子带走 A 的辖域收窄版(仅解除 F1 拒供 + 刷新估计器保底,定价函数不换、仍用面值账——先让提案能进 V,出清交给既有 O)。这样两案各自辖域不重叠、都不需新定价常量,数学可证部分(§3)先落,A/B 只验兜底集排序与频率面。若单选一案:B 见效最快但留 DEATH 全域缺口;A 治本但代价与风险大——组合案是当前证据面下的长期最优。

## 3. 数学先行判定(逐案)

### 3.1 可证:必死子带内「攥金弱劣/任何非负板面提案弱优」(P23.4(i) 直接推论)

P23.4(i)(证明篇 L44,极限形式**严格**成立):若 P(活过本位面剩余战斗)=0,则金终端价值恒 0,故**对任何提案 π:攥金收益 ≡ 0,任何 m_eff·(Δp_π·L_c + w_π) > 0 的提案严格优于攥金,任何 ≥0 的提案弱优于攥金**。

推论延伸(本设计新增,非证明篇原文):

- **推论 E1(解除 F1 的可证性)**:设必死子带内某填充件提案满足「部署成功 ∧ 真实生存概率增量 δ ≥ 0(未测量但非负——上阵件不降低战力)」,则其真实收益 ≥ 0 > 攥金收益 0?——弱优于攥金(严格性需 δ>0)。**因此子带内拒供 dwin=0 提案不可能是最优**:被拒提案的真实价值 ≥ 0 = 攥金价值,而供给后 V 计值即便误判为 0,选择的损失上界为 0(弱劣方向)。**「解除拒供」是弱改进,数学可证,落码即无开关。**
- **推论 E2(R* 降档可证性)**:同一前提下,储备线保护对象(未来升级兑现/息收益流)被死亡截断 → R* 的任何正值在必死子带无保护语义 → R*≡0 可证。**已落地**(P36-a′ crisis_overflow),此处仅确认其数学地位:与 E1 同一前提的推论,非独立假设。

### 3.2 前提的辖域警示(可证性的边界,必须显式)

E1/E2 的前提是 **P(存活)=0 的极限形式**。W810 反事实实测:hp≤emergency_hp(25) 全带内「金必死」**不成立**(携金进 P2 三局 3/3 到达可支出语境、1 局转 +2 轮存活)——这正是 ADR-0493 退役 S0 折价的依据。故:

- 前提只在**真必死子带**可辩护,候选判据 = P23 死亡域判据本体 **E[bleed] ≥ hp**(期望失血 ≥ 现有血量,证明篇 §③ 在用的同一判据)或其严格化(如 hp ≤ 单场败局伤害估计 L_c,即「再败一场必死」)。子带谓词必须先于落码定案并登记,这是本设计留下的**唯一待定标定点**。
- 子带外的 death 帧:前提不成立 → E1 不适用 → 面值账 + 既有 O 维持(ADR-0493 现状),只有「让提案能进 V」的辖域收窄(组合案 A′)可选,且其净效应不可先验判定 → **归 A/B**。

### 3.3 不可证:兜底集构成与买序

「任意 ≤2 费可上阵件」的集合边界与「可合成 2★ > 最低费」的排序,依赖**填充件真实 δ 的分布**——现模型无板面直接战力标定(win_eq 量化盲区正是根因),任何排序权重都是拍值。按 strategy-work §3 分档:经验性 → **A/B 先行于落码**(预注册判据:death 残留 ≥2 轮局数、终局攥金、危机面基线不回归),判正落码不留开关、判负删码留 ADR。

### 3.4 判定汇总

| 修法组件 | 数学地位 | 落地路径 |
|---|---|---|
| 必死子带内解除 w-only 拒供(E1) | 可证(P23.4(i) 推论) | 直接落码,无开关 |
| 必死子带 R*≡0(E2) | 可证 | 已落地(P36-a′),无需动作 |
| 必死子带谓词定档(E[bleed]≥hp 或 hp≤L_c) | 待定标(前提带) | 落码前登记定案 |
| alloc 一致性断言(F2/F2′,W954 移交) | 可证(一致性命题,非定价) | 断言先行直接落码,无开关 |
| 危机臂兜底集 + 买序(方案 B 主体,W954 移交) | 不可证 | A/B 先行,预注册判据 |
| DEATH 非应急子带辖域收窄(A′) | 不可先验 | A/B 先行 |
| swap/equip 供给扩展 | 不可证 | 二阶段,A/B |

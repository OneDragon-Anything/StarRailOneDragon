## 高-1【证明本体】R13-2「真惩罚全式」展开代数错误;登记表内并存两个不一致的「全式」定义

**位置**:`IMPL_FIX_LEMMAS.md` R13-2 引理「真惩罚全式」段(约 529 行);R14 对照表 R13-2 行(504 行)。

**缺陷**:R13-2 写「按 P51 母体 W=λ(g+Φ) 的状态因果差分:W′−W = λ′(g+r+Φ′) − λ(g+Φ) = **λ(r+Δ息流) + (λ′−λ)(g+Φ)**(展开直读)」。该「展开直读」是代数错误的。

**论证**:把 Φ′=Φ+Δ息流 代入并按 λ′ 分组:

> λ′(g+r+Φ+Δ息) − λ(g+Φ) = **λ′(r+Δ息流) + (λ′−λ)(g+Φ)**

而 R13-2 声称的形态把首项系数写成 λ(卖前桶)。两者之差 = **(λ′−λ)(r+Δ息流) ≥ 0**(桶弱化 λ′≥λ 时)。即 R13-2 的「真惩罚全式」不是状态因果差分,是它的下界——漏掉 (λ′−λ)(r+Δ息流) 一项(量级:λ 差可达 ~0.3 × (r+Δ息流,可达 ~5+135)≈ 数十金)。

矛盾证据在登记表内部:R14-1 引理步骤 2 自己写出的「全式真值右端 = **λ′_true**×(refund+Δ息流_true) + d_true×(g+Φ_true)」用的是 λ′_true 首项——这是**正确**的精确形态,且 R14-1 的逐项覆盖论证(首项 λ′_U≥λ′_true)恰以正确形态为目标。于是:

- R13-2 声明的全式(λ 首项)与 R14-1 证明覆盖的全式(λ′ 首项)**不是同一个量**,登记表单一源纪律破;
- R14-1 节头声明「R13-2 的步骤 2 残差登记逐句被 R14-1 复用」——但步骤 2 的 g 分量残差推导基于错误(偏小)的全式,「残余收窄为 Φ 差分分量」的量化登记对象错了;
- 行为层无 fail-open(估计式首项用 λ′_U ≥ λ′_true ≥ λ,对两个形态都覆盖),但这是碰巧,不是登记表声称的论证链。

**修法方向**:R13-2 全式改述为 λ′(r+Δ息流)+(λ′−λ)(g+Φ)(展开直读),并注明与 R14-1 真值右端一致;步骤 2 残差推导按修正全式重核(结论方向预计保持:g 主部残差界不变,新增的 (λ′−λ)(r+Δ息流) 分量被首项 λ′_U×(refund+Δ息流̂) 的覆盖同源承载);R14-1 零冲突自查补「与 R13-2 全式定义一致性」一行。

## 高-2【内部矛盾】V_power 全式消费 d̂×(g+Φ̂) 与 R5-7/R6-4/R2-8 的 Φ 接口收口互斥:差分项数值无合法来源

**位置**:设计 §2.2 line_switch_sell 行(R13-2/R14-1 全式「…+d̂×(g+**Φ̂**)」)× 设计 §1 horizon/lambda_death 行 + 登记表 R2-8/R5-7/R6-4 + §5.3「全量 W 不可达断言」行。

**缺陷**:R13-2/R14-1 的 V_power 全式在**卖面判据比较位**直接消费数值 Φ̂(基础流下界=Ī×R_剩余)。而接口收口三处明文:

1. R2-8/R6-4(设计 §1 horizon 行):「估计器仅作模块内组成说明,**无外部消费位**——敞口比较 API 模块内自算、Δ息流走息律递推,均不消费 Φ̂ 数值输出」;
2. R5-7:「本模块与 lambda_death 对外只暴露 ①增量算子 ②区间敞口比较 API(布尔返回)——全量 W_floor/W_flow/Φ 数值在类型上不可达」;
3. §5.3 静态断言:「全量 W_floor/W_flow/Φ 数值不出现在任何判据比较位…模块私有量被外部 import = 测试红」。

现在 d̂×(g+Φ̂) 需要一个 Φ̂ 数值进比较位,而它的两条取得路径都违反既有纪律:**(a)** horizon 导出 Φ̂ ⇒ 违反收口(Φ̂ 恰是估计器数值输出,「全量 Φ 不可达」的措辞挡不住——Φ̂ 就是 Φ 的代入值);若静态断言按字面实现,R14-1 正确公式**必红**;**(b)** criteria/proof 侧自算 Φ̂=Ī×R_剩余 ⇒ Φ 是总纲 §2 的 22 项状态量之一,「每项只在本层实现一次,判据模块禁止自算」(设计 §1 状态函数层纪律)——双源漂移口。敞口比较 API(布尔)也不承载「产出一项进求和式」的形态。

**论证**:这不是措辞张力而是规格互斥——R13-2 的零冲突自查仅声明「消费的仍是增量算子形态,Φ̂ 为已登记下界口径,非全量 Φ 输出」,但 R5-7 的封闭集是「对外接口仅 ①② 两口」,d̂×(g+Φ̂) 两口都不走;R14-1 零冲突自查的清单(R12-1/R10-1/R8-3/R13-5)漏掉了 R5-7/R6-4。R14-1 的反例论证(「CI 端点不保序」)恰好说明差分项是乘积/求和复合形态,不能再靠「同表同端点」的既有口子糊过。

**修法方向**:三选一并登记——①把 d̂×(g+Φ̂) 项的路由上收到 lambda_death/horizon 的**敞口比较 API 扩展形态**(API 返回该复合项的数值,Φ̂ 仍模块私有),收口语义从「布尔」扩为「布尔+登记复合项」;②在收口清单显式增列「Φ̂ 下界常量输出」为第三口,§5.3 静态断言措辞同步(禁全量 Φ、放行已登记 Φ̂);③维持类型封闭、把整条 line_switch_sell 比较式整体下沉为 horizon 侧谓词(代价大,不推荐)。无论哪条,须回改 R2-8「无外部消费位」句并补 R14-1 自查行。

## 高-3【验证计划漏洞】塌缩出口「开闸」依赖 u/V_slot 标定,但标定批(对拍2)范围不含 u——开闸事件无构造性到达路径,R14-2 双态锚② 复活「正确实现也必红」红线

**位置**:设计 §2.2.1 分支表第 4 行(u/V_ms/V_slot 全🔴 ⇒ 塌缩整体延迟,**对拍 2 标定批完成后开闸**)× §5.3 对拍 2 行 × §2.10 F6 段 × 总纲 §3.3 #1。

**缺陷**:换线塌缩出口的可用条件 = u、V_ms、V_slot 三者全部脱离🔴。而:

- §5.3 对拍 2(标定通道)范围 = **V_gap / V_ms / ρ** 三量——**u 不在标定批清单**;
- 总纲 §3.3 #1 对 u 的口径是「数值不授权(P41 修复批**撤销**)」——撤销之后全框架没有任何再授权/标定路径排期;
- V_slot 的载入依赖「被阻断动作净 EV」,后者又依赖 u/V_ms——V_slot 的标定通道同样未定义;
- §2.10 F6 却把 u 当作「标定后才能开闸的闸门量」写端点纪律(下端/上端分端)——F6 的前提(u 可标定)与总纲 #1(u 不授权)、对拍 2(不含 u)三处互不一致。

**论证**:R14-2 刚论证过「正确实现也过不了的验证行=错误红线」。双态锚的态②「标定开闸后批断言换线事件数>0」以「开闸」事件到达为前提;按当前验证计划,该事件**构造性不可达**(u 永远🔴 ⇒ 出口永远延迟 ⇒ R13-1① 前置门永远拦 ⇒ 换线事件恒 0)。R14-2 消灭的是「首批 sim 构造性必红」,同时在态②里埋了一个「任何 sim 批都构造性必红」的同型红线;连带 R13-1① 前置门、R9-2/R11-1 的 stop_flag 整链在生产态永久休眠——设计花了 R9-R13 四轮打磨的时序,可能整体是死规格(或至少开闸时点无人能定义)。

**修法方向**:①对拍 2 范围显式扩 u(与 V_ms 同源单标定,禁双源同判),V_slot 定义载入条件(=u/V_ms 就绪后的派生量或永久按 R11-4/R12-5 保守端 0 代入并把它从「全🔴延迟」条件里摘出);或②显式定谳「u 永不标定」的降级终态(E_rev/卖面 max(V_opt,…) 臂永久 fail-closed 的行为规格+换线机是否永闭的裁决),并同步改 F6 的 u 行与 §2.2.1 第 4 行的开闸条件。二选一,禁悬置。

## 中-4【验证断言边界错误】§5.3 卖后桶对拍断言②「桶弱化帧(λ′_true≥λ_true)d̂>0 恒成立」在非严格弱化帧为假

**位置**:设计 §5.3「卖后桶 λ 重评对拍」行断言②。

**缺陷与论证**:断言以 **≥**(非严格)定义桶弱化。取 λ′_true=λ_true(桶观测量变、真值 λ 不变的帧)且两桶 CI 退化(点估计):d̂=max(0, λ′_U−λ_L)=max(0, λ′_true−λ_true)=0——断言②的「d̂>0 恒成立」为假,正确实现挂锚。覆盖链只给 d̂≥d_true,不给 d̂>0;这正是 R14-1 自己声明的「点估计退化 CI 时=0」情形,断言没消化自己的前提。

**修法方向**:断言改「桶弱化帧 d̂≥max(0, λ′_U−λ_L 按定义直算值)∧ d̂≥d_true(可由注入真值核)」,或把「桶弱化」限定为严格(λ′_true>λ_true)并在锚场景构造注入。

**缺陷与论证**:安全阀在连续 bench 满拒买 ≥N_crisis=2 个备战期时**无条件卖最弱线外垫件(不限 1★)**——不可逆卖出由一个手写常数触发。骨架层原文只有「连续拒买时无条件卖最弱垫件」,无量值;「2」是本设计新引入的触发门限,却未标【注/推/拟】(公理 5)、未入 audit/provisional.py 或 derived.py 登记表,也未进 §5.2 指标行(设计正文声称「触发计数、N 值与卖出件数进遥测(预期=0 触发)」但 §5.2 无对应行)与 §6.4 测试位(①-⑧ 无安全阀行为锚)。对照:同批的 floor_eff 参数化被严格溯源到 cap_resolved(R8-4),N_crisis 是同位面漏网。

## 中-6【验证断言非构造性】R14-2 态①「switchline_exit_blocked 计数>0」依赖换线判据在 seed 集内至少一次判真——无构造保证

**位置**:设计 §5.3 P16 接线验证行(双态锚态①)。

**缺陷与论证**:态①断言「switchline_exit_blocked>0 ∧ should_switch 评估调用计数>0」。后半(无条件评估)构造性成立;前半要求存在「E(alt)·(1+δ)+θ < E(cur)·(1+δ) 判真、驻留达标、却被前置门拦」的帧——这是状态依赖事件,40 seed 上默认线不劣于任何 alt 时合法取 0。这与 R14-2 治的病同根:验证行把「数据里恰好会出现」当「构造性必然」。态② 同理叠加高-3 的开闸不可达问题。

**修法方向**:锚改合并计数「switchline_exit_blocked + 臂① switchline_skipped >0」(后者由旁路恒 false 构造性非零),或在 sim 批显式注入弱势默认线场景作构造帧;态② 开闸问题随高-3 一并治。

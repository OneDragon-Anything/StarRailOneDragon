# 00 哲学与约束

> 数字来源标注：【注】游戏定义值 /【推】已证推导 /【拟】观测估计 /【拍】用户立场登记值（详见图例 = README 术语表）。
> 本篇是 CW 策略的**第一性约束层**：后面各篇（= 本目录全部现行篇，篇目索引见 [README](README.md) §2）的任何判据与本篇冲突时，以本篇为准。
> 术语：**λ_death** = 死亡危险率（在「当前难度带 × 血带 × 位面 × 节点」条件下打输下一场战斗、进而威胁存活的概率估计），是策略里唯一「错了就出局」的参数。

## 1. 宪法六条（用户裁定，最高权威）

1. **策略不依赖战力建模**。决策依据 = 游戏定义值或核心已定义规则；经验拟合/采样分布不得作决策依据。
   - 判读：任何判据若消费「胜率映射表 / 掉血先验 / 板面强度评分」这类拟合产物作闸门，即违例（旧 strategy/01_posture §6-§7 的 `HP_LOSS_MU`/`p_win_p2`/`effective_hp_threshold` 是违例史实）。
   - 合法例外 = §3 hp 使用边界的合法消费面闭集，出集须用户逐项确认。
2. **位面只能作参数**。位面进通用模型的方式只有一种：作（节点数表/伤害基准表/档位表）的**查表键**。按位面枚举机制适用范围（如「只在位面 2 生效的模块」）= 设计缺陷，必须通用化重写。
3. **姿态 = 发展优先默认，危险信号只升不降**。压制发展的机制不得出现（详见 §4）。
4. **数学先行**。每个机制规格必须可证明或显式登记待证假设；数字来源标注（四种：【注】/【推】/【拟】/【拍】）章程见 [01_math_framework.md](01_math_framework.md) §6。
5. **框架层/策略层所有权边界：框架层只留游戏原始真值，一切衍生打分归策略层**（用户裁定 2026-09-23）。
   - **框架层**（`kernel/`，跨策略共用）只承载三样：①游戏原始效果与机制真值——游戏定义的效果数值/概率/文案原文，注册表【注】直读；②答案由游戏唯一确定的机制事实判定（例：「某投资环境的发放角色是谁」「某策略卡的稀有度是什么」）；③非打分的跨策略共用基建（状态容器/动作类型清单/上报函数族/观察读口）。
   - **一切衍生打分与策略内容归策略层**（`strategies/`，含默认策略实现与第三方插件策略）：评估表（现金/方向/赠卡组件分与立场分等卡牌价值分，如 `strategy_economy` 折算、`LINE_STRENGTH_SCORE` 档分）、定序结构（优先级档/域带/序常数）、权重与阈值、估值模型（金等价折算等）、亲和/契合表、血本位回避等策略立场、决策 policy 本体。
   - 判据线一句话：**换一套策略实现，会不会要不同的值/序？会 → 策略层。** 评估表是策略立场不是游戏知识——别的策略实现完全可以给不同的分；框架层承载它 = 冒充单一源（单一源 = 同一知识只在一处权威定义），既剥夺其他策略的定制权，也使默认策略无法私有自己的评分。
   - 裁定即生效：kernel 内存量评分（评估表/事件定序等）按本条读作**待迁策略内容**，迁移为已登记的待办（追踪归迭代账本，不进本篇正文）；kernel 的物理边界（`kernel/` 目录）不等于所有权边界，判据只认上一行的判据线。
6. **策略层组织：一画面一策略文件、一画面一策略文档；共用判据显式抽离**（用户裁定 2026-09-23）。
   - **代码面**：每个画面的策略（该画面的决策入口 + 打分/定序/立场）单独一个文件，驻策略层；禁多画面决策逻辑共居一个大文件（存量违例面——flow.py 多入口合体、kernel 内多画面评分合体——按第五条一并待拆）。
   - **文档面**：每个画面的策略文档单独一个文件，与代码文件一一对应（存量违例面 = [25_event_overlays.md](25_event_overlays.md) 打包事件面约十个画面，迁移到该画面时随批拆出）；跨画面的共用判据仍归判据权威定义篇（[13_pick_family.md](13_pick_family.md) 等），对应代码侧的共用模块——文档与代码同构。
   - **共用模块**：多画面共用的判据/立场（如血本位回避、用户转向轴、终局方向解析）显式抽离到独立共用文件；依赖方向单向——画面文件 → 共用模块，禁止画面文件互相 import。
   - **迁移节奏 = 逐画面推进**：一个画面一个迁移批（策略代码文件 + 策略文档 + 测试三同步），完成一个再开下一个；批内不夹带其他画面的迁移。

## 2. λ_death 的地位：不是最重要的参数，是唯一「错了就出局」的参数

（出处：已删除旧文档 lambda-risk-philosophy §1）

- 按**决策数量**：约半数决策走阵容知识、纯公式走经济数学，不依赖 λ；λ 只管少数关键节点（保利息 vs 转化的切换）。
- 按**错误后果**：其他参数错 = 少赚（可恢复）；λ 错 = 死亡（吸收态，一局清零）。期望总收益 = Σ(活到 t 期概率)×(第 t 期收益)——不压住死亡概率列，任何「贪心最优」都证不出来（吸收态论证，先验成立，不依赖语料）。
- 由此推出本链的姿态架构（§4）：默认姿态 = 发展优先；死亡风险不作策略判据输入，λ 概率侧只作标定工件与未来安全带通道。

## 3. hp 使用边界：hp 是对局结果，不是策略决策的输入（用户裁定 2026-10-28，权威口径）

- **裁定本体**：策略器做买牌/升级/刷新/阵容/投资决策时，**判据里不出现 hp**——判据判定的对象 = hp 参与「做什么决策」的分支/门/授权；「hp 低于某线就做/不做什么」的策略逻辑 = 过期设计，禁止接入调用。立论：只要策略是正确的，hp 自然没问题可以通关。
- **合法消费面闭集**（现行全部 hp 消费面，出集 = 违例）：
  1. **观测与遥测面**（hp 是事后读数，看结果不构成决策输入）：备战屏血量读取 + 对账 + 状态容器(GameState)三态写端；结算屏读取（P15 掉血公式的 hp 分量数据源）；sim 状态副本(GameState)模型（开局血量查表/败局扣血/首次 0hp 保底——游戏全局机制）；遥测与复盘指标；濒死带观测谓词（`statefn/predicates.py` p1/p2_blood_floor，纯观测分键，零行为）；开局血量先验（状态副本事实面，`cw_opening_hp`）。
  2. **血本位局的币种读数**（血本位局 = 持有「奋斗协议」等把购经验币种从金币改成血量的投资卡的局）：经验批支付门读血余额判「买不买得起」——支付能力/账户余额检查，与「金不够买不起」同构，非「血量低就不做」的线判据（读口 = `kernel/cw_hp_policy.decision_hp` + 可信位）。
  3. **概率侧标定工件**：λ_death 表（P51 标定工件）保留血带维数据；「hp 入概率路由键合法——概率侧非价值侧」（用户裁定二既裁例外）。λ 表现役无决策消费（血带维键构造已随 hp 判据删除撤除），新增概率侧消费须先过 §6 λ 表使用纪律审查。
- **此闭集之外**，任何 hp 进策略判据的形态**须用户逐项确认后才能实施**；观测分键升级为决策消费点 = 触发本条确认义务（决策消费点统一读口纪律见 `kernel/cw_hp_policy` 模块头）。

## 4. 姿态架构：发展优先默认

（出处：已删除旧文档 lambda-risk-philosophy §3 与旧总纲 NEW_MATH_FRAMEWORK.md 安全带架构裁定；hp 维安全带消费面删除 = 2026-10-28 用户裁定，见 §3）

- **默认姿态 = 发展优先**（用户学派）：经济 + 阵容决策做对 → 自然赢 → 血不担心（hp 是对局结果，§3）。该命题的**可证形态 = 域命题**：当 λ×敞口（=当前风险大小）×剩余视界（=剩余战斗数）小到二阶（=影响量级小到可忽略的次级项）时，发展优先 ε-最优（ε 由 λ 上界压住，P52 已证）；**无条件形态不可证**（吸收态论证反对）。
- **hp 维安全带（血线硬地板/λ 顾问升档器）消费面已删除**：血量不入姿态架构；「错了就出局」风险由判据门族自身的保守方向承载（fail-closed：读数或判据存疑时拒绝动作）+ §3 合法消费面闭集。λ 表保留为概率侧标定工件（§3），查表消费纪律见 §6。
- **新增安全带形态的两验收条件（缺一不批；对新安全带提案恒适用）**：
  1. **实现不难**：升档器是判据外的独立薄层（消费既有标定工件，不改七面判据权威定义（01 §3））；
  2. **激活率门**：正确决策下触发率个位数百分比内（骨架与 EV 两形态 sim 实测，超标 = 过敏感回炉）。
- **绑定约束（写入验收）**：安全带的一切行为**不得在安全域内推迟或抑制发展动作**（P52 定理的安全域 D_ε 上安全带不动作）；任何实现或标定违反此约束 = 全架构回炉。

## 6. λ 表使用纪律（实证刻度）

（出处：已删除旧文档 lambda-risk-philosophy §5；旧总纲裁定一：λ 查表键选型 B1）

- **表键 = λ 查表键**（难度带 × 血带 × 位面 × 节点，2×3×2×4=48 格，空格 10 显式标空）。位面在键中 = 查表键，正是宪法第 2 条要求的形态；板面/bench 战力桶**不入键**。
- 消费纪律：区间 + 保守端 + 单调约束（PAA 等保序回归；血带方向 = 血越低危越高，脚本内方向断言护栏）；同格亚组异质性 <0.05。
- 实机刻度 0.34-0.85；λ≈0 段在实机刻度上是空集——旧「三段管辖（按 λ 分段路由判据）」已整体停用（旧总纲裁定取代），现行 = 本篇 §4 姿态架构。
- 局数少的质量门与兜底：翻转面扫描带（held-out 误差、阈值扫描）+ 四层兜底（结构规则地板/保守端/域外保利息/定向补样）。**状态 = 后续待观察，非稳定**（用户 2026-09-02 带条件解除质疑并登记在案：以发展主线不受影响为前提；禁终态表述；观察载体 = 漂移哨兵/键重估触发器/标定批质量门/激活率基线）。

## 7. 数据通道纪律

（出处：已删除旧文档 lambda-risk-philosophy §6）

- **实机 = 点火不是燃料**：实机对局只用于初始化与验收（结算屏三项遥测每局 ≈25 轮样本 + 版本更新基准 + 最终验收），不承担 λ 扩样/标定——λ 的扩样、标定与 sim 压测全部离线进行。
- **sim 战斗表与 λ 表同语料 = 循环**：注入对模型风险零信息——sim 只当压力测试，禁当概率来源。
- 难度值 = 局内读取为准（真值），公式计算值 = 兜底 + 对账（对账持续偏差 = 版本改难度机制的最早警报）。
- 运行时监控钩子禁止吞掉「审计条件行」（只记条件满足与否、不带身份标识的日志行），必须消费带身份键的必写行。

## 8. 死因实证背书（为什么默认姿态是发展优先）

（出处：已删除旧文档 lambda-risk-philosophy §4 与 DEATH_POSTMORTEM.md 57 死局逐局复盘——两者均为已删除的旧文档）

- A 决策质量 54%（最大单一主因）：其中 A1「该买不买」21 局 ≫ 买而烂 10 局；
- B 反应缺失 32% 非零；**A1+B 同根（消费被攒利息/升级姿态压制，无紧急通路）= 68% 单一错误模式**；
- C 不可挽 14% = 预期地板。
- 设计对照：68% 形态恰为骨架层 M1-M4 义务动作直接治（[02_mandate_layer.md](02_mandate_layer.md)）；B 类真实存在 = 安全带（升档器）非死重。验证判据基线 = 同口径复算死因分布，A1+B 塌向 C 地板 = 骨架生效硬信号。

## 9. 机会性精修道（资源分配）

战力建模工作**不设终止**——有并行闲槽即继续（精益求精），两条件：①不影响主体（主流程判据/代码实现/sim 不等精修结果，λ 查表键薄层按既定设计消费）；②新产出进策略仍过硬闸门（逐项用户确认）。精修项池：λ 尾部标定/bench 维扩展/候选形态升级/词缀-λ 交互等，按闲槽派批，主流程优先级恒高。

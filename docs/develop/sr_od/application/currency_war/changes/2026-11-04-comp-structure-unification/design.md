## 1. 问题与动机

### 现状症状（五项，逐项有代码证据）

- **S1 羁绊主次靠字段名分箱 + 键序隐含约定**：`Comp.form_tiers`（主档）/`sub_tiers`（副档）两个独立字段表达同一维度（羁绊要求强弱）；「主派」身份靠 form_tiers **首键**承载（`cw_intention._p1_pair_lines` 唯一生产消费），全库 21 线中行为真正受键序影响的极少（龙丹战技点、专家桑博DOT 两处——首键选择决定体系映射挂载：龙丹次键列车 4 若居首则挂入列车体系，桑博次键贝洛伯格若居首则错挂希儿系；其余 19 线键序无关）。3.1-3.3 过渡期该读法行为不变依赖 dict 插入序保真（语言保证），3.3 随机器退役。
- **S2 克制机器四段间接链路，活链路仅 2 条**：阵容羁绊名 → `LINE_FACTION_TO_MECH`（3 对：2 恒等 1 改名）→ 打法特征 → `MECHANIC_COUNTERS`（12 行）求交。生产者仅 3 特征、克制表值域交集仅 2 行（净化→DoT/减益、掉血削上限→燃血），10 行从未生效；`AFFIX_MECHANIC_MAP` 另有映射到不存在标签的死条目（紧急止血→爆发机会等）。
- **S3 副档消费面未接全**：`sub_tiers` 为后加字段，投资通道（`cw_invest_channels._faction_hit_bonus` 设计文本无副档分支 → 命中落「未命中=0」）与阵容轮廓计数（`all_factions` = form ∪ flex，不含副档）两处直接排除——非设计裁定，是字段加入时消费面没跟上。
- **S4 过渡体系与终局阵容机器不同构**：P1 体系配方机器（cw_system_cards 四体系 + `update_p1_recipe` 体系对组合/对级支持度/门控-冻结-封印-重冻结封禁三态状态机/`pair_target_comp` 伪阵容物化）自成一套，与终局阵容的「候选→锁定」机器（line_select 证据分 + evaluate_lock）形态不同；冻结可撤销与终局锁「锁后不换」语义不一致。
- **S5 富余买入三通道平行、席位约束双轨**：dominance_buy / 富余转压牌库（现行编号 M6）/ 死金压牌库三个同质通道；席位处理 M6 用让位序列承载（shop.py:1893 注释原文「压牌库判据的席位维由序列末位让路承载」），dominance_buy 另搞本体收紧 + P88 特殊禁令。P88 动机事故（s77091 锁席九轮）真凶是死库存对，已有 `dead_stock_pair_buy_reject_reason` 断新生防线根治；`PRESS_NARROWED_ARMS` 已缩至独苗。

### 根因归层

- 表示层（S1/S2）：同一维度用多字段/多命名层表达，靠隐含约定（键序、改名映射）承载语义。
- 流程层（S3）：字段后加，存量消费面未同步接入。
- 约定层（S4/S5）：两套机器/双轨约束各自演化，缺乏「一套机器跑两个域」的结构收敛。

### 解决到哪

四项结构统一（见 §2）；**明确不解决**：
- 21 套阵容的数值知识（成员/档位/装备/星级/站位——数据值不变，S3 的两处副档语义修正除外）；
- 阵容选择算法本体（线分八分量结构、统一让位序十档、部署搜索三段结构不动）；
- 跨羁绊克制（速度抑制克鞋队类）——本迭代删死链路不补全，重立时按「阵容画像产出受克特征」另行立项；
- 过渡阵容的多维证据分（投资/词缀维度）——一维成员持有分先行，扩展另立。

## 2. 方案

### 系统级变化

1. **羁绊优先级结构**（详设 faction-priority）：`form_tiers`+`sub_tiers` 合并为 `faction_reqs: dict[int, dict[str, int]]`——档 0 = 核心羁绊层（同档多键 = 多核心、等权、全部凑齐才成型）；档 ≥1 = 原副档（加分层）。副档全消费面降档包含（投资 0→+30/0、轮廓计数纳入）为仅有的两处行为修正；其余消费面逐位恒等，迁移测试锁死。
2. **克制表直写**（详设 counter-tables）：删改名层 + 12 行克制表 + 词缀映射死条目，换 `词缀 → 受克羁绊名` 直写表（现役 2 条）；受克判定 = 档 0 键 ∩ 名单。行为零变（删的全是死数据）。
3. **过渡阵容结构化**（详设 transition-library）：新增 `TRANSITION_LIBRARY`（Comp 结构、最小字段、4 条起步），复用与终局同构的「0 分起步 → 成员持有计分 → >0 前 3 候选 → 成型即锁、锁后不换」机器；两套候选/锁定独立，终局锁定（现行时点与机制不变）时过渡层退役；**退役边界 = 配方决策层**（状态机/体系对域/物化链/组合决策函数）——四体系判据**数据层**（SYSTEM_CARDS 数据/card_active/engines_count/TRANSITION_TRAITS 及其结算 rung 键、胜率模型、A/B 判据门消费链）全量保留。行为大变，模拟对照。
4. **富余买入归并**（详设 press-stockpile）：dominance_buy 通道删除，场景并入 M6 压牌库（升星目标带优先、1★ 兜底）；席位约束回归让位序列统一承载；P88 全套退役。行为变，实机观察验收。
5. **涉及面黑话清理**（横切四项，用户 2026-11-04 裁定）：本迭代全部文件面（代码 + 文档）触及的文件，其注释/文档用词的**存量黑话**按统一术语表 `terminology.md` 清理——替换表内的词按表列白话改写、保留词首次出现带定义；改到哪清到哪（每个阶段清理自己文件面的存量），正本更新阶段做全文件面的违例终扫；不做本迭代文件面之外的全库回溯（存量清理范围边界以术语表 §0.4 已批准口径为准）。

### 详设划分与跨详设接口契约

四份详设按文件面与阶段边界划分（实现某个阶段只读总纲 + 对应详设）。**接口契约（唯一必须在总纲定死的内容）**：

- **契约 A（counter-tables ← faction-priority）**：受克判定读 `core_faction_reqs`（档 0 键集）；克制表直写落地在优先级结构之后，同批消费档 0 读口。**克制数据拆两张独立表**（同词缀跨羁绊分级、单一键承载不了，各自单一源互不演进）：`AFFIX_COUNTERS_FACTIONS`（3.2 建立，选卡减分，命中即减分不分级，宿主 pick_common.py）与 `TRANSIT_AFFIX_PENALTY`（3.3 建立，过渡候选统一减分——词缀/boss→羁绊名，用户 2026-11-04 裁定纯减分制无排除特殊逻辑，宿主 cw_intention.py）——各详设禁用别名、禁互相吸收。
- **契约 B（transition-library ← faction-priority）**：过渡阵容条目复用 `Comp` 结构，羁绊要求只填 `faction_reqs`（4/4 条目仅档 0，无更高档）；建库校验同规则。
- **契约 C（transition-library ↔ 现行 session_scope）**：过渡锁定 ≠ 终局锁定，互不覆写；终局锁定写入时过渡层退役清空（候选槽、锁定态、囤货带一并），锁定守卫语义不变。
- **契约 D（press-stockpile 与 3.3 的耦合申报）**：席位约束依赖统一让位序现行契约（压牌库件 = 让位末位档）；M6 兜底带的「线内成员」排除面 = 买面义务名单装配（buy_members/obligation_members，shop.py:884-904），该装配在 3.3 被改——落地顺序锁定 3.3 → 3.4（耦合点已申报，非独立批次）。

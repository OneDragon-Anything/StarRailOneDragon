# 货币战争游玩指导

通过项目 MCP server 的 `analyze_screen`（画面识别 + 结构化读数）与 `run_operation`（动作 op）玩货币战争。

## 1. 玩法简介

货币战争是纯闯关玩法，没有对手玩家：一局分 3 个位面共 23 个节点（第一位面 9 个、第二三位面各 7 个），打完全部三位面即通关；小队生命值（HP）归零则立即失败终局。玩法核心是经济——整局金币总量有限，战力要靠金币换出来（买角色、买经验升人口、刷新搜牌），多赚金币、把金币花对地方比记住任何阵容都重要。机制细节见 §3 玩法深入理解（开玩前先读玩法机制文档）。

## 2. 操作指引

工作方式：每调用一个可运行单元（op 或 application），回头做一次画面识别确认效果，再决定下一步——确认的粒度跟着单元走（单步动作 op 每步确认，串联 op / application 跑完确认终态）。画面识别不命中只有两种情况：上一动作的过渡还没结束（等几秒重新识别）；进了没建档的陌生画面（自己读图判断当前状态）。

### 2.1. 直接用自动 bot 还是自己操作

项目有完整的货币战争自动 bot（application：`run_standalone_app` 的 `currency_war`），内建策略自动打完一局。

- **适合直接用**：用户只要打完一局拿结果、不需要人工介入决策（挂机跑、日常清次数）。
- **适合自己逐步操作**：要按用户的具体偏好决策、教学演示、bot 策略不适用的场景（如定向猎取特定投资卡）、或 bot 中断后需要人工接管续局。

### 2.2. 导航

进入玩法用入口 op `CwEntryEnter {}`——全自动从任意画面导航到货币战争大厅，约 15~30 秒；完成判据 = run_status 显示已在货币战争大厅。大厅画面文档：[货币战争-大厅](references/screens/货币战争-大厅.md)。

### 2.3. 各阶段与画面的处理方案

处理方案读法：阶段标题说明这段在玩什么；一级项 = 画面名（即 `analyze_screen` 返回的名字，同时是画面文档名——`references/screens/` 下同名 .md 直达）；缩进的二级项 = 主画面的子态（内容默认在主画面文档的子章节）；「画面名 → 文档名」箭头 = 实际要读的文档与画面名不同（多个画面共用一份文档），不带箭头时名字就是文档名。

## 4. 通用注意事项

每一步都先看图：画面识别读出当前画面后，在 §2.3 的处理方案列表里定位（画面名即文档名），读对应画面文档再继续下一步操作——不要凭记忆或上一画面的印象直接操作。

本玩法特有的通用注意事项（每条 = 现象 + 原因 + 应对）：

1. **按钮点不动先查状态**：置灰 = 前置条件没满足（如三选一投资卡没选完时出战被锁）；商店面板开着时点出战第一下只收店——先收店再操作。排除状态问题后，静态点击对按钮（含长条胶囊形状）普遍有效；微距拖拽（MCP `drag`，duration 0.35）仅作兜底。
2. **动作 op 只管机械执行**：出战、拾矿等 op 不做状态校验——收店前置、未达上限弹窗确认、部署是否满足等状态检查由你负责（按 §2.3 对应画面文档自查）。
3. **传给 op 的坐标、槽号必须来自最新一帧读数**：拾矿开箱的掉落物会插进备战席非首空位、装备栏图标位置会漂——旧读数按旧槽号/旧坐标操作会落空；做完一个入席/穿装动作就重读一次再传参。
4. **延迟弹窗会吞掉先前的点击**：点完关键动作后下一帧发现弹窗（如形态二选一弹窗），视为该动作被吞——先处理弹窗再重发动作；弹窗存在期间，「备战-开商店」这类模糊命中的区域坐标会整体错位，不要按错位坐标点击。
5. **读数语义**：羁绊面板 board 字段只是可见子集（决策以 front_line/back_line 单位表为准）；商店面板开着时 front_line / back_line / deploy_count / deploy_cap / hp / reward_ores 不返回（设计性省略，不是识别坏了），要读就先收店；extras 整体 null = 识别器异常降级，用存图 + 亲自读图 + OCR 散点顶替继续对局（对局结束后按缺陷上报），别卡死等待。

# ADR-0229 遥测判读三维同屏(角色星级+装备分配入 tiers 视图)

## Status

accepted(2026-08-22;r358b;用户点题)

## Context

用户判读痛点点名:遥测采集的数据基本都有用,但判读时**看羁绊忽略了角色、装备乱用不可见**。核查:数据层完整(state 全量序列化,deployed 含 char_id/star/equips、owned 装备栏 SIFT 读入),但查询视图把阵容前景化成单维——hp 视图只显示板深(阵营人次)、tiers 视图 deployed 只显名字且截断 7 个、装备分配在所有视图都不可见。判读被视图边界限制,不是数据缺失。

## Decision Drivers

- 阵容质量的解释变量是三维(羁绊档位×角色构成×装备分配),单维显示 = 盲判(空壳档位/装备乱穿都看不见)
- 既有纪律「新复盘需求 = 新视图/查询参数」——补视图是正道,不是绕道写脚本
- 星级是 boss 质量主矛盾的观测端(核心 2★ 到没到)

## Considered Options

1. 新增独立 view=quality:多一个入口,判读要跑两条命令拼对齐——弃
2. **tiers 视图三维同屏**(选):激活档行下 deployed=名字+★数(去截断,后期 9-10 人不藏人;未知名显示 `?` 暴露身份 miss)+ 装备=谁[穿了什么] 行 + owned 滞留行——单命令单屏看全
3. 只改文档教人直查 jsonl:每次判读手写查询,回归成本高——弃(但保留为兜底,见 telemetry-reading)

## Decision

选 2。同轮沉淀判读方法论进 skill(references/telemetry-reading.md:三维表/维度清单/视图覆盖矩阵/保真位先行/「采集基本都有用,别被视图边界限制」原则)。实测收益:升级后首查即见局46 核心三人组在场/hunt3 桥件上场/全 1★/`?` 身份 miss 槽——旧视图全不可见。

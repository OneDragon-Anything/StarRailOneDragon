# 货币战争域统一术语表(terminology)

> 读者 = 写/读货币战争(CW)文档与代码注释的工程师/智能体。本表 = CW 域术语唯一速查入口:什么词必须替换、什么词保留但首次出现要给定义、什么词不许动。
> 依据:项目根 AGENTS.md「文档规范」(禁自造黑话或项目内部缩写;行业通用术语可用;项目术语首次出现给定义 + 例子)。本表按 2026-11 用户批准的清点对照表定稿(清点草案 = 迭代 2026-09-23-invest-effects-calc 的 designs/T-430-jargon-inventory-draft.md,词频快照以彼时点为准)。

## 0. 使用规则

1. **§2 替换表的词必须替换**,按给出的白话写;一词多义的按义选用对应写法,不许机械全替。
2. **§3 保留词首次出现必须带一句定义**(定义句可直接抄本表)。
3. **§4 保留词与 §5 游戏内容词不许改动**(代码真名/行业词/游戏内容词)。
4. 存量清理范围(已批准):权威版本文档(docs/develop 的 changes/ 以外部分)+ 代码注释 + docs/game 知识文档;`changes/` 迭代过程稿与 `.debug/` 不回溯清理,新写稿守本表。
5. 表内给出的写法即正文唯一写法;旧简称→全称映射表见迭代 T-435 设计稿(designs/T-435-heihua-qingchang.md 批2 节)。

## 1. 核心替换表

| 词 | 白话写法 |
|---|---|
| 腿(名词:卡的效果拆出的独立部分) | **效果条目**(双腿卡 → 含两条效果条目的卡;单腿 → 一条效果条目;腿数 → 效果条数) |
| 腿(实现形态) | 按实际形态直写全称:**写状态的实现分支** / **只登记不写状态的实现分支** / **只供策略算分的实现分支** / **只靠画面读数的实现分支** / **把结果写进状态副本的实现分支**;正文一律用全称,不再使用简称(登记腿/策略腿/观察腿/世界腿),存量由清偿批展开 |
| 世界(指状态时) | **状态副本(GameState)**——我们维护的一份游戏状态数据,模拟器靠它演算,实机运行靠它记账;句中再次出现可简作「状态」 |
| 世界真值 / 世界写 / 世界面 | **状态副本里的值(模拟器里即当作真实值)** / **把结果写进状态副本** / **状态副本这一侧** |
| 锚(画面识别义) | 名词 = **画面识别标志**(画面独有的稳定可见元素);动词「锚定」= **用识别标志确认画面**(保留词,见 §3);「双锚」= **两个识别标志同帧命中** |
| 锚(写稿义) | 「P24 锚」类 = **已裁定结论的引用**;「持久锚」= **符号名引用**(相对会漂移的行号);`cw_anchor.py` 模块名的「流程转点遥测标记点」= 标识符真名,不动 |
| 正本 | **权威版本**(项目已宣布统一此写法) |
| 在册 | **已登记**(在注册表或清单内) |
| 定谳 | **已定案 / 定论** |
| 收口 | ①「观察收口」= **不写逻辑,只靠画面读数**;②证明场景 = **证明收尾**;③流程场景 = **收尾、完结** |
| 挂账 | ①待办义 = **登记成待办**;②金额义 = **登记暂存金额** |
| 接线 | **接入调用 / 把调用点接通**;「接线底账」= **对接对照表** |
| 挂点 | **插入位置 / 调用点** |
| 落码 | **已写进代码 / 已实现** |
| 判例 | **先例 / 已裁定案例** |
| 单口 / 三口 | **唯一入口函数**(某类写操作只经一个具名函数)/ **三个登记入口** |
| 显影 | **显示出来 / 在日志里暴露** |
| 收编 | **纳入统一管理 / 并入统一结构** |
| 拍定 / 拍板 | **人为定为** / **用户决定(用户确认)** |
| 免裁 | **无需用户决定** |
| 双端 | **实机和模拟器两边**;每个文件首次出现必须写全「实机(live)和模拟器(sim)两边」,后续可用「实机和模拟器两边」 |
| 容器写 / 容器 | **字段写操作(直接改 GameState 的字段)**;「容器」首次出现写 **状态容器(GameState)** |
| 鸭子读 | **鸭子类型读取(duck typing)** |
| 口子 | **例外通道 / 旁路漏洞** |
| 宪章 | **模块职责说明** |
| 武装点 | **装配接入点** |
| 替身缝 | **替身函数的接缝(stub seam)**——为测试保留的替身函数挂接处 |
| 闩 | **一次性标志位**(置位后不再重复触发;代码标识符 latch 保留) |
| 承重 | **起决定作用**(「顺序不承重」= 顺序不承担逻辑作用) |
| 底座 | **基础数据 / 初始值**(「开局种子底座」= 开局初始值) |
| 底账 | **对照表 / 数据依据** |
| 冷建 | **每局全新创建** |
| 空发射 | **本帧无动作** |

## 2. 保留词(首次出现给一句定义;定义句可直接抄)

| 词 | 定义句 |
|---|---|
| 逻辑态 | 逻辑态 = 动作执行后不经观察、按游戏规则从动作前状态推算并直接写入状态容器的预期状态;真值以下一帧观察为准 |
| 对账 | 对账 = 推算状态与下一帧实际读数逐项比对,对不上即视为代码错误;只发生在观察边界 |
| 帧 / 帧代次 | 帧 = 一次截取画面并做一轮决策的时点;帧代次 = 帧的版本标记(完整识别/局部查看/未识别) |
| 零判效 | 零判效 = 执行代码只点击/拖拽,不判断动作是否生效;真值归下一次观察 |
| 两态制 | 两态制 = 字段值只有观察/推算两种来源 |
| 逻辑随机态 | 逻辑随机态 = 随机效果按采样结果推算直写(source=logic_rand),无法采样的留给观察 |
| id_mark 锚定 | id_mark 锚定 = 用画面识别标志确认画面,识别到的事实与容器现值比对,领先才采信 |
| 单一源 | 单一源 = 同一事实或规则只在一处定义,其余地方只引用不复写(single source of truth) |
| fail-closed | fail-closed = 输入缺失或判据不可判定时取「不动作」的保守分支,并留遥测,不猜缺省值 |
| 数字来源标注四形态 | 进决策门的数字必须标来源:【注】游戏定义值 /【推】已证推导 /【拟】观测估计(带置信区间)/【拍】用户立场登记值 |
| 终结(动作) / 交回 | 终结动作 = 结束本次访问、返回主循环的动作(如关店/出战);交回 = 结束本次访问并返回主循环 |
| 观察覆盖 | 观察覆盖 = 用本帧实机读到的值,覆盖此前按规则推算写入的值 |
| 口径 | 口径 = 对同一数据的取值范围与计算方式;比较场景优先写「同一算法 / 同一取值方式」,不要用「同口径」 |
| 判据 | 判据 = 判定所依据的条件或规则(criteria) |
| 真值 | 真值 = 当前被当作正确的值(ground truth);本项目语境 = 下一帧实际观察,或模拟器里状态副本的值 |
| 契约 | 契约 = 两个模块之间约定好的调用方式与返回内容(contract) |
| 桥 | 桥 = 把效果登记簿里的数据搬运到状态容器字段的实现(账本→字段桥) |
| 账本 / 台账 / 流水 | 账本 = 按时间或条目登记事实的数据结构;台账 = 同义的登记表;流水 = 按时间顺序的事件记录 |
| 判读 | 判读 = 对照判据读遥测数据并下结论;判读申报制 = 判读结论必须显式登记且可被后续实机数据推翻 |
| 闸门 | 闸门 = 满足条件才放行的检查点;正式文档写全「闸门」,不用单字「闸」 |
| 面 / 形 / 支 / 批(单字后缀) | 正式文档用双字词:「生命面」→「生命方面」、「四形」→「四种形态」、「封顶支」→「封顶分支」、「实施批」→「实施批次」;存量不必机械全替,新写稿遵守 |
| 效果原文 | 效果原文 = 游戏卡面/环境效果文本的官方逐字引用(官方 API 或实机截图逐字);登记纪律「字段语义 = 卡面效果原文直读」「禁从效果原文自动猜装」以它为基石 |

## 3. 保留词(不动)

- 代码接口真名:write_logic / write_logic_rand / observe / EffectSpec / GameState / Field / ChannelSig 等(改标识符不属文档清理范畴;英文标识符层 leg 等历史命名不改)。
- 行业通用词:OCR / 幂等 / 旁路 / 兜底 / 回退 / 降级 / 短路 / 哨兵 / 钩子 / 装配 / 先验 / 沿用 / 镜像 / 署名 / 簿记 / 投影 / 毒化 / 采样 / 拟合 / 标定 / 校准 / 中继 / 遥测 / 建档。
- live / sim:行业通用(实机/模拟器),首次出现写「实机(live)/ 模拟器(sim)」。
- 槽位 / 席位:游戏画面物理槽位 / 队伍槽位(坐标语义见项目 AGENTS.md 注释规范)。

## 4. 游戏内容词保护清单(游戏真名,不许改动)

大世界 / 息(利息)/ 连胜 / 词缀 / 羁绊 / 词条 / overlay(画面名用法)/ 佩佩 等游戏内容词。如遇新游戏名词,默认保护;拿不准时问用户。

# 画面 op 与观察域(screen-op)

> 组件 = `operations/cw_screen/`(一画面一 op)+ `obs/`(一屏一解析器)。路径根 = `src/sr_od/application/currency_war/`;代码定位一律用 `文件::符号名`。

## 1. 画面 op(职责四段 · node = 1 + N + 策略器按需)

- **一画面一 op**,每屏独立类直继承框架 `SrOperation`(无共享基类)。职责按四段组织:识别 → 上报 → 特殊画面流程处理 → 正常画面的策略器处理。

1. **识别**:判定当前画面身份(进入本 op 的前置检查);
2. **上报**:显式读屏〔唯一读屏点〕→ CwScreenXxxObs → `report_screen_*_obs` 写入 game state(`kernel/cw_screen_report/` 每屏一文件)——**上报先于处理**,特殊流程与策略器消费同一份观察;子态分支例外(备战特殊流程段,见「备战(CwScreenPrep)特殊」行):非常规子态帧的子态识别前置(段 1 先于读屏上报,命中即跳过全量读屏与上报),段 2 语义扩展 = **子态流程事实写**(Match 流程态字段配对写 + 接管失效写)非 obs 上报——流程事实不进 game state(真值域不混流程事实);
3. **特殊画面流程处理**:弹窗/锁定态/按钮换形态这类**答案固定**的状态——画面 op 自己的流程反射(识别 + 点击 + until 验证),不问策略器;
4. **正常画面的策略器处理**:需要判断的交策略器——决策(game state 零参读;本帧无动作 = Obs outer_loop 口径)→ 动作〔零读屏〕→ round_wait 循环无防御上限;**终结动作返回主循环**。

- **分段判据**:答案固定的 → 特殊流程;需要判断的 → 策略器。(「单选族」= 事件选卡屏的旧称:有选择面但选完即走,选择判断归策略器、确认链是机械反射。)
- **出口语义**(决策循环只有三种出口):①**终结动作**(执行即本访问结束返回主循环);②**异常 fail**(策略/执行异常上抛交外循环 retry 链;空候选 = 零点击 success 交回,禁盲选派发);③**Obs outer_loop**(本帧无动作的合法返回)。决策无有效输出/返回词表外类型 = 具名 round_fail 保留证据,不发出无依据的动作。
- **画面 op 不支持局外单独调用**:是对局上下文内的组件,不设单跑防御分支、不设兜底决策路径——无 match 场景由上下文缺失自然失败。
- **已登记变体:等待 1-1 就绪等待**(全部画面 op 中唯一允许观察 node 内轮询的特例):1-1 开局补给动画长且无结束标志、备战 id_mark 区分不了画面身份,只能判「备战面板就绪」——轮询放观察 node,超时 = 存图保留证据 + round_fail 交外循环。已登记例外仅此一条,新增观察内轮询画面必须先登记再写代码。
- **复盘同步义务**:新增/停用画面 op 须同步渲染器 `skills/sr-od-dev-currency-war/scripts/replay_to_md.py` 的画面注册表(ACTOR_REGISTRY/SCREEN_REGISTRY)——未注册的 CwScreen 前缀 actor 会在复盘报告暴露「未注册写入者」尾注。
- **node 结构 = 1 + N + 策略器(按需)**:即「1 个识别+上报节点 + N 个特殊流程节点 + 1 个策略器节点」——识别+上报合并一个 node(前置检查 → 读屏 → 上报);特殊流程每类一个独立 node(按需 0..N,**禁多个特殊流程挤在一个 node**);策略器循环一个 node——**有判断需求才有**:处理方式全固定的屏无策略段,画面 op = 1 + N(现役实例 = 敌人信息浮层 `CwScreenEnemyInfo`:识别+上报 node + 点「按钮-关闭」特殊流程 node)。特殊流程 node 的本段识别(标志判定/确认定位)= 决策环读屏例外第三类(§2)。「识别+上报合并一个 node」的线性序在子态分支例外:备战子态识别四查落观察 node 最顶部(先于读屏上报,命中即跳过读屏上报)——子态识别前置 = 识别的细化,处置段的 node 归属按「同画面子态的 node 归属」判。
- **同画面子态的 node 归属**:同一画面的不同子态,处置类似(同一段处置逻辑,子态只是入口条件不同)→ 可共享一个 node;子态间处置互斥(某子态一定只做的事,另一子态完全不做)→ 每类处置一个独立 node——处置完成的出口直达终点(round_success 专属状态词、无后续边 = 本访问结束交回主循环),未命中子态经状态词条件边过到下一处置 node。
- **弹窗归宿形态三分**:
  - **有独立 id_mark 身份的弹窗屏** → **独立画面 op**:四段只走「识别 → 上报 → 特殊流程」即交回主循环,无策略段(先例 = `CwScreenDeployNotFull` / `CwScreenNoFrontHint`——出战单击后渲染的两类真弹窗,经主循环阶段一身份分发接管);
  - **无独立档但经阶段三规则派发的独立 op**(消耗品浮层/阿哈装备)= 合法现役形态——归宿细化(判定宿主画面与是否设独立 op 的前置检查形态)随下批迭代裁;
  - **无独立身份的浮层/子态** → **宿主画面 op 的特殊流程段**;
  - **处置需要判断的子态 → 宿主画面 op 的优先分支**:子态在场时本次访问先走它,常规路径一步不做——观察 node 顶部识别子态并上报读数(零点击),决策动作 node 顶部调策略器的专属入口,由动作 op 落地;不设独立画面档、不设独立收尾 op。先例 = 合成确认浮层(备战的子态,见下方「备战(CwScreenPrep)特殊」行)。
- 备战(CwScreenPrep)特殊:全量观察(heavy)+接管补采+审计留在观察侧的观察 node;决策动作 = 单动作 while 循环;商店编排(`_open_shop_phase`)。**特殊流程段消费首批实例 = 备战交互三段链**(自主循环备战分支迁入,迭代 2026-11-18-prep-special-flow;宿主表述 = `operations/cw_screen/cw_screen_prep.py`):**合成确认浮层优先分支**(浮层 = 备战的子态:在装备栏内找成对的 ✕/✓ 定位,识别住 `obs/cw_synthesis_overlay_obs.py`;读数写 game state `synthesis_overlay`,该字段只有观察上报一个写端)。观察 node 最顶部先探商店开态(只找不点,判据 = 开商店画面档的识别标志「按钮-收起」;商店开着的帧不识别浮层——商店开着时不识别右侧装备),商店没开再识别浮层并立即上报。浮层在场 = 本次访问走**零点击观察通道**:观察 node 只做三件事——上报浮层读数、过 match 缺席前置检查、提前构建动作执行器——子态识别/清场/收店探测/接管补采/全量观察/审计全部跳过;决策动作 node 顶部(三处置之前)调策略器 `decide_synthesis_overlay` → 确认/取消动作 op → 经终结口交回主循环。有按钮候选但配不成对、或配对有歧义 = 观察失败(round_fail 交外循环重读,不写该字段);处置连续三次后浮层仍在场 = round_fail(计数 = `cw4_counters` 分键 `synthesis_overlay_click`,只在确认浮层不在场的帧清零)。处置的触发只认本次访问的识别结果,不拿字段值当触发(字段留着上一帧的值)。浮层不在场,接着做**子态识别四查**(先于 match 缺席前置检查/清场/收店探测/全量观察/补采/审计;优先序 0 > a > b > c),命中即跳过全部既有前置段,四查全未命中走现行全量路径零变化。四查逐条(触发条件 → 处置):
  - **0 锁定确认态**:`Match.locked_resume` 在场(含 3b 重试耗尽后主循环重派发的重入帧)→ 直达处置 3b;
  - **a 返回按钮子态**:OCR 读到「返回投资策略选择」(LCS 相似度 0.9 阈值)→ 进入处置 a;
  - **b 接管局探针子态**:`opened_via=='takeover'` 且尚未探测过(接管局必经,位面 1 第 1 节点的接管局同样探测)→ 分支进入即写接管失效字段(先于探测点击,覆盖全部接管局)→ 点「按钮-商店」试探商店可开性(识别性点击,读屏例外 §2④)→ 判定:可开 = 非锁定 / 不可开 = 锁定 → 探测后写去重标志(一次写);非锁定时收店恢复后按序跑齐全部既有前置段走常规 / 锁定时三字段配对写直达处置 3b;
  - **c 补给分流子态**:节点序表当前节点为 supply 且补给未确认 → 进入处置 c。

  决策动作 node 顶部(段序号置位之前)做**三处置**:a 点返回(成败均交回主循环,计数 = `cw4_counters` 分键 `back_to_strategy_symptom`,cw4 前缀 = 历史策略包代号的遥测键命名残留,该包已删除)/ b `locked_resume_sync_and_battle` 同步步骤+出战(成功 = 锁解除+交回;未执行时重试保持锁定,每访问最多 4 次,耗尽 → 访问 fail → 外循环连续失败计数)/ c 点「返回补给阶段」(成败均交回主循环);交回 = round_success(wait 2/3/2),战斗窗置位由外循环回调统一承载。三子态不拆独立 op(宿主同 = 备战画面,派发依据双识别标志无独立身份);三处置互斥(a 只点返回投资/b 只锁定出战链/c 只点返回补给)→ 按「同画面子态的 node 归属」应拆三个独立特殊流程 node,现状三类处置挤在决策动作 node 顶部 = 待整改(登记在待跟进事项文件 `.temp/tracking/currency-war/待跟进事项.md` 的「备战三处置拆独立 node」条)。

## 2. 观察域(obs/)

- **唯一读屏点**:画面 op 观察 node 的显式读屏(备战入口全量观察 `obs/cw_observe_full::observe_full` 为其重型形态);已登记读屏例外五类——①策略显式发出 Obs(in_place) 触发的重观察;②终结分支返回前机械保留证据读(零决策、不做效果验证,读数只写入缺陷记录行);③特殊流程 node 的本段识别(§1 段 3:答案固定状态的标志判定与确认定位,先例 = `CwScreenDeployNotFull` 落地复查位与 `CwScreenNoFrontHint` 确认后的标志复测);④段 1 子态识别的识别性点击(备战特殊流程:探测点击〔点「按钮-商店」试探商店可开性〕与非锁定收店恢复点击——点击 = 识别手段非策略动作,裁决结论经段 2 流程事实写上报);⑤观察 node 顶部的子态前置识别(备战:商店开态探测与合成确认浮层识别——只找不点,读的是子态标志不是全量观察,结果决定本次访问走不走浮层分支)。
- **观察标准化规则**:观察内容在所属域存在标准注册数据(名字类:投资环境/投资策略/角色/装备等注册表)时,观察 node 必须把读数**转换成标准注册数据再上报**——转换两段:①形变归一(分隔符/全半角等 OCR 常见形变)后精确匹配;②不中再做 LCS(最长公共子序列,OCR 文本相似匹配算法)相似匹配(域级单一实现 `kernel/cw_obs_core.py::lcs_resolve_strict`,阈值常量住各屏);两段皆不中 = 转换失败。**LCS 阶段执行次高分差拒判**——最高分未明显高于次高分 = 歧义 = 转换失败,禁直接取最高分。**任一候选转换失败 = 观察失败**:round_fail 提前返回、不写 game state 不上报,交外循环重读(读不准就重读,禁止带错误数据上报);多候选命中同一注册名(选项互斥屏)同判转换失败(重复名合法的观察面不适用)。标准化后下游全链只在标准名上工作:决策消费标准名,动作上报只携 idx,名字由 game state 标准名单一源按序号提供——动作/上报层零名字转换。未标准化的名字类直报 = 待修问题,禁新增。**登记例外——参考读数类**:流程不依赖的名字读数,对不上注册表时不上报失败。先例 = 合成确认浮层框内的装备名:以 `name=None` 连同分数照报、观察照常成功(流程只依赖按钮坐标;按规则提前失败会让模态浮层永远收不起来、整局停);对得上时取的仍是注册表标准名。新增此类例外,必须在代码注释里写明「流程为什么不依赖这个名字」。
- **实例载体纪律**(决策输入与机械执行载体分立):凡用于**决策**的输入(候选内容)与**门槛判定**(候选非空)一律取 **obs 载体**(观察 node 挂实例属性)或**game state 槽**(零参读);画面 op 实例上的其他载体只准存**机械执行细节**(点击点等「往哪点」),禁承载决策输入、禁作决策门槛。
- 观察 node 上报 = `report_screen_*_obs` 写入 game state(`kernel/cw_screen_report/` 每屏一文件)。**上报接口包形态**:每屏一文件(obs 类 + report 函数同居,与动作侧 `cw_action_report/` 每动作一文件对称);obs 类 = `CwScreenXxxObs`(该屏一次观察的类型化载荷,纯数据);上报函数 = `report_screen_<snake>_obs`(「一个上报概念一个形状」,禁按类型聚合的分派转移函数)。节点推进上报族例外:推进走 kernel `report_node_advance`(trigger 封闭集 {settle_confirm, supply_finish}),不设 report_screen 形态。chosen_*(选择落地记录)不进 report——由动作上报/获得链按「点完即写」契约承载,字段级归属 = 代码字段定义注释(`kernel/cw_game_state.py`)。
- **观察对账唯一发生点**:推算状态 vs 下一帧实读的比对只在观察边界(report 写入 game state 时,由 game state 执行仲裁 `kernel/cw_reconcile.py`);其余任何层不做双态比对。
- 观察 node 上报 = `report_screen_*_obs` 写入 game state(`kernel/cw_screen_report/` 每屏一文件)。
- **观察必须产出坐标**:观察侧识别到的可交互实体(选项卡/备战栏条目/装备栏条目/晶矿/浮层按钮等),其上报事实一律携带画面坐标(cx/cy 或等价定位)——game state 字段与 MCP extras 同源可得,坐标不得只存在于 extras。用途 = 动作原语参数第三类(动态坐标显式传参,见 SKILL.md §1.4)的坐标来源:动作 op 按坐标/idx 自取,零内部识别。坐标字段只由观察上报写入(每次整表覆盖、随帧刷新);**禁止动作执行后回填坐标**(实体刚获得时还没有画面读数);坐标缺席语义 = 动作发出侧跳过该动作、下一帧重新观察后重派,禁止猜值回填。先例:事件线 pick 族的选项坐标字段、`owned_equip_xy`。
- **观察层失约抛错**:决策入口消费的 payload 槽离屏 None = 观察层失约(如 shop payload 离屏)——显式报错,禁策略侧兜底。
- 识别器(`obs/recognizers/`)注册为 `analyze_screen` 的 extras 扩展,MCP 读数与画面 op 观察同一实现(双消费面,见 SKILL.md §1.4)。
- **观察事实双面同集**:同一画面单帧读屏得到的结构化观察事实,op 上报(game state)与识别器 extras 两面键集一致——op 读到的,extras 必须同键返回;只加一面 = 违例,实现同源不豁免(共用同一实现但 extras 不把结果带回仍算缺)。跨帧推导状态与流程事实不属观察事实,两面都不放。用途 = MCP 调用方与策略层消费同一份读数,MCP 侧零推算。
- **识别不到就是 bug 的停机规则**(与动作侧「点完即写」同族规范):商店未识别卡、召唤物/物品未识别等观察侧停机见 [guards.md](guards.md)。

# 0003. 写方法论,不写具体例子(限 SKILL.md + 智能体读的辅助文件)

- **Status**: accepted
- **Date**: 2026-07

## Context
SKILL.md 注入智能体执行上下文。若正文写「某具体项目 / 场景的做法」(具体坐标 / 具体流程 / 具体游戏事实),智能体会把例子的**偶然细节当成必然规则**,套到不匹配的新场景 → 以偏概全。

## Decision Drivers
- **跨场景适用**:方法应抽象成判据(「X 条件下选 A,Y 条件下选 B」),而非某项目的做法。
- **执行有效**:智能体照判据做,而非照搬例子。

## Considered Options
1. **写具体项目例子**:直观,但以偏概全。
2. **只写抽象方法论 / 判据**(选中):跨场景适用。
3. **完全不写具体**:连纯语法 / 字段名都不写 → 连最小可用形式都没有,不可执行。

## Decision
选 2:SKILL.md 正文 + 智能体读的辅助文件**只写方法 / 原则 / 判据**,不写具体项目叙事例子;不得不具体的,**仅限纯语法 / 字段名**(frontmatter `name`+`description`、命令必填参数),给最小可用形式。具体游戏事实(键位 / 坐标 / 机制)归 doc 不归 skill;「为什么选 A」「项目遇过 X」归 design/ 的 ADR。

## Consequences
- **正向**:skill 跨场景通用;智能体不把例子偶然细节当必然规则。
- **负向**:抽象判据对新手不如例子直观(靠 design/ ADR + doc 补具体)。
- **边界**:框架地基级接口名不受本条约束(那是硬规范 3「稳定操作对象」,见 [ADR-0002](0002-self-contained-framework-interface-names.md))。

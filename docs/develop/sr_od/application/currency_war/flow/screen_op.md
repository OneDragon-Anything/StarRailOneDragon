# 画面 op 统一规范（screen_op · 目标态）

> **状态声明**：本篇是单动作循环迁移（accepted）的规格篇,**已随单动作实现批（2026-09-06 实施批）落码**——现行 as-built 描述见 `shop_visit.md` / `prep_visit.md`;本篇「现行代码映射（迁移面）」小节保留为迁移决策记录（落点核验 = r5-migration-plan 处置表）。
> 术语：**画面 op** = 负责一个游戏画面的一次访问的 Operation（如商店、备战）；**外循环** = `cw_loop.py` 的画面识别分发循环；**期望态** = 画面 op 内部维护的「决策所依据的画面状态账」；**终结 op** = 执行后本画面访问即结束、交回外循环的动作；**波批** = 旧形态（已退役）：一次观察算出整波动作列表再逐个执行。路径根 = `src/sr_od/application/currency_war/`。

## 1. 规范总则（决策 1、2）

**一次画面 op 调用 = 一轮「入口观察 + 逐动作决策循环」**（决策 1，用户裁定）：

```
画面 op 入口
  ├─ 入口观察（唯一读屏点之一）：真实读屏 → 生成期望态
  └─ 决策循环：
       while True:
         action = 策略器(期望态)          # 每次恰返回一个动作（决策 2）
         action.execute(ctx)              # 机械执行 + 守卫断言（§2）
         期望态推进 = 容器规则通道直写    # 落地门 apply_action_outcome（§2.1;project 已退役）
         if action 是终结 op: break       # 画面 op 结束，交回外循环
```

- **决策循环内不读屏**（决策 1/8）：期望态的生成与更新都不得依赖读屏；识别质量问题归识别层既有遥测，不进决策循环。
- **策略器每次只返回一个动作**（决策 2）：与现行 `decide_shop_screen` 返回 `list[Action]` 的整波形态相对。「合法性判定全部内化于策略器」（决策 2 和解注，2026-09-04 对抗审查裁决）：策略器以期望态为据只提合法动作——画面内合法性是**提议侧约束**；执行侧只余守卫断言（§2），不是第二道合法性门。
- **外循环形态不变**：画面识别分发、轮次推进、停机/遥测钩子（`outer_loop.md` 全篇）不随本规范改动——改的只是画面 op **内部**从「一次算整波」为「循环问一次」。
- 波批形态消灭的 bug 类（波内口径记账族：金位买后逻辑态口径 / 席位静态逻辑态口径 / Σ活期退金帧级让渡 / j 低估 / 同槽去重防线）：在新结构无存在载体，明细 bug 类。

**现行代码映射（迁移面）**：
- 商店：`strategies/impl/mandate_v1/shop.py:497 decide_shop_wave`（整波 `list[Action]`）→ 改单动作接口（选择序不变，取逐帧最优首项）；`operations/cw_screen/cw_screen_buy_cards.py:415 run_buy_waves` 波循环 → 单动作循环。
- 判据层（criteria/statefn）**零改动**：判据函数已是「输入态 → 布尔/值」纯函数形态，单动作循环只是把「一次调用判 N 次」改为「N 次调用各判一次」。

## 2. 动作基类与动作粒度（决策 3、10、9）

### 2.1 动作基类单方法（决策 10 契约收缩,T-163 落码）

动作 op 基类 = 单方法：

| 方法 | 职责 | 性质 |
|---|---|---|
| `execute(ctx)` | 机械执行（点击/拖拽，op 框架既有的重试/等待语义在此层） | 执行，无判断 |

决策 10 原定的 `project(expected_state)` 逻辑态推算方法（前身契约）**已删除**（T-163:其 simulate 实现即删除对象本身;用户裁定 2026-09-12 纯规则路线,策略域零 simulate 前瞻消费）——§1 决策循环伪代码中的 `期望态 = action.project(期望态)` 行随之退役。

> 术语注(首次出现):逻辑态 = 动作执行后不经观察、按游戏规则推算并直写容器的预期状态;真值以下一帧观察为准(观察赢)。

期望态推进的现行单一源 = **容器规则通道**（容器 = session 级黑板状态对象,经 `board_state_of(session)` 访问）：动作落地门 `apply_action_outcome`（`cw_op_buy_cards.py`）在动作落地且非终结时,对容器依序直写 `apply_shop_action_logic`（逻辑态直写口简单腿:金/店内/板凳简单落位）→ BuyCard 再走 `apply_shop_merge_leg`（合成升星整表直写;基点 = 买前快照三件组 pre_bench/pre_deployed/pre_shop,升星判据单一源 = kernel `detect_merge_upgrade`）。写序 = 先简单腿后整表（后写赢）,两写合计与 simulate 输出逐槽等价（锁 M1 = `test_cw_shop_projection_logic`）;生产落地门与 flow/bridge 两级序列驱动器三门同形。journal 动作行不再带期望态 delta/金/占用字段（判读输入 = 动作行本体 + 容器直写证据）。

### 2.2 动作粒度（决策 3；2026-09-06 补裁方案 A）

- 常规粒度：**买一张 = 一个 op、卖一张 = 一个 op、买经验一击 = 一个 op(单击 +4XP;升级 = XP 过门槛的结果,非动作)、刷新 = 一个 op**。
- **满栏例外补裁（方案 A）**：板凳满时点合成槽位，游戏机制自动多买至 3 的倍数张（每张原价，`docs/game/currency_war/research/merge_mechanics.md` §2.5）——**一击多张 = 一个动作 op**：动作单位 = 点击，张数由游戏规则定，逻辑态直写按实际张数计（min(店内同名, 3−已有 mod 3)）。
- **非满栏常态时合成槽位买的一击张数 = research 知识缺口**（merge_mechanics 通篇未载，禁从满栏例外外推）——flow 实施批先补档验证（决策 7 边界注「验证前置」）。
- **例外**：复合动作类（§5）是另一类粒度，不受「买一张 = 一个动作」辖。

### 2.3 守卫断言（决策 9）

策略器内部保证只提合法动作；执行侧检查退化为**守卫断言**——防 bug 路栏而非控制流分支：非法返回 = 策略器 bug 响亮暴露（断言炸出，禁静默跳过或降级续跑）。点击目标存在性检查等 op 框架既有的重试/等待语义属 `execute` 的执行实现层，不算决策合法性的第二道门。

**现行代码映射（迁移面）**：
- 现行执行侧的合法性/对拍面——卖前对拍守卫 `sell_guard_ok`（`action_exec.md` §4）、执行侧 x 去重、`register_round_sold` 幂等加固——其存在前提是「波批多动作共享同一帧快照」；单动作循环下第一笔动作后期望态已更新，第二笔提案自然不指向已卖槽（bug 类·同槽去重防线）。这些防线在迁移时**按守卫断言语义重定位**（防 bug 路栏保留，作为控制流的跳过逻辑随波批退役），逐个重推而非机械搬移。
- **`sell_guard_ok` 机制改真**：现行守卫 = `cw_op_buy_cards.py:163-173`（守卫函数）+ `:993-1008`（消费点装配）的两条**内存账对拍**——策略侧 `state.bench` 帧首快照 vs 执行侧 `tracked_bench_chars`（同源于循环顶 `bench_from_compact`），**零读屏**。docstring 自述残余风险 = 不防「tracked 名字本身错」（buy-OCR 误读，跟踪保真度既有问题）——即守卫只对拍两账一致，不对抗两账同错的识别层缺陷。

## 3. 终结 op 集与恒可用不变量（决策 4、5、6、7）

- **终结 op 是一等动作**（决策 4）：每画面自定义终结动作集（商店 = 刷新、关店），由**策略器主动选择**，不是循环逃生口。执行即画面 op 结束、交回外循环。
- **策略器 = 全函数**（决策 5）：f(期望态) → 动作，**永不返回 None**；「无动作可做」的表达 = 直接选终结 op（如关店）。动作空间无 no-op。None 通道会把「策略器漏 case」静默降级为关店，守卫断言（§2.3）失去暴露面——被否。
- **恒可用终结不变量**（决策 6）：每个画面的动作空间至少含一个恒可用终结动作——全函数契约在所有画面成立的条件。现况核对：商店（关店）、备战（开战）、单选族（确认）、等待/切换类（推进）全部满足。
- **刷新 = 终结 op 的语义自洽**（决策 7）：刷新是唯一引入新事实的动作（新牌面），而期望态必须在新事实处重建——终结后外循环重观察正好落在这个点。现行截断器的「刷后重观察」语义被结构吸收，**不需要为刷新设计任何循环内重读机制**。

**现行代码映射（迁移面）**：
- 截断器 `truncate_shop_frame_stable`（`shop.py:248`）**退役**——截断点语义被终结 op 吸收（RefreshShop 本来就是截断点）。
- 现行「空序列 = 决策完成触发关店」（`README.md` §2.2、`shop_visit.md` §3）的契约终止语义被「策略器主动选关店终结 op」取代——空序列通道在新契约下不再存在。
- R1 付费刷新发射粒度「每波至多 1 次刷新」（`shop.py:875`）在新结构下自然成立：刷新即本画面 op 结束。

## 4. 期望态生命周期（决策 7、8）

```
入口观察（重建）──→ 逐动作逻辑态直写（纯计算）──→ 终结（失效）
  唯一真值源          期望态随每个动作            画面 op 结束，
  对账发生在此        动作落地后容器规则通道更新    期望态作废，外循环
  （入口观察即对账）   买/卖/升零读屏               下一次入口重建
```

- **入口重建**：每次入口观察 = 事实重建，分叉天然归零——**入口观察本身就是对账**（决策 8），不是额外防线。现行对账面（`cw_prep_expect` 的 compare_* 族、`cw_reconcile`）仍在入口观察处消费，对账时机从「波内多处」收拢为「入口单点」，误读暴露延迟到下一画面入口。
- **逐动作逻辑态直写**：买/卖/升 = 确定性纯计算（金/板凳/持有副本/等级），零读屏（决策 7）。
- **合成逻辑态直写边界**（决策 7 边界注，2026-09-04 对抗审查裁决）：合成（升星合并）落点规则**并入逻辑态直写纯计算**——规则权威档 = `merge_mechanics.md`（场上吸收/备战最左/连锁）；§2.5 满栏例外规则的适用域显式限定为满栏例外语境；规则模型误差由入口对账兜底。**验证前置**：合成规则完备性（连锁/多路触发/边界/满栏例外/非满栏一击张数知识缺口）须在 flow 实施批补档验证；**验证未过则 fallback = 合成触发买升格为终结 op**（重观察，新事实由终结后外循环入口重建）。
- **信任域 = 本画面 op 生命周期**（决策 8）：循环内无失败处理分支——动作 = 机械执行无判断，「动作无效」只可能源于入口误读，循环内不可检测也不需处理。商店槽位在刷新前静态（单人肉鸽），「牌被买走」不存在（决策 8 口述附注）。

## 5. 复合动作类：CompTransaction

整档组合替换保留为**一个宏动作 op**（「换一档 = 一个动作」），不与 §2.2 粒度裁定冲突（那条辖普通买）。定义（四要素）：

1. **一个 op**：`CompTransaction`（`kernel/cw_state.py:696`）整体作为一个动作进单动作循环——策略器一次提案、执行侧一次执行，不按子步（deploy/undeploy/sell/fill）拆。
2. **原子逻辑态直写**：期望态更新 = 全部子步一起纯计算直接产出终态，不存在子步间中间期望态。
3. **C1 前置合法性**：任一子步资源不足（金/槽）⇒ 整体不合法不提案——与契约 C1 整批拒绝语义逐字对齐（`kernel/cw_state.py:696-714`：「任一子步资源不足（金/槽）则整个事务拒绝，不产生半档中间态」）。
4. **合成建模义务**（2026-09-04 对抗审查裁决补充）：`fill` 路径含商店填位买入（`kernel/cw_state.py:713` 金校验含 card_cost），该买入可触发合成与 §2.5 满栏例外规则——宏动作的原子逻辑态直写**必须内含合成连锁 + §2.5 规则**（与 §4 合成逻辑态直写同源）。**fallback 定义**：合成建模验证未过时，CompTransaction 执行后保持现行「截断重观察」语义（`shop.py:273`：RefreshShop/CompTransaction = 截断点）——即宏动作**终结邻接**：执行后本画面 op 结束交回外循环，禁半档中间态（与 C1 一致）。

**现行代码映射（迁移面）**：词表中 CompTransaction 已是单一动作类（`README.md` §2.2 序列决策词表含之）；迁移面在逻辑态直写侧（原子逻辑态直写内含合成建模）与 fallback 侧，不在执行侧拆步。

### 8.1 contract ctx 逐动作取值语义（ADR 开放问题 4）

**问题**：契约核验 `contracts.ensure_contract`（`criteria/contracts.py:268`）的 `ContractCtx`（gold/bench 等字段）在单动作循环下**逐动作取值**——同一字段在两粒度下取到不同值（gold = 波批帧首快照 vs 动作后真值），不定义则契约遥测在新旧结构间不可比。定义落点 = 迁移步 1（契约核验挂单动作决策入口时同步声明）。

**flow 侧裁决建议**：定义为「**动作后真值**」（= 期望态当前值，即下一次决策将消费的值）。理由：①与决策输入同源——契约核验的目的就是审计「决策所依据的前提」，前提变了核验值必须跟着变，否则核的是旧前提；②波批帧首快照口径本身就是  bug 类（金位买后逻辑态族）的病根，契约侧不应保留同款口径；③定义成本为零——ContractCtx 装配点就在决策入口，读期望态即得。配套义务：契约遥测的跨结构对比（A/B 或回归判读）须声明口径切换，禁把两粒度的计数直接对拍。

**flow 侧裁决建议**：**按商店同款：补给刷新 = 终结 op**——「唯一引入新事实的动作即终结」是结构语义（期望态必须在新事实处重建），不因画面而异;现行「节点内刷后重读再选」的循环形态在单动作架构下=终结→外循环重进→入口重建,语义连续。**节点内至多 1 次**的硬限制现由 `_supply_refresh_used` session 态承载——迁移归属=carried 融合（§3.1 同款,入口重建时与 carried 态融合）。若核实发现刷新**无消耗**（图标式或免费）,结构风险（反复刷新外循环无进展）由该 session 计数硬墙天然防住,无须新增。**商店侧对称引用**：商店侧的硬墙重定位与预算归属已按同款论证展开（§3.1），补给侧落此款时与 §3.1 交叉核对，禁单侧定案。留 flow 实施批终裁。

### 8.5 安灯与豁免通道重锚（第五条开放问题；`guards.md` §6 消费面）

**问题**：执行失败安灯分类器 `exec_fail_should_stop` 的三处输入绑定在波级契约上——①数据源 = decisions.jsonl 本轮 shop **plan 行**（plan/开店金，整波一次提案一行）；②豁免通道 = `plan_truncated` 截断申报（「计划≠尝试」分流：硬墙跳过/截断丢弃的尝试不算失败）。单动作循环下「一次画面访问 = 一个 plan」的波级契约消失——plan 行不再有波级载体，截断语义（整波列表执行到一半被墙）也随之无定义。分类器输入与豁免语义必须重锚，禁沿用已消失的波级行。

**重锚面（两处）**：
1. **分类器输入改逐动作事件流**：每动作一行事件（提案/执行/跳过/实收），安灯判定改为消费动作级序列——「计划买 N 实买 M」的差值口径从波级 plan 行改为逐动作累计，语义不变、粒度变细。
2. **豁免通道按单动作语义重推**：`plan_truncated` 的豁免意图 = 「未尝试 ≠ 执行失败」。单动作下不存在截断，但同意图有新载体——动作级「跳过」事件（如守卫拦截 stale_proposal、硬墙拒绝刷新提案）应延续豁免（跳过是守卫防错不是执行失败），「执行了但账不符」才进三态判定。豁免边界须重推而非映射搬移。

留 flow 实施批定；`guards.md` §6 的【待 迁移】标注即指本节。

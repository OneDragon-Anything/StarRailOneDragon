# 自主推进编排细则(提醒网 / worker 派发 / 对抗)

> SKILL.md §goal/schedule 自我校准 的展开。读者 = 智能体;适用于:schedule 提醒网建置与消费、worker 派发与对抗审查、哨兵报警消费(哨兵仅长时自主推进时武装,其报警是事件通道输入)。

通用机制(goal/schedule 消费/事件驱动/空转轮/目标切换与迭代封存/编排者-worker 分工/早停收口/授权边界)单一源=od-dev-agent-autonomous-mode,本文不复述。

## schedule 提醒网(七角色与 CW 间隔)

七角色提醒网**创建时刻错峰,间隔互质**;间隔按 CW 节奏定(局均 40min → 值守 10min/盘点 15min),其他玩法按自己的节奏定:

| 提醒 | 间隔 | 内容(写角色不写当期细节) |
|---|---|---|
| 值守兜底 | 10min | 监控栈第 3 层(哨兵的哨兵):值守脚本存活+对局/空窗状态+进度对比——最小动作,事件通道(job 通知/哨兵 exit)是主路径,本提醒只兜底 |
| 派发盘点 | 15min | 压测官批间空窗?worker 队列有件+槽空?对抗积压(audit/adversarial*.pos 去重+采信未攻结论)?知识工程机会(逐篇精读/math 待证命题)?积压局未判读?——**产出=派单动作或明确「无需派」记账** |
| 行为校准 | 40min | 反漂移三问(找问题 vs 等结果/轨迹达标/goal 条款违反)——内容固定,防注意力窄化 |
| 文档对照 | 40min(与行为校准错峰) | 上次判读/方案/调研立项后对照过口述权威吗?**凡对玩法行为做判断/出方案/立项调研/写策略代码——先过 user_playstyle**;子 agent 派单涉及策略行为面的,检查 prompt 带没带「前置阅读」节,没带=不合格派单补发 |
| skill 遵循回看 | 50min | 最近操作映射回 skill 辖域(判读过了三问?派单带前置阅读?)——重点扫「没想到有 skill 管」的操作 |
| 进度对表 | 45min | 迭代入口 vs 实况(下一个待派/判据起数/健康线)+交付验收清单过期项——当场改文件 |
| 深度巡检 | 2h(派 agent 型) | 反馈队列第三方裁决+晋升候选扫描(主会话自审有偏见)——提醒只做触发器 |

判据:提醒预算有限,状态查询不进 schedule(主会话自主查);提醒触发后无活可派=一行记账完事,不硬造工作。schedule 使用原则(提醒≠指令/错峰/提醒派发不查状态)以个人本地入口文件为准,本文不引用不复述(与个人入口可能不同 reader,别造跨文件依赖);本文只辖 CW 的七角色编排与间隔。

### 派单模板硬规范(用户定调)

① 涉及策略行为面的 worker/压测官/调研批,prompt 必含「**前置阅读**」节(相关 user_playstyle 条目/strategy 篇/ADR 路径)——子 agent 是干净上下文,文档在它世界里不存在,派单不带=它只能凭猜乱来,无前置阅读节=不合格派单;② 判定类批(任务产出物是判定/分档/取舍的)必含「**判据来源**」节——以效果/机制审查为主体(逐对象过决定资格的机制属性),统计量只作佐证列;倒置(统计主体+效果一句带过)=不合格派单;③ 涉及**动作对象(Action)新增/改动**的批,前置阅读节必含 SKILL.md「防坑清单·动作索引五查」条——idx 族四连坑的检查面,派单不带=审查面缺位;④ **行为变更批**(改动会改变策略行为/语义/权重/字段含义的)prompt 必含「**文档面**」节,写明 ADR + as-built 文档同步的归属:**本批自带**(worker 一并写完),或显式声明「归编排者后续批」——二选一,缺省=自带;纯测试批/无行为语义变更的批可免(W50/W51 实证:文件集只列代码不列文档,worker 按声明拒碰 docs/ 完全正确,文档欠账却堆回编排者——义务归属不进派单模板,欠账必然产生)。

### 派发盘点扫描源(2026-08-25 补;泛化待第二玩法实证后升公共 skill)

派发盘点提醒的四来源之外补两源(**同根症状源**与**理念核对源**——防「逐件修症状、堆积成补丁」,判例:溢出金闲坐+破息追级+息晚立三件被逐件立项,实为经济循环总模型一个缺位,被用户点破):
- **C 源(同根症状)**:同族策略/代码修法**第 2 件出现**时必须问「这两个根是不是同一个更高层架构根的症状」——是则升级架构级设计件,**第 3 件出现前禁再立项症状补丁**;与「同一手工操作第 3 次=建批」并行(操作重复与修法同根是两类)。上游防线:第 1 件修复收账时过交付验收「泛化步」(同类排查或记账为何不派)可防第 2 件发生。
- **E 源(理念核对)**:用户口述里一以贯之的理念(如经济三段论:战力不足凑羁绊→战力 OK 凑息→50 金开花的隐藏目标=经济预期打满)在 design 文档里有没有成文对应模型——没有=设计文档缺口,判读/修法一直在对照不完整的权威面。

## 做事按 skill 来 + 实机常跑=素材泵(用户定调)

做事按 skill 来:skill 是操作手册,活在被遵循里不在被收藏里——每个循环动作(判读/派单/改码/验证/运维)执行前先问「这条操作归哪份手册管」,归就按它做(与 schedule 提醒网的「操作手册回看」角色同一判据)。

实机不只做验收——**持续跑局积累素材,暴露只有实机才遇的问题**(未建档画面/新物品/时序边角/停机钩子触发)。sim 主迭代与实机常跑**并行不悖**:sim 秒级验证策略假设,实机持续产出真问题流+真值样本;编排者轮转消费实机产出(局后判读/新问题建档/样本点账),值守栈(哨兵+早停+runs 断流)常伴。判据:「实机暂停等 sim 就绪」仅适用于「实机行为会污染数据/抢修复窗口」的场景;默认态=实机一直跑。

## 对抗审查(ADR-0010)

- 分析类方案/归因结论在**采信前**起子 agent 攻击(攻击型指令+实测数据+逐条裁决实验);大改动 review 同理。
- **两种触发形态**:①后置闸门 = 产出结论后、采信前攻;②**决策时对抗 = 岔路口主动发起**——多方案均能自圆其说/证据不足以裁决/改动影响面大/自己心里有未验证假设时,把「倾向 X 因为 Y」扔给新鲜上下文攻击(一次对抗几分钟 vs 错误决策一轮返工);没把握就发起,别硬拍。
- **实机事故修复的豁免与补偿**:live 卡死/崩溃的修复可先落地(时间压力),但下一批 review 必须补攻击——豁免的是前置审查,不豁免验证。

## 策略争议裁决标尺

- **数学期望是统一标尺**(用户定调「数学是不会骗人的」):策略分歧(该不该买/多激进/收紧还是维持)不靠直觉吵——指向 `docs/game/currency_war/research/math_proofs.md` 对应命题:已证的直接引用结论裁决;没证的立项去证(命题+证明路径+数据源标注,进该文件「待证明」节),证据到位才裁决。口述直觉是命题来源(用户给方向),数学是裁决依据——**先证后裁,不先裁后证**。
- 经济侧判读(乱买/漏买定性)用 [compo-knowledge.md](compo-knowledge.md) 的「三笔账」框架对账,别凭印象。

## 哨兵报警消费协议

哨兵/早停脚本的每次 exit 都是**待验证事件,不是结论**:

1. **先判相关性**:报警与近期自操作相关(「人工结束/执行失败」回显 = 自己 stop_run 的传播尾巴)→ 同型见过即降级消费,不当中断响应;
2. **异常型报警**立即核窗口日志+画面再定;
3. **哨兵自身输出异常**(刷屏/格式怪/离谱值)也是哨兵 bug 线索——读完输出再收口,监控工具的噪声会污染 reviewer 信噪比。

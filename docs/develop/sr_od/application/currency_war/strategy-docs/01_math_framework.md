## 1. 定位与权限总图

本篇把已站住的证明族整合成一套可实现的决策框架：三层权限 + 七面各有唯一权威判据 + 状态函数单一源 + 零调参审计。权限骨架（详 [02_mandate_layer.md](02_mandate_layer.md)）一句话：

```
证明层：选线/终局（证据门 P38 + 换线 P16）——决定骨架为谁服务，无单笔否决权
骨架层：义务 M1-M7 无条件执行，只受四项硬约束（可负担/席位/S 预留/不可逆护栏）
EV 层：只增不减——在骨架之上追加优化动作，本篇 §3 七面判据的主辖域
支配性结论：零参数、无条件、优先于一切带参 EV 比较（公理 1 的执行形态）
```

**注意**：旧 NMF 的「三段管辖」（按 λ_death 分段路由判据）已整体退役（R26-H1；实机刻度上 λ≈0 段 = 空集，三段退化单段、段路由空转）。现行 = 姿态架构（00 §4）：发展优先默认 + 升档器只升不降 + arm2 结构守息门 g* = 10×cap_resolved【推】（零 λ 依赖）。

## 2. 公理栈五条（框架地基，不再论证）

（出处：NMF §0；编号沿用）

1. **零调参**：禁拍死值顶替未标定参数；数值判据必须可溯源（注册表/推导/带 CI 的估计）；未标定项 fail-closed 或走支配性结构判据，不塞拟合常数。
2. **超额收益隔离**：一切证明在「连胜 = 0」的底线口径上成立；连胜成长价值是上行注记，只增不改向（P51 §F.4 / P43 §⑥）。
3. **纯金流记账**：血（hp）不入任何账与自变量——hp=0 仅是死亡事件定义；胜率/掉血只经 λ_death 的概率侧进入决策（P51 §R.3 / P15v2 消费限制 / [39] 裁定）。辖域注记：经 λ_death 的概率路由键（PL 键血带维）间接入场系用户裁定二既裁例外——概率侧非价值侧（00 §3 硬闸门口径）。
4. **阅读门**：证明件须过无偏对抗审查后方可消费；命题可否引用以 `math_proofs.md` 索引状态列为准（站住者可消费，作废/不成立者禁引，待证明者按 §7 钩子处置——结构占位，默认行为退常规门/骨架义务）。
5. **参数溯源**：框架内每个数字标【注】/【推】/【拟】（章程见 §6）。

**玩家裁定三条**（2026-09-01，最高权威，NMF §0）：

- 等待件域 = 阵营相关单位，**不限星级**（P39 臂一谓词②；历史「star≥2 ∧ 目标线名单」双收窄判废）；
- **hp 不作决策输入**（[39]；根因声明与例外辖域见 00 §3）；
- **首次 0hp 保底 1hp，再次归零结束**（一次性保底；P9 候选线语义）。

后续关键裁定（正典化收录）：λ 钥匙选型 = PL 键 B1（数学优劣全口径占优，NMF 裁定一）；安全带架构 + 两验收条件（00 §4）；λ 基座转入观察名单（禁稳态表述，00 §6）；度量家族冻结于 R65 后态（不确定性帧一律默认安全，维持发展主线；只许错账修正，禁新增验证装置）。

### 3.4 刷新

权威判据 = **P40 三层门**（单一结构 R0→R1→R2）：

- **R0 停止**：R0-1/R2 维持结构门（合格集、预算/息账递推，不依赖 V̄）；R0-2 = 结构判据——合格集空 ∨ 预算门不过即 fail-closed；V̄ 比较项（含保守闸形态）已随 V̄ 链整链退役（P53 修订单 R2），**禁消费**；无目标刷新 fail-closed（r2 H1 事故的正确门）。
- **R1 完成门（启动）**：现行形态 = **可负担性启动门（形式二，V̄ 链退役）**——启动 iff `c_eff·E(D|L*) + Σ卡费 + L ≤ g − g*`（判据规格/输入面/决策规则见 [11_shop_decisions.md](11_shop_decisions.md) §3；L* = T_stay/T_up 取小，L = P47 loss_exact；合格集语义勘误）。P40 原始形态（c_eff·E[refreshes|j] + Σ卡费 + L ≤ V_gap）系留史——比较项 V_gap 已随 V̄ 链退役（P53 修订单 R2），禁消费；原始形态下的「标定通道 = sim 对拍批」表述同步作废（A/B 对拍无裁决权）。旧 V̄_net/V_GAP 比较项与 P57 双读法问题随链退役（P53 修订单 R2），窗口门重锚塌缩带 ω（同源）。现行判据输入全为游戏定义量、零消费 V_gap——「V_gap 未标定 ⇒ R1 无付费刷新」的旧缺省句随 V_gap 消费位退役一并作废（R1 现行 fail-closed 面只由合格集空与预算比较承载）。
- **R2 预算门**：spend = c_eff·n + Σ命中卡价，息损项恒走 P47 L 递推；**现行落码形态 = 息线 floor**（刷新门预留 = g* + ρ[合格集最低费卡价]，与 P40 溢余段刷窗式逐位等价，P54 已对拍）。
- 变体①-⑩（淘金客/概率事件/轮岗/市场干预/节点语境等）全部 = 参数替换，骨架不分叉（P40 §④）。
- **支配性例外**：危机帧刷新通道不变式（P36-a）——「B>0 ∧ B≥刷价 ⟹ n≥1」是结构约束，已无条件落地，先于 R0 存在性。

### 3.8 横切修正项与支配性族

- **连胜取舍（P43）**：不是独立决策面，是支出侧的加性外差项——支出会改变战斗胜负时，花侧加 ΔV_streak（引擎口径 DP）；默认姿态 = 保息；旧常量 WIN_STREAK_BREAK_INTEREST=2 在处死名单。
- **残余补部署（P24）**：零支出域补空槽严格支配整轮禁运——无条件，先于一切 EV。
- **危机火力（P36-a/a′）**：通道不阻断不变式 + 应急带储备线降档（R*_crisis≡0）——零参数结构，已落地。
- **等待件部署 d=0（P51 B6/P24）**：买牌/部署当轮落板；XP 升级兑现滞后 d≥1 系保守折价假设（P37v2.1）——下游抵扣按通道折后计。

## 6. 数字三形态章程（正典化；全链硬规则）

> 本章程塌缩自 AUTHORITY.md 语义与 13 号件 R2-N2/13 §2.1 先例（REVIEW §4.3-1 指定在本总纲固化）。

**定义**：框架内每个进决策门的数字必须标注三形态之一——

- **【注】游戏定义值**：注册表机制真值（概率表/退金规则/经验表/池参数/装备图谱等），零调参豁免——它不是拟合，是游戏规则。单一源在代码注册表。溯源子型 **【注·对拍定谳】**：注册表机制真值，但溯源 = 遥测对拍（如 decisions.jsonl 金差对拍与注册表常量一致）而非游戏内直读——机制真值地位与消费权限同【注】，仅溯源形态如实标注；先例 = REFRESH_COST_BASE。
- **【推】已证推导**：闭式/递推/DP 从【注】推出，无自由参数，引命题号（如 L 递推 = P47，V_comp 表 = P49）。
- **【拟】观测估计**：从语料/对拍估计的量，必须带置信区间（CI），**禁点值当闸门**；且须满足三要素——

**【拟】的三要素（缺一不得消费）**：

1. **允许存在（挂账登记）**：每个【拟】量在标定清单登记（消费面、分级 🔴/🟡、fail-closed/支配性退路）；
2. **允许消费的条件**：标定齐备 + CI 两端点扫描下判据方向不变（方向会翻转 = 数据不足，先补数据）+ CI 验收五件套（R4-F6）；
3. **标定义务（owner + 期限）**：每个待标定量有 owner 与期限；**超过一个对局周期未决 = 回炉重裁**（13 §2.1 R2-N2 条款升为全栈通则——REVIEW §4.3-3）。

**fail-closed 缺省**：未标定期该判据不产生动作（EV 层不发射），**绝不向骨架层渗漏为一个否决**（02 §5）。无标注数字不得进决策门。

**在册【拟】清单**（13 项，沿用 NMF §3.3 编号，分级与退路以该表为准）：u_x/H_x、V_ms/V_gap（同源单标定禁双源；其中 V_gap 比较项已随 V̄ 链退役批退役，V_ms 维持在册）、w（臂一只用 w>0）、ρ 摊派、n̄ 估计器、A/T_search、λ_s/partner 到位率、v_F/v_B、c_frame/q、Δp（win_rate_dp_by_plane——已随 V̄ 链退役，注册表字段同批退役，禁消费）、λ_death 连续模型（分层表带 CI 先行）、p_hit/q_conv、V̄（比较项不授权——已整链退役，P53 修订单 R2，win_rate_dp_by_plane/vbar_hp_value_transitional 注册表字段退役，清单留名仅为历史对账）。

## 8. 两条总纲级不变量（REVIEW §4.3-2/3 落地；本链一切判据的审查尺）

1. **位面参数化不变量**：任何机制谓词的辖域条件中**不得出现位面字面量**；位面只允许作为（节点数表/伤害锚表/档位表）的查表键进通用模型。逐格扫判据表，违例格按通用化重写（先例：p2_spend_auth 位面辖域门废除 → 支出授权谓词 + sink 缺口参数；R78-2「P2 中间段」补条 → 通用目标态定义，见 [12_line_and_intention.md](12_line_and_intention.md) §1/§3 与 [11_shop_decisions.md](11_shop_decisions.md) §5）。

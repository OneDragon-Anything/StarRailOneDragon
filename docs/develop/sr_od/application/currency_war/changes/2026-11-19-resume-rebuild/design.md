# 恢复局机制重整（每次运行重建 + 开局方式事实化）迭代设计（总纲）

## 0. 元信息

- **迭代目标**：删掉恢复局三字段状态机的「跨运行记忆」职能，重整为「每次运行从干净状态开始 + 开局方式事实化 + 探针接管局必经裁决」——消解挂账板 §二.7⑥ 的两个失活场景（并顺带消解第三形态：app fail 后残留容器续用致探针失活），顺带删字段。
- **用户裁定集（2026-11-19 讨论，本设计的规范来源）**：
  1. **接管残局是最佳情况，不分模式**：残局（重跑遇到的半途局）一律接管；接管靠画面探查 + 补采（现有备战特殊逻辑本职），**能补多少补多少，补不到就算了**（核三核过：接管降级决策的承接机制现役在位，无崩溃路径）；
  2. **接管不靠记忆**：不记录之前的信息，每次运行从画面重新认识局面；
  3. **每次运行都应该重建**（Match）；
  4. **停点分模式**：`env_config.is_debug=True` 停屏等诊断（维持现语义）；False 弃局回大厅重开——**重开由下一次 app 运行承载**（结构事实：app 单次运行 + 应用组当日按 SUCCESS 跳过，「同 run 自动重开」不存在承载机制且属未来多局调度批，本批申报此语义）；
  5. **挂起局弃局重开**维持既定语义（模式选择-进行中 → 委托退出 op → 回大厅）；
  6. **debug 判断用框架现成** `env_config.is_debug`。
- **关联账**：挂账板 §二.7⑥（本批销账目标）；交接批 design §2.5/§2.6（max_rounds 停点语义按裁定 4 修订，随本批）；loop→exit 交接批正本 loop.md §6（随批订正）。
- **状态**：第 1 轮对抗修订稿（第 2 轮待发；报告=[attack.md](attack.md)）

## 1. 问题与动机

### 1.1 现状机制与失活场景（挂账 §二.7⑥）

恢复局检测现状 = `CurrencyWarMatch` 流程态字段动态状态机（`is_new_match` / `resume_probe_pending` / `locked_resume`〔+`locked_round` 遥测、`locked_sync_done` 配对证据位〕），写入节奏 per-run（loop `handle_init` 每次 execute 重判/重置），裁决链 = 备战画面 op b 查（候选过判 → 探针点击商店验可开性 → 锁定确认/撤回）。失活场景：

1. **跨 run 重入锁定帧**：上次运行探针确认锁定后未走完即停；同进程重跑 → `handle_init` 重置 → 第 0 查失活 → 常规链发商店动作 → 点击落空空转至哨兵。
2. **停点命中后再跑探针永久失活**：停点停在备战屏 → 同进程再跑 → 容器续用（`was_new=False`）→ 探针永不触发。
3. **app fail 后残留容器续用**（调查补充，重整顺带消解）：app 失败收尾不清容器 → 再跑容器续用 → 同型失活。

**病根**：per-run 重置节奏把**已确认的局级事实**（这局是残局——客观不变）也当 run 级状态抹掉了。

### 1.2 接管全景（2026-11-19 调查，判定信号的事实基础）

| 路径 | 画面序列 | 新局/接管 |
|---|---|---|
| 大厅点开始 → 无保存局 | 难度确认 → 简报 → 投资环境 → 备战 | 新局（专属画面 = 新局确凿信号） |
| 大厅点开始 → 有保存局 | 「继续进度」弹窗 → 直达备战（**不经入口链建容器段**，容器由 loop 兜底建） | 接管（游戏保证同一物理局，信息最全） |
| 大厅点开始 → 挂起局 | 模式选择-进行中 | 弃局重开（既定语义） |
| 半局直撞 | app `_in_match` 命中，跳过入口链 | 接管（容器由 loop 兜底建） |
| 残留大厅 | 死按钮态 | 关X + F 重进（导航形态，非局态） |

游戏锁定语义（`obs/cw_resume_lock.py` 实测申报）：进过战斗后游戏 exe 异常退出重进继续该局 → 备战屏锁定「只能出战」（商店按钮零响应）。锁定唯一可观测特征 = 商店可开性 → 探针（识别性点击）是唯一裁决手段。自己开局的新局不可能锁（无「exe 退出重进」前提）→ 新局永不探针。

### 1.3 判定信号（重整核心）

**「新局 vs 接管」由游戏流程自己说**：新局链专属画面出现 = 新局；没经过就到了备战 = 接管。落成 `opened_via` 开局方式事实字段——**容器建立时一次写入、运行内不变**，不再是动态状态机。

## 2. 方案

### 2.1 语义收敛表

| 场景 | 重整后处置 |
|---|---|
| 正常开局（入口链见过新局画面） | `opened_via=new_game`，永不探针，正常打 |
| 接管局（直撞/继续进度/停点重跑重建） | `opened_via=takeover`，首个备战相位探一次：锁定 → 出战接管；非锁定 → 带缺口正常接管（补采照旧） |
| 挂起局 | 弃局重开（既定语义不动） |
| 停点（跑满 max_rounds） | `is_debug=True`：现语义停屏交回（留局采样）；False：loop 出口直接以交接前缀文本交出 → app 交接节点走清场退局回大厅（§2.5）——**重开由下一次 app 运行承担** |
| 接管局停 1-1 备战 | 照常探针（不省点击——触发门只看 `opened_via` 一个条件；无锁则探针必「可开」走常规，结果正确） |

### 2.2 字段收敛

**新字段**（宿主不变 = `CurrencyWarMatch` 流程态区；传播路径不变 = `ctx.cw_match` → `CwScreenPrep` 读）：

- `opened_via: str`（`'new_game'` / `'takeover'`，**缺省 `'new_game'`**——漏传时新局不探是保守方向，sim 直构等外部装配零改动）：容器建立时一次写入。写入端（生产三调用点显式传参）：入口链 `_establish_match_once`（新局确凿信号处）→ `new_game`；loop `handle_init` 兜底 → `takeover`；商店防御兜底（`cw_screen_shop.py::CwScreenShop.observe`，局外独立单跑防御建核）→ `takeover`（局外兜底 = 缺口接管语义）。继续进度直达备战不经入口链建容器段 → loop 兜底建 → `takeover`（探针覆盖，锁定检得出）。
- `created_run_id: str | None`（重建判据载体，见 §2.4；`None` = 外部装配〔sim 直构〕= handle_init 保留）。
- 探针去重标志 `probed: bool`（`takeover` 容器首探前 False、探后置 True 一次写；容器重建天然归零）——申报：字段总数删 2 增 3，换掉的是「三个动态状态字段反复翻转 + per-run 重置 + 撤回双点」，净复杂度下降。

**删除**：

- `is_new_match`——**名实偏差修正（核三抓到）**：现役 `True` 的集合 = loop 兜底新建的容器（入口链新局建容器后 handle_init 求值恒 False）→ 旧 `True` ≈ `takeover`、旧 `False` ≈ `new_game`，**与直觉相反**。消费点迁移判据按 `opened_via == 'takeover'` 方向写死（等价映射表进 landing）。
- `resume_probe_pending`——被 `opened_via` + `probed` 联合门替代。

**保留（本次运行内工作态）**：`locked_resume`（锁定确认后多帧直达标志，出战成功解除）；`locked_sync_done`（配对不变量初版不动——发出核正确性约束，与探针门解耦，design 旧 §2.8-5 维持）；`locked_round`（遥测对照）。

### 2.3 探针裁决链重构（`CwScreenPrep` 段1 b 查）

- **触发门**：`opened_via == 'takeover'` ∧ `probed == False`。第 0 查（`locked_resume` 直达）命中帧不进 b 查、去重标志已置不重探，四查序位互斥保持（核三核过）。
- **`resume_candidate` 纯函数退役**：轮次/位面门删除为**有意变更**（1-1 接管照探，结果正确——design §2.1 已申报）；轮次读数保留于 `locked_round` 遥测链。模块头申报判据变化。
- **裁决流程不变**：探针点击（商店可开性）→ `probe_resolve` 两分支 → 锁定确认三字段同帧配对写 / 非锁定收店恢复常规接管。
- **接管失效写**：挂「探针分支进入即写」——相对时序不变（先于探针点击），**触达面扩大申报**：从「候选过判（轮次>1）」扩为「接管必经（含 1-1 接管局）」，方向保守，heavy 观察同 visit 重锚补偿，净行为差近似零。

### 2.4 每次运行重建的落地（判据定稿）

- **容器记 `created_run_id`**：`establish_new_match` 内部**先确保运行记录已开（ensure_run_started 幂等前置）再记**当前 run → 字段恒非 None（外部装配直构容器不经此漏斗 → 缺省 None = 保留，sim 裸构造点零改动）。
- **handle_init 判据**：容器存在 ∧ `created_run_id != 当前 run` → **先 `discard_stale_match_container` 再 `establish_new_match(takeover)`**（establish 首行幂等直过不弃旧——discard 必须显式前置，否则重整静默失效）；否则保留（本次运行入口链所建 / 外部装配）。
- **全场景闭合推演**：正常开局（入口链建，run 一致 → 保留 ✓）；同进程连续两局（局终清容器 → 入口链新建 ✓）；重跑直撞（残留容器旧 run → 重建 takeover ✓——第三失活形态消解）；停点重跑（同 ✓）；继续进度（兜底建 takeover ✓）；sim 直构（created_run_id=None → 保留 ✓）。
- **手动逐轮验证工作流变更申报**（核一/核三同点）：现状 handle_init 注释明写手动逐轮（max_rounds=1 反复 run_operation）靠跨 run 容器延用保策略 target 稳定；重整后每轮重建 → target 每轮重选 + 接管探针每轮一次。裁定 ③ 字面覆盖，**接受变更**；相关注释（handle_init 手动逐轮段 / `establish_new_match` 幂等分支「保手动逐轮延续语义」）随批改写。

### 2.5 停点分模式与衔接（零 app 侧改动方案）

- **is_debug 读取点单点化 = loop 停点段**：True → 现出口文本（「停备战」→ app 三形态「其余」→ 跳过 exit，halt 留局）；False → **出口直接以 `STATUS_HANDOFF_PREFIX` 前缀文本交出**（如 `'停点重开:<配置值>'`）→ app 三形态判定自动命中异常交接形态 → `CwEntryExit` 清场退局回大厅 → app 结束。**app 侧零改动、不设常量决策维持、假局守卫形态不受影响**（已在大厅无局可弃，「其余」跳过语义对它仍正确）。
- **弃局后重开承载申报**：app 单次运行结束即止，重开 = 下一次 app 运行（应用组次日 / 用户手动）——「同 run 自动重开」无承载机制，属未来多局调度批（用户裁定 4 语义按此申报落地）。
- **max_rounds 配置用户语义变化申报**：配置声明「跑完 N 轮停备战屏（验证采样）」——非 debug 下行为变「弃局回大厅」。配置注释随批同步（T-5）。
- **交接批修订面（修正后）**：交接批 design §2.5 三形态判定表「其余」行补「非 debug 停点已改走交接出口」一句 + §2.6 条目语义修订 + 正本 loop.md §6 停点行 + **交接批测试同步两处**：`test_currency_war_app.py` 用例③（max_rounds→exit 零调用）改 `is_debug=True` 前提 + 新增 False 分支用例；`test_cw_loop.py` 停点出口文本断言同步（False 分支带交接前缀）。

### 2.6 消费方迁移清单（判据方向已定稿）

| 旧读点 | 旧判据 | 新判据 |
|---|---|---|
| SettlementState 新局标记注入（handle_init） | `is_new_match` | `opened_via == 'takeover'`（精确等价映射，核三 §2-1） |
| 战斗帧恢复检测门（loop iter==1） | `is_new_match` | `opened_via == 'takeover'` |
| 探针门（CwScreenPrep b 查） | `resume_probe_pending` | `opened_via == 'takeover' ∧ not probed` |
| `resume_candidate` 输入 | `is_new_match ∧ (round>1 ∨ plane>1)` | 退役（§2.3） |

### 2.7 sim 面（第 1 轮修正稿）

- **事实修正（三核同点）**：`establish_new_match` **无 sim 调用方**（docstring 自证「sim/测试不经本函数」）——sim 容器建立 = 两处**直接构造 `CurrencyWarMatch`**（skill 脚本 cw_sim_match_drive.py / 测试仓 test/harness/sim_backend_runner.py），吃 dataclass 缺省值。
- **缺省值方向定稿**：`opened_via` 缺省 `'new_game'`、`created_run_id` 缺省 `None` → **sim 直构点零改动**：不探针（new_game）、handle_init 保留（None）。
- **sim 探针可达性**：现状 0（容器续用）→ 重整后 0（new_game 不进探针分支）——既有 sim 回归零影响。
- landing T-4 grep 复核口径：`opened_via` **显式传参**生产调用点恰三处（入口链/loop 兜底/商店防御）+ 缺省兜底形态登记（sim 直构两点）——不再写「恰三处写入点」。

### 2.8 测试面（概要，landing 细化）

- `opened_via` 三路径写入断言；重建判据全场景（保留/重建矩阵，§2.4 六场景）；探针触发门（new_game 永不探 / takeover 必探一次 / 两分支结论）；两个失活场景回归；停点 is_debug 两分支；`locked_sync_done` 配对不变量既有断言不回归；SettlementState/战斗帧门迁移等价断言。

### 2.9 关键取舍

1. **重整而非修补**（维持）：跨 run 存活/分层生命周期都是给动态状态机加约束；重整删「跨运行记忆」职能整体，净复杂度下降（核三归层核过）。
2. **接管优先，补不到算了**（维持，核三核过承接机制现役在位）。
3. **重建判据候选 a 定稿**（核一阻断 1 修法）：候选 b 的「运行内标志」宿主跨 run 存活需显式清位方且带脏窗口（入口链置位后 loop 未跑即停 → 标志残留 → 下局直撞误判保留脏容器）——弃；候选 a（created_run_id 比对）单一源现成、全场景闭合、sim 零改动。
4. **停点零 app 改动方案**（核三建议采纳）：交接前缀文本交出复用三形态判定，不设常量维持，判定表行级分叉的二选一困境消解。
5. **`locked_sync_done` 初版不动**（维持，核三面7 核过配对链不受字段删除影响）。
6. **手动逐轮工作流变更接受**（裁定 ③ 字面覆盖）：申报于 §2.4，不设开口子。

### 2.10 开放点收敛声明（第 1 轮草案五项全部定稿）

重建判据（候选 a + created_run_id）、`locked_sync_done` 简化（不动）、resume_candidate（退役）、sim 打标路线（缺省值零改动）、T-1 中间态（阶段重划，见 landing）——无遗留开放点。

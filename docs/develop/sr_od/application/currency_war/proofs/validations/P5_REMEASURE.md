## 结论一句话

**种子出口在 sim 里一次都没有触发(12 seed 全零),对「跨体系加法链第一件被
跳买」零兑现;根因是前置①(主线窗口全覆盖∨满编)在与非线成员候选共现的
165 帧中 0 帧成立——该出口按当前前置在 sim 分布下恒关臂,17.8% 的病灶未被
吃下。**

## 口径声明(seed 与指标)

- **修前 17.8%/670 无持久批次索引**(未找到修前批的 sim_runs 落盘或统计脚本
  存档,仅存于代码注释引述),故本批用 **seed 1..12(12 局)、planes=2、
  pool=snapshot(指纹 32b6139f…+eqg1)**,声明为独立口径,不与修前数字做
  严格配对比较。
- 跳买 = 原始序 6(分类器 `classify_shop_card` 出口改判前)的商店卡中未成交
  者(帧内 raw6 张数 − 种子买入数;序 6 仅有种子出口一条成交通道,故
  减种子买入即未成交)。
- 非当前线体系成员 = 卡名 ∈ `TRANSITION_MEMBER_UNION` 且 ∉ 当帧
  `line_roster`(归一化后比较)。
- 种子出口触发 = BuyCard reason 含 `second_system_seed`(与引擎执行确认点
  `engine_p1` 入账同判)。
- 帧 = 一次 `decide_prep` 调用 = 一个商店波(刷新重判各算一帧)。
- 实现:运行时包装 `Cw3SkeletonStrategy.decide_prep` 与
  `strategy_shell.classify_shop_card`(只包不改),生产代码零改动。

## 修后 vs 修前对照

| 指标 | 修前(引述口径) | 修后(本批 seed 1..12) |
|---|---|---|
| 序 6 跳买总数 | 670 张 | **905 张**(454 帧共 raw6 905,种子买入 0 → 全数跳过) |
| 其中非当前线体系成员 | 119 张(17.8%) | **220 张(24.31%)** |
| 种子出口触发数 | — | **0** |
| 出口兑现率(种子买入 ÷ [种子买入+修后非线跳买]) | — | **0%** |

占比从 17.8% 到 24.31% **不是恶化信号而是口径不可比**:两批 seed 集与批参数
不同(修前批无持久索引),且修前测量未留存脚本与原始批目录。可比的硬事实
是:同口径下出口触发为 0,即修后行为与修前**逐位相同**——0 次种子买入意味
着决策流不存在任何出口分支,修前修后 sim 轨迹恒等(出口只可能通过种子
BuyCard 改变轨迹,0 次 = 无差异点)。

## 出口前置逐帧诊断(为什么 0 触发)

对 165 个「存在非线体系成员候选」的帧复算出口两道前置(与
`strategy_shell.decide_prep` 同式,消费同一帧 `session.cw3_frame`):

| 前置 | 通过帧数 / 165 |
|---|---|
| ① 主线窗口全覆盖 ∨ 满编(main_covered) | **0** |
| ② 金 ≥ S/息线 + 种子价(floor=50,liquid 中位 112) | 131 |
| 配额未耗尽(max_second_system_seeds=1) | 165 |
| **全部前置同时成立** | **0** |

推理链:非线体系成员被判序 6 的帧,几乎总是主线仍有缺口成员在搜
(search 窗口非空)且主线上场未满编——恰是前置①要求「线已无事可做」的
反面。金与配额都不是瓶颈(131/165、165/165 通过),**唯一卡死的是前置①,
且在目标帧总体中零成立**。出口的「窗口全覆盖/满编」前置与「非线第一件
出现」的分布天然不相交:想要第二体系种子的时机(主线还没搜齐)正是前置①
拒绝的时机。

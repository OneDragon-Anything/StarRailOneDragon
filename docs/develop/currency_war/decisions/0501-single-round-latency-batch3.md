# ADR-0501: 单局时长效率第三批——phase_round 死分支删除 + 备战决策结果缓存 + 买牌边界固定开销压缩

> **引用勘误(2026-09-04 ADR 存量 review)**:`.debug/` 归档 → 本目录(decisions/)同名 ADR。文内出现处按此对照读取。

## 状态
accepted→**候选②已撤回(删码留 ADR,生命周期第 4 态)**;候选③①维持 accepted(撤回记录见文末尾注)

## 背景
`W891 备战环操作延迟审计`(`.debug/temp/currency_war/w891_latency_audit/REPORT.md`,
纯离线分析)量化了单轮备战环耗时:p50 14s / 均 31.3s(决策帧间隔口径,近两日
27 局 1512 轮)。最大单一空转源是**买牌执行边界的固定开销 ≈19s/次**(回归拟合
`duration ≈ 19.0s + 2.14s × 操作数`;零操作边界仍 18.4s = 纯固定开销,~120 边界/天),
其次是决策无变化重复求值(单日 55 万行决策日志,同一决策 16 连重算)与
phase_round 数字 fallback 的纯浪费读(868 拒/2 天)。本批落地该审计 TOP3 候选
(候选①买牌边界 / ②决策缓存 / ③fallback 停用)。

## 决策

### 1. 候选③:`read_phase_round` 数字 fallback 死分支删除(主仓 57173711)

`obs/cw_observation.py` 的位面/轮次读取器中,数字 fallback 分支删除。

- **删除判据 = 结构性零信息源**:该分支唯一合法产出是 `(1,1)`(只接受 d==1),
  而它与「无历史时的最终兜底返回值」完全重合——无论命中与否都不改变任何返回值。
  868 次/2 天的被拒全是纯浪费的读+判+留证。被拒数字(d≠1)是 A8 难度/Lv 泄漏的
  **错源**而非形变真值,「上下文规则修复」(OCR 分层规范①)没有修复对象,不适用。
- **`ocr_range` 值域守卫保留(与审计报告「两类并提」的厘清)**:值域外拒
  (288 次/2 天)来自**主路径**正则抓错源(如 `A8-50`),是 M70 假 win 防毒化
  守卫,设计内行为不删;判读成本只是字符串正则,无独立 OCR 开销。审计报告
  §3 把 868(fallback,删)与 288(主路径守卫,留)并提为「fallback 误读」,
  本批厘清两类归属。
- 停用后行为:blob 无合法匹配 → 直接走既有 last-known-good / `(1,1)` 兜底,
  过渡帧语义不变。

### 2. 候选②:备战决策结果缓存(感知态指纹键;主仓 57173711)

`prep_director._run_prep_loop_v2` 的 decide 端口(唯一生产路径;battle_loop
备战分支无需改动):同一决策输入面(指纹)未变的迭代,复用上次
`(Decision, action)`,跳过全量候选枚举与评分(审计口径 55 万行/日决策日志
的主体;墙钟单次求值 <1s,收益在 CPU/日志 churn/IO 竞争)。

- **缓存键 = 感知态指纹 + session 显式面**:指纹对 Snapshot **全部 dataclass
  字段动态枚举**(`dataclasses.fields` 递归规范化——快照契约「字段只增不改删」,
  新增字段自动进指纹,结构性防漏);session 侧只显式追 `defer_count`(框架侧
  唯一会变且指纹不可见的计数);其余 session 消费面(轮簿记)由失效规则覆盖。
- **失效规则**:任一动作 `progressed=True` 即清空缓存(成功动作必然改写 decide
  消费的会话簿记,其中部分不可见指纹;宁可少缓存不可错复用)。命中帧仍记
  F8 步进遥测——decisions.jsonl 缺行会误触发策略失活早停(ADR-0342),缓存只
  省求值不省遥测。
- **开关 `prep_decision_cache_enabled` 默认关 = 策略开关生命周期第 1 态**
  (strategy-work「策略开关的生命周期」门:默认关必须带开臂判据,禁悬置)。
  开臂三判据挂账在 `decision/cw_strategy.py` 开关属性注释(命中率下限 / 零
  复用致异常 / 决策日志行数降幅;任一不满足 → 生命周期第 4 态删码留 ADR)。
  本 ADR 只记录该开关的生命周期状态与判据指针,数值以代码注释为单一源。
  偏差声明:开关落 `CwStrategy` 类属性而非 registry(kernel/cw_registry.py
  为并行批禁碰面),开臂翻默认值同点操作。

### 3. 候选①:买牌边界固定开销压缩(主仓 b410aa78)

`operations/prep/shop.py::BuyShopCards.buy()`,四处:

- **删 `_tgt_state` 独立全量读**:`update_target` 改在波循环**首波**状态上调用
  (插入点与旧输入保真:同为「raw 读 + hp 覆盖」,未救援金、未拷 session 态),
  每执行省一次整帧 OCR 及其前后等待。
- **连击续刷波跳波顶 sleep**:board 面板 tier 链动画由开店/升级触发,刷新不触发;
  光标 park 保留(防光标污染牌行/金区读)。
- **刷新 pre-shot 条件化**:连击续刷波(判定纯函数 `refresh_wave_is_refresh_only`)
  刷前三读整块跳过,改用波循环刚读的同帧 `state.gold/state.shop`(仅刷新波无
  买卡,W592 勘误的失效条件不成立);刷后两帧稳定门与逐刷对拍**逐刷保留**
  (稳定是读牌正确性前提,r97/38 动画帧 SIFT miss 实证)。
- **买后重估增量态**(纯函数 `build_post_buy_incremental_state`,None=构造失败
  回退全量):本单元动作可变 surface 全集 = gold / bench 占位 / level·xp(仅
  LevelUp)→ 非升级轮重估 = 末波 state 垫底 + gold 真读(失读回退全量)+
  bench 重播 tracked(执行侧逐动作同步的权威);升级轮保守维持全量读。

**gate 层裁决(对审计原设想的修订)**:审计候选①设想的「`_OP_SETTLE_S` 与
stable 窗按步叠加改段级一次」经逐对检查(两次等待可合并 ⇔ 中间无改变 gate
指纹区/观察区的点击且服务同一次观察)——gate 各 settle 对应一次独立点击动画,
**不存在可合并对**;重复支付点实际在 shop.py 波循环的观察前置开销(重复全量
读 + 波顶 sleep)。压缩落点改在 shop.py,`cw_observation_gate.py` 零改动,
指纹机制零触碰。同理「连击共享一次稳定门」被保真裁决否决(中间刷后必须读牌
重 plan,读牌前必须稳定)——审计「每刷 7.1s→4s」的原设想达不到,缺口需决策
缓存(候选②)配合,见后果。

## Considered Options

- **A(采纳)三件分别按上法落地**:每件独立可回退;候选①按逐段盘点改
  shop.py 而非动 gate。
- B(拒)gate 层合并 settle/共享连击稳定门:逐对检查无可合并对;连击中间刷
  后读牌前必须稳定,共享稳定门 = 拿读牌正确性换时长(1.4-3 保真裁决否决)。
- C(拒)phase_round 做「上下文规则修复」(OCR 分层①)而非停用:被拒数字是
  错源非形变,没有可修复对象——该分层判据的适用前提(「历史上形变过」)不成立。
- D(拒)决策缓存键手工枚举字段:漏一个字段 = 错误复用,且快照契约「字段
  只增」下手工名单必然漏新字段;动态枚举把防漏变结构保证。

## 尾注:候选②(备战决策结果缓存)撤回记录(生命周期第 4 态)

开臂判据未启动,撤回发生在默认关挂账期——按「策略开关的生命周期」门,
「任一不满足 → 删码留 ADR」的预期形态,撤回代价低(墙钟收益本就小:单次
求值 <1s,收益主体在 CPU/日志 churn,见决策 2)。

- **两击原则触发**:同一机制在三次独立对抗审计中各发现一个会话耦合面破洞,
  枚举法结构性追不全,第三修劣于撤回:
  1. **第一击(相位机重放)**:缓存键不含簿记基线时,失败动作(不
     progressed、缓存不清)被冻结重发,`_main_flow_step` 阶段机的
     `prep_phase` 经命中臂重放反复 +1 越域(0→1→2→3→4…),真实 decide 的
     失败换向恢复机制被冻结 → 无限 stall 强出战。
  2. **第二击(读输入缺键)**:键 v3 修复相位机后仍留一个结构性反例——
     `deploy_fail_counts` 是 decide 的**读输入**(腾席链按它跳过失败候选
     换路)、由 director 失败记账在 decide 树外原地改写,键三成分(指纹/
     defer_count/簿记基线)全不沾,写面全量 diff 锁也探不到:开臂后腾席
     失败同键重放,「拒绝执行 → 重提案同动作」循环,失败记忆/换路机制整体
     被冻结(r93 实机病灶的缓存强化版)。
- **三次审计三个会话耦合面**:写面误归因(decide 单轮门计数不在缓存路径)/
  相位机重放等价性/读输入缺键——decide 对 session 的耦合面(读+写+外写)
  无法用「键 ⊇ 某个可枚举清单」结构性保证,每补一处靠的是又一层人肉枚举
  与新锁,与缓存的「省一次 <1s 求值」收益完全不成比例。
- **撤回内容**:prep_director 缓存四件(缓存表/指纹/键/lookup/store/重放/
  统计)与 `_decide_port` 命中臂全部删除,恢复直接 `adapter.decide` 路径
  (57173711 引入前的形态);`CwStrategy.prep_decision_cache_enabled` 开关
  与其开臂判据注释删除;测试仓 `test_cw_prep_decision_cache.py` 删除(全部
  锁针对被撤机制);F8 步进遥测语义不变(回到无缓存原生路径)。
- **A/B 结果作废**:缓存开关从未开臂,无行为对照意义;相关 sim A/B 数据
  不再引用。
- **未来重做须从三次发现重建设计**:任何「按感知指纹复用决策结果」的方案
  必须先回答——decide 的全部读输入(含 execute 侧外写的失败记忆等 dict 内
  mutation)如何被键捕获或失效?答案若仍是「人肉枚举 + 锁兜底」,则该设计
  不应立项;可考的方向是把 decide 改造成真正的纯函数(会话簿记显式出入参)
  之后指纹复用才安全,那是一次独立的架构改造。

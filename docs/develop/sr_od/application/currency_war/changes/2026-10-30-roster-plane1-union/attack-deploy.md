## 发现清单

### D-1｜「机制事实（已核实）」与「〔待拍板〕」自相矛盾，交换交互实为未验证前提
- 攻击点：§问题与约束「**机制事实（已核实）**：…目标槽被占 = 交换交互…执行层…实装」，而关键取舍 ⑤ 与「待核实」节同文承认「词表/执行层语义 = 设计意图 + 对账暴露式，无专项实测记录〔待拍板〕」。
- 证据：cw_vocab.py:309-311 与 cw_deploy_move_action.py:55 仅是**注释断言**；执行层是机械拖拽零判效（cw_deploy_move_action.py:6-8,92）；容器交换是上报函数的**逻辑推演**（cw_action_report/deploy_move.py:64-67）。三个证据都是「我们按此语义建模」，无一是「游戏确实如此」。整份执行器（§3）与「SellDeployed 发出点清零」（取舍⑤）都以该前提为分支条件。
- 严重度：高
- 处置建议：把「已核实」改为「已建模待实测」，并将取舍⑤的实机复核提为定稿前置项。

### D-2｜层值域隔离无实现机制，「乘法跳变超过渡层上限」数值不成立
- 攻击点：§方案1「核心攒到凑 1 档 → 分数跳变超过渡层上限 → 自然换防」与「层上限隔离只管凑档后的相对高度（锁定线凑档 > 过渡满分 > …）」。
- 证据：按文中公式 L1 = 多核心羁绊**加权平均** of f(角色完成度, 档位完成度)，f∈[0,1]：欢愉档位梯 (3,4,5,7)（cw_factions.py:97）、锁定线 form_tiers 欢愉:5（cw_comps.py:739-740）——凑 1 档（3 人）的档位完成度 = 1/2（按 form_tiers）或 1/4（按梯末 7），f ≤ 0.5；而过渡层满分（两体系各达顶）可达 1.0。任何直读公式的读法下 0.5 < 1.0，「换防」不发生，除非引入层间缩放/偏移常量——而同节明令「加权平均权重 = 自然单位…禁标定参数」。层与层如何合成选人分（字典序多元组？不相交值域求和？）全文未定义。
- 严重度：高
- 处置建议：定稿前给出层合成形式与隔离常量的来源，并用真实 comp 数值复算「换防跳变 > 过渡满分」。

### D-3｜「角色完成度」「档位完成度」两个核心量无计算源，且绕不开 form_progress 单一源
- 攻击点：L1 = f(角色完成度, 档位完成度)，两量全文无定义、无符号引用；「该羁绊最高相关档」未在 FACTIONS.tiers（梯）/ Comp.form_tiers（下限）/ form_tiers_max（上限）三者中选端。
- 证据：注册表注释明令「完成度上限读 form_tiers_max（**新读者显式选端**）」（cw_comps.py:121-124）；form_progress 是成型判据「唯一折法」，含 OR 组承接与 required_deployed 逐名折条，且「禁消费位绕过本函数自写内联判定」（cw_comps.py:1750-1767）——它返回全阵营均值单值，提供不了 L1 需要的逐羁绊完成度；自写逐羁绊版即触犯单一源禁令。锁定线希儿量子（form_tiers={量4,贝2} 全被 or_reqs 承接，cw_comps.py:1756-1759）在详设形状下无从计分。
- 严重度：高
- 处置建议：显式定义两量的读端与 OR/required 折法的承载（扩单一源或声明取代），否则评分函数不可实现。

### D-4｜执行器动作词表不完备，场上单位换排不可表达；「已就位集合单调不减」不成立
- 攻击点：§3「恒可配对交换」「每步已就位集合单调不减 ⟹ 有限动作收敛」。DeployMove 源恒为 bench 槽；当全部单位在板（bench 无单位）、目标仅要求某单位换排时（排分配/char_positions/前排保证都可产出这种目标），无任何动作可表达「场上→另一排」：两上阵动作均 bench↔场上（cw_vocab.py:419-446），无场上↔场上/下场动作——diff 恒非空，收敛论证失效。且「取缺位者中**序**最高者」的序、「槽内位置由执行层固定规则摆」的规则均未定义：若槽位规则按名序等分配，交换会把排正确的目标成员挤回 bench，「已就位集合」可缩小（反例：target={X:front,Y:front}，现板 Y(front,1)✓、Z(front,2)、X 在席，X 的指派槽=(front,1) ⟹ X↔Y 交换后 Y 离板）。
- 证据：cw_vocab.py:303-328,419-446；正本 24 §2「换排 = CwActionDeployMoveParam(to_row 重拖)」与词表 bench_idx 源坐标系互斥（24_deploy_segment.md:52），显示该能力面本身存疑。
- 严重度：高
- 处置建议：定义槽位规则的就位不变量并声明换排帧的可达边界（或补动作词），收敛论证重写。

### D-5｜「上阵窗口适用范围」整体失踪：终局成员会在窗口前被搜上场
- 攻击点：收编清单与 §方案通篇无上阵窗口概念；搜索枚举按手牌全集，唯一性键上无窗口过滤。
- 证据：现行约束链 = entry._deploy_window_blocked（entry.py:320,375,402）+ select_deployment 的 prep.window_blocked_names 过滤（mandate.py:1791-1795,1802）+ 正本「替补受上阵窗口辖域辖」（24_deploy_segment.md:12）；实例 = 反甲流全员 entry_signals=('plane_end',0)「前中期上 = 裸装送战损」（cw_comps.py:1236-1239）。搜索删掉该辖域属未申报的行为变化。
- 严重度：高
- 处置建议：把窗口谓词纳入枚举约束（或显式申报该行为变化并裁定放弃窗口）。

### D-6｜银狼LV.999 上阵变换窗未建模；「变费卡羁绊档按 effective_cost」引用失实
- 攻击点：段 0「变费卡羁绊档按 resolved 费用档（effective_cost）」——effective_cost 是经济域费用档读口（cw_economy.py:180-200），**全仓无任何羁绊计数消费它**，该主张零代码依据。真实存在且方向相反的机制是**上阵变换窗**：拖 3★ 银狼上场 = 写下一费用档 1★（星重置）+ lv999_cost_tier+1 + 合成级联（cw_action_report/deploy_move.py:8-15,122-131,159-169）——「同键多副本取最高星参与评分」对变换单位系统性失真（上场前 3★、上场后 1★），评分板面 ≠ 执行后板面，diff 循环内每步都可能触发计划外形态漂移。
- 证据：cw_action_report/deploy_move.py:122-169；cw_chars.py:157。
- 严重度：高
- 处置建议：删掉 effective_cost 误引，变换窗按「评分用落场后形态、枚举含档位跳变」显式建模。

### D-8｜环境发放上场锁不在枚举约束里，删围栏后必现零推进帧
- 攻击点：段 0 枚举约束只有唯一性键/系统单位/开拓者/变费四条，无上场锁。被锁单位（「在 2 个节点后才能上场」，T-30 契约）deploy_move 上报恒拒 applied=False 零写（cw_action_report/deploy_move.py:112-119；cw_env_grants.py:956）。现行体系里散件围栏（scatter_fence）顺带挡住了这类件的部署提议；详设同时删除围栏（清单「部署围栏 DEPLOY_FENCE/fw_carry 删/收编」）且走查明言「尽量填满」——被锁件会进目标板 → 执行恒拒 → diff 不推进 → 环级守卫反复触发，最长锁两节点内每帧空转。

- 严重度：高

### D-10｜无阵营锁定线（反甲流）在评分层无定义，且核心价值不可见

### D-13｜开拓者形态与排分配的阶段序存在反馈破绽
- 攻击点：段 3 先取选人分（开拓者「按两形态分别评分取优」）再做排分配；形态由**排**定（前台=记忆/后台=欢愉），排却在选人之后由容量/站位分决定——后排容量挤迫时开拓者可被排到非取胜形态的排，羁绊计数改变使已取优的选人分失效，可能低于落选候选板。
- 证据：cw_game_state.py:539-540（形态随排）；cw_action_report/deploy_move.py:121（trailblazer_row_unit 随 to_row 归一）；详设 §段3 步骤序。
- 严重度：中
- 处置建议：形态候选与排可行性绑定（形态选择提前到排分配约束内）。

- 证据：board_structure.md:8,13-25；cw_game_state.py:4881-4914（K=min(人口,4+动态后排)）。
- 严重度：中
- 处置建议：段 0 改为条件规则（占 K 真/假两形态的枚举上限式都给出）。

### D-15｜「残缺骨架」内容未定义，骨架成员不可移除 ⟹ 漏最优板
- 攻击点：段 1「产出多套残缺骨架」未定义残缺骨架含哪些成员；段 2 补人只加不减。反例：K=4，手牌 = 4 张 X 羁绊成员（X 需 5 人成 1 档，不可达）+ 2 张 Y 成员（Y 2 人成 1 档）：X 族骨架若按「能填则填」装满 4 张 X，最优板 2Y+2X（L3=1）不在任何族的枚举空间；同理走查「P1 早期全散牌 → L3 定序摆最强散件」隐含「空骨架 + 全补人」路径，而唯一写明的舍弃规则（锁定家族空核心即弃）方向相反。组合数软上限数值也未定。
- 证据：详设 §段1-2；对照现行 P24 残余补部署（24_deploy_segment.md:13）。
- 严重度：中
- 处置建议：定义骨架成员数下界与空骨架合法性，或允许补人阶段回退骨架成员。

### D-16｜收编行标签失真：「配方链板面易手（_p1_pair_eased/冻结）」
- 攻击点：_p1_pair_eased 是配方对**选择**（方向产出）算子（返回 (pair, cand)，写 ist.p1_pair），无「板面易手」职能；行处置（只留方向产出）实际可行，但标签误导实现者去 nonexistent 的板面易手逻辑里找东西。
- 证据：cw_intention.py:643,759,899,1178。
- 严重度：低
- 处置建议：行名改「配方对选择」。

### D-17｜op 内循环的逐动作固定 2s 睡眠未申报
- 攻击点：§3「一次识别…连续执行多个动作…直至 diff 空」；每个 DeployMove 动作 op 拖后无条件 sleep 2.0s（徽章动画对账保护），K 满换血帧 = N×(拖拽+2s) 的画面 op 时长，超时/看门狗边界未评估。
- 证据：cw_deploy_move_action.py:93-97。
- 严重度：低
- 处置建议：申报最坏动作数与 op 时长预算。

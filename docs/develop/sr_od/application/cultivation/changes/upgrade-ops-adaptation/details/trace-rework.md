# UpgradeTraceOp 面板态重构详设（块 D）

契约源 = 负责人裁定原文（内联如下，探索记录 requirement.md「已裁定契约」节的持久化副本）：
- 节点选择归 agent（树形随命途/角色变，程序层不做技能树节点选择）；op 起点 = 角色-行迹·面板态（`target` 校验技能分类，不符显式失败），终点 = 收尾关面板回树态。
- op 自动闭环 = 升级循环 + 通用材料补全 + 花萼券刷路线（资源窗口→券按钮→共用快速刷取弹窗→回面板）。
- 手动刷本（周本与花萼的非券路径都算）划出 op 边界——结算后回不到面板态，op 判停交还调用方。
- 消耗口径：花萼赤 = 开拓力 10 + 券 1/次（弹窗消耗行实读）。

其余实测事实（screen-flow.md）：面板态锚「简略描述」开关（1741,158）、面板开态树左移 413px、资源窗口行锚与券按钮（1263,415）、节点三态判据（归 agent 读）。现版 = upgrade_trace.py（树态固定节点坐标契约，:5-9 自证逐角色一致性未验）。

## 1. 契约变更总览

| 项 | 现版 | 重构后 |
|---|---|---|
| 起点 | 角色-行迹·树态（op 自己按固定坐标点节点开面板） | 角色-行迹·**面板态**（agent 选节点并点开，op 校验后接管） |
| 节点选择 | 程序层固定坐标（`_SKILL_NAMES` × 点击区 area） | **归 agent**（树形随命途/角色变，程序层不可维护——负责人裁定） |
| 终点 | 树态（原地） | **关面板回树态**（一切出口先收尾关面板，含判停） |
| `target` 语义 | 技能名枚举校验（`_SKILL_NAMES` 五类） | 面板技能分类校验锚：读区分类文本 == `target`，不符显式失败（枚举删除——面板读区是真相源，固定枚举随版本缺类） |
| 刷取参数 | `auto_farm` | `farm_dungeon`（与角色/光锥线对齐）；**不设 `use_fast_ticket`**——行迹线仅券刷路线（手动刷出 op 边界），docstring 显式声明差异 |
| 券耗常量 | `_FARM_TICKET_PER = 3`（未实测先例值） | 回填 **1**（实测定案：花萼赤 = 开拓力 10 + 券 1/次，弹窗消耗行实读） |
| 连刷次数 | `farm_times_per_round` 接收校验但未接入（:85-87 自证待补） | 接入：共用「快速刷取弹窗」画面档与光锥线 `_set_farm_times` 同款（「+」设到目标 / -1 = 点「^」拉满） |
| 记账 | 按 `_farm_rounds` 轮次计数记账（upgrade_trace.py:212-216/:304-305，无负数路径） | 轮次记账保留 + **面板等级读数差值入日志**（升级前后各读一次，可复盘增强——非缺陷修复） |
| 手动刷本 | 未声明 | docstring 契约：op 判停交还 agent——周本走 `ChallengeEchoOfWarByName`；**花萼手动刷由调用方按行迹缺料材料自行导航至对应副本挑战画面（`FarmTraceMaterialOp` 立项前的过渡态，cultivation 正本 §4 规划项）——现版 `FarmLightConeMaterialOp` 只认光锥缺料格，行迹 agent 判停后不可用，禁指** |

## 2. 节点卡

**① 入口校验（is_start_node）**
- 面板态双锚：`简略描述` 开关在场（面板态锚，探索实测 1741,158；树态无此锚）+ `读区-技能分类` 文本 == `target`（**复用已建档 area**：character_traces.yml `读区-技能分类`（:389），现版 `_read_panel_category` 在用；坐标与探索帧不符则纠档。匹配策略沿用现版白名单法平移，读区文本 normalize 后与 `target` 等值比较；多行命中取首个白名单匹配）。
- 命中 → ②；不命中 → `round_fail('不在目标技能面板')`（带截图）。**校验在任何消耗/点击之前**——agent 点错节点在此拦住，零消耗。入口 fail 细分两态：`简略描述` 开关不在场（真无面板/未知态）→ 直落 fail 不经收尾；开关在场但分类不符（**面板开着别的技能**）→ 先经 ④ 关面板回树态再 fail（终点契约=树态，不留面板态破口）。

**② 升级循环（现版逻辑平移 + 光锥线双形态平移）**
- 按钮四态判定与现版一致（upgrade_trace.py 升级循环段）：白底「快速升级」可点 → 升级；「使用通用材料补全」→ fill_generic 授权自动确认——**平移光锥线双形态处理（「材料补全」+「材料合成」，upgrade_light_cone.py:434-441）为实做项**：行迹与光锥晋阶共用属性材料池（现版 docstring :17-18 自证），补全弹窗很可能同样双形态，落地者不补则点补全弹「材料合成」框后误判停；灰底「材料不足」→ farm_dungeon 授权走 ③ 券刷链，否则判停；蓝字「已达最大等级」→ MAX_LEVEL。
- **循环内分类失配（画面异动致面板分类 ≠ target）→ `round_fail('不在目标技能面板')` 交 agent 重新发起**——现版 ③「点固定节点切换」分支依赖将删除的固定节点 area（upgrade_trace.py:249-253），随「节点选择归 agent」契约一并删除，op 不自纠。
- 记账增强：收尾时读面板等级一次（**复用已建档 area**：character_traces.yml `读区-面板等级`（:263），现版 `_read_panel_level` 在用），日志打「入口 target 面板 → 收尾等级 N」；轮次记账（`_farm_rounds`）保留。
- 稳定等待 `_TRACE_SETTLE_SEC` 与现版一致（反馈形态实测后随实机批回填）。

**③ 券刷链（按探索裁定新链实现——非现版平移）**
- 现版 = 面板「快速刷取」按钮**直开弹窗**（upgrade_trace.py:316-319）；重构后 = 面板「快速刷取」按钮 → **培养资源窗口** → 花萼行券按钮 → 共用「快速刷取弹窗」→ **连刷次数设置**（同光锥线 `_set_farm_times`：画面档共用，`farm_times_per_round=-1` = 点「^」拉满）→ 确认 → 结果框关闭 → 资源窗口关闭 → 回面板态。新链依据 = 探索裁定（契约源内联第 2 条「资源窗口→券按钮→共用快速刷取弹窗→回面板」）。
- 回面板态校验 = 简略描述开关回归。**依据分态声明：取消路径已实测（取消 → 回资源窗口 → 关窗回面板）；确认刷取后的返回落点未实测（探索未知段：E2E 授权未批停在控件前）——确认路径回面板为 landing 3.4 券刷 E2E 的验证项，两条路径都以简略描述开关回归为成功锚。**
- 预算 `farm_rounds_max` 与消耗声明（开拓力 10 + 券 1/次，常量已回填）同现版。

**④ 收尾关面板（新，一切出口的必经）**
- 出口传参机制：升级循环判停/完成时置**成员变量 `_final_status`**，④ 读取落终态 status（现版判停在循环内自收尾无现成机制，平移不可行——机制为本块新定义）。
- 点面板外空白区关面板（面板态点空白 = 关面板，探索实测定案）：**新建 area「点击区-关面板空白」（右下安全域）**——不复用现档「点击区-面板外空白」（character_traces.yml:375，画面中央 860-980 与面板态左移 413px 后的树区重叠，且现版 open_panel 前置点击用同名 area，语义不同禁混用）→ until_not `简略描述` 开关（面板关锚）→ 回树态 → 落 `_final_status`。
- 出口集合（全部先经 ④，status 由 `_final_status` 携带）：`MAX_LEVEL`（蓝字已达最大）/ `MATERIAL_CAPPED`（判停）/ **升满当前上限（默认成功出口——升级循环自然退出时落，非独立识别锚，与现版成功出口语义一致）**。
- 例外：① 入口校验「开关不在场」的 fail 直落不经 ④（画面本就在未知态，交调用方处置）；「开关在场但分类不符」的 fail 经 ④ 关面板后落 fail（见 ①）。

## 3. mock 场景

1. 面板校验通过 → 升级至满级 → 关面板 → `MAX_LEVEL`（断言树态收尾：简略描述锚消失）。
2. 缺料 + fill_generic → 补全弹窗确认 → 升满当前上限 → 关面板。
3. 缺料 + farm_dungeon → 券刷新链（连刷次数已设）→ 回面板 → 升级 → 关面板。
4. 缺料 + 两路全关 → 判停 `MATERIAL_CAPPED` → 仍关面板回树态（判停收尾幂等，`_final_status` 携带）。
5. 面板分类 ≠ target（开关在场）→ 经 ④ 关面板 → `不在目标技能面板` fail（树态契约保持）。
6. `farm_times_per_round=-1` → 「^」拉满路径 + 等级读数差值日志。
7. 开关不在场的未知态帧 → fail 直落，零点击零消耗。

## 4. 关键取舍

- **target 改校验锚语义、删枚举**（备选：枚举扩充欢愉技等新分类）——面板读区是唯一真相源，固定枚举每个新命途版本都要补；校验等值判断天然防 typo（不符即显式失败），枚举防 typo 的价值被完全替代。
- **判停也关面板**（备选：判停停在面板态交 agent）——终点契约「树态」是 agent 下一步（读树态节点三态、点下一目标）的前置；判停停面板态 = agent 多一步关面板且两态契约破口。
- **不设 `use_fast_ticket`**（备选：三线参数完全对齐）——行迹线手动刷已划出 op 边界（负责人裁定），券刷是唯一 op 内路线；设一个恒真参数是接口噪声，docstring 声明差异。
- **升级循环逻辑平移 + 券刷链按探索裁定新链实现**（非全部平移）——升级循环按钮态判定已实机验证，平移零回归面；券刷链现版直开弹窗链在新交互（面板态契约）下未验（cultivation 正本 §5 明载 auto_farm 全链未实测），按探索裁定走资源窗口新链并把确认后落点列为 E2E 验证项；重写升级循环才会引入回归面，违背「实现者无需再设计」。

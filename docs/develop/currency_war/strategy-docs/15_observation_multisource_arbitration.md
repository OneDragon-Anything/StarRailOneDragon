## 2. 仲裁层统一设计

### 2.1 现状诊断:六处仲裁、六种私写法、零共享面

家族清点里已有 6 处成型的仲裁(行 2/3/5/8/9/10;A12 勘误:v1 标题「五处」与正文 6 项矛盾,以正文为准),各自私写:hp 用「通道标定记录」、level 用「信源主权序」、deployed 用「min+带」、board 用「帧态门+覆写」、layout 用「CV>公式+防抖」、node_type 用「表+票」。语义内核其实同构——**每处都在答同样三问**:

1. 不一致时采谁(裁决规则);
2. 什么算「真分歧」什么算「读数噪声」(分歧带);
3. 分歧记到哪、按什么键统计(留证+分键)。

同构但零共享面的代价已实际发生:deployed 仲裁(7026c5db)落库时,board 的「帧态门」语义(非备战帧双源都不可信)没有可复用的载体,布局通道的对账语义也没有;三处各自的「分歧带」(spread>1 / ±1 / 阈值 6.0)写死在三个文件,判读侧要拼三个文件才能回答「这个量现在怎么裁」。这是「跨件半问」命中的第 4 件同根:升级为架构级统一仲裁层。

### 2.2 量纲分类与泛化规则

**核心设计裁定:仲裁规则按量的量纲分类,不按量的名字逐个拍。**四类:

| 量纲类 | 定义 | 泛化裁决规则 | 现有先例 |
|---|---|---|---|
| **计数类** | 有全序、有「犯错代价不对称方向」的整数/标量 | **朝声明方向取值或弃权(fail-closed)**:每量在注册时声明廉价侧及依据;分歧带=|Δ|>带(带内=合法读数差,不行动);高危读→行动门另加双帧一致门 | deployed=min(取低,板满假判贵);cap 失读=**拒信 None→调用方不设板满门**(按「门失效」跑,非取 max——A14 勘误,v1「cap 失读取 max」与代码不符:`_debounce_cap` 拒信返 None,cw_op_deploy.py:649 语义=不设门);gold 取末帧(时序单调) |
| **标称类** | 身份/枚举,值不可比、不可 min/max | **优先级+否决制,不做值组合**:①权威表优先(台账制);②画面事实优先(过帧态门:只在可信任帧上裁,污染帧双源皆弃);③缺陷认定需 **≥2 条独立通道票一致反对**权威值——⚠️ A4 勘误:本条在仓内**尚无纯行为位的成型先例**(node_type 票B 与权威同源,真独立票仅 2 张且该量纯记账零行为),规则本身成立但实证支撑如实收缩,首接线处=批 B `back_layout_divergence` 的画面票机制;④空间归属校验(升格为独立第⑤条,见下) | board 徽标覆写+帧态门;ADR-0520 单源化;node_type 表权威(降格为「表优先」先例,不再作「≥2 独立票」先例) |
| **连续标量类** | OCR 易掉位的数值(hp/gold/难度) | **通道仲裁**:同帧多预处理通道各读一次,采声明优先序的通道(A9 修订:「优」不设隐含度量——注册面显式声明**通道优先序+依据引用**(标定产物/复现帧索引),不从任何汇总指标推导;标定翻转=改声明+ADR,不是改隐式度量) | hp 双通道(优先序=放大>原生>二值化,依据=掉十位/漏检帧离线复现全对,cw_observation.py:227-236) |
| **结构/布局类** | 画面几何事实(格数/槽位) | **实测>推导,且两者都过防抖门**:CV 实测可判即采 CV;推导输入未过可信门(见 2.3)时推导弃权;两源皆弃权 → 显式**「布局未知态」**(缺省行为 §3.2④ 读写分级+冻结止损声明,不是静默退某档);CV 与公式的互否、以及任何会改变行动坐标的 CV 读数,一律过防抖重读门 | back_layout CV>公式+W209h 三读防抖(v1 的「瞬时读数才过防抖」界定作废——A1:档位直采同样可被单帧瞬态污染,见 §3.2②) |

**标称类第⑤条(A11 裁定,单列)**:**归属约束(几何先验)** = 身份读自哪个画面区域,该区域必须属于它声称的槽位类(bench 读数的 rect 必须落在备战栏建模 rect 内,不许来自商店行)。它与「独立票」**脱钩**:两者都是 SIFT 对同一肖像库(同引擎同源),rect 归属校验不是第二独立通道,而是读数坐标的先验约束——机制分类不同,批 C' 落地时不再争。

**泛化规则的边界(显式声明)**:①「计数取低」不是普适——方向由每量的代价不对称声明决定(deployed 取低、cap 失读=门失效弃权,行为不同且各有实证),注册面强制写方向/弃权语义与依据,防后人照抄 min;②「≥2 独立票」的独立性 = **通道独立**,且排除判据的**本质是共享错误源而非代码/数据出身**(B4 裁定):同一错误源(如票B 与权威同读一张表,表错则票恒随错,检出力为零)才排除——台账重索引(与权威同表)排除;同一 OCR 引擎的两种预处理(hp 原生/放大)按「通道仲裁」归类不算独立票;**跨画面/跨时机的采集链(如台账 seq vs 逐帧 live 行检测)不在排除列**,其证据力按具体共享错误面逐量评估(§8⑩ 裁决时适用);③单源化优先于一切仲裁——能像 ADR-0520 那样证明某源读的根本不是这个量(行 18)或某账没有存在前提(行 16),删源即治本,仲裁是给「删不掉的真双源」用的。

### 2.3 输入可信门(authoritative 判定)是四类共用的前置

家族四件的共同上游:**公式/推导类源的输入本身可能被毒化**(E3:level 读链毒化 → cap−level 全歪;启发式兜底值参与了布局选档)。统一设计:**一切「派生源」在参与仲裁前必须声明其输入的可信状态**,三态:

- `observed`:输入来自本帧真实读数(OCR/XP/CV)且过各自守卫 → 可参与仲裁;
- `derived`:输入含兜底/启发式(session 单调链、`_expected_level`、缓存沿用)→ 只可作兜底,**不可作裁决依据**;
- `unknown`:输入缺席 → 该源弃权。

现有载体的挂接点:`GameState.level_readable`/`hp_readable`/`board_readable`/`gold_readable` 已是 authoritative 位的实现(先例齐),布局公式通道与 14 号稿 swap 门此前没有消费它们——这是 §3 修法与 §4 接口约束的共同核心。⚠️ A7 补:authoritative 位的**传导缺口**有两处,批 B 一并闭合——①`GameState.level` 写入时不随 `level_readable=False` 打折(启发式兜底值与真值在字段上不可分),布局选档等消费方需要一个可查的伴随位(方案=level 消费统一走「level + readable 位」二元组或 session 侧等价单点,§5);②`cw_op_deploy._session_level` 与 `cw_identity_obs._session_level` 是同逻辑双拷贝,改造必须**合一为单一源**(落点=cw_identity_obs 侧单点,cw_op_deploy 转调),否则修一处漏一处=新双源。

### 2.4 统一注册面(留证与分键)

新模块 `obs/cw_arbitration.py`(设计稿落点,零代码),一个声明式注册表 + 一个裁决入口:

```
ArbitrationRule:
  key: str                    # 量键,如 'deployed_count' / 'back_layout'
  dim_class: 计数|标称|标量|布局   # §2.2 四类之一
  sources: list[str]          # 源名(paddle_x / cv_occupied / badge / formula / ...)
  combine: 规则函数            # 类内泛化规则实例化(方向/优先序随量声明,带依据注;
                              # 标量类=显式通道优先序+依据引用,A9)
  band: 分歧带                 # 带内=噪声不行动;带外=真分歧
  defect_kind: str            # 分键,缺省 f'{key}_divergence'
  fail_closed_side: 方向/弃权语义声明+依据(计数/布局类必填)

arbitrate(key, readings, ctx) -> (value, verdict, divergent)
  # verdict ∈ ok | noise | arbitrated | rejected | unknown(布局未知态)
  # 证据层 = 既有 obs_conflict(key, old, new, screen, verdict=..., source=...)
  # 裁决事件层 = 既有 telemetry.defects 分键记录(7026c5db 先例)
```

**不新建证据通道**:obs_conflict(原始证据行)与 defects 分键(不一致率统计)都是活体且已验证,注册面只统一「谁在什么键下调用它们」。迁移语义不变性 = 每迁移一个量,先用单测对拍「注册面裁决结果 == 原私写法裁决结果」(§6 锁 T-2),零行为变更迁完再谈规则修订。**A13 声明(迁移的「行为」边界)**:裁决值/schema/分键=行为,对拍锁死;obs_conflict 的 verdict 提示文本=判读面证据内容,允许随键迁移改写,T-2 对拍**不锁 verdict 文本**(否则文案润色即红,锁惩罚非行为变更)。

## 3. 布局档错位子问题:「7 格实画选 6 档」的公式缺陷定位与修法

### 3.1 缺陷定位(证据链)

现象(修复批遗留线索+代码直读):画面实画 7 格、系统按 6 档坐标运行(部署/读取漏最右格)。四条失效通路,前三条同向叠加,第四条为对抗轮 1(A8)补全的**反向通路**——全部在 `cw_back_layout.resolve_back_slots` 的现行对账语义里:

1. **公式通道输入未过可信门(2.3 违例)**:`diff = cap − level`,其中 level 来源链=`select_back_layout(level=...)` ← `_session_level()`(cw_op_deploy.py:279,=last_level_obs 与 last_state.level 取大;level=None 时 `cw_identity_obs._session_level` 同逻辑兜底,cw_back_layout.py:314-318)——**启发式兜底 level(`_expected_level`,假设已买经验,P1 早期系统性偏高 +2)混在链里**。level 虚高 → diff 虚低 → 6+(0)=6 档。佩佩局同型实锤已写在 `read_level` docstring(「兜底 4 → cap−level=0 → 后排选 6 格档丢佩佩@7」)——**reader 层修了 level 仲裁,布局消费端没接 authoritative 位**,这是 E3 家族在布局侧的未闭合出口。
2. **CV 通道对 7 格档左探针结构性失明**:左探针三值判据(`_CV_LEFT_STD_MIN` 注)把 7 格左半片 std(26-44)与 8 格空槽暗框(38.8)同置不可判带 [12,48] → 落带的 7 格帧左探针不可判 → cv_back_slots 返 None → 退公式。
3. **退公式时丢弃了仍可用的信号**:右探针(x=1458)对「6 格 vs {7,8} 格」判别(标定背景 ≤2.9/空槽 ≥10.5/立绘 50-67)——整体不可判时「右端有格子」这一条下界信息被整个丢弃,公式说 6 即 6 档直选。
4. **反向通路(7 格误判 8 档,A8 补)**:7 格左半片 std 26-44 是**样本观测区间**且代码自注「随格上立绘大小浮动」(cw_back_layout.py:125-126),其上界未被证明 <48——左半片 ≥48 的帧左探针判「有格」→ cv=8,8∈`_LAYOUT_PREFIX` → CV 优先直采**无防抖**(:340 防抖条件 `cv_n not in _LAYOUT_PREFIX` 不触发)→ 7 格真帧按 8 档跑。v1 病灶只写了「失明」半边,本条补全;右探针单帧瞬态假阳同样有历史实拍(W209h:特效把 1458 位单帧 std 顶到 6.5,擦线过 6.0)。

### 3.2 修法设计:三信号下界仲裁 + 布局未知态(v2 重写)

原则:不拍新阈值(防抖参数 N 的依据见②);复用已标定信号;**错向档的真实代价如实声明**(A1/A3:v1「错向=超集廉价」论证撤回)。

**0. 错向代价重述(A3,全节通用前提)**:三档布局**各自整排居中重排、列位互不重合**(cw_back_layout.py:74-79:6 格中心 604..1316 / 7 格 534..1386 / 8 格 464..1458)。在错向档上运行 = `read_deployed_chars`/部署拖拽的逐格 crop 全部错位 → SIFT 身份读 '?'/错身份 → tracked 毒化 → board computed 底座与部署决策连锁污染。**这不是「拖到不存在格被游戏拒=廉价」可覆盖的失败形态**——「超集=廉价」论证(ADR-0385 原语义)只适用于**未建档新档位(9+)退 8 格超集读全扩展带**,不适用于 6/7/8 三个已建档档之间的错向互跑。因此:任何改变行动档位的裁决都必须过防抖门(①-②),且需要缺省态声明(④)。

1. **公式输入净化(§2.3 落地)**:`resolve_back_slots` 内,diff 只在 `level_trusted ∧ cap 可用` 时计算——level 传参改带 authoritative 位(经 §2.3 合一后的单一 `_session_level` 透传);derived/unknown level → 公式源**弃权**(不是退 6 档!现行 `diff=0 → 6` 把「不知道」当成了「无扩展」,这是把兜底值当裁决依据的直接表现)。
2. **右探针下界否决(帧有效性前置 + 防抖门,A1/B1)**:cv_back_slots 重构为**可部分返回**——`cv_n=None`(整体不可判)时附带 `right_probe_has_slot: bool | None`。**有效性前置(B1)**:`right_probe_has_slot` 只在**两锚位 std 均过 `_CV_SLOT_STD_MIN`**(帧本身有效)时才产出真值;锚位失败帧(overlay 遮挡/非备战态/非 1080p,cw_back_layout.py:178-180)整帧不可信,右探针一律返 None → 直接进未知态④,**不得触发否决**(垃圾值在整帧不可信画面上完成错向档切换=B1 发作场景 1)。仲裁序新增:公式裁决=6 而 right_probe=True(有效帧)→ 公式候选被质疑;**否决成立须过防抖重读门:隔 ~1s 重读 2 次,三次一致才否决(采 7 档);任一不一致=瞬态,保公式+留证**。N=3 的依据(非拍定):①W209h house 先例即「重读 2 次三次一致」(cw_back_layout.py:264-292),复用既有节奏不立新参数;②右探针判据阈值 6.0 两侧的实拍分布=背景 ≤2.9 / 空槽 ≥10.5 / **瞬态假阳实拍 6.5**(run 27,W209h 注)——假阳与真信号间隔仅 1.6×,单帧判据余量不足是**已被事故证明的事实**,多帧一致是不引入新阈值的**瞬态隔离手段**;③右探针否决触发频度低(仅 CV None+公式 6+右高的合取帧),重读 ~2s 成本可接受。**残余风险如实声明(B1)**:防抖只隔离单帧瞬态,**持续性幻影**(特效循环/召唤物模型驻留 >2s,三读全幻影)防不住——该残余不靠阈值消除(加阈值=新拍值),防线=`back_layout_divergence` 分键频度监控,复现即按留证对拍画面修读链(与未知态④同款监控面);本残余申报进批 B 验收锚点(§7 批 B 实机局盯 `back_layout_*` 频次)。反向同理:公式=7/8 而 right_probe=False(有效帧+三次一致)→ 下界矛盾,公式弃权(进④未知态)+留证。防抖期间消费方语义=未知态(④),不按过渡值行动。〔as-built 2026-09-06:本节防抖的**前置触发面**在 C1 门(擦线带 [6,12)+对称比 2.5)下按「证据裁决式」裁决=**结构性吸收,不落三读防抖**:合成噪声实测,单端强不对称噪声(半窗纯平+半窗强噪声)判假 slice,但与另端 none 组合成未覆盖形态 → cv_back_slots 返 None 退公式——假 7 需两端同时 slice(两端共有的强结构证据),合成噪声单端形态不构成;锁=test_cw_data_registry `test_probe_residual_asymmetric_noise_absorbed`〕
3. **左重叠带消解与 CV 直采防抖(A8 处置)**:左带区分特征候选(暗框均匀度/双子窗 std 差/占位亮度)按「未证即退役」纪律先立采集命题(§8⑨),标定完成前不采信。批 B 同步闭合两条**先存的无防抖直采通路**:①左探针可判时 cv=7/8 ∈`_LAYOUT_PREFIX` 直采无防抖(:340);②cv_n 与公式不一致但已建档时同样直采——统一改为「**CV 与公式不一致的所有已建档档读数,过同一三读一致门再采**(一致才采 CV,不一致退公式+留证);CV 与公式一致(常态)零额外成本」。此条将现行「已建档直采」的暴露面收进防抖门,先存通路不再扩权。
4. **布局未知态(读写分级 + 冻结止损,A2/B2)**:三信号全弃权(公式弃权 ∧ 右探针 None/矛盾 ∧ CV None),或否决/防抖未决期间——**不固定选任何档**。缺省语义按**读/写分级**:〔as-built 2026-09-06:①④/T-7/T-8 已落码——`resolve_back_slots(level_trusted=)` 三态形参(False=公式弃权/None=零行为变更/True=observed),可信位单一源=`cw_identity_obs._level_trusted`(session.last_state.level_readable,T-8 同批闭合:`_session_level` 对 level_readable=False 帧的 state 值不参与取大);双弃权 → `n=None/prefix=''` + unknown/frozen/unknown_streak 三键,模块级连续计数(N=3=B3),已知帧清零;消费面=读侧 read_deployed_chars(_tiered) 单帧未知只返前排、冻结退 6 档基线,写侧 cw_op_deploy 后排部署返空/tracked 后排 equips 写入停/整表 reconcile 冻结跳过;每帧 JSONL 留证=`back_layout_unknown` 分键(obs_conflict+defects 出口双落,不节流)。supply 失活治本(§8 外,批 C 件③)同批落库:flow.on_round_end 空 node_type 回落位面节点台账同轮类型(档案装配局后不可得,台账=局内同轮行序单一源),查不到=照旧空串+`blood_alarm_node_type_fallback` 分键〕
   - **单帧未知** → 返回 `n=None`(显式第四态,注册面 verdict=unknown),消费方该帧**跳过后排依赖操作**(后排部署/后排身份读取,「宁缺勿造」同 paddle None 对齐跳过先例);前排/备战栏坐标与前排部署不受影响。
   - **连续未知(B2 修订:冻结止损,不退档行动)** → **读类**(后排身份读取)可按 6 档基线继续读+每帧留证(读面可重读可纠正,读错下一帧即被覆盖);**写类**(后排部署拖拽、任何向 tracked 写入后排身份/坐标的路径)**继续跳过并冻结**——冻结 tracked 后排写入止损,防错向档读数毒化 tracked 底座(§3.2.0 毒化链的向前传播面);真值 7/8 时在 6 档坐标上执行后排写操作正是「7 实画选 6 档」病灶本体的缺省化复发,禁。**恢复信号 = 防抖门任一方向出干净裁决**(三读一致的 CV 档/公式恢复 authoritative)即解冻,正常按裁决档行动。
   - **依据链(B2,如实声明)**:①v2 的「6 是 diff=0 常态先验」是**游戏总体分布**先验,不构成「未知帧 ⇒ 真值 6」的条件分布依据——未知态三种成因(level 非 authoritative/cap 失读/CV None)没有一种与 diff=0 相关,反倒是 level 毒化帧的 diff 分布未知,该论证作废;②与单帧语义反向的「信心越低行动越激进」矛盾由读写分级消解:写面不可逆(毒化入 tracked 底座向前传播,贵)、读面可重读(下一帧覆盖,廉价)——代价不对称天然成立,不依赖分布假设。**fail_closed_side 注册声明(布局类必填,§2.4)**:方向=**写面冻结、读面保守低档**;依据=上述读写代价不对称(重读廉价/毒化传播贵),非「真值=6」分布先验。
   - **连续判定与计数接口(B3)**:「连续」阈值与防抖同 N=3(复用 W209h house 先例节奏,显式声明不立第二旋钮);换算规则=**一次防抖轮(首读+2 重读)三读全不可判,计 1 个未知帧**(一轮=一个独立判定,不按读数个 ×3 虚增);计数器由任一**已知帧**(公式 authoritative 恢复/CV 干净裁决/防抖门出结果)清零复位;未知帧每帧写 JSONL 留证+`back_layout_unknown` 分键。7/8 无信号态(否决成立但 split 无信号)属本未知态,写面同样冻结,**不固定采 7**(v1 拍定值已撤)。
   - **残余声明**:冻结期间系统后排战力不推进(真实代价=战力真空,方向与 r9 停机的「合法化 no-op」同型但**有界**——读类仍在跑、留证与分键持续可见、恢复信号定义明确,复现即修读链;对照 v2 退 6 档行动的代价=tracked 底座毒化向后传播,不可局部恢复)。两个代价不对称方向上,冻结止损取廉价侧。
5. **留证与分键**:三信号任何否决/弃权/未知走 §2.4 注册面,键 `back_layout`,defect_kind=`back_layout_divergence`(+`back_layout_unknown`);右探针否决与公式弃权的留证行带 level_authoritative 位(判读侧可直接看出是否 E3 型毒化帧)。
6. **9 格档缺口不扩批**:e4972b43(cap13 后台 9 格)选档无通路是 ADR-0420 已登记待办,本稿三信号不解决它(公式封顶 8、探针饱和),维持「未建档新档位退 8 格超集读全扩展带」的 ADR-0385 原语义(此语境下超集廉价论证有效),§8② 保留。

## 4. 对 14 号稿消费臂的读数接口约束

14 号稿 §9.2 已登记 E3 为 swap 落码前置项;本稿把它具体化为三条硬约束(落码批执行)。**A5 落点勘误**:swap 发射门=m1/m1′ 的 `deploy_vacancy > 0` 门(mandate.py:133-140 `check_seats`),其 vacancy 数据链 = **cw_screen_prep heavy 段 `obs.deploy_vacancy = max(0, cap − paddle 直读)`**(cw_screen_prep.py:608-610,dep_n 无仲裁、divergent 不传播)→ adapter → mandate frame——约束的真实落地位置是 heavy 段与 snapshot 组装层,不只在 swap 收口位。

1. **swap 发射门 vacancy 读仲裁值**:〔as-built 2026-09-05 批 C:heavy 段 vacancy 已改消费「仲裁后 cap − 仲裁后 deployed」(`vacancy_from_reads` 纯函数,cw_screen_prep),divergent/stale 位已随 PrepObservation 载体就位(缺省关)。**§4.2 传播链消费点候 14 号稿 v5 挂账**:mandate frame 的 divergent 字段、contracts 契约与发射门「分歧帧/陈旧帧延迟」语义尚未落——载体已备,消费链候 v5,勿据本节误判已落地。〕`deploy_vacancy` 消费「仲裁后 cap − 仲裁后 deployed」(`resolve_paddle_pair` + `arbitrate_deployed_count` 链,板满门 7026c5db 同款),禁直读无仲裁的 paddle 单值或 session 跟踪账计数;**divergent 位随 vacancy 传播进 mandate frame**(contracts 现无 divergent 字段,批 C 补字段与传播链)。**缓存兜底帧收口(B5)**:cap/dep 双失帧上 heavy 现行沿 `self._cached_vacancy`(cw_screen_prep.py:611-612)——按 §2.3 这是典型 `derived`(上一帧缓存沿用),批 C 改造后该路径**不得以干净 vacancy 身份过发射门**:缓存兜底帧的 vacancy 须带 stale 标记进 mandate frame(与 divergent 同槽),发射门按 §4.2 分歧帧同语义延迟。r9 停机的最后一环就是 CV 虚高把「该部署」翻转成「合法不部署」,swap 的卖出+重上是不可逆面,毒化代价比部署更高。
2. **分歧帧 fail-closed**:`arbitrate_deployed_count` 返回 divergent=True 的帧,swap 发射延迟一环(留证交外循环重观察),不在分歧帧上执行卖出;重观察后仲裁干净即正常发射。与 mandate 单动作环语义天然兼容(发射-执行错配修复是独立批,dd-030/C3 线,不归本稿)。
3. **level 输入只认 authoritative 帧**:14 号稿一切消费 level 的门(升级费阈值/欠等级判据)沿用 `level_readable` 既有语义,与本稿 §3.2① 公式净化共用同一可信位定义(经 §2.3 合一后的单一源)——两处不得各写一份「什么算可信 level」。

反向声明:14 号稿臂①②③(买/升/危局刷新)消费 gold/board/hp——gold 有稳定门、board 有双源仲裁、hp 有对账层,均已成体系,本稿不新增约束;观测级消费位(supply 失活轮,14 §7.3)读 phase_round last-known-good,时序防抖语义不变。

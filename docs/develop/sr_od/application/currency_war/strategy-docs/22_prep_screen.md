## 1. 决策工序:十段全扫(第 0-9 步)

决策入口 = `strategies/impl/mandate_v1/bridge.py::decide_prep_screen` → `entry.py::emit`。每帧回到备战画面从第 0 步向下扫描,**执行第一个满足条件的步骤并返回其动作,下一帧重新扫描**;全部步骤不中 ⇒ 第 9 步出战。单动作循环不变(逐帧恰取一个动作);回跳语义(腾位后回头点晶矿、买完牌回头部署)在全扫下自然表达,无需状态机记步——**唯一例外 = 跨画面计划变量**(下述前置步:商店侧决策一次定型、备战照计划逐帧游标执行——商店画面信息〔货架/目标牌〕在备战侧不可自证,必须传计划)。策略层无试错计数:全部判据为每帧全量重评的纯判断——该不该做由价值/身份判断直接给出,不做「试 N 次后放弃」形态;动作未生效归执行层落地验证,候选空等异常帧正常返回主循环;计划执行域的对应形态 = 卡死判定(连续 2 次重观察无进展 → 计划失败出口,见前置步——失败即弃计划恢复扫描,非重试计数)。(第 1 步商店随机态重开为 2026-10-17 迭代新增,其后步骤序号顺延 +1;前置步插在第 0 步之后。)

每帧入口先执行**读数协议入口序**(金位账面同步 + 合成结果帧失效检测,协议单一源 = [23_shop_screen.md](23_shop_screen.md) §2 读数协议节),再进入十段扫描。

**第 0 步:溢出告警自救。**
- 触发 = `gs.overflow_warning` 为真。机制事实:告警在场 = 备战席 9 格全满且溢出位有一张卡(角色或占席道具),溢出卡阻断进入战斗;解除方式唯一 = 腾出一个备战席空槽,溢出卡自动归位。
- 自救动作序按损失递增排列(免费腾位在前、有损卖出最后),每帧重评取首个可行:
  1. **上阵安置**(免费腾位):场上人口上限有空位 ∧ 备战席有可上阵单位 → 拖上阵(腾出备战席槽 → 溢出卡归位;同时是有效部署)。
  2. **点开消耗品**(免费腾位):无上阵安置可行 ∧ 备战席有已知占席物品(书册卡/补给箱/星徽秘典)→ 点开腾槽(占席道具不可卖但可点开)。
  3. **卖出**(有损腾位):候选评估非空 → 按卖出候选评估器的**自救全资格豁免面**卖出首位候选(循环防线与身份面全放行——保命优先于防自旋,豁免仅辖本场景;取用 = 部署重排定型后的统一让位优先级序列末位起,判据单一源 = [11_shop_decisions.md](11_shop_decisions.md) §4.0 场景表)。
  4. 全部不可行 → 防御性分支:零动作返回主循环(识别异常真实形态的兜底;全量可卖下候选空在结构上不可达)。
- 告警在场时,其余步骤全部不执行(告警不消出战无效);例外仅上列自救动作本身。
- 空板守卫 as-built 语义:卖出守卫(`sell_gate.py::empty_board_sell_blocked`)为后态判定,deployed = 0 帧全部卖出场景哑火——deployed = 0 帧的自救主路径 = 上阵安置(非卖出,不受守卫辖)。

**前置步:跨画面计划变量执行(计划游标)。** 计划槽 `StrategyState.yield_plan` 非空时,本步优先于第 1-9 全部步(含第 5 步开店与第 9 步出战——计划未完成不出战;时长上界 = 差分深度);被第 0 步自救抢占的帧本步不运行。逐帧消化步骤序列、照单执行零重验(备战执行零搜索——目标板已定型):卖出步骤(目标 = 步骤内名;`SellDeployed`〔场上〕/`SellBench`〔备战〕按名现读落位)/驱板步骤(差分执行器驱当前板面至目标板 T,拖动与重观察交替——每发一个统一拖动后下一帧发 `Obs(in_place)` 环内重观察对账;连续 2 次重观察无进展 = 级联卡死);序列空 → 清槽 → 扫描继续(开店不是序列步骤,由第 5 步常规机制发);执行失败(目标不在场/卖失败/级联卡死)→ 清槽 + X 路径失败标记(节点作用域布尔,在场时获取让位评估的场上件 victim 全部不成立)+ 恢复扫描,失败按计划语境记键(`yield_plan_failed_priority_insufficient`/`yield_plan_failed_priority_insufficient_gold`)。计划槽与失败标记均节点作用域,节点边界清零;无动作可发帧发 `Obs(in_place)` 环内重观察,扫描不前进。计划产生源 = 商店获取让位评估的场上件 victim 路径([11_shop_decisions.md](11_shop_decisions.md) §4.0);出战就绪帧计划槽非空时让位于本步(bridge 前置动作发出点的让位谓词);判据实现 = `entry.py::_step_yield_plan`。

**第 1 步:商店随机态重开(2026-10-17 迭代 design §2.4)。** 触发 = 随机态信号 `shop_randomized_pending` 在册(写端唯一 = 升级值变更回调,源 = 任意经验来源升级,经调度器 `cw_levelup_callbacks` spy 分支):清「本节点已处理」标记 → 发开店动作 → 清信号。进店后入口观察读真牌面,会话循环正常评估(含商业间谍偷入备战席的 3 张新件)。位次依据:随机态 = 商店有未处理的全新牌面,用户裁定「很高的优先级」——置于溢出自救之后(安全动作最高)、资源动作之前。

**第 2 步:点开消耗品。** 触发 = 备战席槽位有 kind 为 bookcard/supply_box/tome 的物品(书册卡/补给箱/星徽秘典);点开顺序 = 书册卡 → 补给箱 → 星徽秘典。点开产生的弹窗由外循环画面分发接住,处理后回备战重新全扫(弹窗不是工序步骤)。

**第 3 步:晶矿。** 触发 = `ore_click_targets_of(gs)` 非空。
- 席位未满:点全部晶矿(判据 = 全点;执行面按批式点击上界分批推进——执行载体 = `operations/cw_op/cw_collect_ore_action.py::CwActionCollectOreOp`,原薄委托 `prep_actions._collect_ore` 已随死代码清偿移除)。
- 席位满:**按序列取用直接判断值不值得腾位,无试错计数**——候选评估(`ore_make_room` 场景)非空 → 卖统一让位优先级序列末位 1 张腾位,下轮全扫回来点晶矿;候选空 → 本节点放弃晶矿(确定的高价值持有不换随机产出——部署定型内的牌 = 档 1 永不先卖,序列自然停在「部署外无可卖」,判据单一源 = [11_shop_decisions.md](11_shop_decisions.md) §4.0 场景表)。判断天然自收敛:序列末位起让位,低价值件卖完后自动停在「无可卖」。
- 依据:确定损失换随机收益只在损失 ≈ 0 时成立(卖出纪律 = 不可逆动作按持有价值守门,弃购/囤积的真实代价 = 再遇窗口)。

**第 4 步:升级检查。** 判据与发射形态单一源 = [11_shop_decisions.md](11_shop_decisions.md) §2(最优概率带单判据三分派 + 资格门六道门序 + 单帧原子整批发射,判据同帧重评,无跨画面授权键)。本步只定义调用时机:每轮全扫评估一次;**判据不过 = 本步零动作,扫描继续到下一步**(经验批支付门/资金线门类拒发同落零动作语义);金不足(花后破线)帧恒整批推迟零动作等节点收入(拒因键 `levelup_fund_line_defer`;不存在升级卖牌凑金——保持最大压牌库,钱够了再升)。

**第 5 步:商店会话。** 入口先调**解拦复核**(未消费机会清单的解拦判定,分键分轴:席满类 `bench_full`/`priority_insufficient` 席位空出即解拦;金不足类 `priority_insufficient_gold` 金位相对记录时点增量 ≥ 记录的缺口绝对值、或重开店帧货架签名变化即解拦;判据单一源 = `criteria/shop_session.shop_unblock_recheck`)——任一记录拦因解除 → 清「本节点已处理」标记;然后判标记 ≠ 当前节点号。满足 → 输出 `CwActionOpenShopParam` 开店;不满足 → 跳过本步。本步是备战侧**决策性**开店意图的唯一来源(金位读数开商店为辅助形态——读金非处理决策,语义单一源 = [23_shop_screen.md](23_shop_screen.md));计划变量序列清空后的开店也由本步常规机制发(前置步不发开店)。部署产生的腾位效果由本步入口的清单复核自然消费,无独立重开钩子。

**第 6 步:部署调整。** 部署 = **统一部署搜索·评分制定型 + 差分执行器执行**(选人/站位/评分/差分判据单一源 = [24_deploy_segment.md](24_deploy_segment.md) §1:搜索枚举手牌组合按评分取最优目标板,执行 = 现板面 → 目标板的统一拖动/换星直卖差分序;换人 = 交换交互,无独立换人机器);调用时机在商店会话之后(先逛店再统一部署)。要点:
- **无上阵窗口辖域**(已退役,2026-11 用户终裁「可退役」:万敌 1 条/白厄 3 条知识真空接受损失,不回流策略层)——上场时机 = 部署搜索的骨架/L1 完成度自适应(终局件在未成型面板被 L1 递减自然挤出,成型骨架齐时自然上场);退化观测挂 sim(终局件在板率/血线),明显再议。
- 部署枚举按**唯一性键**归一(角色名归一,开拓者各排形态互斥;同名多副本取最高星——板上同名并存结构性不可达)。
- 方向读口:现行方向 = 锁定线优先,未锁 = 过渡配方开局面(`session_scope.direction_comp_of`);搜索候选族按阶段分域自行装配(P1 过渡体系组合/锁定线/候选三线,[24_deploy_segment.md](24_deploy_segment.md) §1),无方向(K 空窗)时目标供给经 K 空窗回退(`kernel/cw_intention.k_empty_window_fallback`,回退单一源,禁复制兜底逻辑)。

**第 7 步:装备与工具。** 装备穿戴 = 现行完整实现保留(合成规划/分配/转移,语义 = [18_equip_wear_semantics.md](18_equip_wear_semantics.md));工具使用判据 = `kernel/cw_equip_env.evaluate_tool_actions`;调用位置固定为部署之后。

**第 8 步:节末凑息检查。** 所有花费决策完成后的**最终利息档检查**——「卖活期牌回金」两种目的两个位置:为买而卖(获取让位评估,排在买牌账内)与为息而卖(本步)。本步必须在出战前最后执行:息按节末金位结算,提前卖会被后续购买把金位吃回去。触发 = 存在「单件退金 ≥ 到下一利息档缺口」的资格候选(缺口单一源 = `kernel/cw_economy.py::next_interest_line` = 下一档线 `(g//10+1)×10`;满档/买断制 = None 不凑——**跨不了档的卖出零利息收益,一件不卖**:利息 = `g//10` 封顶,档内卖出金位变动不涨息,旧「卖到饱和线」判据在 P1 早期金 10~40 区间退化为卖光备战席)。动作 = 序列末位起取「单件退金 ≥ 缺口」的候选(**跨档止盈 + 凑息豁免**场景参数:候选池剔除线内未达标成员——为利息不可卖,豁免剔光帧零动作;评估与排序 = 统一让位优先级序列,无身份/星级过滤——判据单一源 = [11_shop_decisions.md](11_shop_decisions.md) §4.0 场景表),逐帧单张:跨档后下帧按新金位重评自然收敛。

**第 9 步:出战。** 以上全部步骤无动作 → 输出 `CwActionStartBattleParam`(备战环唯一完成态)。出战前置动作发出点机制保留(发射前判定宿主 = `kernel/cw_launch_admission.py::readiness_launch_decision`,机制出处 = [26_battle_settlement.md](26_battle_settlement.md)):出战就绪帧短路本工序的出战动作直接发射;**受限商店访问帧不受会话标记辖**(发射帧仲裁授权的富余段消费照常进入商店执行)。出战点击后若长时间未离开备战画面且第 0 步告警已清 → 交外循环(已建档画面的轮转/哨兵保留证据)。

## 2. 卖出候选评估器的备战域消费

全部卖出场景(备战与商店两域)共用一个卖出候选评估器(单一入口 `criteria/sell_candidates.py::evaluate_sell_candidates`):取用 = 部署重排定型后的**统一让位优先级序列**末位起,**单一源定义 = [11_shop_decisions.md](11_shop_decisions.md) §4.0**(场景注册表闭集 = 3:排序单一源/循环防线/场景参数——无场景专属池子)。备战画面消费的场景:溢出紧急处理(第 0 步,全资格豁免)、采晶矿前空位(第 3 步)、节末凑息(第 8 步,跨档止盈 + 凑息豁免)——升级凑金与原会话内筹资场景已整链删除(金不足帧升级恒 defer 等钱,获取让位并入商店买入臂的统一获取让位评估,[11_shop_decisions.md](11_shop_decisions.md) §4.0)。每笔卖出记遥测(场景、卖出名、档位分布),各自可判读归因。

## 3. 节点边界状态重置

策略入口(备战/商店两域各自)在节点号读取处调用同一边界处理函数(`session_scope.handle_node_boundary`):检测到生效序位(位面,轮次)变化 → 按清单表执行一次重置(重置全部幂等;函数内部判重避免冗余执行)。**键清单的唯一所有者 = 该函数的清单表**,其他模块的节点作用域键显式登记进表(键名 + 复位值),禁各自散写重置逻辑。清单:

| 键 | 复位 | 理由 |
|---|---|---|
| `shop_handled`(本节点已处理标记) | 清值 | 新节点牌面全换,旧标记语义死亡(节点切换自动刷新全店) |
| `shop_opportunities`(未消费机会清单) | 清空 | 牌面变了,旧机会作废 |
| `line_eval_signature`(方向证据签名) | 置失效 | 强制下帧重算(节点变动伴随结算收入与自然经验,资产面可能变化) |
| `gold_ledger`(金位账面) | 置失效 | 读数失效条件「节点切换」经本表落地 |
| 会话域旗标(读数意图/受限访问/会话处理中/插件额度) | 复位 | 会话不跨节点,边界帧残留旗标防泄入下一节点 |
| `yield_plan`(跨画面计划槽)/`x_path_failed`(X 路径失败标记) | 清空/复位 | 计划与失败标记均节点作用域——计划跨节点语义死亡(新节点货架/牌面全换),边界清零(§1 前置步) |

(升级预授权重置行已随 2026-10-17 迭代 T-4 键退役删除——判据同帧重评后无跨帧授权可清;商店随机态重开信号宿主 = GameState 簿记槽,边界清扫经边界函数直清不入本策略态表。)

**负登记(不重置项)**:方向状态本身(锁定线槽/候选快照/开局配方)不重置——锁定为一次性决策跨节点持续保留,候选快照随签名重算自然更新,配方物化链每备战期自写;`plane2_started`(第二位面已启动窗口谓词)与 P2 选卡侦测键同不重置(单调历史事实)。

## 4. 会执行的动作清单

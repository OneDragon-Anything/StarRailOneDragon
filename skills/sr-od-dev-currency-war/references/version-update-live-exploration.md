# 货币战争实机探索期作业方法(CW 域)

> 定位与分工:本文档 = 货币战争新版本实机探索期的作业方法——怎么跑实机探索局、怎么把探索产出变成四层覆盖。分工一句话:编排机制(编排者职责/窗口所有权/单局限令机制面/问题处置循环)归 [autonomous-loop.md](autonomous-loop.md);版本适配总流程(判型/各域适配明细/换赛季战役组织)归 [version-update.md](version-update.md);玩法操作与对局决策归玩家 skill `sr-od-currency-war`;本文档只写作业方法本身。适用前提 = 游戏版本更新后的实机探索期。读者 = 实机探索期的编排者与实机探索 agent:编排者派局前读 §2-§3 与 §5,实机探索 agent 开工前读 §4 与 §6,局间循环全员按 §5 走。

## 1. 探索期目标口径

主目标 = 四层覆盖链闭合。四层按依赖序:

| 层 | 内容 | 覆盖判据 |
|---|---|---|
| 画面建档 | bot 会遇到的画面建档到 screen_info | 画面能被识别框架认出(产物形态见 od-dev-screen-onboarding) |
| MCP 识别 | 已建档画面的关键读数接入识别器 | `analyze_screen` extras(结构化读数扩展)能读出该画面的关键数值 |
| 动作 op | 画面上的交互有对应动作 op | 交互可经项目 MCP 工具执行 |
| 游玩指导 | 玩家 skill 有该画面的决策知识 | 玩家 skill 对应玩法文档覆盖该画面的决策面 |

- **标杆 = 商店闭环**:商店画面四层全部在役(建档可识别 / extras 可读数 / 买卖动作 op 可执行 / 玩家 skill 有商店决策指导)。新画面与新节点的覆盖验收以商店为参照:四层缺任何一层 = 未闭合,缺口登记进缺口矩阵(§2.1)。
- **全量覆盖审计先行**:探索期开局先盘点缺口矩阵(§2.1),实机局任务书由缺口清单驱动(§2.3);禁不带目标进局。
- **机制/数据取证顺带,不占主目标**:挂账板上等实机取证的条目(定位见 SKILL.md §3「跨迭代挂账」行)在单局任务书里以顺带清单携带,主线始终是覆盖缺口;取证结论按 §6 可靠性纪律处理。

## 2. 开局三步

探索期开局按序走三步;前两步完成前不派实机局。

### 2.1 覆盖审计(四源盘点 → 缺口矩阵)

盘点四个来源,各自列出「新版本影响到的面」:

1. **建档面**:screen_info 下 currency_war 画面档清单——哪些画面已建档、新版本 UI 变动涉及哪些;
2. **op 面**:画面 op 与动作 op 在役清单——哪些交互已有 op 覆盖、哪些 op 消费的画面与控件已变化;
3. **知识卡面**:玩家 skill 玩法文档与 `docs/game/currency_war/research/` 知识篇——哪些结论基于旧版本、哪些面从未建档;
4. **遭遇面**:遭遇与事件类节点的枚举清单——新版本新增的遭遇/事件/环境词条;这类随机内容是版本增量最常见的入口。

汇总成**缺口矩阵**:行 = 玩法面(画面/节点/机制),列 = 四层覆盖,格 = 已覆盖(附凭据指针)或缺口。矩阵是探索期的覆盖总账,随局更新;下一局任务书从矩阵的缺口格里取。

### 2.2 版本配置研究先行

先离线研究,再耗实机窗:

1. 拉官方攻略广场配置快照(plaza config,拉取命令见 version-update.md §2 第 2 步)——角色/羁绊/装备/投资的官方名单与效果文本;
2. 查 wiki 三源交叉(米游社 wiki / 国际服 wiki / BWIKI,接口入口 = skill `sr-od-official-api`);
3. **随机池类取证(概率/出现规则/池构成)先查配置再耗实机窗**——纯统计推断会被结构盲区骗。结构盲区 = 样本覆盖不到的规则结构(低概率档/隐藏门控/跨局状态),统计上不可见但真实存在;配置与 wiki 先给出结构假设,实机局只做验证。
4. 判据:实机局开工前配置研究已完成一轮;实机读数与配置矛盾的点才是高价值发现,优先排进任务书。

### 2.3 实机局按缺口清单排任务书

- 单局任务书 = 局内目标(打到哪里/验证什么)+顺带取证清单(挂账板条目中本局顺路可取的)。
- 排序判据:覆盖缺口优先,机制取证次之;每局只背一个主目标,顺带清单只收顺路可取的条目,不要求绕路取证。

## 3. 派发纪律

单局限令/最高难度默认/一窗一 agent/占用先登记的机制面归 autonomous-loop.md §2,不在本节重复;本节写执行侧增量,每条附为什么。

1. **任务书完整重申纪律**:每次派发的任务书必须完整重申全部纪律条款(单局限令/停止纪律/最高难度/结算存档义务),不得以「按上次任务书」「同前」指代。为什么:子 agent 会话上下文压缩会丢早期纪律条目,被压缩掉的纪律等于没有纪律,任务书是纪律的唯一可靠载体。
2. **派发前查线表**:派发任何会占用游戏窗口的活之前,先查线表(自主工作文件夹的线调度登记)确认无其他实机线在推进,含其他会话的线。为什么:同一窗口两个操作者会互相干扰——点击落进对方操作的画面、画面被抢,且事后无法从运行记录区分是谁的操作。
3. **实机占用先登记再派**:占用表登记(谁/从何时起/干什么)先于派发动作完成。为什么:登记是窗口互斥的唯一事前凭据,事后归因防不住并发。

## 4. 单局作业规范

实机探索 agent 每局执行以下规范,全部条款并入任务书。

### 4.1 结算画面必存档

每场战斗的结算画面截图存档。用途:读数可靠性核对素材——遥测(对局运行数据流水)与识别读数的数字以结算画面为终审凭据逐项对账(§5 第 2 步)。

### 4.2 逐局账

单局报告按固定字段记账:深度(节点进度,如位面-节点号)/难度(当局难度档)/环境(当局环境词条)/词条(关键选择与获得)/终局(胜负与终止原因)/晋升(晋升级变化)/晶球(余额变化)。字段缺失 = 报告不完整,编排者打回补齐。

### 4.3 新画面先建档再操作

遇到未建档画面,先按 od-dev-screen-onboarding 建档,再继续操作。为什么:在未知画面操作 = 误点风险 + 现场证据丢失;建档本身也是覆盖链第一层的推进。

### 4.4 遇问题停手留证

操作不生效/画面异常/疑似机制变化时:停止一切游戏操作 → 截图留证 → 报编排者等待处置。机制细则 = autonomous-loop.md §2.3,任务书整段并入。

### 4.5 血线保守口径

探索局血量管理按保守执行:血线偏低时优先稳血,不赌斩杀、不贪高收益选项。为什么:探索局的目的是暴露问题与覆盖缺口,单局存活时长比对局胜率更有价值——存活越久,经过的画面与节点越多,覆盖推进越大;血线归零 = 局终 = 覆盖中断。

## 5. 局间循环

每局终了到下一局派发之间按固定序列走,每步产出是下一步的输入:

1. **单局报告**:实机探索 agent 局终发报告(逐局账 + 取证发现 + 遗留 + 晶球余额)。
2. **机械对账**:报告账目逐项与凭据(帧号/截图/遥测)比对,不依赖报告者转述。判据:数字对不上 = 登记疑点并降级该项,不采信报告原文。
3. **挂账板登记**:待办与候选结论登记进货币战争跨迭代挂账板(定位见 SKILL.md §3「跨迭代挂账」行);实机发现类条目按板面现行带圈数字序号顺延,每条附帧号凭据。
4. **知识消化批**:候选知识逐条核实(帧证核对/与既有知识对拍)后回填知识卡。判据:未过核实的候选留在挂账板,禁直入知识卡;核实通过 = 更新知识卡并在挂账板条目标注回填落点。
5. **下一局任务书**:按挂账板开放项 + 本局新发现重排(回到 §2.3),派发前过 §3 纪律。

**知识卡** = 玩法知识的最小归档单元:玩家 skill `sr-od-currency-war` 的玩法文档(单画面卡与总览篇)与 `docs/game/currency_war/research/` 知识篇。归位分层判据见 SKILL.md §3。

## 6. 知识可靠性纪律

1. **帧号制度**:候选实录与机制结论必须附帧号。帧号 = 帧时点的可回查标识,实证形态 = 截图文件名或遥测流水时点。判据:无帧号 = 不可回查 = 不入档;口头转述无帧证的内容只作线索。
2. **单样本知识先核实再入契约**:仅出现一次的观察读数不入消费契约(注册表条目/知识卡的确定性结论)。核实路径 = 第二来源(再局复现/官方配置查询/wiki 交叉)任一命中。为什么:单样本含观察误报的可能,误报入契约会随下游消费放大成系统性错误。
3. **知识源被质疑时暂停下游写入**:某知识卡或数据点被质疑后,先核实,再继续以其为依据写入新条目。为什么:基于未核实源的写入会把单一错误扩散成引用链。
4. **消化批自纠**:知识消化批发现自己此前写入的知识卡有错,直接修正该卡,并同步检查该错误的其他消费点。自纠是消化批的常态义务,不等裁定。

## 7. 长跑与上下文压缩对策

子 agent 长跑时,上下文压缩会丢纪律条款与早期明细。对策三条:

1. **累积报告模式**:发现子 agent 回报内容缺失(早期局明细/纪律条款丢失)= 压缩已发生;此后其回报改为累积模式——覆盖多局的累积账 + 候选名单整体重发,不依赖其会话记忆拼单局明细。
2. **关键结论即时落盘**:每局的关键结论(逐局账/候选结论/挂账)在局间循环内落盘(挂账板/知识卡);落盘完成的结论才视为已保存。为什么:会话记忆跨局不可靠,落盘是唯一持久层。
3. **任务书自足**:每个任务书自含全部纪律与目标(§3),任何环节不引用「会话内此前说过」的内容。

## 8. 数据源优先级

取证优先级从高到低:**官方配置 > wiki 三源 > 项目注册表(代码内注册表与 `knowledge/` 事实常量)> 实机统计推断**。

- 实机局是验证手段,不是发现手段:要发现一个机制或数值,先查官方配置与 wiki(§2.2);两者都查不到才设计实机取证,取证按 §6 附帧号。
- 实机统计样本与官方配置冲突时,以官方配置为准复核读数——先查读数链(OCR/识别/转述环节),确认读数无误再上报矛盾;禁直接按样本改配置结论。

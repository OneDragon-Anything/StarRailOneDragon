# UpgradeTraceOp 面板态重构详设（块 D）

契约源 = 负责人裁定（探索记录 requirement.md「已裁定契约」节）+ 探索实测事实（screen-flow.md：面板态锚/413px 树移/资源窗口行锚/券耗 10+券1 实测定案）。现版 = upgrade_trace.py（树态固定节点坐标契约，:5-9 自证逐角色一致性未验）。

## 1. 契约变更总览

| 项 | 现版 | 重构后 |
|---|---|---|
| 起点 | 角色-行迹·树态（op 自己按固定坐标点节点开面板） | 角色-行迹·**面板态**（agent 选节点并点开，op 校验后接管） |
| 节点选择 | 程序层固定坐标（`_SKILL_NAMES` × 点击区 area） | **归 agent**（树形随命途/角色变，程序层不可维护——负责人裁定） |
| 终点 | 树态（原地） | **关面板回树态**（一切出口先收尾关面板，含判停） |
| `target` 语义 | 技能名枚举校验（`_SKILL_NAMES` 五类） | 面板技能分类校验锚：读区分类文本 == `target`，不符显式失败（枚举删除——面板读区是真相源，固定枚举随版本缺类） |
| 刷取参数 | `auto_farm` | `farm_dungeon`（与角色/光锥线对齐）；**不设 `use_fast_ticket`**——行迹线仅券刷路线（手动刷出 op 边界），docstring 显式声明差异 |
| 券耗常量 | `_FARM_TICKET_PER = 3`（未实测先例值） | 回填 **1**（实测定案：花萼赤 = 开拓力 10 + 券 1/次，弹窗消耗行实读） |
| 连刷次数 | `farm_times_per_round` 接收校验但未接入（:85-87 自证待补） | 接入：共用「快速刷取弹窗」画面档与光锥线 `_set_farm_times` 同款（「+」设到目标 / -1 = 点「^」拉满） |
| 记账 | 配置值差值（`farm_times_per_round=-1` 时打负数） | 面板等级读数差值（升级前后各读一次面板等级） |
| 手动刷本 | 未声明 | docstring 契约：op 判停交还 agent——周本走 `ChallengeEchoOfWarByName`、花萼手动走 `FarmLightConeMaterialOp`（game-coach skill 已同步该口径） |

## 2. 节点卡

**① 入口校验（is_start_node）**
- 面板态双锚：`简略描述` 开关在场（面板态锚，探索实测 1741,158；树态无此锚）+ `读区-技能分类` 文本 == `target`（读区 area 落地时在「角色-行迹」档补建——面板顶部分类 TAB，阿哈样本「天赋」/「欢愉技」）。
- 命中 → ②；不命中 → `round_fail('不在目标技能面板')`（带截图）。**校验在任何消耗/点击之前**——agent 点错节点在此拦住，零消耗。

**② 升级循环（现版逻辑平移）**
- 按钮四态判定与现版一致（upgrade_trace.py 升级循环段）：白底「快速升级」可点 → 升级；「使用通用材料补全」→ fill_generic 授权自动确认（双形态弹窗，「材料合成」一并支持——现版已实现）；灰底「材料不足」→ farm_dungeon 授权走 ③ 券刷链，否则判停；蓝字「已达最大等级」→ MAX_LEVEL。
- 记账改实值：升级前后各读面板等级（等级读数 area 落地时补建），日志打实际差值；`farm_times_per_round=-1` 场景不再出现负数。
- 稳定等待 `_TRACE_SETTLE_SEC` 与现版一致（反馈形态实测后随实机批回填）。

**③ 券刷链（现版链路保留 + 连刷接入）**
- 面板「快速刷取」按钮 → 培养资源窗口 → 花萼行券按钮 → 共用「快速刷取弹窗」→ **连刷次数设置**（同光锥线 `_set_farm_times`：画面档共用，`farm_times_per_round=-1` = 点「^」拉满）→ 确认 → 结果框关闭 → 资源窗口关闭 → 回面板态。
- 回面板态校验 = 简略描述开关回归（券刷捷径可回面板态——探索实测定案）。
- 预算 `farm_rounds_max` 与消耗声明（开拓力 10 + 券 1/次，常量已回填）同现版。

**④ 收尾关面板（新，一切出口的必经）**
- 点面板外空白区（面板态点空白 = 关面板，探索实测定案；点击区进 `角色-行迹` 档，面板态树左移 413px 的事实决定空白区取右下安全域）→ until_not `简略描述` 开关（面板关锚）→ 回树态 → 按出口分支落原终态 status。
- 出口集合（全部先经 ④）：`MAX_LEVEL` / 升满当前上限 / `MATERIAL_CAPPED`（判停）/ `不在目标技能面板`（fail，零消耗场景无面板可关 → 直落，不经 ④——唯一例外，入口校验失败时画面本就在未知态，交调用方处置）。

## 3. mock 场景

1. 面板校验通过 → 升级至满级 → 关面板 → `MAX_LEVEL`（断言树态收尾：简略描述锚消失）。
2. 缺料 + fill_generic → 补全弹窗确认 → 升满当前上限 → 关面板。
3. 缺料 + farm_dungeon → 券刷链（连刷次数已设）→ 回面板 → 升级 → 关面板。
4. 缺料 + 两路全关 → 判停 `MATERIAL_CAPPED` → 仍关面板回树态（判停收尾幂等）。
5. 面板分类 ≠ target → `不在目标技能面板` fail，零点击零消耗。
6. `farm_times_per_round=-1` → 「^」拉满路径 + 记账正数（等级读数差）。
7. 入口校验失败场景的面板缺失帧 → fail 不误触收尾点击。

## 4. 关键取舍

- **target 改校验锚语义、删枚举**（备选：枚举扩充欢愉技等新分类）——面板读区是唯一真相源，固定枚举每个新命途版本都要补；校验等值判断天然防 typo（不符即显式失败），枚举防 typo 的价值被完全替代。
- **判停也关面板**（备选：判停停在面板态交 agent）——终点契约「树态」是 agent 下一步（读树态节点三态、点下一目标）的前置；判停停面板态 = agent 多一步关面板且两态契约破口。
- **不设 `use_fast_ticket`**（备选：三线参数完全对齐）——行迹线手动刷已划出 op 边界（负责人裁定），券刷是唯一 op 内路线；设一个恒真参数是接口噪声，docstring 声明差异。
- **现版升级循环/券刷链逻辑平移而非重写**——两段均已实机验证（upgrade_trace 现版 + 券刷共用画面档），重构只动契约两端与参数面；重写引入回归面，违背「实现者无需再设计」。

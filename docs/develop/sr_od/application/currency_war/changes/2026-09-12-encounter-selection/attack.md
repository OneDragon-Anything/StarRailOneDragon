## 二、指定复核点专项裁定

### 复核点①：判 (ii) 判别子出口的机制自洽

**裁定：机制自洽成立；落码完备性不足（三个连带件未闭合）。**

- **依据链逐环直调核实，成立**。容器 `enemy_difficulty` 非空值的唯一来源 = observe，四通道封闭逐一验证：①observe 拒 None（`cw_game_state.py:2269-2271`）→ 字段首值只能由观察写入产生；②写入半 live=False 走 `bs.carry`（`cw_observation.py:2565-2572`），carry 沿用容器现值并置 `source='carried'`（`cw_game_state.py:2291-2292`），对从未写过的字段早退不写（`:2287-2288`）→ carry 链源头必为历史 observe；③简报恒值只写 session 载体（`cw_screen_briefing.py:183-186`），relay 白名单（`cw_observation.py:2653-2671`）不含该字段，`write_prior` 全仓唯一调用 = hp（`cw_observation.py:2557`），`leave_screen` 调用集 = shop/encounter/supply 三 payload 域无该字段 → 简报值无任何容器入口。**结论：`source=='carried'` ∧ 值非空 ⟹ 值 = 容器自身历史观察写入，「单字段 carry 合法化」的毒化封闭成立。**
- **与 live 门原则相容**。live 门的目的 = 防简报恒值毒化与逻辑值污染，不是教条拒绝 carry；判 (ii) 定谳后「决策帧 D_enc 恒 carry 态」恰是读点语义本体（写入半逐帧 miss 翻源，`cw_observation.py:2168-2188` 读链 + 写入半 carry 链互证），出口按定谳结果切换判别子形态与门原则不冲突。
- **三个连带件未闭合**：①「命中率成员改『读点存在性』判定」无操作定义——「读点存在」指窗口 D_win 行存在、还是决策帧容器值存在、还是 journal 判别子记录存在，全文未写死；无论取哪种定义都与现有结构门成员（窗口无可用 D_win 行 → 暗装）或判别子 value 非空合取部分重合——见中-1。②carry 自证只证溯源不证时点：中间节点 OCR 连 miss 时 carry 延续更旧值，「(ii) = 前一普战写入值」的时点紧邻性无校验——见低-3。③回写走位漏 §9 命中率成员行与 W4 注入形态——见低-1。

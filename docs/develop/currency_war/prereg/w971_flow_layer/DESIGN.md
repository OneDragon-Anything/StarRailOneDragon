# W971 · CW 流程层重构设计(局状态正式化 / 开局序列 op 化 / 结算链收编)

- 日期:2026-09-02;状态:DRAFT(用户口述整理中,持续追加;已确认项见 §2)
- 依据:用户口述架构愿景(2026-09-02,逐段)+ W970(画面分层架构,FINAL)——本篇是 W970 的续篇:W970 治「商店链与决策接口」,本篇治「流程层编排与局状态」

## 1. 背景与动机(用户口述)

1. 从入口开始,入口前的等待按既有固定时长。
2. 到简报画面,应有**第一次数据观察,单独一个 op**;数据保存到**统一的内存状态**——该状态贯穿整个货币战争局,多个 op 观察会更新它,遥测记录要用,对账要用。
3. 简报之后直到 1-1 备战画面,是**固定流程,每个画面有独立的 op**。

现状病灶(亲读实证):

- **局状态不正式**:事实载体 = `StrategySession`(kernel/cw_state.py,贯穿整局、遥测/对账消费),但简报数据进场绕「ctx 信箱」——入口 op 存 `ctx.cw_briefing_affixes/cw_enemy_difficulty/cw_briefing_bosses`,battle_loop 新对局段再「取走」拷进 session(取走清空防跨局复用)。跨 op 通信走全局上下文散字段,无更新者白名单。
- **简报观察三个写入点**:①入口读存 ctx;②battle_loop 0a0b 位面简报分支(P2/P3)再读再存 ctx + 点「下一步」;③session.briefing_bosses 空时从位面详情兜底补采 + 独立对账函数。同一份数据三条路径,职责分散。
- **开局固定流程一半 op 化一半内联**:投资环境/投资策略/遭遇/补给/巨星/伙伴已有独立 handler op(且接策略函数,04_nodes §5 接线表);**位面过渡(点空白)内联分支 6、开局补给无专门处理、位面简报内联 0a0b**;整段序列靠主循环分支序 + 固定等待隐式编排,没有显式的开局序列。
- **结算链内联**(用户质疑「战斗结算那些选择没有自己的 op 吗」):结算屏读 hp 真值链/点「继续挑战」/outcome 记录/DD-006 页间暂存,全部内联在 battle_loop 分支 1f/2/3;自动开店判稳(场景①)以标志位跨分支传递——结算动作的完成承诺无主体。

## 2. 已确认决策(用户逐项拍板)

### 2.1 局状态 = 收编现役 StrategySession(2026-09-02 拍板)

- **不新立状态对象**:StrategySession 字段已全、消费面广(遥测/对账/sim),收编避免双源迁移风险。
- 收编内容:
  1. **消灭 ctx 信箱**:简报三件(词缀/难度/boss 序)改由观察 op 直接写 session,删除 ctx 散字段与「取走拷贝」段;
  2. **字段更新者白名单**:session 每个字段(或字段族)声明合法更新者(op/handler 名),新增写入点 = 违反架构;清单落本篇 §4(整理中);
  3. **遥测/对账统一读路径**:消费 session 的口径单一源(现散在 record_decision/对账函数内的取数逻辑收敛)。
- 边界:session 既有字段语义不动(只收编写路径,不改字段)。

### 2.2 简报观察收敛为单 op(2026-09-02 口述)

- **BriefingOp**(命名待定):简报画面(货币战争-简报,含 P1 开局简报与 P2/P3 位面简报 0a0b 同族)唯一入口:
  - 观察:词缀/敌人难度/三 boss 序(`cw_briefing_obs` 现有读法);
  - 写局状态:session.briefing_affixes / enemy_difficulty / briefing_bosses(替代 ctx 信箱与 0a0b 内联写);
  - 动作:点「下一步」;完成承诺 = DD-011(固定时长或判稳标志,#1 口述「锚出现后 ~1s 动画完结」);
  - 兜底补采(session 空时位面详情补采)并入本 op 重试形态,不再散落第二写入点;
  - 简报 vs 位面详情对账(reconcile_briefing_vs_plane_intel)保留,消费局状态。
- 遥测:exogenous briefing 事件随 op 迁移,语义不变。

### 2.3 开局序列独立于主循环,每画面独立 op(2026-09-02 口述)

**1-1 之前的整段固定流程拉出 battle_loop 主循环**,作为独立的开局编排单元——跑完(1-1 备战就绪)才交常态循环。battle_loop 瘦掉开局分支(位面简报 0a0b、位面过渡点空白、开局投资环境段),只保留本职:常态循环(备战决策 ↔ 战斗 ↔ 结算)+ 局中不定时 overlay 的按画面分发(遭遇/补给/巨星/伙伴/投资策略——节点类型决定出现时机,必须留 loop)。

```
开局编排(P1,进对局后一次性):
BriefingOp(简报观察+写局状态+点下一步;#1 锚后 ~1s)
  → PlaneTransitionOp(位面过渡,点空白;#2 提示出现即点)
  → InvestEnvOp(投资环境 3 选 1;现 handle_invest_env)
  → WaitOneOneOp(特殊:1-1 开局动画等待 ~10s)
  → 1-1 备战 → 交备战循环(PrepDirector)
```

- **顺序依据**(screen_flow_timing #1→#2→#3,#5/#29):简报点「下一步」→ 位面过渡(#2「点击空白处继续」提示出现 = 完结)→ 投资环境(#3 标题出现 1s 内三卡稳定)→ 进 1-1(**触发开局补给,动画长且无结束标志 → 用户裁定特殊等待 ~10s,值待校准**;1-1 **不自动开商店**)→ 1-1 备战。
- **WaitOneOneOp 形态**(用户给两选项,取独立 op):插在 InvestEnvOp 之后,固定时长等待(DD-011 形态①);不给备战循环加「现在是 1-1」的特殊状态参数。
- **投资环境仅开场一次**(screen_flow_timing #11:开场 1-1 前弹投资环境,1-3 后起局中弹的是投资策略,两画面不同 handler)——InvestEnvOp 只在开局编排;局中投资策略 = overlay handler(handle_invest_strategy)由 loop 按画面分发,不在本编排。出现规律(哪些节点后弹)不需精确建模:画面识别分发,出现即处理。

### 2.7 决策输入 = 统一读 StrategySession(黑板模式;2026-09-02 用户拍板)

- **决策接口统一读 session,取消「每画面组装 obs 子集」**:
  - `decide_prep_screen(session, config)` / `decide_shop_screen(session, config)`。
  - 观察 op 读画面 → 写 session;决策读 session 出动作;遥测/对账读 session——**session 是唯一数据总线**,无搬运、无双源。
- **为什么可行(与现役同向)**:现役 `decide_prep(state, session, config)` 已是「本轮快照 + 跨轮状态」双输入,且 state 字段自带可信位(`hp_readable/hp_trusted/gold_readable`,ADR-0491 None 化、hp 新鲜度门 last_hp_t)——「数据新鲜度/可信度」判定机制已在 session/state 体系内。黑板模式下决策统一读 session,**新鲜度位原样复用**,决策侧按位保守(现状行为不变)。
- **代价与对策**:
  - 决策输入依赖隐式化(签名不再列字段)→ §4 字段清单扩展为「字段 × 写者 × 读者」三列,决策实现处 docstring 声明消费字段族;
  - 「本轮观察 vs 历史遗留」区分 → 可信位/新鲜度门(现役机制,非新发明);
  - 单线程 op 顺序执行,无并发读写问题。
- **W970 接口签名变更注记**:W970 §4.1 的 `decide_prep_screen(obs_prep,…)`/`decide_shop_screen(obs_shop,…)` 签名与 §4.1.2「融合 obs 组装契约」由本条**取代**(§4.1.2 的字段来源表语义转化为「观察 op 写 session 的字段清单」,仍是迁移规格);W970 FINAL 文档加 amendment 注记指向本节。

### 2.9 顶层循环语义:纯分发器(2026-09-02 用户口述)

**决策输出一系列操作 op → 执行器只管按序执行 → 执行完交还循环 → 循环重新识别画面 → 调用下一个画面 op。**

```
loop:
  画面 = 识别(§2.2 判定序)
  op  = 分发(画面)      # 备战→备战op / 商店开→商店op / overlay→handler / 战斗→战斗分支
  op.execute()          # op 内部:决策(读 session 出动作序列)→ 按序执行 → 交回
```

- **无业务流的循环**:刷新、关商店、overlay 弹出、位面切换——全部由「交回循环 + 重识别」自然路由,循环本身不含任何「下一步是什么」的知识。
- **两阶段重判自动成立**:决策契约 RefreshShop 必为末位动作 → op 执行完交回 → 重识别「仍是商店开」→ 再调商店 op → 决策读新牌面(§2.8.1)出新动作。无需「流程层显式重调决策」编排(取代 W970 §4.3.2 的显式重判表述——语义等价,机制更简)。
- **关商店**:决策买完输出空序列(§4.1.4)→ 流程层触发 CloseShopOp → 关完交回 → 循环识别出备战 → 备战 op 接管。
- **overlay 延迟弹出(#24 族)**:op 交回后循环识别自然看到 → handler 接管;DeployMove 的触发计算式等待(§2.6.1)只是减少一次无效交回的优化,正确性不依赖它。
- 现役对照:battle_loop 分支序就是「识别→分发」的雏形,本节把它立为唯一循环语义并要求分支零业务流(结算读数等迁出为 op,§2.4)。

### 2.7.1 session 字段生命周期(黑板模式的失效管理;2026-09-02 用户口述)

session 字段按生命周期三分类,**离开产生它的画面时,画面态字段必须清理**(否则决策读到幽灵数据,如关店后残留上一波商店牌面):

| 类 | 语义 | 例 | 清理时机 |
|---|---|---|---|
| **持久知识** | 跨画面、跨轮有效(等级/位面衍生或一次性真值) | briefing 词缀/boss 序、**refresh_probs 每费用刷新概率**(等级函数,`read_refresh_probs` 商店开态识别,经济账/轮岗消费——**不清理**,用户口述确认)、节点台账、tracked 角色 | 局终/显式覆写 |

# CW 装备域 v4.7 换赛季适配 迭代设计（总纲）

## 0. 元信息

- 迭代目标：货币战争装备域跟进 v4.7 换赛季（2026-11-13 会话逐项裁定，域负责人裁定汇总于本篇 §2 各节标注）
- 状态：草案
- 文档清单：无详设（单文档方案，本篇即完整设计）

## 1. 问题与动机

- **现状症状**：装备注册表（`cw_equipment_data.py` EQUIPMENTS，158 件）停留在 S1 末期口径；v4.7 官方 config `equipment_list` 为 105 条（实证：`.debug/game_data/currency_war/plaza/config_v4.7.json`），名单大换血——进阶 36/特权 36/星徽 21/餐品改件 6/列车改件 4/宝钻 1/固有装备 1。注册表内嵌的旧数据源架构为三源分层（plaza 骨架 + 图鉴 OCR 校正 + equipment.md 兜底），自造九分类（简易/进阶/特权/星徽/白昼/命运/骇客/特殊/工具）与官方分类并存双轨。
- **根因归层**：①表示层——注册表分类体系与官方口径分叉（自造九分类系多源拼接期的产物，图鉴/手工源无官方分类字段只能人工归类；v4.7 config 单源后官方分类字段齐全，双轨失去存在理由）；②流程层——三源采集流程为补 API 数据缺口而生（旧 API 无效果全文/无结构化数值），v4.7 API 富化后缺口消失，流程可简化为单源直灌。
- **解决到哪**：装备域闭环——生成器、注册表、合成图谱（`data/cw_synthesis.py`）、穿戴规则数据（`data/cw_equipment_wear_rules_data.py`，§2.3.1）、模板库对齐、跨域影响申报与挂账。
- **明确不解决**（防外溢）：
  - 消费方按新分类的迁移（投资池引用/穿戴计划/识别消耗品判据等约 130 处 src + 248 处 test）——属投资域重建批与穿戴域，本迭代只完成装备域文件内闭环并登记跨域影响（§2.6）；
  - 阿哈升格链（4/5/7 费三档）与角色域裁定同构，归角色域会话；
  - wiki 装备词条建成后的补充采集（挂账探针，§2.6）。

## 2. 方案

### 2.1 数据源与采集通道：config 单源，实机图鉴 OCR 免除

- **裁定**（2026-11-13 用户）：装备数据采集 = plaza config `equipment_list` 单一源；旧「游戏内图鉴 OCR 实机采集」免除。
- **依据**（调研报告 equip_api_research，2026-11-13，结论内联自足）：config 105/105 全覆盖，每条含效果全文（desc 富文本）、合成配方链（compose_list 含子件全文）、官方图标 URL、结构化基础属性（properties 104/105 非空，{属性名, 数值} 对）；三个社区 wiki（米游社频道 242 空壳/211 旧词条 73 同名且 36 条数值过期、国际服 CW 装备菜单未建、BWIKI 覆盖 73/105 且为 S1 快照）均不能作 v4.7 数值源——config 是唯一当版本官方数据。
- **流程影响**：`harvest_equip_codex.py`（图鉴半自动采集 op）→ `extract_equip_data.py`（OCR 整理）→ 数值双向校正整条链路退役（文件保留但生成器不再消费；退役申报见 §2.6）。

### 2.2 Equipment 字段定稿与分类（沿用官方）

- **裁定**（2026-11-13 用户）：分类与字段沿用官方，不自造。
- 字段定稿（9→7 字段）：

| 字段 | API 来源 | 说明 |
|---|---|---|
| `name` | name | 规范名（• 统一 ·，机械规则与角色域同款） |
| `category` | **category_name 原样直落** | 官方分类名：进阶装备/特权装备/星徽/餐品改件/列车改件/宝钻/固有装备；另含派生值「简易装备」（见下） |
| `effect` | desc | 去富文本标签保纯文本；`\n` 转义字面保留（生成产物字符串字面量禁止真换行） |
| `stacking` | 无 API 字段 | 效果文本推断（「可叠加」/「叠加N层」）+ 实机抽检（挂账 §2.6） |
| `source` | **id** | plaza 稳定数字 id 作溯源主键（旧语义「米游社 content_id」废止；icon URL 带资源 hash 会变，不可作键） |
| `recipes` | compose_list | 机械解析，多路线全收（子件名同样 •→· 归一） |
| `props` | properties | 结构化基础属性直取 |

- 删除字段：`official_category`（与 category 合一，双字段冗余废止）。
- **「简易装备」派生层**（2026-11-13 用户裁定命名）：官方 API 无简易件条目（合成材料层），从全部 105 条的 compose_list 子件展开去重派生注册表条目（category 落「简易装备」，条目自带子件 id 与合成说明 desc）。预期派生 11 件（以生成输出为准，验收数字对照）。
- 特权条目独立登记（36 条「XX·特权」自带数值翻倍 properties，与普通版名不同不撞键）；模板段维持特权去重（同 art，`gen_plaza_chars.py` 的 `gen_equip_templates` 既有逻辑不变）。
- API 字段 `ability_name`（105 全空废弃）、`priority`（**类别级排序码**，与 category 一一对应且同类内恒定，条目级无信息量）、`category` 数字码不登记。

### 2.3 生成器改造：config 单源直灌 + 掉出 diff

- `gen_equip_registry.py` 重写：删三源中图鉴（codex 合并/数值校正/配方交叉验证）与 md 兜底两源，保留 plaza 解析函数族（`_stacking`/`_props`/`_recipes`）。
- main 流程：读缓存最新 config（glob `config_v*.json` 后**按解析出的版本号数字比较取最大**，禁字符串词序比较——`config_v4.10` 词序小于 `config_v4.7` 的陷阱；落点 `.debug/game_data/currency_war/plaza`）→ collect（官方分类直落 + 简易装备派生）→ **先对拍旧基准再覆盖写**（diff：旧注册表 158 名单 vs 新名单，stdout 掉出/新增清单，供模板清理与消费方迁移参考；旧基准经 importlib 动态加载，加载前须注册 `sys.modules`（dataclass 装饰器回查 `cls.__module__` 的既有坑，test_replay_render 同款先例））。
- 生成的模块模板更新：模块 docstring（单源声明 + 版本号占位）、Equipment 注释、`_eq` 签名（official 参数删除）。
- **EQUIP_TOOL_CATEGORY / CONSUMABLE_EQUIP_CATEGORIES 两常量**：v4.7 官方分类无「工具」「特殊」类（旧工具 7 件全不在 config；宝钻 1 件单列且可穿戴非消耗品），判据失效。两常量**暂保留旧值 + docstring 失效申报**（[v4.7 待裁]标注）——消费方实测 = 5 文件 16 处（cw_equip_env / cw_equip_wear_plan / cw_gain_chain / cw_investments / mandate.py），本迭代不拆常量（拆即断裂消费文件，超出装备域文件面），迁移归跨域批（§2.6）。

### 2.3.1 穿戴规则数据（cw_equipment_wear_rules_data.py）v4.7 形态 = 门清空、前置保留

- **裁定依据（逐项实证 2026-11-13）**：该文件是注册表紧耦合 data 层（import EQUIPMENTS + `check_equipment_wear_rule_coverage()` 互检），四个构成部分的 v4.7 状态两分：
  - **门侧清空**（对象掉出，实证 = 逐名对 config 105 名单）：件级门 `ITEM_WEAR_GATES` 10 件全部为银狼专属装备（银狼掉出新赛季角色名单，10/10 不在 config）；类别门 `CATEGORY_WEAR_GATES` 键「骇客」不在官方 7 类（消费面查旧类名恒空集，静默失效）；白名单 `YINLANG_WEAR_ALLOWLIST` = {银狼, 银狼LV.999} 两角色均掉出。
  - **前置侧保留**（对象在库，实证 = id 35030404/35040404）：`EQUIP_WEAR_PREREQUISITES` 锚定的「随便骰子」（进阶装备）与「随便骰子·特权」（特权装备）仍在 config 105 名单内，effect 均含「需要空装备栏」关键词——前置防线（「有件在身即拒」）继续有效，互检三向（正向漏建模/措辞漂移/条目名参照）对骰子继续工作。
- **v4.7 形态**：门侧（件级门/类别门/白名单常量）**清空**；前置表**原样保留**；互检函数骨架**完整保留**（门侧孤儿向随表清空自然归零；正向向继续为新件漏建模兜底——新注册表 effect 命中「需要空装备栏」且无条目即显警）。文件头注释申报换赛季清空事实与重建条件。
- **行为影响申报（分层）**：门清空 → 银狼专属装备防误拖保护失效，影响趋零（被保护对象全部掉出，不存在误拖场景）；前置表保留 → 骰子防线无变化。第二消费面：事件卡文装备识别锚（`cw_events.py` `_PLANNER_EQUIP_ANCHORS`）同以门键集为源，自动退化空名单，卡文装备识别落 unknown 响亮兜底，随门重建自动恢复。互检预期返回空（正向有条目不警、措辞核对骰子 effect 仍含关键词不警、孤儿向门空不警）。门重建 = 实机/实战数据工程，挂账（§2.6）。

### 2.4 合成图谱（data/cw_synthesis.py）判据随分类

- `cw_synthesis.py` 进阶配方过滤判据 `eq.category == '进阶'` → `'进阶装备'`（官方类名）；派生依据 = 注册表 category 语义迁移（§2.2）。
- 图谱派生机制本身不变（import 期从注册表 recipes 派生，注册表改自动传导）。

### 2.5 模板库对齐（配方链反查依据）

- **依据**：105 条 compose_list 的子件名集合 = 新赛季实际会出现的简易件官方清单（零猜测）。
- `assets/template/currency_war/equip_plaza/`（混合识别库 185 个）对齐：配方链反查集合 ∪ plaza 69 art 为保留集；集合外的旧赛季遗留模板打印清单**人工裁**（不自动删——简易基础件跨赛季沿用可能性，与角色域「模板暂留」同款保守口径）。
- `assets/template/currency_war/equip_legacy/`（手工底库 156 个）不动（来源库，清理只作用于混合库）。
- plaza 图 69 个已更新（字节比对幂等，29 个图变重烘已完成，本迭代不重复执行）。

### 2.7 边界重申

消费方迁移、投资域重建、穿戴域改造不在本迭代文件面内；本迭代产物（新注册表/掉出清单）是它们的输入。

## B. 本轮新发现(编号续接第一轮,自 F9 起)

### F9 [major] | design.md §0/§1.1/§2.1 | 效果批采样空间契约 = 「剩余池对应费用档桶」,设计的唯一档感知出口 drawable_names 额外耦合「≥9 清空」发牌过滤——契约空间与交付空间不一致,取哪边设计未决

- **发现**:§0/§1.1 申报本批目标 = 为效果批随机授予采样链提供 kernel 侧采样空间,并引定谳「随机获取角色效果的采样空间 = **剩余池对应费用档桶**」(口述·权威 2026-09-20;银狼升星记账批 §2.7:239-240 前置契约同措辞:「采样空间 = 对应档桶**剩余池**」)。但 v2 的档感知改造只落在 `drawable_names` 一处,该函数同时携带「held ≥9 不再进店」这一**发牌(商店)专用过滤**(U11 定稿口径原文 = 「后续**发牌**过滤」,economy.md §1 同限「清空该牌在**商店**的库存」)。「档桶剩余池」与「drawable_names」两个集合在 1/2 费、held ∈ [9,26] 且剩余 > 0 时不同(27 副本卡持 9 张以上仍剩余)。效果批(如人力重组按档随机授予 2★)接手时只有两条路,设计一条没堵、一条没认:①直接用 `drawable_names` = 继承商店专用 ≥9 过滤,把「不再进店」偷换成「不再可授予」,无任何定谳支撑;②用 `remaining_pool` + 自行按 `effective_cost` 分桶 = 档过滤第二实现,恰好复活本批 §1.1 要消灭的「双源必漂移」。§2.1 把档过滤封在 drawable_names 内部、§1.4 不解决表未列此问;§1.2「档感知天然单点 = 一处过滤条件」只在本批内部成立,对已申报的下批消费方不成立。
- **证据**:design.md:5-7(§0 目标)、:18-19(§1.1 定谳)、:40-41(§1.2 桶现分)、:97-99(§2.1 唯一改造点);`sim/cw_sim_pool.py:100-109`(≥9 与档过滤同函数);银狼升星记账批 design.md:239-240(契约措辞「剩余池」)、:229-231(消费面裁决表);changes/2026-09-15-sim-redesign/design.md:371(≥9 = 发牌过滤建模);`docs/game/currency_war/research/economy.md:10`(≥9 = 商店库存清空)。
- **修正方向**:把档过滤从 drawable_names 提为独立单点(纯谓词/小函数),`drawable_names`(商店语义,含 ≥9)与将来授予采样(契约语义 = 档桶剩余池,不含商店过滤)各自组合;或在 §1.4/§2.1 显式申报「授予采样同受 ≥9」并给出定谳记录处(现库无此记录,需用户裁决)。

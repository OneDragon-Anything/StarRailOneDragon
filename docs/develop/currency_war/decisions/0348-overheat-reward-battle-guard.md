# ADR-0348:扑满守卫——「经济过热」类环境 reward 节点按「奖励型战斗」处理(轻投入凑羁绊,禁深花保血)

- 状态:accepted(2026-08-26,W119;↺ 修正 2026-08-26——初版「按战斗节点处理→深花保血」方向推翻,见下方「↺ 修正」节)
- 判据:**用户口述定谒 [16](2026-08-26,最高权威)**——扑满关**不掉血**(扑满关自身机制,与 0hp 保底无因果,两条独立机制),真损失是**打不过就没奖励**(损失很大);正确处理=**凑羁绊刷伤害拿奖励,明确不是深花保血**——boss/遭遇窗的深花授权(boss_floor 下探/保血 EV 加权)对扑满**全部不适用**。附:math_proofs P8 参数化证明(s<ΔP×R≈0.277R,深花远超正期望界);W113 §8-5(E1——其「奖励节点变战斗」命名是初版走偏方向的来源:**识别**按战斗≠**授权**按战斗)
- 影响:decision_v2 新增 ev.REWARD_BATTLE_ENVS/reward_node_is_battle;scoring refresh 轮界豁免×**P8 上限**(registry.piggy_refresh_round_cap=1/节点);遥测 piggy_reward 字段(decisions/sim 账本/rounds 视图);单帧锁(test_cw_w119 ⑥ 负向断言);**地板不降**(discipline._hard_node 不辖扑满)

## 背景

`cw_invest_data.PLAZA_PORTALS` id 105「经济过热」/119「经济严重过热」:
「本局的全部奖励节点替换为(超级)次元扑满主题」——扑满要打且跑得快
(掉更多战利品)。决策层此前零消费:reward 节点被无条件当作零战斗
(「必胜、无血可扣」),持过热局时该攒的伤害没攒、该 D 的轮没 D。

W119 初版把扑满节点接进 `_hard_node`(连胜 EV 地板/保血通道 hard
判定)=「深花保血」语义;**口述定谒后收窄**——扑满不掉血,深花保血
没有对象;要保的是奖励(伤害阵容)。

## 决策

- 环境名单 `REWARD_BATTLE_ENVS` 从 `cw_invest_data.PLAZA_PORTALS`
  按**效果文本派生**(含「奖励节点替换」;单一源,版本重跑自动跟上;
  锁测试断言 == {'经济过热','经济严重过热'})。
- `reward_node_is_battle(state)`:`node_type=='reward' ∧ active_env ∈
  名单` → 扑满节点。**按「奖励型战斗」处理(W122 F-01 落法)**:
  1. **节点识别按战斗**(解除「无战斗奖励节点」的禁令):refresh 轮界
     门(`refresh_max_round`,r>6 恒负分)对扑满节点豁免——为凑羁绊
     伤害 D 牌在后期扑满轮合法;金保底门(`refresh_min_gold`)保留
     (防抽干与节点类型无关);买牌通道本就开放(economy 模式)。
     **不得接深花授权**——boss/遭遇窗的下探授权对扑满全部不适用。
  2. **消费授权=常态 EV 通道 + P8 上限**:单节点凑羁绊支出
     s≤0.277R(R=扑满奖励期望,采集前保守取节点基础收入 6-9 金)→
     **s≤2 金**——豁免限 `piggy_refresh_round_cap`(=1)次/节点,
     超出按无证拒(回常规门恒负分;轮计数 `session.v2_round_refreshes`,
     arbiter 刷新采纳处递增、轮键重置)。
  3. **地板不降**(discipline 侧):扑满节点**不进** `_hard_node`
     ——连胜 EV 地板(降 5)与掉血报警保血通道的 hard 判定都不辖。
- **掉血三臂(BloodAlarmTracker._BATTLE_NODES)不辖**——三臂是用户
  定调的不可回归旁路,语义逐位不动(扑满不掉血,本就无入臂依据)。
- **0hp 保底 1hp 是独立的全局机制真值**(用户口述,2026-08-26;
  与扑满不掉血**无因果关系**——两条独立机制,f5255357 纠偏),不做
  建模、不当未知项。

### 挂账项(数据批/W115 E1 其余跟进)

1. 投资效果表(cw_investments/cw_effect_ledger)加「reward 节点变
   战斗(奖励型,不掉血)」机制突变项;
2. DP 台账指纹纳入该突变重解;
3. 节点识别扑满模板档(cw_node_reader 自陈未建,采集 hook 已有)——
   留实机(模板建档走画面建档流程,非离线可做);
4. **P8 上限的重标**(↺ 修正已接首版):现值
   `piggy_refresh_round_cap=1`(s≤2 金,R 采前保守 6-9 金)——待采
   扑满奖励 R 真值后按等比重标(或按 P(达标|羁绊档)真实伤害阈值
   阶梯重估;P3 是胜负口径代理,扑满是伤害阈值口径,未核);
5. **P8 V 折算与 2 金上限的消费点接线排③**(↺ 修正新增):完整
   P8 账(V=奖励期望差×P(达标)折算进买/刷候选的 EV)与上限的
   **逐候选**消费接线,与 V_D 批口径(W120 检验点 1)同批做——
   ②a 的轮界豁免×次数上限是保守近似,不是 P8 的终形;
6. W120 P8 数据缺口三项:扑满奖励 R 具体值 / 伤害门槛真实阶梯 /
   凑羁绊成本 s 分布(自然搭便车 vs 破档买)。

default 栈的 `_is_reward` 类守卫(cw_evaluate.py:215 族)**冻结不动**
(回退保险+基线臂),两栈同病的 default 侧修复随 default 解冻批次。

## Considered Options

- **按战斗节点处理(进 `_hard_node`,初版,↺ 已推翻)**:否决依据=
  口述 [16](扑满不掉血,深花保血无对象;真损失=打不过没奖励)+
  math_proofs P8(s<0.277R≈2金,深花远超正期望界);硬节点分类服务
  「深花保血/保连胜」,W113 §8-5 的「奖励节点变战斗」命名只适用
  **识别**面,授权面走奖励账。
- **手写环境名常量**:否决——cw_invest_data 是生成文件(勿手编),
  名单派生自效果文本随版本重跑传导;
- **奖励节点进 BloodAlarmTracker._BATTLE_NODES**:否决——旁路铁律,
  且扑满不掉血本就无入臂依据(定谒后此选项双重不成立);
- **效果表突变项同批落**:否决——台账突变影响 DP 世界模型,与 DP
  姿态标定(②b)耦合,归后续批一起裁。

## Consequences

- 行为面:持过热局的 reward 节点上,r>6 的首刷不再恒负分(为凑伤害
  D 牌开放,P8 上限 1 次/节点;金保底仍辖);地板/模式/报警一切照旧
  (禁深花)。**↺ 修正后的实机锚点**:持「经济过热」局进 reward 节点
  伤害不足轮应见**轻投入**刷新/买牌(≤2 金/节点),**无深花/降地板
  动作**;节点模板建档后(node_type 读出非 reward)本守卫自然退化为
  兜底。
- 刷新轮界豁免的刷新 EV 仍是常量口径(refresh_ev=2.5,ADR-0293 标定
  未含扑满语境)——若 ②b 观测到扑满轮过度刷新,标定域=扑满语境的
  refresh_ev,不回退豁免。

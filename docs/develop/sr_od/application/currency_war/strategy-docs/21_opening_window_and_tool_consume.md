## 2. 件一:opening 窗口收窄策略语义(流程:36 残余)

### 2.1 现行语义与缺口定位

现行(18 号稿 §2.1 判据表 + §6 as-built):opening hold 活跃(r≤2 ∧ 节点非战斗类)→ 非 key 件扣留;战斗类节点释放;已定型扣留、生锈/输出侧词缀豁免各行照旧。

**缺口**:「r≤2 非战斗节点 → 扣留」是无条件的——只要在 opening 窗口内且下一节点非战斗,自由件一律囤。但 r≤2 的非战斗节点(奖励/补给/商店类)之后**必然跟着战斗节点**,而装备从判定到落穿只发生在备战帧;等到战斗类节点那个备战帧才释放,遇到发射序拥挤或闩跳过(`equip_latch_skip_m7` 十五~十八局段每局 2–8 次)就会空一拍。195720 的 r1–r4 病灶正是「非战斗节点连扣四轮、战斗帧裸奔」的实证。缺的是**「扣留的资格判据」**——现行语义回答「什么时候不释放」,没回答「什么件在什么帧根本没有资格被扣留」。

### 2.2 成本模型(数学先行,【推】零自由参数;辖域 = opening 期)

> **辖域声明(v2,B2)**:本节论证只辖 **opening 期帧(P1 ∧ r≤2)**——O2 也只在该行帧域生效(§2.3 叠加关系);r>2 的 committed 扣留帧语义 = 18 号稿 row2 原样,本节论证对其零覆盖、零推翻。全域开 O2 的扩展挂账 §6-7(P2 域合成风险另证)。

设 opening 期备战帧 f,owned 中某自由件 e,后随节点 n(f 之后第一个节点)。

**穿戴侧收益(单调 ≥0)**:在 opening 期帧域内,自由件经定义**结构性不含合成减向风险**——P1 阶段 RESERVED_COMPONENTS 全量保留 8 基础件(`cw_synthesis.py:78-82`),故 opening 帧上的自由件只剩进阶系非 key 件,而穿着即合成的触发对只存在于简易×简易(机制篇 §1.1「28/28 全为简易对」),进阶件不参与任何配方对 ⇒ 「穿进阶件」不存在被残留件带偏的不可逆合成。战力提升对战斗败北罚是单调减向——boss/遭遇败北罚 P ∝ 敌方剩余血量(user_playstyle [27],g_20260831_082322 复盘「最大化当场战力直接折算省血」同源)。故:

```
wear(e, f) 的收益 ≈ ΔP(f→n) ≥ 0,严格 > 0 当且仅当 e 的战力贡献
改变了节点胜负或未达标差额;任何参数下不劣。
```

**持有侧收益(逐项消解为 0,均在 opening 辖域内)**:

1. **组件保留价值**:P1 内 8 基础件全被 RESERVED_COMPONENTS 排除(`cw_synthesis.py:78-82`)⇒ opening 帧自由件(进阶系非 key)对「定阵容前不浪费合成」([29])的承诺为空;唯一件(标记「(唯一装备)」)另由保留域④扣留(§2.3),不入本论证;
2. **目标对位价值**(「攒给对的人」):穿戴是可逆暂借——卖角色装备全额回区(机制篇 §1「卖出角色=装备全量回装备区」,[24] 装备转移是常态),错穿成本 ≈ 0;「攒给成型核心」只在核心**已定时**才有意义,而已定时语义由 18 号稿「已定型扣留」行承载(key 命中件随时穿)——opening 期(未定型)的对位赌注没有承重结构;
3. **计件封顶内的滞留罚**:库藏生锈类词缀按 owned 滞留计罚,封顶内单调(18 号稿 row4 论证已立),自由件滞留同样暴露在承伤侧词缀(如「额外打击」按空装备栏计罚)下——滞留不比穿戴安全。

**支配性结论【推】(辖域 = opening 期帧)**:opening 期帧上的自由件穿上,弱占优于继续扣留;严格占优在后随节点为战斗类时成立。该论证不含任何待标定常数——**判据可以不引入新数字,这是它优先于任何「r≥k 才穿」阈值门的理由**(strategy-work §1:存在支配性论证时必须用论证消掉参数)。**该结论不对 r>2 帧与 P2 帧作任何主张**(v2,B2:旧稿「任意备战帧」措辞过述,作废)。

### 2.3 释放判据门(收窄设计;两层判据叠加关系 + 求值序,v2 重写)

**收窄语义**:本篇只改 18 号稿判据表 **row1(opening hold)行**的处置——从「扣留(囤)」改为「按下列三门评估,全不中才维持扣留」;**row2(已定型扣留)行零改动**,其语义原文照旧:**key 命中件随时穿;非 key 件扣留**(r70;as-built `cw_op_equip_all.py` 扣留帧只穿 key_equips 命中件同向)。两层判据的**叠加关系**(v2,B1 补定义):

```
帧域切分:row1(opening hold)辖 P1 ∧ r≤2 帧;row2(committed hold)辖
  已定型帧(判定式原样,含 P1 配对线非空支,可与其他帧域交叠)。
row1 内:key 命中件不受 hold(与 row2 同向,O1/O2 释放本就含 key 命中
  件);非 key 件按三门评估。
两行共现帧(opening ∧ 已定型):按行序评估,row1 三门先评估——任一门
  释放则释放(逐件);三门全不中 → 落入 row2 评估,key 命中穿/非 key 扣。
  即:释放门是「逐件」判定,不是帧级开关;committed 语义不因 opening
  收窄被绕开(非 key 件在三门全不中的 opening 帧仍会被 row2 扣住)。
```

### 2.4 与经济竞争的让位关系

1. **金面零竞争【注】**:装备域与卡池 disjoint、穿戴动作零金币(P42 ⑥,18 号稿 §2.2 已立)——穿不花金、不破息,与必花域/息线门无同一金面的竞争。**声明:opening 期任何经济状态(攒息/停手/必花域)都不构成扣留自由件的理由**;20 号稿停付线让位裁决辖金出口,装备动作不在其辖域,两边不互相借用语义。
2. **发射序不新增位次**:释放仍走 M7 既有发射位(18 号稿「释放动作的次序」),禁为 O1/O2 开第二装备发射位(G1 发射位准入常驻锁,流程:197;发射位增殖 = 卡死事故同构风险,三卡死架构反思 ARCH_REFLECTION_3STALLS.md)。与 StartBattle 的相对位次维持现状(M7 先于出战)。**消费位表达力声明(v2,B1 伴生)**:判定从「帧级布尔 hold」变为「逐件判定」(§2.3 释放门逐件评估)——现行消费位 `hold=True/False` 布尔无法表达「自由件穿+key 扣留」同帧混合态,落码批消费位须改件级输出(影响面 §5),这属接口面改造,判据语义仍由本篇单一承载。
3. **判据混接禁令**(照 18 号稿 §2.2 边界表):O1/O2 禁接入买入判据,买入域囤积臂(M2b/囤腿)禁接入释放判据——两域不同帧不同金面。
4. **备战帧动作预算让位声明**:同一备战帧内,装备释放与买/刷/升级并发出,零金竞争;唯一共享资源是执行时长——「不干等」纪律下不构成策略让位点,如实登记为执行面观测项(非判据)。

### 2.5 不确定声明与辖域出辖

### 3.3 与经济循环(必花域/息线)的接口

1. **工具动作不入必花域出口分层(20 号稿 L1–L3 均为金出口)**【注】:工具动作零金币(门 B 第一条),不产生也不消费滞留金——必花域帧的分层出口序里没有工具动作的位置,禁把「用工具」列为 L4/补充出口(分层封闭性,20 号稿 §3.1 结构)。

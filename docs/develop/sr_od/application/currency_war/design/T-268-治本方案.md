## 2. 修复设计(三决策点,同层同批)

### 决策点 1(核心,v3 重设计): 遮蔽域「诚实 UNKNOWN」主线 + 计数器改判辅助

**位置**: `_deploy_deterministic` 三消费位(L1359/L1400/L1483)共用一个私有 verdict helper(`_wait_slot_occupied` 原语本体不动,保持单一职责)。

**判定序**(替换现状「判负 → 判无效+回收槽」单分支):

1. `_wait_slot_occupied(dst, 2.0)` 为真 → **已落地**(placed+=1,现状不变);
2. 判负 → fresh 帧**遮蔽探测**(registry decision 集锚 presence;语义声明见 F-6②)——未命中 → 维持现状「判无效拖拽」(1-1 防线原样,零放宽);
3. **命中遮蔽 → 主线:诚实 UNKNOWN**(驱动病灶的预期形态):
   - 基准可用性检查(F-2):入口 paddle 直读 `_paddle_x`(L1061-1066 既有,同函数作用域)为 None(双帧失读)→ 无可信同源基线 → 直接 UNKNOWN;
   - fresh `read_deployed_count` 为 None(paddle 读区被覆盖——**partner 型遮蔽的预期几何**,F-1)→ UNKNOWN;
   - UNKNOWN ⇒ 不回收槽位、不计数,**立即终止本轮拖拽循环(含 P24 段,剩余单位留 bench)**,op 以新具名 fail 状态上报(名=`STATUS_LANDING_VERDICT_UNKNOWN`),交框架失败链——下一轮 0a overlay 分支接管(CwScreenPartner 处置)→ 再下轮重派发(去重 → NOOP 收敛)。**与现状轮次代价相当,消灭的是假失败遥测、槽位回收污染面与盲拖风险**。
4. **辅助:计数器改判(辖非覆盖型遮蔽)**:遮蔽在场 ∧ 基线可读 ∧ fresh 可读(paddle 读区未被覆盖的遮蔽形态——目前**实机未观测到**,如实申报)→ `ΔC = fresh − (_paddle_x + placed)`:
   - `ΔC ≥ 1` → **改判已落地**(placed+=1,分键「遮蔽-计数器改判」;槽位不回收,`_deployed_cids`/阵营档照常累加);
   - `ΔC = 0` → 判未落地(同源基线下「计数器确认」成立,F-2 修后);
   - `ΔC < 0` → 判未落地 + 分歧留证(obs_conflict 同款分键;可达域外形态,防御性分支)。

**双形态预期(F-1 要求的明示)**:partner 覆盖型(=两例驱动病灶)预期**恒走 UNKNOWN**;计数器改判路径辖非覆盖型遮蔽,属未观测防线,其存在理由=命题完备性+注册表内其它 overlay 的几何未逐屏测定。若复核认为未观测分支不值得实施成本,可裁剪为纯 UNKNOWN 方案(裁剪不损修复目标)——**呈复核裁**。

**ADR-0601 §3-D2 合规论证(方案审 §2-4 指认须显式,实施批随代码注释落)**:遮蔽探测/哨兵读「批内已部分执行后的动态状态」、行为=截断剩余 ⇒ 执行细节(非闸);UNKNOWN 非跨轮失败记忆(§5 禁令不触);收敛责任=既有守卫指纹制(prep_no_progress_state_fingerprint,状态指纹制非状态字符串制,UNKNOWN 轮正常计数,恒指纹 3 环停机兜底)。

### 决策点 2(同 helper 第二消费位): 拖拽循环内 overlay 哨(F-6 位次钉死)

**哨位=每槽迭代体首步(L1304 fresh 复查之前)**:探测命中 decision overlay → 直接走 UNKNOWN 终止路径,不再发起本槽及后续 drag。位次理由:置于 fresh 复查之后时,全覆盖型遮蔽源下像素复查先行,有误跳过面(partner 型备战栏在面板外故风险低,但语义上哨兵应在一切像素读之前)。成本:每槽 9 锚探测(v2「与入口检查同价」表述错误——入口现 3 锚,已更正);模板匹配毫秒级,相对每槽 2s 验证窗可忽略。

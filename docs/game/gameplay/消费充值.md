# 消费充值(游戏内真实货币操作路由)

> 定位:agent 指导游戏内消费的**操作路由**知识——怎么走到付款、bot 在哪止步。
> 「该不该买」的决策归 `sr-od-game-coach`(养成投入知识),本文不重复。
> 画面细节(识别锚点/子态/交互事实)见 [screens/store.md](../screens/store.md)。
> 已建:小月卡(列车补给凭证);规划中:大月卡(无名勋礼购买)、跃迁(抽卡)。

## 1. 消耗红线(所有消费共用)

- **bot 永不代付**:真实货币支付的终点 = 摆好付款码,扫码由用户完成。
- 打开付款码 = **发起购买**,调用方(agent)必须先向用户确认购买意愿才能走到这一步;
  浏览商品页(读规则/看价格)零消耗,无此限制。
- 支付确认类控件(「继续支付」/二维码本身)bot 不触碰;唯一的例外是
  「确认放弃本次支付?」(收尾清理用)。

## 2. 小月卡(列车补给凭证)充值

### 2.1. 机制(游戏内规则说明实测)

- ¥30/张:立即获得 **300 古老梦华**,列车补给凭证生效时间延长 30 日。
- 生效期间**每日登录**可领 **90 星琼**(每日凌晨 4 点重置;未登录未领取不返还,
  30 日最多 2700 星琼)。
- 生效时间 **<179 天**才可继续购买(可叠加);**≥179 天无法购买**。
- 每日领取入口 = 登录游戏时的领取弹窗(独立画面「列车补给」,「点击领取今日补给」,
  需连点两次)。

### 2.2. 操作路由

| 步骤 | 用什么 |
|---|---|
| 导航到凭证详情页 | op `sr_od.application.cultivation.account.operations.buy_express_supply.BuyExpressSupplyPassOp(open_qr=False)` —— 从任意画面一键到位(内部:手机菜单 → 商店 → 左侧栏凭证页),成功状态 `ON_PAGE`,零消耗;分步替代:MCP `goto_screen(target_screen_name='商店')` 后 MCP `click_game` 左侧栏(区域见 store.md 建档) |
| 读当前状态 | MCP `analyze_screen` —— 详情页可读 商品名/「购买¥30.00」价格/「购买即可获得 300」「30日内每日赠送 90」;生效天数本页不显示(生效态页面形态待条件,见 2.4) |
| 确认购买意愿 | 与用户确认(消耗门);顺带确认支付渠道偏好(支付宝/微信) |
| 打开付款码 | op `BuyExpressSupplyPassOp(open_qr=True, pay_channel='alipay'或'wechat')` —— 自动重新导航(幂等,已在详情页直接续跑)→ 点购买 → 扫码弹窗 → 按渠道就位,成功状态 `QR_OPENED` |
| 交还用户 | 告知「扫码弹窗已就绪(渠道 X,¥30.00),请扫码完成支付」;bot 止步 |

- op 经 MCP `run_operation(op_id='sr_od.application.cultivation.account.operations.buy_express_supply.BuyExpressSupplyPassOp', args={'open_qr': true, 'pay_channel': 'wechat'})` 调用。
- 收尾清理(用户放弃支付/付完后撤摊):点扫码弹窗右上 X → 弹「确认放弃本次支付?」→
  点「确认放弃」,两层全关回详情页(MCP `click_game`,坐标见 store.md 建档
  「按钮-关闭扫码」「按钮-确认放弃」)。

### 2.3. op 状态与失败

- `ON_PAGE` = 已到详情页(open_qr=False);
- `QR_OPENED` = 扫码弹窗已打开且渠道就绪(open_qr=True);
- 失败:商店内找不到凭证入口(左侧栏随版本轮换,需重验建档)/购买按钮缺失
  (**月卡生效 ≥179 天时游戏禁购**,或页面异常)/扫码弹窗渠道按钮均未命中。

### 2.4. 待条件(有生效月卡时补)

- 生效中的详情页形态(生效天数显示位置/购买按钮是否变体);
- 生效 ≥179 天时的禁购形态;
- 每日领取弹窗画面「列车补给」的新版形态(存量建档录于旧版 UI,待复核)。

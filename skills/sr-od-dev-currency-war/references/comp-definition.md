# 阵容定义方法论(Comp schema 设计:字段准入与分层判据)

> 单一源入口 = SKILL.md 分诊表「阵容定义」行。读者 = 智能体;适用于:给
> COMP_LIBRARY 新增/修订字段、评审字段提案、把阵容知识落库为结构化定义。
> 姊妹篇分工:知识怎么从攻略提炼(证据三层)→ `compo-knowledge.md`;
> **提炼出的结论怎么落成结构化字段(字段该不该有、什么语义、什么不进)= 本文档**。

## 第一原则:Comp = 目标态快照,不含时间过程

**结论(2026-11-04 用户已定案):阵容定义不抄攻略的位面 1/2/3(前/中/后期)
三阶段——直接按终局形态定义。**

攻略侧的阶段分段(plaza Early/Middle/Final 聚类;各篇「成型路径」节的
「位面 1 开 X / 位面 2 追 Y / 位面 3 完全体」叙事)是**人读知识**,归
`final_comps/` 各篇;不进 COMP_LIBRARY 结构化字段。

时间维度在本系统的架构归属(结构化字段为什么不需要它):

| 机制 | 层 | 给什么 |
|---|---|---|
| 位面-轮节奏骨架(`cw_economy.get_node_goal`/`_expected_level`) | 策略机制层(阵容无关) | 何时升级/停留/花金 |
| 游戏真值刷新率(`cw_shop_odds` 随等级)+ 自适应找牌(`_core_miss_q`) | 游戏真值层 | 几级能刷到几费卡 |
| 阵容目标态(`core_chars`/`need_star`/`faction_reqs`) | 阵容定义层(Comp) | 刷到之后要什么 |

三者组合,「X 线 7 级停 D 三星主C」这类攻略节奏指令自动涌现(P2 曲线
2-1 即升 7 + 主C need_star 3★ + P1 找牌 core 通道),无需按阵容手编曲线。

位面坐标仅两处合法出现(都不是节奏):

- **辖域闸门**:`session_scope.plane2_started`(进位面 2 的单调布尔)——
  切换策略行为域(配方清除/各辖域开关),消费面在策略层;
- **形态信号**:曾由 `entry_signals` 的 `plane_end` 类承载(白厄 B 套类
  「满编后期特权形态」)——该字段已整体退役(2026-11 用户终裁「可退役」:
  万敌 1 条/白厄 3 条知识真空接受损失,上场时机 = 部署搜索骨架/L1 完成度
  自适应,sim 观测退化明显再议);未来同类需求复现时重新设计,不开复原
  旧字段的例外通道。

**准入硬判据:凡「何时/过程」性质的字段都是层次违规。** 先例:
`level_plan`(等级→动作手编曲线,20 套 ×~7 级 ≈ 800 行)——消费路径
(P1 找牌窗)被「core 通道 + 节奏骨架」取代后整块成为死数据;死因不是
维护疏忽,是**手编曲线 vs 自适应推导的机制淘汰**。

## 字段准入判据(新增/修订字段前逐条过)

1. **消费先行**:先有明确消费它的策略行为,再落字段。「知识完备性」
   不是理由——把攻略知识尽量结构化进注册表的五批叠加史(v2 十字段/
   知识卡/形态端口…),产出的字段随策略演化消费面收窄后成批死亡
   (v2 十字段死 6、level_plan 整死、评分器族 4 字段随评分器整删)。
2. **派生优先**:能从既有字段或游戏真值派生的不手编。先例:
   `factions` ≡ `faction_reqs` 档 0 键集(`core_faction_reqs`,纯冗余派生读口);
   `member_priority` 整字段不存——恒等于 core/shared 两档派生(全库零手编,
   让位序现算 = `derive_member_priority`)。
3. **名单多胞胎警惕**:成员名单字段(core/shared/
   need_star 键)语义高度重叠——
   新增名单前先问能否挂到既有名单的属性上;名单间关系必须有校验
   (先例:key_items 曾有 5 阵容含 core∪shared 外成员——多表无校验
   的维护病;lock_rules 键、entry_signals 键、key_items(存续期 88% 数据行被 carry_set 减法遮蔽,过渡体系建成后路径知识未并入统一体系)、transition_chars(2026-11-05 退役,同族第 4 件——语义 = P1 过渡知识,终局条目不夹带过渡逻辑的裁定收尾)四度上榜,均已整字段退役)。
4. **目标态快照**:见第一原则——过程性知识(何时/怎么长过来)不进
   schema,归 final_comps「达成路径」叙事 + 策略机制层。
5. **攻略口径→结构口径的翻译**:攻略说「X 优先/默认」时,分清**门槛**
   (统一维度实现,新候选零改动)vs **身份**(专属判定,依据读注册表
   数据非名字 if)——与 `compo-knowledge.md`「教义措辞规范」同款
   纪律,防实现层造特权分支。

## schema 分层语义(字段族边界;字段清单与值单一源 = `cw_comps.py`)

- **身份**:阵容是谁、聚类代表;
- **成型**:终局形态判据(AND 档 + required 在板;`form_progress` 唯一折法,禁消费位内联判定)。OR 组(`or_reqs`)已整字段退役——判据:口径错位,过渡体系启动判据(「量子或贝都行」)被误用作终局成型判据,两层判据各自归位(启动归过渡、完全体归终局,考古走 git 历史);`required_deployed` 保留(点名件全部在板才算成型——过渡条目「引擎不可拆」语义的承载);
- **成员**:谁在名单(core/shared 两档终局成员——shared = 第二档终局成员,双列
  重复登记被建库校验禁止(core∩shared 恒空,import 即炸);终局成员集 =
  core ∪ shared,送卡档位机器即以这两名单取档);
- **知识卡**:星级目标(need_star;key_items/lock_rules/entry_signals
  已先后整字段退役——key_items 的 P1 路径知识归过渡体系(TRANSITION_
  BONDS 点名件/羁绊全员),方向证据归各线 core 身份,上线时机归部署搜索
  自适应;新体系建成后旧载体须同批清算,勿留残余通道);
- **装备**:到人配方(equip_assign 真源 + key_equips 投影 + 禁忌);
- **过程性知识不进 schema**(何时/怎么长过来)——归 final_comps 叙事
  与策略机制层。

过渡层不复制这套分层:过渡阵容库(`TRANSITION_LIBRARY`)为**组合条目制**
——`TRANSITION_BONDS` 构造块 × 两两组合建库期生成(单羁绊构造块不是
条目、永不锁定;`required_deployed` 承载点名件在板语义),语义边界归
strategy-docs/12 号篇 §3,本表不镜像。

字段族的具体成员随迭代增减,本表只锁语义边界;「现在有哪些字段」查
`cw_comps.py` 的 Comp dataclass(单一源,不镜像)。

## 读口层(派生概念的消费唯一入口)

**读口** = 从 Comp 数据字段派生、供策略层或 kernel 消费的概念的正式
函数或 property——该概念的**唯一合法取数入口**。Comp 的数据字段层(人编
知识登记)与派生读口层(机器消费)两层分立,凡派生概念一律读口化,禁止
消费点内联拼装字段组合(`set(c.core_chars) | set(c.shared_chars)` 这类
写法即违例)。

**立法三条**(新增/评审派生概念时逐条过):

1. **多消费点概念必须读口化**:一个派生概念出现第 2 个消费点时,必须在
   kernel `cw_comps.py` 立读口;单点消费的一次性表达式不在此列(它不是
   概念——例:送卡档位机器的两名单扫描是合法内联)。
2. **管辖域 = Comp 派生概念**:凡派生自 Comp 数据字段、被策略层或 kernel
   其他模块消费的概念,读口落 `kernel/cw_comps.py`。豁免两类:**策略层
   立场数据**(LINE_HEAT/COMP_MEGASTAR_PREFERENCE/词缀吃怕表——攻略热度
   统计与策略偏好,按 strategy-docs/12 号篇分层归策略层旁表)与**独立
   概念**(intention_core——意向核心,∈core 约束是 miss 计数良定义的
   刻意语义,落 cw_intention)。
3. **两层 docstring 分责**:字段 docstring 写知识登记语义(「凭什么信」:
   出处/校准口径);读口 docstring 写消费语义 + 正典文档锚。漂移在两层
   docstring 对照下可见。

**守卫的诚实声明**:无自动守卫(项目测试纪律禁源码扫描测试)。守卫上限 =
读口清单(概念 → 读口,读口为可 grep 的代码符号;不设「消费面」列——
代码结构的第二抄本必漂移)+ 本节 review 关卡。

**读口清单**(概念 → 读口登记表;读口本体与值单一源 = 各落点代码):

| 概念 | 读口 | 落点 |
|---|---|---|
| 核心羁绊键集/档位 | `factions` / `core_faction_reqs` | Comp property |
| 加层羁绊 | `bonus_faction_reqs` | Comp property |
| 阵容轮廓 | `all_factions` | Comp property |
| 终局成员集 | `members` | Comp property |
| 线 carry 单名锚(聚类+补全口径) | `carry_anchor` | cw_comps 函数 |
| 评分锚(攻略重述口径) | `rating_anchor`(分歧登记 ∘ carry_anchor) | line_select 函数(策略旁表豁免:评分口径取攻略重述是评分决策) |
| 分配器 arm 键 | `arm_key_of`(= carry_anchor) | cw_run_allocator 函数(cw_loop 仅改调) |
| CARRY 档全集 | `carry_set` | cw_comps 函数 |
| 关键装备清单 | `key_equips` | Comp property(委托 derive_key_equips) |
| 成员优先级 | `member_rank_of` / `derive_member_priority` | cw_comps 函数 |
| 意向核心(miss 计数) | `intention_core` | cw_intention 函数(独立概念,豁免管辖域) |
| 攻略热度/巨星偏好/词缀吃怕 | LINE_HEAT / COMP_MEGASTAR_PREFERENCE / affinity 表 | 策略层旁表(策略立场数据,豁免;12 号篇分层) |

## 角色怎么定义:深入游戏理解逐个敲定(第二条)

**结论(2026-11-04 用户已定案):阵容角色定义靠深入游戏理解逐个敲定
——统计只给候选,不能靠统计乱来。** 先例裁定(用户 2026-08-21):「不是统计的可替换,
是功能链」(transition_combos.md 先例链)。

### 两层分离(组织原则)

| 层 | 载体 | 内容 |
|---|---|---|
| **文档层**(玩法完全理解) | `final_comps/` 各篇 | 功能链叙事(为什么是他)/特殊系统(领航员绑定/任务链/升费链/阿哈装备栏)/达成路径/流派语义/外部条件——人读全量,不裁剪 |
| **实现层**(策略消费最小集) | COMP_LIBRARY schema | 见下表——按策略消费裁剪,不为知识完备性落字段 |

### 定义链(文档层怎么得出角色结论)

统计给候选(plaza 聚类频次)→ 人判班底语义(逐篇精读:谁是功能链
哪一环)→ 机制验证(游戏数据原文:羁绊 layer / 角色 skill / 装备
desc——final_comps 各篇「构造机理」节的逐环引用模式)→ 功能链身份
落库。

四个出场率陷阱(为什么拿出场率拼不出阵容;先例细节见
compo-knowledge 证据三层):

1. **填充件出场率虚高**:瓦尔特 529/784 全场第一=通用辅助骨架,
   不是任何阵容的定义角色;列车羁绊 286 篇主导但大量是凑羁绊填充;
2. **副产品羁绊误判**:椒丘 DOT+减益双高频=买件顺带激活,非被选中体系;
3. **一聚类混多形态**:姬子 274 篇=反震 60%/输出 25%/特化 15% 三种
   打法,聚合把流派差异平均掉;
4. **羁绊达成 ≠ 阵容成型**(人员要求分层):DOT2 任意 2 人即用 vs
   仙舟3 最佳班底=功能链各占一环 vs 希儿系单卡依赖——同一档位,
   人员要求完全不同。

### 实现层最小面(2026-11-04 用户裁定)

| 面 | 承载 | 说明 |
|---|---|---|
| 角色 | core/shared 两档名单 | 名单来自功能链,非出场率 |
| 优先级 | 统一让位序 | **=功能链的序数化投影**(文档层留「为什么」,实现层只要序) |
| 站位 | 角色层 position 真值 + 阵容层覆盖(排级+槽位级) | **CW 玩法每角色的可选站位定义**(front/back/common,`cw_chars.position`,官方 Common=双排皆可且技能效果不绑定排,游戏真值);common 默认 back 是无知识兜底而非游戏定义,排差异来自阵容机制面(受击方向/前后台强度分配/装备排绑定/巡海后台供增益类)。`char_positions` 值域 = 排级(`front`/`back`)**+ 槽位级**(`front@0-3`/`back@4-9`,@n=board_index 与攻略记号同源;攻略 board_index 知识如三月七@4-6 护盾相邻中段/万敌@0 一号位硬约束);**策略层槽位知识优先、自适应分配兜底**(落位优先占指定槽,被占/超容软回退;不触发已就位件重排)。同角色不同阵容可不同排(不死途黄泉线后排 vs 白厄线前排) |
| 装备 | equip_assign 到人 + 内在禁忌 | 「装备是角色特定的,到人不是到位置」;禁忌=阵容内在机制冲突(万敌禁盾) |
| 星级 | need_star | 高/低饥渴两档线(A4 星级统计批) |
| 羁绊 | 优先级结构 | `faction_reqs`(档 0 = 核心羁绊层,同档多键等权全凑齐才成型;档 ≥1 = 加分层,进部署次层与采购面不进成型判定;原主/副档两字段已合并);OR 组(`or_reqs`)已整字段退役 |
| 流派 | 分条定义 | A/B 双强各一套 Comp(姬子反震/输出方向拆条),不把分岔变量埋注释 |
| 替班 | ≈名单+优先级 | 替班者进终局成员+序低真核心一档(「不卖转副C」由成员身份自动成立);动态接管(核心缺席时最高优先在场者接管 carry 目标)走策略自适应 |

### 不进实现层的面(归策略层)

| 面 | 归属 | 理由 |
|---|---|---|
| 特殊系统(领航员/任务链/升费链/阿哈装备栏) | 文档层知识 + 策略侧将来立项 | 由特殊角色要求的可先提该角色优先级近似;系统级行为待策略侧特殊实现 |
| 上场条件 | 策略自适应方向 | 与 level_plan 之死同构:手编窗口表 vs 每帧评估——预定义窗口是部署自适应的冗余约束(entry_signals 已按用户终裁退役,2026-11:上场时机 = 部署搜索骨架/L1 完成度自适应,知识真空损失接受——万敌 1 条/白厄 3 条;退化观测挂 sim,明显再议) |
| 外部关联(投资环境/策略、敌人词缀、BOSS) | 策略层分别定义加扣分表 | 投资亲和(ENV/AUGMENT 表)与词缀(线级吃怕表 `cw_affinity_table` + 选卡克制直写表 `pick_common.AFFIX_COUNTERS_FACTIONS`)已是策略层模块级表;BOSS 面待策略侧重建 |

### 两条结论的共同根

**Comp=目标态;一切过程性/条件性知识(何时/谁先上/谁替谁)归策略
自适应。** 第一条(阶段节奏归策略机制层)是它在时间维的特例。

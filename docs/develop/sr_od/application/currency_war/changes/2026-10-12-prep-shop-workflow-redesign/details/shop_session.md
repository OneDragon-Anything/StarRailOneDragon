# 商店会话模型（详设）

## 问题与约束

- 边界：本篇只管商店画面（画面档 `currency_war_battle_prep_shop_open.yml`）的会话组织与店内决策。升级判据见 line_and_upgrade；备战域的进出时机见 prep_pipeline 第 4 步。
- 总纲契约引用：契约 A（进出与标记）、契约 B（方向视图消费）、契约 C（节点键登记）、契约 D（评估器的店内场景）。
- 画面能力面（实机归档帧 `sr-od-test/screens/货币战争-备战-开商店/shop_open.webp` 确认；免费刷新标识 = 画面档 area「标识-免费刷新」，`currency_war_battle_prep_shop_open.yml`）：商店画面为全屏面板，可见商店 5 槽、场上前后台、备战席 9 格；bot 建模的可用交互 = 买牌、刷新（2 金【注·REFRESH_COST_BASE 注册表】，免费刷新次数另有标识）、购买经验、收起（关店）、出战；商店锁定按钮画面存在但 bot 不建模其交互（本迭代不引入，登记未来扩展）。
- **店内动作边界（用户裁定 2026-10-12 + 能力面）**：店内可做 = 买牌、卖备战席、刷新、购买经验；店内不做 = 卖场上角色、点消耗品、拖角色上阵（部署统一店外）。
- **执行链前置依赖**：现行商店域执行环境无执行器端口，卖备战席与买经验在店内发射会失败（as-built 依据 = `screens/README.md` §5.4「商店域执行链未接线」；代码面 = `cw_screen_shop.py` 分发注入的 `ShopExecEnv` 无 `executor` 字段）。启用店内两动作前必须完成执行端口接线（独立落地批，landing §3.5）。
- 单动作循环与零读屏规范不变：刷新维持「访问终结」（op 结束 → 外循环重识别 → 商店 op 重新入口观察读新牌面；出处 = strategy-docs/02 §7、11 §3 决策规则 4）。刷新导致的 op 重进仍是同一会话，不算新访问。
- 失读窗的退出形态 = **工程停机出口**：入口观察发现牌面含未识别槽时框架停机留证（`stop_running`，守卫规范出处 = flow/guards.md §3，用户 2026-08-24 裁决接受阻断代价）；决策侧「花钱动作全禁、只允许关店」仅为纵深第二线。停机后不存在自动恢复路径——人工恢复重跑后，凭「本节点已处理」标记缺失，从备战工序第 4 步重新进入会话继续处理（节点内牌面不变，economy §2.1）。

## 方案

### 1. 会话定义与生命周期

- **一次会话 = 开店动作到关店动作之间的全部商店域决策**。跨刷新重进（op 级）延续同一会话；会话终结 = 输出关店动作。
- **会话入口三条路径（契约 A）**：① 备战工序第 4 步的开店动作；② **游戏侧自动开店**；③ 金位读数开商店（§4.2——非处理性读金，命中处理需求转正常会话）。路径②细节：战斗结算/选卡类画面处理完后游戏自动弹出商店，实机在产，出处 = screen_flow_timing #14/#29；**辖域注（方向修正）**：as-built 在案事实 = 「boss 简报后商店不开」（screens/README §5.1、boss_briefing.md 开放设计注①）——boss 简报帧不属路径②触发面；口述 #14 的「boss 简报关闭后自动开店」一支被 as-built 废除（其余触发源与 #29 在产），以 as-built 为准）——路径②下外循环直接进入商店画面 op。**入口统一行为（决策闸门策略侧自限——flow/README §1 分层铁律，流程侧只做画面分发不做决策）**：商店画面的策略决策函数首查两项——节点边界检测（节点号变化 → 边界重置，含清标记/清单）与 `shop_handled` 标记检查：未处理 → 正常会话决策；已处理 → 输出关店（**复核唯一触发点 = 备战第 4 步**，与契约 A 统一口径——战斗结算入金发生在节点转换后，清单已被节点边界清空，「结算解本节点清单」场景不可达，入口不复核无遗漏亦无往返链）。**例外 = 受限商店访问帧**（出战发射帧经 P70 仲裁授权的溢出段消费，契约 A 豁免条款）：授权帧不受标记辖，授权消费后返回；其消费后的关店**不置标记**（非正常收工路径，现时序无害）。三条路径同一会话语义（③ 不置标记的非处理性读金除外——契约 A）。
- 生命周期：
  1. 入口（路径①②③——③ 读数会话不置标记，本步语义同未处理）判定标记未处理 → 进入会话；
  2. 会话内决策循环（§2）；
  3. 正常收工（无可买且刷新判据不通过）→ 输出关店 + 置标记 + 写未消费机会清单（§4）。
- 异常退出不打标记。失读窗 = 框架停机留证（见 §1 边界段）；run 中断同理——两者都无「自动接着处理」，恢复入口 = 人工恢复重跑后标记缺失 → 重新走第 4 步进会话。**恢复局特例（辖域切分）**：重启后首节点若为恢复局形态（中断续局，商店交互被游戏禁用——economy §2.1 恢复局商店锁死机制）→ 第 4 步开店被游戏侧拒绝，行为 = 既有恢复局语义（只出战推进）、标记不打；恢复局结束回正常对局流后标记缺失 → 重新进会话。两段不矛盾：**恢复局 = 游戏侧禁店形态（按对局形态分流）；失读恢复 = 标记缺失的重新处理（正常对局形态下才适用）**。

### 2. 会话内决策循环

每轮按序评估，输出恰一个动作（现行单动作契约不变）：

**2.1 方向评估（契约 B 消费）**
- 入口调用 `refresh_line_if_needed(gs)`：证据签名同备战域（P77 差分已撤销——线分数不含牌面维；货架影响方向的通道 = 买入后持有证据上升，line_and_upgrade 差分节）。签名未变 → 用现值；变了 → 重算（候选快照更新 / 硬规则锁定检查，line_and_upgrade §1.2/§1.4）。

**2.2 买牌（前置升级检查 + 调用统一买入策略，契约 E）**

- **前置升级检查**：每轮买入评估前执行会话内升级判据（仅在每轮买入评估边界执行——置换/筹资序列中间不插入升级检查，序列闭合后下一轮评估）（line_and_upgrade §2.2：概率主轴/人口位 → 整级预授权 → 变现步 → 店内购买经验整批发射）——升级金优先于买牌金，等级决定概率档，先定概率档再花钱找牌。**次序翻转差分申报（全触发源辖——缺省相下行为差即存在，非仅标定后）**：现行 M2（义务买入）先于 M3（升级）→ 本设计升级前置为次序翻转；**触发源并集五臂中人口位/arm0/溢余段-L3 在缺省相照常触发**（概率账 fail 态仅停概率账自身）——触发帧内：①M2 义务买入顺延下节点（顺延非丢失）；②会话内买入可中途武装人口位（补齐等待件）→ 会话中段升级 → 升级即收工关店（标记照写）→ 同节点剩余已过判据的买入被截断且不入机会清单（拦因闭集外）——真实行为差如实披露，确认批测试必含此形态。升级动作执行后**直接收工关店**（§2.5：标记照写；商业间谍/晋升名额的升级联动商店效果两段未建模，牌面期望态失真——本会话终止买入规避 guard_proposal_vs_expected 误炸（商业间谍整店刷新按牌名比对会炸；晋升名额费用档变化不炸——限商业间谍场景）；该收工路径的标记与机会清单写法同 §2.5 规则（标记照写、清单照写）；升级的概率档收益下节点自然兑现；「升级后同节点找牌」收益放弃 = 已知限界，登记实机观察点）。

买牌策略是全局统一组件（用户裁定 2026-10-12）：类目与优先级序单一源，商店会话只是它的执行画面。序结构完整承继现行六序（判据本体 = strategy-docs/11 §1 逐序不动；未锁定/锁定两态仅变化序 1 的名单来源）：

1. **目标阵容件（序 1）**：**锁定后 = 锁定线名单成员（line_members_view；P1 锁定局 = opening_recipe_comp ∪ 锁定线名单并集——line_and_upgrade §1.3 分域）**；**未锁定 = 候选 top3 线的成员集**（候选 = 线分数 top3，line_and_upgrade §1.2/§1.3——用户裁定 2026-10-12 候选-锁定制：3 个候选的件照买照囤，[21]/[22]）+ 全线路通用贯穿件恒囤；候选件没有而金有余 → 序 4 压库承接（压库不限于候选线，费用档判据，[31]②/[34]）。原「三源候选集」形态作废（候选-锁定制替代——P86 三臂/④臂/K 回退集的收编处置见 §5 承继清单逐行）。买或囤；席满时：满栏合成例外（merge_mechanics §2.5 原文口径 = 席满时凑合成的单张仍可买入）；凑不成合成 → 置换账（§3）。
2. **场况插件（序 2）**：板面羁绊差一人进下一档的件（user_playstyle [35]；判据本体不动）。**店内执行面约束 = 会话累计额度**：额度 = **会话开始帧快照值**（开场读一次 deploy_cap − deployed 存为额度，载体 = session 键：开场写入、买入递减；会话内不再读现场——店内 deployed 恒定，现读会每帧同值永不递减）；额度尽即停，**被拦插件不进机会清单**（上阵空位非节点内可解除资源，拦因在 {席满,金不足} 闭集外；部署步消耗空位后判据下帧自然重评）。**待部署成员竞争**：部署步消费同一空位池、先到先得（额度是商店侧上限，部署侧 P24 判据不动）。**与现行两资源合取门的替换申报**：bench 维收窄 + 席满改走置换账（11 §1 合取谓词替换逐项申报）；[35] 偏差申报：原「买了即上」改为店内买入 + 店外部署。
3. **通用插件（序 3）**：现行 PLUGIN_LIBRARY 判据照旧（座位价值 + 备战席稀缺性定序，出处 = 11 §1 序 3 行）。席满 → 置换账。
4. **压库件（序 4）**：金位超过息线的部分换成低费牌（活期资产，user_playstyle [41] 二次精确化「超 50 尽量压牌库」）。**压库受整买预留约束**：存在待执行整买目标（升级攒批）时，超息线资金优先囤到整买目标，压库只消费预留之外的部分（user_playstyle [41]「>50 也有场景要囤钱」联合口径）——压库不会吃掉升级攒批资金，杜绝「压库换卡 ↔ 升级永远凑不齐裸金」的资金活锁（升级的攒批资金口径 = 裸金 + 活期卡退金，见 line_and_upgrade §2.2）。席满 → 置换账。
5. **凑星件（序 5）**：板面同系单位凑 2★ 素材，稀缺性序（出处 = 11 §1 序 5 行）。席满 → 置换账。
6. **纯冗余（序 6）**：边际贡献 = 0 → 停买（出处 = 11 §1 序 6 行）。
7. **名单核心卡支（C1，邻位通道）**：非名单成员但为注册表核心的在售卡 → 维持现行支配买入支语义（出处 = 11 §1 C1 通道），席满 → **恒买豁免价值比较**（C1 支配语义 = 跳过置换直买：核心在售即买，腾位按价值让位自然发生——摩擦否决仅辖非核心让位候选，行为变更申报）；非核心的凑星件类席满 → 置换账。

序 1/序 2 不走息律门的义务通道语义不变（现行 M2 通道收编）。**优先级序语义（截胡与下沉裁决）**：每帧取最高优先级命中的首个动作，序 N 拒后不回跳序 M>N（单动作契约一帧一决策，拒绝 = 本帧该牌不买、下帧重评——C1 位次为事件序列优先级非回跳链）；核心卡满足序 2（场况插件）时按序 2 买入（行为同向 = 买到）。**金约束门定义落点**（序 3/4/5 共用）= 现行 11 §1 判据：息线 `saturation_line(cap_resolved)`、P46 支出否决域结构、[11] 零息损口径——本迭代零改动，仅随序收编声明。**整级预授权的预留保护全序通用化**：存在待执行整买目标时，全序（序 3/5 亦然）的可花溢余 = 金 − 整级差额预留 − 息线带——序 3/5 溢余段买入同受预留约束（防序 3/5 买入吃掉整级资金，line_and_upgrade §2.2 同源口径）。**滞留副作用申报**：变现键滞留期间（升级授权未发射）该预留持续抑制序 3/4/5 溢余段消费至节点末——有意保守（升级资金完整性优先），副作用如实申报。

**2.3 筹资（金不足时的伴生卖出）**

**前置 = 买入判据已通过**（对照 §3 置换账同款前置）：筹资只为已过统一买入判据的买入供金，不破息为未过判据的牌筹资（金约束门/P46 前置保持——缺此前置则序 3/4/5 可破息为任意牌筹资）。
- 想买的牌金不足：卖活期件凑（过滤 = 1★ 全额退的候选，评估器），凑够即买、不多卖（user_playstyle [41]「凑息需要时把备战里非上阵的卡卖掉筹资」；[11] 卖回量最小化）。筹资候选穷尽仍不足 → 该牌进「未消费机会清单」（拦因 = 金不足）。
- 筹资卖出与买入在会话内闭环，不关店。

**2.4 刷新判据（星级目标驱动；用户裁定 2026-10-12 刷新/升级专题）**

- **判据形态（查表，零计算；「可达最优等级」模型——用户裁定 2026-10-13）**：**值得刷新 ⟺ 存在「当前星级 < 必要星级」的角色 ∧ 当前等级 ∈ 该目标的最优概率带**（最优概率带 = **搜索域 1..9 内的概率峰值区间**〔peak_refresh_level 在产口径——全域峰在 lv10 的 4/5 费取域内峰，4/5费带=[9,9]；禁「全域峰值区间 ∩ ≤9」写法——4/5 费得空集〕；等级被推过带上界 → 当前等级即剩余可达最优，照样刷）（必要星级按攻略逐角色登记——COMP_LIBRARY 每线每角色 `need_star` 字段，知识批交付：CARRY 按线攻略标 2★ 或 3★〔星级饥渴数据为源：千冶·刃 94%/万敌 90% 类标 3★，银狼 48%/DOT 52% 类标 2★〕，辅助标 1★〔无星级要求〕）。**多目标停留顺序 = 按目标角色费用档升序逐个追**（先低费后高费——当前停留目标 = 费用档最低的未完成目标；**最优概率带下界 > 当前等级 → 升级优先**〔升到带内去刷，[3] 语义〕；当前等级已是最优 → 停留刷）；**定了 3★ 追到底，无降档规则**。
- **刷新为星级目标服务，其他顺手买**：刷新途中的其他需要牌照买（序 1-7 既有买入通道），能顺便升星就升（自然合成）。
- **金前提照旧**：息线账管刷新花费上限；**整级预留保护照旧**（存在预授权键/攒批目标时 reserve 含整级差额——刷新不烧升级资金，防活锁）。

## 关键取舍

- **店内卖备战席（翻案）vs 维持店外腾位链**：选店内。店外链每腾一位要「关店→备战卖→重开」三轮画面切换且产生节点内重开语义复杂度；店内卖一步完成。能力面已确认可用。场上角色店内仍禁卖（能力面边界 + 用户裁定），换血场景留给备战域。
- **机会清单 vs 每次状态变化重开检查**：选清单制。备选是「金/席/方向任一变化就重开商店重评」，放弃原因：盲目重开产生大量空转开店动作；清单把重开限定在「确有被拦的判据过牌」时，收敛性显式。
- **筹资放会话内 vs 维持备战域**：选会话内。用户 [41] 原话语义即「买了凑息需要时卖备战线上的卡筹资」，与买牌同账同帧；放备战域会产生「关店筹资重开」的第三种重开场景，复杂度反向。
- **商店锁不建模**：现行未建模锁定交互，本迭代不引入（登记未来扩展；跨节点保牌对「一节点一会话」模型无冲突）。

# λ_death(死亡危险率查表参数)与战力数据消费纪律

> 改任何 λ_death/危险信号/战力建模相关内容前必读本页。λ/风险架构的语义权威版本住 [strategy/00_framework.md](strategy/00_framework.md) 与 [strategy/04_survival_budget.md](strategy/04_survival_budget.md);数学证明体系已整体废弃(2026-11-20 用户裁定,考古走 git 历史)。

1. **λ_death 表现状 = 查表基础设施**:死亡危险率的实机校准表(`statefn/lambda_death.py`,数据工件 git 追踪)。原有的决策消费方(λ 顾问、风险敞口比较、升档器排序键)已随血线地板/λ 顾问/升档器的删除链停用;现役消费只剩审计登记与濒死状态阈值判断。
2. **硬闸门(用户裁定,仍然生效)**:hp/战力数据进策略,仅限逐项经用户确认的授权范围;**其他任何战力相关内容进策略,须用户逐项确认**——hp 使用边界单一源 = strategy/00_framework.md §3。
3. **新增 λ 表消费须过使用纪律审查**:只做区间风险比较、取保守侧值、保持单调性;禁止边际引用、禁止把它做成拦截闸门。
4. **死因实证(存量事实)**:历史死局 68% 的死因相同——该买不买、攥着钱不花(消费被策略姿态压制)。验证判据基线 = 死因分布复算(死因构型编号 A1+B 塌向 C,出处 git 历史)。
5. **数据通道纪律**:实机对局数据用于点火验证而非持续供数;sim 与校准表若用同一批语料构成循环论证,只能当压力测试、不能当数据来源;难度判定以局内读取为准、公式核对为辅(核对偏差是数据漂移的报警信号)。
6. **资源分配**:战力建模 = 机会性小任务(有富余人力时做,不影响主线;新产出必须过硬性质量检查才能使用)——需求件 = docs 侧 sim/sim-power-model.md。

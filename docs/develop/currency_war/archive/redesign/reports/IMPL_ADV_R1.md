## 问题清单(按严重级排序)

### 【高-1】臂①与臂②共用 strategy_id,三臂判读的臂间区分无遥测载体(§4.1/§4.2/§5.1 内部矛盾)

- **位置**:§4.1(STRATEGY_ID='mandate_v1')、§4.2 三臂表(臂①②同为 mandate_v1)、§5.1「分栈按 strategy_id 字段(§4.1)」。
- **缺陷**:ledger_hooks 判栈逐局只读 `strategy_id` 字段(代码直调复核:`ledger_hooks.py` L349-351,字段优先、退 reason 词表)。臂①(骨架-only)与臂②(骨架+EV)共用同一 id、同批跑 40 局,遥测层无法区分两臂——而 §5.2 的核心判读「EV 增量(臂②−①)」恰恰依赖臂间可分。§4.1 自述新 id 的全部理由就是「恢复分栈锚」,结果只恢复了 ②−③ 的区分,①−② 的区分反而丢了。
- **为什么错**:判前锁三闸 + 臂间配对判读要求每局可归臂。臂内开关是「entry 的模式参数」(非策略参数),该参数当前设计只存在于运行配置,不进 ledger 行——判栈词表与遥测都不消费它。
- **修法方向**:①臂位显式写入每局遥测字段(如 `arm`/`mode`),判栈逻辑消费该字段;或②干脆分臂注册两个 id(`mandate_v1_skel`/`mandate_v1_full`),config 值域扩为四值——改动量与「双被测体」方案同量级且零歧义。

### 【高-2】E_rev 豁免的 fail 方向漏标:E_rev 同样依赖🔴未标定量,未按总纲 fail-closed(§2.1 与总纲§3.3#1/#2 矛盾)

- **位置**:§2.1 `ev_buy_veto()` 行——fail 方向列只写「E_line 因 V_ms 未标定 fail-closed」。
- **缺陷**:E_rev 豁免条件 = `V_opt ≥ L+fee`,而 V_opt = u·P_miss·C_rescue(P41 ①),u_x/H_x 系总纲§3.3#1 🔴「数值不授权(P41 修复批撤销);中间类 fail-closed 持有」。E_line 标了 fail-closed、E_rev 没标 = 实现者的自然读法是「E_rev 可算」——要么复活 u 点值注入(正是 TUNING#1/#2 判违规的 calib_v1 注入链形态,违反公理 1/5),要么算出恒假/恒真的不确定行为。
- **为什么错**:P46 豁免 = E_rev ∨ E_line 是两个并列条件不等式;两个的数值输入(V_opt 的 u、E_line 的 V_ms)都未标定,fail 方向必须对称声明。总纲§3.3#2 只点名 V_ms,但 #1 的 u 覆盖 V_opt,IMPL 照抄总纲时把 #1 漏掉了。
- **修法方向**:E_rev 在 u 标定前同样 fail-closed(= 不豁免,D 否决域全效);或先走 P41 修复批的支配性分类分流——燃料类已消参的形态可豁免、中间类不豁免——把这一点写进 §2.1 fail 列。

### 【高-3】换线(P16)双落位且层级倒置:总纲归证明层,IMPL 放 EV 层并回调改写证明层输出(§1 树/§2.7/§3.1 与总纲§5.2 矛盾)

- **位置**:§1 模块树——`proof/line_selector.py` 注释写着「证据门 + **换线** + 停手线」,同时 `criteria/switchline.py` 又是「换线(P16)」;§2.7「产出换线事件 → 回调 sell.line_switch_sell + **通知 proof 层更新目标线 K**」。
- **缺陷**:同一职责两处落位是笔误级问题,但底下是真矛盾:总纲§5.2 明文把换线归**证明层**(「证明层:证据门(P38)+ 换线(P16)+ 停手线——只产出线选择与 L(r) 场景」),权限是「决定骨架为谁服务」;IMPL 把它放 criteria(EV 层)——EV 层的权限铁律是「只增不减,无权否决/改写骨架动作」,而换线恰恰改写骨架的服务对象 K,且触发不可逆卖出(line_switch_sell 塌缩出口)。
- **执行序推演(为什么必错)**:entry 序 = 证明 pass(定 K)→ 骨架 pass(M2 按旧 K 买入)→ EV pass(switchline 翻转 K → line_switch_sell 重评旧线件,**含本帧刚按旧 K 买入的件**)。P16 的 θ 滞回压的是抖动,压不住「同帧买入又卖出」——买入可退 1★ 全额但 2★+ 有手续费,净损为正且是设计自造的。
- **修法方向**:换线机上移 proof pass(与证据门同 pass,总纲口径);换线事件对骨架的生效延迟到下一备战期;塌缩卖出在 K 已切换后的下一帧评;§1 树删掉 proof/line_selector 注释里的「换线」或删 criteria/switchline,单一落位。

### 【高-4】执行序 M4→M1→M3 单遍无 M3→M1 回环,升级开出的人口位本帧无人补——结构性产生 P24 证成的「禁运轮」(§3.1 内部矛盾)

- **位置**:§3.1 执行序 `M5 → M2 → M4 → M1 → M3 → M6 → M7`,及「M1 与 M2 同帧」注。
- **缺陷**:M3 升级抬高人口上限 → board 出现新空位 → 等待件应上场。但 M1 排在 M3 之前且单遍,本帧不再评估部署。M3 臂一的立论基础是「人口位当轮兑现」([33] 明文例外、P39 臂一谓词)、P24 证成「skip 轮补部署严格支配整轮部署禁运」——本执行序让每次人口位升级都产生一个结构性禁运空位期(等下一备战期),恰是 P24 判严格劣的形态。臂一谓词「板满 ∧ 等待件」与 M1 的时序耦合也要求升级后重评(升级前板满才触发 M3,升级后板必不满,等待件还在)。
- **修法方向**:骨架 pass 内 M3 后重跑 M1(或将骨架 pass 实现为循环至不动点,受单帧动作预算约束);至少在 §3.1 序内要点里写明 M3→M1 的回环与预算处理。

### 【中-5】保留血本位安全带(TUNING#38)与公理 3/[39] 裁定的相容性未论证(§6.2 与总纲§0 公理 3 矛盾)

- **位置**:§6.2「血本位安全带(TUNING#38,奋斗协议 rate=6【注】注册表)**保留**但移入 resolved 投资语境修正」。
- **缺陷**:公理 3 = 「血(hp)不入任何账与**自变量**」;玩家裁定 [39] = 「hp 不作决策输入」,且 [39] 的处死对象 `_xp_gold_floor` HP 分支就在同一节。TUNING#38 的批门条件是「血余额 ≥ ⌈need/xp_per_buy⌉×6 才买」——hp 进了判据自变量。IMPL 只说「移入 invest mutation 消费」,没有给出为什么 invest 语境豁免公理 3。
- **为什么不能放过**:若辩护 = 「奋斗协议语境下支付本位就是 hp,hp 是可负担硬约束①的同构物(资源余额 ≥ 成本),不是价值判断输入」——这是成立的,但必须显式写:它是「成本侧可负担检查」而非「决策输入」,且 [39] 的处死口径是决策输入不是支付本位。不写 = 实现与审查各凭理解,下一次对抗又会把它当违例打。
- **修法方向**:§6.2 补一段合法性论证(支付本位 ≠ 决策输入,同构于硬约束①),并落进实现 ADR;否则按公理一处死。

### 【中-6】λ_death 分层表的架构归属与缺省行为未定义:floor_eff/三段管辖的共同输入悬空(§1 statefn/§2.10/§5.3 缺口)

- **位置**:§1 `statefn/lambda_death.py`「λ_death 分层表 + floor_eff 投影」;§2.10 零调参三分类;§5.3 对拍「floor_eff 投影 λ 分层表边界两侧行为切换」。
- **缺陷**:λ_death 分层表是**直测观测表**(P51 §4-B-2,带 CI),按零调参审计属【拟】类(总纲§3.3#11:连续模型 🔴 采集#3,分层表先行)。但 IMPL 把 lambda_death.py 放 statefn(【推】层),provisional.py 只登记「总纲§3.3 的 13 项」——#11 登记的是「连续模型」,分层表这个**实际被消费的过渡数据源**登记不进去也不在 derived.py(它不是从注册表重算的,是采集的)。后果:①分层表数据从哪来(新注册表?P51 语料固化?)无单一源指针;②分层表缺失时 floor_eff 缺省取 50(守息保守)还是 0(该花就花)未定义——两个缺省方向行为相反,arm2 调度门与统一式 ΔW_trunc 全跟着翻转。
- **修法方向**:分层表显式登记为 #11 的过渡态(进 provisional.py,带 CI,缺省 None);None 时 floor_eff 缺省方向按 fail 语义定死(建议保守 50,并写明这是「宁可少花」方向的可逆性取向)并配 fail-closed 测试用例(§6.4 第 5 条现有清单没覆盖它)。

### 【中-7】判前锁三源并存,臂①成型率口径两文档不一致(§5.1/§5.2 与骨架层§4.1 矛盾)

- **位置**:§5.1「判据 = PREREG v5 三闸」+「判读前重申预期指标表(下 5.3)」(交叉引用还错了,表在 §5.2);§5.2 臂①成型率 = 「观察项,保守起判 ≥50%(编排者裁定)」;骨架层§4.1 = 骨架-only 成型率 **≥80%**,且「判读纪律:未达上表 = 假设证伪,禁调参续跑」。
- **缺陷**:同一判读对象(臂①成型率)存在两个锁口径(≥80% 证伪线 vs ≥50% 观察起判),外加 PREREG v5 第三个源。编排者裁定可以改口径,但判前锁的全部价值在「判读前唯一、不可事后移动」——现在 redesign 目录内两份文件对同一指标写不同数字,判读时挑哪个 = 事后自由度。IMPL 也没有声明「5.2 表为锁源、骨架层§4.1 该行作废」。
- **修法方向**:指定单一锁源文件;把臂①口径变更(≥80%→≥50% 观察项)写进该文件并留编排者裁定的追溯行;§5.1 的「下 5.3」改「§5.2」。

### 【中-8】arm1 缺省方向把不可逆支出标成「可逆」,与骨架层§3.4 同表先例不一致(§2.3 与骨架层§3.4/公理 fail 方向矛盾)

- **位置**:§2.3 `arm1_existence()` fail 列:「板面谓词读数缺失 → 保守按『有单位等待』处理(**可逆方向默认做**)」。
- **缺陷**:触发 M3 = 买 XP。卡牌买入可退(1★ 全额),**XP 支出不可退**——把 M3 触发说成「可逆方向」是误分类,按「可逆做/不可逆不做」原则本应缺省不做或不触发。且骨架层§3.4 同类缺输入(L(r) 快照缺失)的既定缺省是**朴素判据**(「等级落后于上阵人数需求」),不是「默认有等待件」——IMPL 无出处地换了更强的缺省。
- **修法方向**:板面谓词读数缺失的缺省对齐骨架层§3.4 先例(退朴素判据);「可逆」标签只给真正可退的动作。

### 【中-9】P46 否决域谓词抄漏「g−c<50」合取条件,否决域扩大到溢余段(§2.1 与 P33/P46 口径矛盾)

- **位置**:§2.1 `ev_buy_veto()` 判据式:「D = 真破息(**⌊g/10⌋ 档变**) ∧ 无当轮兑现 ∧ 非豁免」。
- **缺陷**:P33 定谳的否决域 = 真破息(g−c<50 **∧** ⌊g/10⌋ 下降)∧R≥1∧无当轮兑现∧非豁免。「档变」只写了档下降这一半——溢余段(g>50)大额支出可以降档而无息损(息只按 min(g//10,cap) 计,50 以上跨档本应自由,R2 也明文「溢余段自由」)。按 IMPL 字面实现,溢余段一切降档买入全入否决域,与 P46/P40 的溢余段自由条款直接冲突。
- **修法方向**:谓词补全为 P33 双条件式;这是抄写级修正但影响面是整个序 3-5 支出闸门,必须在落码前改。

### 【低-10】line_switch_sell 不等式漏 [x∈K] 指示项(§2.2 与总纲§1.2 主不等式不一致)

- **位置**:§2.2 `line_switch_sell()`:「refund + V_slot > max(V_opt, V_ms·ΔP̂) + V_power」。
- **缺陷**:总纲§1.2 主不等式右端是 `max(V_opt, V_ms·ΔP̂·[x∈K])`。换线重评的对象是**旧线件**(对新线 K′ 而言 x∉K′),ΔP̂ 项应为 0;照 IMPL 字面式,该项保留正值 → 压制卖出。方向保守(少卖、不可逆动作偏不做),不违 fail 方向,但判据式与证明口径不一致,且「保守」应来自 fail 列的显式声明而不是公式抄漏。
- **修法方向**:补 [x∈K] 项并注明按新线 K′ 取指示。

### 【低-11】P36-a 危机不变式落位在 EV 层,臂①「criteria 整层旁路」会连零参数支配结构一起关掉(§2.4/§4.2 内部张力)

- **位置**:§2.4 `crisis_refresh_invariant()` 在 refresh.py(criteria 层);§4.2 臂①「EV 面全关(criteria/* 整层旁路)」。
- **缺陷**:P36-a 是零参数结构不变式,语义「**先于 R0 存在性**」(支配族,总纲§1.4 支配性例外),prereg 实证 M1 哑火帧 16.21%→0.71%。支配族按总纲属「优先于一切带参 EV、全段无条件」,不应随 EV 面开关。若它在共享引擎(crisis_invariant_lane,ADR-0506)里,臂①不受影响,IMPL 应写明「平移指引擎层、臂①仍生效」;若平移进 cw4 refresh.py(EV 层),臂①就丢了一条支配保证,命题 A 的对照被污染(臂①少了非 EV 的结构项)。
- **修法方向**:写明 crisis_invariant 的运行层归属;落 EV 层的话在臂①旁路集中显式豁免该项。

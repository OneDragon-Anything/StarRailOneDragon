# 知识注册表规格 · 决策层数据访问(resolved input)

> **状态**:v0.1 起草。本文是 [01_strategy_layer.md](01_strategy_layer.md) §4.10「resolved input 原则」的**实现规格**:Phase 3 落码数据访问层时按本文单义实现,不再回读玩法文档。
> **读者**:Phase 3 实现者。
> **标注约定**:【已裁定】= 用户口述/裁定直接支撑;【源】= 出处(文件路径/字段名,持久索引);【gap】= 未登记知识缺口,如实登记不补机制。
> **禁改边界**:本文只描述消费契约,不改变任何现有注册表文件;数值单一源仍在代码注册表,本文写「常量名 + 出处」,不另立第二数值源。

## 0. 术语定义(首次出现)

- **基础值(base)**:游戏机制在「无任何突变」下的取值,单一源 = 代码注册表(如 `cw_shop_odds.POOL_COPIES_PER_CARD`)。
- **突变(mutation)**:改变某个基础值语义的局内效果。来源不止投资卡——**多源**:投资策略/投资环境/角色固有技能/任务奖励(01 §4.10 多源声明;例:银狼升费 = 角色固有技能,非投资卡)。
- **resolved 值**:决策层实际消费的量 = **基础值 ∘ 已激活突变** 按合成律解析后的单一结果。决策层**禁止直接读基础事实**,只读 resolved(01 §4.10 原则)。
- **突变登记三分态**(01 §4.10):
  - **resolved**:有数值、可解析,进 resolved input;
  - **abandoned**:已裁定放弃建模(invest_effects §5:官方 API desc 无数值一律放弃、不实机查;保可见性,不进 resolved input);
  - **未登记(= gap)**:知识缺口,采集后入表,不静默忽略;运行时读到未登记突变时按 §3.4 保守降级。
- **持有副本总数**:某角色在板面+备战席的等价 1★ 张数(3合1 折算:2★ 计 3、3★ 计 9;现有实现 `cw_economy._owned_core_copies` 同口径)。

## 1. resolved 输入清单

决策层要读的每一个量,逐条给:基础注册表字段(来源文件+字段名)、突变源(哪个投资/机制改它)、resolved 语义。条目编号 R01 起,供 §5 对照表与代码注释引用。

### 1.1 池与概率族

**R01 · 固定牌库总量(按费用档 a_c)**
- 基础值:【源】`cw_shop_odds.POOL_COPIES_PER_CARD`(1/2费=27、3/4/5费=9)。
- 突变源:黑塔纪元(id 352601,216 张【黑塔】特殊池,明示「商店能继续刷新」);专家顾问族(见 R02);人才下沉(id 121)与市场活力(id 200801)若实际改池构成则属本条辖域(**现 abandoned,见 §2**)。
- resolved 语义:resolved 固定池 = 基础 a_c ∘ 池构成族突变(改 v_c/a_c 者重生成整表);二/三/四费援军、扩充团队、广聚天下英才等**一次性发放**不改 a_c——发的角色直接进持有,经 R02 池不变量自动离池,无需登记为池突变。

**R02 · 同费用种类数(v_c)与池不变量(建模指令)**
- 基础值:【源】`cw_shop_odds.DISTINCT_CARDS_PER_COST`(从 `cw_chars.CHARACTERS` 派生,禁写死);【源】`cw_shop_odds.SHOP_SLOTS`(=5)。
- 突变源:专家顾问族——「使其在本局游戏中加入商店」十余张(特邀专家:停云/加拉赫/银狼/桑博 id 141-143/148、摸个鱼吧 I/II/III、加拉赫顾问、停云顾问、佩拉、姬子、琼玉/贸易/调饮/锻冶专家等,通道=投资策略/投资环境/专家邀请函三通道,economy.md §1)——入池后该专家费用档 v_c +1。
- resolved 语义(**池不变量**,【已裁定】用户 2026-08-31,建模指令):
  - **剩余牌库 = resolved 固定池(R01) − 持有副本总数**(2★ 计 3、3★ 计 9);
  - **不设「卖出回池」事件、禁独立跟踪池状态**——买/卖/合成只改持有计数,池随不变量自动正确;
  - 推论(消费方直接受益):①买→卖往返池中性;②持有 2★ 期间等效压缩 3 张,卖出一瞬全释放;③「持有 ≥9 张清空该牌商店库存」按同一副本计数(3★=9 即清空);④压库期望价值按「持续持有的副本总数」计(p49 O-1 收口)。

**R03 · 刷新概率表 p(level, cost)**
- 基础值:【源】`cw_shop_odds.REFRESH_PROB`(Lv1-10 × 1-5费,实机 OCR 权威表)。
- 突变源:
  - **轮岗**(环境 id 114):每备战阶段随机翻倍一档费用概率。**激活语义已勘误(裁决记录:docs/develop/currency_war/redesign/decisions/dd-002-rotation-doubling-semantics.md——用户裁定方法论「结合游戏效果数据验证」首战命中)**:游戏原文「备战阶段开始时翻倍一档,每个备战阶段重新随机」= 选择后每阶段 100% 生效(每阶段重掷翻倍档);「20%」(ROTATION_CHANCE=0.2)是 replay 观测在场频率,不是机制概率——sim engine_p1:776 无条件 20% 掷事件系建模错误,Phase 4 被测体替换时必修(对已选轮岗的环境条件化)。【resolved 特例】概率条直接印在商店面板上,**读屏即真值**(`parse_prob_bar`),无需建模翻倍档;决策层实机=读概率条;sim 修复后按「已选则每阶段重掷翻倍档」建模(翻倍档分布=1/5 均匀系**建模假设,实机待核**)。
  - **市场干预**(id 102201):下一次和每 4 次刷新全 3 费面 —— 计数窗状态依赖(resolved,时效=计数窗)。
  - **采购专员·金/彩**(id 201201/303101):每 7/5 次刷新出 5 张同费(费用=备战席最左角色费用)——计数窗 + 板面状态依赖(resolved 语义同构市场干预)。
  - 市场活力/人才下沉(商店 2★ 直出概率)、概念股 ×15(阵营刷新率提高):【abandoned】(API 无数值,invest_effects §5;价值主体留选卡分)。
- resolved 语义:消费点读**合成后的单一概率表**;轮岗在实机=直接消费观测概率条(它是「基础表∘轮岗」的实读 resolved 值),无观测帧退基线表并告警。

**R04 · 商店槽位数**
- 基础值:【源】`cw_shop_odds.SHOP_SLOTS`(=5,注释明示「不考虑昔涟诗篇」)。
- 突变源:昔涟诗篇类非 5 槽商店(01 §4.10 池结构突变语境)。【gap】V4.4 注册表无此条目,登记位空缺——采集后入 `INVEST_MUTATIONS`。
- resolved 语义:超几何/二项模型的格数参数随 resolved 槽位数取值;当前实现恒 5,resolved 层必须暴露为可变参数位。

### 1.2 经济参数族

**R05 · 刷新单价(c_refresh)**
- 基础值:【源】`cw_economy.SHOP_REFRESH_COST` = 2 / `cw_state.REFRESH_COST_BASE`(建模常量,OCR 徽标误读已裁撤,ADR-0456)。
- 突变源:
  - **长线利好**(环境 id 120):累计 30 次付费刷新后本局 1 金/刷,**另一次性 +20 金(30 刷达成时派息——金日程须计入这 20 金)**——【resolved】计数器状态依赖;机制真值在 `cw_invest_data`(运行时注册表,游戏数据单一源),无开关(原 registry 折价接线 `longterm_refresh_threshold/longterm_refresh_price` 已随 dd-009 清退删除,现刷价实现不消费该折价)。
  - **概率事件**(id 300401):45% 概率免费刷 → **期望刷价 1.1**(期望口径,01 §4.10 经济参数族在册例)。
  - **免费刷新额度族**(加油站 200301/存款回报 100501/合并同类项 102901/武力刷新 101801/固定理财/高效决策 301701/市场干预赠 5 刷/搜打撤):每节点/条件 N 次免费——【resolved】`EconomyEffect.free_refresh_per_node` 聚合,add 合成(现实现 `_refresh_cost`/`roll_affordable` 消费)。
- resolved 语义:第 n+1 次付费刷新实付 = max(0, base ∘ 折价突变) − 免费额度余量折抵;期望口径变体(概率事件)供 EV 层,实付口径供执行层,两口径不得混用。

**R06 · 经验单价(c_xp)**

  - **息结算时点 = 节点结束/下一节点开始(两者等价**,用户裁定;p47 A2 收口,节点内金位波动不入账)。

## 3. structured resolution semantics(解析语义结构)

每条突变在 `INVEST_MUTATIONS` 登记为四元组(01 §4.10):

```
(操作数 operand,     # 被改写的 resolved 量 = §1 的 R 编号
 合成律 combine,     # min | max | add | 互斥(登记位声明)
 状态依赖 state_dep, # 无 | 计数器(如长线利好 30 刷/市场干预每 4 刷)| 条件(如成长的快乐 level≥8)
 时效 validity)      # 永久 | 计数窗(如节省工位 3 节点)| 条件移除(如 E2 刷新顶替,实机核)
```

### 3.1 合成律语义
- **add**:代数和(例:成长的快乐 −1 + 商业间谍 −1 → c_xp 4→2)。
- **multiply**:乘法(例:轮岗 = 概率表 ×2——**cw3 实现已在用的律位,本清单补登,文档审计 F4**)。
- **max/min**:取上/下界语义(保留给未来的对称突变;当前在册例无)。
- **互斥(override)**:登记位声明;**首个生效,后续登记为 suppressed**(实机核)。适用:息律 cap 族(R10)、卖出退金 ×2(R13)。
- **异构操作合成序 = 按操作数分层:override 类先于 multiply 类先于 add 类,层内按注册表登记序;合成是分层流水线,任何一层不短路**(例:市场干预 override 概率表 × 轮岗 multiply 概率表,先 override 后 multiply;override 后其余层照常合成——文档审计 F1)。
- **期望口径变体**(概率事件刷价 1.1)是**独立操作数位**(c_refresh_exp),不与实付口径(c_refresh_paid)互混。

### 3.2 状态依赖
- 计数器型突变需要局内计数输入(付费刷新计数、合成次数等)。**当前无观测的计数器 = 开臂判据挂账**(先例:`refresh_count` 缺省 0 → 长线利好永不生效)。计数输入的供给缺口在登记位显式声明,不静默。
- 条件型突变以 GameState 字段为条件(level/bench 占用/位面),resolver 逐帧求值。

### 3.3 时效
- 计数窗/条件移除突变到点后从已激活集移除;移除事件本身也是决策点时(E2 刷新顶替/E15 期权触发),登记 `on_expiry` 消费点。

### 3.4 未登记突变的运行时检出
resolved 读到未在册突变 id 时:**保守降级(按基础值消费)+ 告警入日志,不静默**(01 §4.10)。禁止各机器自选合成方式——消费点只读**合成后的单一 resolved 值**。

## 4. 访问接口契约(决策层取数形态)

### 4.1 函数签名形态

输入恒为 **(GameState, 已激活突变集)**,输出为 resolved 量;决策机器**只准经这些入口取数**:

```python
# 突变激活记录(经 E1/E2/E15 选择、被动获得、角色技能、任务奖励入集)
class MutationActivation:      # id + 登记四元组 + 激活时点/来源
    ...

# 统一解析入口(Phase 3 命名落点自定;形态为准)
resolve_pool(state, mutations) -> dict[cost, tuple[v_c, a_c]]      # R01/R02:resolved 固定池
pool_left(cost) = fixed_pool - held_copies(state)                  # R02:不变量派生,禁独立跟踪
resolve_shop_slots(state, mutations) -> int                        # R04
resolve_refresh_cost(state, mutations, paid_refresh_count) -> (c_paid, c_expected)   # R05
resolve_xp(state, mutations) -> (c_xp, xp_per_buy, xp_table)       # R06/R07
resolve_levelup_currency(state, mutations) -> ('gold'|'hp', rate)  # R08
resolve_income(state, mutations) -> IncomeSchedule                 # R09/R12:逐组分(基础/连胜/败轮/金流日程)
resolve_interest(state, mutations) -> (I_cap, interest_fn)         # R10/R11
resolve_sell_refund(state, mutations) -> refund_fn                 # R13
resolve_board_predicates(state, mutations) -> (max_units, bench_cap, bond_cap)  # R14-R16
resolve_prob_table(state, mutations, observed_probs | None) -> p(level, cost)   # R03
```

### 4.2 派生量的计算责任边界(谁算什么)

| 派生量 | 计算责任 | 输入(全部 resolved) |
|---|---|---|
| 剩余牌库 pool_left | resolver(按 R02 不变量派生,**禁跟踪池状态、禁卖出回池事件**) | fixed_pool, held_copies |
| 利息上限 I_cap / 利息额 Ī | resolver(R10/R11);**息档损失 L 的递推归 p47**(消费 resolved I_cap,不自带 5) | gold, cap 突变, 狸狸 +2 |
| 刷新期望次数 E[refreshes] | `cw_shop_odds.expected_refreshes`(单一源;消费 resolved p/v/a/格数) | R01-R04, R03 |
| 完成概率/金日程 | p38(⑤层金位递推以 resolved income+Ī 为输入;场景快照由 §4.4 消解协议供给) | R05-R12 |
| 升级 EV / 整买目标线 S | p39 / p48(消费 resolved c_xp 与币种;血本位安全带=R08) | R06-R08 |
| 囤积/卖出定价 V_opt/V_slot | p41(卖出价值 = resolved sell_refund + 槽位释放价值) | R13, R02 |
| 压库 EV | p49(按「持续持有的副本总数」计;resolved 池上全表重算后方可消费) | R01-R03 |
| 装备/回收/工具 | p42/p50(E10/E11;喂件纪律 [42]) | R19 工具族 |

**总则**:同一 resolved 量只允许一个计算责任点;证明件消费 resolved 接口,禁止在证明/机器内部内联基础值或自选合成方式。

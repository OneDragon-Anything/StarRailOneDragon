# 终局希儿量子条目改档（详设）

## 问题与约束

- 边界：只改 `COMP_LIBRARY`「希儿量子」一条 + 词缀减分表注释；不动其他 20 条终局条目、不动锁定机器（line_select/evaluate_lock）、不动 deploy_search 终局侧。
- 总纲契约 A：本篇落地后 `COMP_LIBRARY` 内 `or_reqs` 清零（form_progress 对希儿量子按纯 AND 折算）；**全库**清零在详设二替换过渡条目后达成（中间态 = 过渡库旧「希儿引擎」条目仍持 `or_reqs`，OR 机器保持可运行），机器删除归详设三。
- 依据（游戏知识，final_seele_quantum.md 构造机理节，n=67 全量深读）：
  - 类结构 =「量子4+贝4 双修（36/35 篇，几乎不分离）」；
  - 羁绊激活实证：量子3 64/67、贝2 64/67、量子4 57/67（过半上 4 档）、战技点2 53/67、治疗2 36/67、盛会2 33/67、列车2 31/67；
  - 节奏：「贝洛伯格 2贝起步，至少 2 尽量追 4」——贝2 是过渡值、贝4 是终局值；
  - 机制：量子同频 = 易伤（15/30/60/100% 四档），贝洛伯格 = 造物引擎拉条（让伤害最多的贝成员立即行动 → 希儿拉条正循环）——两层乘法关系，双修即唯一主流终局形态。

## 方案

### 1. 条目改档（cw_comps.py）

```python
Comp(
    name="希儿量子",
    core_chars=["希儿", "花火", "符玄", "缇宝", "刻律德菈"],   # 引擎核心组，实证 53-67/67，不动
    faction_reqs={
        0: {"量子同频": 4, "贝洛伯格": 4},   # Final 完全体，纯 AND；删 or_reqs
        1: {"战技点": 2, "治疗": 2},         # 从 flex 升加分层：部署次层 + 采购面覆盖，不进成型判定
    },
    required_deployed=("希儿",),              # 保留：「希儿到手即开线」语义由这条承载
    flex_factions=["盛会之星", "列车同行"],   # 战技点/治疗升档 1 后从 flex 移除
    # key_equips / equip_assign / shared_chars / need_star / key_items / char_positions：全部不动
)
```

- 其余字段（装备公式/星级/骨架/站位）与本迭代无关，逐字段保持原值。
- `SEELE_OR_REQS` / `SEELE_CARRY_CHAR` 常量随详设三删除；本篇阶段该条目不再引用 `SEELE_OR_REQS`（`required_deployed` 直写字面量 `("希儿",)`，等详设三删常量时一并核对该字面量与 `SEELE_CARRY_CHAR` 同值——本篇落地时保留常量定义不删）。

### 2. fp 行为核算（form_progress 只折档 0 + required，档 1 不进——cw_comps.form_progress 现行实现）

新 fp = (min(量,4)/4 + min(贝,4)/4 + [希儿在板]) / 3：

| 板面 | 旧 fp（OR 折法） | 新 fp |
|---|---|---|
| 希儿 + 量1 | 0.75 | 0.417 |
| 希儿 + 量2 | **1.000**（旧判据即「成型」） | 0.500 |
| 希儿 + 量2 + 贝2 | 1.000 | 0.667 |
| 希儿 + 量4 + 贝2 | 1.000 | 0.833 |
| 希儿 + 量4 + 贝4 | 1.000 | 1.000 |

- commit 线（`COMMIT_FRAC = 0.4`，装备工具激活面）：希儿+量1 = 0.417 仍过线——「到手即开线」不丢；希儿+量2 不再虚假满成型。
- 档 1（战技点2/治疗2）效果 = deploy_search L2 层开始追副档完成度、`_line_hoard` 采购集经档 ≥1 键阵营展开覆盖战技点/治疗成员——行为增强方向与实证（53/67、36/67）一致。

### 3. 连带核对（本篇范围内）

- `cw_intention.TRANSIT_AFFIX_PENALTY` 注释「克希儿引擎」措辞随条目名变化更新（详设二替换过渡条目后统一改）；表数据零改动（键 = 羁绊名，希儿量子终局线的词缀面走 cw_affinity_table 线级登记，不受改档影响）。
- `cw_affinity_table` 希儿量子行（量子熄火重开级/蕉研组 boss）按线名索引，零改动。
- LINE_ANCHOR['希儿量子'] = '希儿' 数值不变，零改动（五源统一属外溢项）。

### 4. 行为变化申报

1. 希儿量子终局线成型判据：`希儿在场 ∧ (量≥2 ∨ 贝≥2)` → `希儿在场 ∧ 量≥4 ∧ 贝≥4`；
2. fp 分度恢复（上表）——影响 commit 判据、囤货/升级消费 fp 的全部读点的分度（不改变其他线）；
3. 战技点/治疗从 flex 升档 1：部署次层与采购面新增对这两羁绊成员的覆盖（板面/买入行为增强）。

## 关键取舍

- **放弃「档 0 保留量4贝2 + or_reqs 承接」的兼容写法**：承接规则本身就是被退役的病灶（档 0 变死数据），保留 = 保留病灶。
- **放弃「贝洛伯格档 0 定 2（过渡实证值）」**：终局判据按终局实证（贝4）；贝2 的过渡期价值由过渡层组合条目承载（详设二的「希儿贝2」构造块）——两层判据归位，各自单一。
- **战技点/治疗定档 1 而非档 0**：档 0 是成型判据（全 AND）——实证 53/67 与 36/67 不到「成型定义」强度（对比量子 96%、贝 96%+），进加分层是 Final 标准式「量子4+贝4+战技点2-3+治疗2」的忠实分层映射。

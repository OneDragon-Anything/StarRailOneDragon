# 0151 策略语义绑定逐卡手建模(↺ ADR-0134 文本扫描派生)

## Status

accepted(2026-08-16;用户定调:"还是逐个按意思来建模吧,采集器如果发现效果和上个版本不一样,要提示,让你来重新建模"+"有不确定就加个标记,后续找我确定")

## Context

ADR-0134 把 `strategy_bindings`(阵营/角色绑定)实现为**运行时文本扫描**(注册表键 ∩ name+effect 子串),理由是零维护。ADR-0150 换 plaza 官方全文后探针审计:

- 101/335 有绑定,其中两类**语义噪声**:泛用卡因效果顺带提及阵营/角色误绑 —— 战术义眼(泛用回能,绑了"能量")、生命之花祝福(泛用治疗强度,绑了"治疗");
- 绑定结果**不可审不可纠**:只存在于每次调用的瞬间,无处看全量、无通道纠错 —— 而绑定本质是建模知识(comp 匹配/持卡 pivot 的输入),应有可审阅的载体。

## Decision Drivers

- 绑定是选卡主链路输入(decide_event comp 匹配分 + held_strategy_fit pivot),质量应可保证、可审计;
- 版本更新时效果会变,建模需与数据同步的**提醒机制**,否则静默过期;
- 用户要逐卡语义判断,不确定处显式标记待确认,不静默猜。

## Considered Options

- **维持文本扫描(0134)**:零维护但噪声不可纠,审计已证有两类误绑 → 弃。
- **生成器冻结进 base(随 API 生成)**:绑定依赖 FACTIONS/CHARACTERS 活注册表,冻结后改表即过期,跨注册表对账 → 弃。
- **import 时派生表 + override 通道**:自动派生保留噪声问题,override 修不过来 → 弃。
- **✅ 逐卡语义表(手维护 overlay)**:与 STRATEGY_ECONOMY 同模式;判据显式(效果引用 comp 专属机制/召唤物/星徽/赠 key 角色 → 绑;泛用数值 → 不绑);孤儿键 import 即 raise;`# ?` 标记待确认项。

## Decision

1. `STRATEGY_BINDINGS: dict[str, tuple[frozenset, frozenset]]` 87 条(套组 42/机制强化 19/赠角色·专家 26),`strategy_bindings()` 改查表;未建模卡 → 空绑定(回落评估分,不炸)。孤儿键构建层 raise(同 ECONOMY)。
2. **噪声清除落地**:战术义眼×3/祝福系×4 等泛用卡不再误绑;此前 comp 命中时 +65 的伪分消失,回落 PICK_VALUE(如 生命之花祝福 46)——语义正确的降权。
3. **环境侧补齐**:6 张契约卡(量子同频/公司/持续伤害/战技点/星核猎手/欢愉)效果=获赠该阵营角色,补进 ENV_FACTION(原 overlay 只收概念股/邀请/命运圣杯契约)→ 契约类吃 ENV_FACTION_MATCH_FLOOR=72 的 comp 匹配分。
4. **版本更新提醒闭环**:gen_plaza_invest.py diff 报告对「效果变」条目逐条列 id+名,并打印提示「需重审 STRATEGY_BINDINGS/STRATEGY_ECONOMY/ENV_CATEGORY·ENV_FACTION」→ 语义建模过期不再静默。
5. **`# ?` 待确认标记**(用户确认后删):按劳分配(经济上限随战技点档位,算不算绑)、步狸村之谜(经召唤物穿戴星徽间接绑狼狩)、盗用身份(绑列车同行来自所赠星徽)、飞光·传剑(神君引用+双仙舟角色)、偶像经济(火花变体)、特邀专家:加拉赫→击破(机制挂钩非赠角色,环境侧暂注释不绑)。

验证:绑定表守卫 3 测试(键值合法/噪声清除/语义抽查)+ 契约环境阵营;CW 全套 413 passed。

> 术语(首现定义):**终局线已锁定**(下文简称「锁定」)= 锁定线槽 `StrategyState.target_comp` 非空(一次性写入,锁后只读;`ist.locked_comp`/`ist.phase` 为其 kernel 派生缓存);**候选**(实候选)= 未锁定期经证据门入选的线分数 top3 线(零证据线不入,§1.2);**过渡候选** = 过渡阵容库条目候选机器 top3(§3);**过渡阵容库** = `cw_comps.TRANSITION_LIBRARY` 登记的开局过渡组合条目(构造式生成,与终局线 `COMP_LIBRARY` 两套独立库,§3);**线分数** = 统一评分公式的单值和(§1.1,纯加权零特例);**重开级** = 数量级表的最大负档(排除 = 极大减分,任何构局正项和追不上);**知识卡** = `kernel/cw_comps.py::COMP_LIBRARY` 每线登记的玩法知识字段(need_star 必要星级;原 key_items 跨阶段体系件名单、entry_signals 上线窗口字段、transition_chars 按线过渡打工名单均已整体退役);**帧** = 决策循环的一个观察-动作周期;**单一源** = 某语义在全仓只有一个权威定义处,其余一律引用不复制;**fail 方向** = 判据未验证或输入缺失时缺省行为取保守侧的约定。

## 1. 选线函数(统一阵容评分)

机制形态:`f(局面状态) → 「未锁定(top3 候选已登记)」 | 「锁定线 X」`(一次性决策,锁后不换)。实现载体 = `strategies/impl/mandate_v1/line_select.py`(线分数/候选/锁定判定) + `session_scope.py`(状态重算与锁定写入)。**纯加权和一个公式**(2026-11-03 用户裁定:特殊处理全退役——排除位/角色硬锁/策略即时锁/defining 标记/counters_dot 排除;排除 = 极大减分,非布尔特判):防摇摆不靠滞后余量靠结构(锁后不换线 + 数量级支配)。

### 1.1 线分数(单值和)

```
线分 = 证据分(carry + 插件 + 装备件 + 热度)
     + 投资环境分 + 投资策略分(通道派生)
     + 词缀分(吃怕表: 强吃+/怕−/重开级−极大)
     + 敌情克制分(boss 分 = Σ三只克制,均权 + 非 boss 强敌分,§1.1 末条)
```

- **数量级表**(层间支配靠数量级实现;常数单一源 = `kernel/cw_line_scales.py`,本篇只写常量名):重开级 `RESTART_PENALTY`/万敌无燃料底线同档;carry·anchor `CARRY_ANCHOR`(线攻略引用核心,`LINE_ANCHOR` 表 21 线逐线登记,姬子 A/B 两套同引用)/carry·其余 core `CARRY_CORE`(攻略主次语义:非引用 core 减半)/插件 `PLUGIN_BONUS`/**装备件同插件档**(批 3:key_equips 逐件持有 `PLUGIN_BONUS`——同为「线构成件的持有实证」,装备证据只排序不点亮,证据门不含装备分量)/攻略热度每点 `HEAT_PER_POINT`(满热度 274 < 1 插件——持有实证 > 社区先验)/词缀强吃顶级 `AFFIX_STRONG_TOP`·燃料 `AFFIX_STRONG_FUEL`/投资定义卡 `INVEST_DEFINING`·强档 `INVEST_STRONG`·实证覆盖升档 `EVIDENCE_UPGRADE_BONUS`(量子星徽×3→希儿/罗刹→列车 A/B 两套)·中档 `INVEST_MID`/软档 `INVEST_SOFT`(降档落点:加分层键与 flex 命中的强档→+30、中档→0)/怕 `FEAR_PENALTY`。

### 1.2 候选管理(未锁定期)

- 每帧对全部线算分,**top3 为候选**(候选数量 = `CANDIDATE_TOP_N`,用户立场值);候选快照 = 派生态(每帧随签名重算,非持久状态;锁定写入后清空停算)。**候选入选证据门**:线入选实候选 ⟺ 线分数的证据门分量为正(env〔投资通道〕∨ carry ∨ 插件 > 0——`LineScore.gate_positive` 命名访问,**不含热度**;`compute_candidates` 证据门开启版,候选快照消费;其余调用方缺省全量版)——零证据线不入候选,攻略热度降为**有证据线之间的排序**,不再是入选理由;开局零持有零投资 = 空候选(合法形态,买入/环境/发放逐步点亮入选)。
- **候选双层结构(终局层 + 过渡层)**:终局候选(实候选)= 上述证据门版线候选;过渡候选 = 过渡阵容库条目候选机器(`cw_intention.update_transition_candidates`:过渡库条目按〔持有分 − 克制减分〕排序取 top3,§3)。两层候选分别驱动终局义务面与过渡层贡献,载体 = `line_candidates` 快照与 `transition_candidates` 槽(§2);成员档双层装配 = [32_unified_sell_priority.md](32_unified_sell_priority.md) §2。
- 候选变动:进榜线开始囤件;掉榜线已囤件保留不再新增(1★ 可全额退,不亏);实候选退出 = 证据消失(卖出唯一副本)或被更高证据线挤出 top3。
- 采购纪律(义务面单一面):**义务面** = 实候选(证据门版)三线成员并集 ∪ 过渡候选各条目成员并集(与统一价值序成员档族〔档 2/3/4/5/7〕名单同源——买面与优先级面同一份名单,免息待遇 + 获取受阻〔席满 ∨ 金不足〕统一走获取让位评估,原会话内筹资已并入该评估,[11_shop_decisions.md](11_shop_decisions.md) §4.0);非义务面成员商店见到不买(万金油角色只在恰为候选线/锁定线成员时按序 1 买入,手里持有的未到两星前受统一价值序档 8 保护、无自动补货通道;原「保护集囤货面」为期权级囤货——首副本走囤货臂、买因 `protection_hoard`——已随囤货臂退役拆除:囤的换线期权在锁定后不换线制下无兑现通道);+ 候选件没有而金有余时按费用档判据买牌压牌库(不限候选线;[31]②/[34] 既有纪律)。
- P1 板面恒过渡体系(战力资源约束,与方向正交);过渡体系选与榜首候选重叠的(转正不废件)。**过渡锁定局的采购通道**:过渡锁定后序 1 名单 = 过渡锁定条目成员 ∪ 终局候选三线成员并集(过渡板面 + 终局积累双目的);终局锁定后切锁定线名单单源(过渡层整体退役清空,退出条件 = 终局锁定写入,§3 生命周期)。
- 升级触发口径:锁定后最优概率带单判据三分派([11_shop_decisions.md](11_shop_decisions.md) §2),未锁定期零主动升级(带驱动辖域外,候选缺件刷新承接——原「概率账缺件集并集口径」随概率账臂删除消亡,无聚合消费面);义务面身份判定源 = 候选快照(k_members 未锁定期为空,义务身份集 = 候选 top3 线内成员)。

### 1.3 锁定(P2 时点兜底唯一路径)

| 触发 | 判据 | 时点 |
|---|---|---|
| **时点兜底(唯一路径)** | 时点到 → 锁定 top3 中分数最高者(候选元组已按全序降序,取首);**空候选兜底**(证据门下可达,真规则):候选空 → 锁全 21 线全序首名(缺省全量版重算取首;零证据帧首名 = 热度首线,现行全序的退化情形) | 第二位面已启动 ∧ P2 起首次投资策略三选一完成帧 |

- **硬规则/即时锁全退役**(2026-11-03 用户裁定「全退役」:拿到什么都不直接锁,分数说话):角色型硬锁废(核心在手 = carry 证据分 `CARRY_ANCHOR`/`CARRY_CORE`,数值必然性替代);策略型即时锁废(强关联投资 = 通道派生加分进线分);知识卡 `lock_rules` 字段随之整字段退役(值并入通道派生/证据分,git 历史可溯)。候选构造 = 证据门 + 线分排序,**无排除过滤**——重开级已数值化(含重开级命中的线分恒低于无命中线)。
- 时点兜底触发分支:`plane2_started`(窗口谓词,首入 (2,*) 段置位——P1 内即时/延迟加场卡被结算节点边界引用排除)∧ `p2_strategy_pick_done`(P1 滑动基线 + P2 集合增长侦测;增长来源不区分选卡/节点赠得——对「策略已定 → 可兜底」语义等价;bot 视角完成帧 = 获得后的首个决策帧)。
- **锁定效果**:买牌、升级窗口、装备定向、上场窗口全部围绕锁定线;装备合成材料开始定向留存。锁定写入与连带动作的唯一所有者 = `session_scope.write_line_lock`(§2),禁绕过直写键跳过连带。
- **投资选卡端消费本判定面**:投资环境/策略两屏的阵容冲突护栏,未锁定帧 = 候选与已持有投资(环境+策略)的阵容指向集比对,锁定帧 = 与锁定线 factions 比对(锁后历史误持不入基);护栏只读「锁槽非空 + 锁线 factions + 持有投资名」现值,不读方向层状态、不进 committed 语义,与方向层读口无耦合(权威版本 = 29/28 号稿 §3)。

### 1.4 锁定后

- **不设主动换线**(用户立场:自己玩都很少中途换——「搜不到 → 转线」类预案已被锁定前评估吸收:搜不到的线分数起不来,兜底锁定时自然不选它)。
- 唯一线内调整 = **星级 = 必要星级表驱动,无降档规则**:每线每角色按攻略登记必要星级(知识卡 `need_star`;CARRY 按星级饥渴数据标 2★/3★,辅助标 1★)。定义 3★ 就追到底,无降档;定义 2★ 的线 2★ 即完成。星级是刷新停留的自然积累(刷新判据 = 星级目标驱动,[11_shop_decisions.md](11_shop_decisions.md) §3),不是独立管理对象。
- 等级被硬需求推过目标最优概率带的形态 = 当前等级即剩余可达最优——照样停留刷新(可达最优等级模型,[11_shop_decisions.md](11_shop_decisions.md) §2 停留门)。

## 3. 过渡阵容库与条目候选机器

未锁定期的过渡方向由**过渡阵容库条目候选机器**承载(与终局线的「候选→锁定」机器同构;kernel 驱动 = `cw_intention.update_transition_candidates`,flow 方向节拍贵段调用,窗口守卫 = 未终局锁定帧)。两套阵容库独立、各自候选与锁定,互不覆写。原体系对配方机器(门控-冻结-封印状态机/体系对域/伪阵容物化链/组合选卡)与更早的四层谓词族已随结构统一迭代退役(退役登记 = math_proofs P-T166 行等,考古走 git 历史)。

- **过渡阵容库**(`cw_comps.TRANSITION_LIBRARY`,恒 C(5,2)=10 条组合条目,建库期构造式生成):条目复用 `Comp` 结构,羁绊要求只填 `faction_reqs` 档 0(低门槛快锁口径,完全体档归终局线自己承载)。**生成机制**:五构造块表 `TRANSITION_BONDS`(构造块 = `TransitionBond`:块短名/羁绊键/达标人数阈值/点名件与星级目标/羁绊半边计分开关——旧三型知识〔点名/羁绊/混合〕收进构造块字段)两两组合(`itertools.combinations`),建库期生成器 `_build_transition_combos` 物化为静态条目——**过渡候选域 = 该组合条目库的静态枚举**;构造块本身不是阵容、不进库、永不锁定。字段合并规则(点名件保序去重/档 0 = 两块键 AND/星级目标合批/`required_deployed` = 点名件全部在板)与建库校验五条(含点名件费段须位面 1 商店可刷,违反即建库期报错)单一源 = `cw_comps` 代码注释;条目名 → 两块名映射单一源 = `TRANSITION_COMBO_PARTS`。
- **计分三面**(与终局线分同构的统一评分,纯减分制无特殊逻辑;计分与排序单一源 = `cw_intention.transition_scores(held, sources)` 纯函数):**持有分** = 条目计分基准集(`transition_member_set` 单一源,combo 展开 = 查 `TRANSITION_COMBO_PARTS` → 两块计分域并集)∩ 持有(在场 ∪ 备战席)的成员数(开局全 0);**词缀/boss 减分面** = 开局简报已观察克制源(词缀 ∪ 位面 1 boss)命中条目档 0 键(`TRANSIT_AFFIX_PENALTY` 表)每条源固定减 `TRANSIT_AFFIX_PENALTY_SCORE`(量级同终局怕档;简报未观察帧不触发,fail-closed;终局线分的词缀/boss 面不动,线级登记更细,两表数据同源、粒度分工);**候选** = `transition_scores` 过滤总分 > 0 按(分数降序, 注册序)取前 `_TRANSITION_CANDIDATE_TOP_N`(与终局候选数同值)写 `transition_candidates` 槽(存条目名;排序键在函数内单一实现,禁调用侧自排——排序分叉会使虚拟候选序与实机锁定序分叉)。
- **锁定评估域 = 候选槽内条目,锁定对象 = 组合条目**:候选槽内条目 `form_progress`(条目, 板面) ≥ 1.0 即锁 `ist.transition_locked`(锁定条目名;写端单一 = 候选机器)——锁后不换、不解、不重评。**组合成型才锁**:fp ≥ 1.0 ⟺ 两块羁绊都凑齐 ∧ 点名件全在板(档 0 两键 AND + required 折条);单羁绊凑出时任何组合条目 fp < 1.0 自然不锁(单羁绊局保持软方向——候选继续活动、买面双向,直到组合凑齐或终局锁定统一退役);候选外条目偶然凑齐羁绊不锁(计分门控防偶然锁定)。原三态状态机(门控-冻结-封印-重冻结)语义整体废止。
- **买牌虚拟评估臂共用计分**(过渡货架资格臂,买因 `transition_shelf_qualify_buy`,义务类管线与门链归 [11_shop_decisions.md](11_shop_decisions.md) §1 序 1 扩展臂族):触发窗 = 未终局锁定 ∧ 过渡未锁定(过渡锁定后买面 = 锁定条目成员域,「锁后不换」与方向点亮语义互斥);资格判据(窄门,与终局侧同构) = 货架牌 ∈ `transition_scores(在手 ∪ 货架, 简报克制源)` 前 `_TRANSITION_CANDIDATE_TOP_N` 条组合的计分成员域并集(`transition_member_set` 单一读口展开)——虚拟候选语义 = 「把货架全买了之后的过渡候选」,与实机帧共用同一计分排序函数(对返回列表纯切片取前 N);**零持久化**(即算即用,不写候选槽——实机候选槽语义 = 实持有证据的方向,锁定评估域依赖它防偶然锁定,虚拟结果落状态会污染锁定域)。买入写持有 → 下一帧候选机器重算 → 候选真实跟随(与终局侧「信号进 → 买入 → 点亮」闭环同款);与终局资格臂并存互补:终局侧不点亮的过渡件经组合计分域点亮,同帧终局资格件先消费。
- **冷启动承接**:候选槽为空的帧,买面回退目标 = 过渡库全体条目见即买并集(`transition_library_buy_now_union` 单一源;商店冷启动臂与囤货回退的键域同源派生)——见即买 → 持有 → 计分 > 0 → 候选形成 → 方向确立,死循环闭环。
- **生命周期挂钩终局锁定事件**(不挂位面切换):终局锁定写入(`write_line_lock`)→ 过渡层退役清空(候选槽、过渡锁定态、囤货过渡带),清空出口 = 终局锁定写入点;位面切换不触发退役。凡属过渡机制开闭的按位面判定一律改读终局锁定态——现行终局锁定仅在位面 2 触发,位面 1 行为与旧按位面判定逐位等价;将来终局锁定时点若变,过渡层自动跟随。
- **板面执行分立(部署统一批并入统一结构)**:过渡方向是**方向层产出**——决定 P1 朝哪个过渡条目买/攒,不直接驱动板面;「谁上场」= 统一部署搜索评分定型([24_deploy_segment.md](24_deploy_segment.md) §1),板面不消费候选序——部署侧的同分防摇摆由搜索的稳定键(与现板面一致数)承载。
- 配方对评估数据表引用已收尾(统一保护集迭代末阶段):TRANSITION_PACK 候选体系表及档位标签符号已删除(`knowledge/cw_line_facts`,design §2.4 三判据清点裁决)——身份消费面已全部迁保护集/注册表现算(买面序 1/囤货臂/D7 拒因/hold 登记档位);非身份档位消费迁 `framework_members` 注册表现算(bond_members 派生;原部署围栏 fw_carry 消费面已随部署统一批并入统一结构删除);零生产消费方的休眠框架选线判据族(`cw_transition.pick_framework`/`transition_score` 等)随符号退役。投资选卡帧喂入 CommitSignals 保留(纯遥测,决策面零消费)。
- 过渡锁定后机器照常运行:`update_transition_candidates` 每轮重算候选槽(锁定条目外的候选照常排序),但锁定态不换(§锁定语义);终局锁定写入点整体退役清空。

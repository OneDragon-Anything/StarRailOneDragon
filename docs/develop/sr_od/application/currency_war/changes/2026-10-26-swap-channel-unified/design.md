# 转型域换人通道统一设计 迭代设计（总纲）

## 0. 元信息

- 迭代目标：用户裁定 2026-10-26（登记载体 = 本迭代进度账本 T-1 note）：换人策略按羁绊组双门 + 转型域统一收益-安全框架落地（治本方案）；净战力不证明（宪法第 1 条禁战力建模），行为锚点验收；P61 证明退役。
- 状态：对抗审中
- 文档清单：无详设（单文档方案，本篇即完整设计）

## 1. 问题与动机

- 现状症状：sim 局 g_20261026_203023（seed=20261216）复盘立案 C1——2-1 买主线核心 Saber 后 4 个备战期换人卖出 0 发射，板面保持位面 1 过渡配方直到死亡（复盘报告 = `.debug/currency_war/deep_review/g_20261026_203023.md`）。历史同病：strategy-docs/02_mandate_layer.md §1 A/B 归因「没做占绝对主导（部署 0/934）」；2026-09-18 板满换入分支为同病第一件补丁（`kernel/cw_deploy_logic.py` `required_swap_arm_pending` docstring 出处行）。
- 根因归层：**语义层 + 约定层**。语义层 = 换入判据语义单位错置（单件「一步成型」对多成员多档位阵容结构性不可达）。约定层 = 同一换人动作帧上**多层独立判据**（触发/守恒/素材/放行/窗口）层层封堵，各自演化：判定对象不一致、守恒对象与口径不一、判据折法不一（✗→✓ 与 Δfp 并存）——多层协作无统一「收益-安全」判定约定。**只修触发层不达效**——其余层照样封死同一批 victim。本迭代为同族病第二件，按跨件半问升架构级：公共根 = 协作约定缺失。
- 解决到哪：**转型域**的五层统一到单一判定原则（§2.0–§2.8）；P61 退役（§2.9）；现行转型分支机器（`SWAP_TRANSITION_ARM_ENABLED` 族）归宿裁定（§2.3.1）。
- 明确不解决：**双轨域（P1 配方对锁期）换人行为——现行机器原样保留**（2026-09-18 配方完成件通道继续服务其域，本迭代不触碰，§2.3）；买入面（M2/商店判据）；sim 战斗结算与 hp 校准；净战力强弱证明；经济/升级判据本体（放行层复算接线与来金资格增补除外，§2.5/§2.8）。

## 2. 方案

### 2.0 统一原则（适用域 = 转型域）

**换人合法性 = 组换后板态 × 锁定终局阵容。**

- **转型域判别子（单一源，钉死，三合取全继承现行语义）**：①锁定线槽非空（`locked_comp`/`target_comp` 腿①，`cw_intention.py` 判定权威腿①）**且显式排除 p1_pair 腿②**——`committed_authority` 全值（含配方对锁腿②）在配方锁帧也返 True，不可作本判别子；②**板满**（现行换人只在板满帧发，`cw_deploy_logic.py` `:775`/`:1666-1668`——不继承则与 M1 直上通道抢活白卖）；③**fp < 1.00**（成型帧不进换人域，现行键集回全量语义 `:545-547`/`:991`——丢弃则成型帧行为差未申报）。现行 `ctx.locked`/`_swap_transition_domain` 混轨不可用，本迭代新增专用判别子并让消费位迁移（§2.3.1）。
- **组换后板态** = 板上单位集合 − 换出 victims + 换入组 的派生视图；档位与支撑计数按 §2.1 在该视图上现算。
- 转型域内**统一判定函数辖域 = 触发/守恒/放行/换血让位四层**（同一函数，禁各层自备第二套折法）；素材层与窗口层保留各自折法——理由显式裁定：素材守卫 = 经济价值保护独立关切（非收益-安全判定）、窗口 = 上阵资格辖域（非收益-安全判定），两层的保留是裁定而非统一遗漏。

### 2.1 支撑件与档位（口径定义）

- **支撑件 = 终局名单成员（k_members）∪ 羁绊标签命中终局键集的外部件**（并集）。名单成员无条件计入；外部凑档件按标签计入。
  - 依据：`data/cw_chars.py` 标签实测（吉尔伽美什/Saber=圣杯+能量；开拓者·记忆/藿藿=含能量；瓦尔特/符玄不含；停云=仙舟+**能量**；远坂凛=圣杯+战技点；**青雀=仙舟+战技点**（:112）——战技点档已激活事实的承重标签；爻光非圣杯非能量）；键集 = `kernel/cw_comps.py` 双王圣杯 `form_tiers` 的键集 {命运圣杯, 能量}。
- **k_members 单一源** = `predicates.line_members`（core ∪ shared）；`required_deployed` 名（希儿腿）属 core ⊆ k_members。
- **档位语义源（显式切分，防值对标签错）**：`Comp.form_tiers` = **单阈值成型判据**（两键同时达标 = 阵容成型），**不是档位梯子**；本设计的「一阶/二阶/档位非降」语义源 = `data/cw_factions.py` 档位表**逐档计数**（命运圣杯 2/3/4/5 档、能量 3/5/7/10 档）。form_tiers 在本设计中承担三职：键集来源（支撑件判定）、成型判据（`readiness_form_ok` 现行，不动）、门 1④ 成品腿的 ✗→✓ 判据（§2.2）。
- **支撑件身份 ≠ 不可卖**：victim 资格由门 2 与 §2.7 victim 序独立裁定（§2.2.1 让位语义）——终局标签过渡件（停云/远坂凛类）既是支撑件也可作 victim，序上二级deprioritize（§2.7）；来金/演进侧的排除见 §2.8。

### 2.2 触发层：羁绊组双门

- **门 1（收益门，满足任一，对组换后板态判定）**：
  1. 激活终局羁绊新档位（§2.1 档位梯逐档计数）；
  2. 支撑件数严格增；
  3. 同名升星横换（换入件星级 > 被换件星级）；
  4. **成品腿**：组换后成型判据达成（`form_progress` ✗→✓，折法单一源 = `cw_comps.form_progress` 现行契约含 OR 组承接/required 腿）。
- **门 2（安全门，逐被换件）**：现行 `swap_sell_exclusion_reason` 资格面——义务集、新鲜度排除、资格族（`merge_material_guard` 素材守卫 / `star_guard` / `fp_unreadable` 等拒因面保留；`target_keep` 按 §2.2.1 口径收窄；`fenced_arm_closed` 守恒面按 §2.3.1 域切分处理——关门分支判定迁移到转型域判别子，双轨域照旧，**禁字面移植**否则情形 A 的 fence 件 victim 被封、C1 解锁点失效）。**守恒面域切分**：`engines_guard` 的守恒职在转型域由 §2.3 终局档位非降（=门 1① 档位面同一函数）承接，双轨域原样——门 2 的守恒面以本切分为准（交叉引用 §2.3）。

**§2.2.1 target_keep 口径收窄与让位语义（转型域）**：
- **身份保护面**：target 身份集 = **终局名单成员 ∪ 保护集**（现行 P78 保护语义，不变）。
- **让位路径（victim 合法性白名单，取代阵营视图恒拒）**：
  1. **纯过渡件**（终局键集零标签命中）：一级 victim，序优先（§2.7）；
  2. **终局标签支撑件**（非名单，如停云）：二级 victim，序deprioritize（§2.7）；
  3. **名单成员**：仅两条让位通道——**(a) 同名升星横换**（门 1③，换后该名仍在板且星级升，身份未失）；**(b) 分支 hold 让位**（必需件换血/成品换血的现行让位检验 `_swap_victim_yields_for_swap_in` 通过，含量席让位现行语义 `:999-1003` 保留）。

- 双轨域 target_keep 口径不动。

### 2.3 守恒层：转型域统一、双轨域原样

- **转型域**：守恒判定 = **终局档位非降（组换后板态口径）**，与门 1① 的档位面同一函数，不设第二实现。
- **双轨域**：`engines_guard`（守恒对象 = `SWAP_GUARD_SYSTEMS` 四体系+护盾，victim 离场口径）、配方完成件分支、必需件分支**全部现行原样**。
- 效果：转型域解锁纯过渡件 victim（爻光/青雀类——其 `SWAP_GUARD_SYSTEMS` 守恒体系承载〔仙舟档〕的掉档由换入组的终局新档覆盖，即用户裁定的「拆掉过渡阵容的羁绊」）；C1 帧死局解除（情形 A，经 §2.7 两级序选纯过渡件为 victim）。
- **过渡侧掉档语义申报**：转型域不设过渡阵容完整性的独立守卫——过渡侧损失由 victim 序自然最小化（档边际贡献高者靠后，成型过渡结构如希儿系仅在无可替代 victim 时被拆），终局侧收益由门 1 保证（用户裁定【拍】+行为锚点验收）。

**§2.3.1 现行转型分支机器与 fenced 关门分支归宿**：`SWAP_TRANSITION_ARM_ENABLED`/`_swap_transition_domain`/五消费位键集收窄/transition_domain 快照——**转型域由双门取代**（该分支的 fenced victim 键集收窄与门 1 受让判定合并进 §2.2/§2.7，禁双轨并行双判据）；双轨域照旧。**`fenced` 关门分支判定（逐帧类真值表，唯一实现口径）**：①转型域帧（新判别子 True）→ 关门，fenced 件让位由双门/守恒新义裁定；②pair 帧（p1_pair 非空）→ 关门照旧（围栏件 = 配方换血货币）；③未锁帧 → 不关门落资格族（现行）。**pair 成型帧（fp≥1.0）不关门 = 新增放宽边，显式申报**：配方已成、围栏货币职能终结，bench 围栏件可经普通卖出通道变现（【拍】）。`fenced_arm_closed` 拒因键保留（双轨域仍产，转型域零写入申报）；projection 判读面随正本更新（已入清单）。**`swap_transition_narrow_frame` 归宿**（`mandate.py:732-777`；消费 `shop.py:979`/`mandate.py:1134`）：其键集收窄 = 配方域语义，双轨域消费位保留并改挂双轨域判别（禁引退役符号），转型域消费位由双门接管（retirement face 入 landing 3.1）。**`mandate.py:1495` 发出闸 arm 路由**：双轨域完成品分支保留 arm='transition' 标注（双轨语义不变），转型域换新键族（bond_gate_*，见 arm 分键归宿）。退役面（五消费位 + 快照 + fenced 判定迁移 + narrow_frame）入 landing 3.1 文件面；§2.9 grep 词表补 `SWAP_TRANSITION_ARM_ENABLED`/`_swap_transition_domain`（P88 命题引用同谓词，随引用改写）；**`evolution_swap_arm_trigger` 域腿对账义务**：其代码自声明「域定义变更须随对账，禁静默分叉」（`:1352-1353`）——本迭代判别子变更后该谓词随批对账，入 landing 3.1 判据。**arm 标注分键归宿**：转型分键随分支退役换新键族（`bond_gate_tier`/`bond_gate_support`/`bond_gate_star`/`bond_gate_completion` + victim 序来源键；写点含 `mandate.py` 发出段）；`cw4_m1p_arm_pending` 归因透传载体保留；projection_contract §4.3 判读面随正本更新（已入清单）。

### 2.4 素材层：零改动

`merge_material_guard` 绝对禁卖不变，不设转型豁免（其关切 = 合成进度的经济价值保护，成立）。C1 帧核验：远坂凛持续受保护（bench 有第二张，`same_star_count=2`），爻光/青雀解锁为合法 victim。

### 2.5 放行层：废弃第二折法，改复算统一门

### 2.7 组配对算法与执行形态

- **算法宿主 = kernel**：现行 `select_swap_plan` 为**单对计划形态**（`:1750-1755`），**多对组计划为本迭代新建形态**，宿主落 kernel（kernel→strategies 依赖方向禁反向，策略层只消费计划）。**宪法第 5 条判据线作答**：换策略会不会要不同的序？会——序参数（两级序、换入序、度量域选择）由策略层 **ports 注入**（装配模式同 mandate 桥），kernel 只含机械执行，策略语义可换而宿主不动。
- **最小充分组贪心**：候选换入序 = 名单成员先（星级降序，并列 tie-break = 名单注册序即 core_chars 列表序）→ 外部支撑件（星级降序，并列 tie-break = 标签命中数降序 → 注册表序——3.5 预测表确定性要求全序钉死）；**victim 序两级**——一级：纯过渡件（终局键集零标签命中）先于终局标签支撑件；二级（同层内）= 现行机器 victim 序（**档边际贡献, 星级, 槽位**；度量域显式钉死 = 现行 `:1701` 注册度量继承——`all_factions ∪ SWAP_GUARD_SYSTEMS` 守恒体系、按 cw_factions 档位梯逐档计数；键集收窄退役后 `swap_yield_contribution` 喂入口径不变，禁换第二度量；星级键 = 现行 **1★ 优先桶式**（`:1703-1707` 继承，非全序）；非 11 号稿金当量价值序）。逐个扩组：每入一个换入件从 victim 序配一个；每次扩组对组换后板态算一次门 1；**首个可行组即停**。锚帧复验（度量域直调）：2-1 帧纯过渡件贡献 = 爻光 1 < 青雀 2（青雀=仙舟+战技点双档贡献）→ 一级序首 victim = **爻光**，锚 ① = **Saber 换爻光**（圣杯 3 二阶 + 能量 3 一阶双激活）。无可行组 = 本帧零动作（合法稳态）。

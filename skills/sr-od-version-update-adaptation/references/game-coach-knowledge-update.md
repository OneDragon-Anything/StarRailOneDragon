# 攻略知识更新（game-coach 角色说明与配队说明）

> 数据适配（角色/光锥/遗器录入）之外的**知识适配**：让 game-coach 的角色档/体系档/抽卡建议跟上版本节奏。方法与格式全在 game-coach 侧维护（单一事实源），本文档只管「版本更新日做什么」与分工边界。

## 1. 版本更新日的动作清单

| 时机 | 触发 | 动作 |
|---|---|---|
| 新角色实装/实装首周 | 版本适配清点发现新角色进池（当期 UP 可用官方接口查，见 sr-od-dev-official-api 的 gacha.md） | 调研并**新建角色档**（实装首周口径）；characters/INDEX.md 分组表加行+覆盖追踪表转正；体系档（波及的）调研轮次补实装复盘；investment.md 机制断点表加行（标「实装首周口径」） |
| 上版本角色盖棺 | 新版本适配清点时，检查上一版本实装角色是否进入盖棺窗口（约实装满一版） | **往待复核清单登记**复核条目（对象+触发条件+复核内容），条件到期后由常态化巡检执行复核——版本更新日只登记不执行（版本更新日距「满一版」往往还差半版，此时复核会查得太早） |
| 版本平衡性改动 | 版本公告含角色/光锥改动 | 改动角色档与断点表对应行即时复核修正（官方补丁说明为据）；持续影响的登记进待复核清单 |

前置依赖：数据适配先行——角色/光锥/遗器的静态数据已录入（路由表上游项）且 MCP `character_lookup` 等能查到新角色，攻略调研才有官方文本打底。

## 2. 怎么做（单一事实源在 game-coach）

调研与入档的完整方法论——信息源（米游社攻略+ B站视频 bili-cli）、信源选择判据、字幕噪声校准、调研轮次格式、证据标签——**全部**见 game-coach 的 `references/maintenance/research-methodology.md`，此处不复制。待复核清单（复核条目登记到这里）与知识库现状对账属维护进度记录，不进 git：存巡检工作区（位置与格式见 game-coach 的 `references/maintenance/patrol.md`）。

## 3. 常态化巡检（版本更新日之外的持续演进）

攻略知识的时效性跟着社区共识演进走，不跟版本更新日：新内容对旧角色环境的影响渐进显现；版本初期理解浅（首周口径）、中期实测修正、末期盖棺。这部分**不在本 skill 范围内**——归 game-coach 的常态化巡检：到期执行复核条目、探测新内容对旧知识档的波及、抽样共识漂移并定向修正。任务书见 game-coach 的 `references/maintenance/patrol.md`（自包含，可交定时任务执行，建议每周一轮）。

## 4. 边界

- 本项产出是 game-coach 知识库内容（skill references），不是项目代码——无 ruff/测试要求，验证方式 = 抽查入档结论的信源标注与官方文本一致性。
- 攻略内容有时效性：所有强度结论必须在档内标注口径时点；盖棺复核修正旧结论时保留旧口径并标注版本局限。
- 抽卡决策的最终建议（抽不抽）归用户；game-coach 只提供机制/强度/性价比的结构化依据。

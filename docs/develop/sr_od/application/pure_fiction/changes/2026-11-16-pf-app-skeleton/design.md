# 虚构叙事 app 骨架 迭代设计（总纲）

## 0. 元信息

- 迭代目标：把逐光捡金·虚构叙事做成可独立运行的 Application（`run_standalone_app` 可跑），选人策略随机占位、流程优先（用户裁定 2026-11-16 凌晨：「有时间就把忘却之庭和虚构叙事的也一样串起来」；不进一条龙；无 GUI）
- 状态：定稿（同构复用已对抗审收敛的 2026-11-16-as-app-skeleton 设计，差异面见 §1.3/§5）
- 文档清单：无详设（单文档方案）

## 1. 问题与动机

### 1.1 需求与用户裁定

同 AS 迭代（见 `../2026-11-16-as-app-skeleton/design.md` §1）：末日幻影先行，时间富余则虚构叙事/忘却之庭同构串流程；随机选人占位；不进一条龙、无 GUI。

### 1.2 范围

- 做：虚构叙事单次挑战链路 app 化——导航 → 选关点「纸鹤-关卡01」进编队屏 → 随机选 8 人 → 组合 op 挑战（编队+增益装配+战斗+结算）→ 回大世界。
- 不做：关卡选择（打 01，最高已解锁关卡的选关 area 仅建模 01）；领奖段（期次奖励领取 op 未建模，挂账）；星数检测；策略优化；忘却之庭（若时间允许另批）。

### 1.3 与 AS 迭代的差异面（本迭代新增决策）

| 差异点 | AS | PF | 依据 |
|---|---|---|---|
| 选人数量 | 探测节点实读 2/3 行 | 固定 8 人（2 节点），无探测节点 | challenge.py L53-54（8 人 2 行×4） |
| 选关→编队屏 | 探测节点处理（挑战 op 入口含该跳转） | app 节点点「纸鹤-关卡01」（组合 op 入口只校验不导航，challenge.py L63-70） | 逐光捡金屏 area `纸鹤-关卡01`（treasures_light.yml 已建档） |
| 领奖段 | TlRewardClaimOp | 无（op 未建模） | skill sr-od-treasures-lightward §虚构叙事·奖励 |
| 配置路由 | config_router 显式条目（claim_rewards 可写） | 不设条目（唯一字段 character_pool 为列表，set_config 写不了，describe 无可展示字段；改池直接编辑 yaml） | config_app.py set 值类型 str/int/bool |
| 换人重选 | 有（共享 random_team） | 有（同款；PF 填充失败文案同款 `列表到底未找到 X`，pure_fiction/team_fill.py L186） | random_team.py |

## 2. 方案（单文档完整设计）

### 2.1 流程（四段式）

```
① 导航段 [任意画面] --GotoTreasuresLightward(PURE_FICTION)--> 虚构叙事选关(逐光捡金屏 PF_TITLE)
② 玩法段 [选关] --[点 纸鹤-关卡01]--> 虚构叙事-编队(双锚验证)
          [编队屏] --随机选人(8 人,纯逻辑)--> TlPureFictionChallengeOp(team_names,buff_slot=1,buff_slots=[1,1])
          挑战失败「列表到底未找到 X」→ 剔除重选重试(预算 2 次,同 AS)
③ 领奖段 无（挂账）
④ 返回段 [选关] --BackToNormalWorldPlus--> 大世界
```

### 2.2 结构

包 `src/sr_od/application/pure_fiction/` 六件套，同 AS 形态（const `DEFAULT_GROUP=False`/`NEED_NOTIFY=False`；config = ApplicationConfig 子类仅 `character_pool`；run_record 恒重置；factory 三件全实现；app 节点图见 §2.1）。共享选人逻辑（池快照/抽取/换人重选助手）在 `treasures_lightward/random_team.py`（本迭代从 AS 上移，AS 同步改用）。

### 2.3 失败处理语义

同 AS §5，差异：无领奖段；换人重选预算同（初选+2）。

### 2.4 run_record / config

同 AS 口径（恒重置；character_pool 空回落默认快照池，剔除后不足显式失败）。

## 3. 验收判据

1. ruff + 导入冒烟通过；`pick_random_teams`/提取/重选单测全绿（sr-od-test）。
2. 重启 MCP server 后 `run_standalone_app(app_id='pure_fiction')` 受理并端到端走通：选关 → 编队 → 随机 8 人填充 → 增益装配 → 战斗 → 结算回选关 → 大世界收尾；运行记录成功。
3. 换人重选路径如被触发，按 §1.3 语义工作。

## 5. 差异面自检（对抗结论的承接）

- AS 对抗的阻塞 1（判据口径）与阻塞 2（探测节点状态机）不适用于 PF（无探测节点；注册证据口径沿用）。
- AS 对抗建议 2（进编队屏双实现）在 PF 侧扩大：PF 组合 op 完全不做导航，app 节点承担全部进编队屏职责——沿用「战术权衡声明 + 根治排期」口径，根治（抽「进入逐光捡金编队屏」族 op）与 AS 同批。
- 其余建议项（语义落点/池空边界/测试随功能/过程叙事）已在共享模块与本文件口径中落实。

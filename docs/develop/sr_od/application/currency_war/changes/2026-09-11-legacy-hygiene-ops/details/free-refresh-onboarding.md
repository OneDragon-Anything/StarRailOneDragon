# 免费刷新机制建档接入（详设：T-13）

## 问题与约束
- **症状**：游戏内免费刷新为独立按钮机制，未正式建档；固定理财/大裁员/加油站等效果授予的免费刷新余额，执行面消费依赖此建档（依据 = 旧账 T-237 卡；新账任务卡 T-13）。
- **根因归层**：流程层——画面建档欠账（免费刷新按钮/余额机制未走建档流程）；消费接线另涉表示层依赖——授予计数载体归 unified-state 效果线（总纲 IC-7），非本批域内可解。
- **域边界（总纲 IC-6）**：建档走 screen_info（`upsert_screen_area` 等 MCP 工具）+ 现行读链接入；统一观察基类迁移属 unified-observation 迭代（账本 T-8），本批禁做结构性迁移。
- **防双源对账义务（派前必做，可先行段）**：旧账 T-162 已 done 行①「刷新按钮+剩余次数观察通道重建（screen onboarding）」（入库 1c65941a，投资环境屏刷新通道）。本批开工前亲核该入库面覆盖范围，写明本批免费刷新按钮/余额区与既有投资屏刷新通道的边界（商店免费刷新 ≠ 投资屏付费刷新），防同一机制双源建档（依据 = 旧账 T-237 附注「派前先与 T-162 done 行①对账防双源」）。
- **口径挂账**：免费刷新次数口径若与既有登记（旧账 T-157②口径）存在两说，随实机窗同窗定谳，禁两处并行口径（依据 = 旧账 T-237 附注）。

## 方案
1. **对账段（可先行，零游戏依赖）**：T-162 入库面覆盖核对结论落交付报告；读链落点初勘（商店屏读链现居模块盘点，产出接入点清单）。
2. **建档段（候实机窗，需游戏画面含免费刷新按钮态）**：
   - `analyze_screen` 识别免费刷新按钮区与余额显示区（1080p 游戏坐标），`upsert_screen_area` 建档；id_mark area 按 od-dev-screen-onboarding 规程设立，保 `is_precise` 精准匹配；
   - 读链接入：商店屏读链补免费刷新余额读取（走 screen_info 坐标，禁硬编码坐标——AGENTS.md 坐标单一真相源条）。
3. **消费接线段**：固定理财/大裁员/加油站等效果授予的免费刷新余额接真值通道——执行面刷新消费（商店刷新操作）在余额 > 0 时走免费通道。**数据源前提（总纲 IC-7，attack.md F6 裁决校正）**：`data/cw_invest_data.py` 在册的是 PlazaAugment **效果文本**（`effect='获得N次免费刷新'` 字符串，如固定理财「获得2次免费刷新」、大裁员「获得6次免费刷新」），**不是可消费的计数载体**——授予计数的结构化载体归 unified-state 效果线（账本 T-9..T-12，尤其 T-11「条件判定型免费刷新效果结构化 wire」）。余额真值 = 屏读 + 效果线授予计数对账；**效果线未落期间本段只允许屏读通道 + 候裁，禁在执行面自造第二计数源**（防与效果线 wire 双源）。
4. **验证段**：`analyze_screen` 对账命中（建档区全命中）；CW 测试子集绿；执行面消费接线的单测/锁。

## 边界与验收
- **文件面**：assets/game_data/screen_info/（新建/修改 yml 走 MCP 工具）、商店屏读链模块、执行面刷新消费模块、data/cw_invest_data.py（**本批禁改——效果文本注册表，非计数载体；计数载体归效果线，总纲 IC-7**）、测试仓锁面。注意 screen_info 的 `_od_merged.yml` 有在飞修改——按 GC-1 留树面对账。
- **外部等待（账本 cond）**：实机窗口——复查时机 = 下次实机窗随布防清单一并建档（需游戏画面含免费刷新按钮态；与 T-18 核证段、T-14 验证族同窗盘点）。本批在实机窗前只允许对账段。
- **下游**：本批 done 是 T-28（实机通关）的 deps 之一（账本 T-28 deps 面）。

## 关键取舍
- **建档+读链+消费三段一体立项**：拆开会产生「有档无链」「有链无消费」的中间态任务，验收判据无法独立成立（账本 criteria 四条本就捆绑三段）；实机窗稀缺，同窗一次采集覆盖三段的画面证据。
- **计数源单源化，屏读只作对账信号**：授予计数唯一来源 = 效果线 wire（IC-7），屏读余额与之对账；两源不一致 = 缺陷信号上报，禁静默取其一——原「不预设纯屏读」取舍中的「cw_invest_data 字段」表述随 F6 裁决废止（效果文本非计数载体）。

### 3.2 节点身份定义

**身份键 = 节点序位 `(位面, 轮)`(`NodePos`,二元素整数元组,1 基,单一源住
`cw_node_schedule`;对外标识统一「位面-轮」标签形态如 `2-1`——元组只是标签的
容器内表示,journal 数值列 plane/round_num 是列不是标签)**。序列真值**按局
修饰变长**:默认环境 = 默认序列表(P1+P2+P3 全真值在表);改节点序列的环境
(「人身意外险」插入型/「战争边疆」替换型,统一注册表 = `cw_node_schedule.
ENV_NODE_REWRITE_RULES`)经场字段
`node_seq_by_plane` 修饰——凡持 gs 的生成方同读场字段(None = 未注册态回退
默认表),修饰局下位面 1=10/位面 2=8/位面 3=8,序位键保持各面面内编号,不会被压成全局连续编号。
裁决依据(要点重述):

1. 类型不入身份键(属性入载荷;类型读法多源不入键防第二失真源)。
2. 键与效果账本同源:`advance_node` 去重键同一序位键(登记时点快照
   `acquired_key` 与推进入账同键,cw_effect_inventory)。
3. 位面优先、位面内轮次次序的元组字典序 = 序列全序(「有效节点序列按位面
   拼接展平」的前缀和序,恒等不依赖具体序列值);跨位面比较((1,10) <
   (2,1))由字典序自然严格;跨 run 键隔离(去重键含 run_id,序位是 run 内
   相对量,禁跨 run 比序)。
4. 开局 1-1 vs 重入 1-1:寄存器 None→首节点必触发一次;重入零触发。
5. 战斗窗/结算窗/弹窗 = 同一节点的段内相位(玩法:一节点一战;弹窗在下一节点渲染后弹出,归属其段内,currency_war_prep.md:32)。
6. 坐标系粗糙面(投资环境加节点)为既有面信息项,见文末「未决与信息项」。
7. **序键状态面落点(两态版)**:身份序位在统一 state
   的载体 = 单字段双值——`top_bar_raw`(Field[str],观察层,顶栏原文,observe()
   写入位置 = 观察汇聚,原文缺读不写禁猜)+ `node_pos`(Field[tuple[int, int]],**两态字段**:
   **id_mark 确认态 observation** = `observe_node_anchor` 解析读数直写——节点域专用写入口,
   不经通用 observe(),先例 = `settle_truth` 的结算金币专用口;**推进态 logic**
   = 终结动作上报经 `advance_node_effective` 写入,未确认态);`node_hist_pos`
   = 单调水位 + 去重第二道防线(工程结构位,run 段随容器重基线);**生效序读取入口
   = `effective_node_pos` = max(node_pos 现值, node_hist_pos)(元组字典序取大,
   派生计算,非存储
   字段;kernel cw_game_state.py)**——本方案的判定与比较域统一在该读取入口。观察
   覆盖 logic 失配的通用三种标准处理分支(`observe_vs_logic_mismatch` 缺陷记录行)不适用于节点域
   ——helper 四分支显式处置(§3.3-4)。
   **「禁 observe 直写序键」改判记录**:旧版裁决曾规定旧四规则组全部走

### 3.3 跃迁判定规则(规则本体;动作上报 + 观察 id_mark 确认模型,派生规则单一源)

> 本节 = 派生规则唯一权威出处。现行模型(用户裁定 2026-09-20,2026-09-21 修正):节点推进 = 终结动作
> 上报;观察 = 对账确认 + 兜底。旧四规则组(备战/位面过渡/BOSS 简报/弹窗)、
> 守卫族、缓存守卫、幂等锚、恢复局禁用分支已整体停用(本节 6 号停用申报),旧版
> 全文入 git 历史。实现锚 = kernel `report_node_advance`/
> `advance_node_effective`/`observe_node_anchor`(cw_game_state.py)。

**1. 节点边界定义**:

> **节点推进 = 上一节点终结动作落地**:战斗节点终结 = 结算胜利确认(点击
> 「继续挑战」);补给节点终结 = 补给选择确认。位面末节点推进经后继原语
> `sequence_next` 自然跨位面(位面末 → 下一位面首)。备战画面从「推进触发面」
> 改判为**对账确认面**(确认写入位置 = CwScreenPrep 备战顶栏);补给屏节点条同为
> 确认面(补给「自动弹」形态——无本节点备战帧——的唯一确认点)。开局首节点
> (E4,无前置终结动作)由观察确认建首锚(首次确认行);入口链(cw_entry/)不接上报。

**2. 动作推进路径(`report_node_advance`,动作路径唯一入口)**:

- **观察态门(双条件)**:`node_pos.value is not None ∧ node_pos.source ==
  'observation'` 才放行——只有已被观察确认的节点值才允许被动作推进;门挡 →
  obs_event arbitrate 保留证据零推进,重复上报/重试/任何第二条动作推进路径在结构上
  不可能。**value 守卫不可省**:Field 缺省 source='observation',新容器 =
  (None, 'observation'),只查 source 会在开局/恢复局首次确认前误放行,且
  candidate 在生效序位 None 时无定义。恢复局锁定臂(直出战)首次
  结算确认被 value 守卫挡,由战后备战帧确认补齐(绝对值坐标,无 skew)。
- candidate = `sequence_next(生效序位, gs.node_seq_by_plane.value)` → 经推进
  生效原语落账(source=logic,推进未确认态;
  观察确认同值翻回确认态后,下一节点终结动作由此解锁)。trigger 封闭集 =
  `{settle_confirm, supply_confirm}`(集外显式报错;journal 行 actor 归因映射 =
  kernel `_NODE_ADVANCE_ACTORS`:settle_confirm→CwOpSettleConfirm /
  supply_confirm→CwActionPickSupplyOp)。
- **终局语义(事件式声明)**:`sequence_next` 返回 None(下一位面无序列表,
  或 pos 位面不在序列表——位面 2 末终局确认,或实机位面 3 确认后的上报形态)=
  超出建模域 → **局终声明事件式**——零写入(无后继序位可写)、零效果 tick
  (无节点进入),返回 `applied=True, reason='match_end'` +
  `WorldDecl(next_screen='', trigger='node_advance')`。**applied 契约**:
  「applied = 实际推进落账位」在终局出口单点扩展为「终结动作落地事实」
  (落地但无后继可写);同 run 多条 `match_end` = 同一终局事件的重复发射
  (零状态破坏,判读按 run_id 归并)。
- **触发点 1(结算确认;去证据门,用户裁定 2026-09-21)**:`CwOpSettleConfirm`
  (operations/cw_op/)——点击「继续挑战」(含长按兜底重试)→ **点击即上报**
  settle_confirm → 返回宿主。无证据等待 ⇒「上报先于下一节点任何画面渲染」
  恒成立 ⇒ boss 流「上报落后于流转、简报直定写错节点」结构性不可达——
  简报 op 被分派时 hist 已在 boss 节点,类型直定目标恒正确。重复/未生效的点击
  重试上报被观察态门挡(零推进零危害);战败分支不进本 op、不推进(终局
  流转 E15,节点序止于终局)。
- **触发点 2(补给确认)**:`CwActionPickSupplyOp` 点「确认」→ 补给参数
  上报 + supply_confirm 推进上报直接双发(点击即上报,零证据探查);漏报
  形态兜底归观察确认。
- **报告时点语义**:两触发点均**点击即上报**(用户裁定 2026-09-21)——
  无证据等待 ⇒ 上报先于下一节点任何画面渲染;**「先推进后选卡」结构性
  成立**(确认点击先于下一节点一切弹窗与选卡,由因果序保证,不依赖任何
  弹窗推断)。

**3. 推进生效原语(`advance_node_effective`,序位前进唯一落账入口)**:

candidate 去重守卫(candidate ≤ 生效序位 → 零推进返回,同序位幂等,元组比较;
生效序位 None = 本 run 首建,任何正 candidate 放行)→ 写 `node_pos`(**来源由调用方定**:动作
上报路径 = logic(推进未确认态,观察态门语义的前提);确认补推路径 = observation
(观察采纳新读数即确认态——否则补推后源态落 logic,下一次终结动作被门误挡一帧))→
`node_hist_pos` 占位(单调水位,元组比较)→ **效果推进尾段 `tick_effect_boundary`**
(账本 `advance_node` + 在场效果盘点发放 `grant_effect_node_refresh_balance`
+ 容量重锚 `project_effect_capacity`)同临界区执行。确认补推(读数序位领先/
首次确认)同样
是真实节点进入(恢复局/锁定臂/漏报的自愈路径),序位前进不经尾段即该节点
每节点发放永久丢失。确认直写不经通用 observe()(读数序位领先 logic 现值时
会误入
通用的失配三种标准处理分支并触发告警;节点域专用写入口,先例 = `settle_truth`)。

**4. 观察 id_mark 确认(`observe_node_anchor`,两写入位置共用 helper;处置规则 R = 本帧读数
序位(`NodePos` 元组),v = `node_pos` 现值;全部分支比较 = 元组字典序)**:

| 分支 | 处置 | 依据 |
|---|---|---|
| v = None(首次确认) | 任何 R 经原语落账(observation 确认态)+ 尾段发放 | E4 开局建首锚 / 恢复局重建;开局链期间拾取的效果由此首帧发放 |
| R > v | 观察采纳新读数经原语(observation;**补推 = 漏上报自愈**,序位前进同帧拿到尾段发放) | 绝对值坐标,采纳即对齐 |
| R == v | 直写同值(observation;**logic 态此分支 = 动作推进被观察确认翻确认态**,下一节点终结动作由此解锁) | 重复上报解锁即确认语义 |
| R < v | 不写 + obs_event arbitrate 保留证据(**读数倒退不采信**) | 节点序位局内单调(游戏无回退流转,E15 终局除外);R<v 只能是读数误读或点击未生效产生的假推进残余;跨位面 ((1,10) < (2,1)) 由字典序自然严格,无需序列查询 |

确认写入位置两处:①**`CwScreenPrep` 观察 node**——备战完整观察(全量识别)回执携带本帧
plane/round → `observe_node_anchor((plane, round))`;读数链
(`read_phase_round` 直读/缓存/守卫)语义不变;外循环仲裁路径的 prep_clean 聚合入口
读不挂确认(纯域读数,无缺口);读数缺位/局外 = 跳过禁猜。②**`CwScreenSupplyNode`
观察链**——补给屏顶部居中节点条「备战阶段 X-Y」读数 → 同一 helper(该读数位
不在 A_PHASE 识别区,screen_info 单独建档)。

**点击未生效产生的假推进记账的自愈路径(申报;现行形态 2026-09-21)**:点击即上报下
未生效的点击会产生假推进(上报了但游戏没走)——残余形态 = logic 值领先一个序位,
后续
确认被 R<v 分支挡住、下一次终结动作被观察态门挡、再下一节点观察 R>v 补齐
——绝对值坐标保证无累积误差,偏差有界一个观察周期;重复上报被观察态门挡
(零推进零危害)。效果账本不回滚(`grant_free_refreshes`
计数器与 `advance_node` 递减无逆操作;接受该残余边界并保留证据——最坏损失 =
假推进那次多 tick 一档发放,金额正确、时机略早、期间无消费方,用户已知悉)。

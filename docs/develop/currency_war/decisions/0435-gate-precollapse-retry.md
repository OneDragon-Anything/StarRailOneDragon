# ADR-0435:环入口 gate 12s 满超时的时序竞争修复——预收探针前置重试

- 日期:2026-08-28
- 状态:accepted(攻击来源:`.debug/temp/currency_war/w417_duration_audit/REPORT.md`「确定可压」第 1 条)
- 关联:W358(gate 死等修复,未覆盖本场景)、ADR-0264(gate 快确认)、runtime-ops.md(哨兵)

## Context(为什么)

W417 时长审计实锤:W358 修复后,「环入口 gate 12 秒满超时」仍在每轮发生(三代表局 9/15/25 次,共 113/189/314 秒)。根因是**时序竞争**:战斗结束游戏可能自动开商店,而 `prep_director.py` 的预收探针跑在自动开商店**之前**——探不到「按钮-收起」就落进 12s 完整门等满超时,容忍探针才命中开态,收起+round_retry 重进再花 4-6 秒。

## Decision(逐条)

1. **方案 A 探针前置重试**:预收探针 miss 后,在 ~4.5 秒窗内以 `PRECOLLAPSE_RETRY_S=1.0` 间隔重试至多 `PRECOLLAPSE_RETRIES=3` 次;任一次探到开态 → 走既有「`_try_collapse_open_shop` 收起 → GATE_POST_COLLAPSE_TIMEOUT_S=4s 收紧 gate」路径,免除 12s 死等与重进。
2. **不选方案 B**(gate poll 内顺带探开态):需改 `cw_observation_gate.py` 通用循环(三 profile 共用 + ADR-0264 快确认语义 + r297/r346/r347 迁移历史),风险面大;方案 A 复用既有 `_try_collapse_open_shop` 判据,零新语义。
3. **窗内未开 → 原 12s 完整门,行为不变**(上限防无界等待;从不自动开店的轮次最多多付 ~3.5 秒探针成本,对比开商店轮净省 15-18 秒)。

## Consequences

- **正面**:开商店轮免除 12s 死等+重进,预计每局省 2.5-7 分钟(W417 三局实测 113/189/314 秒的水分)。
- **负面/边界**:非自动开店轮多付最多 ~3.5 秒探针窗(净收益为正的频率前提已由 W417 三局实测支撑);重试窗与游戏开店动画的竞争窗口仍是经验值(1.0s×3),若动画时长变化需回调。
- **实机验证判据**:W420 后首局的 `[cw][gate] timeout` 日志行数应从 9-25 次/局显著下降(趋零);局时长对比 W417 同档基线。

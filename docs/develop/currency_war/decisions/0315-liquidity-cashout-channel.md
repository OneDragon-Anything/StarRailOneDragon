# ADR-0315: 金不足变现通道(压库件「活期存款」变现凑金)

- 状态:accepted
- 日期:2026-08-25
- 背靠:用户发现 + leader 核实(2026-08-25):gold_short 直接拒绝购买、
  无主动变现路径;W51 原批追加任务(W51 报告「追加任务:金不足变现通道」)。
- 落点:`decision_v2/discipline.py`(`liquidity_actions`/`LIQUIDITY_BUY_TAGS`
  /`_line_protect_set`)+ `decision_v2/strategy.py`(decide_prep ⑤b 接线)。

## 背景与动机

压库件(hoard)在现有经济语义里是**双重身份**:占用池位(供给面资源)+
可变现金(流动性)。gold_short 分支直接拒绝购买时,只兑现了前者——
压库件被当作「囤着等成型」的死资产,金不足窗口(目标件在店、金差 4-5)
只能干等,错过方向件在店窗口(期望成本>1 张杂牌的卖出价)。

用户裁定:卖压库件**不是损失,是压库策略的收益兑现**——「活期存款」
该在需要时取现;变现通道 = 把压库件的第二重身份接入经济决策。

## 决策

在层 3(评分)与层 4(仲裁)之间接线(⑤b):按层 3 分数选**最高分的
金不足优先买**(`gold-cost < _active_floor`),为它变现凑金:

- **① 变现通道**:卖件序 = 净0 件(1★/1费,`sell_refund≥cost` 全额退)
  最先 → 低费散件 → 升星沉淀件最后;变现到够即停;同轮顺序动作组
  `[Sell…, Buy]`(卖先于买,序保证金到位);买打 `reason='d2_<tag>'`
  (与 `_materialize` 同式,engine_seed 类照常进种子登记)。
- **② 守卫**:
  - 不为非目标件变现:`LIQUIDITY_BUY_TAGS = {line_carry,
    line_opportunistic, bridge_core, engine_seed, plugin}`——
    pair/copy/bond_fallback 凑数凑对类与 refresh/levelup 不辖;
  - 保护集不卖:`_line_protect_set(comp)`(与 carry_gate 共用单一源,
    防两处派生漂移);无锁定意向时仅引擎件受护;
  - 同轮已买(r408)/种子年龄窗(ADR-0289 §5)/3合1 完整份不动
    (carry_gate 同守卫);
  - 变现不足额**整体放弃**(不卖一半);每轮最多救援一笔。
- **边界声明**:绕过层 4 直发(同 carry_gate);候选 copies_cap/同名
  互斥由生成期保证;未知费级件(CHARACTERS 无档)不入变现序(回金
  不可估)。
- **索引稳定性**:卖出动作的 bench_idx = 生成期原索引;ADR-0316 槽位
  语义下任意发射序零漂移(旧降序重排是紧缩表时代的症状补丁,已删)。

## Considered Options

- **gold_short 直接拒绝(修前现状)**——被否:压库件第二重身份(可变现
  「活期存款」)零兑现,方向件在店窗口干等;用户点破「买了卡发现要卖
  卡怎么办」暴露金不足变现断链。
- **降门槛买(为金不足放宽买门)**——被否:违反经济纪律(买门/息档/
  地板是设计约束,放宽=系统性破息),且不解决「钱从哪来」——降门槛
  只是让缺钱时照买,金照样不够。
- **变现通道(选中)**:把压库件当活期存款,缺钱时按弱序变现凑金;
  收益=方向件窗口不丢,代价=卖压库件(其本就非保护集/非 3合1 素材
  时是低机会成本资产)。

## 影响

- `discipline.py`:`liquidity_actions` + `LIQUIDITY_BUY_TAGS` +
  `_line_protect_set`(carry_gate 原内联保护集构造改为调 helper)。
- `strategy.py`:decide_prep 层 3 与层 4 之间 ⑤b 接线。
- 测试:4 个新锁(变现到够即停/金够零变现/低优先级不触发/保护集+
  不足额整体放弃)+ 索引稳定性回归锁(ADR-0316 槽位语义)。
- 行为面:金不足 + 目标件在店 + bench 有可变现件 → 卖件凑金买入
  (此前直接拒买);其余路径零变化。

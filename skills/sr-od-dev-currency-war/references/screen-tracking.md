# 画面识别与动作 op 的追踪文件

> 定位:货币战争的长期追踪目录里的一份记录文件。它按画面分章,记三样:这个画面的识别最近一次核对是什么时候、结论是什么;画面上每个动作上次用着正常的时候用的是哪个 op 还是鼠标;这个画面还有哪些缺口。
> 读者:登记它的编排者,查它的实机探索 agent 和修复线。编排者、实机探索 agent、修复线、单局报告都是 [autonomous-loop.md](autonomous-loop.md) 里的叫法。同目录另一份文件(待跟进事项)的条目怎么写,见 autonomous-loop.md §2.5。

## 1. 文件在哪,怎么用它

- 路径:`.temp/tracking/currency-war/画面识别与动作op.md`。它不在版本控制里,会话结束了也留着。
- 怎么用:打到哪个画面,读哪一章,不通读全文。按画面名找二级标题,只读那一章。
- 文件不存在 = 还没有核对过任何画面。第一次登记时新建,文件头照 §2 写。
- 换了客户端版本:谁先发现谁在文件头「记录对应的客户端版本」下面加一行,写新版本号。旧记录不删。之后每个画面第一次被打到时,识别核对照常做,日期会更新成新版本下的日期。

## 2. 格式

文件头:

```markdown
# 画面识别与动作 op(货币战争)

> 打到哪个画面,就看哪一章。没有章的画面 = 还没核对过。
> 记录对应的客户端版本:v4.7。
> 怎么记:开发 skill `sr-od-dev-currency-war` 的 references/screen-tracking.md。
```

一个画面一章。一章有三样:识别核对一行、动作一栏、缺口小节。下面是一章完整的样子(日期和报告文件名是示意):

```markdown
## 货币战争-备战-开商店

- 识别核对:2026-11-24,一致。
- 动作:
  - 买牌(`CwBuyShopCardBySlot`):2026-11-24 用过,正常。
  - 买经验(`CwBuyXpRepeat`):2026-11-23 用过,正常。
  - 刷新商店(`CwRefreshShopByClick`):2026-11-24 用过,正常。
  - 收店(`CwToggleShopPanel`):2026-11-24 用过,正常。
  - 卖备战席角色(`CwSellBenchBySlot`):还没用过。
  - 查看商店牌详情(鼠标点击):2026-11-24 用过,正常。
  - 免战跳过(鼠标点击):还没用过。

### 缺口

- 动作 op:「查看商店牌详情」这一步没有动作 op,操作表里写的是鼠标点击。2026-11-24 发现。证据:match-3-1.md。状态:等修复线。
- 动作 op:「免战跳过」这一步没有动作 op,操作表里写的是鼠标点击。2026-11-24 发现。证据:match-3-1.md。状态:等修复线。
```

识别核对对不上、缺口是另外两层时,识别核对那一行和缺口小节这样写(还是示意):

```markdown
- 识别核对:2026-11-24,有不一致,见下方缺口。

### 缺口

- 画面识别:标题下方的数字读成「S0」。2026-11-24 发现。证据:match-4-1.md。状态:等修复线。
- 画面建档:各费用档的出现概率没有建读数区。2026-11-24 发现。证据:match-4-1.md。状态:等修复线。
- 画面建档:按钮「详情」没有建 area,要等这个画面出现第二槽已解锁的形态才能建。2026-11-25 发现。证据:match-5-1.md。状态:已登记待跟进事项(编号 12)。
```

缺口小节没有缺口,写一行「- 无」。

记法:

- **章**:画面名用玩家 skill 入口文件(SKILL.md)「各阶段与画面的处理方案」列表里的名字。列表里二级缩进的子画面,也各算一个画面,自己一章。新章插在哪,跟着那个列表的顺序。
- **识别核对**:把 MCP 画面识别(analyze_screen)返回的画面名和读数,和自己看截图读出来的逐项比。对得上写「一致」。有对不上的写「有不一致,见下方缺口」,并在缺口小节写一条「画面识别」。
- **动作一栏**:按玩家 skill 画面文档里这个画面的「操作」表,一行一个动作。动作名用操作表「目标」一栏的写法。操作表里写鼠标点击或拖拽的步骤也列进来。操作表改了,动作一栏跟着改:加了一步就加一行,删了一步就删一行。这个画面还没有「操作」表的,先列单局报告「画面核对」里实际做过的动作;操作表以后有了,改成按操作表列。
- **动作名后面的括号**写这一步上次用着正常的时候用的是哪个:op 写类名;用鼠标的(点击、拖拽)都写「鼠标点击」。
- **日期**:只留最近一次用着正常的日期,抄单局报告第 12 节写的报告日期。这一局用着不正常的,日期不改,问题写进缺口小节。还没用过的写「还没用过」。
- **缺口小节**:一条写四样——缺什么、发现的日期、证据、状态。缺什么的开头先写它属于哪一层,三层:画面建档 / 画面识别 / 动作 op。证据 = 记着这件事的单局报告或验证报告的文件名。括号里是「鼠标点击」、操作表里这一步也是鼠标的,这里要有一条「动作 op」。
- **缺口的状态**四种:
  - 等诊断(报了要查原因的问题,诊断报告还没到);
  - 等修复线(该立修复线,或者已经有修复线在跟——包括动作 op 已经做出来、等实机验证);
  - 等用户裁定;
  - 已登记待跟进事项(现在探不了。括号里写待跟进事项文件里那一条的编号;卡在什么条件上写在那一头,这里不重复。卡在用户叫停的,后面再写「,卡在用户叫停」——重新开启时按这几个字找回来)。
- **缺口修好并且实机核实以后**,当场删掉那一条。
- **只写日期和结论**:核对了哪些内容、动作具体怎么做,定义在画面文档和画面档里,这里不复述。
- **不预先建章**:第一次核对哪个画面,才建哪个画面的章。没有章的画面不算缺口。

## 3. 谁在什么时候写

| 什么时候 | 谁写 | 写什么 |
|---|---|---|
| 实机探索 agent 交了单局报告以后 | 编排者 | 照报告第 12 节「画面核对」更新到过的画面;照「缺口」「缺动作 op」「未闭环问题」写缺口。步骤见 [autonomous-loop.md](autonomous-loop.md) §3.5 路 B 第 3 步 |
| 要查原因的问题,诊断报告到了以后 | 编排者 | 按诊断报告「处置建议」的第 5 样,改对应那几条缺口的状态。见 [autonomous-loop.md](autonomous-loop.md) §2.4 第 2 步 |
| 修复线的实机验证达标以后 | 编排者 | 删掉修好的缺口;验证时正常的动作、一致的识别核对,日期改成验证那天。见 [autonomous-loop.md](autonomous-loop.md) §3.6 |
| 修复线做出新的动作 op | 修复线 | 动作一栏里这一步,括号里改成新 op 的类名,日期写「还没用过」;动作一栏里没有这一步的,加一行 |
| 用户叫停,以后重新开启 | 编排者 | 叫停时、重新开启时各改什么,见 [autonomous-loop.md](autonomous-loop.md) §3.8「用户叫停」和 §3.2「场景一的开启清单」第 3 步 |
| 不在自主推进里,编排者以外的会话在实机上核对过某个画面、用过某个动作 | 做核对的那个会话 | 照 §2 写 |

## 4. 什么不记在这里

- 画面建档、画面识别、动作 op 三层的缺口记在这里,不管是哪个场景、哪条线发现的。
- 别的待办记进同目录的 `待跟进事项.md`:流程缺陷、机制缺失、要等实机取证的机制问题、等用户裁定的家族级议题。
- 一条缺口现在探不了:卡住的条件和证据登记进 `待跟进事项.md`(状态标签按 autonomous-loop.md 各处的规定),这里的缺口条目只把状态改成「已登记待跟进事项」。同一件事的细节只写在一份文件里:那一头写卡在什么条件上,这一头只留编号。
- 等用户裁定改不改知识文档的发现,记进待裁知识队列([autonomous-loop.md](autonomous-loop.md) §3.7),不在这里。

## 5. 边界

- 为什么长期保存、为什么任务书只带路径:design/overview.md「动机记录」。
- 任务书里怎么给路径:autonomous-loop.md §3.3 第 9 项。
- 有没有动作 op 怎么判断:autonomous-loop.md §3.4。先看这里的动作一栏:括号里是 op 的名字,这一步就有动作 op。括号里是「鼠标点击」的,有没有动作 op 要看玩家 skill 的操作表——括号记的是上一次实际用了哪个,上一次用了鼠标,不等于这一步没有 op。

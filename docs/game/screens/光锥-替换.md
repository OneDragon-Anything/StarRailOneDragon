# 光锥-替换(light_cone_replace)

> source_image: .debug/sr_od_mcp/screenshot/screenshot_20261110_092821_053819.png(2026-11-10 实机建档,黄泉替换列表首屏)
> 识别器:src/sr_od/operations/equip_list_recognizer.py(LightConeReplaceRecognizer——网格定位+逐卡五维识别)

## 何时出现

「角色-光锥」屏点替换按钮进入。独立屏。
显示:左侧=命途相符/不符分组的可用光锥网格(多屏,可滚动),中上=当前/选中光锥对比,右=选中件技能详情。

## 状态流转

```
角色-光锥 点替换 → 本屏(列表定位在「与角色命途相符」组首)
点选光锥卡 → 右侧对比栏切换选中件 → 替换按钮确认
右上返回 → 回「角色-光锥」
```

## 识别特征(滚动态实证 2026-11-10)

- id_mark 仅「标题-光锥替换」[95,25,215,75](左上标题,滚动免疫)。
  **勿把「命途相符组头」等列表内容设为 id_mark**——滚动一屏后组头即滚出
  视野,画面判定退化为不精准(extras 停止输出),曾是实机 bug
- 列表滚动中(拖拽过渡帧)识别不稳定,滚动后需等 ~1.5s 再识别

## 列表结构(翻页实证)

- 9 列网格,列距 139px,卡 139×155;列表按命途分组(「与角色命途相符」组头
  在首屏顶,其余命途组在其后),同组内按建议排序(左下「光锥建议排序」按钮
  可切排序方式,会重排列表)
- 全列表数百件、多屏;EquipLightConeOp 未命中时滚动重扫(300px/屏,预算 12 屏)
- **裁切行卡**(屏幕底缘只露出半张):轮廓补充定位的 rect 有偏移(x 偏右可达
  10px、y 偏差更大)——固定相对坐标的识别窗需留滑动余量(探针窗左扩至
  x+2 实证可容);裁切行卡的等级锚缺失,靠轮廓补充定位

## 叠影圆标(逐卡识别实证)

- 卡左缘中部圆标 = 罗马数字 I-V = 叠影数;半透明底,透出卡底色(金褐/暗紫/
  白底等)——底色差异由归一化相关系数+滑动匹配吸收,无需按底色分模板;
  曾按底色/明暗分多套模板,逐套实测均冗余已并(教训:先实测再分)
- 模板:assets/template/light_cone_superimpose/<1-5>/raw.webp(26×26 紧圆,
  TemplateLoader 规范 webp);采样=紧圆窗裁片,采样后必须放大目检再入库
  (首采错位曾致模板含邻卡立绘)

## automation 要读信息(extras items)

- 每卡 {cone:光锥名, path_cn:命途, level:等级, owner:占用角色, rank:叠影数,
  identity:识别层级}——owner 列表角标头像≠装备者(推荐角色标记),仅参考
- 命途不符组的卡与相符组同构,识别无差异

## 注意

- 替换按钮确认有副作用(换装备),抢件确认弹框一律取消(EquipRelicOp 同款防误触)
- 强化按钮进光锥强化页(未建档;强化流程走晋阶材料,与遗器强化不同构)

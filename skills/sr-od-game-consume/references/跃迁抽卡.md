# 跃迁抽卡(消费路由)

> 画面建档细节归 `docs/game/screens/跃迁.md`、`docs/game/screens/跃迁-星缘相邀.md`;本档只管操作路由与消耗红线。2026-11-12 实机探索建档完成。

## 1. 机制速览(实机实证)

- **池子六类同页**:左侧列表切池——角色活动跃迁×2、光锥活动跃迁×2、联动跃迁(如 Fate[UBW],长期开放)、常驻跃迁(永久开启)。数量与顺序随版本变。
- **票种三色**:角色池/联动池 = 星轨专票(黄);光锥池 = 星轨专票·武意(暗红);常驻池 = 星票(灰蓝)。160 星琼可兑 1 张对应票,跃迁1次耗 1 票、10 次耗 10 票(不足票以 160 星琼/张抵扣)。
- **星缘相邀**:角色活动/联动池抽到 5 星角色时的自选补偿名单(玩家在「跃迁-星缘相邀」页编辑,bot 不代编辑)。

## 2. 消耗红线(在通用红线之上加严)

1. **跃迁1次/10次按钮 = 消耗控件**:点击即扣票/扣星琼(抽卡无支付确认弹窗,一点就扣)。**bot 永不自动点击**;收到用户抽卡请求时,抽卡量与池子必须逐次获用户明确确认(抽卡决策归 sr-od-game-coach 的投入评估)。
2. 「查看详情」「星迹重温」等零消耗页面可自由探索,但见 §4 坑位清单。

## 3. 操作路由

| 任务 | 路由 | 状态 |
|---|---|---|
| 读抽卡资产(星琼/票数/当前池) | op `ReadWarpStatusOp`(`cultivation/account/operations/read_warp_status.py`):任意画面起点 → 跃迁页读数 → 可选回大世界收摊;MCP `run_operation('ReadWarpStatusOp', {back_to_world: true}, block=true)` 的 `data` 携带 pool_name/pool_type(character/cone/collab/standard)/stellar_jade/special_pass(专票)/standard_pass(星票)/warp_progress(万象和鸣进度);2026-11-12 活动/常驻两态实机验证。⚠️ **专票个位数(如「7」)可能读 null**:OCR det 对孤立单字符漏检(引擎边界,两位数稳定)——读数层已做两层取数(全图过滤+3 倍放大兜底)仍偶发 null,null 不阻塞,精确值以游戏内为准;治本方向(数字模板匹配)见坑位清单 | 可用 |
| 进跃迁页 | 大世界右上「按钮-跃迁」(**pc_alt=true** 点 1477,10-1547,88;goto 已建) | 可用 |
| 切池 | 点左侧列表缩略图 slot(y≈215/320/420/500/610/725),**切完必须识别验证**(池子数量随版本变,盲点会错池) | 可用(手动) |
| 执行抽卡(1次/10次) | op `WarpOp`(`cultivation/account/operations/warp_once.py`):在跃迁页**当前选中池**执行跃迁(不切池——调用前先选定池子),抽完自动关结果画面留跃迁页;2026-11-12 全链实测。**消耗红线**:仅限用户明确授权的抽卡请求调用,agent 不得自行发起;票不足不自动兑换星琼(fail 由用户裁决) | 可用(须用户授权) |
| 退出收摊 | 点右上 ×(1830,30-1885,90)回大世界(goto 已建;两 op 均有 back_to_world 参数) | 可用 |

## 4. 坑位清单(实证)

- **「查看详情」是内嵌网页**:实测点击后画面卡在模糊加载帧不动(网络慢时长时间不回),ESC 可退出——bot 不进此页,概率知识走文档。
- **「星迹重温」动画页的 × 直接回大世界**(不是回跃迁页)——误用会打断导航链。
- **UP 名/剩余时间位置随池型漂移**(信息卡两型布局):固定 rect 读数仅对部分池成立,通用读取需全屏 OCR。
- 光锥池无「角色试用」按钮;常驻池无活动标签、无剩余时间行、货币栏少进度条——判池时把这些 sub_state 当信号。
- 顶部「N/3200」进度条是商店「万象和鸣」活动入口(点击跳商店-推荐商店),不是星琼余额。
- **抽卡结果画面的「点击任意处继续」对极短点击不响应**:controller.click 默认 press_time=0 点不动,必须带 0.1s 按压时长(WarpOp 已内置,复用时勿回退到 round_by_click_area)。
- **货币数字读数的引擎边界**:全图 OCR 能检出多位数(「12183」「13」)但漏检孤立单字符(个位数票数);裁剪小图的 det 响应随输入尺寸浮动(对「12183」小图反而检不出),3 倍放大对单字符偶有检出但不稳定——ReadWarpStatusOp 用两层取数(全图过滤→3 倍放大兜底)已到 OCR 路线上限,**治本=数字模板匹配(0-9 模板×双区域)**,首次强需求时再建。货币 area 矩形已视觉校准(票数字≈1567-1581/星琼数字≈1671-1733,均在各自 rect 内),rect 不是嫌疑项。
- **抽卡消耗确认**:「跃迁1次」点击即扣票无确认弹窗;专票不足时游戏弹星琼兑换确认(160/张,未建档)——WarpOp 对票不足的处理是 fail 而非自动兑换。
- 结果画面稀有度形态只实测过 4★(光锥/角色两样本);3★ 更简朴、5★ 有专属动画,闭环设计(循环点击至跃迁页回归)天然兼容,展示时长差异由节点预算兜底。

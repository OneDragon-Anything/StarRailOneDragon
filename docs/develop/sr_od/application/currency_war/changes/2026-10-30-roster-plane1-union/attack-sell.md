## 发现清单

### S-1｜升级等钱收敛性论证引用不存在的机制（待付窗买牌持续吃金未申报）
- 攻击点：§2.5「无新增死锁面……资金序已保证升级金优先于买牌金/刷新金（11 §2/§3）」。11 §2 的「升级金优先于买牌金」指 emit 帧转场排序（先升级再找牌），**不是买牌为升级让位攒钱**；as-built 是：序 1/2 义务买入「不过利息规则门，店面出现即买」（11 :23），升级待付窗「会话照常进入买牌六序与刷新判据」（shop.py:673-678、11 :53），刷新让位只辖刷新（11 §3 :86）不辖买牌。凑金删除后 defer 帧继续义务买牌吃金，升级发射金来源退化为「义务面买尽 + 净收入」，追星缺口成员任意星级照买（shop.py:892-902）可长期压低金位——升级延迟显著放大，而收敛论据引的是不存在的机制。
- 证据：design.md §2.5（:114）；[11_shop_decisions.md](../../strategy-docs/11_shop_decisions.md) :23/:53/§3:86；shop.py:673-678、:892-902
- 严重度：高
- 处置建议：收敛论证改为「义务面买尽 + 净收入」的真实机制并补升级延迟观测锚，或承认需新增买牌让位/攒批机制再删凑金。

### S-2｜「席满路径行为不变（特例）」与排序池扩大自相矛盾
- 攻击点：§2.2 第 4 项导语称六步广义化「仅席位约束 = 其特例，行为不变」、§2.5 称「席满路径行为不变（特例）」、§3 称「席满触发路径现行用例回归不变」；但步 4 把排序池定为「部署外件全集（备战席 ∪ 场上部署外件）」，而现行六步池 = 备战位、明文「场上件不入卖出池」（shop.py:1094、11 §4.0 步 5 :136-137）。场上部署外杂件比 bench 末位更低的帧，victim 从 bench 件（店内卖、店内闭环）变为场上件（意图槽 + 关店跨画面）——victim 选择与执行路径双变，「行为不变」与池扩大不能同时成立，验收断言「现行用例回归不变」必与之冲突。叠加态（席满 ∧ 金不足）现行是先置换后筹资两段（shop.py:1291-1308），新设计一步合并，也非「不变」。
- 证据：design.md §2.2 第 4 项步 4/导语、§2.5 :112、§3 :134；shop.py:1090-1098、:1291-1308；11 :136-137
- 严重度：高
- 处置建议：二选一——如实申报席满路径 victim 池与执行路径的变化并改验收断言，或席位支维持 bench-only 池。

### S-3｜虚拟金币「利息维度」无判定式，press 类 X 的参与与下界均未定义
- 攻击点：步 5 宣称虚拟金币「含利息维度——交易后剩余金可坐到的利息档位，口径与买入侧金约束门同源，前提 = X 已过买入判类」，步 6 让位成立条件只写「虚拟金币 ≥ 0」，无任何利息下界——两处无法同时落地。且「买入侧金约束门」本身双形态：序 1 义务类金门 = 纯 `gold < cost`（shop.py:1296/:1305，无利息下界），序 3-5 press 类 = `gold − cost < s_reserve` 拒（shop.py:1726/:1735）。「X 已过买入判类」在金不足触发帧对 press 类 X 语义未定义（含金门的判类必不过），现行筹资只挂义务类臂（`_fund_or_none` 仅序 1/2，:1275-1279、:1306/:1349/:1394），新评估若纳入 press 类 X 即行为扩大（为 discretionary 买入筹资击穿利息线），若不纳入则「触发 = 席满 ∨ 金不足」的表述需分类改写。实现者无法从设计推出让位成立式。
- 证据：design.md §2.2 第 4 项步 5/步 6；shop.py:1296-1306、:1726-1735、:1275-1279
- 严重度：高
- 处置建议：定死判定式（下界取 0 还是 s_reserve/saturation_line）与 X 参与评估的判类定义（义务类 only 还是全序）。

### S-4｜意图槽「节点边界失效」无实现载体，节点戳语义未定义
- 攻击点：设计称载体 = StrategyState 具名字段「对局内跨画面恒存，节点边界失效」，但 StrategyState 节点作用域键的失效由 `_NODE_SCOPE_RESET_TABLE` 显式登记承载（mandate_state.py:264-268「新键登记进表，禁各自散写重置逻辑」），设计未指定登记；`shop_handled` 的「值比对双保险」（session_scope.py:419-428）是新槽没有的机制。照字面实现（加字段不进表）则槽跨节点残留，旧节点意图在新节点经「V 仍在手 ∧ 部署外」碰巧校验通过即误卖；「节点戳」字段写端/比对端/失效语义也全未定义。§3 测试「节点边界 → 槽失效」无设计依据可测。
- 证据：design.md §2.2 第 4 项跨画面意图槽段、§3 :136；mandate_state.py:264-268、:275；session_scope.py:419-428
- 严重度：中（若照抄实现则高）
- 处置建议：明确登记重置表 + 节点戳写/比/清三端语义。

### S-5｜priority_insufficient 拦因复用的解拦轴错配，前提失效未申报
- 攻击点：`blocked_by` 闭集把 priority_insufficient 定义为席满语境「席位空出即失效，与席满类同轴解拦」（mandate_state.py:70；criteria/shop_session.py:339-341、:357-361 实现同轴）。新设计金不足语境也产 priority_insufficient（步 6），而金不足帧席位常空 → 每节点入口即解拦重开店、进店重评再入清单，直到金位涨够或牌消失——每节点一次空开店的循环行为未申报；且「席位空出后买入不再经六步流程」的解拦前提在新设计（金不足仍走让位评估）下失真。解拦规则的对应改动不在改动点清单，也不在正本更新清单（11 §4.1/23 号篇解拦语义）。
- 证据：design.md §2.2 第 4 项步 6、§3 :134；mandate_state.py:70；criteria/shop_session.py:357-361
- 严重度：中
- 处置建议：金不足语境改用 gold_short 键或为其定义金位解拦轴，并列入改动点与正本清单。

### S-6｜「席位受阻 ∧ 它腾出席位」与场上件意图槽出口不闭合
- 攻击点：步 6 让位成立条件 = 「席位受阻 ∧ 它腾出席位」∨「金受阻 ∧ 前缀可足」；victim = 场上部署外件卖出**不直接腾 bench 席**（间接腾位靠部署补人链，设计自己也写了「bench 满时补人上 field 自然腾出 bench 位」）。纯席满（金足）帧末位 = 场上件时：第一支按字面不成立、第二支无金受阻不成立 → 让位不成立 → 但分流路径又为场上件配置了意图槽出口。该帧该「放弃买入」还是「走意图槽」设计无答案，两处表述互斥。
- 证据：design.md §2.2 第 4 项步 6（成立条件式 vs victim 落位分流）
- 严重度：中
- 处置建议：把「腾出席位」定义为含部署补人间接腾位，或限定席位支 victim ∈ bench。

### S-7｜_step3_liquidation_pending 删除的抑制面行为变化未申报，语义裁决推给落地批
- 攻击点：该函数 as-built 抑制面 = `verdict != GATE_MISS` 即**全部判据命中帧**，docstring 明写「等级帽/奖励帧拦截等非金拒帧也进抑制面……凑金优先于凑息，抑制面拓宽、方向保守」（entry.py:919-940）。设计称「抑制对象消亡，候裁随批删除（落地批核对其余判定分支是否有独立语义）」——等级帽/奖励帧（判据命中、金已足、等帽解除）删除后凑息从「抑制」变「照常」，是未在 §2.5 申报的行为变化；且「落地批核对」把语义裁决推出设计，违反「实现者无需再设计」。附带：levelup.py :385-388 从 entry import `_bench_liquid_gold`，删除函数须连 import 一起删（设计未点名，靠实现者自查）。
- 证据：design.md §2.2 第 3 项末条、§2.5；entry.py:919-940、:1244-1245；levelup.py:385-388
- 严重度：中
- 处置建议：设计内裁定非金拒帧凑息行为（保留抑制或申报放开）并写进 §2.5。

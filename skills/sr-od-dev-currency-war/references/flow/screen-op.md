# 画面 op 与观察域(screen-op)

> 组件 = `operations/cw_screen/`(一画面一 op)+ `obs/`(一屏一解析器)。路径根 = `src/sr_od/application/currency_war/`;代码定位一律用 `文件::符号名`。

## 1. 画面 op(职责四段 · node = 1 + N + 策略器按需)

- **一画面一 op**,每屏独立类直继承框架 `SrOperation`(无共享基类)。职责按四段组织:识别 → 上报 → 特殊画面流程处理 → 正常画面的策略器处理。

1. **识别**:本屏身份判定(门);
2. **上报**:显式读屏〔唯一读屏点〕→ CwScreenXxxObs → `report_screen_*_obs` 落状态容器(`kernel/cw_screen_report/` 每屏一文件)——**上报先于处理**,特殊流程与策略器消费同一份观察;子态分支例外(备战特殊流程段,见「备战(CwScreenPrep)特殊」行):非常规子态帧的子态识别前置(段 1 先于读屏上报,命中即跳过全量读屏与上报),段 2 语义扩展 = **子态流程事实写**(Match 流程态字段配对写 + 接管失效写)非 obs 上报——流程事实不进状态容器(真值域不混流程事实);
3. **特殊画面流程处理**:弹窗/锁定态/按钮换形态这类**答案固定**的状态——画面 op 自己的流程反射(识别 + 点击 + until 验证),不问策略器;
4. **正常画面的策略器处理**:需要判断的交策略器——决策(状态容器零参读;本帧无动作 = Obs outer_loop 口径)→ 动作〔零读屏〕→ round_wait 循环无防御上限;**终结动作返回主循环**。

- **分段判据**:答案固定的 → 特殊流程;需要判断的 → 策略器。(「单选族」= 事件选卡屏的旧称:有选择面但选完即走,选择判断归策略器、确认链是机械反射。)
- **出口语义**(决策循环只有三种出口):①**终结动作**(执行即本访问结束返回主循环);②**异常 fail**(策略/执行异常上抛交外循环 retry 链;空候选 = 零点击 success 交回,禁盲选派发);③**Obs outer_loop**(本帧无动作的合法返回)。决策无有效输出/返回词表外类型 = 具名 round_fail 保留证据,不发出无依据的动作。
- **画面 op 不支持局外单独调用**:是对局上下文内的组件,不设单跑防御分支、不设兜底决策路径——无 match 场景由上下文缺失自然失败。
- **已登记变体:等待 1-1 就绪等待**(全部画面 op 中唯一允许观察 node 内轮询的特例):1-1 开局补给动画长且无结束标志、备战 id_mark 区分不了画面身份,只能判「备战面板就绪」——轮询放观察 node,超时 = 存图保留证据 + round_fail 交外循环。闭集 = 本条唯一,新增观察轮询屏先登记再写代码。
- **复盘同步义务**:新增/停用画面 op 须同步渲染器 `skills/sr-od-dev-currency-war/scripts/replay_to_md.py` 的画面注册表(ACTOR_REGISTRY/SCREEN_REGISTRY)——未注册的 CwScreen 前缀 actor 会在复盘报告暴露「未注册写入者」尾注。
- **node 结构 = 1 + N + 策略器(按需)**:识别+上报合并一个 node(门 → 读屏 → 上报);特殊流程每类一个独立 node(按需 0..N,**禁多个特殊流程挤在一个 node**);策略器循环一个 node——**有判断需求才有**:处理方式全固定的屏无策略段,画面 op = 1 + N(启示 = 敌人信息浮层待建形态)。特殊流程 node 的本段识别(标志判定/确认定位)= 决策环读屏例外第三类(§2)。「识别+上报合并一个 node」的线性序在子态分支例外:备战子态识别四查落观察 node 最顶部(先于读屏上报,命中即跳过读屏上报)——子态识别前置 = 识别的细化,处置段的 node 归属按「同画面子态的 node 归属」判。
- **同画面子态的 node 归属**:同一画面的不同子态,处置类似(同一段处置逻辑,子态只是入口条件不同)→ 可共享一个 node;子态间处置互斥(某子态一定只做的事,另一子态完全不做)→ 每类处置一个独立 node——处置完成的出口直达终点(round_success 专属状态词、无后续边 = 本访问结束交回主循环),未命中子态经状态词条件边过到下一处置 node。
- **弹窗归宿形态三分**:
  - **有独立 id_mark 身份的弹窗屏** → **独立画面 op**:四段只走「识别 → 上报 → 特殊流程」即交回主循环,无策略段(先例 = `CwScreenDeployNotFull` / `CwScreenNoFrontHint`——出战单击后渲染的两类真弹窗,经主循环阶段一身份分发接管);
  - **无独立档但经阶段三规则派发的独立 op**(消耗品浮层/阿哈装备)= 合法现役形态——归宿细化(判定的宿主与 op 门形态)随下批迭代裁;
  - **无独立身份的浮层/子态** → **宿主画面 op 的特殊流程段**。
- 备战(CwScreenPrep)特殊:heavy 观察+接管补采+审计留在观察侧的观察 node;决策动作 = 单动作 while 循环;商店编排(`_open_shop_phase`)。**特殊流程段消费首批实例 = 备战交互三段链**(自主循环备战分支迁入,迭代 2026-11-18-prep-special-flow;宿主表述 = `operations/cw_screen/cw_screen_prep.py`):观察 node 最顶部**子态识别四查**(先于 match 缺席门/清场/收店探针/heavy/补采/审计;优先序 0 > a > b > c)——0 锁定确认态(`Match.locked_resume`,含段3b retry 耗尽后主循环重派发的重入帧,直达段3b)/ a 返回按钮子态(OCR「返回投资策略选择」lcs 0.9 防线)/ b 接管局探针子态(触发门 = `opened_via=='takeover' ∧ not probed`,接管必经含 1-1 接管照探;分支进入即接管失效写〔先于探针点击,触达面 = 接管必经〕→ 点「按钮-商店」试探〔识别性点击,读屏例外 §2④〕→ 判定〔可开=非锁定 / 不可开=锁定〕→ 探后去重标志一次写;非锁定收店恢复后按序跑齐全部既有前置段走常规 / 锁定三字段配对写直达段3b)/ c 补给分流子态(nodeseq current=supply ∧ 补给未确认);子态命中即跳过全部既有前置段,查全否走现行全量路径零变化。决策动作 node 顶部(段序号置位之前)**三处置**:a 点返回〔成败均交回,计数 = `cw4_counters` 分键 `back_to_strategy_symptom`〕/ b `locked_resume_sync_and_battle` 同步步+出战〔成功 = 锁解除+交回;未执行 retry 保锁,每访问 4 次,耗尽 → 访问 fail → 外环 fail-streak〕/ c 点「返回补给阶段」〔成败均交回〕;交回 = round_success(wait 2/3/2),战斗窗置位由外循环回调统一承载。三子态不拆独立 op(宿主同 = 备战画面,派发依据双识别标志无独立身份);三处置互斥(a 只点返回投资/b 只锁定出战链/c 只点返回补给)→ 按「同画面子态的 node 归属」应拆三个独立特殊流程 node,现状三类处置挤在决策动作 node 顶部 = 待整改(登记在跨迭代挂账板「备战三处置拆独立 node」条)。
- 行为规范与观察域细则 = 本篇;逐屏观察实现细节 = obs 解析器代码注释;画面身份 = screen_info yml(id_mark 组合)+ [loop.md](loop.md) 分发规范;画面能力面(每屏能发什么动作)= [action-op.md](action-op.md) §6。

## 2. 观察域(obs/)

- **唯一读屏点**:画面 op 观察 node 的显式读屏(备战入口 heavy 观察 `obs/cw_observe_full::observe_full` 为其重型形态);已登记读屏例外四类——①策略显式发出 Obs(in_place) 触发的重观察;②终结分支返回前机械保留证据读(零决策零判效,读数只进缺陷台账);③特殊流程 node 的本段识别(§1 段 3:答案固定状态的标志判定与确认定位,先例 = `CwScreenDeployNotFull` 落地复查位与 `CwScreenNoFrontHint` 确认后的标志复测);④段 1 子态识别的识别性点击(备战特殊流程:探针点击〔点「按钮-商店」试探商店可开性〕与非锁定收店恢复点击——点击 = 识别手段非策略动作,裁决结论经段 2 流程事实写上报)。
- **观察标准化门**:观察内容在所属域存在标准注册数据(名字类:投资环境/投资策略/角色/装备等注册表)时,观察 node 必须把读数**转换成标准注册数据再上报**——转换两段:①形变归一(分隔符/全半角等 OCR 形变族)后精确匹配;②不中再 LCS 相似匹配(域级单一实现 `kernel/cw_obs_core.py::lcs_resolve_strict`,阈值常量住各屏);两段皆不中 = 转换失败。**LCS 阶段执行次高分差拒判**——最高分未明显高于次高分 = 歧义 = 转换失败,禁直接取最高分。**任一候选转换失败 = 观察失败**:round_fail 早退、不写状态容器不上报,交外循环重读(读不准重读,禁带病上报);多候选命中同一注册名(选项互斥屏)同判转换失败(重复名合法的观察面不适用)。标准化后下游全链只在标准名上工作:决策消费标准名,动作上报只携 idx,名字由状态容器标准名单一源按序号提供——动作/上报层零名字转换。未标准化的名字类直报 = 待修问题,禁新增。
- **实例载体纪律**(决策输入与机械执行载体分立):凡用于**决策**的输入(候选内容)与**门槛判定**(候选非空)一律取 **obs 载体**(观察 node 挂实例属性)或**状态容器槽**(零参读);画面 op 实例上的其他载体只准存**机械执行细节**(点击点等「往哪点」),禁承载决策输入、禁作决策门槛。
- 观察 node 上报 = `report_screen_*_obs` 落状态容器(`kernel/cw_screen_report/` 每屏一文件)。**上报接口包形态**:每屏一文件(obs 类 + report 函数同居,与动作侧 `cw_action_report/` 每动作一文件对称);obs 类 = `CwScreenXxxObs`(该屏一次观察的类型化载荷,纯数据);上报函数 = `report_screen_<snake>_obs`(「一个上报概念一个形状」,禁按类型聚合的分派转移函数)。节点推进上报族例外:推进走 kernel `report_node_advance`(trigger 封闭集 {settle_confirm, supply_finish}),不设 report_screen 形态。chosen_*(选择落地记录)不进 report——由动作上报/获得链按「点完即写」契约承载,字段级归属 = 代码字段定义注释(`kernel/cw_game_state.py`)。
- **观察对账唯一发生点**:推算状态 vs 下一帧实读的比对只在观察边界(report 进状态容器时,由 game state 执行仲裁 `kernel/cw_reconcile.py`);其余任何层不做双态比对。
- 观察 node 上报 = `report_screen_*_obs` 落状态容器(`kernel/cw_screen_report/` 每屏一文件)。
- **坐标伴随域(观察必须产出坐标)**:观察域识别的「可选/可交互实体」(选项卡/备战栏条目/装备栏条目/晶矿/浮层按钮等),其上报事实一律携带画面坐标(cx/cy 或等价定位)——状态容器字段与 MCP extras 同源可得,坐标不得只存在于 extras。用途 = 动作原语参数面③类(动态坐标显式传参,见 SKILL.md §1.4)的坐标来源:动作 op 按坐标/idx 自取,零内部识别。写端 = 观察上报单点整表覆盖,随帧刷新;**禁逻辑写端**(动作后回填坐标——实体获得时点无画面读数),坐标缺席语义 = 发出面跳过自愈、下帧重派,禁回填猜值。先例:pick 族坐标伴随域(事件线选卡动作按 idx 自取坐标)、`owned_equip_xy`。
- **观察层失约抛错**:决策入口消费的 payload 槽离屏 None = 观察层失约(如 shop payload 离屏)——显式报错,禁策略侧兜底。
- 识别器(`obs/recognizers/`)注册为 `analyze_screen` 的 extras 扩展,MCP 读数与画面 op 观察同一实现(双消费面,见 SKILL.md §1.4)。
- **识别不到就是 bug 停机闸**(与动作域「点完即写」同族规范):商店未识别卡、召唤物/物品未识别等观察域停机见 [guards.md](guards.md)。

## 3. 观察解析工具箱(obs/ 地图)

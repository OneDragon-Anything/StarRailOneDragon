# DD-011:操作完成自等动画规范——稳定门(gate)进入退役

- Status: accepted(用户裁定 2026-09-02:「稳定门是旧时代的产物,慢慢去掉;op 完成后必须等待其动画时间,主循环基本不去关心画面稳定」)
- 关联: DD-010(装备区识别纯化,同一哲学:识别器/op 不做画面状态判断)

## 决策

**操作完成自等动画规范**:

1. 每个会改变画面的操作,op 在动作完成后**等待其动画时长**——时长是该操作的
   固有属性,声明在动作调用的 `success_wait` 参数处,注释带出处(口述/实测条目,
   知识档 `screen_flow_timing.md`)。等待结束 = 该 op 对画面状态的承诺完成。
2. 主循环与识别层**不再等待/验证画面稳定**:op 返回成功后直接在当前帧上识别。
3. 动画偶发拖长/未知 overlay 的兜底 = 既有 retry/fail-closed 机制(识别不中预期
   画面 → round retry / bail / 对账缺陷),不预判、不设第二道稳定验证。
4. **稳定门退役**:`wait_stable_frame`/`preset_stable_baseline`/三 profile(ADR-0213
   引入,ADR-0264 融合加速)进入退役流程——调用点逐个替换为「op 自等」,全部清完
   后删除模块(含指纹/fast_confirm/基线预置机制,删除前机制文档化存档)。

## Why

稳定门是「画面身份识别不成体系」年代的测量驱动产物:用截图+全图 OCR 锚定+像素
指纹+时间窗来回答「画面稳了吗」。现在建档识别(id_mark)已能一步判定画面身份,
gate 的确认价值与建档判定重复;而其结构成本(每点 1.6-2.2s 的预睡+确认窗,读数
还被 poll 的全图 OCR 量化)是备战阶段主要等待源之一。「画面稳了吗」的知识本来
就属于产生动画的操作(它知道自己做了什么、动画多长),不属于观察者——归属归位
后,主循环只管「识别→决策→动作」,稳定问题在动作侧闭合。

## Consequences

- 动画时长声明值错(偏短)→ 收尾识别采到尾帧 → 由既有防线暴露:字段级 sanity
  bounds/新鲜度门(hp)、期望态对账(equip/buy)、round retry(画面不中)。
- 时长声明是新的维护面:游戏版本改动画时长 → 值过期 → 表现为偶发 retry 上升,
  由 retry 计数与缺陷台账暴露后校准。
- op 间既有固定间隔(success_wait 之外)若与动画等待叠加,迁移时顺手收敛,
  不保留双份。
- gate 模块删除属破坏性变更,须在迁移清单清零后单独批执行(含测试仓 gate 测试
  同步退役)。

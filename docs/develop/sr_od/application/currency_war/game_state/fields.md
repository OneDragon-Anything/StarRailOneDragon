## 1. 三个名词

- **GameState**(正名兑现;原暂名 BoardState,符号 = `kernel/cw_game_state.py`)——当前仍为
  真的局内已知事实快照。单例,每局新建,只描述「此刻」,不是「本帧画面」;跨画面
  保留的字段与不经画面写入的账本也在其中。历史序列一律归遥测。画面 op 与决策 op
  写,策略器读。
- **StrategyState**——默认策略实现的私有状态(配方方向、义务账本、信号、旗标),
  归策略实现层、框架层不感知(符号 = `strategies/impl/mandate_v1/mandate_state`;
  基类 = `CwStrategy(Generic[_TState])` 仅泛型携带)。归属判据:换一个策略实现就
  不存在的字段放这里;游戏里能观察、框架按游戏逻辑能算的,放 GameState。
- **遥测**——整局历史,每帧每动作照旧落盘。复盘/回放/统计从遥测拼,不从容器读。

## 2. 通用规则

### 2.1 一份数据,来源标记到字段

每个字段 = `{值, 来源, evidence?}`(结构 = `Field[T]`,符号 = cw_game_state.py)。
来源两态 + 随机扩展 + 两个子模:

- **observation(观察)**:亲眼看到的——用本帧识别结果覆盖旧值。sim 侧以 GameState
  真值合成时同样记 observation,evidence 恒带 `sim:synthesized`。
- **logic(逻辑)**:决策动作按游戏规则推算的预期效果,经 `write_logic` 直接写字段
  (两态制);字段值之后仍会被观察覆盖(§2.3)。
- **logic_rand(逻辑随机,随机扩展)**:**效果随机的动作采样链**写入口径,经
  `write_logic_rand` 直接写字段。值 = 一个可能世界的快照,三形态:**采样值**
  (上报函数真掷随机、按采样结果走完整确定性链)/**未变标记**(未抽中类型的
  域值原样、仅翻来源)/**确定外壳**(确定部分照算、随机细节兜底)。观察覆盖
  差异 = 随机效果落地**预期内**,落 `logic_rand_outcome` 记录行直接采纳新读数(无告警
  无停机,不经失配的三种标准处理分支——首现注:三分支 = 白名单差异直接采纳 / logic_rand 预期内差异记录采纳 / 真失配记缺陷并停机);**策略器消费前必须重观察**(查询入口 =
  `logic_rand_fields()`;跨动作污染经 `any_logic_rand()` 入口判定继承)。
  首个落地 = 点晶矿(临时口径 v0,`kernel/cw_ore_reward.py` 常量面,待采集
  校准)。
- **carried(沿用值,子模)**:这一帧没读到、保留上次好值时写入,evidence 必带
  `carried:<来源帧>`——防旧值在遥测里被当成「本帧真读」。
- **prior(先验,子模)**:来自历史遥测调查的先验写入(如开局 hp 先验,§3.1.6),
  evidence 必带 `prior:<来源>`;仅限显式申报的条目,禁扩散。
- **载体中继(session_carrier 约定)**:接管/初始化时把会话已知事实补写进从未写过
  的字段——不设专用中继来源类:中继经 `GameState.relay`,source=logic
  (evidence=session_carrier),已有正式值的字段一律跳过。**空值=未知态禁中继**:
  会话默认空值('''/[])不是已知事实;**五镜像字段封闭集** = `active_strategies`/
  `active_env`/`plane_bosses`/`enemy_affixes`/`selected_difficulty`(校验锚 =
  sr-od-test test_cw_game_state_batch4);新增第六镜像喂入点必须同步扩本集与该测试。

evidence 为可选来源注记,记录证据分级(帧标签稳定范围、当场读还是开局恒值、
`superset` 标记等,随各字段申报)。

### 2.2 识别质量是写入闸门,不是字段

读不到/不可信就不写,保留上次好值;容器里只有「当前最好的已知值」。无质量位:
`None` 只表示**这一帧没读到**,不表示「未建模」——未建模的字段根本不进 schema,
缺域由 gs_schema 的域版本键表达(§3.7.1)。「机制性 None」(该画面机制上读不到)
按字段显式申报(§6.3 同源申报面)。**失读帧的字段处置二选一(统一口径)**:
①字段已有正式值 → 写 carried(沿用+来源帧标注);②字段从未读过(机制性不可读态
+新局)→ 字段保持 None。硬边界:字段一旦有过正式值,任何失读都不得把它清成 None。
**carried 沿用守卫收窄(开局预填初值批)**:现值来源为 `logic_rand`(预填初值/采样链)
时失读**不沿用**——读不到时宁可让字段保持『未验证』,也不允许把随机推算值改标成
『沿用上次读数』——那会把猜测伪装成可信值(假值防线 §8.8 同源)。
**画面附加域显式例外**:shop/encounter/supply payload(§3.3/§3.4/§8.4)语义=
「当前画面的 payload,非当前画面=None」——离开画面置 None 是结构事实非失读,不适用
carried、不受本硬边界约束;在屏失读不写、沿用旧值,在屏与否由分类子态判定(§3.2.17)。

### 2.3 观察与逻辑冲突:以实际观察为准

观察覆盖 logic 值 + 来源改回 observation + 失配记入缺陷记录表
(`observe_vs_logic_mismatch`)。失配 = 推算代码 bug:保留证据后修推算代码,不做运行时
挂起式的对账兜底(错误哲学)。**逻辑随机态旁路**:logic_rand 来源值的覆盖差异 =
随机效果落地**预期内**,落 `logic_rand_outcome` 记录行直接采纳新读数(无告警无停机,不经
三种标准处理分支;等值观察零新信息不产行)——随机口径本就不承诺真值,差异是随机模型
校准遥测面,不是推算缺陷。

### 2.4 写入规则与两个关键结构

写入点以**写入时刻的单例现引用**为基底构造新帧(frozen 帧替换),禁止拿旧帧跨时段
写回。**读不分域**:按画面分组只是方便组织写入,读取时不分区域。两个关键结构:

1. **帧观察完整度标注**(full/view/none)——消费即清;停更检测哨兵用只增不减的
   写入次序号 `write_seq`,不用该标注现值。
2. **gs_schema**——域粒度版本映射(域全集 = `DEFAULT_GS_SCHEMA`,§3.7.1)。

### 2.5 逻辑写入:直接写字段(两态制)

决策动作生效后,按游戏规则推算的预期效果经 `write_logic` 直接写入字段(来源=logic),
策略器立即可读——「在观察态到来之前供决策使用」是逻辑态的全部职能。
> 术语注(首次出现):逻辑态 = 动作执行后不经观察、按游戏规则推算并直写容器的预期状态;真值以下一帧观察为准(以实际观察为准)。推算不是免检
通道:字段值之后仍会被观察覆盖,失配 = 推算代码 bug。原「先记预期、核对转正」的
两步机制(expect/confirm)已随两态制裁决废除。

**逻辑随机态扩展**(来源=logic_rand,写入口 = `write_logic_rand`;**采样语义**,
2026-09-20 logic-rand-sampling 迭代):效果随机的动作在上报函数**真掷随机**,
按采样结果走完整确定性链逐步直写,**全部容器写标随机态**——含终值受随机
分支影响的联动写(如晶矿摘除:后续晶矿开否取决于采样奖励是否耗席,spheres
终值同属采样世界)。值三形态 = 采样值/未变标记/确定外壳(§2.1);观察覆盖
差异预期内(`logic_rand_outcome` 记录行,§2.3),**策略器消费前必须重观察**
(查询入口 = `logic_rand_fields()`;对账巡检面 `logic_written_fields()` 不含
随机态字段;跨动作污染经 `any_logic_rand()` 入口判定继承)。与域级跳写的
分工:采样口径已登记的动作走随机态直写(实机=猜测,sim=世界真值,同一上报
函数两副面孔);未接采样口径的随机效果(如刷新后的整店铺面)仍按域级跳写
留观察。首个落地 = 点晶矿([logic-updates/collect-ore.md](logic-updates/collect-ore.md);
临时口径 v0 待采集校准,常量面 = `kernel/cw_ore_reward.py`)。

## 3. 字段清单(按画面组织)

> 组织规则:字段写在「能写入它的画面」小节里。一个字段能在多个画面写入,主条目写
> 完整语义(None 含义/边界/效果修饰),其余画面条目互引不复制。画面切换不重置字段:
> 没有新写入就是保留值(跨画面沿用标 carried,§2.1)。各画面上的决策操作写入规则
> 见 §4,各画面小节尾有指引。**开局预填初值**:阵容/经济域中 §2.6 所列字段在新局/
> 中断恢复的对局每局全新创建即含种子(rand 态),本节各字段「None=未观察」语义在生产容器上自创建起
> 不可达(直构容器/sim 域保留);各字段行不再复述。

### 3.1 开局序列(难度确认 → 简报 → 位面过渡)

> 开局只写初值;之后整局由各画面自己的写入方接管(各字段主条目)。

#### 3.1.1 职级 selected_difficulty

开局写定,恒稳,之后整局不再变化、不再需要画面。可见画面=难度确认屏(已建档:
标识-当前难度职级);开局简报是否显示职级未建档采证,接线前先补档(§3.1.2 同款

标准 / 超频博弈。可见画面=难度确认屏 + 开局简报(开局写定);**两屏均无建档区域**,

#### 3.2.7 部署容量与后排布局档 back_layout

**语义**:上场单位站两排——前台恒 4 格;**后台一排的格子数会变**(正常 6 格,实拍
最多 9 格)。本字段=「当前这一局后台实际画了几个格子」,决定部署/拖动用哪套槽位
坐标(选错坐标=往不存在的格子上拖)。
**机制(终判)**:后台格数 = 6 + (cap − 等级),**值域 6-9、上限 9**;与
等级无关(旧「等级≥7→8 格」模型已被三帧实拍推翻);等级只进 cap 板满门、不进布局
选档。备战席容量也不随等级变(恒 9,唯一例外=节省工位,§3.2.5)。
**识别(三信号+裁决序,`cw_back_layout.py`)**:
1. **公式通道**:OCR 读「部署数」区域得 cap(防抖;**域外处置=双帧一致
   采信**:域外值重读一帧,两帧一致且 level≤cap≤`DEPLOY_CAP_ABS_MAX` → 采信+
   obs_conflict 保留证据;cap<level 恒拒、超绝对上界拒、两帧不一致拒)− 等级 → 差值 →
   格数=6+差值(`back_slots_from_cap_diff`:差值<0 按 0;>3 封顶按 3;裁决值与坐标
   档分离,9 档坐标未建档由调用侧运行档退 8 格超集)。
2. **CV 通道**:后台那一排直接看图,按灰度差逐位判「有没有格子」(`cv_back_slots`,
   标定阈值已登记)。
3. **占用一致性仲裁**:部署人数−前台人数=后台应有人数,逐候选档比对占用最吻合档。
裁决序:两通道一致→采公式;冲突∧部署数可读→仲裁;冲突∧不可读→CV 结构证据;
CV 不可判/未建档→各自兜底(公式/防抖+8 格超集保留证据)。冲突必 obs_conflict 保留证据,
保留证据时把当局已选投资环境名单(active_env)列入归因输入。**环境扩槽通道**:投资
环境扩槽 6→7(实测+用户确认已登记)。
**画面识别基础**:画面档案建了三套后排槽位区域——6/7/8 格各一套(7 格整排居中重排,
排中心恒 960);选中哪档就读哪套(坐标单一真相源=screen_info)。
**写入规则**:布局档字段写**运行档真实槽位数**——6/7/8 档直读;实拍出现过 9 格
(可达真实档位,坐标建档待办提级),域外一律按 **8 格超集**读全扩展带,evidence 补
`superset` 标记(防超集近似被当精确值消费)。写入方三处:实机 = 三信号裁决链
`resolve_back_slots` 收尾 observe(未知态帧不写);sim = 合成口直写(evidence=
`sim:synthesized`,缺席不写);sim 环境条件发放回调 +1(财富宝钻扩展格,observe
渠道 min 9 封顶,§3.5.5)。已观测最大 cap=13。
**回归测试断言约束**:禁按未截断形态(线性外推)算预期、禁按 level 驱动表写。
**两笔未解问题**:①召唤物张力——钻石使 cap>level,召唤物是否经 cap 起效,尚未定论;②历史 8 格实证与公式差 1 的张力,双通道对账天然覆盖、不硬解。

#### 3.2.8b 声明队列 ore_declared_pending / ore_declared_done

**语义**:声明矿(按环境声明金额发放的金晶矿)环境(登记表 = `cw_investments.py::ENV_ORE_GRANTS`,在用
= 增发货币)的位面开局声明登记,**逻辑态域**(write_logic 专用通道)。声明 =
该环境在该位面开局应发的金晶矿金额(卡面直读,如增发货币位面 1/2/3 = 6/8/12);
发放形态 = 矿进入对局时附着(§3.2.8a 生成消费)→ 点击兑现入账。「已发/未发」
不可从 ore_rewards 现值推导(键随点击/清理/重挂消失),队列是唯一账。

- **ore_declared_pending**:`tuple[(env, plane, gold), ...]` 待兑现队列——
  env = 投资环境规范名,plane = 1 基位面号(与 NodeKey.plane 同坐标系),
  gold = 该位面声明金额。写入口三个(全在 `kernel/cw_ore_channel.py`):
  **入队**(电平检查 `check_ore_declared_level`:env ∈ ENV_ORE_GRANTS ∧
  (env, plane) ∉ pending ∧ ∉ done → 追加;电平触发单一规则——无边沿检测、
  无帧间记忆、无 op 成员,守卫状态放在 GameState,op 每备战环重建无可失忆)、
  **消费**(挂接入口生成刻出队当前 plane 条目、按生成集大小截断,与 done
  追加同一逻辑写原子承载)、**过期**(位面过渡顺手移除 plane ≠ 当前的条目,
  evidence `ore_declared_expired#p<old>` 留痕)。无观察写入方(声明是登记事实
  非观察投影)。
- **ore_declared_done**:`tuple[(env, plane), ...]` 已消费标记——幂等守卫
  第二道防线:同位面多备战环(跨环 op 重建)重查不重发;生成消费刻与 pending
  移除同逻辑步追加;位面过渡随 pending 同清理。
- **恢复局两形态各自闭合**:离线回放(done 随快照存续)→ 不重发声明;
  live 中断恢复的对局(active_env 恒空)→ 入队条件不触发(恢复局语义 = §6.3)。
- **开局预填初值** = `()` 两域(§2.6;与 ore_rewards 同族恒非 None);
  **快照恢复**:恢复表登记(逐元素 (str, int[, int]) 重建 tuple-of-tuple);
  **schema**:`DEFAULT_GS_SCHEMA['ore_declared_pending'/'ore_declared_done']`
  各 = 1 独立登记(§3.7.1)。

**官方卡文逐句**(卡文效果无结构化字段者经 §5.2 缺口登记获得归属,防假全覆盖)。

**扫描五源**:a=STRATEGY_ECONOMY 非默认条目;b=STRATEGY_EFFECTS 全条目;c=装备注册表
效果面(判定谓词=改写金/生命/容量字段∨改写单位装备归属∨发牌进席/解锁获得单位;
代码化=`cw_affix_effects.scan_rewrite_equipments`,申报表=`EQUIP_REWRITE_DECLARATIONS`
恰等测试看管);d=base 注册表发牌/出售面(判定谓词=效果文本含「获得…角色」∨「出售…
所有角色」);e=词缀注册表(判定谓词=改写金/生命/装备/单位面;代码化=
`scan_rewrite_affixes`)。

扫描方法论(四步):①五源×本文档全文做点名/族名覆盖矩阵;②效果族归属逐行×注册表
官方全文锚点核对;③具名锚点抽核实读(命中/错位分开申报);④判定分布申报=全覆盖/
部分/无归属,三数之和=条目总数。判据绑定「零无归属 ∧ 零部分覆盖」,**不绑定固定
条目数**——每轮扫描须随附计数口径与快照数申报(快照与计数明细记入货币战争当前
迭代的进度账本)。

**宝钻 cap+1 效果豁免显式申报**:deploy_cap 字段已已登记(§3.2.7.1,识别真值由采信门
观察写入方覆盖),效果侧不改写布局档字段——豁免申报面=「效果不经效果账本改写
cap/back_layout」,观察写入方照常跟踪真实 cap。

# 货币战争-战斗暂停

## 何时出现

战斗节点内主动打开关卡信息面板(点右上角 X,(1843,42) 一带,exit op 实证)或战斗中途停机后客户端残留的进度保留态(2026-08-30 局9 stop_run 实证:暂停面板带「战斗暂停/关卡信息」标题 + 底部三按钮)。

## 状态流转

- 入口:战斗中点右上角 X → 本面板(战斗保持暂停,进度保留)。
- 出口(实拍 + 退局 op 链实测):
  - **「继续战斗」** → 关面板恢复战斗;
  - **「重新挑战」** → 重开本战斗节点(未实测,消耗类出口);
  - **「撤退」** → 「货币战争-中断挑战弹窗」→「放弃并结算」(不可逆)→ 失败结算页「下一步」→ 结算翻页 → 回货币战争-大厅。

## 识别特征

- `标识-战斗暂停`(左上,(92,26-196,74)):本屏独有锚 —— **同屏的「关卡信息」不能作判据**,与 货币战争-敌人信息浮层 的标识文本撞车(2026-08-30 离线 analyze 实证:暂停面板帧被精准匹配为敌人信息浮层)。
- 底部三按钮布局:重新挑战(左)/撤退(右中)/继续战斗(右),text area 定位。

## 可交互元素

| 元素 | 位置(1080p) | 行为 |
|---|---|---|
| 按钮-继续战斗 | (1568,955-1690,1008) | 关面板恢复战斗 |
| 按钮-撤退 | (1180,955-1265,1008) | 弹中断挑战弹窗(恢复链第 1 步) |
| 按钮-重新挑战 | (228,955-352,1008) | 重开本节点(未实测) |

## automation 要读信息

- 面板本体即「战斗已暂停」信号,无额外数据读取需求(阵容/进度信息以备战屏读取为准)。

## bot 处理策略

- **启动恢复预检**(`CurrencyWarApp._recover_if_paused`):app 起跑入口命中本面板 → 委托 `ExitCurrencyWarMatch` 走 撤退 → 放弃并结算 → 下一步 → 大厅 恢复链,回大厅后正常起跑(局10/11 死因治本;此处「放弃并结算」是恢复语境的主动弃局,与中断挑战弹窗 doc 里「对局中 bot 永不点」的对局中策略分属两个语境)。
- 退局 op(`ExitCurrencyWarMatch` 分支③):战斗中退局经 右上角 X → 本面板 → 撤退 接中断弹窗分支。

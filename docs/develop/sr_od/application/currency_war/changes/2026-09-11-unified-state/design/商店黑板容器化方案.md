## 0. 术语（首次出现给定义）

- **黑板**：策略决策接口的输入帧模式（W971 §2 黑板模式；在码锚 =
  `kernel/cw_strategy_session.py` 黑板模式观察帧容器段）——画面 op 写、策略器读的
  会话槽，决策入口对 None 帧抛错（「观察层失约，禁静默按空态决策」黑板契约）。
- **商店黑板槽**：`StrategySession.shop_state_frame`（GameState 型）。生命周期 = 画面
  态（每次进商店波循环覆写）；写者白名单在码申报 = `run_buy_waves` 波顶融合段 / sim
  引擎（+ 驱动器回写，§1.1 表）。**本方案对象 = 此槽**；备战黑板槽
  `prep_obs_frame`（PrepObservation 型）不在辖域（§1.4）。
- **逐动作投影**：单动作循环内「决策→执行→投影推进」的期望态推进——动作执行落地后
  把该动作的确定性预期效果算进帧，下一动作决策读投影后帧（实现 =
  `ShopActionOp.project`，公式单一源 = `cw_state.simulate`，cw_shop_action_ops.py 在码
  docstring）。循环内零读屏（迁移批裁定决策 1/2）。
- **波顶融合段**：进商店 visit 首段的观察融合——牌面现读 + hp 覆盖 + node_type/dual/
  focus 拷入 + gold 救援 + tracked 播种，产物直写黑板槽（cw_op_buy_cards.py 黑板写路径
  注释段）。
- **容器单例**：统一 state 容器 `BoardState`（session 内单例，写渠道封闭集 =
  observe/carry/write_prior/write_logic/relay，fields.md §8.1 API 正本面）。
- **在屏**：商店 payload 域非离屏态——`bs.shop.value is not None`（payload 离屏语义 =
  「当前画面的 payload，非当前画面=None」，fields.md §2.2 显式例外）。

**波 1 过渡桥张力（本方案要消解的对象）**：波 1 把 kernel 决策簇签名切到 BoardState，
但跨桶调用点（mandate/flow/sim/ops）手里持的是黑板演化帧（GameState），于是立
`board_state_bridge`（`kernel/cw_board_state.py`）把帧值装箱成一次性 BoardState——
桥 docstring 自申报：「局部帧（商店黑板逐动作投影推进的演化帧，容器单例承载不了帧内
演化）……波 4 黑板容器化 + 波 5 真值直写落地后，跨桶调用点直读 session 容器，本函数
随之删除」。张力真身 = **黑板槽混装记录语义与策略/执行语义**（§1.1 表）：记录语义
部分本应走容器两态制（fields.md §2.5：逻辑写 = 推算的预期效果直接写字段，「在观察态
到来之前供决策使用」正是逻辑态的全部职能），却走了独立演化帧。

### 1.2 症状与根因归层

- **症状**：①同一商店窗状态三处可写（黑板槽 / 容器 payload 域 / last_state），决策读
  黑板槽、记录走容器，双轨并行（波 1 桥为此补位）；②投影公式与 op 记录写入规则两套
  载体同源不同面（`simulate` vs 容器 `write_logic`，如 BuyCard 合成升星投影直写已在
  执行落地门写容器，cw_op_buy_cards.py 投影段）；③黑板槽型 = 旧 GameState，W8 本体
  删除后被此槽绊住。
- **根因归层（流程层）**：黑板模式先于统一 state 容器存在（W971 黑板模式 vs
  统一 state），投影推进走独立槽而非容器写渠道——容器两态制就位后，独立演化帧成为
  第二状态面。修法 = 逐动作投影改经容器 `write_logic` 通道、决策读收口容器单例。
- **归层依据**：两态制裁决 = fields.md §2.5；归属判据（确定性预期 → 逻辑写）
  = fields.md §5.3 / effect-domain.md §6.3（玩家裁定 2026-09-09）。

### 1.3 约束

1. **读写端不许跨波**（调研草案 §5 风险 9）：波 4 内 sim 商店帧写点最小同步切换，
   禁读者切容器而 sim 写端留黑板槽（sim 路径决策拿到空牌面/旧类型）。
2. **策略计数写点面零迁移**（决策行 schema 终版 §5.4/§7 负面清单）：容器化不改任何
   `cw4_counters` 写点；商店域计数键（族 L）随策略器状态容器承载，与读写面切换无关。
3. **记录渠道封闭集**：容器写入只走 §0 容器单例列出的渠道；投影直写 = `write_logic`
   渠道（渠道② logic_action，sig 必填，渠道签名纪律）。
4. **观察赢**：投影直写值受后续观察覆盖辖，失配 = 投影模型 bug 走缺陷台账（错误哲学，fields.md §2.3）；商店域已有同款在产先例 = BuyCard 合成升星投影直写
   （cw_op_buy_cards.py 投影段）。
5. **先接后删**：读者全部改道前黑板槽不删；槽删除是波 4 内末步（§2.4 步 4）。

### 1.4 明确不解决

- 备战黑板槽 `prep_obs_frame`（PrepObservation 型，另一槽另型）——其处置随波 4
  strategies 全簇的 adapter 决策缝改造走（调研草案 §3 波 4 行），本方案不辖；
- `session.last_state` 三写点（波 5 喂入改造退役，调研草案 §6 残留表；黑板槽写点与
  last_state 写点在融合段同点并存，黑板槽先亡于波 4，互不阻塞）；
- `cw_state.simulate` 本体（sim 内部模型与驱动器续用至波 5/W8，§2.2 公式语义源段）；
- 旧 GameState 数据类本体（W8 切割）。

## 2. 方案

### 2.1 目标结构

1. **商店窗游戏事实唯一记录面 = session 容器既有域**：`bs.shop`（ShopPayload）/ 
   `bs.gold` / `bs.bench`（BenchView）/ `bs.level` / `bs.xp` / `bs.node`（NodeKey）/
   `bs.shop_refresh_cost` / 免费刷新余额与刷新计数域（fields.md §3.3 已建模字段族）。
   零新增容器字段（字段准入四问，fields.md §8.8）。
2. **逐动作投影 = 执行落地门的 `write_logic` 直写容器**，黑板演化帧消亡。投影写口
   （新 kernel 函数，落位 `kernel/cw_board_state.py`，与 `apply_settlement_cover` /
   `apply_board_rewrite` 同区先例）：

   ```text
   def apply_shop_action_logic(bs: BoardState, action, *,
                               executed: ShopActionExecuted,
                               produced_by: str, sig: ChannelSig) -> None:
       """商店动作投影直写（逐动作执行落地门调用；语义单一源 = fields.md §4.2
       各 op 写入行）。executed = 执行落地门回执：实购张数（BuyCard 满栏多买
       k 执行期确定）与实际击数（LevelUpShop 循环点击至 level+1）等执行期
       决定量以落地门回执为准，禁按动作对象预估；回执缺字段 = 该动作本轮
       不投影，等观察覆盖。逐域 write_logic：BuyCard = gold −单价×实购张数
       + bench 落位 + shop payload −该张；LevelUpShop = xp 按实际击数 + gold
       −击数×单击价；RefreshShop = gold −刷新费（免费帧 −0/不写，fields.md
       §3.3.4 免费帧不写语义）+ 刷后牌面等续段重观察；CloseShop =
       leave_screen(bs.shop)（结构离屏，fields.md §2.2 附加域例外）。合成升星
       面维持既有 detect_merge_upgrade 直写（两态制先例），本口不重复写。
       输入域 None 语义：gold/xp/level_up_cost/刷新费任一为 None（未读）时
       该域跳过本轮直写、值留观察覆盖（域级独立跳写，禁缺省值参与计算）；
       跳写域清单随 §4-M5 登记面申报。"""
   ```

   - **投影域集封闭**：gold / bench / shop payload / xp（LevelUp）四域；未列入域零写
     （禁扩静默，锁 §4-M5）。合成链多级连锁与外部改写（市场混乱强制刷新 / 双手狸代买 /
     采购专员改写）不投影——等观察覆盖收口（fields.md §4.1 豁免与 §5.2 在册改写源）。
   - **公式语义源**：本口逐域规则 = fields.md §4.2 op 写入行（规格正本）；`cw_state.
     simulate` 保留为 sim 内部模型与离线驱动器的既有公式载体至波 5/W8 退役。过渡期
     双形态由 §4-M1 行为等价锁钉住（同动作同输入逐域等价），防漂移。
3. **黑板槽消亡**：`StrategySession.shop_state_frame` 槽与全部写点/读点删除（波 4 内
   末步）。**帧代次标注槽保留**（`shop_frame_class` / `prep_frame_class`）：标注坐标系重锚 =「最近一次商店域容器观察写点」（入口 heavy / 续段重观察），
   写者读者不变——标注是帧语义注记（观察层产物），非游戏事实，不入容器。
4. **策略侧字段归位**：融合段的 dual/focus 拷入取消——决策读改走各自归宿
   （`dual_track_phase` → `cw_intention.committed_from(session)` 派生读；`focus_factions`
   → StrategyState 直读；调研草案 §4 字段对照表两行 / §6 残留表）。
5. **tracked 播种取消**：容器 bench 在商店 visit 期间 = prep 帧观察值 + visit 内投影
   直写，不再从 exec tracked 深拷贝播种；tracked 主账（exec_state）保留为执行侧对账
   副本，`guard_expected_vs_tracked` 对账目标改为容器读值 vs tracked（§2.5-3）。

### 2.2 接口契约

1. **决策入口容器契约**（单动作核 `decide_shop_action` 与序列驱动器同契约）：
   - 输入 = session 容器（调用方显式传 `bs = board_state_of(session)`，与波 1 kernel
     簇显式传 bs 形态一致；禁函数内二次取容器造成同帧两份快照——对齐
     `adapter.decision_state` 同帧同视图在码纪律）；
   - **在屏前置**：`bs.shop.value is not None` 才可决策；离屏帧进决策 = 观察层失约
     同型抛错（黑板契约 None 检查的容器等价物；「禁静默按空牌面决策」语义不变）；
   - 开店态 OCR 失读窗 = 容器沿用上一开店牌面（喂入口失读不写，fields.md §2.2），
     照旧决策、由执行侧核对兜底（W5 视图收编已申报的行为面，cw_bs_view payload 段）；
   - ShopCard 双类型归一 = 容器侧 `ShopCard`（x/merge_preview 不入存储；点击坐标
     screen_info「商店牌-N」现取既有口径；cost_source 三值透传不折叠——fields.md
     §3.3.1 / `cw_board_state.ShopCard` docstring）。
2. **hp 跨件接口**：商店链如需 hp 消费（现役商店决策热点无 hp 读，调研草案 §4 决策
   热点列），一律经波 2 交付的 kernel 政策读口 `decision_hp`（设计件
   `hp施门下沉kernel政策层设计.md` §2.3；波 4 依赖波 2）。
3. **驱动器同路**：`decide_shop_screen` 驱动器循环（flow/bridge/cw_replay 同核）投影
   推进改调 `apply_shop_action_logic`、决策读容器——生产单动作循环与离线驱动器同路
   （W971 sim 适配批「生产/离线同路」原则续守；`engine_p1` 决策段在码注释）。
4. **sim 段最小同步**（读写端不许跨波，§1.3-1）：sim 决策段删黑板槽写点（engine_p1
   决策段 / cw_replay 驱动器段），决策读容器——sim 真值入容器已有既定通道（每段
   `synthesize_from_game_state` 喂入，engine_p1 决策段在码调用），容器即 sim 段入口
   帧的等价载体；sim 内部真值模型 st 保留至波 5 反转（调研草案 §3 波 5 行）。
5. **sig 纪律**：投影直写 `ChannelSig(family='logic_action', actor=<执行 op 登记名>,
   group_id='act:<op类名>@<seq>')`——actor 复用在册登记名（`CwOpBuyCards` 等已登记；
   新登记名按 `REGISTERED_ACTORS` 在册纪律扩表），group_id 对齐既有
   `act:CwOpBuyCards@seq` 先例（合成升星直写在码 sig）。

### 2.3 数据流（目标态）

| 时点 | 动作 | 容器写 | 容器读 |
|---|---|---|---|
| visit 入口 | 观察漏斗 heavy 读屏 | `observe`（shop payload/gold/node/level/xp；bench 保持 prep 帧值） | — |
| 逐动作·决策 | 单动作核读容器 | — | shop payload/gold/bench/level/xp/node |
| 逐动作·执行落地 | 机械执行成功回执 | `apply_shop_action_logic`（投影四域）+ 既有计数/效果账本挂点（不动） | — |
| 布局代次命中 | 重播种 | `write_logic(bs.bench, tracked 重建 BenchView)`（reseed 写点，投影域集例外申报进 §4-M5 登记面） | 计划截断重入决策 |
| 续段刷新重观察 | 刷新后重读牌面 | `observe`（新 payload） | — |
| CloseShop | 终结离屏 | `leave_screen(bs.shop)` | — |
| sim 决策段 | 段首真值喂入 + 段内投影 | `synthesize_from_game_state`（既有）+ `apply_shop_action_logic` | 容器 |

对齐申报：入口观察/续段重观察/合成升星直写/效果计数挂点全部为既有在产写点，本方案
只新增投影直写与 reseed 两个 `write_logic` 写点，其余零新增。reseed 写点是
fields.md §3.2.5 备战席逻辑写端清单外的新增写端——正本清单增行义务挂 landing.md
正本更新清单随批消费（投影直写本口承载 fields.md §4.2 既有 op 写入行语义，非新写端）。

### 2.4 迁移路径（波 4 内四步，先接后删）

### 2.5 边界

1. **外部改写观察收口**：市场混乱 / 双手狸代买 / 采购专员族改写等非 bot 动作的牌面
   变更，投影不建模，等下一观察覆盖（fields.md §5.2 在册改写源；读牌/买牌核对预知
   义务各行在码不变）。
2. **对账守卫输入切换**：`guard_expected_vs_tracked`（期望态 vs tracked 双账守卫）与
   播种期对账的对账目标改容器读值；分叉归因两属（播种/入口账 vs project/mutate 模型）
   语义不变（守卫在码 stage 分支注释）。布局代次检差（`reseed_bench_if_layout_stale`）
   流程不变，重播种写目标改容器（§2.3 表）。
3. **决策行披露面零迁移**：`cw4_counters` 写点、局终聚合读容器浅拷贝，均不经黑板槽
   （决策行 schema 终版 §5.4 写点面零迁移）；`cw4_visit_bought_names` 等策略器状态
   字段照旧。
4. **过渡桥纪律**：波 4 后生产链直读容器，不再新增 `board_state_bridge` 调用点；桥
   存量调用点（sim 内部模型侧）随波 5 删除（桥 docstring 退役条款），波 4 不删桥。
5. **牌位坐标不入存储**：执行侧 buy 点击坐标恒 screen_info 现取（fields.md §3.3.1），
   容器化不改变（黑板帧链自持 x 的旧形态随槽消亡，`cw_board_state` 牌转换函数注释段
   在码申报）。

## 3. 关键取舍

- **投影进容器（选）vs 黑板槽换载体（弃）**：换载体（槽保留、类型换 BoardState 快照
  或派生读口）改动最小，但保留第二可变状态面——桥张力不消解、W8 本体删除被槽绊住、
  「三处可写」双轨照旧，是症状搬迁非治本。投影进容器把期望态归位两态制的逻辑写通道
  （fields.md §2.5 语义本就为此设计），黑板模式保留其有价值的一半（写读契约、None
  失约、代次标注），丢掉其载体（独立帧槽）。
- **投影直写域封闭（选）vs 全帧模拟直写（弃）**：按 simulate 全域逐字段 diff 回写
  容器会引入「容器→scratch 帧→simulate→diff→write_logic」往返与第二公式宿主；四域
  封闭直写与 fields.md §4.2 逐 op 行一一对应，可锁可审。代价 = 过渡期 `simulate` 与
  直写双形态并存（§4-M1 锁钉等价，波 5 随 sim 反转收敛单形态）。
- **黑板槽消亡排在波 4 而非波 5（选）**：波 4 是读者唯一聚齐波（strategies 全簇+
  装配+sim 商店段同波）；拖到波 5 = 波 4 交付的容器读全部再改一遍（读黑板槽 → 读
  容器），且波 5 的 sim 反转依赖决策读容器为前提。
- **标注槽保留 session 宿主（选）vs 入容器（弃）**：帧代次是观察层产物的语义注记
  非局内事实；入容器违反「记录面只存游戏事实」分界，字段准入四问
  ①④不过。

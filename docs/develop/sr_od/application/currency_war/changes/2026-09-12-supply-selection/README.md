# 2026-09-12-supply-selection（补给选卡升级）

> 状态：**草案（口径收集态）**——用户裁定已收齐、设计未深化。深化前置依赖：候选阵容角色价值机器（env 送卡型详设 `2026-09-12-invest-env/details/env-value-models.md` §2.1 结构对齐档，env 侧由其跟进方落地）。
>
> ## 用户裁定汇编（均为 2026-09-12）
> 1. **带钻仍优先选**：钻单件价值高（财富宝钻 = 团队规模上限+1；红/蓝钻 = 阵营/流派星徽合成材料，游戏定义见 `cw_equipment_data.py`）；
> 2. **不为钻刷掉角色或装备**：钻虽强但补给刷新出现率低（plaza_meta：蓝钻×31/红钻×17），无条件刷新找钻废除——原代码注释「拿到基本赢，碾压一切」经用户定谳有误已删（`cw_events.py`/`cw_screen_supply_node.py` 注释批，2026-09-12）；
> 3. **选卡重点 = 目标阵容的角色 > 装备质量**（补给选项 = 角色+携带装备 bundle）；
> 4. **先刷后选**：有高优先级选项也不立刻锁——先用免费刷新（每节点 1 次）看新 offer 再终局选择；
> 5. **未锁终局阵容期的装备选择 = 统计上「输出最需要」的通用先验**，不绑特定阵容；
> 6. **装备选择逻辑做成通用机器**：多消费位（补给装备列/武装箱 `decide_box_card`/装备穿戴分配等），一次建模；
> 7. **角色层相位感知**：除了终局候选，P1 意向未定型期还要考虑过渡阵容的成员（身份单一源 = `cw_card_identity.line_identity_tier` 三分档），锁线后收敛到终局方向；
> 8. **裁定 5 严格辖域覆盖装备穿戴面**（OQ-2 裁决）：未锁态装备选择不绑囤牌方向，equip_pick 的 stash_comp +100 移除（锁 S13）。
>
> ## 机制事实（文档直调）
> - 补给刷新 = **整排重掷**（`data/advantage_layouts.md:18`「重置所有可选角色和装备」），每节点 1 次，刷新后 2s 画面稳定（`screen_flow_timing.md` #19）；现行 op 单按钮模型与机制一致；
> - 策略卡「钻石闪耀」可抬升补给出钻率（影响钻期望价值标定）；
> - 现行观察层已全通：`read_supply_options` 每列角色+装备 OCR、钻双通道（SIFT+文本）、动态列数 3-5。

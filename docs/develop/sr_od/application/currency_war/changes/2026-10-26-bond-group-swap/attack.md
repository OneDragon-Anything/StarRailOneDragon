## 2. 阻断项详证

### A1 验收锚在自家门 2 下不可满足

**锚的原文**：design §2.7「同 seed 复测（seed=20261216）对照 2-1 至 2-4 换人动作面——缺席翻转为发生，Saber 换远坂凛 1 换 1 应发生且圣杯 2 不掉档、能量 2→3」；landing 3.4 同锚。

**复盘局实测板面**（`.debug/currency_war/deep_review/g_20261026_203023.md:2895-2906`，即锚所指 2-1 帧）：

- 板 5/5 满（等级 5 cap）：吉尔伽美什、青雀、远坂凛、停云、爻光；羁绊 = 命运圣杯×2、能量×2、战技点×2、仙舟×3、欢愉×1
- bench 含 **第二张远坂凛 1★**（槽 3），且该副本贯穿 2-1 至 2-4 全窗口持续在席（同报告 2906 / 3093 / 3112 / 3349-3410 各帧）

**逐 victim 过门 2（design §2.2「判据本体不动、不豁免」= `swap_sell_exclusion_reason` 现行全链）**：

| victim | 身份 | 拒因（代码体直调） |
|---|---|---|
| 吉尔伽美什 | 双王圣杯 core | target 核心，保护集禁卖 |
| 远坂凛 | 圣杯标签 target 件 | 换入分支可让位，但 **merge_material_guard**：`same_star_count('远坂凛',1)=2`（板上 1 + bench 副本 1，cw_merge_simulate.py:438-447 全场域同名同星计数；cw_deploy_logic.py:1062-1065 计数=2 即拒） |
| 停云 / 爻光 / 青雀 | 均带仙舟标签（cw_chars.py:112/121/133） | **engines_guard**：守恒门体系集 = 仙舟3/列车2/DOT2/希儿系/护盾（cw_deploy_logic.py:498-507），板仙舟×3 已达档，任一离场使 achieved 档 1→0（cw_deploy_logic.py:1038-1044） |

即：**C1 帧 victim 池 = 空集**。新门 1 只换掉触发/让位的「✗→✓ 折法」（arm 侧），门 2 三道独立封条（engines_guard 守恒门不含圣杯/能量、且只评 victim 离场不计换入；merge 素材守卫的全场域同名计数；target 保护）原样保留 → 2-1 至 2-4 换人动作面在种子确定性复跑下仍恒空。「Saber 换远坂凛」「缺席→发生」两条锚都命中不了；landing 3.4 的「或偏离有归因结论」出口救不了 prereg 质量问题——锚是设计阶段写死的，写了一个按自家规则可证明不可达的预言。

**修正方向**：设计必须正面回答「C1 帧（及 2-1..2-4 各帧）哪个 victim 过门 2」。二选一：① 承认守恒门是同层共根，为转型域门 1 放行面显式改守恒门适用范围（例：门 1① 激活终局档位的换出允许让渡过渡档，以「终局档位不降 + P79-4 让渡序」为界），并重推行为变化申报面；② 保留守恒门不动，则锚必须改到守卫可达的帧/动作面，并如实收窄「缺席→发生」的预言域。无论哪个，都须按 A3 补验收线保全推演。

### A2 landing 3.1 引用不存在的情形枚举

landing.md:20：「枚举 A/B/C/D 情形放行、E/F 情形拒绝，**情形定义见 design §2.2/§2.8**」。实测 design §2.2 只有「用户三触发条件的映射」一段（无字母编号），§2.8 仅出现一次「枚举 B 情形：阿格莱雅类外部能量件进板激活能量 5」。A/C/D/E/F 在全部设计文本中零定义。阶段小节是账本唯一源（iteration-design §3.1），完成判据依赖不存在的定义 = 判据不可验收 = 划分不当。**修正方向**：design 补一节显式 A–F 情形表（放行四情形 + 拒绝两情形，各配板面/bench 最小构造），或 landing 判据改引已真实存在的定义面。

### A3 prereg 完整性硬门无实体清单

strategy-work §6：「凡修复批，其 prereg……必须**逐条列出受本批影响的已登记验收线**（出口金/[13]/通关门/存活等）并证明修复保住各线；保不住 = 设计缺陷非胜利，回设计层。**新批 prereg 缺该清单 = 对抗审查直接打回，不进实现**。」本批改换人触发/让位判据 + 退役 P61 + 改写 14 号篇推迟上界行——受影响已登记线至少波及：14 号篇出战就绪质量门（`launch_quality_defer_frames` 推迟上界由「换人臂翻真」承载，14_p1_consume_arms.md:602）、P88/P89（消费 P61 的换人本体命题）、收敛论证链（cw_launch_admission.py:215）。design/landing 只有 landing 首节一句硬门指针，无任何逐条清单与保全证明。A1 的不可满足锚正是缺这张清单的直接后果——列了就会撞见。**修正方向**：landing 补「受影响验收线清单」节（逐线：出处、本批如何影响、保全论证或显式改线裁定），先于任何实现批。

## 3. 应修项详证

### B4 组配对/选择算法未定义（design §2.3:36-37）

「换入组 = 备战席支撑件集合；|换入| = |换出|；门 1 以组整体换入后的板态判定」——bench 支撑件数量常超空出的板位（如 bench 3 个支撑件、只卖 1 件），选哪几个进组、谁与哪个 victim 配对、组不成时降级为子组还是放弃、多组可行时取哪组，全部未定。现行 `select_swap_plan` 是单 victim 循环（cw_deploy_logic.py:1716-1755，`plan.sell_names = [name]` 单元素），组语义需要全新的搜索结构，其确定性（同帧同输入同输出，发出⇔执行同值契约）与复杂度上界均未声明。`bond_gate_victim_yields(ctx, name)` 的组态判定同样需要先知道组。实现者必须自行设计 = 违反 iteration-design §5.2「实现者无需再设计」。另 §2.3「卖后上序底线照旧（post_sell_req_missing）」未回答组语义下的判据形态（要求上序含全部换入对象还是任一；现行成对复检 `_seat_completes_form` 是单对折法，cw_deploy_logic.py:1742-1749）。

### B5 P79-3 放行门未入设计（design §2.4 接线清单缺项）

生产发出链 = `select_swap_plan` → **`_redeploy_emission_allowed` 三轴**（mandate.py:838-862）→ 逐 victim 发 SellDeployed。三轴：① bench∩membership（压席**线内**成员）非空；② 存在 `_deploy_advances_form`（Δfp>0）的替补线内成员；③ 代价轴。两处与门 1 直接冲突：

- 轴①：全部线内成员上板后，bench 只剩外部凑档件（如阿格莱雅）时轴①恒假 → 门 1 武装也只落 `redeploy_cost_gate_defer`，design §2.8 枚举 B 情形（外部能量件进板激活能量 5）在此帧结构性发不出；
- 轴②：Δfp>0 恰是 §2.8 明确放弃的折法，门 1②（支撑件数增而档位/fp 不动）的放行面会被轴②系统性 defer——判据语义换新、放行门仍旧折法，两层不一致。

design §2.4 接线清单（触发谓词/让位检验/演进分支/上阵窗口）没有这一夹层门。**修正方向**：显式裁定 P79-3 三轴去留（保留/轴②换门 1 判定/对外部支撑件修轴①），并把其正本 10_prep_decisions.md §1 纳入正本更新清单。

### B6 「同帧逐对连发」是新机制，非现状对账（design §2.3:36）

现行 as-built：m1p 先卖（`emit_swap_redeploy` 逐 victim 产 SellDeployed，mandate.py:1502-1518），**上序由后续帧 M1/M1′ 对 fresh 容器重评自然续发**（mandate.py:1421-1423 明文）。design 写「同帧原子序逐对（SellDeployed → DeployMove）连发」如同描述现状，实为发出形态重构，至少含：① 卖后落位坐标预计算（行/槽选择 = 策略层 deploy_plan 语义，设计未指派）；② 与帧稳定截断契约的对账（词表 as-built 权威 = flow/action_exec.md §1，entry.py:146-147「动作发出器增补条目须回契约改版」——**flow/action_exec.md 不在正本更新清单**）；③ `cw4_m1p_plan_pending` 载体与「后续帧 M1 重评」结构的存废。landing 3.2 把「同帧逐对原子序」列为接线核对项，把机制新建低估成对账。**修正方向**：design §2.3 补执行形态迁移小节（旧形态→新形态、落位决策归属、契约对账义务），landing 3.1/3.2 的范围与文件面相应扩，正本更新清单补 flow/action_exec.md。

### B7 §2.6 收敛注记论证无效（design §2.6:55）

「门 1 三分支各带独立有界结构量——支撑数 ≤ 板位、档位组合有限、同名星级组合有限 ⇒ 触发次数有限、无死循环」——**有界 + 逐次严格增不推出有限次触发**，中间缺「触发量在两次触发之间不减」的单调不变式。反例构造（用设计自己的规则）：门 1② 支撑件数可在两次触发之间下降——外部支撑件（非名单）不在保护集（protect_names = core∪shared∪替班），且卖它可不掉终局档（如板能量 4 时卖 1 个能量件：4→3 仍保 3 档，「换出不得使终局档位下降」满足）→ 支撑数 −1 → 同一触发面复燃 → 换入/换出振荡。P61 退役后（B_t 严格增 + 值域有界 ⇒ 有限触发，proofs/p61-bt-swap-arm-dominance.md:26,32,76），通道的无死循环保证实际悬空。伴生问题：§2.3:38 把「换出不得使终局档位下降」写成 victim 选择约束 +「冗余防线」，而「冗余」的论据（终局件受保护集禁卖）恰好不覆盖外部档位承载件——防线不冗余也不闭合。**修正方向**：要么把「终局档位不降 ∧ 支撑件数不降」（或字典序 (终局档位向量, 支撑数) 不减）立为门 2 硬不变式并重写注记使其成为真论证，要么按 strategy-work §1 立待证钩子（占位不授权），不得以无效计数论证顶替已证命题的收敛角色。

### B8 P1 配方对锁（双轨）域归宿未定（design §2.4:42、§1:14）

`_completion_swap_ins` 现行适用范围 = `ctx.locked`（终局阵容锁定 **∨ P1 配方对锁**，cw_deploy_logic.py:828-868；24_deploy_segment.md:11「两套并行意向期间板面义务本体 = 过渡配方」），它就是 2026-09-18 为「配方对锁局板满帧全 plan_empty」补的通道（required_swap_arm_pending docstring 出处行，cw_deploy_logic.py:768-770）。design §2.4「完成品分支整体替换」+ §2.2「档位判定的羁绊范围 = 终局阵容 form_tiers 键集」组合后：配方对锁帧（终局未锁、target = 配方伪 comp）门 1 对什么键集判定没有答案——只认终局键集则配方完成件通道回归死锁（退化 2026-09-18 修复）；认当前 target 视图则与「终局阵容」措辞冲突。§1「明确不解决」也未列双轨域。**修正方向**：显式裁定（例：bond gate 仅辖终局锁定帧、配方对锁帧保留旧折法；或键集定义改为「当前方向 target 视图」），并把该裁定写进 §2.2 适用范围。

### B9 支撑件口径自相矛盾（design §2.1:20）

「羁绊标签命中 form_tiers 键集即计 1」与「终局名单成员天然全计」对双王圣杯直接冲突：瓦尔特（列车同行/星间旅人 + 减益，cw_chars.py:181）与符玄（仙舟 + 治疗/量子同频，cw_chars.py:164）是 core_chars 成员（cw_comps.py:1022）但**零命中** {命运圣杯, 能量}。按标签口径，这两位核心换入既不激活档位也不增支撑数，门 1③（同名升星）之外永远进不了板——本迭代立案的「线核心滞留备战席」病在自家新判据下对这部分核心复发。**修正方向**：二选一并写明——支撑件计数 = 标签命中 ∪ 名单成员（改口径表述），或承认无标签核心成员的进板路径缺位并补分支（如名单成员换入恒计入收益门）。

## 5. 核三·治本核验结论

1. **§1 归层结论只对了一半**：换入判据「单件一步成型不可达」（语义层）成立且经代码体复核（`_completion_swap_ins` 折法 + 双王圣杯双档结构，复盘 2920 主证），但它不是通道封死的唯一根——同一帧上 engines_guard（过渡档守恒门）、merge 素材守卫（同名对保护）、P79-3 放行门三道独立封条同样在封。§1 把 victim 让位检验的「同折法」列入了根因，却没有把门 2 资格族与发出放行层列入，边界声明（「明确不解决」清单）也没把它们划出去——不是「不解决」，是「没看见」。
2. **§2 修的是根的一部分**：换入资格语义单位错置确实被门 1 修正，但在锚点帧（2-1..2-4）修正不可观测（A1）——按本仓判据「验收 = 行为锚点」，行为不变即治本宣告不成立。
3. **同族问题跨件半问**：本迭代是「2026-09-18 板满换入分支」同族病的第二件补丁（design §1 自认「同病上一代形态的补丁」）。两件的公共更高层根 = **转型域换人通道的资格/让位/放行三层判据各自独立演化、无统一收益-安全语义框架**（触发折法、守恒门、素材守卫、P79-3 三轴、窗口辖域五处各自为政）。本设计仍只动其中一层（触发+让位折法），若不再往上收一层架构级设计件，第三件症状补丁可预期。

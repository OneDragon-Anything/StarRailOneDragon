# 卖出场景块无前提对抗报告（第十轮：九轮处置复核 + 推判谓词/重放载体/launch_gate 专项 + 全量一致性）

## 结论（阻断）

**阻断**：3 阻断 + 3 中 + 3 低。三个阻断项全部落在**九轮处置的核心交付物**上——推判机制（S8-2 白卖带的唯一封堵）的两个定稿拼不起来、一个新键定义不完整：

- **S10-1**——九轮 S9-1（推判谓词重写）与 S9-2（重放载体定稿）分别处置后**判定域矛盾**：谓词「V 为线外件 ∧ 虚拟完成板面线外件数 = 0」只覆盖 load_bearing_full 翻转路径；载体「完整重放 readiness_launch_decision（双翻转路径〔load_bearing_full ∨ ¬deploy_plan_available :259-261〕全涵盖）」含 plan 维度路径——该路径的翻转形态（级联提位耗尽 bench → has_deployable False → armed True）**板面可仍非零线外**（九轮 S9-2① 自己证明实体可达）→ 按谓词读「线外件数 = 0」恒假 → 推判不触发 → plan 路径白卖带开放；按重放读则「V 为线外件」项把承重件 victim 的翻转排除。两个定稿谁主谁辅无定义，实现者无法落一致版本。
- **S10-2**——重放输入构造缺口：`readiness_launch_decision` 签名吃 **GameState 对象**（非板面参数，cw_launch_admission.py:209-212），内部读 deployed rows + **bench**（plan_available 直接输入，:190-192）+ **board.value 羁绊计数板**（form_progress 输入，cw_comps.py:1775-1776）+ deployed.value（required 检查）+ max_units；设计只写「板面构造按语境」一个域。**bench 不虚拟 → plan_available 恒 True（真实 bench 有件可上）→ plan 翻转路径在重放中恒不可达，「双翻转路径全涵盖」名存实亡**（与 S10-1 同根但独立成立）；席位语境「定型板面」二义（步 3 含 X 定型 = 与回店帧实际板面〔无 X〕系统性差 X + 涟漪；无 X 搜索 = 商店端未跑、需新搜索 → 「成本 = 纯函数计数不含搜索」申报失实）。
- **S10-3**——launch_gate 键生命周期三缺口（S9-4 处置声称定稿）：解拦轴「受限会话解除/节点边界」对推判写入端**语义空洞**（写入帧本身非受限——armed=False 质量推迟帧，受限帧被 S7-4 前置挡在评估外，「解除」无比较基准、可实现的谓词形态未定义）；拦截条件（armed 预测 ∧ 花后 < g* 双维）与解拦轴（armed 维 + 节点边界）**不对称**——金位涨过闸线（花后 ≥ g*、闸会放行）不解拦 → X 明明可买不重开 → 货架窗口错失；载体/闭集注释/解拦分支/遥测/§3 验收全无登记。

另有 S9-8 处置**虚报**实锤（S10-7：处置记录声称落文总纲推判段的「半途板面偏差申报」在 design.md 全文零命中）。裁定本身不翻案（升级凑金删除 / 统一获取让位 / 意图槽策略层实现边界 / 凑息豁免 / 等钱帧凑息照常 / 拦因分键 / 净腾辖域按语境分的方向 / 虚拟推演的方向 / 非受限前置 / bridge 让位谓词，均不再攻）；攻击面全部落在九轮处置的落文真伪、推判建模写法与文档同步。

## 发现清单

### S10-1｜九轮 S9-1 谓词与 S9-2 载体拼合后判定域矛盾：「翻转判据」只覆盖 load_bearing 路径、「完整重放」涵盖双路径——plan 翻转帧按谓词读不触发推判（白卖带经 plan 路径开放），按重放读则「V 为线外件」项排除承重件 victim 的翻转；谁主谁辅无定义
- 攻击点：design.md:65 推判段落文把两个定稿并排：「**翻转判据按代码语义：V 为线外件 ∧ 售 V + 级联提位后的虚拟完成板面线外件数 = 0（→ load_bearing_full True；……）**」与「**推演载体 = 完整重放 `readiness_launch_decision` 纯函数**（对虚拟完成板面求 armed——**双翻转路径〔load_bearing_full ∨ ¬deploy_plan_available :259-261〕全涵盖**，禁手搓单判据）」。代码事实（cw_launch_admission.py:259-261）：armed = form_ok ∧（load_bearing_full ∨ ¬deploy_plan_available）——**两条翻转路径**。plan 路径的翻转形态（九轮 S9-2① 已论证实体可达）：级联提位耗尽 bench → `deploy_plan_available_fn(bench_entries_of(gs), …)`（:190-192）翻 False → armed=True，**板面可仍非零线外**（定型板含 L3 普通线外件时 line_weight < occupied 但 plan 不可得 → fail-open）。两定稿对同一帧给出相反判定：谓词以「线外件数 = 0」为翻转必要条件 → plan 翻转帧（线外件数 ≠ 0）恒不满足 → 推判不触发 → 该帧让位照写槽照执行 → 回店 armed=True 受限撞闸 → **V 白卖、X 丢货架（八轮 S8-2 的阻断行为经 plan 路径原样开放）**；重放以 armed 输出为准 → plan 翻转该拦，但谓词的「V 为线外件」项（承重件 victim 被 plan 路径翻转时——victim 是统一序末位，可为线内未达标成员，被迫让位无豁免）与重放结论冲突（重放说拦、谓词第一项说不拦）。谁主谁辅、组合逻辑（谓词是触发条件还是解释性注释）正文零定义——实现者无论怎么落都可能重建八轮阻断行为，或做出与另一句冲突的实现。九轮 S9-1 与 S9-2 分别处置、拼合后从未对齐（同 S2-2「处置引用不存在的代码结构」/S3-1①「载体未定」的拼合失调惯犯形态）。附带：谓词「V 为线外件」的独立判定读端（line_weight 计数口径 = comp.core∪shared 核准集 ∨ 羁绊视图交集，:171-183；comp 注入源 = state_of(gs).target_comp，bridge.py:111-113）正文未写——若实现者在重放之外手搓第二份线外判定即判据双源（违单一源纪律的形态）。
- 证据：design.md:65（谓词句 + 载体句并排）；cw_launch_admission.py:259-261（双支）、:190-192（plan_available 读 bench）、:171-183（线外计数口径）；attack-sell-round9.md:59-66（S9-2 原文含 plan 路径论证）/:128-129（两条处置记录）
- 严重度：高｜阻断级：**是**（推判是 S8-2 白卖带唯一封堵机制，判定域分叉 = 实现者无法落一致版本；修复需设计内裁定谓词与载体的组合逻辑，非落地批可自行裁定）
- 处置建议：二选一落设计——①谓词降级为「load_bearing 路径的解释性说明」，主判定 = 重放 armed 输出（重放 True 即拦，删「V 为线外件」前置项或改写为「重放内含 line_weight 计数，无需独立线外判定」）；②保留谓词为触发条件则补 plan 路径的对应谓词项（板面可仍非零线外 → 谓词无法覆盖 → 实质等于回到①）。同时明写「线外」判定读端 = 重放内部 line_weight 计数（禁手搓第二份）。

### S10-2｜重放输入构造缺口：readiness_launch_decision 吃 GameState 对象非板面参数，内部消费 deployed/bench/board.value 羁绊计数板/form_progress 部署视图多域——设计只写「板面构造」一域；bench 不虚拟则 plan 翻转路径恒不可达（「双路径全涵盖」名存实亡）；席位语境「定型板面」二义（含 X 步 3 定型 = 与回店帧实际板面差 X；无 X 搜索 = 成本申报失实）

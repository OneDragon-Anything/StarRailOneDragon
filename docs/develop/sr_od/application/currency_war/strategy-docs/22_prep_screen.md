## 1. 决策工序:十段全扫(第 0-9 步)

决策入口 = `strategies/impl/mandate_v1/bridge.py::decide_prep_screen` → `entry.py::emit`。每帧回到备战画面从第 0 步向下扫描,**执行第一个满足条件的步骤并返回其动作,下一帧重新扫描**;全部步骤不中 ⇒ 第 9 步出战。单动作循环不变(逐帧恰取一个动作);回跳语义(腾位后回头点晶矿、买完牌回头部署)在全扫下自然表达,无需状态机记步。策略层无试错计数:全部判据为每帧全量重评的纯判断——该不该做由价值/身份判断直接给出,不做「试 N 次后放弃」形态;动作未生效归执行层落地验证,候选空等异常帧正常返回主循环。(第 1 步商店随机态重开为 2026-10-17 迭代新增,其后步骤序号顺延 +1。)

每帧入口先执行**读数协议入口序**(金位账面同步 + 合成结果帧失效检测,协议单一源 = [23_shop_screen.md](23_shop_screen.md) §2 读数协议节),再进入十段扫描。

**第 0 步:溢出告警自救。**
- 触发 = `gs.overflow_warning` 为真。机制事实:告警在场 = 备战席 9 格全满且溢出位有一张卡(角色或占席道具),溢出卡阻断进入战斗;解除方式唯一 = 腾出一个备战席空槽,溢出卡自动归位。
- 自救动作序按损失递增排列(免费腾位在前、有损卖出最后),每帧重评取首个可行:
  1. **上阵安置**(免费腾位):场上人口上限有空位 ∧ 备战席有可上阵单位 → 拖上阵(腾出备战席槽 → 溢出卡归位;同时是有效部署)。告警帧豁免上阵窗口辖域——上阵纯为腾槽保命,告警解除后窗口辖域恢复正常。
  2. **点开消耗品**(免费腾位):无上阵安置可行 ∧ 备战席有已知占席物品(书册卡/补给箱/星徽秘典)→ 点开腾槽(占席道具不可卖但可点开)。
  3. **卖出**(有损腾位):候选评估非空 → 按卖出候选评估器的**自救扩展资格面**(候选池仅备战席——溢出解除需腾备战槽,卖场上件无此效果;资格面 = 真全量持有:P78 资格仲裁族〔同 visit 线内禁卖、核心/转线件、种子〕全通道豁免,线内件按价值序整体置末层后仍可卖——告警解除的零停机出口优先于硬资格)卖出首位候选。
  4. 全部不可行 → 防御性分支:零动作返回主循环(识别异常真实形态的兜底;全量可卖下候选空在结构上不可达)。
- 告警在场时,其余步骤全部不执行(告警不消出战无效);例外仅上列自救动作本身。
- 空板守卫 as-built 语义:卖出守卫(`sell_gate.py::empty_board_sell_blocked`)为后态判定,deployed = 0 帧全部卖出场景哑火——deployed = 0 帧的自救主路径 = 上阵安置(非卖出,不受守卫辖)。

**第 1 步:商店随机态重开(2026-10-17 迭代 design §2.4)。** 触发 = 随机态信号 `shop_randomized_pending` 在册(写端唯一 = 商业间谍升级回调):清「本节点已处理」标记 → 发开店动作 → 清信号。进店后入口观察读真牌面,会话循环正常评估(含商业间谍偷入备战席的 3 张新件)。位次依据:随机态 = 商店有未处理的全新牌面,用户裁定「很高的优先级」——置于溢出自救之后(安全动作最高)、资源动作之前。

**第 2 步:点开消耗品。** 触发 = 备战席槽位有 kind 为 bookcard/supply_box/tome 的物品(书册卡/补给箱/星徽秘典);点开顺序 = 书册卡 → 补给箱 → 星徽秘典。点开产生的弹窗由外循环画面分发接住,处理后回备战重新全扫(弹窗不是工序步骤)。

**第 3 步:晶矿。** 触发 = `ore_click_targets_of(gs)` 非空。
- 席位未满:点全部晶矿(判据 = 全点;执行面按批式点击上界分批推进,`prep_actions._collect_ore`)。
- 席位满:**按候选身份直接判断值不值得腾位,无试错计数**——候选经垫件谓词过滤后取价值最小者卖 1 腾位,下轮全扫回来点晶矿;过滤集空 → 本节点放弃晶矿(确定的高价值持有不换随机产出)。垫件谓词 = 1★ ∧ 非线内 ∧ 非合成素材 ∧ 非通用插件注册表成员 ∧ 非核心/转线件/种子 ∧ 非候选 top3 成员(`criteria/sell_candidates.py::is_ore_pad_unit`;P96 释放集复用登记待办不激活,标定前晶矿垫件不含释放集)。判断天然自收敛:候选按价值升序让位,散件卖完后自动停在「无垫件可卖」。
- 依据:确定损失换随机收益只在损失 ≈ 0 时成立(卖出纪律 = 不可逆动作按持有价值守门,弃购/囤积的真实代价 = 再遇窗口)。

**第 4 步:升级检查。** 判据与发射形态单一源 = [11_shop_decisions.md](11_shop_decisions.md) §2(最优概率带单判据三分派 + 单帧原子整批发射,判据同帧重评,无跨画面授权键)。本步只定义调用时机:每轮全扫评估一次;**判据不过 = 本步零动作,扫描继续到下一步**(血预算线/资金线门类拒发同落零动作语义);花后破线帧走凑金(每帧一卖重扫续卖,守线缺口闭合下帧发射;候选穷尽零动作等节点收入,拒因键 `levelup_fund_line_defer`)。

**第 5 步:商店会话。** 入口先调**解拦复核**(未消费机会清单的解拦判定:金位变化/席位空出任一使拦因解除 → 清「本节点已处理」标记);然后判标记 ≠ 当前节点号。满足 → 输出 `CwActionOpenShopParam` 开店;不满足 → 跳过本步。本步是备战侧**决策性**开店意图的唯一来源(金位读数开商店为辅助形态——读金非处理决策,语义单一源 = [23_shop_screen.md](23_shop_screen.md))。部署产生的腾位效果由本步入口的清单复核自然消费,无独立重开钩子。

**第 6 步:部署调整。** 部署面判据整体保留:目标线成员上阵/换位(发射门纪律 = [10_prep_decisions.md](10_prep_decisions.md) §1)、开局配方(过渡体系开局)、空槽凑人数补位(任意合法单位上阵优于空槽,P24 残余补部署);调用时机在商店会话之后(先逛店再统一部署)。要点:
- **上阵窗口辖域**:终局成员在其上线窗口前不上阵——窗口 = 阵容知识声明的上线条件(核心等级/羁绊齐/变阵点等);数据载体 = `kernel/cw_comps.py::COMP_LIBRARY` 的 `entry_signals` 字段(信号类 + 阈值),缺行 → 窗口恒假(纯终局件一律只囤不上,保守侧)。纯终局件谓词 = 终局库成员 ∧ 非现行过渡配方成员(未锁定期按全库知识判定,锁定后按锁定线名单);过渡∩终局重叠件按过渡成员正常上阵;**锁定帧两腿豁免覆盖全件**(判定单一源 = `entry.py::_deploy_window_blocked` 两腿:现行过渡/方向配方成员腿①与锁定线外囤件腿②任一必中)→ 窗口谓词在锁定帧结构性恒 False,凡锁定帧替补均可上,与 entry_signals 登记与否无关;未锁帧窗口照登记语义。全局累积型角色例外(越早越好,例外判定 = entry_signals 的累积型信号类);羁绊组齐信号 = 上线条件之一。判据与建表口径 = [10_prep_decisions.md](10_prep_decisions.md) §5。
- 部署候选排除「场上已有同名同星」角色(游戏约束该状态不可达)。
- 方向读口:现行方向 = 锁定线优先,未锁 = 过渡配方开局面(`session_scope.direction_comp_of`);无方向(K 空窗)时部署围栏目标经 K 空窗回退供给(`kernel/cw_intention.k_empty_window_fallback`,回退单一源,禁复制兜底逻辑)。

**第 7 步:装备与工具。** 装备穿戴 = 现行完整实现保留(合成规划/分配/转移,语义 = [18_equip_wear_semantics.md](18_equip_wear_semantics.md));工具使用判据 = `kernel/cw_equip_env.evaluate_tool_actions`;调用位置固定为部署之后。

**第 8 步:节末凑息检查。** 所有花费决策完成后的**最终利息档检查**——「卖活期牌回金」两种目的两个位置:为买而卖(会话内筹资,排在买牌账内)与为息而卖(本步)。本步必须在出战前最后执行:息按节末金位结算,提前卖会被后续购买把金位吃回去。触发 = 存在「单件退金 ≥ 到下一利息档缺口」的资格候选(缺口单一源 = `kernel/cw_economy.py::next_interest_line` = 下一档线 `(g//10+1)×10`;满档/买断制 = None 不凑——**跨不了档的卖出零利息收益,一件不卖**:利息 = `g//10` 封顶,档内卖出金位变动不涨息,旧「卖到饱和线」判据在 P1 早期金 10~40 区间退化为卖光备战席)。动作 = 取退金 ≥ 缺口中退金最小的 1★ 全额退件(评估器过滤参数 = 仅活期件;卖回量最小化 [11]),逐帧单张:跨档后下帧按新金位重评自然收敛。升级凑金在途时本步受抑制(同池候选,凑金优先;抑制载体 = 升级资格门判据同帧重评,未命中帧本步照常)。

**第 9 步:出战。** 以上全部步骤无动作 → 输出 `CwActionStartBattleParam`(备战环唯一完成态)。出战前置动作发出点机制保留(发射前判定宿主 = `kernel/cw_launch_admission.py::readiness_launch_decision`,机制出处 = [26_battle_settlement.md](26_battle_settlement.md)):出战就绪帧短路本工序的出战动作直接发射;**受限商店访问帧不受会话标记辖**(发射帧仲裁授权的富余段消费照常进入商店执行)。出战点击后若长时间未离开备战画面且第 0 步告警已清 → 交外循环(已建档画面的轮转/哨兵保留证据)。

## 2. 卖出候选评估器的备战域消费

全部卖出场景(备战与商店两域)共用一个卖出候选评估器(单一入口 `criteria/sell_candidates.py::evaluate_sell_candidates`):候选池构成/资格面/价值排序的**单一源定义 = [11_shop_decisions.md](11_shop_decisions.md) §4**(价值 = 变现价 + 再遇期权 + 合成进度的金当量三项 + 羁绊规则项)。备战画面消费的场景:溢出自救(第 0 步,自救扩展资格面)、晶矿腾位(第 3 步,垫件谓词过滤)、升级凑金(第 4 步,备战侧候选池 = 备战席 ∪ 场上无关角色)、节末凑息(第 8 步,仅 1★ 全额退件)。每笔卖出记遥测(场景、卖出名、价值档),各自可判读归因。

## 3. 节点边界状态重置

策略入口(备战/商店两域各自)在节点号读取处调用同一边界处理函数(`session_scope.handle_node_boundary`):检测到生效序位(位面,轮次)变化 → 按清单表执行一次重置(重置全部幂等;函数内部判重避免冗余执行)。**键清单的唯一所有者 = 该函数的清单表**,其他模块的节点作用域键显式登记进表(键名 + 复位值),禁各自散写重置逻辑。清单:

| 键 | 复位 | 理由 |
|---|---|---|
| `shop_handled`(本节点已处理标记) | 清值 | 新节点牌面全换,旧标记语义死亡(节点切换自动刷新全店) |
| `shop_opportunities`(未消费机会清单) | 清空 | 牌面变了,旧机会作废 |
| `line_eval_signature`(方向证据签名) | 置失效 | 强制下帧重算(节点变动伴随结算收入与自然经验,资产面可能变化) |
| `gold_ledger`(金位账面) | 置失效 | 读数失效条件「节点切换」经本表落地 |
| 会话域旗标(读数意图/受限访问/会话处理中/插件额度) | 复位 | 会话不跨节点,边界帧残留旗标防泄入下一节点 |

(升级预授权重置行已随 2026-10-17 迭代 T-4 键退役删除——判据同帧重评后无跨帧授权可清;商店随机态重开信号宿主 = GameState 簿记槽,边界清扫经边界函数直清不入本策略态表。)

**负登记(不重置项)**:方向状态本身(锁定线槽/候选快照/开局配方)不重置——锁定为一次性决策跨节点持续保留,候选快照随签名重算自然更新,配方物化链每备战期自写;`plane2_started`(第二位面已启动窗口谓词)与 P2 选卡侦测键同不重置(单调历史事实)。

## 5. 能力 vs 策略

备战期动作集与能力面同集(原则定义 = [../screens/README.md](../screens/README.md) §1 与 §5.3);商店期「卖备战/买经验收缩至备战期」的旧判例已废止(两画面现为全动作面分工而非能力收缩,对照 [23_shop_screen.md](23_shop_screen.md) §3)。

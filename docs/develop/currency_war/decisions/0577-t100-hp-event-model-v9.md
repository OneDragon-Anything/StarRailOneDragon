## 1. 背景与问题(三件同根,公共根 = hp 真值链的「事件模型」缺失)

链把「读数序列」当「事件序列」用,非标准流在链上没有一等公民语义。三件表现(证据基座 = 单局复盘 `g_20260907_025608` + 对局档案逐行实测):

- **A:XP 血购不入遥测**(采集面为主)——血购动作三层有记录(决策迹/执行账/外生事件),但「HP 支付」这一事实零记录:`LevelUpOp.execute` 只记金口径回执;prep 通道连点循环无 hp 感知;HP HUD 店开态物理不可见(相位门),支付时点结构上无真值可读。换币模型 `'奋斗协议': xp_buy_hp_cost=6`(cw_investments 注册表)是死字段——`effects_from_strategies` 生产零调用者。
- **B:跨段战斗腿膨胀**(聚合面)——`_build_rounds` 单链无段界,游标携带前段值跨段:025608 p2r1 结算 18 对游标 61 出 −43,吸入段尾 prep 血购 −24(真战斗腿 −19)。resume 恢复帧 37 的真值在档(resume_reconciliation 已显影)但链不消费。
- **C:死亡轮 conf=0 无条目**(聚合面为主 + 写端一处诚实性)——补给合成行 hp 取 last_state 快照、conf 取 readable 直通,陈旧快照冒真值占位步进链 → 可信侧被占、回落被跳过、拒锚侧无替代源,死亡腿两头落空(025608 p2r4 实证:合成行 18@conf1.0 占位,真值 1)。结构保证真值(runs.final_hp=0)链不读。

条件链合并:血购发生 → 执行回执无 hp 口径 + HUD 不可见 → 采集面零产出 → 跟踪滞后到下次关店真读 → 段尾停机则永远滞后 → 链只认结算行 → 幻影败场/跨段膨胀/死亡腿两头落空。B 的锚缺失让**任何**间隙变化(已建模的、未建模的)都毒化战斗腿——A 落地只是把「已知变化」变成事件,锚仍是未知变化的最后防线,两修法是分层防御非重复补丁。

## 2. Considered Options

| 方案 | 裁决 | 理由 |
|---|---|---|
| A 件:hp_pay 走 exogenous 通道 | ✓ | SpendReceipt 是 ADR-0504 预算-回执契约载体,已随 decision_v2 整包删除判亡;执行回执位纪律在飞单一源 = ADR-0571 §2.2/§2.3;record_exogenous 通道有 sell_income/modality_gold 执行点先例,切片/视图自动携带零改 |

| C 件:合成行仅写端 conf 降权(方案 v1) | ✗ | 升格为**装配端一律退出步进链**:快照不是事件;v8 给合成行步进资格的唯一立案见证(182456 合成行 45>31「回血」)经帧序复核为鬼值——45 最后观察支持在 18:53:49,18:57:42 已结算 31,陈旧一整轮战斗 −14;先验按「陈旧直到证伪」翻转后旧档案也修到真值 |

| C 件:可信门放宽(conf=0 的 loss_page 入链) | ✗ | 伪值入链伪造条目毒化游标(ADR-0567 §1);修「门后没有替代真值」而非修门——替代真值 = 终局腿(runs.final_hp=0 结构保证)+ 回落路径 |

**机制多样性如实声明(方案审保留意见,采纳入案)**:「一个事件模型」下实为四种机制,适用面不同——①运行时可观测源(血购支付;未来补给回血若证实)→ 事件行(写点采集);②跨段接续真值(resume 帧)→ 装配端锚事件(重锚);③结构保证真值(runs.final_hp)→ 装配端派生兜底(终局腿);④快照行 → 装配端剥夺事件资格(降权)。「后续变化源只需加写点不需动链」仅对①成立。

## 3. 已实施架构

### 3.1 批1 采集端(hp_pay 执行回执)

- **写点 = `prep_actions.record_hp_pay_event`(两通道共用唯一实现)**:店通道 `LevelUpOp.execute`(单动作形态单击=一行)与 prep 通道 `_level_up`(连点循环内**每击一行**,验证成功前每击已实际扣血)。kind='hp_pay' 走 record_exogenous;choice 载 `{plane, round_num, currency:'hp', hp_delta:-cost, mode, clicks:1, basis:'modeled'}`(plane 显式入 choice:顶层 plane 恒 None,先例 record_modality_gold);不传 state 快照(支付时点快照 hp 是陈旧携带值,入行会被误当支付时点真值判读)。
- **mode 与判定同源注册表派生(F8)**:active_strategies 中 `xp_buy_hp_cost>0` 的卡(现唯一命中『奋斗协议』=6);非 active(金本位升级)→ 零行 no-op;多卡命中取 active_strategies 序首个(现版本游戏仅单卡在册,新血本位卡落地写点零改动)。
- **判读口径**:hp_pay 行数 = 血购击数,血购总量 = Σhp_delta。
- **真值对账**:modeled 行只作期望账;装配端在下一**可信结算行**(关店态 HUD 可见,店开盲区不妨碍)处比对「游标(已含事件推进)」,偏差≠0 落 `hp_pay_defects` 一行(留证不阻塞),游标照取结算值自愈——建模错账最多污染到下一结算并当场显影。
- **登记不修的第三通道**:店席满急救盲击购买经验(shop `_handle_bench_full`,回执覆盖不到)——显式申报,不顺手接。
- **死字段归宿裁决(F6-5)**:`effects_from_strategies` 及 `xp_click_hp_cost` 聚合路由(MechanismMutation 字段 + build_ledger 分支)随批**删除**——单一消费形态 = 写点直查注册表,不留「修完仍死」第三态;删除零行为变更(生产零调用者亲核,测试仓零引用)。

### 3.2 批2 装配端(v9 一次 bump)

- **事件步进链**:`_build_rounds` 结算步进链扩为 hp 变化走行——可信结算行 ∪ hp_pay 事件行按 ts 全局交织;**事件步只推进游标不出条目**(保 ADR-0567「一条目=掉血结算行」纯度);真值对账在每个可信结算行处结算(见上);顶层新增派生列 `hp_events`(事件行显影,加法,旧档案恒空)/`hp_pay_defects`。
- **段界重锚**:走行遇换段(以及 rounds 链到达续段首 key)取该段恢复帧 hp 重锚(`_segment_resume_frame` 单一源,与 resume_reconciliation 同一帧定义,防两处「恢复帧」分叉);**重锚差显影归走行单一落点**(步进链游标含事件推进,是「事件已解释边界差 → 重锚 no-op」的唯一知情者;rounds 链锚点静默换锚)——落 resume_reconciliation 扩展字段 `unexplained_delta`(= resume − 重锚前游标)+ `consumed_by_chain=true`,**不进 loss_nodes**。恢复帧不可锚(缺帧/hp None/readable False)→ 不锚维持跨段携带(诚实退化,与 v8 一致)。
- **rounds.hp_delta 跨段语义变化(读端可见)**:续段首槽 delta 从「跨段净额」变「段内变化」(025608 p2r1 −43 → −19)。跨局对照跨段槽位时数字会变,修复语义内非回归。
- **合成行一律退出步进链**:`_settlement_hp_usable` 对 source='synthetic_supply' 恒 False(v8 的仅 0 值防御升格)。降权只及步进链:rounds 槽/query_hp/anomalies 对合成行的显示行为不变。
- **终局腿(C-主,加法零新运行时写入)**:链走完后 `result='loss'` 且步进游标≠0 → 追加 `{hp:0, delta:−游标, hp_source:'endgame_final', outcome_source:'runs.final_hp', ts:None}` 于末 key;游标已到 0(含回落路径到达)守卫不重复;win/abandoned 局零终局腿;游标 None(全程无可锚行)无 delta 可算诚实跳过。loss_nodes 条目语义扩为「掉血结算行 + 终局兜底」。
- **写端 conf 诚实性(C-伴生配套)**:`cw_loop._record_supply_outcome` 快照新鲜性降权——快照 hp 观察节点(`session.last_hp_real_node`,备战域真读写入节点号 = 值被真读到的时刻)≤ 最后可信结算节点(`session.last_hp_t`)→ conf 落 0.0;**禁用 readable 位与赋值时刻作新鲜证据**(025608 03:19:38 帧 readable=True 值陈旧的携带链实证);任一锚 None(无结算/无真读)→ 维持 readable 口径。
- **ts 走行三边界(F5)**:ts 单源 = 记录时点墙钟,排序键字符串比较。①同秒碰撞:事件物料前置拼接 + Python 稳定排序 → 同秒事件先于结算(备战先于战斗的物理先序),结算/回落保持 v8 遍历序(key 升序、key 内 ts 稳定)= 单段局逐字节退化的技术前提,显式申报为 tiebreaker;②缺 ts 行:守卫为**不进步进链**(空串排序键会错位到全局最前;该行步进资格让位回落;缺 ts 回落源行同守卫——ts 走行无位可置,该轮条目丢失是缺 ts 数据的诚实代价,v8 键位内联无此依赖),hp_events 列仍显影;③时钟回拨/NTP 步进:走行序失真,诚实退化(错位条目)与恢复帧不可锚退化并列申报,不加补偿逻辑。
- **存量档案**:auto-rebuild 原地重装配(「能修复就修复」),全量 diff 抽查随批交付(§5)。

### 3.3 取证链硬门(F3④,实施前完成)

182456 补给节点执行路径动态复核 + jsonl 取证,结论:**先验维持(陈旧直到证伪),不回加新鲜分支**。①写点唯一性:`source='synthetic_supply'` 全仓唯一写者 = `cw_loop._record_supply_outcome`(recorder.record_outcome 透传),hp 取 `last_state.hp` 快照、conf 取 `hp_readable` 直通——快照链结构上无新鲜性保证;②182456 帧序亲算:45 最后观察支持 18:53:49(r2 prep)→ 18:57:42 结算 31 → 18:58:00 合成行载 45(19 秒无战斗 −14 无机制)= 鬼值;③旁证:025608 两个补给节点 hp 均与结算值相等(44→44、1→1)——「补给回血」在本项目档案里从未被可信观察过。

## 4. 边界申报

- **v8 T1/T2 锁语义重推(锁的存在性纪律,非机械保绿)**:逐结算行化方向与 M1「仅不可信结算行轮」形态分叉契约保留;「合成行入链」前提撤回——T1 重推预期 = 31→12 = **−19**(战斗腿相对最后可信结算;v8 语义的 −33 建立在鬼值游标上);T2 的「净额≥0 轮漏记」缺陷形态依赖鬼值先占位推进游标,退链后**结构性消除**,改钉消除本身(同 fixture 零条目 + rounds 净额照旧)。M1/T3 断言逐字未动。
- **ADR-0567 §1 立案叙述勘误(鬼值指针)**:v8 依据「同轮补给回血+战斗掉血」立案,其中「回血」见证(182456 合成行 45)经帧序复核为陈旧鬼值——合成行在 v8 下曾获得的步进资格自 v9 撤回;ADR-0567 的「重装配 −19→−33」读数自 v9 起不再成立(182456 实档 schema 7 从未重装配,−19 在册;准确表述 = 「重装配(v8 语义)将捏造 −33,降权使其保持 −19」,勘误对象含方案 §3.3「现存 v8 重建产物(−33 条目)」表述)。
- **取证翻案分支的中间窗口**:若未来取证证明确有「新鲜回血合成行」,降权维持、回血可见性走 hp_receipt 类**事件**写点(另立批,不走快照)——批2 落地到 hp_receipt 落地之间,真实回血会被吸入下一条战斗腿;先验(回血从未被可信观察)使该风险很低,**该窗口期战斗腿判读注意:补给节点后首个战斗腿含未建模间隙,判读并读补给行快照**。
- **归因 +1 不修**:补给合成行轮归因 +1(read_phase_round 走缓存)登记不修——装配端降权已消除其链上危害,归因偏移留判读侧已知缺口。
- **遥测禁入决策输入(F6-2/隔离申报)**:hp_pay 行纯观测追加写,禁任何决策/跟踪代码读它回写 `state.hp`/`session.last_hp_real`/预算门状态;grep 守卫锁钉死('hp_pay'/'hp_delta' 子串 + `\bbasis\b` 词边界,auth_basis 合法存在不误伤)。
- **sim 同病登记不修**:`st.gold -= _lv_cost` 血购扣金(sim/engine_p1)属 sim 行为变更,须独立批 + ADR-0561 申报表式登记。
- **prep 金门错币种登记不修**(prep_actions.py:692-695 现行为:血本位协议下金门不构成血排干保护)——策略层件,关联血本位回避落地后评估。
- **计数口径**:`n_loss_nodes` 可变(合成行占位轮经回落补出死亡条目、终局腿加法、净额形态消失)——修复语义内。

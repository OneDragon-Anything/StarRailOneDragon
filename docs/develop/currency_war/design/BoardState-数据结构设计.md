## 1. 三个名词

> 出处声明：本文标注「玩家裁定/口述 2026-09-09」的条目，口述原文不在仓库；整理以会话引述与 CW 迭代账本（`.debug/progress/2026-09-06-currency-war-redesign/dag.jsonl` 各轮记档）为准（先例=equipment_mechanics.md:122-126「口述原文不在仓库」声明）。涉玩法事实的裁定与在册文档冲突时挂实机复核（例：§4.1 布局修饰注）。

**BoardState**——当前仍为真的局内已知事实快照。单例，每局新建，只描述「此刻」，不是「本帧画面」；跨画面保留的字段（§3 各画面章节所列）与不经画面写入的账本（§3.7）也在其中。历史序列一律归遥测。画面 op 与决策 op 写，策略器读。

**StrategyState**（原 StrategyMemory）——默认策略实现的私有状态（配方方向、义务账本、信号、旗标），**归策略实现层、框架层不感知**：策略器基类仅以泛型参数携带该类型（如 `BaseStrategy[TState]`），框架不知道其字段。随策略实现变化，只有策略器自己读写。归属判据：换一个策略实现就不存在的字段放这里；游戏里能观察、框架按游戏逻辑能算的，放 BoardState。

**遥测**——整局历史，每帧每动作照旧落盘。复盘/回放/统计从遥测拼，不从 BoardState 读。

## 2. 通用规则

### 2.1 一份数据，来源标记到字段

每个字段 = `{值, 来源, evidence?}`。来源四值（+显式申报的载体中继约定，见节末）：

- **observation（观察）**：亲眼看到的——用本帧识别结果覆盖旧值。sim 侧以 GameState 真值合成时同样记 observation，evidence 恒带 `sim:synthesized`。
- **logic（逻辑）**：决策动作按游戏规则推算的预期效果。字段的 logic 值只存**核实通过**的正式值；核实前的预期放在预期条目表，不进字段（两步见 §2.5）。
- **carried（沿用值）**：这一帧没读到、保留上次好值时写入，evidence 必带 `carried:<来源帧>`——防 N 帧前的旧值在遥测里被当成「本帧真读」。
- **prior（先验）**：来自历史遥测调查的先验写入——非本局亲见、非当前推算、非沿用，是第四类（如开局 hp 先验，§3.1.6）。evidence 必带 `prior:<来源>`（如 `prior:adr-0559`）；本类仅限显式申报的条目，禁扩散。
- **载体中继（session_carrier，批次一实现暂用）**：接管/初始化时把会话已知事实补写进从未写过的字段——**不设第五来源类**：中继写入 source=logic（evidence=session_carrier），且**已有正式值的字段一律跳过**（禁把 handler 已写的 logic 翻成 observation，§8.1）；批次二收敛此语义并落测试锁（cw_observation.py:2528-2548 现状）。

evidence 为可选的来源注记，用来记录证据分级（帧标签的稳定范围、当场读还是开局恒值、`superset` 标记等，随各字段申报）。

### 2.2 识别质量是写入闸门，不是字段

读不到/不可信就不写，保留上次好值；BoardState 里只有「当前最好的已知值」。BoardState 无质量位：`None` 只表示**这一帧没读到**，不表示「未建模」——未建模的字段根本不进 schema，缺域由 bs_schema 的域版本键表达（§3.7.1）。「机制性 None」（该画面机制上读不到、无读数机会）按字段显式申报——在册申报面见各字段条目与 §6.3；**恢复局备战期金币已裁定无机制性例外**（同按观察接线，§3.2.9/§6.3；:113 孤例若实机复核不过，才构成该局的无读数机会分支）。**失读帧的字段处置二选一（统一口径）**：①字段已有正式值 → 写 **carried**（沿用上次好值+来源帧标注，§2.1）——即「继承之前的值」；②字段从未读过（机制性不可读态+新局）→ 字段**保持 None**——「机制性 None」专指此态。硬边界：字段一旦有过正式值，任何失读都不得把它清成 None。**画面附加域显式例外**：shop/encounter/supply payload（§8.4）语义=「当前画面的 payload，非当前画面=None」——离开画面置 None 是**结构事实**非失读，不适用 carried、不受本硬边界辖。域内 None 恒=结构清空〔非当前画面〕；在屏失读不写、沿用旧值，在屏与否由分类子态判定（§3.2.17）——None 不承载「没读成」义，与 event_overlay 的 'none'/None 分写同理，双义禁令适用（§3.6.1）。

### 2.3 观察与逻辑冲突：观察赢

观察覆盖 logic 值 + 来源改回 observation + 失配记入缺陷台账。**只管正式值**：还没核实的预期条目只能由它自己的核对点来关闭，观察帧不得确认或清除它。

### 2.4 写入规则与三个关键结构

写入点以**写入时刻的单例现引用**为基底构造新帧，禁止拿着旧帧跨时段写回。**读不分域**：按画面分组只是方便组织写入，读取时不分区域。

随迁移批次一（四个迁移批次见 §8.7）建立的三个关键结构：

1. **预期条目表**——逻辑写入两步机制的本体。每条预期五个键（对齐现役 ExpectedEntry，cw_expected_state.py:55-104）：①path（字段路径寻址）；②confirm_point（绑定的核对点——条目只在绑定的核对点可确认转正）；③group_id（组内条目全有全无清账，禁按单字段半确认）；④last-wins（同字段后写覆盖前写）；⑤at_round（轮键）。
2. **帧观察完整度标注**——记录备战帧/商店帧这一帧观察做得多完整（full=全量识别 / view=只读了部分 / none=没识别），消费即清。停更检测的哨兵用**只增不减的计数**（写点序号/最近推进时刻），不用这个标注的现值（消费即清后多半是 none，当不了哨兵）。
3. **bs_schema**——域粒度版本映射。

### 2.5 逻辑写入的两步：先记预期，核实后转正

决策动作生效后，记录先在**预期条目表**里记一条**待核实的预期值**（执行后应该变成什么样，例如买一张牌=商店少一张、备战席多一张）；核对通过后转**已确认**，才正式写入字段（来源=logic）。策略器只读字段里的已确认值，不读预期条目。核对失败的处置即 §2.3 观察赢。

## 3. 字段清单（按画面组织）

> 组织规则：字段写在「能写入它的画面」小节里——要看一个字段怎么来，就找能写它的那个画面。一个字段能在多个画面写入，就在每个画面小节各写一条：条目写清**这个画面往字段里写什么**；字段的完整语义（None 含义/边界/效果修饰）放在主条目，其余画面条目互引不复制，防同文漂移。读取不受此限制（§2.4 读不分域）。画面切换不重置字段：没有新写入就是保留值（跨画面沿用标 carried，§2.1）。各画面上的决策操作也会写字段——op 维度的写入规则见 §4，各画面小节尾有指引。

### 3.1 开局序列（难度确认 → 简报 → 位面过渡）

> 开局只写初值；之后整局由各画面自己的写端接管（各字段主条目）。

#### 3.1.1 职级 selected_difficulty

开局写定，恒稳，之后整局不再变化、不再需要画面。可见画面=**难度确认屏**（建档在案：标识-当前难度职级）；开局简报是否显示职级未建档采证（现役简报读取仅敌人难度/词缀/首领）——待实机核验，接线前先补档（§3.1.2 同款纪律）。

#### 3.1.2 对局类型

标准 / 超频博弈。可见画面=难度确认屏 + 开局简报（开局写定）；**对局类型两屏均无建档区域**，接线前先补档（§3.1.5 同款纪律）。
**边界**：超频=更快/奖励略少/难度按标准最高职级（gameplay.md:61-72）；超频的节点结构/收入日程差异无文档支撑，登记为知识边界。

#### 3.2.7 部署容量与后排布局档

**这是什么**：上场单位站两排——前台恒 4 格；**后台一排的格子数会变**（正常 6 格，实拍最多 9 格）。本字段=「当前这一局后台实际画了几个格子」，决定部署/拖动用哪套槽位坐标（选错坐标=往不存在的格子上拖，run26 崩坏局根因）。

**后台格数怎么来的（机制，ADR-0385 终判）**：正常 6 格；钻石/召唤物等效果把上场容量（cap）加到等级之上，每超 1 点后台多 1 格——**后台格数 = 6 + (cap − 等级)**（口述公式，用户口述权威源=board_structure.md）。**与等级无关**：旧模型「等级≥7→8 格」（ADR-0281）已被三帧实拍推翻（lv6 差 0=6 格、lv6 差 2=8 格、lv7 差 0=6 格，无一落旧模型）；等级只进 cap 板满门、不进布局选档。**备战席容量也不随等级变**（恒 9，唯一例外=节省工位时限效果，§3.2.5）。

**现在怎么识别（三信号+裁决序，cw_back_layout.py）**：
1. **公式通道**：OCR 读「部署数」区域得 cap（paddle 直读+防抖；**域外处置=ADR-0420 双帧一致采信**：域外值重读一帧，两帧一致且 level≤cap≤DEPLOY_CAP_ABS_MAX=13 → 采信+obs_conflict 留证；cap<level 恒拒、超绝对上界拒、两帧不一致拒——拒信才退基线；禁「域外一律拒信」，防真实高档被降级 6 槽复发〔ADR-0420 决策 3，e4972b43 实证 lv8/cap13〕）− 等级 → 差值 → 格数=6+差值（`back_slots_from_cap_diff` obs/cw_back_layout.py:313-328：差值<0 按 0；>2 封顶按 2；差值=1→7 格已建档直读；公式值未建档→退 8 格超集）。
2. **CV 通道**：后台那一排直接看图——空格子有暗框、没格子的地方是背景，按灰度差逐位判「这里有没有格子」（`cv_back_slots`，标定阈值在册）。
3. **占用一致性仲裁**：部署人数−前台人数=后台应有人数，逐候选档比对哪个档的格子占用最吻合（2026-09-05 修订升级，board_structure.md:66-72，关联 ADR-0420）。
裁决序：两通道一致→采公式；冲突∧部署数可读→仲裁；冲突∧不可读→CV 结构证据（cv>formula 采 CV，cv<formula 采公式）；CV 不可判/未建档→各自兜底（公式/防抖+8 格超集留证）。冲突必 obs_conflict 留证，留证时把当局已选投资环境名单（active_env）列入归因输入（挂迁移批次一/二接线；现役 obs_conflict 不自动附环境名单，接线前判读时人工核对）——**环境扩槽通道**：投资环境扩槽 6→7（2026-08-09 实测+用户确认；board_structure.md:14 口径合一待办+invest_effects.md §4 在案）。

**画面识别基础**：画面档案建了三套后排槽位区域——6 格=「后排-1..6」、7 格=「后排7槽-1..7」（整排居中重排，排中心恒 960，ADR-0390）、8 格=「后排8槽-1..8」；选中哪档就读哪套（坐标单一真相源=screen_info）。

**写入规则**：布局档字段**写真实槽位数**；6/7/8 档全建档；实拍出现过 9 格（diff=5，cw_back_layout.py:57/:103——域外未闭合）——域外一律按 **8 格超集**读全扩展带，evidence 补 `superset` 标记（与 carried 标记同型，防超集近似被当精确值消费；拖到不存在的格被游戏拒=廉价失败方向）；9 格闭合挂 ADR-0420。已观测最大 cap=13。布局字段写入策略需显式申报（挂迁移批次二）。

**依据文档修订义务（归玩法文档维护流程，本文不代改）**：备战屏档案 :53 现行文本=过期口径，以本节为准（迁移批次一的回归测试禁引 :53 level 驱动表）；备战屏档案「lv6→7 格存在性待采」与 cw_back_layout.py「diff==1→7 格已建档直读」一并勘误；gameplay.md:96 速查行「等级=可上阵数；至多 10 人（4 前台+6 后台）」与后台实拍可至 9 格、已观测 cap=13 直接冲突，board_structure.md:36 档案帧 cap=11 同面——并入同类的依据文档修订义务。

**回归测试断言约束**：禁按未截断形态（线性外推）算预期、禁按 level 驱动表写。

## 5. 投资策略与环境效果记录

本章=投资策略/投资环境/装备效果的本体记录：**5.1 效果账本**（谁在场、走到哪）、**5.2 缺口与载体登记**（注册表没建模的写入面）、**5.3 逐族写入归属**（每个效果族怎么写）。效果面冻结判据=§7。

### 5.1 在场效果激活账本 effect_inventory

**记录什么**：「当前正在生效的持续型效果」及其**进展状态**的登记表。一条记录=一个激活中的效果+它走到哪了——倒计时类（躺平「禁买禁刷 3 节点，到期返 20 金」→3→2→1→0 移除+返款；节省工位「3 节点内备战席只有 3 槽」→到期自动回 9）；计数类（长线利好「累计 30 次付费刷新后刷价变 1 金+20 金」的付费刷计数；采购专员「每 7 次刷新发 5 张同费」的计数）；条件窗口类（成长的快乐「8 级起单击 −1 金+4 经验」的开窗态）。

**为什么「持卡名单+注册表」不够**：名单只说「持有哪些卡」，注册表只说「规则文本」；而「还剩几节点/计数到几」是**历史累积量**，从当前局面推不出来，必须记账。没有这本账：策略器会在躺平期间点购买（被游戏拒）、算错当前刷价、按 9 槽摆一个只剩 3 槽的备战席。

**谁写**：触发时点由 ops 与 sim **双写端**维护——买卡=激活登记、节点推进=倒计时递减、刷新=计数累加、到期=移除+**尾款触发面**（金面缺省走观察覆盖兜底——§4.1 九卡纠偏，cw_loop 现役口径禁此处 logic 直写金币防双计；单列逻辑写建模者如超发货币按 §5.3 申报）。
**谁读**：策略器决策前置（能否买/刷、当前刷价、席容量）与效果修饰后的预期值归因核对。
**账本形状（一个账本就够）**：它不是标量，是**记录列表**；每条记录=（效果规格引用、来源、登记时点〔节点序基 1、登记期快照〕、节点余期、次数余量、计数器表）——倒计时/次数/计数三种进展维度同装一条记录，形状由各效果的注册表规格定义（现役同构=cw_effect_inventory.ActiveEffect 类定义，符号名索引——行号随批漂移）。拆成多字段会把一条效果的生命周期（激活→推进→到期）切进多个写入面，故不拆。

**「每个效果都独特」放在哪**：独特性由**注册表条目**承担——每个效果的规格是独立类型化条目（触发/时长/职责旗标/专属载荷，如 BattlefieldEffect.board_rewrite、CounterKey 计数键），账本只承担「实例进展」这个真正同构的部分（登记/推进/到期）。**曾考虑的替代=每效果写独立处理类，否决**：每个类都要重写同一套登记/推进/到期三件套，sim 与生产还要各自实例化，统一接口会自己长回来；且需要专属响应代码的效果是少数（躺平到期返款、节省工位回容量、采购专员改牌类——挂职责旗标 respond 接线），纯修饰型（淘金客每刷 +2XP）注册表条目+通用推进即覆盖。**记录模型的进一步优化（含替代形状再评估）=开放讨论项，暂不展开。**

**规格单一源**=cw_investments.STRATEGY_EFFECTS + STRATEGY_ECONOMY（每条效果记什么、怎么推进，注册表是唯一权威）。**词缀效果辖域申报**：affix_effects_data 词缀（成长的烦恼/变宝为废等）暂无结构化规格——改写面（LevelUp 金/装备库存）暂走观察覆盖+§5.2 缺口登记；ActiveEffect.source 已预留 'affix'（kernel/cw_effect_inventory.py ActiveEffect 类字段注释，符号名索引——该文件批次三后行号整体漂移），结构化归建模批。**过渡口径申报（批次三 as-built 更新）**：effect_inventory 挂点接线已落批次三——登记/tick/bump/consume_use 五挂点在产（结算挂点仍未接）；未结构化字段仍观察覆盖兜底。**待实采定谳挂账**：「持续 N 个节点」型卡文（躺平「持续 3 个节点」自然读法含登记节点）vs「接下来 N 个节点」型（节省工位）两读法现共用 tick 守卫（登记当节点不推进）——躺平方向系统性多冻 1 节点（remaining_nodes 零决策消费，现仅到期时点差一拍）；实采后按卡文逐卡拆两读法（EffectSpec.pending 标记随批）。

## 6. StrategyState 与生命周期

### 6.1 StrategyState（默认策略实现私有，框架层不感知）

### 6.2 生命周期

开局新建（无需任何特殊处理）→ 每个画面识别后观察覆盖（只写该画面可见的字段，§3 各画面小节）→ 每个决策按写入规则推进 → 出战冻结 → 结算真值覆盖 → 下一回合带着旧值重建 → 局终归档喂遥测（**先于**连刷重建执行）→ 连刷重置协议（判定换了新局看两个信号：ctx.cw_match 为 None + establish_new_match）。

### 6.3 接管恢复（恢复局）

进过战斗后 exe 异常退出再继续的局：**恢复局备战期商店不可开**——商店按钮点击无响应/面板不可用/不得尝试开商店（currency_war_prep.md:16-18；retry 耗尽=整个 run 失败）；备战期 gold **无机制性例外**：同按备战帧观察接线（§3.2.9 玩家确认）；首战前商店不可开=无开店读数来源，gold 保持 None 是**无读数机会的数据事实**（§2.2 分支②：从未读过→保持 None），非机制规则。**显式决策表（§3.2.9/本节同源，禁三种读法并存）**：①接线恒观察——备战帧读到即 observe（:113 复核只影响「是否会读到」，不影响接线方式）；②读失败→carried 沿用（从未读过→None）；③None 仅当从未读过——不是机制规则、不是恒 None 口径。

### 8.1 字段容器 Field[T]

```python
@dataclass
class Field(Generic[T]):
    """一个字段：值 + 来源 + 可选源注记。只存正式值——待核实的预期不在这里（§2.5）。"""

    value: T | None = None
    source: Literal['observation', 'logic', 'carried', 'prior'] = 'observation'
    evidence: str | None = None   # 如 carried:<来源帧> / sim:synthesized / superset

    def observe(self, value: T) -> None:
        """观察写入：亲眼看到、覆盖旧值（§2.1 observation）。"""
```

要点：字段只存正式值——observation=亲眼看到的；logic=自己推的、已由核对确认后写入的（**来源保持 logic，不翻成 observation**）；carried=沿用值（消费时读 evidence 来源帧）。**待核实的预期不进 Field**：由 BoardState.expect 记入预期条目表（§2.4 关键结构 1），核对通过经 BoardState.confirm 转正写入字段（§2.5）。

    effects: ActiveEffectInventory = field(default_factory=ActiveEffectInventory)

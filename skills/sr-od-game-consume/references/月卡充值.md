# 小月卡(列车补给凭证)充值路由

> 画面细节(识别锚点/子态/交互事实)走 MCP `get_screen_detail('商店')`;本文管操作路由与状态解读。

## 1. 机制(游戏内规则说明实测)

- ¥30/张:立即获得 **300 古老梦华**,列车补给凭证生效时间延长 30 日。
- 生效期间**每日登录**可领 **90 星琼**(每日凌晨 4 点重置;未登录未领取不返还,
  30 日最多 2700 星琼)。**购买当日**的 90 星琼随购买立即到账(实购核证:
  星琼 +90,页面标「今日已领取」,次日恢复凌晨重置节奏)。
- 生效时间 **<179 天**才可继续购买(可叠加);**≥179 天无法购买**。
- 生效状态读取(两处,area 均已建档):
  - 详情页中央「剩余领取天数：N天」(area `文本-剩余领取天数`;无生效凭证时该
    area 不命中 = 无生效);
  - 左侧栏凭证项角标(生效中如「29天」,无凭证时为「超值」)。
  - ⚠️ 购买后凭证项会**漂移到侧栏末位**,入口 area 已按整条侧栏建矩形,
    不依赖槽位。
- 每日领取入口 = 登录游戏时的领取弹窗(独立画面「列车补给」,「点击领取今日补给」,
  需连点两次;该弹窗建档录于旧版 UI,新版形态待复核)。

## 2. 操作路由

| 步骤 | 用什么 |
|---|---|
| 导航到凭证详情页 | op `BuyExpressSupplyPassOp(open_qr=False)` —— 从任意画面一键到位(内部:手机菜单 → 商店 → 左侧栏凭证页),成功状态 `ON_PAGE`,零消耗;分步替代:MCP `goto_screen(target_screen_name='商店')` 后 MCP `click_game` 左侧栏(区域走 MCP `get_screen_detail('商店')`) |
| 读当前状态 | MCP `analyze_screen` —— 详情页可读 商品名/「购买(或续订)￥30.00」价格/「购买即可获得 300」「30日内每日赠送 90」;**生效中**额外可读「剩余领取天数：N天」、按钮变「续订」 |
| 确认购买意愿 | 与用户确认(消耗门,见 SKILL.md 红线);顺带确认支付渠道偏好(支付宝/微信) |
| 打开付款码 | op `BuyExpressSupplyPassOp(open_qr=True, pay_channel='alipay'或'wechat')` —— 自动重新导航(幂等,已在详情页直接续跑)→ 点「购买/续订」(按钮文案随凭证状态二态,op 自动识别)→ 扫码弹窗 → 按渠道就位,成功状态 `QR_OPENED` |
| 交还用户 | 告知「扫码弹窗已就绪(渠道 X,¥30.00),请扫码完成支付」;bot 止步 |

- MCP `run_operation` 的 `op_id` 直接用类名短名 `BuyExpressSupplyPassOp`(短名全库唯一
  即运行;若未来出现同名类,MCP 会拒绝并列出候选完整名)。
- 收尾清理(用户放弃支付/付完后撤摊):点扫码弹窗右上 X → 弹「确认放弃本次支付?」→
  点「确认放弃」,两层全关回详情页(MCP `click_game`,坐标走 MCP `get_screen_detail('商店')`
  的 area「按钮-关闭扫码」「按钮-确认放弃」)。
- 付款码摆好后核对渠道:支付宝态=「其他支付方式」按钮可见;微信态=「返回支付宝扫码」
  按钮可见(同槽位互斥)。

## 3. op 状态与失败去向

- `ON_PAGE` = 已到详情页(open_qr=False);
- `QR_OPENED` = 扫码弹窗已打开且渠道就绪(open_qr=True);
- 失败:商店内找不到凭证入口(左侧栏随版本轮换,需重验建档)/购买或续订按钮缺失
  (**月卡生效 ≥179 天时游戏禁购**,或页面异常)/扫码弹窗渠道按钮均未命中(弹窗异常,
  现场核查)。

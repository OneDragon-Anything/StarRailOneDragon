## 0. 重估通则（先立尺，再逐表过堂）

1. **消费点是否仍活**是存废前提：消费点已死或被消费通道取代 → 停用；活 → 进入合规审。
2. **合规审的尺**不是「分数是经验值就停用」，而是三问：
   - 该决策面是否**必选面**（UI 强制三选一/二选一，无「不选」动作）？必选面不能 fail-closed（读数或判据存疑时朝「犯错代价小」的方向取值或拒绝动作）到不选——停用必须以替代判据承接，否则无从停用；
   - 该分数的**结构方向**是否有出处（玩法机制原文/注册表结构/用户偏好轴/阵容知识）？方向有出处的部分可保留为知识判据；
   - 该分数的**幅度**是否有推导？无推导的幅度不得承载基数语义（与其它分值族相加/相减、被阈值比较），只可承载同族定序语义——这是「改形」的统一落点。
3. **与消费通道 v4.2.2 的关系**：消费通道（[14_p1_consume_arms.md](14_p1_consume_arms.md)）适用于买/升/刷三类动作发出点（其 §3-§6），事件/选项决策面（pick 族）不在其适用范围——评估表体系是证明层 target 选择与持卡登记的**上游输入**，未被消费通道取代；全部消费点 grep 复核为活（§2 逐表列出处）。
4. **归属对账**：事件面数学规格在 01 §4 显式登记「无数学待立项面」（08_events E1-E18 逐项「待立项推导」）。评估表体系的最终归宿 = 事件面命题批；本批裁定的是过渡期的**合法形态与登记待办**，不预支数值结论。
5. **13 §3 纪律衔接**：「事件判据禁自带数值」在本批的执行口径 = 禁**新增/上调**幅度值；既有幅度的存续以「定序实现常数」的显式降格为条件（见 §1 各表改形条），禁伪装为推导。

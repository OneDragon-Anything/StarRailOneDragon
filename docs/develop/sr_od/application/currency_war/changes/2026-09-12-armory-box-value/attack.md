## 1. 发现清单

### F1【次要】行 8c 的 design↔landing 分类冲突 + design 侧锁安置缺位；R1 成员清单两处不一致

- **位置**：`design.md` §2.6（行 8c「等价（守卫边界）」；R1 辖域 = 行 2b/4b/5/6；纯函数锁落位清单 = 行 7a/7b/7c/9）↔ `landing.md` §3.2（R1 = 行 2b/4b/5/6/**9**；变化行清单含 **8c**）。
- **凭什么**：design 行 8c 性质列 = 「等价（守卫边界）」（需 2 持 1 帧，新旧两制同为 tier3 提权），但 landing（账本阶段唯一源）把 8c 列入「变化行各自落变化锚点锁」；同时 design §2.6 三处锁安置清单（R1 辖域/「其余行为变化行」/纯函数锁落位 7a/7b/7c/9）均不含 8c，design 内部对 8c 的锁落位无着落。另 R1 成员清单两处不一致（design 4 行 vs landing 5 行，行 9 在 design 由「纯函数 + 集成帧」句单独安置）。
- **发作场景**：worker 照 landing 写出 8c 的「变化锚点锁」（语义上仍是该帧的等价断言，实际行为断言不坏），或照 design 找不到 8c 落位而漏写；B 组锁清单审计时两处对不上。
- **修正方向**：统一两处——建议 design §2.6 把 8c 显式归「等价·守卫边界帧」并指明锁落位（`pick_equipment` 纯函数 count 语义帧，与 7a/7b/7c 同点），R1 括注把行 9 的归属写齐；landing 同步把 8c 移出变化行（或反向：两处统一按变化行，并同步 design 性质列）。改后满足「设计改 → landing 改，禁两处各自演化」。

### F2【次要】行 4a 的示例帧「档内两件 material_value 不等（表内 vs 表外）」在现行注册表下为空集

- **位置**：`design.md` §2.6 行 4a。
- **凭什么**（实跑）：档内（tier 1）成员 = key 材料，而 key 材料全体 = mv 表内 8 简易名（实跑：key 材料全集与 `MATERIAL_VALUE_TABLE` 键集相等，无一表外）；tier 3 成员（成品 key）mv 恒 0 等值。「表内 vs 表外」的档内对在现行注册表下不可构造。若 worker 拿非材料的表外件（如火力风暴潮）凑帧，实际构造出的是档间帧（tier 1 vs tier 0），锁对象错位。
- **发作场景**：B 组按行 4a 落锁时帧构造失败或锁错档间序。
- **修正方向**：行 4a 改一般式表述（档内 mv 不等 → base 序），示例改为可构造形态（表内 vs 表内 = 行 3 已覆盖；mv 等 base 不等 = 行 4c），或显式注明「表内 vs 表外」括注在现行注册表为空集、锁由行 3/4c 承载。

### F3【次要】§2.2 反面信号引文「plaza 终局板实证同角色 3×反重力皮靴形态」证据级抬升

- **位置**：`design.md` §2.2（需求守卫取舍的反面信号申报）。
- **凭什么**：仓内可溯证据 = `docs/game/currency_war/research/final_comps/final_yinlang_joy.md`:48（「爻光: 反重力皮靴×3」，出处 = 68 篇 plaza 帖统计的装备公式节），属攻略佐证/帖级统计，非实机终局板实证；research 篇证据分级惯例（代码实锤/攻略佐证/推断）下应标级。该引文在设计中仅作反面信号申报、非守卫主依据（主依据已声明为声明性模型假设），故仅措辞级问题。
- **修正方向**：改为「plaza 帖级统计（final_yinlang_joy.md 装备公式，68 篇）【攻略佐证】」，或补实机终局板实证后再用「实证」。

### F4【次要】行 7a 现行列记法「生命之花（mv 33<37）」值对标签错

- **位置**：`design.md` §2.6 行 7a「现行」列。
- **凭什么**（直调）：`material_value('生命之花')=7`、`material_value('幸运星')=3`；33/37 是含 +30 材料档加分的总分。同表行 3 用的是正确记法「30+7>30+6」，行 7a 把总分标注为 mv = 值对标签错（本仓五犯实证错误类，虽方向结论不受影响）。
- **修正方向**：改「总分 33<37」或「30+7 > 30+3」。

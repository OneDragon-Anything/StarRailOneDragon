# 常态化巡检任务书（game-coach 攻略知识时效巡检）

> 本文件是 game-coach 知识库定时巡检的**完整任务说明**：执行巡检的 agent 拿本文件即可开工，不依赖任何会话上下文。文中路径均相对本 skill 根目录。给知识库建定时巡检任务时，把本文件内容（或其绝对路径）交给执行方即可。

## 1. 为什么巡检（任务背景）

攻略知识的时效性跟着**社区共识的演进**走，不跟版本更新日：

- 新角色/新光锥/新遗器套装实装会改变**旧角色**的环境——新队友进入替补矩阵、新光锥进入旧角色的光锥链、新遗器套装改变推荐装备、平衡性改动改变强度评价。这些影响是渐进显现的，不是版本更新日当天一次性发生。
- 版本初期评测样本少，结论只能标「实装首周口径」；中期实测积累可能推翻首周结论；末期环境稳定、共识成型，此时修正最可信（盖棺口径）。
- 逐光捡金系列（混沌回忆/虚构叙事/末日幻影/异相仲裁）每期轮换会产出**期次级**的推荐阵容信号（游戏内官方推荐 + 社区每期攻略推荐）——期次节奏比版本节奏更细，是与知识库阵容档/体系档直接对账的参照物，能更早暴露环境变化。

所以知识库需要**周期性**对照当前社区共识与环境做修正，这就是巡检。建议频率每周一轮；实际节奏由执行方环境决定（定时任务、手动触发均可），本文件不约束。

## 2. 开工必读与工作区（先读完再动手）

| 位置 | 内容 |
|---|---|
| `.debug/temp/game-coach-patrol/research-status.md`（巡检工作区，相对项目根） | 知识库现状 + **待复核清单**（巡检的主清单）+ 调研轮次记录。**不存在则创建**：从知识档的调研轮次节与「信息缺口」节、`references/characters/INDEX.md` 覆盖追踪表重建待复核清单 |
| `references/maintenance/research-methodology.md` | 调研方法论：信源判据、B站/米游社流程、噪声校准、入档格式、时机差异 |
| `maintenance/methodology.md` | 写档判断规则（证据层级/装备条件式/分层纪律） |

当期版本状态（当前第几版本、各新内容何时实装）用官方当期卡池接口确认，打法见 skill `sr-od-official-api`——注意接口响应无版本号字段，当期版本号靠卡池开始时间 + 版本公告名对照推算。版本公告全文官方渠道不可得时可用第三方转载，须多源互证并在过程记录标注来源。项目 MCP 查询工具偶发首轮报 unknown tool（server 在跑、注册未就绪），重试即自愈；持续不可用时兜底官方 wiki 接口（`sr-od-official-api`）。

**落盘分界（硬原则）**：skill 仓库（进 git）只放**给使用者的最终知识**——知识档本体（角色档/体系档/阵容档/机制档/INDEX）；一切**维护进度与状态**（待复核清单、调研轮次记录、每轮巡检过程记录）落巡检工作区 `.debug/temp/game-coach-patrol/`（不进 git，可能被清理——丢失时按上表从知识档重建，因此跨轮工作不得只依赖工作区里的易失内容）。

## 3. 巡检内容（必做 checklist）

> 没做完这 5 步不算完成一轮巡检。

1. ☐ **待复核清单对账**：逐行检查巡检工作区 status 文件待复核表的「触发条件」——已满足的按调研方法论执行复核；未满足的跳过。判据：每行都有结论（已复核并更新档 / 条件未到 / 复核后仍存疑转新待复核项）。必做。
2. ☐ **环境漂移探测**：确认当期版本与本轮周期内的新实装内容（角色/光锥/遗器套装/平衡性公告），逐项检查是否波及既有知识档——新角色该不该进旧体系替补矩阵、新光锥/新遗器该不该进旧角色的装备推荐、被改动角色的档是否滞后。命中波及面的对象按调研方法论定向调研。判据：每个新实装项给出「波及了谁、改了什么」或「不波及既有档」。必做。
3. ☐ **逐期阵容对账**：查逐光捡金系列当期各玩法的推荐阵容——游戏内官方推荐 + 社区每期攻略推荐（期次机制与环境增益见 skill `sr-od-treasures-lightward`）——与阵容档（`references/lineups/`）、体系档（`references/teams/`）对比。当期 4 个玩法各至少 1 个抽样源，不可得（期次将尽/无内容）的玩法如实标注；游戏内官方推荐需实机读取，无实机的轮次标注「未读取」、以社区推荐为据。判据：当期高频推荐的阵容逐一对比——档案缺失的高频阵容（或新阵容成员组合）登记进待复核清单；已有档但推荐成员/打法轴有出入的按调研方法论复核；档案内阵容连续多期无推荐仅在过程记录登记观察，不动知识档。观察名单首轮（或名单丢失后首轮）从当轮起建，「连续多期」判定自下轮累计（建议连续 ≥3 期再考虑处置）。必做。
4. ☐ **共识漂移抽样**：扫版本环境类汇总内容（强度排名/环境盘点，B站+米游社，方法见调研方法论）找全网级共识变化信号；发现与档内结论冲突的 → 定向复核。最小抽样量：至少 2 个独立源（B站+米游社各 ≥1），不可得时如实标注；与上一步的社区扫描可复用同一批内容，登记一次，勿重复调研。判据：抽样对象记进过程记录；冲突项入档修正或登记进待复核清单。必做。
5. ☐ **产出登记**：§4 各项全部完成。必做。

## 4. 产出登记（巡检结果的落点）

**三层记录各司其职，别写重也别写漏**：

| 层 | 位置 | 装什么 |
|---|---|---|
| 知识档调研轮次节 | 进 git（随档走） | 该档结论的出处证据链——随档修正一起写 |
| status 轮次记录 | 工作区（不进 git） | 每轮一行的摘要，跨轮历史快速可查 |
| 过程记录文件 | 工作区（不进 git） | 本轮详细笔记：逐项检查结果、调研证据、分歧 |

1. ☐ **知识档修正**（进 git，给使用者的知识）：波及对象的角色档/体系档/阵容档/`references/characters/INDEX.md`/`references/investment.md`（机制断点表）按调研方法论入档——修正旧结论时**保留旧口径并标注版本局限**。判据：每处修正带调研轮次与来源标注。必做。
2. ☐ **工作区 status 文件更新**（不进 git，维护进度）：轮次记录加一行（巡检日期 + 本轮发现与动作摘要）；待复核清单增删（复核完的移除或更新触发条件，新发现的过时风险登记进去）；「知识库现状」节有变化则同步。必做。
3. ☐ **过程记录落盘**（不进 git）：写 `.debug/temp/game-coach-patrol/<YYYY-MM-DD>.md`，**边干边写**（检查完一节写一节，中断也留下已完成的部分），结构按下方模板，无内容的节写「无」。必做。
4. ☐ **无更新也留痕**：本轮若无任何滞后，轮次记录同样加一行（巡检日期 + 巡检：无滞后 + 检查了什么），过程记录文件照写。必做。

### 过程记录模板

```markdown
# 巡检 <YYYY-MM-DD>（当期 V<版本号>）

## 1. 待复核对账
| 对象 | 触发条件 | 结论（已复核改档 / 未到期 / 转新待复核项） |

## 2. 环境漂移
| 新实装项 | 波及判定（波及了谁、改了什么 / 不波及既有档） |

## 3. 逐期阵容对账
当期各玩法推荐阵容 → 与阵容档/体系档对比：缺失登记了什么 / 出入复核了什么 / 仅观察了什么

## 4. 共识抽样
扫了什么源 → 发现什么冲突 → 怎么处理

## 5. 本轮动作
- 知识档改动：<文件>：<摘要>
- status 更新：清单增删 + 轮次记录行

## 6. 未实证与分歧
## 7. 下轮建议
```

## 5. 纪律

- **禁全量重调研**：巡检是清单驱动 + 定向深调研，不是把全部角色重跑一遍——每轮的深调研对象只来自 §3 命中的波及面。
- **待复核清单只收攻略时效类条目**（结论会随版本/共识过时的知识档复核项）；运行时事件触发型事项（画面建档样本、抽卡结果采集等）不进本清单——对账时发现已在清单中，标注「归 XX skill 跟进」并跳过。
- **处置无既有判据时**：保守不动知识档 + 登记进待复核清单 + 过程记录声明自定判据，禁止临场发明规则直接改档。
- 单源未交叉结论标【攻：单源】；没查到的进对应档「信息缺口」节，转述时声明「未实证」；禁凭训练记忆编造。
- **分工边界**：版本更新日的硬事件（新角色数据录入、实装首周建档、平衡性改动即时修正、往待复核清单**登记**复核条目）归 `sr-od-dev-version-update-adaptation` skill；巡检负责在登记条目的条件到期时**执行**复核。两边不重复做同一件事。
- 抽卡决策只产出结构化依据（机制/强度/性价比），抽不抽归用户。

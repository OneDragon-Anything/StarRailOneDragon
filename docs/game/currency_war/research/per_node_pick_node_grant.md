# per_node 族效果「拿卡当节点是否即享每节点免费刷新」核查(搜打撤/加油站/双手狸开键盘!/本金充裕)

> **性质**:游戏真值核查结论——投资策略卡在「拿卡的那个节点」游戏是否即发给每节点免费刷新额度。
> 用途 = 节点推进上报化建模(节点推进 = 终结动作上报;效果每节点发放挂节点边界)下,
> 「拿卡登记期是否需补发当节点额度」的单一依据;正本挂点语义见
> [effect-domain.md](../../../develop/sr_od/application/currency_war/game_state/effect-domain.md)。
> 证据分级:**A 原文引用**(版本冻结官方效果全文)/ **B 在册结论**(research 已归档判定)/ **C 推断**(文本惯例推演,待实机复核)。

## 1. 结论速览

| 效果 | 官方 id | 当节点即享? | 建模处置 |
|---|---|---|---|
| 加油站 | 200301 | **是(a)** | 登记期发放 +1(已建模:payload `free_refresh_burst=1` + 注册表 EffectSpec) |
| 搜打撤 | 303701 | 否(b),次节点起 | 零代码(登记期不发放与游戏真值一致) |
| 双手狸开键盘! | 204101 | 否(b),次节点起 | 零代码(同上) |
| 本金充裕/+ | 301001/301002 | 否(b),次节点起 | 零代码(立即腿只有金,已建模 `instant_gold`;刷新腿无立即) |

一句话:**四效果中只有加油站的官方卡文带「现在」立即腿,其余三张的刷新腿都只在「进入新节点时」触发**——新时序(拿卡晚于该节点边界发放)对这三张是向文本真值对齐,不是损失。

## 3. 逐效果结论(A 原文引用)

### 3.1 加油站(200301,金)→ 当节点即享(a)

> 原文:「**现在**及每次进入新节点时获得1次免费刷新,立刻获得8金币。」

「现在」= 拿卡当下立即 +1 次免费刷新(当节点商店即可用);「每次进入新节点时」= 此后每节点 +1。两腿并列、以「及」连接,立即腿显式存在。

### 3.2 搜打撤(303701,棱彩)→ 次节点起(b)

> 原文:「每当你进入新节点时,获得1次免费刷新。通关下一个首领节点后,获得等同于场上和备战席所有角色价值的金币。」

无「现在/立刻」措辞;拿卡动作发生在节点入口弹窗,该节点的「进入」事件先于拿卡,效果的首个发放节点是下一个新节点。首领节点价值返还腿与本命题无关(另行建模,非免费刷新域)。

### 3.3 双手狸开键盘!(204101,金)→ 次节点起(b)

> 原文:「获得【Gemi狸】,它会帮你进行商店和战斗操作!进入新节点时,它会免费刷新商店2次,自动购买你场上拥有的角色。每买到1个角色,【Gemi狸】还会使我方全体获得1%幸运一击率。」

刷新腿(每新节点 2 次)无立即措辞;拿卡当节点 Gemi狸 不刷新,首个自动刷新在下一节点入口。

### 3.4 本金充裕 / 本金充裕+(301001/301002,棱彩)→ 刷新腿次节点起(b)

> 原文:「获得26/45金币。**每次进入新节点时**,若拥有超过50金币,每额外10金币就会获得1次免费刷新(最多3次)。」

立即腿只有金(26/45,建模为 `instant_gold`,与刷新无关);条件刷新腿显式挂「每次进入新节点时」,当节点不评估不发放。加强值差异只在立即金,条件腿两卡逐字同文。

## 4. 文本惯例交叉验证(C 推断,A/B 佐证)

官方卡文对「立即发放」有稳定措辞惯例:**立即腿必带「现在」或「立刻」**,且注册表内现有建模与该惯例一一对应:

| 卡 | 原文立即腿措辞 | 现行建模载体 |
|---|---|---|
| 乱成一锅粥(352101) | 「**立刻**获得5次免费刷新和10金币」 | `free_refresh_burst=5` + `instant_gold=10` |
| 固定理财(201801) | 「**现在**以及每个位面开始时,获得4经验值和2次免费刷新」 | 即时刷 = `free_refresh_burst=2`(位面段另行挂账) |
| 免费午餐(100301) | 「获得11次免费刷新」(纯立即型,无持续腿) | `free_refresh_burst=11` |
| 定期福利(200101) | 「**立刻**获得4个金币,并且在每次进入新节点时,获得2金币」 | 立即金与每节点金分开措辞,建模 `instant_gold=4` + `gold_per_node=2` 分立 |

推演:若无立即腿的卡也在拿卡当节点发放,「现在/立刻」在文本上冗余——同族对比卡(加油站 vs 搜打撤:同为「进节点 +1 免费刷」,一有一无「现在」)证明该措辞承载真实发放差异。故「无立即措辞 = 拿卡当节点不发放」为可信推断,与 §3 逐字结论互洽。

## 5. 对节点推进上报化建模的结论

**时序背景**(语义描述,正本 = effect-domain.md):节点推进挂终结动作上报(战斗节点 = 结算确认、补给节点 = 补给确认),每节点免费刷新发放随推进边界执行;投资策略卡在节点 N+1 入口弹窗拿取,该次拿卡晚于 N+1 的边界发放。

- **(b) 三效果(搜打撤/双手狸/本金充裕族):零代码。** 拿卡当节点不发放 = 游戏真值,新时序自然成立,无需登记期补发。旧「备战帧观察推进」模型中推进发生在选卡之后的备战帧,新拿效果会在当节点边界被盘点发放——按本文结论该次发放是多发(文本不支持),新时序取消它属向真值修正。
- **(a) 加油站:需要登记期发放建模。** 实现 = 两处数据声明、零新机制:
  1. `STRATEGY_ECONOMY['加油站']`(cw_investments.py)增 `free_refresh_burst=1`——「现在」腿按 §4 burst 惯例载体登记;
  2. `STRATEGY_EFFECTS` 增「加油站」EffectSpec 条目——现有选卡登记挂点(CwScreenInvestStrategy 确认落地:register_strategy + apply_effect_burst_grant 同点)即可直通,burst 桥按 payload 发 +1,账本登记同时使已声明的 `free_refresh_per_node=1` 经节点边界桥真实生效(此前该卡无 EffectSpec,两腿在账本面均为死建模)。
- **去重语义**:登记期发放「每效果×节点至多一次」由结构保证,不设去重状态——①发放挂点唯一(选卡确认落地,单调用点);②每次拿卡事件由重入裁决一次性消费(`_confirm_pending` 单发即清,形态),一次拿卡只可能落在一个节点;③同卡跨节点重复拿取(游戏允许)每次拿卡各发一次「现在」腿 = 游戏真值,非重复发放。

## 6. 策略数学依赖核查

策略篇刷新判据(11_shop_decisions §3 形式二等)把免费额度作刷价折抵输入(`c_eff` 变体),不假设「拿卡节点必有/必无本次额度」——本文结论落库后,免费刷新余额账本面与游戏真值的偏差收敛为:加油站每局 +1(当节点)、无反向场景。搜打撤的账本登记缺口(每节点腿未入账本,决策聚合面 `aggregate_economy` 正常)是注册表全量收录推广批的既有挂账,与本命题结论无关,本文只登记不处置。

## 7. 需要实机验证的观察点(证据增强候选,非阻塞)

原文定谳已足,以下观察可在任意实机局顺带复核(按节列出「看什么画面、读什么数」):

1. **加油站当节点**:拿卡后同节点开商店 → 首次刷新应免费(金不减 2);刷新钮费用显示与刷新前后金差为判读面。
2. **搜打撤当节点/次节点**:拿卡当节点首刷应扣 2 金;下一节点首刷应免费 1 次。
3. **双手狸次节点**:下一节点入口商店自动翻牌 2 次(Gemi狸 代刷),拿卡当节点入店无自动翻。
4. **本金充裕次节点**:持金 >50 时下一节点免费次数 = min((金−50)//10, 3);当节点不发放(立即只到账 26/45 金)。
5. 加油站建模落地后,任一拿到加油站的局:结算对账免费余额轨迹应在拿卡帧 +1、其后每推进 +1(账本轨迹面,遥测 journal `effects`/刷新计数组可读)。

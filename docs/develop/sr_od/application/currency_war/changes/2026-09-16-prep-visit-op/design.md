# 备战访问编排 op 化迭代设计（总纲）

## 0. 元信息
- 迭代目标：用户裁定（2026-09-15/16）——cw_loop 备战分支编排迁入备战访问 op；**发射决策迁入策略层 mandate_v1**（用户裁定：必须到策略里，实现可以从简）；建立出战交回契约；发射执行器合一。
- 状态：草案
- 文档清单：无详设（单文档方案）

## 1. 问题与动机
- 现状症状：cw_loop 备战分支持约 150 行编排——达标臂四段（判定消费/浮层闸/发射帧仲裁/发射调用）+ 交回处理。其中达标判定消费与仲裁决策属策略语义（「成型了要不要立即开打」「开打前钱多先花掉」），住框架层，与 op-layer.md §2.6「判据在策略器」相悖；**两套点出战执行并存**（cw_loop `readiness_battle_launch` vs prep_actions `_start_battle`/StartBattleOp，C1 单一化未竟）；出战交回外循环无契约（战斗窗置位靠分支内副作用）。
- 根因归层：流程层历史宿主。达标臂落码时（W971 时代）备战环还是外循环内的动作链，发射位只能落 loop；内环拆解后宿主未跟进。发射决策的治理缺位同理——策略侧动作词汇已有 StartBattle 终点（entry.py），达标臂的发射决策却独立实现在 loop。
- 解决到哪：发射决策进 mandate_v1（简单实现，见 §2 方案 3）；备战编排与达标臂执行进备战访问 op；交回契约建立；发射执行器合一。
- 明确不解决：
  - mandate_v1 深度重构（发射决策与三遍化编排的结构性整合）——**简单实现许可**（用户裁定：策略默认实现后续重做，届时精化）；
  - `cw_launch_admission` 迁层（kernel → mandate_v1）与 L256 宿主分层裁决的重审——判定核本迭代留 kernel（策略决策消费 kernel 读口），迁层挂策略重做批；
  - 恢复局面策略化——锁定局不走策略的直通形态保持；
  - cw_loop 备战分支最终收敛评估（本迭代后剩余 = 派发/交回/恢复局面/失败环，候策略重做后复盘）。

## 2. 方案
- 系统级变化：
  1. **交回契约**：CwScreenPrep 结果携带「出战已发射」事实（实现 = op 实例 `launch_fired: bool`，act 段发射成功即置位；loop 在 `execute()` 返回后读取）。战斗窗置位（`_battle_ts`/`_battle_wait_active`）仍归外循环——start-battle.md §3-1「战斗窗口置位归外循环」不变，改的只是事实传递通道（分支内副作用 → 结果事实）。
  2. **发射执行器合一**：审计 `readiness_battle_launch`（屏态复验/失败计数复位）与 `_start_battle`（重发长按/连败停机）+ StartBattleOp 逐项差异 → 合一为单一出战执行器，落 `prep_actions.py`；`readiness_battle_launch` 退役；恢复局面从 cw_loop 调统一执行器（C1「单一底层发射函数」完成形态）。依据：14_p1 C1（禁各写一套 StartBattle 发射位）、start-battle.md §3。
  3. **发射决策入策略层（简单实现）**：mandate decide 入口新增**前置发射位**（骨架 pass 之前，直线判定不重构三遍化结构）：
     - 消费 kernel 判定核 `readiness_launch_decision`（kernel 不动，策略经读口消费——判定核迁层挂策略重做批）；
     - armed ∧ 金 > 息线（kernel `cw_economy` 息线派生）→ 产出**受限商店访问意图序**（OpenShop 意图携带预算闸；本帧执行访问，次帧复判再发射——与现形态等价：现实现仲裁切屏后发射核复验弃射落守卫链，次帧发射）；
     - armed ∧ 金 ≤ 息线 → 产出 **StartBattle 终点意图**（词表现成，entry.py 终点动作）；
     - 非 armed → 原三遍编排零变化。
     依据：strategy-work.md §1（策略 = 决策函数族，读 GameState 输出动作列表——发射决策即决策函数）；14_p1 §9.6（发射位规格：fp≥1.0 触发、位次 = 动作链之前——前置发射位即该位次的新载体）；op-layer.md §2.4（decide = 策略消费 → 意图）。
  4. **备战访问 op 接管执行面**：浮层闸不再作为独立门——op 入口清场（揭示卡/书册卡/残留模态，CwScreenPrep 既有职责）+ start-battle §3-3 零判效重判语义自然承载（弹窗挡按钮 → 点击不落地 → 交回重判，次帧策略重提案）；受限商店访问执行 = op 既有受限访问机器按意图预算闸执行；仲裁切屏后「同帧发射」的旧复合形态由意图序跨帧承载（行为等价申报见下）。
  5. **cw_loop 备战分支收敛**：达标臂块删除后，备战分支剩余 = 双锚守卫 → 派发 CwScreenPrep → 读交回事实置战斗窗 → 恢复局面分支（调统一执行器）→ 失败 streak 环 → 环让位契约。`_prep_anchors_hit` 发射帧仲裁预检随仲裁意图化退役（其双锚单一源职能由 op 入口双锚守卫承接）。
- 行为变化申报：
  - 发射决策宿主：cw_loop 分支 → mandate_v1 前置发射位（判定核与判据值零变化，宿主更换）；
  - 仲裁形态：单帧复合（仲裁+发射同轮，切屏后弃射）→ 跨帧意图序（访问帧 + 次帧发射帧）——对外行为等价（受限访问恰一次、发射恰一次），内部时序变化；
  - 浮层闸：显式预检门 → op 清场职责 + 零判效重判（对外行为等价：弹窗帧不发射）；
  - 发射执行器合一后的日志标签审计随 3.1 交付（哨兵词汇表对照为落地判据）；
  - mandate_v1 非 armed 帧编排零变化。
- 接口契约（唯一必须定死的深度内容）：
  - 交回事实：`CwScreenPrep.launch_fired: bool`（act 段发射成功置位；loop 消费）；
  - 统一执行器：单一函数，输入 = （op 上下文, 调用面标记），内部承载屏态复验/重发/失败计数/连败停机全语义；两调用面（op 面、loop 恢复局面面）禁各自包装；
  - 仲裁意图：OpenShop 意图携带受限标记（预算闸 = 息线，值源 = kernel 派生），执行机器按闸收口。
- 关键取舍：
  - 备选「发射决策留 op（宿主更换即止）」：放弃——用户裁定发射决策必须进策略层（策略内容不住框架）。
  - 备选「发射决策同步深度整合进三遍化」：放弃——策略默认实现将重做，深度整合的投入会随重做报废；直线前置位是最小正确形态（用户裁定：实现可以从简）。
  - 备选「仲裁保持 loop 侧单帧复合形态」：放弃——复合形态正是策略决策住框架的成因；跨帧意图序对外行为等价（受限访问恰一次、发射恰一次、总耗时同量级）。
  - 备选「`cw_launch_admission` 同批迁 mandate_v1」：放弃——它有 kernel 内（cw_deploy_logic）与 op（cw_screen_deploy）消费面，牵动 L256 宿主分层裁决；判定核留 kernel 期间本迭代无 L256 冲突（策略消费 kernel 读口方向合法），迁层挂策略重做批一并处理。

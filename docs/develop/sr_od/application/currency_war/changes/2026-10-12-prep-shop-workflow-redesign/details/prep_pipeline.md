# 备战画面工序流（详设）

## 问题与约束

- 边界：本篇只管备战画面（画面档 `currency_war_battle_prep.yml`）上的决策工序、溢出告警自救、节点边界状态重置。商店会话内部见 shop_session；升级判据与选线函数见 line_and_upgrade；本篇只定义它们的调用时机。
- 总纲契约引用：契约 A（商店会话进出）、契约 B（方向状态消费）、契约 C（节点边界键清单所有者）、契约 D（卖出评估器场景之一）。
- 全扫语义：每次回到备战画面，从第 0 步向下扫描，执行第一个满足条件的步骤，然后重新扫描（决策入口 `emit` 每帧被调一次，单动作循环不变——现行装配形态出处 = strategy-docs/02 §7）。全扫的回跳语义覆盖：腾位后回头点晶矿、买完牌回头部署。

## 方案

### 1. 工序八步（逐条判据）

**第 0 步：溢出告警自救。**
- 触发条件：`gs.overflow_warning` 为真。机制事实：告警在场 = 备战席 9 格全满且溢出位有一张卡（角色或占席道具），溢出卡阻断进入战斗（建档出处 = `kernel/cw_game_state.py` overflow 字段注释，实机 2026-09-15/2026-09-24 确认）。
- 解除方式唯一：腾出一个备战席空槽，溢出卡自动归位（游戏侧行为，卖出归位已实机实证；消耗品点开腾槽是否同样触发自动归位——未实证，落地批按第 2 手段为主、第 1 手段落地时实测确认归位行为）。
- 自救阶梯（损失递增，逐级下探直到告警消失；候选评估见 §2）：
  1. 点开备战席上的消耗品（补给箱/典籍点开不占席 = 净腾 1 槽）；
  2. 卖 1 个候选评估器给出的首位候选；
  3. 上述穷尽仍告警在场 → 继续下一候选（阶梯自动穷尽到高损候选）。
- 防连卖守卫：同一告警情节内腾位尝试计数（键 = 节点作用域，见 §3），连续腾位满 5 次告警仍在 → 告警识别与实际状态冲突，走框架未知画面兜底（停机留证是工程故障层出口，不属于策略工序——用户裁定 2026-10-12「策略工序零停机出口」）。
- 告警在场时，本工序其余步骤全部不执行（告警不消出战无效，其他动作无意义——现行收窄语义保留，出处 = `mandate.py` 溢出告警门注释）。

**第 1 步：点开消耗品。**
- 触发条件：备战席槽位上有 kind 为 bookcard/supply_box/tome 的物品（现行容器 BenchSlot.kind 判定，出处 = `entry.py` 实体面段）。点开顺序：书册卡 → 补给箱 → 典籍。
- 点开产生的弹窗（武装箱选择等）由外循环画面分发接住，处理后回备战重新全扫（弹窗不是工序步骤）。

**第 2 步：晶矿。**
- 触发条件：`ore_click_targets_of(gs)` 非空（现行晶矿读口）。
- 席位未满：一次性点全部晶矿（现行批式点击保留，出处 = `prep_actions._collect_ore`，飞行等待 2s 口径 = screen_flow_timing #16）。
- 席位满：卖 1 个候选（评估器 §2 首位候选）腾槽，下轮全扫回到本步点击（用户裁定 2026-10-12：席满先卖腾位置只卖 1 个，晶矿必拿）。
- 腾位守卫：同一节点内为晶矿腾位的卖出 ≤ 2 次；第 2 次腾位后仍点不开 → 本节点放弃晶矿，记计数键（不重试）。放弃是合法出口（晶矿为随机资源，不值得为它动高价值持有——消费有效性，user_playstyle [32]）。

**第 3 步：升级检查。**
- 判据与发射形态见 line_and_upgrade §2（概率主轴 + 人口位并列 + 整级一次买齐）。本步只定义调用时机：每轮全扫评估一次；金不足整级时什么都不买（攒钱模式，等节点收入进账后自然满足）。

**第 4 步：商店会话。**
- 触发条件：「本节点已处理」标记 ≠ 当前节点号（标记格式与重开触发见 shop_session §4）。满足 → 输出 `CwActionOpenShopParam`（契约 A）；不满足 → 跳过本步。

**第 5 步：部署调整。**
- 内容 = 现行部署面整体保留：目标线成员上阵/换位（发射门纪律与配方底线门出处 = strategy-docs/10 §1）、开局配方（过渡体系开局）、空槽凑人数补位（任意合法单位上阵优于空槽，P24 残余补部署）。判据本体不改动，仅调用时机移到商店会话之后（用户裁定 2026-10-12：先逛店再统一部署）。
- 部署候选排除「场上已有同名同星」角色（游戏约束该状态不可达，出处 = merge_mechanics §3）。
- 部署完成后调用重开触发检查（shop_session §4.2）：未消费机会清单中存在被席满拦下且现已解拦的牌 → 清「本节点已处理」标记（下轮全扫第 4 步自然重开）。

**第 6 步：装备与工具。**
- 装备穿戴 = 现行完整实现整体保留（用户裁定 2026-10-12），仅调用位置固定为部署之后。工具使用判据 = 现行 `kernel/cw_equip_env.evaluate_tool_actions` 不动。
- 现行「工具动作先于骨架动作发射」的排序取消，固定到第 6 步（用户裁定 2026-10-12 工序序）。

**第 7 步：节末凑息检查。**
- 触发条件：当前金位 < 息线（`saturation_line(cap_resolved)`，出处 = `kernel/cw_economy.py`；息律投资局 cap=10 ⇒ 息线=100，禁裸 50——口径出处 = strategy-docs/11 §1 金约束门）。
- 动作：卖 1★ 全额退件（候选评估器过滤参数 = 仅活期件）补缺口，卖到缺口闭合即止、不多卖一张（卖回量最小化，user_playstyle [11]；「发现凑息可能时将备战卖回去凑息」用户裁定 2026-10-12 保留本动作）。
- 放在出战前的理由：息在节点结算时计，活期牌在手保留到最后一刻，中途部署/合成需要时还在（[11] 动态无损语义）。
- 本步卖出的退金计入「未消费机会清单」的金状态（shop_session §4.2 场景 2），可能触发清单解拦。

**第 8 步：出战。**
- 触发条件：以上全部步骤无动作。输出 `CwActionStartBattleParam`（备战环唯一完成态，现行语义不变）。
- 出战点击后若长时间未离开备战画面且第 0 步告警已清 → 交外循环未知画面兜底（工程层，非本设计范围）。

### 2. 卖出候选评估器（契约 D 的备战域消费）

- 候选池：备战席全部角色 ∪ 场上全部角色（用户裁定 2026-10-12：卖出同时考虑场上和备战席——场上凑人数垫件是合法候选）。
- 资格门（不可卖，fail-closed 不变）：锁定线成员、现行 `sell_gate` 排除集覆盖的身份（骨架件、通用插件等）；空板守卫（卖出后场上占用为 0 拒卖）不变。
- 价值排序（从先卖到后卖；用户裁定 2026-10-12 语义 = 手上价值最低者让位）：

| 维度 | 价值低（先卖） | 价值高（后卖） |
|---|---|---|
| 与目标线关系 | 无关 | 名单成员 |
| 板面羁绊代价 | 卖后不掉档（备战席件天然满足） | 卖后掉当前羁绊档 |
| 合成进度 | 零散单张 | 已有两张同名（差一张合成） |
| 星级/费用 | 1★ 低费 | 2★ / 高费（高费再遇 60-180 轮，持有期权值钱——user_playstyle [22]） |

- 各场景的差异只在过滤参数与消费方式：告警/晶矿场景直接取首位候选；店内置换场景由 shop_session 比较账裁决（见 shop_session §3）；节末凑息过滤为仅 1★ 全额退件。
- 每笔卖出记遥测（场景、卖出名、价值档），自救与腾位场景的卖出必须可判读归因。

### 3. 节点边界状态重置（契约 C）

- 触发点：备战决策入口与商店决策入口共用的节点号读取处，检测到（位面，轮次）变化 → 执行边界处理一次。
- 重置清单（键清单唯一所有者 = 本函数；其他详设把自己的键登记进来）：
  1. 「本节点已处理」标记 → 清除（新节点牌面全换，旧标记语义死亡；机制依据 = economy §2.1「节点切换自动刷新全店」）；
  2. 「未消费机会清单」→ 清空（牌面变了，旧机会作废）；
  3. 晶矿腾位卖出计数 → 清零；
  4. 溢出告警腾位尝试计数 → 清零；
  5. 方向证据签名 → 置失效（强制下帧重算——节点变动伴随结算收入与自然经验，资产面可能变化）；
  6. 方向状态本身（目标线/未定型）→ **不重置**（跨节点持续；换目标只由选线函数的比较账驱动，见 line_and_upgrade §1）。
- 登记扩展方式：其他模块的节点作用域键在边界处理函数的清单表显式登记（键名 + 初始值），禁各自散写重置逻辑。

## 关键取舍

- **全扫 vs 状态机步进**：选全扫。备选是记住「走到第几步」的严格状态机，放弃原因：腾位→回点晶矿、买牌→回部署等回跳在全扫下自然表达，且与现行单动作循环装配零冲突；状态机需额外维护步进位置且每个回跳条件都要显式建模，复杂度更高、漏分支风险更大。
- **溢出死局出口**：阶梯穷尽而非停机报警。用户裁定 2026-10-12：备战席有东西就能卖、能卖就有槽，死局在机制上不存在；把策略纪律（不卖自己人）当游戏限制是原设计错误。
- **晶矿放弃出口**：腾位 2 次守卫后放弃而非无限尝试。防「为点不开的矿卖光备战席」的活锁；放弃损失（随机资源）远小于连卖损失。
- **升级判据的濒死破例不保留**：现行「血线硬地板解锁破息升级」依赖 HP 作决策输入，违反 user_playstyle [39]（HP 不作决策依据）与 [18]（血低是报警非 ALL IN 触发）。本设计删除该解锁层；血本位突变下的支付能力检查（[40]②）保留——它是账户余额检查，非质量信号。

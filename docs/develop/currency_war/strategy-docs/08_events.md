## 0. 章程

- 每项格式：**现有语义**（收录自原 03 §4.9〔已删除〕，用户裁定/知识来源）→ **判据状态**（一律「待 derive」除非注明）→ **立项锚**（判据该走的数学通道：挂到哪个已证命题的参数化，或立新命题）。
- 「待 derive」的含义：该决策点的判据可写成已证命题的参数替换/扩域者，按锚立项推导；无锚者立新命题（P 编号由编排者落 math_proofs 索引时分配）。**推导完成前，实现按「现有语义」列的知识判据执行**（骨架/知识判据先行，数学判据到位后替换——与 01 §7 待证钩子「结构背书形态，数据到位前不授权数值」同构）。
- 事件面的横切纪律：一切「环境/突变改变机制输入」经 resolved input 原则消费（[11_shop_decisions.md](11_shop_decisions.md) §8）；战力族/资产发放族不进经济 resolved（走权重/克制通道与组件缺口通道）。

## 2. 落差管理（本篇的核心职责）

- **现状一句话**：18 项中，E11 已有已证锚可直接消费；E10 大部已证（残余 = 实机采集项）；E13 结构已立（数值挂实采）；E14 无数学面；**其余 14 项全部「待 derive」**（含 E16-E18 三钩子：现行实现为知识/结构打分，数学判据无一已证）——这就是「目录全量/数学全空」落差的如实登记。任何「事件面已有数学」的表述在推导落地前禁用。
- **推导优先序建议**（按消费频率 × 录得难度）：E1/E2/E15（每局必遇、台账价值通道现成）> E3（P26 同构）> E4/E9（组件/池通道现成）> E5/E12（供给硬缺前置，先补供给再立判据）> E6/E7/E8（弱数学面，知识判据长期承载）。
- **禁项**：事件判据禁自带数值（宪法第 4 条）；「奖励偏好序」类知识判据须标注知识来源（combo_methodology 等），不得伪装为推导；供给三缺（E12/E10/E5）未补前，对应事件的实现 = 保守跳过 + 计数披露，禁猜测分类（与契约 §3.3 fail-closed 同款纪律）。
